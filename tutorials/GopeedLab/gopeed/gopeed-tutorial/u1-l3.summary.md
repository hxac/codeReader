本讲义绘制了 Gopeed 仓库地图。cmd/ 是「单 module 多入口」集合（CLI、api、web、host、updater、extmock），共享启动逻辑收敛在 server.go；bind/ 是小而稳定的桥接层，desktop 用 cgo 导出动态库、mobile 用 gomobile 绑定，两者共用同一执行器；pkg/ 是公共库（base 领域模型、download 下载引擎、api 服务层、rest 与 mcpserver 传输外壳）；internal/ 受编译器可见性规则保护，藏有 fetcher 协议契约与各协议具体实现；ui/flutter 则是三端共享的前端。核心结论：pkg 与 internal 的分层保证公共 API 稳定、内部实现可自由重构；pkg/protocol 只放公开参数模型而 internal/protocol 放实现；桥接请求统一汇入 rest.Dispatch，新增接口桥接层零改动；依赖聚集处即模块边界（如 torrent 对应 bt 实现、goja 对应 JS 扩展引擎、bbolt 对应任务存储）。本讲引入的关键术语：多入口、internal 可见性规则、Fetcher 接口、Boot 链式 API、协议注册顺序。
