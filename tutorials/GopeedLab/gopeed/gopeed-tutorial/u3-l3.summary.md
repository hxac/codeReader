本讲覆盖 internal/controller、internal/tempfiles、internal/logger 与 internal/httpclient 四个模块。核心结论：Controller 是 Downloader 与 Fetcher 之间的中介服务包，把只有 Downloader 才能回答的问题——临时文件作用域 TempFiles、临时目录 TempDir、协议配置 GetConfig、代理解析 GetProxy、日志 Logger、内嵌的文件创建接口 FileController——在 setupFetcher 中逐字段装配并经 fetcher.Setup(ctl) 注入，协议实现不反向依赖 Downloader。DefaultFileController.Touch 三步走：MkdirAll 建父目录、Create 建文件、Truncate 预分配稀疏长度，仅新任务调用，续传路径绕开。tempfiles.Scope 以 Track 登记、Remove 销账、Close 兜底清理，关闭后再 Track 会当场删除防泄漏。注意 DownloaderConfig.Controller 字段目前不接线，自定义 FileController 须自建 Controller 注入。ctl.Logger 可能为 nil，协议须判空；GetProxy 实现 Blob 旁路与任务级三态代理，产物直接作为 httpclient 传输层的代理；其自适应伪装传输层遇 403 或 Cloudflare challenge 会按站点缓存浏览器指纹回退结论。
