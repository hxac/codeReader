本讲剖析 Gopeed HTTP Fetcher 的多连接分块下载，覆盖五个最小模块：chunk 区间模型、connection 状态机、downloadLoop 调度扩张、slowStartController 慢启动、helpOtherConnection 工作窃取。核心结论：chunk 以 Begin/End/Downloaded 记账，活跃区间不重不漏覆盖未完成字节；切分点取受害者剩余量一半，必落在其已写位置之前，并发切分因此安全；End 为 *int64，支持总大小未知时的 openEnded 形态。connection 是逻辑车道而非 socket，五态状态机，仅 403、重试耗尽、Range 完整性错误属终态失败。downloadLoop 由容量 1 的 expansionCh 心跳驱动逐批建连，慢启动批次平方增长（上限 16 时序列 1、2、4、9），「成功」以响应头验证通过计。收尾平衡靠工作窃取：干完的连接偷「剩余时间超 3 秒且剩余不少于 512KB」的最慢连接的后一半，受害者读循环每次写入前重读边界并截断超额数据，实现无冲突协作。
