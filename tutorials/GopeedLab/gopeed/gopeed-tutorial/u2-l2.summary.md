本讲剖析 `pkg/download` 的 Task 结构与任务状态机。Task 分三层：公开层（ID、Meta、ParentID、Status、Progress、DoneAt 等可序列化字段）、运行时层（fetcher、锁、timer、测速窗口、runGeneration 等私有字段，JSON 序列化即丢失，恢复时由 initTask 重建）、展示层（MarshalJSON 用别名类型避免递归，动态追加 name 与 group）。状态机为 ready/wait/running/pause/error/done 六态：wait 是纯调度概念，done 唯一终态，error 可重试，重启后未完成任务统一回落 pause。核心结论：状态的唯一写入者是 Downloader，Fetcher 只以 Wait() 返回值汇报，由 watch 循环翻译成 done/error 迁移；DoneAt 的一次写入靠「running 守卫 + done 无出边」的结构保证；分组归属双轨制——ParentID 落盘为权威、group 指针为运行时缓存，批量操作中组 ID 经 expandGroupTaskIDs 展开；速度为约 5 秒滑动窗口的差值均值，任务完成时改写为全程平均速度。
