本讲走通任务主链路。Resolve 做资源发现并把活 Fetcher 缓存进 fetcherCache（扩展钩子短路时 ResolveResult.ID 为空，只能配 CreateDirect）；建任务分两路：CreateDirect 延迟解析（Res 为 nil，推迟到启动时），Resolve→Create 消费解析缓存，二者在 doCreate 汇合装配 Task 骨架并先落盘再调度；满载时任务直写 wait 态入 waitTasks FIFO 队列，由 notifyRunning 在名额释放（暂停、删除、完成、出错）时异步唤醒队首。doStart 为两段式：同步段（statusMut/statusLock）拦截不该启动的任务、restoreFetcher、置 running 并递增 runGeneration；异步 handler 做扩展钩子、Meta 回填、延迟解析、prepareTask 与 fetcher.Start()，三次代数核对防旧协程覆盖新状态。prepareTask 由 NeedsPreparation 标记控制，一次性完成目录决策（decideDownloadDir）与重名改名（CheckDuplicateAndRename），在深克隆预备稿上「先存候选、后发布」；因查重依据磁盘 Stat 而文件要到 Start 才创建，全局 checkDuplicateLock 必须罩住查重、改名、启动全程；已准备任务不再改名，但每次启动仍复检目录白名单。
