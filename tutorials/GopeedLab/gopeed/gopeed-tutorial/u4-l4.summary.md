本讲剖析 Downloader 的暂停、继续、删除与最大并发调度，是全项目竞态最密集的区域。核心结论：暂停/继续/删除共享 TaskFilter 批量过滤模型，组 ID 经 expandGroupTaskIDs 展开为成员任务 ID，实现按组批量操作；MaxRunning 并发由「waitTasks FIFO 队列 + notifyRunning 唤醒」实现，Continue 在空位不足时用腾位算法 doPauseForScheduling 把运行中任务物理暂停并压回队尾；runGeneration 代数计数器配合 preparePause/runPauseHandler 两段式暂停，拦下「暂停与完成同时发生」「过期启动」等竞态；Delete 走三段式——锁内摘除并登记 deletingTasks、锁外 doDelete、失败时回写 bucketTask 并追加回内存与队列恢复，creatingGroups 反向守护创建中的分组；终态仅由只准入 running 的 markTaskDone/markTaskError 守门；事件必须收集后在锁外发射。
