本讲讲解 HTTP Fetcher 的 Resolve 阶段：用一次不带 Range 的 GET 完成元数据探测，响应体保留供下载复用（一次性 URL 场景的关键），并兼作测速探针记录 maxConnTime。Resource 填充规则：Range 由 Accept-Ranges/Content-Range 判定，决定多连接下载可行性；Size 按 206 总长、Content-Length、用户提示三级回退，并以 sizeKnown 区分权威值；文件名按 Content-Disposition、URL 末段、主机名三级回退再补扩展名；另提取 If-Range 校验器留作断点校验。asyncPrefetch 在用户确认下载前的空窗期把响应体写入临时文件实现预取；接管由 resolveFallback 原子仲裁，四条路径——预取即完成、首个 206 验证后 commitResolveTakeover 丢弃 overlap 重叠、Range 失灵时 completeFromResolveFallback 单连接兜底、Pause 抢先物化——保证同一字节只请求一次，为 u5-l2 多连接与 u5-l3 断点续传铺垫。
