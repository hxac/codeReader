本讲精读 pkg/rest，把 u8-l1 的传输无关 API 层组装成真正的 HTTP 服务。核心结论：Start/Stop（托管式，原生端用）与 BuildServer（组装式，服务端部署用）两条启动路径共享 initializeCore 建立的唯一 Downloader+APIService 单例；buildServer 的组装顺序即语义——/api 与 /mcp 命名空间保留（挂 NotFoundHandler）必须先于 Web 静态兜底路由，否则未知 API/MCP 路径会返回 SPA 的 index.html 而非 404；鉴权为双层判定：请求携带 X-Api-Token 或 Authorization: Bearer 头即只按 token 判定（常数时间比较防时序攻击），否则查 7 天 TTL 的内存会话 cookie，登录端点 /api/web/login 永远放行。关键术语：StartConfig、NativeMode、命名空间保留、webSessionStore、taskFileSystem 与 extensionFileSystem（按任务 ID/扩展 ID 把 URL 映射到磁盘文件）、embedCacheFileSystem（统一 ModTime 支撑缓存协商）、gzip 中间件、apiServerManager 的 desired/active 双状态模型（PendingApply 表示配置改了未生效）。
