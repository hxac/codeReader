本讲是 Unit 8 系统集成的收尾，把 RTL、固件、CSR HAL、构建链与仿真台汇聚为两块 AX7201 板卡的端到端实网验证。每个节点经 UART CLI 做三类配置：`config network`（节点身份，落普通 CSR 寄存器）、`config routes`（转发条目，落 `routing_table` external 表）、`config cryptokeys`（peer 身份与密钥，落 `cryptokey_table` external 表），后两者为 tdp_ram，改表前须经 FCR 的 `pause`/`idle` 原子握手。核心结论：左右节点的 `encrypt_key` 与 `decrypt_key` 必须**交叉镜像**（`Left.encrypt==Right.decrypt` 且 `Left.decrypt==Right.encrypt`），这是 ChaCha20-Poly1305 对称加密的硬性要求，配错则单向或全不通；收发计数器 `send_cnt`/`recv_cnt` 为 CPU 与硬件双向可写的状态字段，配置时复位以让 96 位 nonce 从 0 派生。验证分两层：host A 用 `ping` 验隧道双向连通，在网线上用 Wireshark 抓 UDP/51820 确认载荷加密。这套实网验证与 `gen_udp_pcap.py`+`VUserMainPcap` 的仿真 PCAP 验证是同一 DPE 路径的数字孪生，仿真做日常回归与延迟测量、实网做发布前最终验收。现状提醒：当前 PoC 综合 `dpe_dummy_switch` 明文直通，但密钥镜像配置正确且必要，待加解密流水线上线后即驱动真加密隧道而无需改配置。
