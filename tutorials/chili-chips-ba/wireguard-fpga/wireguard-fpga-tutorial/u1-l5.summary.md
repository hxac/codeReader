本讲是上手篇收尾，把 bitstream 烧上板并端到端验证。用 minicom 经 USB 串口（/dev/ttyUSB0，固定 115200 波特率）连上 CLI——它跑在板内 RISC-V 软 CPU 固件上，启动先校验硬件 ID（0xCCBA/0xCACA）再进 `(wireguard-fpga)#` 提示符。核心是三条交互问卷命令：`config network` 配本节点网络身份（IP/MAC/网关/默认接口）；`config routes` 配 64 条路由表（目的网段→peer→出口接口）；`config cryptokeys` 配 WG peer 的本地/远端身份与 256 位加解密密钥。后两者以 external 表（双口 RAM）落地，改表前固件经 FCR 做 pause/idle 原子更新握手，防止数据面读到半成品表项。引入的关键术语：DPE 接口地址 0-7（0=CPU、1-4=eth1-4、5/6/7 组播广播）、external 表、FCR 原子握手。最重要结论：两节点的加解密密钥必须交叉镜像（左 enc=右 dec、左 dec=右 enc），是对称密码 ChaCha20-Poly1305 的硬性要求；验证须 ping 通加 Wireshark 抓包确认密文。当前 Phase1 PoC bitstream 用 dpe_dummy_switch 加软件桥接明文直通，同一套 CLI 配置待加密流水线（U4/U5）上线后即驱动真加密隧道。
