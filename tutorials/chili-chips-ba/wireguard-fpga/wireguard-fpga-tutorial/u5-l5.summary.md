本讲是 Unit 5 资源复用篇，回答加解密能否共用一份 ChaCha20/Poly1305 硬件。覆盖三个最小模块：(1) 共享动机与 ID 标签传播——ChaCha20 的 64 级流水线是 SoC 最贵的组合逻辑，只造一条让加解密轮流用，即「时分复用」，以吞吐换面积；请求注入时盖 1 比特戳 `is_encrypt`，随数据穿越全部 64 级，出口按「穿过来的标签」路由结果，而非入口调度器当前状态。(2) 输入端 round-robin——一个每拍无条件翻转的 static 寄存器给两侧各一拍时间片，固定 50/50，单侧满载也只能用到半速。(3) 输出端 ID 解复用与背压——按标签分发结果，并把目标侧 ready 回传给共享流水线以保数据不丢。核心结论：当前 HEAD 实际只共享了 ChaCha20（背压正确、可投产）；Poly1305 共享文件虽存在于源码、却已注释且背压未完工，改用每侧独立 MCP 实例以保留全速吞吐，尽管 README 把两者都描述为共享。引入关键术语：时分复用、信封、ID 标签传播、round-robin 仲裁、ID 解复用、背压、MCP、`GLOBAL_PIPELINE_INST_W_VALID_ID` 宏（宏自带 ID 端口的手法，与 ChaCha20 手写信封结构体形成对比）。
