本讲拆解控制面总线的三个最小模块：`soc_pkg` 定义的公共类型、`soc_if` 定义的总线接口、`soc_fabric` 定义的中央互联。核心结论是 CPU 如何经 fabric「找到」DMEM 与 CSR 并完成一次访问。

`soc_pkg` 以字地址 `soc_addr_t = logic[31:2]` 配按字节写使能 `soc_we_t` 取代字节地址最低 2 位，`we` 兼任读/写标志与子字掩码。`soc_if` 是一条 vld/rdy 握手总线（同拍为 1 即完成），用 `MST`/`SLV` 两个 modport 把方向定死且互补，且没有超时机制——访问未映射地址会永久挂起。`soc_fabric` 干三件事：地址译码（DMEM 看 `addr[31:28]==1`、CSR 看 `addr[31:29]==1`，二者互斥）、按 select 把 rdy/rdat 多路返回、以及 CPU 与 UART 的双主机仲裁——同时请求时 CPU 赢，但 UART 一旦持有总线则不可被抢占。译码窗口远大于实际资源并产生别名，靠链接脚本回避。

关键承接术语：`soc_if`/`MST`/`SLV`、地址译码与内存映射、`uart_busy` 仲裁，这些为 u2-l5 的 UART 在线编程（`BUSR`/`BUSW` 原子访问）和 Unit 3 的 CSR 寄存器读写提供公共前置。
