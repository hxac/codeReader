本讲把 WireGuard 数据包在 DPE 处理流水线里的完整走向——解封装 → 解密+认证 → 路由 → 加密 → 封装——对应到三个真实 RTL 块。README 的六个概念块在源码里合并为三个 WG 文件：`dpe_wg_disassembler` 逐 beat 用常量诊断包头（注意 EtherType 0x0800 在小端 AXIS 总线上读成 0x0008 的字节序陷阱），剥离外层 Ethernet/IP/UDP/WG 头，把接收计数 `wg_rcv` 与发送方计数 `wg_cnt` 塞进 `tuser`，非 WG/握手报文走 bypass；`dpe_wg_decryptor` 用「验证门 + 512 深 sync_fifo」实现 AEAD 的 verify-before-forward，明文先进 FIFO，整包 Poly1305 tag 校验通过才开闸放行，失败则 fifo_clear 静默丢弃，绝不泄露未认证明文；`dpe_wg_encryptor` 并行喂明文进 ChaCha20-Poly1305 核并逐拍生成新外层头，包尾把 send_cnt+1 回写，保证 nonce（={32'd0, send_cnt}）不复用。核心安全机制——96 位 nonce、单调 send counter、verify-before-forward——借此落地。加解密核当黑盒，其 key/nonce/peer 地址来自双口 RAM cryptokey_table（A 口接 CSR、B 口预留给数据面，见 u4-l6），核内部留待 Unit 5。关键现状：三个 WG 块源码已写好但在 top.filelist 被注释或未登记，dpe.sv 实际例化的是固定明文转发的 dpe_dummy_switch，密钥表 B 口悬空——当前 bitstream 仅跑通 mux/demux/MAC 的「明文直通 + 软件握手桥接」，真加密隧道尚未上线。
