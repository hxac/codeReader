本讲聚焦 `3.build/pipelinec_build/`，讲清 PipelineC 这套开源 HLS 如何把 ChaCha20-Poly1305 的 C 加密代码编译成可综合 Verilog，并覆盖三种设计变体与贯穿其中的 pragma、实例化约定。

三个最小模块：其一，HLS 流程——靠 `$PIPELINEC <src.c> --top <name> --verilog` 把每个 C 函数编译成一条流水线，输出扁平化的 Verilog，每次从零重建；产物在 `generated-files-verilog/`，仓库另存预生成的 `generated-files/*.v`。其二，三种设计变体——独立加密、独立解密、加解密共享，对应三份顶层 C 与三条脚本，差异在面积与吞吐取舍：共享变体让加解密复用一条 ChaCha20 流水线，靠一比特 `is_encrypt` 标签随数据穿越整条流水线实现 round-robin 输入复用与输出解复用，面积近半、峰值吞吐减半；但 Poly1305 因「没那么大」而选择不共享、改用 MCP 换吞吐。其三，pragma 与约定——`PART` 绑定 Artix-7 200T，`MAIN_MHZ` 定顶层与 80 MHz 时钟（生成 `clk_80p0`），`FEEDBACK` 声明位宽转换 ready 的组合环路，`DECL_INPUT/OUTPUT` 配合 `#ifndef SIMULATION` 把 AXIS 结构体端口展平为标量；`#define INST` + `PPCAT` + `#undef` 用预处理器模拟模块多实例化。ChaCha20 核吃 512 位块，进出各有一次 128↔512 位宽转换（4:1），夹在 64 级流水线两侧。需注意当前 HEAD 处加密核尚未焊进 `top.filelists`。
