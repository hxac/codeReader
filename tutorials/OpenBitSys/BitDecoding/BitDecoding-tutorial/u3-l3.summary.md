本讲为绑定层收尾，解读 decode kernel 启动前的最后一项 CPU 决策：`num_splits_heuristic` 与 `set_params_splitkv`。核心动机是「并行度饥饿」：decode 时 block 数约为 batch×heads_k，远少于 SM 槽位，须沿 KV 序列维切分。引入波次效率模型 eff(s)=n_waves/⌈n_waves⌉、伪 split 资格判定（`is_split_eligible`）与 85% 规则——在合法 split 点中取达到峰值效率 85% 的最小值，以少付 HBM 流量；槽位数按 SM 数×2 计。`set_params_splitkv` 将结果 +1，为 residual kernel 预留最后一个累积槽位（splitkv kernel 的 grid.y 为 num_splits−1；KV 每个 token 恰属一个 split，读取总量不随 split 数增长），并分配 float32 中间缓冲 `softmax_lse_accum` 与 `out_accum`（最外维为 num_splits，out 末维是 d_rounded），每层每步分配、靠 caching allocator 摊销；num_splits≤128 上限对应 combine kernel 的 `Log_max_splits` 模板阶梯。Python 侧恒传 num_splits=0，永远走自动启发式。
