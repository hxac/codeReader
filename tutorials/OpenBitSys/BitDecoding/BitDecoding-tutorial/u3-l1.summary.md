本讲精读 decode_api.cpp，打通从 Python 调用到 GPU kernel 启动的完整 C++ 链路。PYBIND11_MODULE 仅导出 4 个函数，实为模板实例 kvcache_qpack<2/4> 与 mha_fwd_kvcache<2/4>；num_bits 是编译期模板参数，Python 层须按位宽分流函数名并按位置对齐 26 个参数。mha_fwd_kvcache 的骨架是防御性校验（CHECK_DEVICE/SHAPE/CONTIGUOUS 与 TORCH_CHECK）→ GQA 的 seqlenq_ngroups_swapped 重排（把 q 头维折入序列维以提高 decode tile 利用率）→ 组装 Flash_fwd_params → 无条件 force_split_kernel=true → run_mha_fwd 分发至 residual/splitkv/combine 三个 kernel → 逆重排返回 5 元组。核心陷阱：dispatch 的 if 链落空会静默无操作、返回未初始化内存，当前仅启用 k-channel × group_size∈{128,32} × num_bits∈{2,4}，dispatch 行与 genfile 显式实例化须成对解开。kvcache_qpack 因 Python 侧折叠了 batch 维，须从 cu_seqlens_k.numel()-1 恢复 batch 数并手工计算 batch stride；residual_block_size 是未被消费的哑参数，实际块大小由编译期常量决定。Flash_fwd_params 字段细节与 num_splits_heuristic 留待后续讲义。
