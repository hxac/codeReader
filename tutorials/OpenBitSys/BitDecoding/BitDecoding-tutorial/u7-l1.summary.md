本讲搭建 BitDecoding 的两层正确性验证：Python 层 test.py 不加载模型，走打包加逐轮 decode 全链路，与 FP16 参考 attention_ref 逐轮比对 MAE，只打印不判定；kernel 层 .cu 测试以自包含的 single_mha 为金标准，按 MAE/MSE 硬阈值判定（residual/single 为 0.1、batch 为 0.01），核心是分层定位思路——kernel 级、Python API 级、模型级各抓不同类型的 bug。唯一与现 API 同步且启用的 test_single_residual 用固定种子和 17 个边界扫描点跑两轮闭环，覆盖「打包→残余→攒满→torch.cat 回写→再 decode」；其残余切分规则（整除时保留一整块）与 test.py（余 0 残余为空）刻意不同。CMake 是独立于 pip 的构建通道，测试 target 须链 5 个 genfile 实例化单元；include 路径硬编码有坑；另两个测试因调用旧版 9 参数/单返回值签名必然编译失败，属 API 化石。k-channel/4bit/group_size=32 在 dispatch 与实例化层均已启用，障碍只在构建层。
