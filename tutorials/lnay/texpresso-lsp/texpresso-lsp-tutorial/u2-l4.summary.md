本讲（u2-l4）讲文档同步机制：texpresso-lsp 如何把编辑器的三个 LSP 文档事件翻译成 texpresso 命令，是 u2-l3 协议层之上的第一个业务消费者。核心映射为：didOpen → open（带路径与基准全文，冷启动喂全文）；didChange → change-range（六元数组 [path, 起行, 起列, 止行, 止列, 新文本]，坐标 0-based）；didClose → close（仅带路径，通知释放资源）；三者均经 sendCommand 写入子进程 stdin。握手时声明 TextDocumentSyncKind.Incremental，故 didChange 只携带「范围 + 新文本」而非全文。三个处理器共用 URI.parse(...).path 把 file URI 归一化为文件路径。关键术语：增量同步（区别于 Full/None）、change-range 六元数组、高层与低层 API 的不对称（变更走低层 connection.onDidChangeTextDocument 配手动 documents.get 守卫，留下「can this be out of sync?」的潜在丢更新隐患与技术债）。
