本讲聚焦 texpresso-lsp 的错误兜底与进程生死，分三模块。一是事件转发两级跳：process-manager.ts 把 ChildProcess 的 error/stderr/exit 转为自身事件，server.ts 统一接到 connection.console.error 打进 LSP 日志；error 为同名转发，因 EventEmitter 对无监听器的 error 事件会抛未捕获异常致崩，必须监听。二是 try/catch 策略对立：onInitialize 用 rethrow 让握手失败（握手要狠），运行期回调用 swallow 保活（其余要稳）；sendCommand 守卫是薄封装唯一硬防线，集中检查 isRunning 与 stdin/stdout。三是 parse-fail 容错与 shutdown：解析失败行伪装成 `["parse-fail", line]` 走统一分发，事件名非 error 故无监听器时静默丢弃不崩溃，实现优雅降级。关键术语 isRunning 是进程状态单一真相，在 start 成功、exit、start catch、stop 四处写入，使 stop() 幂等、进程死后调用安全。已知局限：文档同步回调无 try/catch，崩溃后写入变未处理 rejection；进程崩溃不自动重启。
