本讲讲解 texpresso-lsp 与 texpresso 子进程的对话机制，含三块。其一，行缓冲：stdout 字节流存在半包（一条消息被切两块）与粘包（多条挤一块），process-manager 用 stdout_buffer 先追加、按 \n 切行、lines.pop() 把末尾半行留存到下次拼接，保证交给解析器的总是完整一行。其二，NDJSON 协议：每行一个 JSON 数组 [command, ...data]，第 0 位命令名、其余为数据，发收两端 stringify/parse 对称；空行被 filter 过滤，解析失败则伪造 ["parse-fail", line] 走相同流程降级而不崩溃。其三，事件分发：process-manager 经 EventEmitter 用 emit(command, data) 投递动态命令，并固定转发 error/stderr/exit 三个进程级事件；server.ts 用 .on(...) 接住转成日志或业务，发方向用 sendCommand 编码后写 stdin（含进程健康守卫）。核心结论是「薄封装」——协议层对命令名一视同仁，新增一条命令时协议层零改动，只需在 server.ts 加监听器或 sendCommand 调用。本讲引入的半包/粘包、行缓冲、NDJSON、sendCommand、emit/事件分发、parse-fail、薄封装等术语，以及命令 open/change-range/rescan/close/synctex-forward，是 u2-l4、u3-l1、u3-l3 的共同底座。
