本讲解析 `TexpressoProcessManager` 类，讲清 LSP 服务器如何用 Node 的 `child_process.spawn`（流式，区别于缓冲式的 `exec`）以 `stdio:"pipe"` 拉起 `texpresso` 子进程、并经 stdin/stdout 双向通信。三个最小模块为：spawn 子进程、start/stop 生命周期、状态管理与超时等待。构造函数以 TypeScript 参数属性简写接收 `executablePath`、`args`、`rootTex`，并用 `this.args.push(this.rootTex)` 将主文件追加到参数末尾，最终执行 `texpresso -json -lines main.tex`。生命周期绑定 LSP：`onInitialize` 调 `start()`、`onShutdown` 调 `stop()`；`start()` 重复调用会抛异常，`stop()` 在未运行时静默返回（幂等）。布尔字段 `isRunning` 是进程状态的单一真相，在 start 成功、exit 事件、catch/stop 三类路径上被写入。`start()` 用「5 秒 setTimeout」与「首次 stdout 的 data 事件」赛跑作为就绪检测，超时或无输出即判定失败并使整个握手失败。该类继承 `EventEmitter`，将底层 `ChildProcess` 的 error/exit 事件转发为自身事件供 server.ts 监听，即包装器模式。stdout 逐行缓冲与 JSON 解析留待下讲 u2-l3「JSON 行协议与命令分发」。
