本讲用「读地图」的视角梳理 texpresso-lsp 的目录结构与入口文件链路，覆盖三个最小模块：目录布局、package.json 字段、tsconfig 编译映射与入口链路。仓库为小型项目，版本库内含 src/（server.ts、process-manager.ts、types.ts 三个源码）、bin/texpresso-lsp.sh 入口脚本及若干配置与 CI 文件，node_modules/、dist/ 为构建产物、被 gitignore 忽略。核心结论有四：其一，src/server.ts 是唯一源码入口——它在源码依赖图中是根（导入另两个文件，无人导入它），运行期其编译产物正是被 bin 脚本 require 的对象；其二，package.json 是项目元数据身份证，name 既是包名也是全局命令名，main/bin 分别是「被 require」与「被运行」两个入口，dependencies 与源码外部 import 一一对应（vscode-languageserver、vscode-languageserver-textdocument、vscode-uri 三对外部包），devDependencies 对应构建工具链；其三，tsconfig 的 rootDir→outDir 决定 src/*.ts→dist/*.js 的产物映射，module:commonjs 把 ES import 编译成 require，这是 bin 脚本能加载产物的根本前提；其四，strict:true 实实在在塑造代码风格，催生了 ??、?. 守卫与 catch 中的 instanceof 类型收窄。完整入口链路为：texpresso-lsp --stdio →（bin 字段）→ bin/texpresso-lsp.sh →（require）→ dist/server.js → 顶层 connection.listen() 开始服务。本讲只做静态结构梳理，握手、收发命令、子进程管理等运行期行为留给后续单元。
