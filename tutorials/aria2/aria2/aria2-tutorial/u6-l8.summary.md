本讲精读 aria2 的 BEP10 扩展协议实现。所有扩展消息共用 20 号 BtExtendedMessage 外壳（1 字节扩展 id + bencode 载荷），扩展 id 0 保留给 extended handshake；扩展 id 每对连接、每个方向独立协商——本端表 ExtensionMessageRegistry 固定 ut_pex=8、ut_metadata=9，用于通告与接收反查，对端表存于 peer 会话资源、发送时取 id，两表经扩展握手的 m 字典交换，并遵循「不通告即不支持」的单开关原则（关闭 --enable-peer-exchange 或私有种子即移除 ut_pex 通告）。ut_pex 以 6/18 字节紧凑格式约每分钟广播一次 added/dropped peer 列表（flag 0x02 标 seeder），构成 tracker 之外的第二大 peer 来源。ut_metadata（BEP 9）在 metadataGetMode 下把种子 info 字典当作 16KiB 分片的虚拟文件，用 request/data/reject 三种消息逐片获取，每 peer 同时仅 1 个在途、20 秒超时，收齐后整体 SHA-1 与 infohash 比对终检，为下一讲 magnet 链接的两阶段任务铺路。
