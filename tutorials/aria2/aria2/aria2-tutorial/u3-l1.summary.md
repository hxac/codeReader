本讲从命令层上升到任务层，覆盖四个模块。核心结论：RequestGroup 是 aria2 对“一次下载任务”的容器抽象，聚合 Option、DownloadContext、SegmentMan、PieceStorage、URISelector 与 Dependency 等资源，以 `-s`（numConcurrentCommand_）为并发命令预算——长度已知后流式命令数不超过 min(split, piece 数)；而 `-x`（每主机连接上限）不在 RequestGroup 层，是在 FileEntry 挑选 URI 时按主机在途计数强制执行。RequestGroupMan 用 IndexedList 维护等待/活动两级队列，fillRequestGroupFromReserver 按 `-j` 名额提升任务，靠 requestQueueCheck 脏标记加 FillRequestGroupCommand 例程命令实现按需调度；任务以 numCommand 归零为结束判据，完成后经 PostDownloadHandler 派生新任务插到等待队列头。URISelector 分 inorder/feedback/adaptive 三种策略，反馈数据沉淀于 ServerStatMan。跨任务两类机制：校验/预分配经 RequestGroupEntry 加 SequentialPicker“停车场”串行挂起，元数据任务依赖由 BtDependency 表达。关键术语：GID、belongsTo/followedBy/following 链、DownloadResult、STATE_WAITING/STATE_ACTIVE。
