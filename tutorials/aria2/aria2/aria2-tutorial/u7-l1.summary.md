本讲是 DHT 单元首篇，自底向上讲解 Kademlia 路由表：DHTNode、DHTBucket、DHTBucketTree、DHTRoutingTable 与 DHTRegistry。DHT（BEP 5）让 BT 不依赖 tracker 也能发现 peer：节点以 160 位随机 ID 标识，XOR 距离越小即共享前缀越长；aria2 用字典序闭区间 [min,max] 加二分分裂等价实现 K 桶，每桶至多 8 个正式节点加 2 个替补缓存，只有含本地 ID 的桶可分裂，因此近处细、远处粗。DHTNode 以计数器维护好/可疑/坏三态健康度：累计 5 次查询超时判坏，15 分钟未联系即可疑，收到有效报文清零。DHTBucketTree 是叶子持桶的梳子形二叉树，findClosestKNodes 先向下后向上收集至多 8 个非坏节点且不排序。DHTRoutingTable 的 addNode 是「入桶失败→分裂→下降重试」循环；DHTRegistry 为进程级静态注册表，IPv4/IPv6 两套完全独立。路由表周期性及停机时存入 dht.dat（只存本地 ID 与好节点扁平列表，桶形状加载时确定性重建）。本讲是 u7-l2 报文与 u7-l3 任务系统的查询基础。
