本讲剖析 `--disk-cache` 写盘缓存的完整实现链条：`RequestGroupMan` 持有进程唯一的 `WrDiskCache`（设 0 时根本不创建对象，全链路以空指针退化为直写），每个在途 piece 挂一个 `WrDiskCacheEntry`，数据以按全局偏移 goff 升序的 `DataCell` 集合组织，尾部连续可原地追加，HTTP 路径预留至少 4KiB 余量吸收小数据。核心结论：容量淘汰策略是「缓存字节最大者优先、并列取最久未更新（逻辑时钟）」，`std::set` 键不可变逼出 update 的「erase→改键→insert」舞步；flush 共五个时机——容量超限、piece/segment 完成、segment 换手防 BT 交叠写、自动保存前保位图一致（保留条目）、收尾关文件（释放条目）；cell 级与 piece 级双重排序使写出按文件偏移有序。写盘失败被记错误码后由调用方「清块＋抛错」，piece 重下、哈希兜底；`getDigestWithWrCache` 实现校验免回读。代价是 BT 每块与 HTTP 小数据各引入一次额外拷贝。
