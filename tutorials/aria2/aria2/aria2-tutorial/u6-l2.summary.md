本讲剖析 BT 运行时的装配，核心模块为 BtRegistry、RequestGroup::createInitialCommand 的 BT 分支与 BtSetup。BtRegistry 是 DownloadEngine 拥有的注册表，以 GID 为键存放 BtObject「六件套」（DownloadContext、PieceStorage、PeerStorage、BtAnnounce、BtRuntime、BtProgressInfoFile），并托管 TCP/UDP 端口、LPD 接收器、UDP Tracker 客户端四个进程级槽位；按 infohash 查找是线性扫描，供被动握手、LPD、DHT 按内容反查任务。核心结论：六件套并非 BtSetup 创建，而是在 createInitialCommand 中装配并注册；任务经校验、预分配两个停车场后，由 BtFileAllocationEntry::prepareForNextAction 触发 BtSetup::setup，装配 TrackerWatcher、PeerChoke、ActivePeerConnection、SeedCheck 等种子级周期命令，并一次性完成端口绑定与 LPD 初始化，最后 setReady(true) 放行被动连接；magnet 模式裁剪部分装配。本讲还确立「进程级／种子级／peer 级」三层对象边界，peer 级对象不入注册表，并引入 bittorrent_helper 静态 peer id／peer agent 概念。
