本讲剖析 aria2 走 HTTP 代理的两种方式：GET 模式把请求行从 origin-form 改为绝对 URI，明文 http 与默认 ftp 采用，不新增任何命令；CONNECT 隧道先让代理打通到目标的裸 TCP 管道再跑原生协议，https/sftp 恒为隧道，http/ftp 可由 --proxy-method=tunnel 强制。代理地址按「协议专属选项优先于 --all-proxy」解析并受 --no-proxy（域名/CIDR）豁免，结果装入 proxyRequest，使 DNS 与 TCP 连接目标换成代理，且到代理这一跳恒为明文 HTTP。隧道由 AbstractProxyRequest/ResponseCommand 公共骨架建立：发 CONNECT、等 200，非 200 抛 EX_PROXY_CONNECTION_FAILED 走可重试出口；打通后经 getNextCommand 切回普通命令链——HTTP 侧为 HttpRequestCommand（TLS 在隧道内与目标握手），FTP/SFTP 侧为 Ftp/SftpNegotiationCommand，ConnectCommand 依 ControlChain 决定入口。代理认证头 Proxy-Authorization（凭证内嵌于代理 URI）与目标认证的 Authorization 独立并存，日志中均被脱敏为 <snip>。
