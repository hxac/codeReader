本讲拆解 aria2 与 tracker 交互的三个模块。DefaultBtAnnounce 管决策：定义 started/stopped/completed/周期性四种 announce 时机，构造含 info_hash、peer_id、left、numwant、event 等参数的请求，并消化应答；announce 间隔由三个来源动态决定——tracker 下发的 interval/min interval、用户选项 --bt-tracker-interval、零连接时强制缩短的自救机制。TrackerWatcherCommand 管调度：常驻自循环状态机，通过 AnnRequest 抽象解耦 HTTP 与 UDP 传输；HTTP announce 被伪装成用内存盘落盘的迷你 RequestGroup，完整复用 HTTP 下载命令链；AnnounceList 的 tier 轮换语义为成功者升队首、失败者降级、全部失败后冷却一个间隔重头再来。UDPTrackerClient 实现 BEP 15：CONNECT 换取 connection_id 伪会话票据（缓存一分钟），ANNOUNCE 用 transaction_id 配对应答，采用 5 秒重发/10 秒超时两段式容错；它由 DHTSetup 创建、DHTInteractionCommand 驱动并与 DHT 共享 UDP socket，按首字节是否为 d 区分报文，DHT 关闭时不可用。
