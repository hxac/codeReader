本讲精读 bin/cm.js 一个文件，它是发布流水线的数据入口。核心是 changelog()：用 git log 按时间正序拉取上个版本标签以来的完整提交信息（版本号字符串即 tag 名），再用分段正则把以大写 BREAKING:/FIX:/FEATURE: 开头的独立段落归入 {fix, feature, breaking} 三个数组，多行正文拍平成单行。该正则的灵魂是惰性量词 *? 配合前瞻断言 (?=...) 划定段落边界，[^] 实现跨行匹配；标记区分大小写、必须独立成段，写错不报错而静默丢失，因此发布前要用 cm unreleased 预览。数据入口 run() 以无 shell 的 execFileSync 把 git 输出变成 utf8 字符串，失败异常统一走 error() 出口。releaseNotes() 是纯函数，按 breaking→fix→feature 顺序渲染 Markdown、空类别省略、把 ](## 简写锚点重写为 codemirror.net 文档链接，结果拆成 head 与 body，供 doRelease 前插 CHANGELOG 及 unreleased 预览复用；版本号如何升级（bumpVersion）留给 u3-l2。
