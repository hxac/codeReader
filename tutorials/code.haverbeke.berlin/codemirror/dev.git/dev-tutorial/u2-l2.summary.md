本讲剖析 `cm build` 背后的工具链，覆盖 bin/cm.js 的 `build()` 与 `clean()`、bin/packages.js 的 `Pkg.main` 探测与 `buildPackages` 过滤、package.json 的 `prepare` 钩子与 workspaces、tsconfig.json 的 `paths` 映射。核心结论：`build()` 是纯编排层，自身不编译，把 `buildPackages` 的 35 个入口 `Pkg.main` 连同 buildhelper 的配置交给 `@marijn/buildtool`，产物落在各包 `dist/`；构建有两条触发路径——`cm install` 因 `--ignore-scripts` 抑制了 `prepare` 钩子，须在结尾显式调用 build()，普通 `npm install` 则经 `prepare` 自动触发。关键术语：`Pkg.main` 按三条规则运行时探测（唯一 .ts > index.ts > 剥 theme-/lang- 前缀同名）；`buildPackages` 是全量 36 包中 main 非空的 35 个子集（排除无 TS 入口的 legacy-modes）；`clean()` 只删各 buildPackages 的 dist 目录，与 install 更新时另清 `dist/*`、`test/*.js` 分工不同。双轨解析：npm workspaces 面向运行时、终于 dist 产物，tsconfig `paths` 面向编译期、直达 .ts 源码，其 35 条映射是 main 探测结果的静态镜像，两套机制须人工保持同步。
