本讲精读 `bin/cm.js` 的五个多仓库工作流命令：`status`、`commit`、`push`、`grep`、`run`，共同骨架是遍历全量 `packages`（36 包，含 `legacy-modes`）、用 `run()` 以 pipe 捕获各包目录的命令输出、再以字符串谓词过滤后对命中包执行动作。`status` 以与干净基线的全等比较实现「有变化才输出」；`commit` 用 `git diff` 真值判断，未跟踪文件是盲区、由 `status` 互补；`push` 用词边界正则判「领先远端」，成功静默；`grep` 按注册表收集各包 src/test 的 .ts（`legacy-modes` 特例搜 mode/），单次调用系统 grep，后缀提取正则使多点文件名落选；`run` 无过滤逐包执行、遇错即停。核心结论：这组命令把 git 文本输出当机器数据解析，以几十行轻量脚本替代 monorepo 框架。
