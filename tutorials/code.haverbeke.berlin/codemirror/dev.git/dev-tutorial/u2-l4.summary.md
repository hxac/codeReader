cm test 是纯编排层：@marijn/testtool 的 gatherTests 把 35 个可构建包的测试分成 Node 轨道（tests）与浏览器轨道（browserTests），runTests 执行双轨并把「是否有失败」的布尔映射为进程退出码 0/1，交 CI 判定。参数经手写 for 循环解析：--no-browser 只跑 Node 轨道，--grep 过滤用例，未指定浏览器时默认补 chrome；--chrome 分支因 browser/browsers 笔误会抛 ReferenceError，且帮助文本未列全参数，实现才是权威。gatherTests 的另一消费者是 startServer 的 /test/ 分支：每次请求重新收集、用 testHTML 现场生成 mocha 测试页，依赖 demo/test 下两个 git 跟踪的符号链接把 node_modules/mocha 纳入静态服务；tsconfig 的「types: mocha」注入全局类型，使测试文件免 import 直接用 describe/it。npm 的 test 与 test-node（即 test --no-browser）只是别名，追加参数必须用 -- 分隔符传给脚本。
