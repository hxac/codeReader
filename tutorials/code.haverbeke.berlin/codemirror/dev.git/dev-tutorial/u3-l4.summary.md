本讲是手册收官，从「读」工具链转为亲手扩展。核心概念「扩展点」：它不是插件 API，而是三份「数据 + 约定」——packages.js 的包名清单（core/nonCore 分组、Pkg 三规则入口探测）、cm.js 的命令映射表（新增 cm doctor 需补实现函数、cmdFn 表项与 help() 文本，并自动继承 assertInstalled 守卫）、tsconfig 的 paths 映射。关键结论：注册新包须先建目录与入口、再进清单，否则守卫令全部命令瘫痪；双轨解析中 workspaces 与 tsconfig include 通配自动生效，唯 paths 须手工维护并与 Pkg.main 探测结果对齐。最后权衡「多仓库 + 中央脚本」与单体 monorepo 的取舍：依赖联动 updateDependencyVersion 被主动停用；cm.js 依赖 rm/grep 等外部工具且默认无 shell 执行、glob 不展开，事实上假定类 Unix 环境，可移植性差。
