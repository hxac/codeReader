本讲讲透 #8936 的批量规划层：plan_transfers 复用单参数规划的 _prepare/_emit，只新增「按参数名、目标 location、origin 固定顺序收集请求、一次性调用可插拔 replica policy、逐答案校验」三步，plan_transfer 行为不变。策略经 ReplicaRequest/ReplicaAnswer 协议交互（ReplicaPart 表示沿 axis 0 的切分），location 与进程是两个命名空间，靠 source_processes/target_processes 翻译。内置三策略：first_holder、local_first_least_loaded（默认，本地优先加最少负载贪心、从不切分）、per_request。答案校验只认已验证 holder、parts 须精确平铺无缺口重叠，受 min_split_bytes 与 max_pair_checks 约束，违例抛 InvalidReplicaPolicyError。核心结论：副本一致时任意一致的计划都精确（策略只决定从哪读、不决定送达什么）；所有 rank 必须返回相同答案，由 executor 的 digest 共识执法，故成本感知策略的成本输入必须来自全员共享数据。
