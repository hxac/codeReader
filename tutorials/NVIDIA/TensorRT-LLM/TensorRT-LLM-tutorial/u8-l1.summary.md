本讲拆开 PyExecutor 单步循环里的调度黑盒，讲解 inflight batching 与两步调度。核心结论：inflight batching 的「动态」体现在每个解码迭代都重新决定 batch 成员（短请求完成即让位，GPU 不空转），区别于 static batching。TensorRT-LLM 把每步调度拆成两个串联子问题——`CapacityScheduler` 管 KV cache 块（显存容量准入，量纲是「块数」），`MicroBatchScheduler` 管单步前向 token 预算（量纲是「token 数」，含 chunked prefill 上下文分块），二者因资源量纲不同必须分开把关。`SimpleScheduler` 是默认组合器，输出契约 `SchedulerOutput`（把 context 与 generation 请求分列，因下游用不同注意力 kernel）。容量调度有三种策略：`GUARANTEED_NO_EVICT`（默认，预留块不驱逐）、`MAX_UTILIZATION`（可暂停请求换利用率）、`STATIC_BATCH`。实现有三套并经三选一装配：默认 C++ 绑定版、纯 Python 版（`use_python_scheduler=True`，真身是 `PyCapacityScheduler`+`GuaranteedNoEvictPolicy`）、V2 合并调度器（`KVCacheV2Scheduler` 把容量与 token 预算合入单循环并内联分配显存）。自定义调度器只需实现抽象方法 `schedule_request` 并在 `_util.py` 的 `create_py_executor_instance()` 装配点替换，且资源估算口径须与 `kv_cache_manager` 一致。本讲为后续讲义的请求状态机、KV cache、Decoder 与 Sampling 提供了上下文承接点。
