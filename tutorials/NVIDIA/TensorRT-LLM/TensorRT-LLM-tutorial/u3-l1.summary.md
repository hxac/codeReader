本讲把「HF 模型 → 生成 Token」全链路的前半段（API → Executor → 请求入队）落到源码，是端到端流程总览的第一讲。它拆成三个最小模块：① LLM 入口——`LLM` 采用三层继承（`LLM` → `_TorchLLM` 后端特化 → `BaseLLM` 通用流程），构造阶段经 `_build_model` 最终创建 Executor；`generate` 本质是「提交 + 等待」——`generate_async` 异步提交 future，再逐个 `result()` 阻塞实现同步语义。② Executor 抽象——`GenerationExecutor` 是 ABC，基类 `generate_async` 把零散参数打包成 `GenerationRequest` 再调抽象 `submit`；`create()` 工厂按编排方式（ray/rpc/ipc）返回 Proxy、Worker 或 Ray 执行器，对上屏蔽数部署差异。③ 请求流图——请求「身份」沿链路演变：字符串 → `prompt_token_ids` → `GenerationRequest` → C++ `tllm.Request`，翻译官是 `BaseWorker._enqueue_request`，`py_` 前缀动态属性是 Python 侧挂载的旁路通道。核心结论是「Python 调度、C++ 加速」：`engine.enqueue_request` 是分水岭，之前全是 Python 编排，之后进入 `PyExecutor` 单步循环（Scheduler/前向/Decoder/Sampling，kernel 走 C++/CUDA），细节留待 u3-l2。关键术语：`BaseLLM`/`_TorchLLM`、future（`RequestOutput`/`GenerationResult`）、`GenerationRequest`、Proxy/Worker、`submit`/`_enqueue_request`、`client_id`/`req_id` 映射、in-flight batching。
