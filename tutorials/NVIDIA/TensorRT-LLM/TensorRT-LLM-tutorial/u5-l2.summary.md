本讲解答「用户给一个目录路径，TensorRT-LLM 如何找到对应的 ForCausalLM 类」。自动发现的本质是以 HF config.json 的 architectures[0] 为钥匙，在「架构名→模型类」注册表里查表。仓库存在两套同名注册表：顶层 MODEL_MAP（在 PyTorch 后端刻意留空、已退役）与 _torch 后端的 MODEL_CLASS_MAPPING（真正在用、由装饰器填充），二者各配一个同名 AutoModelForCausalLM，不可混用——import tensorrt_llm 拿到的是顶层查空表的版本。PyTorch 后端靠 @register_auto_model 装饰器在 import 时自注册，import 即注册；装饰器可叠加，实现「一个类、多个架构别名」（如 DeepSeek-V3 同时服务 V3/V3.2/GLM-5），并支持不改源码的 out-of-tree 注册。解析入口 _resolve_class 在查表前会按多模态视觉编码器、EAGLE3 草稿、MTP 草稿等情形重写架构名，故最终实例化的类未必等于 architectures[0] 直接查到者；再经 from_config 实例化模型。
