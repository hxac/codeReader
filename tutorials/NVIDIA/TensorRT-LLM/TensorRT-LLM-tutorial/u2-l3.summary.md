本讲承接 u2-l2，回答 `from .bindings import MpiComm` 中的 `bindings` 从何而来。它拆解三个最小模块：一是 `cpp/tensorrt_llm/` 的 C++ 引擎室，按 `common`（地基）、`kernels`/`layers`（加速）、`runtime`（运行时）、`batch_manager`/`executor`（编排）、`nanobind`（对外暴露）分子系统；二是 nanobind 绑定，顶层 `CMakeLists.txt` 先把子系统编成静态库，用 `WHOLE_ARCHIVE` 聚合成 `libtensorrt_llm.so`，再由 `nanobind_add_module` 编译出单一扩展模块 `bindings`，并通过 `NB_MODULE` 组织成分层命名空间（顶层公共类、`executor`、`internal.{runtime,batch_manager,...}`），Python 侧以 `RTLD_GLOBAL` 提升共享库符号供 NIXL/UCX 解析；三是共享核心组件。核心结论即「Python 调度、C++ 加速」：Scheduler、KVCacheManager 虽用 C++ 实现性能，但接口定义在 Python（`BaseResourceManager` 的 `prepare/update/free_resources` 三段式），可纯 Python 自定义。关键事实：C++ 不暴露可执行 Executor 类，真正的单步循环由 Python 的 `PyExecutor` 驱动。引入术语：nanobind、bindings、WHOLE_ARCHIVE、RTLD_GLOBAL、BaseResourceManager、PyExecutor，供 u3（端到端流程）、u7（KV Cache）、u8（调度）承接。
