本讲讲解 trtllm-serve 如何把 LLM 引擎包装成 OpenAI 兼容 HTTP 服务，分四层。CLI 层：trtllm-serve 为 click 命令组，DefaultGroup 使裸命令默认走 serve；get_llm_args 用 is_non_default_or_required 过滤参数，避免 CLI 默认值覆盖模型默认值；launch_server 先绑 socket 再加载模型，按 backend 构造 PyTorchLLM 或 AutoDeployLLM，包以 OpenAIServer 后起 uvicorn。服务层：OpenAIServer 是普通聚合服务的 FastAPI 容器，/v1/chat/completions 据 use_harmony 在 openai_chat 与 chat_harmony 间二选一，端点把请求翻译成 LLM.generate_async。token 化层：chat_tokenization.py 集中处理 harmony（HarmonyAdapter，GPT-OSS 专用，detokenize=False）与外部 router 的 token 化，标准路径因异步多模态仍用 async_apply_chat_template。后处理层：tool parser 是文本与 tool_calls 间的桥梁，strict 工具用结构化标签约束解码，生成后用 detect_and_parse 或 parse_streaming_increment 解析并把 finish_reason 改写为 tool_calls。关键区分：OpenAIServer 是聚合服务具体类，OpenAIService 是分离式服务的抽象契约，二者勿混，后者留待 u11-l2。
