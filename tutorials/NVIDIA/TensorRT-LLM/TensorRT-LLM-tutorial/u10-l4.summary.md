本讲打开 `u3-l3` 的「CUDA Graph 回放」路径，讲清两套 CUDA Graph 机制与建在其上的编译流水线。三个最小模块：(1) **生成期 CUDA Graph**（`cuda_graph_runner`）服务纯解码，用 `KeyType=(batch_size, draft_len, ...)` 区分多种前向路径分别录图，捕获集中在 warmup 的 `allow_capture()` 上下文，运行期见新 key 回退 eager 而非当场捕获，以避免地址失效与毛刺；(2) **piecewise（分片）CUDA Graph** 建在 `torch.compile` 的 `fullgraph` 追踪之上，自定义后端 `Backend` 在 ATen IR 上做融合 pass 与 re-inplace，再按一组 in-place attention 边界算子把图切段，attention 走 eager、其余段按 `capture_num_tokens` 分桶录图，运行期靠**强制 padding 到下一档**驯服动态形状；(3) **auto multi-stream** 调度器因 `torch.compile` 会丢弃用户 stream 而存在，它建 DAG、算关键路径、把流控制算子直接插进图，开启 piecewise 时多流下沉到每个可捕获子图内部执行。核心结论：piecewise 要求模型所有算子都能被 `torch.compile` 识别，故 attention/MoE 须包成 in-place「黑盒」自定义算子，呼应 `u10-l1`/`u10-l2` 的纯函数约定与 fake kernel。关键术语：`KeyType`、`allow_capture`、生成期图、piecewise、`capture_num_tokens`、强制 padding、ATen IR、自定义后端 `Backend`、auto multi-stream、`graph_pool_handle`、`CudaGraphConfig`/`TorchCompileConfig`。
