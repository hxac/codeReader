本讲为高级篇收尾，从「读源码」转向「写贡献」。测试分三层：单元测试位于 tests/unittest，merge-request 流水线全量跑、无需 GPU；集成测试位于 tests/integration/defs，需 GPU 与真实模型权重、按硬件 YAML 登记；API 稳定性测试位于 api_stability，比对公开签名快照以守护接口契约。CI 须经 PR 评论 /bot run 触发，分 merge-request（pre_merge）与 post-merge（跨硬件）两条流水线；scripts/test_to_stage_mapping.py 解析 Groovy 与 YAML 清单，建立测试名与 Jenkins stage 的双向映射，正查经 yml、Post-Merge 字样、backend 关键词三道闸过滤；已知失败登记 waives.txt 豁免而非删除。贡献合规须：git commit -s 做 DCO 签名、采用 [追踪号][类型] PR 标题、维护 NVIDIA 版权头、过 pre-commit 双组 lint（legacy 基线 gated）、改 LLM args 时重跑 golden manifest；改动受保护 API 会 fail 稳定性测试，需更新参考快照并标注 api-compatible/api-breaking，再请 code owner 审查。
