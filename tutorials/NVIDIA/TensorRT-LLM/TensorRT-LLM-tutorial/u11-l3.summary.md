本讲围绕「能跑多快」与「该用哪套参数」两个部署问题，讲解 `trtllm-bench` 基准工具与配置数据库两个配套机制。`trtllm-bench` 是基于 click 的命令组（throughput/latency/prepare-dataset/visual-gen），全局选项经 `BenchmarkEnvironment` 通过 `ctx.obj` 传入子命令；它与 `trtllm-serve` 构造的是同一个 `LLM`，故 bench 测得的数字对 serve 有参考价值。吞吐基准是一条「翻译链」：CLI 选项 → `GeneralExecSettings` → 启发式 `get_settings` 算 `max_batch_size`/`max_num_tokens` → `RuntimeConfig.get_llm_args` → `LLM` → 异步 `async_benchmark`（由信号量控制并发度）→ 报告。关键概念包括：Pareto 前沿、吞吐-延迟权衡、工作负载键（model/gpu/卡数/ISL/OSL/并发度）。核心结论是 CLI 与 YAML 优先级全仓库统一——用户显式敲的键（经 `collect_explicit_cli_keys` 与 `_BENCH_CLICK_TO_LLM_ARG` 翻译）由共享的 `update_llm_args_with_extra_options` 仲裁覆盖 YAML，这是「一份 YAML 既能 bench 测又能 serve 部署」的根本原因。配置数据库 `examples/configs/database/` 用 `Recipe`/`RecipeList` 给 `lookup.yaml`（204 条）做强校验，每条配方对应一份 `TorchLlmArgs` YAML，同一工作负载键下多份配置用 `profile`（latency/balanced/throughput）区分；并发度是吞吐基准第一旋钮，warmup 不可省。
