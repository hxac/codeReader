本讲聚焦单个 `LlmRequest` 在 `PyExecutor` 中的「一生」，覆盖四个最小模块：**请求状态机**、**等待队列**、**序列槽管理器**、**ADP 路由器**。核心结论：请求是状态机，在 `CONTEXT_INIT → GENERATION_IN_PROGRESS → GENERATION_TO_COMPLETE → GENERATION_COMPLETE` 间线性迁移；C++ 端 `LlmRequestState` 枚举的数值被刻意排序，使「可调度状态」恰好构成连续区间 `[10, 14)`，于是「能否调度」退化为两次整数比较（`_can_be_scheduled`），新增状态须谨慎安排数值。状态不由请求自改，而由 `PyExecutor` 在单步循环固定节点集中搬动（`_update_request_states_tp` 等），分离式服务靠额外 `DISAGG_*` 状态表达「等 KV/传 KV/KV 到齐」。关键术语：序列槽（sequence slot，身份编号，每请求恒需 1 个）、`SeqSlotManager`（`BaseResourceManager` 实现，池空抛 `NoFreeSlotsError`，`prepare/free` 须成对）、`WaitingQueue`（FCFS 或「负优先级最小堆 + 双计数器」，`prepend_*` 保排队位置）、ADP Router（allgather 共识 + 各 rank 本地跑确定性纯函数 `route_requests`，结果天然一致免广播，含负载均衡、KV 缓存感知、对话亲和三种策略）。下一讲 u8-l3 接 Decoder 与 Sampling。
