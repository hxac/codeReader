本讲把 u7-l1 的「KV Cache 专用」三段式生命周期泛化成全资源通用：`BaseResourceManager` 抽象基类用两个抽象**容量接口**（`get_max_resource_count`/`get_needed_resource_to_completion`，供调度器准入控制）与五个带默认实现的**生命周期方法**（prepare/update/free…）统一所有随请求生灭的资源。`ResourceManager` 是一个用 `OrderedDict` 装多个异构资源（KVCacheManager、SeqSlotManager、PeftCacheManager 等）的有序容器，靠正序 prepare、逆序 free、特判 KV_CACHE_MANAGER 多传参的 update 来**扇出**，使主循环与具体资源解耦。本讲进一步区分两条易混的 KV 搬运路径：**KV Cache Connector** 是借鉴 vLLM 的可插拔缓存插件，采用 worker/scheduler 双 ABC + 粘合层 `KvCacheConnectorManager`，scheduler 仅在 rank 0 决策并广播，异步完成以「所有 rank 交集」判定；**KV Cache Transceiver** 则是分离式服务的专用传输器（NIXL/UCX/MPI/Mooncake），与 KVCacheManager 紧耦合，由 PyExecutor 直接驱动 prefill→decode 跨节点收发。二者互不替代，可在 decode 节点串联，非分离式部署时均为 None。
