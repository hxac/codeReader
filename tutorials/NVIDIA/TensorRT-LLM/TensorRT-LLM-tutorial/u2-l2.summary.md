本讲深入 `tensorrt_llm/` Python 包，回答「`import` 时发生什么、公共对象从哪来、版本号如何暴露」三问。核心结论：`import tensorrt_llm` 有副作用，`__init__.py` 依次做平台预加载（Windows DLL 路径、Linux 预加载 `libpython`）、接管 vendored `triton_kernels`、必须先 `import torch`（C++ `.so` 依赖 `libc10.so`），再 re-export 符号并调用 `_common.py` 的 `_init()`；`_init()` 用 `_inited` 守卫保证幂等，以 `RTLD_GLOBAL` 提升 `libtensorrt_llm.so` 供 NIXL/UCX 解析，可用 `TRT_LLM_NO_LIB_INIT=1` 跳过。引入的关键术语：`__all__` 作为顶层公共 API 契约（仅导出 `LLM`/`SamplingParams`/`Mapping`/`TorchLlmArgs`/`__version__` 等常用项）；`llmapi/__init__.py` 是「聚合门面」，从 `llm_args.py` 等 re-export 完整配置族（如 `SchedulerConfig`），范围大于顶层；`tllme`（`tensorrt_llm.bindings.executor`）即 C++ 运行时投影。`SamplingParams` 为 `@dataclass` 翻译层，把字段打包成 `tllme.SamplingConfig`/`OutputConfig`，有比 C++ 更严格的 `_validate()`（拒绝贪心+`best_of>1`）及集中的贪心判定静态方法。`__version__` 由 `version.py` 单一来源定义。
