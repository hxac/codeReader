本讲拆开 PyTorch 后端的 custom_ops 统一门面：模型代码从不直接调 GPU kernel，而统一走 torch.ops.trtllm.<name>。它把四种内核来源（C++/CUDA、Triton、CuTe DSL、cuTile，后两者靠 availability flag 守卫）包装成同一调用，使每个 op 成为 torch.compile/CUDA Graph 可见的算子边界，前提是注册 fake/meta 实现并声明 mutates_args。新增内核须产出四产物 kernel/binding/integration/tests；注册遵循「import 即注册」，C++ op 的 fake 集中在 _register_fake()、由 _init() 加载 libth_common.so 后调用。torch_custom_ops.py 的 op 分三种形态：纯 Python op（包 Triton 内核）、TunableRunner+AutoTuner 外壳（运行期自动调优）、多后端统一路由器（如 nvfp4_gemm 按量化方案与 SM 代际选 backend）。还须区分两类 triton：散落各处的自写 @triton.jit 单文件内核，与仓库根目录 vendored 自上游的第三方 triton_kernels/ 库（禁改、不挂 trtllm 命名空间）。选型原则为优先复用、能 Python 就别上 C++、热点 op 用 fast_custom_op 省 dispatcher 开销。
