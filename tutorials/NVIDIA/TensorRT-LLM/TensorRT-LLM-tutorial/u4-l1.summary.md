本讲讲解 TensorRT-LLM 的运行时配置中枢 `TorchLlmArgs`——一个巨型 Pydantic 对象，贯彻「一次配置、全程生效」。配置分两层继承：后端无关的公共基类 `BaseLlmArgs` 叠加 PyTorch 专属字段得到 `TorchLlmArgs`，别名 `LlmArgs = TorchLlmArgs`（因 PyTorch 是默认后端），AutoDeploy 有独立子类，由 `LLM.__init__` 按 `backend` 派发。核心设计是「扁平与嵌套共存」：高频旋钮（`tensor_parallel_size` 等）摊平到顶层，成族参数打包成子配置。严格性来自 `StrictBaseModel` 的 `extra="forbid"`（拼写错误立即报错）外加 kwargs 白名单。关键模式包括：`model_validator(mode="after")` 把扁平并行字段聚合进私有 `_parallel_config` 并以只读 property 暴露（`world_size = tp*pp*cp`）；自定义 `Field` 包装器标注字段 `status`（成熟度）与 `telemetry`；`speculative_config` 用判别联合实现多态。四大子配置族——`_ParallelConfig`（经 `to_mapping()` 产出 `Mapping`）、`SchedulerConfig`（容量策略 `GUARANTEED_NO_EVICT`、prefix-aware）、`KvCacheConfig`（`free_gpu_memory_fraction` 默认 0.9、`max_tokens`）、`CudaGraphConfig`——中后两者通过 `PybindMirror`/`mirror_pybind_fields` 镜像 C++ 结构体并强制字段同步。需区分调度层 `max_num_tokens`（单步算力预算）与 KV cache `max_tokens`（显存容量）。修改配置须遵循 `CODING_GUIDELINES.md` 并重跑 golden manifest。
