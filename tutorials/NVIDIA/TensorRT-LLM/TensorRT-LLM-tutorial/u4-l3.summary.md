本讲解析 PyTorch 后端加载期到前向期之间的配置桥梁。关键澄清：项目里存在两个同名 `PretrainedConfig`——HF `transformers` 的（PyTorch 后端用，从 `config.json` 解析模型结构）与本仓库旧版 `modeling_utils` 的（legacy 引擎流，其 `MODEL_MAP` 在 PyTorch 后端为空），二者不通用。`QuantConfig`/`LayerQuantConfig` 是量化的纯描述层，分别描述全局统一方案与逐层混合精度，用 `QuantAlgo` 字符串枚举经 `quant_mode` 翻译为底层 C++ `QuantMode` 位标志。核心结论：`ModelConfig`（带泛型 `Generic[TConfig]`、绑定 HF 配置）是运行时包裹层，把 HF 配置与并行拓扑 `Mapping`、注意力/MoE 后端、量化、CUDA Graph 等「部署期确定、checkpoint 不记录」的开关打包，由 `from_pretrained()` 创建后立即冻结供前向只读。`SpeculativeDecodingMode` 用 `IntFlag` 按位组合表达投机解码模式，须与 C++ 头文件同步。
