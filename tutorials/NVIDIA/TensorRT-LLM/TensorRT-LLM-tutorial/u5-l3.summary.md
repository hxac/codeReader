本讲把 u5-l1（三段式架构范式）与 u5-l2（自动发现与注册）串成一条可落地的 PyTorch 后端模型 onboarding 四步流程：配置 → 模型定义 → 权重加载 → 注册。

第一步配置直接复用 HuggingFace 的 `PretrainedConfig` 子类，`config.json` 的 `architectures[0]` 是贯穿全流程的「钥匙」，必须与注册名严格一致。第二步模型定义要写四个类（`Attention`/`DecoderLayer`/`DecoderModel`/`DecoderModelForCausalLM`），心法是「复用多、覆盖少」——基类已封装 lm head、logits、流水线切分，开发者只写模型特有逻辑，并须遵守 attn_metadata 契约与 packed 输入约定（第一维是拍平的 token 总数，非 `[batch, seq]`）。第三步权重加载解决 checkpoint 张量名与模块树名对不上的问题，引入融合层（qkv_proj / gate_up_proj）与 GQA 的 KV 复制概念；基类提供默认 `load_weights` 已能自动处理常见融合，仅当 checkpoint 名非标准（如前缀差异、MLA、FP4 重排）时才需覆盖，并通过 `ConsumableWeightsDict.mark_consumed` 实现边加载边释放以降低峰值显存。第四步注册只需一个 `@register_auto_model` 装饰器，副作用是「import 即注册」，由此分出 in-tree（改 `__init__.py`、用户无感）与 out-of-tree（脚本显式 import、不改源码）两种方式；装饰器可叠加实现多别名注册（如 DeepSeekV3 服务 V3/V3.2/GLM-5）。AutoDeploy 复用同一批模型定义但走图变换路径，留待 u12-l1。
