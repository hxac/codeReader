本讲把 u1-l1 的「HF 模型 → LLM API → Executor → Scheduler → 前向 → Sampling → 生成 Token」高空流程图落到地面，用两个入口真正跑通模型。它覆盖三个最小模块：一是离线 LLM API——构造 `LLM(model=...)`、配 `SamplingParams(temperature, top_p)`、调 `generate(prompts)` 拿 `RequestOutput`；二是在线 `trtllm-serve` 命令——经 `setup.py` 的 console_scripts 注册到 `serve.py:main`（DefaultGroup 默认走 serve 子命令），再 `serve()` → `get_llm_args()` → `launch_server()` 构造 `LLM` 并包一层 `OpenAIServer`；三是 OpenAI 协议兼容——`OpenAIServer.register_routes` 注册 `/v1/chat/completions`、`/v1/completions`、`/v1/models` 等端点，任何 OpenAI 客户端可直接连。核心结论是「殊途同归」：离线和在线两条入口最终都构造同一个 `LLM` 类（`serve.py` 的 `llm = PyTorchLLM(**llm_args)` 即 `tensorrt_llm.llmapi.llm.LLM`），`trtllm-serve` 只是额外套了 HTTP 服务壳。关键术语：`LLM`/`SamplingParams`/`RequestOutput`、tokenizer/detokenizer 由 LLM 实例托管（字符串进字符串出）、chat template（聊天场景把结构化 messages 拼成纯文本）、`--backend`（pytorch 默认 / _autodeploy beta）开关，以及 `Executor/Scheduler/前向/Sampling` 这条仍作为黑盒的内部链路（留待后续讲义拆解）。
