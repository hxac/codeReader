本讲聚焦 PyTorch 后端的显存资源 KV Cache，覆盖三个模块。其一，分页 KV Cache：借鉴虚拟内存分页，把显存池切成等长 block（默认 32 token/块），以页表把逻辑 token 位置映射到物理 block，既消除碎片又支持前缀共享；block 形状含 kv_factor 维，标准 attention 下为 2、MLA 下为 1。其二，KVCacheManager 是 BaseResourceManager 的一种实现，对 PyExecutor 暴露三段式生命周期接口 prepare_resources/update_resources/free_resources，对 CapacityScheduler 暴露容量接口（get_max_resource_count / get_needed_resource_to_completion），对注意力后端暴露读取接口 get_buffers / get_batch_cache_indices。其三，两套实现：V1 为 Python 适配器加 C++ 绑定，分配直接调 add_sequence_batch / add_token；V2 为 Python 适配器加纯 Python（可 mypyc 编译）运行时，支持 GPU/Host/Disk 多级缓存、radix tree 前缀共享与 suspend/resume 换页，分配由专用 KVCacheV2Scheduler 驱动，其容量接口目前为桩。
