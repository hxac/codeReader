本讲是「仓库地图课」，承接 u1 的项目定位，解决「东西放在哪」。它将仓库视作 monorepo，给出三大核心结论。

其一，顶层目录速查表：主体代码是 `tensorrt_llm/`（Python 调度、API、serve、CLI）与 `cpp/`（C++/CUDA 加速、kernel、运行时、nanobind 绑定）；外围是 `examples/`、`docs/`、`tests/`；地基是 `scripts/`（手动工具脚本）、`jenkins/`（CI Groovy 流水线）、`docker/`。其中 `tensorrt_llm/_torch/` 是 PyTorch 后端的心脏，含 `pyexecutor/`、`models/`、`modules/`、`attention_backend/` 等，后续进阶讲义的主战场。引入的关键术语包括 monorepo、Sphinx/toctree、Pydantic，以及「主体—加速—外围—地基」的分层记忆口诀。

其二，`examples/` 沿双轴组织：「按特性」（如 `llm-api/`、`serve/`、`configs/`、`quantization/`、`auto_deploy/`）与「按模型」（`models/core/` 下各模型 README）。关键提醒：旧的 `convert_checkpoint.py → trtllm-build → run.py` 已为 legacy，新项目应走 `trtllm-serve` 或 LLM API。`configs/` 区分 `curated/`（快速上手）与 `database/`（Pareto 优化配置库）。

其三，`docs/source/index.rst` 用 toctree 串联全站，`deployment-guide/` 提供「配方选择器」与按模型的部署文档，是「按模型查部署」的固定入口。治理类文件（`AGENTS.md`、`CODING_GUIDELINES.md`、`CONTRIBUTING.md`）为改码前必读。
