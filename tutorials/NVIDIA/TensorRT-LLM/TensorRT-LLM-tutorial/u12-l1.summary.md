本讲介绍 AutoDeploy 后端：它不是新引擎，而是把任意 PyTorch 模型自动编译成高效 `ModelEngine` 的编译器，产出的 `ADEngine` 仍跑在共享的 `PyExecutor` 单步循环上，复用 in-flight batching、调度与采样。核心定位在于「自动优化」与默认 PyTorch 后端「人工接线」的范式差异，shim 极薄——`LLM` 继承 `_TorchLLM`，仅强制 `backend="_autodeploy"` 并接管 `_build_model`，派发分叉点在 `llmapi/llm.py`。三段式工作流为：`torch.export` 抽 FX 图 → 图变换流水线优化 → 编译后端落地。图变换采用「注册表 + 阶段枚举」架构：`@TransformRegistry.register(name)` 自注册，`Stages` 枚举（FACTORY→EXPORT→…→COMPILE）定执行序，`InferenceOptimizer` 按阶段排序，`BaseTransform.__call__` 是统一清理/统计/dump 外壳，子类只实现 `_apply`，新增优化只需一个类加装饰器加一行 YAML（`default.yaml`）。`fuse_silu_mul` 是典型 pass，在 `post_load_fusion` 阶段把「silu(narrow)*narrow」替换成单个融合算子。编译阶段经独立的 `CompileBackendRegistry` 选后端，默认 `torch-cudagraph` 采用 dual-mode：整图 CUDA Graph 管 decode、piecewise 分片管 prefill/mixed，由 `DualModeCapturedGraph` 按 `batch_info` 分流；分片在动态算子边界切图，静态段包进 `ADPiecewiseRunner` 三态机（warmup/capture/replay），按 num_tokens 分桶捕获。
