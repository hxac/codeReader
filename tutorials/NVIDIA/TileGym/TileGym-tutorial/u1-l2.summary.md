本讲讲解在本地安装并跑通 TileGym 的方法，含四个最小模块。torch/triton 因与硬件及 CUDA 版本强相关，未被列为固定依赖，需用 cu130 索引手动安装，导入时由 `_check_torch_dependencies()` 兜底校验。安装方式分三种：PyPI（`tilegym[tileiras]`，供使用）、源码（看代码）、editable（`pip install -e .`，改 TileGym 代码即改即生效），运行时依赖由 `setup.py` 从 `requirements.txt` 动态解析。默认后端 cuTile 来自独立的 `cuda-tile`(≥1.3.0) DSL 包，并依赖运行时编译器 tileiras 将 `@ct.kernel` 编译为 GPU 代码，`[tileiras]` extra 会把 tileiras 捆绑进环境。`selector.py` 以不同策略探测四个后端的可用性：cuTile 看 `import cuda.tile`、triton 恒为可用（nvtriton 需 `ENABLE_TILE=1`）、tilecpp 要求 nvcc≥13.3 且检查被延迟缓存、cutile-rs 看 `cargo` 或预编译 `.so`；用 `tilegym.get_available_backends()` 可检验哪些后端真正可用，结果随机器工具链而异。
