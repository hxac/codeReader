本讲为「多后端实现」单元首篇，介绍 tilecpp（CUDA Tile C++）后端：以 C++ 模板替代 cuTile 的 Python DSL、以离线 nvcc 替代运行时 tileiras，复用同一套分发机制实现同一算子。

引入的关键术语：CUDA Tile C++（`__tile_global__`、`cuda::tiles` 命名空间）、模板与显式模板实例化、cubin、修饰名（mangled name）、block=1 启动模型，以及 nvcc ≥ 13.3 的版本要求。

四个核心模块：一、成对文件组织，`.cuh` 内核源配 `.py` 包装，用 `kernel_name` 把每个内核绑成 `TileCppKernel` 对象；二、`TileCppKernel` 引擎，`get_kernel` 串起「显式实例化→nvcc 编译→cubin 缓存→修饰名查找→加载」，`launch` 取 torch stream 并以 `block=1` 启动，并行度全靠 grid；三、可用性探测分「廉价预筛（import 时无子进程）+ 昂贵实检（`@functools.cache` 全程一次）」，cubin 经两级缓存、文件锁与原子写保证多进程共享；四、后端无关注册，tilecpp 与 cutile 均用 `@register_impl` 挂入同一算子名，注册受 `is_backend_available` 门控、作为导入副作用发生。

核心结论：算子名是全局键、后端是子键，dispatch 只按当前后端查表，不关心实现语言；是否实现反向属逐后端能力（tilecpp softmax 提供 forward+backward，当前 cuTile 版仅 forward），对调用方透明。
