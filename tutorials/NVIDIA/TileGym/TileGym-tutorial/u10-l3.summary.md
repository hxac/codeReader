本讲介绍 TileGym 中自包含的 `julia/` 子项目：它用独立的 cuTile.jl 前端，把 add / matmul / softmax 内核 lowering 到与 Python cuTile 相同的 Tile IR，证明 tile 编程模型可跨宿主语言复用；该子项目不参与 Python 侧 `@dispatch` / `_REGISTRY` 分发，独立用标准库 Test 跑测试。核心结论是「编程模型同构、语法外壳不同」：内核仍以 `ct.bid`、`ct.load` / `ct.gather`、`ct.launch` 搬运与启动，但类型转换改用 `convert`、逐元素运算必须点号广播、occupancy 写在函数体内宏、编译期常量在调用点用 `ct.Constant` 标注、主机函数须显式 `CUDA.synchronize()`。迁移时最易出错的是三类差异：索引约定按原语分两套——`bid`、`load` 锚点、列块循环跟随 Julia 1-based，而 `ct.arange` 偏移、gather 索引数组、`_swizzle_2d` 沿用 0-based（matmul 的 `bid-1 → swizzle → +1` 是典型范例）；内存布局由行主序变列主序，softmax 对「行」归约的物理访存连续性两侧相反，但 `ct.load` 抽象掉布局故写法不变；启动签名与 autograd（Julia 侧仅前向 in-place、无反向封装）亦不同。依赖以 `Project.toml` / `Manifest.toml` 配 `Pkg.instantiate()`，测试用 `include` 直接包含内核脚本、`@test a ≈ b atol/rtol` 对 CPU 参考逐行比较，比 Python 侧更「裸」。引入的关键术语：cuTile.jl、Tile IR、TileArray、1-based、列主序、点号广播、online softmax（m/l 流式修正）。
