本讲是 cuTile 内核编程模型入门，讲解一个 cuTile 内核的整体骨架，不涉及数据搬运原语与启动细节（留待 u3-l2、u3-l3）。

核心结论：`@ct.kernel` 装饰器把 Python 函数交给运行时编译器 `tileiras` JIT 成 GPU 代码，再由 `ct.launch` 启动；函数体用 cuTile DSL 构造 Tile IR，而非由 Python 解释器执行。内核签名分两类参数——张量（运行期数据指针）与 `ConstInt`（即 `ct.Constant[int]`，编译期常量，会被「烤进」特化内核，使 `ct.arange` 能精确分配瓦片）。

引入的关键术语：`tileiras`、Tile IR、`ConstInt`、瓦片（tile）、block/program、`ct.bid(0)`/`ct.num_blocks(0)`（对应 blockIdx.x/gridDim.x）。

两种调度对照：silu 与 multi-wave softmax 采用「一行一块」（`row_idx = bid`）；basic softmax 采用 `for row_idx in range(pid, N_ROWS, num_programs)` 的 grid-stride 循环，即静态持久化调度——块数 `num_programs` 通常小于行数，每个块跨步处理多行并复用资源。`occupancy` 是编译期提示，launch 用 `num_programs = min(NUM_SM * occupancy, n_rows)` 决定 grid 大小，装饰器系数与 launch 系数须保持一致。
