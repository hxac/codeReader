本讲义给出 TileGym 仓库目录地图。顶层为「主包 + 辅助子项目」布局：`src/tilegym` 是被 import 的核心库，`tests`/`modeling`/`julia`/`skills` 分别承载测试、端到端落地示例、Julia 跨语言实验与技能包。`src/tilegym` 内分四区：总入口 `__init__.py`（依赖检查与后端初始化）、后端管理 `backend/`（`selector.py` 探测可用性、`dispatcher.py` 管理注册表与 `dispatch`/`register_impl`）、算子区 `ops/`、生态区（`suites`/`transformers`/`kernel_inventory`）。核心分层是：统一接口（`ops.py` 中带 `@dispatch`、仅抛 `NotImplementedError` 的 stub/门面）在 `ops/` 顶层，四个后端实现在 `ops/<后端>/` 各一份，形态各异——cuTile 单 `.py`、tilecpp「`.cuh`+`.py`」成对、triton 仅子集作兜底（`fallback_backend`）、cutile-rs「一 op 一 Rust 目录 + Cargo crate」。能否加载由 `is_backend_available` 决定，测试目录镜像源码结构。后续讲义将深入分发注册机制与 cuTile 内核写法。
