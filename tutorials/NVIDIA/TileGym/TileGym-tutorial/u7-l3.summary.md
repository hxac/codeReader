本讲讲解 cutile-rs 后端的四个最小模块。一、用 Rust（cutile crate）写 GPU 内核，所有算子编译进单个 cdylib libcutile_kernels.so，crate 根以 mod+include! 聚合各算子的 kernel.rs/ffi.rs。二、Python 经 cffi ABI 模式跨界：cdef 声明 C 签名，以 #[repr(C)] 的 TensorDesc 搬运张量，Rust 端用 ManuallyDrop 的 borrow_tensor 借用、绝不释放 PyTorch 显存。三、.so 按需 autobuild：源码过期才 cargo build，文件锁内复检防并发重复编译；is_cutile_rs_available 用宽松探测（cargo 在 PATH 或现成 .so 即可，重校验推迟到 dispatch）。四、自动调优沿用 tune-once/cache/launch 模式，但改用 CUPTI（torch.profiler）而非 cuda.Event 计时，以剔除 JIT/FFI 开销，由此引出铁律：kernel_fn 内输出只能用 torch.empty。贯穿结论：算子名是全局键、后端是子键、实现语言无关，注册受 is_backend_available 门控，且 cutile-rs 当前为仅前向后端。
