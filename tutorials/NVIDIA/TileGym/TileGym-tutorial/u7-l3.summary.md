本讲介绍 cutile-rs 后端——用 Rust 编写 GPU 内核、编译成单一 cdylib（`libcutile_kernels.so`），再经 cffi 以 C-ABI 跨界调用。核心模块有四：crate/cdylib（crate 根用 `mod + include!` 聚合各算子的 `kernel.rs`/`ffi.rs`，一次 cargo build 编完所有内核）；cffi/TensorDesc（`#[repr(C)]` 结构体与 Python `_TENSORDESC_CDEF` 逐字段对齐作为边界契约，Rust 用 `ManuallyDrop` 的 `borrow_tensor` 借用显存、绝不释放，本轮新增 NVFP4 dtype 码 6/7）；autobuild 与可用性探测（`.so` 按需构建，文件锁内复检防冗余编译，本轮把管线参数化为 `crate_dir`/`src_roots`/`so_name` 支持 suite 自带内核 crate，`src_roots` 须含 `ops/cutile_rs/` 以感知共享 `ffi_util.rs` 改动，探测用宽松策略把重校验推迟到 dispatch）；CUPTI autotune（沿用 tune-once/cache/launch 模式但用 `torch.profiler` 而非 `cuda.Event` 测纯 GPU 时间，由此引出铁律：`kernel_fn` 内输出分配只能用 `torch.empty`，禁用 clone/zeros 等会启动 GPU 内核、制造幽灵差距的操作）。贯穿结论是：算子名是全局键、后端是子键、实现语言无关；cutile-rs 当前仅前向，覆盖 matmul/bmm/silu_and_mul/swiglu/attention_sink。
