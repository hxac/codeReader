本讲介绍 TileGym 的 Suites（套件）扩展机制：如何在不污染核心接口的前提下成体系接入外部内核库（Liger/FlashInfer/Unsloth）的算子。核心结论是 suites = 复用核心分发机制 + 命名空间前缀——带点号前缀的「命名空间算子名」（如 liger.cross_entropy、flashinfer.gemm.xxx）对 dispatcher 仅是普通字典键，点号不被解析、无任何特判分支。

每个 suite 为固定两层结构：ops.py 用 `@dispatch` 声明带前缀 stub（统一接口），cutile/ 目录下一算子一文件用 `@register_impl` 挂实现，注册靠「导入副作用」触发、受 `is_backend_available` 门控。liger 是最活跃的训练向套件，覆盖训练损失、归一化、激活等族，损失算子多带 autograd Function。

suite 与核心 ops 机制同构（共用 `_REGISTRY`、`@dispatch`、`register_impl`、wrapper 查表），但组织分离：置于 suites/ 子树、须显式 import 才加载（import tilegym 不会自动加载）、stub 多不设 fallback_backend（缺失即报错）。
