本讲针对内核「算错、编译失败、跑得慢」三类问题，覆盖调试、测试与性能剖析三大工具链。调试上，`dump_ir()` 把 `DumpIRInstrument` 挂进 `PassContext`，将每个 Pass 前后的 Tilus IR（落 `ir/`）与 Hidet IR（落 `module/`）逐帧落盘，用于追踪布局推理、降级、死代码消除等环节；`disable_ptxas_opt` 让 ptxas 以 `-O0` 运行，得到与源码逐行对应的可读 PTX。关键结论：缓存键只含 IR 文本与选项、不含 emitter 输出，故改 emitter 后必须手动删 `programs/<hash>/` 才能强制重编。测试上引入 compile-only 模式——当前 GPU 不支持目标架构时，`requires` 装饰器用猴子补丁把 `__call__` 改写为「编译全部调度并抛 `_CompileOnlyDone` 哨兵短路」，编译通过即算测试通过。剖析上介绍 `ncu_run`（内核级，自带诊断 rule）、`nsys_run`（系统级时间线）、`sanitizer_run`（compute-sanitizer 内存检查），三者均以「子进程 + JSON 参数」重跑用户函数，故函数须写在 `.py` 文件内、参数须可序列化；`-lineinfo` 默认开启以支持源码关联，`debug_block` 类属性可让指定线程块在运行时打印指令。
