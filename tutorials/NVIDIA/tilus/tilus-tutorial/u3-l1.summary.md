本讲义从编译器内部视角总览 Tilus 的主编排函数 `build_program`（位于 `drivers.py`），把一段 `__call__` 代码到可执行 `.so` 的过程拆为六阶段：**校验 → 高层优化（Tilus IR）→ 降级 → 底层优化（Hidet IR）→ 代码生成 → 编译**。核心结论有三：其一，优化分两层——高层 `optimize_program`/`get_default_passes()` 面向张量、布局与指令，底层 `optimize_ir_module` 面向标量、循环与 CUDA launch，二者共用「Pass + Instrument（仪器）」框架，仪器只观察不改动 IR。其二，关键术语包括 Tilus IR（高层、`Program/Function/Stmt/Instruction/Tensor` 骨架）、Hidet IR（底层、贴近 CUDA C）、Pass（变换遍）、降级（lowering，由 `generate_ir_module` 完成）、缓存目录 `programs/<12位摘要>/`。其三，缓存键 = `sha256(options_text ‖ str(prog))` 前 12 位，**不含 codegen/emitter 输出**，故改 emitter 后必须手动删缓存；`compiled_program_exists` 以 `lib.so`+`program.txt`+`options.txt` 三件套判完成，配合 `FileLock` 双重检查避免多进程重复编译。`debug.dump_ir` 经 `DumpIRInstrument`/`SaveIRInstrument` 将各 Pass 后 IR 落到 `ir/` 与 `module/ir/`，是观察全链路的主要工具。
