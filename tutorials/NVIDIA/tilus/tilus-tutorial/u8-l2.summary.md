本讲承接 u8-1 的内容寻址缓存，回答「带 @autotune 的内核如何按当前输入尺寸与 GPU 选出最快调度、并把选优结果跨运行复用」。`__call__` 参数按类型标注三分：**常量参数**（int/float/str）精确值进 jit_key、值变重编译；**调优参数**（整数 DataType 如 int32）的整除性指纹进 jit_key（决定编译哪组二进制）、尺寸桶（桶宽约尺寸的 1/4）进 tuning_key（决定选哪份最快），不重编译；**内核参数**（指针/非整数）仅作 launch 实参。调优链路为「并行转译→并行编译→串行 benchmark 选优」：转译、编译用 fork 进程池并行，失败 schedule 只记录不中断；benchmark 独占 GPU 串行测量（清 L2 + CUDA event 取中位数），仅一份候选时跳过。dispatch 表附**环境指纹**（tilus 发行基线版本、target、GPU、算力、CUDA 版本），写入 dispatch_table.json，加载时任一不符即丢弃重调优，无元数据的旧表永不匹配，`"*"` 通配符可手动放宽单项；dispatch 缓存层只存选优结果与软链，真正的 .so 仍在 programs/<hash>，两层各司其职。
