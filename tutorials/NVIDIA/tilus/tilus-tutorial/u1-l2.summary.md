本讲解决「装好 Tilus、跑起来、建立源码地图」三件事。安装上，普通用户用 `pip install tilus`，源码开发者用 `pip install ".[dev]"`；当 GPU 驱动旧于 580.65.06 时需约束 `cuda-python<13`；版本号由 `setuptools_scm` 从 git tag 动态生成，`tilus.__version__` 来自已安装发行版元数据；要求 Python≥3.10。引入的关键术语有：包（顶层包 `tilus`）、依赖（写在 `pyproject.toml`）、**target**（编译目标，如 `sm80/sm90a/sm100a`，由 `get_current_target()` 通过 `torch.cuda` 惰性探测匹配）、**缓存**（按内容哈希复用 `.so`，默认位于 git 仓库内的 `.cache/` 或 `~/.cache/tilus`）。核心结论是项目的编译器架构直接体现为包目录划分：真实代码在 `python/tilus/` 下，按数据流主线为 `lang`（写）→`ir`（表示）→`transforms`（改）→`drivers.py`（编排 `build_program`）→`backends`（生成）→`runtime`（跑），辅以 `kernels`/`utils`/内嵌的 `hidet` 子包（提供低层 IR 与运行时，是 Tilus 的传承来源）。全局开关集中在 `tilus.option`：`cache_dir` 控制落盘、`debug.dump_ir`/`debug.disable_ptxas_opt` 用于调试，多数支持同名环境变量；缓存键是「options+程序文本」的 SHA256 前 12 位，落在 `programs/<hash>/`，这也解释了为何改 emitter 后必须手动删缓存。
