本讲聚焦 Hopper（sm_90a）三大异步硬件能力，并讲解如何用 Tilus 指令组直接驱动。**wgmma** 是 warp-group（128 线程）粒度的异步矩阵乘累加，操作数可留共享内存（SS/RS 形态），须遵循 fence→mma→commit_group→wait_group 四段式协议：fence 建立 generic 代理写与 async 代理读的内存序，wait_group(n) 的 n 控制允许同时在飞的提交组数，是隐藏 MMA 延迟的关键。**cp_async（copy_async）** 把显存数据异步直搬共享内存、绕过寄存器，配 commit/wait 分组等待；Hopper 上更高效的整块搬运是 TMA（cp.async.bulk），其「异步搬运 + 等待」骨架与 cp_async 同构。**mbarrier** 是异步同步中枢，用「待到达计数 + tx-count」双归零与相位（phase）翻转模型绑定搬运/计算完成与屏障放行，arrive_and_expect_tx 追踪 TMA 字节数，arrive 用于纯通知，配合 producer/consumer_initial_phase 约定支撑生产者—消费者多级缓冲流水线。须分清三层同步：wgmma.fence（内存序）、mbarrier.wait（异步事务完成）、self.sync（线程执行同步），三者不可互相替代。
