本讲讲清了 TensorRT Edge-LLM 的**三层测试金字塔**：底层是 `unittests/` 经 CMake `GLOB_RECURSE` 链接成单一 `unitTest` 的 C++ GTest 单测（用 `--gtest_filter` 筛选，遵循「被测实现 vs 可信 CPU 参考」范式，如 `eagleAcceptTests`）；中层是 pytest 风格的 Python 组件/插件测试；顶层是 `tests/defs/` 的 YAML 驱动端到端流水线测试。中央调度器 `tests/conftest.py` 用 `--priority` 把清单名映射到 `tests/test_lists/<name>.yml`，再经 `pytest_generate_tests` 与 `pytest_collection_modifyitems` 两钩子实现「清单即白名单 + 按 YAML 顺序执行」；`--test-param` 可绕过清单直接单跑配置。`test_lists/*.yml` 按目标设备（A30/Orin/Thor 等）切分用例，因 engine 不可跨设备迁移，`l0`/`l1` 区分门槛级与扩展级。核心结论：模型改动 PR 的最低验证证据是 C++ 单测全绿 + export→build→inference 三段式端到端跑通。
