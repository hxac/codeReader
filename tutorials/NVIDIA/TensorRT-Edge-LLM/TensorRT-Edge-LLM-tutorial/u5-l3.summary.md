本讲覆盖运行时执行层三个最小模块：TensorMap、TensorRegistry、EngineExecutor。TensorMap 是非拥有的「名字→Tensor*」纯地址表，只供地址、不参与形状解析，并把 KV 缓存的 past/present 绑到同一地址（attention 插件就地更新）。TensorRegistry 是声明式绑定规格，用 TensorSpec 配以指向 InferenceDims 成员的符号形状模板描述引擎布局，bindAll() 一次性完成 setTensorAddress 与 setInputShape，逐层 %d 按 perLayer 展开；InferenceDims（9 个符号维）由 LLMEngineConfig 的配方方法产出，是符号维解析的唯一来源。EngineExecutor 是「对模型一无所知」的薄封装，靠 prepare/execute/captureGraph 三件套驱动 TensorRT，复用同一个 IExecutionContext、用 setOptimizationProfileAsync 在 prefill(profile 0) 与 decode(profile 1) 间切换，因 TensorRT 切 profile 不清绑定，故每步都重新绑定。execute 以「绑定哈希+完整快照」判定 CUDA graph 缓存命中；LoRA 权重不进注册表，而由 LoRAManager 填入 TensorMap 走兜底绑定，多 LoRA 借「哈希含权重地址」各录一张 graph 实现零成本切换；KV 缓存与上下文显存均不归执行器独占，KV 缓存属 SharedResources。
