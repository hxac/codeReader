本讲承接 u5-l4 的解码策略抽象，拆开四种投机解码器（EAGLE / MTP / DFlash / Gemma4-MTP）的 `decodeStep` 黑盒。四者都遵循「草稿提议 → base 验证 → 接受并提交 KV → 写回 host」的公共骨架，写回统一复用 `decoder_utils::appendAcceptedTokens`，每轮仅一次 D2H 同步；分发由 `DecoderRegistry` 按 `SpecDecodeMode` 选择。核心是沿三个维度对比：草稿提议形状、base 验证掩码、KV 归属。EAGLE 草稿条件于 base 隐状态、逐层深度优先扩展候选树，base 用树注意力掩码 + `eagleAccept`，自带独立草稿 KV（`mDraftCacheManager`）；MTP 概念上是最简链式多头预测（从 base 派生的浅辅助头），但当前运行时代码与 EAGLE 共享同一套树形提议/接受路径（头文件 TODO 记录了简化意图），区分二者主要靠导出/构建期的草稿来源；DFlash 走块状/Jacobi 范式，一次前向填一整个 `blockSize` 的 mask token，支持 linear 因果掩码与 DDTree 两种验证形态，均复用 `eagleAccept`，且选中时会跳过 vanilla 的 CUDA graph 捕获；Gemma4-MTP 最特殊，是真正的顺序链（每步 1 token）、base 用线性因果掩码 + 专门的 `sequentialAccept`，且是唯一与目标模型共享 KV 的策略（构造期强校验 `sharesTargetKV && !hasOwnKVCache`），省下一份草稿 KV，适合显存紧张的边缘场景。导出侧的草稿引擎导出与 d2t 词表映射见 u7-l2。
