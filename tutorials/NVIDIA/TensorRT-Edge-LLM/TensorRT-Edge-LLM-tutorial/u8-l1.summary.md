本讲承接 u2-l5，揭开 Python 端导出的 ONNX 自定义算子（attention、MoE、量化 GEMM 等）在 C++ 端的真正落地点——**TensorRT 插件**，否则 ONNX 解析阶段会因「未知算子」失败。围绕四个最小模块展开：插件两件套与注册机制、CMake 构建目标与共享库加载、AttentionPlugin 落地样本、量化类插件。

核心结论：EdgeLLM 插件采用**工厂模式**的「本体（Plugin）+ 工厂（Creator）」两件套——Creator 以无状态单例对外报出名字+版本与 PluginField 参数、由 `createPlugin` 造实例，本体承担形状推导与 `enqueue` 执行。插件统一用 **V3 接口**，通过多继承 `IPluginV3OneCore/BuildV2/Runtime` 并在 `getCapabilityInterface` 里 `static_cast` 分发能力。全仓 14 个 Creator 各用一行 `REGISTER_TENSORRT_PLUGIN` 宏注册，靠全局对象静态初始化填入进程级注册表。

关键机制：插件库 `NvInfer_edgellm_plugin` **必须是 SHARED 共享库**——`dlopen` 才能整块映射并触发注册代码，静态库因「无直接引用」会被链接器丢弃而注册表为空。宿主经 `loadEdgellmPluginLib()` 以 `RTLD_NODELETE` 加载（库须常驻以免卸载后崩溃），再 `dlsym` 取 `initEdgellmPlugins` 同步日志。

代表性插件：`AttentionPlugin` 融合 RoPE+KV cache 读写+MHA/GQA，靠形状推断分派 prefill/decode/tree 等模式；`Int4GroupwiseGemmPlugin` 是最小模板；`Nvfp4MoePlugin` 与 GeForce 孪生按 SM 架构分工、共享 ONNX 面但消费不同权重布局。本讲止于插件壳，CUDA kernel 实现留待 u8-l2。
