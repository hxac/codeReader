本讲承接 u5-l1 的 handleRequest，补齐请求、响应、流式三块数据契约。请求分三层：Message（role+contents[]，支持 text/image 多模态）→ Request（单序列：messages、imageBuffers、stopStrings）→ LLMGenerationRequest（整批 requests[]，加批次级采样参数 temperature/topK/topP/maxGenerateLength、loraWeightsName、streamChannels）。多模态是双轨：文字经 contents 分词成 inputIds，图片走 imageBuffers，按 image 块出现次序按下标对齐；maxGenerateLength 会被 KV 容量夹紧。响应 LLMGenerationResponse 含 outputIds/outputTexts/logprobs/finishReasons，以 originalIdx 对齐请求顺序；outputIds 保留完整 token 流，仅 outputTexts 被停止串裁剪。流式有两条增量通道：轻量 TokenCallback 只回 token id；完整 StreamChannel 为 MPSC 队列，推送 UTF-8 合法、停止串已裁剪的 StreamChunk。解码循环分两阶段：decodePerSlot 算可发文本，emitChunks push 分块并在终态 finish(reason)；StreamChannelFinalizer 借 RAII 保证异常路径下消费者永不死等。FinishReason（EndId/Length/Cancelled/StopWords/Error 等）是响应与流式终止块共用的唯一终止枚举。
