本讲承接插件架构，打开 `enqueue` 内部讲解 EdgeLLM 真正干活的 CUDA 算子族。首先确立算子的两副面孔：`cpp/kernels/` 是随主仓库 nvcc 编译的架构通用 `.cu`（MoE 路由/激活、RoPE、投机解码工具），`kernelSrcs/` 则是强 SM 特异性的预编译 cubin 与 CuTe DSL 产物（FMHA、XQA、分组 GEMM），区分口诀是「是否按 SM 单独出一份二进制」。注意力被拆为两类 kernel：context FMHA 处理 prefill 大方阵、decode XQA 针对「单 query 读长 KV 缓存」优化，高效性源于历史 KV 只读不重算、并行度铺在 KV 维度、RoPE 落盘与读解耦。MoE 是一条流水线：topk softmax 选路、按专家重排并填分组 GEMM 描述符、分组 FC1/FC2、FP32 激活与门控加权散回。核心术语 SM、cubin、CuTe DSL、context/decode 注意力在此确立。构建上三套 SM 特异性机制共享「从 `CMAKE_CUDA_ARCHITECTURES` 推需求集、排除其余」思路，新增一个 SM 需跨顶层架构表、两处全集、cubin 生成轮与可能的复用映射（如 SM110 复用 SM101）协调改动，并经 export→build→inference 验证。
