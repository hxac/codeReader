本讲围绕 `cpp/runtime/decoding/` 的三个最小模块——`DecodingStrategy`、`DecoderRegistry`、`VanillaDecoder`——讲解解码策略层如何把「解码算法」从运行时主循环中解耦。核心结论是：主循环是与算法无关的固定骨架，每步只调 `decodeStep`，算法差异全部藏在策略子类里。

关键概念与术语：`DecodingStrategy` 是无状态抽象基类，要求子类实现 13 个纯虚方法，分五组（身份标识、核心动作、上下文显存、系统提示 KV、批量驱逐）；昂贵资源（执行器、KV 缓存、采样缓冲）收在 `DecodingRuntimeContext`，由运行时统一拥有、跨请求复用；`DecodingInferenceContext` 则是请求局部上下文。`DecodingStrategyKind` 与配置层 `SpecDecodeMode` 一一对应但分处不同层次。

`DecoderRegistry` 作为门面持有两个指针：永远无条件创建的 `mDefaultDecoder`（vanilla）和可选的 `mSpeculativeDecoder`；构造期按 `SpecDecodeMode` 分发，逐请求 `select()` 依据 `disableSpecDecode` 回退到 vanilla，从而支持廉价切换、且 `select` 本身 `noexcept` 不抛异常。

`VanillaDecoder::decodeStep` 的基准流程是「取上一步 token → embedding → base 前向（decode profile 1）→ commit KV → 采样 → 唯一一次同步拷回 → push 1 个 token」。与投机解码的本质差异在于：vanilla 是「base 一次前向、采样即终、每步 1 token」，投机解码是「draft 先猜一批 → base 一次前向验证 → 命中全部接受」，把「采样即终」推迟为「验证后才终」，并为 u7 投机解码专题铺好抽象接口。
