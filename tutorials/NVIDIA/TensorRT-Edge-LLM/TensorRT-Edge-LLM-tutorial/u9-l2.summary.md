本讲是「特性与扩展」单元第二篇，讲两个面向生产部署的运行时特性：系统提示 KV 缓存与流式输出，承接 u5-l5 的 `HybridCacheManager` 与 u5-l2 的流式接口层。

系统提示 KV 缓存用于消除固定系统提示的重复 prefill、降低首 token 延迟（TTFT）。其缓存键为 `(格式化后系统提示, LoRA 名字)` 二元组，做精确字符串匹配，故 chat 模板感知、LoRA 隔离。保存走一次独立单序列 prefill（`genAndSaveSystemPromptKVCache`），把 base/draft 的 KV 及混合模型的 recurrent/conv 状态「捕获」进内存 map；恢复在 prefill 前发生，复用 `N-1` 个 token 的 KV、把第 N 个留作真实输入，以对齐投机解码的 draft 边界。底层 `captureKVCache`/`restoreKVCache` 是按 headDim 分组的 GPU 拷贝，当前仅支持 FP16（kHALF），FP8 尚未实现；Gemma4-MTP 因与目标共享 KV，草稿侧保存/恢复为空操作。

流式的 `StreamChannel` 是 MPSC 管道：生产者 API（push/finish）私有、仅 friend 可达，`finish` 幂等、首调用者胜。解码主循环每轮按「取消观测 → decodeStep → decodePerSlot → updateFinishStates → emitChunks」顺序，靠 `streamInterval` 节流、靠停止串 hold-back（扣留末尾 maxStopLen-1 字节）避免跨块漏判。`StreamChannelFinalizer` 作为 RAII 守卫，保证 `handleRequest` 任何退出路径下每个 channel 都被 `finish`，使消费者永不死等。

引入的关键术语供后续承接：`SystemPromptKVCache`、缓存键、capture/restoreKVCache、`N-1` 复用、`StreamChannel`、`StreamChunk`、`FinishReason`、`streamInterval`、停止串 hold-back、`StreamChannelFinalizer`、TTFT 双重优化。
