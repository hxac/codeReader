本讲讲透 LoRA 在 EdgeLLM 的全链路，核心是两条互斥路径：动态运行时 LoRA（图插入+sidecar+逐请求切换）与静态合并（焊进检查点后走普通流水线）。关键模块：insert-lora 为各类量化 GEMM 并联 lora_A→lora_B→Add 旁路并把权重暴露为图输入，GEMM 名由 initializer 反推 stem，构成 Python 与运行时命名契约；process-lora 把 PEFT adapter 翻译成 sidecar（剥前缀、丢 norm/lm_head、α/r 预乘进 lora_B、校正轴序、转 fp16），key 须与图输入逐字对齐；merge-lora 用 merge_and_unload 永久合并。运行时 LoRAManager 靠构造期一次性加载+换指针+rank=1 零值 dummy 实现 O(1) 零拷贝切换，切换后须 refreshTensorMap，每个 adapter 各录一张 CUDA graph；--maxLoraRank 决定引擎最大秩。结论：始终需要的 adapter（如 Phi-4-Multimodal 的 vision-lora）须量化前静态合并；需在线切换的走动态 LoRA。系统提示 KV 缓存键含 loraWeightsName，不同 adapter 缓存隔离，为下讲 u9-l2 埋钩子。
