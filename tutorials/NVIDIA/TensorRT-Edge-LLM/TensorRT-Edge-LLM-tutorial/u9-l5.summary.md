本讲打开 `experimental/server` 目录，介绍 NVIDIA 在 C++ 流水线之外的 Python 薄封装。核心是 `LLM` 类：它以 `model` / `onnx_dir` / `engine_dir` 三种互斥来源决定跑几个流水线阶段（导出→构建→加载），已存在的产物（`model.onnx` / `llm.engine`）按配置参数打标签缓存复用。推理有两个入口——同步批量的 `generate`（读 `LLMGenerationResponse`）与流式的 `generate_stream`（后台线程跑 `handleRequest`，主线程从 `StreamChannel` 的 MPSC 队列 `wait_pop` 取 `StreamDelta`），二者共用 `_make_generation_request` 把 `SamplingParams` 与 OpenAI messages 逐字段翻译成 C++ 的 `LLMGenerationRequest`。pybind 模块 `_edgellm_runtime` 经 `PyLLMRuntime` 封装把 runtime/request/response/streaming/builder 暴露成 Python 类，用 RAII 管理 non-blocking CUDA 流与插件库句柄，并在 `handle_request`/`wait_pop` 上释放 GIL。`api_server.py` 是纯 OpenAI 协议适配器，`/v1/chat/completions` 把请求体翻译成 `SamplingParams` 后复用同一条 `llm._runtime.handle_request`，流式经 SSE 发送 `StreamDelta`，没有第二条推理路径。核心结论：Python API、流式、HTTP 服务共用同一个 `handle_request`；`finish_reason_name` 负责把 C++ `FinishReason` 枚举翻译成 OpenAI 字符串。标记 experimental 的依据是 API 不稳定、依赖未默认安装、能力有缺口（如 `prompt_tokens` 硬编码为 0）。
