本讲串联 Python 导出前端与 C++ 构建器，讲清把一个 EdgeLLM 未支持的 decoder-only 新模型从零接入的最小改动与验证路径，贯穿直觉为「Python 优先、配置驱动、以权重事实为准」。核心四块：默认 `CausalLM` 是 GQA+SwiGLU+RMSNorm+RoPE 的通用底盘，形状委托 `ModelConfig`、精度委托 `make_linear`，标准结构常零代码导出；`ModelConfig` 把 HF 散乱字段摊平为强类型结构，能力开关（如 `has_qk_norm`）凭扫描权重 key 而非 `model_type` 判定，新层型需在 `_parse_layer_types` 归一化；`register_model` 是接入自定义类的唯一入口，`AutoModel` 查不到 `model_type` 即回退默认 `CausalLM`；权重加载靠「检查点 key ↔ 模块名」契约，融合权重由 loader 兜底拆分，仅结构性命名差异才需 `key_remap`。配套 `customization-guide` 的 8 扩展点表与 Adding A Text Model 五步法。验证恒为 export→build→inference 三段式，engine 不可跨 GPU/TRT 版本迁移。
