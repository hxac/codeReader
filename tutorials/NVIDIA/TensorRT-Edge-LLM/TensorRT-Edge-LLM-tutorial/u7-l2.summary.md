本讲从 Python 导出端讲清草稿检查点如何被翻写成 C++ 消费的 ONNX 图与 sidecar，核心是**变体解析**与**权重键重命名（key remap）**两条主线。`_resolve_model_variant` 用「互斥校验 + 优先级短路」裁决 base/draft 角色：EAGLE3 draft 是唯一自报告变体（检查点自带 `draft_vocab_size`，判据即 `is_eagle3_draft`），其余由布尔开关驱动。四类 remap 各异——EAGLE3 改名最多（`midlayer→layers.0`、拆 `qkv_proj`、丢 `t2d`/`target_model`，留 `d2t`）；MTP 剥 `mtp.` 前缀、tie 时借 embedding 当 lm_head；DFlash 近似空操作（仅丢 `rotary_emb`）；Gemma4-MTP 不 remap。EAGLE3 走默认 thinker 阶段自动识别，其 d2t（draft-to-target，草稿→目标词表映射）是训练产物，在 `write_runtime_artifacts` 阶段落盘成 `d2t.safetensors`，供运行时采样后翻译压缩草稿词表。DFlash 是配对独立检查点，配置从其 `dflash_config` 解析，lm_head 可从 base 借（探测→`_inherit_dflash_lm_head_quant` 镜像量化→`pre_repack_hook` 加载），`fc` 强制 FP16 以容纳大动态范围的目标隐状态。
