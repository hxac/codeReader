本讲聚焦 C++ 运行时总指挥类 `LLMInferenceRuntime`——所有 LLM 推理（普通自回归、EAGLE/MTP/DFlash 投机解码、多模态）的统一入口。它用 `unique_ptr` 把引擎执行器、KV 缓存、分词器、采样缓冲、多模态 runner、解码策略注册表全部「拥有」起来，构造一次、反复服务。

它有两个构造函数：vanilla（4 参数、加载 `llm.engine`、单套 KV）与 speculative（5 参数、多传 `SpecDecodeDraftingConfig`、加载 `spec_base`+`spec_draft`、双套 KV），都转发给同一 `initializeCommon`，以 `draftingConfig` 是否为 `nullopt` 分流；具体用哪种投机解码由 engine 配置的 `specDecodeMode()` 在 `DecoderRegistry` 里决定，`VanillaDecoder` 始终保留以支持逐请求回退。

`handleRequest` 是运行时心脏，分三阶段：准备（校验、套 chat 模板、分词、预热系统提示 KV 缓存、摆张量）→ prefill（base engine 用 profile 0 得首个 token）→ 解码循环（反复调 `DecodingStrategy::decodeStep`，每步采样、判停 EOS/长度/stop、流式输出、`performBatchEvict` 批量驱逐）。策略逐请求由 `DecoderRegistry::select` 据 `disableSpecDecode` 决定，主循环与解码算法解耦。运行时不自建流，须由调用方传入 non-blocking 流以避免与 TensorRT 辅助流隐式同步；`captureDecodingCUDAGraph` 把 decode kernel 录制成图以省 CPU 启动开销，可选且可降级。本讲为 u5 后续（请求响应模型、引擎执行器与张量注册表、解码策略、KV 缓存）提供公共地基。
