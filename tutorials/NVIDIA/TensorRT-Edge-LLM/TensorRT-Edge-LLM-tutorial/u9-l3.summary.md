本讲讲透三项「导出期产出、运行时消费」的 sidecar 特性。词表裁剪用 vocab_map（压缩 id→全词表 id 查表）把 lm_head 从 V 砍到 V'，经离线选词（特殊 token、d2t 必留）→导出应用（按量化类型分发，INT4 须在 repack 前裁且 V' 为 128 倍数）→运行时 mapReducedVocabToFullVocab 还原三阶段。FP8 KV 缓存由检查点元数据驱动：量化阶段烤进配置，导出期自动启用并挂 q/k/v per-tensor scale，KVCacheManager 用 kFP8 替代 kHALF 使 KV 显存减半，Blackwell 上另有 attention 提速。chat 模板把 HF Jinja 编译成 processed_chat_template.json（各 role 的 prefix/suffix + generation_prompt + content_types），按硬编码模板 > Jinja 提取 > 兜底三级优先级产出，供无 Jinja 的 C++ 分词器拼接复现 prompt。三者同为导出期写、运行时读的 sidecar 契约。已知边界：EAGLE3 draft 不支持裁剪；草稿模型强制关闭 FP8 KV；FP8 KV 与系统提示缓存互斥。
