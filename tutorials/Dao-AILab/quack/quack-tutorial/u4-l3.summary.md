本讲是 GEMM 主机侧系列第二讲，聚焦用户真正调用的公共 API 表面，主角是 `quack/gemm_interface.py`，配套 `gemm_iface.py`。核心结论：这一层是「PyTorch 张量进、张量出」的薄壳，负责把用户参数规整成内核能消化的角色，再汇聚到上一讲的 `gemm_dispatch`/`run_gemm_plan`，并在其上再加一层 `_GemmIfacePlan` 计划缓存。

`gemm` 是 API 的根，语义 D=α(A@B)+bias，靠「热路径—冷路径」之分压低 eager 开销：热路径只换数据指针命中计划缓存，冷路径做完整校验、autotune 并把决策烘焙进 `IfacePlan`。它有四类职责（输入规整、输出分配、路径选择、空输入快路径）和三条真实执行路径——量化输出 `gemm_quant_out`、`torch.compile` 的 `gemm_out`（schema 类型化）、eager 的 `gemm_tuned`；eager 用 `_launch` 绕过约 85µs 的 custom-op 边界。计划缓存键由 `tensor_key`、`bs_format`、`scalar_mode` 等组成。

`gemm_act`/`gemm_gated`（同一函数，靠 `activation` 名字区分）把激活/bias/C 融合进同一次 kernel 的 epilogue，省掉额外显存往返；门控时 `postact` 维度折半，`concat_layout` 让拼接权重免拷贝按交错顺序读取。

`gemm_symmetric` 等变体借助 `VariantSpec` 声明式机器（`canonicalize`/`cold`/`warm`）共享规范化与计划缓存；`gemm_norm_act` 则把乘+rstd 缩放+激活三者融合交给 `norm_act_mod`。最后，blockscaled 输入（`BlockScaledOperand` 容器）与量化输出（`out_dtype=BlockScaledFormat`）正交可组合，e8m0 SF 跨 compile 边界用 uint8 view 绕过 Inductor bug。这些概念为后续 u4-l5、u6、u7、u8 讲义承接。
