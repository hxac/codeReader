本讲围绕纯 Python 叶子模块 `gemm_config.py`，讲清贯穿 GEMM 编译缓存与设备侧内核的「数据契约」。三个最小模块：①`GemmConfig` 是 `frozen` 数据类，用 tile/cluster/pingpong/is_dynamic_persistent/swap_ab/split_k/device_capacity 等 14 个标量描述一次 GEMM 的几何与策略；`SplitKMode` 是配套 `IntEnum`，定义 SERIAL/PARALLEL/SEPARATE 三种 split-K 合并方式，权衡确定性与延迟。②`get_all_configs()` 用 `itertools.product` 为 SM80/90/100/120 生成候选池，每个 config 自带 `device_capacity` 标签供运行时过滤，import 期不碰 CUDA；核心结论是 **SM100 没有 pingpong**——Blackwell 的 tcgen05 MMA 把累加器放进专用 TMEM，配合 warp 分工异步流水线，MMA↔epilogue 重叠由硬件原生提供，故转而调优 `use_clc` 与 `use_tma_gather`。③默认配置经 `_default_config_for_cap` 按架构分流；`blockscaled_config_ok` 是量化合法性的唯一真值来源（如 SF tmem 64-N 颗粒约束），`cta_tile_shape_m` 镜像 SM100 的 2-CTA MMA 折半规则，凡按 M tile 分配的主机缓冲都必须用它。关键术语 tile、cluster、pingpong、blockscaled、动态持久化（CLC）将供后续讲义承接。
