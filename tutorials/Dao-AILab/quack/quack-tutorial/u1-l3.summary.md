本讲为 QuACK 源码建立鸟瞰地图，围绕三个最小模块展开。其一，顶层近 50 个 `.py` 文件按「离用户的距离」分三层：公共 API 层（`rmsnorm`/`softmax`/`gemm`/`linear` 等入口）、内核层（设备侧内核与主机侧编译调度）、工具层（`copy_utils`/`layout_utils`/`cute_dsl_utils` 等被一切复用的积木）。其二，顶层下有 13 个子包，按主题归为内核机制（`epilogue`/`operand_transform`/`gemm_runtime`/`spec`/`sync`）、量化（`blockscaled`）、分布式、算法（`sort`/`transform`）、工具与集成（`dsl`/`cache`/`bench`/`testing`），多数服务于 GEMM。其三，入口 `quack/__init__.py` 的执行顺序为：定义版本 → **副作用导入** `quack.dsl`（对 CuTe 张量类执行 monkey-patch、暴露 `cute_op`）→ 导入公开 API → 用 `__all__` 声明可见名字；副作用导入必须早于内核模块。核心结论：看子包 `__init__.py` 的 docstring 可确认职责，用 `grep` 一键画出任意模块依赖链，`compile_utils`/`cache`(`jit_cache`)/`cute_dsl_utils`/`dsl`(`cute_op`) 是全项目公共地基，归约家族与 GEMM 各有专属件。
