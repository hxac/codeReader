本讲聚焦 ncnn_llm 的构建系统与运行方式，回答「C++ 源码如何被编译成可运行程序」。项目采用 xmake 构建（配置文件 xmake.lua），全局设定语言标准 C++20/C11、强制 UTF-8 编码，并通过平台分支处理 wasm（emscripten）、Windows/MinGW（NOMINMAX、/utf-8、链接 user32/gdi32）等差异。外部依赖仅两个：ncnn（master 分支，编译期通过 configs.vulkan=true 开启 Vulkan）与 nlohmann_json（单头文件 JSON 库），分别由 add_requires 声明、add_packages 引入 target。项目按 10 个 target 分三层：基础静态库（ncnn_tokenizer 分词器、ncnn_llm 核心运行时）、可执行示例（llm_ncnn_run 主入口，及 ocr/asr/embedding/clip/nllb_main）、工具（benchllm、test_llm）；所有 binary 均依赖 ncnn_llm 复用核心代码。核心结论：构建用 xmake build、运行用 xmake run，产物位于 build/<平台>/<架构>/<模式>/；运行 LLM/VLM 还需在 assets/ 准备模型目录；编译期 configs.vulkan 与运行期 --vulkan 是两个层面、需同时开启。关键术语：target、static/binary、add_deps/add_requires/add_packages、set_rundir、compile_commands。读源码应以 xmake.lua 为准（README 提及的 unigram_main 实际未定义）。
