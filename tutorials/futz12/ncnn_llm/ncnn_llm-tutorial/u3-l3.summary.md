本讲实现项目里的 Unigram 分词器（UnigramTokenizer），用于 mclip 等嵌入运行时（`tokenizer.type=="unigram"` 分支），与 u3-l2 的 BPE 形成对比。核心数据是**词表**（每行「词 + 对数概率 logprob」，行号即 token id）和**每词对数概率**。它把分词建模为最优化问题：在所有切分方案里选「总对数概率最大」的一种，而非 BPE 的局部贪心合并。四个最小模块：LoadFromFile（静态工厂加载词表、对象只能移动不能拷贝）、BuildTrie/MatchAt（用按字节展开的 Trie 一次性枚举某位置所有候选词，使查询与词表大小无关）、SegmentPiece（用 Viterbi 动态规划 dp[i]=max(logprob[t]+dp[i+L]) 从右往左填表再回溯，外层套线程安全缓存）、unk_penalty（默认 -10.0，仅在位置完全无词匹配时兜底打分，比正常词更负，保证 OOV 是最后选项，最终经 TokensToIds 映射成 unk_id）。预分词沿用 SentencePiece 的空格→`▁` 约定。
