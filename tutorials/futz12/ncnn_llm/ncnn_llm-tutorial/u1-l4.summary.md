本讲围绕示例入口 `examples/llm_ncnn_run/main.cpp` 讲透命令行这一层。`main` 充当调度员，按固定顺序串联启动流程：`enable_utf8_console` → `get_utf8_args` → 转 `char**` → `parse_options` → `normalize_model_path` → 路径存在性检查（早失败）→ `detect_template_type` → 构造 `ncnn_llm_gpt` → 准备 `builtin_tools`/`router` 与可选图像 → `run_cli`。核心数据结构是 `Options` 结构体，每个字段对应一个命令行选项并带默认值；`parse_options` 用手写 `for` 循环逐个匹配，区分带值选项（`argv[++i]` 取值、缺值报错退出码 2）与标志型选项（直接置反布尔）。`normalize_model_path` 借助 `<filesystem>` 的 `is_absolute`/`has_parent_path`，把裸模型名自动补成 `./assets/裸名`。`get_utf8_args` 与 `enable_utf8_console` 用 `#ifdef _WIN32` 封装 Windows GBK 痛点，分别处理 argv 输入编码与控制台 I/O 编码，非 Windows 上为空操作。新增一个选项只需改 Options 字段、parse_options 分支、print_usage 三处；命令行的 `max_tokens` 与生成层的 `GenerateConfig::max_new_tokens`（默认 4096）是两回事，真正限制生成长度的是后者，留待 u2 展开。模型构造、`detect_template_type` 的模板拼接、`run_cli` 的对话循环细节均作为黑盒留给后续讲义。
