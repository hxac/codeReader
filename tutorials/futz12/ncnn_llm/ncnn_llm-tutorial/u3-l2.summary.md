本讲深入 BpeTokenizer 实现，把 u3-l1「构造对象」推进到「字符串如何切成 token id 并还原」。覆盖四个最小模块：LoadFromFiles 加载、BpeForPiece 合并核心、bpe/bbpe 两条预分词路径、encode/decode 公开 API。

关键契约：vocab.txt 行号即 token id，merges.txt 行序即合并 rank（值小者优先），PairKey 用 `\t` 分隔以防键冲突；LoadFromFiles 是唯一入口（构造函数私有）。BpeForPiece 为贪心 BPE：先将 piece 按 UTF-8 码点切分，每轮只合并 rank 最小的相邻对，循环至无可合并，词边界由预分词决定、不跨词合并，Cached 版用 `mutable`+`mutex` 支持并发。

`use_byte_encoder` 是 bpe 与 bbpe 的唯一开关：bpe 走 SentencePiece 预分词，空格转为 `▁`(U+2581) 前缀、按词分别 BPE；bbpe 走 ByteEncode，把每字节映射成可见且不断行的码点、整段 BPE。其本质是让全部 256 个字节都用可见码点表示，避免裸空格/控制符破坏 vocab 的按行解析；开关必须与词表训练方式一致，否则退化为 unk。

encode 用最长匹配把特殊令牌作为原子整体输出、绕过 BPE；decode 按 `▁`→空格（bpe）或 ByteDecode（bbpe）还原，bbpe 在字节级精确可逆、bpe 会丢失前导空格，fallback_to_chars 兜底防崩。下一讲 u3-l3 讲 Unigram 分词器。
