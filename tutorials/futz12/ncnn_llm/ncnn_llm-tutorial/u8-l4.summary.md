本讲梳理从 HuggingFace（PyTorch）模型到 ncnn_llm 可加载产物的导出管线，落在 `export/` 下四个脚本，分三条支线。权重支线：`nllb_export.py` 把 NLLB 拆成 embed/encoder_noembed/decoder_noembed 三个 TorchScript 模块，刻意不导出正弦位置编码而交由 C++ 补算；从 `.pt` 到 `.ncnn.*` 依赖外部 `pnnx`（待确认）。分词器支线：`extract_tokenizer.py` 与 `hunyuan_ocr_tokenizer.py` 把 HF `tokenizer.json` 翻译成 `vocab.txt`/`merges.txt`，自托管、无需 PyTorch。结构后处理支线：`hunyuan_ocr_add_kvcache.py` 把解码器 `.param` 中的 SDPA 从「4入1出」改写成「6入3出」并打开 `kvcache_enabled`，注入 KV cache。贯穿全讲有两个隐式契约：分词器「行号 == token id」（靠按 id 升序排序、用占位符补 id 空洞来保证），以及 KV cache 的 `cache_k%d`/`cache_v%d` 入、`out_cache_k%d`/`out_cache_v%d` 出槽位命名，二者须与 C++ 共享运行时严格对账。README 已声明导出脚本可能随运行时演进过时。
