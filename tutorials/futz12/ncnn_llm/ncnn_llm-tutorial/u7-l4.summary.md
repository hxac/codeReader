本讲说明 ncnn_llm 如何把 ncnn 原生不支持的算子插入推理流水线。核心机制是：继承 `ncnn::Layer` 重写 `forward`、设置 `one_blob_only`/`support_inplace` 标志位、写 creator/destroyer 工厂、用 `register_custom_layer` 按类型名登记。`register_gdr_layers` 必须在 `load_param`/`load_model` 之前、且只作用于 `decoder_net`，否则 ncnn 解析 `.param` 时找不到构造函数而加载失败。

引入两个混合架构自定义算子：`ShortConv` 是带滑动状态的 depthwise 因果短卷积加 SiLU，靠 `conv_state`（拖尾 K 行）在批与批之间衔接；`GatedDeltaRule` 是门控 DeltaRule 线性注意力，用一个固定大小的状态矩阵 S，每步执行「衰减→用 key 查旧状态→算修正量→用外积写回→用 query 读出」五步递推，内存不随序列增长。

配置字段 `sconv_cnt`/`gdr_cnt`（选填，缺省 0）决定 `create_ctx` 是否选用派生类 `qwen3_5_ctx`（在 KV cache 之外多出 `sconv_cache`/`gdr_cache`），并决定三类状态插槽（`cache_k/v%d`、`cache_conv%d`、`cache_gdr%d`）的循环上限。由于共享运行时 `llm_run_decoder_with_kv` 只认 KV 插槽、不认识 conv/gdr 插槽，qwen3.5 混合架构在 generate 里必须**内联展开** decoder，手动完成三类状态的喂入与回收——这是「跨模型族共享 decoder 运行时」设计主线的唯一例外。
