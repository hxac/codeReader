本讲讲解 `ncnn_llm_gpt` 构造函数如何把模型目录里的 `model.json` 翻译成成员变量。`model.json` 顶层分三块：`params` 给出三张子网（embed / decoder / proj_out）的 `.param`/`.bin` 文件名，六个字段全为必填，真实键名是 `embed_token_*`/`proj_out_*`（README 的 `embed_*`/`lm_head_*` 已过时，以源码为准）；`tokenizer` 块的 `vocab_file`/`merges_file`/`additional_special_tokens`/`eos`/`bos` 是必填键（值可空，空串得 id=-1），`type` 选填，`"bbpe"` 开启字节级编码；`setting` 块几乎全选填，`attn_cnt`（决定 KV cache 层数）、`rope`（含 rope_head_dim/rope_theta 及 LongRoPE 等四种变体）、`vision`（`close`/`vit`/`qwen3.5_vl`，区分纯文本与 VLM）均有 `contains` 守卫和默认值。判定必填与否的标准是代码是否用 `contains` 包了一层。需注意 `model_type` 和 `hidden_size` 不被 gpt 构造函数读取，属 OCR/ASR/embedding 运行时。任何字段读取异常都被 `catch` 统一转成 `load model failed` 报错。本讲只讲「配置→成员变量」一步，这些变量如何驱动 prefill/generate 留给后续讲义。
