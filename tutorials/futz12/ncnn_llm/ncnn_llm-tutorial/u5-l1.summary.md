本讲聚焦 VLM（视觉语言模型）单元第一讲，只讲构造函数 `ncnn_llm_gpt(...)` 加载模型时视觉部分比纯文本模型多做的事，不涉及图像预处理、特征提取与嵌入注入（留给 u5-l2/l3/l4）。核心是 `vision_type` 三值枚举：由 `model.json` 的 `setting.vision.type` 字符串翻译而来，`VISION_CLOSE`（纯文本，不加载视觉网络）、`VISION_VIT`（标准 ViT）、`VISION_QWEN3_5_VL`（Qwen3.5-VL，下游走双帧堆叠与交错 mRoPE）。关键结论：VIT 与 QWEN3_5_VL 在构造阶段加载的网络与配置完全相同（`vision_embed_patch` + `vision_encoder`，可选 `vision_embed_pos`，均为 `shared_ptr<ncnn::Net>`），差别仅在枚举值本身，分歧体现在下游预处理与位置编码。构造闸门是字符串 `vision_type_str != "close"`，大小写敏感。`patch_size`/`patch_dim`/`max_num_patches`/`spatial_merge_size` 四项必填（直接 `get`），`vision_embed_pos` 与视觉 `rope`（含 `mrope_section`）选填（`contains` 守卫）。占位令牌 `<|image_pad|>` 须先在 `additional_special_tokens` 注册、再以 `find` 解析成 `image_pad_id`，供下游 `inject_image_embeds` 整段替换为真实图像嵌入。配置异常统一被 catch 成「load model failed」。
