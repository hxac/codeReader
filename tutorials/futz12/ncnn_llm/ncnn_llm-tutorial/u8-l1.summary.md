本讲义解决「同一模型如何在 CPU 与 Vulkan GPU 间取舍、并配置线程数与数值精度」。最小模块有四：(1) 基类 `ncnn_llm_base` 的 `create_option()`，把 `num_threads_`(默认4)、`use_vulkan_`(默认false)、`use_bf16_storage`(写死false) 下发到 `ncnn::Option`，服务于 NLLB/ASR 等继承者；(2) 主运行时 `ncnn_llm_gpt` 不继承基类，在构造函数里逐网配置，只让最重的 `decoder_net`(及视觉子网) 走 Vulkan，轻量的 `embed_net`/`proj_out_net` 留 CPU，因搬数据开销不划算；(3) 精度取舍——decoder 开 `use_bf16_storage=true`(省带宽且范围与 fp32 相同) 而显式关闭所有 `use_fp16_*`(fp16 上限 65504 易溢出)，体现「存储降精度、算术保安全」；(4) 两层 Vulkan 控制：编译期 `NCNN_VULKAN` 宏(由 xmake `configs.vulkan=true` 决定「能不能」) 与运行期 `use_vulkan` 标志(「用不用」)，gpu instance 的 `create_gpu_instance`/`destroy_gpu_instance` 在基类构造/析构里成对调用。关键术语：`ncnn::Option`、存储精度 vs 算术精度、gpu instance、bf16/fp16。CLI 全链路为 `--use-vulkan`/`--vulkan-device`/`--threads` → `Options` → 构造函数 → 各 `Net::opt`。
