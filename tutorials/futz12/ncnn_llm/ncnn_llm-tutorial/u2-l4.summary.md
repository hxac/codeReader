`generate` 是 ncnn_llm 的自回归解码主循环：一个 `for (step < max_new_tokens)` 循环，每步先用上一步已确定的 `cur_token`（解码输出或累积工具调用文本），再算出下一个 token，直至遇到 `eos` 或步数耗尽。每步数据流为：`embed_net`（单 token）→ `decoder_net`（`is_prefill=false`，带 KV cache）→ `proj_out_net`（logits）→ `llm_select_next_token`（采样）。循环开头用 `clone_ctx` 克隆上下文，不污染调用方，这对多轮对话至关重要。

本讲核心结论有三：其一，KV cache 在 decode 阶段「读旧值、原地覆盖」（`kv_cache[i] = ...`，长度 +1），区别于 prefill 的 `emplace_back` 追加，由 `is_prefill` 开关区分；decode 的 mask 是全 0 向量，因当前 token 恒为序列末尾、因果性天然满足，无需 prefill 的因果掩码。其二，共享采样函数 `llm_select_next_token` 先做**重复惩罚**（历史 token 负分乘、非负分除以 `repetition_penalty`，默认 >1 抑制重复），再按 `do_sample` 选贪心 argmax 或 temperature+top_k+top_p+离散抽样。其三，停止与分流机制：`eos` 触发 `break`；`tool_call_id` 与 `tool_call_end_id` 之间累积的文本经 `handle_tool` 解析 JSON、调用 `tool_callback`、再通过内部 `prefill` 回填上下文并 `continue`；`<think>` 标签当前主循环不做拦截，作为普通文本流式输出。

引入的关键术语供后续承接：`GenerateConfig`（max_new_tokens/temperature/top_p/top_k/repetition_penalty/do_sample/tool_callback）、KV cache 的读-覆盖更新、`llm_select_next_token`、特殊 token id（eos/tool_call/think）、`clone_ctx`。这些为 u2-l5（ctx 与多轮对话）和 u7-l2（工具调用机制）铺垫。
