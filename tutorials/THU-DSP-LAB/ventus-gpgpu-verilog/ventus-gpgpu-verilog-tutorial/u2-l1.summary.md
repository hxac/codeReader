本讲深入 CTA 调度子系统内部，讲清「一个 workgroup 凭什么被派发到某个 SM」。先建立三层调度概念：workgroup（WG/CTA）含若干 warp（WF/wavefront），CU 即 SM，调度器源自 MIAOW。模块链为：cta_interface 作门面，把主机 WG 描述转交 cta_scheduler，并用 generate 把单路调度结果广播成 NUMBER_CU 路、靠 one-hot 的 cta2warp_valid 点选目标 SM。cta_scheduler 例化五子模块闭环：inflight_wg_buffer 收件、allocator_neo 选 CU、top_resource_table 管账本、gpu_interface 派发回收、dis_controller 状态机指挥。核心机制有二：allocator 用 5 个 CAM（VGPR/SGPR/LDS/WF 槽/WG 槽）并行比较并相与得候选 SM 掩码，prefer_select 按 wg_id 轮转挑一个，放不下则 rejected；resource_table 用双向链表管理每个 (SM, WG槽) 的资源占用块，每次分配或回收后 find_max 找出最大连续空闲块的 size 与起始地址回填 CAM。dis_controller 用 IDLE→ALLOC→HANDLE_RESULT 状态机串起分配，并靠 cu_groups_allocating 做互斥保护。gpu_interface、inflight_wg_buffer、cu_handler 的派发握手细节留待后续讲义。
