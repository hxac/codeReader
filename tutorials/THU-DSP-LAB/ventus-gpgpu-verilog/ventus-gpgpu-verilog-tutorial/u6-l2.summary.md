本讲围绕 SM 内的共享内存（shared memory / LDS）展开，它是同 workgroup 内线程共享数据的低延迟暂存区，由 LSU 以 `addr < SHAREMEM_SIZE` 判定分流，与 D-cache 并行、不进 L2、无 tag 检查、不可缺失。核心模块为 `shared_mem` 顶层与 `bankconflict_arb` 仲裁器。容量由 `SHAREDMEM_DEPTH × SHAREDMEM_BLOCKWORDS × 4` 决定（默认 1KB），路数恒为 1；`SHAREMEM_NBANKS = DCACHE_BLOCKWORDS`（默认 2）、`SHAREMEM_NLANES = NUM_THREAD`（默认 4），bank 号取自块内偏移低位，地址解码最简。本讲引入的关键术语：bank、bank 冲突、blockoffset/bankidx、wordoffset1h、activemask、固定优先级仲裁、保留寄存器。核心结论：bank 冲突靠 `pop_cnt` 检测、`fixed_pri_arb` 每拍每 bank 选一个 lane、剩余 lane 存寄存器下拍重试，实现「以时间换端口」串行化；冲突期间 `core_req_ready` 反压上游，读写 crossbar 视角不对称（写按 bank 选 lane、读按 lane 选 bank）。共享内存直接挂在 pipe 上，不经过 `l1cache_arb`，这是其与 D-cache 在系统连接上的关键差别。
