本讲解析 Ventus GPU 每个 SM 的 L1 数据缓存（`l1_dcache`），源码位于 `src/gpgpu_top/sm/l1cache/dcache/`。D-cache 为 32 组×2 路组相联、块字数 2，每 SM 仅 512 字节，靠四接口对接 LSU 与 L2：`core_req/core_rsp` 承载核心侧读写，`mem_req/mem_rsp` 经 `l1cache_arb` 连 L2，流水分 st0~st3 四级。核心结论是：为不阻塞后续命中、隐藏 GPU 访存延迟，缺失处理由 MSHR 承担。引入的关键术语包括：MSHR（缺失状态保持寄存器）、主缺失/次缺失、entry×subentry 二级表（`DCACHE_MSHRENTRY=4`×`DCACHE_MSHRSUBENTRY=2`，最多 4 块在飞、8 个等待请求）、5 态状态机、probe 探查、targetinfo、`source` 字段（类型标签+entry/wshr 号+setidx）。最小模块涵盖：顶层 `l1_dcache`（主板）、`dcache_control`（`{opcode,param}` 译码，覆盖 read/write/lr/sc/amo/flush/invalidate/wait_mshr）、`tag_access_top_v2`（命中判定、LRU 替换、脏/有效位）、`l1_mshr`（缺失合并与回收）、`dcache_wshr`（写缓冲，按块地址去重，与 MSHR 对偶）。脏替换走 `memreq_arb.in0` 用 `TLAOP_PUTFULL` 先写回；读缺失用 `TLAOP_GET` 经 `in1`；三者靠固定优先级仲裁分时复用单一 A 通道，响应凭 `source` 路由回 MSHR entry 或 wshr 表项。`flush/invalidate` 须等 MSHR 与 wshr 排空。`mem_req/mem_rsp` 出 D-cache 后续接 `l1cache_arb`（u6-l3）与 TileLink 协议（u7-l1）。
