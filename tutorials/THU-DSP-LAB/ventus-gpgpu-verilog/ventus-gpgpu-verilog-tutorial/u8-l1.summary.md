本讲剖析 Ventus GPGPU 的仿真验证层，聚焦 `testcase/test_gpgpu_axi_top/` 下的 testbench。核心模块有四个：仿真顶层 `test_gpu_axi_top` 只做例化连线，把 DUT `gpgpu_axi_top`、时钟/复位、虚拟主机 `host_inter`、外部 RAM `axi_ram`、总指挥 `tc` 串成「主机→GPU→DRAM」闭环；`host_inter` 扮演虚拟主机 CPU，靠 AXI4-Lite 握手的 `drv_gpu` task 读 `.metadata` 描述符、写 16 个寄存器、最后写 reg[0]=1 触发 workgroup 派发，并用 `exe_finish` 轮询 reg[17]@0x44 等完成、统计 kernel_cycles；`axi_ram` 是行为级 AXI4 从端 RAM，含独立读写状态机与 `wstrb` 字节使能。关键结论：kernel 代码与数据并非 `$readmemh` 直灌 `mem`，而是 `tc.v::init_mem` 用 `force` 驱动 RAM 的 AXI4 从端口逐段 INCR burst 写入，同时验证写通路；`file_list.f` 中相对路径 `./tc.v` 让一套公共平台服务多用例；PASSED/FAILED 的真正判定在 `tc.v::print_result`，取硬件写回结果与硬编码黄金参考逐字比对。引入的关键术语：testbench、AXI4-Lite 控制通路与 AXI4 数据通路、`$readmemh`/`force-release`、层次化 task 调用、`drv_gpu`/`init_mem`/`exe_finish`/`print_result` 四件套。
