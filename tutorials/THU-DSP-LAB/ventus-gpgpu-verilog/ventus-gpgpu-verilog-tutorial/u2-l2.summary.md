本讲承接 u2-l1，回答「决定派给谁之后，如何把派发动作落实并回收完成信号」。聚焦 `cta_top/cta/` 下四个最小模块：`dis_controller` 是纯控制节拍器，用四态机串起「请求分配→等结果→回 ACK」，靠 `cu_groups_allocating` 组锁互斥避免并发改账本，且**回收优先于分配**；`inflight_wg_buffer` 以 waiting/ready 双表 RAM 缓存主机 WG 元数据（waiting 表供 allocator 算账，ready 表供派发），表满反压主机，并用 RR 轮转（`last_chosen_entry_rr`）公平选 WG；`gpu_interface` 把分配结果与元数据组装成对 CU 的逐拍握手，**每派发一个 warp 把 VGPR/SGPR 基址累加 per-wf size**（LDS 全 WG 共享故不递增），并例化 `NUMBER_CU` 个 `cu_handler`、在多 CU 间仲裁回收；`cu_handler`（每 CU 一个）管理 WF/WG slot，为每个 warp 生成唯一 **tag = {slot 号, warp 序号}**，按 tag 逐 warp 计数，WG 全部 warp 完成时上报 `wg_done`。关键术语：tag 位域、WG slot、逐 warp 递增基址、组锁、双表缓存、stream_fifo 削峰。核心结论：SM 侧派发字段不含 wg_id，WG 身份由 start_pc、各 base 与 tag 隐式携带；回收链末端用 `wf_done_interface_single` 的 stream_fifo 对集中完成的 wg_done 削峰后以握手交主机。
