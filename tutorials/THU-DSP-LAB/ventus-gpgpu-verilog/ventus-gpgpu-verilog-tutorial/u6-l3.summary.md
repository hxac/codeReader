`l1cache_arb` 是 SM 内部 L1 缓存与对外存储接口之间的纯组合仲裁器，规模由 `NUM_CACHE_IN_SM=2` 决定，**只仲裁 icache 与 dcache 两路**；shared_memory 命中即返回、永不缺失、不出 SM，直接旁路挂在 pipe 上，**不参与仲裁**（本讲最重要的认知纠正）。请求方向用固定优先级（icache>dcache）：`fixed_pri_arb` 选最低有效位得 one-hot grant，`one2bin` 转 binary 作为 MUX 下标把选中路字段接到对外 A 通道，ready 反压保证取指不被访存插队。响应方向借用 TileLink source 字段做路由标签：请求时把 cache_id 拼进 source 高位（`D_SOURCE=NUM_CACHE_DEPTH+A_SOURCE`），响应时按 source 高位解复用回对应 cache 并剥掉标签恢复 A_SOURCE 宽度，广播数据但仅目标路 valid 有效。此外，workgroup 完成后的冲刷由顶层 `wg_done` 产生 `cache_invalid`（目前仅驱动 SM[0]）：icache 直接整表无效，dcache 须等 `lsu_mshr_is_empty` 后注入 `opcode=3/param=0` 的 invalidate 请求，冲刷流量与正常访存共用同一条仲裁通路，待 L2 处理完发 `l2cache_finish_issue` 才拉起 `host_rsp_valid_o`。
