本讲是 CTA 调度器单元（u3）收尾，聚焦 `cu_interface` 与 `CTA2warp` 两模块，讲清 host 侧 WG 粒度到 CU 侧 WF 粒度的转换与资源回收。

`cu_interface` 是调度器链路的最后一棒：它从 `wg_buffer`/`allocator`/`resource_table` 三路汇合同一 WG 的不同侧面（三路齐备且下游可收才一起 fire，压入深度 2 的 FIFO），再用 splitter（倒计数器 `splitter_cnt` 加步进寄存器）把 WG 逐个拆成 WF 派发——sgpr/vgpr/pds 基址每发步进、lds 全 WG 共享不步进；每个 WF 携带 `wf_tag={wg_slot_id, wf_id}`（默认 6 bit，高 3 位为 wg_slot_id、低 3 位为 wf_id）作为 CU 与 SM 间的身份证，供后续 barrier 同步与 CSR_TID 计算使用。回程用三态 FSM（`GET_WF/UPDATE/DEALLOC`）仲裁各 CU 回报的 WF 完成，因完成计数存于 `SyncReadMem`、给地址后下一拍才出数据，故「读计数→比较→写回」须多拍完成；当某 WG 计数累加到 `num_wf` 即触发 `rt_dealloc` 向 resource_table 释放资源、`host_wg_done` 向 host 回报，与 u3-l2 的前向资源分配形成反向闭环。其 `init_ok`（清零完成计数）是整个调度器的启动闸门。

`CTA2warp` 在 SM 侧用位图 `idx_using` 配合 `PriorityEncoder` 分配/回收硬件 wid（0~7），并用 `data` 表维护 wid↔wf_tag 的双向翻译（去程存 wf_tag、回程还原），使 wid 作为 SM 私有标识对调度器透明。
