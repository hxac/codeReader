本讲打开 CTA 调度器中间两个核心零件——`allocator`（分配器）与 `resource_table`（资源表），以及夹在其间的 `RTcache`（资源表缓存）。

`allocator` 用主状态机 `IDLE → CU_PREFER → RESOURCE_CHECK → ALLOC/REJECT` 为每个待判定的 workgroup 选定一个能容纳它的 CU：轮询定首选 CU（`上次分配的 CU + 1`），逐个做容纳性判定，找到即分配、查完无解则 REJECT 让 `wg_buffer` 下轮重试。容纳性判定是「三类地址资源（LDS/sGPR/vGPR）的 RTcache 各至少有一块空闲片段不小于需求」与「WG slot 位图未满、WF slot 余量 ≥ num_wf」的「与」运算。`RTcache` 只缓存片段 size、语义为「≥」（用 `size=0` 代 valid），由 `rtcache_writer` 在「ALLOC 上升沿就地扣除选中片段」与「资源表 SCAN 回填」两种写来源间仲裁并写锁定，从而保证不超量分配。

核心设计取舍是**基址惰性求值**：分配器只选 CU，真实基址由 `resource_table` 在分配后遍历链表算出，且采用**最佳适配**（选最小可容纳片段）抑制碎片化。`resource_table` 为每 CU 每类资源各维护一张双向链表（`prev/next/addr1/addr2`，存于 SyncReadMem），ALLOC 子状态机 3 级流水找片段插节点，DEALLOC 仅做 O(1) 摘链不合并，SCAN 用 `sort3` 重算最大若干块回填 RTcache。顶层用 `alloc_record` 强制「全局最多一个 alloc 在途」，使三类资源基址三路对齐后经 `cuinterface_wg_new` 回送 cu_interface。本讲只送到 WG 级基址，warp 拆分留待 u3-l3。
