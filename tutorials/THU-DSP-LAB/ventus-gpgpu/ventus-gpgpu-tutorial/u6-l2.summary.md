本讲解析 Ventus L1 数据缓存（DataCache/DCache），夹在 LSU 与 L2 之间。核心结论：DCache 对**写命中**采用**写回（write-back）**——只更新数据 SRAM 并置 dirty，不立即写 L2；对**写缺失**采用**写不分配（write-no-allocate）**——直接旁路 PutPartial 发 L2、不取块进 cache。证据是 memReq 写来源仅含 dirty 替换、读·写缺失、invalidate/flush 三类，无"写命中即发"，并专门维护 dirty 追踪。对外有 coreReq/coreRsp（面向 LSU）与 memReq/memRsp（面向 L2）四组接口，且会反压 coreReq。引入的关键概念：两级 dirty 追踪（cacheline 粒度 way_dirty + 字节粒度 dirtyMaskAccess，脏块写回三时机：替换、无效化、冲刷）；MSHR 仅管读缺失，primary/secondary miss 合并，块返回时**直接递回 core**（区别于 ICache 的回填+重放）；DCacheWSHR（写状态保持寄存器）登记已发往 L2 未落库的在途写，用 conflict 信号拦截同 cacheline 后续读/写以避免写序违规；DCacheParameters 经 CDE 注入规模，数据 SRAM 按 word 分 bank 支持一拍部分写。默认 64KiB、2 路。
