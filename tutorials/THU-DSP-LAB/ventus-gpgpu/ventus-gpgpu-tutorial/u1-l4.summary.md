本讲打通「Verilog 到跑通首个测试用例」的路径。`sim-verilator/` 仿真框架由三部分组成：`libVentusRTL.so` 是被测的 GPU 板卡仿真模型，把 Chisel 硬件、物理内存与 kernel 按 workgroup 拆分一起建模，经 Verilator 编译并暴露一组 C API（`init`/`add_kernel`/`pmemcpy_h2d`/`step`/`pmemcpy_d2h`/`finish`）；mini driver（可执行 `sim-VentusRTL`）是调用这些 API 的示例程序，其 `main()` 走「取默认配置→解析参数生成 kernel→循环 step→dump 结果」四步；`testcase/` 提供 `vecadd`、`matadd` 测例。关键区别在于：仿真顶层是由 `top.emitVerilog` 生成的 `GPGPU_SimTop`（外挂仿真内存模型），不同于综合用的 `GPGPU_top`；用 `make -j run` 或 `make RELEASE=1 -j run` 构建并运行。一个测试用例由 `.metadata`（驱动视角而非硬件视角的 kernel 元信息，含 startaddr、kernel_size、wf_size、wg_size、寄存器用量、各 buffer 基址/大小，每个 uint64_t 占两行）、`.data`（按 buffer 顺序、小端序排列的初值）、`ventus_cmdargs.txt` 三类文件共同描述。核心 API `ventus_rtlsim_step` 每调用一次推进一个时钟周期，返回 ok/error/idle/time_exceed 作为终止条件；`--dump-mem BEGIN,END` 在仿真结束后按 4 字节一行导出物理内存以核对执行结果正确性。本讲引入的术语 kernel、workgroup/block、warp/wavefront、thread、CTA 调度、CSR 等将在 u2-l1 与 u3 单元展开。
