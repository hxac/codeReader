本讲（u3-l1）讲解 CTA 调度器的总体连接与入口缓冲 wg_buffer。调度器（cta_scheduler_top）夹在 host 与各 SM 之间，解决三件事：把 host 递交的 workgroup（WG）分配到资源足够的 SM，把 WG 拆成 warp（WF）逐个喂给 SM，运行结束后回收资源并回报 host。其内部由四大组件构成：wg_buffer 缓存并轮询喂送 WG；allocator 判定各 CU（=SM）剩余资源能否容纳并选目标 CU；resource_table 用链表记录各 CU 的资源基址与余量；cu_interface 负责 WG→WF 拆分派发与完成回收。关键结论是：调度器对 host 收发的是 WG、对 CU 收发的是 WF，这一粒度转换发生在 cu_interface；init_ok 闸门保证初始化完成前不接收 WG。wg_buffer 用双口 RAM wgram1/wgram2 分别存放资源字段与执行字段，配 wgram_valid/wgram_alloc 两位向量管理状态，每周期并行执行写新 WG、读 WG 给 allocator、处理 accept/reject 三个动作，靠 valid/alloc 锁与互斥断言保证互不冲突；地址挑选采用 RRPriorityEncoder 轮询编码器实现公平，被 reject 的 WG 清掉 alloc 位即可下轮重试而不丢失。allocator 状态机与 cu_interface 的 warp 拆分留待后续讲义。
