本讲讲解 chisel-npu 的开发环境与构建运行方式。核心构建链路为:Chisel/Scala 源码经 `sbt run` 运行 `top.Main`,触发 elaborate 生成 FIRRTL,再由 `firtool`(CIRCT 编译器)翻译成 SystemVerilog,产出仓库根目录的 `top.sv`;下游接 verilator/SystemC 做软件仿真,或 Vivado 做 FPGA 综合。引入的关键术语包括:elaborate(精细化)、FIRRTL、firtool、sbt、`build.sbt`(Scala 2.13.12 + Chisel 6.7.0 主依赖 + chiseltest 5.0.2 测试,配 chisel-plugin 编译插件)、`fangruil/chisel-dev` 开发镜像(打包 firtool 1.62.1、verilator v5.036、SystemC 3.0.1 及本地 `publishLocal` 的 Chisel 6.7.0)、Makefile(将 sbt 命令薄封装进 `docker run`,提供 image/container/test/build/build-sc/docs 等目标)。核心结论:项目优先用 Docker 而非裸机 sbt;最关键 gotcha 是 Makefile 目标名 `top.v` 与 `top.Main` 实际产出的 `top.sv` 不一致,导致 `make build` 每次必重新 elaborate,且 `build-sc` 需先改文件名;`build-fpga` 依赖宿主机 Vivado 跑综合,是 FPGA 上板流程入口(留待 U8)。
