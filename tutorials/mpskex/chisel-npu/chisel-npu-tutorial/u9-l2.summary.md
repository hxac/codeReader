本讲把视角从「单条测试」拉到「整个测试体系与 CI」。其一,测试目录镜像约定:`src/test/scala` 严格镜像 `src/main/scala`(alu/backend/isa/sram/utils),把路径里的 main 换成 test 即可定位;只有类名以 Spec 结尾、继承 AnyFlatSpec 的类才被 sbt 自动发现,utils/ 下放共享工具。其二,测试分两层:单元测试(如 InstrDecoderSpec)只 elaborate 小模块、组合求值、多 simulate 块,跑得快;集成测试(如 NCoreBackendQuantSpec)elaborate 整个 NCoreBackend,因 DUT 大、elaborate 成本高,把所有子用例合并进唯一一个 simulate 块只为付一次 elaborate 钱,并用 resetAddrs 在子用例间清状态;另有绕开硬件仿真的纯 Scala 属性测试。其三,CI 由 `.github/workflows/actions.yml` 定义:push/PR 到 main 或 releases/** 时,在 fangruil/chisel-dev:amd64 镜像里串行跑 Lint→Build(sbt run 产出 top.sv)→Test(sbt test),本地可用 make container 复现;日常单测入口为 tool/test-specific-spec.sh <全限定类名>,build.sbt 的 -oDT 按耗时排序打印用例。
