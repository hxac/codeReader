本讲精读 job.rs 手写的单值（oneshot）通道：Channel 仅由一个 AtomicU8 状态字与两个 UnsafeCell 字段构成，经 Arc 供两端共享，send/recv 均消费 self，「只传一次」由类型系统保证。核心结论：Pending/Waiting/Ready 三态相当于两阶段细粒度锁，静态划定 val 与 waiting_thread 的读写权限；recv 必须先写 waiting_thread、再 CAS 到 Waiting、最后 park，配合 park/unpark 的令牌语义（先 unpark 不丢失）杜绝丢失唤醒；send 以 swap 换成 Ready，仅当旧值为 Waiting 才 unpark。内存序成对记账：val 的可见性由 swap 的 Release 对 CAS 失败序 Acquire（或 unpark/park 同步）担保，waiting_thread 的可见性由 CAS 成功序 Release 对 swap 的 Acquire 担保。通道延迟到 pop_front 才创建，运载 catch_unwind 产生的 thread::Result；Box 加 repr(C) 使布局与 T 无关，为下讲 transmute 铺路；裸 park 未防虚假唤醒是遗留的信任边界。
