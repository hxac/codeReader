本讲建立 chili 的本地验证环与代码地图，分构建命令、目录结构、CI 流水线三块。核心结论：chili 是只有库目标的单 crate，lib.rs 承担公共接口与调度，私有模块 job.rs 封装任务与通道细节——JobStack 存闭包、Job 与 JobShared 表示任务、JobQueue 是本地队列、Channel/Sender/Receiver 回传结果；对外仅暴露 Scope、Config、ThreadPool 三个类型共八个方法。divan 与 rayon 仅为 dev 依赖，不进入下游依赖树；基准以 harness = false 自带入口。三条 deny lint 强制公共项写文档、unsafe 块写 SAFETY 注释。验证节奏：cargo check 类型检查最快，clippy 挑惯用法，cargo test 跑八个单元测试加十个 doctest，bench 按需。CI 五作业并行，前四个用稳定版；Miri 作业用 nightly 的 miri 解释执行、探测 unsafe 的未定义行为——经 nextest 排除最重的 join_very_long，再以 -Zmiri-many-seeds 对跨线程压力最大的 join_wait 多种子反复验证。
