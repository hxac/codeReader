本讲拆解 src/lib.rs 中唯一的心跳线程 execute_heartbeat。核心结论：心跳是周期性触发信号而非工作线程——它只把各计算线程的「心跳旗」（Arc<AtomicBool>）到期立起，提醒其在冷路径 heartbeat() 中把本地队列任务送上货架，自己不执行用户任务。Heartbeat 登记表持 Weak 弱引用，旗的强引用由 Scope 独占；Scope 死后 upgrade 失败，登记项由 retain 在持锁状态下惰性清理，无需显式注销。间隔采用均摊设计：睡眠步长 δ=H/N，使每线程实际心跳周期落在 [H, H+H/N]，代价是每周期 Θ(N²) 的扫描量。旗初始为 true 的「自举」让新 Scope 首次 join 即获得投递机会。心跳线程平时在条件变量 scope_created_from_thread_pool 上休眠，谓词「登记数 == num_workers 且未停机」恰等价于无用户工作（worker 旗常驻），仅用户创建 Scope 与停机会唤醒它，空闲池心跳开销为零。升旗/读旗一律 Relaxed，旗只是建议位，数据同步由互斥锁与 job.rs 的 Channel 保证。
