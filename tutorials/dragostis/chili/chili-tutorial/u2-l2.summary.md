本讲围绕 `ThreadPool` 本身讲解三个模块。其一 `Config`：仅含 `thread_count`（`Option<NonZero<usize>>`，语义为含调用线程在内的总计算线程数，故实际 worker 数 W = C − 1，因调用线程从不闲置；`NonZero` 保证减法不下溢；传 `None` 时用 `available_parallelism()` 探测，失败优雅降级为 0 个 worker）与 `heartbeat_interval`（默认 100µs，控制任务分享节奏）。`with_config` 启动时序为先 spawn W 个 worker、经 `Barrier(W+1)` 等全员就绪，最后才 spawn 唯一的心跳线程。其二全局池：`GLOBAL_THREAD_POOL` 以 `OnceLock` 实现惰性初始化与「只能设置一次」——`global()` 走 `get_or_init` 返回 `&'static` 引用，`set_global` 失败时经 `Err(self)` 把池原样退回且仍可用；全局池永不 Drop。其三 `Drop` 停机三步严格有序：持锁置位 `is_stopping`、`notify_all` 唤醒全部 worker 并 `notify_one` 唤醒心跳线程、先 join worker 再 join 心跳线程，worker 侧「先查标志再等待」配合杜绝丢失唤醒与死锁。另确立 `scope()` 借用签名约定的生命周期闭环，为下讲 worker 主循环与共享 `Context` 埋下伏笔。
