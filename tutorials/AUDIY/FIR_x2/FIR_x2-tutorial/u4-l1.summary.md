本讲聚焦 FIR_x2 中**系数侧的封装模块 FIR_COEF**：它把控制器 SPROM_CONT（管系数读地址）与存储原语 SPROM（管存取）拼成一个对外输出滤波器系数 `COEF_O` 的黑盒，自身不含任何数据逻辑，与数据侧的 DATA_BUFFER 同属「原语→控制器→封装」三层套路（`DATA_WIDTH` 在此实指系数位宽，是个命名陷阱）。

本讲核心结论是**过采样时钟的流水线对齐**：控制器给出的原始时钟 `LRCKx_O` / `BCKx_O` 不直通对外，而是再过 `p1`、`p2` 两级寄存器变成 `LRCKx2_O` / `BCKx2_O`，专门用来补偿系数从 ROM 读出的延迟。对齐的数学约束为**时钟打拍级数 N = ROM 读延迟 L**；顶层固定 `OUTPUT_REG="TRUE"` 时 N=L=2，于是 `COEF_O` 与 `LRCKx2_O` 在输出端同拍变化。关键在于一个 `OUTPUT_REG` 参数通过 `generate` **同时**控制 SPROM 内的读延迟和 FIR_COEF 内的时钟取级（`p2` 还是 `p1`），把两条流水线焊在一起。

此外引入两条结构性分支：`LRCKx2` 由地址最高位派生故总可生成，无需兜底；`BCKx2` 多一个 `ADDR_WIDTH>=8` 阈值，地址够宽才走「派生+打拍」，否则兜底到 `MCLK_I`（派生细节留给 u4-l2）。本讲确立的「`LRCKx2` 是对齐后的过采样样点节拍」与「时钟随数据逐级打拍」思想，将延续至下游 MULT/ADD（u5）。
