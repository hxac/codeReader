# MULT：有符号乘法器与流水线寄存

## 1. 本讲目标

本讲聚焦 FIR_x2 运算通路的第一级——乘法器模块 `MULT`。学完本讲后，你应该能够：

- 理解 `MULT` 如何对 PCM 数据与滤波器系数做**有符号乘法**，以及为什么乘积位宽是 `DATA_WIDTH + COEF_WIDTH`。
- 看懂「输入寄存 → 组合乘法 → 输出寄存」这条两级流水线，并能数出从 `DATA_I/COEF_I` 到 `DATA_O` 经过了几个 MCLK。
- 理解过采样时钟 `LRCKx2`/`BCKx2` 在乘法级里**继续被打两拍**，以和数据保持时序对齐。
- 说清楚为什么乘法用 `assign` 而不是 `always` 实现，并能联系到 FPGA 厂商的 HDL 编码指南。

本讲承接 u2-l1 建立的「顶层实例化图谱」与 u4-l1/u4-l2 建立的「时钟随数据打拍」对齐思想，并为下一讲 u5-l2（累加器 ADD）做铺垫。

## 2. 前置知识

在学习本讲前，你需要先具备以下直觉（这些在前面讲义里已经建立）：

- **FIR 滤波的本质是卷积**：每个输出样点 = 一串历史输入样点 × 对应系数后求和。本讲的 `MULT` 负责「样点 × 系数」这一步，下一讲 `ADD` 负责「求和」。
- **单时钟域设计**：整个 FIR_x2 只有一个时钟 `MCLK_I`，`BCK`/`LRCK` 都被当作数据信号而非时钟（见 u2-l2）。
- **过采样时钟 `LRCKx2` 是「节拍信号」**：它不是外部 PLL 给的，而是由系数地址最高位派生、并且**随数据逐级寄存延迟**，以保证「时钟到达输出端」和「数据到达输出端」发生在同一拍（见 u4-l1）。
- **有符号数（two's complement，二补码）**：Verilog 里 `signed` 关键字决定乘法是否做符号扩展。负数用二补码表示，例如 16 位下 `FFFF` 表示 -1。
- **流水线寄存器**：在组合逻辑前后插入寄存器，可以把一条长组合路径切成几段短路径，从而提升电路能跑到的最高频率（Fmax）。

如果以上任一概念模糊，建议先回头读 u2-l2、u4-l1、u4-l2 再继续。

## 4. 核心概念与源码讲解

本讲按三个最小模块展开：

1. 有符号乘法与位宽扩展
2. 输入/输出流水线寄存
3. 过采样时钟延迟传递

### 4.1 有符号乘法与位宽扩展

#### 4.1.1 概念说明

FIR 卷积的核心运算是「样点 × 系数」。在音频场景里：

- 样点（PCM 数据）是有符号的（正弦波有正有负）。
- 系数（滤波器抽头）也是有符号的（线性相位 FIR 的系数对称，必然出现负值）。

所以这里**必须做有符号乘法**。如果误用无符号乘法，负数的二补码会被当成大正数，乘出来的结果完全错误。

位宽规则也很关键：一个 \(N\) 位有符号数与一个 \(M\) 位有符号数相乘，乘积**不会溢出**一个 \(N+M\) 位有符号表示。因此本讲里：

\[ \text{乘积位宽} = \text{DATA\_WIDTH} + \text{COEF\_WIDTH} = 32 + 16 = 48 \text{ 位（有符号）} \]

这个 48 位结果在顶层会经过 u5-l3 的饱和/截位处理，最终压缩回 32 位输出。

#### 4.1.2 核心流程

乘法本身在 `MULT` 里是**组合逻辑**（一个 `assign`），但它的两个输入操作数和它的输出结果都被寄存器夹住。最小流程是：

```text
DATA_I ──┐
         ├──> [输入寄存 p1] ──> [组合乘法 MULT_WIRE] ──> [输出寄存 p1] ──> DATA_O
COEF_I ──┘
```

注意三点：

1. **两个操作数先各自打一拍**（输入寄存 `DATAI_p1`、`COEF_p1`），再相乘。
2. **乘法用 `assign`**，结果是组合的 `MULT_WIRE`。
3. **乘积再打一拍**（输出寄存 `DATAO_p1`）才送出 `DATA_O`。

之所以把乘法做成「输入寄存 + 组合乘 + 输出寄存」的标准三明治结构，是为了让它能被综合工具干净地映射成 FPGA 里的**硬核 DSP 乘法器**（如 Xilinx DSP48、Intel/Altera DSP、Gowin DSP），这类硬核内部天然就是「输入寄存器 + 乘法器 + 输出/流水线寄存器」的结构。

#### 4.1.3 源码精读

先看端口与参数定义。`DATA_I`、`COEF_I`、`DATA_O` 都带 `signed` 关键字，这是做有符号乘法的前提：

[05_MULT/MULT.v:51-70](https://github.com/AUDIY/FIR_x2/blob/a06376b3aa726029e95f94f88236372533e650be/05_MULT/MULT.v#L51-L70) —— 定义 `DATA_WIDTH=32`、`COEF_WIDTH=16`、`ROM_ADDR_WIDTH=9` 三个参数；输入 `DATA_I`（32 位有符号）、`COEF_I`（16 位有符号），输出 `DATA_O`（48 位有符号 = `DATA_WIDTH+COEF_WIDTH`）。

内部寄存器声明里，乘法相关的三个寄存器也都标了 `signed`，且位宽严格对应：

[05_MULT/MULT.v:77-81](https://github.com/AUDIY/FIR_x2/blob/a06376b3aa726029e95f94f88236372533e650be/05_MULT/MULT.v#L77-L81) —— `DATAI_p1`（32 位有符号，数据输入寄存）、`COEF_p1`（16 位有符号，系数输入寄存）、`DATAO_p1`（48 位有符号，乘积输出寄存），以及 48 位有符号连线 `MULT_WIRE`。

真正的一行乘法在这里，注意它用的是 `assign`（组合逻辑），且两个操作数 `DATAI_p1`、`COEF_p1` 都已 `signed`，Verilog 会自动做符号扩展：

[05_MULT/MULT.v:94-96](https://github.com/AUDIY/FIR_x2/blob/a06376b3aa726029e95f94f88236372533e650be/05_MULT/MULT.v#L94-L96) —— 注释明确提示「乘法器的 assign 推荐写法随 FPGA 厂商而异，请查阅目标 FPGA 的 HDL 编码指南」，随后 `assign MULT_WIRE = DATAI_p1 * COEF_p1;`。

> 为什么位宽刚好是 48 而不会溢出？设样点 \(x \in [-2^{31},\, 2^{31}-1]\)、系数 \(h \in [-2^{15},\, 2^{15}-1]\)。乘积极端值为 \((-2^{31}) \times (-2^{15}) = 2^{46}\)，以及 \((-2^{31}) \times (2^{15}-1) \approx -2^{46}\)。48 位有符号表示范围为 \([-2^{47},\, 2^{47}-1]\)，足以容纳，故无溢出。

#### 4.1.4 代码实践

**实践目标**：亲手验证「有符号」关键字对乘法结果的影响。

**操作步骤**（纯源码阅读 + 推演，无需综合）：

1. 打开 [05_MULT/MULT.v:60-61](https://github.com/AUDIY/FIR_x2/blob/a06376b3aa726029e95f94f88236372533e650be/05_MULT/MULT.v#L60-L61)，确认 `DATA_I`、`COEF_I` 都声明为 `signed`。
2. 假设某时刻 `COEF_I = 16'hFFFF`（即系数 -1），`DATA_I = 32'd100`。
   - 按**有符号**乘法：\(100 \times (-1) = -100\)，48 位二补码 = `FFFFFFFFFFFFFF9C`。
   - 若误按**无符号**乘法：`FFFF` 被当作 65535，\(100 \times 65535 = 6553500\)，结果 = `000000000063FFEC`，符号完全错误。
3. 在 `MULT_TB` 里，`COEF_I` 来自 [05_MULT/MULT_TB.v:83-96](https://github.com/AUDIY/FIR_x2/blob/a06376b3aa726029e95f94f88236372533e650be/05_MULT/MULT_TB.v#L83-L96) 实例化的 `FIR_COEF`，系数由 `FIR512_x2_48000.hex` 加载（见 u4-l3），里面 `FFFF` 类负系数确实存在。

**需要观察的现象**：若在仿真波形里把 `DATA_O` 显示为**有符号十进制**，应能看到随输入正弦波 1 kHz 信号被乘以系数后，结果正负摆动；若误显示为无符号，会看到接近 48 位上限的大数跳变。

**预期结果**：`signed` 声明让乘法按二补码正确扩展，`DATA_O` 随 PCM 输入正负摆动。

**待本地验证**：具体十六进制数值请在本机 Questa 中跑 `MULT_TB`，在波形里把 `u_MULT/DATA_O` 的 radix 设为 Signed Decimal 后对照。

#### 4.1.5 小练习与答案

**练习 1**：如果把 `MULT.v` 里 `DATA_I` 和 `COEF_I` 的 `signed` 关键字都删掉（其余不变），乘积 `MULT_WIRE` 的数值会怎样变化？

**参考答案**：Verilog 中只要有一个操作数是无符号的，整个乘法就按无符号处理。删掉 `signed` 后，负系数（如 `FFFF`）会被当成大正数 65535，乘积变为很大的正值，后续累加结果全错。这正是音频数据通路必须用 `signed` 的原因。

**练习 2**：为什么乘积位宽是 48 位而不是 32 位？

**参考答案**：\(32 + 16 = 48\)。两个有符号数相乘，乘积位宽等于两者位宽之和才能保证不溢出。若强行截成 32 位，正弦波幅度大时就会溢出失真；项目把截位/饱和推迟到 u5-l3 的顶层最后一级统一处理。

### 4.2 输入/输出流水线寄存

#### 4.2.1 概念说明

光有一个组合乘法器还不够。在 FPGA 里，如果把「RAM 读出数据 → 直接进乘法器 → 直接输出」全做成一条长组合路径，这条路径太长，电路能跑到的时钟频率（Fmax）会很低。

解决办法是**流水线**：在组合乘法前后各插一级寄存器，把一条长路径切成两段短路径。`MULT` 模块正是这么做的：

- **输入寄存**（`DATAI_p1`、`COEF_p1`）：把操作数先锁存一拍，让乘法器拿到的是稳定的寄存器输出。
- **输出寄存**（`DATAO_p1`）：把乘积再锁存一拍，让下游（`ADD`）拿到的是稳定的寄存器输出。

这就是经典的「寄存输入 + 组合运算 + 寄存输出」结构，能最大化 Fmax，也最贴合硬核 DSP 块的内部结构。

#### 4.2.2 核心流程

从输入到输出，数据经历的两级寄存器如下（`↑` 表示一个 MCLK 上升沿）：

```text
周期 0:  DATA_I = A, COEF_I = C 已就绪
         ↑ 输入寄存采样:  DATAI_p1 <= A, COEF_p1 <= C
周期 1:  DATAI_p1 = A, COEF_p1 = C
         MULT_WIRE = A * C  (组合, 同周期内已成立)
         ↑ 输出寄存采样:  DATAO_p1 <= A * C
周期 2:  DATA_O = A * C  (对下游可见)
```

所以从 `DATA_I/COEF_I` 输入到 `DATA_O` 输出，**经历 2 个 MCLK 上升沿 = 2 拍延迟**。这条延迟数字是整条运算通路时序对齐的基准，下一节的时钟延迟必须与之匹配。

#### 4.2.3 源码精读

整个时序逻辑集中在一个 `always @(posedge MCLK_I)` 块里。注意输入寄存是无条件赋值（不带复位门控），而输出寄存带同步复位：

[05_MULT/MULT.v:84-92](https://github.com/AUDIY/FIR_x2/blob/a06376b3aa726029e95f94f88236372533e650be/05_MULT/MULT.v#L84-L92) —— `DATAI_p1 <= DATA_I`、`COEF_p1 <= COEF_I` 是输入寄存（第 89-90 行）；`DATAO_p1 <= (NRST_I == 1'b0) ? 0 : MULT_WIRE`（第 91 行）是输出寄存，复位时清零，否则锁存组合乘积。

输出连线把寄存器接出端口：

[05_MULT/MULT.v:100](https://github.com/AUDIY/FIR_x2/blob/a06376b3aa726029e95f94f88236372533e650be/05_MULT/MULT.v#L100) —— `assign DATA_O = DATAO_p1`，`DATA_O` 直接来自输出寄存器，不再有任何组合逻辑。

关于复位的一个设计细节值得注意：

- 第 77-79 行里，`DATAI_p1`、`COEF_p1`、`DATAO_p1` 的声明都带了初值（`= {WIDTH{1'b0}}`），这是给 FPGA 上电寄存器初值和仿真初始化用的。
- 但在 `always` 块里，**只有 `DATAO_p1` 受 `NRST_I` 门控**，`DATAI_p1`/`COEF_p1` 不受复位控制。这是一种常见的「按需复位」做法：只复位真正需要确定的输出，减小复位网络的扇出与布线压力。

> 小术语：**同步复位（synchronous reset）**指复位信号在时钟沿才生效（如这里的 `posedge MCLK_I` 下用 `NRST_I` 选择），相对的是异步复位（复位信号直接进寄存器异步清零端）。`MULT` 用的是同步复位。

**实践目标**：用 `MULT_TB` 仿真，亲手数出乘法流水线的级数与延迟。

**操作步骤**：

1. 进入 `05_MULT/Questa` 目录，运行 [05_MULT/Questa/MULT.bat](https://github.com/AUDIY/FIR_x2/blob/a06376b3aa726029e95f94f88236372533e650be/05_MULT/Questa/MULT.bat) —— 它先 `vlib`/`vmap` 建库，再按依赖顺序 `vlog` 编译各模块（存储原语 → 控制器 → 封装 → MULT → TB），最后 `vsim ... -do "run.do"` 启动仿真。
2. do 文件 [05_MULT/Questa/run.do:3-12](https://github.com/AUDIY/FIR_x2/blob/a06376b3aa726029e95f94f88236372533e650be/05_MULT/Questa/run.do#L3-L12) 会把 `u_MULT` 的端口信号加进波形，`run -all` 跑满 [05_MULT/MULT_TB.v:132](https://github.com/AUDIY/FIR_x2/blob/a06376b3aa726029e95f94f88236372533e650be/05_MULT/MULT_TB.v#L132) 设定的 `#400000 $finish` 时长。
3. 在波形里把 `DATA_I`、`DATAI_p1`、`MULT_WIRE`、`DATAO_p1`、`DATA_O` 都加上（内部信号用 `add wave` 手动加），对齐到一个 MCLK 网格。

**需要观察的现象**：

- `DATAI_p1` 比 `DATA_I` 晚 1 个 MCLK 上升沿。
- `MULT_WIRE`（组合）在 `DATAI_p1`/`COEF_p1` 更新的同一周期内就跟着变化。
- `DATAO_p1` 比 `MULT_WIRE` 晚 1 个 MCLK 上升沿。
- 因此 `DATA_O` 比 `DATA_I` 整体晚 2 个 MCLK。

**预期结果**：数出从 `DATA_I` 到 `DATA_O` 共 2 级寄存器、2 拍 MCLK 延迟。

**待本地验证**：波形绝对时间取决于仿真器，请以「级数 = 2、延迟 = 2 MCLK」为准，忽略绝对时间。

#### 4.2.5 小练习与答案

**练习 1**：如果把输出寄存 `DATAO_p1` 删掉、让 `DATA_O` 直接接 `MULT_WIRE`，对时序和功能分别有什么影响？

**参考答案**：功能上乘积数值不变（仍是 `DATAI_p1 * COEF_p1`），但延迟从 2 拍变成 1 拍，这会**破坏与下游 ADD、以及与时钟 LRCKx2 的对齐**（后者固定打 2 拍）。时序上，`MULT_WIRE → ADD` 这条组合路径变长，Fmax 下降。所以输出寄存既是性能优化，也是对齐所必需。

**练习 2**：为什么输入寄存 `DATAI_p1`/`COEF_p1` 不接复位，而输出寄存 `DATAO_p1` 接了复位？

**参考答案**：输出寄存是直接对外的乘积，复位时清零可避免上电瞬间把垃圾值喂给下游累加器；输入寄存只是暂存下一拍要乘的操作数，下一拍就会被新数据覆盖，复位意义不大，省掉还能减小复位扇出。

### 4.3 过采样时钟延迟传递

#### 4.3.1 概念说明

`MULT` 除了算乘法，还有一项容易被忽略但至关重要的职责：**把过采样时钟 `LRCKx2`/`BCKx2` 也跟着数据打两拍**。

为什么时钟也要打拍？回顾 u4-l1 的核心思想：过采样时钟 `LRCKx2` 是「标记当前在算哪个过采样样点」的节拍信号。数据每经过一级寄存器就晚一拍到达，如果时钟不打拍，时钟会比数据早到，下游 `ADD` 就会在错误的时刻去复位累加器、输出卷积和。

因此整条运算通路的设计契约是：**数据晚几拍，时钟也晚几拍，二者同步抵达下游**。`MULT` 贡献了 2 拍数据延迟，于是它也必须给时钟补上 2 拍延迟。

#### 4.3.2 核心流程

时钟在 `MULT` 内部的延迟路径：

```text
LRCKx2_I ──> [p1 寄存] ──> [p2 寄存] ──> LRCKx2_O     (固定 2 拍)

BCKx2_I  ──> [p1 寄存] ──> [p2 寄存] ──> BCKx2_O      (当 ROM_ADDR_WIDTH >= 8 时, 2 拍)
                                                     (否则 BCKx2_O 直接兜底到 MCLK_I)
```

注意 `BCKx2` 比 `LRCKx2` 多一道阈值判断 `ROM_ADDR_WIDTH >= 8`，这与 u4-l1/u4-l2 完全一致：`LRCKx` 由系数地址最高位派生、永远可得；而 `BCKx` 需要地址足够宽（位 7 存在）才能派生，地址不够宽时就兜底到 `MCLK_I`。本项目默认 `ROM_ADDR_WIDTH = 9`（512 抽头），满足 `>= 8`，走正常的 2 拍延迟路径。

#### 4.3.3 源码精读

时钟延迟寄存器在 `always` 块里紧跟在数据寄存器之后：

[05_MULT/MULT.v:85-88](https://github.com/AUDIY/FIR_x2/blob/a06376b3aa726029e95f94f88236372533e650be/05_MULT/MULT.v#L85-L88) —— `LRCKx2` 固定打两拍（`p1`、`p2`）；`BCKx2` 用 `(ROM_ADDR_WIDTH >= 8) ? ... : 1'b0` 门控，地址不够宽时把寄存器强制写 0。

输出选择在 `assign` 里完成：

[05_MULT/MULT.v:98-99](https://github.com/AUDIY/FIR_x2/blob/a06376b3aa726029e95f94f88236372533e650be/05_MULT/MULT.v#L98-L99) —— `assign LRCKx2_O = LRCKx2_p2`（取第二拍，固定 2 拍延迟）；`assign BCKx2_O = (ROM_ADDR_WIDTH >= 8) ? BCKx2_p2 : MCLK_I`（够宽取第二拍，否则兜底 `MCLK_I`）。

把数据延迟和时钟延迟对照起来看，就能验证「对齐契约」：

| 信号 | 在 MULT 内部寄存级数 | 延迟（MCLK） |
| --- | --- | --- |
| `DATA_I/COEF_I → DATA_O` | 输入寄存 1 + 输出寄存 1 | 2 |
| `LRCKx2_I → LRCKx2_O` | p1 + p2 | 2 |
| `BCKx2_I → BCKx2_O`（默认配置） | p1 + p2 | 2 |

三者都是 2 拍，因此 `DATA_O` 与 `LRCKx2_O`/`BCKx2_O` 在 `MULT` 输出端**同拍变化**，下游 `ADD` 可以放心用 `LRCKx2_O` 的下降沿去复位累加器。

再看顶层如何把 `MULT` 接进链路，确认这套延迟是嵌在真实数据通路里的：

[07_FIR_x2/FIR_x2.v:134-149](https://github.com/AUDIY/FIR_x2/blob/a06376b3aa726029e95f94f88236372533e650be/07_FIR_x2/FIR_x2.v#L134-L149) —— 顶层实例化 `u_MULT`：`DATA_I` 接数据缓冲输出 `RDATA`，`COEF_I` 接系数 ROM 输出 `COEF`，`LRCKx2_I/BCKx2_I` 接 `FIR_COEF` 已经打过 2 拍的 `LRCKx2_COEF/BCKx2_COEF`，`DATA_O` 送出 `MULT_DATA`，`LRCKx2_O/BCKx2_O` 作为 `LRCKx2_MULT/BCKx2_MULT` 继续往下传给 `ADD`。

注意顶层只传了 `DATA_WIDTH`、`COEF_WIDTH` 两个参数，`ROM_ADDR_WIDTH` 走 `MULT` 的默认值 9，因此 `BCKx2` 默认走 2 拍延迟路径，与 `LRCKx2` 一致。

**实践目标**：在波形里验证 `LRCKx2_O` 比 `LRCKx2_I` 晚 2 拍，且与 `DATA_O` 同拍变化。

**操作步骤**：

1. 复用 4.2.4 的 `MULT_TB` 仿真环境。`MULT_TB` 在 [05_MULT/MULT_TB.v:99-112](https://github.com/AUDIY/FIR_x2/blob/a06376b3aa726029e95f94f88236372533e650be/05_MULT/MULT_TB.v#L99-L112) 实例化 `u_MULT`，其 `LRCKx2_I/BCKx2_I` 来自前级 `FIR_COEF`（[05_MULT/MULT_TB.v:83-96](https://github.com/AUDIY/FIR_x2/blob/a06376b3aa726029e95f94f88236372533e650be/05_MULT/MULT_TB.v#L83-L96)）。
2. 在波形里同时加 `LRCKx2_I`、`LRCKx2_p1`、`LRCKx2_p2`、`LRCKx2_O` 以及 `DATA_O`。
3. 在某个 `LRCKx2_I` 翻转沿处，向后数 2 个 MCLK 上升沿。

**需要观察的现象**：

- `LRCKx2_O`（= `LRCKx2_p2`）的翻转比 `LRCKx2_I` 晚 2 个 MCLK 上升沿。
- 这 2 拍正好等于 `DATA_I → DATA_O` 的数据延迟，所以 `DATA_O` 更新的那一拍与 `LRCKx2_O` 翻转的那一拍对齐。

#### 4.3.5 小练习与答案

**练习 1**：如果把 `LRCKx2_O` 的输出从 `LRCKx2_p2` 改成 `LRCKx2_p1`（只打 1 拍），会出现什么问题？

**参考答案**：时钟会比数据早 1 拍到达下游 `ADD`。`ADD` 用 `LRCKx2` 的下降沿复位累加器并输出卷积和（见 u5-l2），时钟早到意味着它在乘积还没稳定时就触发输出，累加的是不完整/错位的数据，滤波结果会错。

**练习 2**：为什么 `BCKx2` 要用 `ROM_ADDR_WIDTH >= 8` 做阈值，而 `LRCKx2` 不需要？

**参考答案**：`LRCKx2` 由系数地址的**最高位**派生，任何地址宽度都有最高位，所以永远可得、不需兜底；`BCKx2` 需要地址的**第 7 位**（bit 7）派生，只有当地址宽度 ≥ 8 时该位才存在。地址不够宽（更短的滤波器）时无法派生 `BCKx2`，只能兜底到 `MCLK_I`。这与 u4-l2 中 `SPROM_CONT` 的派生逻辑完全对应。

3. **回答 `assign` vs `always` 的问题**：结合 [05_MULT/MULT.v:94-96](https://github.com/AUDIY/FIR_x2/blob/a06376b3aa726029e95f94f88236372533e650be/05_MULT/MULT.v#L94-L96) 的注释，说明为何乘法用 `assign DATAI_p1 * COEF_p1` 而不是写进 `always` 块（例如 `DATAO_p1 <= DATAI_p1 * COEF_p1`）。

**参考要点（用于自检）**：

- 寄存器级数：数据 2 级（输入 1 + 输出 1）、时钟 2 级（p1 + p2），组合乘法夹在数据两级之间。
- 时序图核心：`DATA_O` 与 `LRCKx2_O` 同拍变化（均比各自输入晚 2 个 MCLK）。
- `assign` 的理由：把乘法写成对**两个已寄存的 signed 操作数**的纯组合 `assign`，是各 FPGA 厂商 HDL 指南中**最容易被综合工具识别为硬核 DSP 乘法器**的写法；输入/输出寄存器则由 `always` 显式控制，可灵活决定哪些进 DSP 块内部、哪些留在普通逻辑单元。若把乘法塞进同一个 `always`，虽然多数工具仍能推断 DSP，但写法风格对不同厂商的识别成功率有差异，所以作者特意加了注释提醒「请查阅目标 FPGA 的 HDL 编码指南」。这正是项目把存储原语、乘法都隔离成可替换底层的「跨厂商移植」理念在乘法器上的体现（详见 u6-l4）。

> 这一综合实践不需要改源码、不需要综合，纯靠读图与推演即可完成，目的是让你把「数据延迟 = 时钟延迟 = 2 拍」的对齐契约刻进直觉。

## 6. 本讲小结

- `MULT` 做的是**有符号乘法**：`DATA_I`（32 位）、`COEF_I`（16 位）都声明 `signed`，乘积 `MULT_WIRE`/`DATA_O` 为 `DATA_WIDTH+COEF_WIDTH = 48` 位有符号，不会溢出。
- 数据通路是「输入寄存 `DATAI_p1`/`COEF_p1` → 组合乘法 `MULT_WIRE` → 输出寄存 `DATAO_p1`」的两级流水线，从输入到输出**延迟 2 个 MCLK**。
- 乘法本身用 `assign` 而非 `always`，是为了贴合各 FPGA 厂商 HDL 指南、可靠推断硬核 DSP 块；源码注释明确提醒写法随厂商而异。
- 过采样时钟 `LRCKx2` 固定打 2 拍（`p1`→`p2`）；`BCKx2` 在 `ROM_ADDR_WIDTH >= 8` 时同样打 2 拍，否则兜底 `MCLK_I`，与 u4-l1/u4-l2 的阈值逻辑一致。
- **对齐契约**：数据延迟 = 时钟延迟 = 2 拍，使 `DATA_O` 与 `LRCKx2_O` 在输出端同拍变化，下游 `ADD` 才能正确用 `LRCKx2` 下降沿复位累加器。
- 输出寄存 `DATAO_p1` 带同步复位（`NRST_I` 低时清零），输入寄存不复位——典型的「按需复位」做法。
