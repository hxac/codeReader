本讲承接 u6-l1，解决"最后一公里"：把 Python 输出的有符号十进制系数 `.txt` 转成硬件 ROM 能识别的定宽十六进制存储文件。核心脚本 `dec2hex.awk` 用**二补码**将有符号十进制转为定宽大写十六进制：负数 \(v\) 映射为 \(\text{max\_val}+v\)（\(\text{max\_val}=2^{\text{width}\times 4}\)），`width=4` 对应 16 位系数，输出零填充、定宽、大写，否则 `$readmemh` 会出错。关键约定：脚本逐行 **1:1 转换、不做任何地址重排**，`.hex` 顺序与 `.txt` 完全一致，系数落点由 `SPROM_CONT` 运行时镜像寻址（`~CADDR_REG`）保证（u4-l2）。

存储文件格式极朴素：每行一个值、行数 = ROM 深度 \(2^{\text{ADDR\_WIDTH}}\)、每行位数 = `DATA_WIDTH/4`；故系数 ROM（`SPROM`，16 位）每行 4 位，数据 RAM（`SDPRAM`，32 位）初始化文件 `BUFFER_INIT.hex` 每行 8 位。系数 ROM 用 `$readmemh` **强制**初始化，数据 RAM 初始化**可选**（传空串跳过）。

引入的术语供后续承接：**二补码定宽十六进制**、`$readmemh`、`.hex`（Questa 仿真约定）与 `.data`（Vivado 等硬件流程，由 `11_fir_gen/README.md` §3 规定）。二者**内容格式完全相同**，区别仅在扩展名与读取者，移植时用同一脚本重新生成、改扩展名即可，文件内容无需重写。成品 `08_hex/FIR512_x2_48000.hex` 即该流程的参考输出，可用 `diff` 强校验整条链路。
