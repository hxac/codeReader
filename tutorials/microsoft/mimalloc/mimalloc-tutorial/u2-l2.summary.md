本讲讲解 mimalloc 的三种 C++ 接入方式。其一，在唯一一个源文件中包含 mimalloc-new-delete.h，即可把 new/delete 全家族（含 nothrow、数组、sized、对齐版）替换为转发 mi_new/mi_free 的实现；因其中是非 inline 的全局函数定义，多处包含会链接期多重定义。mi_new 与 mi_malloc 的关键差别在于前者实现了 C++ OOM 契约：先调 get_new_handler，仍失败才抛 bad_alloc。Linux 下链接 override 库时无需此头，因为库内 alloc-override.c 已定义 new/delete。其二，mi_stl_allocator 是无状态 STL 分配器，allocate 走 mi_new_n、deallocate 走 mi_free、实例恒等，适合只替换个别容器。其三，mi_heap_stl_allocator 与 mi_heap_destroy_stl_allocator 以 shared_ptr 持有一等堆：前者末次引用时 mi_heap_delete 逐块释放，后者 deallocate 空转、由 mi_heap_destroy 整堆一次性回收，仅适合无外部资源的元素。释放时无需堆指针，靠 page map 从指针反查所属页与堆。
