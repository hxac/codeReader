本讲剖析 mimalloc 安全模式（secure mode）的核心缓解机制。MI_SECURE 并非布尔开关而是 0~5 的分级体系（cmake ON→4、FULL→5），级联出 MI_PADDING、MI_PADDING_CHECK_BYTES、MI_ENCODE_FREELIST、MI_PAGE_KEY_COUNT 四个功能宏，并在编译期强制页元数据与用户数据分离。所有随机量的熵源是自带的 ChaCha20 PRNG，按 theap 分叉，派生每页 keys 与 cookie。free list 指针以双 key 逐页编码，防伪造与防 key 泄露；解码后校验 next 必须同页，否则判定链表损坏。double free 检测已改由 padding canary 承担：free 时校验签名并顺手写墓碑，再次 free 比对即中，报 EAGAIN 不 abort；缓冲区溢出报 EFAULT，secure 下主动 abort。guard page 的本质是「decommit 置守卫、commit 撤守卫」的可逆原语，任何 secure 级别都保护 arena 元数据区，仅 FULL 为每个 mimalloc 页加尾守卫；地址与分配顺序随机化自低级别逐级生效。以上均为缓解而非保证。
