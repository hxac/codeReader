本讲围绕 `src/alloc-override.c` 讲解 mimalloc 如何不改业务代码、不重编译第三方库就全进程接管 `malloc`/`free`。核心是**符号抢占**：ELF 全局符号查找顺序为可执行文件→`LD_PRELOAD` 库→依赖库，mimalloc 导出同名符号即可胜出；GCC/Clang 用 `__attribute__((alias))` 让 `malloc` 与 `mi_malloc` 同地址零开销，因别名要求同一翻译单元，`alloc-override.c` 与 `free.c` 被 include 进 `alloc.c` 并由 `MI_IN_ALLOC_C` 守卫。编译期链路为 cmake `MI_OVERRIDE`→宏 `MI_MALLOC_OVERRIDE`，配 `-fno-builtin-malloc`；平台分支含 macOS `__interpose` 段与 MSVC CRT 定义。`__attribute__((constructor))` 使 `MIMALLOC_VERBOSE=1` 的版本横幅在 `main` 前打印，是覆盖生效的证据。三条途径：`LD_PRELOAD`（推荐）、`mimalloc.o` 优先链接、`mimalloc-override.h` 宏替换——后者有**跨堆指针混用**风险，`mi_free` 查不到归属页时 release 下静默忽略致泄漏。验证组合拳为 `nm -D`、verbose 输出与 `mi_is_in_heap_region`（依赖 page map）。
