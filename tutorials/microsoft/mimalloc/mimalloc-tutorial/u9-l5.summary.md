本讲为手册收官，回答两个工程问题：怎么证明分配器没写错、怎么证明它更快。核心是 track.h 的宏合同：向外部工具申报块生死（mi_track_malloc_size / mi_track_free_size）与内存三态（defined / undefined / noaccess），后端四选一——Valgrind 三态完整、ASAN 仅两态（undefined 降级为可访问）、ETW 只做事件画像、none 空宏零开销；free 申报尺寸须与 malloc 严格一致，MI_PADDING 关闭时块尾取整缝隙是越界检测盲区。追踪构建会改变代码形态（malloc 别名覆盖、debug 魔数填充、rep movsb 内联汇编均被禁用），其性能数据一律无效。test-wrong.c 以九类故意错误作验收尺：影子状态类工具在访问时刻抓错（连读越界都能抓），与 debug padding 在 free 时刻抓写穿形成互补，泄漏靠退出对账。基准方法论把 xmalloc-testN、larsonN、mstressN、leanN 等场景映射回分片 free list、一次 CAS 跨线程 free、abandon/reclaim 等设计根源；test-stress 明确禁作基准。集成走 find_package 或 vcpkg，A/B 性能对比须用无追踪 release 库配 LD_PRELOAD，并同时报告耗时与峰值 RSS。
