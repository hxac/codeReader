本讲打开「向 OS 要内存」黑盒，剖析 mimalloc 的平台抽象层：`include/mimalloc/prim.h` 以 21 个 `_mi_prim_*` 原语函数和能力表 `mi_os_mem_config_t` 构成接口合同，按内存映射、commit/reset、大页与 NUMA、时钟与进程信息、输出/环境/随机、线程六大族组织；`src/prim/prim.c` 是编译期选择器，用 `#include` 把 unix/windows/osx/wasi/emscripten 之一并入同一翻译单元，新平台只需实现这一层。unix 实现以 mmap/mprotect/madvise 打天下，reserve 与 commit 仅差 prot 参数，decommit/reset 用 MADV_DONTNEED/MADV_FREE，并以 syscall 直陷与静态原子标志度过自举期、自适应降级；windows 实现基于 VirtualAlloc 家族，靠 GetProcAddress 动态绑定新 API。核心结论：同一接口可承载相反的平台语义（如 `needs_recommit`、`has_partial_free`、`is_zero`），抽象层把这些差异全部吸收，使 os.c 及以上零 `#ifdef`；能力表在运行时探测填写，驱动整个分配器的策略分支。
