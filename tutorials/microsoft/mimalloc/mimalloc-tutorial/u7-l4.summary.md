本讲剖析 mimalloc v3 的 `mi_subproc_t`：它把原先进程级的静态状态（arena 数组、主堆、元数据堆 theap_meta、统计账本）收进一个结构体，使一个 OS 进程内可并存多个互相隔离的分配域，服务于 CPython 多解释器（每解释器一 GIL）场景。核心结论：subproc 是纯分配器概念而非 OS 进程；隔离体现为 arena 私有、abandoned 页不跨域认领、统计各自记账，任意页沿所有权链上行恒得同一 subproc。动态 subproc 的三件套（结构体、元堆、主堆）均从父 subproc 分配，销毁按「强销毁全部堆 → 并账回主 subproc → arena 整段归还 OS → 结构体还给父」进行，主 subproc 静态自举且不可销毁。线程经 `mi_subproc_add_current_thread` 登记，必须在线程创建后、首次分配前由新线程自己调用，违反则静默降级；page map 全局共享，跨 subproc 的 free 合法。关键术语：subproc、theap_meta、`tld->subproc` 终身定格、不透明的 `mi_subproc_id_t`、独占口径统计 `mi_subproc_stats_get_exclusive`。
