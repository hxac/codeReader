本讲覆盖两个最小模块：include/mimalloc.h（库唯一的公共 API 头文件，按标准接口、扩展分配、对齐、类型化宏、选项、POSIX/C++ 适配分区组织，版本宏 MI_MALLOC_VERSION 当前为 30500 即 v3.5.0）与 test/test-api.c（官方 API 用法示范，用 CHECK_BODY 宏让每个用例恰好执行一次并自动判定，构建产物名 mimalloc-test-api）。核心结论：mi_malloc/mi_zalloc/mi_calloc/mi_strdup 的入口实现都只有一行，先取当前线程默认 theap 再进内层，mi_calloc 额外做乘法溢出检查，释放统一用 mi_free；细粒度统计需 MI_STAT>=2，默认只在 debug 构建开启，release 构建连 blocks 段都不打印。引入的关键术语：默认 theap（线程本地堆，不带 heap 参数的 mi_ 函数第一步都取它）、size class/bin（一个 bin 即一种块规格，报表中 bin 行的 S/M/L/H 标记 small/medium/large/huge 四档尺寸）、MI_SMALL_SIZE_MAX（64 位下 1KiB 的小对象上限）、mi_usable_size（查已分配指针的实际可用字节）与 mi_good_size（查请求 n 字节会拿到多大块，无需真分配）的区别、统计五列 peak/total/current/block/total#（current=total−freed，行尾 not all freed 直接暴露泄漏）、选项系统（MIMALLOC_ 前缀环境变量与 mi_option_enable 等编程接口等价，程序内设置优先级更高，链路为 options.c 解析环境变量、init.c 退出时触发、stats.c 分 blocks/pages/arenas/process 四段打印）。综合实践用 mi_good_size 与 mi_usable_size 对照验证 size class 的台阶效应，为下一讲（u2-l1 三种免改码替换系统 malloc 的方式）及单元三的 size class 表铺垫。
