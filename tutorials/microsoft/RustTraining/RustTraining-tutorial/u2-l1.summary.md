本讲拆解此前被视为黑盒的 `cargo xtask` 命令，覆盖三个最小模块：一是根 Cargo.toml 为虚拟清单（只有 [workspace]、无 [package]），用 members 注册成员、resolver = "2" 固定依赖解析策略，Cargo.lock 与 target/ 由全体成员共享，因此根目录裸跑 cargo run 会失败，必须 --package 指定；二是 `cargo xtask` 的合法性完全来自仓库级 .cargo/config.toml 中的别名 `run --package xtask --`，别名按参数串展开、不经 shell，`--` 之后的内容原样传给进程，main 用 env::args().skip(1) 接收并按 match 分发到 build/serve/deploy/clean 四个任务；三是 xtask 模式＝普通 Rust 二进制 crate＋workspace 成员＋cargo 别名，相比 Makefile/shell 换来编译期检查与跨平台一致性，代价是依赖 Rust 工具链。该工具保持极小依赖面：标准库覆盖进程、文件与网络，唯一外部依赖 ctrlc 仅用于 serve 时以退出码 0 干净响应 Ctrl+C。后续讲义将精读 main 各分支、print_usage 的输出分流与 check_mdbook 子进程探测。
