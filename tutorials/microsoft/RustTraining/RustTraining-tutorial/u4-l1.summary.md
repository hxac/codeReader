本讲精读 GitHub Actions 流水线 pages.yml，为部署篇第一节。引入术语：workflow、触发器、job 与 step、GITHUB_TOKEN、artifact、environment、concurrency、restore-keys。核心结论：流水线以三道门禁开头——push 到 main 加手动 dispatch 触发、最小权限三连（contents 读、pages 写、id-token 写）、pages 并发组排队不取消；缓存键由 OS 与 Cargo.lock 哈希拼成并配前缀回退，缓存 ~/.cargo/bin 用于跳过重编 mdbook；build job 复用与本地相同的 cargo xtask deploy（CI 与本地单一构建入口），产出 docs/ 后上传为固定名 github-pages 的 artifact；deploy job 经 needs 串联，无 checkout、无工具链，仅消费 artifact 发布构建阶段的字节快照，并以 environment 回填站点 URL。已知盲区：单本书构建失败时 build_to 退出码仍为 0，流水线会绿色地部署缺书站点，排查需看 build 日志。
