本讲打开 u4-l2 留下的 runtime 黑盒，精读 docker/nginx.conf 与 compose 编排，是基础设施源码精读的收官一讲。核心结论：`try_files $uri $uri/ $uri.html =404` 以「字面文件→目录→补 .html」三级候选重建 GitHub Pages 的无扩展名链接兼容，xtask 开发服务器刻意不做这层；`add_header` 继承规则是「当前层有声明则父层全部作废」，迫使安全头在每个 location 重复声明，`always` 参数保证 404 响应也带头；缓存按资产分治——HTML 用 `no-cache` 可 304 重验证以保 rebuild 即时可见，静态资产用 `expires 1d` 折中，因 mdBook 资产 URL 不含内容哈希、rebuild 后同 URL 出新字节，故不能用 `immutable`；gzip 以 1KB 门槛与显式类型列表控制收益。运行时三防线：nginx-unprivileged 基镜像以 uid 101 监听 8080，免 root、免特权能力；compose 的 `no-new-privileges` 在内核层封死 exec 提权通道；healthcheck 双保险，`read_only` 为有意未启用的下一层加固。后续讲义可承接这些术语。
