本讲义精读 xtask 的入口层（main 函数），拆成三个最小模块。模块一「match 命令分发」：`env::args().skip(1)` 收集用户参数，`args.first().map(|s| s.as_str())` 把 `Option<&String>` 规整为 `Option<&str>` 后，用一个穷尽的 `match` 把 build/serve/deploy/clean 四个动词映射到对应 `cmd_*` 函数；`--help/-h/help` 与 `None`（空参）共用帮助分支，`Some(other)` 名字绑定兜底未知命令；`serve` 是「先 build 再 serve」的顺序组合，第一个参数之后的额外参数被静默忽略。手写 match 而非 clap 类解析库，是因子命令少且扁平。模块二「usage 与退出码」：`print_usage(code)` 身兼帮助文档、错误报告器、进程终结者三职，用 `&mut dyn Write` trait 对象让同一份文本按退出码选流——0 走 stdout、非 0 走 stderr，`let _ = writeln!` 吞掉断管错误，最后 `std::process::exit(code)` 终止进程。模块三「check_mdbook 依赖探测」：以 `mdbook --version` 一次性子进程探测，输出接 `Stdio::null()`，`.status()` 取退出状态，`.map(s.success()).unwrap_or(false)` 把「未找到」与「找到但失败」压扁成保守的 false；`cmd_build`/`cmd_deploy` 遵循「先检查后行动」（check-then-act），在任何副作用前以码 1 退出，故旧产物目录不被误删；探测不覆盖 mdbook-mermaid，其缺失只在逐书构建中暴露。`build_to` 与 `cmd_serve` 留作后续讲义的黑盒。
