本讲拆开 xtask 构建引擎 `build_to` 的黑盒，并辨析 `build` 与 `deploy` 两个子命令。`project_root` 用编译期宏 `env!("CARGO_MANIFEST_DIR")` 取清单目录的父级来定位仓库根，使构建路径与运行时 cwd 完全解耦；`build_to` 先删后建输出目录实现干净构建，遍历 `BOOKS` 注册表而非扫描磁盘，逐书以 `--dest-dir` 参数覆盖单书 `book.toml` 配置，将 mdbook 产物汇成统一站点；单本失败只打印告警不中断循环，进程退出码仍为 0；收尾写落地页并重建零字节 `.nojekyll`，让 GitHub Pages 跳过 Jekyll 处理。`build` 与 `deploy` 共用此引擎，仅差出口目录：`site/` 供 `cmd_serve` 本地预览，`docs/` 由 CI 上传发布 Pages，两者均不入库。落地页生成函数留待下一讲精读。
