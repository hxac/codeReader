本讲是全册收官，回答「仓库靠什么保证质量」与「改动怎么还回去」两个问题。仓库没有单元测试与 clippy CI，自动化质量体系仅三层：mdBook 严格构建、pages.yml 退出码门禁、docker.yml 冒烟 HTTP 断言，三者防护力递增而覆盖面递减。最大盲区在 xtask 的 build_to：单书构建失败仅打印告警、进程退出码仍为 0，流水线会全绿部署出含死链的站点；docker.yml 只断言 async-book 一本标本书，且因路径过滤，纯内容 PR 在 PR 阶段无任何 CI，本地 cargo xtask build 确认 7/7 是唯一门禁。贡献流程为 fork → branch → PR → CLA 签署，由 bot 自动判定，一次签署对微软各仓库通用。双许可证按内容性质划界：代码与配置走 MIT（仅保留声明），书的 Markdown 走 CC-BY-4.0（须署名、标明修改、附许可链接，且不得对下游加限制），微软商标不在授权内。关键术语：CLA、双许可证、退出码门禁、冒烟测试、路径过滤。
