本讲是收官实战，演示向 RustTraining 仓库端到端添加一本新书的全链路。最小模块三部分：一是新书骨架——一个含 `book.toml`、`src/SUMMARY.md` 与章节文件的目录，因 `additional-js` 相对书根解析，`mermaid.min.js` 与 `mermaid-init.js` 两个资产必须随书携带，`[preprocessor.mermaid]` 使 `mdbook-mermaid` 成为硬依赖；二是 BOOKS 注册——向 xtask 的 `BOOKS` 常量追加 `(slug, title, description, category)` 四元组即完成唯一代码改动，slug 身兼目录名、输出目录与卡片 href 三职，category 应复用现有五类以免标签与 CSS 配色双双退化；三是全链路自动收录——核心概念为「加法式扩展」：新增单元表现为纯增加数据而非修改逻辑，Pages 与 Docker 零改动的原因是单一构建入口、Docker `COPY . .` 整仓带入、deploy job 只发布 artifact 字节快照。关键结论：必须先建目录再注册，否则落地页生成不校验目录的死链卡片且退出码 0 掩盖问题；已知盲区为单书构建失败不报警、Docker 冒烟测试只盯 async-book、README 书籍表格需手动同步。
