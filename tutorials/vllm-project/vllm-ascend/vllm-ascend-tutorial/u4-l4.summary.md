本讲承接 u4-l2 前向终点 `_sample`，讲解 vllm-ascend 在 NPU 上的采样实现，含三个最小模块。采样器 `AscendSampler` 继承上游 `Sampler`，仅重写惩罚项与 top-k/top-p；随机采样用「指数分布+argmax」（Gumbel-max 技巧）替代 `torch.multinomial` 以避开 CPU-NPU 同步；TP 降采样路径 `enable_reduce_sample` 用 HCCL all-gather 拼接各卡候选，并将本地索引加 `rank*V_local` 还原成全局词表索引。惩罚项 repetition/frequency/presence 经 Triton-Ascend 内核就地改写 logits，无 Triton 时安全回退上游。拒绝采样 `AscendRejectionSampler` 服务投机解码验证：draft 与 target 按 token 维度（`cu_num_draft_tokens` 编排）逐位对齐，随机路径按 `u<p(d)/q(d)` 判接受，拒绝位从残差分布 `max(0,p-q)` 恢复（recovered token），全接受则补 bonus token；首个拒绝位即截断，用 argmax 与 should_skip 掩码向量化实现。Block Verify（累积乘积联合验证）与 Entropy Verify（基于熵的后验放宽）可提升接受率。核心结论：拒绝采样使最终分布与「仅用 target 采样」完全一致，实现无损加速。
