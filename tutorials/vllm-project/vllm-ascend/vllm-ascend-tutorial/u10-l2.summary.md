本讲讲清两件事：PD 分离（Prefill/Decode disaggregation）与 vllm-ascend 的 KV 传输连接器。PD 分离把算力密集的 prefill 与访存密集的 decode 拆到两套 NPU，用 `kv_role`（`kv_producer`/`kv_consumer`/`kv_both`）区分角色，P 节点算完 prompt 把 KV 发出，D 节点拉回后再 decode，避免重算。连接器分 scheduler/worker 双角色：前者在引擎核心决策「取不取」，后者在每个 worker 子进程执行真正的读写与网络传输，KV 加载与调度异步并行。三类后端定位不同：`MooncakeConnector`（P2P 直连、不显式保存）、`AscendStoreConnector`（KV Pool 池化、支持 layerwise 逐层 put/get、可命中复用）、`LMCacheAscendConnector`（复用 lmcache 生态的薄封装）；`AscendMultiConnector` 用来串挂多个子连接器。注册靠 `register_connector()` 登记到上游 `KVConnectorFactory`，对同名上游连接器用「pop 再注册」覆盖，全程零侵入。layerwise 模式强制 PIECEWISE 分段图模式。本次更新（#12852）的核心是 `consumer_is_to_put` 开关：`AscendStoreConnector` 的 layerwise 保存守卫从「consumer 无条件跳过」改为「consumer 且未开 `consumer_is_to_put` 才跳过」，使 MLA 等模型下 D 节点也能把 decode 出的 KV 回写进池，提升跨节点命中率，worker/scheduler 三处口径一致。
