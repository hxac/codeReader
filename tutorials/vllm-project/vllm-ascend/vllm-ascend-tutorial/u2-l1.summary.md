承接 u1-l5：插件被选中后，`NPUPlatform` 开始回答上游 vLLM 的硬件询问。本讲覆盖四个模块。首先，「身份注册」用一组静态类属性把 CUDA 概念逐个映射到 NPU：`device_type="npu"`、`dispatch_key="PrivateUse1"`（PyTorch 自定义后端 dispatch key）、`device_control_env_var="ASCEND_RT_VISIBLE_DEVICES"`，并默认走 `simple_compile_backend="eager"`（因 Ascend 有自己的 ACL Graph 方案）。关键术语还包括 `PlatformEnum.OOT`（树外插件标记）和钩子（基类预留、子类填写的回调）。其次，配置改写分布在三阶段：`pre_register_and_update`（注册期，打全局补丁、追加 ascend 量化选项）→ `apply_config_platform_defaults`（默认值注入，早于校验）→ `check_and_update_config`（最重的校验/改写阶段）。核心结论是「时机」至关重要：阶段 2 必须先注入 `max_cudagraph_capture_size` 默认值（去掉了上游 CUDA 的 `*2`，封顶 512），阶段 3 的 `_set_cudagraph_sizes()` 才能正确推导。再次，三个运行期钩子把上游路径改道到 Ascend：`get_attn_backend_cls` 以 `(use_mla, use_sparse, use_compress)` 三元组查表选注意力后端，`get_compile_backend` 返回 `AscendCompiler`，`get_pass_manager_cls` 返回 `GraphFusionPassManager`；这些钩子统一返回类路径字符串以延迟 import。最后，`_fix_incompatible_config` 是「配置守门员」，逐段把 GPU/ROCm 专属参数静默重置为安全值（如 `numa_bind→enable_cpu_binding`、RPC 超时抬高到 3000 以大于 HCCL 的 1836 秒下限），实现 GPU 配置到 NPU 的平滑迁移。此外，`get_device_total_memory` 故意抛 `NotImplementedError`，以避免 `torch_npu` 过早全局初始化。
