本讲承接 u1-l5，拆解 `NPUPlatform` 被选中后替上游 `Platform` 基类实现的内容。它用一组静态类属性完成「身份注册」，把 CUDA 概念逐个映射到 NPU：`device_type="npu"`、`dispatch_key="PrivateUse1"`（torch_npu 挂在 PyTorch 自定义后端）、`device_control_env_var="ASCEND_RT_VISIBLE_DEVICES"`，并标注 `PlatformEnum.OOT`（树外插件）；个别能力方法故意不实现，如 `get_device_total_memory` 抛 `NotImplementedError`，以免 torch_npu 过早全局初始化。

核心是配置改写的三阶段生命周期：`pre_register_and_update`（打全局补丁、追加 ascend 量化选项）→ `apply_config_platform_defaults`（注入 `sp_min_token_num`、`max_cudagraph_capture_size` 默认值，须早于校验）→ `check_and_update_config`（校验并行配置、调 `init_ascend_config` 解析 `additional_config`、改写编译/图模式、选 `worker_cls` 与调度器）；后阶段依赖前阶段注入的默认值，时机不可乱。

运行期三个钩子统一返回类路径字符串以延迟 import：`get_attn_backend_cls` 用 `(use_mla, use_sparse, use_compress)` 三元组查表选注意力后端，`get_compile_backend`/`get_pass_manager_cls` 把图编译改道到 `AscendCompiler` 与 `GraphFusionPassManager`。`_fix_incompatible_config` 作「配置守门员」逐段把 GPU/ROCm 专属参数重置为安全值（如 `numa_bind → enable_cpu_binding`、RPC 超时抬到 3000），让 GPU 配置平滑迁移。`#13484` 再把这批无状态助手从类方法下移为模块级函数，使类聚焦钩子契约、助手可独立测试。
