本讲介绍 vllm-ascend 的上下文并行注意力（Context Parallel，CP），实现形态为 DCP（Decode Context Parallel）：在 TP 组内部沿**序列维度**分片 KV cache，消除冗余存储且不增加进程数。核心开关是 `enable_dcp()`（`decode_context_parallel_size>1`），使各后端的 `get_impl_cls`/`get_builder_cls` 延迟 import 返回 CP 变体——CP 是后端的「特化」而非独立后端。平台按 `(use_mla,use_sparse,use_compress)` 路由到 GQA/MLA/SFA/DSA 后端，一个模型只走其一，故 MLA 与 SWA-MLA（SFA）可各自独立做 CP。`common_cp.py` 提供公共能力：`get_dcp_local_seq_lens`（interleave 感知的本地长度公式）、`DCPMetadataBuilderMixin`、`DCPImplMixin`（all-gather/all-to-all + LSE 合并）。三类后端分片策略各异：GQA 按 head 切并 gather query、MLA 在 `kv_lora_rank` 隐空间 gather 并恢复请求连续 KV、SFA 复制 indexer 分片大 KV 并重映射 sparse 索引、DSA-CP 按 token 切（需 SP 支持）。合并的数学核心是「在线 softmax」：每个 rank 算局部 $(O_i,l_i)$，经 $l=\log\sum_i\exp(l_i), O=\sum_i\exp(l_i-l)O_i$ 无损合并，与单卡全序列注意力数学等价。
