本讲为 Patch 机制总纲，含三个最小模块：Patch 框架、两阶段补丁、登记规范。核心结论：vllm-ascend 不改上游 vLLM 源码，而用 Monkey-patch 在运行时把上游函数/类替换为 Ascend 版本，遵循「捕获原对象 → 定义替换实现 → 重绑定到原模块」三步，且 import 补丁模块即生效。补丁经总闸 `adapt_patch(is_global_patch)` 分两阶段：取 True 触发 platform 补丁，在引擎核心子进程生效，影响调度/配置等全局逻辑；取 False 触发 worker 补丁，在每个 worker 子进程 `__init__` 生效，影响前向/算子。之所以分阶段，是因为 `spawn` 出的 worker 是全新解释器、不继承父进程补丁，且各进程关心的逻辑不同；`_ensure_global_patch` 提供「同进程一次」的幂等保证，而替换必须早于上游真正取用该符号。关键术语：Monkey-patch、platform/worker 补丁、`adapt_patch`、引擎核心子进程、worker 子进程、import 即打补丁、时机约束，以及登记簿五要素（What/Why/How/Related PR/Future Plan）。
