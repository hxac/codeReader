本讲是 vllm-ascend「Patch 机制」单元的总纲，阐明插件以运行时 Monkey-patch 替换上游 vLLM 的函数/类，实现「上游零侵入」的 NPU 适配。核心结论有三：其一，每个补丁遵循「捕获原对象 → 定义替换实现 → 重绑定到原模块命名空间」三步，import 补丁模块即生效，且必须早于上游取用该符号，否则替换无效；其二，补丁经总闸 `adapt_patch(is_global_patch)` 分两阶段应用——platform 补丁在引擎核心子进程生效，影响调度、配置等全局逻辑，worker 补丁在每个 worker 子进程 `__init__` 生效，影响模型前向与算子；之所以分阶段，是因为 vLLM 多进程架构下 spawn 出的 worker 是全新解释器、不继承父进程补丁，`_ensure_global_patch` 仅提供「同进程一次」的幂等保证；其三，`patch/__init__.py` 作为补丁登记簿，每个补丁须登记 What/Why/How/Related PR/Future Plan 五要素，兼作读者地图与维护者的退场清单。本讲引入的关键术语包括：Monkey-patch、Patch、Platform Patch、Worker Patch、adapt_patch 两阶段分流、幂等闸门 `_ensure_global_patch`、登记簿五要素。后续 u3-l2、u3-l3 将分别深入两类补丁的具体实现。
