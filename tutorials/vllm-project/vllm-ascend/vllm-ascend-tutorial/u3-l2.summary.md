本讲解析 patch/platform/ 下的平台级补丁：它们在引擎核心（EngineCore）子进程生效，由 NPUPlatform.pre_register_and_update 调用 adapt_patch(is_global_patch=True) 触发 import，影响调度、配置校验、KV 规划等全局逻辑，以此区别于 worker 子进程的 worker 补丁；_ensure_global_patch 保证每进程只打一次。主角 patch_fused_moe：因上游 FusedMoE 是工厂函数且模型按名直接 import，须先捕获原对象、再同时重绑定包 __init__ 与 layer 模块两处、且早于模型 import；runner_cls=None 时才注入 AscendMoERunner 为非破坏式默认，worker 侧仅 import 复用此补丁以免二次包装。另两类补丁均修正上游的 CUDA 假设：patch_kv_cache_utils 在多组+上下文并行时用 LCM×dcp 放宽限制（hash 块用 GCD）、patch_mamba_config 按 128 token 对齐块大小；patch_distributed 仅 310P 用 all_gather 模拟 broadcast/all_reduce，patch_use_v2_model_runner 用 property 只认环境变量。核心结论：补丁须早于上游取用符号、覆盖多处绑定、按上游形态（property/方法/类方法）替换、并以硬件门控避免误伤。
