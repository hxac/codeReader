本讲梳理 vllm-ascend 的测试与 CI 体系。测试分三层：UT 在 tests/ut/，多用 mock 脱离 NPU、可在 CPU 快速跑；E2E 在 tests/e2e/，按 one/two/four/eight_card 分目录、需真实 NPU；Nightly 在 tests/e2e/nightly/，跑大模型回归与 benchmark。pytest 在 pyproject.toml 集中注册 e2e_model、e2e_coverage 两个 marker，用于 E2E 分组统计与按需挑选。PR 不跑全量，而由 select_tests.py 配合 test_config.yaml 做「按 diff 选测试」的选择性调度——前者读 PR 改动、后者提供「源码路径→测试路径」映射与 runner 路由；default_cpu_ut 模块以 optional:false 保证每个 PR 全量跑 CPU UT 作为质量底线。PR 流水线 pr_test.yaml 是一条 job 链（pre-commit→select-tests→run-selected-tests→ci-gate），最终由稳定名字 ci-gate 汇总并挂分支保护，仅打 ready 标签才在 NPU 上实测。#13442 新增的 A5 夜间流水线 schedule_nightly_test_a5.yaml 走 workflow_dispatch、读 nightly_config.yaml 的 A5 矩阵做长周期全量回归与 benchmark，与 PR 的「按 diff 选测试」是两种完全不同的节奏。最后以 #12852 layerwise 缓冲复用的布局单测示范新特性如何落 UT：纯数据布局计算用假 KVCacheTensor 测 happy path、用非法配置测失败路径，归 distributed 模块、CPU UT 层。
