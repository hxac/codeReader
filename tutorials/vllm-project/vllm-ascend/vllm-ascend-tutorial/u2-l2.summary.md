本讲讲解 vllm-ascend 的配置体系，主角是 `AscendConfig`（`ascend_config.py`）与 `envs.py`。vLLM 通过 `--additional-config` 传入的 JSON 原样存入 `VllmConfig.additional_config` 这块「自由配置 dict」而不解释，由 `AscendConfig` 负责：它用 `.get(key, {})` 把 JSON 切成若干子 dict，分别喂给 `AscendCompilationConfig`、`EplbConfig`、`SchedulerConfig`、`FinegrainedTPConfig` 等子配置类（每个负责填默认值与校验）。配置值遵循「三级优先级」：`additional_config` 显式值 → 环境变量（带 deprecation 警告）→ 默认值，由 `_get_config_value` 统一实现。`AscendConfig` 用模块级 `_ASCEND_CONFIG` 做单例缓存，经 `init_ascend_config`（支持 refresh，供 RLHF/测试换配置）、`get_ascend_config`（只读）、`clear_ascend_config` 三函数管理生命周期，并在 `NPUPlatform.check_and_update_config` 第 431 行被构造。`envs.py` 则用 `env_variables` 字典（名→lambda）加模块级 `__getattr__`（PEP 562）实现惰性求值，按需读取环境变量并统一类型转换。项目正逐步把一批 `VLLM_ASCEND_*` 环境变量迁移到 `additional_config`，过渡期两者共存。关键术语：additional_config、AscendConfig 及其子配置类、`_get_config_value`、单例缓存、惰性求值。
