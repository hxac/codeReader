本讲专讲 vllm-ascend 的 worker 补丁（管「单卡前向」的 monkey-patch）。加载链路：每个 worker 子进程在 `NPUWorker.__init__` 前段调用 `adapt_patch()`（默认 `is_global_patch=False`），触发 `patch/worker/__init__.py` 按 `HAS_TRITON`/`is_310p()`/容错导入四组顺序 import 各补丁，import 即替换上游符号；因 spawn 子进程不继承父进程补丁，每个 worker 必须重打。归纳出四种改写手法：替换方法（`Cls.m=f`）、替换模块属性/函数（`mod.f=f`）、替换整个类（`mod.Cls=NewCls`）、复用 platform 补丁（仅 import 防 double-wrap）。典型实例：deepseek_v2、eagle3_init 重写 `__init__`/`forward` 修正权重布局与 PP 层号（类外定义的 `__init__` 须显式调 `nn.Module.__init__(self)`）；triton、rejection_sampler 把上游算子换 NPU 实现、无 Triton 走 PyTorch 回退；cudagraph 与 patch_v2 系列修正 `CudagraphDispatcher`、把 v2 runner 关键类换 Ascend 版、把投机解码图管理器换 ACL Graph。承接术语：两阶段补丁、import 即打补丁、double-wrap、登记簿、ACL Graph。
