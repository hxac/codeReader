本讲讲解 `NPUModelRunner`：它继承上游 `GPUModelRunner`，是每张 NPU 卡上真正跑前向的对象，采用「继承 + 最小重写」策略，仅在采样器、注意力后端、输入批、ACL Graph 及 CUDA→NPU 兼容（`_torch_cuda_wrapper`）处做特化。一次推理主链路为 `_update_states`→`_prepare_inputs`→`_build_attention_metadata`→`_model_forward`→`_sample`：由 `AscendAttentionState`（PrefillNoCache/DecodeOnly/ChunkedPrefill/SpecDecoding）判定本批状态，用携带 CPU 端 seq_lens 的 `AscendCommonAttentionMetadata`（避免 GPU→CPU 同步）构建元数据，并经 `_determine_batch_execution_and_padding` 选 NONE/PIECEWISE/FULL 图模式；前向在 `set_ascend_forward_context` 注入 MoE 通信方式与图模式。核心结论：`execute_model` 与 `sample_tokens` 拆分实现 v1 异步调度——前者算完 logits 暂存进 `ExecuteModelState` 返回 None，后者接力采样并在投机解码时调 `propose_draft_token_ids` 生成 draft token；稀疏 KV 卸载仅在初始化与元数据构建两处有挂载点，未开启时对普通路径透明。
