本讲剖析 vllm-ascend 在每张 NPU 卡上真正跑前向的对象 `NPUModelRunner`（位于 `vllm_ascend/worker/model_runner_v1.py`）。它继承上游 `GPUModelRunner` 而非从头实现，只在「NPU 与 GPU 行为不一致」处做最小改写，典型模式是先调 `super().xxx()` 再特化。初始化阶段的五条特化主线：用 `AscendSampler`、`get_attn_backend` 选 Ascend 注意力后端、`NPUInputBatch`、`_use_aclgraph` 替代 CUDA Graph，并用 `_torch_cuda_wrapper()` 把 `torch.cuda.*` 临时重定向到 `torch.npu.*` 以兼容父类初始化。一次推理主链路由 `execute_model` 与 `sample_tokens` 两方法承载：`_update_states`→`_prepare_inputs`→`_build_attention_metadata`→`_model_forward`→`_sample`。引入的关键术语包括：`AscendAttentionState` 状态机（PrefillNoCache/DecodeOnly/ChunkedPrefill/SpecDecoding 等）、携带 CPU 端 seq_lens 以避免 device→host 同步的 `AscendCommonAttentionMetadata`、图模式调度（NONE/PIECEWISE/FULL）以及 `set_ascend_forward_context`。核心结论：`execute_model` 返回 `None` 并把中间结果暂存进 `ExecuteModelState` 作为接力棒，由 `sample_tokens` 取出完成采样与记账，从而实现 vLLM v1 异步调度；投机解码在 `sample_tokens` 内经 `propose_draft_token_ids` 衔接。
