本讲讲解 vllm-ascend 如何从源码构建为可运行插件，覆盖依赖体系、构建环境变量与构建系统三块。核心结论是：vllm-ascend = 一个 Python 包 + 一堆按芯片型号编译的 C++/AscendC 内核。依赖分编译期（CANN 工具链/AscendC 编译器、CMake、pybind11）与运行期（torch、torch-npu、triton-ascend、CANN 运行库），CANN 兼具两者且须与上游 vLLM 四方对齐版本。所有构建参数集中在 `envs.py` 的 `env_variables` 字典，用 lambda + 模块级 `__getattr__` 实现惰性求值；三个关键变量是 `SOC_VERSION`（目标芯片）、`ASCEND_HOME_PATH`（CANN 路径）、`COMPILE_CUSTOM_KERNELS`（是否编内核）。`setup.py` 是总指挥，依次探测芯片、生成 `_build_info.py`（写入 `__device_type__`）、按开关决定是否注册扩展、先跑 `build_aclnn.sh` 再 CMake 编译。C++ 内核有两套：自带 AscendC 库 `vllm_ascend_kernels`（310P/950 跳过）和按芯片分批的 ACLNN 算子 `_cann_ops_custom`，外加 pybind11 模块 `vllm_ascend_C` 暴露给 Python。无 NPU 的 UT 环境设 `COMPILE_CUSTOM_KERNELS=0` 并给定 `SOC_VERSION` 即可跳过内核编译。
