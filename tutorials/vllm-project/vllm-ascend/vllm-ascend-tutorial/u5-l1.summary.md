本讲是 u5 注意力后端单元总纲，解析 `AscendAttentionBackend` 的注册与元数据机制。核心区分两套独立机制：`@register_backend` 把后端「登记」进 vLLM 注册表，`NPUPlatform.get_attn_backend_cls` 则按 `(use_mla, use_sparse, use_compress)` 三元组在运行期「选中」标准注意力后端（MLA/SFA/DSA 各有兄弟后端，u5-l2 详讲）。后端本身是「工厂+配置」三件套：`get_impl_cls` 返回真正算注意力的 Impl，`get_builder_cls` 返回元数据构建器，两者按 `enable_dcp()` 在普通实现与上下文并行实现（DCP，u5-l3）间分流。KV cache 形状为 `(2, num_blocks, block_size, num_kv_heads, head_size)`，第一维 2 用于叠放 Key(`[0]`)/Value(`[1]`)，内核块大小固定 128。元数据分两层：`AscendCommonAttentionMetadata`（含 NPU 必需的 CPU 端字段如 `seq_lens_cpu` 以避免 device→host 同步）经 builder 的 `build()` 翻译为每层 `AscendMetadata`；`AscendAttentionState` 五种枚举驱动算子分支；`AttentionMaskBuilder` 为 `@singleton` 单例，按需缓存因果/MLA/splitfuse 掩码。本次更新新增 FA3 选择分支、fiaV2 路径 K/V 的 `.contiguous()` 修复，以及稀疏掩码工具 `build_valid_topk_mask` 与稀疏 KV 卸载字段 `req_ids_tensor`/`token_to_req`，为后续稀疏注意力与上下文并行讲义奠基。
