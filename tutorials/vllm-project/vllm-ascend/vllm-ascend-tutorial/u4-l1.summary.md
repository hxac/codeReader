本讲聚焦执行主链路最贴硬件的一层 NPUWorker（继承 WorkerBase）：每个 worker 子进程的核心对象，负责单卡资源管理与生命周期编排，前向委托给 NPUModelRunner。生命周期主线为：`__init__` 先 `adapt_patch` 重打 worker 级补丁（spawn 子进程不继承父进程补丁）、建 `AscendConfig` 与 `SleepWakeupManager`；`init_device` 处理 DP 设备号偏移、NPU 绑定、HCCL 分布式世界与并行组；`load_model` 在睡眠模式下权重入 weights 内存池、建权重传输引擎；`compile_or_warm_up_model` 捕获 ACL Graph、ATB 预热、CPU 绑核；`determine_available_memory` 探测显存；`initialize_from_config` 在 kv_cache 池分配 KV 缓存。稳态 `execute_model` 仅做 PP/SP 衔接：非首 rank 用 `irecv_tensor_dict` 收 SchedulerOutput 对应的中间张量、委托前向、非末 rank 用 `isend_tensor_dict` 发出，异步发送句柄靠 `_pp_send_work` 跨轮回收。核心结论：#12852 分层 KV 复用时按 `factor=num_layers/num_tensors` 放大 `available_kv_cache_memory_bytes`（仅当 `has_layer_reuse`），使下游按物理缓冲数计块、逻辑每层容量不变；睡眠靠 `CaMemAllocator`（按 tag 卸载/恢复显存）与 `SleepWakeupManager`（清/重建 HCCL 与 ACL Graph）；#13337 中 `wake_up` 改用 `replace_parameter` 保留 MoE 的 `weight_loader`、并在 MTP 场景连同草稿模型恢复，保证「睡眠唤醒→在线权重更新」（`_weight_update_active` 三步状态机）链路完整；`check_health` 调 `npu-smi` 查硬件。
