本讲剖析 vllm-ascend 最贴硬件的一层 NPUWorker。它继承上游 WorkerBase，是每个 worker 子进程的核心对象，负责单卡资源管理与生命周期编排，前向委托给 NPUModelRunner（下一讲主题）。__init__ 须先 adapt_patch 重打 worker 级补丁（spawn 子进程不继承父进程补丁）；init_device 处理 DP 设备偏移、NPU 绑定与 HCCL 分布式世界及 TP/PP/EP 并行组；load_model→compile_or_warm_up_model（捕获 ACL Graph）→determine_available_memory→initialize_from_config 把模型装卡、调图、分好 KV 缓存；稳态 execute_model 是 PP/SP 衔接层，借 SchedulerOutput 与 IntermediateTensors 在 rank 间收发中间张量，异步发送句柄跨轮回收；sleep/wake_up 借 CaMemAllocator 内存池按 tag（weights/kv_cache）卸载/恢复显存，SleepWakeupManager 清理重建 HCCL 与 ACL Graph；在线权重更新由 _weight_update_active 驱动三步状态机；check_health 调 npu-smi。核心结论：#13337 让 wake_up 恢复 MoE 权重布局改用 replace_parameter 以保留 weight_loader（在线更新逐层调用的回调，不可丢），并在 MTP 场景一并恢复草稿模型；#13026 在显存额度计算处为稀疏 KV 卸载留调整钩子（详见 u10-l6）。
