本讲解析 PR #12852 的「分层 prefill KV 缓冲复用」，作用于 ascend_store layerwise prefill 卸载路径（memcache backend）。核心动机是：layerwise 卸载下同一时刻仅当前层需 KV 驻留 HBM，故可让 N 个逻辑层分时复用 K 块物理缓冲，回收显存并放大可用 KV 容量，且逻辑布局不变。

关键术语：逻辑层（KVCacheTensor 描述符）与物理缓冲的区分；新增的 `LayerwiseCacheLayout` 布局对象，含 `num_shared_buffers`、`storage_indices`（round-robin 分配）、`prefetch_layer_map`（复用依赖）、`has_layer_reuse`。

三条主线结论：一是映射规则——复用层在 K 块缓冲间轮转，`prefetch_layer_map[L]` 指向 L 前一轮的源层；二是内存核算放大——worker 按 `factor=num_layers/num_tensors` 放大可用显存，model_runner 在分配前用 `apply_layerwise_kv_cache_plan` 合并描述符，两步配套净得更大 `num_blocks` 而 HBM 不超；三是数据面时序——收发线程在 load 前 wait 复用源的 save 事件（保存完成后才复用），在 `attention_start_gate` 打开后才 batch_copy，decode 期复用缓冲每步必 save。

配套改动包括 partial block 改用请求级键（partial GVA）存取、batch_copy 失败由 log 改为 raise 经 raise_if_failed 传播，以及 sfa_v1 把 `record_attention_compute_start` 前移到 skip_topk 之前，使 GLM-5.2 等无 indexer、复用 top-k 的 SFA 层也能打开 prefetch gate。
