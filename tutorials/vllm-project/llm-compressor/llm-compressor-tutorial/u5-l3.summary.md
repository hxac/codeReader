本讲介绍 `model_free_ptq`：一条绕开 `oneshot` 整套引擎（session/lifecycle/recipe/pipeline）的快车道入口。它不实例化完整 `torch.nn.Module` 模型，而是直接对磁盘上的 safetensors 权重逐文件、逐张量做仅权重的 RTN 量化，适用于无 transformers 定义的模型、放不进内存的超大模型，或只需仅权重量化的场景。其边界由 `validate_scheme` 硬编码：必须 data-free（激活须为 dynamic），不支持 GPTQ/AWQ/SmoothQuant 等需校准数据的算法。主体是文件级批处理六阶段流水线：校验参数→复制配置→构建作业（多卡 round-robin 分配）→meta device 预校验→并行量化→更新 config 与索引。真正的量化发生在 `process_file` 的单张量四步法（初始化→校准→压缩→保存）：`lifecycle.py` 把每个 2D 权重临时包成 Linear，复用 `oneshot` 同款的取整三连（observe/update_qparams/freeze），因此两者 RTN 结果本质等价。microscale 方案（NVFP4/MXFP4）需跨融合伙伴（q/k/v、gate/up）共享 global scale，靠预计算的 inverse_weight_map 处理跨分片伙伴，旧的 `reindex_fused_weights` 预处理已废弃；末尾 `update_config` 写出 `quantization_config`，使产物可被 vLLM 按 compressed-tensors 格式加载。
