本讲是进入 core 核心引擎的第一篇，回答「oneshot 跑起来时模型、校准数据、recipe 存在哪里、谁在推进」。`CompressionSession` 是很薄的「会话容器」，只持有 `_lifecycle`；`session.state` 实为 `session._lifecycle.state`，state、recipe 与生命周期标志都住在 `CompressionLifecycle` 里。其 `initialize/event/finalize` 三方法均转发给 lifecycle 并把结果包成 `ModifiedState` 返回，`reset` 同样转发，由 lifecycle 收尾残留 modifier 并重置字段。

`State` 是压缩现场的「共享黑板」，承载 model/optimizer/loss，并通过 `Data`（四种数据集）、`Hardware`（设备/分布式）分槽存放，`update()` 做防御式赋值且默认 deepcopy 数据；`ModifiedState` 是 session 对外返回的标准结果包裹。

`active_session()` 借线程局部存储始终返回一个会话（默认 import 时建好的全局会话）；`create_session()` 是上下文管理器，with 内临时替换激活会话、退出后恢复。`LifecycleCallbacks`（别名 `callbacks`）把 `EventType` 封装成语义化方法，并禁止把 INITIALIZE/FINALIZE 当普通事件触发。本讲只读容器层，真正驱动 modifier 的 lifecycle 事件系统留待 u2-l2。
