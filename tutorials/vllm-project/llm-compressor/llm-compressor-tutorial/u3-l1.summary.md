本讲精读 `QuantizationModifier`：量化动作的统一入口，继承 `Modifier`（生命周期）与 `QuantizationMixin`（量化字段与 scheme 解析），自身只做 RTN（就近取整）。五个核心字段 `targets`/`ignore`/`scheme`/`config_groups`/`kv_cache_scheme` 中，`scheme` 与 `config_groups` 二选一，判断真实命中目标应用 `resolved_targets`。`scheme` 字符串经 `resolve_quantization_config` 归一化为 `config_groups`，二者等价，非法预设名在 `validate_scheme` 阶段即被拦截。核心结论：RTN 的权重取整精确发生在 `on_sequential_epoch_end` 钩子的 `observe(weight)`+`update_qparams(weight)`；前两钩子只挂方案与开关量化，末钩子卸 hook 并冻结。即使无需校准数据，`DataFreePipeline` 仍触发全部四个生命周期钩子，故 RTN（如 FP8_DYNAMIC、W4A16）能脱离 dataset 完成取整。`requires_calibration_data` 由 scheme 自动推断（静态激活、`imatrix_mse`、`kv_cache_scheme` 触发），进而决定 oneshot 选 sequential 或 datafree 管线。关键术语：量化（scale/zero-point）、scheme（W/A 命名）、RTN、observer、QuantizationConfig。
