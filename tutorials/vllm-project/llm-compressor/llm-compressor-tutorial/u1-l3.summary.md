本讲承接 u1-l1，带学习者打开 `src/llmcompressor` 包，建立「功能→子包」的定位直觉。核心结论有三：第一，顶层按职责划分为 `entrypoints`（入口集合）、`core`（会话/状态/生命周期引擎）、`modifiers`（压缩算法与工厂）、`pipelines`（校准管线）、`recipe`（配方）、`datasets`（校准数据）、`observers`（张量统计）、`modeling`（模型融合与适配），辅以 `args/utils/transformers/pytorch`。第二，包入口 `__init__.py` 把三组 API 提升到顶层：版本与日志、全局会话函数（`active_session/create_session/reset_session`，定义在 `core/session_functions.py`）、压缩入口（`oneshot/Oneshot/model_free_ptq`）。关键陷阱是：`__all__` 只收录版本与日志，但 `oneshot`、`active_session` 等仍是可访问的公开 API，判断公开 API 须看实际 import 而非 `__all__`。第三，`entrypoints` 是入口集合，门面仅转发：`oneshot()` 真正定义在 `entrypoints/oneshot.py`，`model_free_ptq` 在 `model_free/` 子包。本讲引入的关键设计模式是「门面导入即自动注册」（`pipelines` 用 `import *` 触发注册）与「门面只暴露骨架、具体算法靠 `ModifierFactory` 运行时遍历子包动态发现」。
