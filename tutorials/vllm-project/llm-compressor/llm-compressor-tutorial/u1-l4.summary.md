本讲剖析 oneshot() 入口与内部 Oneshot 类的关系。oneshot() 仅是薄包装：收集参数（含 **kwargs 兜底）构造 Oneshot 实例、调用并返回压缩模型，本身不含任何压缩逻辑。Oneshot 把工作组织为三阶段生命周期：预处理（pre_process）、校准（apply_recipe_modifiers）、后处理（post_process）。引入的关键概念：parse_args 借 HfArgumentParser 把 kwargs 按字段名归入 ModelArguments/DatasetArguments/RecipeArguments 三组参数类；全局 CompressionSession（承载 state 与 lifecycle）；校准管线 CalibrationPipeline 的四种类型及推断规则——有 modifier 需校准数据则用 sequential，否则 datafree，而 oneshot 默认 independent。校准阶段由 session.initialize 编译 recipe 并初始化各 modifier、from_modifiers 选管线、pipeline 跑前向、finalize 收尾串成一体；预处理阶段给 save_pretrained 打补丁以支持 compressed-tensors 序列化，为后处理阶段的保存铺路。
