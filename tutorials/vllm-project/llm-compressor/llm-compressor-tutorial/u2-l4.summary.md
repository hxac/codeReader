本讲解析 ModifierFactory：一个纯静态工具类，以「自动发现 + 按名字实例化」实现工厂模式，使 recipe 仅凭字符串类名即可拿到对象、无需 import 算法类。发现机制遍历 modifiers 子包、逐个导入，靠「类名以 Modifier 结尾 + issubclass 校验」两条判据挑出真实的 Modifier 子类，以类名作为注册表键。工厂维护三张分工明确的注册表：_main_registry（正式算法、自动发现、无门槛兜底）、_experimental_registry（需 allow_experimental 开启）、_registered_registry（用户经 register 写入、需 allow_registered、优先级最高），并以 _loaded 实现懒加载、_errors 暂存发现阶段的错误。关键设计是 deprecated 兼容垫片必须在导入之前靠前缀过滤排除，否则会触发弃用警告，并以同名函数（如旧 AWQModifier）污染名字空间、错误落入 _errors。create 按三级优先级查找并实例化；register 则把自定义 Modifier 纳入工厂。Recipe.from_dict 是工厂的主调用方：首次解析时触发 refresh，再对每个 recipe 名字调 create，把 YAML 字符串闭环转化为真实 Python 对象。本讲是 u2-l5（Recipe）与第六单元「自定义 Modifier」的直接前置。
