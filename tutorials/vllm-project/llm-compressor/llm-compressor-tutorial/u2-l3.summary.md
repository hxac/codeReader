本讲精读全库压缩算法的抽象基类 `Modifier`（声明为 `Modifier(ModifierInterface, HooksMixin)`），三重身份分别承担生命周期契约、PyTorch hook 管理与双生命周期骨架。基类采用模板方法模式：`initialize`/`update_event`/`finalize` 是带状态校验的公开骨架方法，真正的算法逻辑下放到 `on_*` 钩子；子类必须实现 `on_initialize`，其余钩子默认空、可选重写。引入的关键术语与概念：带下划线的 pydantic 私有运行时状态标志 `initialized_`/`finalized_`/`started_`/`ended_`（区别于被校验的配置字段 `start`/`end`/`update`）；`update_event` 先无条件跑 catch-all 钩子 `on_event`，再按事件类型分流到两条互斥链——**校准链**（`on_calibration_start`→`on_sequential_epoch_end`→`on_calibration_end`，服务 PTQ）与**训练链**（`on_start`/`on_update`/`on_end` 配合 `should_start`/`should_end` 门控，服务微调式压缩）。其中 `on_sequential_epoch_end` 的 `modules` 参数经管线透传，让逐层算法获知本轮处理哪些模块；`HooksMixin` 提供 `register_hook`/`disable_hooks`/`remove_hooks` 作为校准 hook 的基础设施，对应开始挂 hook、结束卸 hook 的成对用法。
