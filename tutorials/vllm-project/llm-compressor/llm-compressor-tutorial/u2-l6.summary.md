本讲拆解 oneshot 内部的**参数路由**机制，覆盖 `src/llmcompressor/args/` 下的 `parse_args` 与三个 dataclass（`ModelArguments`、`DatasetArguments`、`RecipeArguments`）。流程为：`oneshot()` 用 `locals()` 合并显式参数与 `**kwargs` 整体转发给 `Oneshot`；`Oneshot.__init__` 先截走 `log_dir`（用于日志，不参与路由），`parse_args` 再单独 `pop` 出 `output_dir`，然后用 transformers 的 `HfArgumentParser.parse_dict` 按字段名把剩余 kwargs 路由到三个 dataclass，解包顺序严格等于构造顺序。三个类的分工为：`ModelArguments`（模型加载/保存，`model` 为唯一必填字段）、`DatasetArguments`（校准数据采样与管线配置，含 `num_calibration_samples`）、`RecipeArguments`（压缩配方 `recipe`/`recipe_args`/`stage`）。关键设计：`pipeline` 与 `sequential_targets` 落在 `DatasetArguments` 而非 `RecipeArguments`，因二者由「数据→校准」链路消费；参数归属应以 dataclass 字段为准，而非 oneshot 注释分组。`parse_dict` 默认拒绝多余键，使拼错参数在路由阶段即报错（免费校验）。路由后还有三件后处理：`recipe_args` 列表转字典（值保持字符串）、对 `remove_columns`/`quantization_aware_calibration` 发弃用告警、`resolve_processor_from_model_args` 将 tokenizer 归一到 processor 并禁止二者同时出现。
