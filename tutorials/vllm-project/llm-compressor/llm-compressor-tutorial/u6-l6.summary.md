本讲（测试与贡献流程）是全手册收官篇，承接 u6-l4 自定义 Modifier，回答如何验证、过质量门并贡献回仓库。核心覆盖五个最小模块。其一，pytest 标记体系：七种 marker 集中注册于 pyproject.toml，用 `-m` 表达式筛选；声明不等于使用，`unit` 用得最多、`sanity` 实际无人用。其二，硬件门槛装饰器：`requires_gpu(N)`、`requires_gpu_mem`、`requires_compute_capability`、`requires_hf_token` 把硬件不足从失败降级为跳过；`torchrun` 装饰器靠 `TORCHELASTIC_RUN_ID` 区分主/子进程，实现「单进程调试、多进程执行」，并优先用设备无关的 `torch.accelerator.*`。其三，Makefile 四入口：`style`（自动修复）、`quality`（只读检查）、`test`（默认测试集，可用 `TARGETS` 开关 transformers/examples/sparsity）、`test-xpu`，标准闭环为 style→quality→test。其四，CI 流水线：`.buildkite` 总入口分发到 GPU（base/transformers 逐文件）与 XPU 两线，借助 `git diff` 与 `if_changed` 仅在相关变更时跑昂贵测试，并装 nightly compressed-tensors 做前置适配。其五，风格门槛 ruff（行宽 88、E/F/W/I 规则、isort 识别第一方包）与 mypy（仅查 src/llmcompressor），依赖集中于 setup.py 的 dev extras；贡献须先认领 issue 等绿灯、大型特性走 RFC。关键术语：pytest marker、skipif、requires_gpu、torchrun、ruff/mypy、Buildkite、if_changed 变更检测。
