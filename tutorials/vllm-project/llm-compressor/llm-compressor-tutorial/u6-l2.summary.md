本讲解决「模型大到连显存甚至内存都装不下时如何完成量化」的问题，核心是把压缩显存拆成三条战线——权重、激活、算法状态——每条都有对应的「搬走省内存」开关，本质都是用搬运时间换更低的峰值显存。

权重战线靠 **sequential onloading**：核心直觉是「交换两层 for 循环」，把外层遍历 batch、内层遍历层，改成外层遍历子图、内层遍历 batch，使同一时刻只有一份子图权重在显存。`set_onload_device` 声明权重搬到哪块卡，`disable_offloading` 让权重在子图处理期间常驻不回搬，`sequential_targets` 决定每次 onload 多少权重。CPU 内存也装不下时，权重磁盘 offloading（`load_offloaded_model` + `device_map="auto_offload"`，打包进 `load_context`）是最后防线，与 onloading 配合而非冲突。

激活战线靠 **IntermediatesCache**：写即 offload、读即 onload，使峰值激活与 batch 数解耦。关键概念有 `sequential_offload_device`（offload 到哪，默认 CPU，多卡建议 `cuda:1`）、`consumed_names`（最后一次使用后立即释放）、`sequential_prefetch`（后台线程 + 专用 CUDA 流预取下一 batch，用一点显存换速度，默认关闭）。

算法状态战线靠 **offload_hessians**：把 GPTQ 的 Hessian 常驻 CPU、用时临时 onload，用时间换显存，默认关闭（速度优先）。

最后引入 **norm_calibration_context**：这不是内存策略，而是超大模型常伴的新架构（Gemma/Qwen3Next 的 offset norm）正确性保障，校准期临时把 `output*(1+w)` 换成标准乘性 norm，保证 AWQ/SmoothQuant 等平滑算法正确，退出再转回。
