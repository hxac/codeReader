本讲解析 Recipe——把"如何压缩"翻译为机器可执行动作序列的中间层。Recipe 是 pydantic 容器，自身不执行压缩，持 `args`/`stage`/`modifiers` 三字段，其中 `modifiers` 才是最终被生命周期驱动的 `Modifier` 对象列表。`create_instance` 为多源总入口，按 Recipe→Modifier 或列表→文件→字符串的顺序分派，将异构输入统一归一。`from_dict` 依 `_stage`、`_modifiers` 后缀约定拆解 stage/group/modifier 三层结构，再由 `ModifierFactory.create` 把类名字符串实例化，闭环 u2-l4 工厂机制，解析前懒触发 `refresh()` 登记算法类。反向有 `dict()`/`yaml()` 序列化，剔除 None、下划线结尾运行时标志与 `group` 字段，支持按 stage 过滤及多 recipe 合并（冲突 stage 加数字后缀）。AWQ 变换 modifier 之后必须存在 `QuantizationMixin` 子类，由 `model_validator(mode="after")` 自动校验。解析—序列化—再解析往返无损，使 recipe 可作可存盘、可 diff 的配置。
