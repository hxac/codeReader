本讲聚焦 oneshot 中 `get_calibration_dataloader` 这一行背后的整条数据链路，解决「校准数据从哪来、如何加工、如何组装成 DataLoader」这一个问题，不涉及 DataLoader 之后校准管线如何消费数据。

数据层只有一个入口 `get_calibration_dataloader`，按 `dataset` 字段类型走三路分流：`None` 直接返回 `None`（供 RTN、FP8 动态等无数据算法，后续触发 `DataFreePipeline`）；传入 `DataLoader` 则原样旁路返回；传入 `str`/`Dataset` 则需加工。核心结论是三路的「信任程度」递减。

路径 C 由 `get_processed_dataset` 主导：若 Dataset 已含 `input_ids` 列走快速通道，否则以字符串名为 `registry_id`（非字符串统一记 `"custom"`）通过 `TextGenerationDataset.load_from_registry` 取处理类。内置数据集靠「注册表（`RegistryMixin`）+ 薄包装子类」实现，子类仅在 `__init__` 里 `deepcopy` 后改写真实 HF 名与 `text_column`，需要 prompt 模板的（gsm8k、open_platypus）另实现 `dataset_template`；`__init__.py` 的 import 触发「导入即注册」。

关键术语包括：`__call__` 七步流水线（加载→预处理→改列名→过滤→tokenize→可选拼接→加 labels）、`PROMPT_KEY`（用于将 prompt 掩成 `-100`）、`_preserve_tokenizer_state`（防 truncation 设置泄漏）。最终 `format_calibration_data` 装配 DataLoader，sampler 在 `RandomSampler`（shuffle）与 `LengthAwareSampler`（按长度降序省 padding）间二选一，collate_fn 在 `truncation`（截到最短）与 `padding`（补到最长）间二选一，核心旋钮为 `num_calibration_samples`（默认 512）、`batch_size`（默认 1）、`max_seq_length`。校准数据只供激活统计，不更新梯度。
