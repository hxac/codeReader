本讲讲解 llm-compressor 的四种剪枝 modifier。核心区别：剪枝把权重置零（产生稀疏张量或更小模块），量化则用低位表示稠密权重。关键术语包括稀疏度（零元素占比）、非结构化/结构化/N:M 稀疏（由 `mask_structure` 如 `"0:0"`/`"2:4"` 控制）、以及决定「剪谁」的 saliency 打分函数。`SparsityModifierBase` 是 SparseGPT 与 Wanda 共享的骨架，走校准链三步：`on_calibration_start` 用 `register_hook` 挂 forward hook 累积统计 → `on_sequential_epoch_end` 调 `compress_modules` 改权重并用 `update_offload_parameter` 写回 → `on_calibration_end` 卸 hook，差异仅在 `calibrate_module`/`compress_modules` 两个抽象方法。Wanda 打分 $|w|\sqrt{s}$（$s$ 为激活列范数平方，仅需向量统计，轻量快速）；SparseGPT 用 Hessian $H=2X^\top X$ 的逆做逐块最优误差补偿（与 GPTQ 共享 Hessian 数学，求逆失败退化为简单置零）。MagnitudePruningModifier 不继承该基类，打分纯 $|w|$、无需校准数据，改走训练链（`on_start`/`on_update`/`on_end`）配合稀疏度调度器。REAPPruningModifier 是唯一的结构化剪枝，针对 MoE 专家打分 $S_j=\text{mean}(g_j\cdot\|f_j\|_2)$，剪完真正删除专家模块、裁剪路由器并更新 config，且要求 recipe 中唯一。
