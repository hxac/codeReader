`CompressionLifecycle` 是 llmcompressor 事件系统的「发动机」，承接 u2-l1 的会话与状态概念。它持有 `state`（共享黑板）和 `recipe`（有序 modifier 列表），对外暴露三个核心方法：`initialize`（头，编译 recipe 并逐个初始化 modifier）、`event`（中，把事件广播给每个 modifier 的 `update_event`）、`finalize`（尾，逐个收尾）；session 只是把这些方法转发给 lifecycle 的门面。事件系统由两部分构成：`EventType` 枚举（事件「词汇表」，分端点、训练 batch 生命周期、校准生命周期三组）与 `Event` 数据类（携带 `global_step`/`current_index` 等上下文）。`INITIALIZE`/`FINALIZE` 虽在枚举内，却只能经专用方法触发。`event()` 带三层保护：状态保护、端点保护、顺序保护；顺序校验只约束训练事件（由 `_event_order` 与 `_last_event_type` 游标实现，`BATCH_START` 不可连续，其余满足下标递增），校准事件走独立轨道、不更新游标。`global_step` 在 PTQ 校准中通常「沉默」，门控主要服务训练式压缩。`LifecycleCallbacks` 是语义化门面，pipeline（sequential/basic/datafree）在固定时机触发 `CALIBRATION_START`/`SEQUENTIAL_EPOCH_END`/`CALIBRATION_END`，independent 则把每个 modifier 委派给子管线。关键术语：钩子（hook）、`update_event` 分发器（先 catch-all 的 `on_event` 再按类型分流）、`current_index`/`should_update` 训练门控，为 u2-l3 modifier 基类精读铺垫。
