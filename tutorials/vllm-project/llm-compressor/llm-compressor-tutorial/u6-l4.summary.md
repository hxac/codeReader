本讲讲解 llmcompressor 的第一个扩展点——如何编写自定义 Modifier。它把压缩算法做成可插拔模块：任何压缩动作只要实现 `Modifier` 子类，就能与 `oneshot`、校准管线、recipe、保存流程无缝拼接，像内置算法（GPTQ、AWQ、REAP）一样被调用。

内容拆为四个最小模块。其一，最小实现骨架：分清三层——`ModifierInterface`（对外契约）、`Modifier`（带状态校验的模板方法外壳）、`on_*` 钩子（算法逻辑住处）。`on_initialize` 是唯一必须实现的抽象钩子，校准链钩子（`on_calibration_start`、`on_sequential_epoch_end`、`on_calibration_end`）按需重写，由管线在固定时机触发，modifier 永不自己 fire 事件。其二，参数与运行时状态：配置参数声明为 Pydantic 字段（`model_config = ConfigDict(extra="forbid")` 拒绝拼错字段），跨 batch 的运行时缓存用 `PrivateAttr`（不参与序列化、可变默认值用 factory），目标模块用 `compressed_tensors.utils.match_named_modules` 按 `targets`/`ignore` 筛选，校验应尽量前置（`model_validator` 或 `on_initialize`）。其三，注册与使用两条路径：直接传 Python 对象给 `oneshot(recipe=[...])` 无需注册；或 `ModifierFactory.register(name, cls)` 写入优先级最高的 `_registered_registry`，随后 YAML recipe 用类名字符串调用（`create` 带 `allow_registered=True`）。其四，量化能力复用：若算法需把权重/激活映射成低位整数，双继承 `(Modifier, QuantizationMixin)` 即可免费拿到 scheme/observer/hook 的全套装备管理，自己只需在钩子里调取整三连（`observe`/`update_qparams`）。核心结论：自定义 modifier = 继承 `Modifier`、声明字段与钩子、选择调用路径、在校准链钩子里改权重；参考样板为 REAP（纯 Modifier）与 QuantizationModifier/GPTQModifier（双继承量化）。本讲引入的关键术语——`on_*` 钩子、校准链、`PrivateAttr`、`extra="forbid"`、`ModifierFactory.register`、`_registered_registry`、`QuantizationMixin` 双继承——将供后续「自定义 Observer」等讲义承接。
