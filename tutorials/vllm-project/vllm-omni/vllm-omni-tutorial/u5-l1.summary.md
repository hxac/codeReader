本讲剖析 vllm-omni 扩散推理子系统的编排者 `DiffusionEngine`。核心定位是「编排者不下场」：它只负责请求准入、调度/执行器协调、统一输出流投递、取消清理与启动预热，把真正的前向算子委托给多进程执行器 `MultiprocDiffusionExecutor` 的 worker 进程，引擎内不出现 `transformer.forward`。关键概念有二：其一为两种执行模式 `REQUEST_BATCH` 与 `STEP_BATCH`，分别绑定 `execute_batch`（一次跑完整条 `pipeline.forward`）与 `execute_step`（按步推进 `prepare_encode/denoise_step/step_scheduler/post_decode`），由 `OmniDiffusionConfig` 的 `step_execution`、`streaming_output`（流式强制步执行）、`max_num_seqs` 与 pipeline 声明的 `supports_request_batch` 共同判定，并对应 `RequestScheduler`/`StepScheduler`。其二为统一输出流：流式与非流式调用方消费同一条 `asyncio.Queue[DiffusionOutput]`，后台 busy loop 在普通线程投递，靠 `loop.call_soon_threadsafe` 跨线程安全；STEP_BATCH 逐步出中间块，REQUEST_BATCH 仅在 finished 时投递。`DiffusionOutput` 是承载结果、错误态、中止态、流式块信息与 `to_cpu` 标志的跨进程容器；pre/post 处理函数采用注册表模式，以模型架构名为 key 查表动态挂载。本讲只覆盖引擎外壳，调度器、worker、pipeline 内部数据流留给 u5-l2/l3/l4。
