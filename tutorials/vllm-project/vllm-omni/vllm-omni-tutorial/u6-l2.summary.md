本讲拆解 vLLM-Omni 多模态端点层的四个 serving 模块——它们只做请求翻译与输出打包，自身不跑模型。`OmniOpenAIServingChat` 承载 `/v1/chat/completions`，是最万能的端点，靠 `request.modalities` 与 `is_single_stage_diffusion` 在「扩散快路径」和「多阶段 LLM 路径」间分流，用 `_extract_diffusion_prompt_and_media` 摊平多模态 content，扩散参数经 `extra_body` 透传并由 `_normalize_diffusion_request_args` 归一化。`OmniOpenAIServingVideo` 仅服务 diffusion stage，用 ReferenceImage/ReferenceVideo/ReferenceAudio 支撑 text/image/speech-to-video（image 与 video 互斥，audio 可与 image 共存），遵循「只覆盖用户显式字段」与深拷贝防泄漏两个原则。两个语音端点本质不同：`/v1/audio/speech` 是 TTS（AR 后端、`SamplingParams`），`/v1/audio/generate` 是扩散音频（`OmniDiffusionSamplingParams`）；TTS 靠 `_find_tts_stage`/`_detect_tts_model_type` 按 `model_stage` 识别具体模型，并显式拒绝全模态 talker（应改用 chat 加 `modalities:["audio"]`）。引入的关键术语：stage_type/model_stage、依赖提供者、`OmniTextPrompt`，以及 tts_adapters 框架——`TTSModelAdapter`/`PreparedRequest`/`SpeechServingContext` 三个核心结构，分 `ARTTSAdapter` 与 `DiffusionTTSAdapter` 两个后端基类，其关键顺序约束是 `has_inline_ref_audio` 必须在 validate 之前抓取。
