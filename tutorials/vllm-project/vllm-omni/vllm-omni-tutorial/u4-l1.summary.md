本讲承接 u3-l3 的「每个 stage 是独立 EngineCore 子进程」，回答当某 stage 执行类型为自回归（AR）时其内部类如何继承 vLLM。核心结论：AR 模块以「继承而非重写」沿 vLLM 的 Scheduler/Worker/ModelRunner/Processor 四层派生子类——`OmniARScheduler`（在 `schedule()` 把请求富化为 `OmniNewRequestData`）、`OmniGPUWorkerBase`/`GPUARWorker`（进程级显存与 sleep/wake，并强制 v1 runner）、`OmniGPUModelRunner`/`GPUARModelRunner`、`MultimodalOutputProcessor`（按模态路由输出）。关键术语包括：两阶段 execute/sample——`GPUARModelRunner.execute_model()` 只跑前向并返回 `None`，把中间产物暂存进 `ExecuteModelState`，再由 `sample_tokens()` 取回采样并暴露每请求隐藏态与多模态输出，挂到 `OmniModelRunnerOutput.pooler_output`；该夹层是 AR 向下游 stage 交付语义向量的窗口。`OmniGPUModelRunner` 提供 AR 与 Generation 共享的 **prompt_embeds overlay**（按 prefill 分块把上游预计算 embedding 盖到 `inputs_embeds`）与 **additional_information / model_intermediate_buffer**（每请求运行期元数据透传进模型 kwargs）。本讲还区分了 AR 两阶段路径与 Generation 单阶段直接产出路径，并指出载荷（`prompt_embeds`/`additional_information`）因不被上游 vLLM 识别，需在多边界反复 `getattr` 捡回。
