本讲拆解 vLLM-Omni 两个 AR 调度器，按 execution_type 分派：LLM_AR 用 OmniARScheduler，LLM_GENERATION 用 OmniGenerationScheduler，DIFFUSION 不走这套。重构 PR #5461 把两者重复的「调度管道」上提到共享混入类 OmniSchedulerMixin，统一初始化、重包装请求为 OmniNewRequestData 并拼装输出，靠 model_mode、synthesize_abort_outputs 等开关表达差异。根本区别在 token 分配与结束判定：OmniARScheduler 委托 super().schedule() 增量分配，靠 EOS/max_tokens 多步结束并管 KV 迁移；OmniGenerationScheduler 走单步快路径，一次全量分配、输入算完即一步判完，服务 Code2wav 等基础异构结构。OmniNewRequestData 携带 additional_information、model_intermediate_buffer 等跨阶段载荷；下游等输入由 OmniSchedulingCoordinator 与 chunk_transfer_adapter 管理。
