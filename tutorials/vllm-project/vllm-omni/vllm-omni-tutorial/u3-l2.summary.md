本讲剖析 vLLM-Omni 多阶段运行时的核心组件 Orchestrator。它运行在独立后台线程的 asyncio 事件循环中，通过 janus.Queue（request_async_queue / output_async_queue）与主线程单向通信，内部并发两条路径：请求下沉（`_request_handler`，按消息类型分发，新请求硬编码从 stage 0 投递）与输出上浮（`_orchestration_loop`，主动轮询所有 stage 的所有副本，忙则不休、闲则让步）。阶段前推由 `_route_output` 的组合条件驱动，核心判据是 `stage_id < final_stage_id`（非最终阶段才前推），翻译并投递下一 stage 由 `_forward_to_next_stage` 按 diffusion/PD/AR 三分支完成。`OrchestratorRequestState` 用 `final_output_stage_ids ⊆ finished_final_output_stage_ids` 的子集判断决定请求整体完成，`stage_submit_ts` 兼作投递时间戳与重投判据。`StagePool` 是 Orchestrator 与子进程的中间层，统一 submit/poll 接口，经 `_pick_or_select` 在单机轮询与分布式负载均衡间无缝切换，删副本时置 None 以保 replica_id 下标稳定；可选的 OrchestratorMonitor 按秒采样忙闲比与副本积压以定位瓶颈。
