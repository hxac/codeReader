本讲讲解 vLLM-Omni 的输入输出数据容器。输入侧 `OmniPromptType` 联合 vLLM 原生 `PromptType` 与若干扩展类型，后者继承原生 prompt、仅新增可选字段（`prompt_embeds`/`additional_information`/`model_intermediate_buffer`）以保兼容；扩散阶段另用大型 dataclass `OmniDiffusionSamplingParams` 作参数口袋，仅代表单条 prompt（`batch_size=num_outputs_per_prompt`），经 `from_params` 归一化外部参数。跨阶段传输靠三组 msgspec 线缆载荷：张量拆字节的 `PromptEmbedsPayload`、张量/列表/标量三态的 `AdditionalInformationEntry`、汇总字典 `AdditionalInformationPayload`，最终装进 `OmniEngineCoreRequest`。核心链路为 `flatten_payload` 拍平成"类别.子键"再按值类型编码，由 `upgrade_to_omni_request` 在 input processor 之后捡回被丢弃的 omni 字段并升级请求，`OmniRequest` 在 stage 端把 payload 解码回张量。输出分三层：`OmniConnectorOutput`（调度信号）→ `OmniModelRunnerOutput`（一批结果，含 `multimodal_outputs`/`inter_stage_outputs`）→ `OmniRequestOutput`（用户统一容器，用 `from_diffusion`/`from_pipeline`/`from_error` 工厂方法与 `is_diffusion_output`/`is_pipeline_output` 判别属性同服扩散与流水线两模式）。演进上 `additional_information` 为 legacy 请求级通道、`model_intermediate_buffer` 为新 runner 拥有载荷，两者并存逐步迁移。
