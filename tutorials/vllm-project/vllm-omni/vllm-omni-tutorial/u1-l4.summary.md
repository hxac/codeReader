本讲介绍 vLLM-Omni 的**离线批处理推理**：在 Python 进程里直接调用类生成结果，不涉及起 HTTP 服务。核心入口是同步类 `Omni`（继承基类 `OmniBase`，异步入口为 `AsyncOmni`），最小调用即 `Omni(model=...).generate(prompt)`。实例化时构造 `AsyncOmniEngine` 并为模型建立若干 **stage（阶段）**，单阶段扩散模型（如 Z-Image-Turbo、Qwen-Image）仅有 1 个 diffusion stage。`generate` 接收 `OmniPromptType`（兼容 vLLM 原生与 Omni 扩展 prompt）与按 stage 的采样参数列表，扩散用 `OmniDiffusionSamplingParams`（尺寸/步数/seed/CFG），默认返回 `list[OmniRequestOutput]` 并阻塞轮询输出队列，图片可从 `images` 或 `request_output.images` 取得。`OmniRequestOutput` 是统一输出容器，用 `final_output_type`、`is_diffusion_output`、`num_images` 等字段同时描述扩散模式与多阶段流水线模式。核心机制：每条 prompt 是一个独立**逻辑请求**（独立 `request_id`，形如 `{i}_{uuid}`），运行时**可能**由 scheduler 把兼容请求自动批处理进一次去噪，是否触发取决于 `max_num_seqs` 等参数。官方脚本 `text_to_image.py` 封装了构造 prompt/采样参数→生成→多层兜底取图→保存的完整链路，但本身只接受单个 prompt。
