本讲是 vLLM-Omni 的「源码地图」，覆盖顶层目录全景、`vllm_omni` 包布局与初始化顺序、九大核心子系统目录、学习资源地图四个模块。

仓库顶层分四类：核心代码 `vllm_omni/`、使用示例 `examples/recipes/docs`、工程质量 `tests/benchmarks`、打包元数据。`vllm_omni` 包以「🟡 修改（Modified，用 monkey-patch 改写 vLLM）+ 🔴 新增（Added，如 Diffusion 引擎、OmniConnector）」二分法组织。`__init__.py` 按严格顺序初始化：version → patch → 注册 configs → 暴露 OmniModelConfig → 懒加载 Omni/AsyncOmni；version 必须早于 patch，以便版本不匹配时提前告警，懒加载则避免 import 时拖入重依赖致轻量子进程崩溃。

九大核心子系统对应架构五大组件：`entrypoints`/`engine`（EntryPoints）、`core`/`worker`（AR 自回归）、`diffusion`（DiT 扩散，最大新增模块，近似「迷你 vLLM」）、`distributed`（OmniConnector 全解耦）、`config`/`platforms`/`quantization`（跨组件基础）。引入术语：monkey-patch（猴子补丁）、stage（请求拆分的顺序子任务）、懒加载。`examples` 分 offline_inference（直接 import 类）与 online_serving（起服务用 HTTP 调）；`docs` 分 design（设计动机）与 contributing（工程流程）；`tests/` 镜像 `vllm_omni/` 结构，便于去同名测试佐证源码。
