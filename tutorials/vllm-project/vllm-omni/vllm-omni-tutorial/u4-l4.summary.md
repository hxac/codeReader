本讲是 AR 模块性能优化收口篇。核心结论：异步输出实例化把 `OmniModelRunnerOutput` 的 CPU 侧构造（D2H、张量切片、payload 拼装、连接器信号回收）从 AR 解码关键路径移到后台线程，使第 N 步 payload 构造与第 N+1 步 GPU 解码重叠，且不改生成结果（哈希对照验证）。

关键术语：`OmniAsyncGPUModelRunnerOutput` 继承上游 `AsyncGPUModelRunnerOutput`，保留采样 token 的异步反馈并叠加一个后台 builder 线程，`get_output()` 是完成与异常的唯一同步边界（join 并重抛后台异常）；安全快照靠「CUDA 张量 clone + 专用 stream 的 pinned 非阻塞 D2H + event」与下一步前向解耦；连接器信号为 runner-owned live 态，构造完 wire 后才活取。

启用由 `_should_use_async_omni_output()` 的 7 条运行时守卫自动判定（async scheduling、async_chunk、模型 opt-in、无前缀缓存/投机/routed-expert、postprocess 须 eager），无独立开关，任一不满足则静默回退同步。stage 差异：Thinker 全量快照，Talker 先 eager 跑 decode-state postprocess 再推迟 codec payload 并剔除 hidden，Code2Wav 因是 generation stage 不走本路径。它与 async chunk（阶段间流式切块）互为伴侣，分别负责块的异步构造与流式投递；Ascend NPU 用独立 `NPUARModelRunner` 仍同步构造。实测 Talker 相邻解码空隙由约 2.8ms 降至 41µs，并发 64 下吞吐 +22%。
