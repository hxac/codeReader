本讲剖析 vLLM-Omni 在线服务的 HTTP 外壳 api_server.py。核心结论：它不重写 FastAPI 应用，而延续「借上游 + 改两处」哲学——复用上游 build_openai_app，运行时删掉 /v1/chat/completions 与 /v1/models 两个上游路由，再并入自己的模块级 router。启动由 omni_run_server → omni_run_server_worker 编排，铁律是「引擎构造先于应用构造（应用依赖 supported_tasks）」「删上游路由须先于并入 omni router」。删路由分两类工具：_remove_route_from_app（app 级，启动期剔除上游）与 _remove_route_from_router（router 级，导入期对 omni 自身去重）。

引擎 AsyncOmni 是全局单例：build_async_omni 产出 → omni_init_app_state 钉进 app.state.engine_client → 依赖提供者（Omnichat/Omnivideo/Omnispeech 等）在请求期取用 → serving 模块持有并调用，沿此链保持同一实例引用。

omni_init_app_state 有两条初始化分支：纯扩散模式（单 diffusion stage，走 for_diffusion 类方法，用 _DiffusionServingModels 轻量替身）与 LLM/多阶段模式（完整 OpenAIServingModels + OnlineRenderer + 条件性 serving 模块），由 is_single_stage_diffusion、get_stage_type 判定。协议层三处扩展：_DiffusionServingModels 兜底 /v1/models；多阶段错误处理器在标准错误体上注入 request_id 与 error_stage_id；shutdown_unsupported_routes 按模型 endpoint_restrictions 把不支持端点改成返回 400 的拒绝处理器。
