本讲精读 vLLM-Omni 如何通过 monkey-patch（猴子补丁）在不改 vLLM 源码的前提下改写其核心行为。它把改动二分为 🟡 Modified（修改，几乎全靠 patch.py 的运行时替换实现）与 🔴 Added（新增，独立新文件不碰上游），本讲专讲前者。`patch.py` 是「修改型扩展的唯一汇聚点」，其加载时机由 `__init__.py` 的严格顺序控制：version 检查 → patch → 注册 configs → 暴露 OmniModelConfig → 懒加载 Omni/AsyncOmni，其中「version 必须早于 patch」是铁律。三种典型改写手法为：属性替换（`is_mm_prefix_lm` 的 cached_property 舞步，用 `_OMNI_MM_PREFIX_LM_MODELS` 补充名单做逻辑并集）、方法包装（NVFP4 `weight_scale` 在调原方法前先钳 NaN 字节，否则输出塌缩成 `!!!!`）、枚举扩展（`aenum.extend_enum` 给 `RequestStatus` 加 `WAITING_FOR_CHUNK/-1`、`WAITING_FOR_INPUT/-2`）。另有「全局类替换」遍历 `sys.modules` 快照把 `Request` 等整体换成 `OmniRequest` 子类。工程上沉淀四个健壮性模式：幂等、自熄灭（按 `co_names` 判断上游是否已修）、逃逸舱（`VLLM_OMNI_SKIP_NVFP4_NAN_CLAMP`）、安装断言（关键处用 `raise` 而非 `assert`，防 `-O` 编译掉）。后续讲义将用到被改写的 `ModelConfig` 与 `RequestStatus`。
