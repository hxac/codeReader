本讲梳理 vllm_omni/config/ 三类配置，核心结论：配置不是一张大表，而是「拓扑（代码冻结）+ 部署 YAML + CLI 覆盖」三层合流。模型级 OmniModelConfig 继承 vLLM ModelConfig，新增 stage_id、model_stage、engine_output_type、stage_connector_config 等多阶段字段，经 from_vllm_model_config 走「绕过校验、手动搬字段」快路径构造。结构化视图 VllmOmniConfig（RFC #4021）为顶层容器，含 pipeline_config、stage_configs、orchestrator_config；StageConfig 子类由 execution_type（LLM_AR/LLM_GENERATION/DIFFUSION）决定，基类 BaseVllmOmniStageConfig 聚合八个子配置。冻结拓扑 PipelineConfig/StagePipelineConfig 用 input_sources 表达 stage 间的边、经 validate() 校验；DeployConfig 是用户唯一编辑层。StageConfigFactory 为总入口：create_from_model 产出结构化 VllmOmniConfig，legacy 路径经 merge_pipeline_deploy 产出引擎当前仍消费的遗留 StageConfig（OmegaConf 形态），两套并存逐步迁移。
