本讲（u8-l3）讲解 vLLM-Omni 的基准测试与性能剖析工具，遵循「复用上游 + patch 扩展」哲学。核心模块包括：自包含的 Diffusion 在线压测脚本 `diffusion_benchmark_serving.py`，用数据集、到达过程（Poisson/全量）、并发上限（Semaphore）三要素组织压测，输出吞吐（QPS）、延迟分位数（p50/p95/p99）与基于面积×帧数×步数线性估算的 SLO 达成率；通用在线压测则靠极薄的 `serve.py` 入口 import `patch.py`，通过双写 `get_samples`、注册 `ASYNC_REQUEST_FUNCS`、替换 `serve.benchmark` 三招将 omni 多模态数据集与后端「注射」进上游 vLLM，并以继承 `RequestFuncOutput` 的 `MixRequestFuncOutput` 承载 audio TTFP、RTF、连续性等多模态指标。配套诊断脚本：`bench_attention_backends.py` 对比 SDPA/FlashInfer/FA4 单 kernel 中位耗时定位慢后端，`quantization_quality.py` 用 LPIPS 量化感知质量损失，`audio_continuity.py` 模拟实时播放器捕捉 RTF 合格却因块到达抖动产生的 audible underrun。剖析侧由 `profiling.md` 串联 torch/cuda profiler 与 `/start_profile`、`/stop_profile` 在线端点，并用工具对照表划清 pipeline profiler、orchestrator monitor、Prometheus 的适用边界。关键结论：压测定方向、profiler 定位置、后端/质量评测验方案，三者构成「测→评→剖」闭环。
