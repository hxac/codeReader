本讲讲解如何把自己研发的多阶段全模态模型接入 vLLM-Omni，以 Qwen3-Omni 的 Thinker/Talker/Code2Wav 三阶段结构为范本。核心结论是：接入一个 Omni 多阶段模型需要编写三层代码——统一模型类、冻结拓扑、阶段输入处理器。统一模型类按 `model_stage` 字段（如 thinker/talker/code2wav）单态分派，在每个独立进程里只加载一个子模型。冻结拓扑用 `PipelineConfig` 描述有几个 stage、各自执行类型、上下游关系与最终输出，写在 `pipeline.py` 中并由 `OMNI_PIPELINES` 注册表登记，用户不可改。`StagePipelineConfig` 的关键字段包括 `stage_id`、`model_stage`、`execution_type`（LLM_AR/LLM_GENERATION/DIFFUSION）、`input_sources`（有向图的边）、`final_output` 与 `final_output_type`。阶段间数据由 `stage_input_processors` 转译，分三类后缀函数：`*_full_payload` 把重张量经 connector 跨进程传输，`*_token_only` 在 orchestrator 侧用 0 占位预留 KV 槽位，`*_async_chunk` 负责流式分块。框架用 `VllmOmniConfig.from_pipeline_config` 把冻结拓扑、部署 YAML 与 CLI 覆盖编译成每个 stage 的结构化配置。`final_stage_id` 由用户请求的输出 modality 反向决定，取所有 `final_output=True` 且类型匹配的最小 stage_id，实现按 text/audio 动态收口。多 stage 可分到不同 GPU、配不同资源，是多阶段架构的核心收益。
