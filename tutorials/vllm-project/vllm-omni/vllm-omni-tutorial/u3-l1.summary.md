本讲是进阶层 U3（多阶段运行时与编排）的总览，为 vLLM-Omni 建立**五层架构**全局视图：API 层（同步 `Omni`／异步 `AsyncOmni`，共享基类 `OmniBase`）、Engine 代理层（`AsyncOmniEngine`，不做推理的「薄代理」）、Orchestration 层（`Orchestrator`，后台线程）、Communication 层（`StageEngineCoreClient`/`StageDiffusionClient`，ZMQ+msgpack）、Execution 层（`StageCoreProc`/`DiffusionEngine` 子进程）。

核心结论有三：其一，主线程与 Orchestrator 后台线程靠 `janus.Queue`（`request_queue`/`output_queue`，同步端归主线程、异步端归 Orchestrator）桥接，请求「下沉」到子进程、输出「上浮」回 API 层，全程无函数返回值链。其二，`add_request` 在主线程对 stage-0 跑 `InputProcessor.process_inputs`（仅 LLM，diffusion 跳过）再入队。其三，`OmniBase` 抽出共享逻辑——`_compute_final_stage_id` 依输出模态确定最终 stage，`_handle_output_message`/`_process_single_result` 处理输出；同步入口阻塞轮询，异步入口用后台协程按 request_id 路由到每请求 `asyncio.Queue`。本讲梳理一次 `generate` 的 **8 步执行流**，其中步骤 [5] 的 `_route_output`/`_forward_to_next_stage` 是把 Thinker→Talker→Code2wav 串联成流水线、推进到最终 stage 的心脏。关键术语（薄代理、janus 队列、最终 stage、前推）供 u3-l2（Orchestrator）、u3-l3（阶段进程与运行时）、u3-l4（OmniConnector）承接。
