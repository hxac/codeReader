本讲聚焦 vLLM-Omni 扩散子系统中最贴近模型的 Diffusion Pipeline 层，回答 `pipeline.forward` 内部如何去噪并生成图像。完整数据流为 `encode_prompt → prepare_latents → prepare_timesteps → diffuse → vae.decode → post_process`，请求级在 `forward` 一次跑完，步级拆为 `prepare_encode/denoise_step/step_scheduler/post_decode` 四段。核心负载是请求载荷 `OmniDiffusionRequest`（携带 `prompt/sampling_params/request_id/kv_sender_info`，并在 `__post_init__` 归一化 seed、guidance_scale 与 CFG 开关）与采样参数口袋 `OmniDiffusionSamplingParams`（仅代表单条 prompt，多 prompt 批处理由上层 scheduler 合并）。最耗时的 `diffuse` 是多步去噪循环，每步做 `predict_noise`（调 DiT 预测噪声/速度）与 `scheduler.step`（沿时间轴推进 latent），通用动作置于基类 `CFGParallelMixin`，各模型只定制 `diffuse` 骨架。关键概念包括：latent、prompt embeds、DiT、VAE；CFG 通过正/负 prompt 双前向与合并公式 ε̂=ε_neg+s(ε_pos−ε_neg) 提升质量，可选范数归一防幅值爆炸，CFG 并行用 `all_gather` 分摊双前向、合并与步进因确定性无需广播；`cache_branch`（positive/negative）保证 TeaCache 等缓存的正负状态互不污染；进程级 `set/get_current_diffusion_config` 用「保存-恢复」上下文让 Attention 层构造期免于层层透参。
