本讲剖析 diffusion worker 子进程的内部结构与生命周期。worker 进程分四层：进程入口 worker_main → IPC 大脑 WorkerProc（用 broadcast_mq 收命令、result_mq 回结果）→ 动态继承包装 WorkerWrapperBase → 基础设施类 DiffusionWorker，模型相关操作全委托给 DiffusionModelRunner，遵循「Worker 管基建、Runner 管模型」的对齐分工。init_device 经 current_omni_platform 完成跨硬件（CUDA/NPU）设备选择，再以 init_distributed_environment 与 initialize_model_parallel 建立 NCCL/HCCL 通信域及 TP/SP/CFG/DP/PP 并行组；构造期即同步完成模型加载，故 ready 握手意味着权重已就位。就绪后 worker 永驻 _worker_busy_loop，按消息 type 路由 sleep/wake/rpc/shutdown/直接生成五类，前向主要走 rpc→execute_model，request 模式用 COMPUTE_DONE/OUTPUT_READY 两段式异步回传，使 D2H 拷贝与下一次前向重叠。Runner 前向顺序固定为：KV 接收预取 → cache_backend.refresh（按 num_inference_steps 重置缓存）→ set_forward_context（向进程级全局注入 ForwardContext 供 attention 读取）→ pipeline.forward。权重由 DiffusersPipelineLoader 负责下载、safetensors 分片排序与加载，HSDP 走「CPU 加载后切分」独立路径。worker 进程、forward context、cache_backend、HSDP 等术语为 u5-l4 去噪数据流的前置。
