本讲是入门篇收尾，把离线推理（脚本内调 `Omni.generate`）的能力包成常驻 HTTP 服务。最小模块有三：一是**在线服务全景**——用 `vllm serve <model> --omni --port 8091` 启动，再以 `curl | jq | cut | base64` 管道从 `/v1/chat/completions` 取图；图像以 `data:image/png;base64` 形式藏在 `choices[0].message.content[0].image_url.url`，采样参数经 `extra_body` 透传（对应离线的 `OmniDiffusionSamplingParams`）。二是 **CLI 拦截机制**——`main.py` 用 `"--omni" in sys.argv` 做单一检查站：带则走 omni，不带则延迟 import 透传上游 vLLM；`vllm` 命令识别 `--omni` 依赖上游 vLLM ≥ 0.26.0 协作转发，而非劫持入口。三是 **serve 子命令装配**——通过 `CMD_MODULES` 列表 + `cmd_init()` 动态装配子命令（可扩展的 argparse 模式），`OmniServeCommand` 经 `cmd_init → subparser_init（复用 `make_arg_parser` 并追加 `OmniConfig` 分组）→ validate（扩散模型走快路径跳过 LLM 校验）→ cmd（`uvloop.run(omni_run_server)`）` 四段式生命周期。核心结论：`omni_run_server` 是统一入口，由 `build_async_omni` 经 `AsyncOmni` 自动区分 LLM 与 Diffusion，并借「移除上游 `/v1/chat/completions`、`/v1/models` 路由后挂载 omni 处理器」实现端点定制。关键术语：OpenAI 兼容 API、子命令、拦截、console_script、uvloop、`TrackingArgumentParser`、headless 模式、`_ensure_vllm_platform`。
