本讲聚焦 AIBrix 控制平面的数据层，即 `api/` 下用 Go 结构体定义的自定义资源（CR）数据模型，不讲 reconcile 逻辑。三大模块：一是**三组 API 分组**——按能力域拆为 `autoscaling`（含 PodAutoscaler）、`model`（ModelAdapter、ModelClaim）、`orchestration`（StormService、RoleSet、PodSet 等），目录路径与分组名一一对应，全部处于 `v1alpha1`；每组用模板化 `groupversion_info.go` 暴露 `AddToScheme`，由 main.go 按 Feature Gate 条件化注册进 Scheme。二是 **Spec/Status 字段设计**——每个 CR 遵循 TypeMeta+ObjectMeta+Spec+Status 骨架，Spec 为用户期望状态、Status 为控制器回写实况；Status 普遍具备 Phase+副本计数+Conditions 三件套。典型如 PodAutoscaler（ScaleTargetRef、MetricsSources、ScalingStrategy 枚举 HPA/KPA/APA）、ModelClaim（PodSelector、ArtifactURL、引擎参数及 Pending→Active 生命周期相位）。三是 **kubebuilder 标记与代码生成**——标记作为单一数据源，类型级标记（`subresource:status`、`subresource:scale`、`printcolumn`、`shortName`）生成 CRD YAML，字段级标记（Enum/Minimum/MaxItems）生成 OpenAPI 校验；`printcolumn` 决定 `kubectl get` 输出列，其 JSONPath 可指向 spec 或 status，反映运维关注点。
