本讲聚焦 ModelClaim 控制器。与 u4-l1 的 ModelAdapter「在已有引擎上挂 LoRA」不同，ModelClaim 让运行时边车 fork 出一个独立引擎进程，多个引擎借 kvcached 共享同一张 GPU，实现高密度低成本推理。reconcile 主循环为：列候选 warm Pod → 激活/缩容 → 按运行时快照做就绪收敛 → 刷 status → 跑池化策略。关键机制「端口 0 门槛」：引擎刚激活时 Pod 注解端口写 0（不可路由），直到快照确认 Ready 才翻真实端口，全程「快照权威」，避免网关把请求打到还在 boot 的引擎。控制平面与边车间是 activate/deactivate/snapshot 等 7 个 HTTP 端点的协议，RuntimeClient 可注入假实现便于测试。放置算法用「权重缓存 > 显存 > KV 用量 > 模型数 + 负载 + 名字」字典序选 Pod，无快照时安全回退。池化策略做成 warm-pool Deployment 上的 JSON 注解（非 CRD），用「保底下限 + 剩余按活跃度加权」分配 KV 预算并休眠空闲引擎；finalizer 保证删除时优雅停机。
