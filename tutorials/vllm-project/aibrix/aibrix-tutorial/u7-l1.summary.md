本讲是 AIBrix LLM 网关（数据平面）的入口，讲清网关如何经 Envoy ExtProc 协议接入请求。`cmd/plugins` 的 main.go 是一条装配流水线，核心一行 `RegisterExternalProcessorServer` 把 `gateway.Server` 注册为 ExtProc gRPC 服务（监听 :50052），HTTP 服务（:8080）仅暴露 metrics 与 /v1/models。ExtProc 为每个 HTTP 请求开一条 gRPC 双向流，按生命周期分阶段推送 `ProcessingRequest`；`Process` 是流主循环，用每请求的 `processState` 保存状态，`processOnce` 借 goroutine + select 监听 `shutdownCh`，解决 ExtProc 流粘性导致的优雅关停难题。`handleProcessingRequest` 按四阶段分发：请求头阶段 `HandleRequestHeaders` 做认证与限流，请求体阶段 `HandleRequestBody` 做路由决策，响应头/响应体阶段做错误判断与 token 统计。核心结论：路由发生在请求体阶段而非请求头（model 与 message 在 body 中），策略来源优先级为「请求头 → 配置画像 → 环境变量」；路由分两条互斥分支——未配置算法（`RouterNotSet`）时网关退化为 HTTPRoute 校验器、由 Envoy 原生路由，配置算法时经唯一集成点 `selectTargetPod` 调 `routing.Select` 与 `router.Route` 钦点目标 Pod 并注入 `target-pod` 头。关键术语：ExtProc、`ProcessingRequest`/`ProcessingResponse`、`ImmediateResponse`（短路返回）、`RoutingContext`（贯穿一次请求的路由上下文）、`selectTargetPod`、`RouterManager`（可插拔注册中心）。具体路由算法（评分、归一化、多策略）留待 u7-l3、u7-l4 与第八单元展开。
