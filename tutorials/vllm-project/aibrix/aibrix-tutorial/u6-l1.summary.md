`pkg/cache` 是 AIBrix 数据平面的进程内中央缓存。核心结论：它是**进程级单例**（`sync.Once` + 包级 `store`），「中心」指进程内路由、限流、排队等组件共享同一 `*Store`，而非跨进程；跨进程状态靠 Redis 同步。

本讲覆盖三个最小模块：①**初始化与运行**——`InitWithOptions` 按服务身份（gateway/metadata/controllers）条件化装配，网关启动指标、GPU 画像、请求追踪、跨副本快照、KV 同步五类后台循环，控制器（仅 ModelAdapter 启用时）只做发现与基础指标。②**订阅机制**——`discovery.Provider` 抽象把 K8s informer 与静态 YAML 统一成 `WatchEvent`，`informers.go` 据此维护 `metaPods` ↔ `metaModels` 双向映射。③**查询 API 与快照**——`cache_api.go` 拆成 `PodCache`/`MetricCache` 等小接口，`cache_impl.go` 纯内存无 IO 实现；`cache_gateway_snapshot.go` 经 Redis 周期交换 per-pod 状态，由 `syncRunningRequestsGlobally` 聚合成全局在途请求数，支撑多副本负载感知路由。

引入的关键术语：进程级单例、Provider/WatchEvent、双向映射、跨副本快照、全局在途请求数。重要纠正：网关与 ModelAdapter 调度复用 pkg/cache，但 **PodAutoscaler 不复用**，它有独立的指标管线；`initCacheInformers` 为已无调用方的 legacy 路径。
