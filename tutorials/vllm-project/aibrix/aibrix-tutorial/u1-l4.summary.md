本讲讲解 AIBrix 在 Kubernetes 上的部署流程与 CRD 安装设计。`config/` 是一棵 kustomize 目录树，分三层：依赖层 `config/dependency`（装 Envoy Gateway、KubeRay 等外部组件）、类型层 `config/crd`（AIBrix 自有 CRD）、组件层 `config/default`（operator、网关、RBAC、webhook 等运行体）。安装顺序固定为 dependency → crd → default，因 operator 启动前其 watch 的 CRD 必须已就绪。`config/default` 作为总装层，用 `namespace: aibrix-system` 与 `namePrefix: aibrix-` 做全局改名换空间。核心结论是：CRD 与 operator 被故意拆成两份独立清单（对应 issue #2062），因为 Kubernetes 删 CRD 会级联删除该类型下所有 CR 实例；分开后卸载 operator 不会清空用户的 StormService、PodAutoscaler、ModelAdapter 等数据。CRD/依赖安装统一带 `--server-side` 以规避大对象客户端注解体积上限。安装分 nightly（本地源码、tag=nightly）与 stable（GitHub 预构建 YAML、固定版本），二者经 `config/overlays/release` overlay 通过覆盖镜像 tag 衔接。最后，`samples/quickstart/model.yaml` 是一个普通 Deployment，靠 `model.aibrix.ai/name` 标签与 Service 名、`--served-model-name` 三者一致被 AIBrix 发现，演示「装 operator → 部署工作负载 → 被发现」的最短链路。关键术语：CRD、operator、kustomize、Server-Side Apply、级联删除、overlay、model.aibrix.ai/name 发现标签。
