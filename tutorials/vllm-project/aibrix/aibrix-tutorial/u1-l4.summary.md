本讲讲解 AIBrix 的 Kubernetes 部署与 CRD 安装流程。核心是 `config/` 这棵 kustomize 目录树，分三层：依赖层（`config/dependency`，装入 Envoy Gateway、KubeRay 等外部组件）、类型层（`config/crd`，AIBrix 自有 CRD 如 PodAutoscaler、ModelAdapter、StormService、RoleSet）、组件层（`config/default`，operator、网关、metadata、RBAC、webhook 等运行体）。安装顺序固定为 dependency → crd → default。最关键的设计决策是 CRD 与 operator 故意拆成两份独立清单（issue #2062）：因删除 CRD 会级联删除该类型下所有 CR 实例，分开安装使卸载 operator 时能保留用户的 CR 数据；安装 CRD/依赖统一带 `--server-side` 以规避大对象客户端注解体积上限。安装方式分 nightly（本地源码、tag=nightly）与 stable（GitHub Releases 预构建 YAML、tag 固定版本），经 `config/overlays/release` overlay 衔接。元数据存储默认内置 Redis，可改用开源 Valkey（BSD-3、wire-compatible），因 valkey.yaml 把 Service 名仍设为 `redis-master`，经 namePrefix 加工后仍为 `aibrix-redis-master`，metadata-service 的 `REDIS_HOST` 无需改动（两者不能并存）。示例 `samples/quickstart/model.yaml` 是普通 Deployment，靠 `model.aibrix.ai/name` 标签与 Service 名、`--served-model-name` 三者一致被 AIBrix 发现，演示「安装 operator → 部署工作负载 → 被发现」的最短路径。
