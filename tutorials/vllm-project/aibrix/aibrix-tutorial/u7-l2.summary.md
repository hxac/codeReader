本讲承接 Envoy ExtProc 流主循环，下沉到一个 HTTP 请求在 AIBrix 网关内部被逐阶段加工的过程，核心是四个最小模块：处理链总览、请求头与 Header 处理、API Key 认证、请求/响应体处理链。

网关在 `handleProcessingRequest` 里按 ExtProc 消息类型把请求分发到四个 `Handle*` 阶段：请求头阶段做 Header 提取、认证、按用户限流与 OpenTelemetry 追踪注入，并创建贯穿全流程的 `RoutingContext`；请求体阶段解析 body、校验模型可用性并做出路由决策，把目标 Pod 以 `target-pod` 头注入回请求指挥 Envoy 转发；响应体阶段在流式下逐 chunk 扫描，仅在末块做 Token 计量与收尾。阶段间靠 `processState` 与 `RoutingContext` 传值。

关键术语包括：`ImmediateResponse`（短路返回错误）、`target-pod` 头（路由指令）、RPM/TPM 双计量、TTFT、流式 SSE usage 提取。核心结论有三：一是网关不直接转发 HTTP，只通过改写请求头指挥 Envoy 路由；二是 API Key 认证默认关闭、用 SHA-256 加常数时间比较抗计时侧信道，与按用户限流职责分离；三是 RPM 在请求头阶段预扣、TPM 在响应体末块按实际用量补扣。
