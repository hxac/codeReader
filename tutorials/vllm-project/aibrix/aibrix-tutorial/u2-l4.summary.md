本讲讲解 AIBrix 准入 webhook 的三类职责：边车注入、默认值补全、合法性校验。它位于 `pkg/webhook/`，与控制器同进程、由 Manager 托管，但拦截的是「对象入库前」的一次性写请求。webhook 分两种：mutating（变更，对应 `CustomDefaulter.Default()`，可修改对象）与 validating（校验，对应 `CustomValidator.ValidateCreate/Update/Delete()`，只能放行或拒绝），铁律是「先改后校验」。触发时机由 kubebuilder 标记的 `verbs=create;update` 与 `failurePolicy=ignore`（fail-open）决定，五个 webhook（ModelAdapter/KVCache/StormService/Deployment/PodAutoscaler）用统一模板注册，且全部在 TLS 证书就绪后挂载。核心概念包括：边车注入由注解 `model.aibrix.ai/sidecar-injection: "true"` 触发，`deployment_webhook.go` 的 `injectAIBrixRuntime` 幂等地修改 Pod 模板的 Containers（prepend 一个 `aibrix-runtime` 容器）、Volumes（`adapter-storage` EmptyDir）与各容器 VolumeMounts；`sidecar_injection.go` 提供共享的容器构造函数 `buildRuntimeSidecarContainer` 与按镜像名推断引擎的 `inferEngineType`，并被 StormService 复用。校验统一用 `field.ErrorList` 聚合错误一次性返回，PodAutoscaler 校验最完整，KVCache 演示「先补默认值、后校验」协作。kubebuilder 标记是配置单一数据源，经 `make manifests` 生成清单供 API Server 路由。
