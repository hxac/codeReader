本讲是 AIBrix 自动伸缩单元的入口，讲解 `PodAutoscaler` CR 及其控制器的整体骨架。`PodAutoscaler` 用 `ScaleTargetRef`（伸缩谁）、`MetricsSources`（看什么指标）、`ScalingStrategy`（用什么策略，分 HPA/KPA/APA 三种）声明伸缩意图。控制器 `Reconcile` 主循环按「校验 → 计算并回写 Status/Conditions → 按 HPA 或 KPA/APA 分流」执行，并有 10 秒周期 resync 兜底时间驱动的伸缩。关键设计是职责分离：控制器有状态、负责副作用（改副本数、写 Status），而 `DefaultAutoScaler` 无状态、只做纯计算——其 `ComputeDesiredReplicas` 遍历各指标，多指标取期望副本数最大值（偏可用性）。核心管线 `executeScalingPipeline` 分四步：采集 → 配置 stable/panic 窗口 → 聚合 → 算法计算；`algorithmCache` 用「RWMutex + double-check」缓存无状态算法对象，可安全跨 goroutine 复用。控制器侧另有边界检查、冷却稳定化（扩容取 max、缩容取 min，模仿 K8s HPA）等保护。本讲只接通「从 CR 到期望副本数」的管线，具体算法公式与指标采集留待 u3-l2、u3-l3。
