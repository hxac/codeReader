本讲解析伸缩算法体系。核心是 ScalingAlgorithm 接口，仅含 ComputeRecommendation 与 GetAlgorithmType 两方法，铁律为无状态（空 struct{}）：所有可变数据经 ScalingRequest 传入，产出 ScalingRecommendation，再由公共函数 applyConstraints 用 min/max 兜底。三种策略：KPA 用 stable/panic 双窗口，平时按 stable 决策、突发时切 panic 且只增不减（高水位 maxPanicPods 记峰值），支持从 0 唤醒，实现最复杂；APA 单窗口按「当前副本 × 利用率/target」等比例伸缩，带上下容差与速率限制，适合每 Pod 利用率型指标；HPA 为空实现，直接返回当前副本，真正伸缩委托 Kubernetes 原生 HPA 控制器。策略字符串经工厂 NewScalingAlgorithm 的 switch 映射成算法（未知值兜底 KPA），DefaultAutoScaler 按策略缓存复用，因算法无状态故并发复用安全。核心区别在于：APA 期望副本与当前副本成正比，KPA 则由指标值/target 直接算出绝对值——选策略须先辨清指标是「每 Pod 利用率」还是「系统总量」语义。
