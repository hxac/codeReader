本讲聚焦 PodAutoscaler 伸缩管线的「数据侧」，讲解指标从采集、聚合到算法消费的完整链路，核心是三层结构：Collector（采集编排层，按 MetricSourceType 分流到逐 Pod 或 External 级采集，产出统一的 MetricSnapshot，支持部分失败兜底）；Fetcher（按源抓取层，POD/RESOURCE/CUSTOM/EXTERNAL 四种实现统一抽象为 FetchPodMetrics 接口，外部全局值用 dummy Pod 适配成 per-pod 形状）；MetricsClient（有状态存储层，被多个 PodAutoscaler 共享，靠 MetricKey「PaNamespace/PaName/MetricName」隔离）。

关键设计是接口归一化：所有来源（含 external 全局指标）最终都归一成一组 per-pod float64，下游只面对 []float64 一种数据结构。聚合采用双层平均——先跨 Pod 空间平均（UpdateMetrics 算 sum/len），再跨周期时间平均（TimeWindow.Avg 对窗口内各桶求平均），最终 StableValue 是「窗口内各周期空间平均的再平均」。无状态聚合器 DefaultMetricAggregator 始终同时返回 StableValue 与 PanicValue：APA 只读 stable（按当前副本等比例伸缩），KPA 在 panic 阈值触发时切用 panic；窗口默认 stable 180s、panic 60s，可由 spec 的 ObserveWindowSeconds/PanicWindowSeconds 覆盖。

此外需区分两个易混概念：resync 监控循环（10s ticker 定时触发 Reconcile，是时间驱动数据管线的来源）与 monitor（Prometheus GaugeVec 记录器，用 Set 上报每次决策的期望副本数供 Grafana 可观测，不参与决策）。本讲产出的 AggregatedMetrics 将在后续讲义交由算法层（APA/KPA）消费。
