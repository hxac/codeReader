本讲介绍 AIBrix 的 Standalone（单机）部署，本质是「同一份数据平面、换一种编排方式」，无需 Kubernetes。三大最小模块：一是 docker-compose 在共享网络 aibrix-network 上编排 redis、metadata-service、envoy、gateway、vllm 六类数据平面服务，靠 depends_on+healthcheck 形成启动链，并用 profiles:["pd"] 在同一份文件内切换单引擎与 P/D（prefill/decode 解耦）双引擎拓扑；二是 start.sh 在 compose 之上做参数解析、环境校验、模式切换、轮询就绪四层封装，通过 export ENDPOINTS_CONFIG/ROUTING_ALGORITHM 与 compose 文件达成环境变量契约；三是选型对比——Standalone 只编排数据平面、不含控制平面，故无自动伸缩、LoRA 调度、分布式编排。核心结论：网关二进制是同一个，靠 cmd/plugins 的 --standalone 开关分流后端发现方式——Standalone 走 discovery.NewStaticProvider 读取静态 endpoints.yaml，K8s 走 Informers 动态发现；且 Standalone 下 Redis 可选、K8s 下必需。本讲引入的关键术语：数据平面/控制平面、ext_proc 插件、静态文件发现、profiles 拓扑切换，供后续控制平面、Pod 发现与网关内部讲义承接。
