本讲介绍 AIBrix 的 Standalone（单机）部署，位于 `deployment/standalone/`，用一份 `docker-compose.yml` 把数据平面（redis、metadata-service、envoy、gateway、vllm 或 prefill/decode 双引擎）编排在一台机器上，完全不需要 Kubernetes。核心结论是：Standalone 只编排数据平面，不含控制平面，因此没有自动伸缩、LoRA 调度、分布式编排等 K8s 能力。关键概念包括：六类服务通过 `depends_on` 与 `healthcheck` 构成启动依赖链；同一份 YAML 用 `profiles: ["pd"]` 同时描述「单引擎」与「P/D 双引擎」两种拓扑；`start.sh` 通过 `export ENDPOINTS_CONFIG/ROUTING_ALGORITHM` 与 compose 文件达成环境变量契约。网关二进制是同一个，靠 `cmd/plugins/main.go` 的 `--standalone` 开关分流——Standalone 走 `discovery.NewStaticProvider`（基于 `endpoints.yaml` 的静态文件发现），K8s 走 Informers（动态发现）。元数据存储可在内置 Redis 与开源 Valkey 间一行切换：redis 服务的镜像、command、健康检查 CLI 被 `REDIS_IMAGE`/`REDIS_SERVER_CMD`/`REDIS_CLI_CMD` 三个变量参数化，因 Valkey 与 Redis 协议兼容、消费者用服务名 `redis` 访问，切换对 metadata-service 与 gateway 完全透明。
