本讲梳理 SR Go 路由器 `main()` 的启动序列：选项解析→配置加载（`config.Replace` 写入全局缓存作为唯一真相源）→创建 `routerruntime.Registry` 依赖容器→构造 startup-status writer→在 goroutine 中提前启动 API Server→模型下载→依赖初始化→ExtProc 构造→热身→标记就绪→阻塞起 ExtProc。两个核心设计：一是管理面 API Server 提前启动，使 `/startup-status` 在漫长的下载/初始化期间持续返回 503 与细粒度阶段信息（`starting→downloading_models→initializing_models→ready` 或 `error`），`markRouterReady` 后翻为 200；二是"严格核心加宽容可选"的分级——配置缺失/解析失败、模型下载失败、依赖初始化或 ExtProc 构造失败即 fatal 退出，而 tracing、向量库、warmup 失败仅记 warn。模型下载走 `BuildModelSpecs→GetMissingModels→huggingface-cli`，仅当确有缺失才要求 CLI 存在，并按回调实时上报进度（就绪度 c=r/N）；`--download-only` 供 CI 提前烤模型后 `os.Exit(0)`。本讲把 Registry 与 ExtProc 仅当作依赖桶和起服入口，其内部结构留给后续 u4-l2（Registry）与 u4-l3（ExtProc Server）。
