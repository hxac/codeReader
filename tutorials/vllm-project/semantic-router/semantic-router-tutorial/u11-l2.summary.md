本讲聚焦投影层的可解释性，定义一份版本化、纯数据的投影追踪（Projection Trace）JSON：由包级常量 SchemaVersion 打头，下挂 partitions/scores/mappings 三个 omitempty 数组，对应 partition、score、mapping 三类投影操作。核心结论：追踪只忠实记录投影计算、不参与路由决策，决策读的是写回 SignalConfidences 的最终置信度（如 projection:balance_complex）。

三大字段：PartitionResolution（分区解析）记 softmax/argmax 选出的赢家、原始分与归一化分、首两名边际 Margin、是否走 default 兜底 DefaultUsed，仅在≥2 候选真正竞争或兜底时记录；ScoreBreakdown（评分分解）逐路存 weighted_sum 的权重、取值与贡献，取值分 binary/confidence/raw/kb_metric 四种来源，confidence 缺省兜底 1.0、raw 缺省为 0，且追踪重新取值以保证分解与实际求值同源；MappingDecision（映射决策）逐带记阈值匹配与到活跃边界的 BoundaryDistance，选中首条命中带，用 sigmoid_distance（1/(1+exp(-slope·d))）把距离翻译成置信度，贴边界≈0.5、远离≈1。

复用链路：SignalResults.ProjectionTrace 经两次 Marshal/Unmarshal 深拷贝搬到 RequestContext.VSRProjectionTrace，再到重放 Record.ProjectionTrace，落 Postgres/JSON 供面板展示，列表摘要主动清空以控体积。projectiontrace 为纯类型包（仅 trace.go），被分类、重放、面板三处复用而不引入循环依赖。三段合并写入：分区追踪在分区规约时逐条 append，评分与映射追踪在 applyProjections 收尾时由 mergeProjectionTrace 一次性补齐并保留已有分区条目。
