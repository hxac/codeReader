本讲讲解 SR（vLLM Semantic Router）Go 端配置子系统，回答「磁盘上的 config.yaml 如何变成内存中安全使用的 RouterConfig」，覆盖四个最小模块：解析、规范化、语义校验、热替换。

解析采用「先 map 后类型」分层：config.Parse 无副作用地把 YAML 转成无类型 map 做预处理，再反序列化为强类型 RouterConfig；config.Load 在其外包 sync.Once 做全局唯一缓存。RouterConfig 含多个标 yaml:"-" 的派生字段（Entrypoints/Recipes/RoutingScope/DocumentHash），由规范化阶段从 entrypoints/recipes 段拼出，不直接来自 YAML。

规范化（normalizeCanonicalConfig）以 DefaultGlobalConfig() 为底，依次叠加全局、路由、recipe、provider 四块状态；通过 rejectRemoved* 系列拒绝弃用字段并附迁移提示，把静默错误变成确定性启动失败，同时展开 ${VAR} 环境变量、识别 canonical 五段式形态。

语义校验拆两个家族：全局校验器整份跑一次，路由画像校验器逐 recipe 在 ConfigForRecipe 隔离视图上跑，从而把跨配方信号误引用变成可见启动错误（典型如 validateDecisionSignalReferences）。

热替换由全局缓存、config.Replace、变更订阅 channel 三件套支撑；Replace 发通知非阻塞（select+default），慢消费者不拖住关键路径，有启动、router 构建、apiserver 三条入口。

关键术语：canonical、规范化、语义校验、热替换、ConfigMap 挂载、派生字段、配置家族。
