本讲讲解 apiserver——SR 的控制面 HTTP 服务，默认仅监听本地，与 Envoy/ExtProc 数据面分工，二者经 Registry 共享同一批运行时依赖。其设计原则是「路由目录即真相」：所有端点集中在 routes_catalog.go 声明，每条绑定权限/敏感度/审计动作，统一中间件（请求 ID、鉴权、请求体限流）与 OpenAPI 文档均由此派生。配置部署采用三态模型 source/runtime/active：写盘后轮询 active 哈希以确认数据面真正生效，用 ETag 加 If-Match 实现乐观并发（recipe 端点强制），并以热重载兼容性闸门拒绝需重启的变更。能力端点（classify/eval/kbs/embeddings）是「解析→调 Registry→序列化」的薄封装，eval 强制评估全部信号。鉴权为 disabled/bearer 双模式加 viewer/operator/admin 三角色 RBAC，密钥经环境变量注入、secret_view 控制明文可见性。
