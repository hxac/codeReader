本讲是请求处理主链路收尾篇，讲 Semantic Router 在 ExtProc 响应体阶段如何处理后端返回的字节流再交给客户端。核心入口 handleResponseBody 是调度员：先用 SkipProcessing、Looper 两道早退闸门放行跳过与内部重放请求，再按严格分支顺序分发——两条 Anthropic 流式分支须新先于旧，否则双重 Anthropic 象限会错配。Provider 归一化走「进站翻成 OpenAI、出站翻回客户端协议」的双向模式，仅真改写时才生成 body mutation。流式响应逐块累积 content/reasoning，首块记 TTFT，见 `[DONE]` 时由幂等的 finalizeStreamingResponse 收尾，一次性完成指标、在途、缓存与重放回写。响应阶段插件回调按固定顺序执行：越狱与幻觉检测可短路（block 动作），记忆异步存储遇越狱跳过，告警统一汇入 x-vsr-response-warnings 头。关键事实：缓存命中在请求阶段以 ImmediateResponse 直接回包，根本不进入响应体阶段，其重放回写也在请求阶段完成。
