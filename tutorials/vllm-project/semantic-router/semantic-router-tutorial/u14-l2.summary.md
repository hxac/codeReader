本讲介绍 vLLM Semantic Router 仓库中的离线工具 fleet-sim（命令 `vllm-sr-sim`），定位为**容量规划与路由策略评估工具**，与运行时 Go 路由器构成「离线规划 vs 在线决策」的互补关系。源码分三层：`core/` 是分层离散事件仿真（DES）引擎，按 Fleet→Pool→Instance 三层对应硬件；它把单 GPU 建模为 **M/G/c 排队队列**，以 **KV-cache 槽位为服务台**，靠抢占最长序列还原 vLLM 的 PagedAttention；核心延迟指标为 **TTFT**。`gpu_profiles` 用 `GpuProfile` Protocol 抽象硬件（W/H 线性延迟 + KV 几何 + 功耗曲线），`workload` 用经验 **CDF** 与泊松到达刻画流量，二者可独立替换。`routing` 提供可插拔路由器（`LengthRouter` 主力、`SemanticRouter` 连接在线语义路由理念）。`optimizer/base.py` 的 `FleetOptimizer` 采用**两阶段**：先用 Erlang-C/Kimura 解析公式快速扫描压缩系数 γ 空间筛候选，再用内联轻量 DES 仅验证 top-N 的 P99，并以节点可用率放大可靠性裕度。`base.py` 职责边界明确：只做聚合两池最小成本 sizing，不碰在线路由、画像来源及 disagg/grid-flex 等兄弟优化器。
