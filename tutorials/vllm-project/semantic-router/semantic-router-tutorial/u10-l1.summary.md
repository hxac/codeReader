本讲是「插件链与扩展机制」单元首篇，建立 Semantic Router 插件体系的全貌。SR 维护 13 种受支持决策插件（如 system_prompt、memory、request_params、header_mutation、rag、response_jailbreak、hallucination、router_replay、semantic-cache、tool_selection 等），权威清单集中在 routing_surface_catalog.go。插件配置分三层：载体 DecisionPlugin（仅 Type 与 Configuration）、强类型结构体、访问器 GetXxxConfig()；Configuration 用 StructuredPayload 保存，遵循懒解码——加载期原样保存，校验期与运行期按需解码。核心设计是「按 decision 启停」：插件挂在每条 decision 的 plugins[] 上而非全局开关，运行期以命中决策 ctx.VSRSelectedDecision 的 GetPlugin(type)==nil 作为门控，A/B 决策可各自挂不同插件互不干扰。链式处理指请求阶段按固定顺序改写 body/header（system_prompt→memory→request_params→header_mutation→router_replay 捕获请求体），响应阶段先做可短路的越狱/幻觉检测，再做不短路的记忆存储、告警汇总、replay 回写。router_replay 是唯一横跨两阶段的插件：请求阶段 startRouterReplay 幂等地建记录并写请求体，结构化字段（Prompt/ToolDefinitions）先于 MaxBodyBytes 截断提取；响应阶段 attachRouterReplayResponse 把响应体补回同一条 RoutingRecord，闭合完整审计轨迹。它还特有 EffectiveRouterReplayConfig 的「全局默认+按决策覆盖」合并机制。
