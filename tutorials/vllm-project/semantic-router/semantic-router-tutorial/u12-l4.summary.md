本讲覆盖 SR 的五个本地推理 binding 模块（candle/onnx/openvino/nlp/ml），它们是各自独立的顶层 Go module，通过 CGO 把 Rust（candle/onnx/nlp/ml）与 C++（openvino）推理能力暴露成 Go 函数。核心是统一的 FFI 模式：C 结构体对应 `#[repr(C)]`、`extern` 声明、Go 包装函数做字符串封送与结果转换、按所有权纪律显式调用配对 free 函数（如 `ml_free_string`），并用 `sync.RWMutex` 保护不透明句柄。分工上，candle 为默认主力（嵌入/分类/PII/越狱/多模态最全），onnx 镜像 candle API 以支持 drop-in 但当前仅测试引用未接运行时，openvino 是 Intel IR 路线、由 `openvino` 构建标签门控，nlp 提供轻量 BM25/N-gram 词法分类，ml 提供 Linfa KNN/KMeans/SVM 仅推理、模型从 Python 训练导出的 JSON 加载、服务于模型选择。后端可替换靠两层抽象：`embedding.Provider` + `NewFuncProvider` 接口缝使本地后端就地拼装、保持 `pkg/embedding` 纯 Go；`EMBEDDING_BACKEND_OVERRIDE` 按优先级（环境变量 > 配置 > remote > 兜底 candle）选后端。`EMBEDDING_BACKEND_OVERRIDE=candle` 时，main.go 在推理初始化前经 `applyBackendRuntimeTuningDefaults()` 把 OMP/MKL/OPENBLAS/RAYON 线程数压到 1、关闭 tokenizers 并行，避免 Rust 线程与 Go goroutine 抢核，且只填未显式设置的变量。openvino 的「cgo 文件 + 桩文件」互斥构建标签是处理可选重依赖的 Go 惯用法。
