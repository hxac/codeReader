本讲拆解驱动 K8s 部署形态的 `SemanticRouter` CRD 及其 Operator（控制器）。CRD 用 Kubernetes 原生字段（image/replicas/persistence/vllmEndpoints）表达部署意图，用 `config` 段做路由器运行时覆盖；变化快的 routing/algorithm 用 `apiextensionsv1.JSON`+`PreserveUnknownFields` 透传，使 CRD 不滞后于路由器 schema。Reconcile 是一条幂等的线性管线：取 CR→finalizer→初始状态→按序调和子资源（SA→ConfigMap→PVC→Envoy→Deployment→Service…）→updateStatus，被依赖者先建。Operator 的真正核心是配置翻译：直接复用路由器 `pkg/config` 的 `CanonicalConfig` 类型，按「骨架→后端发现→spec 覆盖」叠加，序列化成 ConfigMap 的 `config.yaml`。`vllmEndpoints` 是 K8s 原生后端发现适配器（kserve/llamastack/service 三路），把集群里活着的后端探测成 `backend_refs` 与 `routing.modelCards`，首个模型成为 `default_model`。Envoy/Gateway 接入分 standalone 与 gateway-integration 两态，由 `gatewayMode` 贯穿资源渲染。引入的关键术语：Reconcile、Owner Reference、Finalizer、canonical config、`default_model`、`gatewayMode`。
