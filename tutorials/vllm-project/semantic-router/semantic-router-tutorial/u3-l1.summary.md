config.yaml v0.3 有七大顶层段落。version 声明 schema 主版本；listeners 为管理面接入监听（推理流量由 Envoy 单独承载）；providers 是模型货架，defaults 放 provider 级默认，models[] 给出「逻辑模型名→多后端 backend_refs 加权 + 四档 pricing」的物理接入，与描述模型能力的 routing.modelCards 职责分离。routing 是路由主体，含 strategy、modelCards、signals、projections（partition/score/mapping）、decisions；核心纠偏是插件为路由级、嵌在每条 decisions[].plugins，不存在顶层 plugins 段。entrypoints 把客户端虚拟模型名映射到 recipe，且顶层 routing 本身即 default 配方；recipes[] 定义其他命名配方，各带 routing 块但无 modelCards，信号/投影/决策名字局部于配方、不可跨配方引用，而模型目录与基础设施共享。global 集中托管 router/services/stores/integrations/model_catalog 五类路由器级基础设施，遵循「全局默认 + 路由级覆盖」分层。本讲只讲结构与定位，决策求值、投影数学、加载校验等内部机制留待后续讲义。
