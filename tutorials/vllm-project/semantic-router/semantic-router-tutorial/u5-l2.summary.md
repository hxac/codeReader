本讲承接 u5-l1，拆解请求处理主链路的内核 `performDecisionEvaluation`：它把「原始模型名 + 协议无关对话历史 + 请求上下文」线性加工成 `(decisionName, confidence, reasoning, selectedModel, error)` 五元组。内核串联五个子步骤：①信号准备 `prepareSignalEvaluationInput` 把对话历史搬运成分类器输入 `signalEvaluationInput`，并做可选 prompt 压缩，产出原文 `evaluationText` 与压缩 `compressedText` 两个文本；②候选决策 `decisionCandidatesForRequest` 取当前配方需参与求值的决策子集；③信号求值 `evaluateSignalsForDecision` 调分类器抽全部信号得 `SignalResults` 写回 `RequestContext`，再经 `evaluateDecisionInternal` 逐字段桥接为 `decision.SignalMatches`，使决策包不反向依赖分类包；④决策引擎 `EvaluateDecisionsWithSignals` 对布尔规则树递归求值（AND 取平均置信度、OR 取最大、NOT 翻转），按分层/confidence/priority 三策略选最佳决策，Name 升序作确定性 tie-break；⑤方法解析跨「algorithm.type 字符串 → SelectionMethod 枚举 → Selector 实例」三道类型鸿沟选具体模型。贯穿全讲的两条边界：passthrough 不参与决策与换模型；配方隔离靠候选取自当前 recipe、空决策返回空非 nil 切片、Registry 按配方选取共同守住。信号族内部实现留待 u8，选择算法数学留待 u6-l2。
