本讲拆解 Semantic Router 管理面板的独立 Go 后端（dashboard/backend/）：它经 main.go → router.Setup → registerCoreRoutes 装配成单进程 net/http 服务，充当前端与基础设施之间的编排层。核心是三类 handler：config 负责 config.yaml 的整份读取与整体替换；deploy 处理 DSL 编译出的路由片段，用 merge/replace 两种节点级合并、deployMu 并发互斥、秒级时间戳版本化备份（保留 10 份）完成部署与回滚；status 按部署形态（容器内托管/直连/仅面板）分派，合成统一的 SystemStatus。三者共享「写盘 → 运行时下发 → 失败回滚」骨架与配置投影记录。本讲引入的关键术语：canonical config（后端与路由器共用的 Go 契约类型）、config projection（带版本号、来源、YAML 哈希的部署历史）、handler 工厂。全程遵循「HTTP 传输薄、业务塞进相邻辅助模块」的约定。后端与路由器进程内 apiserver 是两个进程：后端直接改写 config.yaml 并经 Python CLI 重生成 Envoy，路由器靠热重载读同一文件，二者借 /startup-status、/health 等只读接口协作。
