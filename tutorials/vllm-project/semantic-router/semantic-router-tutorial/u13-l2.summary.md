本讲解析 Semantic Router 面板的 React 前端（`dashboard/frontend/`），承接 u13-l1 后端，回答前端如何组织、门控、取数与编辑。核心为四块：一、**路由壳**——`App.tsx` 按 Auth→Readonly→Setup 顺序包裹三层 Provider（依赖决定顺序），`AppRouter` 先做安装态加载门，再用 React Router v6 的路径less 布局路由组织公共/受保护/兜底三类路由；业务路由表是**声明式数据驱动**（`routeManifest`+`routeLoaders`），`RecoverableLazyRoute` 统一 Suspense 与失败重试，并支持悬停预加载。二、**三道门控**——`AuthGate`（鉴权，未登录记 `from` 跳登录）、`AuthenticatedShell`（setup 模式强制安装）、`accessControl`+`ReadonlyContext`（权限与只读），分散于路由 element、布局壳、页面内部接力；权限遵循「权限数组优先、角色兜底」双轨，未匹配路径默认放行。三、**概览页**合并配置（`/api/router/config/all`）与状态（`/api/status`），双轮询节奏（10s/30s）配合可见性与 `config-deployed` 事件，统计塑造抽为纯函数。四、**配置页**按 `activeSection` 分八段渲染，读写经 `project/canonicalize` 双向规范化（兼容 legacy 字段），`configReadonly` 在保存链路最前端硬拦截。关键术语：路由壳、门控、声明式路由表、懒加载与预加载、规范化双向、权限双轨。结论：加页面成本主要落在声明式路由表+懒加载入口+权限前缀三处数据，而非命令式分支。后续 u13-l3 将承接可视化构建器与 DSL 编辑器。
