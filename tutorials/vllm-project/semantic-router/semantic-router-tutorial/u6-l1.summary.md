本讲深入决策引擎（`pkg/decision/engine.go`），讲解一条 ROUTE 的 WHEN 规则树如何被递归求值。引擎是**无状态求值器**：每次请求传入 `SignalMatches`（按信号族分门别类装好命中的信号容器），对每条决策产出 `(matched, confidence, matchedRules)`。`RuleNode` 身兼两职——`Type` 非空即叶子（指向一条 `族:名` 信号），`Operator`+`Conditions` 则为 AND/OR/NOT 组合节点，由 `evalNode` 据此分发。叶子以**存在性匹配**为主，`domain` 走 `mmlu_categories` 做别名扩展（大类规则匹配细类结果），`classifier` 仅支持 `Predicate` 数值断言；置信度从 `SignalConfidences` 取，缺失默认 1.0。聚合规则：AND 取平均、OR 取最大、NOT 命中固定 1.0；省略规则或空 AND 为置信度 0 的兜底，因而在 `confidence` 策略下不抢占信号路由。多决策同时命中时由单一排序挑出胜者：任一决策 Tier>0 即进入**分层模式**（Tier 升序优先，安全拦截压顶）；否则按 `priority`（Priority 降序）或 `confidence`（置信度降序）策略排序，全 tie 按 Name 升序兜底。本讲承接 u5-l2 的管线纵深，信号如何填入留 u8，选择算法的数学留 u6-l2。
