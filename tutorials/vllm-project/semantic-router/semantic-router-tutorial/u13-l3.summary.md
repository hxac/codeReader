本讲剖析面板两块路由编辑交互：基于 Monaco 的 DSL 编辑器（DslEditorPage）与可视化构建器（BuilderPage）。核心结论是 DSL 文本字符串 dslSource 为唯一真相源，visual/dsl/nl 三种模式共享它。「可视化→文本」走 dslMutations 的正则与花括号计数字符串手术，不经编译器；反向「文本→视图」才走浏览器内 WASM 的 parseAST。该 WASM（signal-compiler.wasm，由 Go 的 pkg/dsl 编译）暴露 compile/validate/parseAST/decompile/format 五个函数，编辑全程不请求后端。关键术语：DSL 仅描述 routing 段，导入 YAML 经 DecompileRouting 反编译，其余基础设施（global/providers/listeners）存入 baseConfigYaml 待部署合并；DSL↔YAML 往返会发生无损归一化（PRIORITY 总写出、OR 加括号、小对象内联、complexity 三段展开、名字规整），路由语义严格可逆但文本不逐字可逆。对照的 ConfigPageRecipePolicyEditor 则走 YAML 直改、仅编辑配方局部信号。
