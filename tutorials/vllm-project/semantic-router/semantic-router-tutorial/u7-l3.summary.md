本讲介绍 `sr-dsl` 命令行工具：将 u7-l2 的库函数 `Compile`/`Decompile` 包装成单一二进制多子命令终端工具，入口 `main.go` 用手写 `switch` 分发；命令行壳只做参数解析与 IO，真正逻辑在 `pkg/dsl` 库（`CLICompile`/`CLIValidateWithRunner`）。五个子命令为 `compile`（DSL→YAML/CRD/Helm，由 `--format` 切换产物，`--base` 把编译出的 routing 叠加到含 providers 的基线 YAML 产出完整配置，`--format crd` 直达 Operator CRD）、`decompile`（YAML→DSL 往返）、`validate`（校验）、`fmt`（格式化）、`generate`（自然语言→DSL）。

核心结论是 `validate` 的两层校验二分：**静态校验**总开、纯 AST、无需模型；**运行时校验**（`--runtime-checks`）用 `buildNativeTestBlockRunner` 构造真实 `classification.Classifier`，复用分类信号 + 决策引擎整条管线真跑查询并比对命中路由。`TEST` 块（`"查询" -> 期望路由`）是可执行文档，由 `TestBlockRunner.EvaluateTestBlockQuery` 求值，仅评估「查询非空且路由名存在」的条目，与静态层互补；静态不通过即跳过运行时，另附投影分区质心相似度健康检查。`generate` 采用 **schema-as-supervision** 哲学：经 OpenAI 兼容端点生成 DSL，带解析失败的修复循环（`Attempts`/`ParseError`/`Warnings`），生成后应立即 `validate` 闭环。推荐工作流为 fmt→validate→compile→runtime-checks。
