本讲讲解 Semantic Router 的「协议适配层」，覆盖三个贴在请求链路两端、把外部 API 形态翻译成内部统一表示再翻译回去的适配器。SR 内核统一跑在协议无关的中间表示上：请求侧为 OpenAI 的 `ChatCompletionNewParams`（称 **IR 核心**），响应侧为 `ChatCompletion`；OpenAI 装不下的字段则称 **IR 扩展**。`pkg/anthropic` 在 OpenAI 与 Anthropic 两种格式间双向翻译，遵循**有损翻译纪律**——有对应字段直接映射，无对应字段（`top_k`、`cache_control`、多段 system、`tool_result.is_error`、思维链签名）走旁路通道：逆向单元用每请求一次的 `AnthropicPassthrough`，对称单元用跨阶段的协议无关信封 `ir.IRExtensions`，旁路函数均 nil-safe。`pkg/responseapi` 用自管 `ResponseStore` 配**链式回溯**，把有状态的 Response API（靠 `previous_response_id` 串对话）摊平成无状态 Chat Completions：`GetConversationChain` 沿链回溯历史（最旧在前），`buildHistoryMessages` 把每条历史的 Input+Output 还原为消息，响应翻译则重新状态化成带新 `resp_` ID 并存库闭合链。`pkg/imagegen` 用 `Backend` 接口加 `Factory` 注册表收敛图像生成后端，`GenerateRequest`/`GenerateResponse` 为覆盖两类后端的超集模型，`openai` 后端走 `/v1/images/generations` 带 Bearer 鉴权，`vllm_omni` 走 `/v1/chat/completions` 把扩散参数塞进 `extra_body`，新增后端只需实现接口并 `Register`。三套机制共享同一设计哲学：用 IR/接口隔离差异，用旁路/超集保留细节，用注册表实现可扩展。
