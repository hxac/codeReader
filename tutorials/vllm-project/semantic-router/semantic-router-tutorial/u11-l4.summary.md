本讲讲解 Semantic Router 的可观测性三件套及其在启动序列中的接入。结构化日志基于 zap，在配置加载前由 `SR_LOG_*` 环境变量初始化，`ComponentEvent` 自动带 `component`/`event` 字段且「调用方优先」不覆盖。Prometheus 指标分两套：全局包级指标（`promauto` 声明即注册、空值归一为 Unknown、批处理按 `sample_rate` 概率采样）与窗口化指标（环形缓冲 + 后台 goroutine 周期重算 P50/P95/P99，空窗口显式置 0）；`inflight` 用自定义 Collector 在抓取时现拉 `pkg/inflight`，确保其为唯一真相、避免镜像漂移。追踪基于 OpenTelemetry，遵循「信号→决策→插件→模型」四层 span 层级，span 名与属性键集中定义；OTLP 导出器不阻塞启动、采样用 `TraceIDRatioBased` 保证整条 trace 完整、span 上下文存于 `RequestContext.TraceContext` 跨阶段传递。三者在 `main()` 的接入顺序为「日志最早、指标/追踪居中、全部失败宽容」，`startup_complete` 日志用 11 个字段一次性交代实例的监听端口与能力开关，是排障第一手线索。三者通过 `request_id`/`trace_id` 关联，可从慢指标下钻到单次 trace 再到具体日志行。贯穿全讲的哲学：可观测性是可选能力，初始化失败只 warn 不 fatal，绝不拖垮核心路由。
