本讲承接 u7-l1 的 DSL 语法与 AST，讲解 AST 与运行时配置 `RouterConfig` 之间的双向翻译，聚焦 `pkg/dsl/` 编译器与反编译器。核心分三个模块：① 编译总线，`Compile`/`CompileAST` 是纯函数式「人友好→机器友好」的单向阀门，先种 `DefaultGlobalConfig()` 默认值，再按「插件模板→信号→投影→模型→路由」固定顺序逐块下沉，错误采用累积而非抛出模型。② 逐块编译中，ROUTE→Decision 是重点：WHEN 布尔树经 `compileBoolExpr` 递归翻译成 `RuleNode` 树（注意 `RuleCombination` 只是 `RuleNode` 的类型别名），叶子填 `Type`+`Name` 与可选 `Predicate`，编译期对同级 AND/OR 做拍平优化；信号走按族分派表；每条 RECIPE 用 `newScopedCompiler` 建全新实例，从结构上杜绝跨配方符号串用，兑现 recipe 隔离契约。③ 反编译方向，`Decompile`/`DecompileRouting` 把配置写回 DSL 文本，`decompileRuleNode` 做逆拍平（OR 须加括号保语义），`EmitUserYAML` 经 `denormalize*`/`pruneZeroValueInfra` 把扁平结构逆规范化回嵌套形态。核心结论：YAML↔DSL 往返定义在 `CanonicalRouting` 层而非文本层，DSL 文本不逐字可逆（存在分段注释、PRIORITY 总写出、插件模板化、MODEL 省略等无损差异），但路由语义经 `reflect.DeepEqual` 严格可逆。
