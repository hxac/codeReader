`routerruntime.Registry` 是路由器进程内显式传递的运行时依赖容器，用一把 `sync.RWMutex` 线程安全地托管 6 类依赖：config、classificationService、memoryStore、vectorStore、modelSelector、learningRuntime，每对读写方法均加 nil 防御。它取代旧的全局单例：ExtProc 与 Bootstrap 作为生产者把活对象写进容器，API Server 作为消费者在每次请求中现读，二者共享同一指针，故控制面操作的就是数据面正在用的对象。配置热重载遵循两条不变式——`PublishRouterRuntime` 在一次加锁内原子发布 config+分类服务+记忆库，`RefreshRuntimeConfig` 坚持「先校验再切换」，分类服务拒绝即整笔回滚，绝不发布半成品。本讲引入的关键术语有：窄接口缝、数据面/控制面、原子发布、`LearningRuntime`。其中 `learningRuntime` 是唯一接口型字段，只暴露 `UpdateOutcome` 一个方法与 `RouterOutcome`、`RouterOutcomeResult` 等纯数据类型，笨重的 `routerLearningRuntime` 实现留在 extproc 包内，使 API Server 完全不依赖 extproc 内部。此外还有一条反向通路：API Server 通过 `UpdateConfig` 与分类服务 `RefreshRuntimeConfig` 将新配置写回 Registry，让数据面立即生效。
