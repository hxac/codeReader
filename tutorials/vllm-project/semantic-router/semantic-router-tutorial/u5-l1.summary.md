本讲是「请求处理主链路」首篇，承接 u4-l3 的 ExtProc 四阶段，覆盖请求体解析、入口解析、信号输入构建三模块，回答请求体字节如何被解析为可路由状态并选定配方。

SR 采用「gjson 快速抽取优先、完整 SDK 解析延迟」策略：先轻量抽取 model、用户文本与会话形状计数产出 `FastExtractResult`，仅在真要改写 body 时才完整解析，使缓存、限流等早退路径只付低开销。

核心是 `model` 字段三类语义：auto 别名（`auto`/`vllm-sr/auto`/`MoM`）走 default recipe、entrypoint 虚拟名走映射 recipe、具体后端模型走 passthrough 绕过配方；两条边界由 `RequestRoutingContext` 三态枚举（unresolved/recipe/passthrough）严格区分以避免 nil 歧义，后续 decisions 与 classifier 均从 `ctx.Routing` 派生且命名 recipe 不跨边界回退。

信号输入构建是搬运解耦层：`signalConversationHistoryFromFastExtract` 把协议无关的 `FastExtractResult` 转成 `signalConversationHistory`，与 `originalModel` 分轨交棒给 `performDecisionEvaluation`。本讲止于决策求值之前的准备，布尔规则求值留待 u5-l2。
