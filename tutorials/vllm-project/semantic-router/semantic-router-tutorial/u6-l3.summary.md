本讲补齐模型选择的脚手架三块：运行时、库存与定价。启动期，`PrepareRouterRuntime` 将本地嵌入/BERT/多模态/模态分类模型编排成可并发的任务清单，交带依赖图、并发上限与 panic 自愈的执行器跑，产出 `EmbeddingRuntimeState`：`AnyReady` 表示至少装好一个嵌入模型，`ToolsReady` 专指工具库与 ML 选择依赖的统一嵌入通路就绪（蕴含前者）。随后 `WarmupRouter` 对请求路径状态热身，任务一律 `BestEffort` 且须显式声明就绪或跳过原因。模型库存分两层：`modelinventory` 是 `/info/models` 的响应类型（反映本地已装载模型与下载进度），`config.ExternalModelConfig` 是外部 LLM 接入目录，分类器按 `model_role` 取用。`modelpricing` 为纯函数包：`Normalize` 把重叠 token 明细切成互斥输入桶（缓存命中优先），`Cost` 按四档单价算总成本，`InputCostMultiplier` 将输入成本归一化到 [0,1]，供 router learning 的 EWMA 慢慢调整打分；配置侧 `MaxCostPer1M` 则直接剔除昂贵候选。成本在响应阶段计算，对排序影响间接而持续。
