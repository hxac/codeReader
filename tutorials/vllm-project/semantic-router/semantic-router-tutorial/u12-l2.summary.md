本讲围绕 `deploy/` 讲清 SR 的集群部署形态。**资产边界**：`deploy/` 只放「创建或配置部署目标」的产物，路由配置、recipe、运行时示例归 `config/`、`tools/`，二者物理隔离、独立演进。**Helm chart**（`deploy/helm/semantic-router`）只渲染 ExtProc router 单容器（gRPC 50051 / api 8080 / metrics 9190），**不部署 Envoy**；其 Deployment 与 `main()` 启动序列一一对应（ConfigMap 喂 config、PVC 喂模型、TCP 50051 探活即就绪）。chart 另渲染常规、headless、metrics 三个 Service，其中 headless Service（`clusterIP: None`）专为 gRPC HTTP/2 长连接的客户端侧负载均衡而设，绕开 kube-proxy 局限；并设一条安全闸门，多副本且开启本地学习状态时渲染期直接 fail。区分两种「Envoy↔router」拓扑：**sidecar 同 Pod 模型**（KServe/OpenShift，Envoy 经 `127.0.0.1:50051` 访问 router）与 **gateway 远程调用模型**（Istio 等，经集群 Service DNS 访问）。`deploy/kubernetes/` 下各子目录即不同 Envoy 网关实现的对接清单，常配 `semantic-router-values` 覆盖 chart 取值；另含 local/kserve/openshift/operator 等部署变体，operator 变体由 `SemanticRouter` CRD 驱动，留待下一讲承接。
