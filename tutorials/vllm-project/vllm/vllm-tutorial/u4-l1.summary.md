本讲是 u4 调度单元的起点，剖析 V1 对「一次生成任务」的统一抽象 `Request`（`vllm/v1/request.py`），分四个最小模块。①核心字段：输入 `prompt_token_ids`、输出 `_output_token_ids`、全量 `_all_token_ids`（=prompt+output，构造时即拷贝 prompt）、进度计数 `num_computed_tokens`，输出经 `append_output_token_ids` 同步追加；它与跨进程可序列化的 `EngineCoreRequest` 通过 `from_engine_core_request` 在进程边界转换。②`RequestStatus` 是 `IntEnum` 状态机，「是否完成」靠 `status > PREEMPTED` 一次整数比较判定，枚举顺序即隐式契约；完成态经映射产出对外 `FinishReason`（stop/length/abort 等）。③生命周期为 `WAITING → RUNNING → FINISHED_*`，中间可经历抢占循环（`RUNNING → PREEMPTED → WAITING`），所有状态变迁均由调度器驱动，`Request` 本身是被动载体，抢占时进度清零重算。④`num_computed_tokens` 在 V1 异步调度下为「乐观计数」：`schedule()` 阶段即推进，由 `num_in_flight_tokens` 等簿记量在结果回来后兑现，并直接决定 KV 缓存的分配起点。
