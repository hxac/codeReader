本讲定义 `Request`（`vllm/v1/request.py`）为 V1 对一次生成任务的统一抽象，核心字段含 `prompt_token_ids`（输入）、`_all_token_ids`（prompt 加输出全量）、`num_computed_tokens`（已写入 KV 的进度计数）、`sampling_params`、`status` 与可选的 `session_id`。`RequestStatus` 是 `IntEnum` 状态机，「是否完成」靠 `status > PREEMPTED` 单次整数比较判定，枚举顺序本身即隐式契约。请求生命周期为 `WAITING → RUNNING → FINISHED_*`，显存不足时经 `PREEMPTED` 进入抢占循环，所有状态变迁均由 Scheduler 驱动，`Request` 自身是被动的数据载体。V1 异步调度下 `num_computed_tokens` 为乐观计数，`schedule()` 阶段即推进，配合 `num_in_flight_tokens` 在 GPU 结果回来后兑现，抢占时清零重算。`session_id` 属「引擎只搬运、不消费」的请求级字段，经可序列化的 `EngineCoreRequest` 跨进程透传，由 `from_engine_core_request` 落到 `Request`，全程不参与调度或采样决策。
