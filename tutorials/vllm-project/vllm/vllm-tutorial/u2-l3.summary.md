本讲承接 u2-l2，回答「服务跑起后，调用方如何向 vLLM 发请求」。核心结论：vLLM 通过实现 OpenAI 兼容 HTTP 接口，让任何用 `openai` SDK 的代码只改 `base_url`（指向本地 `http://localhost:8000/v1`，`/v1` 不可省）即可调用，迁移成本近乎零；客户端 `api_key` 在服务不强制鉴权时可填占位 `"EMPTY"`。引入的关键术语：base_url、OpenAI 协议（事实标准契约）、SDK 方法与 HTTP 路径的映射、流式与非流式返回（`ChatCompletion` 对象 vs `ChatCompletionChunk` 迭代器，服务端对应 `JSONResponse` 与 `text/event-stream` 的 `StreamingResponse`）。覆盖三块源码方位：示例脚本 `openai_chat_completion_client.py` 串起「列模型→发对话→打印」全流程，用 `models.list()` 动态取模型名；`api_server.py` 是 HTTP 服务总装配车间，`build_app` 建 FastAPI 应用并按任务挂路由器，`init_app_state` 把 `engine_client` 写入 `app.state`，`serve_http` 跑 uvicorn，端口在引擎初始化前先绑以避竞态；`/v1/chat/completions` 定义于 `chat_completion/api_router.py`，`/v1/models` 定义于 `models/api_router.py`（返回基础模型与 LoRA 适配器），均经 `generate/api_router.py` 在 generate 任务下挂载。关键方位感：路由处理函数不直接跑推理，而从 `app.state` 取 serving 对象驱动引擎，HTTP 层与引擎层由此解耦；引擎内部的多进程实现留待 u3 展开。
