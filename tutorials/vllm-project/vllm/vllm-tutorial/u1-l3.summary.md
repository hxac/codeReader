本讲是 vLLM 源码的「地图讲」，按六个最小模块建立目录方位感：顶层布局、`vllm/` 包与公共 API 懒加载、`entrypoints`、`v1`、`engine`+`config`、`model_executor`+`distributed`。核心结论：仓库顶层除 Python 主包 `vllm/` 外，还含原生扩展源码（`csrc`/`cmake`/`rust`）与构建脚本（`setup.py`/`CMakeLists.txt`）；`vllm/__init__.py` 用 `MODULE_ATTRS`+`__getattr__` 实现懒加载，避免 `import vllm` 拖入全部重型依赖。`entrypoints` 是进入系统的两扇门——离线推理用 `LLM` 类，在线服务用 `vllm serve`。关键区分：`vllm/v1` 是 V1 当前架构，承载 Engine Core 调度、GPU Worker 执行、采样等运行时职责；`vllm/engine` 已退化为旧引擎兼容别名，实际指向 V1 实现。`vllm/config` 用 `VllmConfig` 聚合各子配置作为引擎级全局状态。`model_executor` 集中模型实现与可复用并行层，`distributed` 管进程组与 TP/PP/DP 通信，二者共同支撑「初始化时分片/量化」的设计。
