本讲聚焦 vLLM V1 运行时核心 EngineCore，即「引擎的内层循环」：只管调度、执行与产出，不问请求来源。它持有 scheduler、model_executor 与若干队列，初始化须先经显存 profiling 算出 KV 缓存 block 数，方能创建调度器。

子类 EngineCoreProc 为其套上进程外壳：以 ZMQ 与 API Server 通信，用两条守护线程做输入/输出 ZMQ IO，靠 input_queue、output_queue 解耦 IO 与主循环，使序列化与 GPU 前向并行。

run_busy_loop 是三段式驱动循环（取输入→发布负载统计→跑一步），借 has_work() 与阻塞式 input_queue.get() 实现「有活就干、没活就睡」的低延迟忙等待；run_engine_core 为子进程入口，由 CoreEngineProcManager 拉起。

一轮 step 为「调度→执行→回写」：schedule() 产 SchedulerOutput，execute_model(non_block=True) 返回 Future 以让 CPU 语法计算与 GPU 前向并行，update_from_output() 回写状态并产 EngineCoreOutputs。关闭为协作式：信号仅置标志位并唤醒，下一轮 _handle_shutdown 安全退出，避免 step 中途被打断。
