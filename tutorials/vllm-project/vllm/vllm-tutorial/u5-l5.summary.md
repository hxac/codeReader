本讲覆盖前端进程的三个输入处理模块。InputProcessor 是输入总入口：校验、委托 InputPreprocessor.preprocess 对原始文本分词、按 max_model_len-seq_len 补全未填的 max_tokens、打包出跨进程序列化的 EngineCoreRequest；本版本新增 session_id 形参并一路透传，性质为「只搬运不消费」。真正的分词仅在原始文本分支发生，阻塞分词经 process_inputs_async 丢入线程池以免卡住事件循环。Detokenizer 由 OutputProcessor 驱动，将生成 token 增量还原为文本——因 BPE 不可逐 token 独立解码，Fast 版用 DecodeStream 原生预热、Slow 版用偏移指针只重算末尾；它兼做 stop 字符串检测，靠 stop_buffer 扣留末尾字符防误发，min_tokens 延迟停止检查。tokenizer registry 以 tokenizer_mode 字符串（auto→hf、slow→hf+use_fast=False，另有 mistral 等）映射到具体 tokenizer 类，get_tokenizer 为加载入口。三者均在前端、不碰 GPU，体现 V1 将 CPU 输入处理与 GPU 计算分进程的分工。
