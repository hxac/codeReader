本讲聚焦 V1 在线服务路径中的 `AsyncLLM`——它是 API Server 眼中的「引擎客户端」，也是 EngineCore 进程的「上游搭档」，自身不跑模型，只住前端进程、通过 ZMQ 把请求送往后端。引入两层易混抽象：上层接口 `EngineClient`（屏蔽引擎实现）与下层 IPC 客户端 `EngineCoreClient`（异步为 `AsyncMPClient`，封装 ZMQ/序列化/进程拉起），二者构成核心「进程边界」。`add_request` 负责输入预处理与「双侧登记」（本进程 `OutputProcessor` 绑定队列 + 跨进程 `engine_core.add_request_async`），返回每请求队列 `RequestOutputCollector`；`generate` 仅循环消费并 `yield`。一个唯一后台 `output_handler` 批量拉回输出、分块处理、推入各队列，形成「单生产者→多消费者」模型，输出回传经收帧解码→outputs_queue→get_output_async→process_outputs→各队列→generate 五个站点。进阶的流式输入 `StreamingInput` 将输入本身变为 `AsyncGenerator`，靠 `prompt_token_ids=[0]` 哨兵请求宣告结束，不支持 pooling/n>1/FINAL_ONLY/stop。
