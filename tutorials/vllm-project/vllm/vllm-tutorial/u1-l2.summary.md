本讲阐明 vLLM 并非纯 Python 库，而是附带一批用 C++/CUDA/Rust 编译的本地扩展（`.so`），因此安装分「装 Python 包」与「获取/编译扩展」两层。核心模块有四：`pyproject.toml` 提供静态元数据与构建后端（setuptools），其依赖列表是动态的；`setup.py` 充当编译总指挥，通过 `load_module_from_path` 读取 `envs.py`，检测 `VLLM_TARGET_DEVICE`（cuda/rocm/cpu 等），组装 `ext_modules`（`CMakeExtension` 列表），并在 `cmake_build_ext`（真编译）与 `precompiled_build_ext`（跳过编译）之间二选一；`VLLM_USE_PRECOMPILED` 会从 wheels.vllm.ai 下载官方预编译 `.so`，跳过全部本地编译，是只改 Python 代码时的推荐安装方式；`CMakeLists.txt` 负责实际编译，用 `define_extension_target` 定义 `_C_stable_libtorch` 等扩展目标，并靠 stable ABI（SABI）让一份 `.so` 跨 Python 版本通用，编译并行度由 `MAX_JOBS`/`NVCC_THREADS` 控制。核心矛盾是「好装」与「跑得快」的权衡。开发流程强制使用 `uv` + `.venv` + `pre-commit`，禁止系统 `python3` 与裸 `pip`。关键术语：本地扩展、构建后端、`VLLM_TARGET_DEVICE`、`VLLM_USE_PRECOMPILED`、`CMakeExtension`、stable ABI、可编辑安装（`-e`）。
