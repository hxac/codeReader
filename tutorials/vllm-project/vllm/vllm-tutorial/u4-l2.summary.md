本讲解析 vLLM V1 调度器 `Scheduler`。它实现 `SchedulerInterface`，是纯 CPU 上的决策者，自身不碰 GPU，每轮 step 只回答「算哪些请求、各算几个 token」。V1 采用统一 token 预算模型：没有独立的 prefill/decode 阶段，只有「本轮给每个请求分配多少 token」，一套逻辑同时覆盖分块 prefill、前缀缓存与推测解码。

`schedule()` 三步走：先保 RUNNING 请求（扣减 `token_budget`），再用剩余预算接纳 WAITING 请求（查前缀缓存命中），最后组装 `SchedulerOutput`。`num_computed_tokens` 在调度阶段乐观推进，由 `update_from_output` 执行后修正，使 CPU 调度与 GPU 计算重叠。

当 KV block 不足时触发抢占（preemption）：换出优先级最低的 RUNNING、释放 block、进度清零回 WAITING 重算（计算换显存），watermark 用于缓冲。`SchedulerOutput` 区分 `scheduled_new_reqs`（发全量）与 `scheduled_cached_reqs`（发增量）以最小化跨进程通信。

关键术语：`SchedulerInterface`、`SchedulerOutput`、`token_budget`、`num_scheduled_tokens`、preemption、`num_computed_tokens`。
