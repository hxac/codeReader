本讲在 u4-l4（PagedAttention 与 ref_cnt 共享机制）之上讲解前缀缓存（prefix caching）：当多个请求共享同一段前缀（如 system prompt）时，直接复用已算好的满块 KV，同时省算力与显存且不改变输出，是契合 block 粒度的「免费午餐」，V1 中 enable_prefix_caching 默认开启。核心是链式块哈希：每个满块的哈希由「父块哈希＋本块 token＋额外键」递推得到，唯一指纹「截至该块的整个前缀」，请求在创建与追加 token 时由 request_block_hasher 增量维护到 Request.block_hashes，额外键纳入多模态、LoRA、cache_salt 等以保证唯一、避免误命中。BlockPool 维护反向查表 cached_block_hash_to_block（哈希＋group_id→物理块）；调度 WAITING 请求时 get_computed_blocks 经 find_longest_cache_hit 逐块查表得到最长命中前缀（留最后一个 token 重算以拿 logits），命中块经 touch 使 ref_cnt＋1 并移出空闲队列而被复用，命中 token 数折算进 num_computed_tokens 从而跳过对应 prefill。缓存只登记写满的整块（cache_full_blocks）；驱逐发生在分配新块且 LRU 队首恰为缓存块时（_maybe_evict_cached_block），free_blocks 仅让带哈希的块作为 LRU 候选存活，故释放≠驱逐；可用 cache_salt 注入首块做多租户隔离、reset_prefix_cache 在换权重或压测时显式清空。
