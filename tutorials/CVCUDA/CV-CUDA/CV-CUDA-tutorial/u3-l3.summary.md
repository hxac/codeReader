本讲拆解 CV-CUDA 算子的两种变体：allocating（如 `cvcuda.flip`）由库创建并返回新输出，`_into`（如 `flip_into`）直接写入调用者预分配的 `dst` 并原样返回；源码上前者只是后者的薄包装，多出一次 `Tensor::Create` 再委托 `_into` 逻辑。该步骤按 shape+dtype+layout 为键查 Python 层对象缓存（仅 Python 层有，C/C++ 层无）：命中复用、未命中才 cudaMalloc 并入缓存；缓存线程局部、默认限额为总显存一半，稳态同形状循环近零分配。变长批（ImageBatchVarShape）的 allocating 需逐图重建输出批，开销随批内图数线性增长，故从 `_into` 获益更大。选择规则：原型或形状多变用 allocating；固定形状生产管线、紧循环、需确定性显存行为用 `_into`，且 dst 的 shape/layout/dtype 必须与算子产出完全一致，否则在 CPU 侧抛异常。算子对象本身（CreateOperator）也走缓存，为两变体共有开销。
