本讲讲解 CV-CUDA 从源码构建的完整链路，核心文件为根 CMakeLists.txt、build.sh、CMakePresets.json 与 Docker 镜像配置。关键结论：根 CMakeLists 是"总装车间"，通过 BUILD_LIB/BUILD_PYTHON/BUILD_TESTS/BUILD_BENCH 等开关矩阵决定挂载哪些子树，且 BUILD_TESTS=ON 会传染性强制开启三个测试子开关；build.sh 是包装层，自动选最新 gcc、启用 Ninja/ccache、用 CVCUDA_BUILD_JOBS 控制总并行度，默认目录 build-rel/build-deb；CMakePresets 提供以 dev 为基座的四个预设（dev/dev-debug/dev-py/dev-bench），加速核心是 CMAKE_CUDA_ARCHITECTURES=native 只编译本机 GPU 架构。依赖解析采用"全 find_package、零 FetchContent"策略：CUDAToolkit(≥12.2)、GTest、pybind11、dlpack、nvbench、nvtx3 头文件必须预装，这正是 Docker devel 镜像预装它们的原因（版本统一由 versions.env 管理）。最终产物是 libnvcv_types.so 与 libcvcuda.so，落在构建目录 lib 下，Debug 构建带 _d 后缀。关键术语：配置/构建两阶段、缓存变量、preset、生成器、SM 架构、native、ccache、builder 与 devel 两族镜像。
