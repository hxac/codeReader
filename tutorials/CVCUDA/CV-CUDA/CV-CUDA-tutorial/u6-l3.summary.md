本讲拆解 nvcv 分配器抽象的四层结构：最底层是纯 C 契约 NVCVResourceAllocator（一对 alloc/free 函数指针、透传 ctx 与 cleanup），按资源类型分 host、CUDA、host-pinned 三个频道；往上是公开 C++ 包装 Allocator（CoreResource 引用计数句柄，hostMem/cudaMem 拆单频道视图）与 priv 层 IAllocator（NVI 惯用法，公开层集中校验 size 非负、对齐为 2 的幂且整除）。实现只有两个：进程唯一的 DefaultAllocator（对齐 new、cudaMalloc、cudaHostAlloc(WC|Mapped)，均复查对齐、失败即抛）与可部分定制的 CustomAllocator（未定制频道自动回填默认）；空句柄经 GetAllocator(nullptr) 解析到前者。容器与分配器经 Requirements 协商：Tensor 先算 stride 与 alignBytes 并 addBuffer 写入按 log₂ 块大小分桶的清单，CalcTotalSizeBytes 压成总量后仅一次 allocCudaMem，分配器被 Tensor 引用计数保活、析构对称释放。自定义路径用 CustomMemAllocator 把 lambda 编组成 C 描述符（平凡小则内联 ctx 零堆分配），再由 CreateCustomAllocator 聚合。核心结论：Python 对象缓存决定「要不要分配」，Allocator 决定「内存从哪来」，缓存命中不会触碰 allocator；Python API 不暴露分配器参数，仅 WorkspaceCache 以 CustomAllocator<>{}（即默认分配器）使用该抽象，u8-l3 将展开。
