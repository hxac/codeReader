本讲围绕 CV-CUDA 的 C ABI 边界机制展开，含四个模块：①错误双轨制——C 侧用 `NVCVStatus` 返回码配合线程局部存储（`CoreTLS`）中的「最后错误」消息，Get 读取即重置、Peek 只读不重置；C++ 侧 `nvcv::Exception` 与 `nvcv::Status` 枚举数值一一对应，错误码只能末尾追加以保 ABI。②异常翻译边界——异常不可穿越 `extern "C"`，每个 C API 函数体都是 `nvcv::ProtectCall` 包 lambda，`SetThreadError` 按异常类型映射错误码并写 TLS（bad_alloc→OUT_OF_MEMORY，其余→INTERNAL）；库内部只抛 priv 异常，公开异常构造即记账但禁止内部抛出。③以 `cvcudaFlipSubmit` 为例的三道防线：句柄校验（NULL/类型/版本）、exportData 张量视图校验、legacy 内核 dtype 与布局白名单，错误码契约写在头文件 `@retval` 与 Limitations 表。④ELF 符号版本——`CVCUDA_DEFINE_API` 生成 `_v主_次` 后缀真实符号加 `@@CVCUDA_主.次` 默认版本别名，`_OLD` 宏用单 `@` 保留旧签名，实现库升级不破坏老程序；句柄 `version()` 与 `nvcvGetVersion` 构成运行期补充防线。
