本讲为代码块子系统收尾篇，专攻三种交互模式中最特殊的 `inline` 模式。核心结论有三：其一，`inline` 仅用 Header/Footer Widget 替换两行围栏行，代码正文留在 `contentDOM` 作真实可编辑文本，点击即输入、高亮随输入实时刷新。其二，高亮走 HAST→mark 路线——`highlightCodeHast` 返回原始 HAST 树，`hastToMarkDecorations` 递归遍历并以 `offset` 追踪字符位置，将带类名文本片段翻译为 `Decoration.mark`，遵循「偏移仅在 text 节点推进、类名向下继承且内层优先」两条规则，复用同一套 `.hljs-*` 主题。其三，因 `drawSelection` 选区层落在不透明背景之后，`inline` 额外挂载仅本模式启用的 `codeBlockSelectionPlugin`，以 `cm-codeblock-sel` mark 把选区画进 `.cm-line` 保证可见。`inline` 不调 `shouldShowSource`、不响应选区变化，源码态由 `setCodeBlockSourceMode` 按钮驱动，与 `auto`/`toggle` 的 innerHTML 路线形成本质分叉。
