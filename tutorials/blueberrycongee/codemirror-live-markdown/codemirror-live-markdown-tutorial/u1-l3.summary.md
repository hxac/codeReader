本讲梳理「源码到浏览器可见效果」之间的工具链与命令，覆盖四个最小模块：npm scripts 与发布产物、tsup 构建配置、Vitest＋jsdom 测试环境、GitHub Actions CI 矩阵。

核心结论：tsup 以 `src/index.ts` 为单一入口，一次性产出 ESM、CJS 与 `.d.ts` 三种产物，并把五个 CodeMirror/Lezer 包标记为 external，与 peerDependencies 一一对应，以保证宿主使用单一 CodeMirror 实例。测试因 `ViewPlugin`/`WidgetType.toDOM` 依赖浏览器 DOM，必须跑在 jsdom 环境中，`globals:true` 让 describe/it/expect 免导入；测试文件按五层 `__tests__/` 分布，共 19 个，读测试即读库的最佳捷径之一。CI 用 `npm ci` 在 Node 18/20 矩阵上依次跑 `lint → typecheck → test → build` 检查链，并单独上报覆盖率。

本讲最重要的易错点：根目录 `npm run dev` 是 `tsup --watch`（重新打包库），demo 目录的 `npm run dev` 才是 `vite` 启动网页（端口 5173）；demo 通过 Vite 别名将包名直接指向 `src/index.ts`，改源码即时生效，页面呈现 5 个真实编辑器。

引入的关键术语：构建、打包器（tsup/esbuild）、模块格式（ESM/CJS）、external、对等依赖、测试运行器（Vitest）、jsdom、条件导出（exports）、source map、tree shaking、`prepare` 生命周期脚本、CI 矩阵策略、`npm ci`。
