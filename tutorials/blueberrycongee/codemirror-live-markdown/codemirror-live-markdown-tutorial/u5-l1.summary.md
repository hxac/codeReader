本讲聚焦 utils 层工具 `codeHighlight.ts`，它是代码块子系统的「高亮引擎」，不依赖 CodeMirror，却同时服务两种渲染模式。

最小模块有三：① **lowlight 懒加载**——lowlight 是把 highlight.js 包装成返回 **HAST 树**的库，被设为**可选对等依赖**。为避免「lowlight 没装就崩库」，源码用动态 `import()` 延迟加载，并靠**三态标记** `lowlightAvailable`（`null`/`true`/`false`）实现「一次异步初始化 + 多次同步查询」的协作：`initHighlighter()`（异步，启动时调一次，用 `createLowlight(common)` 造实例）与 `initLowlightSync()`（同步，每次高亮只读缓存标记）解耦了昂贵加载与廉价查询。② **两个高亮函数**——`highlightCode` 返回 `HighlightResult`（含 `html` 字符串），服务 widget 的 `innerHTML`（auto/toggle 模式）；`highlightCodeHast` 返回原始 HAST 树，服务 plugin 的 `Decoration.mark` 装饰（inline 模式，保留可编辑性）。这是后续讲义「HTML 路线 vs HAST 路线」的分叉点。③ **registerLanguage**——用 highlight.js 的 `LanguageFn` 注册 `common` 集合外的语言。

核心结论是贯穿三者的**优雅降级**：空代码、lowlight 不可用、语言未注册、运行抛错等情形都安全落到「转义纯文本」或 `null`，绝不崩库。HAST 三种节点（`root`/`element`/`text`）与 `detected` 字段（标识是否自动检测）是后续讲义承接的关键术语。
