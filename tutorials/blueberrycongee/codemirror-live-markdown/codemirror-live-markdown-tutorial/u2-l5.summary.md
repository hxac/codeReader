本讲讲解 `markdownStylePlugin`，它是继标记显隐插件 `livePreviewPlugin` 之后的第二种基础 Live Preview 插件，专职为**内容节点**添加静态样式。其核心是一张「语法节点名 → CSS 类」的查找表 `styleMap`，覆盖 `ATXHeading1-6`、`StrongEmphasis`、`Emphasis`、`Strikethrough`、`InlineCode`、`Link` 等内容容器节点，而 `EmphasisMark`、`HeaderMark` 等标记符号节点则不在其中。`build` 用 `syntaxTree.iterate` 遍历语法树，对命中表的节点 push 一条 `Decoration.mark`，落在代码块内（由 `isInsideSkippedParent` 判定）则跳过。标题节点会额外追加一条 `Decoration.line`（`cm-heading-line`）做行级样式，与 `mark`（`cm-header-N`）的字号/字重叠加而不冲突——前者管整行，后者管文字，注意两者 `range` 参数不同：mark 需 `from, to`，line 只需一个定位点。引入的关键概念包括：内容节点与标记节点的区分、`Decoration.mark` 与 `Decoration.line` 的分工、以及样式接力链「节点名 →（styleMap）→ CSS 类 →（editorTheme）→ 真实样式」。本讲最重要的结论是**职责分离**：`markdownStylePlugin` 负责**静态外观**，与光标位置无关，其 `update` 仅在 `docChanged` 或 `viewportChanged` 时重建，刻意不响应 `selectionSet`，因此完全不需要 `shouldShowSource`、`mouseSelectingField` 等动态状态——这正是它比 `livePreviewPlugin` 更简单高效的根因。
