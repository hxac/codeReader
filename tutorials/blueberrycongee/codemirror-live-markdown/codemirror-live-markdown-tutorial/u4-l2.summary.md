本讲实现 GFM 表格只读渲染，由三个模块协同：`tableField`（`StateField<DecorationSet>`，决策中枢）、`TableWidget`（渲染态 DOM 产出单元）、`renderInlineMarkdown`（单元格内联格式渲染器）。核心结论：表格是块级装饰，必须用 `StateField` 而非 `ViewPlugin`。显示哪一面由 `shouldShowSource` 决定——光标触碰表格则逐行加 `cm-table-source` 类进源码态（用 `Decoration.line`，仅染色不替换以便逐行编辑原始文本）；否则用块级 `Decoration.replace` 套 `TableWidget` 进渲染态。`tableField.update` 手动内联「结构变化→拖拽结束→拖拽中→选区→无」的判定，等价于 `checkUpdateAction`，拖拽中冻结装饰防抖动；非法表格（`parseMarkdownTable` 返回 `null`）直接跳过、退化为纯文本。`TableWidget.toDOM` 搭 `thead/tbody`、按列把对齐写进 `style.textAlign`（`null` 不写）、`eq` 完整比较 `TableData`、`ignoreEvent` 返回 `false` 放行点击进入编辑。`renderInlineMarkdown` 先 `escapeHtml` 再按优先级替换，行内代码用占位符保护且优先级最高，输出安全 HTML 字符串。本讲仅做只读渲染，编辑结果不结构化写回；真正可编辑表格是下一讲 `tableEditorPlugin` 的内容。
