本讲讲解表格子系统的纯函数地基——`src/utils/tableParser.ts` 的 `parseMarkdownTable` 与 `tableSerializer.ts` 的 `serializeMarkdownTable`，二者均无 CodeMirror 依赖。`TableData` 是核心数据结构，含 `headers`、`alignments`、`rows` 三字段，分别对应 GFM 表格三要素：表头行、分隔行、数据行。解析器按「切行→至少两行→表头→分隔行校验→列数匹配→算对齐→归一化数据行」顺序处理，任一步失败返回 `null`，数据行被归一化到表头列数（少补空串、多则丢弃）。`alignments` 用 `'left'|'center'|'right'|null` 表达对齐，`null` 表示未指定（与显式 `'left'` 语义不同）。两个关键技巧：转义竖线 `\|` 用「占位符替换」（解析端藏转义再切分还原，序列化端 `escapeCell` 把 `|` 转义回 `\|` 并压换行为空格），两者互为对称；对齐由分隔行冒号位置决定，`parseAlignment` 优先级为 `center > left > right > null`，`alignmentCell` 为其逆映射。核心结论：序列化器总是输出带首尾竖线的规范格式，故一次 parse→serialize 往返会规整化表格（补首尾竖线、统一列数、规整对齐标记）；且序列化器不校验 `TableData` 合法性，信任调用方。这两个函数是后续 `u4-l2` 只读渲染与 `u4-l3` 可编辑表格写回（`commitCell`→`view.dispatch`）的基础。
