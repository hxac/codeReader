本讲为单元2收尾，讲数据准备脚本与 MASt3R 初始化。核心结论：4 视角下 COLMAP 的特征点三角化只能产出极稀疏点云，故推荐改用学习型双视图重建模型 MASt3R（经 MAtCha 封装调用，`--sfm_config posed --sfm_only` 意为位姿已知、仅重建点云）。`n3v2colmap.py` 分两阶段：先把 LLFF 约定的 `poses_bounds.npy`（N×17）经轴系转换、光线两两求交重定位、半径归一化，翻译成只含 `cameras` 与 `images` 的 COLMAP 静态模型（仅写每相机第 0 帧、W2C 四元数，txt 与 bin 双份，无 `points3D`），再以符号链接挑好的帧并把 `sparse/` 搬进 `mast3r_N` 工作目录；真实 CLI 参数是 `--training_view` 而非 `--cams`。`n3v2blender.py` 是依赖 ffmpeg 与 colmap 全流程的遗留备选路线，产出 `transforms_*.json` 与 `points3d.ply`；数据集路由上 `sparse/` 优先于 `transforms_train.json`。消费契约方面：`readColmapSceneInfo` 要求 `images.bin` 位姿覆盖 `images/` 目录全部 png（数量断言），故做评估须用全部视角生成位姿，而初始化点云只由训练视角重建以避免泄漏；`points3D.*` 在首次打开场景时懒转换为 ply 缓存并按 `num_pts` 下采样。脚本写出的文件与 `colmap_loader` 解析器字节级互逆。README 中 `mast3r_${N_DENSE}` 与 MASt3R 实际运行目录存在不一致，待确认。
