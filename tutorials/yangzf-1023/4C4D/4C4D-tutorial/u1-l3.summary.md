本讲绘制 4C4D 仓库地图：入口层（train.py 训练、render.py 推理）、框架层（scene、gaussian_renderer、module、arguments）、支撑层（utils、scripts、configs 及四个 CUDA 子包），并引入入口脚本、包、import 依赖图、CUDA 子包、OmegaConf 配置等术语。核心结论：train.py 顶层链为导入 CUDA 扩展 → 三组参数注册与脚本级参数 → yaml 递归合并 → 参数派生 → training()，后者按 Coefficient（可选）→ GaussianModel → Scene → training_setup 组装，一次迭代含 render、loss、densify、step、save 五阶段。render.py 是纯前向入口，分 --validate 与 --traj 两种模式，restore 传 None 跳过优化器。两入口共享 scene（Scene 靠回调表分发数据集）与唯一的 render 函数；module（Coefficient）仅训练使用，因衰减已写入不透明度；两入口默认参数不同（如 gaussian_dim 4 对 3），一致性靠同一份 yaml 保证。本讲还提醒识别遗留代码（flask 误引入、未被调用的函数、README 参数名不一致）。
