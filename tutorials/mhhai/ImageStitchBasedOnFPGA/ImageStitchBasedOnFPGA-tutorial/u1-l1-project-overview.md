## 2. 前置知识

本讲是入门第一篇，要求很低，但以下几个概念会帮你更好理解：

- **图像拼接（Image Stitching）**：把多张**有重叠区域**的照片拼成一张更大的图。最熟悉的例子是手机相机的「全景拍照」——你转动手机，相机连续拍摄多张，再合成一张长图。本项目是它的「多路摄像头 + 实时 + 硬件」版本。
- **全景（Panorama）**：视角很宽、甚至 360° 环绕的图像。七路摄像头就是用 7 个摄像头朝不同方向拍摄，拼成一个超宽视野的画面。
- **FPGA（现场可编程门门阵列）**：一种可以通过编程重新连线、重新定义硬件电路的芯片。和 CPU「一条一条顺序执行指令」不同，FPGA 可以让很多电路**同时并行**工作，适合做高速图像处理。
- **OpenCV**：一个著名的计算机视觉开源库，里面有现成的图像拼接函数。项目用它作为**软件参考实现**（即「正确答案」），再把其中关键步骤搬到 FPGA 上。

> 一个核心直觉：**软件（OpenCV）功能全、好开发，但不够快；FPGA 快、能并行，但开发难。** 本项目就是在这两者之间做权衡与移植。这个直觉会贯穿整本手册。

如果你对上面任何一个概念完全陌生，也不用担心——本讲会用通俗的方式重新解释，后续讲义还会结合源码深入。

### 4.1 项目说明

#### 4.1.1 概念说明

先回答最根本的问题：**这个项目在做什么？**

项目名叫 **ImageStitchBasedOnFPGA**，直译就是「基于 FPGA 的图像拼接」。README 开篇一句话点明了主题：

> 毕业了，说下七路摄像头拼接。

参见源码 [README.md:L1-L2](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/README.md#L1-L2)，这里的「七路摄像头」指的是用 **7 个摄像头**同时朝不同方向拍摄，再把 7 路画面**实时**拼接成一幅超宽视野的全景图。

把它拆成三个关键词来理解：

1. **七路摄像头**：多路输入。7 个摄像头同时工作，每路都在源源不断地产生图像数据。
2. **图像拼接**：把 7 幅有重叠区域的图，对齐、投影、找缝合线、融合，变成 1 幅大图。
3. **基于 FPGA（实时）**：所有这些处理都要在硬件上**流水线式、并行地**完成，以满足视频帧率的实时性。

那么**为什么要用 FPGA，而不是直接用 OpenCV 写个软件搞定？** 这是理解整个项目的关键直觉：

| 维度 | 软件（OpenCV / CPU） | 硬件（FPGA） |
| --- | --- | --- |
| 开发难度 | 低，函数调用即可 | 高，要写 RTL、调时序 |
| 功能完整度 | 高，OpenCV 上万行现成代码 | 只能挑关键步骤移植 |
| 处理速度 | 受 CPU 顺序执行限制，7 路实时很难 | 并行流水线，可做到实时 |
| 适合场景 | 离线拼一张照片 | 7 路视频**实时**全景 |

README 里也明确提到，作者要求自己**先搞懂 OpenCV 上万行的拼接代码**，再把它往 FPGA 上搬：

参见 [README.md:L10-L11](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/README.md#L10-L11)：

> 2.圆柱面投影算法实现
> a.至少OpenCV中怎么实现图像拼接的上万行代码要搞懂；

这正好印证了本项目的核心思路：**OpenCV 是「软件参考实现」（正确答案），FPGA 是「硬件实时实现」（工程目标）。** 后续 u2 单元会带你读 `圆柱面投影.cpp`，看懂这套软件流水线。

#### 4.2.3 源码精读

**(A) 难点③：24bit 到 64bit 的异步 FIFO 位宽转换**

摄像头采集的像素是 **24bit**（常见的 RGB 各 8bit），而 DDR3 控制器的数据接口是 **64bit**。两者位宽不一致，需要一个**异步 FIFO** 做位宽转换。参见 [README.md:L6-L9](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/README.md#L6-L9)：

```markdown
1.采集的像素数据是24bit，DDR3控制器的接口是64bit，也就是说需要自己写一个
  24bit到64bit的异步FIFO转换模块。
```

为什么这件事很难？作者给了三个子要点，这里先讲最关键的两个直觉（细节留给 u3-l3）：

- **为什么不能用 Block RAM？** 参见 [README.md:L7](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/README.md#L7)。Xilinx 的 Block RAM 做位宽转换时，要求读写位宽满足 **2 的幂次关系**（如 8→16、16→64）。而 24 和 64 之间没有这种关系，所以只能改用「二维寄存器数组」自己实现存储。
  
  这里有个简单的数学直觉：24 和 64 的**最大公约数**是 8：

  \[
  \gcd(24, 64) = 8, \qquad 24 = 3\times 8,\quad 64 = 8\times 8
  \]

  所以作者把 FIFO 的**存储单元宽度定为 8bit**（参见 [README.md:L8](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/README.md#L8)）。这样一来：一次 24bit 的访问正好碰 3 个单元，一次 64bit 的访问正好碰 8 个单元——这就是 README 里「读指针一次加 3，写指针一次加 8」的由来（参见 [README.md:L9](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/README.md#L9)）。

- **为什么格雷码失效？** 普通 FIFO 用「格雷码指针」来安全地跨时钟域，前提是**指针每次只 ±1**。但这里指针一次 +3 / +8，格雷码那套降低亚稳态的办法就不灵了，需要另想办法（用写端逻辑去控制读端）。

> ⚠️ **待确认说明**：README 描述了这个 24→64 异步 FIFO 的设计要点，但**它的实现代码并未收录在仓库中**。后续 u3-l3 会基于 README 的描述来讲解设计思路，具体实现细节标注为「待确认」。

**(B) 难点④：圆柱面投影算法（插值方法的选择）**

圆柱面投影，通俗说就是把每幅照片「贴」到一个统一的圆柱面上，这样多幅图才能在同一个曲面上对齐拼接。作者指出，这里的关键抉择是**用哪种插值算法**，参见 [README.md:L12-L14](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/README.md#L12-L14)：

- **双线性插值**：质量好，但硬件实现代价大——需要**一个时钟周期内同时取出 4 个相邻像素**。作者提到两种方案（4 份相同 Block RAM / 奇偶行列分存），并坦言第二种「仿真没问题，下板时序不对」，最终用了第一种。这正体现了**算法质量 vs 硬件资源/时序**的取舍。
- **最近邻插值**：简单、易实现、工程上更推荐，但画质略差。

这套选择的「软件版」逻辑在 `圆柱面投影.cpp` 里（u2-l3 会讲），「硬件版」在 `圆柱面投影.v` 里（u2-l4 会讲）。

   - 需要注意：① 24→64bit 异步 FIFO（实现未收录，README 描述）；② 圆柱面投影算法（`圆柱面投影.cpp` / `.v`）；③ 投影时序（`圆柱面投影.v`）。

#### 4.2.5 小练习与答案

**练习 1**：为什么作者把异步 FIFO 的存储单元宽度定为 8bit，而不是 24bit 或 64bit？

> **参考答案**：因为 8 是 24 和 64 的最大公约数（\(\gcd(24,64)=8\)）。用 8bit 作为单元宽度，24bit 和 64bit 都能整除它（24=3×8，64=8×8），这样一次 24bit 访问占 3 个单元、一次 64bit 访问占 8 个单元，正好对应「指针 +3 / +8」。

**练习 2**：README 说「双线性插值的第二种方案仿真没问题，下板时序不对」。这句话反映了 FPGA 开发中哪一类常见问题？

> **参考答案**：反映了**仿真通过但实际下板（烧到芯片）时序不收敛**的问题。功能仿真验证的是逻辑对错，而下板还要满足真实时钟下的建立/保持时间等时序约束。这类问题正是难点⑤「时序问题」的体现。

**练习 3**：README 里哪个工程要点的实现代码**没有**收录在仓库中？

> **参考答案**：**24bit 到 64bit 的异步 FIFO 转换模块**没有收录。README 只描述了它的设计要点（存储器选择、宽度深度、指针递增、跨时钟域），具体实现代码不在仓库里，需标注为「待确认」。

## 6. 本讲小结

- 本项目 **ImageStitchBasedOnFPGA** 的目标是：用 **FPGA 实时**地把 **7 路摄像头**的画面拼接成一幅全景图。
- 相比 OpenCV 软件方案，FPGA 的意义在于**并行流水线、实时吞吐**；OpenCV 在本项目里扮演「软件参考实现（正确答案）」的角色。
- README 分两大块：**「做得不好」**（采集白平衡、融合小数权重）和**「需要注意」**（24→64bit 异步 FIFO、圆柱面投影算法、投影时序）。
- 24→64bit 异步 FIFO 的核心直觉：因 \(\gcd(24,64)=8\)，存储单元宽 8bit，对应「指针 +3 / +8」，且因指针非 ±1 递增，格雷码跨时钟域方案失效。
- 圆柱面投影的核心取舍是**双线性插值（质量好、资源大）vs 最近邻插值（简单、工程推荐）**。
- 这是一个**有遗留问题、仍在迭代**的工程项目；读后续讲义时要重点关注「取舍」与「坑」，而非照搬代码。
