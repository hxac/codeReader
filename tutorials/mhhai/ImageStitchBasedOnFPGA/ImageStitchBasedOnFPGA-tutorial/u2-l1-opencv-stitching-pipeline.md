## 2. 前置知识

### 2.1 什么是图像拼接

把多张**有重叠区域**的照片拼成一张更大、视野更广的全景图，就叫图像拼接（image stitching）。本项目要做的是七路摄像头同时拍、实时拼成一个 360° 圆柱全景。

要做到「无缝拼接」，核心难点是：

- **几何对齐**：每张图由于相机朝向不同，存在旋转/投影形变，必须把所有图统一映射到同一个投影面（本项目用圆柱面）。
- **重叠区处理**：相邻两张图在重叠区不能简单地一刀切，否则接缝处会有明显的亮度跳变或错位。需要找一条「最佳缝合线」并在接缝两侧做羽化融合。

### 2.2 OpenCV 的 `stitching` 与 `detail` 模块

OpenCV 把图像拼接封装成了高级类 `cv::Stitcher`，但它内部其实是一条**固定顺序的流水线**，所有零件都放在 `cv::detail` 命名空间下。本项目的 `圆柱面投影.cpp` 没有用高层 `cv::Stitcher`，而是**手动把 `detail` 下的零件一个一个串起来**，目的是为了看清每一步在干什么——这也正是本讲要读的内容。

> 前置讲义 `u1-l1` 已经讲过：这份 `.cpp` 是「软件参考实现（正确答案）」，FPGA 才是追求实时吞吐的工程目标。本讲我们先把这条「正确答案」的流水线读通。

### 2.3 用「数据流」思维读源码

读这种「流水线型」源码，最有用的思维是追踪**数据类型**：上一阶段产出的数据是什么类型、喂给下一阶段什么类型。本讲会反复强调每个阶段「输入什么、输出什么」。

## 4. 核心概念与源码讲解

### 4.1 main 函数：拼接流水线的总入口

#### 4.1.1 概念说明

`main` 函数是这份软件参考实现的「导演」：它**不实现算法本身**，而是按固定顺序调用 OpenCV `detail` 命名空间下的各个零件，把原始图片一步步变成最终的全景图。

理解 `main` 的关键有两点：

1. **顺序**：拼接是严格按阶段串行的，后一个阶段的输入依赖前一个阶段的输出，顺序不能乱。
2. **打点计时**：作者在几个关键位置用 `clock()` 插了时间戳（`t1`、`t2`、`t3`、`t4`、`t6`、`t7`），这其实暗示了作者关心的「耗时阶段」。注意到**没有 `t5`**——这不是笔误，而是作者在「投影变换」阶段前后只打了一个 `t6`，把多个小步骤合并了。

#### 4.1.2 核心流程

`main` 函数的整体流程可以用下面这段伪代码概括（行号对应真实源码）：

```

    读入 num_images=2 张 BMP 到 imgs       # L271-L276
    ── 阶段1：特征提取 OrbFeaturesFinder    # L278-L285
    ── 阶段2：特征匹配 BestOf2NearestMatcher # L287-L291
    t2 = clock()                          # L293
    ── 阶段3：相机参数估计 HomographyBasedEstimator # L296-L309
    t3 = clock()                          # L308

    t4 = clock()                          # L327
```

**练习 1**：为什么作者要在 `main` 里打这么多个 `clock()` 时间戳？

### 4.2 拼接流水线：从特征提取到融合输出的八阶段

#### 4.2.1 概念说明

`main` 函数把 OpenCV 拼接零件串成了**八个阶段**。这八个阶段是阅读本讲最核心的内容，也是后续「软件→硬件」移植的对象。下表先给一个全景：

| 阶段 | 作用 | OpenCV 模块（类） | 是否移植到 FPGA |
| --- | --- | --- | --- |
| 1. 特征提取 | 在每张图上找关键点并算描述子 | `OrbFeaturesFinder` | 否（离线做一次） |
| 2. 特征匹配 | 两两配对，找图像间对应关系 | `BestOf2NearestMatcher` | 否（离线做一次） |
| 3. 相机参数估计 | 由匹配关系估出每台相机的旋转 R | `HomographyBasedEstimator` | 否（离线做一次） |
| 4. 光束平差 | 联合优化所有相机参数，减小误差 | `BundleAdjusterRay` | 否（离线做一次） |
| 5. 圆柱面投影变换 | 把每张图映射到统一圆柱面 | `CylindricalWarper` + `warp` | **是（核心，本项目重点）** |
| 6. 曝光补偿 | 消除相邻图亮度差异 | `ExposureCompensator` | 部分（白平衡相关） |
| 7. 缝合线查找 | 在重叠区找一条「最佳接缝」 | `GraphCutSeamFinder` | **是（动态规划，本项目重点）** |
| 8. 羽化融合 | 沿接缝做加权融合，输出全景 | `FeatherBlender` | 是 |

这张表里最关键的一句话：**阶段 1–4 是「一次性标定」，在软件里做一次就行；阶段 5–8 是「每帧实时处理」，正是 FPGA 要加速的对象。** 这就是本项目「为什么写一份 OpenCV 代码」的根本原因——为了看清阶段 5–8 的算法逻辑，再把它硬件化。

#### 4.2.2 核心流程

八阶段的数据流可以这样描述（用「盒子箭头」表示数据传递）：

```
 imgs(原始图)
   │
   ├─[阶段1]→ features(每张图的关键点+描述子)
   │
   ├─[阶段2]→ pairwise_matches(两两匹配对)
   │
   ├─[阶段3]→ cameras(每台相机的旋转矩阵 R)
   │
   ├─[阶段4]→ cameras(R 被优化得更准)
   │
   ├─[阶段5]→ images_warped(投影后的图) + corners(左上角坐标) + masks_warped(掩膜)
   │
   ├─[阶段6]→ images_warped(亮度被补偿)
   │
   ├─[阶段7]→ masks_warped(被缝合成「谁负责哪块」)
   │
   └─[阶段8]→ result(最终全景图)
```

注意阶段 5 之后多出了三个关键产物，它们贯穿后续所有阶段：

- `images_warped`：投影后的图像本身。
- `corners`：每张投影图在大画布上的左上角坐标（用于定位拼接位置）。
- `masks_warped`：掩膜，标记「这张图的哪些像素是有效的」。

下面按八阶段依次给出真实源码位置。

**阶段 1：特征提取**

**阶段 2：特征匹配**

[圆柱面投影.cpp:289-291](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.cpp#L289-L291) —— `BestOf2NearestMatcher` 做两两匹配。类名「Best Of 2 Nearest」指的是经典的 **2NN（最近邻+次近邻）比值法**：只有当一个特征点的最近邻距离明显小于次近邻时，才认为匹配可靠。

**阶段 4：光束平差**

[圆柱面投影.cpp:310-316](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.cpp#L310-L316) —— `BundleAdjusterRay`（光线发散差）联合优化所有相机参数。第 314 行 `setConfThresh(1)` 设置匹配置信度阈值。第 325–326 行的两句注释很坦白：「光束平差法的效果挺差的」「准确估计的相机参数不是很大」——作者承认在 2 张图、参数本身就比较准的情况下，光束平差的改进有限。

[圆柱面投影.cpp:331-364](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.cpp#L331-L364) —— 这是全项目的核心阶段。先用 `CylindricalWarper` 创建投影器（第 345 行），再调用 `warp(...)`（第 355、359 行）对每张图和每张掩膜做圆柱面投影。`warp` 的数学细节留给 `u2-l2`/`u2-l3`，这里只需知道：它的输出是 `images_warped[i]` 和掩膜 `masks_warped[i]`，以及每张图的左上角坐标 `corners[i]`。第 348 行用 `cameras[0].focal`（焦距）作为投影尺度。

**阶段 6：曝光补偿**

[圆柱面投影.cpp:369-375](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.cpp#L369-L375) —— `ExposureCompensator::createDefault(GAIN)` 创建「增益型」曝光补偿器，先 `feed` 学习相邻图的亮度差异，再 `apply` 把每张投影图的亮度拉平。

**阶段 7：缝合线查找**

[圆柱面投影.cpp:378-395](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.cpp#L378-L395) —— 先把 `masks_warped` 备份到 `masks_seam`（第 379–380 行），因为缝合线查找会**改写** `masks_warped`，而后面融合还需要一份未改写的备份。然后用 `GraphCutSeamFinder`（图割法，第 388 行）在重叠区找最佳缝合线，第 395 行 `seam_finder->find(...)` 的输出就是「被缝合成『谁负责哪块』」的 `masks_warped`。本项目后续把这一阶段用**动态规划**重新实现在 FPGA 上（见 `u4-l1` 的 `DynamicSeam.v`）。

**阶段 8：羽化融合**

[圆柱面投影.cpp:439-492](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.cpp#L439-L492) —— 用 `FeatherBlender`（羽化融合）把所有投影图拼成全景。第 453 行 `setSharpness(0.1)` 设置羽化锐度；第 457 行 `prepare` 根据所有 `corners` 和 `sizes` 规划全局画布；第 469–480 行的循环对每张掩膜做**膨胀**（`dilate`，结构元 20×20）再喂给融合器 `feed`；第 490 行 `blend` 得到最终结果 `result`，第 492 行写出 `pano.jpg`。

> 关于「为什么融合前要膨胀掩膜」：缝合线把重叠区划成两半，但接缝处若一刀切会有明显亮阶跳变。膨胀掩膜制造一个**重叠过渡带**，让融合器在这个带内做加权平均（羽化），接缝就变得平滑。README 第 4 行提到的「小数权重没做好」正是指这一步的融合质量。

#### 4.2.5 小练习与答案

**练习 1**：阶段 7（缝合线查找）会改写 `masks_warped`，但阶段 8（融合）也需要掩膜。代码是怎么解决这个冲突的？
**参考答案**：第 379–380 行先把 `masks_warped[i]` **复制**到 `masks_seam[i]`，缝合线查找只改写 `masks_warped`，融合时用的是经过膨胀处理的 `masks_seam`（见第 461–479 行）。也就是说，缝合线和融合各自用一份掩膜副本，互不污染。

**练习 2**：阶段 2 的匹配器类名 `BestOf2NearestMatcher` 里「2 Nearest」指什么？
**参考答案**：指 **2NN 比值法**——对每个特征点，找距离最近的两个匹配候选，若最近邻距离 / 次近邻距离小于阈值，才接受该匹配。构造参数 `0.3f`（第 289 行）就是这个比值阈值。这种方法能有效剔除歧义匹配。

**练习 3**：阶段 8 为什么选 `FeatherBlender`（羽化）而不是 `MultiBandBlender`（多频段）？
**参考答案**：羽化融合（feather）算法简单、计算量小、便于在 FPGA 上实现；多频段融合（multi-band）效果更好但要做拉普拉斯金字塔分解，硬件实现成本高。从 FPGA 实现成本考虑，作者注释掉了多频段方案（第 444–446 行），改用羽化。这是典型的「算法效果 vs 硬件资源」取舍。

### 4.4 软件流水线到 FPGA 的移植动因

#### 4.4.1 概念说明

读到这一节，你可能会问：既然 OpenCV 几十行代码就能拼全景，为什么还要费力用 FPGA 重写？

答案的核心是**实时性（real-time）**。OpenCV 这份 `.cpp` 处理 2 张图就要几百毫秒到秒级（从 `t1`~`t7` 的打点可见），而七路摄像头要**每秒几十帧**地实时拼接，CPU 根本扛不住。FPGA 的优势在于：

- **并行**：每个像素可以独立并行处理。
- **流水线**：数据像流水一样一级一级往后传，一旦灌满，每个时钟周期都产出一个结果。
- **确定性**：处理时延固定，适合实时系统。

但 FPGA 不是万能的。它最擅长**固定、规则、可并行**的计算，不擅长**复杂控制流、浮点迭代优化**。所以移植时必须有所取舍。

#### 4.4.2 核心流程

把八阶段按「是否适合 FPGA」分类：

```
┌─────────────────────────────────────────────────────┐
│  软件离线做一次（标定阶段，复杂控制流 + 浮点迭代）  │
│    阶段1 特征提取                                   │
│    阶段2 特征匹配                                   │
│    阶段3 相机参数估计                               │
│    阶段4 光束平差                                   │
│  产出：每台相机的 K、R → 固化成 FPGA 的定点常数      │
└─────────────────────────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────────┐
│  FPGA 每帧实时做（规则、可并行，本项目重点）        │
│    阶段5 圆柱面投影（→ 圆柱面投影.v，CORDIC+定点）  │
│    阶段7 缝合线查找（→ DynamicSeam.v，动态规划）    │
│    阶段8 羽化融合（小数权重，README 标注未完成）     │
└─────────────────────────────────────────────────────┘
```

这正是前置讲义 `u1-l2` 给出的「软件→硬件」对应表的来源：浮点焦距尺度 `scale` ↔ 定点常数 `coe`、`sinf/cosf` ↔ CORDIC IP、相机矩阵 `K·R⁻¹` ↔ 定点系数 `k_inv`、双线性 `weight` 表 ↔ `weight_x/y`。这些对应关系将在 `u2-l4`、`u5-l1` 逐对验证。

#### 4.4.3 源码精读

`main` 函数里能直接看到「软件侧计算了什么、这些量最终要去哪里」：

[圆柱面投影.cpp:316-319](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.cpp#L316-L319) —— 打印优化后的相机参数 `cameras[0].R`、`cameras[0].K()`、`cameras[1].R`、`cameras[1].K()`。这些就是阶段 1–4 的最终产物，会被**固化成 FPGA 里的定点常数**（`k_inv0`~`k_inv8`）。作者把这些值打印出来，正是为了手动抄到 Verilog 里。

[圆柱面投影.cpp:258-259](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.cpp#L258-L259) —— `warp` 函数末尾把地址表 `addr` 写成 `addr.coe` 文件。`.coe` 是 Xilinx FPGA 的**系数文件格式**，用于初始化 ROM/查找表。这是「软件算系数 → FPGA 查表」这条链路的直接证据：软件离线算好投影地址表，导出 `.coe`，FPGA 运行时直接查表。这条链路的细节属于 `u2-l3`。

#### 4.4.5 小练习与答案

**练习 1**：为什么阶段 1–4（特征/匹配/估计/平差）不搬到 FPGA？
**参考答案**：这四个阶段是**相机标定**，只需在系统部署时做一次（相机装好后位置固定，R 不变）。它们涉及复杂的特征匹配、矩阵奇异值分解、非线性迭代优化，控制流复杂、数据依赖不规律，不适合 FPGA 的规则并行结构。用软件 CPU 跑一次、把结果固化成 FPGA 常数，是最经济的选择。

**练习 2**：FPGA 实现「阶段 5 投影」时，为什么需要 CORDIC IP？
**参考答案**：投影公式里有 `atan2f`、`sinf`、`cosf`、`sqrtf` 这些超越函数（见第 46–47、56–58 行）。FPGA 没有直接的浮点三角函数硬件，CORDIC（坐标旋转数字计算）是一种用**移位和加法**迭代逼近三角函数的经典硬件算法，是把软件浮点三角函数搬到 FPGA 的标准手段。这部分在 `u2-l4`、`u5-l2` 详讲。

## 6. 本讲小结

- `圆柱面投影.cpp` 的 `main` 函数是一条**严格串行的八阶段流水线**：特征提取→特征匹配→相机参数估计→光束平差→圆柱面投影→曝光补偿→缝合线查找→羽化融合。

- 关键数据容器是 `features`、`pairwise_matches`、`cameras`、`images_warped`/`corners`/`masks_warped`、`result`，理解它们的类型和生命周期就理解了流水线。
- 作者用 `t1`~`t7` 的 `clock()` 打点定位耗时阶段，用 `cout` 打印 K、R 矩阵，用 `.coe` 文件导出查表系数——这些都是「软件→硬件」的数据交接点。
- 本份 `.cpp` 用 `num_images=2` 跑通流水线，但目标是七路摄像头；第 306 行注释「7, 对应六对」印证了这一点。
