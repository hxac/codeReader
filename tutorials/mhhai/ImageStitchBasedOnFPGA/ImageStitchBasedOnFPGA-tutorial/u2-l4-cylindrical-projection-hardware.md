# 圆柱面投影的硬件实现：定点 Verilog

## 1. 本讲目标

本讲是把「软件算法」搬到「硬件」的关键一跃。前面三讲我们用 C++/OpenCV 把圆柱面投影的浮点数学讲透了：正向映射求范围、反向映射填像素、双线性插值生成地址表与权重表。本讲我们要回答一个新问题——**这套浮点算法，怎么在一颗没有浮点运算单元的 FPGA 上跑起来？**

读完本讲，你应该能够：

- 说清「浮点算法到定点硬件」的整体映射思路，知道哪些东西被预先固化、哪些东西逐像素实时计算。
- 看懂 Xilinx CORDIC IP（`cordic_0`）的相位输入 `phase_tdata` 与 `sin/cos` 输出之间的关系。
- 把 Verilog 里的定点系数 `k_inv0~k_inv8` 还原成十进制，并验证它们对应 C++ 中的 \(K\cdot R^{-1}\) 矩阵元素。
- 解释名为 `weight_x00/weight_y00/...` 的信号其实并不是「权重」，而是四个邻居像素的整数坐标（floor/ceil），并理解它扫描目标区域的时序。

本讲只读两个文件，但会反复对照：硬件端 [圆柱面投影.v](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/%E5%9C%86%E6%9F%B1%E9%9D%A2%E6%8A%95%E5%BD%B1.v) 与软件端 [圆柱面投影.cpp](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/%E5%9C%86%E6%9F%B1%E9%9D%A2%E6%8A%95%E5%BD%B1.cpp)。

## 2. 前置知识

### 2.1 为什么 FPGA 不能直接用浮点

CPU/GPU 里有浮点运算单元（FPU），可以直接算 `sinf(u)`、`2707.47 * x`。FPGA 的逻辑单元（LUT/DSP）天然只懂整数比特运算。要在 FPGA 上做带小数的计算，常用两种办法：

- **定点数（fixed-point）**：约定好二进制小数点在第几位，用一串整数比特去「假装」小数。例如约定小数点后 8 位，那二进制 `0000000100000000`（整数 256）就代表 \(256/2^8 = 1.0\)。定点数运算就是整数运算，资源省、速度快，是 FPGA 图像处理的主流。
- **浮点 IP**：用 Xilinx Floating-Point IP 真的做 IEEE754 浮点，资源开销大，本讲项目没采用。

本讲的 `project` 模块**全程定点**，所以我们必须先理解它的「Q 格式」。

### 2.2 Q 格式速览

记号 \(Qm.n\) 表示：总共 \(m+n\) 位（可能还含 1 位符号），其中 \(n\) 位是小数位、\(m\) 位是整数位。一个关键技巧是：**两个定点数相乘，小数位相加、整数位相加**。

例如一个 21 位定点系数（8 位小数）乘以一个 35 位中间量（22 位小数），结果就带有 \(8+22=30\) 位小数。本讲 4.3、4.4 节会反复用到这条规则来定位「小数点在第几位」。

### 2.3 CORDIC：用「移位+加法」算三角函数

`sinf`/`cosf`/`atan2f` 在 FPGA 上不能用泰勒展开硬算（乘法太多）。CORDIC（COordinate Rotation DIgital Computer）只用**移位、加法、查表**就能算出 sin/cos/atan。本项目把它封装成一个 Xilinx IP 核 `cordic_0`：给它一个「相位（角度）」，它吐出一对 `sin、cos`。本讲我们把它当成黑盒，只关心「相位怎么进、sin/cos 怎么出」。

### 2.4 软件参考实现的回顾

u2-l2 讲过，C++ 里反向映射 `mapBackward` 的核心是三步：

1. 把像素坐标 \(u,v\) 除以焦距 `scale` 得到归一化角度；
2. 用 `sinf/cosf` 把角度还原成圆柱面上的点 \((\sin u, v, \cos u)\)；
3. 左乘矩阵 \(K\cdot R^{-1}\)（代码里叫 `k_rinv`），再做透视除法得到源像素坐标。

本讲要做的事，就是把这三步**逐字翻译成定点 Verilog**。请记住这张对照表（u1-l2 已建立，本讲逐项验证）：

| C++ 浮点 | Verilog 定点 |
|---|---|
| `scale = 2707.47f` | 定点常数 `coe`（实为 \(1/scale\)，见 4.1） |
| `sinf(u)` / `cosf(u)` | CORDIC IP `cordic_0` |
| `k_rinv = K*Rinv`（9 个 float） | `k_inv0~k_inv8`（9 个定点系数） |
| `x/=z; y/=z`（透视除法） | **未实现**（见 4.4） |
| `dst_tl/dst_br` 输出范围 | 寄存器 `dst_tl_x/y`、`dst_br_x/y` |
| `cvFloor/cvCeil` 四个邻居 | `weight_x00..weight_x11` 八个信号 |

## 4. 核心概念与源码讲解

本讲按四个最小模块展开：**project 模块整体** → **CORDIC IP** → **k_inv 矩阵** → **weight 坐标生成与扫描**。

### 4.1 project 模块整体：浮点 mapBackward 到定点的映射

#### 4.1.1 概念说明

软件里 `mapBackward` 接收一个目标像素 \((u,v)\)，返回它在源图上的浮点坐标 \((x,y)\)。硬件版 `project` 做的是**同一件事**，但有两点关键工程决策：

1. **「一次性标定」被烧死成常数**。软件流水线里 `K`、`R` 是标定算法（特征匹配+光束平差）算出来的（见 u2-l1）；硬件把这些一次性结果直接写死成定点常数 `k_inv0~k_inv8` 和 `coe`，每帧不再重算。这正是 FPGA 「实时处理」能成立的前提。
2. **「逐像素实时」只保留必要计算**。每个时钟处理一个目标像素：算角度 → CORDIC 取 sin/cos → 矩阵乘 → 取整数邻居坐标。

#### 4.1.2 核心流程

`project` 模块每个时钟上升沿做一次完整投影，伪代码如下：

```
每个 posedge clk：
  若仍在目标矩形内 (dst_tl_y <= dst_br_y 且 dst_tl_x <= dst_br_x)：
    1. u = dst_tl_x * coe        # 像素 → 归一化角度（对应 C++ 的 u/=scale）
       v = dst_tl_y * coe
    2. phase = u 的某个比特切片   # 喂给 CORDIC
    3. (x_, z_) = cordic(phase)   # x_=sin(u), z_=cos(u)；y_=v
    4. x = k_inv0*x_ + k_inv1*y_ + k_inv2*z_   # 矩阵乘，对应 k_rinv 第 0 行
       y = k_inv3*x_ + k_inv4*y_ + k_inv5*z_   # 第 1 行
       z = k_inv6*x_ + k_inv7*y_ + k_inv8*z_   # 第 2 行
    5. weight_x/y00..11 = floor/ceil(x)、floor/ceil(y)  # 四个邻居坐标
    6. dst_tl_x++；行末则 dst_tl_y++            # 光栅扫描
```

注意：C++ 在第 4 步之后还有 `x/=z; y/=z` 的**透视除法**（把齐次坐标变回二维），而 Verilog **没有做这一步**——它只算到 \((x,y,z)\) 就直接取了 floor/ceil。这是本模块的一个重要简化/缺陷，4.4 节会展开。

#### 4.1.3 源码精读

先看模块端口。作者把几乎所有中间变量都声明成 `output`，目的是上板后用 ILA（逻辑分析仪）观察波形，这是典型的教学/调试写法：

[圆柱面投影.v:23-27](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/%E5%9C%86%E6%9F%B1%E9%9D%A2%E6%8A%95%E5%BD%B1.v#L23-L27) — `project` 模块端口：输入只有 `clk`，输出包含最终坐标 `x/y/z`、CORDIC 取出的 `x_/z_`、中间乘积 `tmp1/2/3`、以及八个 `weight_xN/weight_yN`。

> 这种「全部 output」的端口表在真实工程里会浪费大量管脚和布线资源，但它让本讲可以顺着端口名直接读懂数据通路，对学习反而友好。

再看整个时钟块的整体结构：

[圆柱面投影.v:72-111](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/%E5%9C%86%E6%9F%B1%E9%9D%A2%E6%8A%95%E5%BD%B1.v#L72-L111) — 整个投影计算在一个 `always @(posedge clk)` 块里完成，外面再例化一个 `cordic_0`。

这里要特别提醒一条 u1-l3 埋下的伏笔：**这个块里几乎全部使用阻塞赋值 `=`**（而非时序逻辑推荐的非阻塞 `<=`）。在纯组合 `always @*` 里用 `=` 是对的，但本块是 `posedge clk` 触发的时序逻辑，混用阻塞赋值会让综合后的寄存器行为与仿真「看起来对、上板出错」。这和 u4 将要讲的「不能综合的写法」是同一类问题，本讲先记下，不展开。

#### 4.1.5 小练习与答案

**练习 1**：为什么硬件把 `K*Rinv` 烧死成常数，而不是每帧重算？

**答案**：`K`、`R` 是相机标定结果（u2-l1 的特征匹配+光束平差），对同一组摄像头只算一次；每帧重算既无必要又无法实时。烧成定点常数后，逐像素只剩「CORDIC + 3 次乘加」这种 FPGA 擅长的简单运算。

**练习 2**：模块端口为什么把 `tmp1/tmp2/tmp3` 也引出来？

**答案**：这是教学/调试原型，作者想用 ILA 在上板时直接观察矩阵乘的中间乘积，方便核对定点位宽是否正确、是否溢出。

### 4.2 CORDIC IP（cordic_0）：用相位输入算 sin/cos

#### 4.2.1 概念说明

软件里 `mapBackward` 用 `sinf(u)` 和 `cosf(u)` 把「角度」变成「圆柱面上的点」。硬件里这一步由 Xilinx CORDIC IP `cordic_0` 完成。它是一个**AXI4-Stream 接口**的 IP：输入一个相位 `phase`，输出一对 `(sin, cos)`。我们把它当黑盒，只关心三件事——相位怎么进、sin/cos 怎么打包出、有效信号怎么握手。

#### 4.2.2 核心流程

```
phase_tdata  ──►  cordic_0  ──►  dout_tdata[47:24] = sin(u)
                                ──►  dout_tdata[23:0]  = cos(u)
s_axis_phase_tvalid = 恒 1     # 永远声明「相位有效」
```

CORDIC 是**多周期**运算：给它一个 phase，要等若干个时钟后 `m_axis_dout_tvalid` 才拉高，`dout_tdata` 才是有效的 sin/cos。本模块为了简化，把 `s_axis_phase_tvalid` 直接接 `1'b1`（永远有效），并且不检查输出 `dout_tvalid`——这意味着 `x_/z_` 在 CORDIC 流水线填满之前是无效数据。这是一个**时序隐患**，4.4 节和 u5 会再讨论。

#### 4.2.3 源码精读

相位输入由目标像素的 x 坐标算得：

[圆柱面投影.v:78-80](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/%E5%9C%86%E6%9F%B1%E9%9D%A2%E6%8A%95%E5%BD%B1.v#L78-L80) — `u = dst_tl_x * coe`（像素×定点倒数焦距 = 归一化角度），`phase_tdata = u[24:9]`（取 35 位中间量 `u` 的第 9~24 位，重排成 16 位喂给 CORDIC）。

> 关键直觉：C++ 里 `u /= scale`（[圆柱面投影.cpp:53](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/%E5%9C%86%E6%9F%B1%E9%9D%A2%E6%8A%95%E5%BD%B1.cpp#L53)）。硬件用「乘 `coe`」代替「除 scale」，而 `coe` 恰好是 \(1/scale\) 的定点值（4.1 表格里已点明，4.3 会用二进制证死）。这就是定点化最常见的技巧——**把除法变成乘以倒数**。

`u` 是 35 位（11 位有符号 `dst_tl_x` × 24 位 `coe` = 35 位），其中低 22 位是小数（来自 `coe`）。取 `u[24:9]` 有两个作用：①丢掉最低 9 位精度（CORDIC 的 16 位相位不需要那么多）；②把角度值重排到 CORDIC 期望的 16 位定点格式。**相位与角度的具体比特映射取决于 `cordic_0` 的 IP 配置（输入/输出位宽、量化方式），仓库未收录该 IP，故待本地确认。**

CORDIC 的例化：

[圆柱面投影.v:113-118](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/%E5%9C%86%E6%9F%B1%E9%9D%A2%E6%8A%95%E5%BD%B1.v#L113-L118) — 例化 `cordic_0 uut`，把 `phase_tdata` 接到 `s_axis_phase_tdata`，输入有效恒置 1，输出 `dout_tdata`（48 位）和 `dout_tvalid`。

输出的拆包：

[圆柱面投影.v:81-83](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/%E5%9C%86%E6%9F%B1%E9%9D%A2%E6%8A%95%E5%BD%B1.v#L81-L83) — 48 位 `dout_tdata` 高 24 位给 `x_`（sin），低 24 位给 `z_`（cos），`y_` 直接等于 `v`（对应 C++ 的 `y_ = v`，[圆柱面投影.cpp:57](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/%E5%9C%86%E6%9F%B1%E9%9D%A2%E6%8A%95%E5%BD%B1.cpp#L57)）。

至此，C++ 的 \((\sin u, v, \cos u)\) 三元组在硬件里凑齐了，准备进入矩阵乘。

#### 4.2.4 代码实践（源码阅读 + 推导型）

**实践目标**：理解 `phase_tdata[15:0]` 与 CORDIC 相位输入的关系。

**操作步骤**：

1. 读 [圆柱面投影.v:78-81](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/%E5%9C%86%E6%9F%B1%E9%9D%A2%E6%8A%95%E5%BD%B1.v#L78-L81)，确认 `u = dst_tl_x * coe`，`phase_tdata = u[24:9]`。
2. 回顾 4.1 表格：`coe` 是 \(1/scale\)，所以 `u` 就是「像素角度（弧度）」的定点表示，二进制小数点在第 22 位（来自 `coe` 的 22 位小数）。
3. 用文字说明：取 `u[24:9]` 等价于 `u >> 9`，既截断了最低 9 位小数精度，又把剩余的角度值重新对齐到 CORDIC 期望的 16 位相位格式。

**需要观察的现象**：因为目标矩形最左是 `dst_tl_x = -543`，`coe ≈ 1/2707.47`，所以 `u = -543/2707.47 ≈ -0.20` 弧度，是一个很小的数。`u` 的高位整数部分几乎全是 0，真正有意义的比特集中在小数区。

**预期结果**：你能用自己的话讲清楚——`phase_tdata[15:0]` 就是「像素对应的弧度角」经过定点重排后的 16 位相位，喂给 CORDIC 算 sin/cos。**具体的比特缩放比例由 `cordic_0` 的 IP 配置决定，待本地确认。**

#### 4.2.5 小练习与答案

**练习 1**：为什么把 `s_axis_phase_tvalid` 恒接 `1'b1`，而不像 u1-l3 的 UART 那样用 valid/ready 握手？

**答案**：本模块的设计意图是「每个时钟送一个新像素」，所以永远声明输入有效，让 CORDIC 持续吞吐。代价是必须保证 CORDIC 的流水线延迟与下游取数时序对齐，否则会读到未更新的 sin/cos。这是一个简化设计，工程化时通常要加流水对齐寄存器。

**练习 2**：如果 `dst_tl_x` 的范围是 \([-543, 542]\)，对应的角度范围大约是多少？是否落在 CORDIC sin/cos 的收敛域内？

**答案**：角度 \(u = x/scale \in [-543/2707.47, 542/2707.47] \approx [-0.20, 0.20]\) 弧度，约 ±11.5°。这点小角度完全在 CORDIC 的全范围 \([-\pi,\pi]\) 之内，正常工作。（这也说明七路相机各自只覆盖一个窄视角，靠拼接才合成全景。）

### 4.3 k_inv 矩阵：\(K\cdot R^{-1}\) 的定点系数

#### 4.3.1 概念说明

矩阵乘是本模块计算量最大的一步。C++ 里它左乘的是 `k_rinv = K * Rinv`（[圆柱面投影.cpp:116-119](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/%E5%9C%86%E6%9F%B1%E9%9D%A2%E6%8A%95%E5%BD%B1.cpp#L116-L119)）。硬件把这 9 个浮点数烧死成 9 个 21 位有符号定点常数 `k_inv0~k_inv8`。本节我们要做一件最有成就感的事——**把这些二进制手工还原成十进制，证明它们就是 C++ 矩阵里的元素**。

#### 4.3.2 核心流程：如何还原一个定点系数

还原一个定点常数分三步：

1. **读二进制字面量**：`21'b...` 一共 21 位。
2. **定位格式**：源码注释说是「1 位符号位 + 8 位整数位 + 剩下小数位」。但**注释会骗人，比特不会**——我们要用「先猜后验」：先用注释给的格式还原，看结果是否合理；不合理就调整整数/小数位数。
3. **与 C++ 对照**：还原出的十进制应当等于 `K*Rinv` 的对应元素（焦距、主点、0、1）。

定点还原公式（\(n\) 为小数位数）：

\[
\text{value} = \frac{\text{整数解释的二进制值}}{2^{n}}
\]

#### 4.3.3 源码精读

九个系数的声明：

[圆柱面投影.v:62-70](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/%E5%9C%86%E6%9F%B1%E9%9D%A2%E6%8A%95%E5%BD%B1.v#L62-L70) — `k_inv0~k_inv8` 均为 `reg signed [20:0]`（21 位有符号）。注意 `k_inv0` 与 `k_inv4` 二进制相同、`k_inv2` 与 `k_inv5` 相同，这暗示矩阵是类似 \(\begin{pmatrix}f&0&c\\0&f&c\\0&0&1\end{pmatrix}\) 的结构。

矩阵乘的三行：

[圆柱面投影.v:90-92](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/%E5%9C%86%E6%9F%B1%E9%9D%A2%E6%8A%95%E5%BD%B1.v#L90-L92) — \(x\) 用 `k_inv0/1/2`、\(y\) 用 `k_inv3/4/5`、\(z\) 用 `k_inv6/7/8`，分别乘以 \((x_, y_, z_)\)。这与 C++ [圆柱面投影.cpp:61-63](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/%E5%9C%86%E6%9F%B1%E9%9D%A2%E6%8A%95%E5%BD%B1.cpp#L61-L63) 的 `k_rinv[0..8]` 逐项一一对应。

**手工还原 `k_inv0`**（这是本讲核心实践，先在这里示范一次）。

二进制字面量：`21'b0_1010_1001_0011_0111_1000`，拼成 21 位字符串 `010101001001101111000`。

- **先按注释（1 符号 + 8 整数 + 12 小数）**：符号 `0`，整数 `10101001` = 169，小数 `001101111000` = \(888/2^{12}=0.217\)，得 \(169.217\)。这个值看起来不像是相机参数（焦距是 2707.47，不是 169）。
- **改试 1 符号 + 12 整数 + 8 小数**：符号 `0`，整数 `101010010011` = \(0\text{x}A93 = 2707\)，小数 `01111000` = \(120/2^{8}=120/256=0.469\)，得：

\[
\text{k\_inv0} = 2707 + \frac{120}{256} = 2707.469 \approx 2707.47
\]

这正是焦距 `scale = 2707.47f`！而且 `k_inv0` 对应 `k_rinv[0]` = \(K_{00}\) = 焦距（参考相机 \(R\approx I\)，故 \(K\cdot R^{-1}\approx K\)）。✓

**交叉验证（用数据通路的位宽反推格式）**：看 [圆柱面投影.v:90](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/%E5%9C%86%E6%9F%B1%E9%9D%A2%E6%8A%95%E5%BD%B1.v#L90) 的行尾注释「最小小数位为 8+22=30」。`coe`/`y_` 贡献 22 位小数，那 `k_inv` 必须贡献 8 位小数，才能凑成 30。21 位减去 8 位小数 = 13 位（含符号），即 1 符号 + 12 整数。**位宽注释也支持 12 位整数，而非源码注释里的「8 位整数」**。所以源码那行「中间 8 位整数位」的注释是写错的，真实格式是 **1 符号 + 12 整数 + 8 小数**。

把其余几个也还原（同样的 1+12+8 格式）：

| 系数 | 二进制 | 还原值 | 对应 C++ 含义 |
|---|---|---|---|
| `k_inv0` | `0_1010_1001_0011_0111_1000` | 2707.469 | 焦距 \(f\)（\(K_{00}\)） |
| `k_inv1` | `0_0000_..._0000` | 0 | \(K_{01}=0\) |
| `k_inv2` | `0_0010_0010_0110_1000_0000` | 550.5 | 主点 \(c_x\)（\(K_{02}\)） |
| `k_inv3` | `0_0000_..._0000` | 0 | \(K_{10}=0\) |
| `k_inv4` | `0_1010_1001_0011_0111_1000` | 2707.469 | 焦距 \(f\)（\(K_{11}\)） |
| `k_inv5` | `0_0010_0010_0110_1000_0000` | 550.5 | 主点 \(c_y\)（\(K_{12}\)） |

还原出的矩阵正好是：

\[
K \approx \begin{pmatrix} 2707.47 & 0 & 550.5 \\ 0 & 2707.47 & 550.5 \\ 0 & 0 & 1 \end{pmatrix}
\]

这是一个标准的相机内参矩阵（焦距 2707.47、主点约 550.5，主点位于约 1100×1100 图像的中心，与 C++ [圆柱面投影.cpp:167](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/%E5%9C%86%E6%9F%B1%E9%9D%A2%E6%8A%95%E5%BD%B1.cpp#L167) 的 `addr.create(1100, ...)` 吻合）。**九个定点系数完美还原了 \(K\cdot R^{-1}\)。**

> 顺带证死 `coe`：`coe = 24'b0_0_0000_0000_0001_1000_0011_01`，24 位整数 = 1549。若视作 Q2.22（2 整数 + 22 小数），值为 \(1549/2^{22} = 0.0003693 \approx 1/2707.47\)，而且 \(\text{round}(2^{22}/2707.47) = 1549\)。所以 `coe` **不是 2707.47 本身，而是它的倒数**——源码注释「2707.47」只是标明它由 2707.47 推导而来。这与 4.1 节「用乘倒数代替除法」完全自洽。详见 [圆柱面投影.v:30](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/%E5%9C%86%E6%9F%B1%E9%9D%A2%E6%8A%95%E5%BD%B1.v#L30)。

#### 4.3.5 小练习与答案

**练习 1**：源码注释说 `k_inv` 是「1 符号 + 8 整数 + 12 小数」，但还原结果支持「1 符号 + 12 整数 + 8 小数」。除了「还原值刚好等于焦距」之外，还有什么内部证据支持后者？

**答案**：看 [圆柱面投影.v:90](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/%E5%9C%86%E6%9F%B1%E9%9D%A2%E6%8A%95%E5%BD%B1.v#L90) 行尾注释「最小小数位为 8+22=30」。`y_`/`coe` 提供 22 位小数，要凑出 30 位，`k_inv` 必须是 8 位小数；21 位减 8 位小数 = 13 位（1 符号 + 12 整数）。所以数据通路位宽自洽地指向 12 位整数，源码「8 位整数」的注释是笔误。

**练习 2**：为什么 `k_inv1`、`k_inv3`、`k_inv6`、`k_inv7` 全是 0？

**答案**：标准相机内参 \(K\) 的非对角元素（除主点外）都是 0；参考相机的旋转 \(R\approx I\)，所以 \(K\cdot R^{-1}\approx K\) 仍保持这种稀疏结构。零系数在硬件里直接省掉了乘法器，是天然的优化。

### 4.4 weight 坐标生成与目标区域扫描

#### 4.4.1 概念说明

矩阵乘得到的 \((x,y,z)\) 是齐次坐标，理论上要先做 `x/=z; y/=z` 再做双线性插值（u2-l3 讲过的 4 个邻居 + 4 个小数权重）。但本模块在这里做了**大胆简化**：

- **跳过透视除法**，直接对 \((x,y)\) 取 floor/ceil；
- 名叫 `weight_x00/weight_y00/...` 的八个信号，**其实根本不是「权重」，而是 4 个邻居像素的整数坐标**（行 floor/ceil、列 floor/ceil）——也就是 u2-l3 里那张 **addr 地址表**的硬件版；
- 真正的小数权重（坐标的小数部分）被**丢掉了**，所以本模块实际上做的是「最近邻」而非「双线性」。

这正好呼应 README 和 u2-l3 反复提到的遗留问题：**「小数权重没做好」**。

#### 4.4.2 核心流程

floor/ceil 在硬件里非常简单——只要知道二进制小数点在第几位，**丢掉小数部分就是 floor，再加 1 就是 ceil**：

```
x 是 56 位，注释说小数点在第 30 位（30 位小数）
  floor(x) = x[55:30]      # 丢掉低 30 位小数
  ceil(x)  = x[55:30] + 1  # floor 后 +1
```

四个邻居（注意：y 是行、x 是列，与 u2-l3 的 a/b 约定一致——a 存列、b 存行）：

| 信号 | 含义 | 对应 C++ addr 表 |
|---|---|---|
| `(weight_y00, weight_x00)` = (floor y, floor x) | 左上邻居 (行, 列) | `(floor b, floor a)` |
| `(weight_y01, weight_x01)` = (ceil y, floor x) | 左下邻居 | `(ceil b, floor a)` |
| `(weight_y10, weight_x10)` = (floor y, ceil x) | 右上邻居 | `(floor b, ceil a)` |
| `(weight_y11, weight_x11)` = (ceil y, ceil x) | 右下邻居 | `(ceil b, ceil a)` |

扫描时序：模块用 `dst_tl_x`、`dst_tl_y` 两个计数器在目标矩形 \([dst\_tl\_x, dst\_br\_x]\times[dst\_tl\_y, dst\_br\_y]\) 上做**光栅扫描**，每个时钟处理一个像素——这正是 C++ `buildMaps` 双重 for 循环（[圆柱面投影.cpp:136-144](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/%E5%9C%86%E6%9F%B1%E9%9D%A2%E6%8A%95%E5%BD%B1.cpp#L136-L144)）的硬件化。

## 6. 本讲小结

- `project` 模块把 C++ 的浮点 `mapBackward` 翻译成定点硬件，每个时钟处理一个目标像素：**算角度 → CORDIC 取 sin/cos → 矩阵乘 → 取邻居整数坐标**。
- **「一次性标定」被烧死成常数**：`coe` = \(1/scale\)（Q2.22），`k_inv0~k_inv8` = \(K\cdot R^{-1}\)（21 位有符号，1 符号 + 12 整数 + 8 小数）。
- **CORDIC IP `cordic_0`** 用相位输入 `phase_tdata = u[24:9]` 算出 sin/cos，打包在 48 位 `dout_tdata` 里（高 24 位 sin、低 24 位 cos）；具体相位缩放比例待 IP 配置确认。
- **九个定点系数可被完整还原**：`k_inv0=k_inv4=2707.47`（焦距）、`k_inv2=k_inv5=550.5`（主点）、`k_inv8=1.0`、其余为 0，完美对应内参矩阵 \(K\)。
- **`weight_xN/weight_yN` 名不副实**：它们是 4 个邻居的 floor/ceil **整数坐标**（= C++ 的 addr 地址表），真正的小数权重被丢弃，所以本模块实际是最近邻插值。
- 本模块是**教学型原型**：全 output 端口、阻塞赋值、无复位、跳过透视除法、CORDIC 无握手对齐——读懂它的「意图」即可，写法不要照抄（u4/u5 会继续讨论可综合性）。
