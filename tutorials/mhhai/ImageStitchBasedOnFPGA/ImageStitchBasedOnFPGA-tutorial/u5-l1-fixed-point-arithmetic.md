# 定点数运算与位宽设计深入

> 前置讲义：[u2-l4 圆柱面投影的硬件实现：定点Verilog](u2-l4-cylindrical-projection-hardware.md)。本讲在 u2-l4 已经给出「浮点 mapBackward → 定点 project 模块」整体翻译的基础上，专门钻进**数的手感**——每一个定点常数怎么来的、每一次乘法要多少位、每一次取整对应截哪几位。

## 1. 本讲目标

学完本讲，你应当能够：

- 用 **Q 格式**（整数位 + 小数位）描述任意一个定点信号，并说出它的取值范围与精度。
- 把 C++ 里的浮点常数 `scale = 2707.47f` 与相机矩阵 \(K\cdot R^{-1}\)，一步步换算成 Verilog 里的 `coe` 与 `k_inv0~k_inv8` 定点二进制，并解释每一位的来历。
- 看到 `tmp1`、`tmp2`、`tmp3`、`x`、`y`、`z` 这类信号时，能从「两个乘数的位宽」直接推出结果该用多少位，并判断作者给的位宽是否够。
- 看懂 `y[55:30]` 这类**高位截取**如何实现 `floor`，`+1` 如何实现 `ceil`，并指出它们与软件 `cvFloor/cvCeil` 的对应关系。
- 识别这段「教学原型」RTL 里几处真实的定点陷阱（小数点没对齐、累加器无保护位、单时钟塞满乘加），理解 README 里「投影时序收敛是最难的环节」这句吐槽的来源。

## 2. 前置知识

### 2.1 为什么要用定点数

FPGA 的 DSP 乘法器天生只会算**整数乘法**。软件里一句 `scale * atan2f(x_, z_)` 用的是 IEEE 754 浮点，硬件里没有「免费的小数点」——我们必须自己决定：用多少位表示整数、多少位表示小数，把一个实数「钉死」成一串 0/1。这套「约定好小数点位置」的整数运算就是**定点数（fixed-point）**。

定点数与浮点数的最大区别：浮点数的小数点会「浮动」（用指数动态调整），精度随数值大小变化；定点数的小数点**固定**，全设计里同一个量的小数位数量恒定，运算规则简单、可预测、可综合。

### 2.2 Q 格式

记号 **Qm.n** 表示：总共若干位中，小数点之上有 \(m\) 位（含符号位）、小数点之下有 \(n\) 位。例如：

- **Q13.8 有符号**：1 位符号 + 12 位整数 + 8 位小数 = 21 位，范围 \([-2^{12},\,2^{12})=[-4096,4096)\)，分辨率（能分辨的最小差）\(2^{-8}=0.00390625\)。
- **Q2.22 无符号**：2 位整数 + 22 位小数 = 24 位，范围 \([0,4)\)，分辨率 \(2^{-22}\approx 2.38\times10^{-7}\)。

一条铁律：**两个定点数相加，必须先把小数点对齐（小数位补成相同）**；**两个定点数相乘，位宽相加、小数位相加**（\(Q a.b \times Q c.d = Q(a+c).(b+d)\)）。本讲几乎全部内容都是这两条规则的应用。

### 2.3 两个乘法位宽事实

1. \(M\) 位有符号 \(\times\) \(N\) 位有符号，**全精度结果**是 \(M+N\) 位（含符号扩展）。
2. 截取高位 = 丢弃低位 = 舍掉小数位 = **取整**；截取低位 = 丢弃高位 = **取模/溢出**。所以「截哪几位」本质是在回答「我要保留几位小数」。

## 4. 核心概念与源码讲解

### 4.1 定点系数推导：从浮点常数到 `coe` 与 `k_inv`

#### 4.1.1 概念说明

软件 `mapBackward` 里有两个「先除以 scale、再乘矩阵」的关键常数来源：一个是焦距尺度 `scale`（像素单位的焦距），另一个是相机矩阵的乘积 \(K\cdot R^{-1}\)。这两者在硬件里**都不会现场去算**——因为：

- `1/scale` 是除法，FPGA 里除法器又贵又慢；
- \(K\cdot R^{-1}\) 是 3×3 矩阵乘，每帧都一样，是「一次性标定」的产物（见 u2-l1/u2-l2）。

所以工程上的做法是：**在 PC 上离线算好这两个量，转成定点二进制，作为常数直接写死在 RTL 里**。本模块的 `coe` 就是 `1/scale` 的定点化，`k_inv0~k_inv8` 就是 \(K\cdot R^{-1}\) 九个元素的定点化。理解这两个常数的来历，就理解了「软件到硬件的交接点」。

#### 4.1.2 核心流程

把一个浮点数 \(x\) 转成 Qm.n 定点的流程是：

1. 选定 \(m\)（整数位，含符号）与 \(n\)（小数位），保证 \(x\) 的绝对值落在 \([-2^{m-1},\,2^{m-1})\)（有符号）或 \([0,2^m)\)（无符号）内。
2. 计算 \(X=\mathrm{round}(x\cdot 2^{n})\)，得到一个整数。
3. 把 \(X\) 写成 \(m+n\) 位二进制。

对 `coe`（\(x=1/2707.47\)）和 `k_inv`（\(x\in\{2707.47,\,550.5,\,0,\,1\}\)），作者分别选了 Q2.22（无符号）与 Q13.8（有符号）。下面逐个验证。

#### 4.1.3 源码精读

**(a) `coe` = 焦距倒数，Q2.22 无符号**

软件侧，`scale` 就是焦距（[圆柱面投影.cpp:30](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.cpp#L30)），`mapBackward` 一进来就 `u /= scale`（[圆柱面投影.cpp:53](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.cpp#L53)）。硬件把除法换成乘倒数：

```verilog
reg [23:0] coe = 24'b0_0_0000_0000_0001_1000_0011_01;   // 22位小数  2707.47
```

[圆柱面投影.v:30](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L30) — 注释里的「2707.47」是**它由谁派生**的备注，不是 coe 本身的值；coe 本身是 \(1/2707.47\)。

手工还原（24 位，2 整数 + 22 小数）：

\[
\text{coe} = \mathtt{0x00060D} = 1549
\]

\[
\frac{1549}{2^{22}} = \frac{1549}{4194304} = 0.00036917 \approx \frac{1}{2707.47}=0.00036937
\]

误差来自 22 位小数的量化（\(<10^{-6}\)），完全够用。这就是 `coe` 的全部来历。

**(b) `k_inv0~8` = \(K\cdot R^{-1}\)，Q13.8 有符号**

软件侧，`setCameraParams` 预算好 `k_rinv = K * Rinv`（[圆柱面投影.cpp:116-119](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.cpp#L116-L119)），`mapBackward` 用它做矩阵乘（[圆柱面投影.cpp:61-63](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.cpp#L61-L63)）。硬件把这九个浮点数烧成 21 位有符号常数：

```verilog
reg signed [20:0] k_inv0 = 21'b0_1010_1001_0011_0111_1000;  // 21位定点：最高1位符号，12位整数，最低8位小数
reg signed [20:0] k_inv1 = 21'b0_0000_0000_0000_0000_0000;
reg signed [20:0] k_inv2 = 21'b0_0010_0010_0110_1000_0000;
...
reg signed [20:0] k_inv8 = 21'b0_0000_0000_0001_0000_0000;
```

[圆柱面投影.v:62-70](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L62-L70) — 21 位 = 1 符号 + 12 整数 + 8 小数（Q13.8）。

解码三个关键元素（其余为 0）：

| 信号 | 二进制（去下划线） | 整数部(12b) | 小数部(8b) | 还原值 | 对应矩阵元素 |
|------|-------------------|------------|-----------|--------|-------------|
| `k_inv0` | `0_1010_1001_0011_0111_1000` | `1010_1001_0011`=2707 | `0111_1000`=120/256=0.46875 | **2707.47** | 焦距 \(f\)（\(K_{00}\)） |
| `k_inv2` | `0_0010_0010_0110_1000_0000` | `0010_0010_0110`=550 | `1000_0000`=128/256=0.5 | **550.5** | 主点 \(c_x\)（\(K_{02}\)） |
| `k_inv8` | `0_0000_0000_0001_0000_0000` | `0000_0000_0001`=1 | `0000_0000`=0 | **1.0** | 齐次行 \(K_{22}\) |

把九个元素按 3×3 排开：

\[
K\cdot R^{-1}\;\longleftrightarrow\;
\begin{bmatrix}
2707.47 & 0 & 550.5\\
0 & 2707.47 & 550.5\\
0 & 0 & 1
\end{bmatrix}
\]

这正是内参矩阵 \(K=\begin{bmatrix}f&0&c_x\\0&f&c_y\\0&0&1\end{bmatrix}\)（\(f=2707.47,\;c_x=c_y=550.5\)），且说明本原型取了 \(R=I\)（单位阵），于是 \(K\cdot R^{-1}=K\)。换言之，**这套 k_inv 对应「单相机、无旋转」的简化情形**——这也是 u2-l4 把它定性为「教学原型」的原因之一：真实七路相机的 \(R\) 不会是单位阵，每路都要烧一组不同的 k_inv。

> 小结：`coe` 是 Q2.22 的 \(1/f\)；`k_inv` 是 Q13.8 的 \(K\cdot R^{-1}\)。两者都是「离线算好、烧死在 RTL」的标定产物，硬件运行时不再计算。

#### 4.1.4 代码实践

**实践目标**：亲手把 C++ 浮点常数翻译成 Verilog 定点常数，验证两边一致。

**操作步骤**：

1. 打开 [圆柱面投影.cpp:30](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.cpp#L30)，读出 `scale = 2707.47f`。
2. 计算 \(1/2707.47\)，再乘 \(2^{22}\)，四舍五入，应得到 1549。
3. 把 1549 写成 24 位二进制（手工或用计算器），应得到 `0000_0000_0000_0110_0000_1101`，对照 [圆柱面投影.v:30](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L30) 的 `coe`（注意作者用下划线分组）。
4. 用同样的流程还原 `k_inv4`（应等于 `k_inv0`，即 2707.47）与 `k_inv5`（应等于 `k_inv2`，即 550.5），对照 [圆柱面投影.v:66-67](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L66-L67)。

**需要观察的现象**：还原出的十进制值与 C++ 里 `cameras[0].K()` 打印出的 \(K\) 矩阵元素几乎相等；微小差异来自定点量化。

**预期结果**：`coe`≈0.000369（=1/2707.47）；`k_inv0/k_inv4`≈2707.47；`k_inv2/k_inv5`=550.5；`k_inv8`=1.0；其余为 0。

#### 4.1.5 小练习与答案

**练习 1**：如果把 `coe` 的小数位从 22 位降到 16 位（即 Q2.16），量化误差会变大约多少倍？焦距倒数还能表示吗？

**参考答案**：Q2.16 分辨率为 \(2^{-16}\approx1.5\times10^{-5}\)，是 Q2.22（\(\approx2.4\times10^{-7}\)）的 \(2^{6}=64\) 倍粗糙；\(1/2707.47=0.000369\) 仍在 \([0,4)\) 范围内，能表示，但角度 \(u\) 的精度会下降，可能引入亚像素级的投影抖动。

**练习 2**：为什么 `k_inv` 选 Q13.8 而不是像 `coe` 那样用更多小数位？

**参考答案**：`k_inv` 要表示的最大值是焦距 2707.47，需要 \(\lceil\log_2 2708\rceil=12\) 位整数；Q13.8（1 符号+12 整数+8 小数）刚好放下且留了符号位。若想增加小数位，总位宽也得增加（例如 Q15.10 要 25 位），会增大乘法器与累加器位宽。作者在「精度」与「资源」间取了 8 位小数这个折中。

### 4.2 位宽推导：乘法扩展与累加器定尺寸

#### 4.2.1 概念说明

定点乘法的位宽「只增不减」：每次相乘，结果位宽等于两个乘数位宽之和。这条规则决定了 `tmp1/tmp2/tmp3` 以及最终的 `x/y/z` 到底要多少位。理解它，你就能在不看注释的情况下，自己推出每个信号的正确位宽，并判断作者的位宽是否够用——这是读「半成品 RTL」最核心的能力。

#### 4.2.2 核心流程

本模块每个时钟处理一个目标像素，数据通路是：

```
dst_tl_x  ─┐
           ├─ ×coe ──► u (35b) ──► [24:9] ──► phase_tdata ──► CORDIC ──► x_,z_ (24b each)
dst_tl_y  ─┘                                                        │
                                                                    ▼
                                              k_inv0..8 (21b) × {x_, y_=v, z_} ──► 三路乘积
                                                                    │
                                          x = Σ三路(56b)  y = Σ三路(56b)  z = Σ三路(56b)
                                                                    │
                                              y[55:30] / x[55:30] ──► floor / ceil(邻居坐标)
```

位宽规则应用两次：

- **乘法**：\(M\times N \to M{+}N\) 位。
- **三路求和**：结果位宽 ≥ 最宽的一项；为吸收同号相加的进位，理论上还要 +1~2 位「保护位」。

#### 4.2.3 源码精读

**(a) 第一次乘法：坐标 × coe（生成相位 u/v）**

```verilog
u = $signed(dst_tl_x) * $signed(coe);   // 11+24 = 35
v = $signed(dst_tl_y) * $signed(coe);   // 11+24 = 35
phase_tdata[15:0] = u[24:9];
```

[圆柱面投影.v:78-80](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L78-L80) — `dst_tl_x` 是 11 位有符号坐标（Q11.0），`coe` 是 24 位 Q2.22；乘积位宽 \(11+24=35\)，记作 `reg [34:0] u`（[圆柱面投影.v:31](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L31)），格式 Q13.22（13 整数 + 22 小数）。这一步等价于软件的 `u /= scale`（乘以 \(1/f\)）。

`phase_tdata[15:0] = u[24:9]` 是一次**位切片再定标**：u 的 Q13.22 小数点在第 22 位；取 [24:9] 共 16 位，正好保留 2 位整数（bit 23、24）与 14 位小数（bit 9~22），得到 Q2.14 的相位喂给 CORDIC。由于 `dst_tl_x`∈[-543,542]，\(u=x/f\)∈[-0.20,0.20] rad（约 ±11.5°），量值很小，高位全是符号扩展，截取安全。>（CORDIC IP `cordic_0` 的精确输入/输出量化格式取决于其 Vivado 配置，仓库未收录 IP，**待确认**；本讲只解释位宽切片，IP 细节见 u5-l2。）

**(b) 第二次乘法：k_inv × {x_, y_, z_}（矩阵-向量乘的三路）**

```verilog
tmp1 = $signed(k_inv3) * $signed(x_);   // 21+24 = 45
tmp2 = $signed(k_inv4) * $signed(y_);   // 21+35 = 56
tmp3 = $signed(k_inv5) * $signed(z_);   // 21+24 = 45
```

[圆柱面投影.v:84-86](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L84-L86)。三路乘积位宽推导：

| 信号 | 乘数 A | 乘数 B | 位宽 | 声明 | 备注 |
|------|--------|--------|------|------|------|
| `tmp1` | `k_inv3` (21b, Q13.8) | `x_` (24b, sin) | 21+24=**45** | `reg [44:0] tmp1` ([L36](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L36)) | ✓ 够 |
| `tmp2` | `k_inv4` (21b, Q13.8) | `y_`=v (35b, Q13.22) | 21+35=**56** | `reg [55:0] tmp2` ([L37](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L37)) | ✓ 够 |
| `tmp3` | `k_inv5` (21b, Q13.8) | `z_` (24b, cos) | 21+24=**45** | `reg [44:0] tmp3` ([L38](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L38)) | ✓ 够 |

> 注意 [圆柱面投影.v:38](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L38) 的注释写的是「21+16=37」，与实际声明 `reg [44:0]`（45 位）及乘法规律（21+24=45）都不一致——这是源码里一处**注释笔误**：作者大概想写 sin/cos 的「有效 16 位」，但真实乘数 `x_/z_` 是 24 位寄存器，正确位宽就是 45。声明的 45 位是对的，注释是错的。

**(c) 三路求和：累加器 `x/y/z` 定尺寸**

```verilog
x = ($signed(k_inv0)*$signed(x_)) + ($signed(k_inv1)*$signed(y_)) + ($signed(k_inv2)*$signed(z_));  // 位宽21+35=56，小数位8+22=30
y = ($signed(k_inv3)*$signed(x_)) + ($signed(k_inv4)*$signed(y_)) + ($signed(k_inv5)*$signed(z_));
z = ($signed(k_inv6)*$signed(x_)) + ($signed(k_inv7)*$signed(y_)) + ($signed(k_inv8)*$signed(z_));
```

[圆柱面投影.v:90-92](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L90-L92)，三路都声明为 `reg [55:0]`（56 位，[L45-47](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L45-L47)）。位宽取**三项中最宽的一项**（k_inv×y_ = 56 位）。

这里有一个**定点陷阱**，值得单独拎出来（见下一节）。先记结论：三路乘积的小数位并不相同——`k_inv×x_`/`k_inv×z_` 是「8 + sin的小数位」，而 `k_inv×y_` 是 8+22=**30** 位（注释 [L90](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L90) 也是这么说的）。作者把累加器统一按 30 位小数来用，这一假设的成立条件，正是本讲要你警惕的地方。

#### 4.2.4 代码实践

**实践目标**：不看注释，纯凭乘法规律推出 `tmp1/tmp2/tmp3` 与 `x/y/z` 的位宽，并核对作者声明。

**操作步骤**：

1. 查 [圆柱面投影.v:33-35](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L33-L35) 记下 `x_`/`y_`/`z_` 的声明位宽（24/35/24）。
2. 查 [圆柱面投影.v:62](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L62) 记下 `k_inv` 的位宽（21）。
3. 用 \(M+N\) 规则手算三路乘积：45 / 56 / 45。
4. 与 [圆柱面投影.v:36-38](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L36-L38) 的声明比对，找出注释里的笔误。

**需要观察的现象**：声明的寄存器位宽与你算出的全精度位宽一致；只有 `tmp3` 行的注释算术（21+16=37）对不上。

**预期结果**：`tmp1`45 位、`tmp2`56 位、`tmp3`45 位；`x/y/z` 各 56 位（等于最宽的乘积项）。

#### 4.2.5 小练习与答案

**练习 1**：累加器 `x` 声明成 56 位，但它是三项之和，会不会溢出？理论上应该多少位？

**参考答案**：三个 56 位同号数相加，最坏情况需要 58 位（多 2 位进位保护）。作者用 56 位「卡着最宽项」声明，没有加保护位。本原型里由于 \(R=I\)、`k_inv1` 等很多项为 0，三项不会同时取到大正数，实际不溢出；但这是**靠数据兜底，不是靠位宽兜底**，换一组标定就可能溢出。

**练习 2**：`phase_tdata[15:0] = u[24:9]` 取了 u 的 bit 9~24。如果改成 `u[34:19]`（取最高 16 位），物理含义会变成什么？

**参考答案**：`u[34:19]` 把小数点提到 bit 19，相当于把相位再放大 \(2^{3}=8\) 倍后取整，等价于改变 CORDIC 的输入定标，会让 sin/cos 输出对应到错误的角度，投影完全错位。这说明**位切片等价于改变定点的小数点位置**，切片区间必须与下游 IP 约定的 Q 格式严格匹配。

### 4.3 取整、高位截取与定点陷阱（溢出与时序）

#### 4.3.1 概念说明

矩阵乘得到的是带小数的「源像素浮点坐标」，双线性插值需要它的整数邻居（`floor` / `ceil`）和小数部分（权重）。软件里用 `cvFloor`/`cvCeil`（见 [圆柱面投影.cpp:184-191](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.cpp#L184-L191) 的 addr 表），硬件里则是**截取高位丢弃小数位**——这是定点数最方便的地方：取整不花任何逻辑，只是重新连线。

但本模块的取整写法藏着一个**小数点对齐陷阱**，而且整条乘加链塞在单个时钟的阻塞赋值里，带来真实的时序风险。这一节把「取整怎么做」和「哪里会出错」一起讲清。

#### 4.3.2 核心流程

定点取整规则（设一个数有 \(F\) 位小数）：

- **floor** = 右移 \(F\) 位 = 丢弃低 \(F\) 位 = **取 bit \([W{-}1 : F]\)**。
- **ceil** = floor + 1（当存在小数部分时；本模块为简化一律 +1）。
- **小数部分**（双线性权重）= 低 \(F\) 位 = bit \([F{-}1 : 0]\)。

本模块的 `weight_yN/weight_xN` 虽然名字带 "weight"，实际只取了整数坐标（floor/ceil），**完全丢弃了小数权重**（见 u2-l3、u2-l4），所以它退化成最近邻插值。

#### 4.3.3 源码精读

**(a) floor / ceil 的高位截取**

```verilog
weight_y00 = y[55:30];      // floor
weight_x00 = x[55:30];      // floor
weight_y01 = y[55:30] + 1;  // ceil
weight_x01 = x[55:30];      // floor
weight_y10 = y[55:30];      // floor
weight_x10 = x[55:30] + 1;  // ceil
weight_y11 = y[55:30] + 1;  // ceil
weight_x11 = x[55:30] + 1;  // ceil
```

[圆柱面投影.v:93-100](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L93-L100)。`y` 是 56 位、按注释约定有 30 位小数，于是 `y[55:30]`（高 26 位）就是整数部分 = floor；`+1` 就是 ceil。四个邻居组合成 (floor_y,floor_x)、(ceil_y,floor_x)、(floor_y,ceil_x)、(ceil_y,ceil_x)，对应软件 addr 表里的左上/左下/右上/右下四个像素坐标。

**(b) 陷阱一：小数点没真正对齐**

回顾三路乘积的小数位（设 sin/cos 的小数位为 \(p\)）：

\[
\begin{aligned}
\text{k\_inv}\times x\_ &: 8 + p \\
\text{k\_inv}\times y\_ &: 8 + 22 = 30 \quad\text{(因为 }y\_=\text{v 是 Q13.22)}\\
\text{k\_inv}\times z\_ &: 8 + p
\end{aligned}
\]

作者把累加器按 **30 位小数**用（`y[55:30]` 丢 30 位），意味着他默认 \(p=22\)，即 sin/cos 也是 22 位小数（Q2.22）。然而 [圆柱面投影.v:33](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L33) 的注释却写「14 位小数位」，与 30 位累加器假设**自相矛盾**。要让 `x = k_inv0·x_ + k_inv2·z_` 与 `y` 路在同一个 30 位小数标尺下相加/比较，sin/cos 必须是 22 位小数；否则 `x[55:30]` 会比真实 floor 偏差 \(2^{30-p}\) 倍。

这个陷阱目前「没爆」，是因为 \(R=I\) 时 `k_inv1=0`、`x` 路里含 `y_`（30 位小数）的那项消失了，`x = k_inv0·sin + k_inv2·cos` 两项小数位相同（都 \(8+p\)），自己和自己是一致的。一旦哪天 \(R\neq I\)、`k_inv1≠0`，三项小数位不统一又直接相加，结果会**静默出错**——这是典型的「靠特殊数据掩盖的定点 bug」。

> 修复思路：规定一个统一的累加小数位（如 30），对所有乘积做显式的左移对齐（\(\text{shift}=30-(8+p)\)），再相加；而不是裸加。

**(c) 陷阱二：阻塞赋值 + 单时钟乘加链 = 时序风险**

注意整段 datapath 用的全是阻塞赋值 `=`（[圆柱面投影.v:78-100](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L78-L100)）：`u`、`tmp1/2/3`、`x/y/z`、`weight_*` 在同一个 `posedge clk` 里**顺序求值**。这意味着综合器会把「坐标×coe → 切片 → （CORDIC 也算一拍）→ 三个 21×24/21×35 乘法 → 三路 56 位加法 → 截取+1」压在一级组合逻辑里。CORDIC 本身又是一个多周期 IP，这里的写法在真实综合中几乎不可能收敛——这正是 README 反复强调的「投影时序收敛是最难的环节」。教学上看逻辑没问题，**工程上不能照抄**：正确的做法是把乘加拆成若干级流水寄存器（每一拍打一拍），用非阻塞 `<=` 分级。

**(d) 陷阱三：累加器无保护位**

如 4.2.5 所述，56 位累加器没有为三路同号相加预留进位位，靠「多数项为 0」侥幸不溢出。

#### 4.3.4 代码实践

**实践目标**：验证 `y[55:30]` 确实等于「丢 30 位小数 = floor」，并定位小数点对齐隐患。

**操作步骤**：

1. 假设 `y`（Q26.30，56 位）的真值 = 12.3，写出它的定点编码：\(12.3\times2^{30}\approx 1.32\times10^{10}\)，确认落在 56 位范围内。
2. 对该编码做 `y[55:30]`（右移 30 位），应得到 12（= floor(12.3)）；再做 `+1`，应得到 13（= ceil）。
3. 思考：若 `x_`（sin）真的是 14 位小数（如注释所说），那么 `k_inv0·x_` 是 \(8+14=22\) 位小数，要和 30 位小数的 `y` 路对齐相加，应在乘积后左移多少位？（答案：左移 8 位。）
4. 检查 [圆柱面投影.v:90](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L90) 是否做了这个左移对齐。

**需要观察的现象**：第 2 步「右移即取整」成立；第 4 步发现代码**没有**做对齐移位，从而确认隐患存在。

**预期结果**：floor/ceil 用截高位实现无误；代码缺少显式小数点对齐，是潜在定点缺陷。

#### 4.3.5 小练习与答案

**练习 1**：`weight_y01 = y[55:30] + 1` 无条件 +1。这和数学上的 `ceil` 在什么时候不一致？

**参考答案**：当 `y` 的小数部分恰好为 0（`y` 本身就是整数）时，数学 `ceil` 应等于自身（不变），但这里仍 +1，会指向下一个整数邻居。本模块反正只取邻居坐标做最近邻，影响不大；但若要做严格双线性，需要 `ceil = (frac==0) ? floor : floor+1`。

**练习 2**：把 `y[55:30]` 改成 `y[55:28]`（丢 28 位而不是 30 位），floor 结果会怎样？

**参考答案**：少丢 2 位 = 把「2 位小数」当成了整数，floor 结果被放大 \(2^{2}=4\) 倍，邻居坐标全错。再次说明：**截取的起止位必须与累加器小数位数严格一致**，差一位都崩。

## 5. 综合实践

把本讲三块内容串起来，做一次完整的「浮点 → 定点」交接推导，并顺手暴露一处隐患。

**任务**：假设某个相机的旋转矩阵不再是单位阵，\(R\) 使 \(K\cdot R^{-1}\) 的 (0,1) 号元素变成 `k_inv1 = 0.25`（不再是 0）。请：

1. **系数推导**：把 `0.25` 转成 21 位 Q13.8 有符号二进制（写出整数部、小数部、最终二进制）。
2. **位宽推导**：写出此情形下 `x` 路三项 `k_inv0·x_`、`k_inv1·y_`、`k_inv2·z_` 各自的位宽与**小数位**（设 sin/cos 按 22 位小数算）。
3. **隐患分析**：指出 [圆柱面投影.v:90](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L90) 那行裸加，在本情形下会出什么问题，并写出你的修复方案（要包含具体的对齐移位）。

**参考答案要点**：

1. \(0.25\times2^{8}=64\)，整数部 `0000_0000_0000`、小数部 `0100_0000`、21 位二进制 `0_0000_0000_0000_0100_0000`（对照 [圆柱面投影.v:62-70](https://github.com/mhhai/ImageStitchBasedOnFPGA/blob/8728b11c25af93dd1b4f7606aca64433827adfd5/圆柱面投影.v#L62-L70) 的位宽与格式）。
2. 三项位宽：`k_inv0·x_` = 21+24=45（小数位 8+22=30）、`k_inv1·y_` = 21+35=56（小数位 30）、`k_inv2·z_` = 45（小数位 30）。若按注释的 14 位小数 sin/cos，则第一、三项小数位只有 22，与 `y_` 路的 30 不一致。
3. 隐患：三项小数位不统一，直接相加等于把不同标尺的数硬加，`x[55:30]` 取出的「整数」会偏离真实坐标。修复：先把 `k_inv0·x_`、`k_inv2·z_` 各左移 8 位对齐到 30 位小数（`{prod, 8'd0}`），再与 `k_inv1·y_` 相加，最后 `x[55:30]` 取整；同时累加器位宽从 56 扩到 58 留两位保护位，并把乘加拆成多级非阻塞流水寄存器以缓解时序。

> 说明：以上「设 sin/cos 为 22 位小数」是为了让累加器自洽所做的**反推**；仓库未收录 CORDIC IP 配置，sin/cos 精确的小数位**待确认**。无论真实值是 14 还是 22，本实践的目的是让你体会「小数位必须统一」这条铁律。

## 6. 本讲小结

- **Q 格式**是定点数的「度量衡」：整数位决定范围，小数位决定精度；本模块用了 Q2.22（无符号 `coe`）与 Q13.8（有符号 `k_inv`）两种。
- **`coe` = \(1/f\) 的 Q2.22**，原始值 1549 = `0x60D`，还原 ≈ 0.000369 = 1/2707.47；它把软件的 `u/=scale` 换成了硬件的乘法。
- **`k_inv0~8` = \(K\cdot R^{-1}\) 的 Q13.8**，还原出 \(f=2707.47\)、\(c_x=c_y=550.5\)、齐次位 1.0，且本原型 \(R=I\)；两者都是「离线烧死」的标定常数。
- **乘法位宽 = 两乘数位宽之和**：据此推出 `u/v` 35 位、`tmp1/tmp3` 45 位、`tmp2` 56 位、累加器 `x/y/z` 56 位；并发现 `tmp3` 行注释（21+16=37）是笔误。
- **取整 = 截高位**：`y[55:30]` 丢 30 位小数即 `floor`，`+1` 即 `ceil`，对应软件 `cvFloor/cvCeil` 与 addr 表的四个邻居坐标。
- **三处真实隐患**：小数点未对齐（靠 `k_inv1=0` 掩盖）、累加器无保护位、整条乘加链用阻塞赋值塞进单时钟——这正是 README「投影时序收敛最难」的微观根源，写法不可直接照抄。
