本讲精讲本库的核心设计模式「同一实体多架构」：一个 entity（端口契约，含 generic/port）只声明一次，却同时配套多套 architecture（实现），以「接口与实现分离」兼顾可移植性与性能。三套实现按 `<厂商>_behavioural_<功能>` 命名：`xilinx_behavioural_*` 封装 Xilinx `xpm` 原语（如 `xpm_fifo_sync`），`intel_behavioural_*` 封装 Intel `altera_mf` 原语（如 `scfifo`），`own_behavioural_*` 为厂商无关的行为级 RTL 实现。关键风格是厂商库声明（`library xpm`/`library altera_mf`）紧贴各自 architecture 之前，而非堆在文件顶部，使依赖局部化，且 `own_behavioural_*` 前无厂商库正是「厂商无关」的源码证据。使用方用直接例化语法 `entity work.xxx(arch_name)` 选定架构，切换厂商仅需改括号内名字、端口连线不动。两个重要事实：一次例化只绑定一套架构，综合后仅落选中的那份；同一测试台可同时例化多套做跨实现等价性回归。需注意「以源码为准」——`ff_synchroniser` 实际只有 xilinx+intel 两套，且 `own_behavioural_async_fifo` 内部叶子同步器被硬编码为 Xilinx 架构，「自研」是分层的，移植时须手动改这一处选定。
