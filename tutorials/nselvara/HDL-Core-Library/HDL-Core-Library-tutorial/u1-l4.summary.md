本讲把视角从本地单机仿真抬升到团队工程化，覆盖四个最小模块：`vhdl_ls.toml` 库声明、NVC 仿真器、`vunit.yml` CI 流水线、`test_runner_ci_cd.py`。核心结论是：HDL 工具链需同时服务编辑器（语言服务器查符号）和仿真器（绑定厂商原语）两个用途。`vhdl_ls.toml` 是编辑器侧的「库→文件」地图，把 vunit_lib、osvvm、UNISIM、xpm、altera_mf 标为 `is_third_party` 只供跳转，本项目代码归 `defaultlib` 接受严格检查。CI 选用开源 NVC 仿真器，它完整支持 VHDL-2008 但无法绑定 Verilog 原语；流水线靠克隆 gplgpu/grlib 提供厂商库 VHDL 源码，用 `nvc --install` 编译进缓存。CI 脚本与本地脚本同调 `run_all_testbenches_lib`，差异在于 `use_intel_altera_libs=True`、用 `VUNIT_CI_MODE` 切路径、解析 `--xunit-xml` 产报告，并用 `excluded_list` 排除 NVC 跑不了的 PLL——根因是 `PLLE2_BASE` 缺 VHDL 行为级绑定，PLL 是全库唯一无 `own_behaviourral_*` 实现的 IP。引入的关键术语：工具链、CI、语言服务器、NVC、`nvc --install`、xunit 报告、`is_third_party`、`excluded_list`，以及「同一实体多厂商架构」这一承接 u2 的伏笔。
