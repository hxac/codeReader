本讲是「从读到跑」的转折点，解决如何把测试台真正运行起来，含四个最小模块。其一，环境准备：用 Python venv 安装 vunit_hdl（唯一与仿真直接相关的依赖），且必须 git submodule init 拉取 ip/vhdl_utils 子模块，否则 test_runner.py 导入即报 ModuleNotFoundError。其二，test_runner.py 是 VUnit 的薄包装器，构成 test_runner.py → run_all_testbenches_lib（子模块）→ VUnit → 仿真器 的三层调用链，普通用户只面对最上层，无需碰 VUnit 内部。其三，VUnit 测试发现靠两层标志：测试台凭 entity 的 runner_cfg generic（魔法类属）被识别，tb_*.vhd 仅缩小扫描范围；用例凭 test_suite 循环里每个 run("...") 被发现；-- vunit: run_all_in_same_sim pragma 只把已发现的用例合并到一次仿真执行，不参与发现。其四，关键参数中 use_xilinx_libs（默认 True）加载 glbl 模块以解 XPM 原语的 glbl.GSR 报错，gui 切图形调试，timeout_ms 控看门狗超时，excluded_list 排除测试台（CI 据此排除 PLL）。核心结论：README 参数示例与磁盘真实文件不一致，一律以真实文件为准。
