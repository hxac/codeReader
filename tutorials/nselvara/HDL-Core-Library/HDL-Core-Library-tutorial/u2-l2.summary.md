本讲聚焦「厂商仿真库」——即原语的行为模型仓库。介绍了三个库：`unisim`（Xilinx 底层硬件原子原语，如 BUFGCE、PLLE2_BASE）、`xpm`（Xilinx 参数化宏，如 xpm_cdc_single，封装 unisim 并带约束）、`altera_mf`（Intel megafunction，如 scfifo）。核心结论是「点菜/上菜」分工：RTL 只例化原语，仿真行为由厂商库提供，综合映射则由 Vivado/Quartus 内置知识完成；库声明（`library xpm; use xpm.vcomponents.all;`）紧贴 `xilinx_behaviourral_*` 架构之前而 `own_behaviourral_*` 无此声明，正是厂商依赖局部化的源码证据。关键概念 `glbl.GSR` 报错源于 Xilinx 原语的 Verilog 仿真模型用层次引用全局复位信号，修复靠 `use_xilinx_libs=True` 同时加预编译库（`-L xpm -L unisims_ver -L secureip`）与加载 glbl 模块。最后强调同一份库需以三种形态分别供给：编辑器吃 `.vhd` 源路径（vhdl_ls.toml，标记 `is_third_party`）、本地 ModelSim 吃预编译库、CI 的 NVC 因不能编译 Verilog 而改用 grlib/gplgpu 的纯 VHDL 行为模型（`nvc --install`），并因此排除无开源模型的 PLL。
