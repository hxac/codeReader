本讲在 u9-l1 行为级 `fifo_sync` 之上，讲解同一 entity 的另两套架构：`xilinx_behavioural_sync_fifo` 封装 Xilinx `xpm_fifo_sync` 宏，`intel_behavioural_sync_fifo` 封装 Intel `scfifo` 宏。延续「同一 entity 多架构」模式——端口契约不变，内部把整个 FIFO 一次性替换为厂商黑盒宏，不再例化 `dual_clock_dual_port_ram`，这是与行为级实现最根本的结构差异。Xilinx 侧需做复位极性翻转（`rst => not sys_rst_n`）、用属性反推位宽，并以 12 个 `*_unconnected` 悬空信号接住 xpm 的多余输出交综合器删除；Intel 侧 scfifo 端口精简、无悬空信号，但因不提供 `data_valid`，封装多写一行手写 `read_data_valid`（`read_enable` 寄存一拍），并在满时对 `words_stored` 做钳位（`'subtype'high`）。两家均把厂商返回的位向量计数（`wr_data_count`/`usedw`）经 `to_integer(unsigned(...))` 转成本库统一的 `natural words_stored`，位宽取 `to_bits(FIFO_DEPTH)`，约等于 ⌈log₂(D+1)⌉。引入的关键概念包括：厂商宏端口超集与精简集之分、`*_unconnected` 悬空信号、复位极性适配、`lpm_*` 参数与 `usedw` 计数口径。核心结论：厂商封装的时序细节（含一处复位极性不对称疑点、`read_data_valid` 在三家来源各异）现有测试台仅严格校验 `own`、未例化 Intel，须靠带厂商库的本地仿真验证；下一讲 u9-l3 将转入异步 FIFO 与格雷码指针跨域同步。
