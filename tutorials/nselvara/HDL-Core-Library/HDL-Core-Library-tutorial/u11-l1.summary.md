本讲拆解 VUnit 测试台的最小骨架，共四块积木。第一是两个魔法通用量：`runner_cfg`（带默认值，是 VUnit 识别测试台的唯一硬标志，名字不可改）与 `tb_path`（无默认值，运行期注入，用于随机数播种）。第二是仿真生命周期，由隐式信号 `runner` 串联——`main` 进程里 `test_runner_setup` 开场、`test_runner_cleanup` 收尾须成对，并发区的 `test_runner_watchdog` 独立按用例计时防挂死。第三是用例的发现与驱动：用例即 `run("...")` 字面量，编译期静态扫描发现，运行期由 `while test_suite loop` 配合一串 `elsif run(...)` 驱动，循环前强制 `wait` 不可删，末尾 `else assert false` 护栏防止拼错名字静默假绿。第四是编译期 pragma `-- vunit: run_all_in_same_sim`，把 N 次仿真压成 1 次，只改调度不改发现，代价是用例间须显式复位 DUT。`main` 与 `checker` 两进程靠 `simulation_done` 握手，全库 12 个测试台共享此模板。下讲 u11-l2 将承接 `random`、`check_equal`，讲 OSVVM 随机化与断言校验。
