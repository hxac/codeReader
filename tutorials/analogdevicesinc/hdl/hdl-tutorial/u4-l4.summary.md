`library/common` 是 ADI HDL 仓库中约含 57 个 `.v` 文件的**纯 RTL 源文件池**：本身无 Makefile 与 `*_ip.tcl`、不被单独打包成 IP，而是由其他 IP 在各自 Makefile 的**依赖桶**（`GENERIC_DEPS`/`XILINX_DEPS`/`INTEL_DEPS`/`LATTICE_DEPS`）里按需以 `../common/xxx.v` 形式嵌入编译。

本讲聚焦两族最常复用的底层颗粒：**`ad_iobuf`** 为可参数化位宽的**三态双向 IO 缓冲**，用 `generate` 逐位实现「方向位为 1 高阻输入、为 0 驱动输出」，几乎出现在所有带 GPIO 的工程顶层 `system_top.v`；**`ad_mem`** 是等宽简单双口 RAM（同步写、寄存同步读），**`ad_mem_asym`** 是非对称双口 RAM，遵守「读写总比特数相等」约束，按最窄侧切颗粒并以 `{addr, lsb}` 地址拼接完成宽窄位宽转换（如 DMA 位宽桥接），二者均凭 `(* ram_style="block" *)` 综合属性推断为 BRAM，体现厂商无关本性。

核心结论：同一 `common` 文件可因厂商流程落入不同依赖桶——`ad_mem_asym` 三家共用，`ad_mem` 仅 Lattice 需要（其 `util_axis_fifo` 基于 `ad_mem`），印证「Lattice 扁平嵌入 util 源码」。复用广度：`ad_iobuf`（遍布 `projects/`，上百处）远超 `ad_mem`（约 45 处）与 `ad_mem_asym`（约 37 处）。
