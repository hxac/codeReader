本讲覆盖三个最小模块：编码规范、CI 检查、贡献与 PR 流程。编码规范（hdl_coding_guidelines.rst）是全仓 Verilog/VHDL 的「宪法」，按 Layout/Naming/Comments/General 四类组织，区分 must（强制）与 should（建议），只管版式、命名与文件结构，不涉性能优化；关键 must 规则包括一文件一模块且文件名等于模块名、Verilog-2001 参数风格、时钟复位端口先行、端口逐行声明且按接口分组、localparam 先于 reg/wire、license 头必含且改动时更新年份。CI 用 check_guideline.py 把可机械判定的子集自动化，仅检查 PR 中改动文件，任一告警即退出码 1、Action 标红、PR 不可合并；脚本支持 -e 自动修复，对 fir_interp/cic_interp 有豁免名单，library/ 下强制文件名等于模块名而 projects/ 不强制。贡献流程要求 fork+分支开发、本地跑脚本与 Verilator 与构建（无 Critical Warning）、开带 Signed-off-by（DCO）的原子 commit PR、由 CODEOWNERS 批准后合并；两条硬约束是 commit 须带 DCO 签名、不得产生 merge commit，冲突在终端 rebase 解决。改寄存器需同步 docs/regmap 文本、按语义化版本升 IP 版本号，并视情况更新 devicetree compatible、驱动对 VERSION 寄存器的解析、README 及工程 Makefile 的 LIB_DEPS。关键术语：must/should 规则、guideline check（GC）、DCO。
