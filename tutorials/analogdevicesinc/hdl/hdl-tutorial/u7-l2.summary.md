本讲义承接 u7-l1（移植）与 u3-l2（构建 Makefile），讲解如何基于 ADI 三层架构从零定制一个评估板工程。它覆盖三个最小模块：①新工程文件骨架——指出新建工程并非写新 RTL，而是复用载板/评估板 base design，仅补齐第三层五件套（Makefile、system_top.v、system_constr.xdc、system_bd.tcl、system_project.tcl），核心是「拼装 + 声明」；②CFG 参数化机制——区分命令行传参 `make VAR=val`（GNU Make 自动导出环境）与配置文件 `make CFG=file.mk`（需显式 export）两条路径，Tcl 端统一用 `$::env()` 读取，并引入关键概念 DIR_NAME「配置指纹」实现不同配置构建产物隔离互不覆盖，生成目录名时剔除 JESD/LANE 字样；③README 与文档模板——评估板层固定用 evalboard 模板，载板层按「无参数/有参数/固定配置」三选一（template1/2/3），第一行隐藏的 flag 注释（no_build_example/no_dts/no_no_os）控制 GitHub Action 的 CI 行为。核心结论：Makefile 三段式（PROJECT_NAME、LIB_DEPS 填 IP 名翻译成 component.xml、M_DEPS 填带路径文件）；仓库 Makefile 均标自动生成但生成器未随源码发布，现实做法是从兄弟工程复制改写。关键术语：三层架构、五件套、LIB_DEPS/M_DEPS、参数化、DIR_NAME、CFG、README flag，供后续讲义承接。
