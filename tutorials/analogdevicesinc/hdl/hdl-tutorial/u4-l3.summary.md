本讲延续库打包框架，补齐 Intel 与 Lattice 两条厂商支线。Intel 用 `*_hw.tcl`，由 Qsys 在 GUI 内解释执行，核心是回调驱动：`ELABORATION_CALLBACK` 依参数动态增删接口，`VALIDATION_CALLBACK` 推导派生参数；公共原语库 `adi_ip_intel.tcl` 提供薄封装，约束用 `.sdc`，库阶段仅 `touch` 时间戳。Lattice 用 `*_ltt.tcl`，由纯 `tclsh` 声明式构建内存 XML 树（`ipl` 命名空间），`generate_ip` 序列化为 lsccip 格式的 `metadata.xml` 等文件供 Radiant/Propel 消费，条件逻辑以参数/端口上的 Python 表达式（`-editable`/`-dangling`）替代 Tcl 回调。三家共性在于描述同一组源码、参数、接口与约束，差异集中在载体、执行模型与条件逻辑语法。关键不对称：Xilinx 跨库引用他人已打包的 `component.xml`，Intel/Lattice 则将 util 源码扁平嵌入（`INTEL_DEPS`/`LATTICE_DEPS`）；同一份 RTL 会被迫向最严格厂商妥协（如 Xilinx 侧为满足 Intel 而保留的 `dummy_axi_ports`）。
