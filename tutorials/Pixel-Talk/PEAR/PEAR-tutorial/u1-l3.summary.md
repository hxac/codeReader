本讲为 PEAR 仓库绘制代码地图，分三个模块：入口脚本一览、models 子包职责划分、dataset 与 utils 子包职责划分。核心结论：根目录共 4 个可执行入口——app.py（Gradio 视频演示）、inference_images.py（多人+YOLOv8 检测）、inference_wo_detect.py（单人无检测，README 未列出的隐藏入口）、train_ehms.py（训练）。三个推理入口共享“读配置→建 Renderer2→下载权重→Ehm_Pipeline→EHM_v2”的复制式组装套路，最小推理链路仅依赖 5 个项目内模块（ViT、SMPLXTransformerDecoderHead、Ehm_Pipeline、EHM_v2、Renderer2）；权重 checkpoint 只含 backbone 与 head 两段 state dict，EHM_v2 因无可学习参数不在其中。关键概念：入口脚本与库模块之分、用 import 可达性分析划分“入口可达/仅训练可达/孤儿模块”，须看传递可达而非直接 import；注意 models/smplx（可学习解码头）与 models/modules/smplx（参数转网格的官方层）是两回事。dataset 仅服务训练（build_web_tracked_data），utils 横跨两链（ConfigDict、to_tensor、GS_Camera 等）；vitdet、human_matting、utils/bbox 等为孤儿模块，dataset/__init__.py 还引用了仓库缺失的文件。
