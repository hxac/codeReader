# Verilog 数的表示与定点数

## 1. 本讲目标

本讲是 Unit 7（FPGA 数学运算）的入口，只讲一件事：**Verilog 是如何「看待」一个数的**。

读完本讲，你应当能够：

1. 区分 Verilog 里的「有符号数（signed）」与「无符号数（unsigned）」，理解 `signed` 关键字到底改变了什么。
2. 理解位宽（WIDTH）在运算中的截断与扩展规则，尤其是符号扩展。
3. 看懂「定点数」的 Q 格式约定：总位宽 `WIDTH`、小数位数 `FBITS`、整数位数 `IBITS` 三者的关系，并能据此算出一个定点格式的表示范围与精度。
4. 打开 projf 的 `mul.sv` / `div.sv` 时，能立刻读懂它的参数声明与结果截取逻辑。

本讲**不**讲除法/乘法的算法实现（那是 u7-l2、u7-l3 的任务），只讲这些算法所依赖的「数的表示」基础。

## 2. 前置知识

本讲假设你已经读过 [u5-l1 Verilog 库总览与 SystemVerilog 风格](u5-l1-verilog-library-overview.md)，知道 projf 库用 `logic` / `always_ff` / `always_comb` / `enum` / `$clog2` 这一小套 SystemVerilog 子集。如果你还记得下面两个常识，本讲会非常顺畅：

- **二进制**：一个 N 位的向量就是 N 个 0/1 比特，例如 8 位向量 `8'b0001_1000`。
- **十进制小数**：小数点后每一位代表 \( 2^{-1}, 2^{-2}, \dots \)，例如 \( 0.5 = 2^{-1} \)、\( 0.25 = 2^{-2} \)、\( 0.0625 = 2^{-4} \)。

一个关键的直觉先放在这里：**硬件里根本没有「小数点」这种东西**。一条 8 位的线，它存的只是 8 个比特。所谓「定点数」，只是设计者和使用者之间达成的**一个约定**——「我们假装这 8 位里，低 4 位是小数部分」。所有加减乘除底层仍是整数运算，小数点只是个被记在脑子里的「隐含位置」。本讲要解决的核心问题就是：这个约定如何用 `WIDTH` / `FBITS` 表达，以及它如何决定运算的对齐方式。

## 4. 核心概念与源码讲解

### 4.1 signed 语义：有符号数与二进制补码

#### 4.1.1 概念说明

一条 8 位的线本身没有「正负」属性，它就是 8 个比特。让它成为「有符号数」的，是 Verilog 里的 `signed` 关键字。一旦声明为 `signed`，这 8 位就被解释为**二进制补码（two's complement）**：

- 最高位（MSB）是**符号位**：0 表示非负，1 表示负。
- 正数的补码就是它的二进制本身。
- 负数的补码 = 对应正数「按位取反再加 1」。
- 因此 8 位有符号数的范围是 \([-128, +127]\)，而 8 位无符号数的范围是 \([0, 255]\)。

`signed` 关键字真正改变的是**运算行为**：对于有符号操作数，综合工具会生成「符号扩展」（见 4.2）和真正的算术比较；而无符号操作数做的是无符号比较。同一个 `>`，对 `signed` 和 `unsigned` 可能给出不同结果。

一个关键提醒：**只要一个表达式中混用了 signed 和 unsigned 操作数，Verilog 会把整个表达式当作 unsigned 处理**。这是定点运算里极常见的坑，所以 projf 的 maths 模块把所有参与运算的端口和中间变量都声明为 `signed`，保持一致。

#### 4.1.2 核心流程

把一个有符号数拆成「符号 + 绝对值」是很多算法（包括 projf 的除法器）的标准套路：

```
1. 取出符号位 sign = x[MSB]
2. 若 sign == 1（负数），绝对值 = -x（即按位取反加 1）
3. 若 sign == 0（非负），绝对值 = x
4. 用绝对值做无符号运算
5. 最后根据「两操作数符号是否相同」决定结果符号
```

这正好对应十进制里「先算绝对值，再补符号」的小学除法习惯。

#### 4.1.3 源码精读

先看 `div.sv` 如何声明有符号端口——注意 `signed` 关键字紧贴在位宽前面：

```verilog
// [lib/maths/div.sv:20-22] 输入输出全部声明为 signed
input  wire logic signed [WIDTH-1:0] a,   // dividend (numerator)
input  wire logic signed [WIDTH-1:0] b,   // divisor (denominator)
output     logic signed [WIDTH-1:0] val   // result value: quotient
```

完整声明见 [div.sv:8-23](https://github.com/suisuisi/FPGA_Library/blob/1e33525198872d63ced48e8f0cebaa2419b9eb22/ThreePart/projf-explore/lib/maths/div.sv#L8-L23)（这段代码声明了 `WIDTH`/`FBITS` 参数，并把 `a`/`b`/`val` 都标成 `signed`）。

作为对照，无符号除法器 `divu.sv` 的端口**没有** `signed`：

```verilog
// [lib/maths/divu.sv:20-22] 没有 signed，即 unsigned
input  wire logic [WIDTH-1:0] a,
input  wire logic [WIDTH-1:0] b,
output     logic [WIDTH-1:0] val
```

把两段并排看，`signed` 这个词的「分量」就一目了然了。

`div.sv` 取符号位和求绝对值的逻辑在这里（注意 `[WIDTH-1+:1]` 这种「索引部分选择」语法，详见 4.2.3）：

```verilog
// [lib/maths/div.sv:38-41] 取出两输入的符号位
always_comb begin
    a_sig = a[WIDTH-1+:1];  // 即 a[WIDTH-1]，符号位
    b_sig = b[WIDTH-1+:1];
end
```

```verilog
// [lib/maths/div.sv:106-110] 用符号位决定是否取绝对值
au <= (a_sig) ? -a[WIDTHU-1:0] : a[WIDTHU-1:0];  // 负则取反加一
bu <= (b_sig) ? -b[WIDTHU-1:0] : b[WIDTHU-1:0];
sig_diff <= (a_sig ^ b_sig);  // 两符号异或：不同则为 1（结果为负）
```

这里的 `WIDTHU = WIDTH - 1`（见 4.2），意思是「绝对值比原数少 1 位符号位」。运算结束后，再把符号补回去：

```verilog
// [lib/maths/div.sv:84-90] 根据符号差决定结果正负
SIGN: begin
    state <= IDLE;
    if (quo != 0) val <= (sig_diff) ? {1'b1, -quo} : {1'b0, quo};
    ...
end
```

`{1'b0, quo}` 给正结果补一个 0 符号位；`{1'b1, -quo}` 给负结果补一个 1 符号位并对数值取补。这就是「先算绝对值，再补符号」在 RTL 里的落地。

#### 4.1.4 代码实践

**目标**：亲手验证 `signed` 声明如何改变一个 8 位向量的「解释」。

**操作步骤**：

1. 准备一个 8 位向量 `x = 8'b1101_1100`。
2. 如果它是 `unsigned`，它的值是多少？如果它是 `signed`，它的值又是多少？
3. 打开 `div.sv`，确认 `a`/`b`/`val` 都是 `signed`，那么这个 `1101_1100` 在 `div.sv` 里会被当作正数还是负数？

**预期结果**：

- 作为 `unsigned`：\( 1101\_1100_2 = 220 \)。
- 作为 `signed`：最高位是 1，是负数；绝对值 = 按位取反加 1 = \( \sim 1101\_1100 + 1 = 0010\_0011 + 1 = 0010\_0100 = 36 \)，所以值为 \( -36 \)。

**需要观察的现象**：同一串比特 `1101_1100`，在 `unsigned` 视角下是 220，在 `signed` 视角下是 -36。差别完全来自 `signed` 关键字——比特本身没变。

#### 4.1.5 小练习与答案

**练习 1**：8 位 `signed` 能表示的最小值是多少？它的二进制是什么？为什么它「没有对应的正数」？

**参考答案**：最小值是 \(-128\)，二进制 `1000_0000`。它的绝对值 \( +128 \) 超出了 8 位 `signed` 的正数上限 \( +127 \)，所以无法表示——这就是 `div.sv` 里要用 `SMALLEST` 单独检测这种「取绝对值会溢出」的特殊输入的原因（见 4.2.3）。

**练习 2**：把 `signed [7:0] x = -1` 和 `unsigned [7:0] y = 255` 放在两条线上，它们的比特图案相同吗？为什么 projf 仍要显式写 `signed`？

**参考答案**：比特图案完全相同，都是 `1111_1111`（-1 的补码 = 255 的无符号值）。但 `signed` 关键字改变了**比较和扩展**的语义：例如 `x > 5` 在 signed 下为假（-1 不大于 5），在 unsigned 下 `y > 5` 为真（255 大于 5）。projf 写 `signed` 是为了让 `>`、`*`、`-` 等运算按算术语义执行，而非按位模式比较。

### 4.2 位宽扩展与截断

#### 4.2.1 概念说明

运算常常会改变位宽：

- 两个 N 位数相乘，完整乘积是 **2N 位**。
- 两个 N 位数相加，和最多是 **N+1 位**（多一个进位）。
- 把一个 N 位数赋给一个更窄的变量，会发生**截断**（丢掉高位）。
- 把一个 N 位数赋给一个更宽的变量，会发生**扩展**（补高位）。

扩展的规则取决于符号：

- **无符号扩展**：高位补 0（零扩展）。
- **有符号扩展**：高位**复制符号位**（符号扩展）。例如把 8 位 `1101_1100`（-36）扩展到 16 位，得到 `1111_1111_1101_1100`（仍是 -36）。这条规则保证了「扩展不改变数值」。

#### 4.2.2 核心流程

projf 处理位宽的核心公式集中在乘法器里。设总位宽 `WIDTH`、小数位 `FBITS`、整数位 `IBITS = WIDTH - FBITS`，则两个 WIDTH 位数相乘得到 `2*WIDTH` 位乘积后，要从中截取出一个 WIDTH 位的结果。截取的上下界是：

```
LSB = WIDTH - IBITS        // 丢弃低位（多余的小数精度）
MSB = 2*WIDTH - IBITS - 1  // 结果的最高有效位
```

取 `prod[MSB:LSB]` 共 WIDTH 位作为截断后的结果；高于 MSB 的位用于**溢出检测**（正常情况下它们应当全是符号位的复制）。

#### 4.2.3 源码精读

`mul.sv` 用三行 localparam 把上述公式写死（注意 `IBITS = WIDTH - FBITS`）：

```verilog
// [lib/maths/mul.sv:25-27]
localparam IBITS = WIDTH - FBITS;
localparam MSB = 2*WIDTH - IBITS - 1;
localparam LSB = WIDTH - IBITS;
```

默认参数 `WIDTH=8, FBITS=4` 时：`IBITS=4`，`MSB=11`，`LSB=4`。于是乘积的截取窗口是 `prod[11:4]`（8 位），高位 `prod[15:12]` 留给溢出判断，低位 `prod[3:0]` 留给舍入：

```verilog
// [lib/maths/mul.sv:45-48] 先算完整 2*WIDTH 位乘积
CALC: begin
    state <= TRUNC;
    prod <= a1 * b1;   // 16 位完整乘积
end
```

```verilog
// [lib/maths/mul.sv:49-56] 截取窗口 + 取舍入位
TRUNC: begin
    state <= ROUND;
    prod_t <= prod[MSB:LSB];          // 结果 = prod[11:4]
    rbits  <= prod[FBITS-1:0];        // 被丢弃的小数位 prod[3:0]
    round  <= prod[FBITS-1+:1];       // 最高丢弃位 prod[3]，决定是否进位
    even   <= ~prod[FBITS+:1];        // 结果最低位 prod[4] 取反，用于「向偶舍入」
end
```

这段代码还演示了 Verilog 的**索引部分选择（indexed part-select）**语法，初学者常被它绊倒，这里集中解释：

- `prod[FBITS-1+:1]`：从下标 `FBITS-1` 开始，向上取 `1` 位 → 等价于 `prod[FBITS-1]`。
- `prod[FBITS+:1]`：从下标 `FBITS` 开始，向上取 `1` 位 → 等价于 `prod[FBITS]`。
- `a[WIDTH-1+:1]`（出现在 `div.sv`）：等价于 `a[WIDTH-1]`，即符号位。

`+:` 左边是「起始下标」、右边是「位宽」。它比 `prod[3]` 更灵活之处在于起始下标可以是变量，但本讲遇到的用法都退化为单比特。

回到 `div.sv`，看它如何处理「有符号数位宽比无符号少 1」：

```verilog
// [lib/maths/div.sv:25-27] 有符号数：绝对值比原数少 1 位符号位
localparam WIDTHU = WIDTH - 1;                 // unsigned widths are 1 bit narrower
localparam FBITSW = (FBITS == 0) ? 1 : FBITS;  // 避免 FBITS=0 时出现负位宽
localparam SMALLEST = {1'b1, {WIDTHU{1'b0}}};  // 最小负数：8 位下即 1000_0000 = -128
```

作为对比，无符号除法器 `divu.sv` 没有 `WIDTHU`，直接用全宽 `WIDTH`：

```verilog
// [lib/maths/divu.sv:31] 无符号：迭代次数用全宽 WIDTH
localparam ITER = WIDTH + FBITS;       // divu
// 而 div.sv:29 是
// localparam ITER = WIDTHU + FBITS;   // div（有符号，少 1 位）
```

这两行并排，把「signed 比 unsigned 少一个符号位」这件事量化得清清楚楚：同样 `WIDTH=8`，有符号做除法只需迭代 \( 7+4=11 \) 次，无符号要 \( 8+4=12 \) 次。

#### 4.2.4 代码实践

**目标**：用一个 Python（或 C）小程序，验证「符号扩展」不改变数值，而「截断」可能改变数值。

**操作步骤**：

1. 写一段 Python：把 -36 用 8 位补码表示（`x & 0xFF` 得到 220）。
2. 把它符号扩展到 16 位：`(220 | 0xFF00) if (220 & 0x80) else 220`，再解释成有符号 16 位，确认仍是 -36。
3. 把 16 位的 -36 截断回低 8 位（`& 0xFF`），确认又变回 220 → -36。
4. 故意制造一次「错误截断」：把 16 位 +300 截到低 8 位（`300 & 0xFF = 44`），观察数值被破坏。

**预期结果**：符号扩展与匹配位宽的截断是可逆的、不改变数值；但截断到「装不下」的位宽会丢弃有效高位，数值就错了——这正是 `mul.sv` 要做溢出检测的原因。

**需要观察的现象**：步骤 4 中 +300 截断成 44，对应了硬件里「结果超出了 WIDTH 位能表示的范围」这一类溢出。

#### 4.2.5 小练习与答案

**练习 1**：默认参数下 `mul.sv` 的乘积是几位？截取后结果又是几位？被丢弃的低位有几位、各自用途是什么？

**参考答案**：乘积 `2*WIDTH = 16` 位；截取结果 `WIDTH = 8` 位（`prod[11:4]`）；被丢弃的低 `FBITS = 4` 位（`prod[3:0]`）用于舍入判断，高 `IBITS = 4` 位（`prod[15:12]`）用于溢出检测。

**练习 2**：`SMALLEST = {1'b1, {WIDTHU{1'b0}}}` 在 `WIDTH=8` 时等于多少？为什么除法器要单独检测 `b == SMALLEST`？

**参考答案**：等于 `1000_0000`，即 8 位有符号的最小值 -128。它的绝对值 +128 超出 8 位表示范围，无法正确取绝对值，所以除法器把它当作溢出直接报错，而不是去算一个错误的绝对值。

### 4.3 定点数 Q 格式：WIDTH 与 FBITS

#### 4.3.1 概念说明

有了 signed 和位宽基础，现在把「隐含小数点」正式化。projf 用两个参数描述定点数：

- `WIDTH`：总位宽（含符号位、整数位、小数位）。
- `FBITS`：其中小数部分的位数。
- `IBITS = WIDTH - FBITS`：整数部分位数（**含符号位**）。

这就是所谓的 **Q 格式**。默认 `WIDTH=8, FBITS=4` 对应一种「Q4.4」（按 projf 的口径，整数位 4 含符号位、小数位 4）。把 8 位看作：

```
 bit:  7   6   5   4 | 3   2   1   0
       符号  整数 整数 整数 | 小数 小数 小数 小数
                        ↑ 隐含小数点在这两位之间
```

小数点只是「约定」，硬件里并不存在。一个 8 位向量 `0001_1000` 在 Q4.4 下表示：整数部分 `0001` = 1，小数部分 `1000` = \( 1 \times 2^{-1} = 0.5 \)，合计 \( +1.5 \)。

由此可推出表示范围与精度：

- **精度（分辨率）**：\( \Delta = 2^{-FBITS} \)。Q4.4 的精度是 \( 2^{-4} = 0.0625 \)。
- **范围**：\( \big[-2^{IBITS-1},\; 2^{IBITS-1} - 2^{-FBITS}\big] \)。Q4.4 的范围是 \([-8,\; +7.9375]\)。
- **快捷换算**：数值 \( v \) 对应的整数编码 = \( \text{round}(v \times 2^{FBITS}) \)。

**为什么 FPGA 偏爱定点而非浮点？** 因为定点数底层就是普通整数运算，可以直接复用 FPGA 里现成的**整数 DSP 乘法单元**和加法器，只需在结果上做简单的移位/截断（如 4.2 所示）。浮点运算每次都要做「对齐、规格化（leading-one 检测 + 桶形移位）」，耗用大量逻辑和时钟周期。对图像、音频、图形这类「精度要求适中、吞吐量要求高」的场景，定点数用极低的代价换来了足够的精度。

#### 4.3.2 核心流程

把一个十进制小数转成 Q 格式定点编码：

```
1. 用 FBITS 算出缩放因子 S = 2^FBITS
2. 编码值 = round(数值 × S)
3. 若数值为负，对其绝对值求补码
4. 把编码值塞进 WIDTH 位（超出则溢出）
```

反向（从编码读出数值）则除以 \( 2^{FBITS} \) 即可。projf 的 `mul.sv` / `div.sv` 在端口上接收的就是这种「已经缩放好的整数编码」，所有运算按整数进行，最后再用 4.2 的截取窗口把结果拉回同样的 Q 格式。

#### 4.3.3 源码精读

projf maths 分区的 README 把这套约定一句话点明——所有除法/乘法/开方模块都围绕 `WIDTH` 与 `FBITS` 组织：

> [lib/maths/README.md:7-12](https://github.com/suisuisi/FPGA_Library/blob/1e33525198872d63ced48e8f0cebaa2419b9eb22/ThreePart/projf-explore/lib/maths/README.md#L7-L12) —— 列出 `div.sv`（signed fixed-point）、`divu.sv`（unsigned fixed-point）、`mul.sv`（signed fixed-point）等模块，并各自标明舍入方式（高斯舍入 / 向零舍入）。

`mul.sv` 的模块声明把这套约定写进 parameter，并明确标注「width of numbers in bits (integer and fractional)」：

```verilog
// [lib/maths/mul.sv:8-11] 两个参数就是 Q 格式的全部
module mul #(
```

`div.sv` 用完全相同的参数声明，说明这两个模块共享同一套定点约定，可以无缝对接（[div.sv:8-11](https://github.com/suisuisi/FPGA_Library/blob/1e33525198872d63ced48e8f0cebaa2419b9eb22/ThreePart/projf-explore/lib/maths/div.sv#L8-L11)）。

一个值得注意的工程细节：`div.sv` 用 `FBITSW = (FBITS==0) ? 1 : FBITS` 来避免 `FBITS=0` 时出现负的或零位宽（[div.sv:26](https://github.com/suisuisi/FPGA_Library/blob/1e33525198872d63ced48e8f0cebaa2419b9eb22/ThreePart/projf-explore/lib/maths/div.sv#L26)）。这说明 projf 的定点模块**允许 `FBITS=0`**——此时它退化成一个纯整数运算器（Q8.0），同一份代码同时覆盖「整数」和「定点」两种用法。

#### 4.3.4 代码实践

**目标**：用 `WIDTH=8, FBITS=4` 表示 \( +1.5 \) 和 \( -2.25 \)，手算它们的二进制补码编码。

**操作步骤**：

1. 缩放因子 \( S = 2^{FBITS} = 16 \)。
2. \( +1.5 \)：编码 = \( 1.5 \times 16 = 24 = 0001\_1000_2 \)（正数，直接写）。
3. \( -2.25 \)：绝对值编码 = \( 2.25 \times 16 = 36 = 0010\_0100_2 \)；取补码 = 按位取反加 1 = \( 1101\_1011 + 1 = 1101\_1100 \)。
4. 用「快捷换算」反验：把 `1101_1100` 当 8 位有符号 = -36，再除以 16 = -2.25 ✓。

**预期结果**：

| 数值 | 编码（8 位） | 十六进制 | 反验 |
| --- | --- | --- | --- |
| \( +1.5 \) | `0001_1000` | `0x18` | \( 24/16 = 1.5 \) ✓ |
| \( -2.25 \) | `1101_1100` | `0xDC` | \( -36/16 = -2.25 \) ✓ |

**需要观察的现象**：小数部分 `1000` 恰好表示 \( 0.5 \)，小数部分 `0100` 表示 \( 0.25 \)——定点数的小数位就是按 \( 2^{-1}, 2^{-2}, \dots \) 加权，和十进制小数的「按 \( 10^{-1}, 10^{-2} \) 加权」完全类比。

#### 4.3.5 小练习与答案

**练习 1**：`WIDTH=8, FBITS=4` 能表示的最大正数和最小（最负）数各是多少？精度是多少？

**参考答案**：最大正数 `0111_1111` = \( 7 + 15/16 = 7.9375 \)；最小负数 `1000_0000` = \( -8 \)；精度 \( 2^{-4} = 0.0625 \)。

**练习 2**：若想把精度提高到 0.0078125，在 `WIDTH=16` 不变的前提下 `FBITS` 应设为多少？此时整数位还剩几位（含符号）？

**参考答案**：\( 2^{-FBITS} = 0.0078125 = 2^{-7} \)，故 `FBITS=7`；此时 `IBITS = 16 - 7 = 9`（含 1 位符号、8 位整数 magnitude）。这正是「整数位和小数位争抢总位宽」的典型权衡：提高精度就会压缩表示范围。

### 4.4 定点运算的对齐规则：加法与乘法

定点数的加减乘除底层都是整数运算，**唯一需要额外操心的就是小数点对齐**。本节把对齐规则讲透，并顺带解释 projf 乘法器里的「高斯舍入」。

#### 4.4.1 概念说明

**加法对齐**：两个**相同 Q 格式**（同 `FBITS`）的定点数相加，小数点天然对齐，直接做整数加法即可，结果仍是同一 Q 格式。若两者 `FBITS` 不同，必须先把小数位较少的那个**左移**（扩大）到小数位较多的格式，再相加。

**乘法对齐**：两个 `FBITS` 位的定点数相乘，完整乘积的小数位数是 \( 2 \times FBITS \)、整数位数也会翻倍。要把乘积「拉回」原来的 Q 格式，就需要**右移 `FBITS` 位**（即丢弃低 `FBITS` 位小数），并检查高位整数是否溢出。这正是 `mul.sv` 截取窗口 `prod[MSB:LSB]` 的来历。

**舍入**：直接丢弃低位等于「向零截断」，会引入系统性偏差。projf 的 `mul.sv` 和 `div.sv` 都用**高斯舍入（Gaussian rounding，也叫 round-half-to-even / 银行家舍入）**：当被丢弃部分正好是「一半」时，向最近的偶数舍入，从而在大量运算中消除统计偏差。

#### 4.4.2 核心流程

两个 Q4.4 数 \( a, b \) 相乘并拉回 Q4.4：

```
1. 算 16 位完整乘积 prod = a * b      （此时 prod 是 Q8.8）
2. 截取 prod[11:4] 作为候选结果 prod_t （丢弃低 4 位小数 → 降回 Q4.4）
3. 取被丢弃的最高位 round = prod[3]    （决定是否要进位）
4. 若 round=1 且不满足「正好一半且结果为偶」，则 prod_t += 1
5. 检查高位 prod[15:12] 是否全是符号扩展，否则标记溢出
```

#### 4.4.3 源码精读

`mul.sv` 把上述流程落成三拍状态机 `CALC → TRUNC → ROUND`（截取部分已在 4.2.3 引用，这里聚焦舍入）：

```verilog
// [lib/maths/mul.sv:30] 「一半」的阈值：FBITS=4 时 HALF = 1000_2 = 8
localparam HALF = {1'b1, {FBITS-1{1'b0}}};
```

```verilog
// [lib/maths/mul.sv:57-64] 高斯舍入 + 溢出判断
ROUND: begin  // round half to even
    state <= IDLE;
    busy <= 0;
    done <= 1;
    // 仅当需要进位、且不是「正好一半且当前结果已是偶」时才 +1
    val <= (round && !(even && rbits == HALF)) ? prod_t + 1 : prod_t;
    // 溢出：结果符号与输入符号积是否一致 + 高位是否为纯符号扩展
    if (sig_diff == prod_t[WIDTH-1+:1] &&
        (prod[2*WIDTH-1:MSB+1] == '0 || prod[2*WIDTH-1:MSB+1] == '1)) begin
        valid <= 1; ovf <= 0;
    end else begin
        valid <= 0; ovf <= 1;
    end
end
```

注意 `rbits == HALF` 正是判断「被丢弃部分是否正好等于一半（`1000`）」；`even` 是候选结果最低位取反（结果为偶时 `even=1`）。两条件同时成立就**不进位**，实现「向偶舍入」。

> 说明：`prod[2*WIDTH-1:MSB+1] == '1` 这里用 `'1` 与一个多位向量比较，是 Verilog 的「填充（unbased unsized）字面量」，意指「全 1」。本仓库 maths 模块能被 Vivado/Verilator 接受这种写法。

`div.sv` 同样有 `ROUND` 状态做高斯舍入（[div.sv:77-83](https://github.com/suisuisi/FPGA_Library/blob/1e33525198872d63ced48e8f0cebaa2419b9eb22/ThreePart/projf-explore/lib/maths/div.sv#L77-L83)），但实现细节（用余数和商的奇偶性判断）留给 u7-l2 专题展开。

#### 4.4.4 代码实践

**目标**：手算 \( 1.5 \times (-2.25) \)，跟踪 `mul.sv` 的截取与舍入，验证结果是 \( -3.375 \)。

**操作步骤**（沿用 4.3.4 得到的编码）：

1. 输入编码：\( a = 0001\_1000 \)（=24，即 +1.5），\( b = 1101\_1100 \)（=-36，即 -2.25）。
2. 算 16 位有符号乘积：\( 24 \times (-36) = -864 \)。在 16 位补码里 = `1111_1100_1010_0000`（即 `0xFCA0`）。
3. 截取 `prod[11:4]`：从 `0xFCA0` 取出 bits 11..4 = `1100_1010` = `0xCA`。当作 8 位有符号 = \( -54 \)，再 /16 = **-3.375** ✓。
4. 取舍入位 `round = prod[3] = 0` → 不进位，`val = 0xCA`。
5. 溢出检查：`sig_diff = 1`（两输入异号），`prod_t[7] = 1`（结果负），二者相等 ✓；高位 `prod[15:12] = 1111`（全 1，纯符号扩展）✓ → 不溢出，`valid=1`。

**预期结果**：最终 `val = 8'b1100_1010`，即 \( -3.375 \)，且 `ovf=0, valid=1`。注意 \( -3.375 \) 在 Q4.4 里可精确表示（\( 0.375 = 0.0110_2 \)），所以本轮没有发生真正的舍入（`round=0`）。

**需要观察的现象**：乘积原本是 Q8.8（16 位、8 位小数），经过 `prod[11:4]` 截取后被「压缩」回 Q4.4（8 位、4 位小数）——这就是「乘法小数位翻倍后必须丢弃一半」的直观体现。若想换一个会产生舍入的例子，可试 \( 1.1 \times 1.2 \)（在 Q4.4 下先各自四舍五入到最近可表示值）。

> 待本地验证：上述手算可用一段 Python 复算（`((24*-36) & 0xFFFF)` 取低 16 位、再按有符号解释、再取 bits 11..4）。若你装了 Verilator 或 Icarus Verilog，也可直接给 `mul.sv` 写一个最小 testbench 验证，但本实践不依赖仿真器。

#### 4.4.5 小练习与答案

**练习 1**：两个 Q4.4 数相加，结果的小数位是几位？为什么不需要移位对齐？

**参考答案**：结果仍是 4 位小数（Q4.4）。因为两者 `FBITS` 相同，小数点位置天然对齐，直接做整数加法即可——这正对应 4.4.1 说的「同 Q 格式加法无需额外对齐」。加法唯一的代价是可能多出一个进位位（N+1 位），需要决定是否扩展位宽或判定溢出。

**练习 2**：为什么 projf 选择「高斯舍入」而不是简单的「四舍五入」？

**参考答案**：简单的「四舍五入」在遇到正好一半时总是向上进位，会在大量运算中引入正向偏差；高斯舍入（向最近的偶数舍入）让「正好一半」时一半向上、一半向下，统计上互相抵消，长期运算的误差均值更接近零。这对图形渲染、信号处理等「海量重复运算」的场景尤其重要。

**练习 3**：`mul.sv` 的截取窗口在 `WIDTH=16, FBITS=8` 时，`MSB` 和 `LSB` 分别是多少？乘积是几位？

**参考答案**：`IBITS = 16-8 = 8`，`MSB = 2*16-8-1 = 23`，`LSB = 16-8 = 8`，截取 `prod[23:8]`（16 位）；乘积 `2*16 = 32` 位。规律始终是：截取窗口丢掉低 `FBITS` 位（舍入）、检查高 `IBITS` 位（溢出），中间留 `WIDTH` 位作结果。

## 6. 本讲小结

- **`signed` 改变的是解释与运算语义**：同一串比特在 `unsigned` 与 `signed` 下可能是完全不同的数值；projf 的 maths 模块把端口统一标 `signed`，避免混用导致表达式被当作无符号处理。
- **二进制补码**是 signed 的表示法：负数 = 按位取反加 1；最小负数的绝对值会溢出，需特殊处理（`div.sv` 的 `SMALLEST` 检测）。
- **位宽扩展/截断**：有符号数扩展靠复制符号位；两个 N 位数相乘得 2N 位乘积，截取时丢低位（舍入）、查高位（溢出）。
- **Q 格式 = (WIDTH, FBITS)**：`IBITS = WIDTH - FBITS` 含符号位；精度 \( 2^{-FBITS} \)，范围 \( [-2^{IBITS-1}, 2^{IBITS-1}-2^{-FBITS}] \)；`FBITS=0` 时退化为纯整数。
- **定点运算的核心是小数点对齐**：同 Q 格式加法直接相加；乘法后乘积小数位翻倍，需用 `prod[MSB:LSB]` 截回原格式，并用高斯舍入消除统计偏差。
- **FPGA 偏爱定点**：定点复用现成整数 DSP 单元，无需浮点的规格化开销，是图形/信号处理的高性价比选择。
