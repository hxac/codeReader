本讲承接 u6-l1 的显示时序与 u5-l3 的 BRAM/ROM，解决「扫描到每个像素时从哪里取色」的问题，对比两种取色策略。帧缓冲把整幅位图存入 BRAM，由地址计数器随 `(sx,sy)` 逐像素回放：`top_david_mono` 用事件计数器（`frame` 清零、每拍自增）代替乘法寻址，并以 `LAT=2` 提前量补偿 BRAM 同步读延迟；它适合全屏位图但存储开销大、坐标与地址绑定而无移动概念。linebuffer 是「一行长的双时钟域 BRAM」：在 `clk_sys` 写、`clk_pix` 读，借 3 个 `xd` 同步 `frame/line` 脉冲跨域，靠读地址每 `scale` 拍前进一格做水平缩放、靠 `cnt_lb_line` 重复读做垂直缩放，是帧缓冲缩放显示的关键中间件。硬件精灵则不存整屏，只存小图形（ROM 或内联位图），每拍实时判断 `(sx,sy)` 是否落在精灵矩形内、输出 `pix`/`drawing`，背景色由顶层组合逻辑给出，存储极省且移动「免费」。`sprite_inline`/`sprite_rom`/`sprite` 共享 IDLE/REG_POS/ACTIVE/WAIT_POS/SPR_LINE/WAIT_DATA 六状态机，核心寻址为行优先公式 `cy*SPR_WIDTH+cx`；`sprite` 额外用算术右移 `sy-spry` 做垂直缩放、`cnt_x` 计数器做水平缩放。选型口诀：全屏位图用帧缓冲，少量可动图形用精灵，复杂游戏用「帧缓冲背景 + 精灵前景」的混合两层架构。
