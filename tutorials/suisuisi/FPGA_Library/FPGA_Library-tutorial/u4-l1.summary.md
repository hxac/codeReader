本讲是 Unit 4（HLS 高层综合）的入口，建立 HLS 概念骨架与 Vivado HLS 工程地图，以一个 2D 中值滤波器工程为载体。核心要点：**高层综合（HLS）** 是用 C/C++ 写算法、由工具（Vivado HLS）自动生成 RTL 的设计范式，与逐周期手写 HDL 相比开发更快、易验证，代价是资源和时延略逊顶级手工 RTL。其标准工作流为三阶段且顺序不可颠倒：**C 仿真（csim）** 验证算法功能 → **高层综合（Synthesis）** 生成 RTL 并产出时延（Latency）与资源（Utilization）报告 → **协同仿真（cosim）** 用同一 testbench 验证 RTL 行为与 C 一致。工程由 XML 描述文件 `vivado_hls.app` 管理，声明顶层函数（`TwoD_MedianFilter`）、用 `tb="1"/"false"` 区分 testbench 与设计源、用 solution 维护多套优化方案。关键术语包括**顶层函数、testbench、任意精度数据类型、pragma/directive**。本讲引出两条贯穿后续的认知：头文件的 typedef（如 `uint8_t`）与尺寸宏直接决定综合后数据通路宽度和存储大小；testbench 通过 `clean.csv` 作黄金参考实现自校验。性能上目标 <3ms/<25% 资源，实际达 ≈12ms/13%——资源达标、时延未达激进目标，是 pragma 调优「快 vs 省」拉扯的典型，为 u4-l3 优化主题埋下伏笔。算法实现细节留给下一讲。
