本讲剖析 mmdet3d 的训练全流程。核心结论：tools/train.py 是「薄入口」，不含训练逻辑，只做解析参数、Config.fromfile 合并配置、按 CLI 改写配置（--amp 换用 AmpOptimWrapper 开混合精度、--resume 自动找最新断点续训并覆盖 load_from、--cfg-options 深度合并），再把配置交给 Runner.from_cfg 组装模型、dataloader、优化器包装器与 hook 等组件，启动 runner.train() 主循环。日程基座 cyclic-40e 用两段余弦 param_scheduler 让学习率与动量反向变化并逐 iter 连续生效，梯度裁剪是 OptimWrapper 的职责，RepeatDataset 使真实数据轮数等于 max_epochs 乘 times。运行时基座 default_runtime 提供六个默认 hook（计时、日志、推进调度器、存档、分布式种子、3D 可视化）与窗口平滑的 LogProcessor。主循环每 iter 依次执行 hook 计时、model.train_step（内含 data_preprocessor 与 loss 计算）、推进 lr 并记日志，每隔 val_interval 轮跑 ValLoop 输出 mAP。work_dir 产出日志、vis_data/scalars.json 与 checkpoint；日志中 time 与 data_time 之比是判断数据瓶颈还是算力瓶颈的第一依据。
