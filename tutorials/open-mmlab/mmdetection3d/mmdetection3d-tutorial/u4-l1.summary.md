本讲解剖 mmdet3d 的注册器（Registry）机制，即配置中 type 字符串到真实 Python 类的路由中枢。核心结论：registry.py 实际定义 21 个注册节点（头注释的 17 已漂移），每个节点以 mmengine 根注册器为 parent，并声明 locations 自动导入目录；注册由 @register_module() 装饰器在模块被 import 时以副作用完成，import mmdet3d 本身不注册任何类。查找链路三段式：本级注册表 → locations 懒导入 → parent 链上溯；带 mmdet./mmdet3d. 前缀的 type 经 scope 切换跨项目借模块。build 是递归工厂，一行 MODELS.build 滚出整棵对象树。引入术语：parent、locations、懒导入、default_scope、别名注册、TASK_UTILS。另澄清 PointPillars 并非注册名，而是 VoxelNet 加 PillarFeatureNet 等组件的组合，为后续检测器分层与自定义模块打基础。
