本讲只讲分词器基类，不涉具体算法。PreTrainedTokenizerBase 是所有分词器的抽象契约：本身不可直接实例化，它把与算法无关的通用逻辑（参数归并、特殊 token 管理、from_pretrained/save_pretrained）写进基类，把算法相关的 tokenize、_decode 等留空（抛 NotImplementedError）交子类实现，属「模板方法」设计。现代分词器为三层继承：基类 → 后端（快速 TokenizersBackend 委托 Rust、慢速 SentencePieceBackend 用 Python）→ 具体模型类（如 LlamaTokenizer 仅覆盖 padding_side 等少量默认值）。三族核心属性：词表（vocab_size 不含新增 token、__len__ 含新增、get_vocab 双向查表）、特殊 token（分「命名」「额外」两套存储，聚合为 special_tokens_map/all_special_tokens/all_special_ids，与普通 token 共享同一 id 空间）、长度与对齐（model_max_length 默认 1e30 故不自动截断，padding_side/truncation_side）。四组接口：tokenize（切词，抽象）→ convert_tokens_to_ids（查表，具体）→ encode（只要 input_ids）/ __call__（返回 BatchEncoding，同时传 text 与 text_target 时会把目标编进 labels）→ decode（具体方法，下沉到抽象 _decode）。关键术语 token、id、词表、特殊 token、BatchEncoding 供后续讲义承接。
