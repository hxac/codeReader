本讲回答「分词由谁完成」，区分两条并列的分词后端：慢速 `SentencePieceBackend`（`is_fast=False`，Python 调 sentencepiece C++ 库，几乎所有方法是一行转调 `self.sp_model`）与快速 `TokenizersBackend`（`is_fast=True`，封装 Rust `tokenizers` 库，委托 `self._tokenizer`，带来速度优势与对齐信息）。二者都直接继承 `PreTrainedTokenizerBase`，是兄弟而非父子。v5 关键变化：具体模型类统一继承快速后端，不再有 `*Fast` 伴生类；旧 `use_fast` 被忽略，改由 `AutoTokenizer(backend=...)` 选后端，`self.backend` 字段被 Processor 等下游探测能力。Converter 体系（`convert_slow_tokenizer.py`）负责把慢速资产翻译成 Rust 对象：`Converter` 基类 → 家族子类（`SpmConverter`/`LlamaConverter` 等）→ `SLOW_TO_FAST_CONVERTERS` 注册表；`SentencePieceExtractor` 直接解析 `tokenizer.model` 的 protobuf，使转换可脱离慢速实例。加载时 `convert_to_native_format` 自动触发转换，保证只有 `.model` 的 checkpoint 也能用快速后端且结果与慢速一致。关键术语：后端、`is_fast`、`sp_model`、`_tokenizer`、对齐信息、Rust 五件套（model/normalizer/pre_tokenizer/decoder/post_processor）。
