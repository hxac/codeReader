本讲拆解 `from_pretrained` 的「读取底盘」`utils/hub.py`：`cached_file`/`cached_files` 自身不下载，而是委托 `huggingface_hub` 的胶水层——单文件走 `hf_hub_download`、多文件（权重分片）走 `snapshot_download`，并统一本地目录与远端 repo 入口、将 Hub 异常转译为 `OSError`、断网时用 `try_to_load_from_cache` 兜底。

关键术语：repo id 即 git 仓库地址，分支/标签/提交统称 revision；缓存采用「内容寻址 + 符号链接农场」布局 `models--<org>--<name>/{refs,snapshots/<commit_hash>,blobs}`，`blobs/` 按内容哈希存真实文件、`snapshots/<hash>/` 以软链接指向 blob，使同一文件跨 revision 共享存储。`_commit_hash` 快速路径让 config/tokenizer/权重的链式加载在首次后近乎零网络开销；离线模式（`HF_HUB_OFFLINE`/`local_files_only`）则退化为纯本地读取。

本讲还定位了链路中另两层：`core_model_loading.py` 是下载之后的权重加载层（重命名转换张量并灌进 `nn.Module`，并非下载器），`dependency_versions_check.py` 在导入时校验 `huggingface_hub` 等关键库版本，作为整个下载加载流程的依赖守门。
