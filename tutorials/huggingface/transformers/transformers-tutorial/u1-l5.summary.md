本讲围绕 `pipeline()` 工厂函数与 `Pipeline` 基类，讲清一行代码完成推理的内部机制。`pipeline()` 按 `task`（如 `sentiment-analysis`）查 `SUPPORTED_TASKS` 任务注册表，解析别名，装配「模型 + 预处理组件 + 具体 Pipeline 类」并返回实例，本身不做推理；常用参数为 `task`、`model`、`device`，不传 model 时用表内默认 checkpoint 并打印警告。`Pipeline` 基类把一次推理抽象为三段式骨架：`preprocess`（输入转张量）→ `_forward`（张量转模型输出）→ `postprocess`（输出转友好结果），由 `run_single` 串联；公共 `forward` 统一负责设备搬运与 `no_grad`，子类只实现热路径。各 Pipeline 类用 `_load_*` 标志声明所需预处理组件（文本用 tokenizer、图像用 image_processor），`_sanitize_parameters` 负责把 kwargs 路由到三段。核心结论：不同任务预处理差异最大，推理与后处理高度一致。文本生成类 pipeline 置 `_pipeline_calls_generate` 为 True，其 `_forward` 走 `model.generate` 的自回归多步推理。本讲引入工厂函数、任务注册表、三段式骨架、`_load_*` 标志、参数路由等术语，供后续分词器（u3）、模型基类（u5）、生成（u8）承接。
