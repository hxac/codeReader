本讲剖析 `vision_process.py` 的视频链路，核心是 `smart_nframes`、三种解码后端与 `fetch_video` 预算。`smart_nframes` 决定时间维采样：按「时长×期望fps」算理想帧数，夹入 [4,768] 后向下取偶（因 FRAME_FACTOR=2 的时间 2× 压缩，帧数须为偶数），`fps` 与 `nframes` 互斥。解码后端有三种：torchvision 全量解码、永远可用作兜底；decord 与 torchcodec 按帧号随机访问、更快；优先级 torchcodec>decord>torchvision，`FORCE_QWENVL_VIDEO_READER` 在 import 时读取且有 lru_cache，切换须换进程，任何失败自动回退 torchvision。`fetch_video` 空间预算：单帧上限 = min(768 token, total_pixels/帧数×2)、下限 min_pixels，`total_pixels` 只压单帧分辨率、不减帧数，用户 `max_pixels` 只能往下调。帧列表输入路径绕过解码器，线程池复用 `fetch_image`，ceil 补偶帧并合成 `video_metadata`（fps、frames_indices、total_num_frames）与实际采样率 `sample_fps`，为下一讲时间戳机制铺垫。视频总 token ≈ 帧数/2 × 单帧 token。
