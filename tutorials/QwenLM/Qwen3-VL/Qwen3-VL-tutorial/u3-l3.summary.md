本讲将 u3-l2 的离线推理升级为常驻在线服务：`vllm serve` 挂载 OpenAI 兼容路由，CLI 参数与 `LLM(...)` 的 Python 引擎参数同名同义（下划线对应连字符）。多模态关键启动参数包括张量并行 `--tensor-parallel-size`、`--mm-encoder-tp-mode data`（视觉编码器按数据切分）、`--enable-expert-parallel`（MoE 模型专属）与 `--media-io-kwargs`（视频 I/O 层，按请求调 fps 的前提）。SGLang 以 `python -m sglang.launch_server` 提供同类 OpenAI 兼容服务，客户端代码与引擎解耦，但按请求控制视频帧采样目前仅 vLLM 支持。请求侧视觉元素类型从 `image`/`video` 改为 `image_url`/`video_url` 嵌套 `{"url": ...}`，媒体的下载、解码、缩放、抽帧全部移交服务端，客户端不再依赖 qwen-vl-utils。核心机制是经 `extra_body` 传入 `mm_processor_kwargs` 按请求覆盖采样率（服务端默认 `fps=2`、`do_sample_frames=True`），与离线三件套字段同名同义；贯穿规则为「谁采样，谁决定 do_sample_frames」：离线客户端采样传 `False`，在线服务端采样默认 `True`。官方 Docker 镜像基于 vLLM 官方 OpenAI 服务镜像构建，`vllm serve` 开箱即用。
