本讲拆解 Qwen3-VL 的 processor 预处理环节，覆盖四个模块：apply_chat_template 的两种模式、size 像素预算、add_vision_id 视觉编号、batch 推理的左填充。核心结论：tokenize=True 一步返回含 pixel_values 与 image_grid_thw 的张量，是 transformers 默认路径；tokenize=False 只渲染字符串、每图仅留一个占位符，须配合 qwen-vl-utils 缩放并显式传 do_resize=False，是 vLLM 路径。存在因果链「size 预算→缩放后尺寸→视觉 token 数→input_ids 长度」：图像 token 数为 H′×W′/32²，视频再除以 2（时间维 2× 压缩）；image_processor.size 约束单图像素、video_processor.size 约束全部帧的像素总和，按目标 token 数反推预算需分别乘 32×32 与 32×32×2，它与元素级 min/max_pixels 是两层各管各路径的旋钮。add_vision_id=True 在每个视觉块前插入普通文本编号，图像 Picture N 与视频 Video N 独立累加、跨轮不断档。batch 推理须成对设置 tokenizer.padding_side='left' 与 padding=True，左填充令真实内容右端对齐，逐样本 out_ids[len(in_ids):] 裁剪依旧成立，且 batch 可混排多模态与纯文本样本。另明确 AutoProcessor 是 tokenizer、image_processor、video_processor 三合一，patch_size 应从 processor 动态读取。
