本讲解读 web_demo_mm.py，把 u1-l3 的推理链路装进 Gradio 网页：_get_args 解析十个命令行参数，默认后端 vllm、默认模型 235B，且 cpu-only/flash-attn2 只作用于 hf 分支，gpu-memory-utilization/tensor-parallel-size 只作用于 vllm 分支；_load_model_processor 借 try/except 容错导入实现 hf/vllm 双后端，依赖清单不含 vllm 与 qwen-vl-utils，故默认后端需补装两包。predict 将 Gradio 会话状态 task_history 重建为模型 messages：文件按扩展名二分 image/video 并转绝对路径，文本收尾一条 user 轮，messages.pop() 弹掉空 assistant 占位，_transform_messages 把简写键规范成带 type 的标准形态。流式输出分真伪：hf 路径用 TextIteratorStreamer 加后台线程逐 token 输出（真流式），vllm 离线 LLM.generate 整批返回（伪流式）。Docker 脚本校验本地权重 config.json 后，以 vllm-openai 镜像挂载权重一键部署。关键术语：双后端、task_history、真/伪流式、张量并行、_prepare_inputs_for_vllm 输入三件套，承接单元二 process_vision_info 与单元三 vLLM 服务化。
