本讲总览 qwen-vl-utils 库并精读 process_vision_info 主流程。该库把 messages 中的视觉元素转成 PIL 图像列表与视频张量，公共 API 仅 5 个函数，服务 vLLM 等需手动传张量的场景（transformers 路径不需要它）。主流程三步：extract_vision_info 宽进收集视觉元素（兼容数据键与 type 两种写法、支持 batch 输入）→ 按数据键严出分发给 fetch_image/fetch_video，缺数据键即抛 ValueError → 组装返回值与 video_kwargs。返回契约由两个开关决定：return_video_kwargs=True 时额外返回 kwargs，恒含 do_sample_frames=False（帧已在库内采样完，processor 不必再采）；return_video_metadata=True 时每个视频变为（张量， metadata）元组且 kwargs 不再含 fps，对应 Qwen2.5-VL 用 fps、Qwen3-VL 用时间戳元数据的版本兼容策略。关键术语：patch 边长由 14 增至 16、2×2 spatial merge、patch_factor=2p 决定输出对齐倍数 28/32、视觉 token 数=H/2p×W/2p。核心结论：Qwen3-VL 必须显式传 image_patch_size=16，传错不报错、只静默算错 token 网格，最佳实践是从 processor.image_processor.patch_size 动态读取。smart_resize 像素预算、视频帧采样与时间戳机制留给后续三讲。
