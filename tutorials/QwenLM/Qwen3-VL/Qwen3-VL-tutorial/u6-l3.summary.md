本讲解读 VideoMME 视频评测目录。数据侧是三件套的变体：标注经 HuggingFace datasets 按时长档（short/medium/long）加载，视频与字幕按文件名约定存放；build_videomme_prompt 把 fps、帧数、像素预算直接写进 messages 的 video 元素，由 qwen-vl-utils 逐元素消费，字幕经时间窗匹配后拼入文本。主脚本用 subparsers 拆成 infer 与 eval 两子命令，以 JSONL（内嵌 annotation 真值）为唯一接口，解耦 GPU 推理与 judge API 判分，可分开重跑；判分沿用「规则抽取 → LLM judge 兜底 → 随机保底」三级瀑布。核心概念是 Instruct/Thinking 双模式：同规格的两个独立 checkpoint，采样差异集中在 temperature、top_p 与 presence_penalty——Instruct 设存在惩罚 1.5 防复读，Thinking 因长推理链需容忍重复而置 0；输出统一剥 </think> 取末段即可兼容两档。prepare_inputs_for_vllm 三字段模式复用于视频：return_video_metadata=True 使视频成（张量，metadata）元组以显式携带时间戳，do_sample_frames=False 声明客户端已采样、防止二次抽帧。复现陷阱：argparse 默认像素预算与官方 shell 脚本不一致，应以脚本为准。
