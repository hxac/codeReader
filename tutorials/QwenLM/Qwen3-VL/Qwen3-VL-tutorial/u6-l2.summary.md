本讲剖析 evaluation/mmmu 目录的四个环节。build_mmmu_prompt 将 TSV 行拼成「先图后文」的 user 消息，hint 缺失与开放题各有容错分支；MIN_PIXELS/MAX_PIXELS 属 28 口径遗产常数，在 Qwen3-VL 的 32 口径下每图约 980~3920 个视觉 token，抬高下限体现「按数据集定预算、宁多花 token 保细节」的技巧；run_inference 先在 CPU 侧全量构建输入，再单次 llm.generate 批量推理并落盘 JSONL，剥 </think> 兼容两档模型，Instruct/Thinking 档以 presence_penalty 1.5 与 0 区分防复读与护推理链；run_evaluation 用 MMMU_preproc 把开放题改造成二选一并统一 GT 为 A，再经「规则抽取→judge 兜底→随机保底」三级瀑布判分，输出总体与按 split 准确率，预测侧与真值侧是分工明确的双 DataFrame。核心结论：裁剪 subject 子集不能改 TSV（MD5 校验会触发重新下载覆盖），应在 JSONL 层过滤后再评测。
