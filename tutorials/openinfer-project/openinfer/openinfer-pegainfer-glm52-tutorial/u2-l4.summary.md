本讲围绕 GLM5.2 启动期显存预算展开，核心是 cap（单请求上下文上限，须 64 对齐，因 KV 以 64 token 为页）与池（rank 全局 KV 页数）在 #818 后解耦这一前提。模块一精确账本 glm52_cap_bytes：把候选 cap 的开销写成纯算术（slab、rope 表、indexer 桶、块表等求和），对块数严格线性、不碰 CUDA 故可单测，一次差分即得每块 slab 单价约 3.5 MB。模块二 cap 推导 derive_max_model_len：显式值须过最小值、checkpoint 上限、64 对齐、预算四道门；自动模式在 64 倍数候选上二分；floor 取 nominal 池，放不下则退 one-request 池。模块三两阶段实测填充：固定构建（build_fixed）后实测 fleet 最小空闲 VRAM（fate-sharing，按最穷 rank 定），除以 slab 单价定块数，手工 pin（GLM52_KV_POOL_BLOCKS）被上下两道栅栏夹住。构建完成后 headroom 再探测要求每 rank 空闲不少于 1 GiB，把账本漂移变成带数字的启动失败而非服务中 OOM。总原则：精确账本与经验 reserve 分开记账，宁可启动失败、不可带病服务。
