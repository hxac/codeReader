本讲从 prefill/decode 两种负载的差异出发，为 kv-offload 建立运行时心智模型。其一，前缀缓存靠内容寻址：KV 按 16-token 块组织，块键为「父块哈希+本块 token」的链式哈希，同一前缀必同键、免协调复用；admission 时 GPU 命中 G 块与 CPU 命中 C 块叠加成锚定 prefix 0 的连续前缀 [0, G+C)，GPU/CPU 交错形态被刻意排除。其二，三层存储分层：scheduler 出策略、本 crate（OffloadEngine）出机制、pegaflow 出 host/SSD/RDMA 运力。其三，v1 时序红线：save 尽力而为、失败仅记日志；load 强排序（第 i 租约块映射第 i 目标块），query 返回 Ready/Loading 两态，但绝不阻塞 admission，一切经 OffloadHandle 逐调度 tick 非阻塞 poll 收账；丢 save 只损命中机会（退化为重算），撕裂或覆写的错数据入键才致命，故立 ORDERING/REUSE 契约。其四，P/D 分离免 handle 协议：同 prompt 推同键，MetaServer（namespace 编入模型几何防交叉命中）寻 owner、RDMA 拉块，P 以 flush 屏障扣住 Finished 充当 KV-ready 信号，故障一律退化为本地 prefill，无 hang 无 crash。
