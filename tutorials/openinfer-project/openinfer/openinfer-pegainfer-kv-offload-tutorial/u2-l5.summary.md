本讲精读 kv-offload 的 handle.rs：OffloadHandle&lt;T&gt; 包装 oneshot 接收端，是 save/query/load 三条链路的统一收账口。poll 非阻塞可反复（&mut self），None 表示在途（常态而非错误），通道关闭被译为 Storage 错误，服务调度器每 tick 清扫；wait 消耗 self 阻塞结账，服务同步线程；settle 为异步预留对偶，暂无树内调用方。核心结论：drop 句柄只是分离观察者——任务、keep_alive 的 pin、失败日志照常执行到 D2H 落地，但 query 句柄提前 drop 会使 lease 滞留至 TTL。可见性跟随逃逸路径：LoadHandle 公开（qwen3 需跨 tick 持有），SaveHandle/QueryHandle 在 crate 内当场结清；QueryOutcome 分终态 Ready(QueryHit)（num_blocks 为 0 即全 miss、无 lease）与非终态 Loading（需同 req_id 重查）。settled/in_flight 两个构造器支撑无 GPU 的句柄行为测试，settled 兼作 engine 空输入快速路径。
