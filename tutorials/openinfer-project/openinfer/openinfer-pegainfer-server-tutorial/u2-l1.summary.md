本讲精读 pegainfer-frontend 的 model_line 模块，确立 server 与模型 crate 之间的接缝。核心结论：server 只持有一列 `&'static dyn ModelLine`，从不 import 模型 crate 的选项类型；接入新线＝实现 trait＋注册一行＋一个 Cargo feature。trait 共 8 个方法：name、probe、launch 必选，augment_cli、consumed_shared_args、arg_requirements、validate、serve_plan 均有默认实现；分工上 probe 做身份认领、validate 做廉价 CLI 规则、launch 才加载引擎。LaunchContext 为后三者提供只读世界（model_path、被认领的同一份 config、shared、合并命令的 matches），各线经 FromArgMatches 以 cli(ctx) 模式取回 crate 私有 CLI，类型知识不越过接缝。launch 返回 anyhow 的 LaunchedEngine（迁移期 legacy Handle／新 Stepped 二选一），调用方只加上下文传播不分支；错误语言是 DetectError（Conflict／NoMatch，server 仅对 NoMatch 附加 feature 重建提示）与 CliError（UnconsumedFlag／Rule），thiserror 模板即 API，测试逐字断言。Qwen3Line 是 8 方法满配参照，EchoLine 是三方法最小实现。
