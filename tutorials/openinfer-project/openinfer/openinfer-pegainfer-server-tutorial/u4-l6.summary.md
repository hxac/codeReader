本讲讲清 `SchedulerMetrics` 从调度器到 `/metrics` 的完整链路，覆盖 `pegainfer-frontend` 的 engine 模块（metrics 定义、wiring/driver/ledger 的发布通道、handle 的 watch 挂载）与 vllm 桥（bridge 与 stepped）的 stats 上报。核心结论：占用字段是 gauge，事件计数必须存累计 counter——读者只能看到最新快照，存每步 delta 会永久丢失，差分由持有连续基线的桥侧 `StatsTracker` 完成，即“传输层带总额、线上带 delta”。关键术语：`PrefixCacheCounters`（不变式：host 与 external_unspecified 命中之和不超过总 hits）、`SpecDecodeCounters`（前缀形接受直方图）、Option 字段即引擎能力声明；两代发布通道——stepped 引擎用共享单元格加空更新“唤醒消息”搭步流便车，legacy 引擎用 watch 通道且兼任 DP 拓扑声明；另有重启检测从零差分、命中拆分为 device 与 connector 两族计数器，以及 `/metrics` 的生命线 `disable_log_stats: false`。
