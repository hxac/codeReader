本讲聚焦 pegainfer-frontend 的 model_line.rs：ModelLineRegistry 与其查账员 RegistryClaims。因 clap 的 schema 断言在 release 构建中被禁用，注册表用「id 账＋拼写账」两本账（键映射到 ArgOwner：Shared 或某条线）在构造期以 panic 查出全部 flag 冲突；new 的流水线是共享 flag 先入账、核对 CORE_ARGS、逐线登记（线名唯一、consumed_shared_args 须指向真实共享 id）、依赖表收齐后统一校验，probe command 只承载单线独占 flag 供入账。detect 裁决配置归属：恰好一线认领，双认领即 DetectError::Conflict（注册表缺陷，立即返回），无人认领则 NoMatch 并逐线拼 rejections。validate_provided 执行 consume-or-reject：每个显式 flag（按 provided_args 的出身语义）须属核心、被消费共享或线独占之一，否则 CliError::UnconsumedFlag，错误文本即 API。parse_for_line 是单线注册表测试帮手，别线独占 flag 在其中报 unexpected argument 而非 UnconsumedFlag。分工原则：构造期 panic 管代码错，运行期 Err 管命令错。
