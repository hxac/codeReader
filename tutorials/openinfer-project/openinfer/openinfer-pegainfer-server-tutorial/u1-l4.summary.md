本讲拆解 server 启动流程中的「检测门」：在引擎加载之前裁决 config.json 归属哪条编译进来的模型线。registry.detect 有三种结果：唯一认领放行；Conflict（两条线抢同一配置）立即报错并点名双方，属注册表 bug；NoMatch 则收集每条编译线的拒绝原因后整体报错。各线的 probe 只做身份检查（model_type 与 architectures），契约是「恰好一条线认领」，尺寸校验留给后续阶段。因被编译掉的线连 probe 都不在二进制里，server 只能硬编码 families() 身份表，即「必要的第二真相源」，其 compiled 字段由 cfg! 编译期求值。feature_gate_hint 仅在 NoMatch 时被接线，查顶层与 text_config 中的 model_type 两个键，命中未编译家族即把 --features 重建建议拼在错误之后，且提示是 identity-only，不承诺 checkpoint 可服务。集成测试 detect_gate.rs 用冻结真 config 与最小 tokenizer 驱动真实二进制，互斥 cfg 的两个用例分别锁住 stock 构建的提示路径与 enabled 构建的「认领后 launch 诚实拒绝」路径，全程不触达 CUDA。
