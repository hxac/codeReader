本讲精读 pegainfer-frontend 的 driver.rs，模块仅此一处轮询循环。核心结论：`Scheduler` trait 把模型线的全部运行时义务压缩为三方法——`submit` 只做所有权转移（裁决延迟到 step 零代价）、`step` 是唯一裁决点与唯一记账点、`metrics` 为只读快照；超出三方法的能力（如 LoRA 控制）由调度器自建通道、在自己的 step 里排空。`drive` 循环把八条模型线的循环纪律固化为代码：每迭代排空提交（先 register 开户再 submit）、step、发布 metrics、commit_step 恰好一次，保证一步至多一条 StepOutputs；metrics 变化用空更新的「唤醒消息」信号。致命路径 fail_all 以错误原文写销全部在途请求；优雅退出要求通道断开且账本排空，空转 spin_loop 绝不睡眠。spawn_scheduler 经 scheduler_pair 铸 SchedulerHandle/SchedulerBackend 双端并起命名线程，交回 LiveScheduler。关键术语（三方法、drive 四拍、commit_step/fail_all、唤醒消息、排空退出）为下一讲 scheduler_pair 接线与多分区路由铺垫。
