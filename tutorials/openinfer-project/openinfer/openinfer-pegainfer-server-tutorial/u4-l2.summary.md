本讲精读 vllm 装配骨架的后半段，最小模块有三块。一是 `vllm_server::Config` 逐项装配：字段分骨架事实（预绑定 fd、engine_count）、CLI 选择（仅 model、served_model_name、port、tool_call_parser 四条传导链）、带注释固定常量三类；`disable_log_stats=false` 是 `/metrics` 可观测链的生命线，`stream_interval=1` 即逐 token SSE 下发。二是 `load_model_backends` 为 chat 请求整形层加载模板与分词器，失败仅告警降级、服务照常，模型真坏由 server 自行再加载并报自己的错。三是路由扩展链三层洋葱：最外 `normalize_chat_requests` 做 effort 别名改写（激活与否由模板渲染 verdict 作证），内层 `mark_history` 用 Boundary 测量会话边界并写入 `vllm_xargs`（测量放 spawn_blocking），最里 `extend_router` 有恒等、prefill 门、LoRA 合并三形态；effort 必须最外，让边界测量读到路由真正渲染用的值。中间件只拦 chat 路由，body 缓冲有上限且改写后须重修 Content-Length。echo-server 为无 GPU 活体标本：completion 文本即 prompt 的 token 级回声。
