本讲覆盖 extend_router 的两种特殊形态，选择权在 ServePlan。其一是 prefill-only 校验门：P/D 分离的 prefill 角色实例在 axum 层校验生成请求的 max_tokens/max_completion_tokens 恰为 1（completions 只认前者，chat 同给须相等），不合格者在触达引擎前得 400 与 invalid_request_error 信封，合格者重写 Content-Length 后 oneshot 透传，非生成路径经 fallback_service 放行。其二是 LoRA 服务面，核心概念「Option 即能力」：Engine::lora 缺席 LoraClient 则 LoRA 路由根本不挂载，故错误枚举无 Unsupported；命令走 crossbeam、应答走 tokio oneshot，两端失败均折叠为 EngineGone，调度器在 step 顶部排空命令、批空闲时应用。LoRA 路由分管理（装卸适配器）与 OpenAI 代理两组：后者把 model 点名的适配器改回基座名并注入 vllm_xargs 侧信道，桥侧提取为 Request::lora_adapter 交给调度器。--enable-lora 分支因路由闭包需捕获引擎控制平面，必须串行等待加载且只认 LaunchedEngine::Stepped。
