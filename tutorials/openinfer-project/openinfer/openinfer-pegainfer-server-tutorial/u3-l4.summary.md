本讲精读 pegainfer-frontend 的 RequestLedger：它为每个未答复请求开「账户」，账户不存负载（submit 时已所有权转移给调度器），只记引擎欠客户端的事实——abort 标志引用、prompt 长度、排队时间与 token 流水。生命周期单向：register 开户（Queued）→ admit 转 Active → 流式记账 → finish/fail/reject/retire/defer_finish 五种关户，账本 Drop 再把残留账户销账为 Failed，与信封、DeferredFinish 的 drop 炸弹合成「应答到底」三层保护。核心结论「terminal 恰一次」由所有权移除强制：关户即从 HashMap 移走账户，触碰已关或未知账户在出错调用点 panic 且 release 构建仍生效；终态计数只出自账本流水，模型侧算术插不进来。register/commit_step/fail_all 为 pub(crate)，节奏归 driver；StepStatement 把同一步的多次记账合并为每请求至多一条更新。
