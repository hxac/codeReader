本讲以 Cargo.toml 与 main.rs 为源码落点，讲清同一份 main.rs 如何编出支持不同模型线的二进制。模块一：feature 矩阵——default 仅含 qwen3，各模型线经 optional 依赖按需拉入，gemma4、qwen35 等还要向 crate 内部同名 feature 转发以点亮内核面（qwen35 构建期需 Python+Triton）；main.rs 的 model_lines() 用 #[cfg] 守卫镜像 feature 表，未启用的线整体不参与编译，运行时 detect 也无法认领。模块二：二进制身份——包名 pegainfer-server、产物名 pegainfer 由 [[bin]] 决定，--version 输出来自 clap 字面量加编译期宏 CARGO_PKG_VERSION，根 workspace 的 default-members 使根目录 cargo run 直接可用。模块三：GPU 构建必须 --release——debug 档无优化且开调试断言，主机调度循环会拖垮 GPU 流水线；nvcc 侧优化不受 cargo profile 控制。模块四：非 msvc 平台经两处成对的 cfg 门（target 依赖与 #[global_allocator] static）换用 jemalloc 全局分配器。验证工具：cargo tree -e features 与 cargo metadata。
