本讲精读 step 契约的线类型，覆盖 step.rs 与 stop.rs 两个模块。核心结论是「顺序即结构」：一个调度器步产出一条 StepOutputs，每个被触碰请求至多一条扁平 RequestUpdate；旧 TokenEvent 协议靠文档约定的「先调度、终态恰一次」时序被编码成字段的物理排列，终态之后再出 token 在类型上不可表达，跨步保证由账本承接（触碰已关账户即 panic）。关键术语：RequestId 是进程内路由的整数 newtype，由提交点铸造，外部字符串 id 留在协议栈；Request 是纯负载，history_tokens 与 history_marks（新者在前）是多轮会话前缀快照的恢复点坐标；Terminal 三态（完结/拒绝/失败）且拒绝原因类型化；StopPolicy 归一化停止集合、以 EOS 优先判定，StopCause 随终态上行且触发 token 保留。消费侧按「接纳事实→新 token→终态」的字段顺序折叠。
