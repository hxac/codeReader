本讲义拆解 PegaInfer server 跨模型线共享的参数面（pegainfer-frontend 的 model_line.rs）。提出三层 flag 体系：核心 flag（CORE_ARGS，4 个，server 自消费、全线放行）、共享 flag（SharedArgs 其余 16 个，定义一次、消费权由各线 consumed_shared_args 声明）、线独占 flag（经 augment_cli 挂上）——「定义」与「使用权」分离是其核心设计。关键结论是一条共享 flag 要过四道门：值门（value_parser）与依赖门（requires_all，源自 SHARED_ARG_REQUIREMENTS 与各线 arg_requirements）在解析期由 clap 执行、尚未读 config.json；归属门（validate_provided 的 consume-or-reject）与语义门（SharedArgs::validate 加线内 validate）在模型检测后、引擎加载之前。两层规则分工判据：存在性依赖进依赖表，值/模式敏感规则手写进 validate。provided_args 借 clap 的 ValueSource 区分「用户显式提供」与「默认值填充」，该集合是各层校验的共同入参——值相同出身可不同，故只能按出身过滤而非比较值。u2-l3（注册表自检）与 u2-l4（Qwen3 校验矩阵）承接本讲。
