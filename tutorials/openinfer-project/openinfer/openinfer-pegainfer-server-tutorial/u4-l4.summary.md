本讲精读前端两层请求整形中间层：mark_history 与 normalize_chat_requests。前者在 chat 路由前测量会话边界：只渲染最后一条消息，带与不带 generation prompt 各分词一次，尾长 T＝带版长度减两序列的最长公共前缀（LCP），跨界 token 计入 T；结果经 vllm_xargs 侧信道过境，由桥按整条 prompt 长度置 history_tokens＝L−T，落入 step 契约。同层还测 history_marks，即更早轮次（后跟 assistant 消息处）各自的 history_tokens，新者在先、至多 8 个、须严格小于本轮值，供保留多快照的调度器（pooled tier）从更早边界恢复。后者在最外层把模板不认的 reasoning_effort 改写为最近别名（如 high→xhigh），是否启用由启动期模板渲染探测裁决，output_gate_type 仅是探测闸门，逐请求模板覆盖不改写；effort 在外、history 在内，T 才量在路由真实渲染的值下。两层读不懂即原样放行；不产 generation prompt 时 T＝0，整个 prompt 都是 history。
