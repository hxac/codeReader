本讲精读 wiring.rs、handle.rs 与 kv.rs，讲清引擎契约的接线与路由。核心结论：scheduler_pair「铸造而非组装」双端——提交走 crossbeam（同步消费者在调度器线程）、步流走 tokio mpsc（异步消费者在协议栈）、metrics 用 Arc<Mutex> 共享单元只存最新值并以步流空消息唤醒；submit 永不失败，调度器死后由信封 drop 炸弹以 Failed terminal 作答。Engine/EngineInfo 是协议栈溶解的交接包，kv_capacity 与 servable_len 的 None 各有显式语义（跳过 batch-fit 检查／不钳制最大长度）；LaunchedEngine 是迁移期 Handle/Stepped 二选一枚举。legacy EngineHandle 的路由决策树：已解析 KvPrefix 的 rank 压倒调用方绑定（hold 把块钉在该 rank 上，不一致即调用方 bug），否则取 running+4×waiting 最低分分区（并列取小下标），越界 rank 以 Scheduled→Rejected 事件应答并返回 Ok。关键术语：信封 drop 炸弹、take_steps 只发一次、metrics watches 兼任 DP 拓扑声明、路由范围（submit_txs 数）与拓扑声明（watches 数）两个真相。
