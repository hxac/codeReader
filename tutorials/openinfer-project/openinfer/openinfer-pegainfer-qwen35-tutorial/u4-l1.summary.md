本讲沿 `prefill.rs` 的 `prefill_last_hidden` 讲透 Qwen3.5 prefill 主链路，涉及 `prefill_buffers.rs` 的 GDR scratch 与 `unified_forward.rs` 的三个调用入口。核心结论：`PREFILL_CHUNK_LEN` 与 `SCRATCH_ESTIMATE_SEQ` 相等（20000），构成「启动期预留恰好覆盖一个最大 chunk」的显存契约——scratch 在 KV 池之前扣留，且不是准入上限；执行纪律是「先验证后变更」：对整条 prompt 一次性校验位置溢出、`max_position_embeddings` 与 RoPE 覆盖，全部通过后才动状态。分块循环每步用累计 KV 视图配增量 query 计划，base_pos 取 `recurrent.seq_len`，前缀缓存与多轮对话位置自动接续；全注意力层把本块 K/V 融合落池，线性层原地推进 GDN 状态。scratch 各缓冲只随 pass 长度线性伸缩，逐块新建、块毕即释。末块提取最后位置 hidden 拼批共享一次 norm + lm_head；批 prefill 是请求级与 chunk 级两级串行。关键术语：pass、chunk、base_pos、页（page_size=16）、`GdrChunkwiseScratch35`、先验证后变更。
