本讲拆解 pegainfer-qwen35 的构建体系：feature 门控、Triton AOT 工具链与测试入口。核心结论：qwen35 是跨 crate 联动开关——模型 crate 将 feature 转发给 kernels（空 feature，仅作编译期信号），驱动 build.rs 编译该线手写 CUDA 并执行 Triton AOT，模型代码与内核产物同进同退；feature 关闭时整个 crate 编译为空，默认构建不含 Python（CUDA 工具链仍必需）。AOT 链在构建期探测解释器、选定 SM 目标，为七个 GDR 分块预填充内核生成 cubin 与 C 包装，修补多设备句柄后编成静态库，经三级 FFI 重导出由 recurrent.rs 启动。集成测试与基准以 required-features 门控；model_fixture 夹具依模型路径环境变量校验权重，无效即 SKIP 安静通过。关键术语：feature 转发、空 feature、build.rs、AOT/JIT、SM 架构代号、required-features。
