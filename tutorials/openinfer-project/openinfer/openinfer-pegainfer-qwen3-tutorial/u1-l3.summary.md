本讲剖析 Qwen3 如何挂进服务器 CLI。核心概念是 ModelLine trait（「模型线」＝一个模型家族的全部服务侧知识），以 8 个 hook 构成模型 crate 与纯派发服务器之间的唯一接缝，hook 按服务器启动时序依次调用。三个最小模块：Qwen3Cli（13 个专属 flag，含本讲新增的 EAGLE-3 草稿模型路径）、Qwen3Line::validate（15 条跨标志互斥规则）、Qwen3Line::launch（把 CLI 值与共享 flag 纯翻译成 Qwen3LaunchOptions，交给 crate::launch）。关键机制：consume-or-reject——共享 flag 按线认领，未认领而显式提供即拒绝；arg_requirements——按使用触发的声明式依赖，可级联；两者都以 provided（显式提供）为语义基准，默认值永不触发。互斥规则的根源是 LoRA、批不变、草稿器、decode-overlap、TP 各自独占 GPU 的同段资源；validate 的块序即报错优先级；DFlash 与 EAGLE-3 草稿器（分别走共享与专属 flag）在 crate::launch 被折叠为二选一的 Option\<DraftModel\>。核心结论：同一不变量多层设防，失败越早越便宜；启动策略归模型 crate，不泄漏进服务器。
