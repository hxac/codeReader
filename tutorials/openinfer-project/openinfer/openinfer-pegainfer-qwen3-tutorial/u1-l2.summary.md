本讲梳理 pegainfer-qwen3 的测试地图，覆盖四个最小模块：一、`--lib` 单测——`#[cfg(test)]` 模块测纯 CPU 逻辑（配置、调度装箱等），无 GPU 即可跑；空 feature `test-fixtures` 经 dev-dependency 自引用，只向测试编译暴露夹具。二、clean skip 模式——`model_path_or_skip()` 读 `PEGAINFER_TEST_MODEL_PATH`，否则探测默认模型路径，缺权重时打印说明并跳过而非失败，优于 `#[ignore]`。三、hf_golden_gate 数值门——以 HuggingFace 为真值，teacher-forcing 逐位置对比 logprobs；它绕过调度器与 frontend，直接用 `runtime` 再导出的 `Qwen3Executor` 和 plan/result 类型，所有 pass 串在一个 `#[test]` 里独占显存。四、`tests/common/harness.rs`——泵线程把 step 批量更新按请求 id 解复用进 Inbox+Condvar 队列，还原 submit/recv/expect_finished 的每请求阻塞流。核心结论：测试分层让无 GPU 的贡献者也能跑通绝大多数回归。承接概念：cfg(test) 与 feature 的边界、teacher-forcing、bf16 的 ULP 漂移（容差设计后续专讲）。
