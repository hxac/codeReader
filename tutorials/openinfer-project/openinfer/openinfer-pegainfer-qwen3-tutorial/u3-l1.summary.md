本讲剖析 Qwen3 crate 的 executor.rs，即真正执行一步前向的层次。核心结论：调度器与执行器之间只以三组纯数据 plan→result（prefill/decode/unified）交换信息——plan 借用 StepItem 切片，result 拥有新算出的 token 与 logprob；unified 把 prefill 行与 decode 行拼进同一次前向与 GEMM。ModelExecutor trait 是调度器对执行器的全部认知，也是与模型本地 benchmark 共用的相位边界；调度器按它泛型化，可用 FakeExecutor 做 CPU 单测。RequestId 端到端不变量：submit 时铸造，原样贯穿所有队列、effect 与 KV 键，无第二 id 空间。引入的关键概念：StepItem 是双向信封，executor 回填 cached_tokens 等三态字段；draft_context_captured_requests 是投机解码唯一的批级 result 字段，折入 draft_ready_requests 集合，普通 decode 步将其作废；ConnectorLookupCounters 以咨询标记加恰好一次结算记录外部 KV 查找账；max_draft_batch 是草稿器能力位，DFlash 不限、EAGLE-3 仅单请求，调度批宽门据此把宽批退回纯解码，输出无损。
