本讲剖析投机解码的方法无关核心（`speculative.rs` 与 `executor/spec.rs`），把它建模为 decode 循环上的乐观并发事务：草稿器先提出 K 个草稿 token，目标模型一次前向验证 K+1 个位置，接受规则取最长匹配前缀并附加一个修正或奖励 token（每轮恒提交 1..=K+1 个），随后按 KV 事务提交接受前缀或整体回滚预留（预留全有或全无，提交中途失败只回滚未提交者）。关键术语：VerifyStepItem、DraftStepItem、committed token、gated 标志、truncate_after_terminal 终末截断、schedule/apply/revert 事务原语。草稿与验证之间是纯 token 跨界，proposer 隐藏态不越线；贪心与采样请求共用同一接受规则且无损——草稿 rollout 恒为 argmax，committed token 均出自目标分布。DraftModel 枚举按 checkpoint 在 DFlash 与 EAGLE-3 间二选一：两者共享目标隐藏态捕获、draft_ready_requests ready 集与 KV 事务，仅 worker 车道不同；装载草稿器强制关闭前缀缓存，DraftMeta.max_draft_batch 向调度门透出批宽能力。
