本讲覆盖 pegainfer-kernels 的 csrc/shared，主题是 CUDA 侧 FFI 入口的工程约定与异常防护。核心概念「入口样板四件套」：检查、guard、launch、错误返回。因 FlashInfer host 侧 dispatch 会 throw，而 C++ 异常穿越 extern "C" 边界会让进程无消息 abort，故每个入口须用 guard 宏包体，把异常转成 -1 哨兵返回值加 last_error 消息。关键术语：map_cuda_error 把 runtime 的 cudaError_t 统一映射为 driver 的 CUresult；PEGAINFER_CUBLAS_STATUS_BASE=100000 基址偏移让一个 i32 同时承载 driver、runtime、cuBLAS、异常哨兵四种来源；last_error 为 thread_local，进入 guard 即清空、异常时写入，Rust 侧拿到指针须立即拷贝。检查分工：形状检查前置到 Rust wrapper 的 ensure!，依赖设备数据的检查下沉 kernel 用 __trap() 兜底。综合实践为半成品 dflash2 入口补齐 guard。本讲承接 u2-l3 的 Rust 侧错误契约，是 u4-l2 端到端新增算子的直接前置。
