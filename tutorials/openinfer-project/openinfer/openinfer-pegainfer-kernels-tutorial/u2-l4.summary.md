本讲精读 `forward_pass.rs` 的 `typed_pipeline!` 宏：它把前向链里「拿引用→调 typed_ops→`?` 传播」的重复样板折叠成一行声明，是纯语法糖——不实现新算子，每条语句恰好展开为一个 typed_ops 调用（或 zeros 分配、mem::swap、逃逸表达式），等价性可用 cargo expand 验证。宏分两阶段：header 归一化（声明 ctx/eps/seq_len/gemm 模式，共四种形态）+ `@steps` 递归消化语句（tt muncher）。语句目录：tensor 管分配；gemm 可用 `[mode]` 逐条覆盖 header 的 prefill/graphsafe 两档；rms_norm/add/dtype 转换管逐元素；swap 零分配复用缓冲；try/call 为逃逸口（`?` 传播 vs 普通调用）。分配被编译期门禁锁在 `gemm = prefill` 且带 seq_len 的 header 下，落点是「解码/graph 回放零分配」的引擎纪律。关键术语：header、tt muncher、逃逸口、graphsafe/prefill；真实调用在各模型 crate（kimi-k2 线），graphsafe 的下游原因由 CUDA Graph 安全一讲承接。
