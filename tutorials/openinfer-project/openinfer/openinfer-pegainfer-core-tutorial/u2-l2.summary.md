本讲精读 pegainfer-core/src/ffi.rs：与 tensor.rs 孪生的一行再出口门面，真身是 pegainfer-kernels 的 ffi 聚合器与 build.rs。核心结论：FFI 边界收敛于 core（门面）与 kernels（实现）两个 crate——`unsafe extern "C"` 的 CUDA 符号声明只维护在 kernels 一处（单一事实源、防签名漂移），模型 crate 从不自行声明。关键概念：FFI 与 ABI 约定（`Half = u16`、CUstream、CUresult）、再出口门面、feature 门控的 ffi 子模块、静态链接路线（build.rs 用 nvcc 编 csrc 为 .o，ar 归档 libkernels_cuda.a）与「声明→编译→加载→调用」四步闭环。错误契约：C++ 异常绝不穿越边界，失败以 -1 哨兵返回，文本经 pegainfer_kernels_last_error() 取回。门面服务模型 crate 而非 core 自身，上承 u2-l1 tensor 门面，为 u2-l3 ops 封装奠基。
