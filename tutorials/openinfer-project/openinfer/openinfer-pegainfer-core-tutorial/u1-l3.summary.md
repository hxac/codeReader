本讲围绕 pegainfer-core 讲「把 crate 跑起来」的三件事。依赖图：22 个运行时依赖全部以 workspace = true 引用，唯一路径依赖是 pegainfer-kernels，因此构建 core 隐含先跑 kernels 的 nvcc；tempfile 是唯一 dev-dependency，仅 feature kernel-call-trace，错误处理统一 anyhow（并无 thiserror）。内嵌单测：43 个 #[test] 分布在 12 个文件的 #[cfg(test)] mod tests 里，测试专用方法（如 KvState::reset）按函数级 cfg(test) 裁剪。GPU 边界的判据是「构造了什么」：KvLayout 是纯值类型，stride 几何测试免 GPU；KvPool/KvState 持 CudaSlice<bf16>，必须建 DeviceContext。核心结论：crate 里没有任何 #[ignore]，GPU 隔离靠三层——命令分层（--lib 快车道 vs 按名跑 GPU 测试）、--lib 不编译 tests/ 目录、运行时 expect 显式红灯；PEGAINFER_TEST_MODEL_PATH 属于模型 crate 的测试，core 自己只读 PEGAINFER_TRACE_OTLP_ENDPOINT。
