本讲从消费者 pegainfer-qwen3 的视角回看 pegainfer-core：用一条 grep 枚举 pegainfer_core:: 引用，得出"消费清单"，实测 154 处引用、13 个模块中 9 个被消费，tensor+ops+weight_loader 占近八成。再以"四幕落点表"（装配、调度、前向、图回放）定位消费点：core 模块全部落在 executor 层，scheduler 对 engine 契约零引用，插接由 frontend_adapter/model_line 完成。本讲引入两个关键概念：KV 双轨——qwen3 只借 core 的 KvLayout 几何、真池在 pegainfer-kv-cache，gemma4 则直接消费 core 的 KvPool；池无关契约——core 注意力封装只收张量切片、KvLayout 与 PrefillPagedPlan，不绑池实现，KvLayout::kernel_layout() 是通往 kernels 的官方转换器。扩展结论：新增 dense 模型时 core 八个模块原样复用、kv_pool 二选一、宿主服务按需，模型差异留在模型 crate 与 kernels（参照 DFlash2 未改 core 的先例）。
