本讲覆盖 `cuda_graph.rs` 及其 `dump`/`render` 子模块，与 `kv_pool.rs` 的 padding 页。核心结论：decode 热路径经流捕获录成 CUDA Graph，由 `CudaGraphState` 状态机「空态→捕获→实例化→首启→纯回放」管理，捕获失败走排水路径，防止流滞留捕获态。回放原样重发录制时刻烘焙的参数，因此闭包须是纯 GPU kernel 序列（禁 CPU-GPU 同步、禁分配），一切变化只走「内容动、地址不动」通道：预分配 buffer、单块 KV 大缓冲、i32 页表原地重填。decode 按批大小分桶录图，空槽填 padding 行；padding 页在池构造期一次性预留、页号恒定、内容无害，与两段式准入共同保证图录制时见过的页号在图生命周期内永远合法。dump 子模块把已捕获图导出为全保真 detailed DOT 与折叠重复层块的人读 PNG，入口带四道前置检查。关键术语：流捕获、指针稳定性、桶（bucket）、padding 行/页、`padding_page_id`、`CudaGraphPhase`、`DecodeGraphUse`。
