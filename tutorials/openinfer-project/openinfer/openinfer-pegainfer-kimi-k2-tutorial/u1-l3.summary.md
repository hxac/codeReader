本讲绘制 kimi-k2 crate 的模块地图：全部源文件自 lib.rs 的 mod 声明长出，分三块——config（模型几何，无门、永远编译）、weights 子树（把 checkpoint 装载为显存权重）、runner 子树（bringup 启动、scheduler 调度、executor/worker 执行前向），外围是 trace 工具与测试。仓库统一扁平模块布局：foo.rs 与同名目录并存、不用 mod.rs，模块根兼任子树共享头文件，子模块以 use super::* 继承父命名空间。feature 门集中在 lib.rs 根部：默认构建只有 config 和报错的 start_engine 桩；kimi-k2 门住运行时本体并传导 CUDA 编译到 pegainfer-kernels；kernel-report 是叠加 kernel-call-trace 的观测超集；bin/test 另由 required-features 把门；可见性从 pub 到 pub(super) 四级收窄公开面。最后确立历史快照文档的读法：先看 Last touched 再对源码交叉验证，如 worker 五件拆分仍准确、layers 子树已消失。
