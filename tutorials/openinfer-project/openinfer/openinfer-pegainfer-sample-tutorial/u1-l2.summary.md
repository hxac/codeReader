本讲回答「pegainfer-sample 怎么验证」，覆盖 Cargo.toml（本 crate 与 workspace 根）、src/lib.rs 内嵌测试模块、tests/select_batch.rs、tests/gpu_logprobs.rs 与 benches/select_batch.rs。核心结论：验证面分三类——3 个纯 CPU 单元测试（只测主机参考实现 token_logprob_from_row，运行无需 GPU）、16 个 GPU 集成测试（9 个路由与门行为测试，加 7 个设备-主机 A/B logprob 互证测试）、criterion 微基准外加 1 个被 #[ignore] 的延迟探针；判定某测试是否需要 GPU，方法是读源码看它是否构造 DeviceContext。关键术语：--release 纪律、default-members 须用 -p 点名、workspace lints 约束测试代码、GPU 门、模型无关测试（合成 arena，不加载权重）、双实现互证（容差 5e-5）、greedy/sampling/mixed 三档基准语义（批式 argmax 成本下限、采样通道全额成本、混合共批的服务常态）、探针用 -- --ignored --nocapture 手动运行。分工哲学：裸核正确性归 pegainfer-kernels，本 crate 只测策略层；top_p ≤ 1/vocab 必走 argmax 的数学论证留给 u2-l1。
