本讲解读 `pegainfer-kv-cache` 的 `BlockPool`（src/pool.rs）：它是上游 kvbm-logical `BlockManager` 之上的薄包装——通用块逻辑（空闲/活跃/LRU 非活跃池、分配注册）在上游，引擎语义（padding 预留、容量口径）在包装层；自身不持有显存，只发放块 ID，物理页由模型侧消费者按 ID 索引。核心结论：构造链路 `build` 先校验至少 2 块，以 Allow 复制策略与 LRU 后端建管理器，再经「allocate → stage(默认哈希满块) → register + std::mem::forget」把块 0 永久预留为 padding 块——CUDA Graph 页表已固化哑页号，该块与引擎同寿、绝不回收，否则图回放会污染真实请求的 KV。容量不变式：available 与 max_request_blocks 均为 total − 1，block_size 是每块 token 数，padding_block_id 以 i32 直填页表；释放的注册块进 LRU 非活跃池，是前缀缓存伏笔。请求拿块/还块的生命周期由下一讲 RequestKv 承接。
