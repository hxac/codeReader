本讲覆盖 pegainfer-kv-cache 的 KV 事件流机制，其为多 worker 缓存感知路由预留：路由器带外订阅各引擎的块事件流并镜像前缀树。关键术语与结论：构造链为 KvCacheManager::new_with_events（唯一公共入口）→ crate 内 BlockPool::with_events → 上游 EventsManager 的 tokio broadcast，容量常量 KV_EVENT_CHANNEL_CAPACITY 为 65_536、建池前先订阅裸 Receiver；事件 KvCacheEvent（Create/Remove）仅携带 128 位 lineage 哈希，Remove 由 EventReleaseHandle 的 RAII Drop 发出。核心风险模型是「丢事件即永久失步」——Lagged 无补发、前缀树无对账协议，防线为容量宽裕、每步排水、默认关闭三件套。消费契约三件事：忽略 Create；封块点用 emitted_blocks 光标与 take_newly_registered_blocks 自产 RegisteredBlock（u128 plh 与 u64 路由哈希族两套体系并存）；Remove 经 plh→sequence_hash 反查摘树。事件流与 KV offload 互斥，当前尚无 in-tree 消费者。
