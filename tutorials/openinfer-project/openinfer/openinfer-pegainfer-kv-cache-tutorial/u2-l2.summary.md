本讲沿 `RequestKv` 讲清一个请求的 KV 生命周期：预填→解码循环→释放。`RequestKv` 是上游 `SchedulableSequence` 的薄包装，协议在本 crate、机制在 kvbm-logical。每个 forward 步骤固定三拍：schedule 预约块（按步渐进，失败不持资源）→ view 给内核精确页表 → apply 封块并推进 `kv_position`。关键概念：悬空 token（刚采样、KV 未算，故 decode 视图 seq_len 恒为 kv_position+1）；两阶段分离带来失败恢复（`revert_schedule` 撤销一步、drop 守卫归还预约块）；页表行须精确覆盖 seq_len，`step_page_indices` 专门裁掉积极分配多出的块；`apply_decode` 返回 `DecodeOutcome` 四变体；投机解码只提交被接受前缀、LIFO 回收拒绝块；`release` 后注册块进非活跃池供前缀缓存复用。查询族中 `resident_blocks` 含积极分配与未提交块，准入估算必须用它。
