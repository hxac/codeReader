本讲围绕 pegainfer-kv-cache 的三个最小模块展开：layout.rs 的纯值类型 KvLayout、buffer.rs 的物理缓冲 KvBuffer、pool.rs 的逻辑块池 BlockPool，并以 qwen3 消费侧的显存预算代码交叉验证。核心结论：KV 缓存按固定大小、可散布的页管理，既消除外部碎片，又带来前缀块共享、CUDA Graph 指针稳定、整页一次连续拷贝三项引擎级能力；BlockPool 只发放块 ID 不持显存，KvBuffer 一次性分配全部显存且地址永不移动，二者靠页号（块 ID）关联。关键术语是三个步长的纯乘法链，由 num_layers、num_kv_heads（GQA 下缓存只按 KV 头数计）、head_dim、page_size 推出：kv_block_len 是单个 K 或 V 块的元素数，layer_stride 是页内跨一层（K 前 V 后），page_stride 是所有层合成的一整页。排布取页优先：页内按层嵌套、层内 K|V，一页恰为一段连续 page_stride 区间，与池以块为管理粒度对齐。字节换算仅差 ×2（bf16）；页尺寸不是自由参数，须取注意力内核合法值（qwen3 限 16/64）；池预留块 0 作 CUDA Graph 的 padding 槽，实际可用块数为总块数减一。
