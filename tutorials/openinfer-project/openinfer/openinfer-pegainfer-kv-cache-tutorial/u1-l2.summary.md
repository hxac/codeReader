本讲从工程侧解剖 pegainfer-kv-cache：五个私有模块正交分工——layout 是纯几何值类型、buffer 持有 bf16 显存但无分配器（指针稳定保障 CUDA Graph 捕获）、pool 为逻辑块池与请求生命周期的绝对核心（约占 src 七成）、manager 把同几何的池与缓冲配成引擎级门面、view 打包内核只读视图；公共 API 共 11 个自有类型，并再导出 kvbm_logical 与 KvCacheEvent 以保证类型同一。Cargo.toml 仅 17 行，7 个依赖全部经 workspace 继承单一版本：cudarc 封装 CUDA 驱动、kvbm-logical 为本地 fork 的块管理器地基、dynamo-kv-hashing 钉 rev 做 LoRA 加盐哈希、half 提供 bf16、tokio 只用 broadcast 事件通道。测试分两层：restore_commit 纯逻辑、无 GPU 也能跑，兼作 #704 注册成本回归锚；lifecycle 需真实 CUDA 设备。约定：命令一律 --release，用 -p 限定作用域。
