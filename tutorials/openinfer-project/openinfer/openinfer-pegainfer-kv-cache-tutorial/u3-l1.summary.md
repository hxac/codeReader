本讲覆盖 pegainfer-kv-cache 的 pool.rs 恢复链路及其与兄弟 crate pegainfer-kv-offload 的分工边界。核心结论：前缀块被 LRU 逐出 GPU 后仍可从 CPU 层恢复——probe_prefix 探测并以强引用钉住 GPU 命中块，三个口径为 cacheable=⌊(n−1)/b⌋（末 token 规则）、gpu_hit、cpu_query_window=cacheable−gpu_hit，CPU 加载量绝不能超过 cacheable；reserve_loaded_blocks 预约目的地页并产出不透明的 LoadReservation（块压力下返回 None，调用方放弃预取从头 prefill）；物理层异步 load 落字节后，commit_loaded_blocks 以 continuation 哈希 seq_hashes[gpu_hit+i] 补登记，偏移差一个 gpu_hit 链条即断。关键术语：PrefixProbe、LoadReservation、16 字节内容键（sequence_hash_bytes 把 128 位 lineage 哈希大端纯编码、单一翻译点，是两 crate 间唯一契约）、OffloadEngine 与 query/load 间的租约机制。设计不变式：保存尽力而为、恢复永远是优化，装载失败就整段重算；tests/restore_commit.rs 兼作 #704 性能回归锚（1024 块提交 36.4ms→1.67ms，修复落在 kvbm 注册表）。
