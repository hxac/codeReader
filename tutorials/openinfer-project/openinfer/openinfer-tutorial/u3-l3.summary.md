本讲覆盖 pegainfer-frontend 的 vllm 模块四件套：mod.rs 总装入口、bridge.rs 旧桥、stepped.rs 新桥、wire.rs 参数翻译。核心结论：PegaInfer 不自建 HTTP 层，以 git 依赖复用外部 vllm-server crate（路由、分词器、chat 模板、SSE），并在同进程内用 ZeroMQ IPC「冒充」vLLM EngineCore 进程——DEALER socket 收请求、PUSH 发输出、MessagePack 编码，帧分 Add/Abort/Utility 三类，启动先完成 EngineCoreReadyResponse 握手；HTTP 起服与权重加载并行，端口可达即引擎就绪。两条桥对应 LaunchedEngine 双臂与两代契约：LocalEngineBridge（legacy）把共享 TokenEvent 流按请求 tag 做 demux 分桶、保序折叠成一条批量 EngineCoreOutputs；SteppedEngineBridge 将每条 StepOutputs 一比一翻译成 wire 消息，辅以 names 反查表处理 abort、UnixAnchor 做单调钟到墙钟换算。wire.rs 是唯一采样参数词汇表：ignore_eos 由 eos/stop 字段推导、top_k 0→-1 语义映射、seed 恒 None；不支持的参数一律拒绝。两桥共享 Stop 终态补发 stop sentinel 以对冲 EOS 删除语义；迁移方向是全量改走 step 契约后淘汰 legacy 桥。
