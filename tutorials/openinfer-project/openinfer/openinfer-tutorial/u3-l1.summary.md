本讲剖析前端 crate engine 模块的旧一代引擎契约，由五个类型构成：GenerateRequest（一次生成的纯数据输入，不含 CUDA 类型）、TokenEvent（七个变体按时间线排列、恰好一个终态的输出词汇表）、TokenSink（所有请求共享一条 tagged 频道，前端按标签 demux 分解回各请求）、KvPrefix（前缀解析结果，携带目标 rank 与不透明防驱逐 hold）、EngineHandle（多分区路由、负载馈送与生命周期）。核心结论：submit 路由优先级为前缀绑定 rank 高于请求自带 rank，再次是最小负载分区（打分为运行数加四倍等待数）；单请求取消不拆频道，靠每请求共享的原子中止原因实现反应式退役；越界 rank 属调用方错误，handle 补发 Scheduled→Rejected 而 submit 仍返回 Ok；提交频道无界无背压，准入拒绝一律用 Rejected 表达。该契约处迁移期，多数模型线仍经 LaunchedEngine::Handle 启动，为下一讲的 step 新契约铺垫。
