本讲绘制 PegaInfer workspace 的职责地图：20 个成员 = 19 个 `pegainfer-*` crate + 1 个自 NVIDIA dynamo 衍生的 `kvbm-logical`；铁律是依赖只准自上而下、模型 crate 互不依赖。成员按四层归类：前端/入口层（server、frontend、sim）、模型层（qwen3 等 7 条模型线）、共享运行时（core、kernels、sample、bench、build、cupti）、KV 基础设施（kv-cache、kv-offload、kv-store、kvbm-logical）。引入的关键概念：pegainfer-server 是纯分发二进制，不含模型逻辑，经 frontend 定义的 ModelLine 接缝（detect/launch/ServePlan）完成检测与分发，未编译的模型线由 feature_gate_hint 给出重建提示；frontend 分契约半（engine/sampler 等，不含任何 CUDA 类型）与协议半（vllm，复用 vLLM 的 Rust crates）；kernels 拥有 build.rs 与 CUDA FFI，core 是模型侧运行时门面（ops/权重加载/CUDA Graph）；默认仅启用 qwen3 feature，pegainfer-sim 以纯 CPU 实现同一契约验证前端全链路。
