本讲覆盖 PegaInfer 从源码构建到 GPU 服务的全过程。核心结论：workspace 的 default-members 仅含 pegainfer-server，其默认 feature 是 qwen3，因此默认只编译 server→frontend→qwen3→core/kernels 一条依赖链，全程无 Python；GPU 构建必须用 --release。构建期两个关键机制：pegainfer-build 的 CudaToolkit::discover 按 CUDA_HOME→CUDA_PATH→/usr/local/cuda 定位工具链；kernels 的 build.rs 探测 SM 目标（PEGAINFER_CUDA_SM 优先，退回 nvidia-smi 探测，皆失败即 panic），再用 nvcc 预编译 .cu 内核——AOT 而非 JIT，这是无 Python 运行时的关键。新 clone 必须初始化 FlashInfer 子模块。另有两条安装通道：install.sh 预编译包（驱动门槛 580+，versions 目录加 current 原子切换）与 docker/dev.sh 容器（工具链全预置、按 CUDA base 分缓存）。本讲引入术语：default-members、feature 门控、build.rs、rust-toolchain 工具链钉住、SM/compute capability、cargo 参数 `--` 分隔符，供后续 workspace 全景与 kernels 构建系统讲义承接。
