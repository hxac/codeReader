本讲剖析 pegainfer-frontend engine 模块的新一代 step 驱动契约。一次调度步对前端至多发一条 StepOutputs，每个被触碰请求至多占一条扁平 RequestUpdate，旧 TokenEvent 协议靠约定维持的顺序规则由此变成类型上不可违反的结构。RequestLedger 账本为每个未应答请求开户，以 Queued→Active→终态状态机和「触碰已关闭账户即 panic」强制终态恰好一次，token 计数由账本统一 tally。Scheduler trait 仅 submit/step/metrics 三方法，由前端唯一的 drive 循环在专用 OS 线程上按「排空提交→step→commit_step」节奏驱动，绝不停等。scheduler_pair 铸造 SchedulerHandle 与 SchedulerBackend 两端；RequestEnvelope、DeferredFinish 及账本 Drop 三枚 drop bomb 保证未应答请求绝不无声消失。迁移期 LaunchedEngine 双臂共存，终点是把 Stepped 引擎交还协议栈（u3-l3 起点）。
