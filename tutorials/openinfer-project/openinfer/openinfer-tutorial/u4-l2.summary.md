本讲解析 pegainfer-kernels/build.rs 的构建流水线：CudaToolkit 发现 CUDA 工具链（覆盖经典/conda/HPC SDK 三布局）并自愈未初始化的 submodule；SM 探测走 PEGAINFER_CUDA_SM 环境变量 → nvidia-smi → panic 三级策略，gencode 取舍由 nvcc 试编译探针判定，不支持的专属内核降级为 NOT_SUPPORTED 桩而非构建失败；feature 门控用 is_*_source 系列目录谓词裁剪 csrc，未启用的模型目录整体不进编译列表，产物经并行 nvcc 池归档为 libkernels_cuda.a 静态库交给 rustc 链接；qwen35 与 k3 分别走 Triton、TileLang 的 AOT 通道——构建期跑 Python 生成 cubin 与 C 启动代码，实现「构建期可选 Python、运行期零 Python」，这也是默认构建全程无 Python 的根基。关键术语与机制：build.rs 的 cargo: 指令通道、SM/gencode 与加速变体（如 sm_100f）、OfflineCudaDriver 让无 GPU 构建机离线定 target、k3 的生成/预生成/桩三级回退（桩返回 cudaErrorNotSupported 以保链接完整）。另需记住：csrc/qwen35 是原生 CUDA、无条件编译，qwen35 feature 只门控 Triton AOT 阶段。
