本讲澄清 CLI 入口的真实位置：pegainfer-bench 是纯库 crate，无任何 bin；命令行入口在模型 crate 的 feature 门控 bin（qwen3 与 kimi 的 *_model_report，required-features = ["kernel-report"]），以此把 CUPTI 等工具依赖挡在生产依赖图外。参数层用 clap derive：位置参数 command 为 String，由 main 手动校验（现仅支持 decode），Kimi 侧另有 ValueEnum 的 --source。分发是两级的：main 编排「校验 → 运行时 trace 得到 KernelCall 调度 → measure_catalog 用 bench_key 去重 → measure_call 按 op 名 match 到 measure_* provider → compose_report 汇总落盘」；op 注册表封闭，未知 op 直接 bail。库共享件包括 LatencyStats、measure_loop 与 rollup 构件，qwen3 用本地冷 L2 版计时，Kimi 用库版。错误处理遵循 anyhow 四件套（bail!/ensure!/with_context/anyhow!），快速失败、绝不静默兜底。KernelCall 作为擦除张量元数据将在后续讲义展开。
