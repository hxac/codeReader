本讲拆解 WorkerState 的动态核心。plan_step 只决策不计时，预算分配三段：decode 优先（每请求 1 token，由 max_num_seqs ≤ max_num_batched_tokens 保证付得起）→ running prefill 按序分块、队首阻塞 → waiting 严格 FCFS 准入；请求数与 token 预算是两道独立闸门。scheduled_prefill_tokens 落实 PrefillPolicy：Whole 全有或全无、Chunked 恒取 min(剩余， cap, 预算)；核心不变量是 chunk 上限只改步的切法与步数，不改最终输出集合。complete_step 按 StepId 结算：prefill 收尾当步迁入 Decode 并直接产出 token_index 1（省一个 TTFT 步）；decode 每步 ctx+1、generated+1，追平 output 即 finished，与取消请求一起被 retain 出队。契约类型 StepPlan（不可变施工图）、StepOutcome（施工报告）、StepShape（丢请求身份的负载三元组）——StepShape 是 u3 计时预测的查表键，ProfiledRuntime 插在 plan 与 complete 之间据它估时。
