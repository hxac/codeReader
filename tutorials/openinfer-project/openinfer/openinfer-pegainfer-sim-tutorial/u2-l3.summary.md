本讲剖析 pegainfer-sim 的 `worker.rs`：一个纯逻辑、泛型、确定性的调度状态机，只决定「每步装什么」，时间定价外包给 profile 的 `estimate_step`。核心结论：请求生命周期为 Waiting→Prefill→Decode 三阶段，终态（完成/取消）不是枚举变体而是从 running 物理移除；空 prompt 直通 Decode，Prefill 收尾迁移到 Decode 时同时产出首个 token，避免 TTFT 凭空多一步。preflight 有两类拒绝：prompt+output 超 `max_model_len` 返回 `ModelLengthExceeded`（优先判定）；Whole 策略且 output>0 时 prompt 超 `max_num_batched_tokens` 返回 `WholePrefillExceedsStepBudget`；Chunked 可拆块故无后者。submit 顺序固定：重复 id 报 Err、preflight 拒绝、零输出短路成 Finished、否则入队 Queued；Err 属调用方契约违规，Rejected 属请求自身属性。本讲引入的关键术语：`max_num_seqs`、`max_num_batched_tokens`、`max_model_len`、`PrefillPolicy`（Whole/Chunked）、`SubmissionResult` 三分支，以及 `request()` 快照与 `waiting_len`/`running_len`/`is_idle` 观察接口。`plan_step`/`complete_step` 的预算分配与推进留待下一讲。
