本讲义拆解 pegainfer-sim 的 planned_completion、fake_token_id 与私有模块 logprobs.rs，补齐上一讲留下的「发什么 token、带什么附件」空白。核心结论：输出计划在准入时一次性定死——脚本为空则按位循环复用 prompt token（i mod 长度），恒为 Length；脚本非空发 min(max_tokens, 脚本长度) 个，放完即 Stop、截断为 Length，且 Stop 只来自脚本耗尽。pending 反转存储：legacy 车道按栈弹出，profiled 车道转回正序按 1-based token_index 取值；长度孪生函数 planned_completion_len 供 worker preflight 报预算；空 prompt 循环无解，走 fallback_token_id（默认 0）。logprobs 用常数合成协议夹具：PromptEcho 首位为 None（首 token 无上文不打分）且与 ids 严格平行，prompt rank=3、completion rank=1；alternatives 故意不含被计分 token，分数不是模型精度证据，断言只能针对形状。关键术语「脚本化输出、反转存储、fake_token_id、协议夹具、rank、prompt 回显」由 u2-l3 WorkerState 与 u4-l3 工具调用跨分片、logprobs e2e 测试承接。
