本讲只拆解 `core.sv` 一个文件的内部连线，确立 core「一次处理一个 block」的工作模型：dispatcher 派活时递上 `block_id`（映射为 `%blockIdx`）和 `thread_count` 两项 block 元数据。core 内部由三类部件构成：一是**单实例三剑客**——fetcher（取指）、decoder（译码）、scheduler（驱动 `core_state` 七阶段状态机 IDLE→FETCH→DECODE→REQUEST→WAIT→EXECUTE→UPDATE→DONE），它们对应「单指令流」，产出的控制信号（`core_state`、`instruction`、`decoded_*`）被全 core 广播共享；二是**每线程一份**的 ALU/LSU/registers（16 个寄存器，`%threadIdx` 复位为线程号 i）/PC，由 `generate for` 在编译期复制 `THREADS_PER_BLOCK` 套，对应「多数据」。硬件虽建满最大容量，但运行时用 `enable = (i < thread_count)` 门控冻结多余执行单元。两类部件由中间信号缝合：`rs[i]/rt[i]`（registers→ALU/LSU）、`alu_out[i]`（ALU→registers/PC）、`lsu_out[i]`（LSU→registers），在 `core_state` 调度下分 REQUEST/EXECUTE/UPDATE 三拍流动，形成每个线程内 registers↔ALU↔LSU 的闭合数据环路。本讲不展开各子模块内部实现，留待后续讲义。
