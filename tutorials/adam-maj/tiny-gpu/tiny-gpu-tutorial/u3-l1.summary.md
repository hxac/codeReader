本讲确立 tiny-gpu 与外部内存的边界约定。设有两块独立内存：data 内存（8 位地址、8 位数据、4 通道，可读写）与 program 内存（8 位地址、16 位指令、1 通道，只读），规格全部由 gpu.sv 的 parameter 定义。对外采用统一的「多通道 valid/ready/data」握手：请求类信号（valid/address/write-data）为 GPU 输出，应答类信号（ready/read-data）为 GPU 输入。两块内存各由一个 controller 实例作中继——data 控制器在 8 个 LSU 与 4 个外部通道间仲裁，program 控制器服务 2 个 fetcher、1 通道且 WRITE_ENABLE=0。仿真中外部内存由 Python 的 Memory 类扮演，每拍 run() 一次、零延迟同拍响应；因 cocotb 将多通道信号序列化为拼接长串，run() 须逐位/逐段解析请求，再以同一布局把应答拼回写回 DUT。load() 灌入初始数据、display() 打印内存表格以供观察。controller 内部仲裁逻辑留待 u3-l2。
