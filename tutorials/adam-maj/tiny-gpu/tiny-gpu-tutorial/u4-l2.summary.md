scheduler 是 tiny-gpu core 的「指挥」，不参与计算与访存，只把执行一条指令切成七阶段状态机（IDLE→FETCH→DECODE→REQUEST→WAIT→EXECUTE→UPDATE→DONE），用 3 位信号 `core_state` 广播给 fetcher / decoder / LSU / ALU / PC，后者各在自己所属节拍工作——这正是 SIMD 单指令流驱动多线程的硬件体现。其工作粒度是一个 block，从 PC=0 跑到 RET 为止。两类阶段判然分明：DECODE / REQUEST / EXECUTE / UPDATE 是单周期同步推进，根源是非阻塞赋值 `<=` 引入的 1 拍延迟，对所有指令一视同仁；FETCH 与 WAIT 则是变长握手等待。FETCH 靠 `fetcher_state==FETCHED` 与 fetcher 做双向握手；WAIT 用 `for`+`break` 轮询所有线程的 `lsu_state`，只要任一 LSU 仍处 REQUESTING/WAITING 就继续等，因而成为同步指令（1 拍放行）与异步访存（等最慢线程内存往返）的分水岭。UPDATE 阶段以 `current_pc <= next_pc[THREADS_PER_BLOCK-1]` 推进 PC，隐含所有线程 PC 相同的「PC 收敛假设」（忽略分支分歧），遇 RET 则置 `done` 进 DONE。单条指令耗时为 `T_inst = t_FETCH + t_WAIT + 4`，解释了内存密集型内核为何更慢。后续讲义将承接 `core_state` 译码、LSU 四态机、寄存器堆写回以及分支分歧等被简化的话题。
