本讲是 Unit 6 的应用篇，承接 u6-l1（驱动硬件）与 u6-l2（读轨迹），讲解如何往 tiny-gpu 塞入自写内核并验证。核心结论：跑内核需备齐「三要素」——程序内存（手工编码的 16 位指令列表）、数据内存（初始数据列表）、线程数（写入 DCR）；README 里的 `.threads`/`.data` 伪指令只供人读，真正生效的是 `test_*.py` 中的 Python 列表，项目并无汇编器。`matadd` 内核演示了 SIMD 主线：用只读寄存器 `%blockIdx/%blockDim/%threadIdx` 算出全局线程号 `i`，按 `baseA/baseB/baseC` 三段布局定位数据，用 `LDR rd,rs`（取 mem[rs] 写 rd）读、`STR rs,rt`（把 rt 写入 mem[rs]，地址/数据字段方向与 LDR 相反）写。`matmul` 内核首次引入循环控制：`CMP`+`BRn` 实现累加循环；关键反直觉点是，因 8 位无符号减法回绕，`CMP` 的 bit[2] 实际等价于「不相等」，`BRn`（掩码 `100`）据此在 `k≠N` 时跳回，行为上等价于「k<N 则循环」，`k==N` 退出。该内核所有线程分支均收敛，满足 scheduler 的「PC 收敛假设」（为 u7-l1 讨论分支分歧埋下伏笔）。校验环节：数据内存分段使输入/输出区不重叠，仿真后用 `data_memory.memory[i+baseC]` 取回结果，与 Python 独立重算的期望值 `assert` 比对；`display` 只写日志供人看，`assert` 才决定成败。写新内核固定五步：设计汇编→手工编码→填 `test_*.py` 三要素→`setup`+主循环→`assert` 校验。
