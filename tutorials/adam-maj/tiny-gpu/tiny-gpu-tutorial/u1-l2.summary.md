本讲是 tiny-gpu 的「地图篇」，建立文件、模块与架构图的对照表。仓库分四部分：src/ 存 12 个 SystemVerilog 硬件源码，test/ 是 cocotb Python 仿真测试台，docs/images/ 放架构图，gds/ 为流片版图产物。源码围绕 GPU→Core→Thread 三层结构组织：顶层 gpu 实例化 dcr（设备控制寄存器，存 thread_count）、两次 controller（分别服务 data 与只读 program 内存）、dispatch 派发器，以及由 generate 循环复制的 NUM_CORES 个 core；每个 core 含单实例的 fetcher/decoder/scheduler，再用 generate 循环为每线程复制一套 alu/lsu/registers/pc，共 12 个模块、无孤儿文件。引入的关键术语包括：module（带端口的电路积木）、instantiation（实例化）、generate 循环（编译期复制电路）、cocotb（用 Python 驱动 iverilog 仿真）。.sv 是被测对象、由 iverilog 执行，.py 是测试台，二者不可混淆；线程以 enable 门控，只有前 thread_count 个硬件真正工作。学习要诀是「图先行、再回源码印证」。
