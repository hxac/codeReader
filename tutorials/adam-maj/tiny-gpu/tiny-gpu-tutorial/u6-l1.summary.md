本讲把视角从「硬件内部」转向「测试台如何调度硬件」。cocotb 让 Python 充当 testbench，`.sv` 充当被测设计（DUT），二者经 VPI 桥（`libcocotbvpi_icarus`）通信；测试函数是 async 协程，靠 `await` 一个 trigger 把控制权交还仿真器、与硬件同步节拍。核心是 `setup()` 的五步启动序列：建时钟（用 `start_soon` 把方波分叉到后台）、复位脉冲、`load` 装填内存、写 DCR 锁存 `thread_count`、拉 `start` 点火——凡涉 DUT 寄存器都需 `await RisingEdge`，而 `load` 是纯 Python 操作无需等时钟。重点是主循环 `while dut.done.value != 1` 每拍执行 `run()`→`ReadOnly`→`format_cycle`→`RisingEdge`，对应 cocotb 一个周期内 ReadWrite（可写，`Memory.run()` 在此回送多通道内存应答）与 ReadOnly（只读，`format_cycle` 读快照）两阶段，顺序不可颠倒。`Memory` 类以 Python 列表扮演外部 DRAM，每拍零延迟同拍响应；循环退出后由 `assert` 判定成败，轨迹经 `logger.py` 写入带时间戳的 `test/logs/`。引入术语 DUT、VPI、trigger、ReadWrite/ReadOnly、DCR、done，为 u6-l2 执行轨迹阅读与 u6-l3 编写新内核承接。
