本讲解決 tiny-gpu 的 SystemVerilog 源码如何跑起来。仿真工具链由 sv2v（SystemVerilog→Verilog）、iverilog（编译成 build/sim.vvp）、vvp（运行仿真）、cocotb（Python 测试台，经 VPI 驱动）四件工具串联。入口 make test_<名字> 命中 Makefile 的 test_% 模式规则（用 $* 取「茎」），依次执行 compile→iverilog→vvp 三步。compile 中 sv2v -I src/* 会吃掉字母序最前的 alu.sv，故 alu 须经 compile_% 规则单独编译、再 cat 拼回 build/gpu.v 并在顶部补 timescale；iverilog 用 -s gpu 指定顶层模块。cocotb 靠 libcocotbvpi_icarus 与 LIBPYTHON_LOC 搭起 Python↔Verilog 桥。测试台 setup.py 启动序列为建时钟、复位、装程序与数据内存、写设备控制寄存器（设 thread_count）、拉 start，主循环用 RisingEdge(dut.clk) 逐拍同步、每拍驱动一次外部内存。日志写入 test/logs/log_<时间戳>.txt，分「初始数据内存」「执行轨迹」「最终数据内存」三段，内存表标题为 DATA MEMORY。引入的关键术语：仿真器、testbench、VPI、模式规则、DCR、start/done。
