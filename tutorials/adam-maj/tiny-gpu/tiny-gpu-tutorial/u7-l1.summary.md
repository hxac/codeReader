本讲是 Unit 7 首篇，首次「向后看」，聚焦 tiny-gpu 为求简洁而**刻意省略**的调度机制，构成一条递进的「天真链」：地基是 **PC 收敛假设**——scheduler 在 UPDATE 阶段只取 `next_pc[THREADS_PER_BLOCK-1]`，把「每线程一份的 next_pc」压扁成全 core 单一 `current_pc`。由此引出三重后果：**无流水线**（指令六阶段串行，WAIT 期间执行单元闲置，内存延迟无法重叠吸收）、**单 block 串行**（一个 core 一次只背一个 block，跑完 reset 再接下一个）、**分支分歧（branch divergence）被省略**（不同线程想走不同 PC 时硬件只跟随最后一个线程，悄悄算错且不报错；真实 GPU 用活跃掩码与重汇聚栈时分处理，tiny-gpu 直接不支持，故内核必须保证分支点全线程收敛）。最后是 **warp 调度**被简化为「一个 block 即唯一 warp」，core 无多套 PC/core_state 上下文，无法时分切换做**延迟隐藏**。关键约束：分支条件一旦依赖线程间不同数据（如 `%threadIdx`）即发散算错；官方内核靠「所有分支收敛」回避此问题。
