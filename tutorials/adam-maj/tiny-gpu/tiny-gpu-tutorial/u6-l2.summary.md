本讲承接 u6-l1，讲解 cocotb 仿真执行轨迹（execution trace）如何从 DUT 信号翻译为可读日志，主角为 format.py 与 logger.py。核心结论：所有轨迹只写入带时间戳的日志文件、终端无输出。format_cycle 按「cycle→core→thread→字段」四层遍历，每 core 仅读一次 instruction 供全部线程共享（体现 SIMD 单指令流），用核级、线程级与 thread_id 三重过滤控制日志体量，并以 reg_input_mux 选择性打印即将写回的值。关键术语：format_instruction（decoder 逆运算）、四张状态映射表（镜像硬件 localparam，需双向同步）、format_registers（用 reg_idx=15-i 加 reverse 还原 cocotb 倒序遍历的寄存器升序）。字段分 core 共享（PC/Core State/Instruction/Fetcher State）与每线程（Registers/LSU State/RS/RT）两组，是 SIMD 架构的文本投影。两处陷阱：BRnzp 的 nzp 段因字符串与整数比较恒空；format_memory_controller_state 虽定义却从未被调用，属死代码。
