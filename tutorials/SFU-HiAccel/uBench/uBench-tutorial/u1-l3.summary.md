本讲以 read/DDR/2ports_512bit 工程为例拆解 uBench 构建运行系统（Ubuntu 18.04 + Vitis 2020.2 + XRT 2020.2），分三个模块：环境守门——utils.mk 解析期检查 XILINX_VITIS，目标期检查 XILINX_XRT 与 DEVICE，SoC 目标另需 SYSROOT 与交叉编译器；v++ 编译链接——内核源码经 v++ -c 生成 .xo，再经 v++ -l --config ubench.ini 链接成 ubench.xclbin，主机程序由 g++ 编入 xcl2 公共库生成 ubench，产物目录名含 TARGET 与 XSA 以隔离不同目标/平台；运行路径——make check 串起 all/build/exe/sd_card 等目标并自动运行，仿真依赖 emconfig.json 与环境变量 XCL_EMULATION_MODE，真机直接执行。关键概念：TARGET 三档 sw_emu/hw_emu/hw、DEVICE、XSA。核心结论：sw_emu 仅验证功能链路，其带宽数值无物理意义；工程内 utils.mk 是 common 版逐字节副本且优先生效。
