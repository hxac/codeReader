本讲对 common/ 做「仓库考古」。includes 七库中仅 xcl2（16 个 host.cpp 引用：OCL_CHECK 宏、4096 页对齐分配器、设备枚举与 xclbin 读取）与 opencl.mk（OpenCL 头路径与链接项）在 uBench 构建中活跃，cmdparser、logger、oclHelper 及三个图像库零引用休眠，皆自 Vitis 示例仓库整体搬运、未做裁剪。核心是「.mk 片段机制」：库定义 <库名>_SRCS/_CXXFLAGS/_LDFLAGS 命名空间化变量，工程以 COMMON_REPO 为锚点 include 后用 += 注入主机编译；xcl2_LDFLAGS 是从未定义的幽灵变量。文档工具链以 description.json 为单一代码源：makegen.py 派生 Makefile 与 ini（ubench.ini 的 sp/slr/nk 指令源于其 create_config），readme_gen.py 派生 README，update_*/check_* 族批量再生成与巡检；但 uBench 无任何 description.json，整链休眠，唯一活跃 utility 是构建期解析平台名的 parse_platform_list.py。结论：二次开发须保留 xcl2、opencl 与 utils.mk，休眠库可删。
