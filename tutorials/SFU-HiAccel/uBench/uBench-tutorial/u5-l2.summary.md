本讲剖析 uBench 自动生成框架中的四个代码生成器。kernelcode_gen 按端口数循环生成内核源码与 krnl_config.h：签名、m_axi pragma 与测量循环一体产出，比手写版多一个 sum 写回口用于消费读值、防止死代码消除，并省去 WIDTH_FACTOR（位宽换算内联进主机）。hostcode_gen 生成 host.cpp：CONSECUTIVE_DATA_SIZE 换算为 payload 循环边界，BANK_FLAG 注入 cl_mem_ext_ptr_t，RD/WR 分支决定缓冲迁移与否。connectivity_gen 生成 ubench.ini 的 slr/sp/nk 三行连接表。makefile_gen 唯一参数是频率，落点为 --kernel_frequency，其 COMMON_REPO 六级上溯恰好到达仓库根（手写版五级失准）。四者共用「list 装字符串再 writelines」的朴素拼接技术，内核签名、setArg 编号与 sp 行的跨工具契约由同组循环变量构造性对齐。核心结论：RD 临时变量声明缺分号是必致编译失败的脚本缺陷；迁移 Python 3 实质只需改主脚本裸 print 与整数除法（/ 改 //）。
