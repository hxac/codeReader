本讲以 datacenter 读带宽微基准（2ports_512bit）为对象，讲授三个参数的手动修改。加端口需四处联动：内核签名加指针并配异名 bundle 的 m_axi pragma（bundle 异名＝独立端口）、每条循环独占 volatile 临时变量、复制并发读循环（DATAFLOW 并行）、主机改 NUM_PORT 并在 ubench.ini 补 sp= 连线；新指针须置于 size 之前以维持 setArg 编号契约。改位宽仅动 krnl_config.h 的 DWIDTH 一行，INTERFACE_WIDTH 与 WIDTH_FACTOR 自动派生，主机以 dataSize/WIDTH_FACTOR 把 int 数换算成宽字数，故每档实际字节数（payload×4）与带宽公式均与位宽解耦；DWIDTH 须为 32 的整数倍。突发长度改各端口 max_read/write_burst_length，单突发字节＝burst×位宽/8，AXI4 上限 256 拍，对主机透明，仅在连续数据量足够大时生效。核心结论：理论峰值＝频率×端口数×位宽/8，只看乘积（4×256bit 与 2×512bit 同为 38.4GB/s），差异靠实测分晓；README 有两处文档滞后（位宽实际定义在 krnl_config.h、--kernel_frequency 仅见于 auto_collect 生成的 Makefile）；综合实践为手动构造 4ports_256bit，即 auto_collect 的手工版。
