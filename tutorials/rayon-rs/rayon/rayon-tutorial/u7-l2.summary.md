本讲讲解 `ThreadPool::install` 与多线程池协作。核心结论：install 是同步入口，闭包被包装成 StackJob 送入指定池，调用点等到结果返回；`Registry::in_worker` 按调用者身份分三条路径——非池线程（in_worker_cold）睡在 LockLatch 上纯阻塞等待；跨池线程（in_worker_cross）用 SpinLatch::cross 做「帮工等待」，等待期间继续消化原池任务（本地队列→窃取→注入队列）；本池线程则就地执行零开销。池间是孤岛：每个 Registry 拥有独立线程与队列，任务不跨池窃取，跨池投递只能走对方注入队列（以 RegistryId 区分归属）。跨池死锁的成因不是跨池本身，而是池线程上 channel/mutex 等不帮工的纯阻塞等待切断了被等任务的执行资源，修复是把死等换成 install/join/scope 式帮工等待或用 in_place_scope 腾出 worker。嵌套规则：内层 rayon 操作跟随当前线程的池，pool.join/scope 皆为 install 的包装，跨池 install 是一次隐式让步；工程上默认单池，确有隔离需求才分池。
