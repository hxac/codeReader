本讲覆盖三个模块。线程身份查询：`current_thread_index` 的自由函数判「当前线程是否在任意池」，`ThreadPool` 方法版额外比对 `RegistryId`（地址型池身份）判「是否在本池」；索引非全局唯一，跨池会重叠。yield 家族：`yield_now` 沿「本地队列→窃取他人→全局注入」三级链找活，`yield_local` 只消化本线程名下任务；返回 `Option<Yield>`（Executed/Idle/None），让出的是池内执行权而非 OS 时间片，本质是 `install`/`wait_until_cold` 帮工等待循环的单步显式化。防饿死协议：`current_thread_has_pending_tasks` 只看本地 deque，是固有竞态的启发式查询（其自由函数未被 rayon crate 再导出），用作「spawn 还是就地执行」的反压信号，并与 `yield_local` 组成「查条件→查积压→选最小让出动作」的等待循环。核心结论：单线程池上纯阻塞等待自己 spawn 的任务必死锁，多线程下退化为积压饥饿；这组 API 全部尽力而为，影响效率、公平与活性，不承担正确性。
