本讲绘制 rayon 仓库的代码地图，不讲算法细节。核心结论：仓库是严格单向的三层结构——rayon-demo（基准演示）依赖 rayon（上层并行迭代器库），后者再依赖 rayon-core（调度内核）；内核以 links 强制全局唯一，防止多个全局线程池并存。rayon 层按「镜像标准库」组织数据源模块（slice、collections、str、option 等），两个特殊角色是 src/iter 与 delegate.rs：前者定义 ParallelIterator 与 IndexedParallelIterator 两大根 trait，遵循「一个适配器一个文件」规律，plumbing 子模块承载 Producer/Consumer 协议；后者是消除转发重复的委托宏。rayon 入口用 12 条 pub use 把 join、scope、spawn、ThreadPool 等调度 API 从内核再导出，故用户只需依赖 rayon 一个 crate。rayon-core 仅约十五个文件，分三组：任务原语（join/scope/spawn/broadcast）、任务表示（job/latch/unwind）、线程与调度（registry/thread_pool/sleep）；Registry 是 pub(super) 的全局单例，外界只能经 ThreadPool 访问，ThreadPoolBuilder 定义于 lib.rs。本讲引入的关键术语：再导出、prelude、plumbing、工作窃取、Job、Latch、Registry，以及 sleep 与 plumbing 两份官方 README 的位置。
