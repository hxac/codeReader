本讲拆解 rayon 任务的底层表示，核心文件是 job.rs 与 latch.rs。JobRef 用「数据指针 + execute 函数指针」手工擦除类型，固定两机器字、必须恰好执行一次，否则堆任务泄漏；任务分三形态：StackJob 活在调用者栈帧（零分配）、HeapJob 以 Box 转移所有权（执行者即释放者）、ArcJob 靠引用计数供全池各执行一次，另有把队列自身变成任务的 JobFifo；结果与 panic 存入 JobResult，捕获后在等待方重放。Latch 是单向一次性信号，协议为 set 恰好一次、probe 任意次、set 后效果全可见；CoreLatch 的四态状态机把「准备入睡」做成可打断的原子转移以堵死丢失唤醒，其上衍生 SpinLatch（join 自旋）、LockLatch（阻塞）、OnceLatch（免循环引用）、CountLatch（计数等 N 件事）与 LatchRef。核心结论：等待方式由等待者身份决定——池内线程自旋帮工，池外线程睡在条件变量上且连闭包 A 也被搬进池执行，跨池等待则继续帮原池干活。
