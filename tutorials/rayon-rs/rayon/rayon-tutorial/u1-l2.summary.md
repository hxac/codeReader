本讲解决「把 Rayon 开发环境跑起来」。仓库是三包 Cargo workspace：rayon（并行迭代器）依赖 rayon-core（调度内核），rayon-demo（publish = false 的演示程序）依赖 rayon，依赖严格单向。共享配置经 `[workspace.package]` 等段由子包 `.workspace = true` 继承，统一 rust-version 1.85 与 edition 2024；rayon-core 以 `links` 加 build.rs 强制全局唯一，运行时仅依赖 crossbeam-deque 与 crossbeam-utils。构建与测试方面，`cargo test -p rayon(-core)` 在 stable 上可跑，而 rayon-demo 的 bench 因启用了 `feature(test)` 需要 nightly。demo 演示分两类：八个可 `cargo run` 的（matmul、sieve、nbody 等）与十个仅 bench 的 `#[cfg(test)]` 模块（如 fibonacci），后者命令行运行只会打印用法并以退出码 1 结束。默认线程数由 rayon-core 的 `get_num_threads` 决定：显式设置 > `RAYON_NUM_THREADS` 环境变量 > 逻辑核数，什么都不设时即 CPU 数。本讲引入的关键术语：workspace、path 依赖与 version 双约束、`#[cfg(test)]`、`par_chunks_mut` 分块并行；另有两个结论——sieve 的并行加速比相对分块串行版计算（排除缓存友好收益），demo 一律建议 `--release` 运行。
