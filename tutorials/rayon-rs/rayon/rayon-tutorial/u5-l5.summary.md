本讲解读 rayon-core 的 sleep 模块（counters.rs、mod.rs、latch.rs 及 registry.rs 调用方），回答「find_work 三级找活全部落空后线程去哪里」。核心是 `AtomicCounters` 把睡眠数、不活跃数（inactive = idle + sleepy + sleeping）、任务事件计数器 JEC 压进单个 `AtomicUsize`，使「检查 JEC + 睡眠数 +1」能用一次 CAS 原子完成；关键不变量为 sleeping ≤ inactive 与 JEC 奇偶广播（偶=困、奇=有新活）。工作线程状态机为 active → idle →（32 轮 yield 退避）→ sleepy（JEC 盖章）→（第 33 轮）→ sleeping，与 `CoreLatch` 的 UNSET/SLEEPY/SLEEPING/SET 四态机配合。睡眠者先锁 `is_blocked` 再递增睡眠数，配合 `Mutex<bool>`+`Condvar` 管程等待保证唤醒不丢失；唤醒由唤醒者（而非被唤醒者）扣减睡眠数。唤醒是定量决策：`new_jobs` 依据 awake_but_idle、sleeping、任务数与队列是否原本为空决定叫醒几人；latch 置位走定向唤醒，经 `work_found` 涟漪至多 1+2=3 个。两处 SeqCst fence（外部注入 push 后、睡眠侧登记后）以全序论证堵死「全池睡死」死锁。总体分工：唤醒决策只影响性能，正确性由 JEC 检查、注入队列终检、fence 三重保险兜底。这些概念将承接至 u6-l1 scope 与 u6-l3 broadcast。
