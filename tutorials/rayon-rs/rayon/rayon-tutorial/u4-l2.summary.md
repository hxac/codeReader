本讲深入 Rayon plumbing 三角色中的拉模式一侧——Producer。核心结论：`Producer` 是「可切分的 IntoIterator」，关键成员为 `into_iter`、`split_at(index)` 与粒度窗口 `min_len`/`max_len`；其 `IntoIter` 必须实现 `DoubleEndedIterator + ExactSizeIterator`。生产者长度固定但不可自查询，长度由框架侧的 `bridge` 从 `IndexedParallelIterator::len()` 记账，取中点后让生产者与消费者在同一 `mid` 上对齐切分。`split_at` 按值消费 self、返回两个独立生产者，是 O(1) 纯算术的所有权操作；「包装生产者」（如 `MinLenProducer`）只改粒度、切分纯转发。无索引侧引入 `UnindexedProducer::split` 的「按能力切分」语义：切分点由数据自身决定（如字符串须落在 UTF-8 字符边界），分不动时返回 `None`，由 `bridge_unindexed` 回退串行。契约验证依赖 `producer_split_at` 测试的「三刀四段」穷举（切分后按序拼接须等于原序列，含反向与精确长度断言）。综合实践示范了自定义类型 MyRange 走「数据源 → IndexedParallelIterator → Producer」三层实现路径，之后全套索引适配器自动生效。
