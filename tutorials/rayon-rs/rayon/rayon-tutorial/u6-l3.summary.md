本讲讲解 rayon 的广播派发原语，核心模块为 `rayon-core/src/broadcast` 与 Registry 中的广播队列。`broadcast` 是阻塞式 API：向池中每个工作线程各投递一份闭包副本并等待全部完成，同步返回按线程索引有序的 `Vec<R>`；实现上是「每线程一个 `StackJob`（各自独立结果槽）+ 一个计数为 n 的 `CountLatch`」，故闭包只需 `Sync`、可借调用方栈数据。`spawn_broadcast` 是异步版：立即返回无结果，需用 channel 自行汇总且完成顺序不定；用一个可执行多次的 `ArcJob` 派生 n 个 `JobRef`，闭包须 `Send + Sync + 'static`，并靠「投递前加 n 个 terminate 计数、每副本执行完减一」为 registry 保活。关键术语：广播队列（每线程独占的 FIFO 队列，stealer 半边只归本线程持有，因此副本不会被窃取）、`BroadcastContext`（提供 `index()`/`num_threads()`，用 `PhantomData<&mut dyn Fn()>` 做成 `!Send + !Sync` 以留在出生线程）。调度优先级链被精确化为「本地 deque → 自身广播队列 → 窃取他人 → 全局注入队列」，广播「及时但不打扰」，FIFO 特性还使阻塞版可充当先前广播的屏障。panic 语义分家：`broadcast` 在调用点重放恰好一个，`spawn_broadcast` 每副本独立交 `panic_handler`。作用域版 `Scope::spawn_broadcast` 可借 `'scope` 数据。
