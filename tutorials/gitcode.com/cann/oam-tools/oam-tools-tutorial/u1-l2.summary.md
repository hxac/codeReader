本讲讲解 oam-tools 的构建与打包体系：build.sh 是唯一构建入口，其 checkopts 负责参数解析与白名单校验（如 pkg-type、bundle_branch 字符校验），build_oam_tools 组装 CMAKE_ARGS 依次驱动 cmake 配置、make 编译与 make package 打包，产物 .run 包落至 build_out/。根 CMakeLists.txt 是总装配线，探测本机 CANN 安装目录（ASCEND_CANN_PACKAGE_PATH）、拉取 cann-cmake 公共函数库，用 add_subdirectory 挂载 asys、msaicerr、hccl_test、operator_cmp 四组件并定义 install() 装包规则。核心概念包括：纯 Python 组件快车道（asys/msaicerr 跑 UT 时跳过整个 C++ 构建，仅生成 chip_handler.py）、闭源 bundle（libascend_ml.so 等从 OBS 按分支+架构下载，缺失即配置期 FATAL_ERROR）、bundle 分支解析三级规则（显式 --bundle_branch > git 最小领先提交数探测 > master 兜底）、download_libs.py 离线预置机制（含 .branch 元数据防分支错配）。核心结论：所有 shell 层参数都能在 CMake 层找到唯一消费点，测试依赖仅在 ENABLE_UT/ENABLE_COV 开启时引入。
