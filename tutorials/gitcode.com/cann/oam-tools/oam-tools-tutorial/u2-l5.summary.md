本讲深入 asys collect 子命令的内部实现。核心是 `AsysCollect` 类：`run()` 按 `run_mode` 分派 stacktrace 特殊模式与默认全量采集，`collect()` 作为总调度按固定顺序编排日志、graph、data_dump、ops、trace、状态、健康七类采集入口，并用 daemon 线程 + `finish_flag` 开关驱动进度条，状态/健康采集带超时装饰器保护。关键概念包括：EP 与 RC 环境分流（EP 走主机日志加 msnpureport 导出设备文件，RC 只采 RC 日志）；采集子模块的隐式框架契约——统一目录 `collect/<模块名>/<模块名>_collect.py`、统一入口签名 `collect_xxx(output_root_path)`、产物落 `dfx/` 布局、单项失败仅告警不中断；子模块三类形态：搬运型（log/graph/ops/data_dump，依赖 FileOperate 的 COPY_MODE/MOVE_MODE）、解析型（trace/coretrace，多线程逐文件格式转换）、交互触发型（stacktrace，类形态）。trace 模块解析 atrace bin 文件（控制头校验 magic/version，结构段自带 schema，时间戳由 real_time 加 cycle/cpu_freq 换算）；stacktrace 通过 ctypes 调 libascend_trace 发信号 35 触发栈导出，配前置检查链、Y/N 确认与 lsof 轮询；coretrace 用 addr2line 做栈地址符号化。核心结论：新增采集项的最小改动集仅三处——新包目录、入口函数、collect() 里一行调用，与芯片适配层「中心代码零改动」的设计哲学一致。
