本讲精读 msaicerr `-p` 模式第二阶段 `AicoreErrorParser`：其 `parse()` 是十一条流水线，仅 Step 1（`get_op_info()` 从 plog 用 grep+正则提取错误码、出错算子名、PC 与 kernel 文件）决定成败，后续图信息、args 对比、反汇编、memset 检查、dump 解析、单算子复现、环境验证等步骤均为尽力而为、单项失败不中断。关键概念包括：解析前由 `check_plog_info()` 探测 L0/L1 日志级别、FFTS+ 与 SK（SuperKernel）三个模式开关，分流依据是日志形态而非芯片型号；错误码本质是比特标志字段，经 `AIC_ERROR_INFO_DICT` 位映射译为中文描述，六个 `_analyse_*_errinfo()` 按位切出错误类型与地址，error_code 为 0 时还有 V300 三段移位合成；`AicErrorInfo` 作为约 50 字段的结果容器生成 `info.txt` 并按优先级链给出 `MS_AICERR_*` 根因退出码；芯片适配采用运行期目录扫描 + 前缀匹配（`load_ascend_handlers`、`is_chip_handler`），soc_version 经 DSMI、cce 注释、默认 Ascend910B2 三级兜底。dump 解析细节留给下一讲。
