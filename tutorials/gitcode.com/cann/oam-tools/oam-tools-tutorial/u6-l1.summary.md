本讲剖析 oam-tools 测试体系的完整驱动链：build.sh 解析 `-u/--component/--ut/--st/--cov` 参数，纯 Python 组件（asys、msaicerr）命中 `is_python_only_component` 快车道跳过 C++ 构建（仅用 cmake -P 生成 chip_handler.py），再把参数翻译后委托给 scripts/run_tests.sh。run_tests.sh 以 TEST_CASES 映射表定义 8 个用例组（7 pytest + 1 gtest），结果解析采取"先判崩溃再数统计"的防御式策略。关键术语包括：UT/ST 之分、pytest 的 conftest 路径注入与 AssertTest 基类、mocker 打桩（UT 代码级）与 PATH 前插 mock 脚本（ST 环境级伪装）、msprof 的 gtest 清单驱动（`msprof_ut_targets.txt` 由 CMake 生成，新增 UT 零脚本改动）、gcov 动态白名单覆盖率，以及 install/upgrade/uninstall 三组 ST 共享的 run_package（无包自动打包或跳过）与 install_dir fixture。实践任务是仿写 asys arg_checker 的参数化 UT 并跑通闭环。
