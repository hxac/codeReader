本讲梳理 msprof 总体架构。msprof 由两部分组成：C++ 侧 collector（本仓 `src/msprof/collector`，含 `basic` OS 抽象层与 `dvvp` 主体）和 Python 分析 wheel（外部 `Ascend/msprof` 子仓，构建期打成 `msprof-0.0.1-py3-none-any.whl`）。核心结论：架构文档的七大模块（命令行、开关处理、Host 采集、AICPU 采集、驱动采集、数据处理、Platform 管理）全部映射到 dvvp 子目录，如 msprofbin、task_handle、msprof/engine、profimpl/aicpu、driver+transport、analyze、profimpl/platform（`*_platform.cpp` 反射注册）。关键设计思想：多入口（命令行/ACL/acl.json/环境变量）单收敛为 `ProfileParams`；上报走无锁 buffer 与落盘解耦；Platform 抽象隔离芯片差异。部署形态是三个 so 分层（msprofiler/proapi 接口层 dlopen profimpl 实现层，生产态可裁剪）。用户敲的 `msprof` 命令即 msprofbin 目标改名安装至 `tools/profiler/bin`；`profiler_tool/` 目录是「拉子仓→打 wheel→拷贝→解包→install」流水线产物。C++ 与 Python 唯一接缝是路径契约：`running_mode.cpp` 按自身位置拼出 `profiler_tool/analysis/msprof/msprof.py` 并校验。本讲只搭骨架，msprofbin 入口、profapi、analyze 将在后续三讲精读。
