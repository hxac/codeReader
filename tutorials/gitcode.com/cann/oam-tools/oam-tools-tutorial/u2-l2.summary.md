本讲深入 asys 的命令行体系，覆盖三个模块：cmd_parser.py、arg_checker.py 和 param_dict.py。核心结论：asys 采用声明式命令行设计——Arg 枚举成员的值是包含名字、类型、校验器、必选性、choices、帮助文案的元数据字典，Command 枚举把 Arg 组装成 8 个子命令，CommandLineParser 遍历枚举动态生成 argparse 子解析器，argparse 仅作执行引擎。校验分两道防线：argparse 负责类型、choices、required、互斥（如 analyze 的 file/path 互斥组）；ArgChecker 枚举收拢的 check_arg_* 函数在 parse_args() 之后做语义校验（目录存在、可执行命令、设备号运行时查询等），未传的可选参数直接跳过，某些校验器还带“校验即创建目录”的副作用。ParamDict 是 Singleton 全局单例，set_args() 按子命令把 Namespace 翻译成业务统一 key（-d→device_id、-r→run_mode、--symbol_path 切列表），__addArg 同名 key 先到先得防覆盖，业务模块通过 get_arg() 只读访问。新增一个参数只需改 Arg 枚举、Command 的 KEY_ARGS、ArgChecker 注册、set_args() 分支四处，无需碰构建逻辑。
