本讲深入 msaicerr 的 Dump 文件解析链路，覆盖 proto_parse 目录与 dump_data_parser.py。核心结论：「大 Dump」文件为两段式布局——前 8 字节小端 header_length、其后是 protobuf 序列化的 DumpData 元数据（含 input/output/buffer/space 四类容器及 OutputDataType/OutputFormat 枚举）、末尾按 size 顺序拼接张量裸数据。C++ 侧 dump_data_parser.cpp 经 CMake 编成 libascend_dump_parser.so，以 extern "C" 导出唯一接口 ParseDumpProtoToJson，把 header 段反序列化后写成 JSON；选用 C++ 是为复用 CANN 符号隔离的 protobuf 静态库、免除 Python 依赖。Python 侧 BigDumpDataParser 通过 ctypes.CDLL 动态库直调（非子进程、非 Python protobuf 包）传入文件全文与临时 JSON 路径，读回后即删，再按 size 回填数据并做 used_size 对账防越界，tiling 输入（input_type=7）单独摘出。DumpDataParser 负责 dtype 三级兜底判定（proto 枚举＞编译产物 json＞原始枚举号），numpy 可表示的落 .npy、否则落 .bin；-dtype 参数仅在 -d 指向 .bin 时生效，按用户指定 dtype 生成 .npy，冲突时仅告警。关键术语：DumpData、ParseDumpProtoToJson、ctypes 直调、DATA_TYPE_TO_DTYPE_MAP、bfloat16 特殊转换、mapping.csv 超长名反查。
