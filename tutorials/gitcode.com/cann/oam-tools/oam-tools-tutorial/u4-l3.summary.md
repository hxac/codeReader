本讲精读 msprof 的 profapi 插件层（src/msprof/collector/dvvp/profapi），当前仓库仅存头文件契约，实现已在提交 64ebbaa 中删除，可用 git show 考古。核心结论：插件分两条路线——继承路线（ProfPlugin 纯虚基类 + ProfCannPlugin/ProfAtlsPlugin 多态实现，解决设备形态可替换）与符号加载路线（dlopen/dlsym + 惰性函数指针，解决运行期按需取符号）。关键术语：ProfPluginManager（持有 ProfPlugin* 的策略模式，惰性默认 ProfCannPlugin、可 SetProfPlugin 替换）、无锁上报缓冲（ReportBuffer/BlockBuffer/VariableBlockBuffer，解耦业务线程写入与实现层异步落盘）、dlopen 加载 libprofimpl.so（接口层→实现层接缝）、PthreadOnce 惰性加载（ProfAclPlugin 逐方法 once 标志，ProfRuntimePlugin 用 map 集中装载并代理 rtProfilerTraceEx 打点）、ProfTxPlugin 用户打点（Meyers 单例）、ProfAvpPlugin 轻量形态（libprofapi_lite.so）、prof_inner_api.h 的 extern "C" 稳定 ABI 门面。新增数据源插件成本极低：一个头文件即可，数据出口复用主插件上报缓冲。采集的数据交由实现层格式化落盘，下一讲 u4-l4 的 analyze 模块接续处理。
