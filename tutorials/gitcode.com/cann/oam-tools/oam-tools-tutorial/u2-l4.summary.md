asys 芯片适配层的核心是「构建期注册 + 运行期分发」两时刻设计：构建期 asys.cmake 按「common/ascend*」目录约定 glob 出各芯片目录，include 与目录同名的 .cmake 注册文件，把 import 语句与「芯片关键字 → regex → handler」注册项拼入 chip_handler.py.in 模板的两个占位符，经 configure_file 生成 chip_handler.py——该文件不在仓库中，未构建则 asys 无法运行。运行期由模块级工厂 get_device(device_id) 依据 g_device_map 缓存，用 get_chip_info 返回的芯片信息字符串做字典键子串匹配分发到具体 handler，匹配失败退回通用 DeviceInfo 兜底（失败退化哲学）。各芯片 handler 继承 DeviceInfo，体现模板方法模式「按需覆写、默认继承」：Ascend910BHandler 最薄，仅声明能力开关；Ascend91093Handler 覆写 run_diagnose 实现按逻辑主卡多线程诊断；Ascend950Handler 最厚，以 (0x0001<<16)|device_id 编码双 component，覆写温度/电压等 6 个查询方法。注册项中字典键负责子串分发、regex 负责白名单正则，职责分离；supported_chip.py 的 CommandSupportedChipBase 及三个子命令白名单类（config/diagnose/profiling）统一取自 get_support_chip_regex_list()，预留按子命令独立配置的扩展点。新增一款芯片只需 handler 与 .cmake 两个新文件，中心代码零改动。本讲的 handler/DeviceInfo 是 u2-l5 采集子系统的底层依赖。
