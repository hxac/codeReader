本讲给出 HCCL 源码的导航地图，覆盖四个最小模块：顶层目录全貌、src 分层与四条架构硬约束、src/ops 算子目录与 op_common 四大组件、include/experimental/test 边界。核心结论：src 只分 common（通用逻辑，跨仓调用统一走 hcomm_dlsym）与 ops（算子实现）；src/ops 遵循「一个算子一个目录」，每个算子按入口 _op + selector + executor + template 组织，该结构由架构硬约束规定。引入的关键术语：算子（op）、算法（alg）、引擎（engine，分 aicpu/aiv/ccu），以及四大组件——selector 决定算法（产出 algName）、executor 编排执行、template 按「算法×引擎」搬运数据、topo 适配 rankGraph 拓扑。关键区别：selector/executor/template 每算子私有，topo 属通信域控制面基础设施而全体共享（位于 op_common/topo）。此外 include 仅暴露 hccl.h 与 hccl_mc2.h 两个稳定对外头文件，experimental 与 src 同构但不保证兼容、不编入商用版本。
