本讲是 Unit 8 收尾，讲解 HCCL Tuner 插件框架：用户可通过外部 `.so` 在每次集合通信调用时修改 cost table，把特定集群的调优经验注入算法选择。核心契约是头文件 `hccl_tuner_plugin.h` 定义的 C ABI——插件导出全局变量 `hcclTunerPlugin_v1`（含 `init` 与 `getCollInfo` 两个回调）；`hcclTunerAlgoEntry_t` 条目中三维名（engine/executor/template）由 `AlgoNameMapper::Enrich` 预填、插件只读，唯一可写字段是 `cost`（<0 禁用、=0 偏好、>0 覆盖、不改则信 CostModel）。核心侧 `tuner_setup.cc` 管理生命周期：`HcclTunerInit` 每 comm 一次 dlopen+dlsym+引用计数，任何失败静默回退 CostModel；销毁不 dlclose 防竞态；`getCollInfo` 连续 3 次超 100ms 自动禁用插件。`SelectorEngine::Run` 中 `SelectMinCost` 取最小 cost 输出 algName，故 Tuner 只操纵代价而非直接指定算法。参考实现 `examples/06_tuner_plugin` 把干预简化为 JSON 规则（条件全 AND、first-match-wins、Schema 校验失败整体失效），经 `HCCL_TUNER_PLUGIN` 环境变量加载，`test_plugin` 用 stub+mock 实现无 NPU 单测。
