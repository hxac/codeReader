本讲进入 HCCL 三大通信引擎中的 AICPU_TS 引擎，核心是「模板如何把一次集合通信拆成数据搬移动作，再以 Task 描述符下发」。关键结论：AICPU kernel 是预编译二进制，由 `LoadAICPUKernel` 一次性加载为全局句柄 `g_binKernelHandle`；`HcclLaunchAicpuKernel` 是运行在 AICPU 上的 kernel 体，它反序列化 host 传来的 `OpParam` 资源上下文，经 `OpOrchestrate` → executor→ 算子展开（Orchestrate），由模板 `KernelRun` 调数据面原语产出 `HcclHcommBatchTransferDesc` 并批量投递，真正搬数据的是 TS 调度的硬件执行器，故「不占计算核」。四步调度模型（Host 提交 kernel→TS 分发至 AICPU→AICPU 下发 Task→TS 执行）逐一对应源码。以 NHR 模板为例：AllReduce 拆为 ReduceScatter+AllGather，通信轮数 ⌈log₂R⌉（递归减半），流程为 PreCopy→通信→PostCopy。本轮新增静态代价标定函数 `CalcCostCoeff`，申报 T(n)=A·n+B·n+C 三元组（A 跨卡流量、B 本地拷贝、C 固定时延），供新选择器 SelectorEngine 的 CostModelManager 离线比价；未标定模板返回空即跳过。另引入 `IsOpsV2` 新老流程分发与 AICPU Task Cache 回放旁路（下讲主题）。
