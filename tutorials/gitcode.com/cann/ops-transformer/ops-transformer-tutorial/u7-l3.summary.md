本讲讲「写完之后怎么交给社区」，是会用→会读→会写路线的最后一环。新算子贡献为六步流水线：创建 Issue（「Issue 先行」是硬规矩）→ Ops-transformer SIG 评审并分配 experimental/ 分类目录 → fork 后发 PR → 在 PR 下评论 compile 触发 CI 门禁（编译、静态检查、UT、冒烟）→ Committer 打 /lgtm → Maintainer 打 /approve 合入，参与前置是签署 CLA。交付件分两档：生态最简算子仅需单文件 Kernel、测试脚本、CMakeLists 与 README（fast_kernel_launch 形态）；项目标准算子要五层目录，tiling 文件名必须含「_tiling」标识，编译须加 --experimental 旗标。本地门禁两道：pre-commit 五类 hook（基础规范、clang-format、ruff、codespell、OAT）；OAT 开源合规由 OAT.xml 定策略（CANN-2.0 许可证头，yaml/csv 豁免）、oat_check.sh 执行，仅拦截许可证头缺失与二进制/归档混入两项。全讲以 my_sum 为样本演练了一次可发 PR 的完整贡献。
