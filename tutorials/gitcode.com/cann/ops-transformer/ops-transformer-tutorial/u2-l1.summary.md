本讲以教学算子 add_example 为例做全景导览，建立“每个文件放哪里、被谁编译、被谁调用”的地图感。核心内容：算子六个子目录（op_host、op_kernel、op_kernel_aicpu、op_graph、examples、tests）的职责边界；算子根 CMakeLists 通过“GLOB 子目录 + 有 CMakeLists.txt 才 add_subdirectory”的自动发现机制组装构建，tests 仅在 ENABLE_TEST 时纳入，host 源码经 add_modules_sources 按命名约定（如文件名含 _tiling）注册。关键术语：opc 二进制编译（离线预编译 Ascend C 为二进制 kernel）、simplified key（粗粒度匹配减少二进制变体）、binary.json 中 shape: [-2] 表示任意 rank、def 文件中 ExtendCfgInfo("opFile.value") 连接 host 与 kernel 入口、AddConfig 注册到 ascend910b/ascend910_93/ascend950 三代 SoC、tilingKey 按 dtype 分支并与 binary.json 变体一一对应。核心结论：README 支持表是产品化交付范围，def 的 AddConfig 是代码可编译范围，二者可以不一致，源码才是事实；完整链路为 build.sh 编译出 .run 包 → 安装后 aclnn 接口可用 → 示例按两段式（GetWorkspaceSize + 执行）调用。
