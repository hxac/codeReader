本讲是专家层调试调优专题，回答「算子跑错怎么查、跑慢怎么优化」。核心结论：算子问题分正确性调试（host 侧 plog 日志与 aclGetRecentErrMsg、kernel 侧 AscendC::PRINTF 与 DumpTensor、msDebug 单步、msSanitizer 内存检测）与性能调优（msprof op 上板采集、NPU Simulator 指令流水仿真）两类，应先排雷再优化。上板采集在可执行文件目录执行 msprof op，从 OPPROF_* 产物读 Task Duration（Kernel 耗时）、Block Dim（核数）与 ArithmeticUtilization 流水占比；仿真工具 npusim（旧名 cannsim）是 SoC 级 CPU 仿真，与真机二进制兼容、无需驱动，仅支持 Ascend950PR/DT、单卡、AI Core 算子（MC2/HCCL 通信算子不可仿真），流程为 record 执行核精度、report 出 trace_coreN.json 并用 chrome://tracing 查看 MTE1-3/VECTOR/Cube/SCALAR/FIXP 时空条带，判断搬运与计算是否重叠。构建级调试开关（--dump_cce、--oom、--mssanitizer、--op_debug_config）经 build.sh 解析、check_param 互斥校验、翻译为 cmake 变量、最终由 add_opc_config 翻译成 opc 旗标（如 --save-temp-files、--cce-enable-sanitizer），三者两两互斥；--op_debug_config 是统一入口，ccec_O0,ccec_g 服务 msDebug。关键量化直觉：流水占比 η=T_busy/T_total，低则调 tiling 与双缓冲。
