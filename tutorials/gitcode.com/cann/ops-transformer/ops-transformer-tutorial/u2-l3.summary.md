本讲以教学算子 add_example 为样本，首次进入 op_kernel 目录精读 Ascend C 设备侧代码，覆盖三个模块：①kernel 入口与执行骨架——薄入口（`__global__ __aicore__` 修饰、统一的 x/y/z/workspace/tiling 五 GM 参数签名，用 `GET_TILING_DATA_WITH_STRUCT` 解包 tiling、`if constexpr` 按 tiling key 选模板实例）加厚算子类（Init 初始化、Process 内 CopyIn→Compute→CopyOut 三段循环）；②tiling 的 device 消费端——tiling data 是 host 填 device 读的无运行时校验结构体合同，tiling key 是运行期路由到编译期二进制变体的整数，新式 `ASCENDC_TPL_ARGS_DECL` 宏统一维护路由表；③GM/Local 内存模型——Vector 指令只能作用于 UB，kernel 永远是「GM→UB→计算→UB→GM」搬运循环，`TPipe`/`TQue` 以 Alloc/EnQue/DeQue/Free 四步协议管理 UB 并支撑 BUFFER_NUM=2 双缓冲流水，核间靠 SetBlockDim+GetBlockIdx 均分、核内靠 tileNum 切块。核心结论：只改计算逻辑（如 z=(x+y)*2 加 Muls 指令）通常仅动 op_kernel 一个文件，体现分层封闭性；kernel UT 用 `ICPU_RUN_KF` 配合 gen_data.py/compare_data.py 构成 CPU 侧验证闭环。
