本讲以 add_example 为载体讲解算子的两种运行验证方式。核心模块有三：一是 build.sh 的 `--run_example` 入口，按 `test_aclnn_`/`test_geir_` 前缀约定定位示例源文件并现场编译运行，ascend950 优先用 `examples/arch35/` 专属示例，支持整包、cust 自定义包与 simulator 仿真三种形态；二是 Eager（直调）模式，引入 aclnn 两段式 API 概念——第一段 `GetWorkspaceSize` 完成校验、infershape、tiling 并算出 workspace 大小，第二段 `aclnnXxx` 异步下发任务到 stream，骨架为「初始化→构造 aclTensor→两段调用→同步取回→释放」，依赖 op_api 与 op_host 层；三是 GE 图模式，用 `REG_OP` 声明的 IR 原型实例化算子节点、以 `op::Data` placeholder 连边组图，经 `Session::AddGraph`/`RunGraph` 整图编译执行，tiling 对调用方不可见，依赖 op_graph 层且编译期不链接算子库。关键术语包括 workspace、executor、aclTensor、stream、图 dump。核心结论：def 文件的 dtype 白名单是算子能力边界，不支持的输入在第一段即被拦截。
