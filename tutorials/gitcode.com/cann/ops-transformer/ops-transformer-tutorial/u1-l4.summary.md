本讲讲解 ops-transformer 的构建体系：build.sh 是唯一构建入口，本质是「选项翻译器」，经白名单校验、case 解析、assemble_cmake_args 拼 -D 参数后由 main 按标志位分发，四个核心维度为构建目标类型、算子、模块、SoC。构建目标分三类：编库（--ophost/--opapi/--opgraph/--onnxplugin 产出对应动态库）、编 kernel（--opkernel 需配 --soc）、打包（--pkg/--ops 产出 build_out 下 .run 安装包）。CMake 侧由 ASCEND_COMPUTE_UNIT、ASCEND_OP_NAME、ASCEND_MODULE_NAME 三个缓存变量驱动裁剪，should_add_module 实现「不传即全量」，op_add_depend_directory 自动补编依赖算子。SoC 与 arch 目录按下标平行列表映射（ascend910b→arch22、ascend950→arch35），不支持的芯片由 soc_validator.sh 前置拦截或 cmake 层空包兜底。产物目录约定：build/ 构建树、output/ 编库输出、build_out/ 安装包；默认全量 clean，--incremental 增量。日志中「Info: cmake config」行是观察实际生效参数的入口，为下一讲进入 add_example 目录 internals 做铺垫。
