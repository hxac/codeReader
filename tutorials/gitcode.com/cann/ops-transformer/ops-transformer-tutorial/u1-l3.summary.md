本讲义分「环境部署」和「源码管理」两个最小模块。核心结论：环境需求分编译态（仅需 CANN toolkit 包，无昇腾硬件也可学习编译流程）与运行态（需驱动、toolkit、ops 包三者）；部署路径有三种——CANNLab（无设备）、Docker（`-devel` 镜像，需 `--device /dev/davinci0` 等参数做设备映射，驱动装宿主机、CANN 装容器）、手动安装。环境验证三板斧：`npu-smi info` 查驱动、`ascend_toolkit_install.info` 查 CANN 版本、`source set_env.sh` 配环境变量（会话级，每开新终端需重做）。源码管理上，仓库标签与 CANN 版本一一配套（如 CANN 9.0.0 对应 `v9.0.0` 标签或 `9.0.0` 分支），须查 release-management 仓库后用 `git clone -b <tag>` 拉取，禁用 master；仓库依赖由 `install_deps.sh`（幂等的系统级依赖安装，googletest 仅 UT 需要）与 `requirements.txt`（Python 三方库，numpy 锁 `<2.0`）两层组成。关键术语：编译态/运行态、CANN toolkit 包与 ops 包、NPU 驱动、版本配套、`-devel` 镜像、`set_env.sh`，这些将贯穿后续 build.sh 编译讲义。
