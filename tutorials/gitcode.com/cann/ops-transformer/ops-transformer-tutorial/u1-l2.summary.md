本讲建立 ops-transformer 仓库的「地图感」。顶层目录分四类：算子域（attention、moe、mc2、ffn、gmm 等）、公共能力（common、3rdparty）、工程设施（scripts、cmake、tests、docs、torch_extension）、用户扩展（examples、experimental）。核心是单个算子目录的「五层范式」：op_host（Host 侧算子信息库 def、InferShape、Tiling 切分策略）、op_api（aclnn 两段式 Eager 调用接口）、op_kernel（Device 侧 Ascend C 核函数）、op_graph（图模式 proto/fusion）、tests/examples（验证与示例），另有可选的 framework 层（ONNX 插件）。关键结论：缺层有明确语义——缺 op_api 即不支持 aclnn 调用，缺 op_graph 即不支持图模式，缺 op_host/op_kernel 常意味着复用其他算子实现（如 moe_token_permute 转发 moe_init_routing_v2）。引入的术语包括：五层范式、Tiling（文件名须含 `_tiling` 才被编译识别）、tiling_key/tiling_data、Eager 与 Graph 两条调用路径、多版本接口共存（matmul_all_reduce v1~v3）。这些概念将承接至环境准备、构建体系及第二单元的逐层源码精读。
