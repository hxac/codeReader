本讲精读 add_example 宿主侧（op_host）三件套。def 文件是算子的「静态户口」：注册输入/输出元信息（dtype、format）、AutoContiguous 自动连续化、动态 shape 开关、经 ExtendCfgInfo 挂接 kernel 入口、AddConfig 注册 ascend910b/910_93/950 多 SoC，最终由 OP_ADD 宏注入算子信息库，是框架校验第一道关卡。infershape 是「动态量尺」：在 aclnn 两阶段 API 的 GetWorkspaceSize 阶段早期执行，从输入 shape 逐维推导输出 shape（支持含 -1 的动态 shape），经 IMPL_OP_INFERSHAPE 注册。tiling 是「执行计划」：综合平台信息（UB 大小、AIV 核数）与输入 shape，产出四类信息——tiling data、tiling key（按 dtype 路由 kernel 变体）、blockDim、workspace 大小。核心概念：host/device 侧分工、静态与动态信息、tiling data 是 host 填 device 读的「数据合同」（结构体放 op_kernel 目录、无运行时校验）。教学算子 tiling 参数写死（blockDim=8、tileNum=8），工业级策略见后续 flash_attention_score 讲。
