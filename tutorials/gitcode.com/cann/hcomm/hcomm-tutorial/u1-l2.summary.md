本讲围绕三个最小模块讲解 HCOMM 的源码构建：build.sh、CMakeLists.txt 与 version.cmake。核心结论：build.sh 是唯一构建入口，流程为解析参数、按「命令行 -p > ASCEND_HOME_PATH > ASCEND_OPP_PATH > 默认路径」探测 CANN 安装路径、拼装 -D 选项，再按「UT > ST > 正式包」优先级三路分发；正式包经 cmake 配置、编译、make package 产出 build_out 下的 makeself 自解压 run 包，安装后替换 CANN Toolkit 中的 HCOMM 组件。CMakeLists 中 UT（gtest+mockcpp，只编 test/）与正式包（BUILD_OPEN_PROJECT 分支，编 src/ 与 python/，并查找 12 个 CANN 组件）是两条互斥装配线。本讲引入的关键术语：host 侧与 device 侧（默认只编 host，--full/--aicpu 加编 device）、交叉编译（--build_aarch 用 CANN 自带 hcc 工具链）、UT 与 ST、run 包、--noexec（跳过 ctest 执行，无硬件时验证可编译）、ASAN/GCOV、头文件按 hccl/、hcomm/、hcomm/ccu/ 分层安装。version.cmake 声明 HCOMM 9.2.0 及其与 runtime、metadef、bisheng-compiler、asc-devkit 等组件的编译期/运行期配套关系，构建前必须版本对齐；自编译 device 子包还需较新版本 npu-smi 关闭驱动验签。
