本讲深入 `rank_info_detect` 模块，剖析通信域初始化的 bootstrap 阶段：各 rank 如何互相发现并协商出全局 RankTable。核心结论：调用 `HcclGetRootInfo` 的 rank 充当服务端（`RankInfoDetect` 走 `SetupServer`，异步拉起探测服务线程），其余 rank 走 `SetupAgent` 同步连接并等待 `WaitComplete`。关键术语：root info 的 V2 真身是 `HcclRootHandleV2`（ip + listenPort + netMode + identifier，identifier 含 IP/端口/devPhyId/时间戳，全局唯一）；`SocketAgent` 以“8 字节长度前缀 + 正文”成帧解决 TCP 粘包，单条消息上限 100MB；白名单（Whitelist）双层生效——选 bootstrap IP 时过滤本端网卡、建链时以 tag（前缀+identifier+端口）下发底层放行规则，探测结束即删除。消息序列为：agentId → rankSize → 本地 RankTable(+step) 上行，全局 RankTable(+step+failedAgentIdList) 下行，并伴随 rankSize、step、TLS 三道一致性校验；失败时 root 广播失败列表，超时 agent 延迟退出保证错误全网可见。本讲产出的 RankTable 正是 u2-l4 `RankGraphV1::Init` 建图消费的数据。
