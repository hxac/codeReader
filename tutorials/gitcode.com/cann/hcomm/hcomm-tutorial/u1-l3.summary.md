本讲是 HCOMM 仓库的“代码地图课”，建立从接口声明到内部实现的定位能力。核心结论：仓库按受众分三大目录——`include/`（对外头文件，面向所有开发者）、`pkg_inc/`（包间接口，供 CANN 内部组件及 device 侧共享，不承诺对外稳定）、`src/`（内部实现，只有编译器消费），CMakeLists 通过两条 install 规则分发到不同安装目录。`include/` 内部又分 L2 通信域管理（hccl_comm.h，含 17 个弱符号接口）与 L3 数据面资源（hcomm_res.h 的 Endpoint、内存注册/导入、线程分配）等层次；`pkg_inc/hcomm/hcomm_res_entity_defs.h` 定义 `ChannelEntity` 等 host/device 共享内存的 ABI 契约。关键术语：弱符号（支撑 dlsym 动态加载与 HCCL 解耦）、ABI 与 tagged union、两段式查询、控制面/数据面、legacy 兼容层。`src/` 三分为 coll_communicator_mgr（控制面，9 个子目录）、base_comm（数据面，resources + primitives）、legacy（ascend910/ascend950 维护态代码）；依赖方向严格自上而下：控制面 → 数据面。新特性只进前两者。
