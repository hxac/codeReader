本讲从源码视角解析 HCCL C 接口与通信域生命周期。核心结论：`hccl_comm.h` 所有对外函数以弱符号声明、实现在 HCOMM 库内强符号，使算子层与 HCOMM 解耦并支持动态加载；`HcclCommConfigInit` 为内联函数不走此机制。以 `HcclCommInitRootInfo` 为主线，链路为：`op_base.cc` 入口层（group 模式下可异步延迟建群）→ `HCCLV2_FUNC_RUN` 宏经 `hrtGetHcclV2Support` 运行时分派 V2 新架构或 V1 老流程 → V2 创建 `HcclCommunicator` → `HcclCommInitCollComm` 桥接 → `hcclComm::InitCollComm` 中创建 `CollComm` 并注册进单例管理器 `CollCommMgr`。关键术语：弱符号、root info、`HcclComm` 句柄（C++ 对象指针的 C 化转型）、owner 对象 `hcclComm`、`CollComm`、`CollCommMgr` 户口本、`api_c_adpt` 新式 C→C++ 一步适配。销毁与创建严格对称（注销维测与调度挂钩、释放内存与二进制），注册/注销由 owner 驱动以保持依赖自上而下。
