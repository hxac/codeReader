本讲承接 u8-l1 的功能调试，解决「算对了但太慢」的性能问题，主线是上板性能采集工具 msprof op。核心流程为：功能验证通过后删净 PRINTF/DumpTensor 调试打印、重新 --pkg 编译安装，再用 --run_example 生成样例可执行文件（如 test_aclnn_add_example），以 msprof op 包裹运行采集。产出分两层：终端摘要与 OPPROF_* 目录明细（含 ArithmeticUtilization 流水占比文件）。关键指标：Task Duration 仅测 kernel 设备侧执行时间，不含 aclnn 两段式 Host launch 开销，端到端慢但 Task Duration 短说明瓶颈在 launch 路径；Block Dim 由 tiling 中 SetBlockDim(usedCoreNum) 决定，只随输入规模变化，与 kernel 指令类型无关；两次对比须同频（Current Freq/Rated Freq）。调优判断方法：搬运流水占比高为访存受限（调 ubFactor、双缓冲、32 字节对齐三件套），计算占比高为计算受限（精简指令）；elementwise 算子典型为访存受限。无卡或需指令级细节时走仿真流水图（npusim record / msprof op simulator），由 u8-l3 展开。
