本讲承接 u3-l1 的算子原型定义，讲解 op_host 中 `*_infershape.cpp` 的 shape 与 dtype 推导。核心结论：infershape 运行在 Host 侧，在 aclnn 第一段（GetWorkspaceSize）或 GE 图编译阶段被框架回调，因框架须在执行 kernel 前得知输出的内存与类型；注册入口为 `IMPL_OP_INFERSHAPE(算子名).InferShape(...).InferDataType(...)`，算子名须与 `OP_ADD` 严格一致。关键概念包括：静态/动态 shape（-1 透传）、gert 命名空间（gert::Shape、InferShapeContext）、出参加状态码的 C 接口风格、`OP_CHECK_NULL_WITH_CONTEXT` 空指针防御。AddExample 采用逐元素复制策略（先 SetDimNum 再逐维 SetDim），而真实双输入算子遵循广播三规则（左侧补 1、1 维拉伸、不兼容报错）并复用 `BroadcastShape` 工具，失败路径为 `OP_LOGE` 加 `GRAPH_FAILED`；标量 0 维 shape 是复制与广播体系的差异点（`()` 与 `(1,)`）。测试方面，用 `InfershapeContextPara` 描述场景、`ExecuteTestCase`（期望码默认 GRAPH_FAILED）执行真实注册回调，新用例文件放入 tests/ut/op_host 即自动编入。本讲为 u4 的 tiling 与 u7 的完整 UT 体系奠定基础。
