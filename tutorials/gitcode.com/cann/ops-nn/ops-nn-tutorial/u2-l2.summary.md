本讲介绍 ops-nn 算子的第二种调用方式——GE 图模式(GEIR 调用)，与上一讲的 aclnn eager 模式相对：eager 逐算子即时下发，图模式则先把计算描述成一张计算图(Graph),交给 Graph Engine(GE)统一编译优化(算子融合、内存规划)后整体执行。核心交付件是 `op_graph` 目录下的算子原型头文件，用 `REG_OP` 宏声明算子的输入/输出/属性清单并注册进 GE,是算子入图的“报关单”；图编译阶段还需 InferShape/InferDataType 两个推导函数(经 `IMPL_OP_INFERSHAPE` 注册)推出输出描述。样例 `test_geir_add_example.cpp` 展示七步调用骨架：GEInitialize → 构图(op::Data 输入节点 + op::AddExample 算子节点连边，连边方法名由 proto 输入名决定)→ SetInputs/SetOutputs → Session/AddGraph → RunGraph(同步执行，结果直接回填 Host Tensor)→ 落盘 → GEFinalize。graph 模式运行时无需指定 vendor,GE 按环境变量自动加载算子包；排障首选 `aclgrphDumpGraph` 导出的图文本与 `GEGetErrorMsgV2`。下一讲将转向 torch_extension 封装 PyTorch API 调用。
