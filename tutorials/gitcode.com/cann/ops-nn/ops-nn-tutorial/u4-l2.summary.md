本讲承接 u4-l1 的切分算法，聚焦 Tiling 的两份交付物与注册机制。核心结论：TilingData 是 Host 侧写、Device 侧读的纯 POD 字节契约，两侧通过 include 同一头文件（置于 op_kernel/ 目录，供两侧编译单元共用）保证布局一致；Host 经 `GetTilingData<T>()` 写入（先 memset 清零），Device 经 `GET_TILING_DATA_WITH_STRUCT` 从入口末参的 GM 地址按字节还原；字段只能追加、不能改语义。TilingKey 是 uint64 运行期二进制选择器：`ASCENDC_TPL_ARGS_DECL` 声明模板参数取值集合，Host 用 `GET_TPL_TILING_KEY` 编码并 `SetTilingKey`，kernel 入口以 `template <schMode>` + `if constexpr` 为每个取值生成专用二进制；取值宏、kernel 枚举、Host 选 key 分支三处须人工对齐，错位即静默错数。tiling_templates_registry 提供多策略底座：`TilingBaseClass` 固化 8 步流程，`REGISTER_*_TILING_TEMPLATE` 静态注册，按优先级从小到大尝试，`GRAPH_PARAM_INVALID` 表示不适用即回退。add_example 走 `IMPL_OP_OPTILING` 简单路径，生产算子（如 max_pool_with_argmax_v3 的 5 级梯队）走注册表，两路同样产出 TilingData/TilingKey/BlockDim。
