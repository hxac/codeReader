本讲义建立「症状→手段」的算子调试选型框架：Host 侧问题（aclnn 报错码、算子未被调起）先取 plog 日志（默认在 `$HOME/ascend/log/debug/plog/`，`ASCEND_SLOG_PRINT_TO_STDOUT=1` 打屏，`ASCEND_GLOBAL_LOG_LEVEL` 控等级），并用 `aclGetRecentErrMsg()` 编程取回具体错误原因；Device 侧标量问题（tiling 切分错）用 `AscendC::PRINTF` 打印 tiling 字段与核号；Device 侧数据问题（算错）用 `DumpTensor` 在流水线中间点（如 Compute 的 Add 之后）检查 UB 上的 LocalTensor，实现 CopyIn/Compute/CopyOut 的二分定位。关键概念：plog、`aclGetRecentErrMsg`、`AscendC::PRINTF`（仅标量）、`DumpTensor`（Tensor 级）、KERNEL_LOG_* 宏（仅 AI CPU 算子）。核心纪律：改 op_kernel 调试代码必须 `--pkg` 重编安装 run 包；打印是临时注入手段，正式 kernel 不残留，长期验证写成 tiling UT；性能采集前必须删净打印；卡死与 GM/UB 越界等打印不可达场景升级到 msDebug 单步。性能采集（msprof op）与无卡仿真由 u8-l2、u8-l3 承接。
