本讲以官方 dir_structure.md 为字典，解剖 ops-nn 算子工程的标准目录骨架。仓库按「算子大类目录/算子工程目录」两级组织（如 activation/gelu、matmul 下挂数十个工程），每个工程内按交付物拆子目录：op_host 是 Host 侧交付件（*_def.cpp 用 OP_ADD 宏注册算子身份证、*_infershape.cpp 推导输出 shape、*_tiling.cpp 计算切分参数、config/${soc_version} 下按芯片型号存二进制配置 json）；op_kernel 是 AI Core 侧交付件（入口函数经 GET_TILING_DATA_WITH_STRUCT 读取 tiling data——Host 写、Device 读的数据契约，按 tiling key 分发模板实现）；op_api 服务 aclnn 两段式调用（可选，缺省时构建自动生成）；op_graph 的 REG_OP proto 服务 GE 图模式与融合。目录是「合同」，缺失有明确含义：缺 op_api 即不支持 aclnn，缺 op_graph 即不支持图模式。教学样例 add_example 是精简骨架，生产算子 gelu 增加了 docs、op_api 四件套、framework 插件、st 系统测试与 arch35 子场景目录。关键术语：soc_version（ascend910b 等）、tiling、tiling data、tiling key、l0/aclnn 接口、ut/st 测试，均由后续讲义承接。
