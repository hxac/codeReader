本讲解决「如何把 ops-nn 算子源码编译成 CANN 可调用的算子」，覆盖四个模块：环境准备、build.sh 参数体系、编译主流程、安装与运行验证。核心结论：编译需两层准备——CANN 侧须安装与源码分支配套的 toolkit 包并 source set_env.sh 使 ASCEND_HOME_PATH 生效，主机侧依赖（python/gcc/cmake/pigz 等）可由 install_deps.sh 一键安装，build.sh 启动时静默复查。build.sh 只是参数解析外壳，真正编译由 cmake 驱动：--pkg/--soc/--ops/--vendor_name 分别映射为 ENABLE_PACKAGE/ASCEND_COMPUTE_UNIT/ASCEND_OP_NAME/VENDOR_NAME；--ops 单算子编译会自动解析依赖算子一并编入；--pkg 带预编译 kernel 二进制，--jit 则不带。主流程为参数解析→组装 cmake 参数→cmake 初始化→编宿主库→编 kernel 二进制→打包，产物是 build_out 下的自解压 run 包。关键术语：编译态/运行态之分、soc_version（ascend910b/ascend910_93/ascend950 等芯片短名）、自定义算子包（挂载式安装到 opp/vendors/<vendor>_nn，优先级高于内置算子）、LD_LIBRARY_PATH（指向 vendors 下 op_api/lib 才能加载 aclnn 动态库）。验证用 --run_example <算子> eager cust，自动完成样例查找、g++ 编译与执行，且与 --pkg 互不触发——改样例只重跑前者，改算子源码才需重新编译安装。
