本讲义解决「Ascend C 的 API 源码放在哪、怎么组织」的问题，分为三个最小模块。其一定顶层目录分工：`include`/`impl` 是源码核心，`cmake`/`build.sh` 负责构建，`docs`/`examples`/`tests`/`tools`/`scripts` 分别支撑文档、样例、测试、工具与打包。其二核心结论是 `include`（声明）与 `impl`（实现）构成**镜像结构**：两边各有 7 个同名 API 子目录（`adv_api`、`aicpu_api`、`basic_api`、`c_api`、`simt_api`、`tensor_api`、`utils`），命名遵循「声明 + `_impl` = 实现」的约定；`impl/` 比 `include/` 多一层按芯片架构切分的子目录（`dav_xxx`、`npu_arch_xxxx`），隔离同一接口的不同硬件实现。其三引入**主入口头文件**作为聚合器：基础 API/框架编程为 `kernel_operator.h`、SIMD C API 为 `asc_simd.h`、SIMT 为 `asc_simt.h`、AI CPU 为 `aicpu_api.h`，它们做守门检查（防 API 串味）并按 `__NPU_ARCH__` 条件补充架构相关能力（如 `reg_compute` 仅 3510 引入）。关键术语：镜像结构、声明/实现分离、架构子目录、入口头文件。
