本讲承接 u1-l1/l2，讲解 asc-devkit 源码的编译与安装，覆盖三个模块：环境准备、build.sh 编译参数、CMake 工程结构。

环境准备有云开发环境、CANN 官方 Docker 镜像、DevContainer、手动安装四种方式，按「是否有 NPU」与「使用目标」选择，最终目标均为 `set_env.sh` 可被 source、`ASCEND_CANN_PACKAGE_PATH` 指向有效 CANN 目录；CANN 包分 toolkit（必选）与 ops（可选），仅编译 + 仿真不强制安装驱动。

`build.sh` 是 CMake/make/cpack 的封装，`--pkg` 为最常用打包入口（与 `--test` 互斥），`-p` 指定 CANN 路径、`-j` 控线程数、`--pkg-type` 选包格式；CANN 路径查找优先级为「`-p` > `ASCEND_HOME_PATH` > `ASCEND_OPP_PATH` > 默认目录」，脚本与 `cmake/config.cmake` 双重校验。顶层 `CMakeLists.txt` 经 `add_subdirectory(impl)` 挂载 API 实现主体，`--pkg` 通过 `PACKAGE_OPEN_PROJECT` 开关引入 `cmake/package.cmake`（makeself + cpack）产出 `build_out/cann-asc-devkit_*.run`。

`version.cmake` 声明版本 `9.2.0` 并锁定 runtime/metadef/bisheng-compiler 等组件主次版本一致，这是「不能独立升级」的根因；run 包以 `--full` 安装会覆盖原 CANN 中的 Ascend C 内容。
