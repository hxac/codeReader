`.asc` 是 Ascend C 的单源算子源文件，Host（CPU）与 Device（AI Core）Kernel 代码混写在同一文件里，由编译器依据函数限定符自动拆分，而非靠文件物理切分。本讲以 hello_world.asc 和 add.asc 两个最小样例展开，覆盖三个核心模块：文件结构、Kernel 函数限定符、地址空间限定符。关键结论是：Host/Device 的边界由函数限定符隐式划定——带 `__global__` 的为 Device Kernel 入口，无限定符的普通函数（main、kernel_add 等）属 Host。一个合法 Kernel 必须同时具备函数类型限定符 `__global__`（表示「是 Kernel」）与执行空间限定符（`__vector__`/`__cube__`/`__aicore__`/`__mix__`，表示「在哪种核上跑」），两者顺序可互换。地址空间限定符（`__gm__`/`__ubuf__`/`__cbuf__` 等）指明指针指向哪一级物理存储，只能修饰指针，且 Kernel 的指针入参必须用 `__gm__`。本讲引入的关键术语包括：单源混合编译、Host/Device 边界、函数限定符、执行空间限定符、GM/UB 多级存储、`__gm__` 入参约定。两样例中 `__ubuf__` 被 C++ 的 `LocalTensor` 封装隐藏，其裸写形式留待后续 C API 单元。`<<<>>>` 启动语法与 ACL 运行时接口仅作边界标记，细节由后续讲义承接。
