本讲义剖析 ops-math 仓库的组织方式。核心结论：一个算子即一个目录，子目录模板高度统一——`op_host`（算子注册、形状推导、tiling 切分）、`op_kernel` / `op_kernel_aicpu`（AI Core 与 AI CPU 上的 Device 侧计算）、`op_api`（aclnn 用户接口与 L0 接口）、`op_graph` 与 `framework`（图模式与深度学习框架适配）、`tests`（ut 单元测试与 st 系统测试）。许多子目录可选且缺失有含义：缺 `op_api` 表示不支持 aclnn 调用，缺 `op_graph` 表示不支持图模式。算子支持的芯片与 tiling 目录由其 CMakeLists.txt 声明，tiling 文件名须含 `_tiling` 才被编译系统识别。构建链路为 build.sh → scripts 子脚本 → 根 CMakeLists（`ENABLE_TEST`、`ENABLE_EXPERIMENTAL` 等开关）→ 各算子 CMakeLists。`classify_rule.yaml` 划分组件并声明 release/unrelease 交付范围，是判断源码是否随商用包发布的权威依据。`common/` 按同分层共享公共代码，`docs/zh/` 按 install/invocation/develop/debug/context 分类，`experimental/` 存放用户自定义算子。引入的关键概念：Host/Device 分工、AI Core 与 AI CPU、aclnn 接口、图模式、tiling。
