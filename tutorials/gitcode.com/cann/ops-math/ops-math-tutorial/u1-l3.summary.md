本讲围绕三个最小模块讲清 ops-math 的构建体系：build.sh 总入口、scripts/ 子脚本分工、CMake 构建体系与产物。核心结论：环境分「编译态」（仅需 CANN toolkit 包）与「运行态」（还需驱动与 CANN ops 包），编译前必须 source set_env.sh 使 ASCEND_HOME_PATH 生效，否则头文件与库路径为空；官方提供 CANNLab、Docker、手动、Spack 四种搭建方式。build.sh 是纯编排层，source 八个子脚本后由 main() 按 ENABLE_* 开关依次执行建库、编 kernel、打包、测试、样例、脚手架阶段。参数流水线为：checkopts 解析校验（含互斥规则与 set_create_libs）→ assemble_cmake_args 把开关翻译成 -D 参数 → cmake_init 配置 → 逐目标构建。根 CMakeLists.txt 的 option 与 -D 参数一一对应，--ops= 经 ASCEND_OP_NAME 只挂载指定算子，--jit 模式跳过 kernel 二进制编译，测试模式固定 -O0 -g 而发布模式默认 -O2 Release。产物分层：build/ 为 CMake 工作目录（含 kernel 日志），build_out/ 存放最终 run/rpm/deb 包且每次打包前被清空。关键术语：Host 与 Device、编译态与运行态、soc 芯片型号、run 包、ASCEND_HOME_PATH。本讲产出的 run 包（如仅编 add_example）将供下一讲安装并运行 AddExample，走通编译到调用的链路。
