本讲梳理 ATVOSS 的测试体系。tests/ 分两大类：UT（单元测试，Host 侧、gtest、跑得快，成功标志为 PASSED）与 ST（系统测试，端到端走 ACL 全链路、在 NPU 真机或 cannsim 仿真器上验精度，成功标志为 Accuracy verification passed），二者由 scripts/build.sh 的 --host_ut / --st 等互斥模式统一驱动。UT 又分四子类：host/ 用 std::is_same_v 做编译期类型断言，把表达式线性化结果、TypeList 去重、tiling 结构体（56 字节）等编译期不变量钉成可断言事实；builtin_kernel 用 ICPU_RUN_KF 在 CPU 上仿真执行 kernel 并校验数值；builtin_tiling 仅验 tiling 计算；compile_perf 用 chrono 度量 bisheng 编译 120 节点大表达式的墙钟耗时，以 EXPECT_LE 守护编译期性能基线，并佐证 MemMngPolicy::AUTO（约 50s）快于 MANUAL（约 90s）的编译期红利。ST 按文件名分 test_op_/test_compute_/test_tile_rms_norm_/test_block_cast 四大维度，CMake 用 file(GLOB) 自动把每个 test_*.cpp 建为独立 NPU 可执行文件；所有用例共用「Config（封装 Compute + 三级 Builder）+ Run() 十步 ACL 样板 + RAII 释放」的固定模式，算子差异被压缩到 Compute() 一行公式与 golden 值。引入的关键术语：UT/ST、gtest、bisheng、--npu-arch=dav-2201/dav-3510、cannsim、ICPU_RUN_KF、ASCEND_HOME_PATH、compile_perf、MemMngPolicy。
