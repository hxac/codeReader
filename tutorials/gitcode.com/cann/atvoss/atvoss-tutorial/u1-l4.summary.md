本讲以 abs 样例拆解 ATVOSS 的用户编程模型，覆盖三个最小模块。其一，`Config` 结构体是算子的「配置清单」，自顶向下填入 Dtype、TileShape（`Atvoss::Shape<int...>` 编码在类型里的编译期形状，决定 Block 层一次 Tile 处理的数据量）、单核 blockPolicy、多核 kernelPolicy（默认 UniformSegment 均匀切分）、目标架构 ArchTag（DAV_3510）。其二，`Compute()` 是用户唯一写计算逻辑处，用 `PlaceHolder<N, Tensor<T>, ParamUsage>` 声明入参/出参（序号 N 与运行时 `ArgumentsBuilder` 参数顺序一一对应，ParamUsage 取 IN/OUT/IN_OUT），用 `return (out = ...)` 写公式——`=` 与数学函数均为被重载的 constexpr，构造的是编译期表达式 AST（如 `Expression<OpAssign<...>>`），而非运行时赋值。其三，三级 Builder 层层套娃：`BlockBuilder<Compute>` → `KernelBuilder<BlockOp>` → `DeviceAdapter<KernelOp>`，对外暴露 `deviceOp.Run(arguments, stream)`，内部经 PrepareParams、CalculateTiling（Host 侧一次性算核间+核内 tiling）、LaunchKernelWithDataTuple（用 `<<<blockNum>>>` 启动 `KernelCustom`）三步。核心结论：ATVOSS 实现极简编程，算子差异被压缩到一行公式，新增算子通常只需改 `Compute()` 的 return 表达式与 golden 校验值。
