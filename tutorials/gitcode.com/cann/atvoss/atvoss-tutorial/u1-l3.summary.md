本讲建立 ATVOSS 的「整体地图」：自顶向下分为 Device、Kernel、Block、Tile、Basic 五层，抽象程度递减，目的是让开发者只描述计算逻辑，把多核切分、Tiling、流水同步交给框架。Device 层跑在 Host CPU，其余四层跑在 NPU 的 AI Core 内，`KernelCustom<<<blockNum>>>` 是跨 Host/Device 边界的唯一跳板。header-only 主入口 `atvoss.h` 用 5 个 `#include` 一一对应五层，其中 Basic 层对应外部 CANN SDK 头文件 `kernel_basic_intf.h`，不在本仓库内。三层 Builder 以模板参数嵌套组装：`BlockBuilder<Compute>` → `KernelBuilder<BlockOp>` → `DeviceAdapter<KernelOp>`，用户真正填写的只有计算表达式 `Compute`。`DeviceAdapter::Run` 走 PrepareParams → CalculateTiling → LaunchKernel 三步，其中 `CalculateTiling` 在 Host 上一次性算出核间（Kernel）与核内 Tile（Block）两层切分，且 Block 依赖 Kernel 的结果。最底两层 Tile 与 Basic 通过「递归求值 + 模板特化」把表达式翻译成 Ascend C API（如 `DataCopyPad`），由 `Evaluator<Expr>` 驱动；全部调度最终受 `arch.h` 中 `CORE_NUM`、`UB_SIZE` 等硬件常量约束。
