本讲梳理 ATVOSS 的「目录 + 构建 + 运行」工程链路，不涉及算子计算逻辑。仓库骨架为：include/（框架本体，header-only 头文件库，用户只需 include atvoss.h）、examples/（abs/muls/rms_norm 等样例）、tests/（ut 主机侧单测与 st 仿真侧系统测试）、scripts/build.sh、docs/，cmake/ 提供公共片段。顶层 CMakeLists.txt 只做「定环境 + 挂子工程」：强制 C++17、默认 SOC=ascend950、引入 CANN 工具链，再 add_subdirectory 挂载 examples 与 tests。本讲引入的关键术语：CMake（构建系统生成器，configure/build 两步）、target（构建目标）、SOC（昇腾芯片型号，仅支持 ascend950，映射 --npu-arch=dav-3510）、bisheng 编译器（取代 gcc）、cannsim 仿真器、ASCEND_HOME_PATH（指向 CANN 安装目录，编译硬性前置）。scripts/build.sh 以互斥的 MODE 编排行为：--example 编样例、--host_ut 编并跑主机侧单测、--st 编系统测试、裸名走 legacy。产物分两层：中间产物在 build/，最终可执行文件经 cmake --install --component 落到 output/bin/<name>。运行分真机与 cannsim 仿真两种，成功标志为 Accuracy verification passed。
