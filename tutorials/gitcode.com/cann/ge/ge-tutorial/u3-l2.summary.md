本讲深入 OnnxModelParser::Parse 内部，揭示 ONNX 文件如何变成 AscendIR。核心矛盾是连边表达方式的翻译：ONNX 靠张量名隐式匹配建边，AscendIR 靠 Anchor 显式互引。解析由 ModelParseToGraphImpl 的 12 步驱动：先逐 NodeProto 建孤立 Operator（经 AdapterOpType 做算子类型映射、OperatorFactory::CreateOperator 创建、OpParser 解析参数），再用 inputs_map_ / outputs_map_ 两张表按张量名回填 Anchor 边；因 ONNX 节点不保证拓扑序，必须先建好全部节点再统一连边。权重分三类：内联常量（Constant/initializer）由 OnnxConstantParser 将 TensorProto 转 ge::Tensor 写入 value 属性，成为 Const 节点；外置权重（external_data）由 OnnxFileConstantParser 只记路径不读数据，成为 FileConstant 节点；模型输入由 OnnxDataParser 合并 --input_shape 成为 Data 节点；数据类型统一经 OnnxUtil::ConvertOnnxDataType 查表转换。子图适配通过 SubgraphAdapterFactory 按 op_type 派发 adapter，用 BFS 摘取 If 等控制流算子嵌套在属性里的 GraphProto，任务队列递归复用同一套 12 步解析，再经 NodeUtils::SetSubgraph 挂回父节点；IfSubgraphAdapter 还负责补全子图引用父图张量所带来的跨图输入。根图与子图共用该流程，仅以 is_subgraph 标志区分少数步骤。
