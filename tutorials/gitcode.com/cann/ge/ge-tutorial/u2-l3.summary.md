本讲义聚焦 AscendIR 中算子描述对象 `OpDesc`，回答"一个算子由什么描述、属性如何存取、张量元信息放在哪"三个问题，是衔接四层模型 `ComputeGraph → Node → OpDesc → GeTensorDesc` 的核心一讲。

`OpDesc` 承载算子的实例名 `name`、类型 `type`、输入输出 `GeTensorDesc` 列表及一袋可扩展属性；它只描述算子规格，不含计算实现（实现在外部算子仓，按 `type` 查注册表）。全栈采用 Pimpl 模式，对外仅暴露 `impl_` 指针，getter 均委托给 `*Impl`，以保二进制兼容。`Node` 通过 `GetOpDesc()` 持有它，读算子信息皆由此入口。

属性体系以基类 `AttrHolder` 为地基，`OpDesc`、`GeTensorDesc` 等均继承之。提供两层 API：底层 `SetAttr/GetAttr` 操作类型擦除的 `AnyValue`；工程实践统一用带类型的 `AttrUtils::SetInt/GetInt` 等，且 **Get 系列必判返回值**（属性不存在或类型不符均返回 false）。属性分两类：经 `SetAttr` 写入的会被序列化进 IR/OM；经 `SetExtAttr` 写入的仅在内存存活、不序列化。

张量方面，`GeTensorDesc` 是"只有元信息没有数据"的描述，核心为 `GeShape`/`DataType`/`Format`，每类均保留 origin 版本以追踪用户初值；动态 shape 以维度值 `<0`、`-2`（秩未知）及 `SetShapeRange` 表达。`GeTensor = GeTensorDesc + TensorData`，编译期用前者，权重常量等真有数据场景才用后者。
