本讲讲清 atc 的完整主流程。atc 是 GE 的离线编译入口，本质是调度层（不做编译算法），职责为：解析命令行 → 组装 GE 选项 → 调 parser 翻译成 AscendIR → 把图交给 GeGenerator。三个最小模块：①入口与选项——main.cc 转调 main_impl，经 getopt_long 将 --model/--framework/--mode 等解析进 FLAGS_* 全局变量，atc_option_map 维护命令行名与 GE 内部选项名的对照表；②omg 主流程——RunAtcByMode 按 RunMode 枚举路由，生成 OM 类经 GenerateOmModel → GenerateModel → GenerateModelBySingleGraph，其中 ParseGraph（omg.cc）用 ModelParserFactory/WeightsParserFactory 将 ONNX/Caffe/TensorFlow 翻译成 AscendIR，是 atc 与 parser 工厂体系的唯一衔接点；③产物由 mode 决定：默认 .om、mode7 .om2、mode30 .exeom，mode1/5/6 只读不编、mode3 仅产预检报告。最终经 GeGenerator::GenerateOfflineModel 进入编译器四阶段。
