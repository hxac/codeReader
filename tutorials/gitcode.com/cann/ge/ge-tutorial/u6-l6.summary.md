本讲介绍 GE 运行时的第三条执行路径 OM2——一种"把编译产物再编译一遍"的离线模型格式：编译器用 codegen 将整张 GeModel 翻译成 C++ 源码、编成 `lib<模型名>_om2.so`，再与元数据 json、常量、变量、kernel 二进制一起打包成标准 ZIP 归档（复用魔数 `PK\x03\x04`）。运行时用 `IsOm2Model` 判定后，按 ZIP 内路径前缀（`/runtime/*.so`、`model_meta.json`、`data/constants/`、`data/variables/` 等）分派反序列化到 `Om2ModelData`。核心执行器 `Om2ModelExecutor` 通过 `memfd_create` 造匿名文件 → `dlopen` → `dlsym` 解析出 `Om2ModelCreate/Load/Run/RunAsync/Destroy` 五个函数指针，构成 host 与 generated so 的唯一契约；执行层极薄，Create 装配 work_ptr/constants/var_addrs、Load 注册资源、之后每次推理仅调用 run_func。`Om2RTVarManager` 按 session_id 隔离管理 Variable 全生命周期，`GetVarDevAddr` 按 extern 地址→外部池偏移→现分配三级优先懒分配，数据搬运分 init_data 内嵌、trans_road 转换、copy_info 拷贝三条路径，转换用 16 线程池并行。本质差异：v1 解释数据、v2 运行期再组织图、OM2 直接执行编译出的原生代码，运行时开销最低。
