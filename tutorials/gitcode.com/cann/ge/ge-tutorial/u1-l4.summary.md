本讲是入门单元收官，把 GE 离线端到端链路整体跑通：下载 ONNX → 用 atc 编译成 OM → 用 ACL 接口加载 OM 执行推理 → 取回结果。前两步在普通主机完成、不需昇腾卡，后两步才需设备，印证了 GE「编译与执行分离」的设计；OM 正是连接编译侧（GE Compiler）与执行侧（GE Executor/ACL）的产物。

讲义先介绍 examples/ 按「场景分目录」组织，ACL 运行时样例集中于 examples/acl/，用「数字前缀+场景」命名、由浅入深排列。再以 ResNet50 为例拆解出 ACL 推理的完整生命周期——aclInit → setDevice/createContext/createStream → querySize/malloc/loadFromFileWithMem/getDesc → memcpy/execute/memcpy，其中 aclmdlExecute 同步触发整模型下沉执行、aclrtGetRunMode 判断 Host/Device 以决定输出是否需拷回主机。Qwen LLM 样例执行骨架与之相同，差异集中在 atc：必须显式写 --input_shape（含 input_ids 与大量 KV Cache 输入），并加 --precision_mode=must_keep_origin_dtype、--external_weight 等精度与权重参数。

引入的关键术语：ACL（Ascend Computing Language，应用调用 GE 的用户侧 C 接口）、OM（离线模型产物）、modelId、Context/Stream、KV Cache、Host/Device 数据搬运。本讲把 atc 当作命令行黑盒，其内部实现留待单元 3 解析器框架与 ATC 工具链展开。
