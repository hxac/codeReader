本讲是手册收官，以假想算子 MyAdd 串联 metadef 三类扩展点完成端到端闭环：用 ops::OpDef 链式 API 定义算子原型（输入/输出/属性，SetInferShape 挂在 OpDef 本体、SetTiling 挂在 AICore 子对象）；用 IMPL_OP（OpImplRegisterV2）注册 InferShape/Tiling 等阶段函数指针，注册发生在静态对象拷贝构造瞬间且必须同一条链，跨 so 经 GetRegisteredOpNum→GetOpImplFunctionsV2 两步 C 协议取数；用 OpTilingContextBuilder 按槽位配方（输入段＋5 隐藏槽＋tiling 输出段）在宿主内存装配 TilingContext，Builder 写入与上下文读取互为镜像，单测可离线驱动 tiling/infer 函数并断言 TilingData。核心结论：三类扩展点均为头文件＋动态库公共接口，零源码修改即可闭环；只有跨仓公共需求且保持 ABI 兼容（新字段从 reserved_ 尾部切出、st_size/version 自动上报）才应改 metadef，且须 Issue 先行、run_test.sh -u 全通过。
