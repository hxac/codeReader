本讲承接 u4-l4，补齐算子实现 so 从磁盘被发现到进入全局注册表的下半程链路。核心模块有三：一是 `OppSoManager` 负责「找 so」——按 `OppImplVersionTag` 版本维度搜索 opp 包中 op_proto 与 op_impl 两类目录，区分自定义算子（vendors 下全部 .so，优先于内置）与内置算子（按拆分模式选 ct.so/rt.so/rt2.0.so），按包名聚合为 `OppSoDesc`，且 `_legacy.so` 恒排最后以保证新实现优先注册。二是 `AddSoToRegistry` 负责「装 so」——以 so 文件内容为 key 去重后 `mmDlopen(RTLD_NOW|RTLD_GLOBAL)`；关键结论是注册触发没有显式 Init 回调，而是 dlopen 瞬间静态对象构造完成 so 内注册，框架再经 dlsym 两步协议（`GetRegisteredOpNum` → `GetOpImplFunctionsV2`）把注册表拷出，按「先到先得、不覆盖」合并进 `OpImplSpaceRegistryV2`；成功加载的 so 永不 dlclose，失败仅告警不阻断。三是 `OpBinInfo` 反向把内存中的自定义算子交付件落盘为 opp 目录并用三个符号链接伪装交付件，形成安装-发现-加载闭环。关键术语：opp 包、`OppSoDesc`、两步取数协议、内容去重，后续 u5-l2 插件管理将承接 `PluginManager`。
