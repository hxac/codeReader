本讲剖析 metadef 属性体系的地基——`ge::AnyValue`（别名 `GeAttrValue`）与 `TypeId` 类型擦除机制。核心模块三块：其一，TypeId 双轨发号体系：TypeId 为指针大小的值，22 种预定义属性类型（bool、string、int64_t、GeTensorDesc、NamedAttrs 及各 vector 组合）由 `base/any_value.cc` 特化分配固定整数 1~22，保证跨 so 稳定；其余类型用 `TypeIdHolder<T>::id` 静态变量地址发号，仅同 so 内可靠，`remove_cv/reference` 归并 cv 与引用差异。其二，AnyValue 存储：16 字节固定布局（8 字节联合体 + 8 字节函数指针），sizeof≤8 的小对象 placement-new 内联、大对象 nothrow 堆分配，拷贝为深拷贝；Clear/GetAddr/Clone/Move/GetTypeId 五种运行期操作统一由函数指针 `operate_` 分发，其为 nullptr 即空值。其三，安全取值：`SameType<T>` 先对质 TypeId，`Get<T>` 失败返回 nullptr、`GetValue` 失败返回 GRAPH_FAILED，不崩溃；`GetValueType()` 查表把 TypeId 译成语义枚举 ValueType（列表 = 1000 + 标量），未登记类型（如 double）可存取但返回 VT_NONE。ValueType 是序列化契约，只能尾部追加。该 16 字节类型无关布局是 AnyValue 可跨 ABI 边界传递的原因，为后续 GeTensorDesc、NamedAttrs 及张量体系讲解铺垫。
