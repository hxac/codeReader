本讲剖析 RDMA 传输层与 QP 管理。TT_HCCP 引擎在编译期分派两版实现：V1（RdmaTransportManager）走 HCCP RA 手工建链，面向非 950 平台；V2（RdmaTransportManagerV2）走 HCOMM endpoint/channel 模型，面向 Ascend950。建 QP 由三层抽象承担：基类 DeviceQpManager 负责 server socket 创建与端口递增自动分配；FixedRanksQpManager 面向对等全互联，小 id 当 server、大 id 当 client，n 个 rank 共 n(n-1) 条 QP 且启动后 rank 集合不可变；DynamicRanksQpManager 面向 SENDER/RECEIVER 角色，由后台线程按任务增量建链、增量注册 MR。关键术语：QP（SQ/RQ/CQ 队列、WQE、RC 可靠连接语义）、MR 与 lkey/rkey、下发 device 供 kernel 直驱的元数据 AiQpRMAQueueInfo。本轮更新使能 950 多 QP：qpNum 经 aclshmemx_set_qp_num 与 TransportOptions 的 rdmaQpConfig 传入 V2，按每 peer q 条 channel 建链（仅 XSCALE 后端支持），并用 bootstrap allgather 强制全组 QP 数一致，不一致即初始化失败；多 QP 缓解单条 RC QP 按序提交瓶颈，小消息带宽显著提升，device 侧队列索引为 remoteRank×qpNum+qpIdx。
