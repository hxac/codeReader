本讲围绕 Function 基类与 DependenciesFinder 两个最小模块展开源码精读，讲清 pyasc 缓存 key 的来源。Function 在装饰时（即模块导入时）一次性抓取源码、AST、起始行号与函数身份，剥掉装饰器后解析为 FunctionDef，进程内源码视为不可变；不带中括号的直接调用则按普通 Python 语义直通。cache_key 惰性计算且只算一次，由源码哈希、起始行号与 ConstExpr 全局依赖清单共同哈希而成，仅参与文件缓存 key，内存缓存 key 只由 cache_factors 决定。DependenciesFinder 以 AST 访问器遍历源码，把引用的全局值快照记入 used_global_vals，并将被调 @asc.jit 子函数的 cache_key 递归混入自身哈希，实现缓存的传递失效与同名全局冲突检测。最重要的陷阱：普通全局变量改值不进任何缓存 key，也没有启动校验，旧 kernel 会被静默复用；安全做法是用 ConstExpr 包装或改为 ConstExpr 形参传入。
