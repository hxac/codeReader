本讲从读者切换为贡献者视角。pyasc 测试分四层：unit 层用 mock_launcher_run 打桩 Launcher.run，仅验证编译链产出合法 Ascend C、不校验数值；kernels 层真执行并与 numpy 对拍；generalization 层参数化 dtype×shape×backend、默认 NPU、与 torch 对拍；后端用 lit+FileCheck 断言发射文本——各层只承诺一件事。build_llt.sh 是测试总入口，支持覆盖率与按 PR 文件列表的精准触发（文档跳过、公共路径全量、单模块精准、未知兜底），exit 200 表示无需测试。developer_guide 把新增接口拆为五层改动：前端三段式（overload 存根、@require_jit 实现、create_asc_*）、UT 与 API 资料为必需交付件，td 定义常已就绪，AST/pybind 与手写发射仅特殊场景需要；Prelu 等后端就绪、独缺前端封装的算子是最小改动清单的实战靶子。贡献按 L1/L2/L3 分级，新 API 接口属 L1：Issue→PR→compile 门禁（编译、静态检查、UT、冒烟）→检视合入，提交前用 pre-commit、ruff、yapf 自检。
