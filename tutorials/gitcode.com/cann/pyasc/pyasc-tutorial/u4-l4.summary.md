本讲核心是 visit_Call 的分岔：被调对象为 Function 实例时转入 call_jit_function 内联子函数，否则在编译期直接执行，asc.add 等基础 API 靠此向 IR 追加操作。子函数调用先绑定实参并按其自身标注分流 ConstExpr，运行时实参包装为 IRArgType（仅 IRValue 能跨 JIT 函数传递），递归访问子函数 AST 后生成同模块 FuncOp 与调用点 CallOp。「内联」有两层：IR 层子函数与 Kernel 同模块共处，发射层给无 asc.global 属性的函数打 always_inline 前缀，真内联由毕昇编译器完成。is_kernel 标志决定三种差异：符号可见性（Kernel 公开为 extern "C" __global__，Device 函数私有）、return 规则（Kernel 禁止返回对象）、选项作用域（default_options 仅 Kernel 启动路径读取）。同名子函数按名去重只生成一次，二次调用的 ConstExpr 实参被忽略。
