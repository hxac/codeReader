本讲聚焦 `python/asc/language/core/ir_value.py`，讲清 pyasc 前端如何用 Python 对象代表 IR 值。核心是双层设计：下层 `IRHandle` 是 pybind11 暴露的 `ir.Value` 裸句柄，负责与 builder 交互；上层 `IRValue` 抽象类通过 `from_ir`/`to_ir` 协议包装句柄，使其携带 dtype、参与 Python 表达式，PlainValue、GlobalAddress、Array、Tensor 均实现该协议。`PlainValue` 表示设备侧标量的延迟求值：编译期只有类型与 IR 节点，值在核运行时才确定；`RuntimeInt`/`RuntimeNumeric` 类型别名让 API 参数位同时容纳 IR 值与 Python 立即数，纯 Python 常量间运算不产生 IR。`GlobalAddress` 代表 Host 传入的设备指针（torch.Tensor 经 PointerArgType 包装而来），其加法生成指针偏移而非算术加法，由 `set_global_buffer` 消费。`materialize_ir_value` 是统一物化漏斗，`require_jit` 与 `global_builder` 把守 IR 创建时机。关键结论：PlainValue 整数是定宽回绕的 SSA 值，比较结果是 int1，不能用普通 Python int 语义理解。
