本讲剖析 pyasc 基础 API 层（language/basic 目录），覆盖四个最小模块：require_jit 装饰器与 global_builder 单例构成守门机制，把 data_copy 与 vec_* 算子约束在 JIT 编译期调用；OverloadDispatcher 按注册顺序对参数做类型试配，弥补 Python 无运行时重载的缺口；add/sub/mul 等双目算子遵循「overload 声明、op_impl 统一委托、builder 创建 IR」三段式，并引入 L0/L1/L2/L3 分级——L2 连续 count 形态最常用，L3 为张量运算符重载；data_copy 以 7 个候选支持 count、块参数、切片、ND↔NZ 等搬运形态，方向由 dst/src 张量类型组合决定，参数结构体（如 DataCopyParams）构造时即生成 ConstructOp 节点。核心结论：pyasc 接口按「运行时必选、模板必选、运行时可选、模板可选」顺序映射 Ascend C 原型参数，模板参数一律改为运行时参数。
