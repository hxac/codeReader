pyasc 用两级缓存避免重复 JIT 编译：进程内是各 JITFunction 私有的 `kernel_cache` 字典，跨进程是 `FileCacheManager` 以 pickle 把编译产物 `CompiledKernel` 落盘为「函数名.o」，`_cache_kernel` 按「查内存→查文件→未命中才编译并写回」推进。缓存 key 源自五要素 `cache_factors`：两类编译选项（CodegenOptions、CompileOptions）、ConstExpr 的值、运行时参数的类型、函数名；ConstExpr 值会被烘进生成的 Ascend C 代码故必须进 key，运行时参数只影响下发数值故仅类型进 key。文件缓存 key 还编入源码身份哈希（Function.cache_key）与工具链指纹 `pyasc_key()`（逐文件哈希 codegen/language 全部模块与 libpyasc 扩展），故升级 pyasc 后旧缓存整体失效；落盘采用 pid+uuid 临时目录加 `os.replace` 原子改名，读者不会看到半截文件。`always_compile=True` 经三道闸门跳过两级缓存的读与写，且其自身参与 key 形成双重隔离，强制重编对正常缓存零污染。注意：文件命中时不回填内存缓存，是当前实现的特征。
