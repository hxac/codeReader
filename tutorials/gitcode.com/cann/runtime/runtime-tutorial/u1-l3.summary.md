本讲解决「代码都在哪」，将前两讲的分层架构与编译链路落成具体目录地图。仓库顶层按角色分四类：源码（src）、接口发布（include 对外头文件、pkg_inc 仓间管控头文件）、学习验证（example、tests、docs）、构建合规（build.sh、CMakeLists.txt、cmake、scripts、stub 等）。src/ 分四大板块：ACL 对外 API 层（src/acl）、Runtime 核心层（src/runtime，含 api/core/driver/feature/config）、维测组件（src/dfx）、支撑模块（platform、mmpa、tsd 等）；src/CMakeLists.txt 的 add_subdirectory 顺序即权威依赖地图，被依赖者先编、ACL 出口层最后编。核心方法论是接口定位六站口诀「声明在 include、登记在 wrapper、导出在 aclrt、实现在 impl、转译在 api、干活在 core」，以 aclrtSetDevice→rtSetDevice→Api::SetDevice→ApiImpl::SetDevice→DriverFactory 示范；关键机制包括 ACL_RT_FUNC_MAP 宏清单批量生成导出符号、Api 纯虚接口契约支持多平台实现替换。example 按难度七级分类、tests 按 13 个模块组织（build_ut.sh 的 ut_path_map 为查询表）、docs 按读者层次五类组织。另注意 src/runtime/config 下数字目录是芯片平台代号而非版本号。
