本讲打通源码到软件包的编译全链路，分为五个最小模块：依赖安装、编译入口、顶层构建逻辑、第三方依赖获取、产物安装与环境变量。install_deps.sh 检测并安装 python、gcc、cmake、ccache 等基础工具；build.sh 是编译外壳，解析参数后执行 cmake 配置、编译、打包三步，产物为 build_out 下的 run 包；顶层 CMakeLists.txt 是骨架，引入 cann-cmake 框架，按依赖顺序编译 acl、runtime、dfx 等模块，ENABLE_UT 决定是否编测试，TOOLCHAIN_DIR 决定 Device 侧交叉编译；第三方依赖遵循本地优先、在线兜底，离线用 download_3rd_party.py 预下载并经 CANN_3RD_LIB_PATH 传入。核心结论：run 包是替换件而非独立软件，安装后覆盖已装 CANN 的 Runtime 组件，验证依赖 npu-smi info 与 ascend_toolkit_install.info；编译前需 source set_env.sh 使 ASCEND_HOME_PATH 生效，供 build.sh 定位已安装的 CANN 头文件与库。
