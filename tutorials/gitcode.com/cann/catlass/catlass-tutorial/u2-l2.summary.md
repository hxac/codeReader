本讲承接 u2-l1，拆解 `00_basic_matmul` 中那串 `using` 别名，建立 CATLASS「五步组装」自底向上的完整范式：`BlockMmad`（计算砖块）→ `BlockEpilogue`（后处理，本例用 `void`）→ `BlockScheduler`（分核与 Swizzle）→ `BasicMatmul`（Kernel 组合）→ `DeviceGemm`（Host 适配器）。

覆盖三个最小模块：① `BlockMmad` 组装，用 `DispatchPolicy`、`L1TileShape`/`L0TileShape`（`GemmShape<M,N,K>` 编译期常量）、以及由 `GemmType` 把元素类型与布局绑定成的 `AType/BType/CType` 六参数构造单核 K 主循环，其中 `DispatchPolicy::ArchTag` 会自动驱动底层 `TileCopy`/`TileMmad` 的挑选。② `BasicMatmul` 组合，引入用户层 `Arguments`（仅 problemShape 与指针）与 Kernel 层 `Params`（含 layout）两层结构，靠 `ToUnderlyingArguments` 桥接；设备侧 `operator()<AIC>` 以 SPMD 步长循环把 C 块分给各核，`AIV` 特化负责后处理。③ `DeviceGemm` 包装，通过 `CanImplement`/`GetWorkspaceSize`/`Initialize`/`operator()` 四接口转发 Kernel 能力，最终以 `<<<aicCoreNum>>>` 派发到 NPU。核心结论：换需求即换参数，链路闭环为 Host 类型组装 → `Arguments` → `Initialize` 转 `Params` → 派发 → SPMD 循环 → `blockMmad`，Tile/Basic 留待 U5。
