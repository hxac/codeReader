本讲围绕 `0_get_pcie_info` 样例，讲清 DCMI 查询程序的「三段式」调用链。四个最小模块：(1) 样例按「功能大类→序号子目录→main.c」三级组织，统一 `run.sh` 用 `bash run.sh <别名> <前缀>` 编译运行；(2) `dcmi_init()` 无参初始化，返回 0 成功，是一切查询前提；(3) `dcmi_get_card_num_list()` 枚举全部 NPU 卡，返回卡数量与 `card_id` 列表（上限 64）；(4) `dcmi_get_device_pcie_info()` 按「卡号+设备号」把厂商/设备 ID 与 BDF 三元组填入 `struct dcmi_pcie_info`。关键术语：卡(card_id)与设备(device_id)之分、一卡一芯片约定（device_id 固定 0）、BDF（总线/设备/功能）PCIe 地址、`NPU_OK` 错误码宏、每调用后的返回值检查、`-ldcmi` 链接动态库。核心结论：DCMI 查询样例都是「初始化→枚举卡→循环查某类信息」同一套模板，换接口换结构体即得新功能，样例代码与 `dcmi_interface_api.h` 中的接口和结构体定义直接映射。
