本讲义讲两套内核/用户态调度组件。**ts_agent（任务调度代理）**是 Host 内核态模块，仅在 SR-IOV 虚拟化场景出现：模块加载时只做装配，把 `vf_create/vf_destroy/vsq_proc/trans_mailbox_msg` 等回调注册给 trsdrv，自身被动响应。trsdrv 发现有新任务即回调 `schedule_vsq_work`，按「设备→VF→TS→VSQ」四级定位到「每条 VSQ 一个单线程工作队列」，由工作线程 `proc_vsq` 遍历 head→tail，逐条 `memcpy→convert_task→sq_write→irq_trigger`，出错不中断以避免丢失 CQ 上报；同条 VSQ 串行、不同 VSQ 并行。**核心动作是虚拟→物理 ID 翻译**（stream/event/notify/model），全部汇聚到 `hal_kernel_hvtsdrv_resid_v2p`。**esched（事件调度）**用「组—线程—事件」三要素加 submit/wait/ack/subscribe 原语提供设备侧并发同步，所有 `halEsched*` 接口经 `esched_dev_ioctl` 下发到字符设备 `/dev/event_sched`，并用 pthread_key 每线程等待链表实现完成回调、attach 引用计数管理进程绑定、`event_sched_app.c` 提供类 RPC 的同步事件。**二者协作关键**：esched 事件经 `esched_topic_sqe` 打包成 topic SQE 复用 u6-l3 的 TRS SQ/CQ 数据面，且 ts_agent 翻译的 event id 与 esched 共用同一 trsdrv 资源空间（`TSDRV_EVENT_SW_ID`），使任务面与事件面语义对齐。裸机场景下 ts_agent 不参与，Runtime 直接写物理 SQ。
