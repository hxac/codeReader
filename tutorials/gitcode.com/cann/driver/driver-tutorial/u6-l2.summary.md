本讲讲解 SDK-driver 内核态的 `platform` 模块——一个把硬件资源从「发现方」搬运到「使用方」的资源登记中转站。核心模型为**生产者 → 仓库 → 消费者**：生产者读取中断、寄存器基址、预留内存并命名写入，消费者按名/类型读回后再做 `ioremap`/`request_irq`。

生产者按硬件形态分两份：`soc_platform.c`（NEAR/SOC 形态）由 UDA 通知回调驱动，属「注册表风格」，直接调 `soc_resmng_set_*` 登记；`tsdrv_parse.c`（PCIe Host/DC 形态）属「结构体风格」，把结果填进 `devdrv_ts_pdata`。前者更解耦、可扩展，后者紧凑、读写快，差异反映架构演进。中央仓库 `soc_resmng` 以 `(devid, 子系统, subid)` 为主键：寄存器与内存按字符串名字存（链表，O(n)），中断按 `(类型, 下标)` 存（数组，O(1)）。中断区分硬件 vector id 与 Linux IRQ 号两层编号。

关键术语：`soc_resmng` 仓库、UDA 通知回调、`TS_SUBSYS`、`TS_SQCQ_MEM`、`devdrv_ts_pdata`、`KA_EXPORT_SYMBOL_GPL`。消费者 TRS、esched、mailbox 与生产者仅靠约定名字握手。
