本讲把视角从用户态下沉到内核态：`sdk_driver` 编译为内核模块 `.ko`，与用户态 `ascend_hal`（`.so`）经 `ioctl` 跨态通信，而 `kernel_adapt` 是其中唯一直接调用 Linux 内核 API 的适配底座，其余业务子模块只调它经 `EXPORT_SYMBOL_GPL` 导出的 `ka_*` 符号，从而与内核版本解耦。它用三种机制屏蔽版本差异：`LINUX_VERSION_CODE` 宏分支（主力）、`IS_ENABLED(CONFIG_*)` 配置门控、`conftest` 编译期探测（兜底发行版回移植）。最小模块包括加载时建系统 RAM 红黑树的入口、以「薄封装」逐符号导出稳定接口的 `ka_base`、适配 mm 子系统高漂移（mmap 锁改名、pin/get_user_pages 多级签名演进、vm_flags 原子化、4→5 级页表）的 `ka_mem`，以及体量最大、差异最剧烈、适配设备模型与 VFIO/mdev 虚拟化栈的 `ka_driver`。关键术语有 `ka_*_pub.h` 公共头、薄封装、VFIO/mdev、算力切分底座，为后续 vascend、vmng 讲义承接。
