本讲聚焦 HAL 层公共基础库 **PBL**（`src/ascend_hal/pbl/`，含 uda/urd/commlib/queryfeature/ubmm）中最底层的 **UDA（统一设备接入）** 模块。UDA 解决的核心问题是「设备号多命名空间」：同一张 NPU 在应用视角（逻辑 devid）、内核/物理槽位（phy_devid）、跨主机全局唯一（udevid）、算力切分虚拟设备（vdev）下编号不同，UDA 充当它们之间的枚举器与翻译官。代码分两层：`uda_user.c` 是极薄的公共 API 门面，把 `ascend_hal_base.h` 声明的 `drvGetDevNum`/`drvGetDevIDs` 等稳定符号转调到内部实现；`uda_user_kernel_api.c` 是实现核心，经字符设备 `/dev/davinci_manager` 与 `UDA_*` ioctl（命令定义在用户/内核共享的 `uda_cmd.h`）从内核取回并缓存设备表 `logic_dev[]`。关键工程手法包括双检锁懒初始化、fork 安全（pid 检测重开 fd）、EINTR 重试、errno→drvError_t 映射，以及对 admin/docker 可见性与 milan/obp 平台差异的屏蔽。核心结论：**UDA 是 HDC 通信的「寻址层」**——它不收发消息，但把应用给的逻辑号翻译成设备认识的全局唯一身份，上层模块（SVM/DSMI/DMS 等）再据此用 HDC 路由到正确 NPU。
