本讲聚焦 DMC 中最贴近排障的日志子模块 logdrv，确立昇腾驱动的「三层日志模型」：应用类日志（Host 用户态自产自销，经 syslog/slog 输出）、Host 内核态日志（内核模块产生）、Device 系统类日志（NPU 固件产生，msnpureport 导出），排查应自上而下逐层下钻。核心模块有三：`drv_log_user` 是用户态日志打印底座，靠可运行时替换的函数指针表 `g_log_print_info` 决定输出后端（默认 syslog，上层经 `drv_log_out_handle_register` 用 DlogInner 接管），并用 `user_err[]` 表把上百个 Linux errno 多对一收敛为对外 `DRV_ERROR_*`；`drv_share_log` 以固定地址共享内存 + 环形缓冲把内核态日志搬到用户态，「按通道读取」即按 `enum share_log_type_enum`（`SHARE_LOG_ERR`/`SHARE_LOG_RUN_INFO`）分流，对应 `share_log_read_err`/`share_log_read_run_info`（本仓库不存在 log_read_by_type）。`msnpureport` 用 config/report 两子命令分别配置与导出 Device 日志：config 走 HDC 短连接，report 走 HDC 长连接拉文件，`-f` 额外导出历史维测信息与 Host 内核日志（host_kernel.log）。
