本讲是单元 3 收尾，补两条通信拼图。其一，`comm/ascend_urma_adapt` 是把 HAL 的逻辑 devid 适配到外部 URMA RDMA 框架的薄胶水层：靠 constructor 自动触发 `urma_init` 且软容忍失败（非 UB 环境只打 info 日志），设备发现按 `INFO_TYPE_HD_CONNECT_TYPE` 分 UB 形态（O(1) 读内核缓存）与其他（O(n) 遍历设备列表）两路；并在裸 URMA 上叠加 context 缓存（devid 数组＋读写锁＋uref 引用计数）、token 池化、segment 红黑区间树（atomic 引用计数）三层增量，上层消费者为 SVM。其二，`pbl/queryfeature` 用「函数指针表＋枚举下标」的表驱动设计实现 `halSupportFeature(devId, type)`，新增特性只需加枚举、写判断函数、注册一行。引入的关键术语：URMA、UB 形态、EID、token、segment、指定初始化器。核心结论是双层适配：编译期宏（`--soc`→CMake→`CFG_*`）冻结二进制能力，运行期 `halSupportFeature` 判断当前芯片是否可用，二者配合实现一份代码多芯片兼容。
