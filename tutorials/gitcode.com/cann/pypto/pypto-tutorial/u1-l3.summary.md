本讲是 PyPTO 的仓库源码地图课，只解决「东西放在哪、谁负责什么」。仓库分五大区域：docs 文档；examples 分级教学示例与 models 大模型算子参考实现；python 双包——pypto 为高层包（Tensor API、frontend 解析器、PIL、op 算子库），pypto_pro 面向 Tile/Block 低层编程；framework 为 C++ 编译框架；根目录 CMakeLists.txt 与 build_ci.py 构成构建区。import pypto 的顺序是先加载 torch（避免 cxxabi 冲突）、再由 _loader 加载 libtile_fwk_*.so、最后导入 frontend 以避免循环依赖；pypto.jit 的定义源头在 frontend/parser/entry.py，前两层仅转发。framework/src 与编译链路一一对应：passes（三层图 Pass，约定一文件一 Pass、RunOnFunction 入口）、codegen（工厂模式按 NPUArch 选后端）、machine（运行时与 SIM 仿真）、interface。核心结论：CMake 的 InstallTargets 与 _loader 加载清单及安装后 pypto/lib 下的 .so 基本一一对应。引入术语：PIL（简化版 Python AST）、pybind11 绑定、LogicalTensor、门面文件。
