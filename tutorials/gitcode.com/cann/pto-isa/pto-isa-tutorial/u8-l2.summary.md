本讲剖析 MoE 三个真机算子：moe_dispatch（去程分发）、moe_combine（回程归还）、dispatch_mega_combine（七段融合单 kernel）。核心结论：MoE 通信不是集合通信指令，而是路由表驱动的变长分段拷贝加信号握手——tokenPerExpert/cumsumMM/preSumBeforeRank 换算每段源/目的地址，expandedRowIdx 承担重排与恢复的逆映射。dispatch 用 pull 拉取并拆包交织量化行为 gmA 与 perTokenScale，combine 用 push（TPUT 远写＋TNOTIFY/TWAIT）再按 probs 加权恢复 token 原序，方向由「谁掌握寻址信息」决定；乒乓流水跨源卡延续，段边界须 drain 尾块。mega 融合以 AIC/AIV 分工与专家级 arrival/ready epoch 协议重叠通信与计算，count-as-flag 免计数栅栏。最普适的结论是 pending-credit 类跨 dispatch 状态同步问题：稀疏同步留下的账目（尾块、TPipe free credit、计数标记）必须在生命周期边界精确结算，否则残留 stale 状态致下次 dispatch 死锁或静默丢数据；跨卡读回前需 dcci/dsb 保证内存序。
