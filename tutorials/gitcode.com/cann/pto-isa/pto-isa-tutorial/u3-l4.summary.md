本讲以 TADD 为标本剖析 PTO 指令的 CPU 仿真实现。核心结论：CPU 仿真只求功能正确，不模拟硬件流水线或 repeat 粒度；调用链固定三层——公共 API（TSYNC 空桩 + MAP_INSTR_IMPL 转发）→ *_IMPL（取有效区、以 dst 为准）→ *_Impl（循环体）。引入的关键概念：有效区遍历、分形与非分形布局的 GetTileElementOffset 坐标映射、if constexpr 编译期分支与 PTO_CPU_VECTORIZE_LOOP 向量化、parallel_for_rows 行级多线程（元素数低于 16384 串行）；以及「一条模板派生一族指令」的 Element 仿真骨架三层结构——ElementOp 枚举 + ElementOpCal<DType,op> 特化（一行数学语义，默认特化 assert 防静默错算）、Binary/UnaryElementTileOp_Impl 遍历层（支持异构 tile 类型但失去向量化）、BINARY_OP_DEF/UNARY_OP_DEF 指令层宏。并列出三种实现风格对照：手写裸指针（TAdd，最快）、SetElement/GetElement 成员函数（TSub，自带检查与布局处理）、骨架宏（长尾指令零成本新增）。最后对照 NPU a2a3 版：两者 *_IMPL 签名逐字相同、按宏互斥编译，但 NPU 版贴紧 vadd intrinsic、按 256B repeat 组织数据通路，并多出 dtype 白名单、仅行主序等契约检查——故 CPU 仿真通过不代表真机约束全部满足。
