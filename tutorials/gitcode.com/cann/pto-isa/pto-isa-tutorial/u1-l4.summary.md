本讲以 Add 算子为例首次逐行精读一个最小 PTO 算子的完整工程：kernel 侧指令序列、host 侧 PyTorch 算子注册（schema 声明、PrivateUse1 派发注册、EXEC_KERNEL_CMD 启动）与 CMake 构建脚本。核心结论：kernel 标准骨架为「构造 GlobalTensor 视图 → TASSIGN 绑定 Tile → 循环{更新视图地址 → TLOAD → 事件同步 → 计算 → 事件同步 → TSTORE}」。引入的关键术语：`__gm__`（全局内存地址空间标注）、`AICORE`（设备端函数标注）、`GlobalTensor`（GM 数据的 shape/stride 视图，不搬数据）、`Tile`（UB 上固定形状片上块，含动态掩码防尾块越界）、`TASSIGN`/`TLOAD`/`TSTORE`（地址绑定与搬运指令）、MTE2/Vector/MTE3 三条并行流水线及 set_flag/wait_flag 事件同步（生产者挂牌、消费者等牌）、ping-pong 双缓冲实现搬运与计算重叠。同时对照了 NPU 真机版（20 核切分 + 乒乓流水）与 CPU 仿真 ST 用例 tadd（最小单 tile 投影，numpy golden 比对，`pto_cpu_sim_st` 注册机制）。综合实践为把 TADD 改成 TSUB，仅改一行指令与一行 golden 运算即可跑通，体现 PTO 指令接口的正交性与可替换性。
