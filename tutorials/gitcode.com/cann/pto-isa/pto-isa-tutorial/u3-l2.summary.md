本讲阐明 PTO 中「缓冲管理」的真实语义。核心结论一：Manual 模式下 Tile 变量不自带存储，片上缓冲的「分配」实为 TASSIGN 手工摆放地址——把整型片上偏移绑给 Tile，或把元素类型匹配的指针绑给 GlobalTensor 视图；两种形式中编译期形式 TASSIGN<Addr> 额外触发 SA-0351～0354 静态检查（存储存在、容量装得下、不越界、32 字节对齐），但 CPU 仿真与 CostModel 后端跳过检查，且任何形式都不查地址重叠——排布不重叠、不越界是 Manual 模式开发者的第一责任，绑错会以数据互踩的形式静默出错。核心结论二：TAlloc/TFree 并非通用片上 malloc/free，而是 TPipe 生产者-消费者环形 FIFO 的槽位申请与归还，与 TPUSH/TPOP 构成跨核（Cube 与 Vector）数据交接协议：TALLOC 取槽视图→TSTORE 写→TPUSH 挂牌，TPOP 等牌取槽→TLOAD 读→TFREE 还槽；同步按 SyncPeriod 稀疏进行，SlotNum 决定生产者领先量；A2A3 上 TileData 流的 TFREE 为空操作（TPOP 已内部通知），保留接口只为跨架构与 API 对称。核心结论三：Auto 模式（`__PTO_AUTO__`）下编译器按 Tile 活跃区间自动分配缓冲并自动插入同步，Tile 的 TASSIGN 与 TSYNC/Event 均变空操作，但 GlobalTensor 的 GM 视图地址仍需手工维护。关键术语：manual placement、编译期/运行期 TASSIGN、TPipe、槽位生命周期、ping-pong 双缓冲，为后续讲义承接使用。
