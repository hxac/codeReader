本讲为性能方法论总结，用 gemm_performance 实测数据串起「判定→调优→验证」闭环。模块一瓶颈判定：按 TLOAD、变换、TMATMUL、TSTORE 四阶段占比把 kernel 归为 CUBE（Compute）、MTE（Memory）或 Vector（Conversion）Bound，证据链为 Ratio 阈值法、算术强度法（AI=FLOP/GM 字节，所需带宽=峰值算力/AI，与硬件带宽比较）与时间增量法。模块二调优三正交维度：tile 大小（先过 L0 半区 32 KiB、L1 双缓冲容量预算）、tile 形状（32 字节对齐、整除约束）、指令排序（只在真依赖处细粒度事件同步，忌循环内全局 TSYNC）。模块三内存三板斧：数据复用（Acc 常驻、stepK caching）、布局对齐（成本序：改视图<TRESHAPE<TMOV<TTRANS）、削减 GM 流量（融合、TPREFETCH、double buffer）。核心结论：加大输出块提升算术强度是逃离 Memory Bound 的第一手段；输出块固定时扫描 baseK 不改 GM 流量与 AI，Bound 属 kernel 级属性；CPU 仿真仅验证功能，性能证据须靠真机 msprof 或 CostModel。
