本讲建立 pto-isa 仓库的“目录地图感”。核心结论：仓库是 header-only 库，顶层按交付物分四组——核心头文件 include/、算子与演示 kernels/+demos/、测试 tests/、文档与工程 docs/+scripts/+cmake/。include/pto 内部五层分工：common（跨后端公共类型与 API 声明）、cpu（CPU 仿真）、npu（按 a2a3/a5/a6/kirin 架构分目录的真机实现）、comm（通信扩展指令）、costmodel（性能模拟）。关键概念：同一条指令是“指令 × 后端 × 架构”三维坐标下的多个同名文件（如 TADD 同时存在于 cpu 与 npu/a2a3）；指令名前缀约定（T 矩阵 tile 级、M 矩阵级、Set 配置类）；逐指令后端支持状态表在 include/README.md。后端路由机制：pto/pto-inst.hpp 是唯一统一入口，按 __CPU_SIM、__COSTMODEL、__CCE_AICORE__ 三宏选择头文件集合；arch_macro.hpp 把 __NPU_ARCH__ 数字翻译为 PTO_NPU_ARCH_* 架构宏，pto_instr_impl.hpp 据此批量引入实现；API 与实现的粘合约定是 XXX → XXX_IMPL 宏转发。掌握此地图后，精读任何指令均可按“docs/isa 查语义、include/pto/{cpu,npu} 查实现、tests 查验证”定位。
