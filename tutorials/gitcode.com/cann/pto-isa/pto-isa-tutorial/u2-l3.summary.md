本讲围绕 PTO 的事件与同步机制展开三个模块：事件记录与等待、flag 语义、流水线同步。核心结论：昇腾 AICORE 内 MTE2（搬入）、V（向量计算）、MTE3（搬出）等硬件流水线并行执行，程序书写顺序不等于完成顺序，跨流水线的生产-消费依赖必须显式用事件表达。一个 flag 由 (srcPipe, dstPipe, eventId) 三元组唯一确定，set/wait 三元组必须一致才配对；每对流水线仅 8 个编号、按模 8 轮转，事件须像 SSA 变量般“记录一次、等待一次”，泄漏会在 CPU/CostModel 后端触发断言。两套等价写法：裸 set_flag/wait_flag 原语，与 Event<SrcOp,DstOp> + RecordEvent 对象风格（赋值即记录、传参即等待，pipe 对与编号自动推导）。指令 API 统一骨架为 TSYNC(events...) 折叠等待后返回 RecordEvent；TSYNC<OpCode>() 是单流水线屏障（真机 pipe_barrier）。指令到流水线的映射由 Op 枚举静态表在编译期确定（如 TLOAD→MTE2、TADD→V、TMATMUL→M）。CPU 仿真后端将同步全部做成空桩、单线程按序执行，故 CPU 只验证功能逻辑，同步正确性需真机验证；乒乓双缓冲用两套事件编号隔离相邻轮次的重叠依赖。
