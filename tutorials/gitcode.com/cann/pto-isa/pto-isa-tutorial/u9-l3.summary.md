本讲覆盖 CMake 结构、build.sh 与 wheel 打包三个模块。核心结论：PTO 是 header-only 库，顶层 CMakeLists.txt 是「打包工程」而非编译工程——FetchContent 拉取共享 cann-cmake 后经 CPack 产出 .run/.rpm/.deb 安装包；真正编译代码的是 tests/demos/kernels 下各自独立的消费工程。关键术语：__CPU_SIM 由 CPU 工程显式定义，__CCE_AICORE__ 由 bisheng 编译器的 -xcce 模式自动预定义，架构由 --cce-aicore-arch 指定（dav-c220 对应 A2/A3），sim/npu 差异体现为链接 runtime_camodel 还是 runtime。build.sh 是解析与执行分离的状态标志分发器，--run_all/--build/--cpu/--pkg 分别转发 run_st.sh、build_st.py、run_cpu.py 与 CPack，且 build 默认 a5、run 默认 a3。wheel 打包：setup.py 用 data_files 把头文件装进无 Python 代码的 wheel，落点 share/pto-isa/include；MANIFEST.in 只管 sdist；版本号在三处文件冗余，发版须同步。
