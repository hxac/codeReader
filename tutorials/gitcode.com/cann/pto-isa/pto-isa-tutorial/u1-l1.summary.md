PTO（Parallel Tile Operation）是 Ascend CANN 定义的 tile 级虚拟 ISA，本仓库提供 90+ 条标准 tile 指令的头文件实现、示例算子、测试与文档，核心价值是用高层 tile 编程模型桥接昇腾不同代际硬件差异、降低跨代迁移成本。其定位是“抬高抽象但不隐藏底层”：固定 tile 形状下保证行为正确，tile 大小、形状与指令排序仍留给开发者调优。关键概念：ISA/虚拟 ISA、Tile（固定形状的二维数据块）、昇腾 A2（910B）/A3（910C）/A5（950）、CANN、CPU 仿真。平台矩阵是仓库组织钥匙：后端含 CPU 仿真（include/pto/cpu/）、CostModel（costmodel/）、A2/A3 共用（npu/a2a3/）、A5（npu/a5/，含 MX 指令等新特性）、Kirin（npu/kirin9030/）及通信指令（comm/），逐指令支持状态见 include/README.md；新特性通常先落 CPU 仿真再随新硬件落地。PTO 还有通信扩展指令集（点对点、信号同步、集合通信），与计算指令同用 tile 抽象。生态上下游包括 PyPTO、TileLang Ascend、PTOAS、pto-dsl，上层接入只需包含统一入口头 pto/pto-inst.hpp，由构建宏（__CPU_SIM/__CCE_AICORE__/__COSTMODEL）路由后端。推荐工作流：CPU 仿真验证逻辑→真机验证与测性能→按 CUBE/MTE/Vector Bound 定位调优。
