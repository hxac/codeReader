本讲以新增勾股指令 THYPOT 为例，讲解 PTO 二次开发的完整闭环。核心结论：一条新指令横切接口、实现、装配、文档、测试五层，共 8 处必改——公共 API 薄壳、Op 枚举与流水线登记（PTO_DEFINE_OP_PIPE）、CPU 侧 `*_IMPL` 实现、汇总头按「架构 × 后端」宏挂载、ISA 文档、文档索引、后端状态表、ST 用例四件套及 ALL_TESTCASES 注册，另有 NPU 实现与 CostModel 系数登记两处可选。关键术语：三段式指令结构（MAP_INSTR_IMPL 把指令名拼接转发到 IMPL）、有效区、golden 镜像比对、三方命名契约（TEST_F 名、gen_data 目录名、main 寻址路径须逐字一致）。关键要点：漏登记流水线在 CPU 仿真完全不可见、真机编译期才触发断言，须靠清单纪律兜底；ISA 文档约束须与实现的 static_assert 一一对应并按架构分节；NPU 侧无 1:1 intrinsic 时按 TFMOD 先例走组合实现，并给公共 API 增加 tmp 暂存操作数；最后按 CONTRIBUTING.md 走 Issue 讨论、本地开发、PR 评审的贡献流程。
