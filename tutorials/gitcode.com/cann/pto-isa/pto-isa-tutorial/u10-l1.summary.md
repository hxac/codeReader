本讲覆盖 PTO 测试体系的三个模块：用例结构、运行脚本、覆盖校验。关键概念：ST（System Test，一条指令一个目录、一个 gtest 可执行，C++ 产出的 output.bin 与 golden 逐元素比对）与 golden（gen_data.py 用 numpy 独立计算的标杆答案，与 C++ 实现互为镜像、必须成对修改）。每条用例由四件套构成：<op>_kernel.cpp（被测计算加显式模板实例化）、main.cpp（读入→Launch→写回→ResultCmp 比对）、gen_data.py、一行注册的 CMakeLists.txt；CPU 树注册函数为 pto_cpu_sim_st，NPU 树为 pto_vec_st，两树同构。命名是三方契约：TEST_F 的 Suite.Case 名、gen_data 建的数据目录名、main 的寻址路径须逐字符一致。运行入口：run_cpu.py（-t 构建期定向、-g 运行期过滤，靠 ALL_TESTCASES 与 CMakeCache 差集增量构建）与 run_st.py（NPU/sim 的构建→造数→跑 gtest 三段式）。两个守护脚本防静默失效：validate_op_coverage.py 防用例未接入推荐套件，validate_testcase_names.py 防 case 名失配及「filter 匹配 0 测试仍退出 0」的假覆盖。综合实践为 tcolprod 新建 CPU 四件套并跑通。
