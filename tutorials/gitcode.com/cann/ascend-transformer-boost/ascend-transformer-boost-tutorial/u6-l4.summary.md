本讲承接 u6-l3「算子能跑」，解决「算子能被校验、能被序列化、能被测试、能被构建」的配置交付件问题。新算子交付件分代码与配置两类，本讲聚焦后者，核心是六类配置：Param 定义、ini 规格、param_to_json 特化、测试反序列化、op_list.yaml 登记及 MKI 层 Param 头聚合。关键结论：ini（atb_ops_info.ini）用「逗号并列＝支持组合」声明各算子合法的 dtype/format 组合，运行时由 CheckIniMatch 按 supportIdx 枚举校验，失败返回 ERROR_INVALID_TENSOR_INI_MATCH；其段名（IR key）简单算子用静态名、复杂算子（如 Linear）由 Param 字段动态拼接。Param 的 JSON 化靠函数模板 OpParamToJson 逐类型全特化，只投影业务字段、刻意排除 rsv；rsv 走另一条路，由 OP_PARAM_RSV_CHECK 在 CreateOperation 入口逐字节校验，构成版本兼容闸门。测试反序列化在 operation_funcs.cpp 手写 XxxOperationCreate（字段级 contains 回填 + 枚举转型 + rsv 容错）并登记进 g_funcMap，JSON 用例缺省字段自动取默认值；op_list.yaml 是构建期交付件，决定某 Kernel 在哪些芯片编译，漏登则运行时取不到 Kernel。引入的关键术语：交付件、IR key、支持组合（support combination）、Param 的 JSON 往返、注册名一致铁律的两个新落点（ini 段名与 g_funcMap 键名）。主仓与 ops_customize 共用同一套 ini/Param/rsv 契约模板，为 u6-l5 铺垫。
