本讲覆盖 ATB 可观测体系三部分：日志体系、ATB_LOG 宏门面、Python 端 ProfStats 耗时统计。日志底层依赖 MKI 的 LogCore 与 Sink（Stdout/File 两类下沉点），公开面收敛为 atb::LogLevel 五档（DEBUG/INFO/WARN/ERROR/NONE）。环境变量按 CANN 版本分三组：8.3 前用 ASDOPS_LOG_*，8.3 起用 ASCEND_GLOBAL_LOG_LEVEL，8.5 起新增高优先级的 ASCEND_MODULE_LOG_LEVEL=OP=0，可单独放大 ATB 日志；atb::Utils 的 SetLogLevel/ResetLogLevel 支持运行时动态调级，NONE 借 MKI 的 FATAL 当「关闭」哨兵并删除 Sink，重开时补挂。ATB_LOG/ATB_FLOG/ATB_LOG_IF 宏内置级别门控，消息级别低于阈值则整条 << 链短路、参数不求值，故热路径埋点近乎免费。关键术语：Sink（日志下沉点）、级别门控、thread_local。ProfStats（Python 类 torch_atb.Prof）以算子名为 key、thread_local 单例、滑动窗口保留最近 1000 次，自动统计每次 forward() 的 Host 端墙钟耗时，用于定位 Host Bound 与 Setup 开销，但不等于 Kernel 真实执行时间，后者需 msProf 采集 Device 侧。核心结论：日志回答「跑到哪、对不对」，ProfStats 回答「哪个算子在 Host 侧最贵」，二者互补。
