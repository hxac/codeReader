本讲是「工程化、调试与贡献」单元第二篇，承接 u1-l3，深入 ATB 编译开关背后的语义与组合。核心覆盖三个模块。一是 **CXX11 ABI**：由 GCC 宏 `_GLIBCXX_USE_CXX11_ABI` 切换 `std::string` 等容器的内存布局与符号修饰，ABI 不匹配会导致接口传参错乱或链接报 `undefined symbol`。ATB 默认跟随 `torch.compiled_with_cxx11_abi()` 自动探测，把结果同时注入编译宏、本地变量与安装目录 `output/atb/cxx_abi_0|1`，实现两套产物的物理隔离；切换 ABI 必须 `--clean-first` 以清缓存与第三方库残留。二是测试开关：顶层 CMake 用 13 个 `option()` 管理全部编译维度，默认除 `BUILD_PYBIND`/`USE_CXX11_ABI` 外全 `OFF`；测试分 `BUILD_TEST_FRAMEWORK`（测试引擎库）与六个 `USE_*_TEST`（具体测试），由 `tests/` 总闸「或」条件控制编译范围，`build.sh` 子命令（如 `unittest`/`csvopstest`）负责打开开关、拉 googletest 并运行。三是两套正交的 Sanitizer：`USE_ASAN`（`--asan`）管 Host/CPU 内存，靠 GCC `-fsanitize=address/undefined` 加全局插桩并强制 Debug；`USE_MSSANITIZER`（`--mssanitizer`）管 Device/AI Core 内存，靠 CCE `--cce-enable-sanitizer`。易混的 `--msdebug` 是 Kernel 源码调试开关，并非 sanitizer。`unittest --asan` 即「单元测试 + Host ASAN + 自动 ABI 对齐」的组合用法。
