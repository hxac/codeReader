本讲讲解 ATB 通信算子与 HCCL 通信域。核心结论：通信算子仍是 Operation，其后端 Runner 不调 AscendC Kernel 而调 HCCL/LCCL 通信库，整条 Operation→Runner→后端链路与普通算子同构。三个最小模块：其一，通信域（类型别名 HcclComm，即 void* 不透明指针）是多卡协同通信的逻辑上下文，comm.h 提供外部自管通信域路径（CreateHcclComm/ByRankTableFile/CrossMulitComm/DestoryHcclComm），另有 HcclRunner 在首次执行时库内自动建链的路径，hccl 多线程模式只支持前者。其二，AllReduce/AllGather/AllToAll 共享「七件套」Param 模板（rank/rankSize/rankRoot/backend/hcclComm/commMode+rankTableFile/commDomain+rsv）与 CommMode（多进程/多线程）；校验极重，集中卡死 backend×芯片×dtype×allReduceType 非法组合；InferShape 各异（AllReduce 透传、AllGather 第 0 维前置 rankSize、AllToAll 在 lccl+transpose 时转置形变）；CreateRunner 是 backend 与 hcclComm 各二选一的模板化决策树。其三，HcclRunner 经单例 CommPool 按 rank+commDomain 复用通信域（建链仅一次），多进程建链靠 /dev/shm 共享内存与 barrier 协同；基类 ExecuteImpl 只做校验，子类才真正调 HcclAllReduce/HcclAllGather 下发到 GetExecuteStream 返回的流。关键术语：HcclComm、CommMode、七件套 Param、HcclRunner、CommPool、rank/rankSize/rankRoot。
