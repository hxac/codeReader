本讲把视角从单算子提升到「算子图」，讲解 ATB 图算子（Graph Operation）的原理与三个核心模块。首先明确边界：图算子在**调度层**把多个已存在的 `Operation` 拼成 DAG，整体对外暴露为一个 `Operation`，**不做 kernel 融合**，其收益来自减少 Host 下发开销、中间张量与 workspace 的内存复用。组图用 `GraphParam` 与 `Node` 表达：所有张量按「输入→输出→中间」三段分配全局 `tensorId`，`Node` 用 `inTensorIds`/`outTensorIds` 引用，共享同一 id 即自动连线，**中间张量由图内部托管**，调用方无需分配内存。`GraphOperation` 继承 `OperationBase`，通过 `CheckGraphParam` 严格校验拓扑序，`InferShapeImpl` 沿拓扑序传播形状，`CreateRunner` 产出执行后端。`GraphRunner` 将图级 Setup/Execute 展开为逐节点串行下发，借助活跃性分析实现中间张量显存复用、并按 stream 取各节点 workspace **最大值**复用。其中 `BuildFullTensorPtrs` 建立的 tensorId→`Tensor*` 映射，是把逻辑图翻译为物理指针图的桥梁。本讲为后续 `GraphOpBuilder` 自动推导 tensorId 的组图实战奠基。
