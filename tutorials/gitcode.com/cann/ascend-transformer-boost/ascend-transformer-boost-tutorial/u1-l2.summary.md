本讲把 ATB 分层架构落到具体文件夹。顶层目录分三类：源码（include/、src/、torch_atb/）、配置/资源（ops_configs/、ops_customize/、tests/ 等）、生成目录（3rdparty/、build/、output/，被 .gitignore 忽略，编译后才出现）。核心是 src/ 的单向分层：框架层 atb → 算子层 ops（ops_infer 推理 / ops_train 训练 / ops_common 公共）→ Kernel 层 kernels（kernels 单算子、mixkernels 融合、lcal 通信），torch_atb 用 pybind11 把能力暴露给 Python。CMake 以 GLOB_RECURSE 自动扫描各子目录，产出 atb、atb_train、asdops、atb_mixops 等库，往目录加 .cpp 即自动入编。一个算子横切分布在多目录：Operation（负责形状推导与选 Runner）在 ops_infer/<算子>/，设备执行为 Kernel 层「四件套」（kernel 计算 + tiling 切分 + operation 注册 + CMake），Python 绑定在 src/torch_atb/ 与顶层 torch_atb/，规格约束在 ops_configs/。关键区分：linear 等算子经 aclnn runner 路由到 CANN 后端而无自家 Kernel 目录，concat、kv_cache 则四件套齐整，是单算子与融合算子的典型样例。
