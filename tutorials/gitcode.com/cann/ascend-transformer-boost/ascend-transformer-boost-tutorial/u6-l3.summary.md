本讲承接 u6-l2 的 Kernel 开发，讲解把自定义算子接入 ATB 调度框架的胶水层，覆盖三个最小模块：高层 Operation、OpsRunner、注册宏与工厂。核心结论是 ATB 算子体系存在「同名两层 Operation」——高层 `atb::Operation`（用户面，继承 `OperationBase`，管 IO 个数、校验、形状推导、建 Runner）与 MKI 层 `AtbOps::Operation`（Kernel 面，管选 Kernel），二者唯一的接线点是 Runner 节点 `opDesc` 里的操作名字符串，它是「注册名一致」铁律的第 4 个落点。写高层 Operation 即填四个纯虚钩子（`GetInputNum`/`GetOutputNum`/`InferShapeImpl`/`CreateRunner`）加可选校验钩子；in-place 算子表现为 `GetOutputNum=0`。写 OpsRunner 的本职是组 `KernelGraph`：拓扑固定在构造函数组图，拓扑随形状变化则重写 `SetupKernelGraph`，in-place 靠「输出指针==输入指针」实现。三套注册各管一摊且键不同：`CreateOperation` 特化或 `OPERATION_PARAM_FUNCS` 宏管工厂、`REG_RUNNER_TYPE` 管 Runner 池下标、`REG_OP_PARAM` 管 MKI 参数比较函数（支撑 Tiling 复用）。所有高层 Param 带 `rsv` 字段，工厂入口以「全 0」校验作为版本兼容闸门。全链路为 `CreateOperation → 高层 Operation::Setup → OpsRunner::SetupImpl → RunKernel → MKI GetBestKernel → AscendC Kernel`。
