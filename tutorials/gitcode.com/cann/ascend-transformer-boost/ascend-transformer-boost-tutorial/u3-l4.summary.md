本讲下沉到 ATB 的 Kernel 层与 MKI 框架，说明一个算子如何从「调度入口」最终落到跑在 NPU AI Core 上的二进制。`src/kernels` 分三块：`kernels/`（单算子）、`mixkernels/`（融合算子）、`lcal/`（通信/Cube 算子），分别编进 `libasdops`、`libatb_mixops` 与 Cube 库。每个算子在 Kernel 层由「四件套」协作：① AscendC kernel 计算（Device）、② tiling 切分（Host）、③ MKI Operation/Kernel 注册（Host）、④ CMake 构建。

关键术语包括：TilingData（Host 与 Device 间唯一的参数信使，Host 填、Device 读，字段顺序须严格对齐）、BlockDim（核间并行度，激活几个核）、TilingKey/TilingId（分支选择码，单算子用 SetTilingId，Cube 算子用位域打包）。AscendC kernel 标准写法为 CopyIn→Compute→CopyOut 三段式流水，配合 TQue 双缓冲掩盖访存延迟。

核心结论：MKI 提供 KernelBase（管 tiling 与能力校验，用 REG_KERNEL_BASE 注册）与 OperationBase（管选 kernel 与形状推导，用 REG_OPERATION 注册）。注册名是衔接点——REG_OPERATION 名等于上游 Runner 的 opDesc 字符串；REG_KERNEL_BASE 名、GetKernelByName 名、add_kernel 关联的 Kernel 类名三处必须完全一致。本讲是后续自定义算子开发（u6）的硬前置。
