`extract_ptq_data` 是 AMCT LLM 训练后量化（PTQ）四阶段链路（eval→extract→ptq→deploy）的第二阶段，定位为 `ptq` 的「数据准备工」：只跑前向、把每个待量化子模块的输入激活录下来存到 `--data_dir`，供 `ptq` 阶段读回训练量化参数，本身不做量化。

核心是 `LlmExtractPtqDataWorkflow._run_blockwise` 三步骨架：按 `--quant_target` 选 `hook_name` → `get_pileval` 切出 `nsamples × [1, seq_len]` 校准样本 → `do_embedding_forward` + 逐层 `do_block_forward` 接力前向。

关键概念与术语（供后续承接）：**校准数据**、**中间激活**、**decoder block 两段结构**（注意力前接 `input_layernorm`、FFN 前接 `post_attention_layernorm`）。hook 选择直觉是「录子模块输入就 hook 紧挨它前面的 norm」——attn 目标（attn-linear/attn-cache）hook `input_layernorm`，mlp/moe hook `post_attention_layernorm`，norm 名从适配器属性读取、默认即 HuggingFace 命名。两种截获手段：`Catcher`（embedding 阶段靠抛 `ValueError` 截 layer-0 输入与位置参数）、`register_forward_hooks`（block 阶段截 norm 输出）。落盘契约 `block_{layer_idx}_{target}_in.pkl` 两端对齐（attn-linear/attn-cache 归并为 `attn`），这是 extract 与 ptq 的 `--quant_target` 必须一致的文件层根源。`sharded_block` 标志在 extract/eval 置 True 走多卡分片前向，ptq 保持 False 走 CPU 暂存，是两阶段行为分叉的关键开关。产物将由 u4-l2 的 `load_ptq_inps` 读回。
