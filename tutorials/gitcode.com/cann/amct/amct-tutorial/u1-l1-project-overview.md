## 2. 前置知识

本讲面向零基础读者，但有几个名词先解释清楚，后面读起来会更顺：

- **模型量化（Quantization）**：把神经网络里用高精度浮点数（如 FP16/BF16，每个数占 16 bit）表示的权重或激活值，换成低比特表示（如 INT8 占 8 bit、INT4 占 4 bit）。这样模型体积更小、推理更快，代价是通常会有轻微精度损失。
- **推理（Inference）**：模型训练好之后，拿它去「使用」（回答问题、识别图片等）的过程，区别于「训练」。
- **NPU（Neural Processing Unit）**：专门为神经网络计算设计的处理器。本项目的 NPU 特指华为**昇腾（Ascend）**系列 AI 处理器。
- **CANN（Compute Architecture for Neural Networks）**：昇腾 NPU 的软件栈（驱动、算子库、工具链等），类似 GPU 上的 CUDA。AMCT 依赖 CANN ≥ 8.5.0。
- **PTQ / QAT**：训练后量化（Post-Training Quantization，模型训完再量化）与量化感知训练（Quantization-Aware Training，边训练边模拟量化）。AMCT 的主线是 PTQ。这两个概念会在第 2 单元详细讲。
- **LLM（Large Language Model）**：大语言模型，如 DeepSeek、Qwen 系列。AMCT 当前重点支持的正是这类大模型。

如果你对「量化为什么能省体积」还没有直觉，记住下面这条最朴素的换算即可：

\[ \text{体积压缩比} \approx \frac{\text{量化后的位数}}{\text{量化前的位数}} \]

例如从 16-bit 浮点量化到 8-bit，体积约为原来的 \( \tfrac{8}{16} = \tfrac{1}{2} \)，也就是节省了一半（↓50%）。这个公式在本讲的性能收益表里会反复用到。

### 4.1 README 概述与核心特性

#### 4.1.1 概念说明

AMCT 的全称是 **Ascend Model Compression Toolkit（昇腾模型压缩工具包）**。它的定位可以用一句话概括：

> **AMCT 是昇腾 NPU 原生的模型量化压缩工具。它把浮点模型压缩成低比特模型，使其能在昇腾 NPU 上启用低比特运算，从而显著提升推理性能、降低部署成本。**

这里有几个关键词需要拆开理解：

- **「昇腾 NPU 原生」**：AMCT 量化的产物是**专门对接昇腾 NPU 低比特运算单元**的，不是通用量化工具。这是它与一般量化框架最大的区别。
- **「模型压缩」**：压缩手段以**量化**为主（本项目核心），辅以图压缩（如张量分解）等能力。
- **「工具包」**：AMCT 既能作为命令行工具（CLI）使用，也提供 Python API，可以集成进自己的流水线。

#### 4.1.2 核心流程

从「用户的模型」到「NPU 上跑起来」，AMCT 处在中间的「压缩」环节。整体价值链可以抽象成三段：

```text
[浮点模型]  ──AMCT 量化──▶  [低比特模型]  ──部署──▶  [昇腾 NPU 低比特推理]
(FP16/BF16)                 (INT8/INT4/...)           (体积小、吞吐高)
```

1. **输入**：一个训练好的浮点模型（通常是 HuggingFace 格式的大语言模型）。
2. **AMCT 量化**：用 AMCT 提供的算法与流程，把模型里的权重（以及可选的激活）转换成低比特表示。
3. **输出与部署**：量化后的模型体积更小，部署到昇腾 NPU 后可启用低比特运算单元，获得更高的吞吐与更低的时延。

AMCT 在 README 里把自己的价值凝练成**三大亮点**：

| 亮点 | 含义 |
|------|------|
| 🎯 **硬件亲和** | 量化结果直接对接昇腾 NPU 的低比特运算单元 |
| 🔢 **多精度全栈** | INT8 / INT4 / MXFP8 / MXFP4 / HiFloat8 任选 |
| 🚀 **大模型就绪** | 原生支持 DeepSeek-V3.2 / V4 等前沿大模型 |

在「核心特性」表里，AMCT 又把自己的能力分成了四类：PTQ 量化算法、HiFloat8 量化、NPU 自定义算子、大模型量化。这四类特性正好对应了后续几个学习单元的主线。

### 4.2 部署架构与性能收益表

#### 4.2.1 概念说明

理解 AMCT 的价值，关键要理解它在**部署链路**中的位置，以及**量化到底省了多少**。

先说部署链路。AMCT 的 README 用一张架构图说明了整个链路（`docs/zh/figures/amct_architecture.png`）。虽然我们在这里看不到图片本身，但结合上下文可以还原出它的三段式结构：

```text
┌──────────────┐      ┌────────────────┐      ┌──────────────────────┐
│  浮点模型     │ ───▶ │   AMCT 量化     │ ───▶ │ 昇腾 NPU 低比特推理   │
│ (FP16/BF16)  │      │ (压缩为低比特)  │      │ (体积小 / 吞吐高)     │
└──────────────┘      └────────────────┘      └──────────────────────┘
```

AMCT 是中间那一段——**它不负责训练，也不直接做推理，它只负责「把模型从高比特压成低比特」这件中间事**。

再说性能收益。量化的本质是「用更少的 bit 表示差不多大小的数」，所以体积收益几乎完全由「目标位数」决定。AMCT 在 README 里给出了一张性能收益表，把收益按**精度格式**和**量化范围**两个维度组织：

- **精度格式**：INT8、INT4、HiFloat8、MXFP8、MXFP4 五种。
- **量化范围**：
  - **仅权重（W，Weight-only）**：只量化模型权重，激活（activation）仍用较高精度。适合「带宽瓶颈」场景。
  - **全量化（W+A，Weight + Activation）**：权重和激活都量化。适合追求极致计算性能的场景。

#### 4.2.2 核心流程

体积收益的换算非常直观，可以用第 2 节给出的公式推导。假设原始模型权重是 16-bit 浮点（FP16/BF16，这是大模型最常见的存储格式）：

| 目标精度 | 每个权重占的 bit | 相对原始 16-bit 的体积 | 节省比例 |
|---------|-----------------|----------------------|---------|
| INT8 / HiFloat8 / MXFP8 | 8 bit | \( \tfrac{8}{16} = \tfrac{1}{2} \) | ↓50% |
| INT4 / MXFP4 | 4 bit | \( \tfrac{4}{16} = \tfrac{1}{4} \) | ↓75% |

\[ \text{节省比例} = 1 - \frac{\text{目标位数}}{\text{原始位数}} \]

这就是为什么表里 INT8/MXFP8/HiFloat8 都是 ↓50%，而 INT4/MXFP4 都是 ↓75%——**完全由 bit 数决定**，与具体格式是整数还是浮点无关。

至于不同格式之间的差异（比如同样是 8-bit，为什么还要分 INT8 / MXFP8 / HiFloat8），核心在于**数值表示方式不同**带来的精度与动态范围差异——这部分会在第 2 单元「量化数据类型全览」详细讲，本讲只需要记住体积收益即可。

#### 4.2.5 小练习与答案

**练习 1**：为什么 INT4 和 MXFP4 的体积收益都是 ↓75%，而 INT8 和 MXFP8 都是 ↓50%？

> **参考答案**：因为体积收益只取决于每个数值占用的 bit 数，与是整数还是浮点无关。从 16-bit 浮点压缩到 4-bit，体积为 \( \tfrac{4}{16} = \tfrac{1}{4} \)，节省 75%；压缩到 8-bit，体积为 \( \tfrac{8}{16} = \tfrac{1}{2} \)，节省 50%。

**练习 2**：「仅权重（W）」和「全量化（W+A）」有什么区别？分别适合什么场景？

> **参考答案**：W（Weight-only）只量化模型权重，激活保持高精度，适合「显存带宽是瓶颈」的场景（权重读取是大头）；W+A（Weight + Activation）把权重和激活都量化，能进一步利用低比特计算单元提升算力，适合追求极致计算性能的场景，但对精度更敏感、算法更复杂。

**练习 3**：AMCT 仓库里 `amct_pytorch/` 和 `amct_ops/` 这两个顶层目录的职责有什么区别？

> **参考答案**：`amct_pytorch/` 是 PyTorch 量化压缩的核心源码（算法、流程编排、量化模块等）；`amct_ops/` 是独立的 NPU 自定义算子层，用 Ascend C kernel 实现，与核心源码职责分离，可独立构建打包。

## 6. 本讲小结

- **AMCT** 全称 Ascend Model Compression Toolkit，是昇腾 NPU **原生**的模型量化压缩工具包。
- 它的部署链路是三段式：**浮点模型 → AMCT 量化 → 昇腾 NPU 低比特推理**；AMCT 只负责中间的「压缩」环节。
- 三大亮点：**硬件亲和**（对接 NPU 低比特单元）、**多精度全栈**（5 种精度）、**大模型就绪**（支持 DeepSeek 等前沿模型）。
- 五种精度格式的体积收益由 bit 数决定：8-bit 系列（INT8 / MXFP8 / HiFloat8）↓50%，4-bit 系列（INT4 / MXFP4）↓75%。
- 量化范围分 **W（仅权重）** 与 **W+A（全量化）**，各有适用场景与配套算法。
- 仓库分两大块：`amct_pytorch/`（核心源码）与 `amct_ops/`（独立 NPU 算子层），职责分离。
