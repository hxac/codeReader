本讲打开 AMCT 量化算法的公共契约黑盒，只讲一件事：算法基类与通路开关。`QuantAlgorithmBase`（双继承 `nn.Module, ABC`）是所有算法的插座标准，定义五个接口：`calib_forward`（默认原样返回，校准态透明）、`forward`（抽象方法，强制子类实现量化行为）、`trainable_params`（向 solver 暴露可学习参数）、`export_ptq_params`/`load_ptq_params`（存取训练参数，断点续跑）。核心机制是布尔开关 `is_observe`：它让同一挂载模块在「校准态」（算法/量化器全透明，激活原样穿过，但算法可偷偷记统计量）与「量化态」（算法施加截断、量化器伪量化）间切换；`ActivationQuantizer.forward` 中的三元表达式 `calib_forward if is_observe else algo(x)` 是通路分叉本体。因「一标志多处持有」（算法、激活量化器、权重量化器各一份），必须由 `set_model_to_observe` 用一次 `modules()` 遍历齐整翻转。PTQ workflow 在 `_prepare_unit_batch` 里以 `True → materialize_gt → finally False` 的三明治结构保证 GT 是干净浮点参考，是重建训练成立的前提。LAC 是典型示范：`calib_forward` 更新 `maxval/minval` buffer 而 `forward/apply_clip` 用其配合可学习 `clip_factor` 做截断，故须重写存取接口；对照 LWC（权重算法、不校准、不重写）可看清 activation 算法对 observe 的依赖。训练态与推理态在模块层面走同一通路（都 `is_observe=False`），区别只在外层 solver 反向更新与 `no_grad` 测精度。
