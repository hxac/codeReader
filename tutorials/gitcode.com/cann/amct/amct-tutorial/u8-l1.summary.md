本讲聚焦 AMCT 的 NPU 自定义算子层 amct_ops：与做量化算法编排的 amct_pytorch 分工不同，它用 Ascend C kernel 实现底层尚未覆盖的低比特量化与数据类型转换算子，产含 .so 的平台相关 wheel。核心结论是 amct_ops 须做成独立 wheel——amct_pytorch 运行时先探测 torch_npu 是否原生支持，支持则用原生、否则在 try/except 中回退 import amct_ops，使核心包保持即装即用。关键术语：--soc（ascend910b 默认 / ascend910_93 / ascend950）映射到 NPU_ARCH（A2、A3 共用 dav-2201，A5 用 dav-3510）；PrivateUse1 为 torch_npu 占用的后端槽位、Meta 供 torch.compile 做形状推导；算子经 TORCH_LIBRARY_FRAGMENT 注册到统一 amct 命名空间，提供模块导入与 torch.ops.amct.<op> 两种等价接口。构建由 ops_build.sh 四步流水线（加载 CANN → 编译 → 汇集 staging/ → pip wheel）完成，setup.py 以 staging/ 为包根、用 BinaryDistribution 强制平台相关并经 package_data 把 .so 打入；通用算子 hifloat8_cast 走 NPU_ARCH 简捷 CMake，svd_quant 走 CANN open project 且仅 A5 构建、非 A5 静默跳过。
