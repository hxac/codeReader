# 量化数据类型全览：INT / MXFP / HiFloat8

## 1. 本讲目标

上一讲（u2-l1）我们建立了量化的通用心智模型：把浮点数映射到低比特，误差来自 `round`（舍入）和 `clip`（饱和），并区分了权重 / 激活、PTQ / QAT、四种量化粒度。但「低比特」到底低到什么格式？AMCT 给的答案是 **五种** 数据类型：`INT8`、`INT4`、`MXFP8`、`MXFP4`、`HiFloat8`。

本讲要解决的问题是：**这五种数据类型分别长什么样、各有什么取舍、什么时候选谁**。读完本讲你应该能够：

- 说清 `INT8` / `INT4` 整数量化的基本思想，以及「更低位宽 = 更小体积但更大精度损失」的权衡。
- 解释 Microscaling（微缩放）格式 `MXFP8` / `MXFP4` 相比普通浮点 `FP8` / `FP4` 多出来的 **shared exponent（共享指数）** 机制。
- 描述华为自研 `HiFloat8` 的 **Dot 位**、**锥形精度**、**大动态范围** 三个特点。
- 看懂 README 性能收益表，为给定场景选出合适的数据类型。

> 本讲是**概念课**，主要依据 AMCT 官方文档 `docs/zh/compression_concepts.md` 的「数据类型概念」一节和 README 的性能收益表。不涉及量化算法实现（那是第 6 单元的事）。

## 2. 前置知识

本讲默认你已经掌握 u2-l1 的核心结论，下面只做一句话回顾，不再展开：

- **量化公式**：\( \text{int\_val} = \mathrm{clip}(\mathrm{round}(\text{float\_val}/\text{scale}+\text{offset}),\,-128,\,127) \)。误差来自 `round`（舍入）和 `clip`（饱和）。
- **权重 vs 激活**：权重是静态的，可离线量化；激活是动态的，需要校准数据集估计范围。
- **量化粒度**：per-tensor / per-channel / per-group / per-token，LLM 常见组合是「权重 per-group + 激活 per-token」。
- **PTQ vs QAT**：AMCT 的 LLM 主流程属于 PTQ（训练后量化），只需少量校准数据。

本讲新增的术语先列在这里，后文逐一解释：

| 术语 | 一句话解释 |
|------|-----------|
| 浮点（float） | 由符号位、指数位、尾数位组成的数，能表示很大的动态范围 |
| 指数位（exponent） | 决定能表示的**范围**（最大最小能到多少） |
| 尾数位（mantissa） | 决定能表示的**精度**（每个数有多少有效数字） |
| shared exponent（共享指数） | 一组元素共用同一个指数，节省存储 + 提升精度 |
| Microscaling（微缩放） | 上面这个「共享指数」思想的正式名称 |
| Dot 位 | HiFloat8 独有的一个特殊位，用来动态调节指数/尾数的位宽分配 |

### 4.1 数据类型全景与体积收益

#### 4.1.1 概念说明

AMCT 把「量化到低比特」具体化为 **五种可选数据类型**。README 在「核心特性」里把它们列为三大亮点之一：

> 🔢 **多精度全栈** —— INT8 / INT4 / MXFP8 / MXFP4 / HiFloat8 任选

这五种可以分成 **三个家族**：

- **整数家族**：`INT8`、`INT4` —— 把浮点映射到均匀分布的整数格点。
- **Microscaling 浮点家族**：`MXFP8`、`MXFP4` —— 基于共享指数的低比特浮点。
- **华为自研浮点**：`HiFloat8` —— 带 Dot 位的特殊 8-bit 浮点。

> 补充：文档里还提到普通的 `FLOAT8`（FP8，仅 E4M3）和 `FP4_E2M1`，它们是 MXFP 家族的**基础元素**（MXFP 就是「一组 FP 元素共享一个指数」），4.3 节会讲。

#### 4.1.2 核心流程：体积收益只看「位数」

量化能压缩模型，本质原因只有一个：**用更少的比特存同一个数**。AMCT 的基线是 16-bit 浮点（大模型常用的 fp16 / bf16）。体积收益纯粹由目标位宽决定，和数据类型是整数还是浮点**无关**：

\[
\text{体积收益} = 1 - \frac{\text{目标位宽}}{16}
\]

- 8-bit 家族（INT8 / MXFP8 / HiFloat8 / FP8）：\( 1 - 8/16 = 50\% \) → **↓50%**
- 4-bit 家族（INT4 / MXFP4 / FP4）：\( 1 - 4/16 = 75\% \) → **↓75%**

也就是说，同样是 8-bit，`INT8`、`MXFP8`、`HiFloat8` 的体积压缩比**完全一样**（都 ↓50%）。它们的区别不在「省多少空间」，而在「**精度如何**」和「**硬件怎么算**」。这是本讲最重要的一个直觉。

#### 4.1.3 源码精读：README 性能收益表

README 用一张表把「数据类型 × 量化范围 × 配套算法 × 收益」一次铺清。这是你做选型时的第一手参考：

[README.md#L57-L63](https://github.com/gitcode.com/cann/amct/blob/ba53a0fdd6f3ed91a2d4875141d02aff746191a3/README.md#L57-L63) —— 性能收益对照表。逐行含义：

- **精度格式** 列：五种数据类型。
- **仅权重（W）** 列：只量化权重（缓解显存带宽瓶颈）时，每种数据类型支持的算法。
- **全量化（W+A）** 列：权重 + 激活都量化（追求算力）时支持的算法。
- **收益** 列：体积压缩比 + 一句话特点。

把这张表的「收益」列单独抽出来，就是一张体积速查表：

| 数据类型 | 位数 | 体积收益 | 一句话特点（README 原话） |
|----------|------|---------|--------------------------|
| INT8 | 8 | ↓50% | 吞吐 ↑ |
| INT4 | 4 | ↓75% | 低带宽友好 |
| HiFloat8 | 8 | ↓50% | 大动态范围 |
| MXFP8 | 8 | ↓50% | 高精度 |
| MXFP4 | 4 | ↓75% | 微缩浮点 |

注意两个细节：① 同是 8-bit 的 INT8/HiFloat8/MXFP8 收益都是 ↓50%；② 算法列（Min-Max/AWQ/MXQuant 等）是下一讲（u2-l3）的内容，本讲先记住「每种数据类型都有配套算法」即可。

4. **预期结果**：体积收益**只**由位数决定，和数据类型是整数还是浮点无关。这也解释了为什么「选哪种数据类型」是一个**精度问题**而不是一个**体积问题**。

#### 4.1.5 小练习与答案

**练习 1**：如果一个模型权重共 40GB（bf16 存储），分别量化到 INT8 和 MXFP4 后大约多大？

**参考答案**：INT8 是 8-bit，体积为原来的 \( 8/16 = 0.5 \)，约 20GB；MXFP4 是 4-bit，体积为 \( 4/16 = 0.25 \)，约 10GB。注意 INT8 和 HiFloat8 同为 8-bit，体积也一样是 20GB。

**练习 2**：既然 INT8 和 MXFP8 体积一样，为什么 AMCT 还要同时提供两者？

**参考答案**：体积由位数决定，但**精度表现**由数据类型的格式决定。整数（INT）是均匀格点，浮点（MXFP）是非均匀格点、对异常值更友好。不同权重的数值分布适合不同的格式，所以 AMCT 把选择权交给用户。

### 4.2 整数量化家族：INT8 与 INT4

#### 4.2.1 概念说明

整数家族是最经典、最容易理解的量化方式：把连续浮点数**等分**到若干个整数格点上。

- **INT8**：8 个比特，能表示 \( 2^8 = 256 \) 个整数（有符号范围 \(-128 \sim 127\)）。把 float32 矩阵乘法换成 int8 矩阵乘法，既加速又压缩。
- **INT4**：4 个比特，能表示 \( 2^4 = 16 \) 个整数。比 INT8 压缩得更狠（↓75% vs ↓50%），但格点更稀疏，精度损失通常更大。

整数格点是**均匀分布**的：相邻两个格点之间的距离（即 `scale`）处处相等。这正是上一讲量化公式 \( \text{int\_val} = \mathrm{clip}(\mathrm{round}(\text{float\_val}/\text{scale}+\text{offset}),\,-128,\,127) \) 的几何含义——等距切分。

#### 4.2.2 核心流程：位宽与精度的权衡

整数家族的核心权衡是一个**三角关系**：

```
位宽 ↓   →   体积 ↓（好）   但   格点数 ↓   →   精度损失 ↑（坏）
```

- INT8 有 256 个格点，多数层精度够用，是「安全牌」。
- INT4 只有 16 个格点，体积诱人（↓75%），但直接 Min-Max 量化往往掉点严重，所以 INT4 几乎总要搭配更聪明的算法（AWQ / GPTQ / FlatQuant，见 README 表第 60 行）来补偿。

文档对两者的定位很直接：INT4「相较于 int8 量化，可以实现更优的量化效果（指压缩率），但可能带来更大的精度损失」。

#### 4.2.3 源码精读：INT8 / INT4 定义

整数家族在概念文档里只有简短两段，但点出了本质——**把 float 矩阵乘换成 int 矩阵乘**：

[docs/zh/compression_concepts.md#L95-L101](https://github.com/gitcode.com/cann/amct/blob/ba53a0fdd6f3ed91a2d4875141d02aff746191a3/docs/zh/compression_concepts.md#L95-L101) —— INT8 与 INT4 定义。关键信息：

- 第 97 行（INT8）：用 8-bit int8 表示（比如）32-bit float32，**把 float 的矩阵乘运算转换为 int8 的矩阵乘运算**，加速运算 + 压缩。
- 第 101 行（INT4）：用 4-bit int4 表示 float32；相较 int8 压缩更好，但**可能带来更大的精度损失**。

文档还在「量化因子」一节给出了 INT8 的具体映射公式（上一讲已学过，这里只做锚点）：

[docs/zh/compression_concepts.md#L144-L146](https://github.com/gitcode.com/cann/amct/blob/ba53a0fdd6f3ed91a2d4875141d02aff746191a3/docs/zh/compression_concepts.md#L144-L146) —— INT8 量化公式 `int_val = clip(round(float_val/scale+offset), -128, 127)`。这条公式就是整数均匀量化的数学表达：除以 `scale`（等距切分）、加 `offset`（对齐零点）、`round`（舍入到最近格点）、`clip`（限制在 \(-128 \sim 127\)）。

#### 4.2.4 代码实践

1. **实践目标**：用一张小算例直观感受「位宽越低、格点越稀、误差越大」。
2. **操作步骤**：阅读下面的**示例代码**（非项目代码，仅为演示概念），理解每一步。
3. **需要观察的现象**：同一组浮点数，用 INT8（256 格点）量化后几乎无损，用 INT4（16 格点）量化后误差明显变大。
4. **预期结果**：INT4 的最大误差显著大于 INT8。这解释了为什么 INT4 必须配好算法。结果待本地验证。

```python
# 示例代码：演示 INT8 vs INT4 的均匀量化误差差异（非项目代码）
import numpy as np

x = np.array([0.12, -0.37, 1.55, -2.10, 0.88, 2.45, -1.02, 0.50])

def uniform_quant(x, n_bits):
    scale = x.max() / (2 ** (n_bits - 1) - 1)   # 对称量化
    q = np.clip(np.round(x / scale), -(2 ** (n_bits - 1)), 2 ** (n_bits - 1) - 1)
    return q * scale                              # 反量化回浮点

xq8 = uniform_quant(x, 8)
xq4 = uniform_quant(x, 4)
print("INT8 最大误差:", np.abs(x - xq8).max())
print("INT4 最大误差:", np.abs(x - xq4).max())
```

5. **预期输出**：INT8 最大误差接近 0（待本地验证具体数值），INT4 最大误差明显更大。

#### 4.2.5 小练习与答案

**练习 1**：INT8 有符号模式下能表示多少个不同的值？INT4 呢？

**参考答案**：INT8 有 \( 2^8 = 256 \) 个值（\(-128 \sim 127\)）；INT4 有 \( 2^4 = 16 \) 个值（\(-8 \sim 7\)）。

**练习 2**：为什么 README 表里 INT4 的「仅权重」和「全量化」算法（AWQ/GPTQ/FlatQuant）都比 INT8（Min-Max）复杂？

**参考答案**：因为 INT4 只有 16 个格点，朴素 Min-Max 均匀量化误差太大，必须用感知激活（AWQ）、逐层优化（GPTQ）或可学习变换（FlatQuant）等更聪明的算法来重新分配量化误差，才能保住精度。算法细节在 u2-l3 和第 6 单元讲。

### 4.3 浮点量化与 Microscaling：FP8/FP4 → MXFP8/MXFP4

#### 4.3.1 概念说明

整数家族的格点是**均匀**的，但神经网络里的数值分布往往**不均匀**（很多小数 + 少数大异常值）。均匀格点在异常值上浪费严重。**浮点**格式用「指数 + 尾数」表示数，格点是**非均匀**的，对异常值更友好。

一个 \( b \)-bit 浮点数由三部分组成：

\[
\underbrace{S}_{\text{符号}} \;+\; \underbrace{E}_{\text{指数位（决定范围）}} \;+\; \underbrace{M}_{\text{尾数位（决定精度）}}
\]

- 指数位 \( E \) 越多 → 能表示的**范围**越大（动态范围）。
- 尾数位 \( M \) 越多 → 每个数的**精度**越高。
- 总位宽固定时，\( E \) 和 \( M \) 是**此消彼长**的。

文档里出现的浮点基础格式有两种：

- **FP8（E4M3）**：4 比特指数 + 3 比特尾数 + 1 符号位，用于推理。
- **FP4（E2M1）**：2 比特指数 + 1 比特尾数 + 1 符号位，共 16 个值。

而 **MXFP8 / MXFP4** 就是「让一组 FP8 / FP4 元素**共享一个指数**」——这就是 **Microscaling（微缩放）**。

#### 4.3.2 核心流程：shared exponent 共享指数

普通浮点：**每个**元素都自带一个指数，要花额外比特存。

Microscaling：把元素**分组**（AMCT 对权重按 `-1` 轴，**每 32 个元素一组**），**整组共享一个指数**，组内每个元素只存小尾数。这样：

- 单个元素的存储位宽大幅下降（指数被「摊」到 32 个元素上）。
- 共享指数天然捕捉了这 32 个数的整体量级，组内只需表示相对差异 → **精度更高、量化粒度更细**。

用伪代码表示这个「先求共享指数、再量化每个元素」的过程：

```
输入: 一组元素 x[0..31]   （沿权重 -1 轴的 32 个数）
1. shared_exp = 根据本组最大绝对值算出一个共享指数   # 见文档公式图
2. shared_scale = 2 ^ shared_exp
3. 对每个 x[i]:
       normalized[i] = x[i] / shared_scale          # 归一化到本组量级
       element[i]    = quantize_to_fp(normalized[i]) # 量化成 FP8 或 FP4
存储: {shared_scale, element[0..31]}                  # 1 个 scale + 32 个低位元素
```

> 说明：文档第 67、81 行写明「每 32 个数据计算一个 shared exponent」，并把具体公式放在两张图里（`...029086.png` / `...029084.png`）。由于无法直接读取图片内容，上面的伪代码给出的是 Microscaling 的**通用思路**（取组内最大绝对值推共享指数），精确表达式以文档公式图为准（待确认）。

为什么是 32？这是 Microscaling 标准（OCP MX 规范）的默认块大小，也是昇腾硬件加速单元的处理粒度。文档「总体说明」里点了一句：MXFP8/MXFP4 **有专门的硬件加速单元，处理量化因子速度更快**。

#### 4.3.3 源码精读：FP8 → MXFP8 → MXFP4 → FP4_E2M1

文档按「基础浮点 → Microscaling」的顺序组织，建议照此顺序读：

**第四步：FP4_E2M1 的可表示值**。[docs/zh/compression_concepts.md#L85-L93](https://github.com/gitcode.com/cann/amct/blob/ba53a0fdd6f3ed91a2d4875141d02aff746191a3/docs/zh/compression_concepts.md#L85-L93) —— FP4_E2M1 定义。第 93 行给出了它仅有的 16 个值：

\{ \pm 0,\ \pm 0.5,\ \pm 1,\ \pm 1.5,\ \pm 2,\ \pm 3,\ \pm 4,\ \pm 6 \}
\]

这就是 MXFP4 里每个 element 能取的全部值（注意 \(\pm 0\) 算两个表示，合计 16 个码点）。可见 4-bit 浮点的格点**非常稀疏且非均匀**（0.5、1、1.5 之后直接跳到 2、3、4、6），所以必须靠共享指数把它们对齐到正确的量级。

**第五步：选型小提示**。[docs/zh/compression_concepts.md#L103-L107](https://github.com/gitcode.com/cann/amct/blob/ba53a0fdd6f3ed91a2d4875141d02aff746191a3/docs/zh/compression_concepts.md#L103-L107) —— 总体说明。第 107 行给出一个实用经验：数据**均匀分布**建议 FP4_E1M2，**高斯分布**建议 FP4_E2M1。

#### 4.3.4 代码实践

1. **实践目标**：用一小段代码把「共享指数」这个抽象概念变成可看的数字。
2. **操作步骤**：阅读下面的**示例代码**（非项目代码），关注「共享一个 scale 后，32 个稀疏格点被整体对齐到正确量级」这件事。
3. **需要观察的现象**：同一组 FP4 格点（16 个值），配上不同的共享 scale，就能表示完全不同量级的数（0.x、几十、几百…）。
4. **预期结果**：你能理解为什么「共享指数」让低比特浮点既省空间又有精度。待本地验证。

```python
# 示例代码：演示 shared exponent 让稀疏 FP4 格点对齐到不同量级（非项目代码）
import numpy as np

# FP4_E2M1 的全部 16 个码点（正半部分，负半部分对称）
fp4_positive = np.array([0, 0.5, 1, 1.5, 2, 3, 4, 6])

# 假设某组 32 个元素的最大绝对值约等于 48
shared_scale = 48 / 6      # 让最大码点 6 对齐到 48 → shared_scale = 8.0
representable = fp4_positive * shared_scale
print("这组可表示的值（正半）:", representable)
# → [ 0.  4.  8. 12. 16. 24. 32. 48.]   # 32 个元素共享这一个 scale
```

5. **延伸思考**：如果不共享指数、每个元素各存一份指数，4-bit 几乎被指数占满，留给尾数的位根本不够；共享指数正是 MXFP4 在 4-bit 下仍能保持精度的关键。

#### 4.3.5 小练习与答案

**练习 1**：用一句话回答：MXFP8 相比普通 FP8 多了什么？它带来什么好处？

**参考答案**：多了 **Shared Exponent（共享指数）**——一组（32 个）元素共用一个指数。好处是：指数被摊到组内所有元素上，单个元素只需存低位尾数，存储更省、精度更高、量化粒度更细（文档第 55 行原话）。

**练习 2**：FP4_E2M1 一共能表示多少个不同的非零绝对值？为什么说它的格点「非均匀」？

**参考答案**：正半部分非零绝对值有 7 个：0.5、1、1.5、2、3、4、6（负半对称）。相邻间距分别是 0.5、0.5、0.5、1、1、2——间距越来越大，所以是**非均匀**（越大的数间距越大），这正是浮点区别于整数（INT）均匀格点的核心特征。

### 4.4 华为自研 HiFloat8：Dot 位、锥形精度与大动态范围

#### 4.4.1 概念说明

`HiFloat8`（HiF8）是**华为为 AI 处理器定制的自研 8-bit 浮点格式**。它和普通 FP8 一样是 8-bit，但多了一个独特的 **Dot 位**，从而同时拿到两个看似矛盾的好处：

- **大动态范围**：能表示的数值跨度比普通 FP8 大得多。
- **锥形精度（tapered precision）**：在小数值附近精度更高，大数值附近精度更低——像锥子一样「一头尖」。

README 把它列为独立特性：`锥形精度 + 大动态范围`（第 61 行）。

#### 4.4.2 核心流程：Dot 位如何动态调节位宽

普通浮点的指数位宽和尾数位宽是**固定**的（比如 E4M3 永远 4 指 3 尾）。HiFloat8 在 IEEE 754 基础上**扩增了一个 Dot 位域**，用来**动态调整阶码域（指数）位宽和尾数域位宽的分配**。

直觉上可以这样理解：

```
普通 FP8:   指数位宽 E = 固定值    尾数位宽 M = 固定值
HiFloat8:   指数位宽 E ⇄ 尾数位宽 M  由 Dot 位动态调节（此消彼长）
```

当 Dot 位取不同值时，同一组 8 个比特被切成不同的 \( E + M \) 组合——需要更大范围时多给指数位，需要更高精度时多给尾数位。这种「按需分配」造就了 **锥形精度**：数值越小、能用到的尾数位越多，精度越高；数值越大、精度越粗。这恰好匹配神经网络权重「大量小数 + 少数大数」的分布，所以对量化更友好。

> 注意：第 23 行提到「dot 位为 `0b'0000` 时，HiF8 数据为 Denormal value（非规格化值）」——这是浮点格式处理极小数的标准机制，本讲只做了解，不展开。

#### 4.4.3 源码精读：HiFloat8 定义与精度边界

**定义与组成**。[docs/zh/compression_concepts.md#L17-L34](https://github.com/gitcode.com/cann/amct/blob/ba53a0fdd6f3ed91a2d4875141d02aff746191a3/docs/zh/compression_concepts.md#L17-L34) —— HIFloat8 定义。关键信息：

- 第 19 行：HiF8 由 **Sign（符号）、Dot、Exponent（指数）、Mantissa（尾数）** 四部分组成；**Dot 位用于动态调整阶码域位宽和尾数域位宽**——这是它和普通 FP8 的根本区别。
- 第 23 行：\( S \) 为符号、\( E \) 为指数、\( M \) 为尾数；dot 位为 `0b'0000` 时为 Denormal value。
- 第 27–32 行：转换原则（NAN→NAN、INF→INF、超上限→MAX、低于下限→0）。

**精度边界——量化「大动态范围」的硬证据**。[docs/zh/compression_concepts.md#L34](https://github.com/gitcode.com/cann/amct/blob/ba53a0fdd6f3ed91a2d4875141d02aff746191a3/docs/zh/compression_concepts.md#L34) —— 第 34 行给出两条精度下限，是理解「动态范围」最直观的数字：

- 普通 **float8**：当数据绝对值 \( < 1.5 \times 2^{-10} \approx 0.00146 \) 时，精度无法保证。
- **HiF8**：当数据绝对值 \( < 1.5 \times 10^{-24} \) 时，精度才无法保证。

把这两个下限放在一起对比：

\[
1.5 \times 2^{-10} \approx 1.5 \times 10^{-3} \quad \text{（float8）} \qquad \text{vs} \qquad 1.5 \times 10^{-24} \quad \text{（HiF8）}
\]

HiF8 能精确表示的数比 float8 小了约 \( 10^{21} \) 倍——这就是 README 所说「大动态范围」的来源。

**总体定位**。[docs/zh/compression_concepts.md#L105](https://github.com/gitcode.com/cann/amct/blob/ba53a0fdd6f3ed91a2d4875141d02aff746191a3/docs/zh/compression_concepts.md#L105) —— 第 105 行一句话总结：**「HiF8 相比于 float8 能更好的兼顾精度和动态范围」**。

#### 4.4.5 小练习与答案

**练习 1**：HiFloat8 比普通 FP8 多了哪个位？它的作用是什么？

**参考答案**：多了 **Dot 位**。它的作用是**动态调整指数位宽和尾数位宽的分配**——需要更大范围时多给指数位，需要更高精度时多给尾数位，从而造就锥形精度 + 大动态范围（文档第 19 行）。

**练习 2**：为什么说 HiFloat8 的精度是「锥形」的？

**参考答案**：因为 Dot 位让位宽分配可变：小数值附近能用到更多尾数位 → 精度高；大数值附近尾数位变少 → 精度低。精度随数值大小像锥子一样变化（小端尖、大端粗），这恰好匹配神经网络「小数多、大数少」的分布，比均匀的整数格点更省精度。

**练习 3**：同为 8-bit，HiFloat8、MXFP8、INT8 的体积收益是否相同？它们的区别在哪？

**参考答案**：体积收益**相同**（都 ↓50%，因为位宽一样）。区别在**精度特性**：INT8 是均匀整数格点；MXFP8 是带共享指数的非均匀浮点；HiFloat8 是带 Dot 位的锥形浮点、动态范围最大。选谁取决于权重分布和精度需求。

## 6. 本讲小结

- AMCT 支持 **五种** 低比特数据类型，分 **三家族**：整数（INT8/INT4）、Microscaling 浮点（MXFP8/MXFP4）、华为自研浮点（HiFloat8）。
- **体积收益只由位宽决定**：8-bit 一律 ↓50%，4-bit 一律 ↓75%，和数据类型无关；选型的本质是精度问题。
- **INT8/INT4** 是均匀整数格点，位宽越低格点越稀、误差越大，所以 INT4 几乎必须配更聪明的算法。
- **MXFP8/MXFP4 相比 FP8/FP4 多了 shared exponent**：沿权重 `-1` 轴每 32 个元素共享一个指数，存储更省、精度更高、粒度更细，并有专门硬件加速单元。
- **FP4_E2M1** 只有 16 个非均匀值 \( \{\pm 0, \pm 0.5, \pm 1, \pm 1.5, \pm 2, \pm 3, \pm 4, \pm 6\} \)，正靠共享指数对齐到正确量级。
- **HiFloat8** 多一个 **Dot 位**，可动态调节指数/尾数位宽，造就**锥形精度**与**大动态范围**（精度下限低至 \( 1.5 \times 10^{-24} \)，比 float8 的 \( 1.5 \times 2^{-10} \) 小约 \( 10^{21} \) 倍）。
