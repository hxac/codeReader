本讲是 AMCT 的「能跑起来」入门课，讲清一次完整 LLM 训练后量化（PTQ）如何拆成四条按固定顺序串联的 CLI 命令：`eval`（评估精度）→ `extract_ptq_data`（录制校准数据）→ `ptq`（逐层优化量化参数）→ `deploy`（烘焙导出可部署权重）。四阶段靠 `data_dir`（extract↔ptq 传数据）和 `*_param_dir`（ptq↔deploy 传参数）两个目录接力；`eval` 是旁观者，不参与数据链。用户侧统一用 `python -m amct_pytorch.<cmd>`，它先命中根目录「薄壳」模块（延迟导入以加速启动），再转发给 `amct_pytorch/cli/llm/<cmd>.py` 真入口，统一套路为 `parser_gen(command=...)` → 构造 Workflow → `run()`。引入的关键术语包括：PPL（困惑度，量化前后各测一次以看掉点幅度）、Block（decoder layer，默认量化粒度 granularity=block）、`--quant_target`（量化模块，取值 mlp/moe/attn-linear/attn-cache，extract 与 ptq 阶段每次只能填一个且必须一致）、`--quant_dtype`（int/mxfp/hifp）、`--bit_config`（yaml 解析为 BitPolicy 对象控制 w_bits/a_bits）、`--algos`（如 lwc lac 等量化算法）。强约束：extract 与 ptq 的 quant_target、granularity 必须一致；eval_mode=bf16 时 bit_config 不得含低于 16-bit 的配置，否则 `_validate_eval_mode` 报错。本讲不深入算法与实现，只解决命令怎么写、怎么串。
