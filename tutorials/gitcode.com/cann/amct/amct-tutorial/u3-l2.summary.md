本讲剖析 `amct_pytorch/workflows/` 下四条命令（eval/extract_ptq_data/ptq/deploy）对应的四个 Workflow 类。核心结论是：它们共用一套「`run()` → `setup()` → 按 granularity 分发 → `logger.remove(sink_id)`」三段式编排骨架，稳定区为 setup 与收尾，变化区仅在中段的分发分支。`setup()` 固定四步：惰性注册组件 → 准备目录 → 建 pipeline → 挂日志 sink，其中注册必须先于建 pipeline（取模型适配器依赖注册表）。引入的关键术语：**运行粒度 granularity**（block/model/tensor，与 classic 量化算子 strategy 的 tensor/channel/group 同名但异义，默认值 `model`，PTQ/extract/deploy 须显式传 `block`）、**sink_id**（loguru 临时文件 sink 句柄，由 setup 返回、run 收尾卸除以防日志串台）、**惰性注册 + 幂等保护**（注册不在 import 时、而在每次 setup 触发，靠 `_REGISTERED` 布尔位避免重复）、以及 PTQ 特有现象——granularity 兼做 `SOLVER_REGISTRY` 选型键（`block`→`BlockwiseSolver`）。此外 PTQ 独有断点续跑逻辑：逐 unit 检查 `.pt` 参数文件存在即跳过。
