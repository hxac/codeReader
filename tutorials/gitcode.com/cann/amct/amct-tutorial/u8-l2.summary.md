本讲以 hifloat8_cast 为样本剖析 amct_ops 的 NPU 算子三层结构：op_kernel（device 端 Ascend C kernel）、op_extension（host 端 C++ binding 与注册）、python（`.so` 加载与薄包装），三层由 CMakeLists 编进同一 `.so`。引入并建立 GM、UB、AIV、tiling、MTE、LUT、dispatcher、PrivateUse1、Meta 等昇腾硬件与 PyTorch 分发术语。核心结论：device kernel 用 LUT 查表实现 HiFloat8↔FP16/BF16 转换以避开 Dot 位的复杂位运算，encode 借「半空间 LUT + 符号分离」把 32KB 表压成一半；tiling 是 host 查平台实际 UB/核数算好后传给 device 的单向只读契约；host 侧用 TORCH_LIBRARY_FRAGMENT 往统一 `amct` 命名空间追加算子，并挂 PrivateUse1（NPU 真跑）与 Meta（形状推导）两套 dispatcher 实现，昂贵 LUT 按 (deviceIndex, castMode) 做进程级缓存。
