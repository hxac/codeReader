本讲讲解 AMCT 四条命令（eval/extract_ptq_data/ptq/deploy）的参数体系与命令分发。命令分发采用「根目录薄壳 + 统一三段式」结构：根目录 `amct_pytorch/<cmd>.py` 用延迟导入加速启动，转发到 `cli/llm/<cmd>.py` 的 `main()`，执行「`parser_gen(command)` 解析参数 → 构造 Workflow → `run()`」四条命令同构，仅 `command` 字符串与 Workflow 类不同。核心是参数定义中心 `parser_gen(command=None)`——四条命令共用一份参数表，按六组划分；`command` 是命令身份钩子，触发命令专属校验。关键术语：`--quant_target` 的四个取值 `mlp`/`moe`/`attn-linear`/`attn-cache` 是模块分类名（非层名），与 `bit_config` yaml 顶层分组一一对应，且 extract_ptq_data 与 ptq 两阶段必须一致（使用约定，非解析期强约束）。`--bit_config` 经 `BitPolicy.from_yaml` 初始化为 `args.bit_policy`，不传则全 16-bit。仅 `command=="eval"` 时调用 `_validate_eval_mode`：当 `eval_mode=bf16`（测原始浮点基线）而 yaml 任一处出现 <16-bit 条目（由 `has_quant_linear()`/`has_quant_cache()` 递归扫描判定）即抛错，防止低比特配置被静默忽略导致误导性 PPL。本讲到「准备 run()」为止，Workflow 内部编排骨架留给 u3-l2。
