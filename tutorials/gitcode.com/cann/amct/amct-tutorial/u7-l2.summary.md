本讲拆开 quant_obj 黑盒。DTYPE_REGISTRY 登记 int/mxfp/hifp 三类量化数据类型，三者共享统一契约：forward 在 observe 或 16-bit 时透传、否则 fake_quant；export_deploy 产出真低比特 payload。QuantDequantInt 委托无状态 int_impl，权重走 per-channel weight_quant（带舍入偏移 v、用 STE 保证可微），激活走 per-token dynamic_per_token_quant。QuantDequantMx 用 Microscaling，每 32 元素共享一个 uint8 指数 e8m0，MXFP8 尾数为 float8_e4m3fn、MXFP4 为打包 uint8；HiFloat8 仅支持伪量化，deploy 尚未实现。export_deploy 落盘链路为 QuantLinear→WeightQuantizer→quant_obj→payload 字典，命名规则是 qweight 覆盖原 .weight、其余字段改写为 .weight_<字段名>、值为 None 的字段跳过。同名 key 语义随数据类型不同（INT 的 weight_scale 为 float32、MXFP 为 uint8），这是 deploy 阶段 is_mx 总开关区分的根本原因。
