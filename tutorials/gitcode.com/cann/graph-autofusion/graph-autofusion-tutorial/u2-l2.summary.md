本讲讲解 `super_kernel/` 组件的源码分层与构建产物。组件为双层结构：JIT 层（`src/jit/superkernel/`，Python，编译期）负责读入算子元数据（`op_infos`/`sub_op_infos`）并经入口 `super_kernel.py: compile()` 生成融合超核的 C++/设备源码；AOT 层（`src/aot/`，C++，运行期）编入 `libascendsk.so`，经入口 `aclskOptimize()`（内部走 `SuperKernelOptimizer::Process`）做图优化、scope 调度与超核下发。两层语言、时机不同，无源码级 import/include 依赖，仅靠公共 C 头对接。

关键术语：`include/super_kernel/super_kernel.h` 是唯一对外公开的 C 头，以 `extern "C"` + `ACL_FUNC_VISIBILITY` 导出 `aclskOptimize`/`aclskScopeBegin`/`aclskScopeEnd` 等稳定 ABI 契约，并用「枚举 `aclskOptionType` + 联合体 `aclskOption`」传参；JIT 侧 `SuperKernelKernelType`/`SuperKernelDeviceType` 与头内核类型枚举编号不同，不可混用。

核心结论：CMake 定义两个目标——`superkernel_whl`（产出 `superkernel-0.1.0-py3-none-any.whl`，JIT 包）与 `ascendsk`（产出 `libascendsk.so`，AOT 运行时）；`kernel/` 子目录按 `dav-2201`/`dav-3510` 两平台编 `sk_entry`/`sk_scope`，再由 `gen_sk_entry_stub.py` 将设备 `.o` 二进制转为 C++ 数组嵌入 `.sk.kernel` 段，实现单 `.so` 部署；JIT 走 pytest、AOT 走 CMake+gtest 测试，两路径分离。
