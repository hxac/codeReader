本讲梳理 Autofuse 测试体系的三个模块：autofuse_framework（编译器框架 UT/ST）、autofuse_ascendc_api（AscendC API 层）与 autofuse_e2e（端到端）。核心链路为 build.sh 的模块路由表转发到 autofuse_module_test_suite，再由 run_autofuse_test.sh 按「解析选项 → cmake 配置 → make 目标 → ctest」四段式编排，UT/ST 各由按模块名分发的 case 控制，任一步失败即 exit 1。关键概念包括：RUN_V35_TESTS 总开关（由 v35 目录存在性决定）、backend_e2e_v2 用例的「两级注册」机制（CMake 侧 add_subdirectory + backend_e2e_st_test 生成 _codegen_v2/_e2e_v2 双目标，脚本侧 MAKE_TARGET_LIST 显式登记并经 sed 推导与 ctest -R 正则消费）、两阶段 e2e（build_backend_test1/test2 标签）以及 indirect_load 用例工厂（IL_* 编译期宏参数化 SIMD/SIMT/SK 用例）。最重要结论：新增 v2 用例目录不会被自动发现，漏登记脚本清单会导致用例「编译通过却静默不跑」。覆盖率由 RUN_TEST 配置下 gcc 插桩供数，get_coverage 用 lcov/genhtml 产出报告。
