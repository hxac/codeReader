本讲介绍 graph-autofusion 的构建系统，分为 Bash 编排层 `build.sh` 与 CMake 构建描述层两层结构。`build.sh` 不传选项会直接报错，所有开关默认值集中在 `checkopts()` 函数，默认开启 autofuse 构建。核心机制有三：一是「模块（superkernel/autofuse_framework/autofuse_ascendc_api/autofuse_e2e）× 实现（py/cpp）× 动作（ut/st）」三维选择体系，合法组合登记在关联数组路由表 `MODULE_ACTION_HANDLERS` 中，由 `normalize_test_selection` 展开，不存在的组合会被跳过；二是 `-f <变更文件清单>` 智能跳过，按改动落在 `super_kernel/` 还是 `autofuse/` 决定跳过无关组件，纯文档改动直接 `exit 200`；三是 `-j` 经 `check_param_j` 校验为正整数并钳制到 CPU 核数，项目约定手动加 `-j 8` 以防 Autofuse 大型 C++ 工程编译 OOM。`cmake_config` 作为 Bash 与 CMake 的翻译器，将 `--no-autofuse` 等开关翻译为 `-DBUILD_AUTOFUSE=OFF`，驱动顶层 CMake 的 `add_subdirectory` 装配；`--pkg` 最终产出 `.run` 自安装包。关键术语包括路由表、智能跳过、退出码 200、OOM 约定，后续讲义据此承接环境搭建与测试体系。
