本讲是 ATT（自动 Tiling）阶段的开篇，围绕 `gen_model_info` 子模块讲清性能建模如何完成。核心结论：ATT 把 AutoSchedule 产出的候选 scheduled graph 翻译成 `ModelInfo`——「目标 + 约束」总账本，目标 `objects` 是按 `PipeType`（MTE2/VEC/MTE3 等）分桶的符号耗时表达式，满足 Cost_p = Σ t_n·c_{n,p} + H_p；因支持动态 shape，全部用 `Expr` 符号表达式而非数值。建模入口 `GenerateSingleModelInfoWithContext` 固定三步：parser（`AscendGraphParser` 把图翻成中间表示 `TuningSpace`）→ expr 生成（`PipePerfExpr` 累加 pipe 耗时）→ pass；本次重构引入文件内私有的 `ModelGenerationContext`，把 Codegen 路径门禁 `is_cv_ub_fusion`（kUBFuse 时 raw 1D 节点回退 legacy 模型）传入并回填到 `NodeInfo`，不扩公开接口。算子单次耗时 c 由 `api_perf_register` 子模块以自注册模式提供（`EvalCosts` + `ApiPerfFactory`），cost 数据来自 `v1/perf_param_v1.cpp` 内嵌 JSON 的线性模型（k·repeat_time+b）与 Load/Store 带宽模型；`NodeDetail` 新增 `NddmaDescriptorInfo` 为 NDDMA 精确模型透传合轴前原始描述。`TuningSpace` 同时是调优维度载体：轴级属性、图级配置，以及新增的 Reduce R 轴与尾轴平衡重排策略（`ReduceTailTilePolicy`）。下一讲进入 expr_gen 与求解器，把 `objects` 从符号变成具体 tiling 取值。
