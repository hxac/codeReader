本讲解答 Autofuse 中算子能力的最终来源：codegen 生成的设备 kernel 里每个算子的计算代码从何而来。结论：`autofuse/ascendc/api/*.h` 是 CANN 原生 AscendC API 的二次封装，函数均为 `template + inline __aicore__`、运行于设备端（AI Core），封装动机为补齐 dtype/场景、统一签名、承担对齐与分块调度；公共工具 `KernelUtils::BlkSize/RptSize` 基于 `ONE_BLK_SIZE`(32)、`ONE_REPEAT_BYTE_SIZE`(256)、`MAX_REPEAT_TIME`(255) 换算硬件的块与重复单位。代表类里 reduce 用 `Adapt` 适配层抹平原生 7/8 参签名、`ReduceLast` 按 (m,k) 分块并补齐 int32，datacopy 以两个重载分别承担 GM↔UB 的 load/store，broadcast 按 dtype 与 (m,k,z) 形状多层 `if constexpr` 分发。衔接机制是本讲核心：codegen 的 `api_call` 层只生成「调用语句」，ascendc/api 提供「函数定义」，定义经 sed 包成原始字符串字面量 `*_str.h`、启动期注册进 `AscendCApiRegistry` 单例、生成期 `GetFileContent` 按图中算子按需取出并拼进 kernel 源码（集合去重，`utils.h`、`brc_inline_api.h` 无条件嵌入），两端靠同名函数与签名对接。新增算子设备端封装的最小改动面为 `api/CMakeLists.txt`、`ascendc_api_registry.cpp` 与对应 `api_call` 生成器（外加 ASCIR 注册）。
