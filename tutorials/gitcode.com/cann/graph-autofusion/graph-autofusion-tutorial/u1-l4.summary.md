本讲承接上一讲的编译产物，讲清 Autofuse「从能编译到能上板运行」的最后一公里，关键是搞懂 CANN 软件栈分层与每层的环境注册。运行环境须自底向上搭建四层：NPU 驱动与固件（仅上板需要，管理设备文件）、CANN Toolkit 与 ops 算子包（提供编译器与运行时）、graph-autofusion 的 .run 增量包（把增强后的 Autofuse 能力装进 Toolkit 同一棵目录树）、torch_npu（让 PyTorch 识别 NPU 并为 torch.compile 提供 ascendc 后端）。CANN 有 CANNLab、Docker、手动三种安装方式。每次新开终端必须 source 两层脚本：驱动层的 setenv.sh 与 Toolkit 层的 set_env.sh，并 export ASCEND_DEVICE_ID 指定所用 NPU 卡。使能 Autofuse 只需一行 torch.compile(options={"npu_backend":"ascendc"})，用例 af_add_ge.py 演示了 add 与 ge 的 pointwise 融合；融合成功时 torch_compile_debug 目录下会出现 autofused_ 前缀产物。最关键的结论是：跑用例前必须先安装 .run 包，否则运行时会加载旧动态库报 undefined symbol。
