本讲精读 `configs/op_list.yaml`：SiP 的算子编译清单，用 YAML 两层嵌套表达 Operation→Kernel(tactic)→芯片架构的三级映射，与 `build_config.json` 的 `targets` 共同构成两层芯片开关（AND 关系）。解析器住在 MKI 外部依赖的 `op_list_utils.py`：配置期把为 true 的三元组译成 `BUILD_<Op>_<Tactic>_<SoC>` 开关写入生成的 `op_build.cmake`；`kernel_config.cmake` 的 `add_operation`/`add_kernel` 宏按开关放行，调 `scripts/compile_ascendc.py` 提取 tiling key、按 soc×channel 查 arch（ascend910b 用 ccec 编 dav-c220-vec，ascend950 用 bisheng 编 dav-c310）、用 ld.lld 链成 fatbin 并写 meta json；`build_util.py` 再按架构清单收集 `.o`/`.json` 归拢进交付目录并写 meta.ini。新算子登记可手改 yaml 或删除后由扫描器按源码树重生成；tactic 名须与 `add_kernel` 实参、Operation 名须与 `REG_OPERATION` 注册名逐字一致。核心结论：登记缺失即「静默不存在」——Host 注册代码与 Device kernel 均不编译，meta.ini 无记录，直到运行期查找算子才暴露。
