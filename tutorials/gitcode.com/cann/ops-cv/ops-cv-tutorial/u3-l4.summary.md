本讲承接 u3-l3 的 Tiling 机制，回答「tiling 选了哪种策略如何告知 kernel」。核心概念是 TilingKey：Host 侧 TilingFunc 通过 `SetTilingKey` 写入的 uint64 策略编号，框架据此选择 kernel 二进制与执行分支，kernel 侧以 `TILING_KEY_IS` 镜像判断，两者是需人工保持一致的跨侧契约。讲义覆盖四个模块：add_example 的声明宏新式写法（`ASCENDC_TPL_ARGS_DECL` 配合 `GET_TPL_TILING_KEY`，编译期展开、防两侧数值不一致，kernel 侧用 `if constexpr` 分发）；common 层 `GET_TILINGKEY` 十进制位组装工具（key = 10^19 + Σ id_i·10^i，每位一个策略维度）及 `tiling_templates_registry.h` 的 soc_version + priority 多候选注册降级机制；resize_bilinear_v2 手写万位分段常量的 9 策略实战，采用「特化在前、通化兜底」有序匹配链（all_copy→point_copy→broadcast→c_parallel→simt），索引宽度 useIdx32 亦是策略维度，且一种策略配一套专属切分算法；多架构适配依赖 `op_host/arch35`、`op_kernel/arch35` 目录隔离与 def 文件 `AddConfig("ascend950")` 芯片绑定，config 目录的 `binary.json` 登记 dtype/format 到二进制映射，`simplified_key.ini` 控制 opc 编译选项。
