本讲建立 ops-cv 仓库的目录地图与算子工程交付件标准。仓库顶层分四类：算子分类目录（image、objdetect、experimental 预留贡献区）、公共代码（common、cmake）、示例与测试（examples、tests）、文档与工程配置（docs、build.sh 等）。标准算子工程由 CMakeLists、README、docs、examples、op_api、op_graph、op_host、op_kernel（或 op_kernel_aicpu）、tests 等交付件组成，多数可选；命名遵循小写下划线算子名与大驼峰 aclnn 接口两套约定。核心概念：Host 侧（op_host，负责注册、Infershape、Tiling）与 Device 侧（op_kernel，执行计算）；根 CMakeLists 自动收集带 CMakeLists.txt 的子目录，目录存在即参与编译。关键结论：缺目录是实现方式声明——缺 op_host/op_kernel 可能复用其他算子或暂无 Ascend C 实现，缺 op_api 不支持 aclnn，缺 op_graph 不支持图模式。add_example 为精简标准件（op_api 自动生成），resize_bilinear_v2 为齐全样本（含 config、arch35 子场景、framework、st），roi_align 为组合式反例（无 op_kernel，aclnn 实现内嵌 op_host/op_api）。
