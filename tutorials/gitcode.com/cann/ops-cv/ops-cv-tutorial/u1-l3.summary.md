本讲走读 ops-cv 仓库的统一编译体系。核心模块包括：总入口 build.sh（薄入口，main 按开关调度 scripts/ 下 conf/options/cmake/lib/ut 等 8 个子脚本）、build_options.sh 的 checkopts（解析 --pkg/--soc/--ops/-u/--vendor_name 等参数并做互斥校验，点亮 ENABLE_BINARY、ENABLE_CUSTOM、ENABLE_PACKAGE 等开关）、build_cmake.sh（把 shell 变量翻译为 -DASCEND_OP_NAME、-DASCEND_COMPUTE_UNIT 等 CMake 变量，逗号转分号成列表，--soc 做白名单校验并清除 CMakeCache）、根 CMakeLists.txt（option 开关与目录收集，examples/ 仅在 --ops 含 add_example 时编译）、cmake/ 目录三件套（variables.cmake 定义 NEED_COMPILE_OPS 与 COMPILED_OPS 对账及 vendors/<vendor>_cv 安装路径；opbuild.cmake 调 op_build 从 *_def.cpp 自动生成 aclnn 接口代码到 build/autogen；gen_ops_info.cmake 为全芯片生成算子信息、仅为目标芯片编译二进制）。关键结论：--ops 隐式走自定义算子包路线，产物为 build_out 下 run 包；check_compiled_ops 兜底拼错算子名。下一讲将安装该 run 包并运行 AddExample 打通编译-安装-运行闭环。
