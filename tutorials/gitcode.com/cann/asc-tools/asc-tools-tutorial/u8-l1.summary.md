本讲义拆解 `optype_collector`——一个纯 Python 单文件、零第三方依赖的算子"交付体检"工具，覆盖三个最小模块：OpType 来源扫描、SoC 名称映射、冲突检测与返回码。

关键术语：OPP 包（算子交付形态，配置按 SoC 分目录存放）、OpType（算子全局唯一类型名）、SoC（昇腾芯片型号）。算子名从三类来源采集：`built-in` 内置包、`vendors` 已安装第三方包、`ASCEND_CUSTOM_OPP_PATH` 开发中自定义包，扫描各来源 `op_impl/ai_core/tbe/config/<soc>` 下的 JSON 配置。

核心结论：JSON 解析用三条识别规则（显式 OpType 键、容器键下 `name`、键名本身）加黑名单过滤兼容多种历史格式，单文件损坏仅记告警不中断扫描。SoC 映射运行时从 `platform_config/*.ini` 读取外名↔内名对照表，叠加硬编码别名 `ascend950 ↔ ascend910_95`；大写 SoC 名须命中映射表才被支持，否则返回空列表；同包多目录按 `root_path.parent` 合并以规避伪冲突。冲突检测 `detect_conflicts` 用集合求交分 custom-vs-builtin（自定义包对内置并集求交）与 custom-vs-custom（自定义包两两求交），结果归入 `ConflictReport`。返回码三级判定：扫描 errors→2、有冲突→1、无冲突→0，且 errors 优先于冲突。
