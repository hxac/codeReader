本讲剖析 cpudebug 的执行引擎 `RunKernelFunctionOnCpu`，讲清它如何用 POSIX 多进程原语在 CPU 上仿真 NPU 多核。其主流程分三阶段：fork 前由父进程做全局准备（记录 `g_mainPid`、`GmAlloc` 两段共享内存 `sysWorkSpacePtr` 与 `ffts_addr`、`StubInit`、`block_num = numBlocks`、取 `processNum = get_process_num()`）；随后进入 fork 循环，每轮产生一个子进程即一个模拟核，子进程装信号 `Handler`、设核类型后唯一执行 `kernelFunc`；最后父进程逐个 `waitpid` 回收并释放资源。核心设计决策是选 `fork` 而非线程：子进程的私有地址空间天然对应「每核独立核」，而 `mmap(MAP_SHARED)` 实现的 `GmAlloc` 对应共享 HBM，配合头尾页 `mprotect` 实现「越界即 SIGSEGV」。引入的关键术语包括：`get_process_num()` 解耦 `numBlocks` 与实际 fork 数、`block_num`/`block_idx` 供 `GetBlockNum`/`GetBlockIdx` 读取、FFTS flag 区、跨进程锁（`PTHREAD_PROCESS_SHARED`）、父子共用的 `Handler`（靠 `getpid()==g_mainPid` 区分身份完成崩溃堆栈打印、僵尸子进程回收与临时文件清理），以及 mix 模式下 `g_taskRation` 对核名编号的影响。
