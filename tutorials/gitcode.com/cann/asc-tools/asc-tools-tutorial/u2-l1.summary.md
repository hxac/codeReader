本讲阐明 CPU Debug 的核心思想——孪生调试：用 CPU 构造 NPU 行为的孪生体，使同一份 Ascend C 源码不改一行即可在 CPU 域与 NPU 域运行，把上板前验证前移到可用 gdb 的环境。使用遵循"两步走"：以 `#ifdef ASCENDC_CPU_DEBUG` 包裹 `#include "cpu_debug_launch.h"`，再用 `CMAKE_ASC_RUN_MODE=cpu` 编译。关键术语含 CPU 域/NPU 域、功能验证与精度验证、编译期 lowering（转义）。`<<<>>>` 是 ASC 语言层的核函数启动语法，bisheng 编译器在编译期据模式将其 lowering：CPU 模式改写为对入口头文件中 `AscCPUKernelLaunch` 的普通 C++ 调用，NPU 模式则译为真实 NPU 启动。`cpu_debug_launch.h` 经 `tikicpulib.h` 一次性引入 fp16/bf16/fp8 等低精度类型与内建函数 stub，并定义启动函数；`AscCPUKernelLaunch` 职责分层、只分发不执行，先按核函数名设置 kernel 模式，再托付给 `RunKernelFunctionOnCpu` 真正运行（其内部多核 fork 执行模型留待 u3-l1 深入）。因 `ASCENDC_CPU_DEBUG` 仅 CPU 模式定义，CPU 专用代码在 NPU 模式被预处理器整体剔除，故同一份源码两域互不影响、切回 NPU 无需移除。
