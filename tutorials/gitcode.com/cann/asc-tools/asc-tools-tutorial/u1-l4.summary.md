本讲完成 asc-tools「编译 → 安装 → 运行验证」的完整闭环，覆盖三个递进的最小模块。第一，build.sh 是项目唯一的编译入口，把「探测 CANN 路径、配置 CMake、编译、打包」封装为一条命令；`--pkg` 走 CMake 的 package 目标触发 CPack 打包，`--test` 走 all 目标只编译，二者互斥；常用参数还有 `--pkg-type`(run/rpm/deb)、`-p`(CANN 路径)、`-j`(线程数)，产物落在 `build_out/`。第二，编译生成的是 CANN 标准交付物 run 包(`.run` 自解压脚本)，文件名由 version.cmake 的版本号(9.1.0)与 package.cmake 检测的架构(x86_64/aarch64)拼成；用 `--full --pylocal` 安装时，会在 `tools/cpudebug/lib64/` 下建立 `libtikcpp_debug.so→libcpudebug.so` 等软链，作为新库名 cpudebug 与旧名 tikcpp/tikicpulib 的兼容层。第三，`examples/02_cpudebug` 的 add 样例用 `cmake -DCMAKE_ASC_RUN_MODE=cpu` 编译，`.asc` 源码经 ASC 语言转译后链接 cpudebug 仿真库；CPU 域下定义 `ASCENDC_CPU_DEBUG`，引入 `cpu_debug_launch.h`，把 `<<<>>>` 核函数启动翻译为 CPU 仿真，成功标志是 `[Success] Case accuracy is verification passed.`。核心心智模型：必须先编译安装 asc-tools(提供 cpudebug 库)，样例的 `find_package(ASC REQUIRED)` 才能定位工具链，两步顺序固定。关键术语：build.sh、run 包、软链、CMAKE_ASC_RUN_MODE=cpu、ASC 语言/.asc、cpudebug、ASCENDC_CPU_DEBUG、cpu_debug_launch.h、`<<<>>>` 启动语法、dav-2201 架构，均供后续讲义承接。
