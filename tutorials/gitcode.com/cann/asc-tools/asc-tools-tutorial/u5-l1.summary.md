本讲剖析 asc-tools 的 npu check 运行时检查层。它与 api_check 的边界在于：后者做调用点静态参数校验（ASSERT），前者全程动态跟踪内存生命周期、地址依赖、同步与多核踩踏，产物为 `*_npuchk.log`，仅在 api_check 未断言时完整。npu check 无独立入口，寄生在 `RunKernelFunctionOnCpu` 的 fork 模型上，由 `ASCENDC_NPUCHK_OFF` 宏包裹 kernel 级与每核 block 级挂载点（故多核每核一份日志），触手为注册表 `"npuchk"` 前缀 stub、由构建期 `write_npuchk.py` 生成，引擎本体在闭源 `libcpudebug_npuchk.so`。错误体系为 6 大类 19 个扁平错误码（ErrorRead/Write/Sync/Leak/Free/Buffer），其中 ErrorRead2、ErrorWrite3 为非致命可疑提示。Tensor 生命周期状态机 AllocTensor→EnQue→DeQue→FreeTensor 违例归 ErrorBuffer2；GM 多核写区间重叠判踩踏、Atomic add 豁免。`ascendc_npuchk_report.py` 经 addr2line+c++filt 将日志译回源码行。
