本讲义讲解 Ascend C 搬运类 API 的校验器，覆盖 `DataCopy`、`DataCopyPad`、`DataCopySlice` 三个变体，沿用 u4-l1 三层结构（入口函数 `CheckFuncDataCopy*Impl` → 校验器子类 `Tikcpp*Check` → 基类通用检查），失败统一经 `ASCENDC_CHECK` 短路返回并记入 `*_npuchk.log`。核心结论：普通 `DataCopy` 的开源 high-level 校验只做地址对齐，对齐粒度由 `alignSizeMap` 按物理位置决定（GM 不查，L1/UB=32B，L0A/B/C=512B，BIAS=64B）；`DataCopyPad` 另查左右填充元素数 ≤ `32/srcDtypeBytes`、B64 类型填充值必为 0；`DataCopySlice` 检查最重，要求 scope 落 UB、逐维 `SliceInfo` 一致、搬运指令数 ≤ `MAX_SLICE_SIZE(1536)`、stride 折算字节为 32 倍数、UB 容量不溢出、32B 对齐。本讲引入的关键术语：scope（存储位置 GM/UB/L1/L0A/L0B/L0C/BIAS）、逻辑位置 `TPosition`（如 VECIN/VECOUT/VECCALC）经 `GetPhyType` 映射到物理位置 `Hardware`（如 UB）方能查对齐表、burst（搬运粒度）；`alignSizeMap` 管对齐粒度、`bufferSizeMap` 管容量上限。三类校验本质都是在表达「对齐 + 范围」两类硬件约束，差异仅在粒度来源与容量来源。
