本讲解析 asc-tools 的 api_check 校验框架——它是 npuchk 在 CPU 域「边跑边查」算子参数合法性的检查内核。框架采用三层结构：入口函数层（CheckFuncXxxImpl）→ 校验器子类层（TikcppXxxCheck）→ 基类与通用函数层（TikcppBaseCheck），通用检查下沉基类、特有参数归子类，控制流靠返回值自底向上传播。基类提供四类与具体 API 无关的通用检查：CheckTensorScope（scope 存储位置）、CheckBufferSizeOverFlow（硬件容量上限）、CheckMaskArray/CheckMaskImm（mask 合法性）、CheckTensorAddrAlign（地址对齐）。核心是越界检查数学模型：GetMaskLength 由 mask 推每个 repeat 的元素数、CalculateVectorMaxOffset 由 repeat/stride 几何关系算最远访问偏移、CheckTensorSizeOverflow 比较 expectedSize 与 tensorSize。本讲引入的关键术语包括：repeat、mask（normal 位掩码 / counter 计数两种解释）、stride（repStride/blkStride）、scope（GM/UB/L1 等硬件存储）、ModeType（NONE/NORM/COUNTER 仅影响错误信息后缀、不影响比较逻辑）。错误报告由 ASCENDC_CHECK / ASCENDC_CHECK_AND_LOG 宏族驱动，以「失败即 return false」短路退出，配合 CHECK_LOG_ERROR 的 stdout 与 dlog 双通道输出；违例最终记入 *_npuchk.log，供 u5 解析，也为 u4-l2（搬运校验）、u4-l3（向量计算校验）奠定数学基础。
