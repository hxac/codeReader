本讲是专家层首篇，把 api_check 校验框架收束成二次开发手册。它给出三个自下而上的扩展点：参数结构体、校验器子类（继承 TikcppBaseCheck）、入口函数（CheckFuncXxxImpl）。入口函数模板固定：用 ASCENDC_CHECK_INTRI_NAME 校验名称后构造子类并调 CheckAllHighLevel/CheckAllLowLevel，业务逻辑全下沉子类。新增检查即把参数翻译成基类通用武器——成员方法（如 CheckTensorOverflowHigh/Low、CheckTensorAddrAlign）自带 apiName，自由函数（如 CheckTensorSizeOverflow）需显式传 apiName，配合 ASCENDC_CHECK 短路。关键结论是闭源/开源边界：src/api_check 全开源且被 CMake GLOB 自动收集，而 libcpudebug_model.a 与 libcpudebug_npuchk.so（stub 接线产物，由不随仓分发的脚本生成）闭源。故增强已有 API 校验在开源仓内完全闭环，给尚无 stub 接线的新内建函数挂校验会被卡在最后一跳，可用 gtest 直调入口函数验证逻辑。
