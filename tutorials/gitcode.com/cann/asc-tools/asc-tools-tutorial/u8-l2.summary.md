本讲承接 u8-l1，回答"全新自定义算子的工程骨架从何而来"。核心结论：`msopgen` 是 asc-tools 仓库之外的外部代码生成器，它以**算子原型定义文件**（json，描述算子名与输入输出形状）为唯一输入，生成可编译的工程骨架（build.sh、CMakeLists、CMakePresets、framework 适配层），算法源码则由开发者手写后拷入，形成"生成骨架 + 拷贝源码"的两步工作流。asc-tools 的贡献是维护 `utils/templates` 下的工程模板：新式 `new_op_project_template`（用 `npu_op_package` 等 npu_op_\* 高层封装宏，是 msopgen 标准骨架）与经典 `op_project_templates/ascendc/{customize,aclnn,common}`（用 opbuild/CPack/makeself 底层原语自打 run 包），两者由根 CMake 经 `BUILD_OPEN_PROJECT` 开关一并装进 CANN 的 `tools/`。引入的关键术语包括：算子原型 json、Tiling（输入张量切分策略）、vendor_name（决定 `vendors/<vendor>` 安装目录）、三层分工（op_host 做 Tiling 与原型注册并产 aclnn 接口库，op_kernel 跑 NPU 上 Ascend C 核函数，framework 做训练框架翻译插件且可选）。关键数据通路是 TilingFunc 写入共享结构体、GET_TILING_DATA 读出，最终经 install.sh 落到 OPP 的 `vendors/<vendor>/` 四个子目录，与 u8-l1 的 optype_collector 扫描链路闭环。
