本讲解决「show_kernel_debug_data 解析工具」单元的前置问题：算子调试数据从哪来、如何配置、如何生成，只讲「生成与配置」，不涉及解析。核心分三个最小模块：一是 Dump 配置文件，由 CANN ACL 运行时通过 `aclInit` 读取 `acl.json` 启用，必备字段为 `dump_kernel_data`（取值 all/printf/tensor/assert/timestamp，无序可组合的集合）与 `dump_path`（开启 Dump 时必填）；二是 Dump 路径优先级，三来源依次为环境变量 `ASCEND_DUMP_PATH` > `ASCEND_WORK_PATH` > 配置文件 `dump_path`，环境变量可临时覆盖配置；三是 kernel 侧四类调试 API（`DumpTensor`、`printf`/`PRINTF`、`PrintTimeStamp`、`ascend_assert`），由 `kernel_operator.h` 提供，是调试内容的真正生产者。关键结论：生成 bin 文件的是 CANN 运行时加算子侧内建函数，asc-tools 只做离线解析；bin 文件名三字段「核号 / index / loop」分别对应 `GetBlockIdx()`、`DumpTensor` 的 desc、循环变量。引入的术语有 Dump、kernel 侧/host 侧、bin 文件、AIV/AIC，供 u7-l2（TLV 格式）与 u7-l3（解析实现）承接。
