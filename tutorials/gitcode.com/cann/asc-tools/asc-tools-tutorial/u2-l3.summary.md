本讲讲清 CPU 域算子为何「进不去」核函数以及如何用 gdb 进入。核心结论：CPU Debug 用「一个核 = 一个 fork 子进程」模拟 NPU 多核——`<<<>>>` 在编译期被转义（lowering）为对 `AscCPUKernelLaunch` 的调用，后者转交 `RunKernelFunctionOnCpu`（`kern_fwk.h`）；父进程在循环里 `fork()` 出若干子进程（进程数由闭源的 `get_process_num()` 返回），核函数 `add_custom`→`Process`→`CopyIn/Compute/CopyOut` 全部跑在 `pid==0` 的子进程分支内，父进程只做 `waitpid`。因此 gdb 默认跟踪父进程时断不到 `Compute`，必须先 `set follow-fork-mode child`、再 `break`、最后 `run`，让 gdb 在 fork 处切换到子进程。关键术语：fork 子进程模型、`follow-fork-mode child`、`processNum`、默认配置下实际调试的是 0 号核（`detach-on-fork on` 行为）、LocalTensor 实现位于闭源模型库（`print` 对象可行，底层指针成员待确认，可用「输入恒等 `x[i]==y[i]==i*0.1f`」间接验证数据）。fork 的信号处理、进程同步、核名映射等细节留待 u3-l1 展开。
