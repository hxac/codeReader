本讲承接 u9-l1，讲清「`.so` 编出来之后」的打包安装期，覆盖四个最小模块：打包分支、install 落盘、软链兼容层、封装与装机。核心结论是：`bash build.sh --pkg` 的本质是向 CMake 注入 `-DPACKAGE_OPEN_PROJECT=ON -DPACKAGE_TYPE=run/rpm/deb` 并走 target `package` 触发 CPack；`--msot` 必须配 `--pkg` 且走独立子仓构建早退分支。install 规则把每架构 `libcpudebug.so` 装进 `tools/cpudebug/lib64/${Product_cap}`（`product_dir()` 把 `ascend910B1` 翻译成 `Ascend910B1`），架构无关的头文件与三个 stub 库（cceprint/npuchk/stubreg）装进公共 `include`/`lib64`。关键术语包括软链兼容层、COMPONENT 组件标签、product_dir 映射。库名从 `tikcpp`/`tikicpulib` 改为 `cpudebug`，用 6+ 处 `install(CODE create_symlink)` 建相对名软链做向后兼容，使旧样例无须改动。makeself `.run` 封装逻辑在闭源 cann-cmake 工具链，`cmake/package.cmake` 只描述「打什么」。装机链路为 install.sh（解析 `--full/--pylocal`、校验架构、算多版本路径）→ run_asc-tools_install.sh（按 filelist.csv 铺文件）→ asc-tools_custom_create_softlink.sh（补建 latest 软链），最终落在 `<根>/cann/<版本>/tools/cpudebug/...`。
