本讲（u4-l3）延续 u4-l1/u4-l2 的 API 校验框架，聚焦**向量计算类**校验器，核心模块包括二元计算、归约、广播三类。向量指令的访存由 **block（32B，寻址最小单位）/ repeat（256B=8 block）/ repeatTimes（≤255）/ mask / stride**（单位为 block，默认 blkStride=1、repStride=8）共同刻画，校验的本质是把这只「访问脚印」的最远端点算出来与 Tensor 容量比大小。

数学核心三步：`GetMaskLength`（扫描 mask 最高置位 bit 得每 repeat 元素数，对 dtype≥4 字节封顶 256/dtypeSize）→ `CalculateVectorMaxOffset`（由 repeat×stride 几何算最远元素下标）→ 乘 dtypeBytes 后经 `CheckTensorSizeOverflow` 比较。mask 分 normal（位掩码 `[maskHigh, maskLow]`）与 counter（计数，需拆 main/tail 取较大值）两种模式。

`TikcppVecBinaryCheck` 将此模型同时套到 dst/src0/src1，前置 `CommonCheck`（须在 UB、不超容量、32B 对齐），`Compare` 走比特打包专用公式；`TikcppVecReduceCheck` 难点是 **work tensor**——ReduceSum 走线性公式，ReduceMax/Min 带 `calIndex` 时经 `CheckWorkTensorOffset` 多轮迭代推导；广播族（broadcast/gather/scatter）mask 固定为 `FULL_MASK`，复用基类 `CheckTensorOverflowLowBrcb`，绕过 `GetMaskLength`。关键术语供后续承接：block/repeat/stride 参数模型、`TensorOverflowParams`、normal/counter 模式、work tensor、`*_npuchk.log`。
