asc-tools（Ascend C Tools）是 CANN 为 Ascend C 算子开发语言配套提供的调试工具集，核心价值是把原本只能在真实 NPU 上才能发现的问题，前移到 CPU 域和离线阶段解决，从而缩短算子开发周期。本讲定位为全景篇，覆盖三个最小模块：项目定位、五大工具功能划分、工具链整体定位。

关键术语包括：CANN（昇腾异构计算软件栈）、NPU（昇腾 AI 处理器）、算子与 Kernel（核函数）、Ascend C（算子开发语言）、CPU 域与 NPU 域（两种运行环境）、以及「孪生调试」（用 CPU 构造 NPU 行为的孪生体来做调试）。

核心结论是：asc-tools 并非开发框架，而是横跨「开发→调测→交付」的诊断工具集，包含五个工具——cpu debug 让 Ascend C 源码经 GCC 编译后在 CPU 上跑通并支持 gdb 调试；npu check 依附于 cpu debug，在算子执行时同步检查内存与同步逻辑（产物为 *_npuchk.log）；msobjdump 离线解析算子 ELF 文件；show_kernel_debug_data 离线解析 DumpTensor/printf 落盘的调试 bin 文件；optype_collector 位于 utils 目录，采集 OpType 信息并检测自定义算子与内置算子的重名冲突。前两者在 CPU 域执行算子时起作用，后三者离线对产物起作用。整体链路可概括为：算子源码 → CPU 调测（cpu debug + npu check）→ 离线分析（msobjdump / show_kernel_debug_data）→ 交付体检（optype_collector）。对应源码目录为 cpudebug/、npuchk/、utils/msobjdump/、utils/show_kernel_debug_data/、utils/optype_collector/。
