本讲剖析 Ascend C 算子编译产物 Kernel ELF 的结构与元信息。核心结论：Kernel ELF 不是新格式，而是标准 ELF64 加两个 Ascend 专属段——`.ascend.meta.<kernel名>`（元信息）与 `.aicore_binary`（机器码负载）。融合编译产物有「套娃」结构：外层文件的 `.aicore_binary` 段经 msobjdump 用 `llvm-objcopy` 自动抽出后，即得内层真正的 Kernel ELF。`.ascend.meta` 段采用 TLV（Type-Length-Value）编码，`ElfTlvHead` 为 2 字节 Type 加 2 字节 Length，靠 Length 推进游标、跳过未知 Type，天然前向兼容。关键术语：KERNEL_TYPE（核类型）、MIX_TASK_RATION（Cube/Vector 核占比）、CROSS_CORE_SYNC（跨核硬同步）。重要分工：C++ 运行期解析器只认 type=1（KERNEL_TYPE）与 type=3（MIX_TASK_RATION），经 ToKernelMode 映射为最终运行模式 KernelMode；其余字段仅供 Python 工具打印。融合编译以 Cube 核为主，一个算子产出 `_mix_aic` 与 `_mix_aiv` 两份 kernel。本讲为 u6-l2（msobjdump 解析实现）打地基。
