本讲义回答 asc-tools 的代码放在哪里、如何组织成可编译整体。仓库按职责分目录：`cpudebug/` 为 C++ 核心（CPU 域孪生调试），`npuchk/` 与 `utils/` 放四个 Python 工具（npuchk、msobjdump、show_kernel_debug_data、optype_collector）及 templates 模板，根 `CMakeLists.txt` 负责构建，docs/tests 等提供辅助。核心结论：asc-tools 本质是「一个 C++ 核心 + 四个 Python 工具」，C++ 厚、Python 薄、目录严格分离；根 `CMakeLists.txt` 用 `add_subdirectory` 串起各模块，tests 与 third_party 为条件挂入；cpudebug 为多种 NPU 架构分别编译，`src/` 下分 acl_stub（ACL 桩）、api_check（API 校验）、regfwk（注册框架）三个子目录。引入的关键术语：CMake、`add_subdirectory`（模块组装机制）、`__main__.py`（Python 命令行入口）。定位规律：Python 工具普遍遵循 `__main__.py`（入口）→ `xxx_main.py`（实现）的二层结构，C++ 库则看 `CMakeLists.txt`（构建入口）与头文件 `cpu_debug_launch.h`（API 入口）；README 目录树未必完整（如 optype_collector、templates 未列出），真实模块清单以根 `CMakeLists.txt` 为准。
