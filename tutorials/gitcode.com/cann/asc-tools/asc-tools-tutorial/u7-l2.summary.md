本讲解析 dump bin 的 TLV 二进制布局。最小记录单元是 TLV：头部 8 字节（`"II"` 即 tag、length，均 uint32）加 length 字节 Value，可顺序扫描、自描述切分；Type 取值见 DumpType 枚举（如 TENSOR_TYPE、SCALAR_TYPE），其中 SIMT_PRINTF_TYPE=0xF0E00F0E 决定头必须用 4 字节。文件分两种形态：workspace（legacy）多核拼接，每核用 BlockInfo（32B，magic 0x5AA5BCCD，块默认 1MiB）；FIFO 单核一份，用 FifoBlockInfo（56B，magic 0xAE86）。两种信封的魔数都落在文件偏移 16，故顶层 parse_dump_bin 只读偏移 16–19 四字节即可分流，且判定顺序为先 FIFO 后 workspace。解析实为两级分发：外层 magic 决定信封怎么拆，内层 TLV tag（add_tlv_data）决定信纸怎么读（DumpTensor/PrintStruct/ShapeInfo/TimeStampInfo）。DumpTensor 的 Value 内部还套一层 24B 的 DumpMessageHeader（含 data_type、desc），是通往具体数据还原的入口，留待 u7-l3 展开。
