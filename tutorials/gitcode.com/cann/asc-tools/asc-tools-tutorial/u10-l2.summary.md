本讲承接单元测试，讲解如何把改动合规地交回 asc-tools 社区，覆盖四条主线：一是贡献链路——非简单 Bug 须先开 Issue 讨论方案、首次贡献需签 CLA（贡献者协议）、按 PR 模板打约定式提交标签后评审；二是 pre-commit 五道关卡——基础格式、C++ clang-format、Python ruff、codespell、OAT 合规，任一失败即阻断提交；三是 OAT 开源合规——`oat_check.sh` 对暂存文件做增量扫描，`OAT.xml` 声明允许 CANN-2.0 许可证与华为版权、禁止二进制，仅阻断许可证头缺失与非法文件类型两类问题，环境不可用时容错放行，故每个源文件须带标准 CANN 许可证头；四是版本协同——`version.cmake` 声明 asc-tools 与 runtime、ge-executor、metadef、asc-devkit 主次版本对齐（占位符 `CUR_MAJOR_MINOR_VER`），不能孤立升级。核心结论是「把问题前移到本地与 PR 阶段拦截」。
