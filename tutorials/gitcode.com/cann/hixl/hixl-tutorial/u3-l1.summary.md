本讲剖析 HIXL Engine 的引擎抽象体系。`Engine` 是 src 内部抽象基类，以纯虚接口规定生命周期、内存注册、建链、传输、通知及回调处理器六组能力，接口面与 `Hixl` 公开 API 对应，但异步建链（由 `ConnectPoolExecutor` 承担）与静态 `GetCapability` 除外。现有三个子类：主力 `HixlEngine`（双角色合一，按值持有 `HixlServer` 被动方与 `ClientManager` 主动方，是否监听由 `local_engine` 带不带端口决定）、适配旧 ADXL 引擎的 `CommEngine`（逐字段翻译类型，批量 GetTransferStatus 返回 UNSUPPORTED）、`FabricMemEngine`。`EngineFactory::CreateEngine` 是引擎选择唯一决策点，分支顺序为 FabricMem 开关、LocalCommRes version==1.3、protocol_desc 配置、SoC kV5 探测、兜底 CommEngine，并打 selected engine 事件日志。`HixlServer` 封装 CS 层 C 接口，维护内存台账（幂等与重叠检查）、四类控制面消息处理器（endpoint 信息、内存信息、心跳、notify）及 notify 队列。工厂加抽象基类使 `HixlImpl` 对引擎种类零感知。
