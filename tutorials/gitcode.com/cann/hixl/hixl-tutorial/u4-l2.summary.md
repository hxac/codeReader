本讲深入 CS 控制面的消息系统，覆盖四个模块：server 侧的 MsgHandler（分发中枢）与 MsgReceiver（拆包器），client 侧的 ConnMsgHandler 与 MemMsgHandler（静态编解码工具类）。核心结论：控制面消息统一采用「CtrlMsgHeader（magic 0xA4B3C2D1 + body_size）+ 消息类型 + 消息体」三段式帧格式，消息体分为定长二进制结构体（建链类）与变长 JSON（内存导出类）两种形态。server 接收链路三段分工：epoll 线程只做 O(1) 轻量操作，MsgReceiver 以两状态机（等 header/等 body）拆 TCP 字节流解决粘包半包（body 上限 4MB），MsgHandler 用「注册表 + 请求队列 + 线程池」模式异步分发四类核心消息（MatchEndpoint、CreateChannel、GetRemoteMem、DestroyChannel），worker 执行前需 SetCurrentContext 恢复设备上下文；client 断连时伪造空 DestroyChannelReq 入队，体现「一切清理皆消息」。关键术语：dst_ep_handle 是贯穿建链与内存拉取的「通行证」，由 MatchEndpointResp 发放；channel_index 由 server 原子计数器统一发放以保证两端 channelName 一致；server 的 RegisterMem 是纯本地调用，client 通过 GetRemoteMem 拉取 JSON 格式的导出描述（含 export_desc、mem_tag 及内置 trans_flag 条目）并 ImportRemoteMem 后才获得可单边读写的远端内存。下一讲将学习被消息驱动的 EndpointStore、Channel 与 TransferPool。
