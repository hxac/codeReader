本讲深入 `src/llm_datadist/cache_mgr/`，讲清 KV Cache 在 LLM-DataDist 内的登记、获取与寻址。核心组件分工：CacheManager 是账本，用 `CacheEntry`（含 `is_owned`、`ext_ref_count`、`stride`）和五张索引表维护 cache_id、DataCacheKey、batch_index 的双向映射；DataCacheEngine 是门面，负责发号 cache_id、装配内存池与 cache table、编排注册与记账两步；CommMemManager 把 cache 地址经 TransferEngine 的 RegisterMem 注册成远端可单边访问的 mem_handle 并按 (addr,size) 去重，GlobalMemManager 单例管理内存池整块与 cache table 等进程级内存。获得 Cache 有两条路径：Register 注册外部内存（is_owned=false，逐块注册，C++ 公开可用）与 Allocate 从内存池切分（is_owned=true，池整块已注册故免逐块注册，需 `llm.MemPoolConfig` 选项，当前仅 Python allocate_cache_v2 驱动，C++ 公开接口暂返回 LLM_FEATURE_NOT_ENABLED）。关键机制包括 `remote_accessible` 注册开关、`CachePlacement` 选池、以及 Deallocate 基于 cache_key 引用的延迟释放（需 RemoveCacheKey 收敛）。下一讲 u6-l4 从 PullCache 查表出发讲 Push/Pull 传输接口。
