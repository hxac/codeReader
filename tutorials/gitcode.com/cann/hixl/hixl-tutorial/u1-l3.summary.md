本讲精读 quickstart 样例，拆为三个最小模块：server/client 双进程模型、HIXL C++ API 调用序列、启动方式与失败排查。核心结论：一份源码通过 `--role` 参数分派两种角色，server 只负责填数据、注册内存并告知地址，client 独占全部主动调用，体现单边通信中被动方工作量近乎为零；典型调用序列为 Initialize → RegisterMem → 地址交换 → Connect → TransferSync(READ) → 校验 → Disconnect → Finalize。引入的关键术语与概念包括：单边通信、注册内存与 MemHandle、engine 标识（ip:port 形式）、MemType（MEM_DEVICE/MEM_HOST）与 TransferOp（READ/WRITE）两个正交维度、TransferOpDesc 三元组（local_addr/remote_addr/len）、hccs:device 链路选项，以及“控制面（socket 地址协商）与数据面（HIXL 传输）分离”的工程事实。顺序约束是隐性合同：server 先注册再发地址，client 先 Connect 再传输，done 信号保证引擎存活。默认 device 0/2 组合是为兼容 A3 单卡双 die 不互通而设；排查工具为 npu-smi、hccn_tool ping 与 tls 检查。样例失败路径不做清理，仅用于功能验证。
