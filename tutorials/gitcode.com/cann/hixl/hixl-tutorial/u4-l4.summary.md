本讲为 CS 通信服务模块的收尾篇，覆盖三块基础设施：GlobalConfig、NotifyAddrResolver、HostRegisterProxy 与 load_kernel。GlobalConfig 解析 comm_resource_config 的三个键——listen_port（[1,65535]，仅 server 认）、qos（[0,7]，仅 client 认）、max_active_channels（≥1，双侧认，默认 128）；通过 ParseTarget 实现字段隔离，字段用 std::optional 承载，默认值由消费方 value_or 回填而非解析层决定。NotifyAddrResolver 负责「notify 句柄 → 设备地址」翻译：按 SoC 白名单（A2/A3 共 12 型号）分派，命中走 HccpProxy::RaGetNotifyAddrLen（HCCP 路径），否则走 Runtime 路径（aclrtGetNotifyId + rtGetDevResAddress），是换芯片代际的显式适配点。HostRegisterProxy 以 per-device 实例表加引用计数管理 aclrtHostRegister(ACL_HOST_REGISTER_MAPPED)，保证同一 host 内存被多 endpoint 共享时注册/解注册正确配对。load_kernel 从 ASCEND_HOME_PATH 下的 JSON 描述文件动态加载 AICPU 内核二进制，解析 HixlBatchGet/HixlBatchPut/HixlSyncTransferContext 三个函数句柄，bin_handle 复用实现幂等；FabricMem 复用同一加载入口但失败时优雅降级为 UNSUPPORTED。核心结论：配置决定资源规模，notify 提供完成信号，host register 与内核加载打通 device 直接访存的最后一段。
