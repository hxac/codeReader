本讲围绕三个最小模块讲解 HIXL 从源码到可运行产物的全流程：其一，build.sh 编译入口，它是 cmake/make 的参数化薄封装，常用参数包括 --build-type（默认 Release）、--examples（联动打开样例、基准与 hixl_tool 三个开关）、--host（跳过 device 子工程、复用缓存的 device 包以加速日常开发）、--asan/--cov（强制 Debug 构建）与 -j 线程数，产物统一搬运到 build_out 目录；其二，顶层 CMakeLists.txt 的工程组织，按“开关 → add_subdirectory”决策：ENABLE_TEST=ON 时只挂 tests 目录，正常构建挂 src 并按需挂 examples/benchmarks，非 host-only 构建会检查 CANN hcc 工具链路径，这是环境变量未加载时最常见的报错来源；其三，tests/run_test.sh 测试执行，在独立的 build_test 目录以桩（stub）替代真实硬件完成构建，C++ 五个测试套件（llm_datadist、adxl、channel_pool、hixl、fabric_mem）并行执行且各有 600 秒超时看门狗，Python 测试借助桩库与 PYTHONPATH 在无 NPU 环境运行，日志位于 build_out/report。关键术语包括 CANN、Toolkit 与 ops 包、host/device 产物之分、ASan、gtest/unittest、stub 桩环境，为下一讲运行 quickstart 样例奠定基础。
