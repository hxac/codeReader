本讲围绕「本机有哪些链路、两端如何配对」这一控制面核心问题，讲解四个模块。`EndpointConfig` 是内部端点数据模型，核心字段为 protocol（roce/hccs/ub_ctp/uboe/ub_rtp 五种）、comm_id、placement（device/host），UB 端点还携带 plane、dst_eid、net_instance_id 等字段。`EndpointGenerator::BuildEndpointList` 按优先级生成本端列表：显式 `local_comm_res` JSON 优先，否则按 SoC 类型自动生成（A5 走 ScaleOut+UB，V2/V3 走 RoCE+HCCS），并用 `protocol_desc` 过滤；无卡环境必须显式配置，且 `ub_rtp` 与 `uboe` 互斥。A5 的 ub_ctp 端点由 `local_comm_res_generator_v1`（topo 文件+urma_admin+路由，产出 D2D/H2D/D2H/D2U/H2U 边）与 `rootinfo_builder_generator_v1`（EID 字节解码出 die/port/PG 信息）协作生成。`EndpointMatcher` 用静态优先级规则表选路：同实例（net_instance_id 相同）优先 UB 分组（GROUP 规则，产出 UB handler 与多 CommType 配对），跨实例仅单协议 DIRECT（uboe>ub_rtp>roce），全部规则落空返回 `hixl::PARAM_INVALID`。端到端流程上，engine 字符串仅是控制面 TCP 门牌号，client 在首次 Connect 时经控制面拉取远端端点列表、反序列化、匹配后交由 ClientHandlerFactory 建立数据面链路。
