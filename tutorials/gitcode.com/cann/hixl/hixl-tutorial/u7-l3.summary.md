本讲是单元七收官实战，通过仓库自带的 PD 分离双进程样例，把 Prompt 集群与 Decoder 集群之间 KV Cache 跨集群传输的完整流程串讲一遍。最小模型为「两进程、四端口、一条链路」：26000/26001 是 LLM-DataDist 控制面监听端口，26002/26003 是业务自建 TCP 通知通道。核心结论包括：端到端接口合同为 Initialize→RegisterKvCache→LinkLlmClusters→Push/Pull→Unlink→UnregisterKvCache→Finalize，失败时进入顺序化兜底清理；KV Cache 传输分 Cache 粒度（连续 batch 整批搬，size=-1）与 Blocks 粒度（src_blocks[i]→dst_blocks[i] 离散配对）两种正交方式；SetRole 角色切换必须在无链路（Unlink 后）时调用，切到 kPrompt 需经 options 补监听地址；LLM-DataDist 不提供跨集群业务通知原语，C++ 样例用 sleep 加裸 TCP、Python 样例用 gloo barrier 自建通知面；`llm.TransferBackend="hixl"` 仅需一个选项即可切换传输后端，体现后端可插拔设计。关键术语：PD 分离、Push/Pull 方向、cluster_id 与 CacheIndex 三级寻址、业务自建通知面、角色切换时序约束。
