本讲是「地图课」，建立 HIXL 仓库的目录结构与公开 API 全局索引。核心内容：`include/` 下仅有四组共 8 个公开头文件——`hixl`（点对点单边传输 C++ 类 `hixl::Hixl`）、`cs`（`extern "C"` 风格的 Client-Server 接口，用 void* 句柄与裸 uint32_t 错误码）、`adxl`（已废弃的兼容层）、`llm_datadist`（KV Cache 语义层 `LlmDataDist`，含 PullKvCache/PushKvCache 与基于 ge::Status 的独立错误码）；前三组之外的 `src/` 头文件均为内部实现，无兼容性承诺。关键结论：头文件与实现目录非一一对应——`hixl.h` 落在 `src/hixl/engine/hixl_impl.cc`，`hixl_cs.h` 落在 `src/hixl/cs/`，而 `adxl_engine.h` 却实现在 `src/llm_datadist/api/` 下；公开类普遍采用 Pimpl 惯用法隔离内部依赖。四套接口是分层关系：ADXL 内部经 `EngineFactory::CreateEngine` 直连 HIXL 引擎，仅是兼容壳；LLM-DataDist 通过 `HixlTransferEngine` 适配层把 HIXL 作为可配置传输后端（`llm.TransferBackend` 选项）之一。另注意产品形态约束（不同芯片对协议与内存形态支持不同）。这些映射与术语将在 u2/u3/u4/u6 各单元反复引用。
