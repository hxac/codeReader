本讲剖析 LLM-DataDist 的 DataTransfer Job 体系：`DataTransferJob` 抽象基类约定 `Initialize/Process/PullCache` 三接口，job 自身无线程，由服务端 FSM 的 SendState 按“源 placement × 目的 placement”三 分派创建（D2D/D2H/H2D，HOST→HOST 拒绝）并周期性非阻塞驱动。核心总纲是“job = 请求解析 + 任务展开 + 分批执行 + 完成上报”。关键概念：`TransferCacheReq` 是两端全部合同，控制消息也走单边 PUT 写远端请求缓冲区；`HcclOneSideOpDesc`（本地地址+远端地址+字节数）是任务展开的目标形态。D2D 为直通路径，一次性展开 op 后按 ≤64 条分批执行，event 作批次同步点；`PullCacheByGet` 凭 cache access table 直接单边 GET，远端零参与。D2H/H2D 经 device 中转 buffer 两段搬运，`DataTransferTaskGenerator` 切成 Start/Transfer/End 任务序列，多块 buffer 轮转加 device flag 握手实现流水线重叠。`LayerWiseTransferJob` 提供按层粒度传输（不继承基类），支持“层到即算”的通信计算重叠。客户端编排器为 `DataTransferClient`/`D2HDataTransferClient`。下讲 u6-l6 讲 FSM 状态机，u6-l7 讲传输后端。
