本讲义剖析 LLM-DataDist 的 KV Cache 跨集群传输接口。核心是 Push/Pull 四个接口按「传输粒度（连续 Cache / 离散 Blocks）× 方向」排成矩阵：PushKvCache/PushKvBlocks 与 PullKvCache/PullKvBlocks；CopyKvCache/CopyKvBlocks 为占位实现（返回 LLM_FEATURE_NOT_ENABLED）。关键术语：`CacheIndex`（cluster_id + cache_id + batch_index 三级寻址定位远端 Cache，实现层翻译为内部 CacheKey）；`KvCacheExtParam` 的层区间语义（`{-1,-1}` 表示全部层，tensor_num_per_layer 默认 2）。核心结论：参数顺序统一「源在前、目的地在后」，本地端用 cache_id、远端端用 CacheIndex；Push 只支持 device 内存且 size 仅支持 -1、要求 src/dst 层区间等宽，逐层循环下发 TransferCache；Pull 的 size 支持 -1 或正数（唯一支持部分字节传输），层区间一次性展开为 src/dst_tensor_indices，两种模式在 V2 层汇合到同一 PullCache；Blocks 地址按下标配对（src_blocks[i]→dst_blocks[i]，须等长非空），Blocks 模式 batch_index 恒为 0。典型错误码：LLM_NOT_YET_LINK、LLM_KV_CACHE_NOT_EXIST、LLM_PARAM_INVALID。样例确认完整合同：Initialize→Register→Link→Push/Pull→Unlink→Unregister→Finalize，跨进程通知需业务自建。
