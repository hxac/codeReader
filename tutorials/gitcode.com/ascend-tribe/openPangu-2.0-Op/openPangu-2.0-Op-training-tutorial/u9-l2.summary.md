本讲讲解 tiling_sink：把 Tiling 计算从 Host 下沉到设备侧 AICPU 执行，解决 Host 三大盲区——动态 shape（真实序列长度在 device 张量）读不到、Host-Device 往返开销、super kernel 无 Host 介入点；可行基础是 Tiling 为纯 C++ 逻辑、经 gert::TilingContext 依赖注入。核心三件套：任务信封 TilingAicpuTask（tilingContext/opType/notifyAddr/workspace 五字段协议结构）、注册表 DeviceOpImplRegistry（单例 map 绑定算子名与 SinkTilingFunc，同名重复注册静默覆盖）、执行器 RunAicpuRpcSrvLaunch（拆信封→查表→执行→回填 TilingData→写 notifyAddr=1 并用 dsb st 屏障跨核同步）。活体样本：pioneer 的「一套实现、两个入口」（IMPL_OP_OPTILING Host 注册 + DeviceDoOpTiling* 默认可见导出）、FAInfer 的 isTilingSink 分支（核间切分推迟到设备侧，split workspace ×2 双缓冲）。关键结论：框架代码随 common 携带但当前不参与主构建（opmaster 工程因上游算子源码缺失而休眠），读公共组件必须以 CMake/grep 核实接线；术语上 attention sink（沉洞 token）与 Sinkhorn（MHC 算法）均与本讲无关。
