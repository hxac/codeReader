本讲精读全仓库唯一的 AICPU 算子 ai_infra_attention_pioneer_metadata，即 u4-l8 pioneer 注意力的前置算子。它解决变长场景下真实序列长度在 device 侧、Host tiling 无法精确分核的问题：以串行 C++ 在 AICPU 上完成一次“设备侧 tiling”，输出 int32[1024] 的 metadata 协议缓冲（布局为 36 核×10 槽+16 个基础字段），供 AICore 侧注意力 Kernel 启动时回读、反推本核工作区间。核心结论：AICore 管稠密计算、AICPU 管控制流密集；AICPU 算子注册三件套为 op_graph 的 REG_OP 原型头、aicpu json 引擎绑定（DNN_VM_AICPU）与 config.ini 芯片门禁（ascend950），op_host 仅有 infershape、无 tiling；Kernel 六阶段流水 Prepare→CheckIsDecode→ParseAxisInfo→SetTilingParams→ComputeSplitNBSeq→GenMetaData，核心是按目标权重的贪心负载均衡分核；op_api 中 aclnn 层第一段运行时回填 AIC/AIV 核数、workspaceSize 恒为 0。关键术语：设备侧 tiling、metadata 协议缓冲、贪心分核、needInit、核数回填；生产者与消费者各持一份镜像布局定义、须手工同步，是二次开发高危点。
