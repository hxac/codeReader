本讲建立"算子跑上一款芯片要过几道门”的双层适配模型：编译期由 `_def.cpp` 的 `AICore().AddConfig(soc, config)` 决定为谁生成产物，运行期由 tiling 中 `GetSocVersion()` 白名单决定调用是否放行。核心结论：AddConfig 是必要不充分条件，sparse FA 即“注册双芯片、仅放行 910B"的窄门样本。仓库用 `arch32/`（服务 ascend910b/910_93，FA 前反向）与 `arch35/`（服务 ascend950，pioneer 家族）目录隔离两代实现，纠正了"arch35 属 A3"的旧说法；Host 侧由 CMake 统一挂进 optiling，芯片差异显形于设备侧 kernel 与运行时探测。关键术语：`SocVersion` 枚举、`GetCurNpuArch()`/`NpuArch::DAV_3510`（指令集代际，x86 下需 compileInfo 兜底）、按 soc 注册 tiling 模板的 `REGISTER_TILING_TEMPLATE_WITH_SOCVERSION`、AICPU 算子的 `config.ini aicore_versions` 门禁、`build.sh -c`→`ASCEND_COMPUTE_UNIT`（A2/A3 镜像 cann8.5.0 对应 910 系，A5 镜像 cann9.0.0 对应 950）。原则：门禁看 soc，算法看平台参数（如 48/40 核数特判）。实践产出全仓库芯片支持矩阵与 aggregate_hidden 新增 950 的改动清单。
