本讲剖析 tiling_base 框架。TilingBase 基类用模板方法把一次 tiling 固定为七步流程（取 shape/attr、平台信息、IsCapable 能力自判、DoOpTiling 切分、高阶 API 参数、workspace、PostTiling 写回），末尾统一 SetTilingKey，子类只填内容不管流程；三态返回值是责任链的调度语言：GRAPH_SUCCESS 成功终止、GRAPH_FAILED 立即中止、GRAPH_PARAM_INVALID 让位给下一优先级实现。tiling_templates_registry 以「工厂函数＋优先级表＋静态注册宏」支持一算子注册多 tiling 模板，分带 socVersion 的 TilingRegistryNew 与不带的 TilingRegistry 两套，优先级数值越小越先执行；FA 前向的 90~98 六级责任链展示了各模板经共享 context TilingData 接力合作的高级用法。tilingKey 采用十进制位组装（RecursiveSum，首参为最低位）加 10^19 偏移，枚举值须小于 10，它只作运行期分支选择信号，不改变编译产物份数；sinkhorn 则是两级 tiling 文件组织、单一实现、朴素 0/1 key 的简单样本。tiling_util、data_copy_transpose_tiling 等公共工具当前仓库内无调用者，读公共库须用 grep 核实真实调用关系。
