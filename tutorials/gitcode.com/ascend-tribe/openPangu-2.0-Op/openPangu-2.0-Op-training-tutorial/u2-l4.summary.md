本讲解剖 ai_infra_aggregate_hidden 设备侧 op_kernel 的三个文件。kernel 入口 extern "C" __global__ __aicore__ 只做三件事：用 TILING_KEY_IS 按 Host 写入的 tilingKey 选精度分支、用 GET_TILING_DATA_WITH_STRUCT 把 GM 字节流解包为 TilingData 结构体、实例化模板类执行 Init+Process。模板类 Init 绑定 GM 并按 alignBaseH 划分 UB，Process 做权重 fp32 预热与 B/S 双循环 CopyIn→Compute→CopyOut，TPipe 统管 UB，TQue/TBuf 分别承担队列同步与裸缓冲。算法核心是把 W=3 因果卷积改写为沿 S 的递推：y0/y1/y2 三个 fp32 状态跨 token 复用，mask 只掩输出不打断递推。公共基类 CutHBS 用三级取模把 GetBlockIdx 反解为 H/B/S tile 身份并用 Tail 字段处理尾块，与 Host 侧 blockDim 乘法严格互逆，TilingData 13 个字段全部被消费。新增 fp32 需同步改 def、tiling、kernel 三层并重算 UB 预算。关键术语：GM/UB、AIV、SPMD、DataCopyPad、Cast、PipeBarrier、SetWaitFlag；跨侧契约：入口参数顺序即 def 声明顺序、tilingKey 常量双侧同值，失配即静默出错。
