本讲讲清 UT/ST 用例如何被构建系统收集、编译并运行。`-u` 置 ENABLE_TEST 使 build.sh 变为单测构建器，`--ophost`/`--opapi` 在 UT 模式下退化为 UT 目标选择器（与库构建开关双身份），编译前强制检查算子须有 tests/ut 目录，`-n` 为精确目录名匹配。cmake/ut.cmake 按 test_*_tiling.cpp 等文件名 glob 收集用例并按 `-n` 白名单过滤，新增用例因此「零注册」，文件改名即被静默排除。ENABLE_UT_EXEC 经 POST_BUILD 在链接成功后立即执行 transformer_op_host_ut，即「编译即运行」；手动重跑必须补 BUILD_PATH 环境变量，否则 so 无法注入注册表。ST 不走 CMake：pytest.ini 与 conftest.py 组成资源门禁，resources marker 是白名单准跑证，无 marker 即被 deselected；--device 为双向 fnmatch 匹配，--nodes/--npus-per-node 精确相等；rootdir 未锚定 src/tests/st 时 conftest 不加载，门禁即被绕过。requirements.txt 并非 ST 真实依赖。
