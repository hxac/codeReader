本讲义精读 op_host 层的 `_def.cpp` 原型定义文件，拆为三个模块：一、OpDef 类骨架——继承 CANN 基类 `OpDef`，用 `Input()/Output()/Attr()` 链式声明张量名称、必选性（REQUIRED/OPTIONAL）、`DataType`/`Format` 集合与带默认值的标量属性；核心结论是 Input 声明顺序即运行期索引，与 tiling 侧 `INPUT_INDEX` 等常量一一对应，调序必须两侧同步，`AutoContiguous()` 要求框架保证张量内存连续。二、`OpAICoreConfig` 编译开关——六个 Dynamic* Flag 声明动态 shape/格式/维数等能力，`ExtendCfgInfo` 键值对（jitCompile.flag、opFile.value、coreType.value 等）向工具链传附加信息；def 只管能力开关，具体 shape 数值校验归 tiling 的 CheckInputValid。三、注册链路——`AICore().AddConfig("ascend910b"/"ascend910_93", config)` 构成编译期芯片白名单，`OP_ADD(类名)` 在启动期把原型登记进 CANN 注册表，op_build 据此生成 aclnn 接口，tiling 侧以同名 `IMPL_OP_OPTILING` 绑定；类名是四层对齐的锚点，漏写 OP_ADD 会静默失败。`register/op_def_registry.h` 属 CANN 包而非本仓库。下一讲 u2-l3 进入 tiling.cpp。
