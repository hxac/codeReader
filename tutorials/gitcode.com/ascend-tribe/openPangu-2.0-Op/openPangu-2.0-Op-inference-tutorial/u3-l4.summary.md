本讲以 npu_lower_triangular_inverse 为贯穿案例，收官第 3 单元，复盘从 torch 调用到 AscendC kernel 执行的六层边界：L1 Python 调用层、L2 csrc 实现层（PrivateUse1/Meta）、L3 ops_common 适配层（EXEC_NPU_CMD_V1）、L4 aclnn 两段式接口层、L5 op_host 层（OpDef 查表与 Tiling 施工图）、L6 op_kernel 层（GET_TILING_DATA 解包执行）。前三层属 wheel 包、后三层属 run 包，两包唯一缝合点是 L3 的 dlopen/dlsym，因此必须先装 run 包后装 wheel 包，且两包可独立升级。setup.py 的两条 glob 规则使新增算子零改动打包进单一 custom_ops_lib.so；import omni_custom_ops 的副作用完成签名注册、converter 激活与 torch_npu 镜像挂载。符号找不到类报错按五环节排查：装包、ASCEND_OPP_PATH、load_priority、nm 查符号导出、csrc 宏拼写。核心结论是 torch schema 名、aclnn 符号名、OpDef/kernel 名需三次命名对齐，任何一处不一致都会失败。
