本讲义把多 SOC 适配与算子包发布流程讲完。结论一：多 SOC（910b/910_93/950）适配有三层落点——OpDef 的 AddConfig 准入声明（950 需独立 OpAICoreConfig 加宏守卫）、op_host/config/<soc>/ 按需存放的 binary.json/simplified_key.ini/runtime_kb.json 三类配置（预编译清单、简化键模式、matmul 调优知识库）、kernel/tiling 架构特化分支。结论二：--tiling_key 经六级传递链落盘 custom_tiling_keys.ini，编译期按 key 裁剪二进制但不影响 host 侧逻辑，被裁 key 运行期无法执行；--disable-check-compatible 控制版本校验且仓库默认关闭。结论三：发布闭环为 CMake 三大库目标（opapi/opsproto/optiling）装入 vendors/omni_custom_transformer 树，kernel 二进制按 SOC 分目录并由 binary_info_config.json 索引，CPack 打出 run 包，安装后 source set_env.bash 注入环境，再装 torch 侧 wheel 包，顺序必须先 run 后 wheel。
