本讲剖析 ascendc 仓库的 ST（系统测试）框架，覆盖三个模块：一是 `src/tests/st/` 的 conftest.py 与 pytest.ini，用例以 `@pytest.mark.resources` 声明 device/nodes/npus_per_node 硬件需求，命令行以 `--device/--nodes/--npus-per-node` 声明供给，收集期不匹配即 deselect，忘贴 marker 的用例会被静默跳过，device 匹配为双向 fnmatch 通配、nodes/npus 要求精确相等；二是 NPU 与 CPU「对拍」的三种精度断言模式——纯搬运算子用 torch.equal 二进制一致，浮点算术用 assertRtolEqual/torch.allclose 容差比较（bf16 约取 1e-2），参考答案难算时用数学恒等式（A·A⁻¹≈I）；三是工程化要点：import omni_custom_ops 不可省、固定双随机种子、失败须带 shape/dtype/max_diff 诊断、用例分组对齐 kernel 分支、eager 与 aclgraph 双模式对拍，执行时须把框架目录一并传给 pytest 才能加载 conftest。
