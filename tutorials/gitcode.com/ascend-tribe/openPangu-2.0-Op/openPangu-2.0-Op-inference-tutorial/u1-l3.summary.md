本讲以 ScatterBlockUpdate（按索引把 update 整行原地写入 input）为标本，剖析算子目录五件套：docs 文档、op_api 接口层、op_host 原型与切分层、op_kernel 计算层、tests 测试。核心结论：调用链为 op_api → op_host → op_kernel——aclnn 两段式接口做参数三步检查并组装执行器异步下发；OpDef 注册算子原型；Host 侧 Tiling 算出 TilingData 施工图，Device 侧 kernel 按 TilingKey 分支照图做 GM 与 UB 间搬运，Host 只算计划、Device 只执行。关键术语：Host/Device 侧、GM 与 UB 两级内存、Tiling/TilingData、aclnn 两段式、L0 封装（l0op）、TilingKey、原地更新（input 用 CreateView 保留 stride，kernel 按 stride 偏移写回）。CMakeLists 把各层挂到三个动态库；UT 无硬件验逻辑、ST 真机逐位比对；文档注释可能滞后，以代码为准。
