本讲为推理篇收官实战，以假想的逐元素加法算子 my_add 为例，整合六层调用链，走通从建目录到 torch 可调用的完整流程。核心概念「九件套」指新增算子的最小文件集：OpDef 注册、tiling 头/源、kernel 入口与实现、aclnn 两段式接口与 L0 封装、算子级 CMakeLists，外加 torch 侧一处 m.def 与一个 csrc 文件。核心结论：小写下划线目录名、大驼峰 OpDef 类名、npu_ 前缀的 torch/aclnn 符号三重命名必须严格对齐，def 文件名还驱动自动代码生成；构建由 GLOB 按「族/算子」两层目录发现、build.sh -n 过滤，源文件分别挂入 opapi、opsproto、opmaster 三个动态库；验收先 UT（纯 CPU 验 tiling）后 ST（真机与 CPU 标杆对拍）；TilingKey 双侧镜像与 kernel 入口参数布局是编译器救不了的人工契约，靠 UT 断言兜底。
