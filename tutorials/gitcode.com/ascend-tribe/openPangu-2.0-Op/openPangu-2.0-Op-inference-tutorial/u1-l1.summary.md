openPangu-2.0-Op 是昇腾亲和大模型自定义算子仓库，顶层分 training/ 与 inference/；推理子仓 inference/ascendc 仅有 AscendC 一种实现（Triton/PyPTO 只在训练场景）。子仓两大组成：src 下的 AscendC 融合算子库（编译成 CANN run 包装入 opp/vendors，是「发动机」）与 torch_ops_extension（打成 omni_custom_ops wheel，是「方向盘」）；wheel 把算子注册进 torch.ops.custom 并 setattr 挂载到 torch_npu，故 torch.ops.custom.npu_xxx 与 torch_npu.npu_xxx 两种写法等价。一级目录分构建系统（build.sh、CMakeLists.txt、cmake、scripts）、算子源码 src、PyTorch 扩展三组。算子共六族 18 个目录：attention（11 个）、mhc、index、posembedding、moe 位于 ops-transformer，matmul 位于 ops-nn；每个算子目录呈 docs/op_api/op_host/op_kernel/tests 五件套（AICPU 算子例外）。本讲引入术语：昇腾 NPU（910B/910C/950PR）、算子与自定义算子、AscendC、CANN、aclnn 接口、torch_npu/PTA、run 包与 wheel 包双包协作。核心结论：README 算子表与实际目录双向不一致（漏收 moe、matmul 等 4 项、多收不存在的 causal_conv1d_add），盘点以 ls 实际目录为准。
