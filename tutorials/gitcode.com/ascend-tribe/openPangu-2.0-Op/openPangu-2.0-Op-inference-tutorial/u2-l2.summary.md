本讲精读 op_api 层，标本仍是最小算子 ai_infra_scatter_block_update。核心结论：aclnn 接口为两段式——第一段 GetWorkspaceSize 在 Host 侧同步完成参数检查、输入连续化并填充 aclOpExecutor，动态汇总 workspace 需求；第二段仅携 workspace、executor、stream 交给运行时按流异步下发，executor 是横跨两段的接力棒。参数三步检查 NotNull、空张量、dtype 合法，次序不可换（先判空才能解引用），错误码区分参数错与内部错。非连续输入两种处理：只读输入用 l0op::Contiguous 拷贝、占 workspace；原地写入目标 input 必须用 executor->CreateView 零拷贝保留 stride/offset，否则原地语义被破坏。aclnn 层经 l0op 命名空间的 L0 封装与 ADD_TO_LAUNCHER_LIST_AICORE 把算子登记进 executor 下发列表而非立即执行；本算子为原地算子，输出即 input。命名规律：带 aclnn_ 前缀的文件对是对外接口，无前缀同名文件是 L0 封装。登记阶段连带的 tiling 计算留给下一讲。
