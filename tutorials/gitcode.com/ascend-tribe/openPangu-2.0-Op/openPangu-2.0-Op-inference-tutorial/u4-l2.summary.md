本讲剖析仓库仅有的两个 AICPU 算子之一：AttentionSink Metadata 算子，它是 FIA Sink 主算子的“影子搭档”。与 AICore 路线的关键差异：原型改在 op_graph 下用 ge::REG_OP 流式声明（无 OpDef 与 tiling 文件）；计算体是 op_kernel_aicpu 下继承 CpuKernel 的纯 C++，经 REGISTER_CPU_KERNEL 注册，跑在设备通用 ARM CPU 核上，交叉编译为 libtransformer_aicpu_kernels.so；aicpu.json 的 engine、kernelSo 字段是运行时路由表，算子名需在 REG_OP、REGISTER_CPU_KERNEL、json 键三处对齐。核心结论：FIA Sink 的分核依赖 actual_seq_lengths_kv 的张量数值，Host 侧 Tiling 读不到，故由 AICPU kernel 直接解引用设备张量，用线性代价模型加核数枚举做贪心分核，结果按 FiaSinkMetaData 结构体覆盖写进 1024 元素输出张量（AIC/AIV/BASE 三段布局）。关键术语：AICPU、REG_OP、CpuKernel、ADD_TO_LAUNCHER_LIST_AICPU（aclnn 第一段自动填 soc_version 与核数，workspaceSize 恒为 0）、主算子目录下的共享头文件单一事实源、双流加 event 的生产者-消费者同步、aclgraph 入图。此模式是 u5-l4“tiling 下沉”的算子级前身。
