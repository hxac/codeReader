本讲剖析模型最佳实践配置系统：ModelExtraConfig 单例聚合 TaskConfig（环境事实）、ModelParallelConfig（并行策略）、ModelOperatorOptConfig（算子优化开关，如 moe_comm_strategy、预取）三层配置类，json 文件只装载后两层，加载发生在 NPUWorker.init_device、早于模型构建。模型识别走两级查表：match_hf_configs.json 以架构超参指纹把 model_type 细化为规格名，best_practice_configs.json 再按「模型+硬件+精度+PD 形态」路由到 P/D 各自的 json。CUSTOM_MODEL_CONFIG_PATH 是优先级最高的覆盖通道，--additional-config 的 enable_low_latency 决定查高吞吐还是低时延目录。核心结论：低时延路由表 openPangu 条目命名与指纹名不一致，自动匹配落空仅告警并回退代码默认值（登记路由但文件缺失则报错），生产模板因此一律显式钉死配置文件；features 后处理在 eager 模式裁剪多流/预取并对序列并行做插件门禁；json 中拼错的键会被静默丢弃，最终生效配置以日志「ModelExtraConfig:」回显为权威。
