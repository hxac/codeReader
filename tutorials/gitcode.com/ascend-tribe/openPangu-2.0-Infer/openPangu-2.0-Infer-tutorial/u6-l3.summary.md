本讲拆解 ansible run_proxy 部署链路与 omni-proxy 分组调度。核心结论：run_proxy 是「收集上游 fact → Jinja2 渲染 run_proxy_cmd 脚本 → docker exec 进 C 容器调 omni_proxy.sh 生成 nginx.conf 并启停 nginx」的流水线，decode 上游以 ip:port@卡数 压缩再展开成逐 server 端点。分组由 omni_proxy_prefill/decode_groups 两条指令表达，段式语法「组id：数量」按 server 顺序消费，须过三条启动校验：成对配置、两侧 id 集合相等、段数等于 server 数；「prefill 3 组、decode 1 组」等不对称写法必然启动失败；运行期 decode 与 prefill 必须同 group，未配置则全员 group 0，README 示例已过不了当前校验，应以源码为准。APC 开启是双端链路：USE_OMNI_PROXY=1、proxy 侧 --omni-proxy-model-path（生成 vllm_kv_port_offset 100）、引擎侧 --kv-events-config 在 api_port+100 发 ZMQ KV 事件，缺一端不报错但 radix tree 匹配恒空；92B 基线模板两端未接线，505B OmniCache 模板才是完整示例。验证手段为 dry-run 渲染检查与 Add Prefill/Decode peer (group=N) 日志。
