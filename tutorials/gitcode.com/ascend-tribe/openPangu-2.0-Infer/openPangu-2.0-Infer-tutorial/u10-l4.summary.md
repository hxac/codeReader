本讲是手册收官实战，把 INT8 量化、OmniCache 主机内存池与 omni-proxy 分组调度组装进 505B 的 4P81D16 生产拓扑：4 个单机 P 实例（TP16、kv_rank 0–3）+ 1 个双机 D 实例（32 个 decode DP server）+ 1 个 C 节点，共 6 台 A3；模板按 unique host_ip 算出 PREFILL_POD_NUM=4、按设备拼串数出 dp=32。核心结论：INT8 信息装在权重目录的 quantization_config（compressed-tensors），模板零量化参数；OmniCache 改写 KV 规则，KV_CONNECTOR 换成 OmniCacheConnector，KV_PARALLEL_SIZE 由基线 5 变为 P 侧 1、D 侧 33，日志回显属正常而非配置错误；分组调度模板未配，须满足段数等于 server 数且两侧组 id 集合相等；大页预留 P 机 786432 页、D 机 262144 页（以字节数为准）；上线遵循可观察、可判定、可回退三段式，回退执行 set_hugepage_limit.sh 恢复 262144 页。
