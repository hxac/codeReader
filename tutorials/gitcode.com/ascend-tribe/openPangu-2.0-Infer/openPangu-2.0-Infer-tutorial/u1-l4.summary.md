本讲实战用 ansible 拉起首个 1P1D BF16 服务。核心心智模型：inventory 管「有哪些机器」（只改 ansible_host 与 host_ip，C 组填 P 机 IP），playbook 定义任务，tag 决定执行哪段。run_docker 先删旧容器再重建 P/D/C 三个容器，NPU 容器三要素是 --device 透传设备文件、挂载驱动、--net=host；run_server 生成并执行 vllm_run_for_p/d.sh，单机 P 走 mp 后端、排在 D 之后启动；run_proxy 起 nginx+proxy 监听 7000。环境变量沿 play environment → task environment/docker exec -e → 脚本 export 三层传递，必改项为 LOG_PATH、MODEL_PATH、DOCKER_IMAGE_ID 与容器名；调整 P/D 行为只需改模板变量 run_vllm_server_prefill_cmd/decode_cmd 并重跑 tag，无需重建容器。1P1D 中 P 为 TP16 的 kv_producer，D 为 16 个 DP server 的 kv_consumer，KV_PARALLEL_SIZE=2。日志排障先看 run_prefill/decode.log（脚本层）再看 server_N.log（引擎层），「Application startup complete」为就绪标志；请求经 proxy 7000 端口，model 字段须等于 SERVED_MODEL_NAME。
