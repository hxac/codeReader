本讲剖析 omni-npu worker 侧四个模块：NPUWorker、NPUModelRunner、NpuMemAllocator、NPUInputBatch。核心结论：NPUWorker 由 vLLM 执行器按固定生命周期驱动——init_device（绑定 npu 设备，HCCL 组网先于模型配置加载）、load_model、determine_available_memory、initialize_from_config（首行 ensure_kv_transfer_initialized 创建 KV connector，再把 KV 张量注册给它）、compile_or_warm_up_model；initialize_cache 为空操作；可用 KV 显存＝总显存×gpu_memory_utilization−profile_run 峰值。NPUModelRunner 继承 GPUModelRunner，以四类手法适配：switch_torch_device 上下文临时把 torch.cuda 换成 torch.npu、覆写 _init_device_properties 等预留钩子、按 pangu DSA/MLA 特性覆写 get_kv_cache_spec、替换 NPUSamplerV1 与 ACLGraphWrapper 等实现类。NpuMemAllocator 是可插拔分配器单例显存池，按 weights/kv_cache 两种 tag 记账以支撑 sleep/wake 模式的分池卸载与重建；NPUInputBatch 通过运行时换类挂载三张惩罚缓存表，并随批槽位搬移严格同步。ACLGraphWrapper、use_gegraph、set_aclgraph_recapture、LLMDataDistConnector 等术语留待 u3/u4/u5 讲义承接。
