本讲剖析 omni-npu 不改 vLLM 源码的运行时补丁（monkey patch）机制，是插件机制的第三块拼图（与 u2-l2 声明式平台适配互补的命令式适配）。VLLMPatch 基类与 register_patch 装饰器标准化补丁写法：补丁类用 _attr_names_to_apply 声明替换符号，apply() 经 setattr 挂到 vLLM 目标类/模块，self 接管原对象。PatchManager 负责注册与应用：两级去重分别防「同一补丁重复应用」与「两个补丁改同一符号」；OMNI_NPU_VLLM_PATCHES 未设置、空或严格等于 ALL 时全量应用，否则按逗号分隔注册名应用；单个补丁失败仅记日志、不阻断启动。补丁目录即生效范围：common 对所有模型加载，models 子目录经 OMNI_NPU_PATCHES_DIR 手动精确匹配，或按 model_type 依映射表、前缀、包含自动匹配；生产模板手动写死 pangu_v2_hybrid 与 pangu_v2_moe。全链路由 entry point omni_npu_patches 在 vLLM 启动早期触发，先 auto_import_patches 注册再应用，须赶在目标模块被使用前生效；生效名单以 successfully applied patches 日志为准。分析补丁的四要素法：注册名、目标、符号、动机。
