本讲深入 openPangu-2.0 MoE 层内部：`OpenPanguV2MOE` 组装 fp32 路由 gate（sigmoid 打分加 `e_score_correction_bias` 偏置修正）、整卡复制不切 TP 的共享专家，以及经 `@register_oot` 多继承 vLLM 类的 `NPUSharedFusedMoE` 路由专家容器。核心结论是把 MoE 前向规范为「prepare_permute → apply_experts → unpermute_finalize」三段式：dispatch/按专家重排、两次 `npu_grouped_matmul` 夹 `npu_swiglu` 计算、combine 加权聚合，量化方法只需替换中间段。专家并行（EP）下有三种通信策略：all2all（按专家拆包直寄）、agrs（AllGather 全量加本地过滤再 ReduceScatter）、dispatch_combine（HCCL 融合分发回收算子），由 `CommunicationStrategySelector` 按设备型号、TP/DP 规模与 token 阈值自动选择（A5 强制 agrs）。关键术语还包括逻辑/物理专家与 EPLB 冗余、`expert_map` 本地专家映射、W8A8 量化在回收阶段融合反量化、FRACTAL_NZ 权重布局。部署上每个 rank 仅持约 E/EP 个专家加一份共享专家，EP 出口无需再 AllReduce。
