本讲是 omni-cache 单元概述，讲清 OmniCache 的「是什么与怎么部署」，源码精读留给 u7-l2。核心模型：KV 沿「P 侧 HBM→P 主机内存池→OX 传输引擎→D 主机内存池→D HBM 或 MMU 直读」流动，区别于基线 LLMDataDistConnector 的 RoCE 直传；主机内存池（hugetlbfs 大页，默认 500 GiB，约可承载 7.6 亿 token KV）既降低两侧 HBM 压力以提升序列长度与并发，又因 KV 持久化提升多轮对话 APC 命中率。关键术语：OX、hugetlbfs、卸载/加载、ENABLE_OMNI_CACHE、ENABLE_HOST_MAPPING（P 侧 0、D 侧 1 配合 MMU 直读，D 仅 DSA indexer 留 HBM）、VLLM_WORKER_MULTIPROC_METHOD=fork、MAP_SIZE_BYTES、NUM_GPU_BLOCKS_OVERRIDE。部署要点：两个脚本分工（set_hugepage_limit.sh 定内核页数，setup_hugetlbfs_2MB.sh 挂载+建池+写零，launch 脚本自动调用）；真正体现 OmniCache 全参数的是 pangu_v2_pd/launch_*.sh，examples/run_server_p/d.sh 实为 LLMDataDist 基线骨架；kv_parallel_size 文档与脚本不一致，以脚本回显为准；D 侧强制关闭 vLLM 自带前缀缓存。KV 命中证据：num_computed_tokens 日志、DYNAMIC-TOPO 拓扑日志、vllm:omni_cache_reuse_rate 指标。
