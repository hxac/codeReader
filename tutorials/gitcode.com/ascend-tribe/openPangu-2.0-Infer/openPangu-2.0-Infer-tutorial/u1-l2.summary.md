本讲覆盖三个最小模块：monorepo 结构、git submodule、构建入口。仓库只有两个装代码的顶层目录：components/ 放 omni-npu、omni-cache、omni-eplb、omni-proxy 四大运行组件，tools/ 放 ansible、docker、quant、scripts 等部署工具链——改前者影响推理行为，改后者影响部署方式，其中 ansible 按 92B（Flash）与 505B（Pro）两种模型规格分目录。上游形态中四组件各自独立建仓、经 git submodule 挂载到 components/ 下。构建是两级流水线：顶层 build/build.sh 由 parse_args 解析 -m/-s/-sp/-si 参数，check_git 无条件检查 .gitmodules，init_submodules 拉码，再由 check_and_build 分发到各组件自带的 build/build.sh（产物为三个 pip 包和一个 RPM，任一模块失败即整体退出，fail fast）。关键事实：当前 gitcode 开源仓缺 .gitmodules，组件源码以普通文件平铺，顶层脚本会卡在 check_git，需直接调用组件子脚本；bash build/build.sh -m omni-npu 最终执行 pip install -e .（可编辑安装，改码即生效）。
