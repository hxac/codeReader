本讲讲解 OmniPlacement（omni-eplb 组件）的 MoE 专家负载均衡原理与启用配置。路由是模型学出的，热门专家被过度选中使 EP 组内负载不均，MoE 耗时由最慢 rank 决定（木桶效应），均衡目标即压低最大卡负载。四大特性：专家重排、层间不均匀部署、冗余专家（兼具分摊负载与高可用）、近实时激活采集；分静态（dump 激活→生成 pattern→重启应用）与动态（推荐，热更新）两种模式。关键术语：逻辑/物理专家、部署三件套（wheel、P/D 各一份 config.yaml、三维 0/1 部署矩阵 pattern，多卡同为 1 即冗余副本）。开源仓经 `--enable-eplb` 加 `--additional-config` 的 omni_placement_config 键启用，MoE 层构造 OmniPlanner 并扩容本地专家数，补丁接管 EplbState 逐步驱动重排。硬约束：冗余与 AllGather 通信互斥，pattern 须匹配物理部署。OmniPlanner、ExpertMapping 等核心类实现精读留给 u9-l2。
