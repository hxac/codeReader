本讲打开 omni-proxy 黑盒，精读五个核心 C 模块：主模块（HTTP 处理与事件汇合）、omni_scheduler（调度）、omni_radix_tree（前缀树）、omni_apc（msgpack 解析）、omni_zmq_handler（ZMQ 订阅）。核心结论：整体是「主模块 + 卫星模块」单向依赖结构，调度由 1ms 定时器、ZMQ 读事件、分词响应管道三条事件源异步驱动；全局状态放共享内存，多 worker 经探活选举唯一主调度器，标量更新走原子操作、结构修改走互斥锁。关键术语：请求排序权重公式（prefill 侧 0.8 短 prompt 项 + 0.2 等待项）、过载保护三阈值、APC（前缀缓存）命中优先三级比较、earliest_batch 预测算法、128 token 链式块哈希（PYTHONHASHSEED 作链首）、radix tree 乐观无锁匹配（version 号重试）、prefill/decode_match_depths、decode 必须同 group_id 硬约束、BlockStored/Removed/AllBlocksCleared 三类 KV 事件经 ZMQ 分片订阅落树。命中深度数组是 APC 匹配与调度器之间的解耦接口。
