本讲打开 u1-l4 中视为黑盒的 omni-proxy：它是 Omni Infer 第二代请求调度引擎，以两个 Nginx 动态模块（主模块 ngx_http_omni_proxy_module 与 set_request_id 辅助模块）寄生在 Nginx 1.28.0 上，调度行为全部表达为 omni_proxy_* 配置指令。核心概念：请求 10 阶段生命周期（接收→Tokenize→APC matching→P/D 各自等待/调度/执行→完成），逐阶段埋点并映射为 access log 字段（tknized、wait_p、ttft 等）；sequential（先 P 后 D，配 vLLM，本仓库默认）与 parallel（P/D 同选、KV 按层推送与 Prefill 计算重叠，配 SGLang）双调度模式，另有不建 prefill upstream 的 aggregation。omni_proxy.sh 将约 40 个参数渲染为 nginx.conf，支持 dry-run/reload/rollback，分组调度需 prefill/decode groups 成对；proxy 侧完成 tokenize 后透传，PYTHONHASHSEED=123 是 APC 匹配前提。注意普通启动路径未做 nginx -t 校验；C 源码精读留待 u6-l2。
