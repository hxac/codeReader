本讲精读 generate.py 的 APIModel 类，它以「单请求—并发—同步门面」三层结构封装异步 API 调用：generate_one 发单次异步请求，把返回的 reasoning_content 与 content 拼成带 </think> 标记的单字符串（content 非空时开头 <think> 标签会因重新赋值被丢弃，下游只按 </think> 切分故无碍）；generate_all 用 asyncio.gather 并发整批请求，结果按输入顺序返回；generate 是同步门面，经 asyncio.run 驱动事件循环，兼容 messages/prompt 两种输入，并以 {**item} 合并输出、保留原字段、将 finish_reason 小写化。核心结论：API 配置唯一入口是 __init__ 硬编码的 api_key 与 base_url（--api_url 被静默忽略）；timeout=300000 秒等于禁用超时；finish_reason 为 stop 且含 </think> 构成下游判定样本完整的双重判据；gather 无重试与异常兜底，单请求失败即整批作废。本讲为 u2-l2 的多进程队列与断点续跑做铺垫。
