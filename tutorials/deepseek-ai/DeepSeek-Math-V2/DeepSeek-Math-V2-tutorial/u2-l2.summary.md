本讲精读 generate.py 中 APIModel 之后的工程骨架：mp_generate_loop 进程入口与主进程的分发、收尾循环。核心结论：采用两级并发——多个 worker 进程抢 input_queue 里的批次，每进程 sleep(5) 错峰启动并各自实例化 APIModel 与独立事件循环（客户端连接池不可跨进程共享），批内再由 asyncio 并发。引入的关键概念包括：哨兵 (None, None) 与队列协议（任务、哨兵、结果、回声四种二元组消息，回声用于确认 worker 全部退出）；断点档案 .meta（pickle 存 n、batch_size、complete_batches 集合），已完成批次在投递前跳过实现去重，n 与 batch_size 决定批次号到数据的映射、续跑改动会被 assert 拦截；多次采样是在数据层把每行复制 n 份而非用 API 原生 n 参数，计数公式为输出条数＝请求数＝n×输入行数，批次数＝⌈nL/b⌉。已知弱点：协议是批次级 at-least-once，「半批已落盘、meta 未更新」窗口内崩溃会因 "a+" 追加写产生重复行，可用 meta 记录已确认行数并在重启时截断输出文件修复。
