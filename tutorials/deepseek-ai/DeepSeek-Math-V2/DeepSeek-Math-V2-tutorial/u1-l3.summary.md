本讲梳理推理流水线的启动链条与参数全景：README → run.sh（拼装参数）→ main.py（轮次编排与各阶段 input.jsonl 准备）→ generate.py（唯一真正发 HTTP 请求的引擎），main.py 通过三处 os.system 外包生成任务且不检查返回值。run.sh 竞赛配置相对 argparse 默认值的关键差异是验证强度 ×16（64 对 4）、开启 --skip_meta_verification 开关、max_rounds 取 16。API 配置唯一真实入口是 generate.py 中 APIModel.__init__ 硬编码的 api_key 与 base_url，命令行 --api_url 因接收端未注册而被 parse_known_args 静默忽略。本讲引入的关键概念：parse_known_args 的宽容解析、--help 提前退出、断点续跑（文件存在判断加 .meta 批次元数据）、计数公式「输出条数＝输入条数×n」、第二轮起生成条数为 floor(n_parallel/n_agg_trials) 可能为零。核心结论：proof_gen_url、proof_rate_url、infer_script 三个属性被使用却未注册，按 README 直接运行必抛 AttributeError，修复只需补三行 add_argument；APIModel 会把 reasoning_content 与 content 拼回带 think 标签的单字符串，为后续讲义铺垫。
