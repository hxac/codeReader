本讲解决「项目长什么样、入口在哪里」的导航问题。`tile_kernels` 包由「四层 + 两件基础设施」组成：算子层（`transpose`/`moe`/`quant`/`engram`/`mhc`，用 TileLang DSL 写高性能 GPU kernel 并附 Python wrapper）、torch 参考层（`torch/`，纯 PyTorch 参考实现，供测试对拍验证）、modeling 层（`modeling/`，用 `torch.autograd.Function` 把 kernel 封装成可求导层，目前仅覆盖 engram 与 mhc）、testing 层（`testing/`），外加基础设施 `config.py` 与 `utils.py`。包入口 `__init__.py` 不写算子逻辑，只做「导入子模块 + 选择性再导出」，把 `config` 的三个函数提升到顶层。每个算子家族的子包 `__init__` 遵循同一模式，从 `*_kernel.py` 再导出 wrapper——用户调用入口是 wrapper 而非 TileLang kernel 对象。调用路径以 `tile_kernels.transpose.transpose` 为例分三级解析：包入口导入子包 → 子包 `__init__` 再导出函数 → wrapper 所在文件。`config` 提供 SM 数量与每 SM 共享内存的硬件探测（探测函数带 `lru_cache` 缓存），并支持 `set_num_sms` 限制可用并行度，算子应通过 `get_num_sms()` 查询。`utils` 提供无副作用小工具 `ceil_div`/`align`/`is_power_of_two`，服务于分块、对齐与合法性校验。
