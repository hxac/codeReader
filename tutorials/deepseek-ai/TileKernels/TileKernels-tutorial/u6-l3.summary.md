本讲是 engram 门控模块的收尾篇，覆盖两个不参与门控核心数学但不可或缺的最小模块。`engram_hash` 用滚动异或哈希 h_i = h_{i-1} ⊕ (t_i·m_i)（m_i 为每位置独立乘法因子）把 token 窗口映射成嵌入表下标供查表；单 token 不产生输出，从 bigram 起每列下标为 (hash % vocab_size) + offset，每 token 输出列数为 (max_ngram_size-1)×num_embed_table_per_ngram。kernel 是「一线程一 token」的 embarrassingly parallel 结构，小常量故意拷进每线程 local 以「寄存器换同步」省掉 shared memory 与同步，哈希全程在 int64 上算避免高位溢出。`fused_weight` 在前向开始时把两份 RMSNorm 权重 w_h、w_e 预乘为一份 fp32 张量 weight_fused，依乘法结合律把与 token 无关的乘法搬出每 token 热循环；它主要省算力与权重流条数（两条降为一条，降低寄存器与 SMEM 压力）而非字节数（fp32 与两份 bf16 均为 4 字节/元素），且一份产物被前向、反向 kernel 两次复用，预乘代价摊薄。最后辨析：fused_weight（前向预乘产物，每步重算）与 main_grad（反向 fp32 梯度累加缓冲，跨步常驻）是 engram 模块里两个互不冲突的「权重」优化，分别覆盖前向与反向两端。
