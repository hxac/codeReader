本讲聚焦 mhc 的「编排层」`functional.py`：它不写任何算子逻辑，只把 ops 层多个 `autograd.Function` 按固定配方组合成三个用户入口 `expand_from_embedding`、`mhc_pre`、`mhc_head`（`__init__.py` 仅导出这三个）。核心结论有三：一是 `mhc_pre` 按 `torch.is_grad_enabled()` 自动分流——推理态走单融合 op `mhc_pre_big_fuse`（无反向、换带宽），训练态走 `pre_norm_fn → pre_split_mixes → sinkhorn → pre_apply_mix` 四步可反传链，两条路径都返回统一契约 `(layer_input, ctx)`，编排层还重排融合 op 的返回顺序以稳定 API。二是 `ctx=(post_mix, comb_mix)` 是 pre/post 之间的「不透明元组（opaque tuple）」接力棒：对调用方不解释内部含义，原样透传给 `mhc_post` 即可，使夹在中间的子层对多股残差完全无感知而实现解耦；训练态下它是带 grad 历史的真实张量，autograd 图经它连通。三是 `mhc_head` 用 `F.pad` 把 lm_head 的小权重补零到 `mhc_mult3` 行，100% 复用 `mhc_pre_norm_fn` kernel——因 GEMM 行独立、补零行平方为零不抬高 RMSNorm 分母，切片前 `mhc_mult` 个通道与专用 kernel 逐位等价。三个入口本身均为普通函数而非 `autograd.Function`，可微性全部来自链式组合，是单 op 封装范式向多 op 组合场景的自然延伸。
