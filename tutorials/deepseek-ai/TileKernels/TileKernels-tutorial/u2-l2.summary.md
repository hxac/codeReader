本讲讲「GPU kernel 内部数据放哪里、怎么搬」，建立 global(HBM)→shared(SMEM)→register 三级存储心智模型，承接 u2-l1 的 `@tilelang.jit` 骨架。引入 TileLang 三种分配原语：`alloc_fragment`（协作布局寄存器，支持 `T.copy`/规约/`annotate_layout`）、`alloc_local`（线程私有寄存器，适合手控线程-元素映射）、`alloc_shared`（块内共享 SMEM，写后须 `T.sync_threads`）。核心原语 `T.copy(src, dst, disable_tma=True)` 做跨级批量搬运，方向由两端存储层级决定；`disable_tma` 关掉 Hopper/Blackwell 的 TMA 硬件路径、走向量化 load-store，适合目标是 fragment 或需精细控制时。shared memory 物理切 32 个 bank，矩阵转置「按行写按列读」最易撞 bank：静态地给每行加 `+block_k` padding 让行宽不再是 32 的倍数，把最坏 32 路 conflict 大幅降低，残留冲突由动态 swizzle（改线程-元素映射）兜底。两种风格对比：转置全程直接索引 + local + 手写 swizzle（细粒度控制），量化用 fragment + T.copy（集体加载与跨线程规约如 `T.reduce_absmax`，后者承接到 u2-l3）。
