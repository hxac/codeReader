本讲回答「算子如何感知硬件并据此决定并行度」，覆盖三个最小模块。`config.py` 是硬件感知唯一入口：`get_device_num_sms`、`get_max_smem_per_sm` 带 `lru_cache` 探测物理 SM 数与每 SM 共享内存上限；`get_num_sms`/`set_num_sms` 不带缓存，靠可变全局 `_num_sms` 做运行时覆盖，`set_num_sms` 用 `assert` 锁定上界不超过物理 SM 数。engram 前向 kernel 作为持久化 kernel 范例，其编译期占用启发式 `_choose_num_persistent_blocks` 以 `smem_bytes = 2H + 4·blk_d` 估算每 SM 可驻留 block 数 `blocks_per_sm`（取 SMEM 上限与寄存器压力上限 16 的 min），再乘 `num_sms` 除 `hc_mult` 得持久化块数 `num_persistent_blocks`。核心结论：`num_sms` 一律作为编译期参数传入 jit 装饰的构造函数、从不在 prim_func 内运行时读取，故 `set_num_sms` 会触发重新编译、改变网格形状，只改性能不改正确性。`testing/generator.py` 的 `generate_num_sms` 以物理 SM 数为基线生成「受限 + 满载」扫描点并把满载值排末尾以防测试间状态泄漏，用于自动化验证「set_num_sms 不改正确性」这一不变量。
