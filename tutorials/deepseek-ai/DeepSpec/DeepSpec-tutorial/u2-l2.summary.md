本讲精读 deepspec/data/parser.py，它在数据流水线中把 u2-l1 产出的纯文本对话（id + conversations）转换为 input_ids/attention_mask/loss_mask 三张量，唯一入口是 preprocess_record。核心内容：ChatTemplate 数据类与 TemplateRegistry 注册表以 data.chat_template 字符串（如 "qwen"、"gemma4"）登记各模型族的 assistant 头、结束符、默认 system_prompt 与 loss 前缀，模板冻结且防重复注册；渲染权威归 tokenizer 的 apply_chat_template，parser 只用非贪婪正则逐轮定位 assistant 片段的字符区间；再以「前缀重编码」技巧把字符区间换算成 token 区间——对两个前缀分别分词取长度，依赖特殊 token 的原子性，并用 min 钳制兜住截断样本。监督区间包含结束符（如 <|im_end|>\n），让模型学会停止；Gemma4 的 assistant_loss_prefix 渲染时插入空 thought 通道、计算损失时跳过，实现非思考训练。该解析仅在生成 target cache 阶段执行一次，ConversationCollator 用 min_loss_tokens 过滤监督 token 过少的样本，loss_mask 随缓存落盘供训练与后续 DSpark/Eagle3 损失计算使用。
