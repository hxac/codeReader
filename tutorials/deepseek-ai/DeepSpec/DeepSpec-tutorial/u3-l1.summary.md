本讲剖析 deepspec/trainer/base_trainer.py 中 BaseTrainer.__init__ 的完整装配流程：分布式初始化 → 断点发现 → 模型构建 → 权重恢复 → torch.compile → FSDP 包装 → 数据校验 → 训练日程计算 → 优化器构建 → 训练状态恢复，顺序严格线性，任何环节不符即断言失败。核心结论：草稿模型的 embed_tokens 与 lm_head 从目标模型（CPU 上加载、拷完即释放）拷贝并冻结，既钉死与目标模型一致的输入输出接口，又省下约 778M 参数的 fp32 主权重与 AdamW 动量（Qwen3-4B 下约 9GB）；FSDP 以 use_orig_params=True 包装且默认 no_shard，只作统一分布式外壳，故优化器建在裸模型上依然正确；训练日程由纯函数推出：梯度累积步数 = global_batch/(world_size×local_batch)，samples_per_epoch 向下取整到全局批整数倍再算 steps_per_epoch。引入关键术语：模板方法模式（子类 Qwen3DSparkTrainer 只填 _build_draft_model 与 run_batch 两个钩子）、BF16Optimizer 与 fp32 主权重、CacheDataset 及 validate_train_cache 三项合同校验、next_micro_step 作为训练进度唯一真相源。train() 主循环留待 u3-l2。
