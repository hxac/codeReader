本讲剖析 DeepSpec 评估侧骨架：薄入口 eval.py 用 spawn 每 GPU 拉起一个 worker，凭草稿 checkpoint 的 config.architectures[0] 查 EVALUATORS 分发表确定 Evaluator（DFlash 与 DSpark 同 architectures 故自动复用同一评估器），TASKS 以「数据集名+配额」规定评哪些基准、各抽多少条。BaseEvaluator 采用模板方法模式固化「遍历数据集→逐卡生成→汇总→打表」流程，子类只需填 build_models、max_proposal_tokens、generate_one_sample 三个钩子。数据契约是 eval_datasets 下 JSONL 每行的 turns 字段（非空字符串列表），加载时强制截断为首轮、仅做单轮评测；assistant 回复由目标模型在投机解码循环中现场生成，prompt 渲染复用训练侧 encode_chat_messages 保证一致。多卡按 stride 分片，逐样本种子 seed_all(seed+idx) 挂在样本下标上，使结果与卡数无关且可复现；指标遵循「本地合计数、all_reduce 求和、rank 0 再除」。核心指标由逐轮计数（有效提议 n_t、接受数 a_t）构成：accept_len 为含兜底 token 的平均每轮提交数（加速比近似上界），verify_rate 为草稿命中率，满足恒等式 verify_rate=(accept_len−1)/(n̄+1)，accept_rate@k 按槽位刻画接受概率衰减。解码循环与拒绝采样验证留作黑盒，交由 u6-l2、u6-l3 精读。
