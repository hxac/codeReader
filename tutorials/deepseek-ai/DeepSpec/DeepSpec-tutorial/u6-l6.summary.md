本讲精读 Eagle3 评估器的三个钩子（init_context / propose / update），是评估单元收官篇。核心结论：预填充须做 token 错位对齐——草稿槽位 i 消费 (h_i, x_{i+1}) 而 RoPE 位置保持 i，做法是丢 prompt 首 token、锚点补尾（shifted_prompt_ids）；_update 则借「隐状态含锚点、token 不含锚点」天然实现同一错位。_propose 是链式提议：k 个草稿 token 需 k−1 次单 token 前向，滚动隐状态 draft_hidden 逐环下传，投机槽位真写入草稿 cache，由 cache_len_before 标记回退点。断言 draft_num_hidden_layers==1 的安全依据：_update 不带因果掩码批量追加已提交 token，仅单层草稿的 K/V 逐位独立（cache 无污染）且只保留末位输出。末尾与 DSpark 对照：前者记目标特征窗口、块式提议、propose 内裁剪，后者记草稿 cache 加滚动状态、update 开头裁剪；两者每轮起点均满足草稿 cache、目标 cache 与 start 三者同步的不变式。
