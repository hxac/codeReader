本讲建立 DeepSpec 仓库的「导航地图」，覆盖三个模块：仓库目录结构、三阶段工作流、shell 启动脚本。核心结论：仓库为「扁平入口 + 单一 Python 包」结构，train.py 与 eval.py 是命令行入口，deepspec/ 包按 data/modeling/trainer/eval/utils 五个子包组织，其中 modeling、trainer、eval 均按算法（dspark/eagle3）× 模型族（qwen3/gemma4）双维度划分；config/ 下 3 算法 × 4 目标模型共 12 份配置文件。数据准备 → 训练 → 评估三阶段通过磁盘文件而非函数调用交接：数据阶段产出训练 JSONL 与 target cache（默认 Qwen3-4B 约 38 TB），训练经 --opts 注入缓存路径、产出 checkpoint（~/checkpoints/<project>/<exp>/step_*），评估读 checkpoint 与 eval_datasets/*.jsonl，输出投机解码接受率等指标。本讲引入的关键术语：target cache、checkpoint、--opts 点路径覆盖语法、由 CUDA_VISIBLE_DEVICES 决定的每 GPU 一进程 spawn 启动语义（非 torchrun）、BASE_CKPT_DIR 等集中式路径常量。这些概念将供后续讲义在深入各模块内部时承接复用。
