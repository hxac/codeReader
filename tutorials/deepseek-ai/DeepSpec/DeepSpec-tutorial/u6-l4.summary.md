本讲精读 DSpark 评估器提议侧，模块为 evaluator.py 与 draft_ops.py，实现四钩子中的 init_context/propose/update（post_verify 留待 u6-l5）。核心结论：_propose 以「锚点 + mask token 噪声块」做一次长度 B 的并行草稿前向（forward_dspark_draft_block），一次产出整块隐状态，胜于链式逐 token 提议；位置切片从草稿缓存长取到 start+B，同时覆盖新上下文键与块内 query 的 RoPE；草稿与目标 KV cache 对偶维护，轮末各自 crop(start) 且长度同步；draft_probs 取 markov 头修正后 logits 构造，保证拒绝采样无损；置信度头按阈值截断低置信前缀，截到 0 成空提议，退化为仅验证锚点、目标直采 bonus；_update 切出「锚点 + 被接受前缀」共 a+1 个目标隐状态，替换滚动窗口 target_hidden_states 以补齐草稿缓存缺口。关键术语：噪声块、双缓存对偶、滚动窗口、置信度早停、空提议、DSparkDraftProposal。
