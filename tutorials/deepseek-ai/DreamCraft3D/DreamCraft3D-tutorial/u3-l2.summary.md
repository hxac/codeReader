本讲剖析 threestudio 的四个基类：Configurable、Updateable、BaseObject、BaseModule。核心结论：Configurable 用内嵌 Config dataclass 加 parse_structured（基于 OmegaConf structured）把 yaml dict 转成强类型 self.cfg，配置错误在构造瞬间暴露；BaseModule 生命周期固定四步——解析配置、绑定设备、configure 组装网络、可选加载权重，并在装权后用检查点的 epoch/global_step 调 do_update_step(on_load_weights=True) 恢复渐进状态。Updateable 定义 update_step/update_step_end 两个钩子，do_update_step 对所有公开的 Updateable 属性做后序递归遍历（下划线开头的属性被跳过），叶子组件先于容器更新。触发时机由 BaseSystem 决定：各阶段 batch start 先 update_if_possible 刷新 dataset、再刷整棵组件树，且发生在 training_step 之前；评估与导出路径同样会刷新。DreamCraft3D 的分辨率爬坡、渐进视角、哈希编码层级解锁（ProgressiveBandHashGrid）与扩散时间步区间调度，全部是该机制配以 C() 插值或 bisect 换档的同一模式应用。
