本讲剖析 gradio_app.py 的三进程松耦合架构：Gradio 前端用 Popen 拉起 launch.py --gradio 训练子进程与看门狗子进程，彼此无函数调用，仅靠试验目录下 progress、logs、alive 三个文件通信。核心结论：界面旋钮最终都译成命令行 extras 覆盖，目录类覆盖保证双方共用同一 trial_dir；--gradio 开关在 launch.py 引发四处变化——无色日志、日志落盘、ProgressCallback 替换 TQDM 进度条、训练后自动 predict 导出。alive 心跳由前端轮询写入，watcher 发现失联超十秒即 SIGKILL 训练进程，防止孤儿 GPU 任务。CodeSnapshot 与 ConfigSnapshot 回调（git ls-files 双查询并集、parsed/raw.yaml 快照）构成不依赖 git 历史的可复现闭环。注意仓库缺失 configs/gradio/，前端直接启动会抛 FileNotFoundError。二次开发地图：九类可插拔扩展点（system、data、geometry、material、background、renderer、guidance、prompt_processor、exporter）统一遵循「X_type 注册名 + find 实例化」模式，custom_import 提供零侵入接入；exporter 契约是返回 ExporterOutput 列表、save_type 反射到 SaverMixin；callbacks 是唯一须改 launch.py 的扩展点。实践以 stats-exporter 演示注册、注入与验证全链路。
