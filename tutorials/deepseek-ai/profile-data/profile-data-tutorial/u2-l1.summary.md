本讲把 CPU 与 GPU 的轨迹记录正式接起来。核心结论：一次内核启动在轨迹中呈三层记录——cpu_op（算子）→ cuda_runtime/cuda_driver（API 调用）→ kernel/gpu_memcpy/gpu_memset（GPU 执行）；CUPTI 分配的 correlation 字段是 CPU 侧 API 与 GPU 活动之间一对一的外键，train 两侧各 983 条、prefill 各 4152 条，严格对账。关键术语：correlation、Ev Idx（CPU 记录顺序号）、External id（CPU 侧为算子编号，CUDA 侧实测与 correlation 相等，不能用于跨层 join）、ac2g 流事件（ph:"s"/"f" 按相同 id 配对，是查看器中 CPU→GPU 箭头的数据来源，另含不成对的孤儿事件）。追回 CPU 算子须用同 pid/tid 的区间嵌套法，可得到如 ProfilerStep#1→1F1B→attn(F)→算子的注解链。提交→执行延迟 Δ=ts_kernel−ts_api 量化排队深度：train 微秒级即被接手，prefill 呈约 16 ms 的深排队形态。
