本讲以 train.json 为对象，解析 1F1B/DualPipe 调度的 CPU 侧记录，分三个模块：容器注解、stage 注解体系、GPU 进程时间线阅读。核心结论：全文件共 42 条 user_annotation，外层 ProfilerStep#1（约 112ms）套住框架主动打点的 1F1B，之下是 10 类 stage 注解——attn/mlp×F/B/W 加 dispatch/combine×F/B，每种恰出现 4 次，对应每个 chunk 含 4 个 MoE 层；每轮固定顺序以 combine(B) 打头、反向与前向交错，实证 DualPipe「先反后前」的成对编排。关键概念：F/B/W 分别指前向、反向数据梯度、反向权重梯度（B 与 W 拆分是为错峰）；注解 dur 是 CPU 墙钟而非 GPU 时长（dispatch(F) 的 20ms 是 DeepEP 扩展内部等待）；8 条 GPU 轨道是采集版式，内核全在 GPU 0，计算在 stream 7、通信在 stream 27，二者时间上重叠。解读前提：模拟绝对均衡 MoE 路由、PP 点对点通信未计入轨迹。
