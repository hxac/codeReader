本讲将前两单元的点查沉淀为可复用脚本 analyze_trace.py，用 Python 纯标准库定量分析 train/prefill/decode 三份轨迹。模块一：JSON 加载——decode 为单行压缩文件，必须用 json.load 结构化解析（文本工具计数会失真），事件需按 ts 排序；模块二：按 cat、内核名、stream 三维聚合——时长只计 ph=="X" 事件，占比只在同一 cat 内计算（CPU 墙钟不可与 GPU 执行混算）；模块三：Top-N 耗时榜——内核名截断归一化成家族，分母取 kernel 总时长。核心结论：聚合结果本身就是结构指纹——decode 的 cpu_op 骤减暴露 CUDA Graph 回放；train 的 GPU 时间头部为 DeepEP 通信（约 46.5%）、FlashAttnBwd 与分组 GEMM 三类大块；decode 的 dispatch_ll 时长呈双峰。关键术语：名称归一化、args.stream 分组（kernel 事件的 tid 即流号）、左闭右开事件区间 [ts, ts+dur)（微秒），该区间是 u3-l2 重叠率分析的基座。
