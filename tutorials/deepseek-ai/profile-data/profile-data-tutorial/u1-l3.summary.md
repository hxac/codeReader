本讲解剖 PyTorch Profiler 导出的 Chrome Trace JSON 的顶层骨架。三份轨迹（train/prefill/decode）同构：四个核心字段 schemaVersion（均为 1）、deviceProperties、distributedInfo、traceEvents，外加 PyTorch 附加的 traceName（原始文件名，常编码实验配置）。核心结论：采集底座是 NVIDIA H800——132 个 SM、约 79.1 GiB（标称 80 GB）显存、计算能力 9.0（Hopper 架构），train 记录 8 块卡属性而另两份仅 1 块；distributedInfo 的 backend=nccl、rank=0，world_size 64/32/128 分别对应 EP64 训练、EP32 预填充、EP128 解码，是区分三份文件的最快判据，rank 0 提醒这是单进程视角、看不到对端；traceEvents 是数据主体（14240/85422/19417 条），ts 为 Unix 纪元微秒，数组按记录顺序而非时间顺序排列，分析前必须按 ts 排序，尾部藏有进程/线程命名元数据与采集窗口 span。decode.json 为单行压缩格式，只能用 Python 解析。
