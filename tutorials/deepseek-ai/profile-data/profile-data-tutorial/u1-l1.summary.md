本讲厘清 profile-data 仓库的定位：它是 DeepSeek 公开的性能分析（profiling）数据集而非代码库，主体是 PyTorch Profiler 导出的三份 Chrome Trace 格式 JSON 与三张对应截图，核心主题为通信-计算重叠。三份轨迹各对应一个场景：train.json 是训练（EP64、TP1、4K 序列），展示 DualPipe 中一对前向/反向 chunk（每 chunk 含 4 个 MoE 层）的交错重叠，PP 通信未计入轨迹；prefill.json 是预填充（EP32、每 GPU 16K tokens），用双微批重叠计算与 all-to-all，并要求两微批注意力负载均衡；decode.json 是解码（EP128、每 GPU 128 请求），all-to-all 采用 DeepEP 低延迟实现，RDMA 消息发出后释放全部 SM，通信不占计算单元。本讲引入的关键术语：profiling、预填充/解码两阶段、EP/TP/PP/world_size、MoE 路由、dispatch/combine、RDMA、SM。最重要的解读前提：采集时模拟了绝对均衡的 MoE 路由，数据只反映理想负载下的调度行为，不能外推真实路由倾斜场景。
