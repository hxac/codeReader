本讲为系列收官，从「读轨迹」转为「造轨迹」。最小模块有三：一是用 torch.profiler 采集小模型，activities、record_shapes、schedule、record_function 等参数各在轨迹中留下指纹（如 ProfilerStep#N 注解、Input Dims 字段、user_annotation 事件），with 块结束后用 export_chrome_trace 导出与仓库同格式的 Chrome Trace；二是与 train.json 逐字段对照，顶层结构同构，差异勾勒出单卡与集群的边界；三是把轨迹证据映射回生态仓库——10 类 stage 注解对应 DualPipe 调度，dpsk::ep:: 两代通信内核对应 DeepEP（normal 代走独立通信流、ll 代与计算同流），dpsk::gemm:: 按命名空间推断对应 DeepGEMM，内核签名中的 CUtensorMap_st 指向 Hopper 特有的 TMA。综合实践用双流复现通信-计算重叠并以区间求交计算重叠率。核心结论：轨迹是采集参数的指纹，会造才算读懂格式；证据须分级，推断须标注待确认。
