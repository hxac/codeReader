本讲把轨迹中的内核事件转为微秒时间区间，以区间合并与求交为底座，定义三族指标：通信重叠率、计算并行率、暴露通信（未被计算遮挡的通信），以及气泡、计算覆盖率与 decode 特有的发送段/等待段分解。核心结论：train 轨迹是双流真并行——DeepEP 通信内核独占 stream 27、约占 kernel 总时长 46.5%，与 stream 7/23 的计算区间相交，单个 6.5ms combine 窗口内计算覆盖 80.6%，两流覆盖率之和可超 100%；decode 轨迹的 dispatch_ll/combine_ll 与计算同在 stream 7，同流串行使区间交集近 0，重叠由资源级并发转为延迟隐藏（发送-填隙-等待三段式），通信集须按内核名称而非按流划分，窗口账本为计算+发送+等待+气泡。
