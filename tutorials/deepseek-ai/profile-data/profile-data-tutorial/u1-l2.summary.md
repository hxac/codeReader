本讲解决「打开轨迹 JSON 并在满屏轨道中不迷路」的问题，主要观察对象是 train.json。两种查看方式：README 官方推荐的 chrome://tracing（Edge 对应 edge://tracing）与更现代的 Perfetto UI（ui.perfetto.dev），二者能通用是因为三份轨迹均为 Chrome Trace Event 格式（顶层 schemaVersion: 1）。事件时长相差四个数量级，浏览须先全局后局部：W/S 缩放、f 聚焦、/ 搜索、点选事件查看 args。时间线版式由 ph:"M" 元数据事件决定：process_labels 把 pid 命名为 CPU 与 GPU 0~7，thread_name 把 tid 命名为 stream 7/23/27（stream 即 GPU 上的任务队列）；ts 与 dur 均以微秒计。关键事实：963 个 GPU 内核全部落在 GPU 0（stream 7 占 907 个），GPU 1~7 轨道为空，原因是采集视角为 world_size 64 中的 rank 0；1F1B 总注解约 112 毫秒。correlation 编号用于配对 CPU 侧 CUDA 调用与 GPU 内核，详细机制留待下一讲。
