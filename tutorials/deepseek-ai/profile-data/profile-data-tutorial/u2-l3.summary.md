本讲解析训练/预填充轨迹中的 DeepEP 跨节点（internode）通信内核：dispatch 把 token 按路由结果发往专家所在 GPU，combine 将专家输出原路聚合回源端并按权重求和，notify_dispatch 与 cached_notify 是传输前的两种握手，get_dispatch_layout 做本地路由布局计算；由此引入 MoE Top-K 路由、专家并行（EP64）、all-to-all、RDMA、SourceMeta 等概念。核心结论：train.json 中 36 个 DeepEP 内核占 GPU kernel 总时长的 46.5%，全在通信流 stream 27，每个 MoE 层呈「量化→握手→发送→聚合」式十步循环，combine 普遍慢于 dispatch；通信与计算真并行——单个 6.5ms 的 combine 窗口内计算流跑了 17 个内核（利用率 80.6%），而通信内核仅占约 15% 的 SM。关键教训：CPU 注解名与 GPU 内核名错一位对应（如 dispatch(B) 区间启动的是 combine 内核），必须用 correlation 反查，重叠分析要基于内核自身执行区间。prefill 中同族内核 580 个、占 48%（stream 16），且每次 dispatch 前都重算布局，对应真实路由与模拟均衡路由之别。
