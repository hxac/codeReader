本讲把 train、prefill、decode 三份轨迹（EP64/EP32/EP128）拼成横向全景。配置信息分三层来源：README（场景）、distributedInfo 的 world_size（TP1 时即 EP 数）、traceName（实验指纹，decode 缺失）；因采集窗口与注解口径不同、且基于模拟绝对均衡 MoE 路由前提，只能比占比与形态，不能比绝对时长。通信上，train/prefill 用 normal 全家族 DeepEP 内核（含布局与握手），占 kernel 时长 46.4%/48.0%，毫秒级、独立通信流；decode 用 low-latency 的 dispatch_ll/combine_ll，占 18.9%，微秒级、与计算同流。注意力上，训练含反向 FlashAttnBwd，预填充用 compute_attn_ws，解码用 split-KV 两段式 splitkv_mla，占比 8.2%/9.1%/34.9%，解码因无大 GEMM 摊薄而注意力登顶 Top-1。重叠率 train 96.2%（DualPipe）、prefill 91.2%（双微批）；decode 区间交集为 0，实为 SM 级延迟隐藏——RDMA 发出即释放 SM、等待期填入另一微批计算，叠加 CUDA Graph，故其通信集须按内核名而非流划分。核心结论：通信策略由通信绝对量与时延预算决定，而非 EP 规模。
