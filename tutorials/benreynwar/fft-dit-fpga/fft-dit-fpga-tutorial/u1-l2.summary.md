本讲梳理「让 Verilog 设计跑起来并验证其正确性」的完整构建链路。运行测试需同时具备 Verilog 侧的 Icarus Verilog（`iverilog` 负责编译、`vvp` 负责运行）与 Python 侧的 MyHDL、numpy、jinja2；仓库自带的 `myhdl.vpi` 作为 VPI 模块充当 Python 与 Verilog 仿真器之间的协同仿真桥梁，numpy 则提供标准答案供逐点比对。

关键前置步骤是：编译前必须先调用 `make_twiddle_factor_file(N, tf_width)` 生成 `twiddlefactors_N.v`——它将旋转因子 W_k=e^(-i2πk/N) 量化为定点整数，再经 jinja2 模板 `twiddlefactors_N.v.t` 渲染成一个 `case` 查表的 Verilog 模块；缺此文件 `iverilog` 找不到源文件，编译必失败。随后 `TestBench.prepare()` 借 `-D` 宏把 N 与位宽参数注入 `dut_dit.v` 中 `dit` 的例化，并把 `dut_dit.v`、`dit.v`、`butterfly.v`、`twiddlefactors_N.v` 四个源文件编译成仿真可执行文件 `fftexec`；`simulate()` 再用 `vvp -m ./myhdl.vpi fftexec` 启动仿真，二者构成「先编译、后运行」两步。需注意本项目为 Python 2 语法，在 Python 3 下能否直接跑通待本地验证。
