本讲为纯阅读讲，绘制 PyPTO 仓库地图并讲解三层架构：① C++ 核心层（include/pypto 与 src，目录镜像），定义 IR 节点（expr.h 的 Var/Call/Submit）、各 Pass（src/ir/transforms）、PTO 代码生成与按架构分目录的后端；② 绑定层（python/bindings），用 nanobind 把 C++ 编译成二进制扩展 pypto_core，import 时执行 ValidateTileOps 等导入期自检；③ Python API 层（python/pypto），含 language（DSL）、jit、ir、runtime 等子包。核心结论：pypto_core 目录只有 .pyi 类型桩，改 C++ 必须重编，改桩无运行时效果；跨层同步要求一个 API 在声明、实现、绑定、类型桩、使用五处齐动（以 inline_functions 走通全链）；Pass 文档编号即默认流水线执行顺序；docs 英文版权威、中文镜像；tests 分 ut/st/lint，examples 按难度分层。
