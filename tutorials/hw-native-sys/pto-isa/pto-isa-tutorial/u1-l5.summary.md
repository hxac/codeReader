本讲剖析 PTO-ISA 统一入口 pto-inst.hpp 与多后端装配机制。核心结论：该入口仅 33 行，以「公共基础层 → stub 选择 → 指令层装配」三段式条件编译完成装配；后端由编译期宏决定——`__CPU_SIM`（CPU 模拟器，构建脚本定义）、`__CCE_AICORE__`（NPU 真机，CCE 编译器内置）、`__COSTMODEL`（性能估算，须与 `__NPU_ARCH__` 成对出现），幕后宏 `__NPU_ARCH__` 再把 NPU/CostModel 细分到 a2a3、a5 等实现目录。引入的关键概念：header-only 模板库、cpu_stub 的三类替身（空宏、空同步函数、malloc 版 aclrt 加多线程启动器）、「stub 必须先于 memory.hpp」的包含顺序契约、指令签名集中于 common 层而实现按后端分布的分层设计、MAP_INSTR_IMPL 装配枢纽与 TADD_IMPL 三份实现、CostModel 复用 include guard 实现 drop-in 替换。重要结论：CPU 模拟器只验证数值语义、不验证时序（set_flag/wait_flag 为空函数），g++ -E 可验证 include 依赖图。
