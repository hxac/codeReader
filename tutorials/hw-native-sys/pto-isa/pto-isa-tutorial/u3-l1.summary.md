本讲解释 PTO 内核为何需要显式事件同步：昇腾 AI Core 的 MTE2、V、MTE3、M、FIX、S 等流水线异步并行，书写顺序不等于完成顺序，跨流水线数据依赖必须用事件表达局部同步，否则退化为全局串行。四个最小模块：`pto::Op` 编译期操作码枚举（含 OP_COUNT 哨兵）；`OpPipeEntry` 配合 `PTO_DEFINE_OP_PIPE` 构成指令到流水线的编译期映射表（TLOAD→MTE2、TADD→V、TSTORE→MTE3），未特化兜底为 PIPE_ALL；`set_flag`/`wait_flag` 原语，参数为源流水线、目的流水线、事件 ID（0~7），配对要求三者一致且 set 在生产指令后、wait 在消费指令前；`RecordEvent` 与指令尾部 `WaitEvents&...` 变参是同机制的类型化写法，`EventIdCounter` 按流水线对自动轮转分配 ID。另区分：同流水线保序用 `pipe_barrier`，跨核同步走 FFTS。关键结论：CPU 模拟器把 set/wait 实现为空函数、依赖单线程程序序，删除 wait_flag 这类事件链错误在 CPU 上检不出，须上 NPU/sim 验证。
