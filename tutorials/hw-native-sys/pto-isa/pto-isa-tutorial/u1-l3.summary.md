本讲建立 PTO-ISA 仓库的「地图感」：五大内容目录各司其职——`include/` 是 header-only 模板库的全部对外交付，`kernels/` 放手工调优等性能参考算子，`demos/` 放端到端最小示例（含纯 CPU 路径），`tests/` 按运行平台分 CPU/NPU/CostModel 三条纵队并配统一驱动脚本层，`docs/` 含逐指令 ISA 文档与编程模型文档。核心是 `include/pto/` 五模块划分：`common/`（平台无关的 Tile 类型系统与指令公共声明）、`cpu/`、`npu/`（按 SoC 代际再分 `a2a3/`、`a5/`、`kirin9030/`）、`comm/`、`costmodel/`；规律是「声明永远在 common，实现按后端各归其位」，由统一入口头 `pto-inst.hpp` 按编译宏（`__CPU_SIM`/`__CCE_AICORE__`/`__COSTMODEL`）组装。由此引出「指令定位法」六落点：公共 API 声明、CPU 实现、a2a3 实现、a5 实现、ST 测试目录、ISA 文档与状态表；`include/README.md` 状态表是指令在六后端可用性的权威查询处。ST 用例遵循「四件套」模板（kernel、main、gen_data.py、CMakeLists），目录名即指令名，CPU 与 NPU 两侧结构平行。
