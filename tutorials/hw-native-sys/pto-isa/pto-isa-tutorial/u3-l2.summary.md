本讲承接 u3-l1 的事件配对规则，讲清三件事：一是 PTO 的八条硬件流水线（S/V/MTE1/MTE2/MTE3/M/ALL/FIX，编号 0~7）的职责划分，事件全名是三元组 (srcPipe, dstPipe, id)，事件 ID 是「每对流水线 8 个名额」而非全局资源；二是 event.hpp 中 OpPipeEntry 主模板加 PTO_DEFINE_OP_PIPE 模板全特化构成的编译期「指令 → 流水线」映射表，129 条指令全部显式登记（V 上 101 条，FIX、S、MTE、M 各若干），漏登记会兜底成 PIPE_ALL 并被 TSync 的 static_assert 拦截，且跨缓冲移动指令按目的地归类（如 TSTORE_ACC 走 FIX、TMOV_M2L 走 MTE1），不能按名字猜；三是 EventIdCounter 按流水线对独立轮转发号（模 8 复用）并带「拿了没 Wait」占用断言。以 add demo 说明乒乓双缓冲事件编排：一个缓冲槽位独占一个 ID，预置段声明槽位初始空闲，收尾段收净残留 set 保证通道配平，CPU 模拟器上 set/wait 为空操作，正确性需靠推演与 sim/NPU 验证。
