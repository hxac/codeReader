本讲围绕公共声明层 pto_instr.hpp 与装配枢纽 pto_instr_impl.hpp，建立指令 API 的四层抽象：User API wrapper → 后端 *_IMPL（含 Check）→ TF 结构体 → CCE 内建。核心结论：签名即契约——wrapper 只做等待前置事件、转发操作数、返回 RecordEvent 三件事，不含算法；PTO_INST 与 PTO_INTERNAL 的可见性差异区分公共 ISA 面孔与内部零件。WaitEvents 变参永远排在签名尾部，只在 wrapper 层被消费、不进 IMPL，产出会被消费数据的指令才带它（TLOAD 有、TPREFETCH 无），异步变体返回 AsyncEvent。分发靠 MAP_INSTR_IMPL 预处理拼接，同名 *_IMPL 多份定义由装配层互斥条件块实现编译期单选。构词法可解码指令名：S 后缀=标量、_ACC=累加、_MX=微缩放、_ASYNC=异步。装配教训：__DAV_VEC__ 条件块必须立即 #endif 闭合，旧版缺失曾使非向量核单元丢失约 80 个 A5 头；A6 经 arch_macro 翻译后以汇总头接入，专属指令自研、成熟指令头文件级复用 A5。
