本讲解读 Ground3D 数据集的原始组织：每个数据源分三大块——processed_data 存每帧四类逐点对齐的 npy（vert 为 N×6 的 XYZ+RGB 点云，sp/part/object 三类 label 均为长度 N 的实例标签，是实例而非类别）；refined_qa_data 按 part_qa、object_qa、multiturn_qa 三层组织 QA JSON，单轮嵌套结构为「条目 id → 任务名 → 问答列表」，任务名共 9 类（常量 ALL_TASKS，以代码为准）；train/val 划分只认 txt 清单。核心规则：vert.npy 是帧存在的标志，帧 ID 为「场景_frame_序号」；转换时标签统一 int64 写裸 .bin；展平阶段做第一道清洗——跳过统计键与未知任务、给问题补 <SEG>（单轮无条件、多轮看答案），产出的三个键即评估旋钮 task_level 的取值，为下一讲 create_data.py 的格式转换铺垫。
