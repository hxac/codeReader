本讲深入 `src/nvlink.cc`（配套 `nvlink.hpp`、`group.py` 的 `_require_nvlink`、`cli.py` 的 `doctor` 子命令），讲解 `UlyssesGroup(require_nvlink=True)` 背后的 NVLink 拓扑探测。核心结论：NVML 通过 `dlopen` 运行期加载（五个入口点），库缺失或太老时返回 `nullopt` 表示「说不出」，绝不让扩展加载失败；探测严格区分答案的三种状态——是、否、说不出。关键术语：BDF（PCI 总线号，连接 CUDA 设备号与 NVML 句柄的桥）、直连 GPU-GPU 链路与 NVSwitch 全互连补全（单节点单 fabric）、`NOT_SUPPORTED`/`INVALID_ARGUMENT` 属于设备已答完、每设备一份 `answered` 标志防止「没人问成功」被误读为链路缺失。核心语义是 fail-open：`check_nvlink` 对 `nullopt` 返回空串放行，只在矩阵确实回答且含 false 对时拒绝；Python 侧先 `all_gather` 保证全组答案一致、拒绝集体发生，两 rank 共享一 GPU 时跳过检查。`cudaDeviceCanAccessPeer` 不能替代此探测，因为它无法区分 NVLink 与 PCIe 上的 P2P。`fast-ulysses doctor` 打印整机矩阵（`y`/`N`/`.` 三态），「说不出」单独可见化且退出码 0；测试用 pynvml 第二意见钉死 fail-open 行为。
