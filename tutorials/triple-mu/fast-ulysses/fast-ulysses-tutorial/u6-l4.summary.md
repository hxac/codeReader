本讲划定 fast-ulysses 六个算子与 torch 追踪生态（FakeTensor、AOTAutograd、torch.compile、vmap）的集成边界。核心模块与结论：一、`all_to_all_4d` 及其 out 变体的 Meta 内核复用 `group->plan()` 做真形状传播，形状与 splits 校验只有一份纯主机实现，torchbind 的 group 经 FakeTensorMode 原样到达使 world_size 可用，out 变体只校验不推导；显式 Meta 注册胜过 CompositeExplicitAutograd 别名，避免 fake 张量坠入真实内核死于误导性报错。二、`empty_output`（集合分配，rendezvous 位置不能交给图）、`staged` 一对（work registry 残留、真实流句柄入参）、`timed`（返回 CUDA 事件测量）拒绝被 trace，贯穿原则是「返回形状不是半个答案，是错误答案」。三、vmap 无 batching rule 时静默回退为按 batch 元素的 for 循环，各 rank 发出不同次数的集合通信导致无报错挂起；库在 FuncTorchBatched 与遗留 Batched 两个 dispatch key 上注册只抛错的 boxed 内核，把挂起变成显式报错，闭包常量调用仍合法。整体契约：形状传播与 backward 可 trace，torch.compile 在 group 调用处 graph-break，async、分配、计时一律 eager。
