本讲聚焦 torch 算子的注册层：schema、dispatch key 与 torchbind 自定义类。核心结论：一次集合通信在 functional/out、sync/async、辅助三个维度上拆成六个 op，全部注册于唯一的 TORCH_LIBRARY 块；拆分的根源是带 Tensor(a!) 的可变 schema 无法注册 autograd 公式，out 变体以空返回 `-> ()` 满足 can_auto_functionalize。关键概念：CompositeExplicitAutograd 是连 Meta 一起覆盖的别名键，故各 op 显式挂 Meta 内核（真形状传播或抛错拒绝）；唯一 Autograd 内核经 dispatch_below_autograd 重入调度器；empty_output/timed 用 fallthrough 免建图；refuse_vmap 以 FuncTorchBatched+Batched 双键显式拒绝 vmap；UlyssesGroup 因要进 schema、进 autograd 的 saved_data、挂方法而必须是 torchbind 类，其 epoch_debug 与 staging_slots_debug 两个测试专用方法补充结果本身证明不了的观察维度；staged 内部 op 以两个整数传调用者流，pybind 侧只留进不了 schema 的函数。
