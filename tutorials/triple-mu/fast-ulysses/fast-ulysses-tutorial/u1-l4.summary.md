本讲建立 fast-ulysses 阅读地图：仓库按「依赖 torch 与否、依赖 CUDA 与否」分层——python/ 薄门面、bindings.cc torch 算子层、group.cc 有状态层、a2a_plan.cc 纯主机寻址层、transfer.cu 与 barrier.cu 设备层，全部源文件编入唯一扩展 _C。核心结论：a2a_plan.cc 刻意无 CUDA、无 torch、无通信库（新术语「翻译单元」），换来无 GPU 布局测试与 Meta 内核复用 plan() 两收益；torch 与 plan 唯一相遇点在 plan_bindings.cc 的 a2a_plan_debug 算子。引入 A2ADims/CopyOp/A2APlan 数据结构与 torchbind 自定义类（UlyssesGroup）概念。sync 调用链骨架：group.py 转发 → prepare（校验并取 plan 与窗口）→ 屏障 → 传输 → 屏障 → copy_out，校验必须先于第一个屏障。工具链：pre-commit（ruff 加钉版 clang-format）、pytest 以 multigpu 标记分层、setup.py→CMake→nvcc 构建。
