本讲剖析 fast-ulysses 的四层测试架构：host-only 布局测试（仅需构建好的 _C 扩展，用 numpy 重放 plan 验证寻址）、torchrun 包装的 8 个多卡 worker（需至少 2 卡、按世界规模参数化）、wheel 矩阵一致性测试（对账三处定义防漂移）、无 GPU 的 CI 编排。核心结论：验证应下放到最便宜的环境；CI 只能证明编译、链接、加载与布局正确，一切多卡行为由打 tag 前的 preflight_gpu.sh 人工门覆盖——CI 绿不等于全部绿。超时清理采用三段式：subprocess 超时只杀 torchrun 启动器，被孤儿化的自旋屏障 worker 会永久占用 GPU，故先 SIGTERM 委托 elastic agent 回收 worker，再以 killpg 兜底。关键术语：multigpu 标记、_NEEDS_PEERS、NVLINK BLIND（机器盲转 skip、测试盲必须红）、证明边界。
