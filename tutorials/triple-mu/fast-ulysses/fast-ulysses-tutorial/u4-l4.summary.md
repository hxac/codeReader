本讲解读 `lend_window()` 与 `LentPool`：`lend=True` 是 `all_to_all_4d_async` 专属的第四种零拷贝入口——调用者不传 `out`、不自备缓冲，group 按 dtype 出借窗口，peers 直写，结果即窗口密集前缀的视图，copy_out 消失。核心规则「槽由调用计数选择、引用计数只做检查」：idx = calls mod 4（kLentSlots=4），前 4 次边填充边集合分配、之后纯轮转；轮转落回仍被存活结果指向的槽时抛 RuntimeError，且先于第一个屏障——一切软化（等待、拷出、再分配）都是 rank 本地决策，故拒绝而非放慢。根因是 SPMD 铁律「共享量做选择、局部量做检查」：传输经所选窗口的 peer_ptrs、屏障经其 flag_ptrs，若以引用计数选槽，各 rank 会选中不同窗口、互写互等而永久挂起。使用边界：至多 4 个 lend 结果同时存活；与 `out=` 互斥；不可微；各 rank 必须在程序同一点丢弃结果，错位则挂起而非报错。
