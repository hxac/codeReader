本讲解析异步调用 `all_to_all_4d_async`：它与同步版共用「暂存→屏障→CE 传输→屏障→copy_out」流水线，区别只是整段搬到组级最高优先级 comm 流上，与 caller 流计算重叠；sync 刻意不进 comm 流（省两次事件跳），两流互不排序故窗口分 kSyncWindow/kAsyncWindow。核心机制：caller 流须在 Python 侧捕获，以 caller_stream_id、caller_device_index 两个整数传入 C++ 并经 Stream::unpack3 重建；输入在 caller 流拷入按 (shape,dtype) 池化的暂存缓冲，comm 流只读副本；输出做两次 record_stream 双流记账，完成事件由 register_stream_completion 绑到 storage。AsyncCollectiveTensor 语义：.wait() 与首个 aten op 仅在 caller 流插入 GPU 侧等待、主机不阻塞；view 不等待只再包装；带梯度输入被拒；丢弃结果留注册表残留；无 registry 构建退化为 CompletedHandle（正确但无重叠）。
