本讲拆解 src/bindings.cc 中一次调用的完整流水线：prepare 校验 → 开路屏障 → CE 传输 → 收尾屏障 → copy_out。核心结论：一切可能抛错的检查必须先于第一道屏障，否则单 rank 报错会将其余 rank 留在 GPU 自旋中挂起；校验链是跨语言两级结构——Python 侧先拒 out= 带梯度与 out=+lend 互斥，C++ 侧依次做 check_alive、prune_owned、设备与连续性、make_dims 及重叠检查。关键术语：Call 结构、out_is_window 布尔、window_of 按基址精确匹配 owned_ 表；重叠检查按字节区间判定、窗口一侧用自身 nbytes（保守容量），out 即窗口时豁免。三段式中开路屏障是「写者等读者」，挂在调用开头是因为零拷贝结果的读取时刻算子看不见；CE 写可见性是假设而非厂商保证。copy_out 是一条平坦 D2D 拷贝，仅当 out_is_window 为假时执行：默认路径与普通 out= 仍要拷出，zero-copy（empty_output 缓冲）与 lend 路径由 peers 直写、拷贝消失。
