本讲是 XLS 仓库的「认路」讲义，核心结论是：**`xls/` 子目录的物理划分几乎等于编译流水线的逻辑阶段**。主干六层为前端（`dslx` 解析 DSLX 源码、`contrib/xlscc` 转 C++）→ IR 枢纽（`ir`，定义 `Package` 容器与 `Op` 枚举）→ 优化（`passes` 跑各种 Pass）→ 调度（`scheduling` 把操作分配到流水线级，依赖 `estimators/delay_model` 提供延迟）→ 代码生成（`codegen` 经 Verilog AST「VAST」生成 Verilog）→ 执行与验证（`interpreter` 解释器、`jit` 即时编译、`simulation` 仿真、`solvers` SMT 形式化验证、`netlist` 网表分析）。引入的关键术语有：DSLX、XLS IR、优化 Pass、流水线调度、Verilog AST（VAST）、延迟模型、LEC、Fuzzer 四引擎交叉验证。`tools/` 是命令行入口收口（`opt_main`、`codegen_main` 等），`build_rules` 把流水线封装成 Bazel 宏，`common`、`data_structures` 为各阶段共用的横向支撑。`xls/BUILD` 的可见性分组区分公开 API 与内部实现。后续讲义均可据此把主题迅速定位到对应目录。
