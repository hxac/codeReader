本讲承接 u4-l1 的优化 Pass 框架，详解五个代表性 Pass：arith_simp（算术化简）、cse（公共子表达式消除）、dce（死代码消除）、const_fold（常量折叠）、inlining（内联）。它们的统一契约是 PassBase::Run 必须返回布尔 changed：true 表示本轮改动了图，框架据此驱动 fixedpoint 迭代、做不变式校验（changed==false 时节点数必须不变），并用 RedundancyGuard 跳过冗余运行。底层有两套机制贯穿全讲：一是「替换语义」——改图不原地改 Node，而用 ReplaceUsesWith 造等价表达式、旧节点留给 DCE 回收；二是 QueryEngine，本讲用的 StatelessQueryEngine 只看局部上下文，推断能力弱。arith_simp 在逆拓扑序上做模式匹配重写（自带 fixedpoint），把除/模/移位/比较换成 magic multiplication、slice+concat 等更省硬件的形状，签名带 opt_level。CSE 以 CseNode（op+规范化操作数+misc_data+type）定义等价类合并重复运算，副作用节点强制唯一；DCE 用工作表法自底向上删除无 user、无副作用（gate 除外）的死节点，是清道夫。const_fold 复用 InterpretNode 在编译期求值全常量运算并替换为字面量。inlining 是 Package 级 Pass，按调用图后序把 invoke 替换为被调函数体，有 kFull 全展开与 kLeafOnly 仅叶子两种深度，拍平调用边界以释放后续 Pass 的跨函数优化能力。标准管线在 optimization_pass_pipeline.txtpb 中以「变换一次、dce 清理一次」的方式密集穿插这些 Pass。本讲铺垫的查询引擎将在 u4-l3 引入更强的 bdd/forwarding 引擎。
