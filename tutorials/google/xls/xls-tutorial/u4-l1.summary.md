本讲介绍承载 XLS 所有优化的 Pass 框架，不涉及具体变换。核心是统一接口：每个 Pass 遵守 `Run()` 返回「是否改动」布尔值的契约，子类只实现 `RunInternal` 或作用域版 `RunOnFunctionBaseInternal`，而 bisect_limit 截断、冗余跳过、计时与不变式校验全由基类 `PassBase::Run` 包办，`FunctionBasePass` 等作用域基类再封装对 Function/Proc/Block 的遍历。两类复合原语负责编排：`CompoundPassBase` 顺序串接子 Pass、`FixedPointCompoundPassBase` 反复跑到不动点收敛，配合 `CapOptLevel`/`IfOptLevelAtLeast` 等 opt_level 包装器按优化等级开关。整条管线数据驱动：每个 Pass 经 `REGISTER_OPT_PASS` 宏注册进单例 `GetOptimizationRegistry()`，标准顺序写在 `optimization_pass_pipeline.txtpb` 的 `default_pipeline` 三大段（simplify-and-inline → post-inlining → prepare-for-scheduling），运行时由 `CompoundPassAdder` 递归拼装成内存 Pass 树，可经 `opt_main --list_passes` 查看。本讲为 u4-l2 的具体优化 Pass 与 u4-l3 的查询分析引擎奠定框架基础。
