本讲搭建 multi_buffer 的实验环境。测试本体挂在 `#[cfg(test)]` 门槛下的 multi_buffer_tests 模块；test-only 构造器 build_simple、build_from_buffer、build_multi、build_random 位于 `#[cfg(any(test, feature = "test-support"))]` impl 块，下游 crate（editor、vim 等）经 dev-dependencies 启用 test-support feature 复用，该 feature 会级联启用依赖 crate 的同名 feature。构造器均为通用装配入口的语法糖，产物结构与生产代码一致。`#[gpui::test]` 分同步 `&mut App`、异步 `&mut TestAppContext`、带 StdRng 三种形态，SEED、ITERATIONS 等环境变量控制种子与规模，失败可精确重放。随机化工具分层：randomly_edit 编辑逻辑文本、randomly_edit_excerpts 增删 excerpt（受 MAX_BUFFERS 约束）、randomly_mutate 总调度并每轮 check_invariants 自检。关键结论：excerpt 拼接不插入任何分隔符；build_multi 的数组下标即 PathKey 排序键；用 `cargo test -p multi_buffer <子串>` 过滤运行测试。
