本讲下钻 `Platform` trait 生命周期组：`run`/`quit`/`restart`/`activate`/`hide` 家族与回调注册。核心结论：`run(on_finish_launching)` 是「执行一次启动回调 + 阻塞进事件循环」，回调类型为 `FnOnce`（一次性），时机各平台不同——Linux/Windows 进循环前同步执行，macOS 等 AppKit `did_finish_launching` 通知，Web 等异步图形初始化后且 `run` 不阻塞（对应 `run_embedded`）。优雅退出链路为 `App::quit` → 平台 quit（Linux 用 calloop `LoopSignal::stop`，macOS 推迟 `terminate:` 防重入，Windows 用 `PostQuitMessage`）→ 循环退出后触发 `on_quit` → `App::shutdown` 限时 200ms 跑 `on_app_quit` 观察者；`QuitMode` 决定关最后一个窗口是否退出。Linux 侧回调集中于 `LinuxCommon` 的 `PlatformHandlers`，系统唤醒链路为 login1 `PrepareForSleep` → DBus → calloop channel → `handle_system_wake` → App 观察者。`on_app_lifecycle`/`on_memory_warning` 是移动端专属默认空实现，`AppLifecyclePhase` 四阶段映射 iOS/Android 回调，桌面永不触发。`restart` 靠外部 shell 进程轮询旧 PID 消失后重启。
