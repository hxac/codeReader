本讲从桌面平台转向浏览器，覆盖 gpui_platform 的 wasm 专属入口（web_init、application_with_web_backend、single_threaded_web）、gpui_web 的 WebPlatform、ConsoleLogger 与 FetchHttpClient，以及定义于 gpui_wgpu 的 WebBackendPreference。核心结论：wasm 启动序列为 web_init()（装 panic hook、把 log 宏接到浏览器控制台）→ application_with_web_backend（构造 WebPlatform 并注入 FetchHttpClient）→ run。application() 在 wasm 上分叉为 Auto 偏好，single_threaded_web 仅禁多线程，current_platform 分支则不注入 http client。WebPlatform 为两段式构造：构造期只搭骨架，图形初始化推迟到 run 内 spawn_local 完成，回调晚于 run 返回，由此产生 open_window 的 GraphicsInitializationPending 等生命周期闸门。Auto 偏好先试 WebGPU、失败换新画布再试 WebGL2，显式 WebGpu/WebGl 只试一种即报错。浏览器三约束（网络仅走 Fetch、浏览器 API 仅限主线程、UA 头不可伪造）决定入口注入 FetchHttpClient、经 dispatcher 把请求投回主线程执行，替换默认只会报错的 NullHttpClient。
