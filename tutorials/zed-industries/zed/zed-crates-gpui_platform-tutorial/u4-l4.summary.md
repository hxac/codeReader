本讲精读 macOS 与 Windows 的 PlatformDispatcher 实现。MacDispatcher 是无状态单元结构体，把调度完全外包给 GCD：主线程任务进 main queue（严格 FIFO、priority 被忽略，提交即唤醒主 run loop），后台进全局队列，延迟用 dispatch_after。WindowsDispatcher 自持状态：任务进三条 VecDeque 优先级队列，按 60/30/10 加权抽签执行；唤醒靠向消息专用窗口 PostMessageW 私有消息并附验证号防伪造；wake_posted 标志实现唤醒合并，「先清标志再查队列」防丢失唤醒；run_foreground_task 以 10ms 预算切片并泵 paint/input 消息保响应，后台与延迟交给系统线程池。关键术语：trampoline（闭包经裸指针过 C 回调还原）、唤醒合并、丢失唤醒、加权抽签、消息专用窗口、验证号。核心结论：延迟任务三平台都只在后台线程「点火」，continuation 在 awaiter 所属执行器上继续；四平台共享寄生宿主事件循环、容器与信号分离、唤醒即再投递、!Send future 主线程专属、RealtimeAudio 拒绝入队、profiler 对称插桩的六步共性，为 u4-l5 的 WebDispatcher 与 u4-l6 的 profiler 铺垫。
