本讲精读 gpui_linux 的 LinuxDispatcher。核心结论：它不拥有主事件循环，主循环归 Wayland/X11/headless 客户端所有，调度器只持有 main_sender（优先级队列 + ping）作为唤醒引线，自建线程仅 Worker 池与一条 Timer 线程。引入的关键概念：calloop 事件循环库的 ping（eventfd 唤醒）、channel、timer、insert_idle、LoopSignal 原语；PriorityQueueCalloopSender/Receiver 适配器把无 fd 的同步优先级队列实现为 EventSource，入队后 ping、排空有产出再 ping 防漏。三条投递路径：dispatch 落 Worker 池；dispatch_on_main_thread 经 ping 唤醒主循环，X11/Wayland 用 insert_idle 保证输入事件优先，headless 直跑；dispatch_after 经 TimerAfter 信封进 Timer 线程插入一次性 timer 源（TimeoutAction::Drop）。失败时后台投递 panic、主线程与延迟投递 mem::forget 以规避 ！Send UB；优先级为 60/30/10 加权抽签；quit 由 LoopSignal.stop() 实现。
