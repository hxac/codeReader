本讲覆盖 zed crate 构建与运行的三个模块。一是 build.rs：在编译包本体前运行，以 cargo:rustc-env 注入 ZED_COMMIT_SHA 与 TARGET，以 rustc-link-arg 追加平台链接参数（Linux rpath、macOS 弱链接框架与 -ObjC、Windows 大栈），并在 Linux/FreeBSD 按 RELEASE_CHANNEL 环境变量挑选图标、缩放后写入 OUT_DIR。二是 Cargo.toml 分层配置：平台条件依赖与 build-dependencies 表达编译期差异；四套 bundle 元数据配合桌面文件模板、entitlements 承载打包差异与 zed:// scheme 注册。三是本地运行：仓库根 cargo run 即调试构建，由 default-members 与 default-run 两级兜底；性能调试用 release-fast profile。核心结论：「构建脚本写 OUT_DIR、源码以 include_bytes!/option_env! 消费」是文件名级隐式契约，Linux 窗口图标即走此链路；错误处理分级——图标解码失败即中断构建，conpty 下载等外围失败仅警告；macOS 零平台专属依赖，差异全靠链接参数与打包元数据表达。另须区分 RELEASE_CHANNEL 文件（声明发布通道）与 CI 同名环境变量（挑选图标），本地不设置时默认 dev 通道。
