本讲覆盖 `main.rs` 中 `main()` 至 `app.run()` 之前的启动前置阶段。核心结论：zed 是多模式二进制，经 clap 解析 `Args` 可切换为 askpass 助手、崩溃处理服务器、ETW 追踪器及 printenv、dump-all-actions、system-specs 诊断模式并提前 return；沙箱启动器须先于参数解析，`--user-data-dir` 须先于 `init_paths()`。`init_paths()` 用 `create_dir_all` 创建 8 个目录，失败按 `io::ErrorKind` 聚类，由 `files_not_created_on_launch` 以最小 GPUI 窗口兜底提示。zlog 初始化按 `stdout_is_a_pty()` 分流 stdout 与日志文件（受 `ZED_FORCE_CLI_MODE` 否决，读后即从环境移除），文件打开失败降级回 stdout。单实例检查晚于基础设施就绪、早于窗口创建，`ZED_STATELESS` 与 Dev 通道跳过；Linux（open_listener.rs）抢占按通道命名的 unix datagram socket 兼作 CLI 打开请求信箱，macOS 查进程列表，Windows 用命名对象。
