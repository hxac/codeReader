本讲确立 crates/zed 的定位：它是 zed 仓库大 workspace 的总装型二进制 crate，自身几乎无业务逻辑，以 160 多个依赖把各功能 crate 装配成可运行编辑器；workspace 根的 default-members 与包内 default-run 使仓库根 cargo run 默认构建并启动主程序。它声明两个二进制目标：zed 无条件构建，zed_visual_test_runner 需 visual-tests feature。四个 feature 分两类：test-support 与 visual-tests 属传递型，为 gpui、workspace、project、editor 等依赖递测试开关，并以 dep: 前缀激活 image、tempfile 等 optional 依赖；tracy 与 track-project-leak 属剖析诊断选配。发布通道体系三件套：RELEASE_CHANNEL 文件（当前为 dev）、release_channel crate 编译期 include_str! 嵌入并解析为 ReleaseChannel 枚举（debug 构建可被 ZED_RELEASE_CHANNEL 环境变量覆盖）、四段 bundle 打包元数据；Dev 通道跳过单实例检查与更新轮询，四通道靠不同 identifier 实现同机共存。
