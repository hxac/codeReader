本讲分析 `derive_action.rs` 的属性解析阶段（L119 之前）：派生宏遍历 `input.attrs`，只认领 `action` 与 `doc` 两种属性，其余（如 serde）跳过。核心 API 是 `attr.parse_nested_meta`：它对 `Meta::List` 形态的 `#[action(...)]` 按逗号逐项回调，`meta.path` 给出参数名，等号与值需在闭包内手动 `parse`。六个参数各有类型与「重复指定即报错」查重：`name`/`deprecated` 为字符串字面量、`namespace` 为裸标识符、`deprecated_aliases` 为方括号字符串列表、`no_json`/`no_register` 为无值标志；未识别参数走兜底分支报错（文案漏列了 `name`）。`///` 文档注释本质是 `#[doc = "..."]`（Meta::NameValue），逐行 trim 后以换行拼接，最终整体 trim 成为 `documentation()` 返回值。名称规则：`name` 缺省回退结构体名，含 `::` 即 panic（防止伪造命名空间），有 namespace 时拼为 `namespace::Name`，编译期固化为 `&'static str` 常量。解析错误以 `panic!` 收口，由 rustc 转成编译错误。解析产出七个状态变量（含 `full_name`、`is_unit_struct` 判定），是下一讲 u2-l2 拆解 `impl gpui::Action` 生成代码的输入。
