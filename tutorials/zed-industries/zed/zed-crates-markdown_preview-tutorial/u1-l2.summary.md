本讲覆盖 markdown_preview 入口文件、markdown_preview_view::register、zed_actions 与默认键位表。核心结论：init(cx) 只做两件事——用 workspace::register_serializable_item 全局注册一次可序列化条目（预览标签页会话恢复的入口），再用 cx.observe_new(...).detach() 让每个新 Workspace 都执行 MarkdownPreviewView::register，挂载三个「打开预览」动作。关键术语：actions! 宏为每个名字生成实现 Action 的单元结构体，动作全名 = 命名空间 + 结构体名（如 markdown::OpenPreview），同名注册会在创建 App 时 panic，deprecated_aliases 保证动作改名后旧键位仍可解析；OpenPreview/OpenPreviewToTheSide 定义于 zed_actions 并被本 crate 重导出，8 个滚动与关闭动作则定义在本 crate。动作处理分两级：打开动作经 Workspace::register_action 挂在 Workspace 根元素（窗口级），滚动/关闭经 render 中的 .on_action 挂在预览 div（视图级）；键位表按 (context, key) → 动作名匹配，预览以 .key_context("MarkdownPreview") 声明上下文，cmd-shift-v 因此在编辑器里打开、预览里关闭，一键双义；OpenFollowingPreview 无默认键位。
