本讲横跨 markdown_preview、workspace、language、project_panel，讲清从按键到预览标签页出现的完整链路：键位在 Editor && extension == md 上下文命中后，动作分发到 Workspace 根元素上由 register 注册的三个回调——OpenPreview 同面板抢焦点、OpenPreviewToTheSide 经 adjacent_pane_of 开到右侧不抢焦点、OpenFollowingPreview 面板内 Follow 单例。回调先经 resolve_active_item_as_markdown_editor（act_as::<Editor> 加 is_markdown_file）把关，再由 open_preview_in_pane / open_preview_to_the_side_of_pane 显式传入 (editor, pane)，落到分发器 activate_or_add_preview：有则 activate_item 复用，无则 create_markdown_view 后 pane.add_item。核心结论：复用判定 find_existing_independent_preview_item_idx 按 buffer 实体（as_singleton、is_previewing）而非 editor 实体匹配，且只复用 Default 预览；绑定则始终指向触发编辑器。Markdown 判定有两条路径：is_markdown_file 按 buffer 语言名，is_markdown_path 按路径查 LanguageRegistry；项目面板入口 open_for_project_path 会异步打开 buffer、用 Editor::for_buffer 造源编辑器，汇入与动作入口相同的尾段。
