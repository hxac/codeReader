本讲梳理 gpui 的 src/ 目录地图。核心结论：gpui.rs 是 crate 注册表，以约 40 条 mod 声明挂载全部顶层文件与 7 个目录模块，未声明者不参与编译；再经「目录汇总模块 → crate 根」两级 pub use 重导出拼出扁平命名空间，并在根上定义 AppContext、VisualContext 等最高层 trait。由此引出关键技能「反查定义文件」：gpui::XXX 的定义位置与名字表面无关，需用 grep 定位（如 KeyBinding 实际在 keymap/binding.rs）。五大子目录分工：app/ 管实体状态与所有权，elements/ 为内置元素库，window/ 管绘制、焦点与动作派发，platform/ 定义 Platform trait（实现在外部后端 crate），text_system/ 管文本与字体；keymap/、profiler/ 为小目录，且目录名不等于能力边界。条件编译集中于边界层：cfg(doc) 文档模块、test-support 测试设施、target_os 平台门控，核心 UI 逻辑几乎无门控；App 持有 Rc<dyn Platform>、Window 持有 TaffyLayoutEngine 是两条所有权事实。
