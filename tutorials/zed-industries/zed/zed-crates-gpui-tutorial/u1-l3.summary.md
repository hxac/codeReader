本讲是 gpui 的目录结构地图课，不读实现、只建导航图。核心结论：src/gpui.rs 是整个 crate 的注册表，用约 40 条 mod 声明挂载全部顶层文件与 7 个目录模块，未在其中声明的文件不参与编译；AppContext、VisualContext 等最高层 trait 也定义于 crate 根。五大骨架目录：app/（应用状态与实体所有权）、elements/（内置元素库）、window/（单窗口运行时与绘制管线）、platform/（操作系统接口侧）、text_system/（文本与字体），另有 keymap/、profiler/ 两个小目录。扁平 API 由「两级 pub use 重导出电梯」（定义文件→目录汇总模块→crate 根）拼成，由此引出关键技能「反查定义文件」：gpui::XXX 的真实定义位置与名字表面无关，须用 grep 定位。条件编译集中在边界层——target_os 门控平台代码、any(test, feature="test-support") 放行测试设施、cfg(doc) 收纳文档专用模块，核心 UI 逻辑几乎无门控。所有权事实上 app 持有 Rc<dyn Platform>，window 持有布局引擎 TaffyLayoutEngine，element 与 window 互相引用。
