本讲拆解 GPUI 应用生命周期。核心结论：Application 是 Rc<AppCell> 的配置期包装，用 with_assets、with_quit_mode、with_restart_arguments 等钩子在启动前完成配置，run 把控制权交给平台事件循环；App 是根上下文与全局状态容器（实体、窗口、键位表、观察者、执行器）；AppCell 即 RefCell<App>，配合单前台线程做运行时独占借用检查，重入（如在 run 回调里调 AsyncApp::update）会 panic，最外层更新结束时冲刷效果队列（flush_effects 消化 Notify/Emit/Defer）。退出是一条链：cx.quit → platform.quit → 平台回调 on_quit → App::shutdown，on_app_quit 收尾 future 仅 200ms 预算；QuitMode 决定最后一个窗口关闭是否自动退出。重启先回调 on_app_restart，再把 restart_path 与 restart_arguments（Vec<OsString>，原样转发非 UTF-8 argv）交给 Platform::restart 拉起新进程。run 在桌面平台阻塞至退出，run_embedded 返回 ApplicationHandle 供 wasm 等嵌入宿主反复进入。钩子均返回 Subscription，drop 即注销。关键术语：AppCell、AsyncApp、QuitMode、restart_arguments、flush_effects。
