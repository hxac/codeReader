本讲是 gpui 的性能剖析与调试专题，模块含 profiler.rs、app/bench_context.rs、debug_overlay.rs、inspector.rs 及 window.rs 接线。核心结论：`profiler` feature 下分三层采集——每线程任务计时（100µs 准入门槛的 top-5 统计）、`WindowProfiler` 每窗口帧直方图（draw 耗时、动画呈现间隔、输入延迟）、trace 开启后的逐帧事件环形缓冲；统计与明细分层，热路径近零开销，各埋点同时向 journal 双写（u7-l6 主题）。关键术语：TaskTiming、FrameTiming、PresentTiming、FrameTimingCollector、set_trace_enabled、BenchReport、DebugBelow、InspectorElementId、pick_depth。基准方面，`#[gpui::bench]` 在 Criterion 上接入真实 GPUI 运行环境，`BenchAppContext` 提供 bench_iter/bench_task/bench_renderer 三种入口，`BenchReport` 按帧预算换算丢帧数。调试方面：debug()/debug_below() 经 `Style::paint` 画红框并用临时 `DebugBelow` 全局限定子树，hover 与修饰键点击可查元素 ID 及构造源码位置；`DebugFrameOverlay` 以自带点阵字模直接向 Scene 插 quad，避免「观察帧」本身触发新帧；`Inspector` 机制在 gpui、面板 UI 与各类型检查状态由宿主应用注册。上述工具多数仅在 debug_assertions 或对应 feature 下编译。
