本讲精读 view.rs 与 element.rs 的视图层机制，核心结论：视图即实现了 Render 的实体，GPUI 没有独立的 View 类，实体知识对视图全部适用。引入的关键术语：Render（把状态映射为元素树，签名为 &mut self 加 Context）；View trait（统一有状态视图与无身份的 RenderOnce 组件，entity_id 即身份）；ViewElement（桥接两个世界的包装元素，以实体 id 作为元素 id，为子树提供独立的元素状态命名空间，view 字段每帧被消费）；AnyView（AnyEntity 加单个 render 函数指针构成的类型擦除句柄，窗口根视图即此类型）；AnyElement（类型擦除元素盒）。心智模型：元素树是立即模式、每帧从根重建并丢弃回调；应用状态是保留模式、实体跨帧存活。完整追踪了 notify 链路：cx.notify() 经 App::notify 把正在显示该实体的窗口标脏并调度下一帧，同时入队 Effect::Notify 通知观察者；下一帧脏视图连同全部祖先进入 dirty_views，帧收尾清空脏集合并重建「窗口↔被访问实体」倒排表。渲染缓存为显式 opt-in：entity.cached(style) 启用后，prepaint 按 bounds、content_mask、text_style 不变且未脏且非 refresh 判定，命中则重放上一帧录制的区间、跳过 render；未缓存视图随窗口整树重建。
