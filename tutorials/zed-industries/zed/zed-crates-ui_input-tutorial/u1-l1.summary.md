本讲概览 `ui_input` crate：它为表单类场景（搜索框、配置字段等）提供 UI 组件，全 crate 仅库根 `ui_input.rs` 与 `input_field.rs` 两个源文件，依赖只有 `gpui`、`ui`、`component` 三个。核心结论：组件在逻辑上依赖庞大的 `editor`，而 `ui` 被全仓库引用、不能依赖 `editor`（会形成循环依赖并拖垮编译），因此这类组件必须另立 crate，并以「依赖反转」解题——`ui_input` 自定义 `ErasedEditor` trait 做类型擦除，`editor` 在 `init` 时把构造函数注入 `OnceLock` 全局工厂 `ERASED_EDITOR_FACTORY`，`InputField` 运行期取用 `Arc<dyn ErasedEditor>`。引入的关键术语：`ErasedEditor` 共 13 个方法（文本操作 9、焦点 1、事件订阅 1、渲染与类型还原 2）、事件枚举 `ErasedEditorEvent` 仅 `BufferEdited` 与 `Blurred`、`InputField` 的「外壳＋内芯」结构与委托方法、`as_any` 类型还原逃生舱；工厂未初始化时 `InputField::new` 会 panic，故任何环境（含测试）须先执行 `editor::init`。
