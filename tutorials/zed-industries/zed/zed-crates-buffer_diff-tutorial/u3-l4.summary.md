本讲聚焦 buffer_diff.rs 中 `BufferDiff` 实体的状态机与异步更新，核心结论：实体只持状态不算 diff。它有基准 buffer（只读 `language::Buffer`，为锚点与语言信息）、可选 diff 快照、secondary diff 等字段；三种构造函数 `new`（先建后灌）、`new_with_base_text_buffer`（外部基准）、`new_unchanged`（零差异快路径）覆盖不同初始化场景。`update_diff` 只算不写，返回 `Task<BufferDiffUpdate>` 交调用方提交，`unchanged_hunks` 快路径以「存在标志＋基准版本＋buffer 版本」三相等直接复用旧 hunk 树。`set_snapshot` 系列是唯一写入口，继承 pending_hunks，先发 `BaseTextChanged`（仅基准变化）再发 `DiffChanged`（每次必发）；`snapshot()` 对未计算状态返回 `base_text_exists: false` 的空兜底。`set_base_text` 为四步异步流程（基准自 diff → 生成未来快照 → 后台计算 → `fast_forward` 与提交同事务），两个版本检查丢弃点防并发交叠，drop Task 即取消。测试用 `recalculate_diff_sync` 同步重算。下一讲将深入 `compare_hunks` 与 `DiffChanged` 的精确范围。
