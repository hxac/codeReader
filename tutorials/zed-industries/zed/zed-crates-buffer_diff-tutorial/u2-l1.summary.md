本讲剖析 buffer_diff 中「一块差异」的数据描述。公开的 `DiffHunk` 含六字段：`range`（Point 行区间）、`buffer_range`（Anchor 锚点区间）、`diff_base_byte_range`（base 字节区间，注意是字节而非行号）、`secondary_status` 与 buffer/base 两侧词级差异字段；SumTree 内部实际存不含 `range` 与 `secondary_status` 的 `InternalDiffHunk`，查询 API 时临时组装成公开形态。核心结论一：`status()` 完全由两个区间的空与非空推导——buffer 侧空为 Deleted、base 侧空为 Added、否则 Modified。核心结论二：`buffer_range` 用锚点而非 Point，因为 diff 异步计算、行号会过期，锚点提供跨编辑的稳定身份，且空锚点区间恒空，保证 Deleted 判定持久成立；行号仅在查询时对最新快照解析。`is_created_file()` 以 base 区间为 `0..0` 且锚点取 min/max 哨兵识别整文件新增，此类 hunk 由 `compute_hunks` 的无 base 文本分支手工构造，不经 diff 算法；「空 buffer 即 `"\n"`」是另一手工特例，产出整文件 Deleted。测试惯用 `assert_hunks` 四元组断言，现有测试缺纯删除场景。下一讲进入 SumTree 存储层（Item、Summary、SeekTarget）。
