本讲解决 hunk 坐标与调用方坐标不一致的问题：同一时刻存在 base text、diff 计算时的 original buffer 快照与当前 buffer 三份文本，hunk 只描述前两者的差异，而调用方给的坐标属于当前 buffer。核心工具是 text crate 的 Patch 代数：Edit 含 old/new 区间，invert 交换二者得反向 patch，compose 首尾复合，edit_for_old_position 按三规则映射点——编辑前恒等、编辑内折叠到整条新区间、编辑后按累计长度差平移。由此得出双向公式：buffer→base 为 E⁻¹∘H（E 为 edits_since 增量编辑，H 为 hunk 编辑），base→buffer 为 H↔∘E 且 E 不取反。patch_for_buffer_range 借 SumTree 游标定位与 prefix_edit（把范围之前 hunk 的累计位移折叠成一条编辑）做范围裁剪，只保证查询范围内准确，并以「宁多勿漏」的 min/max 校正端点；patch_for_base_text_range 结构对称，另有游标重定位与双出口循环。其上封装 buffer↔base 的 range 与 point 四个点级 API；naive 全量实现仅存于测试，作为随机对照测试的 oracle。
