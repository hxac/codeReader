本讲聚焦 `compute_hunks`——buffer_diff 中唯一真正执行 diff 计算的私有纯函数，运行在 `update_diff` 的后台线程中，输入可选 base 文本、buffer 快照与 diff 选项，输出 `SumTree<InternalDiffHunk>`。核心内容是 imara-diff 的三步 API：`InternedInput::new(lines(base), lines(buffer))` 装载（token 含行尾符，保障偏移表可累加重建）、`Diff::compute(Algorithm::Histogram, ...)` 计算、`hunks()` 取 `before`（base 行号）/`after`（buffer 行号）对；行号到字节区间与锚点的换算则完全由本 crate 的 HunkSink 承担（下讲主题）。关键概念「最小差异的歧义摆放」：重复内容使最小编辑脚本不唯一，`postprocess_lines`（git slider/indent 启发式）将其规范化为唯一锚定——这不是美化，而是多基准 diff（HEAD vs index）对齐 hunk 的正确性前提，否则会误标 staged 状态甚至损坏 git index（issue #60424）。另有两条绕过算法的特例：空 buffer（`"\n"`）产出整文件 Deleted hunk（base 区间不含末尾换行）；base 缺失（None，对应未跟踪文件）产出整文件 Added hunk（`is_created_file()` 为真）。base 文本计算前统一 LF 归一化；「尚未计算」与「无 base」是两种不同状态。
