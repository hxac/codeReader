本讲以 gpui_web 的 window.rs 帧循环与绘制为最小模块，追踪完整链路：rAF 回调 → GPUI request_frame 回调 → Window::draw/present → WebWindow::draw → WgpuRenderer::draw → frame.present()。核心结论：帧循环是需求驱动的——cx.notify() → set_dirty → frame_waker → wake_frame_loop（防重入守卫，保证同一时刻最多一个挂起 rAF）→ rAF，空闲窗口零帧耗电；frame_waker 以 Rc::downgrade 弱引用断开引用环防泄漏；rAF 闭包体首句置空 raf_id，防止帧执行期间的唤醒被守卫吞掉而丢帧。关键术语：_raf_closure（Rust 侧保活）与 raf_function（JS 侧排程句柄）的双重持有、pending_physical_size（ResizeObserver 投递、延迟到 draw() 开头应用，以合并中间尺寸、避免清空画布闪白、保证 surface 先重配置）、completed_frame（web 上空操作）、sprite_atlas/gpu_specs/is_subpixel_rendering_supported（渲染器能力门面）。
