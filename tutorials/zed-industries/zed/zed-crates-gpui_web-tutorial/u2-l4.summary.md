本讲剖析 window.rs 的 resize 链路，分四个模块：①测量双路径——优先读 ResizeObserver 的 devicePixelContentBoxSize（物理像素、无舍入误差），Safari 回退用 contentRect 的 CSS 像素乘 DPR 估算；②回调去重——以 last_physical_size 物理元组与 notify_scale 一次性标志判定，零尺寸画布（display:none）仍写状态并派发回调但不触碰渲染 surface；③物理尺寸经 max_texture_dimension 钳制后须重算逻辑尺寸，暂存 pending_physical_size、延迟到 draw() 才写 canvas 缓冲区；④DPR 变化靠轮换的等值 matchMedia 媒体查询捕获。关键术语：CSS 逻辑像素、物理像素、DPR（GPUI 侧即 scale_factor）、canvas 两套尺寸、MqlHandle 自引用环。核心结论：GPUI 的 resize 回调仅作信号，bounds_changed 经 getter 回拉权威状态，故平台须先写状态、后派发；应用层可用 observe_window_bounds 订阅尺寸变化。
