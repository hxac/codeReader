本讲剖析 GPUI 的平台抽象契约。核心结论：`Platform` trait 是 gpui 定义的「操作系统能力清单」，框架核心只持有 `Rc<dyn Platform>` 做动态分发，新增平台无需改框架；契约由中立的 gpui 持有以避免循环依赖。crate 分工：gpui_web 实现契约、gpui_wgpu 提供渲染与文本设施、gpui_platform 是按 cfg 编译目标装配实现的门面。装配链路为 `application_with_web_backend` → `WebPlatform::new_with_backend` → `Application::with_platform`，并用 `with_http_client` 注入 Fetch 客户端替换默认的 NullHttpClient。本讲引入的关键概念：trait 默认方法；`impl Platform for WebPlatform` 的 49 个方法四分类（真实实现、静默空实现、礼貌性成功、显式错误），判据是「沉默是否伤害用户」；窗口生命周期四态状态机 Available/Open/Closed/Unavailable，仅支持单顶层窗口；`wgpu_context` 等图形字段因 WebGPU 异步初始化延迟到 `run()` 回调填充，故开窗必须写在 run 回调内（否则报 GraphicsInitializationPending）。
