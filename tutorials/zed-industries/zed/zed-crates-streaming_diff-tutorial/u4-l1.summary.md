本讲剖析 `LineDiff` 的状态模型：它把 `StreamingDiff` 的字符级操作流折叠为行级视图，但不存储操作列表，只维护最小状态，可随时用纯函数 `line_operations(&self)` 重建输出。七个字段分四组：双游标 `old_end` / `new_end` 是旧、新两套坐标系里的消费进度条，满足守恒律 offset(old_end) = 已 Keep + 已 Delete；行号集合 `deleted_rows` / `inserted_rows` 分属旧、新坐标系、不可直接比较，「改写一行」即旧行号进删除集且新行号进插入集，`BTreeSet` 的有序与去重是后续归并重建的前提；缓冲 `buffered_insert` / `buffered_delete` 暂存行归属未定的操作；标志 `inserted_newline_at_end` 记录旧文本末尾长出新行。游标推进必须走 offset_to_point(point_to_offset(p) + bytes) 往返，因为 column 是行内偏移、跨行加法非法；rope 换算带越界钳制。`is_line_start`（column==0）与 `is_line_end`（column==line_len(row)）把位置分成行首 / 行中 / 行尾三类并决定结算分支；由于 line_len 含换行且换行后位置规范化为下一行行首，规范坐标下 is_line_end 仅在文本末尾为真。状态如何随 Insert / Delete / Keep 转移（flush 与 trim 状态机）留待下一讲。
