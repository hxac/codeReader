本讲绘制 picker crate 的模块地图。库根是 src/picker.rs（由 Cargo.toml 的 [lib] path 指定，替代 lib.rs），空 feature test-support 配合 cfg 门控向下游 crate 的测试开放专用 API。crate 采用门面模式：子模块大多私有，对外类型统一经库根 pub use 再导出（如 PreviewLayout、PreviewBackend、PickerAction 及转发的 ErasedEditor、HighlightedText），仅 popover_menu、parts、highlighted_match_with_paths 三个为 pub mod。依赖分层清晰：叶子层（head、preview、parts 等）→ 几何层 shape（RelativeWidth/RelativeHeight 相对尺寸、Shape、SizeBounds）→ 持久层 persistence（db 键值 pickers_v2，按预览布局存视口分数）→ 库根总装（Picker<D> 与 PickerDelegate）→ 扩展层（footer、render 及其嵌套的 window_controls、popover_menu）。核心结论：Render 实现拆在 render.rs；可见性沿路径逐级收紧；同 crate 内模块互相引用合法。
