本讲确立 editor crate 的定位：它是 Zed 的编辑器底座，既是完整代码编辑器，也以单行、多行、固定高度三种形态充当通用文本输入框，被 53 个 crate 依赖，可独立编译。精读两个最小模块：Cargo.toml 的 [lib] 段（库根为 src/editor.rs，遵循描述性命名的约定）与唯一 feature test-support；editor.rs 顶部的模块声明与 pub use 导出面。核心结论：feature 会层层开启依赖方的测试开关并拉起 tree-sitter 等测试专用可选依赖；私有模块经选择性导出，multi_buffer 等类型被原样转发，editor 由此充当整个编辑器技术栈的门面。引入的关键术语：库根、feature、模块可见性（pub mod、mod、#[cfg(test)] 及 test-support 门控的 test 模块）、导出面、五类模块地图（数据与坐标、渲染、语言智能、git 与 diff、测试）。官方文档点名 element（全部渲染）与 display_map（文本切块与坐标映射）为两大子模块，Editor 结构体的逐字段拆解留待下一单元。
