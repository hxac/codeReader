本讲介绍 sum_tree 的谓词剪枝遍历：`SumTree::filter` 返回 `FilterCursor`，即普通 `Cursor` 加 `FnMut(&Summary) -> bool` 谓词闭包的薄包装；`next`/`prev` 分别转发 `search_forward`/`search_backward`，没有 `seek`，起点只有两端。核心概念是谓词作用于子树 summary 而非单个 item，且须满足可靠性契约：返回 false 必须保证子树内无任何匹配，返回 true 允许误报（如 `contains_even` 用逻辑或折叠）。前向剪枝跳过一棵子树只做一次 `add_summary`，并同步更新 `entry.position` 与 `self.position`，因此 `start()` 恒为元素在原树中的前缀位置；反向版本每步从父栈帧重算前缀，fresh 游标从虚拟末端槽位出发，越过头部后栈空、start 归零、next 可恢复。复杂度上 FilterCursor 为 O(B(h+m)) 次 summary 判定，优于 `iter().filter()` 的 Θ(n)，匹配越稀疏优势越大；rope 用 `search_forward` 跳过不含换行的 chunk、buffer_diff 用 `FilterCursor` 反向枚举 hunk 是两个生产范本。
