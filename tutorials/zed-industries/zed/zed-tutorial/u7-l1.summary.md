本讲拆解 Zed 设置系统的三层分工：settings_content 定义 JSON 形态（字段全为 Option，None 表示“该层未设、继承上层”）；settings_macros 提供 MergeFrom（Option 逐字段覆盖、枚举整体替换）等宏；settings 的 SettingsStore 是唯一权威 Global。新增设置项用 #[derive(RegisterSetting)] 经 inventory 自注册，并实现 Settings trait 的 from_settings；默认值必须写入 default.json，缺失即启动 panic。分层合并顺序为默认←扩展←管理员全局←用户（含渠道/OS/profile 覆盖）←服务器，项目本地 .zed/settings.json 按目录栈叠加成局部值，读取时取最深包含路径的一份。热更新链：watch_config_file 去抖后重读全文 → 解析前先迁移 → recompute_values 全量重算 → refresh_windows，凭渲染期同步读值即时生效。migrator 对原始 JSON 文本执行按日期排序、只增不改、必须幂等的迁移链（TreeSitter 与 Json 两型），自动覆盖渠道/平台/profile 作用域，Succeeded 表示内存已迁移而磁盘待用户确认写回。案例 git_gutter_width 由 Option<f32> 演进为 GitGutterWidth 枚举（Default 随行高缩放、Custom 固定像素），配套迁移把旧数值改写为 {"custom": n}。
