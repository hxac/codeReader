本讲以 crates/zed 的 main.rs 与 zed.rs 为主线，讲清 Zed 从 main() 到首个窗口出现的完整启动流程。main() 前段是顺序剧本：沙箱检查先于 clap 解析 Args，--askpass、--system-specs 等旁路模式靠提前 return 在开窗前退出；init_paths 创建运行时目录，失败会弹错误窗口而非静默退出。随后 current_platform 按编译目标选定 Platform 实现并构建应用壳 Application，mimalloc 全局分配器先于 main 生效，本地 Dev 通道构建跳过单实例检查。app.run 闭包是手工编排的「注册大会」：settings::init、theme_settings::init、extension_host::init、AppSession 与 AppState 依次全局化，书写顺序即依赖拓扑序。首个窗口由 restore_or_create_workspace 三分支决定：OpenListener 门铃请求优先，否则按设置恢复上次工作区，全新安装（无 FIRST_OPEN 键）显示欢迎页，兜底新建空工作区。GPUI 的 App、Entity 等机制本讲仅作黑盒，留待第二单元展开。
