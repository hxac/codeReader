Zed 的 workspace 成员名单手工维护，分三块：产品 crates 243 个、扩展 4 个、工具 3 个；default-members 仅 zed，裸 cargo 命令只构建编辑器主程序；新增 crate 须同时登记进名单与共享依赖表 [workspace.dependencies]。命名规律：_ui 为界面层、_store 为状态仓储、gpui* 为 UI 框架、厂商名为 LLM 接入。依赖关系是有向无环图（DAG）、禁止循环：内部依赖少而扇入大者居底层（gpui、rope），zed 以 140 余个内部依赖在顶层组装产品；collab 为平行服务端二进制，复用 rpc/text 而不依赖 editor；读源码宜自底向上，判层须区分 [dependencies] 与 [dev-dependencies]，探索用 cargo tree 与 cargo metadata。术语：Project 由多个 Worktree 组成，Buffer 是文件的内存表示。
