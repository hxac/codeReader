本讲全景梳理 ui_macros 的两个宏及其消费者。函数式宏 derive_dynamic_spacing! 全仓库仅一个调用点（ui crate 的 spacing.rs），把 14 行间距清单在编译期替换为 DynamicSpacing 枚举：三元组直接指定三档密度像素值，单值按 max(n-4,0)|n|n+4 公式推导，变体名取 Default 档像素值补零为 BaseXX，运行时经 .rems(cx)/.px(cx) 查询 theme 的 UiDensity 三档设置。派生宏 RegisterComponent 有 60 余处调用点、横跨 11 个 crate，每处生成“编译期 trait 断言＋类型名拼接的注册函数＋inventory 提交”三段代码，经链接期分布式收集，运行时由 component::init() 写入全局注册表，供 component_preview 浏览。核心结论：必须区分 Cargo 依赖箭头与宏展开箭头——ui_macros 仅依赖 syn 和 quote，生成代码中的 theme、component 路径全部由调用方解析；ui 的 prelude 再导出两个宏的产物。关键术语：调用点、再导出、分布式注册、UiDensity 三档密度。
