本讲覆盖 ui_macros 的 dynamic_spacing 宏及其全仓库唯一调用点 spacing.rs，聚焦宏在编译期生成的两样产物：变体名与 doc 注释。核心结论：BaseXX 中的 XX 恒取 Default（默认密度）档的像素值——Single 输入取 n 本身，Tuple 输入取中间值 b，再经 format_ident! 的 {:02} 补零成两位（如 Base04），超过两位不截断。三档 UI 密度取值来源不同：Single 按 (n−4, n, n+4) 推导且紧凑档下限钳为 0，Tuple 直用三元组，分别对应 Compact、Default、Comfortable。doc 注释与代码共享同一批计算，按紧凑｜默认｜宽松列出三个像素值并标注 @16px/rem（16px=1rem，随用户 rem 设置缩放）；因 /// 无法出现在 quote! 模板中，宏以对 rustdoc 完全等价的 #[doc] 属性注入。新增间距值只需修改 spacing.rs 清单，变体、文档与 match 分支即自动生成，体现数据驱动的代码生成；宏不查重，撞名输入会产生重复变体的编译错误。三档值在运行时如何被选用留给下一讲 u3-l2。
