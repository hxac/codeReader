本讲拆解 ui_macros 作为过程宏 crate 的骨架。核心结论：`proc-macro = true` 把 crate 变成编译器插件——只能导出宏，syn/quote 依赖在下游 crate 编译期运行、不进入最终二进制；`[lib] path` 指向非默认库根只是 Zed 的命名规范。过程宏本质是 TokenStream 进、TokenStream 出的编译期函数：token 既非字符串也非类型化数据，返回的 token 拼回源码后按普通代码做名称解析与类型检查。三种过程宏形式中 ui_macros 使用两种：函数式宏（`#[proc_macro]`，derive_dynamic_spacing!，输出替换调用点）与派生宏（`#[proc_macro_derive]`，RegisterComponent，输出追加在原类型之后），属性宏未使用。库根 ui_macros.rs 采用薄入口模式：宏声明与文档（含 doctest）加一行转发到 dynamic_spacing 与 derive_register_component 实现模块。最后记住存在 proc_macro 与 proc_macro2 两种 TokenStream，经 parse_macro_input! 与 .into() 在边界互转。
