本讲介绍 Zed 的 proc-macro crate ui_macros：入口文件只做声明、文档与一行转发，实现分别在 dynamic_spacing.rs 与 derive_register_component.rs。它仅导出两个宏：函数式宏 derive_dynamic_spacing!（#[proc_macro] 声明）在编译期为 ui crate 的 spacing.rs 生成密度感知的 DynamicSpacing 枚举（Compact/Default/Comfortable 三档），全仓库只有一个调用点；派生宏 RegisterComponent（#[proc_macro_derive] 声明）让实现 Component trait 的组件自动登记进 ComponentRegistry，漏实现则编译报错。Cargo.toml 要点：proc-macro = true 使产物成为编译器插件，正式依赖只有 syn 与 quote，component 与 ui 仅为 doctest 的 dev 依赖；宏生成代码引用的 ::theme::、component:: 等路径须由调用方 ui 的依赖解析。本讲引入的关键概念包括过程宏三种形式、TokenStream 与 workspace 依赖继承。
