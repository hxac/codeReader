本讲精读 `crates/ui/src/styles/color.rs` 的语义颜色系统。核心结论：`ui::Color` 是按「意图」而非颜色命名的枚举（共 24 个变体，如 `Default`、`Muted`、`Error`、`Created`、`Ignored`），组件只在构建期存下这个语义键，真正的 `Hsla` 颜色值延迟到渲染期由 `Color::color(cx)` 查询当前主题获得。解析链路为：`Color::color(cx)` → `ActiveTheme::theme()`（读取 gpui 全局 `GlobalTheme`）→ `Theme` 的三张色表 `colors()`（界面基础色）、`status()`（每状态含前景/背景/边框三件套，`Color` 只取前景）、`players()`（协作者色表）。ui crate 只管语义、theme crate 只管外观，二者在渲染期汇合，因此切换主题后组件无需重建即可整体换色。关键术语：`Selected` 与 `Accent` 语义分离但当前同色，体现解耦收益；`Color::Custom(Hsla)` 是被源码双重强调劝退的逃生门，且 `From<Hsla>` 使 `.into()` 可能静默绕过语义体系；`Color::Player(u32)` 用取模映射为协作参与者分配稳定颜色，槽位 0 保留给本地用户。这套「语义键 + 渲染期解析」模式将在后续讲义（`Label`、`TextSize` 等）中反复出现。
