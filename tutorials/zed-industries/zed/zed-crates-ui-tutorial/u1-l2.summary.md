本讲精读 `crates/ui` 的 `src/prelude.rs`（35 行）与 `src/component_prelude.rs`（6 行），并联系 crate 根 `src/ui.rs`、`src/traits.rs`、`src/styles.rs`、`src/components/stack.rs`。核心结论：prelude 存在的根因是 Rust 的 trait 作用域规则——`on_click`、`h_flex` 等方法均由 trait（`Clickable`、`StyledExt`、`Styled`）提供，trait 必须进作用域才能调用，故全仓库统一以 `use ui::prelude::*;` 一行 glob 导入开头。prelude 条目可按五层读作「公共 API 地图」：gpui prelude 转发、gpui 显式类型/函数（`div`、`px`、`SharedString`）、能力 trait、设计令牌（`Severity`、`TextSize`）、组件与布局函数（`Button`、`h_flex`/`v_flex`），另跨 crate 转发 `theme::ActiveTheme` 支撑 `cx.theme()` 取色。关键术语：glob 导入、re-export、能力 trait、双 prelude、扁平化再导出。`component_prelude` 专供组件预览体系（多出 `ComponentId`、`ComponentStatus`、`Documented`、`RegisterComponent`），不含渲染条目，组件文件总是两套并导。crate 根与 prelude 经 glob 再导出形成双向引用，`ui::Button` 与 `ui::prelude::Button` 同一真实定义；`components`/`styles`/`traits` 为私有模块，保障内部重构自由。注意「在根上不等于在 prelude 里」：`CommonAnimationExt`、`Transformable` 需显式导入。
