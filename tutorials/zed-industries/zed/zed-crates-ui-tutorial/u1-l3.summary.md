本讲精读 ui crate 的 Icon 与 Popover 组件，机制上追溯 gpui 的 element/view trait 与派生宏，并以 ContextMenu 作有状态对照。核心结论：无状态组件的标准骨架是派生 IntoElement 加实现 RenderOnce——组件结构体只是「一次渲染输入的配方」，无跨帧状态，每帧由父视图重建、在 render 中被按值消费；机制链为派生宏把值包进 ViewElement 桥接类型、blanket impl 使其成为无身份的 View（entity_id 为 None）、布局时走无状态路径。builder 方法统一按值接收 self，容器组件实现 ParentElement 的 extend 即可获得 child/children。引入的关键术语：RenderOnce 与 Render 的签名差异、FluentBuilder 的 when/when_some、IconSource 三种来源、语义 Color 在渲染期查主题解析、尺寸统一以 rem 表达。有状态视图走 Entity 加 cx.notify() 的响应式路线，与无状态组件构成外层状态、内层配方的分层；综合实践为从零实现 StatusDot 组件。
