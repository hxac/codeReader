本讲核心是 sidebar crate 的归档视图（Thread History）集成。`SidebarView` 枚举定义互斥二形态：默认 `ThreadList` 与持有子实体句柄的 `Archive(Entity<ThreadsArchiveView>)`；render 在 match 点把列表主体整体替换为该子实体，根容器、导入横幅与底栏两形态共享，归档视图自带迷你刷新循环、不走主列表的 `update_entries` 重建管线。切换是一组有序副作用：`show_archive` 含遥测、双守卫（活跃工作区与 AgentPanel）、新建子实体、订阅五类事件（Close/Activate/CancelRestore/Import/NewThread）存入 `_subscriptions`、焦点迁移与 serialize 落盘；`show_thread_list` 清空订阅以防幽灵回调。`open_thread_from_archive` 把历史线程拉回活跃：无目录走快路径（unarchive 加三岔激活决策），有关联目录需先 git 恢复被归档工作树、改写元数据路径再激活；任务存 `restoring_tasks`，ThreadId 为键，drop 即取消。`replace_archived_panel_thread` 是工作区切换护栏，为仍停在已归档线程的面板新建草稿。持久化经 `SerializedSidebarView`：serde alias 兼容 Archive→History 改名（序列化只出新名），坏状态回退默认不崩溃，恢复走 defer_in 延迟。
