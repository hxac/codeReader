本讲精读 sidebar.rs 中的 rebuild_contents（本 crate 最长的单函数，约 630 行）：它以项目分组（MultiWorkspace::project_groups）为遍历单位，持久元数据打底、活跃信息覆盖。要点：WorktreePaths 的 main/folder 双路径使每个分组对线程与终端各做四路查询（main 正路、分组键 folder 兜底、逐打开工作区、逐 linked worktree），靠声明在分组循环外的 seen_thread_ids/seen_terminal_ids 做跨分组首次收录去重；分组标签撞名由 compute_disambiguation_details 先排序去重再逐级加深路径后缀消歧（结果存 path_detail_map），行内 worktree 徽标的分支名来自打开工作区 git 快照构建的 branch_by_path；活跃信息以 session_id 为桥，经 apply_active_info 配合 Arc::make_mut 写时复制覆盖到行，「Running→Completed 且用户未在看」的通知跳变靠记忆字段 live_thread_statuses 检测，折叠分组走同一支线；旧快照经 mem::take 取走、仅回收 notified_threads，收尾再按 current_* 集合裁剪记忆；草稿行经两道 retain，空草稿仅作当前线程且无 pending 激活时置顶保留（钉在 DateTime::MAX_UTC）；搜索过滤发生在分组头压入之前，整组无命中时连分组头一并丢弃。
