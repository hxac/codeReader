本讲精读 sidebar crate 最长的核心函数 rebuild_contents：任何事件后都从「当前世界状态」全量重推导 contents.entries，流程分准备、分组遍历、四路查询收集线程/终端、草稿判定、排序过滤、收尾 GC 六个阶段。数据源分三类：持久化元数据（ThreadMetadataStore 与 TerminalThreadMetadataStore）、进程内存活跃信息（AgentPanel 的 ActiveThreadInfo）、Sidebar 记忆字段（live_thread_statuses、notified_threads）。关键术语与结论：WorktreePaths 存 folder/main 两列等长路径；线程与终端各走四路索引查询，以 seen_* 集合跨分组去重，先到的查询决定行的 Open/Closed 归属；compute_disambiguation_details 逐级加深路径尾部直到分组名不撞；branch_by_path 每轮从打开工作区的 git 快照现收分支名；apply_active_info 以 session_id 为键把活跃信息覆盖到八个字段，old_statuses 记忆字段支撑 Running→Completed 的通知跳变检测（折叠分组走 entry_by_session 反查的对称路径）；收尾用 current_* 在册名单裁剪通知集合与 MRU 时间戳，防止记忆字段泄漏。
