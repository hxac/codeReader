本讲解决「如何在本地构建与测试 sidebar crate」：它是纯库 crate（库根为 src/sidebar.rs，无 bin），需在仓库根目录执行 cargo check/test -p sidebar；测试模块 sidebar_tests 经 `#[cfg(test)]` 挂入库内，dev-dependencies 成片开启 test-support 特性以搭建假世界。关键术语：TestAppContext 是无窗口的确定性测试上下文，经 add_window_view 遮蔽升级为带窗口的 VisualTestContext，run_until_parked 负责把异步任务泵到收敛后再断言。脚手架链为 init_test → init_test_project（隔离内存数据库 + FakeFs 假文件系统）→ setup_sidebar_closed → setup_sidebar（再 toggle 打开）；save_thread_metadata 播种线程元数据并经 observe 自动刷新列表，visible_entries_as_strings 把列表压平成字符串数组作断言出口。单测按测试名子串过滤；改坏 DEFAULT_WIDTH 仍全绿说明无测试覆盖，MAX_WIDTH 小于 MIN_WIDTH 会经 clamp panic 变红。观察 UI 用 cargo run -p zed，截图回归工具 zed_visual_test_runner 仅限 macOS。
