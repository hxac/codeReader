本讲确立 sidebar crate 的定位：它是 Zed 多项目模式下的 Agent 线程与终端侧边栏，不是文件树项目面板；列表覆盖窗口内全部项目分组，因此挂载于 MultiWorkspace 而非单个 Workspace。crate 仅三个源文件：sidebar.rs 为库根（Cargo.toml 直接指定，无 lib.rs），承载 Sidebar 实体、订阅接线、重建管线与渲染交互；sidebar_tests.rs 仅测试编译；thread_switcher.rs 是自包含的 ctrl-tab 式线程切换器。核心架构约束：任何变化都经 schedule_update_entries → update_entries → rebuild_contents 从当前世界状态全量重推导列表，禁止增量协调状态。Sidebar::new 是全 crate 接线图：构造期订阅宿主事件、两个子编辑器（搜索过滤与行内重命名）并 observe 两个线程元数据存储，再经 defer_in 补订已有工作区并首次刷新；以 WeakEntity 持宿主防止循环引用。依赖方向即分层方向：sidebar 只组合 agent_ui、workspace、project、git* 等能力，自身不做持久化与 git I/O。装配发生在 zed crate：observe_new(MultiWorkspace) → defer → cx.new(Sidebar::new) → register_sidebar，以 Box<dyn SidebarHandle> 实现 workspace 侧定义的 Sidebar 契约 trait（Focusable + Render + EventEmitter<SidebarEvent>，含 SerializeNeeded 持久化事件）。
