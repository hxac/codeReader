本讲剖析 component crate 的文件骨架与符号管道。核心结论：该 crate 极简到仅两个源文件——component.rs 管机制（Component trait、全局注册表、scope/status 枚举），component_layout.rs 管展示（ComponentExample 示例卡片、ComponentExampleGroup 分组，及 single_example、example_group_with_title 等辅助函数）；Cargo.toml 用 `[lib] path` 指向 component.rs，遵循仓库「根文件与 crate 同名」的非默认约定。私有 `mod` 加 glob 重导出制造出扁平命名空间，外界只能走 component::X 一层平面路径，符号在文件间搬家不会破坏调用方。ui crate 提供两条导出通道：ui::prelude 面向所有写 UI 的人，重导出 Component、ComponentScope、single_example、example_group(_with_title) 与 RegisterComponent 派生宏；ui::component_prelude 面向组件作者，额外含 ComponentId、ComponentStatus、Documented。「写组件走 ui::prelude，读注册表（components()、ComponentRegistry 等）直接依赖 component crate」是本讲确立的关键架构分界线。
