本讲建立 component crate 的全局地图：它是 Zed 设计系统的「元层」注册中枢，自身不渲染业务 UI，三大职责为定义 Component trait（可预览组件的契约）、提供预览布局（component_layout.rs 的示例卡片与分组）、以及基于 inventory 分布式切片的注册机制（链接期收集注册函数，运行期由 component::init() 填入全局注册表 COMPONENT_DATA）。引入的关键术语：RegisterComponent 派生宏（由过程宏 crate ui_macros 生成注册代码）、ComponentRegistry、ComponentMetadata、ComponentScope（15 个分类）、ComponentStatus（生命周期）。依赖关系已验证：ui 依赖 component 与 ui_macros；ui_macros 不依赖 component，只生成引用其路径的代码；component_preview 依赖 component、ui、workspace；workspace 依赖 component 但不依赖 component_preview——OpenComponentPreview 动作定义在 workspace，处理器由 component_preview 注册（依赖反转），zed 主程序调用 component_preview::init() 完成接线。实测约 62 个文件、11 个 crate 使用该体系，其存在意义是可视调试、UI 模式文档与组件变体展示。
