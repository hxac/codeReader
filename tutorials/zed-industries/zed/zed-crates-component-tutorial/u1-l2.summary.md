本讲讲组件预览的两条启动路径：独立 example 二进制（`cargo run -p component_preview --example component_preview`，其 main 手工组装字体、设置、AppState 等最小宿主环境后开窗口）与 Zed 编辑器内命令面板动作 `workspace: open component preview`，两者最终都构造 ComponentPreview 并以 add_item_to_active_pane 加入窗格。核心结论：`component::init()` 在运行期遍历 inventory 于链接期登记的 ComponentFn，把 ComponentMetadata 按组件 id 写入全局 COMPONENT_DATA，写入幂等、多次调用无害；`components()` 返回克隆快照且之后不更新，故真正的时序约束是 init 必须早于第一个读快照的消费者（ComponentPreview::new）。`workspace::init` 首行即调用 `component::init()`，构成框架级保证，example 里的显式调用只是冗余双保险。依赖反转体现为：workspace 仅定义动作，component_preview 经 `cx.observe_new` 注册处理器，zed 主程序无条件完成接线。
