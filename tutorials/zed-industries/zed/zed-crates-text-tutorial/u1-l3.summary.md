本讲绘制 text crate 十个源文件的模块地图。text.rs 既是库根（由 [lib] path 指定）又是门面与主逻辑，Buffer、BufferSnapshot、Fragment 与编辑合并算法皆在此。模块可见性分四档：pub mod（locator、operation_queue、subscription）；私有 mod 加 pub use 再导出（anchor、selection 全提升，patch 仅提升 Patch 单名）；私有 use 纯内部（undo_map，外部写不出该路径）；#[cfg] 门控（network、tests 仅测试构建编译）。各模块职责：Anchor 以「插入时间戳＋操作内偏移」表示编辑无关位置，须借 BufferSnapshot 才能解析比较；Locator 是类分数的可插入有序标识，充当 Fragment 的 id；Patch 是不相交编辑的集合，支持 compose/invert 补丁代数；Topic/Subscription 以弱引用实现防泄漏的发布订阅；UndoMap 用撤销计数奇偶性判可见性；Selection 存恒有序 start/end 加 reversed 标志；OperationQueue 以 Lamport 时间戳为 key 暂存乱序远程操作；network 模拟重复、乱序、部分投递与断线重连的不可靠网络。核心结论：依赖图是中心辐射加回边的网状结构而非分层树——子模块以 use crate 回指 text.rs，文件拆分求可读性而非架构隔离；仅 locator、operation_queue、network 完全自足。关键术语：门面、再导出、模块可见性与类型可见性之别、Lamport 时间戳、补丁代数、撤销奇偶性。
