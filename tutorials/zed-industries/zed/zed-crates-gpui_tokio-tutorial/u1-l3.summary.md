本讲梳理 GPUI 的执行器与 Task 模型，为 gpui_tokio 的前置。核心结论：GPUI 采用双执行器——前台 ForegroundExecutor 单线程承载实体状态、UI 与事件（future 免 Send，且以 PhantomData<Rc<()>> 禁止跨线程），后台 BackgroundExecutor 线程池承接纯计算（future 须 Send），标准形态是前台 await 后台任务。任务句柄 Task 定义于 scheduler crate、由 gpui 转手导出，可 await、detach 或用 Task::ready 构造，最重要的语义是「drop 即取消」，并有 #[must_use] 保护。入口上，cx.spawn 是各上下文的固有方法（闭包拿 AsyncApp，Context<T> 版附 WeakEntity 弱句柄防内存泄漏），而 background_spawn 与 read_global 是 AppContext trait 方法，故 Tokio::spawn<C: AppContext> 仅依赖这两个方法即可对 App、Context<T>、TestAppContext 等通用。测试经 #[gpui::test] 用 TestAppContext 无界面运行，靠 run_until_parked 驱动假时钟调度，且每个测试的全局状态相互独立。
