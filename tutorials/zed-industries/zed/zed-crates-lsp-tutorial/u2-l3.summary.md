本讲核心是 crates/lsp 的启动握手：客户端发 initialize 请求（InitializeParams 声明 ClientCapabilities），服务器回 InitializeResult（含 ServerCapabilities），客户端再补发 initialized 通知；握手完成前禁止其他消息，能力协商原则是双方只使用对方声明的功能。LanguageServer::initialize 按值接收 self、返回 Task<Result<Arc<Self>>>，用类型系统保证谈判期间不插队，并以 server_info 回填 version 与 process_name。default_initialize_params 是 Zed 的能力底稿，pull_diagnostics、augments_syntax_tokens 两个开关用 then_some 控制字段是否出现在 JSON 中——能力缺失（None）不等于能力关闭（Some(false)）。SEMANTIC_TOKEN_TYPES/MODIFIERS 是语义高亮图例，token 类型按索引、修饰符按位掩码编码，顺序一经发布不可重排。capabilities 因 Arc 共享后拿不到 &mut 且读多写少而存于 RwLock；update_capabilities 由运行时动态注册驱动——服务器能力清单本质上是客户端本地维护的视图。
