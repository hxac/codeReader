本讲义剖析 lsp crate 中 src/lsp.rs 的 JSON-RPC 消息模型，覆盖四个最小模块：RequestId、三种消息建模、NotificationOrRequest 粗解析、unit 类型处理。核心结论：LSP 只有请求（有 id 与 method）、通知（无 id）、响应（result 与 error 恰含其一）三种消息。RequestId 是 serde untagged 的 Int/Str 二态枚举，反序列化按声明顺序尝试，"2" 保持字符串身份，并充当响应配对表的键。出站用泛型 Request/Notification 强类型一次序列化；入站用弱类型 NotificationOrRequest（method 字段的有无是判别消息种类的真正依据，两分支分发顺序不可颠倒）与 AnyResponse（result 以 &RawValue 零拷贝借用原始 JSON）。Response 借 LspResult 枚举加 flatten 在类型层面保证两键互斥。is_unit、deserialize_params、deserialize_result 用 TypeId 识别 () 类型，兼容服务器以 {} 或 null 表示空值的不一致。粗解析、两分支分发等概念由下一讲 stdout 分帧读取承接。
