本讲精读 lsp crate 的 src/input_handler.rs，解决「服务器 stdout 字节流如何切成一条条消息」。LSP 采用 HTTP 风格分帧：头部块以四字节 \r\n\r\n（HEADER_DELIMITER）收尾，Content-Length: （CONTENT_LEN_HEADER，大小写敏感）按字节声明 JSON 体长度，写出方向分帧与之对称。read_headers 借 read_until 增量逐行读取、以缓冲尾部定界，天然容忍分包到达，EOF 则报错。LspStdoutHandler 的 handler 主循环依次读头、解析长度、read_exact 读定长体，先经 io_handlers（IoKind::StdOut、原始文本）记录——这是 LSP 日志面板的数据源，再两分支分发：先试严格的 NotificationOrRequest（必有 method），送入容量 128 的有界通道 incoming_messages，满则挂起形成背压；后试宽松的 AnyResponse（必有 id），按 RequestId 一次性 remove response_handlers 中的回调，result 以原始 JSON 文本交付，error/result 皆缺时归一为 Ok("null")。顺序不可颠倒，否则带 id 的服务器请求会被静默吞掉；两分支皆失败仅 warn 不终止会话，任务错误经 loop_handle 传播。
