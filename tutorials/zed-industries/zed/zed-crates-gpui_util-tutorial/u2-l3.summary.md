本讲精读 gpui_util 的三个开发期工具。`debug_panic!` 宏透传 panic! 风格参数：debug 构建直接崩溃，release 构建记一条带回溯的 error 日志（依赖 RUST_BACKTRACE 环境变量）后继续执行，是「不该到达的分支」的标准处置。`some_or_debug_panic` 是带 `#[track_caller]` 的 Option 恒等断言：debug 构建遇 None 即 panic，release 构建纯透传且不打日志。二者引出 debug_assertions 的两种判定形态：`#[cfg]` 属性把未选中分支整段剔除、不做类型检查；`cfg!()` 展开为布尔字面量、两分支都要过类型检查。`maybe!` 宏三条规则把块展开为立即调用闭包（普通、async、async move），因 `?` 的提前返回只作用于最内层闭包，故可在不改外层函数签名的前提下用 `?` 折叠 Option/Result 流水线；async 形态产出 Future，需 `.await` 取值。
