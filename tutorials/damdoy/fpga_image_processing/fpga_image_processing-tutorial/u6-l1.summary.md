本讲讲解仿真后端（simulation/ 目录）如何驱动核心 HDL 模块。它由两个文件实现，引入四个关键概念：`Operation` 结构与 `FIFO_OP` 命令队列把一次高层调用拆成「命令字节 + 数据字节」脚本，等价于报文格式，传输外壳是内存队列；`main_loop_clk()` 是驱动心脏，手动翻转 `clk` 并两次 `eval()` 走一拍，每拍从 `fifo_in` 弹 1 项驱动 `comm_cmd`/`comm_data_in`，并把模块输出经 `fifo_out` 回收；`counter_free` 反压机制模拟通信线路占满——模块每吐 1 字节即把 `comm_data_out_free` 拉低 3 拍，逼其按真实握手等待，从而覆盖与硬件相同的输出路径；`memory[]` 用 128KB 的 `uint16_t` 数组模拟单端口 RAM，`addr/2` 换算字下标，并保留 `rd_en`→`data_read_valid` 的一拍读延迟。核心结论：仿真与硬件两套后端能跑通同一份 HDL，是因为它们实现了同一组接口契约（输入握手、输出反压、存储器时序），仿真用队列加数组模拟，硬件用 SPI 加 SPRAM 实现。本讲承接 u2-l1/u3-l1，为后续 u6-l2 SPRAM、u6-l3 SPI 从机、u6-l4 主机软件讲义铺垫。
