本讲在 u2-l1 符号契约基础上，定义主机与 image_processing 模块之间的字节级报文格式。核心结论：一条命令即一帧，由「1 字节操作码 + 0 到 N 字节参数」组成，操作码取自 Commands 枚举并与 HDL parameter 数值一一对应；模块靠操作码在派发时给计数器 counter_read 预装 N−1，从而预知要读几个参数字节。

引入的关键机制：16 位参数统一用小端序（先低字节后高字节），有符号与无符号数拆法相同；多个布尔标志（clamp、absolute_diff、input_source、add_to_output）按位移加法位打包进同一字节，硬件以位索引 comm_data_in[0/1/2] 解包；卷积 3×3 核的 9 个 8 位有符号定点数字节经符号扩展存为 16 位 convolution_matrix，数值不变。

最重要的跨讲结论：仿真与 iCE40 两套后端用完全相同的表达式打包拆分，剥去传输外壳（Operation + is_command 标志 vs SPI 的 SEND_CMD/DATA 事务）后，送入 comm 接口的字节流逐字节一致——这正是逻辑协议与物理传输分层、一份 main.cpp 驱动两套后端的根本原因。
