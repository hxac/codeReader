本讲聚焦 iCE40 硬件后端在 PC 一侧的软件实现，是仿真与硬件两条后端单元的收官篇。主机软件为三层栈：上层 `Image_processing_ice40` 把每个高层调用（如 `send_add`）按「1 字节命令字 + N 字节小端参数」拆成一串 SPI 事务；中层 `spi_command_send_recv` 负责事务编排与重试；底层 `xfer_spi` 通过 FTDI 芯片的 **MPSSE 引擎**把 C 调用变成 SCK/MOSI/MISO 真实时钟。关键概念有四：其一，存在**两层命令**——核心命令（`COMMAND_*`，业务语义）与 SPI 命令（`SPI_*`，传输外壳），数值无关，SPI 命令把核心命令当数据字节送入 FPGA；其二，主机与 FPGA 对操作码采用**镜像命名**（主机 `SEND_*`/`READ_*` ↔ FPGA `RECEIVE_*`/`SEND_*`），`SPI_INIT` 的 body 第三字节 `0x11` 为初始化握手密码。其三，针对 SPI 全双工时序错位，引入 `STATUS_FPGA_RECV_MASK`（bit6=`0x40`）**重试机制**：FPGA 在 `SPI_TRANSMIT` 状态把 bit6 恒置 1 当「已响应」信标，主机在第 3 个回字节看到它才停，最多重试 10 次；状态字节 bit0 则是 `buffer_full`，供读方向判断有效数据。其四，`send_image`/`read_image` 用 **32 字节批量事务**（`SPI_SEND_DATA32`/`SPI_READ_DATA32`）把搬运有效率从 25% 提至约 97%，不足 32 字节的零头回退逐字节发送。核心结论：同一份 HDL，仿真后端用 FIFO 队列、硬件后端用 SPI 事务，剥去传输外壳后送入核心模块的命令/数据字节流逐字节相同。
