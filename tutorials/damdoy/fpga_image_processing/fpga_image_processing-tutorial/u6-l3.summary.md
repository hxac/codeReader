本讲讲解 FPGA 硬件后端的通信接口——`spi_interface.v` 如何驱动 iCE40 片上硬核 `SB_SPI` 并充当 PC 与 `image_processing` 核心模块之间的「翻译官」。PC 侧的 FTDI 芯片是 SPI 主机，FPGA 的 `SB_SPI` 被配置为从机。

`SB_SPI` 是一块固定硅电路硬核，软件不必逐 bit 处理 `SCK`/`MOSI`/`MISO`，而是通过统一握手访问其寄存器：给地址 `spi_adr`、数据 `spi_dati`、读写方向 `spi_rw`，拉高选通 `spi_stb`，等 `spi_ack` 应答后读 `spi_dato`。上电后状态机先依次走过 `INIT_SPICR0…INIT_SPICSR` 五个状态写控制寄存器（使能、LSB first、时钟分频），再进入 `SPI_WAIT_RECEPTION` 收发循环。

主机与 FPGA 对同一操作码数值采用「镜像命名」（主机 SEND↔FPGA RECEIVE，主机 READ↔FPGA SEND）。`SPI_READ_OPCODE` 状态按 opcode 与帧内字节序号 `counter_read`，把 SPI 字节翻译成 `image_processing` 的 `comm_cmd`/`comm_data_in`。`SPI_TRANSMIT` 每次先回送状态字节 `0x40 | buffer_full`：bit6 是固定标记（主机据此用 `STATUS_FPGA_RECV_MASK` 重试确认），bit0 表示后续字节是否为有效输出。

输出方向靠单字节缓冲 `buffer_data_in`/`buffer_full` 与组合逻辑反压信号 `spi_data_in_free`（接到核心模块的 `comm_data_out_free`），防止 `image_processing` 吐字过快而丢失。`SEND_DATA32`/`RECEIVE_DATA32` 用 33 字节批量事务摊薄命令开销，使整块图像能一次性搬过 SPI，逼近 SPI 吞吐上限。
