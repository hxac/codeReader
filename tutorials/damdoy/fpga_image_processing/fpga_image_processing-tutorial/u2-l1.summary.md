本讲解读全项目最薄却最关键的契约文件 image_processing.hpp，分五个最小模块。其一，Commands 枚举：操作码从 COMMAND_PARAM=0 连续递增至 COMMAND_APPLY_MULT=12，末尾 COMMAND_NONE=255 作哨兵；数值与 HDL 的 parameter 逐字对应，是软件、两套后端与硬件四方共守的根本契约，新增命令须两侧同步。其二，纯虚基类 Image_processing：用纯虚函数声明操作、强制后端实现，两后端把同一高层调用译成完全相同的字节序列，差别仅在发送通道（FIFO 队列还是 SPI 总线）。其三，基类以 protected 成员托管 image_width/image_height，在 send_params 写入一次、处处复用。其四，main.cpp 借配套 #ifdef SIMULATION/ICE40 宏编译期选后端、靠多态运行期分派，实现一份源码编出两个程序。其五，send_clear 不发新命令，转调 send_threshold(0,value,true)，因无符号像素恒满足「>=0」而把整图填满，体现了把硬件复杂度藏进接口设计的思想。规律：凡触发硬件实际运算的命令都须 wait_end_busy，仅搬运数据或切缓冲的不用。本讲只建函数到命令的符号级映射，参数字节打包留待下讲。
