本讲是收官实战，演示新增一条逐像素命令 `COMMAND_APPLY_GAMMA`（近似 gamma 校正）如何贯穿「四层五文件」的扩展链路：契约层（`image_processing.hpp` 加枚举值与纯虚函数）、传输层（仿真 FIFO 与硬件 SPI 两套后端各自打包）、控制+运算层（`image_processing.v` 加派发分支、读参状态、运算分支）、业务层（`main.cpp` 端到端验证）。核心结论：四方契约要求软件枚举与 HDL parameter 数值严格相等（同为 13），新命令只能加在枚举末尾；两套后端必须产出逐字节相同的字节流，否则命令在某一层「消失」、仿真卡死。关键术语：扩展点（贯穿四层的加命令链路）、读参状态（`counter_read` 数字节、读完末字节一次性交接 `processing_command` 运算工单）、复用 `STATE_PROC_UNARY` 两拍流水双像素；gamma 近似用 `out=(in²)>>n` 替代浮点幂，且须先移位压回 8 位再 `apply_clamp`，否则会触发其内部 `$signed` 比较误判、把大值钳到 0。
