本讲围绕 `image_processing.v` 讲清命令的接收、解析与派发，核心是双 FSM 架构：`state`（命令解析主 FSM）与 `state_processing`（运算 FSM）置于同一 `always` 块的两个独立 `case`，共享时钟、互不阻塞——长卷积期间主 FSM 仍能响应状态查询，busy 位取自 `state_processing != STATE_IDLE`。引入两套枚举：`COMMAND_*`（操作码 0–12，与软件侧逐字对应、即四方契约）与 `STATE_*`（硬件内部状态名）。`STATE_WAIT_COMMAND` 是派发总台，按 `comm_cmd` 导向收发图状态或各 `*_READ_PARAM` 状态（预装 `counter_read`），或当场完成（取反当场启动运算、切换缓冲当场互换地址）。`processing_command` 寄存器充当「运算工单」：交接拍一次性写入它与 `state_processing`，使复用的 `STATE_PROC_UNARY`/`STATE_PROC_BINARY` 按命令选算法分支；带参数运算的交接发生在 `*_READ_PARAM` 读完末字节那一拍，仅零参数取反例外。
