本讲讲解如何用 Verilator 把 Verilog 核心模块 `image_processing.v`「跑」起来。它串起三个文件构成「构建→运行→可视化」闭环：`build_simulation.sh`、`software/main.cpp`、`run_gnuplot.sh`。核心结论是：Verilator 把 Verilog 翻译成等价的 C++（而非模拟电路网表），再用普通 make 编译成可执行文件。构建分两条命令——`verilator --exe` 把 `image_processing.v` 与仿真驱动、`main.cpp` 登记进同一工程并生成 Makefile，`make` 再编译出可执行文件。所有产物集中于 `obj_dir/`，其中 `Vimage_processing` 一个名字同时指代 C++ 类、Makefile 和可执行文件，其前缀由顶层模块名 `image_processing` 决定。本讲引入的关键术语包括 Verilator、`obj_dir/`、`Vimage_processing`、`-DSIMULATION` 宏、纯虚基类 `Image_processing`（多态）。`-DSIMULATION` 从 make 命令行注入，在 `main.cpp` 的「选头文件」和「new 后端对象」两处起作用，使同一份 `main.cpp` 编译出仿真后端而非 ICE40 硬件后端，揭示「宏→后端→Verilator 模型」的依赖链。最后，`main.cpp` 把结果像素写成 gnuplot matrix 格式的 `output.dat`，`run_gnuplot.sh` 以 `plot ... matrix w image` 渲染灰度图，其中 `set yrange reverse` 修正上下方向、`set cbrange [0:255]` 固定灰度映射是显示正确图像的关键。本讲仅覆盖「跑起来」，仿真后端内部驱动与 `test_*` 接口契约留待后续讲义。
