本讲精读 `px_demux_kern`（像素解复用内核）。与 u5-l1 广播 slowtime/RC（全员共享一份数据）相反，目标像素需「各取一份」，故改用**包交换（packet switching）**按内核寻址下发。demux 充当「串行→分包器」，把普通 `input_stream<float>` 转成 `output_pktstream` 包流，经 `pktsplit<32>` 按 `pkt_id` 分发给本 switch 的 32 个重建内核（`in[2]`），顶层再用 7 个 switch 复制成 224 路；`pktsplit`/`pktmerge` 上限 32，根因是 `pkt_id` 仅 5 位。核心原语：`getPacketid(port,index)` 间接获取编译期分配、未必连续的 `pkt_id`（不可硬编码），`writeHeader(port,pkt_type,pkt_id)` 写 32 位包头——`pkt_id` 占低 5 位、`pkt_type` 占 bits[14:12]，源行列与奇偶校验由硬件补全（UG1079）。每包数据量 `px_components_per_ai=(PULSES×RC_SAMPLES)/IMG_SOLVERS×3=4128`，即 1376 像素 ×3(X/Y/Z)，依赖 u1-l4 的整除约束成立。TLAST 在 `px_idx==(px_components_per_ai-1)` 时置 1，是 `pktsplit` 识别包边界的唯一标记；故 demux 写「包头+4128 float（末 beat 置 TLAST）」与重建内核读「包头+1376 像素」逐 float 对齐。像素在包流中以 float 写、以 int 读再 `reinterpret_cast` 还原，细节留待 u5-l3。
