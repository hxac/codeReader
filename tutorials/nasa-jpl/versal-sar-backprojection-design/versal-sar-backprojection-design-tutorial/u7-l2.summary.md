本讲对比 main / host_stride / pl_stride 三分支，核心结论：三者只在"输入侧预排序由谁做"上不同。main 由 AIE 的 Pixel Demux 整块投递（每核 1376 像素）；host_stride 由 ARM 预排后改为轮流 16 像素投递；pl_stride 由新增的 PL DMA Stride Controller 以步进式取址完成预排。main 与 host_stride 共用同一张系统架构图（差别纯在软件，ARM 是否在 DDR 里预排），pl_stride 才真正多出一片 PL 硬件；把排序搬出 AIE 的收益是各 Image Reconstruction 内核能更早并行启动。引入的关键术语包括输入侧预排序、步进式取址（stride）、轮流投递。两个承接性要点：其一，"后处理恒在 PL"是系统不变量——无论输入侧谁排，输出侧都由 PL 包路由器按 instance_id 把经 pktmerge 合并后打乱顺序的图像包重排回连续 DDR；其二，pl_stride 被锁死在 AIE_SWITCHES=1 的根因是 system.cfg 无法表达数组化 AXI4-Stream 端口 pl_stream_out[AIE_SWITCHES]，属工具链表达力限制，而非算法或仿真问题，包路由器因采用"每实例一个命名端口"而无此约束。
