本讲承接 u4-l1 的静态拓扑，回答三个"怎么做"，含三个互相独立又配合的模块。

包交换：每个 bpCluster 中 Pixel Demux 仅有一个 output_pktstream 端口，却要服务 32 个重建核。ADF 的解法是用 pktsplit<32>／pktmerge<32> 借包头 pkt_id 在一条物理流上复用多路逻辑数据，实现目标像素的 1→32 分发与图像的 32→1 汇合；两者各最多 32 路，这正是 IMG_SOLVERS_PER_SWITCH 上限 32 的由来。判据：广播数据（每核同一份）走 connect + single_buffer，按核切分数据（每核不同）才走 pktstream。

类内核与唯一 id：重建内核需各自持有跨调用累加的 m_img 与区分身份的 m_id，自由函数内核做不到，故用 kernel::create_object<ImgReconstruct>(id) 实例化类内核，并以 REGISTER_FUNCTION 注册入口。id = 32×bp_subgraph_insts + i 全局唯一（共 224 个），它不参与计算，仅在 dump 阶段写入输出包元数据，供 PL 包路由器按 ddr_offset = m_id × 每核样本数 把图像回写正确 DDR 段。

布局约束：location<graph>(*this) = area_group({...}) 把每个子图钉在 7 列×8 行的矩形 aie_tile 区域，外加同列 shim_tile 给 PLIO 留出口；col_start = bp_subgraph_insts × 7 使 7 个簇首尾相接铺满 0–48 列，适配 VCK190 的 50 列阵列。

综合实践揭示：bp_subgraph_insts 这一计数器在单子图构造期被端口命名、内核 id 基址、tile 列基址三处共用，依赖 C++ 成员按声明顺序构造的特性。32 路包交换上限与 50 列阵列上限共同框死 IMG_SOLVERS_PER_SWITCH 与 AIE_SWITCHES 的调参范围。
