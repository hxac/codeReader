本讲以 pipeline.py 为主、兼及 work_queue/metrics/check，梳理从 main() 到 worker() 的编排主线。核心结论：main() 是纯编排层，本身不做 OCR，按十个检查点「搭台—派活—收场」——建 WorkQueue、收集 --pdfs 分组入队（--stats/--beaker 填队后短路返回，无需 GPU）、下载模型、起 vLLM、拉起 N 个 worker 消费队列，最后 cancel 长驻协程并打印总结。use_internal_server（未给 --server）决定是否查 GPU、下载模型并改写 server/model。事件循环上四类协程（worker、vLLM 看护、报表、main）靠共享队列、模块级全局量与 cancel 协作；worker 用 TaskGroup 同生共死、异常不退出，整组落盘才写 done flag——断点续跑的根源。关键术语：协程与事件循环、create_task/gather、信号量限流、生产者-消费者模式、items_per_group、日志检查点跟踪法。
