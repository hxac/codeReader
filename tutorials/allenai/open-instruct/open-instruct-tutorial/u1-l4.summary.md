本讲讲解跑通首次训练的最小链路。核心结论：build_image_and_launch.sh 是统一启动入口——先校验 git 工作区干净，按当前 commit 构建或复用 Beaker 镜像，再以镜像名作为第一个参数调用下游脚本；debug 目录下的冒烟脚本（smoke test）与正式训练共用同一入口，仅缩小模型、数据与步数，带镜像名时经 mason.py 提交 Beaker（pure_docker_mode、可抢占短任务），否则本地运行。GPU 测试因 CI 无 GPU 须手动启动，run_gpu_pytest.sh 按镜像名整串匹配路由集群：cuda13 与 cuda13-moe 系镜像去 ai2/holmes，其余按 CUDA 12 处理。本讲新概念 MoE v2（OLMoDDPModel，如 Olmo 3.5 Small）：其 token permutation 依赖 transformer-engine，须用仅限 --cuda-version 13 的 --moe 变体镜像（Dockerfile 的 cuda13-moe 阶段加装 TE）；缺 TE 时 require_transformer_engine 会在启动早期抛出带修复指引的 RuntimeError。关键术语：冒烟测试、Beaker、mason.py、镜像三变体（cuda12/cuda13/cuda13-moe）。
