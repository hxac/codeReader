本讲解决 open-instruct 的环境搭建与工具链问题，分四个最小模块：①依赖管理：uv sync 按 pyproject.toml 与 uv.lock 精确装环境，Python 钉 3.12，默认装 dev+cuda12 组，cuda12 与 cuda13 两组互斥，由 tool.uv.sources 按组切换 torch/vllm 的 wheel 下载索引，requirements.txt 是 lock 文件的自动导出物；②Dockerfile：以 CUDA_VERSION 与 IMAGE_VARIANT 两个构建参数组合出 cuda12、cuda13、cuda13-moe 三种训练镜像，依赖层与代码层分离以利用缓存，镜像内同样用 uv --frozen 安装；③cuda13-moe 变体专供 MoE v2 模型（OLMoDDPModel，如 Olmo 3.5 Small）：加装 transformer-engine 2.16.1、设 DS_SKIP_CUDA_CHECK=1、把 venv 内 torch 自带的 cuBLAS 替换为系统副本并做构建期符号自检，两个默认镜像完全不受影响，运行期由 require_transformer_engine 启动检查兜底；④质量工具链：uv run pytest、make style（ruff format）、make quality（关键字检查+ruff+compileall+ty），conftest 在缺 vllm/GPU 时自动跳过相关用例。核心结论：transformer-engine 只随 -moe 镜像分发、本地装不到；文档可能滞后，冲突时以 pyproject.toml、uv.lock、Dockerfile 为准。
