本讲围绕 convert_moe_checkpoint_to_hf.py，讲解 MoE v2（KDA/OLMoE3，A4B）训练 checkpoint 从 olmo-core 格式导出为 HF 格式的方法。脚本是 olmo-core 转换器的薄封装，补三件事：其一，load_ddp_main_params 收集 OLMoDDP 融合优化器以 module.<参数名>.main 存储的权威权重——以 .main 后缀探测布局、六类候选键首匹配、numel 整型校验、缺任一参数硬报错；-c 必须传训练配置 JSON（含 model 与 dataset.tokenizer 节）才能保证块结构与权重对齐。其二，write_generation_eos 把 generation_config.json 的 eos_token_id 改写为 chat EOS 列表 [100265, 100257]（im_end 与 endoftext），防止 vLLM 服务缺停止符导致回合不终止、工具调用重复到 token 预算（BFCL 真实故障）。其三，校验策略：--device 默认 cuda 以防 Triton 内核在 CPU 上崩于权重写出之后、留下「已转换未校验」假象；KDA 1.2B 上严格 logit 校验必然失败，生产做法是 --skip-validation --device cpu 加功能性评估替代。边界：仅支持本地/WEKA 路径；GDN 混合 MoE 会误入 dense-hybrid 导出器，KDA 因类继承关系免疫。
