本讲建立 OLMo 仓库代码地图，含三个模块：目录职责、构建打包、开发工具链。仓库按角色分层：库代码（olmo、hf_olmo、olmo_data）、入口脚本（scripts/train.py 为训练总入口，官方集群训练命令与之同构）、配置（configs/）、独立工具集（inference/、evaluation/，各带独立依赖）与测试（tests/）。核心结论：pip 安装得到的只有 olmo 及其 data、eval 子包、hf_olmo、olmo_data 五个包，边界由 pyproject.toml 的 include/exclude 包发现规则决定；olmo_data 的词表 JSON 以 package data 身份随包分发，经 get_data_path 定位。开发命令集中在 Makefile：run-checks 依次执行 isort、black、ruff、mypy 与 CPU 模式 pytest，构成贡献代码的质量门禁。贯穿全讲的判断标准：区分「会被 pip 打包的库代码」与「仅仓库内使用的工具、配置、数据」。
