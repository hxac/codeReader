本讲围绕 `olmo_core.optim.scheduler` 展开：OLMo-core 自研学习率调度体系，区别于 `torch.optim.lr_scheduler`，每个调度器是可序列化、经 `Registrable` 注册的 Config，核心接口为纯函数 `get_lr(initial_lr, current, t_max)`；副作用集中在 `set_lr()`，由 `TransformerTrainModule.optim_step()` 每步对每个参数组调用，以 `initial_lr`（钉入 `fixed_fields`、随 checkpoint 保存）为基准重算 LR，保证幂等与断点续训一致。`units` 可选按 step 或 token 计进度。主力调度器 `CosWithWarmup` 为线性 warmup 加余弦衰减，`warmup`/`warmup_fraction` 二选一，`alpha_f`（默认 0.1）设定衰减下限，`t_max` 可覆盖训练 horizon。关键结论：余弦曲线相对总步数定义，horizon 改变后 LR 随之改变，故分阶段训练须换调度器——OLMo-3 第二阶段退火（anneal）用 `HalfCosWithWarmup` 从余弦后半段接管、避免 LR 弹回峰值，第三阶段用 `LinearWithWarmup(alpha_f=0)` 线性衰到零。另介绍组合机制：`SequentialScheduler` 使前段终点 LR 自动成为后段 `initial_lr`；`PerGroupScheduler` 配合 `OptimGroupOverride` 按参数组分派不同曲线。
