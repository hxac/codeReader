本讲解读 `olmo_core/optim/scheduler.py`：OLMo-core 自研学习率调度体系（共 14 个调度器），而非 torch 内置的 lr_scheduler。`Scheduler` 基类混入 Config 与 Registrable，计算接口是纯函数 `get_lr(initial_lr, current, t_max)`，副作用集中在 `set_lr(group, trainer)`，由 `optim_step` 每步对每个参数组调用；LR 总是从 `initial_lr`（钉在 `fixed_fields`、随 checkpoint 保存）重算，调度幂等、断点续训曲线不漂移，`units` 可按 steps 或 tokens 计进度。主力 `CosWithWarmup`＝线性 warmup＋余弦衰减到 `alpha_f`·峰值（默认 0.1，并不衰到零），`warmup` 与 `warmup_fraction` 恰给其一，`t_max` 可覆盖总步数。核心结论：余弦曲线相对总步数（horizon）定义，换阶段必须重设曲线——OLMo-3 三阶段即 `CosWithWarmup` → `HalfCosWithWarmup`（从余弦中点接管退火并重设 lr）→ `LinearWithWarmup` 衰到 0。组合件还有 `SequentialScheduler`（前段终点 LR 作后段 initial_lr）与 `PerGroupScheduler`（配合 `OptimGroupOverride` 按参数组分派）。
