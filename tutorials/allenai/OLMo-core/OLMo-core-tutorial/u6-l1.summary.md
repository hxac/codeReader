本讲剖析 olmo_core 的 Trainer 训练循环。核心结论：Trainer 是编排者而非计算者，fit() 只管节奏——前向/反向/优化委托给 train_module，checkpoint 与评测不在循环正文里，而分别由 CheckpointerCallback 的 post_train_batch 和 EvaluatorCallback 的 post_step 钩子触发。四个模块：①Duration 以 steps/tokens/epochs 计量训练时长，due() 判定到期（epochs 用严格大于），换算出的 max_steps 是学习率调度前提，hard_stop 可提前刹车而不改变 LR 曲线；②单 step 顺序：取 batch、簿记自增（global_step 等）、pre_step、train_batch（前向+反向）、pre_optim_step、optim_step、清梯度、post_train_batch、post_step，停训检查在步末；③指标由 record_metric 缓存、按 metrics_collect_interval 攒批，仅用两次 all_reduce 完成 ReduceType（mean/sum/max/l2_norm）语义的跨 rank 归约，异步簿记把通信放到后台线程；④LoadStrategy（if_available/always/never）约定断点续训行为，从 save_folder 恢复强制带 trainer 与优化器状态，RNG 仅在 world size 一致时恢复。
