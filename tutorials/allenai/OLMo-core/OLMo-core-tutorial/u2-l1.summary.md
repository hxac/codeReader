本讲解析 `Config` 基类（src/olmo_core/config.py），它是全库「一切皆 Config」的地基，分三个最小模块：基类本身、yaml/json 序列化、dotlist 覆盖（merge）。核心结论：子类须重新加 `@dataclass`、字段只用简单类型或嵌套 Config，即免费获得序列化、嵌套组合与 dotlist 覆盖能力；基类没有 `save()`，存档需自行将 `as_config_dict()` 结果写盘。序列化出口两种：`as_dict()` 无损供程序内用，`as_config_dict()` 注入 `_CLASS_` 与 `type`、JSON 安全，是官方存档格式；入口 `from_dict`/`from_yaml`/`from_json` 依 `_CLASS_` 动态 import 还原确切子类，保证往返（round-trip）等价。`merge(dotlist)` 走「转 dict → 下钻改值 → 重建」路线并返回新对象，天然兼容 `--foo-bar=x` 命令行风格，值按 YAML 规则解析。继承链 Config → ModuleConfig（`build()`）→ ModelConfig（`num_params`）→ TransformerConfig（含 `olmo2_190M` 等工厂方法）。关键术语：dotlist、round-trip、`_CLASS_`、StrEnum、DType。本讲为 u2-l2（Registrable 与 `type` 字段）和 u2-l3（命令行覆盖链路）铺垫。
