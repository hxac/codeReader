本讲打开 u6-l1 留下的 train_module 黑盒。TrainModule 抽象基类是与 Trainer 的「合同」：train_batch/eval_batch/optim_step/zero_grads 按固定节奏被调用，指标经 record_metric 回流，且继承 Stateful 以整体进出分布式 checkpoint。TransformerTrainModuleConfig 挂 DP/TP/CP/EP/PP/AC 六套并行配置，因并行化必须位于模型 build 之后、优化器 build 之前；构建四步为校验尺寸→build_world_mesh→parallelize_model（固定顺序 PP→FP8→CP→TP→EP→激活检查点→compile→DP，最后 init_weights）→optim.build，pp_config 非 None 时自动分发出 TransformerPipelineTrainModule。train_batch 自动生成 labels（input_ids 左移、忽略位 pad 成 -100）并按 token 预算切 micro-batch，loss 以 sum 归约再除以全批有效 token 数 N，使梯度与 micro-batch 划分无关；梯度同步仅在最后一个 micro-batch 触发（no_sync / set_is_last_backward）。optim_step 三段式：裁剪（DTensor 范数须 full_tensor 归约）→逐参数组 scheduler.set_lr→optim.step；SkipStepOptimizer 则要求 loss 在 train_batch 末尾即时跨 rank all-reduce。
