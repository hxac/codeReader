本讲拆解 `Config.merge()` 的 dotlist 覆盖机制与 `script_utils` 官方脚本入口。核心结论：覆盖发生在「字典世界」——merge 先用 `_clean_opt` 清洗覆盖项（值按 YAML 规则解析、无等号默认 true、连字符归一为下划线），把配置树降级为字典，经 `_set_nested` 按点号下钻写入，再由 `from_dict` 依 `_CLASS_`/`type` 线索重建新对象，多态子类身份不丢失；`strict` 与 `prefix` 参数分别支持宽松忽略和剥前缀。`get_cli_parser()` 借 `parse_known_args` 把命令行分流为少量正式选项（`--save-folder` 唯一必填）与任意 dotlist 覆盖。`ExperimentConfig` 是五块积木（model/dataset/data_loader/train_module/trainer）的顶层配置，`main()` 串起参数解析、环境准备、组件 build、配置落盘与 `trainer.fit`，`--dry-run` 可零 GPU 预览最终配置。官方脚本以「代码定基线、命令行 merge 微调」收尾，最终配置经 `ConfigSaverCallback` 固化进每个 checkpoint 的 config.json，形成可复现闭环。
