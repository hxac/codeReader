本讲剖析 OLMo-core 回调系统，核心结论是「主循环极简、功能外挂」：checkpoint、评测、日志、吞吐监控全部以回调实现，不在 fit() 循环正文。模块一讲 Callback 基类的 16 个生命周期钩子（post_attach、pre_train、每步的 pre_step、pre_optim_step、post_train_batch、post_step、log_metrics、post_train、on_error、close 等），触发点全在 trainer.py；模块二讲注册与排序：回调经 TrainerConfig.callbacks（with_callback() 链式挂载），按 priority 降序、同级按插入序在每个钩子轮次统一执行，console_logger、checkpointer、speed_monitor、garbage_collector 四个默认回调自动补齐，替换须子类化；模块三讲 CheckpointerCallback 的保存决策树（永久/临时/定点保存、两段式删除、post_train 同步终存）；模块四讲 SpeedMonitorCallback 生产 throughput/* 指标、ConsoleLoggerCallback 按通配符消费，构成解耦的生产者—消费者指标流水线；模块五讲 EvaluatorCallback 与 CallbackConfig 双层模式（不可序列化回调存配方、build(trainer) 返回 None 即不启用）。关键术语：钩子、priority、Stateful、ephemeral checkpoint 及其阻塞机制；回调顺序是被回归测试锁定的设计契约，也是分布式正确性的前提。
