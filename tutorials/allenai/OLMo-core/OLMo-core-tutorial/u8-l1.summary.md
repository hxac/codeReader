本讲拆解 OLMo-core 的 in-loop（训练中）评测框架，核心结论：评测是回调而非训练循环正文。四个最小模块：① Evaluator 抽象基类，定义批次迭代协议（可被 eval_duration 截断且跨轮可比）与 update/compute/reset 三段式指标协议；② MeanMetric 原语，O(1) 内存的分布式加权均值，只在 compute 时 all-reduce，单进程静默退化；③ LMEvaluator 按数据集 metadata 的 label 分桶，逐 token 统计交叉熵，输出「{label}/CE loss」与「{label}/PPL」，只需 ce_loss 故天然兼容 CP/TP；④ 下游评测任务逻辑外置给 olmo_eval 库，task_groups 提供任务名单，DownstreamEvaluator 需要完整 logits，CP/TP 下不可用。EvaluatorCallback 挂在 post_step 等钩子上按 eval_interval 驱动评测，前向委托 train_module 的 eval_batch（逐 token 不归约 CE）；指标全名固定为「{prefix}/{评测器名}/{指标名}」。关键结论：PPL=exp(CE)，CE 的理论下界是数据本身的熵。
