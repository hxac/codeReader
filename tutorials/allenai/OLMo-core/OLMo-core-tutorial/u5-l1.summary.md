本讲解读 olmo_core.optim 的优化器配置体系。核心结论：OptimConfig 是可注册（Registrable）基类，统一管理 group_overrides、compile、fixed_fields、mup、completedp 五个公共字段，子类自定义字段经 build() 自动透传为优化器构造参数；build 流程为 build_groups 组装参数组、工厂方法实例化、逐组设 lr 与 initial_lr、快照 fixed_fields 并挂 checkpoint 后置钩子。AdamWConfig 直接包装 torch.optim.AdamW；Lion 为库内自实现（符号更新、单动量、默认 lr 更小）；矩阵感知的 Muon/Dion 走 MatrixAwareOptimConfig，按参数维度自动分组，不支持手动分组与 muP/CompletedP。OptimGroupOverride 用 fnmatch 通配符按全限定参数名把 embedding、lm_head 等拉入独立参数组，未覆盖参数进默认组，strict 模式下匹配为空即抛错。关键术语：参数组（param_groups）、initial_lr（钉入 fixed_fields 防止续训被旧 checkpoint 污染，供 u5-l2 调度器承接）、mup 与 completedp（新增可选字段，仅 AdamW 系支持，详见 u10-l7/u10-l8）。
