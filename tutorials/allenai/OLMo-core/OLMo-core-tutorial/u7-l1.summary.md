本讲围绕 OLMo-core 数据并行的三种策略展开：DDP 每进程持完整参数、以梯度桶 all-reduce 归约；FSDP 将参数/梯度/优化器状态按进程分片，前向 all-gather、反向 reduce-scatter；HSDP 是二者折中，把进程划分为副本×分片（R×S）。核心结论：`DataParallelConfig.name`（fsdp/hsdp/ddp）是唯一策略开关，fsdp 与 hsdp 共用 `fully_shard`（FSDP2）路径，差异完全由 mesh 维度承载——HSDP 产生 `dp_replicate`×`dp_shard` 二维网格。关键概念包括：`build_world_mesh` 组织多维 DeviceMesh；模型视角 `get_dp_model_mesh` 与数据视角 `get_dp_mesh` 对 CP/EP 维的不同折叠规则；`parallelize_model` 中 DP 最后应用、优化器 build 之前的顺序契约；梯度累积窗口内只在最后一个 micro-batch 归约（FSDP 用 `set_is_last_backward`，HSDP 加 `set_requires_all_reduce`，DDP 用 `no_sync()`）；以及显存与通信量的量化取舍（默认每节点一副本）。
