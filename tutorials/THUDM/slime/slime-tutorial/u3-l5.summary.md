本讲讲清 slime rollout 的动态采样、过采样与过滤。动机源于 GRPO：优势由组内相对算出，若同一 prompt 的 n 条采样奖励方差为 0（全对或全错），优势全为 0、无梯度信号，故按 DAPO 风格丢弃这类组。

丢弃后须凑够 rollout_batch_size 组，由三个量协同：target_data_size（要保留的组数）、over_sampling_batch_size（补采粒度，须不小于目标批量）、remaining_batch_size（GenerateState 维护的「已提交未丢」计数）；后者低于目标即触发新一轮补采，实现「丢一组补一批」，主循环为双层 while 配合异步等待。

过滤器是可插拔函数，签名 (args, samples, **kwargs) -> DynamicFilterOutput，经 --dynamic-sampling-filter-path 以 import 路径加载。DynamicFilterOutput 含三字段：keep 决定去留，reason 仅供日志，keep_when_insufficient 在候选紧张（remaining_batch_size <= target_data_size）时破例保留，避免无限补采；should_drop_dynamic_filter_output 用 <= 与补采门槛对齐，call_dynamic_filter 兼容旧式 bool 返回值。内置 check_reward_nonzero_std 以 1e-6 阈值判零方差，_with_fallback 版在候选紧张时接受零方差组，二者权衡数据质量与补采开销；丢弃原因经 MetricGatherer 汇成 rollout/dynamic_filter/drop_* 指标。
