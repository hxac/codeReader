本讲是智能体 RL 主题的入门与路线图。核心立场是：slime 不为 agent 另起框架，而是把多轮工具调用、沙箱执行、环境反馈作为一类数据生成工作流，接入已有的「rollout → buffer → training」闭环。

关键结论是接口的包裹层级：`data-source` ⊃ `rollout-function` ⊃ `custom-generate`/`custom-rm`/filter。四个主接口越外层越重，覆盖外层会使内层挂载点失效，因此首选 `--custom-generate-function-path` + `--custom-rm-path`；仅当默认 rollout 循环的形状、调度或并发不够用时（全异步、跨轮续传、非「一 prompt 一组采样」）才升级到 `--rollout-function-path`，判据是工作流形状而非 agent 复杂度。

本讲确立的根本原则是训练目标必须保持 token-based：agent 环境虽是字符串/消息/工具观测，但训练序列要用模型实际采样的 token，恪守「string in / token out」契约以避免重分词漂移；`loss_mask` 用 1/0 区分模型生成与 prompt/模板/环境文本。正确性护栏规定：当多轮 prompt 与先前采样输出在 token 层面漂移时，保留上下文但把该段 loss_mask 置 0。fan-out 让一次执行返回 `list[Sample]`，兄弟样本须共享同一 `rollout_id`，总 reward 按 1/K 分摊，使 per-rollout-mean 归约不重复计数。旗舰示例 `coding_agent_rl` 以四阶段（准备→沙箱执行→打分→轨迹导出）示范了 custom-generate + 内联打分 + adapter + fan-out 的完整选型。
