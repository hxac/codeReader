本讲解决 slime 训练后端 Megatron 无法直接读取 HuggingFace（HF）检查点的格式不匹配问题。HF 格式用未切分的 safetensors 存完整张量并附 config.json；Megatron 的 torch_dist 格式则按 TP/PP/EP 并行策略预先分片存储，且 Megatron 不读 config.json，要求命令行显式声明模型结构，因此必须依赖 scripts/models/*.sh 手写结构参数。

核心机制是 model_provider：它是一个「参数→Megatron GPTModel」的工厂，用命令行参数（num-layers、hidden-size、num-experts 等）搭出按并行策略分好片的随机初始化空壳模型。正向转换 convert_hf_to_torch_dist.py 走「借壳」路线：搭空模型→用 load_hf_weights 灌入 HF 权重→Megatron 原生 save_checkpoint 写盘→tracker 标记 release，产物可直接供训练的 --ref-load 使用。反向转换 convert_torch_dist_to_hf.py 在纯 CPU 上运行，用 WrappedStorageReader 与 EmptyStateDictLoadPlanner 安全读取分片，展开折叠的层与专家，去 vocab padding，分块写回 safetensors，并从原 HF 目录拷贝 tokenizer 等资产。

关键术语包括：torch_dist、padded_vocab_size（需用 --vocab-size 去 padding）、按 model_type 分发的 hf_to_megatron/_LOADERS 与 megatron_to_hf/_convert_to_hf_core 注册表、release 终态检查点。核心结论是：正向转换需 GPU 与分布式，反向转换纯 CPU 即可；round-trip 数值一致只证明格式无损，不证明 --rotary-base 等结构参数语义正确，仍需对照 config.json 人工核对。
