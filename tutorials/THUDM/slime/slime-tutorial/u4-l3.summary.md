本讲解答 rollout 产出的变长 Sample 如何被打包成 Megatron 可消费的张量微批。核心是两阶段管线：rollout 端用 build_dp_schedule 一次性、纯 Python 地算好全局调度表（先 first-fit 装箱成微批，再把微批数对齐到 dp_size 的倍数，最后按 strided round-robin 或 Karmarkar-Karp FLOPs 均衡分发给各 rank），从而保证「所有 DP rank 跑相同微批数」这一 PP 同步不变量，并约束同一 rollout 的样本必留同一 step。训练端用极薄的 DataIterator 按既定 micro_batch_indices 逐微批拉数，再由 get_batch 张量化，同时解决三件事：THD 布局用 cu_seqlens/PackedSeqParams 防跨样本注意力泄漏；开启 context parallel 时逐条 zigzag 切片或 allgather_cp 全局等分；loss_mask 左补 prompt_length-1、右补 1 以对齐 next-token 预测的 logit 轴。开 CP 后每条序列约按 1/cp_size 分摊，故 max_tokens_per_gpu 应设为约 max_response_len//cp_size。
