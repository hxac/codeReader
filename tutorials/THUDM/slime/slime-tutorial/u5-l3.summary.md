本讲聚焦 slime 推理引擎接收端，讲解 `SGLangEngine` 这个 Ray actor 的封装与生命周期。核心结论：`SGLangEngine` 只是 SGLang 服务进程的「远程遥控器」——自身轻量，靠 `multiprocessing` 拉起真正的 SGLang HTTP 子进程，通过 HTTP 控制它；采用「构造轻、init 重」两段式，`init` 负责拼 ServerArgs、拉子进程、等健康并注册到 router，多机引擎中仅 `node_rank==0` 作对外控制面。本讲引入的关键术语包括：router（前端负载路由器）、node_rank 早退约定、on-policy、KV cache。引擎侧提供三条权重同步「按钮」——`update_weights_from_tensor`（IPC/NCCL 元数据）、`from_disk`（checkpoint reload）、`from_distributed`（NCCL 通信组），顺序由 Megatron 侧 weight_updater 编排为固定的「pause → flush → 发权重 → continue」四步仪式；换权重前必须先 flush_cache，否则旧权重产出的 KV cache 会与新权重混用，破坏 on-policy 正确性。此外，`abort_server_until_idle` 用「发 abort + 轮询 `/v1/loads`」排空采样中途多余请求，与 flush_cache 均排空在途请求，但不涉及 KV cache、由 rollout 侧触发。
