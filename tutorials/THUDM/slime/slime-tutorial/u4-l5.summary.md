本讲拆解 Megatron 工人初始化的 `init(args)` 与 `get_model_provider_func`。前者建立 TP/PP/CP/EP/DP 通信组（order 默认 `tp-cp-ep-dp-pp`）、设并行感知随机种子（PP 必偏移、DP 可选）、建 tokenizer，并由 `is_megatron_main_rank`（DP、TP 为 0 且 PP 末段）判定指标上报归属。后者把命令行参数翻译成按并行策略分片的 `GPTModel`：先选层规格（`--spec`、MoE block spec 或 TE/local spec）再组装，critic 角色把输出层换成 `LinearForLastLayer(hidden_size→1)` 以输出标量价值——这是 actor 与 critic 的唯一结构差别。定制模型结构有三种入口需分清：`--spec`（换层规格，最常用）、`--custom-model-provider-path`（整体替换模型工厂）、`--custom-megatron-init-path`（仅追加初始化逻辑）。参数冻结由 `freeze_model_params` 用互斥的白名单 `--only-train-params-name-list`（先全冻再解冻）与黑名单 `--freeze-params-name-list`（按 `re.search` 子串匹配）完成，于模型搭好、优化器建之前生效，故优化器只收到 `requires_grad=True` 的参数。
