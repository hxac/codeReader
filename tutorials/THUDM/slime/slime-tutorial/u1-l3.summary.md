本讲围绕 slime 的环境搭建，核心矛盾是：slime 自身只是纯 Python 包，却必须与一组被精确定版的 CUDA 原生库共存。由此提供三条安装入口——官方 Docker 镜像（首选，依赖与补丁开箱即用）、build_conda.sh（无 Docker 时从零构建等价 conda 环境）、pip install -e . --no-deps（仅在已有镜像里升级 slime 源码）。setup.py 声明包名 slime、版本 0.3.1、要求 Python 不低于 3.10，打包范围限定 slime* 与 slime_plugins* 两棵包树，依赖直接读取 requirements.txt。该清单只收录纯 Python 依赖，刻意排除 torch、SGLang、Megatron-LM、flash-attn 等重型 CUDA 库——它们由 Dockerfile 与 build_conda.sh 统一锁定为黄金组合（如 torch+cu129、sglang v0.5.15）。安装采用两步法：先装纯 Python 依赖，再以 --no-deps 装 slime，防止 pip 重新解析依赖而覆盖已锁定的原生库。Megatron-LM 既可经可编辑安装被 import，也可用 PYTHONPATH 定位源码树，并与 SGLang 一同打 docker/patch 下的临时补丁。
