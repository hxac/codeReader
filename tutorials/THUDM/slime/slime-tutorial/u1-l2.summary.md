本讲绘制 slime 源码导航地图，只解决「代码放哪里、各目录如何关联」。仓库核心包为 `slime/`（框架本体）与 `slime_plugins/`（模型/缓冲区插件），由 setup.py 打包为第一方可 import 代码；其余 `scripts/`（启动脚本与模型参数）、`tools/`（权重转换与性能剖析）、`examples/`（自定义接口范例）、`tests/`、`docs/` 为不被 import 的外围资源。

`slime/` 用五大子包切分关注点：`ray/` 编排层（用 Ray 分配 GPU、建工人、暴露统一接口）、`backends/`（`megatron_utils/` 训练 + `sglang_utils/` 推理两个后端，文件最多）、`rollout/` 数据生成层（采样、算奖励、过滤、产出训练样本）、`utils/` 共享工具与参数中枢、`agent/` 智能体运行时。程序入口是根目录的 `train.py`（同步循环）与 `train_async.py`（异步，开头断言非 colocate），二者都很薄，只做解析参数→调 `slime/ray/` 装配工人→跑训练循环。

关键术语包括：核心包、子包、入口文件、编排层、后端、数据生成层、插件。`slime/utils/arguments.py` 的 `parse_args` 是参数中枢，合并 Megatron/SGLang/slime 三族参数，各 `backends/*/arguments.py` 定义后端专属参数。`slime/__init__.py` 为空，表明框架不在包级别持有全局状态，一切由入口脚本显式 import 装配，读源码须从入口顺着 import 往里看。
