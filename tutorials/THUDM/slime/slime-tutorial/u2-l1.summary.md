本讲是 slime 源码阅读的「地图课」，确立三大模块构成的全局框架。slime 把 RL 训练切成三个职责清晰的模块：**rollout（采样，SGLang+router 实现）** 用当前模型生成新数据并计算 reward；**training（训练，Megatron 实现）** 用这些数据更新权重；**data buffer（桥梁，纯 Python）** 管理数据流转，避免两模块直接耦合。三者串成闭环：rollout 产 **Sample**（含 prompt、tokens、loss_mask、reward 等，是闭环流动的核心数据载体，u3-l1 详述）→ data buffer 经 `_convert_samples_to_train_data` 转成训练张量 → training 消费 → 训练后同步权重回 rollout，每轮重复。`train.py` 主循环极薄，`generate / async_train / update_weights` 三步每轮必做。两个关键结论：一是**权重同步是 training→rollout 单向**——因 on-policy 要求下真理之源在 training、rollout 权重只是副本，反向写回会污染优化器；二是 slime **刻意只选 SGLang 单一 rollout 后端**（SGLang-native），不做多后端抽象以无损复用其全部能力。后续讲义按 Ray 编排、三大对象、Sample 结构、权重同步实现逐层展开。
