本讲解决 slime「谁用哪几张卡」的资源编排问题，源码聚焦 `slime/ray/placement_group.py`。核心机制是用**一个 placement group（放置组）**装下所有卡，靠 `rollout_offset` 把 bundle（资源束）列表切成 actor/rollout 两段，配合 PACK 策略原子预约、挤在同机以降低跨机通信。

关键术语：bundle（声明「要几张卡」的单位）、placement group（把 bundle 打包原子预约的容器）、PACK（挤同一台机器的摆放策略）、InfoActor（声明 `num_gpus=1` 的临时探针，探测每张卡的「节点 IP＋物理 GPU 编号」后立即 kill）、needs_offload（标记推理引擎组是否与训练卡重叠）。

`_get_placement_group_layout` 是分配大脑，用 if/elif 把普通分离 / colocate / debug_train_only / debug_rollout_only / rollout_external 五种模式收敛为 `(num_gpus, rollout_offset)` 二元组。colocate 的实现极简：`rollout_offset=0` 让 actor 与 rollout 指向同一段 bundle（同一批物理 GPU），省卡但必然导致 `needs_offload=True`——推理引擎起始槽位落入训练区间时必须轮流释放显存，否则 OOM（该判定在 `rollout.py` 按引擎组精确计算）。探测结果按「节点＋GPU」重排，得到稳定的「逻辑 rank→物理 GPU」映射；等待就绪用每 30s 轮询打日志避免静默挂死；critic 直接复用 actor 同组卡，靠 offload_train 时分复用（故 PPO 会强制开启 offload）。
