slime 把测试与 CI 分两层：常驻 CPU 层（cpu-unittest、agent-test，无需标签、不抢 GPU、每次 PR 必跑）负责快速拦下不变量；标签触发的 GPU e2e 层（run-ci-megatron 等）在 Docker 容器里跑真实 Megatron+SGLang 训练流程。两者各自独立——pytest 的 marker（管跑哪些用例）与 GitHub 的 label（管跑哪个 CI 任务）是两套机制。pyproject.toml 是 pytest 中枢，用 testpaths、norecursedirs 和 --strict-markers 控制测试发现，未声明的标签启动即报错。本讲核心是 plugin 契约测试：tests/plugin_contracts/ 下四个文件分别守护 custom_generate、rollout_function、runtime hook、path loading+custom_rm 四类 hook 的「形状契约」，靠 _shared.py 的桩模块在纯 CPU 上运行。它做三层断言：inspect.signature 比对参数顺序、用假数据真调一次校验返回结构、对 runtime hook 额外读框架源码文本确保调用点字符串未被重构掉。配合 SLIME_CONTRACT_* 环境变量与 load_function，工程师几秒、无 GPU 即可自检自定义函数形状是否合格，但契约测试只保证「不会被框架咬」，不保证语义正确。
