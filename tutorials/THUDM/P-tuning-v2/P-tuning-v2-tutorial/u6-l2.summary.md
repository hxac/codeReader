本讲承接模型注册表路由（u3-l2），精读注册表里两类尚未展开的任务模型。**多选题（Multiple Choice）** 采用「折叠→打分→还原」三步：将 `(batch, num_choices, seq)` reshape 成 `(batch*num_choices, seq)`，用 `Linear(hidden,1)` 给每个候选拟合一个标量分，再 `reshape(-1, num_choices)` 成组做交叉熵。关键在于前缀注入时 `get_prompt` 的 batch 维须取 `batch_size*num_choices`，主干眼中即一个普通大 batch，注入逻辑与单句分类逐字相同。**Token 分类（Token Classification）** 输出逐 token 的 `(batch, seq, num_labels)` logits，用 `active_loss = attention_mask.view(-1)==1` 配合 `torch.where` 将 padding 标签置为 `-100` 屏蔽；并独有一行 `attention_mask[:, pre_seq_len:]` 切掉注入时拼上的前缀段，使掩码与逐 token 损失对齐。贯穿全讲的结论是：`get_prompt`（`view→permute→split` 重排）被三类任务原样复制，体现深度提示调优的任务无关性，任务差异仅在头输出维度与损失对齐方式；浅层 Prompt 版的 `get_prompt` 只返回普通嵌入、拼进 `inputs_embeds`，不做逐层注入。
