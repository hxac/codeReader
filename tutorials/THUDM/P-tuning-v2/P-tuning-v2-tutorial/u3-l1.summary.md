本讲专讲 P-tuning v2 的「配置流转」管道：命令行字符串如何变成模型构造时可读的 config 对象。核心机制是 HfArgumentParser 把四个 @dataclass 类自动翻译成命令行参数，get_args() 解析后按固定顺序返回四元组 (ModelArguments、DataTrainingArguments、TrainingArguments、QuestionAnwseringArguments)，全系统据此解包；其中 TrainingArguments 复用自 transformers，choices 校验借自 tasks/utils.py 的 TASKS/DATASETS 注册表。P-tuning v2 三大开关均定义在 ModelArguments：--prefix 总开关、--pre_seq_len 前缀长度、--prefix_projection 是否加 MLP 头，后两个为不带值的开关型参数。最关键的结论是：args（运行设定）与 config（模型结构描述，AutoConfig）是两套分离的对象，--pre_seq_len 不会自动进模型；必须在 get_model() 里把 model_args 的前缀字段手动「粘」到 config 上，模型 __init__ 与 PrefixEncoder 才读得到。三种模式对 config 写入量不同：深度前缀写四字段并走 PREFIX_MODELS，浅层 prompt 仅写 pre_seq_len 走 PROMPT_MODELS，全量微调不写走 AUTO_MODELS；--prefix 本身只起路由作用、不进 config。下一讲将展开这三张注册表与 TaskType 的二维路由。
