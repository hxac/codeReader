本讲对比 P-tuning v2 仓库中三种调优模式的实现差异。`get_model` 作为模型工厂，通过命令行开关路由：`--prefix` 查 `PREFIX_MODELS`（深层注入），`--prompt` 查 `PROMPT_MODELS`（浅层提示），都不加则查 `AUTO_MODELS`（全量微调），且 `prefix` 优先级高于 `prompt`。核心对比在于「提示如何进入网络」：深层 Prefix 用 `PrefixEncoder` 生成每层 key/value，经 `past_key_values` 逐层注入，照常传 `input_ids`、直接用 `outputs[1]`；浅层 Prompt 用普通 `nn.Embedding` 生成提示向量，拼进 `inputs_embeds` 仅在嵌入层注入，并须切掉提示段后手工重建 pooler（取真正的 `[CLS]`）。引入的关键概念包括：深层注入与浅层提示、`past_key_values`、冻结主干、`inputs_embeds` 拼接、pooler 切片重建。可训练参数量排序为：全量微调 ≫ 深层 Prefix（带 MLP）> 深层 Prefix（无 MLP）> 浅层 Prompt，后两者前缀参数比约为 1/(2L)。三种模式的参数打印位置与措辞各异：深层 Prefix 在模型 `__init__` 内打印（不带星号），全量微调在 `get_model` 内打印（带星号），浅层 Prompt 不打印。`PROMPT_MODELS` 任务覆盖面明显窄于 `PREFIX_MODELS`，印证深层 Prefix 才是本项目重点。
