本讲提出任何 PyTorch 训练工程都是五段流水线：数据获取、预处理、模型构建、训练循环、评估与保存，并精读第 13 章燃油效率回归与 MNIST 分类两个完整项目，二者骨架逐段同构，是拆分复用的直接证据。torch.save 有两条路线：整模型保存经 pickle 序列化对象与类引用，加载端必须能 import 到模型类，代码重构后易失效；state_dict 只存「参数名→张量」的有序字典，加载端先搭同名同形骨架再注入参数，为官方推荐，其键名由子模块属性路径与参数注册名拼成。张量携带 device 信息，跨设备加载需用 map_location 指定落点，推理时模型与输入须同设备。工程化按函数化、模块化、notebook 只做组装三步推进，拆出模型构建、数据加载、训练循环三类工具。checkpoint 存档可含优化器状态以断点续训，为下一讲 Lightning 与 Ignite 等高层训练框架铺垫。
