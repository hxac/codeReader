本讲是第13章收官，用同一个MNIST多层感知机对比原始PyTorch、Lightning与Ignite三种训练写法。Lightning把单批训练、验证、测试与优化器选择写成LightningModule的training_step等方法，梯度三件套由Trainer代劳；LightningDataModule以prepare_data、setup和dataloader方法统一数据准备，是唯一真正切出独立验证集的版本；ModelCheckpoint按valid_acc键保留最佳存档，trainer.test(ckpt_path='best')自动加载测试。torchmetrics指标以update/compute/reset三段式累计按样本加权的整体准确率。Ignite核心是Engine封装循环、Events触发事件、handler挂回调，create_supervised_trainer/evaluator可搭出带日志、checkpoint与TensorBoard的流程。结论：框架价值在把验证、存档、续训、日志等工程项标准化而非省行数；Lightning藏循环、Ignite露循环，选型看控制粒度（仓库基于Lightning 1.5.0，2.x API有变动）。
