本讲承接 u8-l1，讲三件事。一、对照迁移：Lightning 版保留纯 PyTorch 模型本体，约定类名 PyTorchModel、forward 只返回 logits；设备搬运与手写双层训练循环由 Trainer 接管，手写准确率换成 torchmetrics.Accuracy；DataModule 用 random_split 新增验证集，ModelCheckpoint 按验证准确率存最优。口诀：抄模型、删循环、包 LightningModule、换 DataModule、一行 fit。二、模板化：所有 Lightning notebook 是同一份分类模板的填空实例，唯一模型入口是 UNIQUE MODEL CODE 占位 cell；模板 %load 引用的共享代码目录已不存在，需从现役 notebook 复制对应代码段。三、脚本化：tune 脚本是模板的命令行版，三件套逐字相同，超参改由 argparse 传入（learning_rate 误写 type=int 是真实坑点），deterministic=True 保逐位复现，配 grid run 展开超参网格扫描。另注意两版 cnn-basic 配方（优化器、学习率、epoch 数）不对齐，97.97% 对 98.79% 的差异不能归因于框架。
