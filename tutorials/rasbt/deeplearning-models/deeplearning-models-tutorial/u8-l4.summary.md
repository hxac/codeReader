本讲以 NiN 顺序模型（23 个子模块）为载体讲解梯度检查点（gradient checkpointing）。训练显存中参数、梯度、优化器状态为常数，中间激活随层数×batch size 线性膨胀才是优化对象。核心思想是「用重计算换显存」，折中两个极端：vanilla 反传保存全部激活（显存 O(n)），low-memory 全靠反向重算（计算 O(n²)）；最优策略是每 √n 层设一个检查点，得 O(√n) 显存、多约一次前向。实践上用 `checkpoint_sequential` 包装顺序模型，关键坑是段输入须设 `x.requires_grad = True`（否则参数无梯度），Dropout 一致性由保存 RNG 状态保证，`segments` 是显存-时间旋钮。核心结论：检查点不改变训练数学，两版逐 batch 损失完全一致；实测峰值内存约降两成、耗时约增一成半；注意 `tracemalloc` 仅测 Python 堆，GPU 显存应以 `torch.cuda.max_memory_allocated()` 实测。下一讲 u8-l5 转向多 GPU 并行。
