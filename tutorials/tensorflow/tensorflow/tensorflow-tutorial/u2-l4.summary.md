本讲围绕 `python.framework.ops` 讲清 Operation 与 Tensor 的对象关系：一个 Operation（op）消费若干输入 Tensor、产出若干输出 Tensor，二者是「生产者—产品」关系；op 的 inputs/outputs 与 tensor 的 op/value_index 互为**双向链接**，是自动微分、图优化的地基。核心结论是：用户眼中的 tf.Tensor 并非单一类，而是 `tensor.py` 中抽象基类 `tensor_lib.Tensor` 的两种实现——图模式为 `ops.py` 的 `SymbolicTensor`，Eager 模式为 `_EagerTensorBase`/`EagerTensor`，二者共享基类以对外提供一致 API。属性实现分两处：`inputs` 在 Python（带 `_inputs_val` 惰性缓存），`outputs`/`name`/`type` 在 C++ 桥接层 `tf_session_wrapper.cc`，体现「Python 做策略，C++ 做数据」；op 创建时传入张量工厂 `SymbolicTensor` 以逐个造出输出。此外 `a+b` 等运算符经 `_override_operator` 接线变为构造 op 的调用。引入术语：Operation、SymbolicTensor、EagerTensor、C 扩展类型、双向链接、张量工厂、运算符重载。
