本讲承接 u6-l1（Device/DeviceFactory），解决「op 张量内存由谁分配、如何回收」。三个最小模块：其一，`Allocator` 抽象在「设备」之上再套一层分配接口，op 仅经 `OpKernelContext` 调 `AllocateRaw/DeallocateRaw`，由 `AllocatorAttributes`（`on_host` 等）路由到 CPU 或 GPU 分配器；真正向系统/GPU 驱动申请大块内存的是 `SubAllocator`，其 `SupportsCoalescing()` 决定相邻内存能否视作连续。其二，`AllocatorFactoryRegistry` 用静态全局对象 + `REGISTER_MEM_ALLOCATOR` 宏在启动期按 name/priority 自动注册工厂，运行期取优先级最高者，与 DeviceFactory 同构。其三，`BFCAllocator`（best-fit with coalescing）是 arena 分配器，以 `AllocationRegion` 反查指针、`Chunk`（边界标记双向链表）描述块、`Bin`（21 个 size-class 桶）索引空闲块：分配走「取整→算桶→best-fit→切分」，逐级降级至 Extend、紧急合并、垃圾回收；释放走「置空闲→与邻居合并→入桶」。核心结论是释放即合并修复外部碎片，缓解碎片三手段即分级桶、coalescing、GC；GPU OOM 多由碎片而非真实显存不足，关键旋钮为 `TF_FORCE_GPU_ALLOW_GROWTH`、`TF_ENABLE_GPU_GARBAGE_COLLECTION`。引入术语：Allocator、SubAllocator、AllocatorAttributes、arena/pool、外部/内部碎片、best-fit、coalescing、Chunk/Bin/AllocationRegion、kMinAllocationSize(256)、`AllocatorStats`、timestamped_chunks 与 safe_frontier（异步安全）。
