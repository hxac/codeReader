本讲讲解 tf.function 如何在 Eager 之上重新引入图。`@tf.function` 将普通 Python 函数包装成 `Function`（多态函数 PolymorphicFunction），是对外的可调用对象；规格点名的 `def_function.py`、`function.py` 已退化为 shim，真实实现位于 `polymorphic_function/` 目录。`Function` 内部持有 `FunctionCache`，按输入类型管理多个 `ConcreteFunction`；每个 `ConcreteFunction` 绑定一张 `tf.Graph`，并区分推理函数与前向/反向函数对。核心动作 tracing：在临时图模式下跑一遍 Python 函数，op 登记为图节点，纯 Python 副作用只在追踪时发生一次。缓存命中由 `TraceType` 决定——张量按 dtype 加形状归类，Python 值按 `Literal`（值相等且不可泛化）归类，这是「同形状复用、不同 Python 值重追踪」的根因。执行链路为 `__call__`→`_call`（首次 `_initialize`）→`_maybe_define_function`（先查缓存、未命中才建图）→`_call_flat`（送入 C++ 原子函数）。`run_functions_eagerly` 可绕过建图用于调试。
