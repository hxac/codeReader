本讲承接 Keras 高层 API，揭示 `optimizer.minimize(loss, vars, tape=tape)` 这一行如何把 loss 变成变量更新，覆盖两个最小模块：Keras 新版优化器基类 `OptimizerV2` 与旧版 `tf.compat.v1.train.Optimizer`。核心结论：Optimizer 的对外接口是两段式——`compute_gradients`（求梯度，本身不重写微分，只消费 GradientTape 的产物）与 `apply_gradients`（把梯度写回变量），`minimize` 仅把两者串联；TF2 鼓励用户自开 GradientTape 再调 `apply_gradients`，以便中间插入梯度裁剪等加工。关键术语包括：`OptimizerV2` 维护的三类状态——步数计数器 `iterations`、为每个主变量惰性创建的 slot 槽位变量（如 Adam 的一阶矩 `m`/二阶矩 `v`，`trainable=False` 且与主变量同设备）、以及由 `_set_hyper`/`_get_hyper` 统一管理的 hyper 超参数（学习率、β，支持 LearningRateSchedule）。真正的参数更新发生在子类必须实现的 `_resource_apply_dense`/`_resource_apply_sparse` 中：Adam 稠密路径调融合 kernel `ResourceApplyAdam`，稀疏路径手写 `assign`+`scatter_add`，二者实现同一套 m/v/θ 公式与偏差校正。旧版 V1 则以 processor 抽象、`_finish` 收尾、`gate_gradients` 与外部 `global_step` 组织更新；V2 删除这些为图模式/ref variable 服务的机制，将状态统一纳入 Trackable 体系。在训练流水线中，`Model.train_step` 把已打开的 GradientTape 连同 loss/变量传给 `minimize`，贯通「前向→反向→更新→度量」四拍。后续讲义将承接 `_distributed_apply`、`colocate_vars_with` 等进入设备抽象与分布式策略。
