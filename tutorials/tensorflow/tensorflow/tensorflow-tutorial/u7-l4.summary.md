本讲讲解 TFRT（TensorFlow Runtime）新一代运行时，对照传统 `DirectSession`，回答「它想解决什么、如何跑图」。TFRT 的设计目标是异步优先、可组合、与 op 解耦并支持渐进迁移，以替代单体、同步、与 op 强耦合的 `DirectSession`。核心链路为 `Runtime → TfrtSession → GraphExecutor → runtime_fallback`。

引入的关键术语包括：`AsyncValue`（尚不可用、将来填充的异步数据单元，TFRT 异步优先的基础）；`BEF`（字节码执行格式，把图预编译成可序列化产物）与其后继 `MLRT` 字节码（进程内解释器，由 `enable_mlrt` 开关二选一）；`fallback`（回退机制）。

最小模块四块：`tfrt_stub::Runtime` 是 TF 侧运行时抽象，包装上游 `tfrt::CoreRuntime` 并经 `WorkQueueInterface` 复用 TF 线程池；`TfrtSession` 是适配层，伪装成普通 `Session`，其 `AcceptsOptions` 与 `DirectSession` 互补，仓库默认仍走 DirectSession、TFRT 需 `use_tfrt()` 或 `target="tfrt_session"` 显式开启；`GraphExecutor` 负责 `GraphDef → MLIR → BEF/MLRT` 的编译，按 `joined_name` 缓存子图并可据运行时代价重编译，体现「编译期与执行期分离」；`runtime_fallback` 经 `KernelFallbackExecute` 与静态注册的 fallback kernel，让无原生 kernel 的 op 透明回退到老 `OpKernel::Compute`。核心结论是：BEF 执行器以字节码解释 + 异步数据流替代了 `DirectSession` 的同步拓扑序调度，fallback 则保证渐进迁移不必等全部 op 重写即可上线。
