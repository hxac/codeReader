本讲承接 DirectSession 的执行链路与 Device 抽象，解析 TFRT（TensorFlow Runtime，独立仓库 @tf_runtime）这一以异步数据流为核心的「新一代运行时」，覆盖三个最小模块：core.tfrt.runtime、core.tfrt.tfrt_session、core.runtime_fallback，并以 core.tfrt.graph_executor 作中间层。核心结论是：TFRT 想解决 DirectSession 同步模型固化、执行器与设备/算子强耦合两大痛点，策略是「调度归 TFRT、计算归既有 OpKernel」，从而渐进迁移而非推倒重来。引入的关键术语包括：HostContext（资源根）、ConcurrentWorkQueue（异步任务队列，由 TF 线程池适配）、AsyncValue（可在未就绪时被引用的异步值）、CoreRuntime（持有 HostContext 与一组 OpHandler 的运行时中枢）、OpHandler（细粒度后端抽象）、BEF（MLIR 图序列化的二进制格式）、MLRT（TF 自实现的 MLIR 字节码解释器，与 BEF 执行器并列的过渡引擎）。落地路径为：tfrt_stub::Runtime 包装 CoreRuntime 提供进程级单例；TfrtSession 经 SessionFactory 注册为「tfrt_session」，透明替换 DirectSession；GraphExecutor 把 GraphDef 经 Placer/Grappler 优化后导入 MLIR，编译成 BEF 或 MLRT 字节码，按输入输出名缓存 LoadedClientGraph，并在加载期跑 _tfrt_fallback_init / _tfrt_resource_init 预创建回退 op 以实现热路径零开销；FallbackState 按模型实例持有 DeviceMgr/函数库/PFLR，与进程级 Runtime 形成「模型级 vs 进程级」分离。
