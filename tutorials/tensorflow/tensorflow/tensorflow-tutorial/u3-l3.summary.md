本讲讲解 TF2 默认的 Eager（即时）执行模式及其核心运行时 Context。首先区分两种模式：Graph 模式下 op 调用仅在建图中登记节点，需 Session.run 才执行；Eager 模式下 op 一被调用即执行并返回真实数值的 EagerTensor。分叉点位于代码生成器为每个 op 产出的 `if tld.is_eager:` 判定，命中则走立即执行快路径。其次介绍 Context：它是进程级单例，扮演「常驻 Session」，持有 C++ 执行器句柄、当前设备与作用域状态，采用延迟初始化加双重检查锁，仅在 ensure_initialized 时才创建 TFE_Context。「是否 Eager」由线程局部的 is_eager 决定，可用 graph_mode/eager_mode 上下文管理器临时切换并恢复。最后讲解 execute.py 的 quick_execute（别名 execute）：取设备、ensure_initialized 后通过 pywrap_tfe.TFE_Py_Execute 把单个 op 立即派发到 C++ 内核并返回 EagerTensor，是 Python 与 C++ Eager 内核的最终跨语言桥；它显式传入 num_outputs 以避免注册表查询开销，并将 C++ 状态异常翻译为用户友好的 TF 异常。本讲为后续 tf.function（Eager 与 Graph 的桥梁）与自动微分（GradientTape 替换 must_record_gradient 桩）埋下伏笔。
