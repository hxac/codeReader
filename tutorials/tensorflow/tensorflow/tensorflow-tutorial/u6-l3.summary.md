本讲深入 TensorFlow 执行链路中的「优化」阶段，讲解 Grappler 图优化子系统如何在图被执行前将其等价改写为「算得更少、更快」的图。Grappler 工作在扁平的 `GraphDef`（`NodeDef` 列表）层，运行时机位于「放置之后、分区之前」，接入点是 `GraphExecutionState::OptimizeGraph` 调用的 `RunMetaOptimizer`。其架构采用**策略模式 + 流水线**：抽象基类 `GraphOptimizer` 定义统一 `Optimize()` 接口，总调度器 `MetaOptimizer` 依据 `RewriterConfig` 把数十个优化器（常量折叠、算术化简、布局优化、remap 融合等）串成流水线依次运行，并支持不动点迭代与 deadline 超时保护。输入封装为 `GrapplerItem`（含 feed/fetch 与 `NodesToPreserve()` 安全边界），导航工具 `NodeMap` 建立「名字→节点」「节点→消费者」索引以维护 fanout。本讲重点剖析最典型的**常量折叠**：将「输入全常量、无副作用、输出不过大」的节点，**通过在 CPU 上真正实例化 OpKernel 并跑一遍 `Compute` 求值**（`EvaluateNode`），替换为内嵌结果的 `Const` 节点，并以 BFS 级联传播至不动点；安全性由保守判定函数 `MaybeFoldable`/`IsFoldableUncached`（排除随机数等副作用节点、控制流、placeholder 及超 `kMaxConstantSize` 者）保障。最后辨析了仓库两套常量折叠：grappler 的 `ConstantFolding` 类（基于 `GraphDef`、功能完备、TF2 主力）与 common_runtime 的 `ConstantFold` 函数（基于运行时 `Graph*`、更早期轻量），二者共享「用 CPU OpKernel 求值」的核心思想。
