本讲拆解 tf.data 输入流水线源码。核心结论：Dataset 不是数据容器，而是「如何产出元素的描述」——每个变换返回一个新 Dataset，从而支持链式组合；整条流水线底层是一棵以只读 `_variant_tensor`（DT_VARIANT 张量）为根的 op 子图，即 Python 描述与 C++ 运行时之间的接线点。三个最小模块：抽象层 dataset_ops.py 中 DatasetV2 强制实现 `element_spec`，并以 DatasetSource、UnaryDataset、UnaryUnchangedStructureDataset 等骨架类归纳源头与变换范式；map/batch/prefetch 只是 DatasetV2 上的薄壳，实现在各自的 `*_op.py` 并各调一个 `gen_dataset_ops.*`（方法内延迟导入以打破循环依赖），三者差异归根结底是 element_spec 如何计算——prefetch 透传结构、batch 给每个分量加一维（drop_remainder=False 时最外维为 None）、map 由用户函数返回值决定；捕获函数机制中，map(f) 里的 f 经 StructuredFunctionWrapper 追踪成 ConcreteFunction，C++ 侧 CapturedFunction（静态：函数与捕获张量）和 InstantiatedCapturedFunction（运行时绑定句柄）配合，在每次取元素时把当前元素与闭包捕获的外部张量一并送进函数执行。关键术语：`_variant_tensor`、`element_spec`、UnaryDataset、`captured_inputs`、AUTOTUNE、CapturedFunction，承接 u3-l4 的 tf.function 机制。
