本讲承接 u1-l1 的「定位—构建—语言入口」方法，建立对 TensorFlow 仓库的整体空间感。核心结论有四：其一，仓库顶层可划分为三大区域——源码区 `tensorflow/`、外部依赖区 `third_party/`、工具与基础设施区（`tools/`、`ci/`、`configure.py`、构建脚本）。其二，`tensorflow/` 内部按**语言层**细分：`core/` 是 C++ 核心地基（图、运行时、op/kernel、分布式），`python/` 是 Python API 实现，`c/` 为语言无关的 C API 边界，`cc/` 是建在核心之上的 C++ 客户端，`compiler/` 负责 MLIR/XLA 编译加速，`lite/` 面向移动端推理；README 明确**仅 Python 与 C++ 是稳定 API**，对应 `python/` 与 `core/public/`。调用栈呈自底向上（python→c→core，compiler、lite 为支线）。其三，依赖管理双轨并存：传统 `WORKSPACE` 与实验性 `MODULE.bazel`（Bzlmod）负责「点名」，`third_party/` 负责「出力」（下载、补丁、BUILD 模板），二者对外仓库名均为 `org_tensorflow`。其四，给出定位功能的两步法：先判语言层选目录，再用 Glob 按文件名、Grep 按内容（如 `REGISTER_OP`、`@tf_export`）精确定位。本讲引入的关键术语（三大区域、语言层、BUILD 目标、Bzlmod、`REGISTER_OP`、`@tf_export`、org_tensorflow）将贯穿后续讲义。
