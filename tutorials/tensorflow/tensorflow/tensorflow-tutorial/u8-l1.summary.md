本讲讲解 TFLite 作为面向移动/嵌入式单设备推理的轻量运行时：它主动舍弃桌面端 DirectSession 的多设备放置、图分区、异步 Executor 与全局 OpRegistry，换来小体积、低内存与 FlatBuffer mmap 零拷贝。最小模块有二：一是「四件套」推理架构——FlatBufferModel 把 .tflite mmap 成只读模型，InterpreterBuilder 配合 OpResolver 解析算子、装配 Interpreter，再由 AllocateTensors 做内存规划（昂贵、一次性），Invoke 按扁平 execution_plan 顺序遍历各算子（廉价、可重复）；二是两层 C 边界——common.h 用扁平 C struct（TfLiteTensor、TfLiteNode、TfLiteContext、TfLiteRegistration，算子即 init/prepare/invoke 一组 C 函数指针）定义运行时↔算子的内部契约，c_api.h 以 TfLiteModel、TfLiteInterpreter 等不透明指针提供稳定 ABI 边界。核心结论：Interpreter 仅是门面，真正存张量、遍历算子的是它持有的 Subgraph，其自身核心状态为 TfLiteContext；新引入的术语（FlatBufferModel、OpResolver、Subgraph、arena、execution_plan、不透明 ABI）将在后续讲义中承接。
