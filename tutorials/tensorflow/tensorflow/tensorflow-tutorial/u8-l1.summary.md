本讲讲清 TFLite 作为移动/嵌入式单设备推理运行时的轻量定位：它放弃桌面端 DirectSession 的多设备放置、图分区、异步 Executor 与全局注册表，换得小体积、低内存与 FlatBuffer 的 mmap 零拷贝。推理由四件套完成：FlatBufferModel 经 InterpreterBuilder 配合 OpResolver（把 op code 解析为 TfLiteRegistration）装配成 Interpreter，再由 AllocateTensors 做形状推导与 arena 内存规划、Invoke 按 execution_plan 顺序遍历算子。Interpreter 只是门面，真正存张量、遍历算子的是它持有的 Subgraph，其核心状态为纯 C 的 TfLiteContext。common.h 定义运行时与算子之间的内部 C 契约（TfLiteTensor、TfLiteNode、TfLiteContext 与 TfLiteRegistration 的 init/prepare/invoke 函数指针），c_api.h 则以不透明指针构筑应用与运行时之间的稳定 ABI 边界。AllocateTensors 是昂贵的分水岭，Invoke 是廉价可重复的纯遍历。
