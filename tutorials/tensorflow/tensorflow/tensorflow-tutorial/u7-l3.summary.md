本讲讲 TensorFlow 的 JIT 自动聚类（auto-clustering）：在全局 JIT 开关（`--tf_xla_auto_jit` 或 ConfigProto 的 `global_jit_level`，经 `GetGlobalJitLevelForGraph` 解析，区分单 GPU / 一般等级）开启时，自动把相邻的、XLA 认得的 op 圈成簇（cluster）整体编译，以获得融合收益。流水线注册在 `POST_REWRITE_FOR_EXEC` 阶段，两端是两个锚点：`MarkForCompilationPass(10)` 决定「圈谁」并写 `_XlaCluster` 属性（聚类记账本，由 `GetXlaClusterForNode`/`GetXlaAutoClusteringSummary` 读取）；`BuildXlaOpsPass(60)` 把经 `EncapsulateSubgraphsPass(50)` 封装好的簇物化成 `_XlaCompile`/`_XlaRun`。聚类分两步：`RecursiveCompilabilityChecker` 的 `HasXLAKernel` + `OperationFilter` 筛候选，再由 `RunEdgeContractionLoop` 用边收缩（`TryToContractEdge` 把关死活谓词、设备、作用域、规模、资源变量安全）经三阶段启发式得到极大聚类。核心是「尽力而为」的两套退路：聚类阶段无 XLA kernel 的 op 不进簇并切断两侧；运行阶段懒模式用 `Switch`/`_XlaMerge` 在编译成功（走 `_XlaRun`）与失败（退回 `StatefulPartitionedCall`）间二选一，`cannot_compile_cluster_` 缓存失败避免重试。`_XlaCompile`/`_XlaRun` 与严格/懒编译模式是后续讲义理解 XLA 运行调度的关键。
