本讲讲解 TF 的「自动聚类」机制：在图执行前自动把连续可编译 op 合并成 XLA 簇单独编译，簇外 op 照常用 TF 原生 kernel 执行。聚类由三个注册于 POST_REWRITE_FOR_EXEC 阶段（放置后、分区前）的 pass 接力完成：MarkForCompilationPass(10) 判定并给节点打 _XlaCluster 属性、EncapsulateSubgraphsPass(50) 把簇封装成函数并打 _XlaCompiledKernel、BuildXlaOpsPass(60) 改写为 _XlaCompile+_XlaRun。本讲聚焦 build_xla_ops_pass 与 xla_cluster_util 两个模块：前者按严格/惰性两条路径改写，惰性路径用 Switch+_XlaMerge 保留一条 TF 原生退路；后者提供簇属性读写、处理 while 循环的环检测、全局 JIT 等级判定、ref 变量安全分析等公共工具。一个 op 进簇需过设备、策略等级、递归可编译、特殊排除四关且簇达最小规模；不支持时编译期不进簇、运行期经 _XlaMerge 透明回退。整体是尽力而为、对用户透明的加速机制。
