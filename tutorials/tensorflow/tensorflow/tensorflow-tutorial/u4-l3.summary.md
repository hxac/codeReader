本讲围绕 `core/ops/` 目录展开：它是 Op 的「声明层」，只声明输入/输出/属性与形状推导函数，不含任何计算代码。`.SetShapeFn(fn)` 把类型为 `OpShapeInferenceFn`（即 `absl::Status(InferenceContext*)`）的函数存入 `OpRegistrationData`，挂到全局 `OpRegistry`。形状函数以 `InferenceContext` 为工具箱，读取输入静态形状、常量值与属性，用一套形状代数（Concatenate/Subshape/Merge 及维度级 Add/Divide）算出输出并 `set_output`，遇未知维度则「尽力而为」返回带秩的部分已知形状。可复用库 `common_shape_fns`（UnchangedShape、ScalarShape、BroadcastBinaryOpShapeFn、ConcatShape 等）把常见规则抽成积木供数十个 op 共享。最核心结论是：形状推导必须在不执行 kernel 的前提下完成，故与 `core/kernels/` 的计算实现仅靠 op 名字松耦合、互不调用；它由 `ShapeRefiner::RunShapeFn` 在建图/tracing 期调用，服务于类型检查、Grappler 优化、MLIR/XLA 编译与自动微分——这些阶段都远早于 kernel 执行。
