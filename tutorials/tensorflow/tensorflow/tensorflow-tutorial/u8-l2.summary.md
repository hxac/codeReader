本讲承接 u8-l1，回答两个问题：`.tflite` 如何存算子、运行时如何把文件记录映射到 C 函数指针。它覆盖四个最小模块：FlatBuffer 模型格式、`OpResolver` 查表抽象、`MutableOpResolver` 实现、`flatbuffer_conversions` 参数翻译。核心结论：`.tflite` 用 FlatBuffer 序列化，图结构与权重经 mmap 零拷贝，仅算子配置 `builtin_options` 需由 `ParseOpData` 拷成 C 结构体；模型把算子身份 `OperatorCode`（去重存一份）与算子节点 `Operator`（用 `opcode_index` 引用身份）分离设计。查表铁律是 builtin 用枚举查、custom 用名字查，二者均带 version，由 `GetRegistrationFromOpCode` 把 `OperatorCode` 翻译成一次 `FindOp` 调用。`MutableOpResolver` 用 `builtins_` 与 `custom_ops_` 两张哈希表落地，`AddBuiltin`/`AddCustom` 写入时回填 `builtin_code`/`custom_name`/`version` 三字段，故 kernel 工厂（如 `Register_ADD`）本身不关心身份；`InterpreterBuilder` 对每个 opcode 只查一次表并缓存，同类节点共用同一份注册。注册自定义 op 即写好含 `init/free/prepare/invoke` 的 `TfLiteRegistration` 工厂并用 `AddCustom` 写入 resolver。本讲为 u8-l3 delegate 的第二条算子解析路径埋下伏笔。
