本讲从 Python 侧切入 C++ 内核，围绕 `tensorflow/core/public/` 这一**稳定的 C++ API 边界**展开，覆盖四个最小模块。其一确立 `core/public/` 与内部 `framework/`、`common_runtime/` 的分工：外部只依赖 public 头文件，通过 `NewSession()` 间接获得实现而非编译期耦合具体类。其二辨析**两套版本号**：`version.h` 定义的是 **GraphDef / Checkpoint 数据格式兼容版本**（`TF_GRAPH_DEF_VERSION=2474`、`TF_CHECKPOINT_VERSION=1`，GraphDef 自 2019/05/09 起按日期每日递增，用于前后兼容判定），并非发布版本号；`release_version.h` 配合 `tf_version.bzl` 才是**语义发布版本** `TF_VERSION_STRING="2.22.0"`，靠 Bazel 构建期注入、`#error` 强制单一来源。其四讲清 `Session` 是驱动图计算的**抽象入口**，核心契约为 `Create/Extend/Run/ListDevices/Close` 五个纯虚方法；`SessionOptions` 仅回答 `target`（空=本地）与 `ConfigProto` 两个问题；`NewSession()` 经 `SessionFactory::GetFactory` 选工厂，默认的 `DirectSession` 借 C++ 静态全局对象在启动时自动注册为 `"DIRECT_SESSION"`。关键概念「抽象类与工厂模式」「静态自动注册」「版本号双轨」将直接承接 u2（张量）与 u3（执行模型，展开 `DirectSession::Run`）。
