本讲精读 `python/framework/constant_op.py`，揭示 `tf.constant` 从 Python 调用到产生张量的完整链路。核心结论：`tf.constant` 只是一层薄薄的 Python 包装，自身不做计算，职责是整理参数并按执行模式分派，开关是 `ctx.executing_eagerly()`。Eager 路径经 `_constant_impl` → `_constant_eager_impl` → `convert_to_eager_tensor`，最终调用 C++ 构造器 `ops.EagerTensor(value, device, dtype)` 立即产生张量，不建图；Graph 路径经 `ops._create_graph_constant`，在默认图中建一个无输入的 `"Const"` 节点，值序列化成 `TensorProto` 嵌在节点 `value` 属性里。关键术语包括：Python 层 op 包装与底层内核的两层区分、`EagerTensor`（C 扩展类型）、`Const` 节点与 `TensorProto` 属性、`is_constant`（靠 `op.type == "Const"` 判定）。dtype/shape 推导借助 numpy，并施加「int64→int32（无损时）、float64→float32」的偏好规则，故 `[1,2,3]` 默认是 `int32`。此外 `tf.constant` 与 `tf.convert_to_tensor` 本质相同——后者通过张量转换注册表把 list/tuple/普通对象路由回 `constant_op.constant`。下讲 u2-l3 将转入可变的 `tf.Variable`。
