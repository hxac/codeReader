本讲讲解 TensorFlow Profiler 如何回答「程序慢在哪里」。它有两条技术路线：老式 tfprof 基于 `Session.run` 副产品 `RunMetadata`，对 op 级耗时/内存/参数量做离线聚合，提供 scope/graph/code/op 四视图；新式采样式 profiler 基于全局会话 `ProfilerSession`，主动采集散布在各算子里的 `TraceMe` 打点与 GPU/TPU 硬件事件，收进统一容器 `XSpace`（`XPlane→XLine→XEvent`，皮秒精度、可嵌套），在 TensorBoard 展示甘特图。关键概念：`TraceMe` 是构造记开始、析构记结束、上交三元组的采集原语，靠 `TraceMeRecorder::Active(level)` 级别过滤实现「profiler 关闭时近乎零开销」；`tf.profiler.experimental.Trace` 是其 Python 薄壳，用来标定 step 边界。核心指标：三时间 `micros = accelerator_micros + cpu_micros` 与四类内存 `bytes` 等；因 GPU 异步并发，各算子 micros 之和常大于墙钟时间。结论：定位瓶颈看相对占比与 CPU/加速器时间比，据此选择 tf.data prefetch、XLA 融合或混合精度。进程内同一时刻只允许一个活跃 profiler 会话。
