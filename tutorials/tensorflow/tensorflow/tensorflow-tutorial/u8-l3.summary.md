本讲讲解 TFLite 的 delegate（委托）机制：在不更换 Interpreter 的前提下，把计算图的部分节点卸载到 GPU/NNAPI/XNNPACK 等加速后端。delegate 是一个 C 结构体契约（`TfLiteDelegate`），核心是必填的 `Prepare` 函数指针，用来声明「我支持哪些节点」。运行时据此做图分区（PartitionGraph），把连续的支持节点切成 `NodeSubset`，每个支持分区被替换成一个 `builtin_code=kTfLiteBuiltinDelegate` 的宏节点，重建后的 execution_plan 由 CPU 段与宏节点交替构成。所有 delegate 的 Prepare 都是同一三段式模板（构造 TfLiteRegistration→判定支持性→ReplaceNodeSubsetsWithDelegateKernels），差异仅在「判定支持性」这一步。三大实现：GPU delegate 多后端合一、组合式持有 TfLiteDelegate；NNAPI delegate 直接继承 TfLiteDelegate 并把子图翻译成系统 NNAPI 模型；XNNPACK 是默认开启的高度优化 CPU 后端。三级回退保证正确性：加载期失败即 RemoveAllDelegates 还原图、输入形状变化用 Undo/RedoAllDelegates 暂存重做、运行期 InvokeWithCPUFallback 备份输入后用 CPU 重跑（依赖 ArenaPlanner 的 preserve_inputs，故要求模型无状态）。
