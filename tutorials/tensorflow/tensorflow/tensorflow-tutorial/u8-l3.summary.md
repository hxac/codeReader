本讲讲清 TFLite 委托（delegate）机制：一套让 GPU/NNAPI/XNNPACK 等加速后端认领并执行计算图中部分节点的通用插件框架。delegate 由用户运行期显式挂载（区别于普通 op 的启动期自动注册），核心契约是 `TfLiteDelegate` 结构体的 `Prepare` 函数指针——运行时借此把图视图交给 delegate。改图由 `ModifyGraphWithDelegateImpl` 三步完成：验证并留底原始计划、回调 `Prepare`、保持图状态一致，任一步失败用 `RemoveAllDelegates` 回滚。`ReplaceNodeSubsetsWithDelegateKernels` 调分区算法把图切成 `kTfPartition`（delegate 段）与 `kTfNonPartition`（CPU 段）交替，每段合并成一个宏节点。该宏节点仍是一份 `TfLiteRegistration`（`builtin_code=DELEGATE`），`init` 编译子图、`invoke` 在加速器执行，对 Interpreter 执行循环完全透明。三大 delegate 定位不同：GPU 擅浮点卷积、NNAPI 打 Android NPU/DSP、XNNPACK 为优化 CPU 库，但共用「`IsNodeSupportedFn` + `GraphPartitionHelper` + `ReplaceNodeSubsetsWithDelegateKernels`」同一 Prepare 模板。失败分两类：Prepare 失败自动恢复 CPU 计划（返回 `kTfLiteDelegateError`）；Invoke 失败需调用方主动用 `InvokeWithCPUFallback` 抢救输入、撤销 delegate、纯 CPU 重跑，前提是模型无状态。
