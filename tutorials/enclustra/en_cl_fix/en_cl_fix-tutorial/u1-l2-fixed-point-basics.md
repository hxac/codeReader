## 4. 核心概念与源码讲解

### 4.1 定点数格式 [S, I, F]：定义与总位宽

#### 4.1.1 概念说明

en_cl_fix 用一个三字段元组来描述任何一个定点数格式：

```
[S, I, F]
```

- `S` = 符号位（sign bits）个数，取值只能是 **0 或 1**。`S=1` 表示有符号数（补码），`S=0` 表示无符号数。
- `I` = 整数位（integer bits）个数。整数位可以**为负**，详见 4.3。
- `F` = 小数位（fractional bits）个数。小数位也可以**为负**，详见 4.3。

因此，一个格式真正占用的物理二进制位数为：

\[
\text{width} = S + I + F
\]

这个宽度可以等于 0，但库不允许为负（即要求 `S + I + F >= 0`）。

为什么需要用一个「格式」来描述？因为硬件里只存着一串 0/1 比特，单看比特本身无法判断它代表多少。必须额外约定「小数点在第几位」「是否有符号位」，这串比特才有数值意义——这个约定就是 `[S, I, F]`。

#### 4.1.2 核心流程

给定一个格式，确定总位宽只需一步：

1. 读取 `S`（0 或 1）、`I`、`F`。
2. 计算 `width = S + I + F`。
3. 这个 `width` 就是硬件中实际存储的比特数，也是后续算术、resize 时关心的大小。

在 Python 里，这个宽度由 `FixFormat.width` 属性给出，`cl_fix_width()` 函数就是直接返回它。

### 4.2 位权模型与二进制换算：BitWeights 与 Example 图解

#### 4.2.1 概念说明

有了格式，下一步是「把一串比特换算成数值」。这靠的是**位权（bit weight）**：二进制小数点（binary point）把比特串分成左右两半。

- 小数点**左边**是整数位 `I`，从低位到高位权重依次是 \(2^0, 2^1, \dots, 2^{I-1}\)。
- 小数点**右边**是小数位 `F`，权重依次是 \(2^{-1}, 2^{-2}, \dots, 2^{-F}\)。
- 如果 `S=1`，最高位（符号位）坐在 \(2^I\) 的位置上，但权重是**负的** \(-2^I\)——这正是**二进制补码（two's complement）**的体现。

这与十进制完全同理，只是把「10 的幂」换成「2 的幂」。整体位权示意就是 README 嵌入的 BitWeights 图。

设第 \(k\) 位（从 LSB 起算，LSB 为 \(k=0\)）的权重为：

\[
w_k = 2^{\,k - F}
\]

那么一个无符号定点数的值就是所有「值为 1 的位」的权重之和；有符号数则把最高位的正权重换成 \(-2^I\)。

#### 4.2.2 核心流程

把一段二进制换算成十进制的标准步骤：

1. 根据格式 `[S,I,F]` 确定小数点位置：它落在从右往左数第 `F` 位与第 `F+1` 位之间。
2. 小数点右侧 `F` 位是小数部分，权重 \(2^{-1}\dots2^{-F}\)。
3. 小数点左侧（直到符号位之前）是整数部分，权重 \(2^0\dots2^{I-1}\)。
4. 若 `S=1`，最左边的符号位权重为 \(-2^I\)。
5. 把所有「1」位的权重相加，得到最终值。

伪代码：

```
value = 0
if S == 1:
    if sign_bit == 1:
        value += -2**I
# 遍历剩余整数位与小数位，按 2 的幂累加
for each bit that is 1:
    value += 2**(该位的指数)
```

让我们跟着 README 把这个例子算一遍（格式 `[0,11,5]`，无符号，16 位）：

- 小数点在第 5 位左侧。小数部分（右 5 位）`00011`：\(2^{-4} + 2^{-5} = \tfrac{1}{16} + \tfrac{1}{32} = 0.09375\)。
- 整数部分（左 11 位）`11111100111`：\(1024+512+256+128+64+32+4+2+1 = 2023\)。
- 合计：\(2023 + 0.09375 = 2023.09375\)。

> 一个等价的理解（也是后面 Python 验证的依据）：把这 16 位当成一个**普通无符号整数**看，它的值是 `0b1111110011100011 = 64739`；因为 `F=5`，真实定点值 = \(64739 / 2^5 = 64739 / 32 = 2023.09375\)。这正是「定点数 = 整数 × 比例因子 \(2^{-F}\)」的直觉。

### 4.3 有符号数、负整数位/负小数位与表示范围

#### 4.3.1 概念说明

两个容易被初学者忽略的细节：

1. **有符号数（补码）**：当 `S=1`，最高位是符号位，权重是 \(-2^I\)（注意是负的）。这使得同一个比特模式在有符号和无符号下代表截然不同的值。例如 4 位 `1111`：作为 `[0,4,0]` 是 `15`；作为 `[1,3,0]` 是 \(-8+4+2+1 = -1`。

2. **负的 `I` 或 `F`**：`I` 和 `F` 都允许为负。直观上，这意味着「小数点落在了物理位之外」，于是物理位的一侧出现了若干**缺失的、隐含为零的位**。这会改变 LSB/MSB 的权重，并改变可表示范围，但不改变「总位宽 = S+I+F」的算法。

   - `F` 为负（如 `[1,4,-2]`）：小数点跑到 LSB 的**右边**，物理 LSB 的权重变成 \(2^{-F} = 2^{|F|}\)（一个正幂，粒度更粗）。README 用 `110--.` 里的 `--` 表示这两个「缺失的小数位」。
   - `I` 为负（如 `[1,-2,4]`）：小数点跑到 MSB 整数侧的**左边**，所有可表示值都小于 1（纯小数）。README 用 `.-sff` 里点号后的 `-` 表示「缺失的整数位」。

#### 4.3.2 核心流程

给定格式，求「最小值 / 最大值（表示范围）」：

1. 无符号（`S=0`）：最小值 = 全 0；最大值 = 全 1（所有物理位权重之和）。
2. 有符号（`S=1`）：最小值 = 符号位置 1、其余全 0（即 \(-2^I\)）；最大值 = 符号位置 0、其余全 1。
3. 通用的单物理位权重公式仍为 \(w_k = 2^{\,k-F}\)（\(k\) 从 LSB 起算），符号位例外取负。

以 `[1,4,-2]`（3 个物理位）为例：LSB 权重 \(2^{-(-2)} = 2^2 = 4\)，三位权重依次 \(4, 8, -16\)（最高位为符号）。比特 `110` = \(-16 + 8 + 0 = -8\)；范围 \(-16 \dots +12\)。

### 4.4 舍入与饱和：为什么需要它们（概览）

#### 4.4.1 概念说明

当我们把数据从一个格式「搬到」另一个格式时，位宽往往要变化。变化方向只有两种，分别对应两类处理：

- **小数位 `F` 变少**（丢精度）：低位要被丢弃，需要决定「丢掉时是否进位」——这就是**舍入（rounding）**。这和十进制里「保留两位小数」是同一回事，只是底数是 2。
- **整数位 `I` 变少 / 符号位 `S` 变少**（丢范围）：高位要被丢弃，可能导致数值超出新格式能表示的范围——这就是**饱和（saturation）**要处理的场景。

> 本讲只建立「为什么需要」和「有哪些模式」的概览。具体每种模式如何用「加偏移再截断」实现，留到单元 4 详讲。

#### 4.4.2 核心流程

- **舍入**：当目标格式的 `F` 比源格式小，先按所选舍入模式决定低位进位，再截断多余小数位。不同模式的差别主要在「正好处于一半（tie）时往哪边进」。
- **饱和**：当目标格式的 `I`/`S` 比源格式小，数值可能超出范围。
  - 不启用饱和 → 直接丢弃高位，超出范围的值会**回绕（wrap）**（类似整数溢出）。
  - 启用饱和 → 把超出范围的值**钳位（clamp）**到最近的可表示边界。
  - 启用告警 → 仿真器/软件在检测到超范围时**发出警告**。

## 6. 本讲小结

- en_cl_fix 用 `[S, I, F]` 描述定点格式：`S`（符号位，0 或 1）、`I`（整数位）、`F`（小数位），总位宽就是 `S + I + F`。
- 每个二进制位都有一个「位权」，整数位是 2 的非负幂，小数位是 2 的负幂；有符号数的符号位权重为 \(-2^I\)（补码）。
- 等价直觉：定点值 = 把比特当普通整数看，再乘以比例因子 \(2^{-F}\)。README 招牌示例 `1111110011100011` 在 `[0,11,5]` 下就是 \(64739/32 = 2023.09375\)。
- `I` 或 `F` 允许为负：表示小数点落在物理位之外，出现「缺失/隐含为零」的位，会改变粒度与范围，但不改变位宽算法。
- 「小数位变少」需要**舍入**（7 种模式），「整数位/符号位变少」需要**饱和**（4 种模式，可选告警）——本讲只看概览表，实现细节留待单元 4。
