本讲剖析程序入口 `main.rs`，将其定位为一个按固定顺序“装配”协议核心的脚本：手写解析命令行参数（设备名、`-f` 前台、`--disable-drop-privileges`），先用 root 绑定 UAPI 套接字、创建 TUN 网卡，再降权、daemonize、初始化日志。关键概念“平台别名 `plt`”由 `src/platform/mod.rs` 用条件编译把当前 OS 实现统一别名化，使 `main.rs` 中 `plt::UAPI`/`plt::Tun`/`plt::UDP` 与平台解耦；`plt::Tun::create` 返回 `(readers, writer, status)` 三元组。随后构造 `WireGuard<plt::Tun, plt::UDP>` 核心对象——`WireGuard::new` 内部按 CPU 核数 spawn `handshake_worker`，`add_tun_reader` 为每个 reader spawn `tun_worker`，并用 `WireGuardConfig` 隐藏 IO 泛型。最后起两条常驻线程：Tun 事件线程把 `TunEvent::Up/Down` 翻译成 `cfg.up/down`，UAPI 线程为每条 `wg(8)` 连接 spawn 一线程跑 `configuration::uapi::handle`；主线程在 `wg.wait()` 处经 `WaitCounter`（`Mutex` + `Condvar`）阻塞，直到所有 `tun_worker` 退出。降权细节留给 u1-l5。
