本讲讲解 WireGuard 路由器数据面的**入站对称篇**：`ReceiveJob` 如何把一条 UDP 密文传输报文解密成明文 IP 包并写回 TUN 网卡。核心是入站处理被拆成两阶段：并行阶段 `parallel_work` 做重活——AEAD 解密（`open_in_place`）与 cryptokey 路由校验（`check_route`，按**源地址**反查防伪造，与出站按目的地址对称）；串行阶段 `sequential_work` 做对顺序敏感的副作用——`AntiReplay::update` 防回放、密钥确认、更新端点、写 TUN、触发 `C::recv` 回调。判据是：无副作用只读的放并行以榨干多核，修改共享状态且顺序敏感的（防回放位图，乱序会误丢合法报文）放 per-peer 保序串行。安全设计上，认证或路由失败时将缓冲区 `truncate(0)`，使串行阶段解析传输头失败而提前返回，杜绝未认证字节流向 TUN，构成纵深防御。关键概念包括：receiver id 查 `recv` 表定位 `DecryptionState`、密钥静默确认（响应方首个成功报文经 `confirmed.swap` 触发一次 `confirm_key`，把 KeyWheel 的 `next` 转正为 `current`）、keepalive 识别（并行靠 `packet.len()==SIZE_TAG` 放行、串行靠 `inner_length` 返回 `None` 拦在 TUN 门外但仍触发回调以保活），以及无缝漫游的端点更新。
