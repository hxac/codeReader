本讲精读 `src/configuration/uapi/set.rs`，讲清 WireGuard 用户态如何把 `wg(8)` 发来的 `set=1` 文本逐行翻译成对协议核心的配置调用。主角 `LineParser` 是两态状态机（`Interface`/`Peer`）：遇 `public_key=` 切到 peer 态并 flush 旧 peer，空行触发最后一个 peer 提交。`ParsedPeer` 作草稿容器，以 `Option`/`Vec` 区分「显式设置 vs 不触及」，以 `bool` 控制位表达 `remove`/`update_only`/`replace_allowed_ips`。接口级字段即时下发（密钥走十六进制+常时间比较判全零，端口/mark 靠 `parse()` 由形参反推类型，零值表「清除」）；peer 字段先攒批，由 `flush_peer` 按固定顺序（删→建→allowed-ip→psk→keepalive→版本校验→endpoint）一次性下发到 `Configuration` trait，解析逻辑只依赖该 trait。另指出两处实现细节：`#[cfg(debug)]` 日志在当前 features 下为死代码；`replace_allowed_ips` 被写入但 flush 从不消费。实践任务是让解析器对 `x-` 实验前缀 key 宽容跳过。
