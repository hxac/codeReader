本讲义打开 `src/util.rs` 中两个"黑盒"函数。守护进程化 `daemonize()` 采用经典"双 fork + `setsid`"套路：第一次 fork 确保调用者非进程组组长（`setsid` 成功前提），`setsid` 脱离控制终端，第二次 fork 使 daemon 不再是会话首领、永久无法重获控制终端；辅助函数 `fork_and_exit` 据 fork 返回值三段（负/零/正）区分失败、子、父进程。特权降级 `drop_privileges()` 把进程从 root 永久降为 `nobody`，步骤顺序受两条硬约束支配：需读 `/etc/passwd` 的 `getpwnam` 必须早于 `chroot`（改根后读不到），需 root 的 `chroot`、`setgid` 必须早于 `setuid`（降级单向不可逆），故顺序为 getpwnam → chroot → umask(0) → chdir → setgid → setuid。错误类型 `DaemonizeError` 用六个变体枚举所有失败点并实现 `Display`。核心调用时序为绑 UAPI → 建 TUN → 降权 → daemonize → 初始化日志，根因为前两步需 root 而 fork 不需，故先降权后后台化；日志在降权后才初始化，意味着 `drop_privileges` 内的 `log::` 默认无输出。
