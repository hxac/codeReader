本讲讲解 wireguard-rs 中贯穿多模块的零拷贝报文解析手法：用 zerocopy 库的 `LayoutVerified` 把原始字节「就地」当作结构体读写，省去反序列化拷贝与堆分配。核心配方为 `#[repr(packed)]`（无填充、布局即线路）+ `FromBytes`/`AsBytes`（安全按字节解释）+ `U16`/`U32`/`U64`（带字节序、可未对齐访问的包装类型）。两个构造方法：`new`（整段即一个结构体，用于定长握手报文）与 `new_from_prefix`（前缀为头、剩余为载荷，用于变长传输报文与 IP 头），均返回 `Option`，`None` 即「长度闸门」。该手法用于：send.rs 就地写头 + `seal_in_place` 加密 + 填标签；receive.rs 用 `open_in_place` 对称解密，认证失败则 `truncate(0)` 清空缓冲作为数据形状信号；ip.rs 的 IPv4/IPv6Header 视图与 `inner_length` 剥尾部 AEAD 标签；route.rs 按目的/源地址做 cryptokey 查表。失败映射：传输报文入口 `Device::recv` 中 `new_from_prefix` 失败返回 `RouterError::MalformedTransportMessage`，握手层 `new` 失败返回 `HandshakeError::InvalidMessageFormat`。字节序刻意混用——WireGuard 自有报文小端、内层 IP 包大端。
