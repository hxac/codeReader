本讲围绕 `src/wireguard/handshake/device.rs` 中的 `Device<O>`，它是握手模块的调度中枢，承接报文线路格式（u4-l1）与 Noise IK 密码学（u4-l3），既不拼字节也不算密码，而负责管理全部 peer、维护本地密钥、分配 receiver id 并把入站握手报文分用到正确的密码学函数。`Device<O>` 含四个字段：`keyst`（本端私钥/公钥与 MAC 校验器）、`pk_map`（公钥→peer）、`id_map`（receiver id→公钥，并发 DashMap）、`limiter`（抗 DoS 限速器）。其设计核心是「公钥 ↔ receiver id」双向映射：发送按公钥查 peer，接收按 4 字节临时 id 经 id_map→pk_map 两跳回溯到 peer；id 之所以两跳存储，是因其临时可回收、生命周期短于 peer。关键术语：receiver id（线路上的 32 位一次性短期标识）、DH 共享密钥 `ss=DH(sk,pk)`（可预计算）、不透明类型 `O`（关联上层路由句柄）。`set_sk` 改私钥会经 `update_ss` 为每个 peer 重算 `ss` 并释放被中止握手占用的 id，剔除与设备公钥撞车的 peer。`allocate` 用拒绝采样从 2³² 空间取不可预测 id，借助 `DashMap::entry` 在分片锁内原子完成「检查+插入」，消除竞态并提升并发（提交 6e307fc 的核心改进）。`begin`/`process` 为两个握手入口，`process` 按 type 字段把 Initiation/Response/CookieReply 三类消息分用到对应 Noise 函数，返回 `Output` 三元组（opaque、回复报文、派生 KeyPair）。
