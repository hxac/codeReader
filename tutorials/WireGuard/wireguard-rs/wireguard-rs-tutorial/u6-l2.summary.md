本讲讲解 WireGuard 用户态实现的 UAPI 协议处理框架。UAPI 是纯文本、按行、`key=value`、以空行结束事务的控制协议，只有 `get=1`（读状态）与 `set=1`（写配置）两种操作，客户端为官方 `wg(8)`。协议唯一入口是 `handle<S: Read + Write, C: Configuration>`：内层用 `readline` 逐字节读行（带 256 字节超长保护）、`keypair` 按 `=` 拆键值，再按操作行分用——`get` 无状态地直接 `serialize` 吐出状态，`set` 则由 `LineParser` 维护 `Interface`/`Peer` 状态机，攒批多行配置，于空行结束并以 `parse_line("","")` 触发最后一个 peer 的 `flush_peer` 提交。无论成败，`handle` 末尾统一回写 `errno=<n>\n\n`，数字由 `ConfigError::errno()` 映射（成功为 0）。平台层用 `PlatformUAPI`/`BindUAPI` 两个 trait 抽象双工流，`BindUAPI::Stream: Read + Write` 正是 `S` 的来源；Linux 上是 `/var/run/wireguard/<name>.sock` 的 `UnixListener`，`connect` 即 `accept`，`main.rs` 每连接一线程跑 `handle`。该 `S: Read + Write` 约束使协议层与平台解耦，故可用内存流做端到端测试。关键术语 UAPI、`handle`、`readline`/`keypair`、`LineParser`/`flush_peer`、`errno` 统一回写、`ConfigError::errno()`、`PlatformUAPI`/`BindUAPI`/`LinuxUAPI` 将由 u6-l3、u6-l4、u7-l4 承接。
