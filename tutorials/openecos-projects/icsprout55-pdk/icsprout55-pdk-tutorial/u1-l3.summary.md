本讲剖析 ICS55 PDK 的「git 存小文件、Release 存大文件」两层分发机制：三套标准单元库（H7CH/H7CL/H7CR）的 liberty 与全部 GDS 体积庞大，作为 GitHub Release 的 asset（共 7 个 .tar.bz2）按需下载，git 只跟踪约 41 个文本文件。核心是 96 行 Makefile 的三大块：变量定义（`:=` 立即展开、`?=` 可被命令行覆盖）、下载规则（curl 查 API → grep 匹配 `browser_download_url` 与目标文件名 → cut 切出 URL，配合 `.part` 临时文件与 fail-fast）、解压模式规则。关键概念「文件名即协议」：`patsubst` 从压缩包名抽出库名拼出解压目录（DECOMP_DIR），模式规则用 `%` 与自动变量 `$@`/`$<`/`$*` 把目录目标与压缩包绑定；因标准单元与 IO 的路径前缀不同，gds 需两条规则。`make unzip` 按 start→clean-dir→解压→clean-bz2 顺序实现幂等，`download` 仅是别名；参数 RELEASE_TAG 固定版本、TOOL 换 wget、PROXY_USE 走镜像。.gitignore 四行恰好挡住全部下载产物，同时放行 IO 库 6 个小 liberty，体现按体积划界。下一讲进入 techLEF 工艺文件。
