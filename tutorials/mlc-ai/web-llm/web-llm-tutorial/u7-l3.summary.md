本讲拆解 WebLLM 的性能观测面：计时写入全部发生在管线层 llm_chat.ts（performance.now() 计时器），引擎层 engine.ts 负责读取换算并组装成 usage.extra。核心结论：TTFT（首 token 延迟）的口径就是当轮 prefill 耗时，包含 tokenizer 编码、分块前向与首 token 采样，随 prompt 长度增长；逐 token 解码延迟靠 KV cache 兜底，与 prompt 长度基本无关；e2e_latency_s 从抢锁前计起，比两者之和多出排队时间。统计分两级账本：跨轮累计账本（runtimeStatsText 读它，因 resetStatsPerPrefill 恒真、每轮 prefill 即被清零而废弃）与 curRound 当轮快照账本（usage.extra 的数据源）；n>1 时 TTFT 取各 choice 之和、每 token 延迟取平均。curRoundLatencyBreakdown 六个数组是采样链（grammar 掩码、LogitProcessor、logit_bias、惩罚、抽样、总时）的逐 token 分解，不含模型前向，数组按功能条件填充，需 extra_body.enable_latency_breakdown 显式开启；流式请求需 stream_options.include_usage 才能在末尾拿到 usage chunk。
