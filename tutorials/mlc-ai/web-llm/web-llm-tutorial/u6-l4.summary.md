本讲是第六单元收官篇，讲解 `response_format.type = "structural_tag"` 的触发式标签（triggered tags）机制：回复分成自由文本区与受约束区，仅触发串到结束串之间的内容受 JSON schema 约束。协议层设镜像双向配对校验（关卡 6.3，抛 `InvalidResponseFormatStructuralTagError`）；标签定义由 triggers、begin（函数名硬编码其中，杜绝幻觉函数名）、content、end 及 at_least_one、stop_after_first 次数开关组成。管线层经 `compileStructuralTag` 编译（缓存键为标签定义字符串化，命中即 reset 复用），掩码是采样链第 0 步、先于 `LogitProcessor` 执行，语法约束绝对优先，采样后 `acceptToken` 推进状态机。核心结论：该路线不限模型（绕开 `functionCallingModelIds` 白名单），性能优势源于自由文本区掩码近似全合法；代价是 finish_reason 恒为 stop、tool_calls 需调用方自解析；另发现引擎 usedGrammar 统计漏列 structural_tag，致其 usage.extra 缺 grammar 耗时字段。
