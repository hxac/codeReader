本讲剖析 WebLLM 引擎层生命周期。核心结论：`CreateMLCEngine` 是工厂函数，等价于 new `MLCEngine` 后 await `reload`，返回时模型已就绪；构造函数轻量，只初始化以 modelId 为键的四个 Map（引擎状态的全部载体）和三个 OpenAI 风格门面。`reload` 先 unload 释放显存，再依次查 ModelRecord、三层合并 ChatConfig、下载并实例化 wasm/tvmjs、GPU 检测、载入 tokenizer 与权重、构造 LLMChatPipeline 或 EmbeddingPipeline（VM、权重、KV cache 就位）、编译 shader，最后注册进 Map；支持多模型加载与 AbortController 中断。生命周期三方法分工：`unload` 释放一切，`resetChat` 仅清会话且对空引擎为 no-op，`interruptGenerate` 只中断当前生成。`MLCEngineInterface` 是静态契约，`MLCEngine` 与 `WebWorkerMLCEngine` 共同实现，经 getModelStates 把请求路由到已加载管线，使业务代码无感切换主线程/Worker 模式。
