本讲剖析 WebLLM 的 completion 接口：输入裸 prompt，不经对话模板直通 tokenizer，适合基础模型；chatCompletion 则用结构化 messages 套 conv_template，适合指令模型，这是两个接口的本质差异。引擎在 prefill 以「是否含 messages」分流，completion 路径每次无条件 resetChat 清空 KV cache（chat 视为可复用资产、completion 每次全清），TextCompletionExpectsKVEmptyError 是公共 API 下不可达的管线层不变量断言。关键术语：Completions 门面类仅转发 engine.completion（兼容 OpenAI SDK 写法）；postInitAndCheckFields 做四道字段校验（不支持字段、流式数量、seed 类型、stream_options）；Conversation 以 isTextCompletion 进入哑模式，appendMessage 等会话式方法被守卫拦截；响应的 choices[i].text、echo 回显、n 候选各自独立跑一遍 prefill+decode，usage.extra 提供性能指标，seed 用后即重置。
