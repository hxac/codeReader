一次 `reload()` 需持久化四类产物——聊天配置、model_lib wasm、tokenizer、权重分片——它们分存于 `webllm/config`、`webllm/wasm`、`webllm/model` 三个缓存作用域，便于分类管理与精确删除。本讲以 `cache_util.ts` 为核心：`getCacheOptions` 是后端选择唯一收口，把 `AppConfig.cacheBackend` 的四个取值（cache、indexeddb、opfs、cross-origin）归一为 tvmjs 的 `cacheType`，缺省 cache；`opfsAccessMode` 三种取值仅 opfs 后端消费。作用域注入分两路：产物缓存由 `createScopedArtifactCache` 以位置参数携带作用域，张量缓存由 `getTensorCacheAccessOptions` 把 `cacheScope` 混入选项对象，体现「作用域隔离」思想。缓存管理 API 构筑其上：`hasModelInCache` 只查权重，`deleteModelAllInfoInCache` 清除全部产物。结论：默认选测试最充分的 CacheStorage（Cache API），OPFS 利于大文件读写但环境要求更高；缓存不跨后端迁移，且缓存后端属于 AppConfig 身份的一部分。
