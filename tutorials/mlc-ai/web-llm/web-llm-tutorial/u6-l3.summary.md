本讲完整展开采样链路最前端的「grammar 掩码」，即结构化输出与约束解码机制。协议层结论：ResponseFormat 的 type 仅有 text、json_object、grammar、structural_tag 四种，不存在 json_schema 类型——schema 约束是 json_object 携带 schema 字段的组合，关卡 6 系列做字段配对校验，Hermes 函数调用时 response_format 会被原位覆写为官方 schema。运行时核心是 xgrammar 引擎的 GrammarMatcher：在每次请求的 prefill 阶段与 prompt 预填充并行编译创建（按 type 分派 compileJSONSchema 等），responseFormatCacheKey 命中时仅 reset() 复用、跳过编译，TokenizerInfo 与 GrammarCompiler 为管线级持久。逐 token 流程：getNextTokenBitmask 取合法 token 位掩码，拷到 GPU 用 apply_bitmask_inplace 就地屏蔽非法 logits（采样链路第 0 步），采样后 acceptToken 推进状态机；语法走完只放行停止 token，生成自然以 stop 收尾。开销由 usage.extra 的 grammar_init_s 与 grammar_per_token_s 观测，且仅在 type 为 json_object 或 grammar 时输出。语法合法性由机制保证，但语义合理性与 finish_reason 为 length 时的截断风险仍需调用方兜底。u6-l4 将承接 structural_tag，讲分段约束式工具调用。
