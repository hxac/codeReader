本讲覆盖 `src/service_worker.ts` 与 `src/extension_service_worker.ts` 两个模块。核心结论：`ServiceWorkerMLCEngineHandler` 继承 `WebWorkerMLCEngineHandler`，原样复用 19 种消息路由，只重写三处——构造（`self` 全局监听并用 `waitUntil` 包住处理过程防中途回收）、`postMessage`（`clientRegistry` 按 uuid 向对应页面定向回包）、`onmessage`（keepAlive→heartbeat 应答与 reload 去重两个特例）。reload 去重以影子状态比对模型与配置，已加载则跳过并直接报进度完成；配合基类 `reloadIfUnmatched` 形成 Service Worker 被杀后的自愈闭环。页面侧三件套：`ServiceWorker` 类把 `navigator.serviceWorker` 适配成 `ChatWorker`，引擎子类增加心跳（`missedHeartbeat` 计数）与多窗口容错，工厂等 `ready` 后「构造+reload」但不负责注册。扩展版是 MV3 变体：通道换成 `chrome.runtime.Port`（`PortAdapter` 适配），点对点回包免注册表，心跳只发不收，经 `index.ts` 以 `Extension*` 别名导出与网页版同名类共存。该方案的收益是多个标签页与扩展 popup 共享同一份权重与 GPU 资源，代价是空闲即被浏览器回收（MV3 约 30 秒），需靠心跳与自愈机制兜底。
