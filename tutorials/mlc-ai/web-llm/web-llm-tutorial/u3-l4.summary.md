本讲拆解码码阶段三个模块：decodeStep 主循环、终止条件判定、统计与 KV 长度维护。decodeStep 每次仅把上一步采样的单个 token 前向，借 KV cache 免于重算历史，内核按输入长度分流；循环由引擎层以 stopped() 为判据驱动，中断信号每轮开头检查。终止判定集中于 processNextToken，共五类：停止 token、停止字符串、max_tokens、上下文窗口写满、手动中断，对应 finish_reason 的 stop/length/abort，逐条判定、后判覆盖先判；停止 token 在追加前被拦截故不占 max_tokens 名额，停止字符串在文本层截断故占名额，ignore_eos 会清空两类停止表。filledKVCacheLength 是全局 KV 账本：prefill 加块长、decode 加一（有不变量断言）、多轮对话不清零；输入侧超窗抛 ContextWindowSizeExceededError，生成侧写满则优雅停止。滑动窗口模型以环形 KV 自动淘汰旧页，不存在窗口判停。解码统计分跨轮与本轮两层，经 usage.extra 以 decode_tokens_per_s 暴露，并为下一讲采样控制（appearedTokensFreq、LogitProcessor）铺垫。
