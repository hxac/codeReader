本讲精读 `prefillStep`：prefill 将整段 prompt 分块并行前向，为全部位置写入 KV cache，并仅采样最后一个位置的 logits 产出第一个回复 token（因果模型下仅末位置 logits 有效）。长 prompt 由 `getChunkedPrefillInputData` 贪心切成不超过 `prefillChunkSize` 的块：token 可切、图片不可切，块大小读自模型库 metadata，不能通过 appConfig 修改。KV cache 写入是事务式的（`kv_state_begin_forward` 预留、内核写入、`kv_state_end_forward` 提交），游标 `filledKVCacheLength` 是增量编码、多轮 KV 复用与上下文窗口检查的共同依据。`embedAndForward` 是 prefill/decode 共用的前向原语，按块长分派内核；GrammarMatcher 初始化与 prefill 并行以隐藏开销。统计汇入 `usage.extra` 的 `time_to_first_token_s` 与 `prefill_tokens_per_s`，故 TTFT 约等于 prefill 耗时；当前无逐块进度回调，中断需等 prefill 跑完才生效。
