本讲精读 WebWorkerMLCEngineHandler：其 onmessage 按 kind 将 19 种消息路由到引擎方法，多数经 handleTask 统一包装，成功回 return、异常退化为字符串回 throw，setLogLevel 等三类无响应，keepAlive 留给 Service Worker 子类。Handler 仅维护影子状态：modelId/chatOpts 镜像支撑 reloadIfUnmatched 失配自愈，生成器 Map 按 selectedModelId 分桶以支持多模型并发。流式输出为拉模型：StreamInit 只创建惰性生成器不算 token，主线程循环发 NextChunk 逐 chunk 拉取，收到 undefined 即流结束，每 chunk 一次往返换来背压。customRequest 是协议预留但基类空实现的扩展点（源码并无 onrequest 回调），正确扩展方式是子类重写 onmessage 拦截分发，复用 public 的 engine/handleTask 与 protected 的 getPromise；onComplete/onError 参数则为 Service Worker 的 waitUntil 预留。
