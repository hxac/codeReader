本讲围绕 `src/integrity.ts` 讲解 WebLLM 的模型完整性校验机制，借用了 Web 平台 SRI（子资源完整性）的字符串格式「算法-Base64 哈希」来验明远端下载产物在分发链路上未被篡改。核心内容：SRI 字符串仅接受 sha256/sha384/sha512（摘要 32/48/64 字节），`parseSRI` 做两层校验——正则匹配加解码字节数推算，`isValidSRI` 是其布尔包装并对外导出；`verifyIntegrity` 对整块 `ArrayBuffer` 做一次性 `crypto.subtle.digest` 后整串比对，是整块校验而非流式，其安全价值在「缓存之后、使用之前」的时序。关键概念：`ModelIntegrity` 接口（config、model_lib、tokenizer、onFailure 四个可选字段）、`FileIntegrityMap`（tokenizer 按文件名索引哈希）、`IntegrityError`（携带 url/expected/actual 三字段）。需区分两条异常路径：SRI 格式错误抛普通 `Error`，内容不符按 `onFailure` 策略抛 `IntegrityError` 或仅警告。引擎在 `reload()` 中设三个独立挂载点：config 在 `JSON.parse` 前、model_lib 在 `instantiate` 前、tokenizer 在解析前，均在权重装载之前，任一失败即中止 reload；但模型权重分片（.bin）不在校验范围内。校验只保证与作者审定的版本逐字节一致，不评价源头可信度。
