本讲讲解 WebLLM 的 Web Worker 架构：推理搬入 worker 线程，以免主线程解码阻塞 UI。核心是代理模式——主线程侧的 WebWorkerMLCEngine 与 worker 内由 WebWorkerMLCEngineHandler 包裹的 MLCEngine 真身实现同一引擎接口，业务代码无感切换。线程间只能 postMessage 加结构化克隆，调用被编码为 WorkerRequest{kind, uuid, content} 信封：请求 kind 共 19 种，响应为 return/throw/initProgressCallback，uuid 负责把异步消息还原为请求-响应配对，进度推送则是 uuid 为空串的广播。流式调用拆成 StreamInit 建立生成器加 N 次 NextChunk 拉取的拉模型，天然承担流控。双端分别记录期望与实际加载的模型清单，reloadIfUnmatched 失配时自愈重载。错误跨线程会退化为字符串；回调类配置（如 logitProcessorRegistry）无法过线程，须在 worker 脚本内注册。ChatWorker{onmessage, postMessage} 两字段结构化抽象让真 Worker、Service Worker 与测试替身均可接入。用户入口为 CreateWebWorkerMLCEngine(worker, modelId, engineConfig)。
