本讲是异步协调单元第一讲，只讲单个 mbarrier 的状态机与三类到达路径。核心前提是「已发起」不等于「已完成」：程序顺序与 `cta_sync` 只能同步线程，观察不到 TMA 引擎或 Tensor Core 的进度，交接必须依赖显式完成信号。mbarrier 是共享内存中的硬件同步对象，内部维护四个量：phase parity、pending/expected arrival count 与 tx-count。其关键设计是 arrive 与 wait 分离：生产者报告后继续干活，消费者按需等待。三条到达路径汇入同一对象：普通线程 `mbarrier.arrive`、发起线程 `arrive.expect_tx`（减 pending 且登记在途字节）、`tcgen05.commit`（硬件在异步 MMA 完成后补一次到达）；TMA 引擎每完成一段传输以 complete-tx 核减字节。相位完成的充要条件是 pending 与 tx-count 同时为零，随后屏障原子翻入下一相位并从 expected 重装 pending；wait 只观察、不修改状态。expect_tx 字节数必须精确等于本相位全部关联 TMA 传输的送达字节（fp16 双 128×64 tile 为 32768），登记过小导致静默读错数据，过大导致内核挂死。多级流水线的相位复用与 full/empty 双屏障留给下一讲。
