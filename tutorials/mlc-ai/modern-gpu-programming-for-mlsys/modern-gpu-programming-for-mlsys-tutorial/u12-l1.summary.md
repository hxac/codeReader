本讲讲解 hgemm 内核 Step 4（TMA 异步加载）：相对 Step 3 只改 dispatch——GMEM→SMEM 搬运从 128 线程协作的 Tx.cta.copy 加 cta_sync，改为 tid==0 单线程发起 Tx.copy_async（dispatch="tma_auto"），由 TMA 引擎执行；scope 与 128B swizzle 布局不变，回写新增 Dsmem 中转走 TMA store。核心结论：cta_sync 观察不到引擎，load 靠 mbarrier——arrive.expect_tx 一次贡献线程到达并登记 32768 字节（(BLK_M+BLK_N)·BLK_K×2），引擎 complete_tx 扣减，到达与字节两计数同归零相位才完成；登记过小则提前放行、静默产出错果，过大则挂死于 try_wait。store 方向相反，等源缓冲可复用，用 commit_group/wait_group(0) 排空，两道 warpgroup_sync(10)（命名屏障，与 TMA 无关）分别防写入未完就搬运与未排空就覆写。TIRx 中 TMA 配置是五个设置点（tma_config 字典、字节数、mbarrier 初始化、@T.inline 辅助函数、store 同步），tensor map 描述符由 tma_auto 依 buffer 形状与布局自动推导。本步数据路径已正确，但每次 load 后仍立即等待，load 与计算未重叠，Step 5 将引入双缓冲软件流水线。
