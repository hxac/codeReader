本讲引入 IKET（内核内事件追踪）：一种源码级插桩——在 TIRx PrimFunc 内创建 IketProfiler，用 mark() 打瞬时事件、range_push()/range_pop()（栈式配对，另有句柄式 range_start()/range_end()）圈出阶段区间，标注随内核编译进设备代码。它补齐 nsys 只见内核两端、NCU 只给整次 launch 聚合指标的盲区，给出内核内部按 warp 角色划分的时间线，回答「谁在等、谁在干、重叠多少」。双 warp 最小示例标出 producer_load、wait_for_data（包住 cta_sync）、consumer_compute 三段区间。两条硬纪律：区间须在 warp 的每条控制流路径上配对平衡；等待区域必须显式标注。采集用 iket.run() 重启脚本，tvm.compile 与 JIT 加载须留在被传入函数内，产物含 JSON、pftrace（用 Perfetto 查看）与 HTML。结论：各角色区间之和可超内核总时长，是 warp specialization 角色并行的直接证据；插桩会改变内核并带来开销，IKET 数字只用于诊断，报告延迟须回未插桩的 CUDA events 基线。
