本讲基于调试附录讲解 warp-specialized 内核的调试方法，含四个模块：八步工作流（先环境、再编译、最后内核，一次只改一处交接）；交接 worksheet（roles/storage/handoff/lifetime 四行表，用于核对生成 CUDA 的角色守卫、屏障初始化与到达数）；生成代码检视（保存 inspect_source 输出，按 wg_id、warp_id、lane_id、elect_sync 的守卫映射，先搜 mbarrier_init、tcgen05 等字符串再读源码）；症状映射表（把故障归为死锁、崩溃、错误结果、正确但慢四类分支排查）。核心结论：排除环境与编译问题后，运行期故障皆归结为五种断裂交接——屏障未初始化、到达数错、集体操作被守卫缩小到达集、相位过期、存储提前复用，因此不要先重写内核；非法访存会毒化 CUDA context，须重启 Python 再测。引入术语：handoff（交接）、worksheet（工作表）、context poisoning（上下文污染）、XID、drain（排空）。
