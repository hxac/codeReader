本讲是异步协调单元收官，介绍 Blackwell 的 Cluster Launch Control（CLC）。静态 persistent 调度在开工前用公式冻结 tile 分配，worker 起步晚或 tile 代价不均（如 causal 掩码）都会造成尾部空闲，且运行中无法修正。CLC 让运行中的 worker 取消一个尚未启动的 CTA/cluster launch 并继承其 blockIdx 坐标：坐标即任务 ID，零状态迁移，每个坐标恰好处理一次。请求协议为：单线程提交 try_cancel.async，硬件把 16 字节应答写入共享内存，用 mbarrier（一次到达加 tx-count 登记 16 字节）等待完成，先验 is_canceled 谓词再取 get_first_ctaid 坐标，失败必须退出请求循环（否则未定义行为）。「先请求、后计算」把网格调度器的裁决延迟藏进当前 tile 的计算；屏障逐迭代复用须翻转 phase，读写应答还要跨 async/generic proxy 加 fence。选型结论：SM 稳定且 tile 代价相近用静态公式（近零开销、可定制 L2 顺序）；资源或代价难预测才值得 CLC，TIRx 中可包成动态 tile 调度器，主循环不感知坐标来源。
