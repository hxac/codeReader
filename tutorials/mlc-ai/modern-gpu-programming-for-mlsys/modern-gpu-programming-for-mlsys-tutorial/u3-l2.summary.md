本讲承接 u3-l1 的 roofline 结论，回答「判定为 memory-bound 之后怎么优化」，覆盖三个模块：访存削减的两条出路、算子融合、数据复用与搬运效率。核心结论：低 AI 内核的出路只有两条——减少 HBM 字节以抬高 AI（融合、复用、更小 dtype），或流量减不动时把实际搬运率逼近带宽屋顶；一旦贴住屋顶，优化计算侧零收益，唯一出路是换算法搬更少字节。关键术语：中间张量落盘的「HBM 往返」（写一次加读一次，每元素 2s 字节）是核心记账单位；算子融合让中间值改在寄存器/SMEM/TMEM 交接、消灭这笔流量（典型现场如 GEMM epilogue 与 Flash Attention 不物化 score 矩阵）；tiling/blocking 是单算子内的数据复用，AI 从无复用的 1/s 到完美复用的 N/3 相差约 2730 倍，CTA tile 档 AI≈B/s；纯 copy、elementwise、单遍 reduction 无融合无复用，只能走有效带宽核查单（每字节只搬一次、合并/向量化访存、TMA、保持在途请求）。方法论要点：字节比不等于时间比，时间下界取计算项与字节项的较大者，省下的字节只有落在关键路径上才兑现为加速。
