本讲以 hgemm_v1 为标本确立 TIRx 分析框架：每项 tile 操作由三要素刻画——scope（哪些线程执行）、layout（逻辑元素落在哪个物理位置）、dispatch（走哪条硬件路径），分别对应编译器生成的控制流、地址计算与指令选择，LowerTIRx 据此把一条 Tx.gemm_async 展开为 4 条 tcgen05.mma。scope 由操作名前缀（Tx.cta./Tx.wg.）与 if 守卫（warp_id==0、elect_sync）表达，须区分发起者与执行者，取得线程 ID 本身不是 scope；layout 有三族实例：SMEM 的 128B swizzle（mma_shared_layout）、TMEM 的 TLane/TCol 命名轴、寄存器的 tid_in_wg，铁律是读写两端对同一元素给出相同位置，可用元素数守恒检验；dispatch 仅在存在多种硬件实现时有意义（本版唯一显式参数为 dispatch="tcgen05"），并受 scope 与 layout 制约。讲义埋下伏笔：后续将把 GMEM→SMEM 拷贝改为 TMA 派发，须同时调整单线程守卫、TMA 兼容布局与 mbarrier 同步协议。
