本讲拆开 `tvm.compile` 的 tirx 编译黑盒：编译产出 CPU launcher 与 GPU 内核两份代码，整体路径为先 BindTarget 挂上目标，再跑 19 步 tirx_pipeline，其中 SplitHostDevice 把函数拆成 host/device 两路、各自终化后生成 C/LLVM 与 CUDA。19 个 pass 分六类，TIRx 特有的只有前端两步，其余复用通用 TIR 的归一化、合法化与 ABI 机制。核心首 pass 为 LowerTIRx，内部分两步：TilePrimitiveDispatch 消费三要素（scope/layout/dispatch）中的 scope 与 dispatch，为 TilePrimitiveCall 选定后端实现、把 T.cta_id/T.thread_id 变为线程绑定；LowerTIRxCleanup 消费 layout，把逻辑布局化为物理索引，因此 FlattenBuffer 只摊平剩余的多维访问；末段 MakePackedAPI 把 host 函数适配为 packed-function ABI，使编译产物能直接接收张量。其余关键术语：PrimFunc、PassContext、finalization、T.device_entry()。实践上跟踪 Tx.gemm_async 从 authored IR 到 CUDA 源码的四站变形，一条 tile 调用展开为 4 条 tcgen05.mma；检视手法为 kernel.show() 看 lowering 前级、inspect_source() 看最终 CUDA。
