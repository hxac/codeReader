本讲解决 TMA 异步搬运「怎么知道搬完了」的问题，是 TMA 单元的收尾。load 侧（GMEM→SMEM）用 mbarrier：一个 phase 同时维护线程到达计数与在途字节计数（pending transaction bytes），两者都归零 phase 才算完成。被选中的单线程发起 load 后执行 `arrive.expect_tx` 登记字节数（各 tile 元素数之和×每元素字节数），TMA 引擎每完成一次搬运即 complete-tx 扣减，消费者用 `try_wait(phase)` 等账清零；`cta_sync` 只同步线程、观察不到引擎。登记过小会提前通过、读到旧数据，过大则永远等不到而挂死。store 侧方向反转，等待问题从「目标可读」变为「源缓冲何时可复用」：发起 store 后 `commit_group` 打包成 bulk async group、`wait_group 0` 排空，之后才能覆写源缓冲；发起前还需 `fence.proxy_async` 与 `warpgroup_sync` 保证可见性与全组齐步。流水线中每个 stage 有两个等待方向：MMA 读前等 full（数据就绪），TMA 覆盖前等 empty（缓冲归还），双缓冲按 stage 分 barrier。完成机制是重叠的前提，重叠本身靠双缓冲与角色划分实现。
