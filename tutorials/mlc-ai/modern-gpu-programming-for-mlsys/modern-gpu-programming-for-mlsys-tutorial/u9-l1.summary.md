本讲引入 TIRx（Tensor IR next）：一个不隐藏硬件的 Python DSL，仍直接操作线程、SMEM、TMEM、barrier 与 tcgen05.mma，其贡献是把 CUDA/PTX 中散落于 intrinsic 参数、地址计算与编码约定的三个决策显式写进结构化 IR——scope（哪些线程执行）、layout（tile 的物理排布）、dispatch（走哪条硬件路径）。核心载体是首个可运行内核 hgemm_v1：单 tile、单 CTA、128 线程，计算 D=ABᵀ（A/B 为 128×64、D 为 128×128，fp16 输入输出、fp32 累加），按五阶段组织：分配 SMEM/TMEM（SMEMPool、tcgen05.alloc）；Tx.cta.copy 由全 CTA 协作搬 A/B；warp 0 中 elect_sync 选出的单线程以 Tx.gemm_async（dispatch="tcgen05"、accum=False）发起 MMA，经 tcgen05.commit 与 mbarrier.try_wait 等待完成；Tx.wg.copy_async 由 warpgroup 集体读 TMEM 入寄存器，Tx.cast/Tx.copy 写回 GMEM；最后释放 TMEM。关键结论：一条 Tx.gemm_async 即声明整块乘加，编译器按 ⌈K/16⌉ 展开为 4 条 tcgen05.mma；本版无 K 循环故 accum=False。调用分两层：Tx.* 为 tile 操作（声明做什么），T.ptx.*/T.cuda.* 为底层辅助（资源与同步，三次 cta_sync 各守一道交接）。hgemm_v1 是后续 GEMM 优化与换 dispatch（如改派 TMA）的共同起点；编译验证归 u9-l2，三要素深挖归 u9-l3。
