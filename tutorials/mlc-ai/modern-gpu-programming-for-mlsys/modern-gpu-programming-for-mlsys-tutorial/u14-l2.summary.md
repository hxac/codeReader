本讲在 FA4（QKᵀ→softmax→PV，S/P/O 驻留 TMEM）算法链的基础上落实到线程层，含三个模块。其一 warp 角色与 scope：512 线程按 warpgroup 分固定角色，WG3 的三个 warp 分别发起 TMA load、两类 MMA 与 TMA store（elect 单线程提交、引擎执行），WG0/WG1 各跑一个 Q stage 的 softmax（wg_id 即 stage 编号），WG2 做校正与非 causal epilogue。其二屏障协议，沿用「屏障类型由完成者决定」：装载类 full/empty 用 TMABar 或 TCGen05Bar，线程侧用 MBarrier；核心结论是 p_o_rescale 需 256 次到达（softmax 组与 WG2 各 128，首块由 WG2 预释放），让一次 wait 同时证明 P 前 K_SPLIT 列就绪与 O 槽可用；p_ready_2 仅数 128 次、只放行第二段 PV；softmax 与 WG2 经 SMEM 邮箱和命名屏障交接 acc_scale，可跳过重缩放数据路径但不跳过同步。其三 setmaxnreg 按角色重配每线程寄存器上限 200/200/64/48，总计 65536，softmax 的 200 主要供养整行 128 个 fp32 的 s_chunk_buf。
