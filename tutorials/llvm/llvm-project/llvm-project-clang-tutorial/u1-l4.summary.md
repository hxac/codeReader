本讲是「用户视角」终章，分三个最小模块。其一，编译阶段：源码依次经预处理、编译、汇编、链接成为可执行映像；Clang 仅负责前端（Lex→Parse→Sema→CodeGen，止于 LLVM IR），汇编与链接交给 LLVM 后端和系统链接器，由此区分前端、中端、后端。其二，driver 与 cc1 分工：`clang` 命令内含 driver（模仿 GCC 的命令行协调者，负责解析参数、推断目标、构造 Action 图并调度工具）与 cc1（真正的编译器前端）两个角色，其边界可用 `-###` 与 `-ccc-print-phases` 观察；driver 内部经 Parse→Pipeline→Bind→Translate→Execute 五阶段构造并执行 Action 图，入口 `clang_main` 会先拦截 `-cc1` 以分流直接调用与普通调用，普通调用默认以进程内回调（`-fintegrated-cc1`）方式驱动 cc1。其三，常用选项：`-E`/`-S`/`-c`/`-fsyntax-only`/`-emit-llvm` 控制流水线停站，`-o`/`-x` 控制输出与语言类型，均定义于 Options.td 的 Action_Group。后续 u2 将钻进 driver 与 cc1 源码内部。
