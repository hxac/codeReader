本讲钻进 clang driver 的源码，覆盖官方五阶段（Parse / Pipeline / Bind / Translate / Execute）中的前两段，把命令行字符串追踪到 Action 图为止。第一模块讲 `Driver` 类：它是无状态的总管，构造期只设不变配置（名字、目标三元组、driver 模式、目录），命令行解析与每次编译的细节都装入独立的 `Compilation` 对象，因此可被 IDE 长期复用；总入口是 `BuildCompilation`，内部依次串联 `ParseArgStrings`、`getToolChain`、`BuildInputs`、`BuildActions`、`BuildJobs`。第二模块讲 Parse：选项由 TableGen 在 `Options.td` 声明，每个选项带 Visibility 元数据（`ClangOption`/`CLOption`/`CC1Option` 等），`getOptionVisibilityMask` 按当前 driver 模式（GCCMode、GXXMode、CLMode、FlangMode、DXCMode）算出可见选项集，`ParseArgStrings` 据此把字符串切成轻量的 `Arg`/`InputArgList`，并对未知选项给「did you mean」建议。第三模块讲 Pipeline：`getFinalPhase` 按 `-E`/`-S`/`-c`/`-fsyntax-only` 优先级判定最终阶段，每个文件实际要走阶段 = `Types.def` 中该类型绑定的阶段集合与 final phase 的交集（`getCompilationPhases`）；`BuildActions` 为每个输入建一条 Action 链，逐阶段用 `ConstructPhaseAction` 包成对应 `JobAction`，多链在 `LinkJobAction` 汇合成图。核心结论：`-fsyntax-only`/`-emit-llvm` 的「停站」本质是把输出类型设成 `TY_Nothing`/`TY_LLVM_*`，使后续阶段无事可做。本讲到 Action 图为止，把 Action 绑定到工具并生成可执行命令的 `BuildJobs`（Bind/Translate/Execute）留给下一讲。
