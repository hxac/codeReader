本讲围绕「如何把 Clang 源码变成可执行的 `clang` 命令」，覆盖三个最小模块：CMake 选项、集成与独立构建、构建产物。

顶层 `CMakeLists.txt` 用 `option()` 和 `set(... CACHE ...)` 定义大量 `CLANG_*` 选项，分三类：能力开关（如 `CLANG_ENABLE_STATIC_ANALYZER`、`CLANG_BUILD_TOOLS`、`CLANG_PLUGIN_SUPPORT`）、默认行为（如 `CLANG_DEFAULT_LINKER`、`CLANG_DEFAULT_CXX_STDLIB`、`CLANG_SPAWN_CC1`）、构建与安装位置。命令行 `-D` 值写入 `CMakeCache.txt` 并覆盖默认值。

构建分集成与独立两种：集成构建把 Clang 当 LLVM 子项目（`-S llvm`，配 `LLVM_ENABLE_PROJECTS=clang`），官方推荐；独立构建（`-S clang`）则设 `CLANG_BUILT_STANDALONE`，需自行 `find_package(LLVM)` 并定位 `llvm-tblgen`。判定依据是 `CMAKE_SOURCE_DIR` 是否等于 Clang 目录。无论哪种，都依赖 LLVM 库与 `llvm-tblgen`（把 `.td` 翻译成 C++）。源码内构建会被 `FATAL_ERROR` 拒绝。

`-DLLVM_ENABLE_ASSERTIONS=ON` 在 Release 构建中保留断言，违反内部不变量时立即中止并打印调用栈，利于调试；其设置须与所链接的 LLVM 一致。

产物落在 `build/bin`（可执行文件，如 `clang`、`clang-format`）、`build/lib`（`libclang*` 子库及可选的 `libclang-cpp.so`、`libclang`）、`build/.../include`（由 `configure_file` 生成的 `Version.inc`、`config.h`）。子库与工具分别由 `lib/CMakeLists.txt`、`tools/CMakeLists.txt` 列出。
