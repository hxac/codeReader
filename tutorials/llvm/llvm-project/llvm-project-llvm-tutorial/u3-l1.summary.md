新 Pass 管理器（新 PM）把优化拆成两个相互配合的管理器：PassManager 管有序的 pass 队列并改 IR，AnalysisManager 管懒加载的分析结果缓存且只读 IR，二者按 IRUnit（Module/Function/CGSCC/Loop）分层、跨层用 adaptor 适配。pass（变换）须用 PreservedAnalyses 声明保住了哪些分析，管理器据此精确、按需地失效过期结果，分析间依赖经 Invalidator 现场递归判定，这是相对老 PM 的关键改进。PassManager::run 主循环的五步（BeforePass → pass.run → 失效 → AfterPass → 累积保留集）是新 PM 的心脏。新 PM 没有统一 pass 基类：任何带 run 方法的类都是 pass，靠 CRTP mixin（PassInfoMixin/AnalysisInfoMixin）提供元信息，靠 PassConcept/PassModel 做类型擦除（用函数指针而非虚函数）统一调度；analysis 遵循 Result 模型、以 AnalysisKey 为身份，getResult 触发缓存。PassInstrumentation 经 Before/After 回调点提供可观测与可插拔能力（如 -time-passes、二分 bisect），本身伪装成永不过期的 analysis 流转；PassBuilder 负责批量注册并解析 -passes= 文本。本讲只讲管理器骨架，写 pass 与流水线解析分别留待 u3-l2、u3-l3。
