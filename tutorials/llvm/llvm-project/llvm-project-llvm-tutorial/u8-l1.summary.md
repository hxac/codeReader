本讲围绕「LLVM IR 如何变成机器码并真正执行」展开。`ExecutionEngine` 是统一「解释器」与「JIT」两种实现的抽象基类，现代用法多弃用 `runFunction`，改用 `lookup` 取地址后直接调用。核心是 ORC v2 的层式架构：`ExecutionSession` 为中枢，`JITDylib` 模拟动态库，各 `Layer`（IRCompileLayer、ObjectLinkingLayer 等）组成「向下降级」管道；与之反向的是「向上查找 + 惰性物化」——加模块只登记定义，首次 `lookup` 才真正编译链接。`HowToUseLLJIT` 以 `add1` 示例把这套抽象落成最小可运行程序。`DefinitionGenerator` 是「现场生成定义」的扩展点：查找缺符号时由生成器造定义（可异步、可合成桩），造不出才失败。本次版本新增的 `COFFAutoImportGenerator` 是其典型实例——绑定单个 DLL、以导出表为权威，按需合成 COFF dllimport 所需的 `__imp_X` 指针槽与 `X` 跳转桩，桩设为 Weak 可被真实定义覆盖，并共享一个可回收的 `ResourceTracker`。
