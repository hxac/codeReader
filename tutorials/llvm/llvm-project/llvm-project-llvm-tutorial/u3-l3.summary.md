本讲讲清「pass 如何被串成流水线」，含三个模块。文本解析：`parsePipelineText` 按「左括号压栈、右括号弹栈」把 `-passes=` 字符串切成 `PipelineElement` 嵌套树，括号表跨层 adaptor、逗号表同级顺序；`parsePassPipeline` 检测首层 pass 所属层级并自动补 `function(...)`/`cgscc(...)` 外壳（故 `instcombine` 等价 `function(instcombine)`），再由各 `parseXxxPass` 经 `PassRegistry.def`（X-Macro）展开内置 pass。默认流水线：opt 把 `-O2` 改写成 `default<O2>`，与手拼流水线共用同一条 `parsePassPipeline` 通道；`default` 注册为带参 module pass，参数 `<O2>` 经 `parseOptLevelParam` 解析后调用 `buildPerModuleDefaultPipeline`，按「准备 pass → 触发 PipelineStartEP → buildModuleSimplificationPipeline → buildModuleOptimizationPipeline → 收尾」拼装，O1/O2/O3 共用骨架、靠 OptimizationLevel 调节。两类扩展机制须分清：`registerPipelineParsingCallback` 给自定义 pass 起名字（用户须在 `-passes=` 显式写出）；扩展点回调 EP（如 `registerPipelineStartEPCallback`）在默认流水线固定位置经 `invoke...EPCallbacks` 自动注入 pass，用户无需改 `-passes=`，且仅当运行 `default<O#>` 时才触发。
