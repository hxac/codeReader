本讲打开五个命令行工具的 `main()`，揭示它们都是「薄壳」——只负责用 `cl::ParseCommandLineOptions` 解析参数，真正逻辑都来自 `lib/` 下的组件库。核心结论围绕 LLVM IR 的两种等价格式展开：人类可读的 `.ll` 文本与紧凑二进制 `.bc` 位码，`llvm-as`/`llvm-dis` 在二者间做无损互转（仅格式转换，不做优化）。

关键术语包括：`Module`（一段 IR 在内存里的根对象）、`LLVMContext`、`verifyModule`（验证器，确保 SSA 正确、类型匹配）、`BitcodeWriter`/`BitcodeReader`。`opt` 是三段式模型中「优化器段」的化身，输入输出都是 IR，通过 `-passes=...` 描述流水线（新 Pass 管理器），`-O2` 等价于 `-passes="default<O2>"`，典型 pass 如 `mem2reg` 把 alloca/store/load 提升为 SSA 寄存器。`llc` 是「后端段」，通过 `InitializeAllTargets`、`TargetRegistry::lookupTarget` 把 IR 编译为任意架构的 `.s`/`.o`（`-filetype`）。`lli` 用 `InitializeNativeTarget` 仅支持本机，默认 ORC JIT 直接执行 IR，默认入口函数为 `main`。完整数据流为 `.ll →(llvm-as)→ .bc →(opt)→ 优化 .bc →(llc)→ .s/.o`，分支经 `lli` 直接执行。
