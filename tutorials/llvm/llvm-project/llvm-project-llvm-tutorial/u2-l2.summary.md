本讲承接 IR 层次结构，把视角下沉到「树上每个节点到底是什么」，覆盖三个最小模块：Type 体系、Value/User/Use 关系、Constant 体系。

Type 是类型系统的根，**不是 Value**：它描述值长什么样，但不参与运算。Type 不可变、由 LLVMContext 全局唯一化，比较相等只需比指针；内部用 TypeID 区分基本类型（void、浮点等）与派生类型（IntegerType、FunctionType、PointerType、VectorType 等）。所有类型都通过 Type::getInt32Ty、PointerType::get、FunctionType::get 等静态工厂方法获取，派生类型把被包含类型统一存在 Type::ContainedTys 里。现代 LLVM 采用不透明指针，只记录地址空间。

Value 是「所有可被引用对象」的基类，每个 Value 持有一个 Type 和一条 use 列表；User（继承 Value）持有 operand 列表，Use 是连接二者的「边」，构成 SSA 要求的双向可达 def-use 关系。类型识别不靠 RTTI，而靠 Value.def 集中生成的 ValueTy 枚举与 classof 的区间比较。

Constant 继承自 User，分无 operand 的 ConstantData 与有 operand 的 ConstantAggregate 两支，按结构等价全局共享、不可变；ConstantInt 用 APInt 存值，ConstantFP 用 APFloat。核心结论：IntegerType 属 Type 树，ConstantInt 属 Value 树，一个值通过 getType() 指向其类型——「值持有类型」而非「类型继承值」。
