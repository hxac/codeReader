本讲讲解 OpenMP 用户面 `omp_target_*` C API，让用户绕过 `map` 子句手动管理设备内存，与编译器生成的 `__tgt_*` 隐式链路并列。涵盖四个模块：一是**设备标识体系**，区分 `DeviceNum`（连续下标，不稳定）与 `UID`（`<plugin>-<vendor_uid>` 字符串，稳定），主机在两套体系下分别是设备号 `N`/`-1` 和字符串 `"HOST"`，由 `isInitialDevice` 统一判定；二是**显式内存分配与释放**，`omp_target_alloc/free` 经 `targetAllocExplicit` 走「主机短路（malloc/free）+ 设备转发（`DeviceTy::allocData`/`deleteData`）」骨架，由 `TargetAllocTy` 枚举（DEVICE/HOST/SHARED/DEFAULT）选择内存空间，Kind 从用户 API 一路透传到插件且分配/释放 Kind 必须匹配，否则 fail-fast 中止；三是**数据搬运**，`omp_target_memcpy` 按源/目标是否主机做四向分发，D2D 优先 P2P 直传（`dataExchange`）、失败回退经主机中转，异步版通过 helper task 与 `depend` 协作；四是**映射查询**，`is_present` 查映射表、`is_accessible` 查硬件能力、`associate_ptr` 手动登记引用计数为 INF 的映射、`get_mapped_ptr` 取设备指针。核心结论：所有用户面 API 最终汇聚到 `DeviceTy` 这个 Facade 再转发给具体插件，显式分配的指针不进入 `HDTTMap` 映射表。
