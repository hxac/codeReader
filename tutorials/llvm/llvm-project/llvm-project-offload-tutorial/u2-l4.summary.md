本讲解析 libomptarget OpenMP 上层逻辑层（`include/OpenMP/` 与 `libomptarget/OpenMP/`）中 `DeviceTy` 内嵌 `MappingInfoTy` 的主机-设备数据映射机制。

每段绑定由映射条目 `HostDataToTargetTy` 描述，采用**动态（DynRefCount，OpenMP 4.5）+ 保持（HoldRefCount，OpenACC `ompx_hold`）双引用计数**状态机；INF 计数代表「永不释放」（如 `omp_target_associate_ptr`），`reset` 供 `delete` 子句使用。条目存于按 `HstPtrBegin` 排序的有序表 `HDTTMap`。

两条核心算法：`getTargetPointer`（enter 路径）建映射并按条件 H2D 搬运——仅当有 `to` 标志且为新条目或 `always` 时复制；`getTgtPtrBegin`（exit 路径）用 `decShouldRemove` 预测递减后是否归零，`IsLast` 才触发延迟删除。`lookupMapping` 借 `upper_bound` 加前驱判断，区分包含/前延/后延三种命中。

并发由「表锁（`ProtectedObj`/`Accessor`）+ 条目锁」两层保障，锁序固定为先表后条目；`TargetPointerResultTy` 以 RAII 在持有期锁条目，使耗时数据搬运移出表锁临界区。辅助机制含影子指针 `ShadowPtrInfoTy`（进入改写、退出还原，支持 Fortran 描述符）、`Event`（保证 map 子句原子性）与 `MappingConfig`。核心结论：「何时复制」与「何时释放」相互正交、分由 enter/exit 两条路径负责，嵌套区域内层退出不释放、仅计数归零才回收。
