`PluginManager` 是 libomptarget 的调度中枢，作为进程级全局单例（由指针 `PM` 暴露）持有异构插件清单与设备账本，把 host/cuda/amdgpu/level_zero 等后端展平成一组从 0 连续编号的 `DeviceTy`。核心数据成员包括插件数组 `Plugins`、正向映射 `DeviceIds`、受锁保护的设备数组 `Devices`、镜像集、`RequirementCollection` 及三把互斥锁。关键术语区分两种设备号：用户面的 `UserId`（OpenMP 设备号）与插件内的 `DeviceId`/`RTLDeviceID`；`GenericPluginTy` 子类实例即「插件」。

插件列表由构建期 X-macro（`Targets.def`）决定，`init()` 只构造对象，`initializePlugin` 才探测硬件，二者分离即「构造≠初始化」。设备编号在 `initializeDevice` 中以「数组当前长度」当 UserId 连续分配，公式为 UserId(Pk,j)=Σ(i<k)ni+j，正向表 `DeviceIds` 与 `DeviceTy` 的反向字段 `(RTL, RTLDeviceID)` 构成双向映射，`getDevice` 据此转发。

设备容器用 `ProtectedObj`/`Accessor`（RAII）做独占访问，另有 `RTLsMtx`、`TrlTblMtx`、`TblMapMtx` 三把锁，存在外层 `RTLsMtx` 内层 `TrlTblMtx` 的锁序。`RequirementCollection` 在注册期收集 `omp requires` 标志并强制跨翻译单元一致性，APU 上自动追加 `OMPX_REQ_AUTO_ZERO_COPY`。「延迟注册」化解插件 init 期间重入注册的竞态，「延迟加载」（`loadImagesOntoDevice`）把镜像 `loadBinary` 推迟到设备首次使用，共同构成「注册期登记、使用期加载」的按需设计。
