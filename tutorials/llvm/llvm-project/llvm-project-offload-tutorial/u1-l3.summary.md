本讲建立 offload 子项目的目录地图与分层架构，是后续讲义的导航基础。项目按层次组织：`include/`（契约层，编译器与运行时共用的头文件，含 `omptarget.h` 的 `__tgt_*` 入口签名与 `tgt_map_type` 枚举、`PluginManager.h`）、`libomptarget/`（绑定 OpenMP 的成熟运行时，产出 `omptarget.so`，含 `interface.cpp` 入口实现）、`plugins-nextgen/`（设备插件框架 `common/` 与 host/cuda/amdgpu/level_zero 各后端，核心基类为 `GenericPluginTy`/`GenericDeviceTy`/`GenericKernelTy`）、`liboffload/`（开发中的通用新 API，由 `.td` 经 `offload-tblgen` 生成 `ol*` 接口）、`tools/` 与 `test/`/`unittests/`（构建期工具、运行期诊断工具、lit 与单元测试）。核心结论有二：其一，构建组装顺序（tblgen 与插件先、运行时与新 API 后、测试最后）反映了模块依赖；其二，运行期调用链为「编译器生成 `__tgt_*` → `interface.cpp` 入口 → 全局单例 `PM`/`PluginManager` → `DeviceTy` → 具体插件 → 设备硬件」，且 libomptarget 与 liboffload 是插件层之上两条并列、互不依赖的上层路径。关键术语：入口函数、插件、调用链、`PM` 单例、`DeviceTy`、泛型基类、分层模型。
