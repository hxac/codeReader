本讲是「核心运行时调用链」首讲，聚焦 libomptarget 的入口与初始化，覆盖四组入口：`__tgt_rtl_init`/`__tgt_rtl_deinit`、`__tgt_register_lib`/`__tgt_unregister_lib`、`registerLib`、`__tgt_init_all_rtls`。核心结论：运行时是「被驱动」的全局单例，靠 `RefCount` 实现「首次进入构造、末次退出销毁」，并用原子量 `RTLAlive`/`RTLOngoingSyncs` 保证去初始化期间无进行中同步。注册路径解决「懒初始化 + 延迟注册」两个问题：`__tgt_register_lib` 必先 `initRuntime()`；`delayRegisterLib`/`registerDelayedLibraries` 用「先暂存后重放」化解插件初始化期间重入注册的时序竞态。`registerLib` 是重头戏——遍历设备镜像做「插件级（`isPluginCompatible`）+ 设备级（`isDeviceCompatible`）」双层兼容判断，把镜像登记进以 OpenMP 设备号 `UserId` 为下标的 `TranslationTable`，但**只登记不加载**。关键术语：二进制描述符 `__tgt_bin_desc`、`PluginManager`、`DeviceTy`、翻译表、`UserId` 映射 `(插件, 插件内设备号) → 设备号`。此外 `__tgt_register_requires` 已废弃，requires 标志现随特殊条目在注册期收集并由 `RequirementCollection` 强制跨翻译单元一致性；真正的 `loadBinary` 推迟到 `getDevice` 首次使用时由 `loadImagesOntoDevice` 完成，体现「注册期登记、使用期加载」的按需设计。
