本讲解答「offload 子项目如何构建」。它首先确立前置条件：作为主机运行时，要求 CMake ≥ 3.20、C++17、64 位，排除 macOS/WASM 及 GPU 三元组，Windows（MSVC）下跳过 `libomptarget`。依赖探测脚本 `LibomptargetGetDependencies.cmake` 收集 LLVM 头文件目录，并用 `offload-arch --only={nvptx|amdgpu|intel}` 探测本机 GPU 架构，产出 `LIBOMPTARGET_FOUND_*_GPU` 与架构列表。插件选择由 cache 变量 `LIBOMPTARGET_PLUGINS_TO_BUILD`（默认 `"all"`）控制，`host` 插件始终追加，而 `cuda`/`amdgpu`/`level_zero` 按操作系统与 CPU 架构自动裁剪；该清单还会生成 `Targets.def` 供运行时枚举。目标三元组清单 `LIBOMPTARGET_ALL_TARGETS` 罗列所有受测目标，产物统一输出到 `LIBOMPTARGET_LIBRARY_DIR`，安装走 `install-offload`（`--component offload`）。调试、OMPT、LTO 三类开关分别绑定 `OMPTARGET_DEBUG`、`OMPT_SUPPORT`、IPO 标志。官方缓存预设 `cmake/caches/Offload.cmake` 是最简构建入口。引入的关键术语包括 cache 变量、runtimes 构建模式、目标三元组、`offload-arch`、per-target runtime dir 与 `install-offload`，供后续讲义承接。
