本讲聚焦 libomptarget 最核心的 `DeviceTy`，它是「上层 OpenMP 逻辑」与「底层设备插件」之间的外观/转发层（Facade）：自身不碰硬件，把上层请求翻译成 `RTL->某方法(RTLDeviceID, ...)` 交给 `GenericPluginTy`。它同时持有 `DeviceID`（OpenMP 用户面 UserId）与 `RTLDeviceID`（插件内下标），把 u2-l2 的双编号映射对象化；内嵌 `MappingInfoTy` 负责主机-设备指针映射，禁拷贝以保证唯一身份。生命周期分三级按需推进：`PluginManager::initializeDevice` 构造、`init()` 调 `init_device` 初始化、首次 `getDevice()` 触发 `loadBinary` 延迟加载镜像。对外接口含内存分配（`allocData`/`deleteData` 按 `Kind` 选设备/主机/共享空间）、数据搬运（`submitData`/`retrieveData`/`dataExchange`，默认异步，转发前做信息打印与 OMPT 回调）、内核启动（`launchKernel` 近乎透明转发）、事件五原语与同步/查询（`synchronize` 阻塞、`queryAsync` 非阻塞，完成与否看 `AsyncInfo.isDone()`）。`loadBinary` 还负责解析 indirect 调用表、上传 `DeviceEnvironmentTy`。关键术语：UserId、RTLDeviceID、AsyncInfoTy、Facade、TargetAlloc Kind、OFFLOAD_SUCCESS/FAIL。
