本讲精读 libomptarget「指挥层」，连接编译器入口 `__tgt_target_data_begin/end/update_mapper` 与 u2-l4 映射算法。核心结论：「搬运」与「引用计数」正交——前者决定数据何时在主机与设备间移动，后者决定设备内存何时分配/释放。三阶段共用 `targetData<>` 模板外壳，差别仅是传入的内部函数指针；`StateInfoTy` 临时账本只在 begin/end 分配，记录本次构造的新分配、ATTACH 与被跳过的 FROM。`targetDataBegin` 正序遍历，跳过 LITERAL/PRIVATE、延迟 ATTACH，调 `getTargetPointer` 完成「+1 计数 + 可能 H2D」，触发条件为 `to && (新条目|always|本构造新分配)`。`targetDataEnd` 逆序遍历，调 `getTgtPtrBegin` 完成「-1 计数 + IsLast 预测」，FROM 搬运条件为 `from && (IsLast|always|曾被释放)`，未触发者记为 skipped 待补救；真正的设备内存删除推迟到 `AsyncInfo.synchronize()` 之后的 `postProcessingTargetDataEnd`，避免与在途搬运竞争。`targetDataUpdate` 以 `UpdateRefCount=false`、`MustContain=true` 查既有映射，只做 `submitData`/`retrieveData`，不分配、不删除、不改计数。`targetDataMapper` 把自定义 mapper 展开成一族普通条目后回调同一 `targetData*` 函数（`FromMapper=true`）。这套 begin/end 流程被内核启动前后的 `processDataBefore`/`processDataAfter` 复用，承接 u2-l6。
