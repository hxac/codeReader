本讲拆解 libomptarget 的异步执行模型，覆盖 `include`（契约与抽象）与 `libomptarget`（入口与实现）两个最小模块。核心结论：异步上下文分两层——下层 `__tgt_async_info` 是插件契约（核心字段为 `Queue`，CUDA 中即 `CUstream`，`Queue==nullptr` 即代表完成），上层 `AsyncInfoTy` 包装它并持有设备引用、`SyncType` 与后处理列表，靠 `operator __tgt_async_info*()` 与 RAII 析构 `synchronize()` 桥接。同步语义由 `BLOCKING`（阻塞，插件须清空 Queue）与 `NON_BLOCKING`（轻量查询）区分，「队列空」是判定完成的唯一判据。后处理机制（`addPostProcessingFunction`/`runPostProcessing`）承载延迟删设备内存、释放临时缓冲、还原影子指针、释放私有参数等须在异步完成后才做的善后，且支持执行中新增。`target nowait` 经 `TaskAsyncInfoWrapperTy` 把堆分配的非阻塞 `AsyncInfoTy` 存入 OpenMP task 内部数据以逃逸栈帧，无法获取 task 槽位则降级为栈上阻塞。`__tgt_target_nowait_query` 在再调度时查询完成，并用 `thread_local` 的 `ExponentialBackoff`（线性增、指数减）在自旋与阻塞间自适应切换。上层同步最终都经 `DeviceTy` Facade 一行转发至插件层。
