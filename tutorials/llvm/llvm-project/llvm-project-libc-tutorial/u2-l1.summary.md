本讲义阐述 LLVM-libc 的中心抽象——入口点（entrypoint）：每个对外公开的函数或全局变量都是独立、有名的构建单元，贯穿源码布局、构建系统与配置管理。全讲围绕四个最小模块：入口点定义把「实现、构建目标、平台取舍」三个正交关注点解耦；三阶段生命周期（实现→`add_entrypoint_object` 注册→`entrypoints.txt` 配置）分别回答 HOW、HOW、WHETHER；两条核心 CMake 规则中，`add_entrypoint_object` 造单个目标文件，`add_entrypoint_library` 把一批对象聚合成 `libc.a`/`libm.a`/`libllvmlibc.a` 等静态库；SKIP 机制让配置名单外的入口点只造空占位目标、不真正编译。引入的关键术语包括：构建单元、配置驱动、`TARGET_ENTRYPOINT_NAME_LIST`（配置名单，由点分路径取末尾分量推导）、ALIAS 别名入口点（典型实例 `setjmp`/`longjmp` 经 `ALIAS` 转发到架构特化实现）。核心结论：入口点粒度把传统单体归档焊死的「实现、构建、平台取舍」三者解耦，使同一份实现仅靠更换配置即可服务 Overlay/Full 两种构建模式，并支撑新平台的渐进式 bring-up。
