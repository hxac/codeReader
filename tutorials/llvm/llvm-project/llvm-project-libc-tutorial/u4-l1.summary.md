本讲回答「`src/__support` 是什么」这一核心问题，确立它为所有入口点共享的**私有标准库**：不对应任何公共头文件、不产生公开 C 符号，用 `add_header_library`/`add_object_library`（而非 `add_entrypoint_object`）声明**内部构建目标**，由入口点经 CMake 的 `DEPENDS` 引用。入口点之所以「薄」（如 `isalpha` 只做边界检查再委托），正因为真正的算法都下沉到 `__support`。内容分两类：按主题划分的能力子目录（`CPP`、`FPUtil`、`OSUtil`、`printf_core`、`File`、`threads`、`math` 等，常再按 OS/架构细分），以及根目录的扁平工具头（`ctype_utils.h`、`error_or.h`、`str_to_integer.h`、`block.h` 等）。基础设施层由 `common.h`（聚合层）与 `macros/config.h`（定义层）构成：前者用 `#error` 强制 `LIBC_NAMESPACE` 必须由 CMake 注入，并定义 `LLVM_LIBC_FUNCTION`/`LLVM_LIBC_VARIABLE`；后者定义带隐藏可见性的 `LIBC_NAMESPACE_DECL`；`macros/attributes.h` 则提供 `LIBC_INLINE` 等便携属性宏。关键约定：C++ 源码 `#include` 的每个 `__support` 头都必须在 `DEPENDS` 中有对应目标，二者一一对应。本讲引入的 entrypoint、内部目标、`DEPENDS`、命名空间宏等术语将由 u4-l2（CPP 子集）、u4-l3（错误处理）等后续讲义承接。
