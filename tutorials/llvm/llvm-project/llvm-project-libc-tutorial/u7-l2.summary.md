本讲剖析 LLVM-libc 把 `printf` 引擎拆成的三段式架构，所有逻辑位于 `src/__support/printf_core/`，是对外入口点（`printf`/`fprintf`/`sprintf`/`snprintf`/`asprintf`）共用的私有内核。核心数据流可概括为：`Parser` 生产 `FormatSection`，`Converter` 消费 `FormatSection`。

最小模块包括：① 核心数据结构——`FormatSection` 把一段转换说明的标志、宽度、精度、长度修饰符、转换名及参数位模式（统一存进 `UInt128` 的 `conv_val_raw`）装进一个结构体；配套有 `LengthModifier` 枚举、`TypeDesc`（专供 index mode 按索引跳参）和从 -1001 起的负数错误码。② 解析器 `Parser<ArgProvider>`，靠模板化的 `ArgProvider::next_var<T>()` 与参数来源解耦，边解析边按「转换名+长度修饰符」查表取参，使转换器无需碰可变参数。③ 写入器 `Writer<write_mode>`，用一层固定缓冲加三种 `WriteBuffer` 子类（`DropOverflowBuffer`/`FlushingBuffer`/`ResizingBuffer`）的溢出策略，让同一份 `convert_*` 代码同时服务丢弃、冲刷、扩容三种目标。④ 转换器与编排，`printf_main_modular` 主循环把三段串成引擎，`convert()` 按转换名分派到具体转换器。

关键结论：`printf` 与 `scanf` 复用的是同一套架构设计与同一个 `internal::ArgList` 抽象，而非同一份源码——`scanf` 有一套平行的 `scanf_core`，仅以 `Reader` 取代 `Writer`。三段式的职责隔离提供了换 `WriteBuffer`、换 `ArgProvider`、在 `convert` 加 `case` 三类扩展点，为后续模块化格式串埋下伏笔。
