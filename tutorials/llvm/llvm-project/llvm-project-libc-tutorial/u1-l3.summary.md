本讲把 LLVM-libc 从目录认知落到「能编译、能测试、能链接」的实操，含四个最小模块。依赖安装核心是 Clang（≥15）+ CMake + Ninja + gcc-multilib，后者关键在于建立 /usr/include/asm 符号链接，使 Full 构建能找到 Linux 内核头文件。CMake 配置走官方推荐的 runtimes 构建：构建根位于仓库根的 runtimes/ 而非 libc/，它是按 LLVM_ENABLE_RUNTIMES 解析并路由到各子项目的分发型入口；带上 compiler-rt 是为给 libc 接入 Scudo 内存分配器。LLVM_LIBC_FULL_BUILD=ON 选 Full 模式，产出独立的 libc.a/libm.a，而 OFF 默认为产出 libllvmlibc.a 的 Overlay 模式。编译通过 ninja 三层目标表达：库目标 libc/libm、测试伞目标 check-libc、以及形如 libc.test.src.<头文件>.<函数>_test.__unit__ 的单测目标。Hello World 链接是 Full 模式灵魂：用 -nostdinc/-nostdlib 屏蔽系统库，再手工链入启动对象 crt1.o（提供程序入口 _start，由 start/tls/do_start 等多个对象 relocatable 合并而成）加 libc.a、libm.a，并补上 Clang 自带的 resource dir 头文件。
