本讲回答两个工程问题：用模糊测试挖掘手写测试漏掉的边界 bug，用微基准精确测量仅占几个周期的低延迟内存函数。涵盖四个最小模块：（1）模糊测试组织——`fuzzing/` 目录镜像 `src/` 结构，以差分测试为主（与手写参考实现或系统 libc 同名函数比对输出，不一致即 `__builtin_trap()`），底层由 libFuzzer 经 `-fsanitize=fuzzer` 同时插桩并注入驱动 `main`，每个 fuzzer 实现 `LLVMFuzzerTestOneInput`，`add_libc_fuzzer` 负责把源文件链接入口点 object 文件；（2）微基准框架——`benchmark()` 模板用「迭代数几何增长批量重测 + 按迭代数加权均值 + ε 收敛」算法，把几周期函数测到 1% 精度，停机条件外化于 `BenchmarkOptions`，借 `randomize` 防 CPU 分支预测器作弊、`benchmark::DoNotOptimize` 防编译器优化掉无副作用调用；（3）内存大小分布——`MemorySizeDistribution` 是从真实生产负载采样的「尺寸→概率」数组，随机模式按它抽样得代表性平均耗时，扫描模式逐尺寸画曲线，二者互补，且批量数据须留在 L1 以隔离内存子系统；（4）结果分析——`Study` 序列化为 JSON，由独立 Python 脚本渲染，支持多 trial 置信区间与多报告并排。核心结论：随机化与真实分布抽样使测量既具代表性又可复现；改完内存函数须以基准看性能、以 fuzzer 守正确性，二者成对验收。
