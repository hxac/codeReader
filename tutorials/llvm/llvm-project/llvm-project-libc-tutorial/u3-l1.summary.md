本讲拆解 LLVM-libc 公共头文件生成管线。头文件由 YAML 生成而非手写：`include/` 下约 55 个 `*.yaml` 是唯一事实来源，用结构化字段描述五类内容（函数、宏、类型、枚举、对象）；函数条目用 `name`/`return_type`/`arguments` 渲染 C 声明，`standards`/`guard`/`attributes` 负责分类与条件编译。Python 工具链 hdrgen 走“YAML→类对象→C 字符串”三段式——`yaml_to_classes` 反序列化为 `Function`/`HeaderFile` 并按名排序保证稳定，`Function.__str__` 把字段映射成声明，`public_api` 拼成片段并统一追加 `__NOEXCEPT`。无法用 YAML 表达的手写内容（如 errno 的平台包含）经可选 `.h.def` 模板承载，用 `%%public_api()` 占位符由 `fill_public_api` 字符串替换拼装，仓库仅 5 个 yaml 配 `.h.def`，其余用默认模板。CMake 的 `add_gen_header` 构建期调用 `main.py`，借 `--entry-point` 名单过滤本平台函数，Overlay 模式默认不生成、回退系统头。引入术语 hdrgen、`.h.def`、`%%public_api()`、`add_gen_header`、entry-point 过滤，承接 u3-l2 代理头与公共宏/类型、u5-l1 函数族。
