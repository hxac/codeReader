本讲回答「如何验证 LLVM-libc 数学函数算得对」。核心思路是**参考实现对照**：用任意精度的 MPFR（实数域）/MPC（复数域）充当「真值」，把参考值舍入到目标类型后与实现输出做 **ULP**（末位单位）比较，而非比绝对值。封装分三层：`MPFRNumber`/`MPCNumber` 做 RAII 值对象、`Operation` 枚举配 `switch` 实现运算分派、`MPFRMatcher`/`MPCMatcher` 伪装成 gtest 匹配器，并用 `is_valid_operation` 的 SFINAE 在编译期校验输入输出元数。精度容差由 `get_precision` 决定：容差 ≤ 0.5（要求正确舍入）时用与输入同精度以防**双重舍入**误判，否则用 `ExtraPrecision`（128/256/512 位）高精度中间计算；复数比对要求实部虚部同时达标。本讲特别澄清：`check_mpfr.cpp` 仅是构建期探针，CMake 经 `try_compile` 设定 `LIBC_TESTS_CAN_USE_MPFR`；真正的逐点比对由 `EXPECT_MPFR_MATCH` 宏（覆盖手挑难点）与穷举测试（多线程枚举每位模式）驱动，误差超限时分两级打印输入/结果/ULP 诊断。
