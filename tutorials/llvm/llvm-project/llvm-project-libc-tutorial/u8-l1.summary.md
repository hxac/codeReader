本讲讲解 LLVM-libc 的 `__support/OSUtil` 子模块——所有入口点共享的私有工具库，定位为跨 OS 的系统调用抽象层。其核心是「目录隔离 + 头文件分派」的两层机制：顶层 `syscall.h` 在预处理期按 OS 预定义宏（如 `__linux__`）选 OS，`linux/syscall.h` 再按 `LIBC_TARGET_ARCH_IS_*` 选架构，最终落到具体陷阱指令（x86_64 用 `syscall`、aarch64 用 `svc 0`、riscv 用 `ecall`）。分派有两条平行通道：源码通道靠编译器预定义宏，构建通道靠 CMake 的 `LIBC_TARGET_OS`/`LIBC_TARGET_ARCHITECTURE`（源自目标三元组），二者各自独立却天然一致。

封装分两层：`syscall_impl` 是变参模板，把参数转为 `long` 后调用架构版内联汇编、不做错误检查；`syscall_checked` 在其上加判错并返回 `ErrorOr`。Linux 内核出错时返回负 `errno`（绝对值 ≤ 4095），syscall 层据此用 `ret >= -MAX_ERRNO`（无符号）或 `ret < 0`（有符号）判错，取反成正 `errno` 包进 `Error`，成功值由 `bit_or_static_cast` 安全转换。`syscall_wrappers/*.h` 中的薄封装统一返回 `ErrorOr`，供上层入口点消费并翻译为「设 `libc_errno` 并返回 `-1`」的标准 C 语义。这套分层加双通道分派使更换 OS/架构几乎无需改动业务代码，为后续程序启动、stdio FILE 模型、分配器与线程等讲义奠定地基。
