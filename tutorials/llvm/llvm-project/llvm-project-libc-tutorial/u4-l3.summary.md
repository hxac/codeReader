本讲义讲解 LLVM-libc 中「失败需报告 errno」的函数的两层错误处理机制。内部传错用统一类型 `ErrorOr<T>`（即 `cpp::expected<T, int>` 的别名，`Error` 为 `cpp::unexpected<int>` 的别名），以 `union` 加 `bool is_expected` 构成判别式联合，提供 `has_value()/value()/error()/operator bool` 等接口。对外写错引入 `libc_errno` 抽象：实现代码一律写 `libc_errno`、不直接碰 `<errno.h>`，其落地方式由 `LIBC_ERRNO_MODE` 六种取值（UNDEFINED/THREAD_LOCAL/SHARED/EXTERNAL/SYSTEM_INLINE 等）决定，Full 模式默认 THREAD_LOCAL、Overlay 模式默认 SYSTEM_INLINE；自带模式下 `libc_errno` 是 `Errno` 全局对象，经 `operator=(int)`/`operator int()` 转发存储，错误码常量则经代理头 `hdr/errno_macros.h` 按构建模式分流。核心结论是一条端到端错误传播模式：内核返回负错误码 → syscall 封装层用 `Error(-ret)` 取反后包成 `ErrorOr` 失败侧 → 公开入口点 `if(!ret){ libc_errno=ret.error(); return -1; }`，成功则 `return ret.value();`，`dup` 为其范本，内部传错与对外返回约定两层相互解耦。
