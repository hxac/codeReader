本讲解决实现代码如何用同一条 `#include` 在 Full/Overlay 两种构建模式下取得「语义相同、来源不同」的类型与宏，引入四类核心构件：代理头 `hdr/` 以 `#ifdef LIBC_FULL_BUILD` 在「内部自包含定义」与「系统头」间二选一，使 `src/` 只写一条 include；`llvm-libc-types/` 与 `llvm-libc-macros/` 是两类自包含公共头成品（一类一文件、安装即用），Full 下既被 hdrgen 拼进公共头，又被代理头采用；`__llvm-libc-common.h` 作所有公共头的通用前缀，提供 `__LLVM_LIBC__` 标记与跨 C/C++ 移植宏（`__BEGIN_C_DECLS`、`__NOEXCEPT`、`__restrict`）。关键术语：代理头、自包含成品、`LIBC_FULL_BUILD`、`__SIZE_TYPE__`、不透明前向声明、`FULL_BUILD_DEPENDS`/`DEPENDS`。核心结论：`size_t` 自包含、零系统依赖；`FILE` 因 ABI 敏感，Overlay 下须挂 overlay 头目标拉系统布局，这正是 `fopen` 不能进 Overlay 的根因。
