本讲厘清 LLVM-libc 的五种构建场景，指出它们本质只沿两个正交维度变化：构建根目录（`runtimes/` 还是 `llvm/`）与开关 `LLVM_LIBC_FULL_BUILD`。Overlay 模式（开关 OFF）产出 `libllvmlibc.a`，借助静态库的链接顺序语义覆盖系统 libc 中的少数符号、其余回退，只能放入不依赖实现私有 ABI 的纯算法函数（如 `strlen`、`round`）。Full 模式（开关 ON）则是完整 libc 替换品，产出 `libc.a`、`libm.a`、启动对象并自生成头文件，强制要求 `headers.txt`。关键概念是 ABI：`fopen` 因依赖 `FILE` 结构的私有布局而不能进 Overlay，证据是代理头 `hdr/types/FILE.h` 在两模式间切换不同的 `FILE` 定义。Bootstrap 与 Cross 描述构建流程，可与两者组合；GPU 因无系统 libc 而天生走 Full。
