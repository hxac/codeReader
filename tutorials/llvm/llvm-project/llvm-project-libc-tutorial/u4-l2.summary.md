本讲阐明 LLVM-libc 必须自备一套 C++ 标准库子集 `src/__support/CPP/`：它要替换系统 libc、要跑在 GPU/baremetal/UEFI 等无 C++ 运行时的目标上、且追求符号洁癖，故不能依赖 libstdc++/libc++，只能自带「只够自用的部分重实现」。该子集靠三条纪律维持「自包含」：只 include 本目录头、free-standing C 头（用 `<stddef.h>` 而非 `<cstddef>`）与少数 `macros/` 宏头；全部锁进 `LIBC_NAMESPACE::cpp` 命名空间；每个 `CPP/foo.h` 是 `std::<foo>` 的「精确子集」，语义可平移。代表性工具 `cpp::numeric_limits` 以模板特化加位运算（`T(-1)<T(0)` 判符号、`CHAR_BIT*sizeof(T)` 算位数）推导整型极值，取代魔法数字，浮点交由 FPUtil；`cpp::span` 则是安全的「指针+长度」非拥有视图，复用自家 numeric_limits（`dynamic_extent`）与 type_traits。入口点使用须两步缺一不可：C++ 里 include 对应头并写 `cpp::xxx`，CMake `DEPENDS` 里加 `libc.src.__support.CPP.<foo>`。
