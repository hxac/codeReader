本讲讲解把 LLVM-libc 移植到全新 OS/架构的方法论流程。核心结论有四：其一，移植第一步是在 `config/<os>/<arch>/` 按命名约定建配置目录，构建系统据目标三元组推导的 `LIBC_TARGET_OS`/`LIBC_TARGET_ARCHITECTURE` 定位它（架构名需归一化，如 riscv64→riscv）；早期可用 `LIBC_CONFIG_PATH` 逃生口绕开登记。其二，`entrypoints.txt` 是渐进增长的清单，用 `set()`+`if()` 条件块表达「本平台在何前提下支持哪些函数」，由顶层 CMakeLists.txt 直接 include()；baremetal 配置是「第一波（syscall 无关纯算法）入口点」最佳范本。其三，平台底层最小实现集很薄：一条 syscall 陷入指令（三级分派链最底层）+ 架构相关 `_start` + 一份 `app.h`，其余算法跨架构复用，体现 retargetable 设计；需同时照顾源码通道（`#ifdef`）与构建通道（CMake `LIBC_TARGET_OS_IS_*`）两条分派路径。其四，「能编译」≠「能用」，`exclude.txt` 用 `try_compile` 做运行环境二阶裁剪；上游化需维护者、CI、接受 sunsetting 三要素。
