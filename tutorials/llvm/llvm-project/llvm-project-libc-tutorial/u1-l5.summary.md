本讲以 `isalpha` 为例，打通 LLVM-libc 一个公开函数从规范到测试的完整链路。入口点（entrypoint）由「五件套」协作：yaml 规范、内部头、cpp 实现、CMake 注册、单元测试。核心结论：`include/ctype.yaml` 是函数签名的事实来源，由 hdrgen 生成公共头；入口实现很薄，仅做边界检查（将输入限制在 [0,255]）与类型转换，真正判定委托给 `ctype_utils.h` 中与字符编码无关的 `internal::isalpha(char)`。引入的关键术语：`LIBC_NAMESPACE_DECL` 把内部符号关进带隐藏可见性的 `__llvm_libc` 命名空间，`LLVM_LIBC_FUNCTION` 用 asm 别名把它映射为公开 C 符号；`add_entrypoint_object` 让函数「可被构建」，各平台 `entrypoints.txt` 决定它「是否进产物」，Overlay 守卫据此把 locale 版函数挡在 Overlay 外；测试直接对内部命名空间 `LIBC_NAMESPACE::isalpha` 断言，`EXPECT_NE(...,0)` 尊重「真即非零」的 C 标准语义。
