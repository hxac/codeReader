本讲解决 printf/scanf 格式串驱动设计的「死代码」难题：浮点转换表、errno 转换等大块代码因格式串在运行期才解析、对编译器不可见，会被无条件链入只打印整数的程序。核心机制是 clang 的 modular_format(impl_fn, impl_name, aspects) 属性，它在 format 属性之上扩展，让编译器在编译期分析字面量格式串，按需把调用重定向到模块化实现（如 __printf_modular），只发出实际所需 aspect 的重定位。关键术语包括：aspect 符号（如 __printf_float）是空函数形式的链接锚点，与浮点实现同处一个 TU，链接器据其是否被引用决定浮点是否进二进制；LIBC_PRINTF_MODULE 宏三态展开（内联定义/弱声明/真定义）配合 LIBC_PRINTF_DEFINE_MODULES 的同一头文件二次包含，把 convert_float 切成弱引用与独立 TU 定义两种形态；默认入口用空重定位 `.reloc ., BFD_RELOC_NONE, __printf_float` 在编译器无法分析格式串时兜底拉入全部 aspect。整套机制由用户配置 LIBC_CONF_PRINTF_MODULAR 开启，经 CMake 的 libc_add_definition 翻译为编译宏 LIBC_COPT_PRINTF_MODULAR，并把把「格式串死代码」从运行期不可见转为编译期可分析、链接期可剔除的闭环。
