本讲为 compiler-rt 建立「目录地图」，覆盖三个最小模块：顶层目录职责、`lib/` 子库分类、`include/` 与 `test/` 的对应关系。核心结论：顶层目录按职责分工——`lib/` 放实现、`include/` 放公共头、`test/` 放功能测试、`cmake/` 放构建逻辑，`docs/`/`utils/`/`www/` 不参与编译；只有 `include`/`lib`/`unittests`/`test`/`tools` 被 `add_subdirectory`。`lib/` 约 28 个子库归为 11 类，构建范围由顶层 `COMPILER_RT_BUILD_*` 开关控制，经 `lib/CMakeLists.txt` 翻译为 `add_subdirectory`。关键术语包括运行时库、sanitizer、`sanitizer_common`（被推导构建的公共底座）、builtins（libgcc 替代品）、`*_interface.h`（每个 sanitizer 一份接口头）。「三位一体」模型指一个运行时库由 `lib/<X>/` 实现、`include/sanitizer/<X>_interface.h` 接口、`test/<X>/` 测试三部分组成；少数例外（如 `test/shadowcallstack` 测编译器特性、`lib/stats` 为公共组件）打破一一对应。
