本讲是 builtins 单元（u2）的地基，阐明 `compiler-rt/lib/builtins` 的本质：它是 GCC `libgcc` 的对应物，专门提供「编译器生成机器码时偷偷调用、但目标 CPU 没有对应单条指令」的帮手函数，如 32 位机上的 64 位除法（`__divdi3`）、无 FPU 机器上的浮点运算（`__addsf3`）、位计数（`__clzdi2`）。核心结论是：这些函数名属于 ABI，builtins 必须沿用 libgcc 的命名，否则已有程序链接失败。

引入的关键术语与概念：（1）函数命名规律 `__<操作><宽度/类型>[目标类型][数字]`，宽度用 `si/di/ti`（32/64/128 位），浮点类型用 `sf/df/xf/tf`，转换类函数同时编码源与目标类型；（2）统一整数类型体系——`int_types.h` 定义 `si_int/di_int/ti_int` 别名与 `dwords/udwords/twords` 等 union，把大整数拆成高低位「字」，使一份纯 C 代码能在 32 位机器上操作 64/128 位数；`int_lib.h` 是每个实现都包含的配置头，含跨编译器宏与三条公共假设（补码、算术右移、大小端）；（3）工程组织——「一函数一文件」，顶层 `GENERIC_SOURCES` 为可移植兜底实现，各架构子目录放汇编优化版，CMake 经 `filter_builtin_sources` 让架构版覆盖同名通用版，最终为每个架构编出 `clang_rt.builtins-<arch>` 静态库。后续 u2-l2/l3/l4 将分别深入整数算术、软浮点与架构相关内建。
