本讲拆解 compiler-rt 测试基础设施 lit，核心结论有三。其一，测试以 lit 的 ShTest 格式执行：测试文件用 `// RUN:` 声明命令，lit 替换其中的替换符（substitution，如 `%clang`、`%run`、`%librt`）后按退出码判定。其二，配置呈两层结构：CMake 模板 `lit.common.configured.in` 注入构建期变量（编译器、目标三元组、libdir），`lit.common.cfg.py` 写公共逻辑——设定 ShTest、清理 ASAN_OPTIONS 等危险环境变量、用 `clang -print-resource-dir/-print-runtime-dir` 定位资源目录并在不一致时以 `-resource-dir=` 与 `-Wl,-rpath=` 强制覆盖；胶水 `lit.site.cfg.py.in` 再加载子套件 `lit.cfg.py`，定义套件特有规则（后缀、`%clang`、`%librt`）。builtins 还由 CMake 按实际编进库的函数生成 `librt_has_<函数>` 特性（feature），实现「按库内容条件运行」。其三，按架构限制测试应优先用精确的 `target-is-${arch}` 特性，避开 `target=...` 正则的两个陷阱（mips 家族误伤、一次测多架构失效）。关键术语：lit、ShTest、替换符、特性、目标三元组、`REQUIRES`/`UNSUPPORTED`/`XFAIL`；运行用 `check-compiler-rt` 或 `llvm-lit [-v|-a]`。
