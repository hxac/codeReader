本讲剖析 LLD ELF 后端的调度中枢 `linkerMain`，它严格按 parse→readConfigs→createFiles→inferMachineType→setConfigs→checkOptions→link 七步推进，两处 `errCount` 检查点分别守护文件加载与选项校验。命令行解析基于 OptTable 框架：`Options.td` 经 TableGen 生成 `Options.inc`，`ELFOptTable::parse` 将 `argv` 解析成结构化的 `InputArgList`，并支持响应文件、`--help` 与拼写纠错；`readConfigs` 与 `setConfigs` 按"架构无关 vs 架构相关"分工，分列于 `createFiles` 之前与 `inferMachineType` 之后。文件加载引入 `LoadJob` 延迟加载抽象：`addFile` 用 `identify_magic` 按文件头魔数（而非扩展名）将输入分类入队为 `Obj`/`Bitcode`/`Archive`/`Shared`/`Binary`，`deferLoad` 标志使同一函数兼顾批量与即时加载；`loadFiles` 用 `parallelFor` 统一并行展开，仅对访问 `ctx.saver` 的 bitcode/fatLTO 路径细粒度加锁，归档成员则全部展开并标记 lazy，故 LLD 无需 `--start-group` 即可处理循环依赖。最后 `inferMachineType` 从首个目标文件推断 `ekind`/`emachine`，`invokeELFT` 以 `switch(ekind)` 分发到正确的 `link<ELFT>` 模板实例。本讲止于产出装满 `InputFile` 的 `files` 列表，交由下一讲 `link<ELFT>` 完成符号解析与写盘。
