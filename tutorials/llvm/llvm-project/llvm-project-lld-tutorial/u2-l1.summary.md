本讲进入 ELF 后端内部，覆盖三个模块。其一，`elf::link()` 是薄入口，接收 `args`/`stdoutOS`/`stderrOS`/`exitEarly`/`disableOutput` 五个参数，只做装配：在堆上建 `Ctx`、初始化 `ErrorHandler`、创建栈对象 `LinkerScript` 与 `SymbolTable`、预置 `symAux`，再调 `ctx.driver.linkerMain(args)`，以 `errCount(ctx)==0` 判定成功。其二，`Ctx` 继承公共层 `CommonLinkerContext`，是链接过程的「总账本」，同时聚合公共状态（分配器 `bAlloc`/`saver`、诊断 `e`）与 ELF 专属状态（`arg`/`driver`/`script`/`target`/`symtab`/`objectFiles`/`inputSections`）；把全局状态堆聚合而非用程序级全局变量，解决了初始化顺序不确定与不可重入两大问题，使 LLD 可在一个进程内当库反复调用。其三，诊断流 `ELFSyncStream`（`Err`/`Warn`/`Fatal`/`Msg`/`Log`/`ErrAlways`）借助 RAII：临时对象先写内部缓冲、析构时加锁一次性提交，既支持流式写法又线程安全并维护错误计数；`Err` 在 `--noinhibit-exec` 下会降级为 `Warn`，`Fatal` 则立即终止。引入的关键术语 `Ctx`、`CommonLinkerContext`、`ErrorHandler`、`ELFSyncStream`、`errCount` 与配置入口 `ctx.arg`，将承接后续 `linkerMain` 内部的选项解析与文件加载。
