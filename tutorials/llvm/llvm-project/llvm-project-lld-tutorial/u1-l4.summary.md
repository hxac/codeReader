本讲解释 LLD 为何是「一个二执行文件内含 ELF/COFF/Mach-O/WebAssembly（含 MinGW 包装）多个后端」，以及它如何决定调用哪一个。入口 `lld_main`（`tools/lld/lld.cpp`）有两条路径：非测试时走快路径，`exitEarly=true` 时用 `_exit` 直接退出、不清理内存；lit 测试时开启 `CrashRecoveryContext`，按 `LLD_IN_TEST` 连跑多遍并校验结果一致性，体现「可重入性」（re-entrancy）。分发逻辑集中在 `Common/DriverDispatcher.cpp`：`-flavor` 选项（优先）或 `argv[0]`（回退）经解析得到 `Flavor` 枚举（Gnu/MinGW/WinLink/Darwin/Wasm），若结果为 Gnu 但目标是 PE（`-m i386pe*`），`isPETarget` 会将其升级为 MinGW。`Driver.h` 用 `LLD_HAS_DRIVER` 宏声明各后端 `link()`，用 `LLD_ALL_DRIVERS` 把它们登记成一张 `{Flavor, 函数指针}` 表，`whichDriver` 查表分发，使后端实现与分发逻辑彻底解耦。库入口 `lldMain` 用崩溃恢复包住 `unsafeLldMain`，返回 `Result{retCode, canRunAgain}`；当 `canRunAgain=false`（内存被污染、不可再入）时调用方应调 `exitLld()` 退出进程。
