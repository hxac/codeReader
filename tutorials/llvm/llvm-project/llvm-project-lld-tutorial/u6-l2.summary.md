本讲讲解 LLD 重定位处理的两阶段架构：并行**扫描**（scanRelocations）只对符号打原子标志位（NEEDS_GOT/NEEDS_PLT/NEEDS_COPY）以规划输出体积，串行**后扫描**（postScanRelocations）才真正分配 GOT/PLT 槽位并生成 copy reloc，拆分动因是 mmap 输出需预知体积。扫描主链 scan→process→processAux 中，process 用 needsGot/needsPlt 把**RelExpr**（机器重定位归约出的架构无关语义）归类打标志；processAux 再由**isStaticLinkTimeConstant**基于 PIC 与可抢占性判定每条重定位是链接期常量（直接 patch 进 .text，零开销）还是运行期**动态重定位**（写入 .rela.dyn，增大体积）。copy relocation（数据符号→.bss）与 canonical PLT（函数符号→.plt）均靠**replaceWithDefined**将 SharedSymbol 就地改写为 Defined，依托所有符号共用等大槽、overwrite 改字节而指针不变。本次 NFC 更新：该函数不再 memcpy 整个 Symbol，只暂存 versionId（因 Defined::overwrite 会将其重置为 VER_NDX_GLOBAL）并用 flags.fetch_and(NEEDS_GOT) 取代快照读写。
