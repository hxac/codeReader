本讲解决「LLD 源码如何变成可用链接器」，分三个模块。其一，LLD 作为 monorepo 子项目，有「随 LLVM 构建」（`-DLLVM_ENABLE_PROJECTS=lld`，最常用）与「独立构建」（`LLD_BUILT_STANDALONE`，自行 `find_package(LLVM)`）两种形态，靠比较 `CMAKE_SOURCE_DIR` 与 `CMAKE_CURRENT_SOURCE_DIR` 判定；顶层用 `add_subdirectory` 无条件纳入 Common 及 ELF/COFF/MachO/wasm 四后端，印证 LLD 始终是全架构交叉链接器。其二，构建只产出唯一可执行目标 `lld`，再经符号链接变出 `ld.lld`、`lld-link`、`ld64.lld`、`wasm-ld` 四个名字，运行时据 `argv[0]` 做 flavor 分发（下讲详述）；`LLD_BUILD_TOOLS` 控制是否编出可执行文件。其三，lit 测试（`check-lld`）重度依赖 FileCheck、llvm-readelf 等 LLVM 工具，借 `LLD_IN_TEST` 连跑两遍 main 验证可重入性。实际使用多以 `clang -fuse-ld=lld` 或符号链接覆盖 `/usr/bin/ld` 调用。
