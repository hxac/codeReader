本讲把 BOLT 的使用串成一条完整的「四步标准流水线」：Step 0 在最终链接加 `-Wl,-q`（即 `--emit-relocs`）保留 `.rela.text` 重定位元数据，使后续能重排函数顺序；Step 1 用 `perf record -e cycles:u -j any,u` 采集分支采样（应用型直接跟命令、服务型用 `-a -- sleep N` 全机定时采样）得到 `perf.data`；Step 2 用 `perf2bolt` 聚合并符号化成紧凑的 fdata；Step 3 用 `llvm-bolt` 叠加 profile 重排代码。核心结论：没有 profile 就无法优化，建议 profile 覆盖约 10 亿条指令，首选 `cycles` 事件。引入的关键术语包括：profile（运行时热冷信息）、分支采样（x86 LBR / AArch64 BRBE）、重定位、`-reorder-blocks=ext-tsp`（块级重排）、`-reorder-functions`（函数级重排，cdsort/hfsort 算法可互换）、`-split-functions`（热冷分裂）、`-dyno-stats`（括号百分比即优化前后相对变化）、MPKI（icache miss 量化，经验阈值约 10）。在无 LBR/VM 环境下，可用 `-instrument` 插桩路径替代：插桩版跑负载直接产出 `/tmp/prof.fdata`，跳过 Step 2，Step 3 命令不变——这是精确计数与高运行开销的取舍。BOLT 默认只做布局优化，不改指令逻辑，故指令总数几乎不变而 taken branches 大幅下降即布局变优的信号。
