本讲承接 u1-l1，讲清三件事：BOLT 如何作为 LLVM 子项目被构建、标准构建命令长什么样、`ninja bolt` 产出哪些工具。

BOLT 是 LLVM monorepo 的子项目（与 clang、lld 同级），配置入口在 `llvm/` 目录，靠 `-DLLVM_ENABLE_PROJECTS="bolt"` 纳入构建；其顶层 `CMakeLists.txt` 里的 `set(LLVM_SUBPROJECT_TITLE "BOLT")` 只是登记身份、用于 IDE 分组，并非构建开关——这是本讲核心认知点。标准命令为 `cmake -G Ninja ../llvm` 配合 `LLVM_ENABLE_PROJECTS=bolt`、`LLVM_TARGETS_TO_BUILD`、`CMAKE_BUILD_TYPE=Release`、`LLVM_ENABLE_ASSERTIONS=ON`，再 `ninja bolt`。

关键概念：BOLT 仅支持 `AArch64;X86;RISCV` 三种目标架构，`BOLT_TARGETS_TO_BUILD` 是 BOLT 支持目标与 `LLVM_TARGETS_TO_BUILD` 的交集，二者不匹配会配置报错；运行时库（`libbolt_rt_instr`/`libbolt_rt_hugify`）经 `ExternalProject_Add` 单独构建，交叉编译时默认关闭。`bolt` 是元目标，一次编出全部工具。

产物分两类：主二进制 `llvm-bolt` 凭 `argv[0]` 分流为优化器、`perf2bolt`（profile 聚合器）、`llvm-boltdiff`（差异对比器）三种模式，后两者是符号链接；`merge-fdata`、`llvm-bolt-heatmap`、`llvm-bat-dump`、`llvm-bolt-binary-analysis` 是各自独立的轻量工具，为后续讲义的端到端流程奠定基础。
