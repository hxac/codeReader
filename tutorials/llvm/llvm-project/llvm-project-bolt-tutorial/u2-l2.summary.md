`BinaryFunction` 是 BOLT 对「一个被处理的函数」的统一抽象，是承接 `BinaryContext` 的核心数据结构：它是一个带阶段标签的加工件，靠 `State` 状态机约束各操作的先后顺序。六个状态 `Empty → Disassembled → CFG → CFG_Finalized → EmittedCFG → Emitted` 分别对应空、反汇编出指令、建好 CFG、布局锁定、发射（保留/释放 CFG），`hasCFG()`、`hasInstructions()`、`isEmitted()` 是常用状态查询谓词。本讲引入四个最小模块：指令表 `InstrMapType`（`offset→MCInst`，CFG 构建前的临时容器，建 CFG 后清空，指令转入基本块）；`FunctionLayout`（描述输出顺序与热/冷/暖分片，是热冷分裂的底层载体，`isSplit()` 判定是否被拆成至少两片非空）；`isSimple()`（函数能否被常规优化的分水岭，遇到拿不准的情况即降级为非 simple，在 `buildCFG` 阶段被 `SkipPredicate` 整体跳过，但重定位模式下仍被搬运）；以及状态回退 `clearDisasmState()`（轻量）与 `resetState()`（重量，回 `Empty` 并标记忽略）。核心结论：常规优化依赖完整可信的 CFG，非 simple 函数只搬运不优化。
