本讲承接 u7-l1，回答 MLIR 的 Operation 从哪里来、归谁管——答案是 Dialect（方言）。它是 MLIR 可扩展性的基本单元，在全局唯一的 namespace（如 `toy`）下封装一组 Operation/Type/Attribute，并配套解析、打印、验证、常量物化、规范化、接口等整组公共行为；操作名前缀即方言 namespace。

本讲含三个最小模块：其一，Dialect 的定义——`Dialect` 类持身份证三件套（name/dialectID/context）与一组钩子，操作/类型/属性经 `addOperations`/`addTypes`/`addAttributes` 在 `initialize()` 登记到 context 全局表，方言对象由 `MLIRContext` 独家拥有。其二，注册与加载——定义方言需 `.td`（ODS 声明）→ `mlir-tblgen` 生成 `.inc` → 手写 `initialize()` 三处协同；核心结论是「注册 ≠ 加载」：`DialectRegistry` 只登记「namespace → 构造函数」目录，`getOrLoadDialect` 才在首次需要时懒加载并拥有方言对象，解析器据此按需加载。其三，内置方言举例——`func`/`arith`/`memref`/`tensor`/`vector`/`scf`/`affine`/`linalg`/`llvm` 各司其职，串成「渐进式下降」链条；自定义方言（如 Toy）机制与之一致，常复用 builtin 类型。
