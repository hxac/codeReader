本讲讲解内存 `Module` 的两种持久化形式：人类可读的 `.ll` 文本与紧凑的 `.bc` 位码。四个最小模块围绕 `Module` 构成无损往返环：`AsmParser`（`LLLexer` 切 Token、`LLParser` 组装 `Module`）解析文本，`AsmWriter`（`AssemblyWriter` 配 `SlotTracker` 为无名值分配 `%0/%1` 编号）打印文本，二者互为镜像、共同定义 `.ll` 文法；`BitcodeWriter` 与 `BitcodeReader` 处理位码。核心结论：两种形式序列化的是同一棵 `Module`，语义等价，差别仅在可读性、体积与读写速度。位码以 bitstream 的「块（block）+ 记录（record）+ 缩写（abbreviation）」组织，文件头魔数为 `42 43 C0 DE`，类型表与常量表前置、每个函数体单独成块。`BitcodeReader` 兼作 `GVMaterializer` 支持**惰性物化（lazy materialization）**——先读骨架、函数体留到用时按需读取，这是 LTO/ThinLTO 与 IR 分发能扩展到大规模的关键；版本兼容性由文本侧 `UpgradeDebugInfo` 与位码侧「纪元（epoch）」+ `ParserCallbacks` 自动升级机制保证。`llvm-as`（`.ll→.bc`）与 `llvm-dis`（`.bc→.ll`）是这条往返链的胶水工具。
