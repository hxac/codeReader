本讲拆开新 Pass 管理器中「分析 pass」的黑盒。分析 pass 只读 IR、不改 IR，产出可被流水线复用的分析结果对象，区别于真正改写 IR 的变换 pass。`AnalysisManager` 以「按需计算 + 缓存 + 失效」三件套管理结果：`getResult` 未命中才计算、`getCachedResult` 只读不计算、`invalidate` 据 `PreservedAnalyses` 丢弃过期项；`Invalidator` 负责「连带失效」，使支配树失效时下游分析跟随失效。随后精读三类核心分析：LoopInfo 依赖支配树（DominatorTree），组织循环森林并回答循环不变性（loop-invariant）查询；别名分析（AA）由 `AAManager` 把 BasicAA 等提供者聚合进 `AAResults`，首个确定性答案（非 MayAlias）胜出，结果分 NoAlias/MayAlias/PartialAlias/MustAlias；MemorySSA 将内存访问建模为 SSA（MemoryUse/MemoryDef/MemoryPhi 与哨兵 liveOnEntry），依赖支配树与 AA，用 walker 的 `getClobberingMemoryAccess` 高效回答 clobber 查询，非默认开启需声明。这三类分析共同构成 u4-l3 经典优化 pass（LICM/GVN）的直接前提。
