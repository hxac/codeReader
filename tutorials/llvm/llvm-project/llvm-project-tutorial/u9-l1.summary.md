本讲覆盖 LLVM 测试基础设施的两大必过类别：位于 `llvm/test` 的回归测试与位于 `llvm/unittests` 的单元测试（整程序 test-suite 在独立仓库，未展开）。核心结论有三：其一，`lit` 是纯 Python 的调度器，主流程为「解析参数→发现→过滤→执行→汇报」，本身不懂 LLVM，靠 `lit.cfg.py` 的工具替换（tool substitutions）与特性登记（available_features）配齐环境；回归测试用 ShTest 格式把 `; RUN:` 行当 shell 流水线执行。其二，`FileCheck` 是独立校验器，靠「单调前进的有序扫描」逐条匹配 `CHECK` 家族指令（`CHECK`/`CHECK-NEXT`/`CHECK-NOT`/`CHECK-LABEL`），退出码 0/1/2 分别表示全匹配、有未匹配、用法错误。其三，单元测试基于 gtest/gmock，`llvm/Testing/Support` 通过 `TakeError` 把不可拷贝的 `Error`/`Expected` 拆成可匹配结构，提供 `EXPECT_THAT_ERROR` 等宏；单元测试同样跑在 lit 之下，由 `GoogleTest` 格式驱动。引入的关键术语：lit、FileCheck、ShTest、GoogleTest、lit.cfg.py、REQUIRES/UNSUPPORTED/XFAIL、update_test_checks.py，为后续 u9-l2 Pass 插件机制承接埋下伏笔。
