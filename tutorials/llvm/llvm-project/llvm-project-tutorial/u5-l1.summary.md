本讲建立 Clang 的整体地图，只覆盖两个最小模块：Driver 与 cc1 的两层划分，以及编译动作编排。核心结论是：`clang` 命令由**外层 Driver**（入口 `clang_main` → `Driver`）与**内层 cc1**（入口 `cc1_main`）配合完成——Driver 兼容 GCC 风格命令行、编排工序、为每个待编译输入自动拼出一条 `clang -cc1` 命令；cc1 才是真正的前端，产出 IR / 汇编 / 目标文件。两者靠 `-cc1` 标志与 `Driver::CC1Main` 回调衔接，默认以 integrated-cc1 在同进程内执行。Driver 的编排分五阶段：**Parse（解析参数）→ Pipeline（构造 Action 动作树）→ Bind（按 ToolChain 选 Tool）→ Translate（生成 Command）→ Execute**，对应三个递进数据结构 `Action` / `Tool 绑定` / `Command`，并可经 `Compilation` 上下文对象复用。关键术语包括 Driver、cc1、Action、Tool/ToolChain、Command、Compilation，以及 Phases 枚举（Preprocess/Precompile/Compile/Backend/Assemble/Link/IfsMerge）。观测开关 `-ccc-print-phases`、`-ccc-print-bindings`、`-###` 分别展示动作树、工具绑定与最终命令。本讲到「Driver 把编译交给 cc1」为止，cc1 内部细节留给后续讲义。
