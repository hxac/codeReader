本讲解决「不重编 LLVM 即可把自定义 pass 注入 opt/clang 流水线」的问题。工具与插件之间是纯 C ABI 契约：插件仅导出 `extern "C"` 的 `llvmGetPassPluginInfo()`，返回 `PassPluginLibraryInfo` 结构体（含 API 版本、名字、注册回调与可选的 pre-codegen 钩子），从而摆脱 C++ 名字修饰耦合。`PassPlugin::Load` 四步完成动态加载：`dlopen` 打开库、`dlsym` 找入口符号、调用取回结构体、按 `LLVM_PLUGIN_API_VERSION` 校验版本，任一步失败即拒绝。pass 真正生效，靠插件在 `PassBuilder` 上挂两类回调：扩展点回调（如 `registerVectorizerStartEPCallback`）让 pass 在默认 `-O2` 流水线的固定位置自动插入；流水线解析回调（`registerPipelineParsingCallback`）让 pass 获得可被 `-passes=` 显式引用的名字，返回 true 即认领。动态插件、显式 `PassBuilderCallbacks`、静态扩展（`Extension.def` 的 X 宏）三种来源最终汇入同一 `PassBuilder`，行为一致；动态与静态形态由 `LLVM_<NAME>_LINK_INTO_TOOLS` 开关切换，同一份源码用 `#ifndef` 守卫 C 入口是否导出。仓库 `Bye` 是同时演示两种回调与两种形态的官方范本。
