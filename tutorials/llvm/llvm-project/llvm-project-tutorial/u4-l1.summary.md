本讲介绍 LLVM 新 Pass 管理器（New PM）架构，它是中端优化流水线的基础设施。核心结论：新 PM 将「执行变换」与「缓存分析」严格分离，由 PassManager 顺序执行变换 pass、AnalysisManager 惰性计算并缓存分析结果，二者经 PassManager::run 主循环协作。

IR 抽象为四层单位 Module、CGSCC、Function、Loop（层次为 Module→CGSCC→Function→Loop，CGSCC 可选）。pass 分变换 pass（改写 IR）与分析 pass（产出可复用结果）两类，经 CRTP 混入 PassInfoMixin 获取元信息。跨层协作靠两类机制：适配器（Adaptor，如 ModuleToFunctionPassAdaptor）把高层 pass 下钻到低层执行；代理分析（经 crossRegisterProxies 接线）实现跨层分析共享，内层只读外层缓存。失效由 PreservedAnalyses 驱动，pass 声明保住的分析，流水线累计保住的是各 pass 保住集合的交集。

PassBuilder 充当「装配车间」：注册内置分析、按优化等级构造默认流水线、经扩展点（EP）回调让前端/后端/插件注入 pass、用 registerPipelineParsingCallback 扩展 -passes 词表。opt 的 -passes 以逗号分隔、圆括号嵌套描述层级流水线，parsePassPipeline 在首 pass 非模块级时自动包一层管理器，runPassPipeline 串联建四层管理器、PassBuilder、解析与执行。本讲为后续分析 pass、经典优化 pass、自写 pass 讲义奠定框架基础。
