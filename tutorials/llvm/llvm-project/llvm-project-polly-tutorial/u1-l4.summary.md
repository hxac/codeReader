本讲讲清 Polly 插件「被发现、被加载、被挂进 LLVM 默认 `-O3` 流水线」的机制，分两个最小模块。一是 **Pass Plugin API**：Polly 共享库靠导出唯一的 `extern "C"` 符号 `llvmGetPassPluginInfo` 被 LLVM 识别，它返回 `PassPluginLibraryInfo` 结构体（含 API 版本、名字 `"Polly"`、LLVM 版本字符串、回调函数指针 `registerPollyPasses`），体现「入口符号→结构体→回调」的三层间接与控制反转——插件只负责注册，不主动跑优化。二是 **New Pass Manager 注册**：`registerPollyPasses(PassBuilder&)` 注册三类回调——pass 名映射、流水线解析（使 `-passes='polly'` 可用）、扩展点 EP；其中 EP 由 `-polly-position` 二选一，`early` 走 `registerPipelineStartEPCallback`（模块级、需补规范化），`before-vectorizer` 走 `registerVectorizerStartEPCallback`（函数级）。关键结论：代码默认是 before-vectorizer（`cl::init` 实证），而源码注释过时地声称默认 early，印证「信代码不信注释」。两位置最终都汇入 `buildCommonPollyPipeline`，加 `PollyFunctionPass` 加函数简化清理；`PollyFunctionPass::run()` 即后续 U2 的 `PhaseManager::run()`。引入的关键术语有：Pass Plugin、New PM、PassBuilder、Extension Point、`PollyFunctionPass`、X-Macro（`PollyPasses.def`）。
