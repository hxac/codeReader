# 项目总览：Polly 是什么与多面体模型入门

## 1. 本讲目标

Polly 是 LLVM 项目里的一个**多面体循环优化器（polyhedral loop optimizer）**。本讲是整本学习手册的第一篇，目标是让你从零开始建立对 Polly 的整体认知。

学完本讲，你应当能够：

1. 用一句话说清 **Polly 是什么**：它的输入是什么、输出是什么、它处在 LLVM 工具链的哪一环。
2. 理解 **多面体模型（polyhedral model）** 的基本思想，能把一段简单嵌套循环抽象成「迭代域 / 访问关系 / 调度」三件套。
3. 说出 Polly 相对一个普通 `-O3` 编译流程**多做了什么**，以及它能做哪几类循环优化（分块、并行、向量化、常量穿越数组等）。
4. 看懂 Polly 在 LLVM 的标准 pass 流水线中**可以挂载在哪些位置**，以及不同位置各自的取舍。

本讲不要求你懂任何 Polly 内部实现细节，我们只读两个文档级文件：`README` 和 `docs/Architecture.rst`。真正的源码精读从第二讲（U2）开始。

## 2. 前置知识

读本讲前，最好对下面几个概念有**最基本**的了解。如果某个概念陌生，不必担心——本讲会用通俗语言再解释一遍。

- **编译器与中间表示（IR）**：编译器把源代码翻译成机器码时，通常会先转成一种介于「高级语言」和「机器码」之间的中间形式。LLVM 的中间表示就叫 **LLVM-IR**。Polly 工作在 LLVM-IR 这一层，而不是 C/C++ 源码层。
- **pass（编译步骤）**：LLVM 把优化拆成一个个小程序，每个小程序做一件事，这种小程序就叫一个 pass。把多个 pass 串起来运行，就构成了一条「pass 流水线」。`-O3` 本质上就是一条预设好的 pass 流水线。
- **循环（loop）与嵌套循环**：例如矩阵乘法里的两层 `for`，外层遍历行、内层遍历列。Polly 优化的主要对象就是这样的循环核（loop kernel）。
- **矩阵与线性代数直觉**：知道「坐标系里的点」「直线/超平面围成的区域」这类概念即可，不需要会解线性规划。

> 名词速查：
> - **SCoP**（Static Control Part，静态控制部分）：一段「形状规整、可以放心做数学分析」的循环区域。这是后续讲义的主角，本讲先建立直觉。
> - **仿射（affine）**：简单理解为「线性 + 常数」。例如 `2*i + 3*j - 1` 是仿射的；`i*j`（相乘）、`a[i]`（下标里套数组值）就不是。Polly 能否处理一段循环，很大程度上取决于它是不是仿射的。

## 4. 核心概念与源码讲解

本讲拆成两个最小模块：

- **4.1 多面体模型基础**：Polly 用来表示和变换循环的数学语言。
- **4.2 LLVM 优化流水线定位**：Polly 挂在 LLVM 流水线的哪里，以及这背后的取舍。

### 4.1 多面体模型基础

#### 4.1.1 概念说明

传统编译器优化循环时，往往是「盯着一条条指令做局部改写」，比如把循环不变量搬到循环外（LICM）、把两次循环合并（fusion）。这类优化很实用，但有一个根本局限：**它们很难回答「这个循环变换安不安全」这类全局问题**，因为它没有看清整个循环巢的全貌。

多面体模型换了一个思路：**先用一套数学语言把整个循环核完整地描述出来，再在数学层面做变换，最后把变换后的数学结果翻译回代码。**

这套数学描述由三件套组成：

1. **迭代域（Domain）**：每条语句在哪些「迭代点」上执行。一个嵌套循环的循环索引组合起来就是一个整数坐标点，所有合法坐标点的集合就是迭代域。
2. **访问关系（Access Relation）**：每个迭代点会读写哪些内存单元。把数组下标写成迭代坐标的函数。
3. **调度（Schedule）**：这些迭代点按什么先后顺序执行。

为什么叫「多面体」？因为循环索引要满足的约束（比如 `0 <= i < N` 且 `0 <= j < M`）在数学上是一组**线性不等式**，它们在整数坐标空间里围出来的区域就是一个**多面体（polyhedron）**。整个循环核就被压缩成「几个多面体 + 它们之间的函数关系」，于是循环变换就变成了对这些数学对象的代数操作。

Polly 用一个叫做 **ISL（Integer Set Library）** 的库来表示和操作这些整数集合与映射。你在后续讲义里会反复看到 `isl_set`、`isl_map`、`isl_union_map` 这些类型——它们就是「多面体」在代码里的样子。

#### 4.1.2 核心流程

以一段经典的矩阵乘法为例：

```c
for (int i = 0; i < N; i++)
  for (int j = 0; j < M; j++)
    for (int k = 0; k < K; k++)
      C[i][j] += A[i][k] * B[k][j];
```

把它抽象成多面体三件套（用伪数学表示）：

- **迭代域**：设语句为 `S(i,j,k)`，则
  \[
  \text{Domain}(S) = \{\,(i,j,k) \mid 0 \le i < N,\; 0 \le j < M,\; 0 \le k < K\,\}
  \]
  这就是所有「会真的执行一次加法」的坐标点集合。

- **访问关系**：把数组下标写成坐标的函数。
  \[
  \text{Read}_A = \{\,(i,j,k) \to (i,k)\,\},\quad
  \text{Read}_B = \{\,(i,j,k) \to (k,j)\,\},\quad
  \text{RW}_C = \{\,(i,j,k) \to (i,j)\,\}
  \]
  「读 `A[i][k]`」就映射成「坐标 `(i,j,k)` 读单元 `(i,k)`」。

- **调度**：原始执行顺序就是「字典序」
  \[
  \text{Schedule}(i,j,k) = (i, j, k)
  \]
  即先按 `i` 升序、再 `j`、再 `k`。

多面体优化的威力在于：**只要改变调度，等价于改变了循环结构，而迭代域和访问关系不变、程序语义也不变。** 例如：

| 想要的优化 | 调度怎么改 | 直觉效果 |
| --- | --- | --- |
| 循环交换（interchange） | `Schedule = (j,i,k)` | 改变遍历顺序，可能改善缓存局部性 |
| 循环分块（tiling） | 把 `(i,j)` 按 `tile` 大小重排成多层 | 提升缓存命中，改善局部性 |
| 并行化 | 若某维无依赖，调度里把它标记为可任意顺序 | 可用 OpenMP/向量化并行执行 |
| 向量化 | 把最内层重排成连续段 | 供 SIMD 向量单元一次处理多个元素 |

这里有一个关键问题：**怎么知道某个变换安不安全？** 答案是**依赖分析（dependence analysis）**——如果两个迭代点之间有数据依赖（先写后读之类），就不能随意重排。依赖分析会在 U5 专门讲，本讲你只需知道「Polly 之所以敢大胆换循环，是因为它能数学地证明换完不破坏依赖」。

Polly 的端到端流程用一句话概括就是：

```
LLVM-IR  --检测-->  SCoP  --建模-->  多面体模型  --变换-->  优化后模型  --代码生成-->  优化后 LLVM-IR
```

#### 4.1.4 代码实践

这是一个「概念应用型」实践（纸上推导），目的是验证你真的理解了三件套，而不是停留在名词上。

1. **实践目标**：亲手把一段简单嵌套循环抽象成「迭代域 / 访问关系 / 调度」。
2. **操作步骤**：
   - 取下面这段矩阵逐元素缩放代码：
     ```c
     for (int i = 0; i < N; i++)
       for (int j = 0; j < M; j++)
         Y[i][j] = 2.0 * X[i][j];
     ```
   - 写出语句 `S(i,j)` 的迭代域（约束用数学不等式）。
   - 写出读 `X[i][j]`、写 `Y[i][j]` 的访问关系（用「迭代坐标 → 内存坐标」的映射）。
   - 写出原始调度。
   - 思考：如果把调度改成 `(j,i)`（即交换两层循环），语义是否改变？为什么？（提示：每个 `(i,j)` 读写的单元只取决于 `(i,j)` 本身，不依赖执行顺序。）
3. **需要观察的现象**：你会发现「调度的改变不会影响每个迭代点读写哪个单元」，这正是「只换调度就能安全变换循环」的直觉来源。
4. **预期结果**：
   - 迭代域 \(\{\,(i,j) \mid 0 \le i < N,\; 0 \le j < M\,\}\)。
   - \(\text{Read}_X = \{\,(i,j)\to(i,j)\,\}\)，\(\text{Write}_Y = \{\,(i,j)\to(i,j)\,\}\)。
   - 原始调度 \((i,j)\)。改为 \((j,i)\) 语义不变，因为没有迭代间依赖。
5. 关于是否能在本机用 Polly 实际验证循环交换效果：**待本地验证**（需要先按 U1-L3 构建好带 Polly 的 clang，本讲尚未到那一步）。

#### 4.1.5 小练习与答案

**练习 1**：下面哪个数组下标是「仿射的」（Polly 较容易接受）？

- (a) `A[2*i + 1]`
- (b) `A[i*j]`
- (c) `A[p[i]]`（`p` 是另一个数组）

> **答案**：只有 **(a)** 是仿射的。`2*i+1` 是「线性 + 常数」。`(b)` 含两个循环变量相乘，非线性；`(c)` 下标里套了另一个数组的值，依赖运行时数据，不是常量下标函数。Polly 主要处理仿射访问。

**练习 2**：多面体三件套里，哪一个改变会「直接对应一次循环变换」？

> **答案**：**调度（Schedule）**。调度决定执行顺序，改变调度等价于改变循环结构；而迭代域和访问关系描述的是「算什么、读写哪里」，一般保持不变。

**练习 3**：为什么多面体方法能比传统逐指令循环优化「看得更全局」？

> **答案**：因为它把整个循环核一次性抽象成数学对象（域 + 访问 + 调度 + 依赖），可以在数学层面精确证明「某种重排是否破坏依赖」，而不是在指令层面靠启发式规则逐条判断。

### 4.2 LLVM 优化流水线定位

#### 4.2.1 概念说明

知道了 Polly「做什么」，还要知道它「挂在哪」。Polly 不是一条独立的命令，而是**插在 LLVM 的 pass 流水线里**的一段。理解标准 LLVM `-O3` 流水线的结构，才能理解 Polly 为什么有两种典型挂载位置、各自的取舍。

`docs/Architecture.rst` 把标准 LLVM pass 流水线（`clang/opt` 在 `-O1/-O2/-O3` 下用的那条）划分成几个概念阶段：

- **规范化（Canonicalization）**：以 `mem2reg`、`instcombine`、`cfgsimplify`、早期循环展开等为主，目标是尽量简化 IR、消除冗余。
- **内联循环（Inliner Cycle）**：由「标量简化 + 简单循环优化 + 内联」三组 pass 反复迭代组成。它的主要目的其实仍是规范化、为后续铺路，顺便做一些小优化。
- **目标特化（Target Specialization）**：这是流水线最后一段，**会刻意增加 IR 复杂度**以榨取目标硬件性能，代表就是**向量化（vectorization）**、目标相关的循环展开与循环分布。

Polly 想插进这条流水线，自然就有「插在哪个位置」的问题。

#### 4.2.2 核心流程

`Architecture.rst` 指出 Polly 概念上可以跑在三个位置，但实际只讨论两个（第三个「内联循环里」会干扰内联器，不推荐）：

```
[规范化] -> [内联循环(标量简化/简单循环优化/内联)] -> [目标特化(向量化...)]
   ^                    ^                                   ^
   |                    |                                   |
   '-- early 位置 ------'-- (不推荐) -----------------'-- before-vectorizer 位置
```

两个推荐位置及其开关：

| 位置 | 开关 | 含义 | 当前状态 |
| --- | --- | --- | --- |
| early（流水线最前） | `-polly-position=early` | 在标准流水线**之前**跑 Polly | **默认** |
| before-vectorizer（向量化之前） | `-polly-position=before-vectorizer` | 在内联循环结束后、**向量化之前**跑 | 非默认（在推进中） |

两者的取舍（直接来自 `Architecture.rst`）：

- **early（默认）**：
  - 优点：此时 IR 离源码很近，「程序员一眼能看懂」，循环核不易被前面的变换改得面目全非，用户反馈好。
  - 缺点：需要额外跑一组规范化 pass，**编译时间略增**；依赖内联才能展开的代码此时还没展开，享受不到内联红利。

- **before-vectorizer**：
  - 优点：内联循环已完整跑过，连重度模板化的 C++ 代码也可能受益；IR 已经规范化好，**几乎不增加编译时间**（检测很快，真正的优化只在含值得优化的循环核的函数上跑）。
  - 缺点：此时 IR 经历了大量 LLVM 优化，往往带有很多**额外的标量依赖**，让 Polly 效率下降——这也是它还不是默认位置的原因。

#### 4.2.5 小练习与答案

**练习 1**：在标准 LLVM `-O3` 流水线里，「向量化」属于哪个概念阶段？

> **答案**：**目标特化（Target Specialization）**。这一段会刻意增加 IR 复杂度来榨取硬件性能，向量化是其中最有代表性的优化。

**练习 2**：为什么 Polly 默认位置是 `early` 而不是 `before-vectorizer`？

> **答案**：因为 `before-vectorizer` 位置下，IR 已经过大量 LLVM 优化，带有很多**额外标量依赖**，使 Polly 效率明显下降（Polly 还在改进以适应这种情况）；而 `early` 位置 IR 贴近源码、循环核未被改坏、用户反馈更好，代价只是少量编译时间增加。

**练习 3**：如果你写的是「重度模板化、必须靠内联才能露出循环」的 C++ 代码，哪个位置对 Polly 更友好？

> **答案**：**`before-vectorizer`**。因为它在内联循环之后运行，模板代码已经被内联展开，Polly 才有机会看到真正的循环核；`early` 位置此时还看不到（还没内联）。

## 6. 本讲小结

- **Polly 是什么**：LLVM 的多面体循环优化器；吃 **LLVM-IR**，吐**优化后的 LLVM-IR**，不碰源码与机器码。
- **核心数学语言**：用「**迭代域 + 访问关系 + 调度**」三件套把循环核抽象成多面体对象，依赖 ISL 库表示与操作。
- **变换的本质**：在保证依赖的前提下**改调度**，等价于改循环结构（交换/分块/并行/向量化）。
- **声称能做的优化**：常量穿越数组、删无效迭代、缓存局部性优化、数组优化、自动并行化、向量化、软件流水线。
- **流水线位置**：标准 `-O3` = 规范化 → 内联循环 → 目标特化（向量化在此）；Polly 默认在 **early**（流水线最前），也可选 **before-vectorizer**（向量化前）。
- **取舍**：early 贴近源码、循环核不易被改坏，但编译时间略增、吃不到内联红利；before-vectorizer 几乎不增加编译时间、能享受内联，但 IR 带额外标量依赖、Polly 效率打折。
