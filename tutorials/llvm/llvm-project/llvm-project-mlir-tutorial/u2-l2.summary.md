本讲深入 MLIR 核心节点 `Operation` 的内存表示，是第 2 单元「承重墙」。核心结论：`Operation` 是一段「前缀 results（反序）+ 本体 + 尾随对象（正序）」的定制变长连续内存，由工厂 `create` 一次性 `malloc` 并用 placement-new 逐个填充，故不能用普通 `new`/`delete`，销毁走定制 `destroy()` 退回真实起点再 free。引入的关键术语与概念：trailing objects（尾随对象，`llvm::TrailingObjects`）；result 分两类——前 6 个为 `InlineOpResult`（索引塞进类型指针低位、不占字段），第 7 个起为 `OutOfLineOpResult`（多 `outOfLineIndex`），反序前置使任一 result 可 O(1) 算回 owner；operand 存于 `OperandStorage`，初始走尾随数组、超容量则按 2 的幂外迁到动态缓冲区，是唯一可变的「形状」；region 为恒定数量尾随 `Region[]`，successor 为终止符才有的尾随 `BlockOperand[]`；`OperationState` 是「建操作的物料清单」；`OpOperand`/`BlockOperand` 构造即自动挂入 Value 的 use-def 双向链表，支撑高效 RAUW；块内顺序用「等距编号+中点插入+懒重算」实现摊还 O(1) 支配判断。result 的语义、use-def 链留待 u2-l3，Region/Block 的控制流语义留待 u2-l4。
