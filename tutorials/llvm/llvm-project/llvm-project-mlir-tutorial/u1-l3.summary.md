本讲剖析 MLIR 命令行工具 `mlir-opt` 的入口骨架与执行链路。核心结论：`mlir-opt` 是「读 IR → 可选跑 pass → 写 IR」的试验台，并非完整编译器；其 `main` 极薄，仅做两件事——注册能力，再委托给共享库函数 `MlirOptMain`。

引入的关键概念：IR（中间表示，含文本与字节码两种落盘形式）、dialect（方言，Operation/Type/Attribute 的命名空间）、pass（IR 变换单元）、registry（方言注册表）、`MlirOptMain`（类 opt 工具的公共入口）。

执行主线为 `main → 注册 → MlirOptMain → performActions（解析/跑流水线/打印）`。关键区分：dialect 注册填入具体 `DialectRegistry` 对象，决定能解析哪些方言（延迟加载）；pass 注册填入全局表，决定命令行能按名字调度哪些 pass（如 `--cse`）。`MlirOptMain` 内部经 `processBuffer` 为每段输入建独立 `MLIRContext`，再由 `performActions` 完成 `parseSourceFileForTool → pm.run → 序列化输出` 三段式。最后通过对比 `mlir-minimal-opt`（空 registry 最小骨架）与 `standalone-opt`（按需注册），说明「只需注册会被解析的 dialect」这一白名单本质，并介绍 `--pass-pipeline`、`--show-dialects`、`--emit-bytecode`、`--allow-unregistered-dialect` 等命令行参数。
