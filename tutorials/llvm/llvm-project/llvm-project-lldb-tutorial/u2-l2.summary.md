本讲拆解 SBDebugger 的生命周期，核心是「系统初始化（全局一次）」与「实例创建（可多次）」两层分离。`SBDebugger::Initialize/Terminate` 只是公共薄壳，转发给全局守卫 `g_debugger_lifetime`（即 `SystemLifetimeManager`，由 `llvm::ManagedStatic` 管理）。守卫用引用计数保证整个 LLDB 系统「只在第一次请求时真正初始化、只在最后一次请求时真正终止」。真正的启动逻辑在 `SystemInitializerFull::Initialize` 中按固定顺序展开：先底层设施（`SystemInitializerCommon` 负责日志、文件系统、Host、Socket），再初始化 LLVM/Clang 后端，随后遍历 `Plugins.def` 用 `LLDB_PLUGIN_INITIALIZE` 宏注册全部插件，再 `PluginManager`、全局设置（须在插件之后），最后 `Debugger::Initialize` 建全局列表与线程池；`Terminate` 严格逆序。公共 `SBDebugger` 与内部 `Debugger` 是「代理↔实现」关系（`Debugger` 继承 `UserID`、`Properties`、`enable_shared_from_this`）。`Create` 经 `Debugger::CreateInstance` 登记进全局列表 `g_debugger_list_ptr`，实例 ID 来自计数器 `g_unique_id`（自 1 起），实例名为 `debugger_<ID>`。销毁分两层：`Destroy` 销毁单实例、`Terminate` 终止整个系统。关键约束是「对称性」——`~SystemLifetimeManager` 用 `assert(m_initialized==m_terminated)` 强制 `Initialize`/`Terminate` 成对次数相等，否则进程退出时崩溃。关键术语：引用计数、RAII/析构对称、`g_debugger_lifetime`、`SystemInitializerFull`、`Plugins.def`、`g_debugger_list_ptr`、`g_unique_id`、对称不变量。
