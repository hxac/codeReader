本讲在「SBDebugger 是入口」之上展开 LLDB 的核心 SB 对象模型，建立两条层级：一是运行时执行层级 SBTarget→SBProcess→SBThread→SBFrame→SBValue，描述程序运行到某一刻所形成的对象树；二是与进程状态无关的符号层级 SBModule→SBSection/SBSymbol/SBCompileUnit，承载断点设置、行号回溯与 image 系列命令。核心结论有：SB 导航的本质是取出内部对象的共享指针（XxxSP）并重新封装为一个新的轻量代理对象，从不复制业务数据，无效对象导航只得无效对象；读取线程、栈帧、变量之前进程必须处于停止状态，由 StopLocker（运行锁）保证数据稳定、GetAPIMutex 串行化 API 访问、GetStoppedExecutionContext 统一前置检查，而目标级取模块因模块列表自身线程安全、且在进程启动前已建好而无需加锁。关键术语包括共享指针、代理模式、执行上下文、StopLocker，以及 ValueImpl——SBValue 借它在保持「单一成员」与 ABI 稳定的前提下携带「动态类型值/合成展示」偏好，并可递归展开为一棵值树。C++ 与 Python 走的是同一套 SB API。
