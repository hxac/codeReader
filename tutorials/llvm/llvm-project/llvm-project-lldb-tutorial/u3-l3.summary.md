本讲（u3-l3）以 `breakpoint set`、`expression`、`disassemble` 三条命令为样本，讲透「命令文本如何变成一次真实调试操作」。核心模块有三：一是命令注册表——`CommandInterpreter::LoadCommandDictionary()` 用 `REGISTER_COMMAND_OBJECT` 宏把命令名映射到 `CommandObject` 类，由此可反查任意命令的 `DoExecute`；二是三种命令形态在此齐聚，`breakpoint` 为多词容器（`CommandObjectMultiword`），靠 `LoadSubCommand` 挂载 `set/enable/list` 等子命令，`expression` 为原始命令（`CommandObjectRaw`）用 `OptionsWithRaw` 切出表达式，`disassemble` 为解析命令（`CommandObjectParsed`）直接驱动 `Disassembler` 插件。核心结论是：命令层只是翻译层，职责仅限「解析选项、判断意图、调用 `Target`」。`breakpoint set` 用优先级瀑布把选项组合翻译成断点类型（`eSetTypeFileAndLine` 等）再 switch 调 `Target::CreateBreakpoint`；`expression` 组装 `EvaluateExpressionOptions` 后调 `Target::EvaluateExpression`，返回的 `ValueObjectSP` 被 Dump 输出。关键洞见：命令层直接操作 `lldb_private` 内部对象而非 SBAPI，命令路径与 SB API 路径最终汇聚到同一批 `Target` 方法上。
