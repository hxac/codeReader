本讲拆开 `lldb` 可执行文件的启动链路，揭示它只是链接 `liblldb` 的一层薄壳「驱动（Driver）」，自身不含调试逻辑。`main()` 主线为 `InitLLVM` → `LLDBOptTable::ParseArgs` → `SBDebugger::InitializeWithErrorHandling` → 构造 `Driver` → `ProcessArgs` → `MainLoop` → `SBDebugger::Terminate`，且 Initialize/Terminate 与 Driver 生命周期靠花括号严格对称。引入的关键术语：TableGen 声明式选项系统（`Options.td` 生成 `Options.inc`，由继承 `GenericOptTable` 的 `LLDBOptTable` 解析，新增选项只需改 `.td`）；`SystemInitializerFull`（初始化 LLVM 后端并按 `Plugins.def` 注册全部插件，设置初始化须在插件之后）；`MainLoop` 两次调用 `RunCommandInterpreter`——首次同步执行命令行翻译出的命令流，第二次进入 stdin 交互循环；`--version` 等选项在 `ProcessArgs` 置 `exiting` 提前退出，不进入 MainLoop。`SB*` 公共 API 与 `lldb_private::` 内部分层亦在此体现。
