本讲阐述 LLDB 公共 C++ API（SBAPI）的设计哲学。LLDB 分两个命名空间：lldb（公共 SB API，承诺 ABI 稳定）与 lldb_private（内部实现，可自由重构）。SB* 类是轻量代理，唯一成员是指向内部对象的共享指针，只做转发与封装，复杂逻辑置于内部类。

为保障 ABI 稳定与 SWIG 绑定，SB 类须守五条规则：命名 SB<Name>、不可继承、无虚函数、单一成员、可默认构造——这使对象内存布局恒定，可新增方法而不破坏已链接的旧二进制。关键术语：ABI（二进制接口，改了会让旧二进制失效，区别于只需重新编译的源码 API）、SWIG（据 C++ 头自动生成 Python/Lua 绑定的工具）。内部类以不透明前向声明集中于 lldb-forward.h，公共头不泄漏内部布局；需额外状态时用 Impl 类（如 SBValue→ValueImpl）保持 SB 对象大小恒定。默认构造产生空对象，用 IsValid() 判定有效性，方法须优雅处理后端为空（SBError 例外）。同一套 SB 类经 SWIG 同时服务 C++/Python/Lua，用 #ifndef SWIG 宏控制方法是否暴露给脚本。具体 SB 业务方法与对象导航关系留待后续讲义。
