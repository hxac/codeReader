本讲讲「如何把 LLDB 源码变成可执行文件」，含四个最小模块。其一是两种构建方式：in-tree（cmake 指向 monorepo 的 llvm 目录，用 `LLVM_ENABLE_PROJECTS="clang;lldb"` 一个树建全，官方推荐）与 standalone（指向 lldb 目录，靠 `LLVM_DIR`/`Clang_DIR` 借已建好的 LLVM/Clang，迭代 LLDB 更快），判据是顶层 `CMakeLists.txt` 比较 `CMAKE_SOURCE_DIR` 是否等于当前目录，相等即 standalone 并置 `LLDB_BUILT_STANDALONE`。其二是选项体系：`cmake/modules/LLDBConfig.cmake` 是「选项字典」，可选依赖（Python、Lua、LibEdit、Curses、LZMA、LibXml2、SWIG、Tree-sitter）经 `add_optional_dependency` 三态管理（Auto 自动探测/On 缺失报错/Off 静默关闭），Python/Lua 启用才构建 `bindings/`。其三是三类核心产物：命令行驱动 `lldb`（薄壳，链接 liblldb）、调试服务端 `lldb-server`（平台相关，刻意不链接 liblldb 而直链内部库与插件）、聚合动态库 `liblldb`（在 `source/API/CMakeLists.txt` 定义，链接几乎全部内部模块与 `${LLDB_ALL_PLUGINS}`，对外暴露 SB API）。其四是测试开关：`LLDB_INCLUDE_TESTS` 总控、`LLDB_INCLUDE_UNITTESTS` 细控 gtest，关闭可大幅加速；跑 API 测试必须开 Python。核心结论：构建恒为两步（`cmake` 配置生成 `build.ninja`→`ninja <target>` 编译），可用 `ninja lldb` 等单目标省时，验证产物最简方式是 `./bin/lldb --version`，其版本串来自 `SBDebugger::GetVersionString()`，默认沿用 LLVM 版本。关键术语 in-tree/standalone、`LLDB_BUILT_STANDALONE`、`add_optional_dependency`、`liblldb`、`lldb-server`、`LLDB_INCLUDE_TESTS`、`SBDebugger::GetVersionString()` 供后续讲义承接。
