本讲聚焦 orc-rt 执行端的 `Service` 抽象——由 `Session` 独占拥有的「资源管家」基类，负责管理 JIT 内存、动态库等资源。它仅定义两个异步纯虚回调 `onDetach(OnComplete, ShutdownRequested)` 与 `onShutdown(OnComplete)`，完成回调类型为 `OnCompleteFn = move_only_function<void()>`。异步契约要求 Service 清理完毕后必须主动调用 `OnComplete`，否则 `Session` 永久阻塞；`onDetach` 恰在 `onShutdown` 前调用一次，且 JIT 代码可能与 `onDetach` 并发访问 Service，故多数 Service 的 `onDetach` 实现为空操作，真正释放留到 `onShutdown`。

注册 Service 有三种 API：`addService`（传入已构造 `unique_ptr`）、`createService`（原地构造、不可失败）、`tryCreateService`（走 `ServiceT::Create` 静态工厂、可失败返回 `Expected`）；三者都汇聚到私有 `appendService`，返回引用且所有权归 `Session`。

核心不变量是「逆序关闭」：detach 与 shutdown 均按注册逆序（C→B→A）通知，源码用「`back()` + `pop_back()` + 完成回调里递归」优雅兼容异步，保证后注册的依赖者先被销毁（RAII 语义）；通知前须先解锁以防死锁。`appendService` 还会对迟到注册的 Service 同步补做错过的回调，确保每个 Service 恰好经历一次完整生命周期。
