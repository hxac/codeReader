本讲是 orc-rt 仓库的「地图课」，以多个 CMake 文件为依据，理清源码目录布局，核心结论有三。其一，仓库顶层分为 `docs / include / lib / tools / test` 五大目录，由顶层 CMakeLists 串联；其中 `lib/` 下只有 `executor/`，印证 orc-rt 仅运行于 executor 侧。其二，头文件分三层：`include/orc-rt/`（C++ API，含 `Session`、`Error`、`ExecutorAddr` 等）、`include/orc-rt-c/`（C ABI 边界，用 `orc_rt_*Ref` 不透明指针保证布局稳定）、`include/orc-rt-utils/`（工具用）；另有由 `config.h.in` 渲染生成的 `config.h`。其三，`lib/executor/` 的 20 个基础 `.cpp` 编译为静态库 `orc-rt-executor`，日志后端按 `ORC_RT_LOG_BACKEND` 条件追加，平台代码以 `Unix/*.inc` 被 `#include` 进 `.cpp`。本讲引入的关键术语：SPS-CI（Simple Packed Serialization Controller Interface，`sps-ci/` 下 `XxxSPSCI.cpp` 与核心服务一一对应，`AllSPSCI.cpp` 为聚合入口）、Service（资源管理抽象）、`orc-rt-headers`（INTERFACE 纯头文件库）。测试分三类：`test/unit/`（GoogleTest 单元，入口 `check-orc-rt-unit`）、`test/regression/`（lit/FileCheck 回归，入口 `check-orc-rt`）、`test/tools/`（测试支持工具）；测试名与被测源码一一对应，是反向定位源码的捷径。
