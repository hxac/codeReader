本讲概览 orc-rt 错误处理体系，覆盖四个最小模块：`Error`（表示成功或失败）、`Expected<T>`（表示值或错误）、「错误必须被检查」契约、以及错误的创建与消费工具。核心结论：`Error` 与 `Expected<T>` 都是通过返回值传递的一等值，不依赖 C++ 异常，在 `-fno-exceptions` 下也能工作；它们只用于可恢复错误，程序性错误（违反契约、非法状态）应用断言。成功是零开销空值，失败才携带 `ErrorInfoBase` 子类的类型化载荷。心脏契约是：每个 `Error`/`Expected<T>` 析构前必须被检查，失败值还须取走（消费或处理）其载荷，否则 `abort()`，从物理上杜绝静默吞错。需特别留意相反的布尔语义——`Error` 转 bool 为真表示失败，`Expected<T>` 转真表示成功。引入的关键术语有 `make_error`、`StringError`、`consumeError`、`handleErrors`/`handleAllErrors`、`toString`、`cantFail`、用于自定义错误类型的 `ErrorExtends`（背后是不依赖 `-frtti` 的内置 RTTI），以及把 `Error` 暴露给 C 侧的不透明指针 `orc_rt_ErrorRef`。指针位编码、可变参数分派、异常互操作等内部实现留到 u9 展开。
