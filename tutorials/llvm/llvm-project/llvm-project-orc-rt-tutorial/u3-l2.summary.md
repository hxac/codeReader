本讲剖析 orc-rt 执行端 `Session` 的生命周期状态机，覆盖三个最小模块：状态枚举与转移、detach/shutdown 的并发协调、关闭顺序与等待。`Session` 用一个**单调向前**的四态状态机（`Start → Attached → Detached → Shutdown`，另加 `None` 作占位符）描述生命周期，核心是同时维护两个状态变量：`CurrentState`（已发生的事实）与 `TargetState`（被要求的意图），二者落差即「正在进行的工作」。并发协调采用「抢驱动权」机制：第一个把 `TargetState` 从 `None` 改非 `None` 的线程成为驱动者，一气呵成推进；后来者只用 `std::max` 合并意图即返回，而 shutdown 意图天然包含 detach。shutdown 分三阶段：Detach（断 `ControllerAccess` + 逆序 `onDetach`）→ Drain（关闭 Token 窗口、事件驱动等待所有托管代码 Token 释放）→ 逆序 `onShutdown`；两个逆序均靠「`pop_back` + 在完成回调里递归」兼容异步。关键函数链为 `proceedToDetach → completeDetach → waitForManagedCodeTasksThenShutdown → proceedToShutdown → completeShutdown`。`~Session()` 会触发 shutdown 并用条件变量阻塞到 `CurrentState == Shutdown && TargetState == None`，保证对象回收时无托管代码引用，避免 use-after-free。本讲引入的 `onDetach`/`onShutdown`、`Service`、`TaskGroup`/`Token` 等概念将由后续讲义承接。
