本讲聚焦 orc-rt 跨进程通信的「字节容器」`orc_rt_WrapperFunctionBuffer`，它是 wrapper function「字节进、字节出」签名的 C ABI 载体，布局固定、与 C++ 编译器无关。容器仅含 `Data`（指针/内联数组联合体）与 `Size` 两字段，由此衍生四种状态：empty（`Size==0` 且指针为 0）、small（`0<Size≤sizeof(char*)`，复用内联数组，免 malloc）、large（超出阈值走堆分配）、error（`Size==0` 但指针非 0）。SBO 阈值随平台指针宽度自动伸缩。C 端由 `Init/Allocate/FromRange/FromString/FromOutOfBandError/Dispose` 构成生命周期，其中 `Dispose` 的释放条件与「做过 malloc 的状态」精确镜像，故仅 large/error 才 free，杜绝泄漏与误释放。带外错误（out-of-band error）复用一个本不可能的状态来编码失败，零额外字段、零成功路径开销，使通信层只搬字节不解释错误；硬契约是「先 `GetOutOfBandError` 判错，再取 `Data`/`Size`」，否则触发 assert。C++ 层 `orc_rt::WrapperFunctionBuffer` 以仅移动的 RAII 封装上述 C 结构体，用 `swap` 转移所有权避免双重释放，并提供 `allocate/copyFrom/createOutOfBandError/release` 等接口，`release()` 用于把所有权交还 C 边界（如 `Return` 回调）。该容器是整个 RPC 通信层的地基，后续讲义将在此基础上讲 call/handle 流程与 SPS 字节格式。
