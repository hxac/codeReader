本讲把 u6-1 的 SPS 序列化与 u5-2 的 WrapperFunction 流水线焊接成一层极薄的模板 `SPSWrapperFunction<SPSSig>`。它的模板参数是一个 C++ 函数类型（即 **SPS 签名**，如 `int32_t(int32_t,int32_t)`、`SPSError(bool)`），模板在编译期将其拆成返回标签与参数标签，据此装配 SPS 序列化器并注入底层 `call/handle`，自身不搬一字节。类型安全体现在两端：执行端 `handle` 把 `ArgBytes` 反序列化为 handler 声明的强类型参数、按值/引用/右值转发，结果经返回回调序列化回传，并有三处**带外错误短路**；调用端 `call` 把强类型实参序列化、把结果还原成 `Expected<RetT>` 交给 `ResultHandler`，签名不匹配编译即失败。`Serializable<>` 特化实现 `Error`/`Expected<T>` 与 `SPSError`/`SPSExpected<T>` 的**透明转换**，业务函数无需手写桥接。最后 `ORC_RT_SPS_WRAPPER` 宏把任意业务可调用对象包成具备 C ABI 签名、可登记进符号表的具名 wrapper，`Handle` 还可搭配 `handleWithAsyncMethod/SyncMethod` 适配成员方法、用 `SPSExecutorAddr`/`ExecutorAddr::fromPtr` 传对象地址，为 u6-3 的 sps-ci 符号登记铺路。
