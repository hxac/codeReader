本讲围绕 orc-rt 中 `Session::ControllerAccess` 这一执行端↔控制端的桥接抽象展开。它是 Session 的嵌套抽象基类，独占持有，承载双向 RPC：入站由控制端按地址调执行端，出站由执行端按 tag 调控制端。契约含四个纯虚方法（`connect`/`disconnect`/`callController`/`sendWrapperResult`）与一个语义约束 `notifyDisconnected`，后者要求恰好一次触发，并对双向断开幂等——远端先掉线时后续 `disconnect` 须为 no-op。核心难点是 drain 协议：`disconnect` 须在 `notifyDisconnected` 之前用 `failPendingControllerCall` 排空所有 pending（在飞）调用，并与 `callController` 的断开检测串行化，避免遗漏。完成处理器 `OnControllerCallReturn` 必须恰好完成一次，只能经三条受控路径之一：`handleControllerCallResult`（正常结果，领 fresh Token 并 Dispatch）、`failPendingControllerCall`（断开 drain，等价以 `"disconnected"` 走前者）、`failControllerCallInline`（调用者栈尚在时内联失败，借用其 Token、不经 Dispatch）。三条路径互斥穷尽，保证处理器总在能安全触碰托管代码的上下文运行。
