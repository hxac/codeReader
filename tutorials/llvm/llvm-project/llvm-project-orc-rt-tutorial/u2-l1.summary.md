本讲是 orc-rt 架构地图课，建立控制端（链接 LLVM ORC 库、负责编译链接）与执行端（链接 orc-rt、负责执行 JIT 代码及资源管理）的二分模型。围绕五个地基概念展开：Session 是执行端根对象，拥有若干 Service（资源抽象，仅 onDetach/onShutdown 两回调，逆序关闭）；ControllerAccess 是 Session 嵌套的双向 RPC 桥，其不对称性是核心——controller→executor 按地址调用、可触达任意代码，executor→controller 按 tag 调用、只能命中显式登记入口（体现最小权限），未 attach 时立即返回带外错误 "no controller attached"；WrapperFunction 把一切跨端调用收敛为「字节进、字节出」的异步 C 签名，通信层只搬字节、不解释含义，类型还原留给序列化层。托管代码（managed code）由 TaskGroup 与 Token 标定「执行中」，使 shutdown 推迟至所有 Token 释放；关闭三阶段为 Detach→Drain→逆序 onShutdown。本讲仅建立心智模型，状态机、缓冲三态、SPS 序列化留待 u3/u5/u6 展开。
