本讲讲清 orc-rt 的构建与配置。核心结论：它不能独立 cmake，须纳入 LLVM runtimes 体系，配置 `<llvm>/runtimes` 并以 `-DLLVM_ENABLE_RUNTIMES=orc-rt` 引入；runtimes 框架以正确的目标三元组与工具链调用其 CMakeLists，确保与同次构建的 ORC 库 ABI 对齐。最终产物是静态库目标 `orc-rt-executor`，编译标志以 `PRIVATE` 挂载、不传染消费者；顶层固定 C++17、禁用编译器扩展。配置全为编译期：`ORC_RT_ENABLE_RTTI`、`ORC_RT_ENABLE_EXCEPTIONS`（默认均开）等 `option()` 经 `configure_file` 把 `config.h.in` 模板渲染成 `config.h`，源码再以 `ORC_RT_*` 宏裁剪代码，模板内 `#error` 守卫把非法取值挡在编译前。日志由两个正交旋钮控制：`ORC_RT_LOG_BACKEND`（none/printf/os_log，默认 none）决定日志写往何处，`ORC_RT_LOG_LEVEL` 作为 floor 决定编译进二进制的最低级别；默认 none 会整段裁掉日志，但调用点仍被 `sizeof` 做类型检查。测试有两个目标：`check-orc-rt`（lit 回归，依赖 FileCheck/not）与 `check-orc-rt-unit`（GoogleTest）。
