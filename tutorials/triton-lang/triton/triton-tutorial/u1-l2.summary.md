本讲解决「如何把 Triton 在本地装起来、如何验证装对了」这一核心问题，覆盖四个模块：安装方式、CMake/LLVM 构建、测试运行、构建调优。Triton 是编译器项目，安装天然分两步——装 Python 前端与编译 C++/MLIR 后端。安装分三档：pip 预编译 wheel、源码 editable 安装（默认路径，`pip install -e .`）、自定义 LLVM，可控程度递增。editable 安装的本质是「软链接 + 一个 CMake 扩展」：`setup.py` 的 `CMakeBuild` 把 CMake/Ninja 构建伪装成 Python 扩展，并把 `third_party` 下的 nvidia/amd 后端软链到 `triton.backends.*`。C++ 部分依赖由 `cmake/llvm-info.json` 的 `llvm_hash`（40 位 commit）精确锁定的 LLVM 版本，默认下载官方预编译包并做 SHA256 校验，可用 `LLVM_SYSPATH` 指向自编译版本。测试分两套：`test/` 下的 lit 测试（由 `triton-opt` + `FileCheck` 驱动，无 GPU，验证 IR pass 变换）与 `python/test/` 下的 pytest（多需 GPU，端到端）；`make test-nogpu` 是无 GPU 环境的最全组合，其包含关系为 `test-lit ⊂ test-nogpu ⊂ test`。关键调优开关：`MAX_JOBS`（限编译并发防 OOM）、`TRITON_PARALLEL_LINK_JOBS`（限链接并发）、`TRITON_BUILD_WITH_CCACHE`（跨构建缓存）、`--no-build-isolation`（稳定构建路径避免重链）；纪律上仅改动 native/C++ 才需 `make` 重建。关键术语：editable 安装、构建隔离、llvm_hash、triton-opt、lit/FileCheck、TTIR/TTGIR、CMakeBuild，均为后续源码阅读的基础。
