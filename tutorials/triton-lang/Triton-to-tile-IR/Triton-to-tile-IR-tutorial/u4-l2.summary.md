本讲聚焦 TileIR 后端的性能调优实践（以阅读文档与源码为主，不修改源码）。核心结论：性能「主开关」是 occupancy（每 SM 活跃块数，1–32，默认 1，控制寄存器使用）与 num_ctas（每 CGA 的 CTA 数，1/2，默认 1）；num_warps 被 TileIR 忽略、不可调，autotune 搜它无意义；num_stages 在 TileIR 是「成本提示」而非强制指令，应放宽搜索（1–10）；approx/ftz 默认关（与 PTX 默认开相反），用环境变量开启并计入重编译 hash。这些旋钮在 make_tileir 中分流——occupancy/approx/ftz 走 opt（TileIROptions），num_ctas/num_warps/num_stages 走 metadata，旋钮在此烘焙进 IR、tileiras 看不到。本讲引入两条结构性优化原则：TMA API 偏好（tileiras 对 tl.load 有已知性能问题，dot 类内核须用 tensor descriptor 加载，比指针式快约 18%）与 CGA 级 tile 表示（tile 以 CGA 为单位，BLOCK_SIZE 应比 PTX 适当放大，tile 宽即 BM×BN≥256×128 时配 num_ctas=2 启用 Blackwell 2CTA MMA）。关键术语：CGA（协作网格阵列）、2CTA MMA、TMA、Helion，以及 indexing 的 tensor_descriptor/pointer/block_ptr 三种取值（后者 TileIR 不支持）。最后是 Helion 移植禁忌：不可直接复用 PTX 后端配置，须删除 range_*、static_ranges、load_eviction_policies、indexing="block_ptr" 等 PTX 独有旋钮并从零 autotune，且 ENABLE_TILE、HELION_BACKEND、HELION_AUTOTUNE_COMPILE_TIMEOUT 须在 import 前设置。
