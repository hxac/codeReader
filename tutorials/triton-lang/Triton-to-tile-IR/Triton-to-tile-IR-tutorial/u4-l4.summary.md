本讲梳理「Python 打包脚本 → CMake 配置 → 外部依赖克隆/补丁/构建 → 静态库链接」的完整构建链路，含三个最小模块。其一，cuda-tile 是 NVIDIA 上游项目（定义 cuda_tile 方言及 bytecode），构建期在 CMake configure 期以 pinned commit 与 tag v13.3.0 克隆到构建树，因本仓库 LLVM 更新而施加 6 类补丁（含全局 DenseIntOrFPElementsAttr 重命名与 i1 bytecode 布局兼容桥），补丁只作用于构建副本、源码保持纯净。其二，setup.py 将 tileir 与 nvidia/amd 一视同仁地注册为 in-tree 后端，经 -DTRITON_CODEGEN_BACKENDS 透传 CMake、triton.backends entry point 暴露运行期、符号链接让 python/triton/backends/tileir 指向 third_party/tileir/backend。其三，TritonTileIR 插件直接链接三个 cuda-tile 静态库（libCudaTileTransforms/BytecodeWriter/BytecodeCommon），并经 in-tree 库 PUBLIC 传递引入 libCudaTileDialect.a。关键术语：CMake configure/build 期、entry point、symlink、静态库、CUDA_TILE_INSTALL_DIR、HAVE_CUDA_TILE_INSTALL、TRITON_BACKENDS_TUPLE、INIT_BACKEND。后端名 tileir 从 setup.py 列表贯穿至 C++ 入口 init_triton_tileir，构成单一命名链。
