本讲聚焦 TileIR 后端编译链路核心环节——把 TTIR lowering 成 `cuda_tile` 方言的转换 Pass——的「骨架与入口」，不展开具体算子 lowering。

核心结论有三条。其一，Python 侧 `tileir` 模块来自 C++ 插件 `TritonTileIR`（源文件 `triton_tileir.cc`）：后端名 `tileir` 经 setup.py → `TRITON_CODEGEN_BACKENDS` → CMake 宏 → main.cc 的 `INIT_BACKEND` 宏一路贯穿，自动决定 C++ 入口函数名（`init_triton_tileir`）与 Python 子模块名；`triton_tileir.cc` 通过 `m.def` 暴露 `tileir.passes.*`（`add_triton_to_cudatile` 等薄壳函数）及 `load_dialects`、`only_contain_legal_dialects`、`write_bytecode`。

其二，`Passes.td` 用 TableGen 定义 `convert-triton-to-cuda-tile` 的七个选项（approx/ftz/capability/num_ctas/num_warps/occupancy/num_stages），`mlir-tblgen` 生成基类供 Pass 类继承；选项在 `.td` 字段名、pybind 形参、Python 实参三处一一对应，其中 `num_warps/num_ctas/num_stages` 走 metadata，其余走 opt。

其三，`CudaTileConversionTarget` 把 `cuda_tile` 设为合法、`triton/scf/cf/gpu/ub` 设为非法，并对 `BarrierOp`、`IndexCastOp`、`UnrealizedConversionCastOp` 开白名单；`applyFullConversion` 强制不残留非法 op，把不支持算子的错误前移到编译期。`CudaTileTypeConverter` 把 triton 的张量/指针/标量/TensorDesc 统一映射成 `cuda_tile` 的 `TileType`/`PointerType`/`PartitionViewType`，转换前还需插入 `cuda_tile.module` 容器。
