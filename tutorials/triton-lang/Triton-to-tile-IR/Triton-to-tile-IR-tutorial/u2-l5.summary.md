本讲承接 u2-l1 后端选择与 u1-l4 端到端编译链路，讲解 TileIR 后端「编译产物如何被真正启动」的最后一步，聚焦三个最小模块：TileIRDriver、make_launcher 胶水代码、cuLaunchKernelEx tile 启动。

TileIRDriver 继承上游 GPUDriver，靠 torch 获得设备探测能力；其 C 工具模块 TileIRUtils 即时编译两份 driver.c——TileIR 仅自研 load_tileir_binary（装载 tile cubin），其余设备函数直接复用 NVIDIA 的 driver.c。make_launcher 针对 kernel 签名现场拼接 C 胶水代码（固定骨架加可变参数片段），即时编成 .so，完成 Python 对象到 C 参数数组（含浮点位打包、指针转 dev_ptr）的翻译；所有 launcher 共享前缀 _BASE_ARGS_FORMAT="iiiKKpOOOO"，其中第 5 位 launch_pdl 是编译期值，由 __call__ 注入。核心结论是 TileIR 以 tile 为单位启动：gridDim 表示 tile 数、blockDim 恒为 1、sharedMemBytes 恒为 0（共享内存已烘焙进 cubin），与 PTX 后端以线程块（num_warps）启动截然不同。启动属性方面，cluster scheduling 无条件设为 SPREAD（围绕 CGA 组织），PDL 仅在 launch_pdl≠0 时追加；cuLaunchKernelEx 指针运行期用 dlopen/dlsym 取得以兼容老驱动。关键术语：tile、driver/launcher、GPUDriver、TileIRUtils、make_launcher、_BASE_ARGS_FORMAT、launch_pdl、PDL、SPREAD/cluster、cuLaunchKernelEx。
