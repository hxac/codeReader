本讲拆解 TileIR 后端的「三段式」编译流水线：后端把 make_ttir / make_tileir / make_cubin 三个工厂函数注册进 stages 有序字典，由上游 compile() 按插入顺序驱动，每段接收上一段的 module 与共享 metadata、返回变换后 module，并以 .ttir / .tileir / .cubin 落盘。make_ttir 只挂六个通用 MLIR 清理 pass（inliner / combine / canonicalizer / cse / licm / symbol_dce），不做方言转换、与硬件无关。make_tileir 是核心，把 TTIR 的 tt.* lowering 成 cuda_tile 方言：lift_cf 与 assume 在主转换前，convert-triton-to-cuda-tile 是主转换并插入 cuda_tile.module 容器，memtoken / inliner / fma / strip 在转换后，顺序由各 pass 操作的方言决定。旋钮在此注入——enable_approx / enable_ftz / occupancy 走 opt，num_ctas / num_warps / num_stages 走 metadata，根源是 approx/ftz 为 @property 不在 __dict__。转换后用 only_contain_legal_dialects 校验完整性：只允许 cuda_tile 方言与 builtin ModuleOp，残留 op 即抛 RuntimeError，把失败前移。make_cubin 委托 call_tileiras，经 write_bytecode 查找嵌套的 cuda_tile::ModuleOp 序列化后交给外部 tileiras 生成 cubin。
