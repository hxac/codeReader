本讲承接 u2-l5，解决 TileIR 后端独有的难题：kernel 参数含 TMA tensor descriptor 时如何送进 GPU 内核。核心结论是：CUDA Tile IR 只提供 device 侧 TMA API，没有 host TMA，因此 Triton 在语言层把描述符降级（lowering）为「base 指针 + shape + stride」这些原始材料，在内核内由 device API 重建描述符。这与 PTX 后端把描述符当不透明 `nvTmaDesc` 句柄整块传入形成本质对比。

关键概念：host TMA 与 device TMA 之分；语义层 `make_tensor_descriptor` 在 TileIR 下返回多带 `base` 字段的 `tileir_tensor_descriptor`，该指针在 IR 扁平化时插于 handle 与 shape/stride 之间。

核心模块是描述符拆解规则：一个秩为 n 的描述符被拆成 `[占位 i32, 指针, *(i32 shape), *(i64 stride)]` 共 2+2n 个槽。构建期 `expand_tensordesc` 处理类型字符串生成 C 胶水，调用期 `make_tensordesc_arg` 处理 `TensorDescriptor` 实例输出数值，两者同构且严格对齐，最终汇入 `void *params[]` 交 `cuLaunchKernelEx`。`TileIRLauncher` 在两个时机统一处理：构建期重写签名，调用期由 `wrap_handle_tensordesc` 铺平实参；描述符嵌套于 tuple 时由 `expand_tuple`/`_expand_tensordesc_tuple` 递归展开，保留容器、铺平内部描述符。本讲衔接 u2-l7「tileiras 编译器与 cubin 生成」，闭合编译/启动链路。
