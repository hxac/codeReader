本讲是全册第一讲，建立 Triton-Ascend 的全局地图。核心结论是：Triton-Ascend 并非新语言，而是社区标准 Triton 的「昇腾 NPU 可插拔后端」——上游 Triton 负责把 Python kernel 翻译成与硬件无关的 TTIR，Triton-Ascend 接手把它变换成可在昇腾 NPU（Atlas A2/A3/950，软件栈为 CANN）上执行的二进制。

讲义围绕四大模块展开：项目定位、compiler、driver、Ascend 语言扩展。三大核心组件各有分工——compiler 是最重的编译后端，门面类 `AscendBackend`（继承 `BaseBackend`）配合 `NPUOptions` 编译选项，通过 `add_stages` 把每个编译阶段登记为「阶段名→处理函数」（如 `make_ttir`、`ttir_to_linalg`、`ttir_to_npubin`），其中 `force_simt_only` 分支可跳过 Linalg 直达二进制；driver 负责运行时，由 `NPUDriver`（门面）、`NPUUtils`（探测 arch/核数）、`NPULauncher`+`make_launcher`（按签名生成并缓存 C++ launcher，通过 CANN API 启动）构成；Ascend 语言扩展对用户可见，以 `triton.language.extra.cann` 挂载 `libdevice`（数学函数）与 `extension`（`custom_op`、`compile_hint`、跨核同步原语等昇腾亲和算子），与标准 `tl` 并列叠加。

核心编译主链路为 `TTIR → Linalg IR → AscendNPU IR → triton_xxx_kernel.o`，越往右越贴近硬件，最终经 BiSheng 编译器生成 `.o` 并由 driver 经 CANN 加载启动。这套「总导航图」将贯穿后续所有讲义。
