本讲把 Triton-Ascend 的「环境准备、安装、构建」拆成四个最小模块。首先介绍 whl 包、源码编译、Docker 镜像三种安装方式：产物相同，区别只在「谁来准备 CANN、谁来现场编译 C++」；只有源码安装才会触发 CMake 构建与构建期补丁。其次讲解 CANN 是整个项目的地基——编译期提供 BiSheng 编译器把 AscendNPU IR 编成 `.o`，运行期提供 ACL/runtime（如 `rtKernelLaunch`）启动内核，且必须 `source set_env.sh` 导出环境变量；软件版本以 `setup.py` 为源码安装权威（Python `>=3.10,<3.15`，依赖 `triton==3.6.0`）。然后聚焦 `setup.py`：它在 cmake 之前用 `apply_triton_ascend_patch()` 把 Ascend 补丁贴到干净上游源文件（先 `git checkout` 还原、再 `git apply` 以保证幂等），再驱动 CMake，最后通过 package 映射、符号链接与 entry points 把 ascend 后端挂载进 `triton` 命名空间。最后说明仓库内 `CMakeLists.txt` 为干净上游版，Ascend 专属 option（如 `LLVM_MAJOR_VERSION_22_COMPATIBLE`）由补丁注入；LLVM 经预编译下载或源码自建，包名由 `llvm-hash.txt` 加 LLVM 补丁哈希拼成。
