本讲是「GPU→Ascend NPU 迁移」单元第一讲，只动 Python 宿主侧，不碰 `@triton.jit` kernel body，遵循「先验正确性」第一原则——优先验证结果正确，性能/grid/对齐等深水区留给 u2-l2、u2-l3。核心是官方迁移指南的**五步法**：(1) `import torch_npu`，它是让 PyTorch 注册 `npu` 设备、桥接 CANN 运行时的**适配层**，缺失则一切 `npu` 调用抛 `AttributeError`；(2) **设备声明替换**，即字面镜像 `cuda→npu`，覆盖 `device='cuda'`、`.cuda()`、`.to('cuda')`、`torch.device('cuda', id)` 四种形态；(3) **运行时接口替换**，把 `torch.cuda.current_device/synchronize/set_device` 映射到 `torch.npu.*`；(4) 删除仅用于 GPU 设备发现的逻辑（如基于 `get_active_torch_device()` 的断言）而非替换；(5) 保持 kernel body 不变，用 NPU 张量验证编译与正确性。关键结论：Triton-Ascend 自身探测设备也走 `torch.npu.current_device()`，印证该替换是项目真实调用；NPU 与 GPU 同为**异步执行**模型，benchmark/校验前必须 `torch.npu.synchronize()` 才能可靠读取结果。
