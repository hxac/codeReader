本讲承接 u5-l1 的设备发现与 function 句柄注册，聚焦连接 Python 调用与设备内核的 launcher，核心覆盖四个模块。①NPULauncher 是「一次构造、反复调用」的桥：由 core CompiledKernel._init_handles 懒创建，调用时透传参数，参数顺序固定为 9 个头部(gridX/Y/Z、stream、function、packed_metadata、launch_metadata、enter/exit_hook)加可变 kernel 实参。②make_npu_launcher_stub 用 sha256(源码内容) 做内容寻址缓存，缓存名带 CXX11 ABI 隔离二进制接口(torch_npu=1、mindspore=0)。③make_launcher 是 C++ 模板渲染器，用 _extracted_type/format_of/ty_to_cpp 把签名转成 C 类型与格式字符，拼出含 _launch(packed struct) 与 launch 入口的整段源码。④C 侧参数解析分两步：PyArg_ParseTuple 按 "iiiKKOOOO"+后缀 拆 Python 元组，getPointer 再把张量对象经整数/None/data_ptr() 三分支转成设备地址。结论：launcher 按签名定制、签名变即重编；启动分普通 rtKernelLaunch 与 950+SIMT 的 rtKernelLaunchWithFlagV2 两条路径，torch_npu/mindspore 差异经 get_backend_func 策略表注入。
