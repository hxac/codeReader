本讲承接 compile_mode 分流机制，深入分流后到底发生什么，覆盖两个模块。混合模式下离散访存的 SIMT 模板快路径分两步：discrete-mask-access pass 满足条件时仅给 op 贴 `route_discrete_mask_to_simt` 标记、不改 IR；triton-to-unstructure pass 命中闸门后把 `tt.load/store` 改写为 `indirect_load/store`、把 atomic 改写为 `__builtin_indirect_atomic`，跳过标量循环展开。纯 SIMT 路径 `simt_only` 经 `force_simt_only` 让 `add_stages` 只注册 `{ttir,npubin}` 提前返回、跳过 Linalg 主线，用 `--enable-triton-ir-compile` 与 `--pure-simt` 把 TTIR 直喂 BiSheng，`mix_mode` 固定 aiv。引入的关键术语包括 indirect_load/store、route_discrete_mask_to_simt 标记、force_simt_template/force_simt_only 开关、pure-simt 选项族、mix_mode。核心结论：SIMT 快路径闸门为 950(A5)+force_simt_template+秩≤5（atomic 另需偏移静态形状且非 i8/i16），任一不满足即回退标量循环；上述 indirect 算子由编译器内部生成、非用户 Python API；纯 SIMT 仅 950 可用，面向无 tl.dot 的 reduce/elementwise。
