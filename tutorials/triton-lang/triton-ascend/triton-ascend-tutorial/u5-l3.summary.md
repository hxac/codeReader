本讲剖析 `make_launcher` 生成的 C++ launcher 如何把 kernel 在 NPU stream 上跑起来，含四块：`launch_args`——按 `(o+a-1)&~(a-1)` 对齐把异构参数打包成连续字节，字段顺序为 ffts?/syncBlockLock?/workspace?/用户参数/gridXYZ/DTData?，对齐按字段大小自适应（8/4/1）；`workspace`——每 block 一份 HBM 工作内存，大小由 BiSheng 回调推断的 `workspace_size` 乘 block 数申请，经 torch_npu 缓存分配器管理；`sync_block_lock`——跨核同步锁内存（每锁 8 字节），分配后须用 `rtMemcpy(H2D)` 写入 `lock_init_value` 初值，并以 `shared_ptr` RAII 自动释放。两条启动 API 的分水岭是 `compile_on_910_95 and enable_simt`，后者由 IR 中 triton-to-linalg pass 写入的 `parallel_mode`（如 `mix_simd_simt`）决定；增强版 `rtKernelLaunchWithFlagV2` 相比普通 `rtKernelLaunch` 额外携带 `localMemorySize`（取自 `shared_mem_dynamic_size`），用于声明 950 SIMT 执行模型的 per-block 动态局部存储。启动任务默认经 `TRITON_ENABLE_TASKQUEUE` 异步派发到 stream。
