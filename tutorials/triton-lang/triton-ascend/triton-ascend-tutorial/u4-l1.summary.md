本讲总览 Ascend 后端 ttir_to_linalg 函数：它是 ttadapter 编译阶段的实现，把 make_ttir 产出的 TTIR 文本 lower 成 Linalg IR 文本，输入输出均为字符串。其以 ir.pass_manager 建 pass 管理器，用 ascend.passes.ttir.add_* 按固定顺序登记约十几个 pass，再由一次 pm.run 统一执行，登记序即执行序。主线顺序为控制流优化、结构化、离散掩码转换、annotation、标量化、hivm/hfusion/llvm 方言 lowering、bubble-up、二次结构化兜底，最终由 add_triton_to_linalg 才产出 Linalg IR（前序皆为预处理），其中 add_triton_to_structure 跑两次，第二次为兜底。两大门控开关：compile_on_910_95（简称 950，作为参数影响若干 pass 内部行为）与 enable_dynamic_cv_pipeline（门控整块 CV 流水线分支及配套 metadata 改写，950 代默认开启）；所有门控字段皆源自 NPUOptions，经 core compile 用 **options.__dict__ 灌入 metadata。pm.get_pipeline_str() 可把流水线导出为文本，与 triton-opt --pass-pipeline= 一一对应，便于在命令行复现调试。后续讲义 u4-l2~l6 将逐篇精读各 pass 的内部 IR 变换。
