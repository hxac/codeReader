本讲讲解 `triton.language.extra.cann` 命名空间的挂载与 libdevice 数学函数机制，含四个模块。其一，`cann` 子包并非 core 原生，而是由 `setup.py` 在安装期经 entry points（whl）或 symlink（editable）从 `third_party/ascend/language/cann` 挂载进来；其 `__init__.py` 是聚合层，`libdevice` 既含 ascend 自研函数，也复用 core 的 `tl.math`，并把部分 extension 函数挂到其名下。其二，libdevice 函数经 `@core.extern`（等同 `@core.builtin`）登记，由 `core.extern_elementwise` 与 `dispatch` 按 dtype 查 `arg_type_symbol_dict` 符号表，翻译为 IR 的 `extern_elementwise` 算子，引用 `__hmf_*` 外部符号。其三，`triton_enable_libdevice_simt()`（仅 950 硬件生效）在编译期为同一 Python 接口分派 SIMT/SIMD 实现，形成三种模式：双 extern（如 `reciprocal`）、extern+软件实现（如 `acos`）、仅 SIMT（如 `logb`，SIMD 下编译报错）。其四，所有 `__hmf_*` 符号最终由 `libdevice.10.bc` 经 `NPUOptions.bisheng_options` 默认的 `-cce-link-aicore-ll-module` 链接解析；`TRITON_ENABLE_LIBDEVICE` 可追加链接，注意区分作用于分派的 `TRITON_ENABLE_LIBDEVICE_SIMT`。后续讲义 u7-l2、u7-l3 将承接 `cann/extension` 的自定义算子机制。
