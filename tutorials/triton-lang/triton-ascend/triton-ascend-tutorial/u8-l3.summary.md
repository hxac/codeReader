本讲承接 u8-l2，进入 DynamicCVPipeline 的重构/落地阶段，覆盖四个模块。其一，重写后的 `SeparateMemoryFromCompute` 退化为薄壳，只调度 `MarkGMLoadPass`：该 pass 用「源追溯 GM 函数参数、目标追溯片上 alloc、份数由 scope 核类型决定」三条规则识别 GM load 候选并打 `multi_buffer` 标记，把解耦策略下放给 BiSheng；当前份数常量为 1，标记保守关闭，体现「纯增益」设计。其二，`SplitDataflow` 按 7 步串联，核心是 `DataDependencyAnalysis`（产出 V→C/C→V/内存/iterArg 四类跨核依赖，并用 LCA 对齐层级）与 `InterCoreTransferAndSync`（按 PIPE 约定插入搬运与成对 `SyncBlockSet/Wait`、用 flag id 配对）。其三，区分三套易混多缓冲机制：CV 内部 `AllocMultiCache`（MLIR 层 Inner/Outer）、`multibuffer` 选项（映射为 BiSheng `--enable-auto-multi-buffer`）、`MarkGMLoadPass` 的 GM load 标记（预留接入点）。其四，`AutoBlockify`（`TRITON_ALL_BLOCKS_PARALLEL`）用「展平 program id + 分块 + `scf.for` 包裹 + 运行期裁剪核数」把逻辑块映射到有限物理核，atomic/volatile/inline_asm/cache 修饰算子被黑名单禁用；生产流经 `--enable-auto-blockify-loop` 触发，in-tree `AutoBlockify.cpp` 为参考实现。整条流水线贯彻「克隆备份 + fallback 还原」，任何子 pass 失败都安全回退到不开 CV 流水线。
