本讲覆盖 SimX 前端的三个最小模块：RVC 解压器（decompressor）、RISC-V 译码器（decode）、微操作展开器（sequencer），对应核心流水线 `schedule → fetch → decode → ibuffer` 中的 fetch 与 decode 两级。核心结论：前端采用「icache 永远按 4 字节对齐取 + 专门的 Decompressor 阶段」策略支持 RVC，解压器用 `on_icache_rsp` 的三路分类（对齐 32 位 / 半字 RVC / 跨字补取）处理 2 字节对齐，且跨字补取优先级最高以防饥饿；解压器只把原始比特放进 `trace->code`，16→32 语义展开集中在无状态 `Decoder::decode` 入口（`code&0x3!=0b11` 时调 `rvc_decompress`）。译码器按 opcode 大 switch 填 `fu_type`/`op_type`/寄存器/立即数，并标记两个关键标志：`is_wstall`（停顿取指）与 `is_macro_op`（需展开）。宏指令（WGMMA/WMMA、packed load、多槽窗口读）在译码时只产生一条，在发射阶段由按 warp 创建的 `Sequencer` 按 `fu_type` 绑定 `TcuUopGen`/`LsuUopGen`/`RtuUopGen`，用幂等的 `get` + 显式的 `advance` 逐条裂成独立流过流水线的微操作，全部展开完毕才 `resume` 取指。引入的关键术语：RVC、Decompressor、`Instr` 对象、`is_wstall`/`is_macro_op`、宏指令/微操作（uop）、Sequencer、`is_rvc`（搭车进 `IntrBrArgs` 驱动 PC 的 +2/+4）。本讲产出 `instr_trace_t`/微操作 trace，供 u6-l3（记分板与操作数收集）消费。
