本讲讲解 Vulkan 如何跑在 Vortex 上，核心结论是 Vortex 图形栈刻意拆成「两棵树」：`mesa_vortex` 提供 vortexpipe 驱动，以 SDK 形式经 `$VORTEX_PATH`/`$VORTEX_HOME` 单向消费本仓库平台，目标 north star 是 submit→present 全程设备常驻的真 GPU。`vortexpipe` 是 Mesa `llvmpipe` 之上的薄装饰器，只覆盖特化入口、其余转发；引入关键术语「inherit and accelerate（继承并加速）」的一致性模型——继承 lavapipe 全 Vulkan 表面、加速子集、未覆盖部分逐次调用回退到 llvmpipe CPU，且 lavapipe 兼作正确性 oracle。编译走 Shape C：NIR→`vp_nir_to_llvm`→LLVM-IR→fork clang 链接 `libvortex2.a`→`.vxbin`。图形 ISA 用 RISC-V custom-1 opcode，靠 funct3 区分 OM(2)/GETWS(4)/TEX(5)/window(6)/RTU(7)。硬件光栅路径下一次 `vkCmdDraw` 是一笔设备常驻事务：VS 折进前端 stage 0，设备侧 sort-middle 前端产出 RASTER 缓冲，RASTER 以 FWD-5 push 模型自启动 run-once 片段着色器，操作数经 SETW/GETW 寄存器窗口暂存。纪律要点：门控回退永远优于静默坍缩，`$MESA_VORTEX_STRICT` 与 `check_run` 双重守住该纪律。FF 单元恰为 RASTER/TEX/OM 三个，定点通路为 gfx-v1。
