本讲讲清 Vortex 构建系统的三个最小模块。一是 `configure`——一台「模板填空机」：采用 out-of-tree 源外构建，在 `build/` 目录运行 `../configure`，用 sed 把 `--xlen/--tooldir` 等 9 个 `@占位符@` 烘焙进 `config.mk`、各 `Makefile`、`ci/*.sh`，并调 `gen_config.py` 从 `*.toml` 生成 `hw/*.vh` 与 `sw/*.h`。二是工具链两段式：`ci/toolchain_install.sh` 按 VERSION 的 TOOLCHAIN_REV 从 GitHub 下载预编译工具到 `$TOOLDIR`，`config.mk` 定义各工具子路径供全树 `common.mk` include 共享，`XLEN` 自动选用 `riscv32-`/`riscv64-` 工具链。三是 AGENTS.md §2 纪律：改 toml/Makefile/目录后须重新 configure，警惕 stale `VX_config.h` 大坑，禁用 `-DVX_CFG_*` 覆盖绕过。核心结论：每棵树 `config.mk` 自带互异绝对路径与 `XLEN`、不依赖全局环境变量，故 `build32/`/`build64/` 等多树可同机共存。
