本讲承接 u4-l2，覆盖设备内核会用到的三类服务。打印：vx_printf 经 vx_serial（基于 SPLIT/JOIN）在 warp 内让线程逐个独占执行、保证单次字符串不交错，再由无 malloc、可重入的 tinyprintf 格式化，最后 vx_putchar 把字节写入设备 IO 区的 COUT 环；该环是每个 hart（由 MHARTID 折叠到 64 槽）独占的有界环形缓冲（wr/rd/data/lost，RING=512），采用单写者模型，满则丢字节并原子累加 lost、绝不阻塞，对齐 CUDA printf 语义；vx_putchar 用 fence ow,ow 发布屏障使字符先于写指针对主机可见，主机侧 CoutDrainer 每个 cycle 读 wr、拷出 [rd,wr) 数据、推进 rd，软硬两端共享同一份 VX_types.toml 布局契约。同步：vx_barrier 是一条 custom0 WCTL 指令，核心是阶段号 phase 代际——到达数到齐且 events==0 时翻代并唤醒所有 wait 者，__syncthreads() 即 vx_barrier(local_group_id, num_warps)；异步 arrive/wait/expect_tx 靠 rd 是否为 0、rs2[31] 区分语义，C++ 封装 barrier/gbarrier/group_barrier 对应 CTA 本地、跨核全局、跨 CTA 会合三种作用域。系统调用：设备无 OS 故无真正 trap，所谓"系统调用"即 vx_syscalls.c 的一组 newlib 桩——_write 桥接 vx_putchar、_getpid 返回 hart id、_sbrk 用 ebreak 显式禁掉动态堆分配；该文件还负责 __init_tls 与 __libc_init_array，是 CTA 入口进入正常 C/C++ 运行时的前提。
