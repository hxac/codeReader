本讲在 u1-l3 的构建体系之上，完成 Vortex 的「构建→运行→验证」首次闭环，覆盖三个最小模块。

其一，统一启动器 `ci/blackbox.sh`：它是一个参数翻译器加流程编排器，把人类友好的架构旋钮（`--driver/--app/--cores/--warps/--threads/--clusters/--l2cache/--l3cache`）翻译成 `VX_CFG_*` 宏（如 `--cores=2` → `-DVX_CFG_NUM_CORES=2`），累加进 `CONFIGS` 变量，再按「定位后端→定位 app→重建驱动→调用 `make run-<driver>`」的顺序执行。默认驱动是 `simx`，默认程序是 `sgemm`。

其二，测试样例 `tests/regression/demo`：一个完整的向量加法样例（`dst=src0+src1`），主机程序用运行时 API 编排「打开设备→分配显存→拷入→启动→拷回→校验」，设备内核由 RISC-V clang 编译成 `.vxbin`。关键认知是：主机程序在运行时通过 `vx_device_query` 查询 `NUM_CORES/NUM_WARPS/NUM_THREADS` 再计算启动维度，因此改 `--cores` 会改变程序处理的数据点数。

其三，配置覆盖机制：架构基线来自 `VX_config.toml`，旋钮只是临时覆盖；核心纪律是「配置必须在驱动侧与应用侧同时生效」，`common.mk` 的 `config.stamp` 机制保证两侧宏一致。判断跑通的判据是程序打印 `PASSED!` 且退出码为 0。关键术语包括 `CONFIGS`、`VX_CFG_*` 宏、`vx_device_query`、`vx_enqueue_launch`、stub 分发器、`libvortex.so`。
