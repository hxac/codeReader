本讲梳理 Vortex 测试基础设施的组织与运行。可执行测试分十一类置于 `tests/`，regression 套件（58 个程序）为日常主力，每个测试是 `kernel.cpp`+`main.cpp`+`Makefile` 三件套，由总 Makefile 的 `run-%` 模式规则扇出到各子目录；核心纪律是 `CONFIGS` 必须在驱动侧与应用侧同时生效。`ci/regression.sh` 是 CI v2 唯一本地入口，`--all`/`--test` 皆为 `pytest ci` 的薄封装，跑测前先强制两道 HW/SW 边界检查。核心模型为「一个测试用例是 N 维空间（category/driver/xlen/config/shape/tier/needs/touches）中的一个点」，全部声明于 `ci/testcases/*.yaml` 目录；每个维度取值即 pytest marker，`via` 有 blackbox/make-run/script 三种、`check` 有 model_parity/perf_gate 两种；引擎由 `testcase.py`+`conftest.py`+`test_runner.py` 三件套构成，独立于 Make 的 `TESTS` 主表。`tier`（smoke/full/nightly）控制「何时跑」，配合 event×driver 矩阵把昂贵的 rtlsim 推迟到 PR 与 nightly。判定细节与门控纪律留待 u13-l4 深入。
