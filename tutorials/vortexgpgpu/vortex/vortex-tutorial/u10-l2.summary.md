本讲承接 u10-l1（FF 硬件实现），讲解图形流水线在软件层的镜像与回退。核心是 Vortex 图形栈的「双轨」设计：FF 硬件快路径（RASTER/TEX/OM）与设备侧 SIMT 软件回退，北极星目标是 true GPU——从 submit 到 present 全程设备常驻，绝不走主机回路。

引入的关键模块与术语：① 主机侧 FF 软件模型 `gfx_ff_model`，模拟三个 FF 单元、被 SimX 消费，使图形测试在硬件未就绪时也能跑；② 单一真相头 `gfx_sw.h`，把每像素深度/模板测试、混合、纹理采样、光栅覆盖的纯数学写成 freestanding 头，主机模型与设备回退编译同一份代码；③ C ABI 桥 `gfx_sw_abi`，靠 POD 描述符 + `static_assert` 守布局逐字节一致，让 Mesa 的 C 驱动调用 C++ 数学；④ 编译约定 `libgfx_sw.mk`，用 divergence 闸门（`-vortex-divergence-max-bbs=512` + `GFX_SW_DIVERGENCE_OK`）应对合并代码撑爆 CFG 的难题。

最核心结论：软件路径与 FF 路径逐位一致，因为它们就是同一份代码——这也让 SimX↔RTL 的 model_parity 天然成立。需区分本讲的「FF 行为软件模型/回退」与 `sw/runtime` 中 `program_*` 那种「FF 寄存器打包器」。
