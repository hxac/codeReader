本讲剖析引擎四步主流程第一步的内部——OCR 驱动器 OCR.recognize。它以生成器形式逐页产出六种 OCREvent：START（每页开头）、IGNORE（页码越界）、SKIP（缓存命中）、RENDERED（渲染完成）、COMPLETE、FAILED；引擎消费循环把事件转发给 on_ocr_event 回调并累计 OCRTokensMetering，其中 COMPLETE 与 SKIP 均计为可用页。断点续跑靠 ocr/ 目录三件套：page_N.xml 是结果缓存，page_N.failed 是失败标记（存在即该页必重试，成功后自动删除），done 是全书完成哨兵（出现过 IGNORE 或 FAILED 就不写；存在且无失败标记时重跑零事件、零 token）。token 预算分总额与输出额双轨跨页累计扣减，页级预检在渲染前进行，耗尽抛 TokenLimitError。被忽略策略放行的失败页会产出兜底 Page（整页截图或占位文本）照常落盘、计量为 0；若存在失败页且可用页为 0，引擎抛 NoUsableOCRPagesError 拒绝空包。AbortError 与 TokenLimitError 不会自动转换，须经 to_interrupted_error 显式包装为携带 InterruptedKind 与计量的 InterruptedError；aborted 协作式中止在每页 START 前检查。下一讲 u3-l4 将深入 RENDERED 之后的识别入口 image2page。
