本讲把 u7 精读的 XMLTranslator 引擎放进完整工程管线，讲解 translate_epub——五大工作流中唯一不碰 PDF 的一条。主流程：校验 LLM 配置→构造 XMLTranslator→以双句柄 Zip 打开源/目标包并最先迁移 mimetype（借源 ZipInfo 保留不压缩属性、锁定第 0 条目）→盘点 spine/目录/元数据→生成三类任务→流式逐元素翻译写回→收尾兜底迁移其余文件。三类任务：目录与元数据各编码为单个 XML 元素（APPEND_BLOCK 被降级为 APPEND_TEXT），章节按 spine 逐文档取 body；写回时章节先去重 id，目录/元数据解引号。进度模型为固定权重：目录 5%、元数据 5%、章节均摊剩余 90%，回调单调递增、语义是工作量占比。LLM 配置：llm 可兜底 translation_llm 与 fill_llm 但缺一不可，校验先于任何文件操作；缓存种子由库版本与目标语言拼成，配合双 protocol_version 隔离缓存；max_retries 属语义层结构修复，区别于传输层 retry_times。关键术语：spine、mimetype 首条目约束、Zip 兜底迁移、SubmitKind、FillFailedEvent。
