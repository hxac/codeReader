本讲绘制 pdf-craft 的仓库模块地图，是后续单元的导航基础。核心结论：仓库分两层——pdf_craft/ 是发布到 PyPI 的核心库，pdf_craft_tool/ 是不随包发布的仓库本地 CLI。核心库沿数据流分子包：提取引擎 PDFExtractionEngine 固定四步（OCR 循环、目录分析、章节生成、元数据落盘），依次由 pdf/、extractor/toc/、extractor/chapter/ 完成，产出 document/ 定义的 DocumentPackage 中间包契约；此后可经 transformer/（格式无关 XML 变换，含 XMLTranslator）处理，再由 renderer/ 渲染 Markdown/EPUB，或由 pipeline/ 完成译文回写 PDF 与现有 EPUB 翻译；llm/ 与 common/ 提供支撑。关键概念：__init__.py 是公开 API 边界、DocumentPackage 是提取与渲染间的中立契约、PDFCraft 门面对 OCR 延迟加载、tests/ 分单元测试/资产/冒烟矩阵三层并有架构守卫测试固化模块边界。
