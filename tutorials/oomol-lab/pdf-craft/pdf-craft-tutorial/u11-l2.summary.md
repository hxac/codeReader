本讲梳理 pdf-craft 的三层测试体系：单元测试（零网络、CI 每次提交必跑，由 test.py 驱动 unittest 发现 tests 下的测试文件）、边界测试（架构守卫）、冒烟测试（真实 OCR/LLM 后端、分钟级、手动触发）。核心模块是冒烟矩阵：用 JSON 描述「资产×路由×后端×翻译配置」组合，expand_matrix 以 defaults 合并展开为 SmokeRun，八条路由按 PDF/EPUB 资产格式分组校验；每条 run 五阶段执行并落盘 manifest、checks 与日志，密钥一律脱敏，无 CUDA 记 skipped 而非 failed。单元测试三种武器：纯函数直测、伪协作对象（fake 与捕获器）、mock.patch。边界测试分两类：模块边界用符号归属断言与源码文本扫描，守住「XMLTranslator 格式无关、EPUB 编排归 pipeline.epub」；组合边界用伪协作者驱动真实跨层流程，固化「全失败拒绝空包」「空章跳过翻译」「断点续跑不重渲染」等契约。核心结论：修复提交与回归测试成对落地是本仓库的明确惯例。
