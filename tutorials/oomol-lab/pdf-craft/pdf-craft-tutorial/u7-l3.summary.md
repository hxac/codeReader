本讲剖析 pdf-craft 将章节 XML 切成翻译组的机制。三级片段分工明确：TextSegment 把 XML 树摊平为非空文本节点流，InlineSegment 以块级元素为界打包成最小翻译单元（内联标签与 MathML 公式作嵌套子片段，标签永不半开），BlockSegment 是回填阶段整组片段的 id 化快照，支撑校验与按 id 回配。分组预算用「分数」而非纯文本 token：按 XML 渲染 token 数加每个带 id 父片段 80 分计，故仅在同 tag 子片段指纹互异时才发 id。切缝（incision）标注结构边界，引导通用切分算法在预算内选点，且翻译组可跨元素合并（max_group_tokens 默认 2600）。serial 子包（Segment 协议、split_into_chunks、splitter.split）以「头—身—尾三明治」将该思想通用化：head/tail 仅作上下文进入请求、结果剥掉头尾，保证每个片段恰好翻译一次；生产路径实际由 stream_mapper 直接对接 resource_segmentation 实现等价逻辑。
