本讲围绕 `typst-library` 的 `#[elem(...)]` 宏、字段系统与 `Packed<T>` 三个最小模块，回答「元素被擦除成 `Content` 后字段在哪、类型如何安全取回」。核心结论：`#[elem]` 宏在编译期生成 struct 改写、`NativeElement`、字段 trait、`Construct`/`Set`、静态 `ContentVtable` 五块代码，并以 `const _: () = { .. }` 隔离。字段标注分七类——`#[required]` 存原类型必填、`#[default]` 注入默认、`#[synthesized]` 存 `Option<T>` 且不参与相等比较、`#[ghost]` 不入 struct 只活样式链（故需自定义 `Construct`）、`#[fold]` 使取值折叠而非替换、`#[parse]` 覆盖参数解析、`#[external]` 仅存文档；每类对应一个字段 trait（`RequiredField`/`SettableField`/`SettableProperty`/`SynthesizedField`/`ExternalField`）与一种 `FieldVtable`，字段 ID 在按 `internal` 排序后分配。引入的关键术语：`Settable<E,I>`（元素侧 `Option`，取值优先元素自带值、回退样式链、再回退默认值，昂贵默认值用 `OnceLock` 缓存）、`Packed<T>`（`repr(transparent)` 包装，靠 `is::<T>()` 受检后 transmute 与 `Content` 互转，借 `Deref` 还原具体类型字段）、`materialize`（把样式链烘焙进元素）。重要约定：`Synthesize`/`ShowSet` 等能力 trait 必须写在 `Packed<E>` 而非 `E` 上，因 vtable 与能力调用均以 `Packed<E>` 为对象类型。本讲为 u4 的 `StyleChain`/`Fold`/`Resolve` 语义打下基础。
