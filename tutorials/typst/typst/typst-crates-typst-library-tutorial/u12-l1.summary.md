本讲义讲解 typst-library 如何通过「特性开关」按需装配不稳定 API，并解析 pdf/html 输出模块。`Feature` 是 `#[non_exhaustive]` 枚举（Html/Bundle/A11yExtras），`Features` 是基于 `SmallBitSet` 的 Copy 位图，二者无稳定性保证、用户须显式 opt-in；装配期共三处判断：Bundle→`AssetElem`、A11yExtras→三个无障碍函数、Html→整个 html 子模块。pdf 模块用「子模块挂载式」装配，`AttachElem`（文件附件）/`ArtifactElem`（PDF artifact 标记）默认注册且 API 稳定，a11y 函数仅是 `TableElem` 方法的薄包装，本 crate 只做归一化、真实写入在行为 crate typst-pdf。html 模块体不在本 crate，须经 `routines.html_module` 函数指针在运行期注入，以避免 typst-library↔typst-html 循环依赖；顶层 crate 用同一 `Library.features` 在导出前二次校验，形成装配与导出双重闸门。关键判据是「定义是否在本 crate 内」——在内直接 `define_elem`，在外经 routine 注入。
