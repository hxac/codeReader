本讲是「内省（introspection）与上下文」单元的地基篇，只讲位置的表示与入口，不涉及收敛循环（u9-l3）与 Counter/State（u9-l2）。覆盖四个最小模块：Location/Tag、Locator/SplitLocator、query/locate/here、Context。

核心结论：第 N 轮排版时用户代码查到的是第 N-1 轮建好的索引，故内省需要反复迭代才稳定。

关键术语与概念：Location 本质是 u128 哈希，作为 locatable 元素的「身份证号」，Copy+Hash 但故意不实现 Ord（需排序用 LocationKey）；variant 可从已知位置派生新位置。Tag/TagElem 把位置盖章进帧树，Start/End 两变体分担信息，仅 introspectable 的 tag 被内省器收集成索引；TagElem 为 #[internal]。Locator/SplitLocator 是分层哈希发号机，用 h_n=hash(h_{n-1},k_n) 兼顾跨迭代稳定、跨编辑稳定与可并行；故意不 Clone，逼排版器在 split（不同号）与 relayout（同号）间显式选择；next(key) 推荐用 span，测量模式下退化为找最接近的真实元素。query/locate/here 三个用户函数统一套路：先过 Context 门禁，再走 engine.introspect(XxxIntrospection) 查 Introspector；返回的元素都带 location。here() 最薄，只从 context 取位置；locate(裸 Location) 连门禁都不需要。Context 是「数据缺失式」门禁，两字段 Option，缺失时经 require 返回 "can only be used when context is known"；context{} 块的 CONTEXT_RULE 负责把 context 填满。Engine::introspect 是所有查询的统一入口，查询会被记录供收敛诊断。
