本讲聚焦 Typst 文本系统的核心元素 `TextElem`，拆解三个最小模块。

其一，`TextElem` 是「几乎全是 ghost 字段」的元素：struct 实际只存一个 `#[required]` 的 `text: EcoString`（一个文本 run 的字符串），`size_of::<TextElem>()` 即等于 `EcoString`；其余几十个样式字段（font/size/fill/style/weight/stretch 等）以及内部字段（delta/emph）均为 `#[ghost]`，只活在 `StyleChain` 中。因此 `text` 函数的 `Construct` 不创建文本节点，而把参数转成 `Styles` 套在 body 上原样返回（`body.styled_with_map`）；真正的节点由 `TextElem::packed` 在文本处理阶段创建。样式属于环境、不属于单个字符，一条样式链可复用于海量节点。

其二，字体回退由三级数据结构构成：`FontFamily`（族名转小写存储 + 可选 `Covers` 覆盖集）、`Covers`（预定义 `LatinInCjk` 或受限正则，用于按字符范围分配字体）、`FontList`（非空族列表）；`families()` 在用户列表后依 `fallback` 字段追加 emoji 兜底族。

其三，`variant()` 是综合函数：以用户可见的 `style/weight/stretch` 为基线，叠加内部 `delta`（`WeightDelta` 求和折叠 + `thicken` 饱和调字重）与 `emph`（`ItalicToggle` 异或折叠 + 翻转斜体），产出匹配字体的 `FontVariant`。`#strong`/`#emph` 通过内置 `ShowSet` 规则将语义化强调翻译成对 `delta`/`emph` 的写入，从而「反向影响」最终选哪款字体。同属 `#[fold]` 的还有 `TextSize`（线性函数复合）。

关键术语：ghost 字段、`TextElem::packed`、`FontList`/`FontFamily`/`Covers`、`families()`、`FontVariant`、`variant()`、`WeightDelta`/`ItalicToggle`/`TextSize`、`thicken`、内置 `ShowSet` 规则。本讲是 u7-l2（FontBook 距离匹配与变量字体轴）与 u7-l3（OpenType 特性）的入口。
