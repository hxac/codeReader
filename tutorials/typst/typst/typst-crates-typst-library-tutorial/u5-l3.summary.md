本讲精读 `src/diag.rs`，讲清 Typst 编译器如何「造错误」。核心是三种结果类型：`SourceResult`（错误载体 `EcoVec<SourceDiagnostic>`，带源码位置、可一次携带多条）、`StrResult`（`EcoString`，无位置）、`HintedStrResult`（`HintedString`，无位置但带提示）。诊断单元 `SourceDiagnostic` 含 severity、span、message、trace、hints 五字段，靠 severity 字段区分错误与警告。`bail!` 是 early-return 分发宏，`error!`/`warning!` 仅构造对象（后者 severity=Warning）；按「首参是否为 span」决定产出类型——带 span 走 `SourceResult`，不带则走 `StrResult`/`HintedStrResult`。`Hint` trait 的 `.hint()` 把 `EcoString` 升级为 `HintedString` 累积提示；`At` trait 的 `.at(span)` 把无位置错误补位置升级为 `SourceResult`，其中对 `HintedStrResult` 的专属 impl 会保留提示。三个宏因 Rust 限制只能以 `__xxx` 真名在 crate 根导出，再用 `pub use ... as ...` 改名重暴露。整体设计是「底层只报字符串、上层补 span」的两段式机制，使底层纯计算函数保持简单。
