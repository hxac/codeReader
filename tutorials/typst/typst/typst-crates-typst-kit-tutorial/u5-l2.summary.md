本讲是 typst-kit「网络下载子系统」第二讲，承接 u5-l1 的 `Downloader` trait，讲解如何**无侵入地给任意下载器加进度条**，全部源码集中在不受任何 feature 门禁的 `downloader.rs`。

核心围绕四个类型展开。`ProgressDownloader<T, F, P>` 是**装饰器**：实现同一个 `Downloader` trait，内持真正的下载器 `inner` 和一个工厂闭包 `progress: Fn(&dyn Any) -> P`，自己不碰网络。它的关键是**用 `key: &dyn Any` 把「是否显示、显示成什么名字」的决定权交给上层**——上层工厂闭包对 `key` 做 `downcast_ref` 区分：包下载传 `PackageSpec`、自更新传 `"release"`（均显示），包索引用 `"package index"`（静默），无需改动 typst-kit。

注意 `download()` 与 `stream()` **不对称**：只有 `download()` 经私有 `ProgressReader` 自己驱动 8192 字节分块读取循环并上报进度；`stream()` 退化为全量缓冲、不上报（因为驱动权交还上层）。

`ProgressReader` 按固定周期 `period`（默认 100ms）采样，把「本周期字节数」压入 `SAMPLES = 25` 的 `VecDeque` 滑动窗口，回调 `ProgressReporter` 的 `start`（必调）、`update`（可能 0 次）、`finish`（必调）。

`ProgressReporter` 是三回调的「显示策略」抽象；`Progress` 是纯统计结构，其 `Display` 用滑动窗口算平均每周期字节数、乘以频率得 bytes/s，有 `content_len` 时再算百分比与 ETA，`format_byte_unit` 用 1024 进制 KiB/MiB/GiB。
