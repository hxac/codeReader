本讲讲 typst-kit「文件加载子系统」抽象层（核心文件 `files.rs`），把「记住已读文件」与「字节从哪来」拆成两层：缓存层 `FileStore<L>` 按虚拟 `FileId` 在 `Mutex<FxHashMap<FileId, FileSlot>>` 中懒加载；来源层 `FileLoader` 是唯一可插拔接口，仅 `load(id) -> FileResult<Bytes>` 一法，换来源即换泛型参数。`FileStore` 对外四入口：`source(id)` 返回带行号索引的 `Source`（解析 `.typ`），`file(id)` 返回原始 `Bytes`（图片/数据），两者对同一 id 可共享底层缓冲；`dependencies()` 收集自上次 reset 起被访问的 FileId（连带返回 loader 以便解析路径，顺序任意）；`reset()` 不清空内存而保留 stale source 供就地编辑，是增量编译性能关键。所有读取统一经私有 `slot(id, closure)`，靠 `entry(id).or_default()` 保证同一 id 恒对应同一 FileSlot。typst-cli 的 `SystemWorld` 用 `FileStore<SystemFiles>` 原样转发实现 `World` 的 `source/file` 回调。`FileSlot` 三态状态机、`SystemFiles` 与 `FsRoot` 的磁盘路径解析分别留待后续讲义。
