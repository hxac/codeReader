本讲讲清 typst-kit 三个顶层字体发现函数。`embedded()`（依赖 `embedded-fonts`）取出编译进二进制的静态字体，返回**已加载的 Font**，字节已在内存、收录后零读盘；`scan(path)` 与 `system()`（均依赖 `scan-fonts`）分别扫描用户指定目录与操作系统标准目录，返回 **FontPath**（仅 path 与 index，字节未读），读盘留到 `FontStore` 首次访问时触发——这正是懒加载的前提。

`scan` 与 `system` 共用适配器 `with_db()`：闭包把字体塞进第三方库 fontdb，`with_db` 再把 face 翻译成 Typst 的 `(FontPath, FontInfo)`，借 fontdb 读字节、用 Typst 的 `FontInfo::new` 判定可用性、用不了的安静跳过；因 fontdb 是局部变量，结果须先 `collect` 成 Vec 才能解绑返回。收录顺序即下标顺序即匹配优先级，typst-cli 按 system→embedded→scan 拼装。`load_adobe_fonts()` 仅在 Windows/macOS 编译，补 Adobe CoreSync 非标准目录字体，体现发现过程尽力而为、容错跳过的设计。
