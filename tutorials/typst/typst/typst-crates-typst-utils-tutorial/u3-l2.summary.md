本讲围绕 `typst-utils` 的两个小文件 `fat.rs` 与 `protected.rs`，讲授两套用「改写 API 形状」表达纪律的机制。胖指针部分的核心结论是：指向 `dyn Trait` 的指针在内存里就是 `(data, vtable)` 两个机器字；`fat.rs` 用一个 `#[repr(C)]` 的私有 `FatPointer` 结构体镜像这一布局，借 `mem::transmute_copy` 在「两个地址」与「真正胖指针」间双向转换。三个公共 `unsafe` 函数构成拆装对：`vtable()` 抠出 vtable 地址（且从不解引用 data，因此悬空 data 也安全），`from_raw_parts` / `from_raw_parts_mut` 把 `(data, vtable)` 拼回胖指针；每个函数都带「`T` 必须是 `dyn Trait`、vtable 须来自本模块」的安全契约，并用仅 debug 生效的 `debug_assert_eq!(Layout::...)` 做布局守卫、发布期零开销。真实驱动场景是 `typst-macros` 用 `fat::vtable` 为元素构建 `TypeId → vtable` 映射。`Protected<T>` 是另一思路的 newtype 守卫：它不实现 `Deref`，逼迫调用方写 `access("理由")` 才能取内部引用；理由限定为 `'static str`，构成可 grep、可审计的证据链；`into_raw`/`from_raw` 则是「已放行值搬运」的逃逸通道。关键术语：胖指针、vtable、`FatPointer`、`transmute_copy`、`Protected`、`access`。
