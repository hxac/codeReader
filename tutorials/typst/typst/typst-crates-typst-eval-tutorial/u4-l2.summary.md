本讲承接 u4-l1，专门拆解 Typst 中点号（`.`）的两种用法在解释器里的分派机制，只涉及 `src/code.rs` 与 `src/call.rs` 两个文件。核心区分「字段读取」与「方法/字段调用」：`a.b`（不带括号）走 `FieldAccess::eval → access_field`，`a.b(...)`（带括号）走 `FuncCall::eval → eval_field_callee`。关键术语包括：字段（field）与方法（method）的区分、类型 scope 与元素 scope、`FieldCallee` 枚举（`Method`/`Func`/`NonFunc` 三变体）。`access_field` 先做普通字段读取，失败后对「元素函数 + settable 字段」从 `vm.context.styles()` 惰性兜底现算（如 `block.stroke`，需在 context 内）。`eval_field_callee` 按固定优先级分派：①类型方法 → ②元素方法 → ③符号/类型/模块字段 → ④函数字段 → ⑤报错；方法命中时自动把目标作为首参插入。字段调用仅对 Symbol/Type/Module/Func 四类放行，Dict/Args 即使字段存在也会被 `disallowed_field_call_error` 拒绝，并给出「加括号包裹」或「移除参数」的差异化修复提示。变更方法（push/pop/insert/remove）在常规分派之前被 `maybe_resolve_mutating` 提前拦截，经 `Access` trait 取可变引用就地修改；拦截失败时把已求好的 `(target, args)` 退还常规路径。
