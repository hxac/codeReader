本讲承接 u3-l1，专门拆解 typst-eval 解释器中 `break`/`continue`/`return` 三个关键字如何以「带外信号」方式实现，形成「产生—传递—消费」三段式。核心载体是 `FlowEvent` 枚举（定义于 `src/flow.rs`），含 `Break(Span)`、`Continue(Span)`、`Return(Span, Option<Value>, bool)` 三变体；它们不借助 Rust 异常，而是写入虚拟机字段 `vm.flow: Option<FlowEvent>`（信箱）。三个生产者 `LoopBreak::eval`/`LoopContinue::eval`/`FuncReturn::eval` 都用 `if vm.flow.is_none()` 护栏保证首个事件优先、不被覆盖，且统一返回 `Value::None`。「保存-恢复」三段式（`vm.flow.take()` 清空 → 求值 → 按需恢复）使控制流事件不会跨作用域泄漏：循环消费 `Break`/`Continue`（清空）、放行 `Return` 穿透，`eval_code` 对所有事件只放行不消费。`Return` 最终由 `eval_closure` 消费，带显式值则取值，否则取函数体产出；漂入函数的 `Break`/`Continue` 由 `forbidden()` 报错。`Return` 第三字段 `conditional` 经 `Conditional`/`WhileLoop`/`ForLoop` 冒泡时置 `true`，其唯一读者 `warn_for_discarded_content` 据此跳过条件 return，只对无条件 return 丢弃内容告警。模块顶层残留事件由 `eval`/`eval_string` 调 `forbidden()` 兜底。关键术语：`FlowEvent`、`vm.flow`、`is_none()` 护栏、保存-恢复模式、`forbidden()`、`conditional` 字段、`warn_for_discarded_content`、`eval_closure`、`eval_code`。
