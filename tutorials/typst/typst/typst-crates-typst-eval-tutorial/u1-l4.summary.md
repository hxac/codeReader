本讲精读 typst-eval 的两大基石：`Eval` trait 与 `Vm` 虚拟机，聚焦 `src/lib.rs` 和 `src/vm.rs`。`Eval` trait 用关联类型 `Output` 让各类 AST 节点返回各自类型，签名 `fn eval(self, vm: &mut Vm) -> SourceResult<Output>` 表达「一次性遍历、有副作用、可能失败」的求值语义；枚举节点（如 `ast::Expr`）用大 match 做总分发。`Vm` 是求值状态容器，含五个字段：`engine`（环境句柄）、`flow`（控制流事件）、`scopes`（作用域栈）、`inspected`（IDE 检查的 span）、`context`（幕后上下文）；每求值一个模块或调用一次函数都新建一个以隔离状态。核心方法 `define`/`bind`（插入绑定并附带 trace 与 `is` 警告）、`trace`/`trace_at`（条件式 IDE 追踪，`trace` 标 `#[cold]`）。关键约定：每个产生值的表达式都应调用 `trace_at`，靠 span 比较做到「全量埋点、近乎零成本」。`hint_if_shadowed_std` 则体现「错误信息 + 定位 + 修复提示」三要素诊断哲学。
