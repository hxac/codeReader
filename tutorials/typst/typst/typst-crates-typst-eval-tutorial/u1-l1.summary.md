本讲是 typst-eval 学习手册的开篇鸟瞰，只涉及 `Cargo.toml` 与 `src/lib.rs` 两个文件，确立后续所有讲义的总框架。

核心结论是：typst-eval 是 Typst 的代码解释器（tree-walking interpreter），职责单一——把语法树求值成运行时值；它不负责解析（归 typst-syntax），也不定义运行时类型与内置函数（归 typst-library）。整个 crate 建立在两块基石上：统一的 `Eval` trait（每类 AST 节点各自实现 `eval`，并用关联类型 `type Output` 声明输出，如表达式产出 `Value`、Markup 产出 `Content`）和携带求值状态的 `Vm` 虚拟机（每求值一个模块、每调用一次函数都新建一个）。

顶层入口 `eval()` 用 `#[comemo::memoize]` 缓存，把一个 `Source` 求值为 `Module`，走「循环防护 → 准备 Engine → 准备 Vm → 收集错误/警告 → 求 Markup → 装 Module」六步；第二入口 `eval_string()` 按 Code/Markup/Math 模式求值字符串返回单个 `Value`。两大设计细节：循环检测用 `panic!`（属内部错误），有语法错误时若处于 inspect 模式仍继续求值以服务 IDE hover。

关键术语包括：解释器、求值（eval）、`Eval` trait、`Vm`、`Module`、`Value`、`Content`、`Engine`、`Route`、`Sink`、`Traced`、`Scopes`、comemo 记忆化与 `Tracked` 参数判等。三大核心依赖为 typst-syntax（上游）、typst-library（运行时类型）、comemo（缓存），数据流主线为「源码文本 →（解析）AST →（求值）Module/Value」。
