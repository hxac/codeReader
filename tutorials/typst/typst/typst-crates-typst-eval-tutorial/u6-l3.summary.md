本讲是 typst-eval 手册收官篇，讲解求值的运行时安全三道防线与缓存机制，涉及 lib.rs、call.rs、import.rs 与跨 crate 的 engine.rs。核心结构 Route 是记录「怎么走到这里」的调用链，一身二用：用 id 字段沿 outer 链做循环防护（contains），用 len 字段做调用深度检查（check_call_depth，上限 80）。循环 eval 命中走 panic!（编译器内部不变量），循环 import 命中走 bail!（用户友好报错）；eval 用 Route::extend.with_id 把当前文件挂进链。物理栈溢出由 stacker::maybe_grow(32KB,2MB) 兜底，剩余栈低于红线时把执行挪到堆上新栈，wasm32 因缺陷绕开；逻辑深度防层数、物理栈防字节数，缺一不可。性能上 eval 与 eval_closure 均带 comemo::memoize，按全部参数指纹做缓存键，TrackedMut<Sink> 的写入副作用在命中时重放；Route::within 的 upper 上界与 track() 跳空段优化刻意让等价深度指纹一致，最大化缓存复用。关键术语：Route、Tracked/TrackedMut、comemo、Sink。
