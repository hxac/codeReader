本讲聚焦 typst-timing 的零成本门控设计：默认关闭时遍布代码库的 timed! 埋点为何几乎不拖慢编译。关键在于门控唯一入口 with_span 刻意返回 Option<Self>——开关为假时直接返回 None，连带让真正干活的 new_impl（加锁、取时间、push）与 Drop 都不被求值；因 None 不触发内层 Drop，一次门控同时挡住 Start 与 End，且异常安全。本讲引入的关键术语：门控、零成本抽象、冷热分离、代码膨胀。设计把短检查函数（is_enabled、new、with_span）标 #[inline] 以跨 crate 内联进调用点，体量大的 new_impl 与 Drop 则刻意不内联以防复制膨胀。禁用态开销约为一次 Relaxed 原子读加一次预测命中的分支，启用态额外付两次锁、两次取时间、两次 push，量级悬殊。整体策略为默认关闭、关闭态零成本、运行时经 enable() 开启，兼得生产零负担与按需 profiling，无需像 cfg feature 维护两份产物；timed! 与 #[time] 两入口最终汇入同一道门。
