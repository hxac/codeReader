本讲总览 typst-timing 这个极小的 crate（仅 `Cargo.toml` + `src/lib.rs` 约 320 行）。它是 Typst workspace 的基础设施型 crate，职责单一：在关键路径埋点收集性能计时事件，并导出为 Chrome Trace / Perfetto 可读的 JSON，供开发者用时间轴定位编译热点。它本身不参与排版，却被 syntax、eval、layout、render、svg、pdf、cli 等十余个核心 crate 依赖。

`src/lib.rs` 分五大块：对外 API、全局状态、计时作用域 `TimingScope`、事件模型 `Event`/`EventKind`、跨平台时间抽象 `Timestamp`/`ThreadData`/`WasmTimer`。对外 API 包括 `timed!` 宏、`enable/disable/is_enabled`、`clear`、`export_json` 及 `TimingScope`；内部用 `ENABLED`（AtomicBool）作全局开关、`EVENTS`（Mutex\<Vec\>）作缓冲区、`THREAD_DATA`（thread_local）存每线程数据。依赖管理演示了 `{ workspace = true }` 继承（parking_lot/serde/serde_json）与 wasm 三重门控（仅 wasm32 目标的 optional web-sys + `wasm` feature 用 `dep:` 拉入 + 源码双重 cfg）。关键术语事件、作用域、时间戳、线程、零成本门控将由 u2/u3 各篇承接展开。
