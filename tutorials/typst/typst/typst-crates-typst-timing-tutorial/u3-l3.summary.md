本讲解析 typst-timing 在 wasm32 下的计时实现 `WasmTimer`，分三块。其一，用三层门控隔离 wasm 计时：Cargo.toml 限定 wasm32 目标并以 optional 的 `wasm` feature 让 `web-sys` 可选，源码再叠 `cfg(all(target_arch="wasm32", feature="wasm"))` 双重保护，使 native 下完全不引入 `web-sys`。其二，`WasmTimer::new` 以回退链取 `Performance` 句柄：先 `web_sys::window()` 取主线程 performance，失败再用 `js_sys::global()` 经 `dyn_into` 转 `WorkerGlobalScope` 兜底，兼顾主线程与 Web Worker。其三为核心：因各全局上下文 time origin 不同、`perf.now()` 零点各异，直接跨线程相减无意义，故每线程缓存各自 `time_origin`，`now()` 返回 `time_origin + perf.now()`，把时间戳拉到同一类绝对基准，使跨线程可比、`micros_since` 做差天然正确。未开 feature 时 wasm 分支返回 `0.0` 优雅退化，句柄缺失则 `.expect` panic，构成两种有意为之的错误哲学。引入术语：三层门控、`Performance` 句柄、`time_origin`、优雅退化。
