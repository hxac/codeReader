本讲剖析 typst-timing 如何用全局状态承载计时数据，全部集中在唯一源文件 lib.rs。核心是两个进程级静态量：`ENABLED`（`AtomicBool`，默认关闭的计时开关）与 `EVENTS`（`Mutex<Vec<Event>>`，所有线程共享的事件缓冲区）。事件写入集中在 `TimingScope`——创建时 push `Start`、`Drop` 时 push `End`，均经 `EVENTS.lock()`；`export_json` 用 `std::mem::take` 取出事件并清空缓冲区。每条事件的 `thread_id` 来自 `thread_local` 的 `THREAD_DATA`（每线程一份 `ThreadData`），其 `u64` id 由内嵌的进程级 `static COUNTER` 经 `fetch_add` 在线程首次访问时分配——需区分「共享发号机」与「每线程储物柜」。自造 id 而非用 `std::thread::current().id()` 是为 wasm 兼容且更便宜。全文件原子操作清一色 `Ordering::Relaxed`，因这些量只是独立状态位/计数器、不发布伴随数据，`EVENTS` 的线程安全由 `Mutex` 自身保证；`Start`/`End` 在创建时取一次 `thread_id` 并复用，保证一对事件 tid 严格一致。
