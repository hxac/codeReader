本讲是 typst-bundle 学习手册的第一篇，定位「认识 typst-bundle 是什么」，覆盖四个最小模块：输出目标与定位、多文件输出的价值、实验性 feature 开关、crate 依赖关系。

核心结论：Typst 有三种输出目标（target）——`Paged`、`Html`、`Bundle`，其中 bundle 是唯一的「多文件」目标，打破「一次编译 = 一个文件」的限制，一次产出多个文档与原始资产。bundle 是实验性特性，需 `--features bundle` 开启。`typst-bundle` crate 是一个编排层，自身不做底层排版与格式编码，而是组合 `typst-layout`/`typst-html`/`typst-pdf`/`typst-svg`/`typst-render`/`typst-library` 等兄弟 crate。

引入并需后续承接的关键术语：`Target` 枚举与 `Output` trait（一一对应，`Output::create` 调 `bundle()`）；`Bundle` 顶层产物对象（之于 bundle 犹如 `PagedDocument` 之于 pdf/png/svg）；`BundleFile`（`Document`/`Asset` 两类）、`BundleDocument`（`Paged`/`Html`）、`#document(...)` 与 `#asset(...)` 元素；`Feature::Bundle` 与 `warn_or_error_for_bundle`（未开报错、开启降级为警告）；`compile::<T>()` 泛型分发、`bundle()`/`bundle_impl()` 入口、`files: IndexMap<VirtualPath, BundleFile>`、`#[comemo::memoize]`。同时区分 CLI 侧 `--format bundle`（决定编译成什么）与 `--features bundle`（决定是否允许）两个层面。
