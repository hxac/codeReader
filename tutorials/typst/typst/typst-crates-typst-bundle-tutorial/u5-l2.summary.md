本讲讲解 bundle「一次编译产出多文件」下，一个文档的 `#link(<标签>)` 如何精确跳转到另一文档（乃至某个 PDF 元素或 asset 本身）。核心结论是跨文档链接 =「相对路径 + 锚点片段」，而锚点字符串要等所有文档排完版才能统一分配，再回填给导出阶段解析。关键链路为：先由 `link_targets()` 收集目标——它合并 `LinkElem` 逻辑链接与 frame 内原始链接两类来源，并用 `path()` 按目标文档路径分桶；再由 `create_link_anchors()` 并行分派：HTML 走 `typst_html::create_link_anchors` 原地注入 DOM `id`（含元素/文本/多节点/空节点四种形态），paged 走 `create_paged_link_anchors` 把命名目的地写入 `PagedExtras.anchors` 侧车。锚点字符串由 `AnchorGenerator` 统一生成：优先复用合法且唯一的标签，重复加 `-N` 消歧，无标签则给 `loc-N`；paged 路径必须先按 `loc_index` 排序，以保可复现构建与记忆化正确。最后 `create_link_anchors` 为每个 document/asset 自身补一个空字符串锚点，使「链接到整个文件」成立；`LateLinkResolver::resolve` 据此判定 `Local`/`Cross`，`into_relative_uri` 输出最终相对 URI（空锚点不带 `#`）。引入的关键术语：锚点（HTML 的 DOM id / PDF 命名目的地）、Location、侧车（PagedExtras.anchors）、AnchorGenerator、空锚点、LateLinkResolver、ResolvedLink（Local/Cross）。
