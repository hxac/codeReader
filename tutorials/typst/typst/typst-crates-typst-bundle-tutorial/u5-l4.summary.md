本讲是 typst-bundle 手册收尾篇，从 CLI 视角讲清 bundle 的端到端落盘链路。核心结论有四：一是 CLI 用运行时枚举 `OutputFormat::Bundle` 分派，对接编译器 `compile::<Bundle>` 类型分派，进入导出入口 `export_bundle`；二是 `export_bundle` 构造 `BundleOptions`（聚合 html/pdf/png/svg 四类选项），调 `typst_bundle::export` 得到 `VirtualFs`（路径→字节映射），再由 `write_virtual_fs` 用 rayon 并行、经 `VirtualPath::realize` 安全拼到磁盘根落盘——`VirtualFs` 是 bundle 与 CLI 的干净交接格式，编码层区分 document/asset、落盘层只认字节。三是区分两个 feature：Cargo feature `bundle`（编译期、CLI 默认开、门控代码存在）与运行时 `--features bundle`（门控 `warn_or_error_for_bundle`：开=警告、不开=报错），且 bundle 多文件不能写 stdout。四是 watch 下 `set_bundle` 把 bundle 托管进 http-server 内存，按 URL 路由取字节、支持目录默认页，HTML 文档享 live-reload、非 HTML 按 MIME 直出。
