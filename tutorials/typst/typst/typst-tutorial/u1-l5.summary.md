本讲介绍 Typst 的集成测试体系。tests/ 分四层：src 存运行器代码，suite 存 .typ 输入，ref 存期望输出，store 存活输出与报告（不入库）。cargo testit 是别名，经 test-wrapper 转发为 cargo test --workspace --test=tests；测试包设 harness=false、使用自定义运行器，支持名字正则与 -p 路径过滤、--exact 精确匹配、--stages 裁剪环节、--list 与 --update 更新引用。套件用「--- 名字 属性+ ---」分节，测试分三类：断言型（运行器注入的 #test）、诊断型（// Error 等注解）、视觉对照型（与参考图比对）。stage 构成树：eval→paged→render/pdf→pdftags/svg，另有 html 与实验性 bundle，蕴含与前置规则决定实际执行集。引用分两种：render/bundle 用文件引用（≤20 KiB），pdf/svg/html/pdftags 用 hashes.txt 哈希引用；失败生成 store/report.html，缺旧活输出时 regen 可在旧 revision 重跑补齐。核心结论：README 属性列表滞后（如 pdfstandard 已不在代码中），以 collect.rs::parse_attrs 为准。
