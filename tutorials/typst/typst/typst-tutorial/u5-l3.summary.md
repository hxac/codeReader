本讲回答「导出格式如何插入编译器」。核心结论：`Format` 是结构体而非 trait，它把一种导出格式的注册信息（格式元素、选项默认值、feature 门、规则注册函数）数据化为 `FORMAT` 常量，由导出 crate 自己定义，宿主经 `Library::builder(formats)` 注入，typst-library 因此不认识任何具体格式；装配时格式元素定义进 `std.format` 模块，再经 prelude 提升为全局名（继承 feature 门控）。关键术语：格式元素（如 `HtmlFormat`，仅供 `set` 规则配置）、`Target`（Paged/Html/Bundle，与输出类型一一对应）、`Output` trait（`target()`/`create()`）、按 (元素， 目标) 键控的 `NativeRuleMap`、汇集文档内 set 选项的 `DocumentFormatOptions`。HTML 目标与 paged 共用同一条 realize 流水线，差异仅在规则查表时分岔，产物经 convert 转为 DOM、finalize_dom 收尾后序列化输出；`html.elem` 与 `html.frame` 提供语义手控与局部 paged 逃生舱。目标分叉由类型层、样式层（`TargetElem` 写入样式链，`context target()` 读取）、规则层三层配合，CLI 依输出格式选择 `compile::<PagedDocument>` 或 `compile::<HtmlDocument>`；feature 开关控制库可见性，与编译目标相互独立。
