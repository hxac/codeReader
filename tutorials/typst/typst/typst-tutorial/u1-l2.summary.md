本讲把 Typst 仓库当作一个 Rust 工程从源码构建，引入 crate、workspace、集中依赖表、profile、cargo 别名等术语。核心结论：根 Cargo.toml 是 workspace 清单而非包清单，members 纳入 17 个编译器 crate 及 docs、tests 包，default-members 指向 typst-cli，故根目录裸跑 cargo 默认只构建 CLI；共享元数据（版本 0.15.1、MSRV 1.92、edition 2024）集中声明，成员以 workspace = true 继承。依赖分三种来源：path（仓库内部 crate）、git（typst-assets、typst-dev-assets 等锁定 rev，保证可复现，首次构建需联网）、registry（crates.io）。profile 分三档：dev（依赖强制 opt-level 2）、dev-fast、release。cargo testit 与 docit 是 .cargo/config.toml 中的普通别名，分别运行 test-wrapper 集成测试与 typst-docs 文档站。常用命令为 cargo build -p typst-cli、cargo run -p typst-cli -- compile、cargo test。本讲打通克隆—构建—运行闭环，为下一讲 crate 分工全景铺路。
