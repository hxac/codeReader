
### 4.3 遍历与反查模式：从 Span 找回源码

#### 4.3.1 概念说明

Span 是「身份证」，但用户最终要看的是源码片段。反查需要两样东西：

- **从 Span 到字节区间**：Source::range（单文件底层 API，直接可用）和 WorldExt::range（编译器全链路的推荐入口，因为它先按 FileId 定位文件再查区间）。
- **LinkedNode**：SyntaxNode 树只存「相对长度」，不存绝对偏移；LinkedNode 在遍历时携带父链与累计偏移，既能给出绝对 range()，也能支撑按编号/区间剪枝查找。

#### 4.3.2 核心流程

```text
调用方拿到 Span
   |  span.get() 展开
   |-- Detached -----------------> 返回 None（无位置）
   |-- Number { id, num } -------> 按 id 找到 Source（World::source 或直接持有）
   |                                 |-- LinkedNode::find_number(num) 剪枝下行
   |                                 v
   |                                 linked.range() = offset..offset+len
   '-- Range { id, range } ------> 直接返回字节区间
```

正向（节点到 Span）则是 O(1) 字段读取 node.span()；批量场景可用 Span::find（span.rs L199-L204）从迭代器里挑第一个非 detached 的 span——典型用法是「一系列候选节点里找一个有真实位置的」。

#### 4.3.3 源码精读

**① LinkedNode：带定位的遍历包装**

[crates/typst-syntax/src/node.rs:L1068-L1077](https://github.com/typst/typst/blob/64c5e8c02fe0394d913ead36e42ef8c1334d2107/crates/typst-syntax/src/node.rs#L1068-L1077) 定义结构：底层节点 + 父链（Rc）+ 在父孩子数组中的下标 + 绝对字节偏移。[crates/typst-syntax/src/node.rs:L1080-L1103](https://github.com/typst/typst/blob/64c5e8c02fe0394d913ead36e42ef8c1334d2107/crates/typst-syntax/src/node.rs#L1080-L1103) 提供入口与定位：new(root) 从根开始、range() 返回 offset..offset + node.len()。

[crates/typst-syntax/src/node.rs:L1115-L1122](https://github.com/typst/typst/blob/64c5e8c02fe0394d913ead36e42ef8c1334d2107/crates/typst-syntax/src/node.rs#L1115-L1122) 的 find 按 SpanKind 分派；[crates/typst-syntax/src/node.rs:L1124-L1138](https://github.com/typst/typst/blob/64c5e8c02fe0394d913ead36e42ef8c1334d2107/crates/typst-syntax/src/node.rs#L1124-L1138) 的 find_number 文档注释明确写了它依赖的两条有序性保证（父编号小于所有子孙、兄弟从左到右递增），并实现「目标编号小于当前编号即可放弃子树」的剪枝。

**② Source 侧的两个入口**

[crates/typst-syntax/src/source.rs:L116-L124](https://github.com/typst/typst/blob/64c5e8c02fe0394d913ead36e42ef8c1334d2107/crates/typst-syntax/src/source.rs#L116-L124)：Source::find 先校验文件 id 归属，再委托 LinkedNode::new(self.root()).find(span)，返回 LinkedNode（还能顺藤摸瓜拿父节点）：

```rust
pub fn find(&self, span: Span) -> Option<LinkedNode<'_>> {
    if span.id() != Some(self.id()) {
        return None;
    }
    LinkedNode::new(self.root()).find(span)
}
```

[crates/typst-syntax/src/source.rs:L126-L144](https://github.com/typst/typst/blob/64c5e8c02fe0394d913ead36e42ef8c1334d2107/crates/typst-syntax/src/source.rs#L126-L144)：Source::range 接受 SpanNumber（和可选 SubRange），走 find_number 后返回纯字节区间；文档注释提示「更简单的方式是用 WorldExt::range」。

**③ WorldExt::range：官方推荐入口**

[crates/typst-library/src/lib.rs:L142-L159](https://github.com/typst/typst/blob/64c5e8c02fe0394d913ead36e42ef8c1334d2107/crates/typst-library/src/lib.rs#L142-L159) 为所有 World 实现提供了 blanket 实现：接收 impl Into<DiagSpan>（所以普通 Span 直接可用），按 DiagSpanKind 三分支处理——编号形态先 self.source(id) 找到对应 Source 再调它的 range：

```rust
impl<T: World + ?Sized> WorldExt for T {
    fn range(&self, span: impl Into<DiagSpan>) -> Option<Range<usize>> {
        match span.into().get() {
            DiagSpanKind::Detached => None,
            DiagSpanKind::Number { id, num, sub_range } => {
                self.source(id).ok()?.range(num, sub_range)
            }
            DiagSpanKind::Range { id: _, range } => Some(range),
        }
    }
}
```

#### 4.3.4 代码实践

**实践目标**：完成一次完整反查——从树里取一个 FuncCall，拿到它的 Span，再打印它对应的源码文本。

1. 新建 crates/typst-syntax/examples/lookup.rs（示例代码，练习后删除）：

```rust
use typst_syntax::{ast::{self, AstNode}, Source, SyntaxNode};

fn first_call(node: &SyntaxNode) -> Option<ast::FuncCall> {
    // 先看自己能不能转成 FuncCall 视图
    if let Some(call) = node.cast::<ast::FuncCall>() {
        return Some(call);
    }
    // 否则在孩子里递归找
    node.children().find_map(first_call)
}

fn main() {
    let source = Source::detached("#calc.max(1, 2)");
    let call = first_call(source.root()).expect("应有函数调用");
    let span = call.span();

    // 反查：拿到带父链的 LinkedNode，取字节区间
    let linked = source.find(span).expect("span 应指向本文件");
    let range = linked.range();
    println!("callee 源码片段: {:?}", &source.text()[range]);
}
```

2. 运行：cargo run -p typst-syntax --example lookup
3. 观察现象：程序打印 calc.max(1, 2)（整个 FuncCall 的源文），而不是只有函数名。
4. 预期结果：call.span() 覆盖整个调用表达式；source.find 到 linked.range 再切片 source.text 这条链把 Span 还原成了文本。如果把输入换成没有函数调用的文本，expect 会如预期般报错。具体输出待本地验证。

#### 4.3.5 小练习与答案

**练习 1**：Source::find 和 Source::range 都能定位，选哪个？

答案：要「节点本身及其父链/兄弟上下文」（比如编辑器要高亮外层结构）用 Source::find，返回的 LinkedNode 可以取 parent、range、继续遍历；只要一个 Range<usize>（比如给诊断附加位置）用 Source::range；跨多个文件、或不确定 span 属于哪个文件时，用 WorldExt::range 一步到位。

**练习 2**：为什么 find_number 能剪枝，而「按字节区间找节点」（find_range，见 node.rs L1120 处的分派）通常不能同等程度剪枝？

答案：剪枝依赖编号的全序不变量（父小于子、兄弟左小右大），这是 numberize 主动维护的数学性质；而字节区间只是节点的派生几何信息，树上有错误节点或零长插入（u2-l3 讲过 Error 节点可为零长）时，区间之间的重叠与包含关系更复杂，无法仅凭比较两端点安全排除子树。
