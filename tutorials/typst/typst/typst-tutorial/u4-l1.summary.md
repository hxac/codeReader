本讲把 Typst 编译拆为五阶段流水线：parse（typst-syntax，字符串→语法树，纯函数永不失败）→ eval（typst-eval，→ Module 与 Content，执行脚本和 set 规则）→ realize（typst-realize，应用 show 规则得到可排版元素）→ layout（typst-layout，→ PagedDocument/Frame）→ export（独立导出 crate 输出字节）；官方架构文档将 realize 并入排版、按四阶段叙述。核心结论：编译循环中求值只执行一次，排版按不动点迭代多轮——comemo 记录本轮读取了内省器哪些条目，constraint.validate 保守判定收敛；上限 MAX_ITERS=5，不收敛不报错，由 introspection::analyze 生成警告并返回末轮文档。泛型 Output 与 Target（Paged/Html/Bundle）让同一主流程服务多编译目标，realize 等跨 crate 行为经 ROUTINES 函数指针表接线。计时靠 timed! 宏与 RAII 的 TimingScope，CLI --timings 导出 Chrome Tracing JSON，可数出 iter(n) 排版轮数；layout（含 realize）是最耗时阶段。
