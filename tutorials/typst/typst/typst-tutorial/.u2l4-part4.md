
**④ 以函数调用为例：三个视图如何协作**

[crates/typst-syntax/src/ast.rs:L2119-L2151](https://github.com/typst/typst/blob/64c5e8c02fe0394d913ead36e42ef8c1334d2107/crates/typst-syntax/src/ast.rs#L2119-L2151) 定义 FieldAccess 与 FuncCall 的语义方法——全部用 cast_first/cast_last 在孩子里「捞」出需要的视图：

```rust
impl<'a> FieldAccess<'a> {
    /// The expression to access the field on.
    pub fn target(self) -> Expr<'a> { self.0.cast_first() }

    /// The name of the field.
    pub fn field(self) -> Ident<'a> { self.0.cast_last() }
}

impl<'a> FuncCall<'a> {
    /// The function to call.
    pub fn callee(self) -> Expr<'a> { self.0.cast_first() }

    /// The arguments to the function.
    pub fn args(self) -> Args<'a> { self.0.cast_last() }
}
```

对 f(x, y) 这棵 CST 子树：第一个能转成 Expr 的孩子是 f（被调者），最后一个是 Args 节点，中间的括号等 token 自然被跳过。

[crates/typst-syntax/src/ast.rs:L2153-L2206](https://github.com/typst/typst/blob/64c5e8c02fe0394d913ead36e42ef8c1334d2107/crates/typst-syntax/src/ast.rs#L2153-L2206) 是参数列表：Args::items 用 children().filter_map(SyntaxNode::cast) 把每个孩子转成 Arg（逗号被 cast 拒绝而过滤）；Arg 是手写的枚举——Named（draw: false）、Spread（..things）各自对应 kind，其余统统转成 Expr 作为位置参数：

```rust
pub enum Arg<'a> {
    Pos(Expr<'a>),      // 位置参数
    Named(Named<'a>),   // 命名参数
    Spread(Spread<'a>), // 展开参数
}

impl<'a> AstNode<'a> for Arg<'a> {
    fn from_untyped(node: &'a SyntaxNode) -> Option<Self> {
        match node.kind() {
            SyntaxKind::Named => Some(Self::Named(Named(node))),
            SyntaxKind::Spread => Some(Self::Spread(Spread(node))),
            _ => node.cast().map(Self::Pos),
        }
    }
}
```

**⑦ 补充：set.rs 是 SyntaxKind 的集合工具，与 Span 无关**

一个常见误解是「set.rs 和 Span 有关」。读源码会发现并非如此：[crates/typst-syntax/src/set.rs:L7-L48](https://github.com/typst/typst/blob/64c5e8c02fe0394d913ead36e42ef8c1334d2107/crates/typst-syntax/src/set.rs#L7-L48) 的 SyntaxSet 是一个 u128 位图（致敬 rust-analyzer 的 TokenSet），new/add/remove/union/contains 全是 const fn。它真正服务的是解析器：STMT（L63）声明哪些 kind 能开始一条语句，CODE_EXPR（L96-L97）声明哪些 kind 能开始一个代码表达式，解析器用 [crates/typst-syntax/src/parser.rs:L1641-L1642](https://github.com/typst/typst/blob/64c5e8c02fe0394d913ead36e42ef8c1334d2107/crates/typst-syntax/src/parser.rs#L1641-L1642) 的 at_set 做超前判断。它与本讲的间接联系是：**SyntaxSet 决定解析器在每种模式下认哪些结构，进而决定 CST 上会出现哪些 kind，进而决定 cast 能成功哪些 AST 视图**。这是「解析决策、树、视图」的一条因果链，而非 Span 相关机制。
