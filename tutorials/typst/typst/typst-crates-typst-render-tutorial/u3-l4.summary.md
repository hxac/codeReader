本讲聚焦 typst-render 的记忆化与计时机制，讲清「算完的结果如何存与复用」。它覆盖三个被 `#[comemo::memoize]` 缓存的最小模块：字形光栅化 `rasterize`（text.rs）、图像纹理 `build_texture`（image.rs）、渐变采样 `cached`（paint.rs）。核心结论：缓存键等于全部参数的逐位相等，命中即返回 `Arc<T>` 实现零拷贝共享。三键各有侧重——`rasterize` 含 `f32::to_bits()` 编码的字号 ppem 与绝对像素位置 tx/ty；`build_texture` 键为 `(image, w, h)` 且不含位置（贴位由 Pattern 完成）；`cached` 键含 `gradient_map`（仅负尺寸矩形 + `Self_` 模式非 `None`）。关键术语：因 `f32` 未实现 `Eq`/`Hash`，须用 `to_bits`/`from_bits` 转可哈希的 `u32`，且保证亚像素级精确比较。由此推断：同一字形同字号不同位置不命中 rasterize，缓存收益主要体现在 watch 重渲染同版面时。缓存全 workspace 共享，由 `comemo::evict(10)` 代际清理。此外 `#[typst_macros::time]` 给入口 `render` 挂计时探针：宏插入 `TimingScope`，Start 在构造、End 在 `Drop`，默认关闭时返回 `None` 近乎零开销，`enable()` 后可导出 Chrome Tracing JSON 定位热点。最后指出平铺 `Tiling` 当前未 memoize，是渐变与平铺间的一处性能不对称。
