本讲是 typst-svg 绘制系统的枢纽，解决「`Paint` 如何落到 SVG 的 `fill`/`stroke` 属性」与「同一渐变/平铺被反复使用时如何避免重复写出完整定义」。核心涉及 `src/paint.rs` 与 `src/shape.rs`：入口函数 `write_fill`/`write_stroke` 按 `Paint` 三变体（`Solid`/`Gradient`/`Tiling`）分发，纯色直接写字符串，渐变与平铺走 `push_gradient`/`push_tiling` 拿到 `DedupId`，再用适配器 `SvgUrl` 包成 `url(#id)`；`write_fill` 还无条件补 `fill-rule`（NonZero/EvenOdd），`write_stroke` 再补 `stroke-width`/`linecap`/`linejoin`/`miterlimit`/`dash`。

最关键的是「源（source）+ 引用（ref）」两层去重模型：源不带变换、键不含使用变换 `ts`，故同一渐变/平铺无论用多少处只存一份；引用只记「源 ID + `ts`」，每个不同使用变换各存一份但近乎空壳。`push_*` 内 `ts.is_identity()` 为快速路径，成立时直接返回源 ID（命名空间 `f`/`t`），否则返回引用 ID（`r`/`p`）。由于真实形状包围盒极少恰好 1pt×1pt，现实中多走引用层。

`finalize` 阶段集中写出定义：`write_gradients`/`write_tilings` 写源（不带 `gradientTransform`/`patternTransform`），`write_gradient_refs`/`write_tiling_refs` 写引用空壳，仅含变换属性、`id`、`href` 与兼容用的 `xlink:href`；`GradientKind`（Linear/Radial/Conic）决定元素名与变换属性名。引入术语：`Paint`、`FixedStroke`、`aspect_ratio`、`Deduplicator`、`SvgUrl`/`SvgIdRef`/`SvgTransform` 适配器、两层去重模型。体积收益为 Θ(S+N·R) 对 Θ(N·S)。后续 u5-l3 讲源定义几何细节，u5-l4/l5 讲圆锥与平铺特例，u6-l3 讲 `Deduplicator` 底层。
