本讲承接 u6-l1，专门拆解 typst-svg 中嵌入 PDF 图转 SVG 的路径。核心结论是：矢量 SVG 导出里嵌入的 PDF 图不能直接字节透传，因为浏览器/SVG 阅读器看不懂 PDF 内容流，必须先经 **hayro** 解释器读出 PDF 一页的绘图指令，再用 **hayro_svg** 后端重新写成 SVG 矢量原语，以保真、可缩放、省体积。接入点是 `WebImage::new` 的 `ImageKind::Pdf` 分支，调私有函数 `pdf_to_svg`，把返回的 SVG 标记为 `WebImageFormat::Svg`，之后复用 SVG 图的 base64 内联与 `<image>` 写出机制，PDF 在此被「抹平」成普通 SVG；该 `new` 被 `comemo::memoize`，同一 PDF 图只转一次。`pdf_to_svg` 为三段式：`select_standard_font` 字体闭包、`InterpreterSettings` 配置、`hayro_svg::convert` 调用。关键术语包括：**InterpreterSettings** 的四字段（`font_resolver` 提供字体、`cmap_resolver` 恒返回 None 以省体积、`warning_sink` 静默、`render_annotations` 为 false 取打印效果）与透明背景 `SvgRenderSettings { bg_color: [0,0,0,0] }`。14 种 **PDF 标准字体（Base-14）** 呈「三族（Helvetica/Courier/Times）×四变体 + ZapfDingBats + Symbol」结构，查表映射到 `typst_assets::pdf::*` 常量。最后点明 `// Keep this in sync with typst-png!` 是跨 crate 手工同步约定：typst-render 的 `build_pdf_texture` 与本函数共享同一套 hayro 配置与字体表，仅输出后端不同（SVG vs 位图），唯一护栏是这行注释，两处还互为对方缺失「为什么」的文档。
