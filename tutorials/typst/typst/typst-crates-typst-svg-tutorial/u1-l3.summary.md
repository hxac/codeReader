本讲从调用者视角俯瞰 typst-svg 的公共 API：全部仅「4 个导出函数 + 1 个 SvgOptions」，集中于 src/lib.rs。四函数按输入类型与目标宿主分工——svg（单页文件）、svg_merged（多页纵向拼接）、svg_in_bundle（bundle 一份子、含锚点与跨文档链接解析）、svg_in_html（HTML 内嵌、em 单位、接收裸 Frame）；仅后两者携带 link_resolver（LateLinkResolver）以延迟解析链接。SvgOptions 只有两个布尔字段：pretty（缩进可读性）与 render_bleed（印刷出血），默认皆 false。单页导出统一遵循七步骨架：page_bleed → new → svg_header → State::new → render_page → finalize → end_document。其中 page_bleed 决定画布尺寸与平移变换，svg_header 写 viewBox/width/height 及命名空间并把尺寸 clamp 到 ≥1pt；返回的 SvgElem 借 RAII/Drop 自动闭合标签，finalize 把字形、裁剪路径、渐变等可复用资源集中写入 `<defs>`。在 typst-cli 中，pretty 由 --pretty 标志端到端透传，而 render_bleed 被硬编码为 false，故命令行产物永远不含出血，只有程序化调用才能启用。本讲只覆盖入口与编排，render_page/render_frame 的渲染细节留给后续单元。
