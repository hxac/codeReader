本讲聚焦 typst-svg 中纯色（`Paint::Solid`）的序列化，核心问题是 Typst 内部的 `Color` 如何变成 SVG/CSS 可识别的字符串，主战场为 `src/paint.rs` 中的 `impl SvgDisplay for Color`。入口先经 `to_process()` 将任意颜色（含专色 Spot Color）归一为 8 变体的 `ProcessColor` 枚举（Luma/Oklab/Oklch/Rgb/LinearRgb/Cmyk/Hsl/Hsv），再用 `match` 分发到两条路径：路径①是 Rgb/Luma/Cmyk/Hsv 走 `to_hex()`，内部恒先 `to_rgb()` 落成 `#rrggbb`（含 alpha 时为 `#rrggbbaa`），对前三种几乎无损，CMYK 为务实有损兜底；路径②是 LinearRgb/Oklab/Oklch/Hsl 走 CSS 函数语法（`color(srgb-linear …)`/`oklab()`/`oklch()`/`hsl()`|`hsla()`），保留原坐标。划分依据是能否在 8 位 sRGB hex 中无损或务实落地——不能则交给浏览器做色域映射。alpha 在 hex 中作第 4 字节（`a != 255`），在函数中追加 ` / <alpha>` 后缀（`alpha != 1.0`），HSL 还会据 alpha 切换函数名。精度由 const-generic 工具函数 `round::<DIGITS>`（放大取整再缩回，f32 输入 f64 输出）控制：感知量（明度、百分比、色相）用 3 位，需忠实往返的原始坐标与 alpha 用 5 位；其结果再经 `SvgWrite::push_num` 二次舍入（9 位 + itoa/ryu），形成「双重舍入」，共同保证输出短而可复现。渐变与平铺的 SVG 引用留待 u5-l2/u5-l3。
