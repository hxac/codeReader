本讲聚焦 Typst 编译器贯穿求值与布局全过程的中央上下文对象 `Engine` 及其四个「乘客」，全部定义在 `typst-library/src/engine.rs`。`Engine` 把 `world`、`library`、`introspector`、`traced`、`sink`、`route` 六个字段打包传递，绝大多数是 comemo 追踪句柄，使其既是数据容器又参与缓存失效；其中 `library` 因访问频繁单独缓存，`introspector` 用 `Protected` 包裹强制登记访问。`Sink` 是只增容器，收集告警（按 `(span,message)` 哈希去重）、延迟错误、内省记录与追踪值（上限 10），并通过 `extend_from_sink`/`extend` 在稳定化循环与并行任务间分合回流。`Route` 是带 `outer` 父指针的链表，`contains` 检测循环导入、`within` 检测过深嵌套，四档阈值（64/72/72/80）让更具体的错误优先报出；其 `upper` 上界「故意不精确」以换取不同深度间的缓存复用。`Traced::get(id)` 按文件 id 过滤 span，把追踪失效限制在真正含该 span 的文件内。核心范式是「克隆 Engine → 各自子 Sink → 合并回流」。
