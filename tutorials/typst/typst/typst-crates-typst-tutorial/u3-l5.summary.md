本讲围绕 `typst` crate 与 `compile()` 并列的第二个公开入口 `trace()` 展开，剖析「值追踪」这条与编译共用逻辑却长期被忽略的副线。核心结论是：`trace()` 与 `compile()` 共用同一套 `compile_impl`，唯一实质差异是传入的 `Traced`——前者用 `Traced::default()` 不追踪，后者用 `Traced::new(span)` 追踪指定 span；`trace` 还对返回值调 `.ok()` 丢弃错误，只关心观察到了哪些值，从而支持 IDE 在带错文档里 best-effort 给出悬停取值。

引入的关键术语包括：`Traced`（携带目标 span 的小结构体，其 `get(id)` 按文件 id 过滤，把 comemo 缓存失效收敛到唯一一个文件）；`Sink::value`（只增容器里记录 `(Value, Option<Styles>)` 的方法，硬上限 `MAX_VALUES = 10` 超限静默丢弃，`extend` 合并子 sink 时同样尊重此限）；求值侧 `Vm` 的 `inspected` 字段（由 `traced.get(id)` 初始化），以及 `trace_at(span, value)`（仅当精确命中目标表达式 span 才经 `#[cold]` 的 `Vm::trace` 写入 sink）。

完整调用链为：IDE 悬停 → `analyze_expr` → `typst::trace::<PagedDocument>` → `compile_impl` → `eval` → `Vm` → `Sink::value` → `sink.values()` 返回给 IDE 渲染悬停提示。注意布局阶段的 `eval_string` 用 `Traced::default()` 不参与追踪，追踪值只来自主模块求值。
