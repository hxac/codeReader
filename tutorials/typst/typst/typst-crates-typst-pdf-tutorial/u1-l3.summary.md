本讲拆解 typst-pdf 的 `PdfStandard` 与 `PdfStandards`（源码集中在 `src/lib.rs`）。`PdfStandard` 是带 `#[non_exhaustive]` 的「原料菜单」，统一三类目标：PDF 版本（1.4–2.0）、PDF/A 归档标准（a-1b~a-4e，各绑定底层版本）、PDF/UA 无障碍标准（ua-1），`#[serde(rename)]` 决定用户输入字符串。装配核心是 `PdfStandards::new()`：先用三道闭包门（set_version、set_archival_validator、set_accessibility_validator）拦下版本重复、两个 PDF/A、两个 PDF/UA 等常见冲突，再把版本号与校验器交给 krilla 的 `ConfigurationBuilder`；版本区间相容性在 `builder.finish()` 检查，其 `ConfigurationError`（NoOverlappingValidatorsRange / VersionDoesNotMatchValidatorsRange）经 `version_hint()` 译成带修正建议的 `HintedString`。关键区分：tagged PDF（写结构树，默认开）≠ PDF/UA 校验（须含 Ua_1 才启用）；`PdfOptions::accessibility_validator()` 仅在标准含 PDF/UA 时返回 Some，驱动 tags/link 等下游模块的严格行为。默认配置为 PDF 1.7、无任何校验器、tagged: true；装配好的 config 经 `SerializeSettings` 流入 krilla 驱动序列化，`PdfStandards` 手动实现 Hash 以支持增量编译缓存。
