本讲精读 `src/shape.rs` 与 `src/util.rs` 的 `convert_path`，讲清 Typst 图形如何导出为 PDF。`handle_shape()` 是所有图形绘制的唯一入口，用户图形与页面背景填充共用，差异仅在 tagged PDF 的 `artifact_type`（`Layout` vs `Background`）。其执行链为：发射 tagged 标记（RAII 的 `TagHandle`，drop 时自动收尾）→ 用 `push_transform` 压入 `FrameContext` 累计变换并以 `defer` 配对 `pop` → 调 `convert_geometry` 把几何体转成 `Path` → 转 `fill`/`stroke` → 判空后 `draw_path`。核心结论是判空：须过滤掉 `thickness ≤ 0` 的描边（PDF 中线宽 0 会被当作最细线而非不画），且仅当 fill 或 stroke 至少一个非空才绘制，否则 krilla 会用默认黑色填充。`convert_geometry()` 把 `Geometry` 的 `Line`/`Rect`/`Curve` 三变体翻译成 krilla `Path`；负尺寸矩形用 `Transform::from_scale(w.signum(), h.signum())` 做镜像还原，因 krilla 不支持负尺寸而 Typst 支持。`convert_path()` 以追加式接收 `&mut PathBuilder`，将 `CurveItem` 的 `Move`/`Line`/`Cubic`/`Close` 一一对应 PDF 的 `m`/`l`/`c`/`h` 算符，`Cubic` 仅传两控制点加终点（起点为隐式当前点）。填充与描边颜色的具体翻译留待下讲 `paint.rs`。
