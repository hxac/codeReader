本讲建立 `typst-pdf` 的全局地图，确立其「薄门面 + 厚后厨」结构：`lib.rs` 仅对外暴露 `pdf()` / `pdf_in_bundle()` / `PdfOptions` / `PdfStandards` / `PdfStandard` / `Timestamp` / `Timezone`，12 个内部模块（convert/page/text/shape/paint/image/link/outline/metadata/attach/tags/util）全部私有。核心结论有三：其一，`convert::convert()` 是总调度，采用编排者模式，按「设置→建文档→页号转换→命名目的地→tags init→GlobalContext→convert_pages→附件→tags resolve→大纲/元数据/结构树→finish」共 13 步串联各子模块；`handle_frame` 作为内容分派器按 `FrameItem` 变体路由到各翻译器，`GlobalContext` 是贯穿全程的状态容器；`util` 是横向复用的工具层。其二，12 模块分三类——`convert`（调度）、`util`（工具箱）、9 个「内容翻译器」。其三，`tags/` 是最复杂的子系统，生成 tagged PDF，内部五段划分（groups/tree/context/resolve/util）遵循「build 构建→tree 遍历发射→resolve 解析校验」三段式，默认开启但与 `page_ranges` 互斥。本 crate 是 typst workspace 的库成员，用 `cargo check/build/test -p typst-pdf` 单独操作，测试为源码内联、无独立 `tests/` 目录。
