本讲聚焦 typst-pdf 的公共 API 表面：lib.rs 是门面，convert.rs 是后厨。crate 对外仅两个入口——`pdf()`（单文档独立导出）与 `pdf_in_bundle()`（多文档打包、支持跨文档链接），二者都是对 `convert::convert()` 的一行委托，唯一区别在 `anchors`（命名目的地址，独立导出传 `&[]`）与 `link_resolver`（跨文档链接解析器，独立传 `None`、打包传 `Some`），均返回 `SourceResult<Vec<u8>>`。关键术语：`SourceResult`（带 span 的诊断错误）、`Smart<T>`（Auto/Custom）、named destination、`LateLinkResolver`（延迟解析）。`PdfOptions` 是导出控制面板，七个 pub 字段（`ident`/`creator`/`timestamp`/`page_ranges`/`standards`/`tagged`/`pretty`）派生 `Debug`/`Hash`，`Hash` 供增量编译缓存复用；默认配置为 PDF 1.7 无校验器、`tagged=true`、`pretty=false`，其中 `pretty`、`tagged` 经 krilla 的 `SerializeSettings`（如 `compress_content_streams`、`enable_tagging`）影响最终 PDF 字节。`standards` 字段的深度内容留待下一讲。
