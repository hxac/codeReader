本讲聚焦 typst-html 的内省（introspection）子系统，核心是单文件 introspect.rs。`HtmlIntrospector` 是一层薄壳，仅三字段：`elements`（委托给目标无关的泛型引擎 `ElementIntrospector<HtmlPosition>`，分页用 `PagedPosition`、HTML 用 `HtmlPosition`，故查询算法两边复用）、`frame_link_targets`（收集 SVG frame 内部 `FrameItem::Link` 目标）、`anchors`（事后注入的 fragment ID）。它实现 `Introspector` trait 时页面相关方法一律返回 `None`，`position` 返回 `DocumentPosition::Html`。生命周期分两段：构建期 `new`（`discover_nodes`→`finish`，此时 anchors 为空）与装配期 `set_anchors`（因锚点需先 `link_targets` 查询、再 `create_link_anchors` 改写 DOM，故必须事后注入，这也是 `HtmlDocument` 不实现 `Hash` 的根因之一）。

关键术语：`HtmlPosition` 是从根出发的一串 DOM 孩子索引（`<html>` 根不入路径，首段即 `<head>`/`<body>`），可选附带文本偏移或帧内坐标（`in_frame`）；`iter_with_dom_indices`（dom.rs 状态机）把扁平下标对齐成真实 DOM 序号——`Tag` 不前进游标、连续 `Text` 共享同一序号；`discover_nodes` 用 `current_position` 的 `push`/`pop` 动态维护当前路径；元素的 `parent` 字段配合上游 `start_insertion`/`end_insertion` 截获孩子事件并回放到父元素之后，使内省顺序符合 Typst 逻辑结构而非 DOM 物理顺序，支撑 `counter`/`query(...).before(...)`。`discover_frame` 钻进 `html.frame` 的 `Frame`，带累积变换 `ts` 二次内省，把帧内 `Tag` 映射成「DOM 路径 + 帧内坐标」。下一讲 u5-l4 将承接 `link_targets()` 的产出，讲解链接锚点分配。
