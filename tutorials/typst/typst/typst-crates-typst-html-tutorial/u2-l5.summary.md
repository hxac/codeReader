本讲聚焦 `typst-html` 的 `typed.rs`，揭示 `html.div`/`html.a` 等「类型化构造函数」并非手写，而是运行时依据 `typst-assets::html`（记作 `data`）的规范数据批量生成的，函数数量随规范表自动增长。核心生成链为：`define()` 注册入口 → `FUNCS` 惰性静态（用泄漏的 `Bump` 换取闭包与字符串的 `'static` 生命周期）→ `create_func_data` 装配 `NativeFuncData` → `create_param_info` 推导参数签名 → `construct` 运行时装配。关键结论有二：一是所有类型化函数共用同一份 `construct` 实现，差异仅来自各闭包捕获的 `element`；二是「签名」与「实现」对 void/raw 的判定成对一致——由 u2-l4 的 `is_void`/`is_raw` 驱动，void 标签无 body，raw 标签 body 为 `Str`，普通标签 body 为 `Content`。`construct` 复用 u2-l3 的 `HtmlAttrs`/`HtmlAttr::constant` 把命名参数压入属性，产出的 `HtmlElem` 与手写 `html.elem` 等价，即类型化 API 本质是 `html.elem` 的强类型语法糖。引入术语：`data::ElemInfo`、`AttrType::convert`（其完整类型体系留待 u6-l3 展开）。
