本讲聚焦 `src/rules.rs`，讲清 typst-html 如何把 Typst 元素映射成 HTML 标签：核心是一张「元素 → HTML」的映射表，由 `register()` 在编译器启动时填充。`register()` 是 typst-html 与编译核心之间的装配点，按 Model / Text / Visualize / Math 四组把几十条 `XXX_RULE` 常量注册进共享的 `NativeRuleMap`，体现依赖倒置：核心定义扩展点，插件填充。

关键术语：每条规则是 `ShowFn<T>` 函数指针（参数为元素、Engine、样式链），经 `NativeShowRule::new` 用 `transmute` 类型擦除后，以 `(Element, Target)` 为键存表，调用时由 `apply` 做运行时类型断言兜底。内建规则是兜底：realize 阶段先查用户 show 规则，未命中才查内建表，这正是用户 `#show strong: ...` 能覆盖默认 `<strong>` 的原因。

代表性规则分两种复杂度：`STRONG_RULE` 最简（包一层标签），`RAW_RULE` 展示读样式、组装序列、按 `block` 分流的典型形态。两个反直觉设计：`HEADING_RULE` 把 Typst level N 映射为 `<h{N+1}>`，因为 `<h1>` 留给文档标题 `TitleElem`，level ≥ 6 走 `<div role="heading" aria-level>` 的 ARIA 回退；`FrameElem` 是唯一注册在 `Target::Paged`（而非 Html）上的规则，且为 no-op，用于防止 `show math.equation: html.frame` 造成 Frame 无限嵌套。`FOOTNOTE_RULE` 不直接产出 `HtmlElem`，而是产出多元素序列，借 `HtmlElem::role` 挂载 `doc-noteref` 等 DPUB-ARIA 角色。
