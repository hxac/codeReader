本讲顺着数据流走通了 typst HTML 导出的完整调用链，覆盖五个最小模块：CLI 格式判定、`Target::Html` 驱动编译、`HtmlDocument` 实现 `Output`、`html_document` 编译入口、`html` 编码入口。

核心结论：typst-cli 在 `compile_and_export` 的 `OutputFormat::Html` 分支先调 `typst::compile::<HtmlDocument>(world)` 再调 `export_html` 写盘；格式由 `--format/-f` 或 `.html` 后缀判定。编译主循环对 Paged/Html/Bundle 统一，靠类型参数 `T` 区分，差异由 `T::target()`（返回 `Target::Html`）与 `T::create()`（转发到 `html_document`）表达，并反复重排直到内省收敛。`Target::Html` 不是 if 开关，而是经 `TargetElem::target.set` 注入样式链、由下游 show 规则读取。

引入的关键术语：`OutputFormat`（CLI 侧文件格式枚举）、`Target`（引擎侧编译目标 Paged/Html/Bundle）、`Output` trait（声明 target/create/introspector，是 typst-html 与核心的唯一耦合点，体现依赖倒置）、`Engine`、`Warned`、`HtmlDocument`（含 output/info/introspector 三块）、`HtmlOptions { pretty }`。核心分工是编译（`html_document`：Content→DOM，三层结构含 memoize 缓存壳）与编码（`html`：DOM→String，不依赖 Engine）分离，二者由 HtmlOptions 解耦。
