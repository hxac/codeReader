本讲精读 `src/fragment.rs`，讲解三类「递归编译片段」入口如何把嵌套 HTML 元素的内部内容交给独立子流程翻译。`html_block_fragment`（块级）走标准 memoize 三明治：公开入口拆解 `Engine` 为可哈希的 Tracked 句柄转发给被缓存的 `_impl`，接收 owned `Locator` 派生独立定位子树，并内部自建 `SmartQuoter`，因状态自包含、不外泄而可安全缓存。`html_inline_fragment`（行内）放弃缓存，借用 `&mut SplitLocator` 与 `&mut SmartQuoter`，让智能引号状态作为有状态机器在行内流中跨元素共享——这正是其与 memoize「纯函数」前提冲突、不能缓存的根本原因。`html_math_fragment` 签名同 inline，但绕过公共助手 `realize_fragment`，直调 realize 并传 `RealizationKind::Math`，以跳过段落分组、避免破坏 MathML 结构。`realize_fragment` 是 block/inline 共用的具象化封装，固定用 `RealizationKind::Fragment` 并忽略回填的 `FragmentKind`。三者入口均先调 `route.check_html_depth()`（上限 72），把无限递归转化为友好报错而非栈溢出。块级翻译后外层还会复位 quoter，呼应块级「断开」行内语境的语义。
