本讲精读 `src/span.rs` 前半部分，核心是讲清 Typst 如何用 8 字节给 CST 每个节点一个稳定身份证号。关键结论：`Span` 本体是 `NonZeroU64`，用整数编号而非字节范围定位源码，目的是在增量编辑下保持稳定，从而保住记忆化缓存命中率。64 位布局为高 16 位 `FileId`、低 48 位 `number`，由 `pack`（左移+或）、`id`（右移）、`number`（掩码与）这组互逆位运算拆装；因内部非零，`Option<Span>` 也只占 8 字节（null 优化）。低 48 位再分四段：detached 哨兵（值 1，文件号为 0）、numbered（`[2, 2^47)`，最常见）、external（`[2^47, 2^47+2^46)`，仅 `DiagSpan`）、range（`[2^47+2^46, 2^48)`，两个 23 位下标）。需注意「四类取值」≠「三个变体」：普通 `Span::get()` 只返回 `Detached`/`Number`/`Range`，external 留给 16 字节的 `DiagSpan`（u6-l3）。关键术语 `Span`、`SpanKind`、`SpanNumber`、`FileId`，以及 `from_number`/`from_range`/`get`/`detached`/`pack` 这套打包—还原 API 将被后续讲义承接；编号如何分配则由 u6-l2 的 `numberize` 详讲。
