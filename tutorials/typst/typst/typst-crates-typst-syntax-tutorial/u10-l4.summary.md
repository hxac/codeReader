本讲是 typst-syntax 手册收官篇，将前述零件串成「新增语法构造」的端到端改动链：kind.rs 立名（加 `SyntaxKind` 变体，补 `name()`、`mode_after()` 两处穷尽 match）→ lexer 产 token → parser 写规则（仿 `strong()` 的 marker→assert→markup→wrap 事后圈子树）→ set 入位集 → ast 用 `node!` 宏声明类型化节点 → highlight 加 `Tag` 与 `highlight()` 分支 → 评估 reparser。核心结论有三：`name`、`mode_after`、`highlight` 三处穷尽 match（无通配符）是编译期防遗忘骨架，新增变体必同时报错；判别值 < 128 才能进 `SyntaxSet`（u128 位集），决定变体在枚举中的位置；新构造只要成对消费定界符保持 `balanced` 且位于顶层/content block 正文，reparse 多数零改动，落列表项/标题/math 内则回退全量但仍正确。测试上，parser.rs/lexer.rs 无内联测试、本 crate 无 tests/ 目录，正确性由 node.rs（`test_debug`）等消费方经 `crate::parse` 间接验证。关键术语：判别值、穷尽 match、事后圈子树、`node!` 宏约定、`balanced`、消费方驱动测试。
