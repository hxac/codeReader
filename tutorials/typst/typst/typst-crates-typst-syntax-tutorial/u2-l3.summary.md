本讲精读 `src/set.rs`，引入 `SyntaxSet`——基于 `u128` 的位集 newtype，将多个 `SyntaxKind` 打包成一组。其 `add`/`remove`/`union`/`contains` 全为 `const fn`，可在编译期构造常量集合，运行期查询仅一次按位与。硬限制是只容纳判别值 < 128 的 kind，`SyntaxKind` 末尾 9 个结构节点变体（`ImportItems` 至 `DestructAssignment`）无法入集，越界在 const 上下文触发编译期 panic。`syntax_set!` 宏把一列 kind 标识符展开成 `.add()` 常量链，本身不做位运算，仅 `pub(crate)` 可见。预定义常量 `STMT`、`CODE_EXPR`、`ATOMIC_CODE_EXPR`、`UNARY_OP`、`BINARY_OP`、`ARG`、`PARAM`、`PATTERN` 层层 union/add 复用构成依赖图，parser 经 `at_set(set::NAME)` 判断「当前 token 是否属于某类」做决策。可见性要点：`set` 模块为私有 mod，`SyntaxSet` 未被 pub use，属 crate 内部工具，不在公开 API。集合口径（`STMT` 装关键字 token，面向未来 token）与谓词口径（`is_stmt` 判已解析节点）是同一语法概念在解析两个阶段的不同表达。
