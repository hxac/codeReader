本讲聚焦 `src/path.rs`（及 `src/span.rs` 的位布局），解决「编译器内部如何指代一个文件」这一工程问题。核心结论有四：其一，Typst 在操作系统真实路径之上架设虚拟文件系统，用 `RootedPath = (VirtualRoot, VirtualPath)` 标识文件身份——`VirtualRoot` 区分项目根与包根，`VirtualPath` 是规范化、以 `/` 开头且词法上不可能越根的绝对路径，`virtualize`/`realize` 负责其与真实路径的双向转换。其二，因 `RootedPath` 太重、不适合塞进每个 span，Typst 用驻留技巧将其映射为轻量的 `FileId(NonZeroU16)`，`Copy`/`Eq`/`Hash` 全为整数操作，相等的路径永远得到同一个编号。其三，全局驻留表 `INTERNER` 维护 `to_id`/`from_id` 双向映射，命中复用、未命中则分配并用 `Box::leak` 永久驻留；该 leak 策略可接受，源于三点：$2^{16}-1$ 的硬上限、实际占用很小、路径生命周期与进程等长，并换来 `'static` 路径引用与极简类型签名。`FileId::unique` 不走去重、不可反查，专供 stdin 等无路径身份的虚拟文件。其四，`FileId` 之所以正好 16 位且非零，与 `Span` 互相锁死：`Span` 高 16 位存 FileId、低 48 位存节点编号，`NonZeroU16` 既保证真实文件 id 永不为 0 从而与 detached span（id 为 0）天然区分，又让整个 `Span` 满足 `NonZeroU64`、使 `Option<Span>` 享受 null 优化。本讲承接 u6-l1 的 Span 系统，为后续 u10-l2 包清单解析埋下 `PackageSpec` 伏笔。
