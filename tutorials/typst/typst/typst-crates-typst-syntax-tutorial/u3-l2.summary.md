本讲聚焦 `Lexer` 的 `mode` 字段，解释为何同一字符在 Typst 不同位置被切成不同 token。`next()` 是模式分派总枢纽：它先以「公共前缀」处理空白、shebang、行/块注释、`*/` 报错与 raw 反引号，最后才按 `SyntaxMode`（Markup / Code / Math 三变体）调用 `markup()`、`code()`、`math()` 三个分派函数。关键术语：`SyntaxMode`、公共前缀、位置敏感标记、`text()` 续接规则、`invalid_char_in_code`、`MathShorthand`、`math_ident_or_field`。核心结论：Markup 以 `text()` 为默认产物，靠位置规则（行首 `=`/`-`/`+`/`/`、`!in_word` 的 `*`/`_`）识别结构；Code 最严格，无默认文本，无法识别即产出 `Error`；Math 独有大量简写，且会在词法阶段越权构造 `MathFieldAccess` 子树，故其返回类型为 `(SyntaxKind, Option<SyntaxNode>)`。空白与注释为三模式共享，唯一模式相关细节是 Markup 下连续 ≥2 换行产出 `Parbreak`。需注意 `Lexer` 是 `pub(super)` 私有类型，外部只能经 `parse`/`parse_code`/`parse_math` 三个入口按模式词法化。
