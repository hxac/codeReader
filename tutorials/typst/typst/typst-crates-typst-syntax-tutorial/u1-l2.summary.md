本讲承接 u1-l1，解决「如何构建、测试并调用 `typst-syntax`」的工程问题，覆盖三个最小模块。其一，依赖配置：本 crate 的 `Cargo.toml` 极简，几乎全用 `{ workspace = true }` 引用仓库根 `Cargo.toml` 的 `[workspace.package]` 与 `[workspace.dependencies]`，关键外部依赖各有分工——`unscanny`（词法游标）、`unicode-*`（字符判定）、`ecow`（紧凑字符串）、`rustc-hash`（快速哈希）、`serde`+`toml`（包清单）、`typst-utils` 的 `LazyHash`、`typst-timing`。其二，`parse` 入口：以 `SyntaxMode::Markup` 解析文本，返回根 kind 为 `Markup` 的裸 CST（尚未 numberize、无 Span）；`parse_code`/`parse_math` 结构对称，仅模式与根 kind 不同。其三，`Source` 类型：用 `Arc<LazyHash<SourceInner>>` 打包「`FileId`+文本+`Lines`+已编号语法树」，提供廉价克隆与哈希；`Source::new` 走 parse→numberize→建行索引的正规流程，`Source::detached` 用假路径 `main.typ` 便于测试，`Source::with_root` 复用既有树用于增量重解析。核心结论：`Source::detached("= Hello").root().kind()` 等于 `SyntaxKind::Markup`；用 `cargo build/test -p typst-syntax` 可单独构建测试本 crate。
