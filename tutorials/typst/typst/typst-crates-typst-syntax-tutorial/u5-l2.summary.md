本讲聚焦 `src/node.rs`，从对外 API 角度讲清 `SyntaxNode` 的构造与访问。构造器分两类：从零造节点的 `leaf`（叶子）、`inner`（带 children 的结构节点）、`error`（错误节点）；以及在已有节点上加工的 `warn` / `warn_at`，后者用 `mem::replace` 把原 `data` 抽出包进 `WarningWrapper`，kind 不变，即 Warning 半透明层的产生方式。关键不变量：`leaf` / `inner` 拒绝 `Error` kind（错误只能走 `error(message, text)`，先消息后文本，并存出错文本以保 CST 无损）；所有从零构造的节点 `span` 初始为 `Span::detached()`，待 `numberize` 统一编号。访问器中需区分 `leaf_text`（inner 返回空、O(1)）与 `full_text`（遍历拼接、可能较贵）；`kind()` 是少数不下钻的方法，直接读 Warning 复制出的 kind。`Inner` 形态的载荷是私有 `InnerNode`，除真实 `children` 外缓存了 `len` / `descendants` / `diagnosis` / `upper` 四个字段，使 `len()`、`diagnosis()` 能 O(1) 回答，并支撑增量重解析的差量更新（`update_parent` / `replace_children`），是 U9 的基础。
