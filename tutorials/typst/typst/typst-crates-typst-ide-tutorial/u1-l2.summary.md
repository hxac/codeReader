本讲剖析 typst-ide 的统一数据契约 `IdeWorld`。核心动机是「解析 vs 枚举」之别：编译器只需要 `World` 按 id 取单个资源（七个被 comemo track 的方法：`library/book/main/source/file/font/today`），而 IDE 还需枚举全部候选，故 typst-ide 在 `World` 之上定义子 trait `IdeWorld: World`，使编译器实现者免受 IDE 数据牵累。`IdeWorld` 三个方法中 `upcast` 必填，`packages`/`files` 可选且带空默认实现。引入的关键概念包括：supertrait 与 `&dyn IdeWorld` 统一收参、comemo 的 `track`、以及「trait 向上转型」。`upcast` 之所以必填，源于设计时 Rust trait upcasting 尚不稳定（跟踪 issue rust-lang#65991，后于 1.86 稳定），内部 `with_engine`、`analyze_expr` 必须拿到确切 `&dyn World`，实现体一行 `self` 即可。`packages()` 仅被 `package_completions` 消费、`files()` 仅被 `file_completions` 消费，二者缺失只让包名/路径补全为空，悬停、跳转、字体补全（依赖必填的 `World::book()`）等其余功能完全不受影响——即「可选增强 + 优雅降级」。
