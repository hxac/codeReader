本讲只精读 typst-ide 的悬停提示公共入口 `tooltip` 及其分发骨架，不展开各分支内部。核心结论有三：其一，入口先用 `LinkedNode::new(source.root()).leaf_at(cursor, side)?` 定位光标叶子，再 `if leaf.kind().is_trivia() { return None; }` 显式跳过空白/注释，避免把无语义节点归到相邻表达式。其二，六个分支用 `Option::or_else` 串成短路分发链：`named_param → font → label → import → expr → closure`，首个 `Some` 即返回。其顺序遵循「最具体/最便宜在前，最通用/最昂贵在后」——前四个靠查表/遍历，`expr` 要靠 `analyze_expr` 重新求值整篇文档（u2-l4），故排在倒数第二；`label_tooltip(output?, &leaf)` 中的 `output?` 则实现「有编译产物则增强、无则降级」。其三，返回类型 `Tooltip` 只有 `Text`（散文/文档/列表）与 `Code`（值的代码表示/单位换算）两类，供 LSP 客户端分别渲染。本讲引入的关键术语：短路分发链、`or_else` 惰性短路、trivia 显式过滤、`Side::Before`/`Side::After` 在 token 交界点的不同选中规则（同一光标可得不同提示）。各分支内部实现留待 u3-l3（expr_tooltip）与 u3-l4（font/label/import/closure）承接。
