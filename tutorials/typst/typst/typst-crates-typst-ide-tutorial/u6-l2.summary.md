本讲聚焦 typst-ide 的「字段访问补全」，核心模块是 `complete.rs` 中的 `complete_field_accesses`（位于补充分发链最顶端、最优先的第一关）与 `field_access_completions`，并依赖 `analyze.rs` 的 `analyze_expr`。`complete_field_accesses` 识别两类互斥触发形态：形态 A `expr.`（光标在点号上）与形态 B `expr.id|`（光标在半成品标识符上），需区分真正的 `Dot` token 与 markup/math 模式下被解析为 `Text`/`MathText` 的「文本点号」，并通过守卫链排除正文句号误触发。两类形态都把 `analyze_expr` 作用于「对象表达式」（点号左边的 `prev`/`prev_prev`）取一个代表性运行时值。拿到值后，`field_access_completions` 按五大来源生成候选：① 类型/元素作用域里首参名为 `self` 的方法（`call_completion` 带括号）；② `value.scope()` 中模块/类型/函数的全部成员；③ `fields_on` 列出的类型预定义字段；④ `match value` 分派出的符号修饰符、Content 字段、Dict 键、Args 具名项（后两者用 `value_completion` 不带括号）；⑤ 元素函数的 get 规则，唯一依赖 `analyze_expr` 返回的 `Styles`，无样式则优雅降级。关键术语包括：对象/目标表达式、`value.ty()`、`value.scope()`、`self` 方法过滤、`fields_on`、文本点号。
