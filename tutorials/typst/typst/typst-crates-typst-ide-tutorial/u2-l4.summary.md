本讲聚焦 typst-ide 的 analyze.rs 与 utils.rs，讲解如何推断表达式「可能取到的值」。贯穿认知是：同一 span 可被多次求值，返回类型为 EcoVec<(Value, Option<Styles>)>。五个最小模块：① with_engine 借一个复用 world 库、配空 EmptyIntrospector/Traced/Sink 的临时 Engine 跑闭包，供需要真正求值的功能复用；② analyze_expr 是值推断主入口，字面量直接构造 Value（轻、Styles 恒为 None），复杂表达式回退到 typst::trace——用 Traced::new(span) 标记目标 span 后把整篇文档重新求值一遍，求值器命中时把值连同活动样式存入 Sink，因此能拿到 set/context 之后的真实运行时值；③ analyze_expr_with_fallback 在 analyze_expr 落空（死代码）时回退到标准库 globals，仅处理裸 Ident 与单层 FieldAccess；④ analyze_import 先推断 import 源，已是模块则直接返回，否则在临时引擎上执行 typst_eval::import 得到 Value::Module（靠 source_span 解析相对路径，失败静默为 None）；⑤ analyze_labels 返回 (labels, split)，split 之前为文档元素标签、之后为参考文献键，消费方按 @、<label>、#cite 三种上下文用 skip/take 各取所需。
