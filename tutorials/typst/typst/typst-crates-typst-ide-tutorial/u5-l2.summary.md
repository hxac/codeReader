本讲聚焦补全引擎（src/complete.rs）的「数据模型」薄层，承接 u5-l1 的补全分发管线，打开两个贯穿全流程的对象：单个候选项与可变上下文。

Completion 用四字段描述一条候选：kind（类别标签）、label（菜单显示文本）、apply（选中后写入源码的文本，默认回退 label）、detail（一行说明）。label 管「看」、apply 管「做」，二者分离；apply 采用 LSP 片段语法 ${} 表达可 Tab 跳转的占位符，与 Typst 自身的 `$` 语法无关。

CompletionKind 是十种取值的枚举：Syntax、Func、Type、Param、Constant、Path、Package、Label、Font、Symbol，其中仅 Symbol 携带字形串；调用方未显式指定时，value_completion_full 按值兜底归类（函数→Func、类型→Type、符号→Symbol、其余→Constant）。

CompletionContext 是分发链共享的可变上下文：new 一次性构造，before/after 由 text 与 cursor 派生，from 初值为 cursor（表示纯插入），各分支往 completions 写入候选并按需前移 from，最终返回 (from, completions)。三个工具方法服务于不同分支——snippet_completion 快捷产出 Syntax 片段，enrich(prefix, suffix) 批量套前后缀且只改 apply（回退 label），seen_casts 用 hash128 给 CastInfo 去重以防递归展开产生重复候选。
