本讲聚焦 `typst-ide` 的 `docs.rs`（约 170 行），它是悬停提示（tooltip）与补全说明（detail）共享的「文档提取」后勤，共拆为五个最小模块。

核心结论：文档的来源本质上有两种，被统一成 `Docs` 枚举——`Docs::Native(&'static str)` 来自 Rust 原生函数 / 类型的编译期常量（零拷贝），`Docs::Comment(EcoString)` 来自用户源码注释（运行时收集）。`Docs` 借助 `Deref<Target=str>` 被「当字符串」使用，下游调用方完全不区分来源，只认 `Option<Docs>` 与 `.summary()`。

引入的关键术语与概念（供后续讲义承接）：①`find_value_docs` 的两级回退——先 `value.docs()`（仅原生 `Value::Func`/`Value::Type` 命中），再对「父=Closure、祖父=LetBinding」的用户闭包回源码抠注释；②`find_param_docs` 按 `ParamInfo` 三变体分发——`Native` 取常量、`Closure` 从参数节点本身往前收集、`Plugin` 返回 `None`；③`collect_doc_comment` 沿 `prev_sibling_with_trivia` 向左遍历，`Space`/`Hash` 是不打断注释链的「胶水」，撞到别的代码节点即停，并通过两步 `strip_prefix` 把 `///` 与 `//` 归一化；④`summary` 用字符级状态机抽取「第一段第一句」纯文本，丢弃 `*`/`_` 强调、保留反引号代码、链接退化为 label，并用 `scout(-3)!='.'` 防止 `e.g.` 等缩写误断句。

整个模块是 best-effort / pragmatic 的：`///` 三斜杠只是生态约定，typst 语言层面并未标准化 doc 注释格式。后续讲义将进入消费方 tooltip 与 complete。
