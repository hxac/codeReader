本讲精读 `typst-ide` 补全引擎 `src/complete.rs` 中两条「特定场景」补全链路：`complete_rules` 与 `complete_params`，它们在分发链中排在通用模式补全之前。

`complete_rules` 通过「光标前一个叶子」识别三个互斥触发点，且仅在 trivia 上触发以防误触：`set` 后用 `func.params().any(|p| p.settable())` 只补「带可设置参数」的函数；`show` 后用 `to_element().is_some()` 只补「元素函数」并用 `enrich("", ": ")` 自动补冒号；`show 选择器:` 后补 recipe 片段与任意函数。

`complete_params` 先向上定位参数列表、callee 及是否 SetRule，再用 `deciding` 节点向左回溯到 `(` / `)` / `,` / `:` 之一分派：冒号→补参数值；左括号或逗号（逗号需非紧贴或 explicit）→补参数名；右括号→不补。其下游 `param_completions` 用计数器去重位置参数、用集合去重具名参数，并在 set 下跳过不可设置参数；`named_param_value_completions` 把冒号后交给 `param_value_completions`，按参数名（font/path/figure body 特化）或类型（`cast_completions`）产出值候选。

关键术语：可设置参数（settable）、元素函数（to_element）、deciding 节点、recipe、位置/具名参数去重，类型驱动补全（cast_completions，详见 u6-l4）。
