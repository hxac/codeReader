本讲建立 typst-cli 在 Typst 工作区中的全局认知：它是产出 `typst` 命令行的**二进制 crate**，区别于纯逻辑的编译器核心 `typst`。引入的关键分层是「核心 + 薄壳 CLI」——核心是「大脑」，CLI 是「组装车间」，依赖方向为 CLI 单向依赖核心，二者通过 `World` trait 沟通；同核心可被命令行、Web 编辑器、语言服务器复用。工作区 `default-members` 指向 typst-cli，故仓库根直接 `cargo build` 即可。关键术语包括 Cargo workspace、crate、feature 开关、clap 派生宏。典型文件层面：`Cargo.toml` 的 `[[bin]] name="typst"` 决定产物名，`default = ["embedded-fonts","http-server"]` 控制默认能力，`self-update` 按需拉入 `self-replace`/`zip`/`xz2`；`main.rs` 顶部声明全部子模块，`dispatch()` 是 9 个子命令到处理函数的映射表，`main()` 负责 SIGPIPE 重置、错误与提示打印、退出码管理，无参运行触发 `greet` 欢迎信息。默认 feature 下 `query`（弃用）与 `update`（未启用）被隐藏。
