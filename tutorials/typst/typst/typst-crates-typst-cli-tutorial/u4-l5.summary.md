本讲剖析 typst-cli 中「同一份命令行定义如何同时服务于构建期与运行时」的机制。核心围绕四个最小模块展开。第一，`src/args.rs` 是共享根基：它被运行时二进制（常规模块声明）和构建脚本 `build.rs`（通过 `#[path = "src/args.rs"]`）双重导入，物理一份、编译两次；由此带来硬性约束——`args.rs` 只能引用同时存在于 `[dependencies]` 与 `[build-dependencies]` 的 crate（如 `clap`、`clap_complete`），而仅构建依赖的 `clap_mangen` 与仅运行时依赖的 `typst` 均不可入内。第二，`build.rs` 受环境变量 `GEN_ARTIFACTS` 门控，设置后用 `clap_mangen` 生成主命令及各子命令 man 页（`typst.1`、`typst-compile.1` 等）、用 `clap_complete::generate_to` 生成全 shell 补全，面向发行版打包者。第三，`build.rs` 与 Cargo 立两条契约：`cargo:rustc-env=TARGET` 把目标三元组焊进二进制（供 `update.rs` 的 `env!("TARGET")` 读取），`cargo:rerun-if-env-changed=GEN_ARTIFACTS` 保证环境变量变化时重跑。第四，运行时 `typst completions <shell>` 用 `clap_complete::generate` 把单一 shell 补全打到 stdout，与构建期同源但不产 man 页。两类产物一致的根本原因是都复用 `CliArguments::command()` 这一单一真相源。
