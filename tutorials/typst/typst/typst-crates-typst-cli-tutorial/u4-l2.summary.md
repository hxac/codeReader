本讲讲解 Typst CLI 中已弃用的 `typst query` 子命令（定义于 `src/query.rs`，在 `args.rs` 中以 `#[command(hide = true)]` 隐藏但仍可运行）。它整体走「编译文档取内省器 → `retrieve` 检索 → `format` 序列化打印」三段流程：弃用警告在进入成功/失败分支前无条件注入，故永远出现，且结果走 stdout、警告走 stderr。`retrieve` 用 `eval_string`（`SpanMode::Uniform(Span::detached())`）把命令行选择器字符串求值成 `LocatableSelector`，再用编译产物的真实 `introspector.query`（带哈希缓存）完成检索；求值时传 `EmptyIntrospector`。`format` 按 `--one`（断言恰一个）与 `--field`（`get_by_name` 取字段、取不到静默丢弃）处理，经共享的 `crate::serialize` 输出 JSON/YAML。核心亮点是 `deprecation_warning`：按 `(one, field)` 四种组合在 `query(selector)` 后追加 `.map()` / `.first()` / `.at()` 后缀，经 `shell_escape` 包成等价 `typst eval "..." --in <path>` 迁移命令。关键结论：`query` 是 `eval` 的真子集，二者共享 `eval_string` 骨架，但 `eval` 用 `Mapped` span 提供更精准诊断；迁移提示是「最佳努力」——匹配多个元素时 `--one` 报错而 `.first()` 静默返回第一个，二者不完全等价。关键术语：内省器（introspector）、选择器/LocatableSelector、可定位元素、`eval_string`、SpanMode。
