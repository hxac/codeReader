本讲聚焦 typst-cli 的通用下载基础设施（`download.rs`），它只是一个「薄适配器」。核心是工厂函数 `downloader()`：它读取命令行/环境变量 `--cert` / `TYPST_CERT`，装配出带 TLS 证书与 `typst/<版本>` user-agent 的 `SystemDownloader`（证书惰性加载，404 被翻译成 `NotFound`），再用 `ProgressDownloader` 装饰器包一层，返回 `impl Downloader`。真正的 HTTP/TLS（ureq + native_tls）与分块采样逻辑住在 typst-kit，CLI 只负责「配置接入」与「终端渲染」。

关键术语：`Downloader` trait、`ProgressDownloader`（装饰器）、`ProgressReporter`（`start`/`update`/`finish` 回调）、`ProgressReader`（8 KiB 分块、100ms 周期、容量 25 的滚动窗口算平滑速度）。每次下载带一个 `&dyn Any` 的 key，CLI 用 `key → 名称` 闭包决定是否显示进度：`PackageSpec` 与恰好为 `"release"` 的 key 显示，`"package index"` / `"release information"` 静默——大体积下载才打扰用户。

CLI 的 `PrintProgress` 实现 `ProgressReporter`，靠 `terminal::out()` 的 `clear_last_line`（ANSI `\x1B[1F\x1B[0J`）实现单行刷新，与诊断、watch 共用同一条 stderr singleton；非 TTY 下 `clear_last_line` 退化为 no-op，进度自动变成逐行追加。同一 `downloader()` 被包下载（`packages::system` → `UniversePackages`）与自更新（`update` → `Release`）两场景复用。
