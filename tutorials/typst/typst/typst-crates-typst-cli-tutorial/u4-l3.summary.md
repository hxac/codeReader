本讲承接多格式导出，彻底展开 `compile_and_export` 中区别于 PDF/PNG/SVG 的两条分支，并讲解 watch 模式内置的 HTTP 服务器。

核心结论有四点：其一，`OutputFormat::Html` 走独立目标类型 `HtmlDocument`，经 `export_html` 序列化为 HTML 字符串写盘，watch 模式下额外调用 `server.set_html`。其二，`OutputFormat::Bundle` 是唯一的多文件目标，编译出 `Bundle`（文件清单，含 `BundleFile` 的 Document 与 Asset 两种），经 `typst_bundle::export` 渲染成 `VirtualFs`（路径→字节映射），再由 `write_virtual_fs` 用 rayon 并行铺成磁盘目录树；输出到 stdout 会被显式拒绝。其三，`BundleOptions` 因编译期无法预知每个文件格式，需一次性打包 html/pdf/png/svg 四套选项，其 helper 也被对应单格式导出复用。其四，HTTP 服务器仅在 `typst watch` 且格式为 Html/Bundle 且未 `--no-serve` 时创建，端口默认在 3000–3005 选取，由 `ServerArgs`（`--no-serve`/`--no-reload`/`--port`）控制；它在独立线程跑请求循环，主线程通过 `Bucket`（`Mutex`+`Condvar`）喂数据。live reload 依赖 Server-Sent Events：服务器返回 HTML 时动态注入 `EventSource("/__events")` 脚本，重编译后推送 `reload` 事件触发 `location.reload()`，仅作用于 HTML 文件，`--no-reload` 关闭注入但不影响落盘。`--open` 在此场景下打开网址而非文件路径。
