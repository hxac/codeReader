本讲剖析 `typst-cli/src/eval.rs`，讲清 `typst eval` 命令的「先编译文档、再求值表达式」两段式流程：编译的真正目的是借用产物里的 introspector（文档内省器），让表达式里的 `query()` 等上下文函数有数据可查；三种 Target（Paged/Html/Bundle）的产物被擦除成 `Box<dyn Output>`，统一通过 `Output::introspector()` 取出内省器。关键概念包括：`ExpressionWorld`——一个装饰器模式的 World 包装器，虚构 `<input-expression>` 文件（`EXPRESSION_ID`），只在 `name` 与 `file` 两处拦截，使命令行表达式能获得精确行列诊断；`evaluate_expression` 借核心库 `typst_eval::eval_string`，用 `SpanMode::Mapped` + `RangeMapper` 把字符一一映射到虚拟文件，配 `SyntaxMode::Code` 按代码模式解析、`Scope::default()` 不注入局部变量、`Context` 带库默认样式；结果经公共 `crate::serialize` 序列化成 JSON/YAML 打印，失败走软失败 `set_failed()`，编译与求值警告合并后由 `print_diagnostics` 输出。eval 与已弃用的 query 共享同一套 `eval_string` + 编译取内省器结构，但 eval 用更精细的 Mapped span，是 query 的超集替代品。
