本讲围绕 `compile.rs` 讲清「把命令行参数变成一次真正编译」的主干。核心结构 `CompileConfig` 在编译前一次性构造，把松散的 `CompileArgs` 翻译成已校验、可直接消费的「施工图」；`new`（compile）与 `watching`（watch）共享同一份 `new_impl`，靠第二参数区分是否 watch，仅 watch 路径会构造 HTTP 服务器。`new_impl` 完成三件事：输出格式推断（优先级 `--format` > 输出扩展名 > 默认 PDF）、输出路径推导（`--output` > 输入换扩展名）、以及 `tagged`/`--pages`/PDF 标准的约束校验——`--pages` 隐含 `--no-pdf-tags` 并产生静态警告，带 `a`/`UA` 的无障碍标准强制要求标签，冲突时按原因给出带或不带 hint 的 `bail!`。`compile_once` 是软失败心脏：编译失败仍返回 `Ok(())`，靠 `set_failed()` 改退出码，串联「状态显示→编译导出→合并静态警告→打印诊断→写依赖」，用 `Span::detached()` 把命令行警告并入源码警告走同一管道，并被 `#[typst_macros::time]` 与 `Timer::record` 包裹，仅 `--timings` 时真正计时。PDF 标准走三段链路：命令行字符串 → CLI `PdfStandard`（clap）→ 核心库 `typst_pdf::PdfStandard`（`From` 转换）→ `PdfStandards`（构造与兼容性校验）→ `PdfOptions.standards`，CLI 只做忠实搬运与类型映射。`compile_and_export` 按 `output_format` 分发到 `PagedDocument`/`HtmlDocument`/`Bundle`，多格式导出细节留给 u2-l3。
