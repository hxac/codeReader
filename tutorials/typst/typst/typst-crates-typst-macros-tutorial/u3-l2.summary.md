本讲承接 u3-l1 的解析，进入 `#[func]` 的「生成」阶段，核心全部集中在 `src/func.rs`。关键结论：过程宏不执行而是**包装**函数——`create` 输出「改写后的原函数 + 影子类型（可选）+ creator」三件套。creator 二选一由**是否有 parent** 决定：无 parent 时生成同名空 `enum` 并 `impl NativeFunc`，有 parent（位于 `#[scope]` impl 块内，该块禁止定义新类型）时退而生成 `#[doc(hidden)] fn {ident}_data()`，供 u3-l3 的 `#[scope]` 调用注册。`create_func_data` 用局部 `static DATA` 满足 `&'static`，`scope/params/returns` 借 `LazyLock` 延迟求值以规避类型初始化顺序问题。**包装闭包**适配「固定运行时签名 ↔ 多变用户签名」：`create_param_parser` 按优先级矩阵 `args.all/named/eat/expect` 取值并按 `#[default]` 兜底；`args.take().finish()?` 仅当函数未声明 `args` 参数时插入以报多余参数；engine/context/args/span 用 `.then(...)` 按声明与否转发。`create_param_info` 在生成阶段派生 `positional=!named`、`required=!named&&default.is_none()`，按需以 `Container::Inner` 解包 `Vec/Option`，且 `settable` 恒为 `false`（函数与元素的分界，对比 u4）。逐级拼接的 `def_site_key` 配合 `file!()` 支撑 IDE 跳转。本讲完成 `#[func]` 解析→生成闭环，为 u3-l3 `#[scope]` 提供注册件。
