本讲是 `#[elem]` 系列第一讲，只覆盖「解析」阶段：把 `#[elem(..)]` 元数据与被装饰的 struct 字段整理成 `Elem`、`Field` 两个中间结构（代码生成留给 u4-l2~u4-l4）。核心概念有三。其一，`parse_field` 的优先级推导链 `variadic ⇒ required ⇒ positional`：variadic 字段自动也是 required、positional，固定了字段取参的优先级。其二，两类互斥校验——`required ∩ synthesized = ∅`，以及 `(required ∪ synthesized) ∩ (default ∪ fold ∪ ghost) = ∅`；元素级还禁止「公有 ghost 字段 + 无 Construct 能力」的组合。其三，`Elem` 上五个嵌套字段过滤器（`real ⊃ struct ⊃ accessor`，`construct ⊃ set`）决定每个字段流向哪部分生成代码：`external` 仅进文档/vtable，`ghost` 不进 struct。此外，字段经 `sort_by_key(internal)` 排序后分配索引 `i`（非 internal 在前），作为后续 const generic 与 vtable 槽位的底层编号；util.rs 的 `BlockWithReturn` 将 `#[parse({ stmt; expr })]` 切成 `prefix`+`expr`，为「自定义字段解析覆盖默认取参」提供基础。本讲产出的 `Elem`/`Field` 模型是后三讲生成的输入。
