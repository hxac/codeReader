本讲聚焦 `layout_pages` 的第一步 **collect**：一个纯切片函数，把 realize 产出的扁平 `Vec<Pair>` 切成三类指令 `Item`——`Run`（唯一可并行排版的连续内容）、`Tags`（只剩隐形标签、需暂存的碎片）、`Parity`（奇偶补页指令）。其中仅 `Run` 进入 `parallelize`，`Tags` 与 `Parity` 依赖串行全局状态（已暂存标签、已排出页数）在 `layout_pages` 循环中消费。

核心布尔状态机 `staged_empty_page`：strong pagebreak 仅「预约」一张空页，真实内容「占用」之，循环末尾「刷出」，避免连续换页产生多余空页。`PagebreakElem` 三态——strong（强制换页并预约空页）、weak（当前页空则跳过）、boundary（scope 边界保底换页，连样式都不强加）。`Parity`（`to: "odd"/"even"`）在 collect 阶段无条件记录，延后到 `layout_pages` 用 `parity.matches(pages.len())` 判断是否补空页，因为补页依赖物理页号。`migrate_unterminated_tags` 用稳定排序把分页符前「未终止的 start tag」迁到分页符之后，修正 `show heading: it => pagebreak() + it` 这类规则的页号归属；纯标签碎片则记为 `Item::Tags` 暂存，避免无端成页。
