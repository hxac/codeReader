本讲收尾「页面与文档布局」单元，讲解 `PagedIntrospector` 如何从已排好的 `&[Page]` 派生出一份支持高效查询的内省索引。核心结论：索引是排版产物的纯派生物，构造只读每页的 `frame`/`numbering`/`supplement`，不读源码、不依赖引擎。

关键流程是 `discover_frame` 深度优先扫描帧树，把 tag 收集成 Start/End 事件，并累积坐标变换把局部点换算成 `PagedPosition`（其中页号为物理页号，区别于逻辑页号）。对带 `parent` 的 `Group`（如脚注内容），`start_insertion`/`end_insertion` 将其 tag 分流暂存到 `insertions[parent.location]`，在 `finalize` 的 `visit` 里紧贴父元素 Start 之后整体展开，使父元素的 `locations` 区间完整覆盖所有后代，从而修正跨帧元素的逻辑顺序。

`PagedIntrospector` 把绝大多数查询转发给与目标无关的泛型引擎 `ElementIntrospector<PagedPosition>`，后者靠 `elems`/`locations`/`labels`/`keys` 四张加速表加 `QueryCache` 支撑 `query`/`Before`/`Within` 等；有序查询依赖按 `elem_index` 的二分查找。最后，`PagedDocument` 以 `Arc` 共享索引且刻意不参与 `Hash`，因为它是 pages 的派生物，这是 comemo 记忆化缓存正确与高效的前提。
