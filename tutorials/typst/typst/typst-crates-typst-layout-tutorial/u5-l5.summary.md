本讲是 inline 行内段落管线（collect→prepare→linebreak→finalize）的收尾篇，覆盖 line.rs、deco.rs、finalize.rs 三模块。核心结论：`line()` 把字节区间装配成只含测量信息的便宜 `Line`（字段 items/width/justify/dash），真正的建帧推迟到昂贵的 `commit`，二者分离使断行算法可反复廉价测量。`Line` 借 `LogicalIndex`（行首连字符 0、普通 item i+1、行尾连字符 MAX）记录逻辑顺序，提交时按其排序恢复源码顺序，保证内省与计数器按逻辑而非视觉顺序工作。`commit` 处理悬挂缩进、标点悬挂 overhang、两端对齐两步分配（justification_ratio 与 extra_justification）、基线对齐，并手工挂载 introspectable:false 的 `ParLineMarker` tag 供行号检索。`decorate` 区分高亮（背景矩形）与线型装饰，下划线的 evade 求装饰线与字形 Bezier 轮廓交点切段以绕开降部，删除线则强制连续。`finalize` 极短，只决定段落宽度（含 Fr 分数间距须撑满 region.x，否则收缩到最宽行）并逐行 commit 堆成 Fragment；inline 只吃单个 Size，跨区域断裂属 flow 职责。
