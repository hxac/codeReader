本讲聚焦 `typst-layout` 与 `typst-library` 间的粘合函数 `register`，回答「原生 show 规则如何被挂载、挂在哪、长什么样」，不展开单条复杂规则的实现。

围绕四个最小模块展开：`Target`（编译目标）让 `Target::Paged` 成为分页排版的默认目标，并作为 show rule 的第二维索引，使同一元素在不同产物下有不同展示；`ShowFn<T> = fn(&Packed<T>, &mut Engine, StyleChain) -> SourceResult<Content>` 是所有原生 show rule 的统一签名，因其是裸函数指针，故每条 `*_RULE` 都是不捕获环境的 `const` 闭包；`NativeRuleMap` 是以 `(Element, Target)` 为键的规则注册表，`register` 方法对重复注册 panic（启动期 fail-fast），与目标无关的通用规则由 typst-library 在 `new()` 预装，与排版强相关者才交 typst-layout；`register` 按 Model/Text/Layout/Visualize/Math/PDF 六类共注册 59 条规则，分「纯样式变更型」（如 `STRONG_RULE`/`EMPH_RULE` 只改 `TextElem` 样式、不碰几何）与「挂 layouter 型」（经 `BlockElem::multi_layouter`/`single_layouter` 接入 typst-layout 未导出的排版器）。关键结论：show rule 负责语义→样式翻译，layout 负责样式→几何；实际注册发生在顶层 `typst` crate 的 `ROUTINES` 懒加载静态量里，随 Library 构建执行一次后表即只读。后续讲义将承接 `HEADING_RULE`/`FIGURE_RULE` 等单条规则的实现细节。
