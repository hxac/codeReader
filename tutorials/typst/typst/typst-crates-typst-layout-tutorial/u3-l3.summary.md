`layout_page_run` 是 `layout_pages` 三段式（collect → 并行排版 → finalize）中**可并行**的那一步：每个 `Item::Run`（两次分页符间的连续正文）由 `engine.parallelize` 分配一个独立任务，返回「半成品」`Vec<LayoutedPage>`，而 `Tags`/`Parity` 因依赖串行全局状态被过滤。它沿用「公开薄封装 + memoize 的 `_impl`」模式，内部重建局部 `Engine`、`Locator`，并累加 `Route` 排版深度。

核心流程分四步：解析 `PageElem` 各字段、用 `layout_flow(FlowMode::Root)` 排正文、用 `layout_marginal` 闭包（内部调 `crate::layout_frame`）排各 marginal、组装 `LayoutedPage`。引入的关键概念：`width/height` 为 `Auto` 时 fallback 到无穷大以贴合内容；默认边距公式 `2.5/21 × min(width,height)`（A4 ≈ 25mm）；`bleed`（出血）默认 0；`two_sided` 标记是否按 inside/outside 解释左右边距。

页码归属规则：`number_align.y == Top` 进 header，`Bottom`（默认）进 footer，但用户显式的 header/footer 优先；`number_align` 的 X 控制水平对齐、Y 控制归属。`header_ascent`/`footer_descent`（默认各 30%）从边距中减去对应比例以缩小页眉页脚可用高度；background/foreground 用含 margin+bleed 的整页尺寸，header/footer 用正文宽×缩减边距。

关键结论：`LayoutedPage` 把 margin/bleed 的「值 + two_sided 标记」一并暂存，因为依赖物理页号的左右互换在并行阶段无法完成，必须推迟到串行 `finalize`（u3-l4）由 `binding.swap(counter.physical())` 处理，以此保住并行独立性。
