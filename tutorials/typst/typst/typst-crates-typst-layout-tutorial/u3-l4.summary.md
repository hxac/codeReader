本讲讲解 `layout_pages` 三段式（collect → parallelize → finalize）的最后一环——`finalize`：把并行排出的半成品 `LayoutedPage` 串行总装为最终 `Page`。它必须发生在并行之后且串行执行，因为边距互换和显示页码都依赖跨页递增的全局状态。围绕三个模块展开：一是 `finalize` 的组装流程；二是 `Binding` 装订方向判定，由 `binding.swap(counter.physical())` 决定是否互换左右边距与出血——左装订在偶数页互换、右装订在奇数页互换，且仅当该侧 `two_sided` 为真时生效；三是 `ManualPageCounter` 的双轨页号：物理页号反映「第几张纸」、不可改写，逻辑页号可被 `counter(page)` 改写。关键结论：页面按 `background → header → inner → footer → foreground` 固定顺序拼装，该顺序决定 `counter.visit` 与内省解析顺序；整页 frame 尺寸为正文加边距、不含 bleed；`Page.number` 存逻辑页号，边距互换用物理页号，两者仅在出现 `counter(page)` 更新时才偏离。
