本讲把上一讲的 IP 头封装/解封装子模块拼成完整 IPv4 核心模块 `ip`（8 位）与 `ip_64`（64 位）。`ip` 顶层是**布线层**：RX 直接透传 `ip_eth_rx`（被动、无状态机），TX 在 `ip_eth_tx` 前加一段三状态机 IDLE→ARP_QUERY→WAIT_PACKET。TX 侧由顶层填死以太网类型 `0x0800`、IP 标识 `0`、分片标志 DF=1、源 MAC（`local_mac`），应用只提供业务字段。发送前必须查 ARP，`arp_request_ip` 恒等于当前包目的 IP；命中则锁存 MAC 启动发包，失败走丢包分支——用 `drop_packet_reg` 拉高 tready 读空整帧载荷（吞包而非反压），经 `tx_error_arp_failed` 上报，`ip` 自身不超时，依赖 ARP 层 error 解锁。`ip_64` 仅把数据加宽并引入 `tkeep`，控制逻辑与 `ip` 逐行相同。该 ARP 请求/应答接口与 `arp` 模块对偶，将在 u7-l3 的 `ip_complete` 中对接真实 ARP 实例。
