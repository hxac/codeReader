本讲是 cocotb 仿真平台架构（u13-l1）的动手篇，以 `eth_mac_1g` 为范本，讲解如何为新 RTL 模块搭建现代 testbench，分三块：其一，**Makefile 三件事**——用 `VERILOG_SOURCES` 手工列全 RTL 依赖（iverilog 不自动找子模块），用 `TOPLEVEL`/`MODULE` 指定顶层与 Python 模块，用 `PARAM_` 前缀经 `-P` 开关注入参数，派生参数在 Make 内用函数算；其二，**DUT 例化**——现代流程把 DUT 自身设为 `TOPLEVEL`，cocotb 经 VPI 直接驱动端口，无需 `.v` 封装，仅当需要胶水逻辑、多 DUT 级联或观测内部信号时才写传统封装（输入 `reg` 带初值、输出 `wire`、命名端口连接）；其三，**Python 双用途测试文件**——`TB` 类封装时钟/端点/复位，`run_test_*` 协程走「发送—接收—断言」范式，`TestFactory` 做笛卡尔积铺开覆盖率，`test_*` 配 `cocotb_test.simulator.run` 作与 Makefile 镜像的 pytest 入口。关键约定：`AxiStreamBus.from_prefix(dut,"s_axis")` 一行接好 AXI；端点库 `check_fcs()` 与 `zlib.crc32` 一致；断言须用 `output_fcs_valid` 等状态信号对齐采样点而非固定延时。根目录 `test_*.v`/`test_*.py` 为 myhdl 历史遗留，已被 `tox.ini` 排除。
