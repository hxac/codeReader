本讲精读 `arp_cache` 与顶层 `arp` 两个模块，并把 `arp_eth_rx/tx` 当黑盒。`arp_cache` 是一张**直接映射哈希表**：索引取 `CRC32(IP)` 的低 `CACHE_ADDR_WIDTH` 位（默认 9，即 512 槽），每个槽存有效位、全 32 位 IP 与 MAC；命中条件是「有效且 IP 相等」，否则报 `error=1`。替换策略是无条件覆写，**非 LRU**，靠存全 IP 判别冲突，代价是冲突 IP 会互相踢出（thrashing）。查询与写入均为 2 拍流水线，`clear_cache` 自增扫表、清空期间暂停服务。顶层 `arp` 是布线层加一段组合状态机，对外提供 `arp_request(IP)→arp_response(MAC/error)` 接口，做四件事：**被动学习**（任何合法帧的发送方地址入缓存）、**被动应答**、**子网/网关判断**（跨网段改查 `gateway_ip`）、**未命中自动解析**。自动解析即广播 ARP 请求并按 `REQUEST_RETRY_COUNT` 重试、`REQUEST_RETRY_INTERVAL` 间隔，最后一次后等 `REQUEST_TIMEOUT` 仍无应答则报错；解析态每拍重查缓存，应答经被动学习写入后立即命中结束。下一讲 `arp` 的接口将被 IPv4 层直接调用。
