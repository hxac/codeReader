`eth_mac_10g` 是 10G/25G MAC 的**布线层**，自身几乎不含时序逻辑，靠两段 `generate` 拼装：按 `DATA_WIDTH`（32/64）选 `axis_xgmii_rx/tx_64`，按 `PAUSE_ENABLE||PFC_ENABLE` 选配 `mac_ctrl_*`/`mac_pause_ctrl_*`，关闭则零面积直连。它与千兆 `eth_mac_1g` 的本质差异在数据通路宽度——从 8 位/拍升到 64 位/拍，由此引入 `tkeep` 标记末字有效字节、XGMII 用 `START`/`TERM` 控制字符在一拍内定界帧、8 个并行 CRC 引擎应对变宽末拍。

本讲核心是**缺陷填充（Deficiency Idle Count, DIC）**：IEEE 802.3 要求相邻帧间至少 12 字节帧间间隔（IFG），但 8 字节/拍的 XGMII 无法用整数拍表达 12。`ENABLE_DIC=1` 时，TX 翻译器维护 2 位跨帧亏空计数 `deficit_idle_count`（0–3），配合 lane swap（把下一帧 `START` 放到 lane 4，让 lane 0–3 充当 IFG 尾巴），使单帧 IFG 不低于下限、多帧平均 IFG 恰好等于配置值；`ENABLE_DIC=0` 则每帧独立向上取整到 4 字节边界，简单但浪费带宽。IFG 需求公式 `max(cfg_ifg,12) - ifg_offset + (swap?4:0) + deficit` 四项分别对应基准、FCS 收尾拍已贡献的 IDLE、lane swap 偏移与累计亏空。

PTP/PFC/PAUSE 接口与千兆 MAC 同源：RX 时间戳在 `START` 处锁存并随帧尾塞进 `tuser`，TX 时间戳因发送已结束而走旁带总线回送，lane swap 时均做半拍补偿 `ts_inc_reg>>1`；PFC 量子步长按位宽换算为 `cfg_quanta_step=(DATA_WIDTH*256)/512`（64 位时为 32）。仿真 `run_test_tx_alignment` 提供了 DIC 的权威 Python 参考模型。
