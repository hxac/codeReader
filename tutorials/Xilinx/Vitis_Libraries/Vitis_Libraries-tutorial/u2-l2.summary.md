本讲以 utils 库下 stream_dup 为例，带读者跑通第一个 L1 HLS 用例，确立「目录即用例」的约定：每个 L1 用例是独立可 make 的目录，标准文件为 test.cpp、Makefile、description.json，外加 hls_config.tmpl 与 run_hls.tcl。核心命令 make run TARGET=csim 经 Makefile 翻译为 vitis-run --mode hls；csim 是五档大写 TARGET（csim/csynth/cosim/vivado_syn/vivado_impl）中最轻量的纯软件仿真，不做综合。关键术语：DUT（extern "C" 顶层函数，会被综合）、testbench（以 #ifndef __SYNTHESIS__ 包裹，仅仿真运行）、hls::stream 与 end 标志流；test.cpp 一人分饰两角，main 依 argv[1] 选测试，csim 固定传 "0"。description.json 是用例的元数据身份证，向工具链/CI 声明 flow、平台白名单、顶层函数、时钟与各阶段资源限额。核心教训：改参数前先读源码——test_dut0 黄金参考生成处硬编码字面量 16、核对处却用 NUM_COPY，故把 NUM_COPY 改为 8 会造成比对错位与数组越界，结果 FAIL。
