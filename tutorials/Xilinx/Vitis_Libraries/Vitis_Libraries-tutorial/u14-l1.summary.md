本讲义把视角从「单个加速内核」抬升到「整个仓库如何被机器自动测试」，覆盖四个最小模块。一是 `description.json` 元数据：它是每个用例目录的机器可读身份证，核心字段 `flow`（hls/aie/system）决定走哪条流水线，`platform_allowlist`、`topfunction`、`clock`、`testbench.argv` 描述身份，`testinfo.targets`、`jobs`（max_memory_MB/max_time_min）、`category`（canary 全量/fast smoke 与 full）描述 CI 调度，体现「数据与代码分离」。二是 `hls_config.cfg` 模板生成：`hls_config.tmpl` 用 `${VAR}` 占位符，由 Makefile 内嵌 Python 经 `string.Template(...).substitute(**os.environ)` 渲染，唯一随 TARGET 变化的占位符是 `${VIVADO_FLOW}`（vivado_syn→syn，其余→impl），Makefile 再用 `ifneq` 把五个大写 TARGET 分派给 `v++ -c`/`vitis-run`。三是 blas 的 `run_test.py` 批量驱动：按 profile 参数笛卡尔积并发跑，落 `statistics.rpt` 并用进程退出码（0/1）给 CI 机器可判的契约。四是顶层 `Jenkinsfile` 仅两行（加载 pipeline-library 并调用 `FullVitisLibPipeline`），体现「薄入口 + 厚共享库」架构，复杂性下放到「每用例一份 description.json」加共享流水线库，字段名即作者与 CI 之间的契约。关键术语：flow、档位指纹（`hls_*`/`vitis_aie_*`/`vitis_hw_*`）、canary/full、模板渲染、退出码契约。
