本讲承接单仓库配置视角，解决「在自己机器上把 AMD 工具链跑起来」这一问题，拆为五个最小模块。基线方面：所有库共享同一硬要求——受支持的 RHEL/Ubuntu、C++14、Vitis 2022.2 及以上且版本须与 XRT（Xilinx Runtime，主机端运行时）匹配。环境脚本方面：工具不会自动入 PATH，唯一标准方式是 `source` 两个脚本——`Vitis/settings64.sh`（注入 `XILINX_VITIS`/`XILINX_VIVADO`）与 `xrt/setup.sh`（注入 `XILINX_XRT`），必须用 `source` 而非直接执行，否则变量在子 shell 退出后失效。指定目标硬件有三个变量：`PLATFORM`（平台名/awk 模式/`.xpfm` 全路径，大小写不敏感）、`PLATFORM_REPO_PATHS`（搜索根，冒号分隔）、`XPART`（裸 FPGA part，优先级最高，设置后忽略 `PLATFORM`）；L1 Makefile 的 `check_part` 将其实现为三级兜底搜索——`PLATFORM_REPO_PATHS` → Vitis 安装目录 → `/opt/xilinx/platforms`，再用 `platforminfo` 从 `.xpfm` 反查 part。`platform_map.json` 把 Versal/AIE 逻辑名（如 `vck190`/`vek280`）映射到带版本号的真实平台名，使脚本与平台版本解耦（仅覆盖 AIE 路线，PL 的 Alveo 卡不在此列）。最后用 `v++ --version`、`vivado -version`、`vitis-run --help` 验证工具链，三者均来自 `${XILINX_VITIS}/bin`；Makefile 的 `check_vivado`/`check_vpp` 已内置前两者的存在性检查。旁注：AIE/嵌入式路线还额外需要 aarch64 交叉编译器、`SYSROOT` 与 `aietools`，细节留待后续讲义。L1 HLS 流程的关键标志是 `v++`/`vitis-run` 均带 `--mode hls`。
