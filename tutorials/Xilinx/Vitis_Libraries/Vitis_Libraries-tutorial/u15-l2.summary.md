本讲承接 hw_emu 仿真流程，推进到真正上板的 hw 构建及嵌入式部署全链路。核心结论：hw 与 hw_emu 共用 v++ -c/-l/-p 三段流程，区别仅在 -t 参数；hw 需跑完整 Vivado 综合与布局布线，代价从分钟级跳到数小时级，故 CI 通常只对 canary 用例跑 hw。

嵌入式平台（aarch32/aarch64）必须额外准备 Common Image 三件套——sysroot（交叉编译的目标板头文件与库）、Image（Linux 内核）、rootfs.ext4（根文件系统）。Makefile 靠固定相对布局由单个 SYSROOT 自动派生出 K_IMAGE 与 ROOTFS，缺失即报错；host.elf 须用 aarch64 交叉编译器配 --sysroot 编译并链 -ladf_api_xrt。x86 PCIe Alveo 卡则无需此套，host 用本机 g++ 编译、无 SD 卡。

SD 卡内容为系统镜像＋设计（xclbin/pdi/dtbo）＋应用（host.elf/run_script.sh）＋数据，由 --package.generate_sdcard 从零生成；AIE2PS 平台则手动拷 pdi/dtbo，后者经 sdtgen+lopper+dtc 从 xsa 生成。

关键术语：platform_map.json 把 vck190 等逻辑名映射到带版本号的真实 .xpfm，由 utils.mk 四级 wildcard 加 awk 模糊匹配落地。已知问题：2025.2 起 7 个 PL 库废弃、Alveo U200/U250/U280 不再支持，AIE 库不受影响；各库 Known issues 决定 target 与 URAM 选型。
