本讲讲透 Vitis_Libraries 单体多库仓库的「跨库组合」工程技能。核心是 `dependency.json` 依赖图：它只记录九个库的直接依赖（`lib → dependsOn`），要用某库须手算其**传递依赖闭包**，主干链为 `utils ← data_mover ← dsp ← solver`，闭包即「最小引入集」；blas/vision/motor_control/ultrasound 为无依赖孤岛，可单独引入。关键寻址约定：`library.json` 只声明本库内部路径（`LIB_DIR/...`），跨库路径一律下沉到用例层——`description.json` 用 `LIB_DIR/../<lib>`、Makefile 用 `$(XFLIB_DIR)/../<lib>`，二者语义相同。两条复用链为证：**solver 复用 dsp**（AIE 路线，头件 `fir_utils.hpp` + `xf::dsp::aie` 命名空间 + 测试脚本三重复用，由 `DSP_DIR ?= ../dsp` 接入）；**dsp 复用 data_mover** 达到源码级——把 `mm2s/bmm2s/s2mm` 直接写进 `containers` 编译进系统，是最彻底的组合。易踩坑：solver 自带 `x_matrix_utils.hpp` 为本地副本而非 utils 加速库，同名却不同源。排错直觉：跨库报「找不到头件」几乎总是闭包漏了某库的 `-I` 路径，回到 `dependency.json` 重算闭包即可定位。
