本讲解析 L1 HLS 流程的五个大写 TARGET（csim/csynth/cosim/vivado_syn/vivado_impl）：它们构成保真度与代价逐级递增的阶梯，csim/csynth 属 60 分钟级日常档，后三档属 420 分钟级重型档。csim 只验功能不综合，csynth 是首个产出硬件报告（II、latency、资源利用率）的档。其次拆解 Makefile 分派机制：用内嵌 Python 将 hls_config.tmpl 的 `${VAR}` 占位符替换为环境变量生成 hls_config.cfg，再由两个条件判断分发——csim 仅跑 vitis-run、csynth 仅跑 `v++ -c`，其余三档两者都跑；vivado_syn 与 vivado_impl 共用 `--impl`，靠写入配置的 VIVADO_FLOW（syn/impl）区分。最后讲 csynth 报告解读：II 决定吞吐、latency 决定单次延迟、BRAM/DSP/FF/LUT 决定能否装下，报告文件以 top 函数命名（如 dut0_csynth.rpt）。关键结论：streamDup 因 `#pragma HLS pipeline II=1` 预计达成 II=1，纯复制无算术故 DSP 预计为 0——均为待本地验证的预判。本讲建立的大写 TARGET（HLS 流程）与小写 target（L2/L3 Vitis 流程）的边界，以及 II/latency/资源三维度，是后续讲义承接的基础。
