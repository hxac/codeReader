本讲聚焦如何工程化地量化和报告一个加速内核的质量，覆盖四个最小模块。首先区分 `benchmarks/` 与 `tests/` 目录：前者用大数据压满带宽并在 README 归档 Profiling 表，二者共用 `description.json` 元数据契约（`flow`/`category`/`targets`）。其次归纳参考模型比对的三种范式：bit 精确（CRC 用 `!=` 无容差）、绝对误差阈值（DSP FFT 用 `level=256` 定点整数单位）、范数误差阈值（solver SVD 重构 `A_out` 再比 L2 范数，阈值 1e-4）；范式选择由运算数值性质决定，数值内核因定点/浮点差异、浮点非结合律、迭代合法多解而无法 bit 精确。第三，PASS/FAIL 判定统一采用「累加失败标志 + 进程退出码」骨架，阈值本质是工程上对可接受精度损失的人为约定。最后定义性能指标四件套——频率、延迟、吞吐、资源，并区分主机 wall-clock（`gettimeofday`）与设备 profiling（OpenCL event）两种计时段，对比数字前必须先对齐口径。
