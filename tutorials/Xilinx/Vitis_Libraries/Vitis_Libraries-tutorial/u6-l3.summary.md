本讲以 dsp 库 `vss_fft_ifft_1d` 为完整端到端示例，把 AIE 内核、PL 搬运器与原生 XRT 主机控制三类零件焊成一条线，拆为四个最小模块：AIE 图生命周期（`init()/run(n)/end()`，仿真下由 `aie.cpp` 的 `main()` 驱动、上板下由主机 `xrt::graph` 的 `reset()/run()/end()` 驱动，共用同一 `tl_graph`）；参数驱动代码生成（`my_params.cfg → update_cfg.py → gen_tb_from_cfg.py → config.h`，以 `#define` 喂给 C++ 模板）；VSS 构建（AIE 图 `libadf.a` + 转置内核 XO + 连接配置，经 `v++ --link --mode vss` 链成 `.vss`，`VSS_MODE` 决定后端由 AIE 还是 RTL `xfft_bd` 做）；端到端打包运行（`example.mk` 五目标：vss→xclbin→host→sd_card→run）。关键术语：ADF 图、PLIO、VSS、SSR、POINT_SIZE、`config.h`。核心结论：SSR 直接决定 PLIO 流数量与 AIE 图拓扑；最大工程陷阱是 `my_params.cfg` 与 `example.mk` 硬编码变量为两套独立参数源，改 SSR/POINT_SIZE 必须两边同步。
