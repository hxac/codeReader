本讲承接 u4-l1（OpenCL 路线），改用 Xilinx 原生 XRT C++ API 编写主机程序，以 `dsp/L2/examples/vss_fft_ifft_1d/host.cpp` 为蓝本，讲解四类核心对象。XRT（Xilinx RunTime）是主机侧运行时库，提供 OpenCL 与原生 C++ 两套等价 API；原生 API 更直接，且具备 `xrt::graph`、`xrt::ip` 等 OpenCL 缺失的 AIE 专有能力，因此凡涉及 AI Engine 的混合系统几乎一律采用原生 API。

主机控制链固定为四步：`xrt::device`（按序号打开加速卡）→ `load_xclbin`（加载 `.xclbin` 容器，返回 uuid 作为后续查找内核的凭证）→ `xrt::kernel`（按"函数名:{实例名}"取出内核的静态签名，实例名须与 `system.cfg` 的 `nk` 声明对齐）→ `xrt::run`（一次具体调用）。

核心心智模型是：**kernel 是定义，run 是调用**，一个 kernel 可建多个 run。run 通过 `set_arg` 绑参、`start()` 非阻塞提交、`wait()` 阻塞收尾；start/wait 分离即并发的来源——本例中 mm2s（灌数据）与 s2mm（收数据）两个 PL 内核在硬件里经 AXI 流（串接 AIE 图）并发执行，主机不创建任何线程，仅负责点火与收工，整条流水由 s2mm 收够数据终止（对应 `NUM_ITER=-1` 自由运行）。

`xrt::bo`（buffer object）是设备内存缓冲，用 `kernel.group_id(arg)` 挂到内核参数对应的 DDR/HBM bank，`map()` 建主机视图、`sync()` 控制数据流向（`FROM_DEVICE` 取回结果）。bo 与 group_id 的细节留待 u4-l3，AIE 图结构留待 u13-l1/l2。
