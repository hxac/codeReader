本讲把 dsp 库的 AIE 内核范式搬到 solver。核心认知：solver 对同一运算（Cholesky/QR/SVD）同时维护 **PL HLS**（`include/hw`，跑 Alveo）与 **AIE**（`include/aie`，跑 Versal AI Engine）两套不共享源码、仅数学语义对应的实现。AIE 路线讲两类拓扑：cholesky 用**二维网格分块**（`TP_GRID_DIM`/`TP_X`/`TP_Y`，靠 `registerKernelClass()` 按坐标分派对角核/下三角核）；qrd 用**修正 Gram-Schmidt + 级联**（`TP_CASC_LEN`，按 `CASC_IN/OUT` 四种偏特化裁剪端口）。关键约定是「kernel.hpp + traits.hpp + utils.hpp + 运行时 .cpp」**四件拆分**：前三件不含 intrinsics、参与图级编译，`.cpp` 含 intrinsics、由核级编译经 `source(...)` 引入；L2 **图包装器**（如 `qrd_graph`）负责实例化、连级联与防御性 `static_assert`。`L2/benchmarks`（gesvj/gesvdj/gtsv）则是 PL HLS 路线基准，在 Alveo 量真实延迟/频率/资源，与 L1 csim 功能仿真、`tests/aie` 精度双图比对在目标上根本不同。
