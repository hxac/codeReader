本讲从「数据流」转向「控制流与硬件映射」，揭示 `#pragma HLS` 如何把同一段 C++ 循环综合成不同吞吐的硬件。先立三个直觉：HLS 把 C++ 编译成 RTL；吞吐、延迟、面积三者互相矛盾；II（启动间隔）是最关键的数字。随后覆盖四个最小模块：`pipeline II=1` 作用在循环级，决定吞吐（=1/II），II 翻倍则吞吐减半，违例多由资源冲突或跨迭代数据依赖引起；`unroll` 展开循环换取空间并行，必须配 `array_partition` 拆分 RAM，否则被端口卡住迫使 II 上升；`dataflow` 作用在函数/任务级，把多个子函数经 `hls::stream` 串成流水线，端到端吞吐由最慢 stage 决定，要求 stage 间只用 stream、一写一读、顺序消费；`XF_UTILS_HW_STATIC_ASSERT`（映射 `static_assert`）是模板内核的编译期护栏，零运行时代价，把参数误用前移到编译瞬间。核心结论：四者层次为 dataflow ⊃ pipeline ⊃ unroll，静态断言贯穿编译期作为安全网，`axiToStream` 是同时集齐这四件套的样本；HLS pragma 不区分大小写，全库混用。
