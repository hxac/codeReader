# 定点数表示与旋转因子量化

## 1. 本讲目标

学完本讲，你应该能够：

1. 说清楚「为什么 FPGA 不能直接算小数」，以及用「定点放大」把小数变成整数的通用套路。
2. 看懂 `RotatorMemory8.v` 里 `cos45_18 = 46341` 这类魔数是怎么来的：把 \(\cos45^\circ\approx0.707\) 放大 \(2^{16}=65536\) 倍再四舍五入。
3. 解释 `multiplier.v` 里乘完之后那句 `>>16` 的作用：抵消旋转因子当初多乘的 65536，让结果回落到和数据一致的量级。
4. 自己动手把任意角度的 \(\cos/\sin\) 量化成 Q16 定点整数，并判断它能不能在 18 位里表示。

本讲只解决一个核心问题：**旋转因子这种 \([-1,1]\) 之间的小数，在硬件里到底是怎么存、怎么参与乘法、又怎么被还原的。**

## 2. 前置知识

本讲需要你已经掌握（来自前面几讲）：

- **旋转因子（twiddle factor）**：\(W_N = e^{-j2\pi/N}\)，第 \(k\) 个因子是 \(W_N^k = \cos(2\pi k/N) - j\sin(2\pi k/N)\)。它的实部、虚部都是 \([-1,1]\) 之间的小数。这一点在 u1-l3 已建立。
- **复数乘法器 `multiplier.v`**：实现 \((a+jb)(c+jd)=(ac-bd)+j(ad+bc)\)，其中 \((a+jb)\) 是数据、\((c+jd)\) 是旋转因子。这一点在 u2-l2 已建立。
- **二进制与位宽**：知道 `1<<16` 等于 65536，知道有符号数（two's complement，二进制补码）用最高位当符号位。

一个最关键的直觉先放在这里，本讲会反复用到：

> **FPGA 的运算单元（加法器、乘法器、DSP 块）本质上只认整数。所谓「定点数」，就是人为约定「把小数先乘上一个大常数（这里是 65536）当成整数存和算，用完再除回来」。**

## 4. 核心概念与源码讲解

本讲拆成三个最小模块：

- 4.1 定点数基础：硬件如何用整数表示小数
- 4.2 旋转因子量化：`RotatorMemory8.v`
- 4.3 乘法还原：`multiplier.v` 的 `>>16`

### 4.1 定点数基础：硬件如何用整数表示小数

#### 4.1.1 概念说明

先回答一个最基本的问题：**为什么 FPGA 不能直接算小数？**

通用 CPU 里有专门的浮点运算单元（FPU），能处理 `0.707` 这种小数。但 FPGA 里你用 Verilog 写出的加法器、乘法器，本质上都是对**整数**的位进行操作。浮点运算需要一套很复杂的「对阶、规格化、舍入」电路，占用大量逻辑资源。所以在 FPGA 的信号处理里，几乎清一色用「定点数（fixed-point）」而不是浮点。

定点数的思路非常朴素：**把小数乘上一个大常数，变成整数来存、来算；等算完了，再除以这个常数还原。**

具体到这里，旋转因子是 \([-1,1]\) 的小数，项目选择的放大倍数是

\[
2^{16} = 65536 = 1 \ll 16
\]

也就是说，真实值 \(x\) 在硬件里被存成整数

\[
X = \text{round}(x \times 65536)
\]

反过来，知道整数 \(X\) 后，真实值是 \(x = X / 65536\)。

> 这种「放大倍数是 \(2^{16}\)」的定点格式，习惯上叫 **Q16**（或更精确地写成 Q1.16，含义见 4.2）。用 2 的幂次当放大倍数的好处是：还原时不用真的「除」，只要**右移 16 位**（`>>16`）就行，而移位在硬件里几乎是免费的。

#### 4.1.2 核心流程

把一个小数量化成 Q16 定点整数，三步：

1. **放大**：\(x \times 65536\)。
2. **取整**：四舍五入到最近整数 \(X\)。
3. **存进固定位宽**：把 \(X\) 写进指定宽度的寄存器（这里有符号，用补码）。

还原（在乘法器里）反过来：

1. 算完之后**右移 16 位**：\(X \gg 16\)，相当于除以 65536。
2. 截断回目标位宽（32 位），让结果回到数据的量级。

举个贯穿全讲的例子：

\[
\cos45^\circ = \cos(\pi/4) \approx 0.70710678
\]

\[
X = \text{round}(0.70710678 \times 65536) = \text{round}(46340.95) = 46341
\]

所以「\(\cos45^\circ\) 量化后」就是 **46341**。这个数字会马上在 `RotatorMemory8.v` 里原样出现。

#### 4.1.3 源码精读

定点放大的动机，作者直接写在了 `RotatorMemory8.v` 的注释里：

```verilog
//rotator的实部虚部在0~1之间，扩大65536倍
//硬件不支持小数运算
//cos45 65536倍量化后为46341
```

对应源码：[`src/RotatorMemory8.v:13-L15`](https://github.com/guanjiess/fpga-fft/blob/411062734ac2bdc2d08968c639bb7bec630a9e10/src/RotatorMemory8.v#L13-L15)

这里要小小地纠正一句注释：旋转因子的实部、虚部范围其实是 \([-1,1]\)（因为 \(\sin/\cos\) 可以为负），而不是「0~1」。后面你会看到 `W2_img = -65536` 就是 \(-1.0\) 的量化值，注释里那句「0~1」是写松了，以 \([-1,1]\) 为准。

#### 4.1.4 代码实践

**实践目标**：亲手做一次 Q16 量化，建立对「魔数 46341」的直觉。

**操作步骤**：

1. 打开计算器或 MATLAB/Python。
2. 计算 \(\cos(\pi/4) \times 65536\)。
3. 四舍五入。
4. 和注释里的 46341 比对。

**需要观察的现象**：你会发现 \(\cos(\pi/4)\times65536 = 46340.95...\)，离整数 46341 只差 0.05，说明 46341 就是这个值四舍五入的结果，几乎没有量化误差。

**预期结果**：

```text
cos(pi/4)        = 0.70710678
* 65536          = 46340.95033...
round(...)       = 46341        <-- 与 RotatorMemory8.v 里的 cos45_18 完全一致
```

#### 4.1.5 小练习与答案

**练习 1**：如果项目改用 Q12（放大 \(2^{12}=4096\)），\(\cos45^\circ\) 会量化成多少？误差比 Q16 大还是小？

**参考答案**：\(0.70710678 \times 4096 = 2896.34\)，取整 2896，反算 \(2896/4096 = 0.70703\)，误差约 \(8\times10^{-5}\)；Q16 下 \(46341/65536=0.70711\)，误差约 \(4\times10^{-6}\)。所以 Q12 误差更大、但每个旋转因子只占 12~13 位、更省存储。这就是「精度 vs 资源」的典型取舍。

**练习 2**：为什么放大倍数要选 65536（\(2^{16}\)），而不是随便选一个 60000？

**参考答案**：因为 \(2^{16}\) 是 2 的幂次，还原时可以用「右移 16 位」代替「除以 65536」，移位电路几乎不占资源；而除以 60000 需要一个真正的除法器，又慢又费逻辑。

### 4.2 旋转因子量化：RotatorMemory8.v

#### 4.2.1 概念说明

8 点 FFT 在这一层需要用到 4 个旋转因子 \(W_8^k,\ k=0,1,2,3\)。用 \(W_N^k=\cos(2\pi k/N)-j\sin(2\pi k/N)\) 展开（注意指数是负的，所以虚部带负号）：

| k | 真实值 | 量化后（实部, 虚部） |
| --- | --- | --- |
| 0 | \(1 + j0\) | \((65536,\ 0)\) |
| 1 | \(\cos45^\circ - j\sin45^\circ \approx 0.707 - j0.707\) | \((46341,\ -46341)\) |
| 2 | \(\cos90^\circ - j\sin90^\circ = 0 - j1\) | \((0,\ -65536)\) |
| 3 | \(\cos135^\circ - j\sin135^\circ \approx -0.707 - j0.707\) | \((-46341,\ -46341)\) |

`RotatorMemory8.v` 没有用 ROM IP，而是直接把这 4 个因子的量化值**硬编码成常量**，再用一个 3 位计数器轮转输出。

#### 4.2.2 核心流程

模块的工作流程：

1. `rotator_valid` 拉高时，每个时钟 `counter` 加 1（模 4，因为只用 4 个因子）。
2. 根据 `counter` 的值，`case` 语句把对应的 \(W_0\sim W_3\) 选出来，送到 `rotator_real_tmp / rotator_img_tmp`。
3. `rotator_valid` 无效时，输出默认值 \((1\ll16,\ 0)\)，即「\(W=1\)」，表示这一拍不需要真正乘旋转因子。
4. 复位时同样输出 \(W=1\)（实部 `1<<16`，虚部 0）。

#### 4.2.3 源码精读

先看四个量化常量的定义（这就是 4.1 里算出来的那些数）：

```verilog
parameter	[18-1:0]	cos45_18		= 18'b0_0_1011_0101_0000_0101;  // +46341 ≈ +cos45°
parameter	[18-1:0]	m_cos45_18		= 18'b1_1_0100_1010_1111_1100;  // ≈ -cos45° 的补码
parameter	[18-1:0]	one				= 18'b0_1_0000_0000_0000_0000;  // 65536 ≈ 1.0
```

对应源码：[`src/RotatorMemory8.v:16-L18`](https://github.com/guanjiess/fpga-fft/blob/411062734ac2bdc2d08968c639bb7bec630a9e10/src/RotatorMemory8.v#L16-L18)

这里的 18 位写法很有讲究。下划线只是给人看的分隔符，Verilog 会忽略。我们把 18 位拆成 **1 位符号 + 1 位整数 + 16 位小数**，这是一种 **Q1.16 有符号定点**格式：

\[
\text{真实值} = \frac{\text{18 位补码整数}}{65536}
\]

逐个验证：

- `one = 18'b0_1_0000_0000_0000_0000`：整数位 = 1，小数位全 0 → 整数值 65536 → 真实值 \(65536/65536 = 1.0\)。所以「1.0」在硬件里就是 `1<<16`。
- `cos45_18 = 18'b0_0_1011_0101_0000_0101`：小数位 = `0xB505 = 46341` → 真实值 \(46341/65536 \approx 0.7071\)。正是 4.1 里算出来的 \(\cos45^\circ\)。
- `m_cos45_18`：最高位（符号位）为 1，是 \(-\cos45^\circ\) 的二进制补码编码，数值上约等于 \(-46340\)（即 \(\approx -0.707\)）。注意它和 `cos45_18` 不只是符号位不同，整个低位模式是补码取反加一后的结果。

> 为什么是 18 位而不是 16 位？因为 \([-1,1]\) 的小数放大 \(2^{16}\) 倍后，最大值 \(1.0\) 已经需要第 16 位（\(65536\)），再留 1 位符号位，就是 17 位起步；用 18 位还多出 1 位冗余，避免溢出。这就是「18 位旋转因子」的来历。

再用这些常量拼出四个因子：

```verilog
parameter W0_real = one;          // 65536   -> +1.0
parameter W0_img  = 0;
parameter W1_real = cos45_18;     // +46341  -> +0.707
parameter W1_img  = m_cos45_18;   // -46341  -> -0.707   (注意虚部是负的)
parameter W2_real = 0;
parameter W2_img  = -65536;       // -> -1.0
parameter W3_real = m_cos45_18;   // -46341  -> -0.707
parameter W3_img  = m_cos45_18;   // -46341  -> -0.707
```

对应源码：[`src/RotatorMemory8.v:22-L29`](https://github.com/guanjiess/fpga-fft/blob/411062734ac2bdc2d08968c639bb7bec630a9e10/src/RotatorMemory8.v#L22-L29)

把这张表和 4.2.1 的理论表对照，会发现完全吻合——尤其是 `W1_img` 是负的（`m_cos45_18`），正是因为旋转因子定义里虚部带负号（\(e^{-j2\pi/N}\)）。`W2_img = -65536` 直接用十进制写，Verilog 会自动转成 18 位补码，等价于 \(-1.0\)。

轮转输出的核心是 `case (counter)`，按计数器选因子：

```verilog
case (counter)
    3'b000: begin rotator_real_tmp <= W0_real; rotator_img_tmp <= W0_img; end
    3'b001: begin rotator_real_tmp <= W1_real; rotator_img_tmp <= W1_img; end
    3'b010: begin rotator_real_tmp <= W2_real; rotator_img_tmp <= W2_img; end
    3'b011: begin rotator_real_tmp <= W3_real; rotator_img_tmp <= W3_img; end
    default: begin rotator_real_tmp <= 1<<16; rotator_img_tmp <= 16'h0; end
endcase
```

对应源码：[`src/RotatorMemory8.v:51-L72`](https://github.com/guanjiess/fpga-fft/blob/411062734ac2bdc2d08968c639bb7bec630a9e10/src/RotatorMemory8.v#L51-L72)

复位和无效时的默认值也是 \((1\ll16,\ 0)\)（即 \(W=1\)）：

```verilog
if (rst) begin
    rotator_real_tmp <= 1<<16;
    rotator_img_tmp  <= 0;
end
```

对应源码：[`src/RotatorMemory8.v:44-L47`](https://github.com/guanjiess/fpga-fft/blob/411062734ac2bdc2d08968c639bb7bec630a9e10/src/RotatorMemory8.v#L44-L47)

含义很清楚：默认「不旋转」（乘 1），只有 `rotator_valid` 有效的那几拍才真正输出需要乘的因子。这一点会和 u3 讲的时序对齐（`rotator_valid`）接上。

#### 4.2.4 代码实践

**实践目标**：自己量化两个旋转因子，确认 Q1.16 量化的正确性，并理解「18 位够不够装」。

**操作步骤**：

1. 计算 \(\cos(\pi/4)=\cos45^\circ\) 和 \(\cos(\pi/8)=\cos22.5^\circ\) 各自乘 65536、四舍五入后的整数。
2. 把 \(\cos(\pi/4)\) 的结果和 `RotatorMemory8.v` 里的 `cos45_18 = 46341` 比对。
3. 思考：\(\cos(\pi/8)\)（即 16 点 FFT 的 \(W_{16}^1\) 实部）这个值，在 8 点层用不到，它会出现在哪一层？

**需要观察的现象**：两个 \(\cos\) 值乘 65536 后都落在 \(0\sim65536\) 之间，说明 18 位（1 符号 + 1 整数 + 16 小数）确实装得下。

**预期结果**：

```text
cos(pi/4) * 65536 = round(46340.95) = 46341   <-- 等于 cos45_18 ✓
cos(pi/8) * 65536 = round(60547.26) = 60547   <-- 16 点层 W16^1 的实部，约 0.9239
```

`cos45_18` 完全对上，说明量化的路子是对的。`cos(pi/8)` 的量化值 60547 不会出现在 `RotatorMemory8`（它只管 8 点层），而是会出现在 16 点层的旋转因子表（`Rotator16` / ROM）里——同一套 Q1.16 规则，只是 N 更大、因子更多。

#### 4.2.5 小练习与答案

**练习 1**：`RotatorMemory8` 里 `counter` 是 3 位宽，但只用 4 个因子（0~3），为什么要 3 位而不是 2 位？

**参考答案**：2 位就够表示 0~3。用 3 位多半是为了和后续更高层（计数器要计更多）保持写法一致，或是为 `default` 分支留余量。功能上这里 2 位即可，3 位不会出错（`counter` 只会经历 0~3）。

**练习 2**：如果把 `cos45_18` 直接改成十进制 `46341`，行为会一样吗？

**参考答案**：会完全一样。二进制 `18'b0_0_1011_0101_0000_0101` 和十进制 `46341` 是同一个数，作者用二进制只是为了让人一眼看到「1 位符号 + 1 位整数 + 16 位小数」的 Q1.16 结构。

### 4.3 乘法还原：multiplier.v 的 >>16

#### 4.3.1 概念说明

旋转因子被放大了 \(2^{16}\) 倍存进硬件。那么当数据和它相乘时，乘积里就**多带了一个 \(2^{16}\) 的因子**。如果不处理，每经过一级旋转因子相乘，结果就会膨胀 65536 倍，几级之后就爆掉了。

所以 `multiplier.v` 在算完复数乘法之后，要做一次 `>>16`（右移 16 位 = 除以 65536），把旋转因子当初多乘的 \(2^{16}\) 抵消掉，让输出数据回到和输入数据一致的量级。这就是本讲标题里「乘法后右移 16 位再截断还原」的含义。

#### 4.3.2 核心流程

`multiplier.v` 是一条三级流水线（u2-l2 已讲过整体结构，这里只盯「定点还原」这一段）：

1. **第一级**：算出复数乘积的实部和虚部
   \[
   \text{real} = ac - bd,\qquad \text{img} = ad + bc
   \]
   此时结果里**还带着旋转因子多乘的 \(2^{16}\)**。
2. **第二级**：右移 16 位
   \[
   \text{real\_shifted} = \text{real} \gg 16,\qquad \text{img\_shifted} = \text{img} \gg 16
   \]
   这一步等价于除以 65536，抵消定点放大。
3. **第三级**：截断回 32 位，取低 32 位作为最终输出 `data_real_trunc / data_img_trunc`。

位宽上是配套设计的：

- 数据 `a/b`：32 位（当作整数看待，不带额外定点放大）。
- 旋转因子 `c/d`：18 位（Q1.16，放大了 \(2^{16}\)）。
- 乘积 `ac/bd/bc/ad`：\(32+18=50\) 位。
- 加减后 `r_data_real/img`：51 位（多 1 位吸收加减的借位/进位）。
- 右移、截断后：32 位（与输入数据同宽）。

#### 4.3.3 源码精读

先看端口，确认数据 32 位、旋转因子 18 位这套位宽：

```verilog
input	[32-1:0]	a,        // 数据实部
input	[32-1:0]	b,        // 数据虚部
input	[18-1:0]	c,        // 旋转因子实部 (Q1.16)
input	[18-1:0]	d,        // 旋转因子虚部 (Q1.16)
...
output	[32-1:0]	data_real_trunc,  // 还原后的实部
output	[32-1:0]	data_img_trunc    // 还原后的虚部
```

对应源码：[`src/multiplier.v:10-L20`](https://github.com/guanjiess/fpga-fft/blob/411062734ac2bdc2d08968c639bb7bec630a9e10/src/multiplier.v#L10-L20)

第一级：复数乘法的加减（结果还在 \(2^{16}\) 放大态）：

```verilog
always@(posedge clk)begin
    ...
    r_data_real <= ac - bd;   // (ac-bd)，含 ×2^16
    r_data_img  <= ad + bc;
end
```

对应源码：[`src/multiplier.v:36-L44`](https://github.com/guanjiess/fpga-fft/blob/411062734ac2bdc2d08968c639bb7bec630a9e10/src/multiplier.v#L36-L44)

第二级：**本讲的主角——右移 16 位还原**：

```verilog
// right shift and truncate
always@(posedge clk)begin
    ...
    r_data_real_shifted <= r_data_real >> 16;   // 除以 65536，抵消旋转因子的定点放大
    r_data_img_shifted  <= r_data_img  >> 16;
end
```

对应源码：[`src/multiplier.v:47-L56`](https://github.com/guanjiess/fpga-fft/blob/411062734ac2bdc2d08968c639bb7bec630a9e10/src/multiplier.v#L47-L56)

> 这里的 `>>16` 之所以成立，正是因为 `RotatorMemory8` 当初把每个旋转因子放大了 \(2^{16}\) 倍。「左移 16 位存进去」和「右移 16 位除回来」是成对设计的——这就是定点数在硬件里的标配套路：**放大（存）→ 当整数算 → 缩回（还原）**。

第三级：截断到 32 位：

```verilog
always@(posedge clk)begin
    ...
    r_data_real_trunc <= r_data_real_shifted[31:0];   // 取低 32 位
    r_data_img_trunc  <= r_data_img_shifted [31:0];
end
```

对应源码：[`src/multiplier.v:58-L66`](https://github.com/guanjiess/fpga-fft/blob/411062734ac2bdc2d08968c639bb7bec630a9e10/src/multiplier.v#L58-L66)

中间用 51 位（`r_data_real_shifted`）暂存、最后只取低 32 位，是为了：① 给加减和移位留足位宽余量，避免溢出截断真实数据；② 让最终输出回到和输入数据 `a/b` 相同的 32 位量级，这样数据从一级流到下一级时位宽稳定、不会越乘越胖。

四个实数乘法 `ac/bd/bc/ad` 由 `mult2` IP 完成：

```verilog
mult2 real_ac( .CLK(clk), .A(a), .B(c), .P(ac) );
mult2 real_bd( .CLK(clk), .A(b), .B(d), .P(bd) );
mult2 real_bc( .CLK(clk), .A(b), .B(c), .P(bc) );
mult2 real_ad( .CLK(clk), .A(a), .B(d), .P(ad) );
```

对应源码：[`src/multiplier.v:69-L95`](https://github.com/guanjiess/fpga-fft/blob/411062734ac2bdc2d08968c639bb7bec630a9e10/src/multiplier.v#L69-L95)

至于例化时 `.rstn(~rst)` 这种写法（把顶层高有效复位 `rst` 翻成乘法器要求的低有效 `rstn`），u2-l2 已经讲过，这里不再重复。

#### 4.3.4 代码实践

**实践目标**：用一个具体数值走完「放大 → 相乘 → 右移 → 截断」全流程，确认 `>>16` 的确把结果还原到数据量级。

**操作步骤**（纯手算 / 计算器，不用跑仿真）：

1. 设数据 \(a = 10000\)（实部），\(b = 0\)（虚部）；旋转因子取 \(c = 46341\)（\(\approx\cos45^\circ\)），\(d = -46341\)（\(\approx-\sin45^\circ\)）。
2. 算 \(ac = 10000 \times 46341 = 463410000\)。
3. 算 \(\text{real} = ac - bd = 463410000 - 0 = 463410000\)（这一步结果里带着 \(2^{16}\) 放大）。
4. 右移 16 位：\(463410000 / 65536 \approx 7071.0\)，取整 7071。
5. 对比「真实应当的值」：数据 \(10000\) 乘上 \(\cos45^\circ\approx0.7071\)，应该是 \(7071\)。

**需要观察的现象**：第 4 步右移后的结果（7071）和第 5 步「真实值」（7071）完全吻合，说明 `>>16` 准确抵消了当初的 \(2^{16}\) 放大。

**预期结果**：

```text
ac        = 10000 * 46341 = 463410000      (含 ×2^16 放大)
real      = 463410000
>>16      = 7071                            (还原后)
真实值    = 10000 * cos(45°) = 10000 * 0.7071 = 7071   ✓ 吻合
```

> 结论：如果没有 `>>16`，输出会是 463410000（膨胀了 65536 倍），下一级根本接不住；有了 `>>16`，输出回到 7071，和「数据乘旋转因子」的真实数学结果一致。

#### 4.3.5 小练习与答案

**练习 1**：如果某一级的旋转因子不放大（直接用真正的 0.707），`multiplier.v` 还需要 `>>16` 吗？为什么实际不这么做？

**参考答案**：不需要 `>>16`，因为乘积里没有多余的 \(2^{16}\)。但实际不这么做，是因为 FPGA 的乘法器只认整数，`0.707` 这种小数根本没法直接表示和相乘；必须先放大成整数 46341 才能送进 `mult2`，于是就得配套用 `>>16` 还原。

**练习 2**：`r_data_real` 用 51 位、`r_data_real_trunc` 只取 `[31:0]`。如果数据 \(a\) 本身就接近 32 位满量程，这一级乘法会不会溢出？

**参考答案**：有溢出风险。旋转因子绝对值 \(\le 1\)，所以乘旋转因子后幅度不会变大（\(7071 < 10000\)），单级通常安全；但 FFT 多级累加、且数据本身就是 32 位时，没有块浮点（block floating point）做伸缩的话，仍可能逐渐溢出。这正是 u5 架构反思里会提到的「块浮点防溢出」改进方向之一。

## 5. 综合实践

把本讲三块知识串起来，完成下面这个「一条龙」小任务。

**任务**：从「公式」一路推到「硬件整数」，再解释「还原」。

1. **画单位圆**：运行 `matlab/FFT_figures.m`（内容见 [`matlab/FFT_figures.m:1-L8`](https://github.com/guanjiess/fpga-fft/blob/411062734ac2bdc2d08968c639bb7bec630a9e10/matlab/FFT_figures.m#L1-L8)），它会画出 \(N=16\) 时 16 个旋转因子在复平面上的散点。确认它们都落在单位圆上，且实部、虚部都在 \([-1,1]\) 内——这就是「旋转因子必须用定点小数表示」的根本原因。
2. **量化**：从图上任取一个因子（比如 \(W_{16}^1\)），写出它的实部和虚部的真实值，再用 Q1.16（乘 65536、四舍五入）把它们量化成 18 位整数。
3. **相乘还原**：假设数据 \(=20000+j0\)，它乘上你刚量化的 \(W_{16}^1\)，走 `multiplier` 的流程：先算 \(ac-bd\)（注意此时含 \(2^{16}\) 放大），再 `>>16`，写出最终 `data_real_trunc` 的值，并验证它约等于 \(20000 \times \cos(22.5^\circ)\)。
4. **回答**：一句话总结——为什么「旋转因子左移 16 位存」和「乘法器右移 16 位还原」必须成对出现？

**参考要点**：

- 第 1 步应看到 16 个点均匀分布在单位圆上（每隔 \(22.5^\circ\) 一个）。
- 第 2 步：\(W_{16}^1\) 实部 \(\cos22.5^\circ\approx0.9239\rightarrow60547\)，虚部 \(-\sin22.5^\circ\approx-0.3827\rightarrow\) 约 \(-25080\)。
- 第 3 步：\(ac = 20000\times60547\)，`>>16` 后约 \(20000\times0.9239\approx18478\)，与直接乘 \(\cos22.5^\circ\) 吻合。
- 第 4 步：因为硬件乘法器只算整数，必须先把小数放大成整数才能相乘，放大多少（\(2^{16}\)）就得在乘完后移回多少（`>>16`），否则结果会被多乘 65536 倍。两者是同一定点约定的存与取。

## 6. 本讲小结

- FPGA 运算单元只认整数，旋转因子这种 \([-1,1]\) 小数靠**定点放大**变成整数：约定乘 \(2^{16}=65536\)（即 Q1.16）。
- \(\cos45^\circ\approx0.707\) 量化后就是 **46341**（\(0.7071\times65536\) 四舍五入），这就是 `RotatorMemory8.v` 里 `cos45_18` 的来历；`1.0` 量化后是 `1<<16=65536`。
- 18 位旋转因子 = 1 位符号 + 1 位整数 + 16 位小数，刚好能装下 \([-1,1]\) 且让 \(1.0\) 精确表示。
- `multiplier.v` 乘完后 `>>16`，是为了**抵消旋转因子当初多乘的 \(2^{16}\)**，让输出回到数据原来的量级；「左移 16 位存」与「右移 16 位还原」是成对设计。
- 51 位中间暂存 + 取低 32 位截断，是为了留足加减/移位余量，并让输出位宽与输入数据一致。
- 注释里「实部虚部在 0~1 之间」应理解为 \([-1,1]\)，因为有 \(-1.0\)（`W2_img=-65536`）这样的负值。

## 7. 下一步学习建议

本讲搞定了「旋转因子怎么量化、怎么参与乘法、怎么还原」。接下来：

- **向「时序」走**：旋转因子的量化值你已经会读了，但它们到底在**哪一拍**被送进乘法器、怎么和蝶形的输出对齐？这就是 u3-l1（旋转因子 ROM 与寻址）、u3-l3（时序对齐与跨级握手 `rotator_valid`）的内容，本讲里那个 `rotator_valid` 信号会在那里被详细解释。
- **向「更大点数」走**：8 点层用 `RotatorMemory8` 硬编码 4 个因子；点数一大（如 1k、16k），因子多到没法硬编码，就要换成 ROM IP 存（`Rotator16`、`rotator_*_real/img`），这套机制在 u3-l1 和 u4 讲。
- **自己验证一遍**：在做 u5 的 MATLAB 黄金参考（u5-l1）时，可以顺手把你这讲量化的旋转因子代入，看看定点量化引入的误差有多大，把「精度 vs 资源」的取舍用数据坐实。
