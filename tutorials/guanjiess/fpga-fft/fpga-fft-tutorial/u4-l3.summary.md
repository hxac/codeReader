本讲解析参数化模块 butterfly_general.v：它把 fft_8/fft_16 中反复手写的「状态机 + S 控制 + RAM 延时 + 下一级启动 + rotator_valid」五段逻辑收进一个 layer 参数控制的黑盒，消除了 fft_32 至 fft_16k 共 11 个高层模块的重复代码。全部行为由 layer 一处导出：PERIOD=1<<layer、HALT_FOR_NEXT_LAYER=6+PERIOD/2、WAIT_FOR_ROTATOR=PERIOD-2，延时实例为 delay #(.layer(current_layer))。内部核心是一条 SDF 反馈闭环：状态机驱动 butterfly 与 delay，蝶形下支 B 经 RAM 延时半周期后作为 C 回流配对，D 为唯一前向出口。模块对外暴露两个门控信号：next_level_start（计数到 HALT-3 发单拍脉冲驱动下一级 start）与 rotator_valid（计数到 WAIT_FOR_ROTATOR-1 拉高、放行真实旋转因子，此前默认输出 W=1）。关键分工在于旋转因子寻址 Rotator_address、ROM 与复数乘法 multiplier 因实例名随层变化、无法参数化，被留在各 fft_* 包装层；fft_32 即首个同构装配模板，fft_1k、fft_16k 仅差 layer 参数与 ROM 实例名。本讲为后续高层模块对比与平台移植奠定认知基础。
