# 项目定位与整体架构：什么是实时流水线 FFT

## 1. 本讲目标

本讲是整套 fpga-fft 学习手册的第一篇，目标不是让你看懂某一行 Verilog，而是先建立**全局认知**。读完本讲，你应该能够：

- 说清楚**离散傅里叶变换（DFT）/ 快速傅里叶变换（FFT）**在信号处理中做什么，以及为什么大点数 FFT 在通用 CPU 上「算不过来」。
- 理解本项目选择 **FPGA + 流水线结构（SDF）** 来做实时 FFT 的动机。
- 从顶层模块 `fft_top` 看到整条流水线是如何由一级一级的硬件模块（`fft_16k` → … → `fft_2`）首尾相连的，建立「每一级是一个独立硬件」的直觉。
- 读懂项目自带的设计文档（README、`参数和问题.md`、`FFT.md`），并知道项目目前**已完成什么、还缺什么**（比如输出倒序尚未实现）。

本讲只要求「看懂动机与全貌」，不要求理解任何模块内部的时序细节——那是后续讲义的内容。

## 2. 前置知识

本讲尽量从零讲起，但如果你预先了解下面几个名词，会读得更顺：

- **信号**：随时间变化的数值序列，比如一段语音的采样值、一段音频波形。在数字系统里它是一串离散的数 \(x(0), x(1), \dots, x(N-1)\)。
- **频率 / 频谱**：把一段信号拆成「不同频率的正弦波」的叠加，看每个频率成分有多强，这就是频谱。
- **DFT（离散傅里叶变换）**：把「时域」的信号序列转换成「频域」表示的数学运算。
- **FPGA（现场可编程门阵列）**：一种可以通过编程重新连线的芯片。与 CPU 不同，它没有固定的「取指—译码—执行」流程，而是直接用硬件电路并行计算，适合做高速、固定的数据流处理。
- **流水线（pipeline）**：像工厂流水线一样，把一个任务拆成多个工位，每个工位每个时钟都在处理一个半成品，整体吞吐量由最慢的工位决定，而不是所有工位耗时之和。

不熟悉也没关系，下面的章节会结合项目源码逐一解释。

### 4.1 项目背景与设计动机：为什么要在 FPGA 上做实时 FFT

#### 4.1.1 概念说明

我们先用一句话回答「这个项目为什么存在」：

> 大点数 FFT 在通用处理器（CPU）上难以**实时**处理；本项目用 FPGA 的**流水线结构**来实现实时 FFT。

这里有两个关键词：「大点数」和「实时」。

- **大点数**：FFT 的「点数 N」就是一次变换处理的样本数，比如 1024 点、16384 点。点数越大，频率分辨率越高，但计算量也越大。
- **实时（real-time）**：数据源源不断地到来（比如麦克风每秒采几万个样本），要求系统**跟得上输入速度**，在每个采样周期内完成处理并产出结果，而不是「攒一批、算一批、再等下一批」。

为什么要强调实时？因为**通用 CPU 跑实时大点数 FFT 很吃力**。CPU 是**冯诺依曼架构**：数据要频繁地在存储器和运算单元之间搬来搬去，受限于访存带宽和串行的指令执行节奏。当采样率很高、点数很大时，CPU 常常算不过来。

FPGA 的思路不同：它不用「取指—执行」的循环，而是直接**用硬件电路**实现算法。对于 FFT 这种结构固定、数据流规整的运算，FPGA 可以做成一条**流水线**——数据像水流一样从一端进入，经过一连串专用硬件级，从另一端源源不断地流出结果。每个时钟周期都在吞吐数据，这正是本项目的研究动机。

`scheme/参数和问题.md` 就是作者把上述动机整理成的一份「关键词清单」，它是理解项目定位最好的入口。

#### 4.1.2 核心流程

可以把项目的动机链条整理成下面这条逻辑链：

```text
信号处理的实时性需求（语音/音频等）
        │
        ▼
需要实时计算 FFT
        │
        ▼
大点数 FFT 在通用 CPU 上难以实时处理（冯诺依曼架构瓶颈）
        │
        ▼
改用 FPGA（专用硬件电路，可并行、可流水）
        │
        ▼
采用流水计算结构 ──► SDF FFT（单路延迟反馈）
        │
        ▼
面向嵌入式边缘端 / 异构计算场景
```

其中 **SDF** 是 Single-path Delay Feedback（单路延迟反馈）的缩写，是流水线 FFT 的一种经典结构。它的特点是：每一级只保留一条数据通路，用「延时反馈（RAM）」把数据攒够再做蝶形运算，资源占用低、适合做成深流水线。本讲你只要记住「SDF = 一种把每一级做成独立硬件模块、首尾串成流水的 FFT 结构」即可，细节在第三、四单元讲。

### 4.2 从 DFT 到流水线 FFT：核心思想总览

#### 4.2.1 概念说明

在讲流水线之前，先用最少的数学说明 FFT 到底在算什么。

**DFT（离散傅里叶变换）** 把一个长度为 \(N\) 的时域序列 \(x(n)\) 变成同样长度的频域序列 \(X(k)\)，定义见项目文档：

[FFT.md:5-10](https://github.com/guanjiess/fpga-fft/blob/411062734ac2bdc2d08968c639bb7bec630a9e10/scheme/FFT.md#L5-L10) —— DFT 的定义式与旋转因子。

写成公式就是：

\[
X(k)=\sum_{n=0}^{N-1} x(n) W_{N}^{nk}, \qquad W_{N}=e^{-j\frac{2\pi}{N}}
\]

其中 \(W_{N}\) 叫**旋转因子（twiddle factor）**，本质是单位圆上的复数。直接按定义算 DFT，每个 \(X(k)\) 要做 \(N\) 次复数乘加，\(N\) 个 \(X(k)\) 总共要 \(N^2\) 次复数乘法——计算量是 \(O(N^2)\)。点数一大，平方增长就吃不消：

[FFT.md:34-37](https://github.com/guanjiess/fpga-fft/blob/411062734ac2bdc2d08968c639bb7bec630a9e10/scheme/FFT.md#L34-L37) —— DFT 计算量分析：复数乘法 \(N^2\) 次。

**FFT（快速傅里叶变换）** 利用旋转因子的**对称性**和**周期性**，用「分而治之」把 \(N\) 点 DFT 拆成两个 \(N/2\) 点 DFT，递归下去，计算量降到 \(O(N\log_2 N)\)。这就是 **Cooley-Tukey 算法**：

[FFT.md:57-65](https://github.com/guanjiess/fpga-fft/blob/411062734ac2bdc2d08968c639bb7bec630a9e10/scheme/FFT.md#L57-L65) —— Cooley-Tukey 推导：\(X(k)=A(k)+W_{N}^{k}B(k)\)，把 \(N\) 点拆成偶数项 \(A(k)\) 和奇数项 \(B(k)\) 两个 \(N/2\) 点 DFT。

最终的计算量：

[FFT.md:174-178](https://github.com/guanjiess/fpga-fft/blob/411062734ac2bdc2d08968c639bb7bec630a9e10/scheme/FFT.md#L174-L178) —— FFT 分成 \(\log_2 N\) 级，每级 \(N\) 次复数乘法，总量 \(N\log_2 N\)。

> 注：文档里写「总的计算复杂度为 \(O(\log_2 N)\)」是一处笔误，正确应为 \(O(N\log_2 N)\)。我们以它前面「\(N\log_2 N\)」的推导为准。

把 Cooley-Tukey 的「递归分治」翻译成硬件，最自然的方式就是**每一级做一个独立的运算模块**，数据从第一级流向最后一级——这就是**流水线 FFT**。每一级内部做的事情高度规整：取两个数据做一次「蝶形运算（加减）」，再乘一个旋转因子。本项目选用的 **SDF（单路延迟反馈）** 结构，就是让每一级用一块 RAM 把数据「攒够再放行」，从而只用一条数据通路就能完成该级的蝶形。这正是「为什么 FFT 特别适合做成 FPGA 流水线」的算法根源。

#### 4.2.2 核心流程

把上面的算法和硬件对应起来，得到本项目的总体数据流：

```text
       时域输入 x(n)
            │
            ▼
   ┌────────────────────┐
   │ 第 1 级 fft_16k     │  ← 最大点数层，延时最深，放在流水线最前端
   │ (蝶形 + RAM延时 +   │
   │  旋转因子 + 复数乘) │
   └─────────┬──────────┘
             │ data_out 喂给下一级 data_in
             ▼
        第 2 级 fft_8k
             │
             ▼
            …………（共 14 级，逐级减小）
             │
             ▼
        第 13 级 fft_4
             │
             ▼
   ┌────────────────────┐
   │ 第 14 级 fft_2      │  ← 最末级
   └─────────┬──────────┘
             │
             ▼
       频域输出 X(k)（注意：此时是倒序的，详见 4.3）
```

这条流水线的级数 = \(\log_2 N\)。对 16384（\(2^{14}\)）点 FFT 来说，正好 14 级，对应 `fft_16k`、`fft_8k`、…、`fft_2` 这 14 个模块。**每一级都是一拍一拍地吞吐数据**，整条流水线填满之后，每个时钟周期都产出一个变换结果——这就是「实时」的硬件含义。

#### 4.2.5 小练习与答案

**练习 1**：直接按 DFT 定义算 1024 点变换需要多少次复数乘法？用 FFT 呢？

> **参考答案**：DFT 是 \(N^2 = 1024^2 = 1\,048\,576\) 次；FFT 是 \(N\log_2 N = 1024 \times 10 = 10\,240\) 次，相差约 100 倍。

**练习 2**：为什么本项目要把**最大点数层（fft_16k）放在流水线最前面**，而把 fft_2 放在最后？

> **参考答案**：这是 SDF 流水线的级联顺序——大点数层对应 Cooley-Tukey 分治中「最先分解」的那一级，延时（RAM 反馈）最深，因此放在数据流入的最前端；逐级往后点数减半，直到最末的 2 点层。具体每级为什么这么排、延时如何配置，会在第 3、4 单元讲，本讲只要记住这个顺序即可。

### 4.3 项目现状与已知问题：从设计文档看完整度

#### 4.3.1 概念说明

读开源硬件项目，第一步往往不是看代码，而是看它的**设计文档**里标注的「已完成 / 未完成」。本项目没有传统意义的 CHANGELOG，但 README 里用很直白的方式标注了状态，比如某些子模块标了「**已完成**」，某些标了「还没有具体的思路」。这些标注决定了你能不能直接拿来用、用的时候要小心什么。

这一节我们做两件事：
1. 搞清楚 `fft_top` 顶层里那个 `data_config`（配置级数）端口到底有没有用。
2. 搞清楚输出结果需不需要「倒序」，以及项目有没有实现它。

#### 4.3.2 核心流程

```text
读 README 的「功能子模块」章节
        │
        ├─► 找到标注「已完成」的模块（butterfly 等）→ 可放心学习/复用
```

#### 4.3.5 小练习与答案

**练习 1**：如果直接拿 `fft_top` 的输出 `out_real`/`out_img` 当作频谱使用，会出什么问题？

> **参考答案**：输出是 **bit-reverse 倒序**的——第 k 个位置放的不是频率 k 的分量，而是下标二进制位反转后的那个频率分量。直接当频谱用会把频率顺序搞乱，必须先做倒序重排（而该重排模块 Reverse 尚未实现）。

**练习 2**：顶层 `data_config` 端口为什么说「目前没用」？给出你从源码中找到的证据。

> **参考答案**：因为 `data_config` 在 `fft_top.v` 第 13 行声明后，整个模块体内没有任何地方引用它（未连到任何子模块的输入）。README 接口表也标注其「条件不成熟」。所以当前点数是固定的（16384 点全流水线），不能通过它改变。

## 6. 本讲小结

- fpga-fft 是一个用 **Verilog** 在 FPGA 上实现的**实时流水线 FFT**，动机是「大点数 FFT 在通用 CPU（冯诺依曼架构）上难以实时处理」。
- 算法上，FFT 用 Cooley-Tukey 分治把 \(O(N^2)\) 的 DFT 降到 \(O(N\log_2 N)\)，每一级做规整的「蝶形运算 + 旋转因子相乘」，天然适合做成硬件流水线。
- 硬件上，顶层 `fft_top` 把 **14 级**模块（`fft_16k` → … → `fft_2`）首尾相连：上一级 `data_out` 喂下一级 `data_in`，上一级 `start_next` 触发下一级 `start`，对应 16384 点 FFT 的 \(\log_2 N=14\) 级。
- 项目采用 **SDF（单路延迟反馈）** 流水结构：每一级用 RAM 把数据「攒够再放行」，只用一条数据通路完成该级蝶形。
- 当前完成度：蝶形等核心子模块「已完成」，但**输出倒序（Reverse）尚未实现**、`data_config`（配置点数）端口**未启用**——使用时需注意输出是倒序的、且点数固定为 16384。
- 仓库分四类目录：`src/`（设计源码）、`tb/`（仿真测试）、`matlab/`（算法参考脚本）、`scheme/`（设计文档）。
