# 蝶形运算单元 butterfly.v：加减与 S 控制信号

## 1. 本讲目标

学完本讲，你应当能够：

- 说清楚 radix-2 蝶形运算（butterfly）在数学上做了什么，以及它对应 DIF（按频率抽取）流程的哪一步。
- 看懂 `butterfly.v` 的端口：A/C 输入、B/D 输出、`S` 与 `enable` 控制信号各自的作用。
- 解释为什么加法和减法的结果要「打一拍」（用 `r_x_added` / `r_x_subtracted` 寄存一拍），以及为什么用 `S_1d` 把 `S` 信号也延时一拍来做对齐。
- 手绘出 `S` 从 0 切到 1 时，`A_real / C_real / B_real / D_real` 四个信号的逐拍时序，并标注寄存器造成的延迟。
- 在 `fft_2.v`（最简的 2 点 FFT 层）中看出 `butterfly` 是如何被例化、`S2` 是如何翻转的。

本讲是整个项目「逐级流水线」里最小、也最基础的一块算子砖头。把这块砖头彻底搞懂，后面 `fft_4`、`fft_16`、`butterfly_general` 直到 `fft_top` 的级联不过是把同样的砖头重复 14 次。

## 2. 前置知识

在进入源码前，先用三段话把背景补齐。如果你已学完 u1-l3（算法基础）和 u1-l4（流水线总览），可以跳过前两段。

**什么是蝶形运算。** FFT 把一个 N 点 DFT 拆成 log₂N 级，每一级都由大量结构完全相同的小运算组成，这个小运算长得像一只张开的蝴蝶，所以叫蝶形（butterfly）。最常用的 radix-2（基 2）蝶形吃进两个复数、吐出两个复数，只做一次复数加法和一次复数减法（外加一次复数乘旋转因子）。`fpga-fft` 的每一级硬件就是用大量蝶形 + 延时 + 旋转因子拼出来的。

**DIF 蝶形的数学式。** 按频率抽取（DIF）的 radix-2 蝶形是这样的：给定两个输入 \(A\) 和 \(C\)，输出

\[
D = A + C \quad(\text{上支，求和，不乘旋转因子})
\]

\[
B = (A - C)\cdot W \quad(\text{下支，求差，再乘旋转因子 }W)
\]

其中 \(W\) 是旋转因子。本讲只关心「加减」这一半，旋转因子相乘是下一讲 `multiplier.v` 的内容。注意代码里下支写的是 \(C - A\) 而不是 \(A - C\)，两者只差一个负号，这个负号可以并进旋转因子里，不影响结果。

**硬件里的「时钟」与「打一拍」。** FPGA 是时钟驱动的同步电路：所有 `always @(posedge clk)` 块里的赋值 `<=`（非阻塞赋值）都在时钟上升沿「采样」输入、在下一拍才「出现」在输出端。把一个信号接进一个寄存器，使它整体往后推迟一个时钟周期，俗称「打一拍」。本讲里你会反复看到「打一拍」：加法/减法的结果被打一拍，`S` 信号也被打一拍，目的是让「计算结果」和「选择信号」在同一拍对齐。

## 4. 核心概念与源码讲解

### 4.1 蝶形运算的数学含义与端口定义

#### 4.1.1 概念说明

`butterfly.v` 实现的是一个 DIF radix-2 蝶形的「加减部分」。它有四个数据口：两个输入 `A`（复数）、`C`（复数），两个输出 `B`（复数）、`D`（复数），还有一个控制信号 `S` 和一个使能信号 `enable`。

关键在于：`butterfly` 并不是每个时钟都在算。它被设计成「半个周期算、半个周期直通（passthrough）」，由 `S` 来切换：

- 当 `S == 0` 时，蝶形处于**直通**状态：`B` 直接输出上一拍的 `A`，`D` 直接输出上一拍的 `C`，不做加减。
- 当 `S == 1` 时，蝶形处于**计算**状态：`D` 输出求和 \(A+C\)，`B` 输出求差 \(C-A\)。

之所以要「半周期直通 + 半周期计算」，是因为 SDF（单路延迟反馈）结构要求：延时 RAM 先把前一半样本攒着、原样放行（直通），等到后一半样本到来时，才把它们和 RAM 里吐出的旧样本配对做蝶形（计算）。`S` 正是「现在该直通还是该计算」的指挥棒。这一点在 u1-l4 的流水线总览里已经埋下伏笔，本讲把它落到 `butterfly` 这一个模块上。

#### 4.1.2 核心流程

`butterfly` 端口与控制信号的角色如下表：

| 信号 | 方向 | 位宽 | 含义 |
|------|------|------|------|
| `clk` | 输入 | 1 | 时钟，所有寄存器在上升沿更新。 |
| `rst` | 输入 | 1 | 同步复位，**高电平有效**（`rst==1` 时清零）。 |
| `S` | 输入 | 1 | 模式切换：`0`=直通，`1`=计算加减。 |
| `enable` | 输入 | 1 | 计算使能：只有 `S==1 && enable` 才真正执行加减。 |
| `A_real / A_img` | 输入 | 32 | 第一个复数输入的实部 / 虚部。 |
| `C_real / C_img` | 输入 | 32 | 第二个复数输入的实部 / 虚部。 |
| `B_real / B_img` | 输出 | 32 | 下支输出（求差结果或直通的 A）。后续送乘法器乘旋转因子。 |
| `D_real / D_img` | 输出 | 32 | 上支输出（求和结果或直通的 C）。直接送往下一级。 |

注意一个初学者容易踩的坑：端口名字是 `A/C → B/D`，**而不是** `A/B → C/D`。也就是说，`C` 是输入、`D` 是输出，别按字母顺序误判方向。

#### 4.1.5 小练习与答案

**练习 1**：如果把下支的 `C - A` 改成 `A - C`，最终 2 点 FFT 的结果会怎样？
**答案**：只是下支输出多了一个负号。由于下支随后还要乘旋转因子 \(W\)，这个负号可以并入 \(W\)（即把旋转因子取反），最终频谱结果不变。所以从功能上看，写 `C-A` 还是 `A-C` 是等价的，作者只是选了其中一种写法。

**练习 2**：`enable` 信号如果永远为 0，`butterfly` 还能正常做加减吗？
**答案**：不能。加减的触发条件是 `S == 1 && enable`（见 4.2.3）。`enable` 为 0 时，`r_x_added/r_x_subtracted` 永远保持初值 0，输出端在 `S_1d==1` 时会吐出 0，而不是真正的和与差。

### 4.2 加减运算的打拍寄存：r_x_added 与 r_x_subtracted

#### 4.2.1 概念说明

这一节回答一个关键问题：**为什么加法和减法的结果要用寄存器存一拍，而不是直接组合逻辑输出？**

两个原因。第一，**时序收敛**：32 位加法器后面通常还要接一堆逻辑（多路选择器、下一级的延时 RAM 写口等），如果加法用纯组合逻辑，关键路径会很长，时钟频率上不去；把加法结果寄存一拍，等于在长路径里插了一级寄存器，电路能跑得更快的代价只是多一个时钟周期延迟。第二，**对齐**：把加法结果寄存一拍后，它出现的时间点正好和「打了一拍的 `S`（`S_1d）」、打了一拍的输入（`r_A_1d / r_C_1d`）对齐」，于是输出端的三选一多路器就能在正确的拍上选到正确的数据。

#### 4.2.2 核心流程

加减结果的产生流程（伪代码）：

```
每个时钟上升沿：
    if (rst) 清零 r_x_added / r_x_subtracted
    else if (S == 1 && enable):
        r_x_added_real      <= A_real + C_real    // 上支求和
        r_x_added_img       <= A_img  + C_img
        r_x_subtracted_real <= C_real - A_real    // 下支求差
        r_x_subtracted_img  <= C_img  - A_img
    else:
        保持原值不变（hold）
```

也就是说，「求和」「求差」不是立即出现在输出端的，而是**先被写进寄存器，下一拍才可被读取**。这就是「打一拍」。

#### 4.2.3 源码精读

实部求和的寄存（虚部完全对称，不再贴）：

[src/butterfly.v:L61-L71](https://github.com/guanjiess/fpga-fft/blob/411062734ac2bdc2d08968c639bb7bec630a9e10/src/butterfly.v#L61-L71) —— 当 `S==1 && enable` 时把 `A_real + C_real` 锁进 `r_x_added_real`；否则保持不变。`rst==1` 时清零。

实部求差的寄存：

[src/butterfly.v:L85-L95](https://github.com/guanjiess/fpga-fft/blob/411062734ac2bdc2d08968c639bb7bec630a9e10/src/butterfly.v#L85-L95) —— 当 `S==1 && enable` 时把 `C_real - A_real` 锁进 `r_x_subtracted_real`。

虚部两个寄存器 `r_x_added_img`、`r_x_subtracted_img` 结构完全一样，分别在第 73–83 行和第 97–107 行。一句话总结：**四个寄存器（实部和、虚部和、实部差、虚部差）只在 `S==1 && enable` 的那一拍被更新**，其余时间冻结。

第 30 行那条被乱码遮住的注释，原意是：「加减运算需要一个时钟，所以需要对 A、C 的数据各留一个备份（打一拍）」。这正好对应下一节的 `r_A_1d / r_C_1d`。

#### 4.2.4 代码实践（源码阅读型 + 跟踪）

1. **目标**：亲眼确认「加法结果比输入晚一拍出现」。
2. **步骤**：在 `src/butterfly.v` 的第 66 行 `r_x_added_real <= A_real + C_real;` 这一拍想象一个时刻 `T`：此刻 `S==1, enable==1`，输入 `A_real=10, C_real=6`。
3. **观察**：在时刻 `T` 这一拍里，`r_x_added_real` 的「当前值」还是上一拍算出来的旧值；而 `10+6=16` 要等到**下一个时钟上升沿（时刻 `T+1`）**才会出现在 `r_x_added_real` 里。
4. **预期结果**：你应当能口算出——`T` 拍输入 10 和 6，`T+1` 拍 `r_x_added_real` 变成 16、`r_x_subtracted_real` 变成 `6-10=-4`（注意是 `C-A`）。
5. 待本地验证：如有仿真器（如 Vivado/IVERilog/GtkWave），可把 `r_x_added_real` 加进波形窗口观察这一拍的延迟。

#### 4.2.5 小练习与答案

**练习 1**：`S==1 && enable` 这一拍写入的 `r_x_added_real`，是在这一拍就生效，还是下一拍生效？为什么？
**答案**：下一拍生效。因为用的是非阻塞赋值 `<=`，右侧表达式 `A_real + C_real` 在时钟上升沿被求值并调度，但赋值结果要到该上升沿之后（即下一拍）才在 `r_x_added_real` 上稳定。

**练习 2**：如果连续多拍 `S` 都保持为 1、`enable` 也为 1，`r_x_added_real` 会被反复刷新，那会不会把还没来得及用的旧和覆盖掉？
**答案**：会刷新，但这正是期望行为。在 SDF 流水线里，蝶形是流水化工作的，每一拍 `S==1` 都对应一对新的输入样本，理应算出新的和。旧的「和」会在它被算出的那一拍（`S_1d==1` 那拍）被多路器选走送往下一级，之后就可以被新结果覆盖。

### 4.3 S_1d 延时对齐与 B/D 输出选择

#### 4.3.1 概念说明

上一节我们看到：加减结果被打了一拍，比输入晚一个时钟周期出现。但 `S` 信号本身是「当拍」的，如果输出端用当拍的 `S` 去选择「输出求和结果还是输出直通数据」，就会对不上——因为这一拍的 `S` 描述的是「现在该不该算」，而加减结果描述的是「上一拍算的东西」。

解决办法很优雅：**把 `S` 也打一拍**，记作 `S_1d`。这样 `S_1d` 表示的恰好是「上一拍该不该算」，正好和上一拍算出来的加减结果、以及打了一拍的输入 `r_A_1d / r_C_1d` 全部对齐到同一个时钟。于是输出端只要做一个简单的二选一：

- `S_1d == 1`（上一拍在计算）→ `B` 输出 `r_x_subtracted`（差），`D` 输出 `r_x_added`（和）。
- `S_1d == 0`（上一拍在直通）→ `B` 输出 `r_A_1d`（即上一拍的 A），`D` 输出 `r_C_1d`（即上一拍的 C）。

这就是「计算结果」和「选择信号」的对齐技巧，是本讲最值得记住的设计点。

#### 4.3.2 核心流程

把输入、寄存器、输出串起来，逐拍看（设 `enable` 一直为 1，`rst` 已释放）：

| 拍号 | 输入 `S` | 输入 `A/C` | `S_1d`（=上一拍 S） | `r_A_1d/r_C_1d` | `r_x_added`（=上一拍和） | 输出 `B` | 输出 `D` |
|------|----------|------------|----------------------|------------------|---------------------------|----------|----------|
| T0   | 0        | a0 / c0    | —（初值）             | —                | —                         | —        | —        |
| T1   | 1        | a1 / c1    | 0（来自 T0）          | a0 / c0          | 旧值                      | **a0**（直通） | **c0**（直通） |
| T2   | 0        | a2 / c2    | 1（来自 T1）          | a1 / c1          | **a1+c1**                 | **c1−a1**（求差） | **a1+c1**（求和） |
| T3   | …        | …          | 0（来自 T2）          | a2 / c2          | …                         | **a2**（直通） | **c2**（直通） |

读这张表的诀窍：**任意一拍的 `S_1d`、`r_A_1d/r_C_1d`、`r_x_added/r_x_subtracted`，全部来自「上一拍的输入」**，所以它们天然同步；输出 `B/D` 只是在它们之间做二选一。

关键规律：

- 输入 `S=0` 的那一拍，**下一拍**输出走直通（`B=A`，`D=C`）。
- 输入 `S=1` 的那一拍，**下一拍**输出走计算（`B=C−A`，`D=A+C`）。
- 整个 `butterfly` 的**输入到输出延迟固定为 1 个时钟周期**。

把 `S` 和输入 A/C 各打一拍的三个小寄存器：

[src/butterfly.v:L51-L57](https://github.com/guanjiess/fpga-fft/blob/411062734ac2bdc2d08968c639bb7bec630a9e10/src/butterfly.v#L51-L57) —— `S_1d <= S`，把控制信号 `S` 也打一拍，用来做输出选择。

把 4.2 和 4.3 合起来，`butterfly` 的全貌就是：**`S` 决定「算不算」，加减结果与对齐用的 `S_1d`、`r_A_1d/r_C_1d` 一起被寄存一拍，输出端用 `S_1d` 在「直通」与「计算」两路之间二选一。**

#### 4.3.4 代码实践（本讲主实践——画时序图）

2. **操作步骤**：
   1. 准备一张纸或画图工具，横轴是时钟周期（T0, T1, T2, T3 …），每个周期画一个 `clk` 上升沿刻度。
   2. 设定输入：在 T0、T1、T2 三拍分别给 `S = 0, 1, 0`；给 `A_real = 10, 20, 30`，`C_real = 6, 8, 12`（`enable` 恒为 1，`rst` 恒为 0）。
   3. 逐拍推导内部寄存器：`S_1d`、`r_A_real_1d`、`r_C_real_1d`、`r_x_added_real`、`r_x_subtracted_real`（记住它们都比输入晚一拍）。
   4. 用 `assign` 公式算出 `B_real`、`D_real`。
3. **需要观察的现象**：`B_real / D_real` 相对 `S` 的变化**总是滞后一拍**；当 `S` 在 T1 拉高时，求和/求差结果要到 T2 才在输出端出现。
4. **预期结果**（参考答案，按下表逐格核对）：

   | 拍号 | `S` | `A_real` | `C_real` | `S_1d` | `r_x_added_real` | `r_x_subtracted_real` | `B_real` | `D_real` |
   |------|-----|----------|----------|--------|------------------|-----------------------|----------|----------|
   | T0   | 0   | 10       | 6        | 0（初值）| 0                | 0                     | 0        | 0        |
   | T1   | 1   | 20       | 8        | 0      | 0                | 0                     | **10**（直通 A_1d） | **6**（直通 C_1d） |
   | T2   | 0   | 30       | 12       | 1      | **28**（=20+8）  | **−12**（=8−20）      | **−12**（求差） | **28**（求和） |
   | T3   | …   | …        | …        | 0      | …                | …                     | **30**（直通） | **12**（直通） |

   在波形上用箭头标出：T1 的 `S` → T2 的 `S_1d`、T1 的输入 → T2 的 `r_*_1d / r_x_added / r_x_subtracted`，这就是「打一拍」的延迟。
5. 待本地验证：若想用仿真器确认，可临时写一个最小的 `butterfly_tb`，按上表喂激励，把 `S_1d / r_x_added_real / B_real / D_real` 加进波形窗比对。

#### 4.3.5 小练习与答案

**练习 1**：如果不把 `S` 打一拍（即输出选择直接用当拍的 `S`），会发生什么？
**答案**：会错位一拍。当拍的 `S` 描述的是「现在」，而加减结果描述的是「上一拍」，二者对不齐，会导致在错误的拍上把还没算好（或已被覆盖）的结果选出去，整个蝶形输出就错了。`S_1d` 的作用就是消除这一拍错位。

**练习 2**：`butterfly` 的输入到输出延迟是多少拍？哪条路径（直通 vs 计算）的延迟更长？
**答案**：两条路径都是 1 拍延迟。直通路径是 `A→r_A_1d→B`、`C→r_C_1d→D`；计算路径是 `(A,C)→r_x_added/r_x_subtracted→D/B`。二者都恰好经过一级寄存器，所以延迟相等，这正是用 `S_1d` 对齐后刻意达到的效果。

### 4.4 在 fft_2 中例化：最简的 SDF 蝶形复用

#### 4.4.1 概念说明

`butterfly` 是个纯算子，光看它还不知道 `A` 和 `C` 从哪来、`S` 谁来翻转。`fft_2.v` 是「`butterfly` 最小的真实使用场景」：2 点 FFT 只需要一个蝶形，而且 2 点 FFT 的旋转因子 \(W_2^0 = 1\)，所以**连乘法器都省了**，直接例化一个 `butterfly` 就完事。看懂 `fft_2` 怎么用 `butterfly`，你就能推广到 `fft_4 / fft_8 / fft_16`（它们只是多接了延时 RAM 和旋转因子）。

#### 4.4.2 核心流程

`fft_2` 里和 `butterfly` 直接相关的三件事：

1. **`S2` 的翻转**：`fft_2` 用一个 1 位寄存器 `S2` 当 `S` 信号源，每个处理时钟 `S2 <= S2 + 1`，于是 `S2` 在 `0/1` 之间来回翻转，正好对应 `PERIOD = 2`（2 点 FFT 一个周期 2 拍：一拍直通、一拍计算）。
2. **`butterfly_enable`**：状态机在 `START / PROCESSING` 期间把 `butterfly_enable` 拉高，让蝶形真正工作；`END` 时拉低。
3. **例化连线**：`fft_2` 把外部输入 `A_real/A_img` 接到蝶形的 `A` 口；把蝶形的 `B` 输出反馈回去当 `C` 口输入（经一级 `r_C_real` 寄存，实现 SDF 的「单路反馈」）；`D` 输出则直接当作本级的 `out_real2/out_img2`。

#### 4.4.3 源码精读

`S2` 的翻转逻辑（注意复位后 `S2` 初值为 1，之后每拍 `+1` 在 1 位寄存器上等效于来回翻转）：

[src/fft_2.v:L89-L99](https://github.com/guanjiess/fpga-fft/blob/411062734ac2bdc2d08968c639bb7bec630a9e10/src/fft_2.v#L89-L99) —— 在 `START/PROCESSING` 期间 `S2 <= S2 + 1`，制造出 0/1 交替的方波送给 `butterfly` 的 `S` 口。

`butterfly` 的例化（这是本讲把「算子」和「层级」连起来的关键代码）：

[src/fft_2.v:L147-L160](https://github.com/guanjiess/fpga-fft/blob/411062734ac2bdc2d08968c639bb7bec630a9e10/src/fft_2.v#L147-L160) —— 把 `S2` 接到 `S`、`butterfly_enable` 接到 `enable`、外部 `A_real/A_img` 接到 `A` 口；`C` 口接的是 `w_B_real/w_B_img`（即 B 输出的反馈，形成 SDF 单路反馈）；`D` 输出作为本级的 `out_real2/out_img2`。

第 128 行和第 155 行有两句注释，点出一个设计意图：在 2 点这一级，**不单独用 RAM 延时模块**，因为蝶形本身的加减寄存（打一拍）已经天然提供了所需的延时。换句话说，`butterfly` 内部那一级寄存器在 `fft_2` 里「兼任」了延时单元。

#### 4.4.4 代码实践（源码阅读型）

1. **目标**：在 `fft_2.v` 里把「`S2` 谁来翻、`A/C` 谁来喂、`D` 送到哪」三件事看明白。
2. **步骤**：打开 `src/fft_2.v`，跳到第 147–160 行的例化块，对照端口名逐一标注每个连接是「外部输入」「反馈」「还是输出」。
3. **观察**：你会看到 `C_real(w_B_real)` 而 `B_real(w_B_real)`——也就是说 `B` 输出和 `C` 输入接到了同一根线 `w_B_real`，这是 SDF 反馈的标志特征。
4. **预期结果**：能用一句话描述 `fft_2` 的工作方式——「`S2` 每 2 拍翻转一次，蝶形在一拍直通把第一个样本存住、在下一拍把它和第二个样本做加减，`D` 输出求和结果作为本级输出」。
5. 待本地验证：进阶读者可对照 `tb/` 下的 testbench，看仿真激励是如何给 `start2` 和 `A_real` 的，进一步印证上述流程。

#### 4.4.5 小练习与答案

**练习 1**：为什么 `fft_2` 里没有像 `fft_16` 那样例化一个 `delay` 模块？
**答案**：因为 2 点 FFT 的延时深度只有 1（只需要把第一个样本存 1 拍），而 `butterfly` 内部把输入打一拍的 `r_A_1d / r_C_1d` 以及加减寄存器本身已经提供了这 1 拍延时，所以注释里说「加减运算实质上充当了 delay 模块」，不必再单独加 RAM 延时。点数更大的级（如 `fft_16` 用 `layer=4`）延时深度是 \(2^{layer-1}\)，寄存器存不下，才必须改用 RAM。

**练习 2**：`fft_2` 复位后 `S2` 的初值是 0 还是 1？这对第一拍蝶形是直通还是计算有影响吗？
**答案**：初值是 1（见 `src/fft_2.v` 第 91 行 `S2 <= 1`）。这意味着复位后进入处理态的第一拍 `S2=1`，但真正进蝶形的 `S` 还要看 `S2` 在 `STATE_START` 的那一拍是几。结合 `butterfly` 的打一拍特性，初值的细微差别只会平移输出一个周期，不影响最终 2 点 FFT 的正确性，因为它最终会把两个样本都处理完。

## 5. 综合实践

把本讲三块知识（端口与数学含义、加减打拍、`S_1d` 对齐）串成一个小任务。

**任务**：用一张图把 `butterfly.v` 的完整数据通路画出来，并标注每个「打拍」位置，然后回答两个问题。

1. **画数据通路图**：
   - 画出 `A_real`（以及对称的 `A_img`、`C_real`、`C_img`）进入模块后的两条路径：
     - 直通路：`A_real → [寄存器 r_A_real_1d] → 多路器 → B_real`；`C_real → [寄存器 r_C_real_1d] → 多路器 → D_real`。
     - 计算路：`(A_real, C_real) → [加减法器] → [寄存器 r_x_added_real / r_x_subtracted_real] → 多路器 → D_real / B_real`。
   - 在每一个 `[寄存器]` 框上标「+1 拍」。
   - 画出 `S → [寄存器 S_1d] → 多路器选择端`，并标「+1 拍」。
   - 用一句话在图边写明：多路器由 `S_1d` 选择，`S_1d=0` 走直通、`S_1d=1` 走计算结果。

2. **回答**：
   - 为什么直通路和计算路的延迟必须设计成一样（都是 1 拍）？提示：想一想下游模块（延时 RAM、乘法器）希望 `B/D` 以什么样的节拍稳定输出。
   - 如果把加法器改成纯组合逻辑（不寄存 `r_x_added`），`S_1d`、`r_A_1d` 还需要存在吗？整个 `butterfly` 的延迟会变成多少？

**参考答案要点**：
- 直通与计算两路延迟一致，下游才能不区分「这拍的数据是直通来的还是算出来的」，统一按 1 拍节拍接收，简化级间时序。
- 若加法改组合逻辑，则计算路变 0 拍、直通路仍是 1 拍，两路不再对齐；此时 `S_1d`、`r_A_1d/r_C_1d` 都得相应调整（要么也删掉直通那拍、要么把 `S` 改回当拍），整个模块的延迟会从 1 拍降到 0 拍，但关键路径会变长、最高时钟频率下降。作者选择「两边都打一拍」是为了用 1 拍延迟换取更短的组合路径。

## 6. 本讲小结

- `butterfly.v` 是一个 DIF radix-2 蝶形的加减核心：`D = A + C`（上支求和）、`B = C - A`（下支求差），下支后续再乘旋转因子。
- 它由 `S` 信号在「直通（`S=0`）」和「计算（`S=1 && enable`）」之间切换：直通时 `B=A`、`D=C`；计算时 `B=C-A`、`D=A+C`。
- 加减结果用 `r_x_added / r_x_subtracted` 寄存一拍，既是为了时序收敛（切断长组合路径），也是为了与对齐信号同步。
- `S_1d`（`S` 打一拍）和 `r_A_1d / r_C_1d`（输入打一拍）把「选择信号」「直通数据」「计算结果」三者对齐到同一拍，使输出端的二选一能正确工作。
- 整个 `butterfly` 的输入到输出延迟固定为 1 个时钟周期；直通与计算两条路径延迟相等。
- `fft_2.v` 是 `butterfly` 最简的真实用例：`S2` 每拍翻转产生 `S`，`B` 输出反馈成 `C` 输入形成 SDF 单路反馈，且因 2 点旋转因子为 1 而省去了乘法器。
