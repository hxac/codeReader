本讲揭示这套 FFT 无法「拿来即跑」的根因：源码里直接例化了五类厂商 IP——`mult2`（DSP 乘法器）、`Delay`（双口 RAM）、`rotator_<N>_real/img`（旋转因子 ROM）、`blk_mem_gen_0`（块存储）、`addr_ctrl`（地址控制器），它们的实现不随源码提供，必须用目标平台工具重新生成。`delay.v` 与 `Rotator16.v` 同时保留 Anlogic（注释）与 Xilinx（启用）两套例化，端口对照为 `dia/dina`、`cea/wea`、`dob/doutb`、`doa/douta`；作者刻意让两套 RAM 同名 `Delay` 以解耦，但端口名未统一，且注释版残留复制粘贴 bug（误用 `r_addrb`），切回 Anlogic 必须修正。最隐蔽的移植陷阱是 `HALT_FOR_NEXT_LAYER` 的 offset：Anlogic 用 `-2`、Vivado 用 `-3`，差额精确对应两家 ROM 读延迟之差（README 注明 Xilinx ROM 读延迟 2 拍），且该 offset 散落于 `butterfly_general.v` 与 `fft_4/8/16` 多处。移植三步走：重新生成全部 IP 并对齐端口与流水线延迟、修正注释版笔误、按新平台 ROM 实测读延迟重校 offset，最后用 MATLAB 黄金参考仿真验证。引入的关键术语：厂商锁定、IP 核、ROM 读延迟、`HALT_FOR_NEXT_LAYER` offset、双平台端口映射。
