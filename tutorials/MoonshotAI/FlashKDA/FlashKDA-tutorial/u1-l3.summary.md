本讲解决从零构建并验证 FlashKDA 的工程问题。流程：clone 后拉取 CUTLASS submodule，再 pip install --no-build-isolation——构建需 import torch，隔离环境必败；setup.py 首行自动拉取 submodule 兜底，CUTLASS 为 header-only 库，仅编译期需其头文件。CUDAExtension 产物 flash_kda_C 只有 host 侧 flash_kda.cpp 与唯一 .cu 文件 fwd_launch.cu 两个编译单元，K1/K2 两个 kernel 以 .cuh 实现头形式汇入同一翻译单元。FLASH_KDA_CUDA_ARCHS 分 auto/all/列表三种模式，目标架构 90a/100a/103a/120a，a 后缀是启用 TMA/GMMA 专有指令的硬性要求，产物只嵌 cubin、不嵌 PTX。nvcc 选项各司其职：-U__CUDA_NO_* 恢复 half/bf16 运算，--expt-relaxed-constexpr 支撑 CuTe 元编程，--use_fast_math 与 bit-exact 数值设计绑定，--ptxas-options=-v 报告寄存器与 smem，-lineinfo 服务 ncu。tests/test.sh 三步：可编辑安装、装 fla（fp64 金标）与 matplotlib、跑以 torch.equal 为标准的 exact match 测试；改 csrc 代码需重装。可选 setup_clangd.sh 配 IDE 跳转。关键术语：flash_kda_C（Python 与 CUDA 层的边界，u1-l4 调用链的起点）、K1/K2 kernel、bit-exact、可编辑安装。
