本讲剖析 FlashKDA 前向两个 kernel 之间的 workspace 契约。K1（prepare）按 (tile, head) 写出六个中间分量：k_decayed、q_decayed、k_restored（各 [16,128] bf16）、g_total（[128] fp32）、INV 与 Mqk（各 [16,16] bf16），共 13824 字节/tile，构成六段 128 字节对齐的分离数组；total_tiles 分分配与启动两个口径，但两个 kernel 拿到同一标量。两侧共用寻址公式 ws_idx = head×total_tiles + tile：K1 写侧 tile 为全局 tile 号，K2 读侧为 tile_base+t（varlen 下由线性扫 cu_seqlens 求得，与 K1 的 tile_prefix 二分结果一致），加上同一批 gmem 张量与同一套 TMA swizzle 布局类型，保证「K1 写下的比特即 K2 读到的比特」（位一致契约）。K1 由线程 0 发起六次 TMA store，前置 fence_view_async_shared 代理围栏、后置 tma_store_arrive/wait 收尾；K2 的 LOAD warp 在 3 级流水线中每 stage 以一个事务 barrier 聚合 8 份拷贝（v、beta 加六个分量，共 17984 字节）。最后讲 SharedStorageK1 以 Phase A/Phase B 生命周期不相交的 union 复用省约 14 KB smem，并以 __launch_bounds__(256,8) 把寄存器压到每线程 32 个、换 8 CTA/SM 满占用。
