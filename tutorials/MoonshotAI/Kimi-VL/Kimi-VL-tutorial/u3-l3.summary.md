本讲承接 u3-l2 离线推理，用 vllm serve 把 Kimi-VL 从进程内对象变为常驻 HTTP 服务（默认 8000 端口），暴露 OpenAI 兼容的 /v1/chat/completions 路由，openai SDK 只需改 base_url 即可接入。核心模块三块：一是启动参数：--served-model-name 实现部署名与仓库名解耦（换模型客户端零改动），--trust-remote-code 放行 HF 仓库自定义代码，另有张量并行、单步批量、单请求长度与图片数上限；二是图像编码调用链：PIL 转 RGB、JPEG 内存编码、base64（体积膨胀约 4/3）拼 data URL，以 image_url 分片放进 messages，服务端代劳解码、客户端直接拿文本；三是调优权衡：max-model-len 卡单请求总 token、limit-mm-per-prompt 卡图片张数、max-num-batched-tokens 卡引擎单步批量，三道闸门独立把关；视觉 token 约为像素数÷196÷4，调大上限以 KV cache 与并发能力为代价，官方建议长上下文场景提到 131072、多图场景提到 image=256。
