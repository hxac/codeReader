本讲介绍 vLLM 离线批量推理：在 Python 进程内直接调用引擎、不起网络服务（区别于下一讲的服务化形态）。核心结论是分工模式「transformers 出模板、vLLM 出算力」：AutoProcessor 与 apply_chat_template 原样保留，负责渲染带图像占位符的文本；生成侧换成 vllm.LLM 与 llm.generate。输入从「张量对」变为请求字典：prompt 键放渲染文本，multi_modal_data 键放原始 PIL 图像，编码与占位符对齐移交引擎内部，但两者数量与顺序一致的硬约束不变。采样参数移入独立的 SamplingParams 对象（max_new_tokens 改名 max_tokens），输出直接是纯生成文本，无需裁剪与解码。llm.generate 接收请求字典列表，一次调用由引擎内部调度批量生成，这是高吞吐的来源；vllm 不在 requirements.txt 中，需单独安装。
