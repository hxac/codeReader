本讲打开 async_finish 黑盒，聚焦 Buffer 的两个模块：通信流管理与异步握手路径。Buffer 创建唯一一条高优先级通信流（priority 默认 -1），由 dispatch、prefetch_weight、combine、reduce_grad 四个 API 共享；所有 launch_* 均取当前流发射，故 with torch.cuda.stream(comm) 是内核路由的唯一开关。异步分支遵循五步握手：对全部涉及张量 record_stream，主流 record_event，通信流 wait_event，进流上下文发射内核并 record_event，返回 done 事件，调用方须 wait 后才能读输出。record_stream 声明「主流分配、通信流使用」的分配器生命周期，漏掉将埋下偶发错数竞态；共享一条流以流序换取 meta_buf 屏障等共享资源的互斥，是正确性而非偷懒。调度旋钮含 num_sms（默认 32）、num_sms_dedup（默认满卡，由环境变量 MOONEP_NUM_SMS_DEDUP 覆盖）、enable_pdl 与 comm_stream_priority。destroy 须先同步通信流与设备、再 dist.barrier、最后解除 VMM 映射。
