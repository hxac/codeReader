本讲精读 moonep/dispatch.py 的 DispatchKernel 设备内核与 launch_dispatch 宿主封装。核心结论：dispatch 内核采用 warp 特化分工——warp 0 为 G2S 生产者、warp 1 为 S2G 消费者、warp 2 零填充、warp 3..6 去重构建（仅新鲜规划路径编译保留）；grid 取 num_sms 并以 cooperative 模式启动。数据通路是「按行 TMA + mbarrier」多阶段流水线：smem 按 stages 环形分份，生产者 acquire 后发 cp.async.bulk，消费者等 full、逐 k 解码 dst，非负才 S2G 直写远端对称内存并散射权重，延迟 stages−1 个 token 才 release；深度由 _smem_bytes/_pick_stages 按设备 smem 预算自动选档。负 dst 条目经 -dst-1 还原后只散射权重不拷 payload，重复槽由 dispatch_epilogue 在接收端补齐。内核退出经 cross_rank_barrier（grid 栅障加跨 rank 原子握手与两道 proxy fence）发布数据，再按 pdl_trigger 放行 epilogue；宿主侧含三组校验、lru_cache 编译缓存与 int32 权重位拷贝。零填充与去重构建 warp 的内部细节留待 u4-l3。
