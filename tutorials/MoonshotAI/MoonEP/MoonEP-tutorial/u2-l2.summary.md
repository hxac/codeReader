本讲剖析 MoonEP 通信缓冲的地基：nvl_shared_buffer.cuh、bindings.cu 与 buffer.py（经 pybind11 导出为 moonep._C）。核心是 CUDA VMM 分配-映射两步模型：cuMemCreate 分配可导出的物理显存，Reserve/Map/SetAccess 搭建并授权虚拟地址；nvl_dist_alloc 封装此流程，返回 keepalive、shareable 句柄与 owned handle。VMM 大小必须对齐粒度（取 fd 与 fabric 两类句柄粒度的最大值），Python 侧 pad_dim0_for_alignment 只补第 0 维完成对齐，nvl_dist_map 会拒绝未对齐形状。nvl_dist_map 把各 rank 的句柄按 rank 顺序映射成布局完全一致的连续虚拟地址，构成对称内存：第 r 段物理上就驻留在 rank r 的 GPU 上，所有段对本设备可写，dispatch 内核可经 NVLink 直写远端接收区，这是零拷贝的物理基础。owned handle 因多播绑定需要而延迟释放。句柄跨进程分发与多播视图分别留给 u2-l3、u2-l4。
