本讲解析仓库测试体系：gpu marker(注册于 pyproject.toml)把测试分成两层——需多卡 torchrun 的 GPU 端到端层，与 CI 用 `-m "not gpu"` 把守的纯 CPU 单元层。test_update.py 是自举(bootstrap)结构：pytest 函数只是发射台，由 subprocess 拉起 torchrun 回头执行同文件的 `__main__` 分支，并借 PYTEST_CURRENT_TEST 检查拒绝直接 torchrun。端到端策略是「真协议栈+假业务逻辑」：checker 子进程复用真实的 update_weights_from_ipc,仅把 run/post_hook 两个注入点换成逐张量比对与 synchronize 来顶替 vLLM;req_func 由跨进程队列 queue.put 充当，以 None 为毒丸终止；错误注入用例同时锁死协议两端的消息契约，混合文件输入则压测三条加载路径。CPU 层引入两种测试替身(test double)范式：MagicMock 加 TestClient 的严格往返校验(test_api.py),与 `ParameterServer.__new__` 跳过 `__init__` 再装配 SimpleNamespace、以 assert_not_called 守住「守卫先于副作用」(test_p2p_guard.py)。仓库惯例：文件头 docstring 声明测试边界，硬件用例响亮失败而非静默跳过。
