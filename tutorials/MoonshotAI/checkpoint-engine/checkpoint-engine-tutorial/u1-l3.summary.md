本讲绘制 checkpoint-engine 的代码地图，核心结论：目录结构是部署结构的投影，同一主包分别活在训练侧与推理引擎两个进程里。ps.py 是服务端总装车间，ParameterServer 只编排「注册→收集→更新→注销」生命周期，加载锁页、IPC 句柄、集合通信等底层能力下放给 pin_memory、ipc_handler、distributed、p2p_store 等模块；worker.py 是消费端镜像，以 REP 状态机按「ipc 句柄、张量列表、两次 None、Exception」四类消息完成 attach、装载、释放、收尾，因依赖 vLLM 必须独立成文件。两侧真正共享的只有 data_types(消息语言)、device_utils(硬件抽象)与 ipc_handler(IPC 契约)。__init__.py 是纯门面，用 __all__ 声明公共 API，一次 import 即拉起除可选依赖外的整个代码图；mooncake、vLLM、XPU 扩展等可选依赖全靠延迟导入隔离。结构分析用 git ls-files、wc -l、inspect、grep 即可，纯 CPU 环境可完成。
