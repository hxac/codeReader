本讲精读 `ps.py` 中 update 广播主流程的四个函数。`update` 是纯编排：临时进程组按轮建毁（PrefixStore 前缀防 TCPStore 键冲突），`store_based_barrier` 经 TCPStore 做不依赖进程组的全局会合，finally 按 LIFO 次序拆组。`_detect_bucket_size` 用一次 all_reduce(MIN) 同时取集群最小空闲显存与最大 ZMQ 计数器，预算为 free/3（h2d_buffer 占 1 个桶 + 双缓冲占 2 个桶）或显存不足时回退 free/2，桶大小还须装下最大单张量。`_copy_to_buffer` 有两种来源：owner 在本地则从锁页内存异步 H2D，在远端则聚合为一次批量 RDMA 读。核心的 `_update_per_bucket` 是四拍循环：预取 H2D、装填半区并广播、等 worker ACK、发张量清单；gidx%2 双缓冲使「写第 gidx 步」与「worker 装载第 gidx-1 步」跨进程重叠，h2d_buffer 让各 rank 的 H2D 并行且离开广播链关键路径；`dist.broadcast` 以 receiver_rank 为源，是数据持有者反当广播源的倒置设计。错误传播：worker 把异常以文本回传，ret_code 经全体约减投票，双向下发 RuntimeError，保证全集群一致提前退出。收尾按固定次序释放：views → base → gc → ipc_collect → empty_cache → 两次 None（worker 释放资源 / 执行 post_hook）→ barrier → 关 socket → P2P 注销。关键术语：桶（bucket）、四拍循环、gidx、双缓冲、h2d_buffer、倒置广播源、错误传播链。
