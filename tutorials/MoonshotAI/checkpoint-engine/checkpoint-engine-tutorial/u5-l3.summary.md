本讲精读 `vllm_nccl.py` 与 `vllm_compat.py`。核心结论：colocated 部署下 PS 与 vLLM 同进程，不能占用 torch 全局进程组，`DistributedNccl` 后端改用 vLLM 的 `StatelessProcessGroup`(TCPStore 会合)与 `PyNcclCommunicator`(裸 NCCL)绕开;`create_stateless_process_group` 用 `inspect.signature` 探测形参以兼容新旧 vLLM 构造签名。模块在 import 时用 ctypes 给 `NCCLLibrary` 追加 `ncclCommSplit` 声明并挂方法，借 color(0 加入 / -1 不加入)与 key(取全局 rank,组内升序编号)把 ranks 列表切成子通信组；组外进程得 NULL 通信器，仅成员获得 `CommGroup`。`_use_group` 上下文管理器临时换 `pynccl.comm` 并把全局 src 与自身 rank 经 `ranks.index()` 重映射为子组编号，finally 对称恢复，是带组 broadcast 正确的前提。各集合操作遵循「换组→发起→流同步」骨架；barrier 用零张量 all_reduce 模拟，backend/timeout 被 `**kwargs` 吞掉。
