本讲精读 worker.py 中不依赖 vLLM 的三个模块：取货单类型 FlattenedTensorMetadata、_extract_weights 与 update_weights_from_ipc。核心结论：worker 是由 PS 消息驱动的 REP 状态机（PS 侧 REQ bind，worker connect），四类 payload 中 list 装载一桶、Exception 强制退出、第一个 None 释放 IPC 资源、第二个 None 执行 post_hook，布尔标志 released 区分两个 None。取货单的 offset 是含双缓冲半区基址（gidx%2×bucket_size）的绝对偏移，按 aligned_size（256 对齐）累计；_extract_weights 用「字节切片 → view(dtype) → view(shape)」三步零拷贝还原张量，size 取真实字节数、跳过 padding。每桶 b"" ACK 在 synchronize 后发出，兼作双缓冲背压；两次 None 之间隔着 PS 侧清理以腾显存。worker 本地出错只回传 traceback 文本而不 raise，由 PS 经 all_reduce 投票统一下发 RuntimeError，实现全集群一致退出，finally 幂等兜底清理。设备层依赖仅 DeviceManager 与 IPC 句柄两个接缝，可在纯 CPU 上用替身完整驱动；run/post_hook 的生产实现（vLLM load_weights、process_weights_after_loading）留待 u4-l2 承接。
