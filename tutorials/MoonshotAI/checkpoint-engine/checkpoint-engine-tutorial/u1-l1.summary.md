本讲是全手册第一讲，只涉及 README、ParameterServer、Broadcast、P2P 四个模块。核心结论：checkpoint-engine 是夹在 RL 训练侧与推理引擎（vLLM/SGLang）之间的轻量级权重更新中间件，不做训练与推理，只负责把新权重高效热更新进推理引擎；Kimi-K2（1 万亿参数、数千 GPU）量级下更新约 20 秒。核心逻辑集中在 ParameterServer 类，生命周期为 register_checkpoint → gather_metas → update → unregister_checkpoint，update 必须在 gather_metas 之后调用。两种更新方式共用入口 `_update_per_bucket`，由 ranks 参数分流：Broadcast（ranks 为 None 或空列表）是默认最快方式，将传输组织成 H2D → broadcast → reload 三阶段流水线，靠 2 倍桶大小的双缓冲重叠通信与拷贝，显存不足时退化为串行；P2P（ranks 指定）面向实例重启与弹性扩容，经 mooncake-transfer-engine 走 RDMA 点对点传输，不打扰存量实例。本讲引入的关键术语包括：RL 训练循环、推理引擎、checkpoint、H2D、锁页内存、CUDA IPC、RDMA、colocated 与 disaggregated 部署、中间件，以及 bucket（桶）与 bucket 大小上限（默认 8GB）。硬件支持 CUDA/NPU/XPU 三条路径，P2P 在 XPU 上不可用；安装分基础包与 [p2p] extra 两种形态。
