本讲精读昇腾 NPU 通信后端 vllm_hccl.py，与 CUDA 路径逐段对照。四个模块：用 ctypes 复刻 18 字段的 HcclCommConfig 结构体，以 size/magic_word/version 三件套做 ABI 版本协商，0xFFFFFFFF/-1 哨兵表示「用库默认」；import 期给 vllm_ascend 的 HCCLLibrary 动态补上 HcclAllGather 与 HcclCreateSubCommConfig 两个绑定；PyHcclCommunicatorEx 的 create_subcomm 负责切子组；DistributedHccl 适配器实现八个操作。核心结论：HCCL 切子组仅由成员调用，组内编号由 Python 侧 ranks.sort() 后 ranks.index(self.rank) 算出，等价于 NCCL 的 color/key 集体语义；subcomm_id 计数器显式区分同父多次切组；广播依赖 _use_group「换子组通信器＋全局 src 重映射为组内编号」，与 CUDA 路径逐字相同。NPU 上默认走 TorchBackend，仅 vLLM colocated 部署需切换到本后端。部署要点：版本矩阵钉死、Transfer Engine（ascend_direct 协议）须源码编译、HCCL 与 HIXL 同占 16666 端口须用 ranktable 分配 device_port，ASCEND_RT_VISIBLE_DEVICES 影响 P2P 校验。
