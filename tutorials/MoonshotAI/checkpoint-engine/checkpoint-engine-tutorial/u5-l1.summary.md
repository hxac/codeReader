本讲精读全项目唯一的硬件入口 DeviceManager（device_utils.py）：状态仅 device_type 与 device_module 两字段，构造时按 npu、xpu、cuda 顺序探测，全不可用即抛 TypeError，且 device_type 字符串可直接作 torch 设备名。核心结论是两张映射表：属性 backend 把设备类型译成通信后端 npu→hccl、xpu→xccl、cuda→nccl，由 ps.py 建进程组时消费；属性 transfer_engine_protocol 译成传输协议 npu→ascend_direct，cuda/xpu 为 rdma 或 efa（由 has_efa_pci 读 sysfs 网卡 vendor 判定），由 p2p_store.py 初始化 mooncake 引擎时消费。三个能力开关 supports_inplace_pin、supports_device_ipc、supports_device_p2p：原地锁页仅 CUDA；XPU 的 IPC 委托 xpu_ipc.is_available 运行时探测；P2P 排除 XPU。违反时分软降级（锁页回落 normal pin）、入口硬失败、构造期跳过加使用期硬失败三种哲学。清理原语 ipc_collect 与 host_empty_cache 按后端分岔（如 XPU 前者为 no-op）。测试用 DeviceManager.__new__ 加 SimpleNamespace 替身即可纯 CPU 验证。
