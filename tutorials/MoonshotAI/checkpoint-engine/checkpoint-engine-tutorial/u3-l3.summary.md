本讲覆盖 ParameterServer 生命周期「收集」阶段的四个模块：DataToGather 数据模型、gather_metas 主流程、get_metas 导出、load_metas 导入。核心结论：gather_metas 用 all_gather_object 在控制面只交换元数据（每块锁页 buffer 的参数清单、ptr、size，加 p2p_store_addr、host_ip、device_uuid、rdma_device 寻址字段），不搬 TB 级权重本体；产出以 owner_rank 为键的全局参数表 _current_global_parameter_metas（空注册 rank 不入表、不能当 owner，但仍在拓扑里可当 receiver）、「网卡名@主机IP → rank 集合」的 RDMA 拓扑 _local_rdma_devices，以及仅首次填充的 _all_hosts 与 _global_device_uuids。gather 末尾默认收发双方同拓扑；get_metas 返回内部引用，经 GET /v1/metas 或 rank 0 的 JSON 文件导出；load_metas 用外部 metas 整体替换全局表并重建远端拓扑（不动 local），是 join 复用模式的元数据入口，且须在每次 gather 之后调用。
