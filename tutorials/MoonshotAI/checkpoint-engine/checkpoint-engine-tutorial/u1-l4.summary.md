本讲把 checkpoint-engine 的静态文件地图升级为动态数据流图：一次 Broadcast 更新是 `_update_per_bucket` 编排的三阶段流水线——H2D（锁页内存异步预取到 h2d_buffer）、broadcast（D2D 写入 IPC 双缓冲半区后 dist.broadcast）、reload（worker 按元数据零拷贝切张量并 load_weights）。gidx%2 双缓冲使相邻桶的广播与 reload 重叠，h2d_buffer 使 H2D 与广播重叠，代价是 3×bucket_size 显存；当最大单张量超过全集群最小空闲显存的 1/3 时退化为串行（省一份桶显存、上限放宽到 free/2），连 free/2 也装不下则报错。worker 的 update_weights_from_ipc 是 ZMQ REP 状态机：list 装载、Exception 退出、首个 None 释放 IPC、第二个 None 执行 post_hook；出错只回传文本，由 PS 经 ret_code 约减统一下发异常。P2P 更新（ranks 非空）与 Broadcast 共用同一骨架，仅把 H2D 换成 Mooncake RDMA 远端读，服务动态扩容场景。引入术语：锁页内存、H2D、双缓冲、桶、IPC 句柄、REQ/REP、post_hook。
