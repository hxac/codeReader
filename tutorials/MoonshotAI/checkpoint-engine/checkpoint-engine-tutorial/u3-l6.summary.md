本讲把广播更新中 PS（REQ）与 worker（REP）放到同一条 ZMQ 消息线上对齐，覆盖 `_bind_zmq_socket`、`req_func`、`update_weights_from_ipc` 与 `_extract_weights` 等模块。核心结论：地址 `ipc://@checkpoint-engine-<设备UUID>-<计数器>.sock` 走 Linux 抽象 Unix domain socket，不落文件、免清理；计数器借一次 all_reduce 取负捎带、全局取 max 对齐，因为地址清单由组首拼装却须覆盖各 rank 实际 bind 的地址；REQ/REP 严格交替构成协议骨架，错序即报错。消息共五类：自描述 IPC 句柄、含绝对 offset（带 `gidx % 2` 双缓冲半区基址）的张量清单、`b""` 与堆栈文本构成的 ACK 通道、两个 `None`（第一个释放 IPC 资源、第二个执行 post_hook）、`RuntimeError` 实例强制退出。worker 是 `released` 标志驱动的 REP 状态机：本地失败只回文本不退出，退出指令由 PS 经 ret_code 全体约减后统一下发，保证全集群同生共死。关键概念：抽象 UDS、设备 UUID 寻址、控制面走 HTTP、数据面走 ZMQ 加设备 IPC。
