本讲剖析 pin_memory.py 的 checkpoint 加载链路（纯 CPU 可复现），含四个最小模块。`_align_size` 把张量字节数向上取整到 256 的倍数，定义张量在扁平 uint8 缓冲区中的“对齐槽位”。`_load_checkpoint_file` 是单文件加载器，按后缀分发：safetensors 经 safe_open 零拷贝读取、tp_concat_dim 恒为 -1；废弃的 npy 走“多数组流 + .meta pickle 侧车”，tp_rank 由文件名解析；两者产出统一的 FileMeta 五键元信息。`_concat_tp_weights` 三规则：concat_dim 为 -1 时取第 0 份（共享权重），单份原样返回，否则沿指定维 torch.cat 拼回完整张量。`_load_checkpoint` 跨文件把分片按参数名与 tp_rank 归位，以“最大 rank 加一”推断 tp_size，对拼接参数放大 shape 后整体重算 aligned_size，并做元数据与实际张量的对账自检，只返回张量字典。核心结论：safetensors 无法表达 TP 分片，同名参数只应出现在一个文件，否则被静默覆盖；该链路仅服务 normal pin 路径，inplace pin 路径另行手工解析文件头。关键术语：对齐槽位、共享权重、哨兵值 tp_concat_dim=-1（真实拼接维必须写非负下标）、tp_size、FileMeta。
