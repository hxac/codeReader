本讲围绕 examples/update.py 的 join()、ps 的 get_metas/load_metas 与 /v1/metas 端点讲解 join 复用机制：新拉起的推理实例不读 checkpoint 文件，凭旧实例导出的 metas（指针、大小、p2p_store_addr、rdma_device）以 RDMA 单边读直接从旧实例锁页内存拉取权重，旧实例只需进程存活、无需配合。metas 经互斥的文件通道（--save/--load-metas-file，rank 0 写 JSON）或 HTTP 通道（GET /v1/metas 配 --metas-url）交接，共用线格式 _METAS_ADAPTER。load_metas 定向改写：整体替换全局参数表，按「网卡名@主机IP」为键重建远端拓扑而不动本地拓扑，且必须在 gather_metas 之后调用（gather 会重置全局表）。join() 依次为：读 metas→建组→等 vLLM→barrier→空注册 gather→load_metas→P2P update；owner 与 receiver 分属新旧两个编号空间，仅靠共同拓扑键配对。「GET 字节==POST 可接受」往返契约由测试钉死，422 在路由前拦截且 PS 零副作用；UDS-only 部署与 httpx 的 TCP 错位要求 --metas-url 另备 HTTP 通路。
