本讲是正册收口，围绕四块最小模块展开：一、vllm_fp8.patch 补丁精读——FP8 量化权重热更新在 vLLM 上无法原生支持，根因是量化后处理 process_weights_after_loading 假设只冷启动跑一次，用新 Parameter 对象替换权重会改变数据指针、破坏已录制的 CUDA Graph（指针固化问题），并可能访问未建立的 scale 属性；补丁以 _wrap_parameter_or_copy 实现「已是 Parameter 就 copy_ 原地刷值保指针、首次才新建并迁移 weight_loader」，对 KV cache scale 用 create_weights 整体补建并以断言拒绝半建状态，使后处理可重入；补丁仅测过 DeepSeek-V3.1 与 Kimi-K2，上游化为 vLLM PR #24488。二、worker.py 的 update_weights_from_ipc 是引擎无关通用状态机，引擎依赖压缩为 run 与 post_hook 两个注入点，「中间件管协议、引擎管权重布局」。三、以 VllmColocateWorkerExtension 为范本提炼新框架接入五必要件：控制通道（如 collective_rpc，须引擎自建）、与 ps.py 逐字符一致的设备 UUID、load_weights 式装载入口、指针稳定的后处理钩子、冷启动 dummy 占位。四、项目边界：仅测试 vLLM/SGLang（SGLang 编排在自家仓库），论文的完美三阶段流水线未实现（当前为双缓冲两两重叠近似），XPU 无 P2P，vLLM 需含 collective_rpc。关键术语：指针稳定性、可重入、注入点、接入五必要件。
