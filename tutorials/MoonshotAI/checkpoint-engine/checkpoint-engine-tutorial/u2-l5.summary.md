本讲围绕 `use_shared_memory_pool=True` 选项讲解锁页内存跨 checkpoint 复用，覆盖 `ps.py` 的三个状态字段与注册/注销共享分支、`pin_memory.py` 内层函数 `register_pin_memory` 的复用分岔，以及 `MemoryBuffer` 这一复用最小单元。核心结论：保留键 `__shared_memory_pool__` 恒在 `_memory_pool` 中，空列表表示池尚未定型；`_current_shared_memory_pool_user` 空串表示无人使用，`_get_memory_pool` 三路分发让下游无感知。注册时强制单一使用者、强制关闭 inplace pin；复用条件是桶数量相同且逐桶字节数相等，metas 每轮重建、仅底层 buffer 被复用。注销分两种语义：非 force 只是「让位」（清使用者标记，池与 p2p 注册保留），force 才真正「释放」（删条目、重置空列表并 `host_empty_cache`）；让位后名字即失效，再 force 只得 not-found 警告。p2p store 仅在首次注册，且注册名恒为 `__shared_memory_pool__` 而与 checkpoint 名无关——地址不变则注册不变，远端按旧地址即可读到新权重，这也是后续 join 复用模式的物理基础。
