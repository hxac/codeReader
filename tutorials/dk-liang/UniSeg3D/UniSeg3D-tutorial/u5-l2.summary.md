本讲讲解 UniSeg3D 的稀疏匹配器与代价函数。核心结论：因查询直接采样自超点（「超点即查询」），`_select_queries` 生成的 `query_masks`（`sp_masks` 按存活查询的列子集）自带「查询归属哪个 GT」的先验，使匹配从 DETR 全局匈牙利匹配退化为每个 GT 独立的稀疏 top-k 选择，仓库中的 `linear_sum_assignment` import 仅是残留。三种代价函数：`QueryClassificationCost`（负 softmax 类别概率）、`MaskBCECost`（逐点 BCE 均值）、`MaskDiceCost`（整体重叠度），均经 einsum 一次算出 (n_queries, n_gts) 矩阵，配置权重 0.5/1.0/1.0；novel 伪掩码用的 `ov_matcher` 不含分类代价。`SparseMatcher` 两个技巧：inf 掩码（禁止组合代价置 1e8）与 topk+1 阈值（第 k 小值做严格小于筛选），天然处理允许数不足或为零的情形；返回一维对齐的 (query_ids, gt_ids)，`iter_matcher=True` 时解码器七份预测逐层重新匹配。超点「每列至多一个 True」使 base 匹配近似一对一，novel 与 base 的交叉由先 base 后 ov 两阶段规避。下一讲 u5-l3 将展开 `OVInstanceCriterion` 的 base/novel 双路损失。
