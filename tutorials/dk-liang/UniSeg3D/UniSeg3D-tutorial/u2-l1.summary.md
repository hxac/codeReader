本讲是全书的机制性地基，回答「配置字符串如何变成对象」。核心结论有三：其一，Registry 是「名字→类」的全局字典，build 取 cfg 的 type 查表、其余键全部作为 __init__ 参数，嵌套 dict 被逐层递归 build 成「骨干+解码器+语言分支+五路损失+匹配器」的完整模型对象图；其二，注册是 import 的副作用，@register_module() 装饰器在类定义那一刻执行，主配置的 custom_imports 让 mmengine 代为 import uniseg3d 包，import 链触发全仓库 29 个类进入 5 张注册表，注册粒度是模块而非导出名；其三，入口脚本只做读配置、回写命令行参数、Runner.from_cfg 后启动，Runner 负责总装模型、dataloader、优化器、hooks 与三个循环，训练循环在 before/after_train_iter 等固定时机回调 hook（日志、checkpoint、学习率调度）。另须注意 model 内与顶层两个同名 train_cfg 分别由模型和 Runner 消费。
