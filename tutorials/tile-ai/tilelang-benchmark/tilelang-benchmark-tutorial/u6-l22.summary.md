本讲讲 TileLang 两条调优入口与多内核组合。装饰器式用 `@autotune`+`@jit` 装饰全 `None` 形参的 `kernel()`，无参调用即触发搜索，返回字段更全的 `best_result`（含 `.kernel`）；显式式用 `AutoTuner.from_kernel(kernel, configs).set_compile_args(...).run(...)`，把「kernel 工厂」（返回 prim_func 的普通 Python 函数）与调优流程解耦，返回 `tune_result`（取 `.latency/.config`），其 `out_idx` 不在调优链上，需另用 `tilelang.compile(program, out_idx=...)` 固化可运行内核。关键术语：kernel 工厂、supply_type、多内核组合、条件返回。核心结论：一个工厂可定义多个 `@T.macro` 与多个 `@T.prim_func`，按 `num_split>1` 在 `main_split`（flash_attn_split+combine 两内核流水）与 `main_no_split`（单 flash_attn）间条件返回，两者保持相同参数签名以共用同一 `out_idx`；把 `num_split` 纳入搜索空间，使调优器在调 tile 尺寸的同时也调「要不要 split、切几段」这一结构决策，这正是显式 API 相对装饰器式的独特优势。
