本讲拆解编号 `1.triton-benchmark` 的 Triton fp16 GEMM 基线，分四个最小模块：搜索空间、网格映射、指针式内核主体、统一计时接口。搜索空间由 `@triton.autotune` 挂一组 `triton.Config` 显式列出，`key=['M','N','K']` 决定何时重新调优；其中 `BLOCK_SIZE_*` 进 kernel 作为 `tl.constexpr`，`num_warps`/`num_stages` 作编译器旋钮。内核经 `@triton.jit` 编译，每个 block 用 `tl.program_id` 取 pid，再按 **grouped pid** 映射到 C 子块——只改调度顺序不改数值，借此提升 L2 命中率。主体是"指针运算 + 块级原语"：传裸指针与 stride，用 `tl.load`/`tl.dot`/`tl.store` 完成「取 A、取 B、累加、写 C」，`tl.dot` 自动走 Tensor Core。计时统一交给 `triton.testing.do_bench`，入参为零参 lambda，返回**毫秒**级延迟，TFlops 按 `2MNK×1e-12/(ms×1e-3)` 换算。关键结论与术语：**单位陷阱**——Triton 输出 ms、TileLang 输出 (s)，措辞上 Triton 用 "Mean"（统计量）、TileLang 用 "Best"（autotune 最优），跨框架对比前必须统一；并提示读源码以代码为准（实际为 fp16 累加而非注释所述 fp32、日志文件名误写为 tilelang），为 u2-l7 的数据提取与第 3 单元 TileLang 声明式内核对照埋下伏笔。
