本讲承接 u5-l16 的 FlashAttention 四段 macro，专门解决因果注意力在 TileLang 内核中的落地，聚焦同一文件四处：`is_causal` 的传播、`MMA0` 的掩码写入、`main` 的 `loop_range` 裁剪、`Softmax` 里被注释的 `Check_inf`。

`is_causal` 是贯穿三处的开关：掩码、循环上界、FLOPS 折半。掩码机制利用 `T.gemm` 的累加语义，在 gemm 之前用 `T.if_then_else(q_idx >= k_idx, 0, -T.infinity(...))` 给分数块 `acc_s` 预置 0 或 \(-\infty\)，使屏蔽格累加后仍为 \(-\infty\)。关键术语是**绝对位置**：query 用 `bx*block_M + i + past_len`（`past_len = seq_kv - seq_q` 处理历史 KV），key 用 `k*block_N + j`。

`loop_range = min(全 KV 块数, ⌈(bx+1)·block_M/block_N⌉)` 按 query block 裁剪 KV 循环，跳过整块被掩码的 KV 块，方阵加 `block_M=block_N` 时退化为 `bx+1`，省约一半算功（注意此式不含 `past_len`，故仅适用于 prefill 方阵，不适用于解码）。

核心结论是 \(-\infty\) 经 `exp2` 自动归零的前提是行内 `scores_max` 有限；若整行 \(-\infty`，`scores_max=-∞` 触发 `exp2(NaN)` 污染 softmax。`Check_inf`（源自 FA3）把全 \(-\infty` 行的最大值归零来防御，但本配置下 `loop_range` 已保证无整行 \(-\infty`，故可注释；当 `block_M > block_N` 时则需启用。
