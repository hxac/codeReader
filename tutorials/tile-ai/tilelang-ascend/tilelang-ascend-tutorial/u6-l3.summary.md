本讲揭示 codegen 生成的 C++ 调用最终落在哪：`src/tl_templates/ascend/common.h` 与 `src/tl_templates/pto/common.h` 两个模板头文件是 codegen 与硬件之间最后一层 C++ 胶水。它们依赖三个来自 `gitcode.com/cann` 的 git 子模块——`catlass`（布局标签与搬运/计算模板）、`pto-isa`（`pto::Tile` 类型族与 `TASSIGN/TMOV/TMATMUL/TEXTRACT/TTRANS/TCMP` 指令宏）、`shmem`（OpenSHMEM 风格核间通信原语），JIT 时必须 `-I` 到这些头文件，否则生成代码无法编译。两条路线编程模型根本不同：ascendc 是对象模型，用 `LocalTensor/GlobalTensor` 隐藏地址、靠 `TileCopyTla` 按 `TPosition` 自动选 DMA（如 `copy_gm_to_l1` 落到 `DataCopyPad`、`mma` 落到 `Mmad`、`copy_l0c_to_gm` 落到 `Fixpipe`）；pto 是地址模型，用 `TASSIGN(tile,addr)` 显式绑定地址后直发指令宏（init/累加拆成 `TMATMUL`/`TMATMUL_ACC` 两条指令）。`T.gemm_v0` 模板内部即 `copy_l1_to_l0a/l0b`+`mma`+乒乓 flag 流水的封装。两个 `printf.h` 调试头亦分野：ascendc 包装 `AscendC::DumpTensor`，pto 用 `cce::printf`+`TPRINT` 且仅在 `_DEBUG`/`__CPU_SIM` 下生效。codegen 通过一张「intrinsic 名→模板名」分发表衔接模板库，简单官方 API（如 `WholeReduceSum`）可绕过包装直发。
