本讲拆解 tilelang-ascend 的「即时编译 + 运行」完整链路，是后续进阶讲义的总线。核心模块有四：`@tilelang.jit` 装饰器、`JITKernel`、`lower()` 三阶段编译、bisheng 编译与运行时调用。`@tilelang.jit` 只在首次 `func(a, b)` 时触发编译，按实际 shape 生成实例级缓存，`compile()` 内部还有一层基于 SHA256（综合算子逻辑、target、配置）的磁盘缓存，故 JIT 能支持动态 shape 且按 shape 编译缓存，对应概念是 JIT 与 AOT 之别。`JITKernel` 是外壳，先用 `tilelang.lower()` 产出 Ascend C 源码级 `CompiledArtifact`（非二进制），再交给默认的 `CythonKernelAdapter` 落地。`lower()` 分三阶段：`LowerAndLegalize`（语义降级与合法化，如推断 buffer 存储层级、Parallel 降级）、`OptimizeForTarget`（硬件优化，如软件流水、同步插入、存储重写）、`device_codegen`（按 `target.model` 分发 ascendc 与 pto 两条 codegen，产出源码）。最后由 CANN 的 bisheng 编译器（ascendc 用 `-xasc`、pto 用 `-xcce`）将源码编成 `.so`，经 ctypes 加载，codegen 在源码中同时生成设备函数 `<symbol>_kernel` 与 host 启动器 `extern "C" void call`，运行时 `cython_wrapper.forward` 打包 torch 张量指针与 aclrtStream 调用 `lib.call`，完成 Python 到 NPU 的最后一跳。`func.get_kernel_source()` 是观察整条链路最直接的窗口。
