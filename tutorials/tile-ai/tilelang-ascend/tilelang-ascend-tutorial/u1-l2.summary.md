本讲讲解 tilelang-ascend 的环境准备与构建流程，覆盖四个最小模块：前置依赖与三条安装路径、两个构建脚本、USE_ASCEND 开关、setup.py 打包头文件与 JIT 的关系。运行前置为 CANN（≥8.3.RC1）与 torch-npu，经环境变量 ASCEND_HOME_PATH 定位 CANN；README 给出直接装 wheel、build_wheel_ascend.sh 编 wheel、install_ascend.sh 源码编译三条路径，后两者需递归拉子模块（TVM、catlass、pto-isa、shmem 等）并打 tvm 补丁。USE_ASCEND 是贯穿全流程的总开关：经 setup.py 或 config.cmake 传给 CMakeLists.txt，决定是否把 4 个 Ascend 后端源文件（codegen 与 rt_mod 各两个）编进 libtilelang.so，CUDA/ROCm 的开关结构与之对称。核心结论：setup.py 把 catlass/shmem/pto-isa 的头文件目录打进 wheel，供 JIT 阶段 libgen.py 调用 bisheng 编译 kernel 时用 -I{TL_ROOT}/3rdparty/... 引用，因为 codegen 生成的 Ascend C 代码会 #include 这些模板库；即使 pip 装好 wheel，机器仍需 CANN 提供 bisheng 与 libruntime。引入的关键术语 CANN、bisheng、JIT、USE_ASCEND、TL_ROOT、libgen.py 均由后续讲义承接。
