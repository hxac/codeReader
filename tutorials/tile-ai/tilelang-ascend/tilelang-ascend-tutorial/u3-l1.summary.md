本讲解决「算子数据该落在哪块存储」。tile-lang 把 Ascend 五块片上存储（GM、L1、UB、L0A/L0B/L0C）压缩为两层前端抽象：shared 对应片上缓存 L1/UB，fragment 对应寄存器级 L0A/L0B/L0C。引入三类分配原语：T.alloc_shared（默认 scope "shared"，dynamic）、T.alloc_fragment（默认 "local.fragment"）、T.alloc_var（分配带初值的单元素标量，scope "local.var"），三者都是 T.alloc_buffer 的薄封装。核心机制是 AscendInferBufferScope pass（注册名 tl.InferAllocScope），它在 LowerAndLegalize 最早阶段按 buffer 使用上下文把 dynamic scope 钉死：fragment 看在 gemm 调用中的位置（A→L0A、B→L0B、C→L0C），shared 看是被 Cube 还是 Vector 使用（落 L1 或 UB），并为 L1 buffer 补默认 zN 布局。关键结论：Developer 模式只声明语义层、物理位置交给编译器推断，Expert 模式（alloc_L1/alloc_L0C 等）则显式指定换取更细控制粒度，两套抽象可混用；bool 类型因 merge smem pass 限制被强制钉到 UB。TIR scope 映射表（shared.l1/shared.ub/wmma.matrix_a/matrix_b/accumulator）是后续搬运与计算讲义的基础。
