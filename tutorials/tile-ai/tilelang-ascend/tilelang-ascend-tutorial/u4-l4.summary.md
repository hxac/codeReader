本讲拆解 Ascend 的**存储布局（layout）**与 **L2 swizzle** 两个正交优化：layout 决定片上数据怎么摆，swizzle 决定核间任务怎么轮流算，二者可叠加。

Cube 核以 **fractal**（16 行一摞）为单位吞吐数据，L1 矩阵默认按 **zN**（非行优先）排布，粒度由 C0（32 字节）与 fractal（16 个 C0）决定，**nZ** 则把分形放 N 方向；**scope（放哪块硬件）与 layout（怎么摆）正交**。

`T.annotate_layout({buf: layout})` 把布局作为块属性 `layout_map` 贴到 block；`make_zn_layout`/`make_nz_layout` 同时产出仿射变换（供推理）与 `layout_tag`（供 codegen 打印 `layout::zN`）。默认 zN 由 `AscendInferBufferScope` pass 注入并回调 Python，显式标注用于覆盖默认或给非 L1 buffer 提供传播起点。`LayoutInference` pass 用 BFS 三级（Strict/Common/Free）推理沿算子链自动传播布局，排在 `LowerTileOp` 之前，是 GPU/Ascend 共用框架。

`T.use_swizzle` 是**核间任务重排而非数据布局**，经 `thread_block_swizzle` 模板用 `off` 偏移错开相邻核取数据以提升 L2 命中率；前端两个同名 `use_swizzle` 靠 `del+重定义` 切到 Ascend 版。`src/layout` 里 `gemm_layouts.cc`/`swizzle.cc` 属 GPU 路线（bank conflict、Fragment），Ascend 实现主要在 Python `ascend_layout.py`，两者共享 `LayoutNode` 基类与 `LayoutInference`。
