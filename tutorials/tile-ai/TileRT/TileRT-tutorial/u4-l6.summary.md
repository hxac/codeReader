本讲是 PD 分离系列收尾篇，解决反量化后的 KV 如何「灌进」TileRT 解码引擎继续解码。核心结论是：**引擎认位置、认缓存，但不认缓存的来源**——只要把正确形状的 `(ki, kv, pe)` 写进正确的 `caches` 槽位并把 RoPE 位置游标对齐，外部 prefill 的 KV 对引擎不可区分，这正是 PD 分离成立的物理基础。引入四个最小模块与术语：①`PDEngine` 协议（`inject/decode/reset`）与无 GPU 的回声引擎 `StubEngine`，靠 `Protocol` 结构化类型可互换，支撑无 GPU 联调；②`profile.build_engine` 经工厂函数「加载后端→构造 Generator→`from_pretrained`→包成 `MlaNsaEngineAdapter`」收口模型差异，框架对模型无感；③`inject_cache` 用 `base_idx = layer_id * 3` 把外部三元组逐层写入扁平 `caches`，并在 8 卡各复制一份（因 MLA 潜 KV 在张量并行间复制）；④注入后**必须** `set_cur_pos(seq_len - 1)` 同步 RoPE 游标，否则新 token 被当作位置 0 旋转导致相对位置整体错位；`inject_last_hidden_state` 写入 `temp_vars[Idx.LAST_HIDDEN_STATES]` 供 MTP 预处理层消费，是 Generator 暴露的扩展点（当前适配器走 token-id 种子路径）。`NUM_LAYERS`（含 MTP draft 层）需在接收缓冲、convert、inject 三处一致。
