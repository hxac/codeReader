本讲精读 prefill 侧的 `TileRTConnector`——寄生在 vLLM prefill 进程内、经 `--kv-transfer-config` 加载的 V1 KVConnector 插件，跨 scheduler（决策发谁）与 worker（真正发 KV）双侧，靠 `TileRTMetadata` 跨进程传递。三个最小模块：(1) claim 纪律：`_claim` 仅认带 `tilert_host` 的请求、其余严格 no-op，从而能与 `NixlConnector` 安全共存于 `MultiConnector`(Topology B)；(2) chunked prefill 累积：`_Pending` 跨调度步累积 prompt token 与 block id，判据 `num_computed+n≥total` 命中即 `_emit` 构造 `_ReqMeta`；(3) worker 发送链路 `classify_layers→wait_for_save→extract→rdma_plan→_send`，走 TCP 控制平面握手（hello 校验 magic/layout_version/transport/max_seq）+ RDMA 数据平面写双轨。核心结论：MLA 潜 KV 在 TP 间复制，故 `sender_ranks={0}` 只 rank0 发、省 7/8 带宽；`extract` 只做字节搬运、反量化推迟到 decode 侧；默认异步 `_sender_loop` 使 prefill 计算与发送重叠；模型差异统一收口于 `ModelProfile`。本讲只覆盖发送端，接收服务、传输层细节与 decode 侧缓存注入留待后续讲义承接。
