本讲以 `DSAv32Generator` 为主角，讲解脱离 CLI 的程序化 API 与 Generator 生命周期。核心结论：Generator 是普通 Python 类，构造廉价——仅记录配置、加载 tokenizer、构造执行器 `decode_layer`（`ShowHandsDSALayer`），不加载权重也不初始化后端；`with_mtp` 是构造时「是否加载 MTP 投机解码权重」的开关。生命周期为「构造 → init（握手 `tilert_init_op`）→ from_pretrained（加载 8 卡分片权重）→ generate（可多次复用，每次 `reset_sequence` 复位 KV 缓存而无需重载权重）→ cleanup（调 `go_home` 释放，`__del__` 兜底）」，须先握手后加载。`generate` 返回四元组 `(text, time_list, accepted_counts, prompt_len)`：非 MTP 时 `accepted_counts` 为 `[]`，`prompt_len` 是 chat template 渲染后的 token 数；平均单 token 延迟 = 求和/计数，有效 TPS = 1/平均延迟，由 `stats_time` 统一计算。`enable_thinking` 非采样参数，而是映射到 `apply_chat_template` 的模板变量（DSv3.2 为 `thinking`，GLM-5 为 `enable_thinking`），会改变渲染后的 `prompt_len` 与生成行为。
