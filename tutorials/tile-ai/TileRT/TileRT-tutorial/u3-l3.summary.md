本讲讲解 TileRT 的 MTP（多 token 预测）投机解码通道：由 `with_mtp=True` 开启，`mtp_seq_len` 从 1 变 4，对调用 API 透明。与 draft-model 投机解码不同，MTP 复用主模型自身的投机头预测并验证多个候选 token。核心是 prefill/decode 双阶段：prefill 把 prompt 切成长度 4 的块（不足用末位 token padding，配合 `set_prefill_valid_tokens`/`set_prefill_mtp_extra_token`）灌 KV 缓存；decode 每步用上一轮 `next_draft_tokens` 拼输入，读 `num_accepted`/`predicted_tokens`，写到 `cur_pos+1+i` 并 `cur_pos += num_accepted` 推进游标——这是省 forward 的根本机制。收益由平均接受长度 μ 决定，README 的 `mean=2.77` 表示一次 forward 平均产出 2.77 个 token，上限为 4。MTP 头（`MTP` 容器）= `MTPPreprocessLayer`（融合 embedding 与末层隐状态）+ 复用的 `MoeBlock` + 复用的 `RMSNormHeadProj`，挂在 `layer_61_` 前缀下，复用主模型 V2 P2P 通信缓冲，依赖 `LAST_HIDDEN_STATES`；结果经 `Idx` 槽位（`ACCEPTED_TOKENS`/`PREDICTED_TOKENS`/`NEXT_DRAFT_TOKENS`）从 temp_vars 读回。
