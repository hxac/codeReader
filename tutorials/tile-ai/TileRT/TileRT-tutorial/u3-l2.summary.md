本讲精读 TileRT 非投机解码路径 `_generate_without_mtp`：它不做 chunked prefill，而把 prompt 与生成统一成「每步只喂一个 token」的解码循环，靠 KI/KV/PE 缓存记住历史，以压低单 token 延迟。流程为：`apply_chat_template` 渲染 prompt 得到 `prompt_tokens`，按 `total_len = min(max_seq_len, max_new_tokens + prompt_len)` 开定长缓冲，以 `-1` 为哨兵填充生成区，`prompt_mask = tokens != -1` 区分 prompt 区与生成区。循环里 `decode_layer.forward(tokens[prev_pos])` 只传单 token，C++ 后端算子 `dsa_show_hands` 把预测写进 temp_vars 的 `TOKEN_OUT` 槽，位置始终满足 `cur_pos_val = prev_pos + 1`；核心一行 `torch.where(prompt_mask[cur_pos_val], 原值, 预测)` 同时实现 prompt 区 teacher forcing 与生成区采样。EOS 终止仅在生成区生效（`~prompt_mask AND == eos_id`），`time_list` 记录每步耗时。收尾的 `reset_sequence()` 只清 KV 缓存不动权重，支撑「权重加载一次、`generate` 多次复用」。非 MTP 时 `accepted_counts` 恒空，MTP 的 `num_accepted`、多 draft token 等概念留到 u3-l3。`decode_layer` 即 `ShowHandsDSALayer`，8 卡张量并行，最终 token 取 device 0 的汇聚结果。
