本讲绘制 TileRT 仓库导航地图，覆盖三个最小模块：目录结构、双后端 .so 架构、单进程单后端约束。顶层包 tilert 分四区：generate.py（CLI 入口）、benchmark/（基准测试）、models/（模型组装）、pd_vllm/（PD 分离部署）。核心结论：真正的运行时大脑编译进两份后端库 libtilert_dsv32.so 与 libtilert_glm5.so，由 __init__.py 的 _BACKENDS 字典按 model_type 映射，经 load_backend() 用 ctypes.CDLL(RTLD_GLOBAL|RTLD_LAZY) 加载，再由 torch.ops.load_library 把算子注册到共用命名空间 torch.ops.tilert.*。引入的关键术语：模型族（DeepSeek-V3.2 与 GLM-5）、镜像对应（modules 层完全镜像，ops 层部分镜像，glm_5/_dsa_v32 是复用 DeepSeek 架构的 DSA 算子副本，其 docstring 仍自报为「deepseek v3.2」）、tilert_init_op 握手点、精确锁版本的 ABI 依赖。最关键的硬约束是「一个 Python 进程只能加载一个后端」：两个 .so 共用 tilert 命名空间且以 RTLD_GLOBAL 全局注册会撞车，故 load_backend 用 _loaded_backend 做软互斥——同后端重复调用幂等，换不同后端则直接抛 RuntimeError 并提示另起进程。
