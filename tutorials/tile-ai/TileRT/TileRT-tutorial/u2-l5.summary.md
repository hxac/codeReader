本讲讲清 Python 算子树如何压扁成交付给 C++ 后端的「四元张量列表契约」：`params`（权重，递归 `extend` 聚合，一次加载反复用）、`caches`（KV 缓存 `ki/kv/pe_cache`，每层 3 个、跨 token 累积）、`temp_vars`（56 个激活槽，每个 forward 覆写）、`profile_logs`（埋点），外加 `forward_max_seq_len`，统一由 `dsa_show_hands_prepare_money` 绑定并捕获进 CUDA Graph。核心结论有三：一是 `Idx`（`DsaTempVarIdx`，常量 `TEMP_VARS_SIZE=56`）作为 `IntEnum` 给扁平列表的下标起名，`temp_vars[Idx.TOKEN_OUT]` 等价于 `temp_vars[25]`，每个槽 dtype 由用途定（激活 bf16、索引 int32、概率 fp32）、shape 由 `ModelArgs` 定，且此「名字↔下标」映射 Python 与后端必须逐字段一致（ABI 一致性）。二是 `generate_params_with_continuous_storage` 把 56 个张量拼进一块 1024 字节对齐的大显存作视图，使地址稳定（CUDA Graph 回放前提）、分配最小、访存对齐。三是 `validate_temp_vars_layout` 在 `__init__` 跑三道护栏——成员数、下标连续无空洞、与后端 `dsa_temp_vars_size()` 对拍，把枚举写错和 Python↔.so 版本错配挡在启动期。本讲承接 u2-l3 的「搬运者」，为后续 u2-l6（MLA 与稀疏选择读写 caches）、u2-l7（MoE 路由算子链读写 temp_vars 各槽）、u3-l2（生成主循环读写 `TOKEN_OUT/CUR_POS`）提供四元组与 Idx 下标两大通用视角。
