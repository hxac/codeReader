本讲聚焦 TileLang 的调试工具链，覆盖四个最小模块。`T.print` 是编译进 kernel 的运行时打印原语，按 buffer scope（global/shared/fragment/local）分四种策略：shared/fragment 加 `tx==main_lane` 条件只让一个线程打印以避免重复；fragment 因数据散落各线程寄存器且物理排布由布局推断决定，必须先 `T.copy` 回 shared 中转才能逐元素打印。其链路为「Python 卫生宏 `@macro` → `tirx.call_extern` → codegen 印码引入 `debug.h` → 设备端 `printf`」，CUDA 与 MACA 后端对称。`plot_layout` 是纯 Python 可视化工具，把 `T.Layout`/`T.Fragment` 画成彩色网格，Fragment 标「线程号+线程内槽位」，依赖 `map_forward_thread`/`map_forward_index` 两个查询；它与编译期集成的 Visual Layout Inference（`TL_LAYOUT_VISUALIZATION_ENABLE`）互补。日志分两侧：Python 用标准 `logging`，C++ 复用 TVM 的 `LOG/DLOG/VLOG/ICHECK`；关键易混淆点是两个同名 `TVM_LOG_DEBUG`——编译期宏决定 `DLOG` 是否编入，运行时环境变量决定显示级别，两者缺一不可。`env.py` 用 `EnvVar` 描述符统一管理环境变量，动态读取、可强制覆盖，调试最常用 `TILELANG_CLEANUP_TEMP_FILES`、`TILELANG_DISABLE_CACHE`、`TILELANG_PASS_DIFF`。工具箱还含 Pass Diff、AutoDD、postproc 回调，分别解决 IR 逐 pass 对比、最小复现缩放与源码拦截改写。
