本讲以 MACA 后端为样板，讲清「给 TileLang 新增一个 target 后端」本质是在 Python 与 C++ 两层注册表里填一串具名插槽，并用同名 FFI 字符串对齐。最小模块有四：一是 backend 注册，编译时按 target kind 顺次查 detector、pipeline、device codegen、execution backend 四张表；二是 lazy 注册，`register_lazy_device_codegen`/`register_lazy_execution_backends` 仅存模块路径字符串，首次用到该 target 才 `import_module` 触发真实登记，由 `_LOADED` 集合去重，使 `import tilelang` 保持轻量；三是 target detector，`register_target_detector` 按 dict 插入顺序（即 `tilelang/__init__.py` 的 import 次序 cuda→hip→metal→maca）短路遍历，MACA 在 HIP 版 torch 或找不到 SDK 时让位返回 `None`，仅 `auto` 触发；四是 target_utils 公共分发，C++ `TargetHasAsyncCopy` 按 `TargetIsCuda/Rocm/Maca` 分发，新增后端只需在此挂一个分支。核心结论：加后端＝填表，Python 侧填 detector/lazy-codegen/lazy-execution/pipeline 四表，C++ 侧填 target_kind/device_api/build 函数/target_utils 四件套，C++ target_kind 通过 `TVM_REGISTER_TARGET_KIND` 把 kind 绑到 DLDeviceType（如 `kDLMACA`），`warp_size` 钉为 64；构建系统用 `USE_MACA` 开关配 `ALWAYS_SRCS`/`MACA_SRCS` 两段式编译。关键术语：注册表、target kind、懒加载、FFI、DLDeviceType、canonicalizer、target detector/normalizer。
