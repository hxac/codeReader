本讲聚焦 TileLang 的 CUDA/HIP 两个 GPU codegen 后端，覆盖三个最小模块：codegen 本体、intrin_rule、target_utils。核心链路是「设备 TIR → 源码文本 → nvcc/hiprtc」。`CodeGenTileLangCUDA` 与 `CodeGenTileLangHIP` 均 `final : public CodeGenC`，override visitor 处理共享内存作用域、warp shuffle、张量核等 GPU 专有构造；采用「按需 include」机制——印码时置位的 `need_*` 标志在 `Finish()` 中翻译为 `#include`。两者由 `rt_mod_*.cc` 的 `BuildTileLang*` 实例化并注册为全局函数 `target.build.tilelang_cuda/hip`，供 Python `DeviceCodegen` 调用。intrin_rule 通过 `<target>.FLowerIntrinsic` 属性，在 `LowerIntrin` pass 中把可移植 `tirx.*` 算子改写为后端 extern 调用（如 `rsqrtf`、`__shfl_sync`）；CUDA 复用 TVM 默认规则，HIP 因缺向量数学内置函数需逐个标量化注册。target_utils 提供按架构检测能力的纯函数，并经 FFI 暴露为 `tl.TargetIs*`：CUDA 看 `arch` 整数判代际，HIP 看 `mcpu` 字符串前缀，warp_size 在 CUDA 恒 32、HIP CDNA 为 64。关键结论：异步拷贝能力由公共层 `TargetHasAsyncCopy` 统一分发，既驱动高层 pipeline pass 是否规划异步生产者，又驱动 copy op 选 cp.async 还是普通循环，是「自动选搬运指令」的最终落点。本讲为后续张量核（u6）与 MACA 后端（u7）承接了「三后端结构对称、细节各有坑」的对照基线。
