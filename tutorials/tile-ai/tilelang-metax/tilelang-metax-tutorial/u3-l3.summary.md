本讲聚焦 tilelang-metax 的核心——MACA 后端，讲解如何把一份 TileLang kernel 编译并运行在 MetaX GPU 上。关键结论：`maca` 是与 `cuda`/`hip` 平级的一等 target kind，C++ 侧注册，默认 `thread_warp_size=64`（区别于 CUDA 的 32），canonicalizer 会自动补齐 `mtriple` 与 `mcpu`（探测不到回退 `xcore1000`）。覆盖四个模块：target 构造与属性规范化；可用性检测（HIP 版 torch 让位、能否找到 MACA SDK 路径，最终落到环境变量 `MACA_PATH`/`MACA_HOME`）；执行后端（登记 tvm_ffi/mcrtc/cython/cutedsl，`tvm_ffi` 为默认且始终可用，`mcrtc` 当前已登记但不可用）；运行验证（设备编译调 `mxcc` 产出 `mcbin`，无设备可经 `tilelang_maca_without_compile` 只取源码）。引入术语：MACA、mxcc、mcbin、warp_size、canonicalizer、检测器、执行后端。运行需 `MACA_PATH`+`LD_LIBRARY_PATH`+`PATH` 三件套；`import tilelang` 成功不等于 MACA 后端就绪。
