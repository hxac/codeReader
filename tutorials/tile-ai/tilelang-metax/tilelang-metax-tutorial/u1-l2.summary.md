本讲围绕「tilelang-metax 如何从源码编译出可导入的 Python 包」展开，覆盖四个最小模块：构建依赖、CMake 构建、MACA SDK 定位、安装验证。核心结论是：tilelang-metax 由 C++ 编译器（产出 `libtilelang.so`）与 Python 前端组成，构建依赖分三层——OS 级（gcc/cmake/python-dev）、Python 级（cython、apache-tvm-ffi、z3-solver、torch）、硬件 SDK 级（CUDA/ROCm/MACA）。

本讲最关键的洞见是 MACA 后端的接线方式与 CUDA/ROCm 不同：它不在 `TILELANG_BACKENDS` 集合中，而是通过 `USE_MACA` 环境变量触发，因此构建命令是 `USE_MACA=ON cmake -B build` 而非 `cmake -DUSE_MACA=ON`。引入的关键术语包括 CMake、pyproject.toml/scikit-build-core、MACA SDK（mxcc 编译器）、cu-bridge 兼容层、tvm-ffi、定制版 TVM 子模块（`3rdparty/tvm`）、`find_maca` 宏的三级搜索顺序（显式路径→`MACA_PATH`→`/opt/maca`）、以及运行期与构建期两侧的 SDK 路径检测。验证分两级：最低门槛 `import tilelang`，完整验证跑 `examples/quickstart.py`，MACA 运行期还需导出 `MACA_PATH`/`LD_LIBRARY_PATH`/`PATH`。`import tilelang` 成功不代表 MACA 后端真正可用，后者要用 `target={"kind":"maca"}` 编译并跑通 kernel（留待 u3-l3）。
