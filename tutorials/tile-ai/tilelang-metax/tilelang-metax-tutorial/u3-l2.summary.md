本讲说明用户写的 kernel 函数如何变成可直接接受 torch 张量调用的 kernel 对象。`@tilelang.jit` 只把函数包成 `JITImpl` 暂存编译参数，真正编译发生在 `.compile()` 或 `__call__` 时，经 `tilelang.compile`（并行版 `par_compile`）收口到 `cached()`，委托 `KernelCache` 做下译、codegen 与 adapter 包装，产出 `JITKernel`。关键术语：JIT 分 lazy（显式返回 PrimFunc，得到可调用对象）与 eager（builder 模式即写即跑）两种自动推断模式；TIR 是基于 TVM 的中间表示；adapter 是张量与设备指针间的胶水层；执行后端（tvm_ffi/cython/nvrtc/torch/cutedsl，MACA 多出 mcrtc）与 target 正交但受各 target 注册清单约束，auto 取首个可用。系统采用两级缓存：进程内快速缓存与磁盘级 `KernelCache`（原子落盘，缓存键由 TIR 脚本、target、执行后端、pass 配置与版本共同决定）。`JITKernel` 既是可调用对象，又提供 `get_kernel_source`、`get_profiler`、`export_sources`、`export_library` 等自省与导出方法，是后续自动调优与基准测试的基础。
