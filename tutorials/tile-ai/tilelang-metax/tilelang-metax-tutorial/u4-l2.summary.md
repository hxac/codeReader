本讲承接 u4-l1 的 lowering 框架，剖析 GEMM 算子下译。三个 DSL 入口 `T.gemm`/`T.wgmma_gemm`/`T.tcgen05_gemm` 共用 `_gemm_impl`，差异仅在 op_key 与 `is_wgmma`/`is_tcgen05` 注解，C++ 侧统一反序列化为 `GemmNode`。GEMM 采用两级分派：C++ `ResolveGemmImpl(target).select_inst` 依 target×dtype×scope×形状返回指令键（如 `cuda.wgmma`、`maca.mma`、`rocm.mfma`、`cpu.scalar`），Python `resolve_gemm_impl` 再把键映射到实现类。`GemmWarpPolicy`（Square/FullRow/FullCol）决定 warp 切分输出 tile 的方式；MACA 因 `warp_size=64`、`k_n_per_warp=16`，与 CUDA（`warp_size=32`）得到不同的 warp 数与划分。`Lower` 与 `InferLayout` 在 C++ 中是薄壳，按全局函数名 `tl.gemm.lower`/`tl.gemm.infer_layout` 外包给 Python 实现类，且 `reuse_existing_shared_layout` 仅普通 MMA 可复用既有 shared 布局，WGMMA/TCGEN05 须自定布局。
