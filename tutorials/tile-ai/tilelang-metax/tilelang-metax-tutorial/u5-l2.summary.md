本讲钻入 `src/transform/` 的 pass 体系，核心结论是「顺序看 Python 流水线、实现看 C++」：单个 pass 由 C++ 实现，执行顺序由 `tilelang/<backend>/pipeline.py` 经 `resolve_pipeline` 编排，引擎 `lower` 逐条串联。

聚焦四个 pass：`MaterializeKernelLaunch` 紧跟 `BindTarget`，把 `T.Kernel` 的 target 无关线程绑定帧物化——SIMT 后端变 `thread_extent`，CPU 变串行 `for`（thread 维钉 0），由开关 `lower_thread_binding` 控制；`LowerTileOp` 在 `LayoutInference` 之后，把 `tl.tileop.*` 占位调用降级为 `cp.async`/`mma` 等底层 TIR，并用 `layout->Forward()` 把 fragment 布局刷进 buffer 访问，收集 TMA/smem 对齐写成属性；`SplitHostDevice` 在 `AnnotateDeviceRegions` 之后，把设备区抽成独立 device PrimFunc（命名 `<name>_kernel`）放进 `device_mod`，原区域换成 `Call`，参数新建同名 Var 防 `ConvertSSA` 误改名；`StorageRewrite` 做生存期（liveness/gen-kill）分析与 attach 作用域，但 `enable_reuse=false`，shared memory 复用归 `MergeSharedMemoryAllocations`、寄存器复用归后端编译器。关键依赖：`LowerTileOp` 需 layout、`StorageRewrite` 需 buffer 一维化、`SplitHostDevice` 须早于 `MergeSharedMemoryAllocations`。MACA 流水线与 CUDA 同构，仅多插 `LowerMACAIntrin`。
