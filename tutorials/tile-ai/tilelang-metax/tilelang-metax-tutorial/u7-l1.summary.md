本讲是 U7 Metax/MACA 后端系列首篇，回答「为把 TileLang 跑在 MetaX GPU 上，metax 分支新增了哪些零件」。核心是「运行时四件套 + Python 三注册点」：C++ 侧通过 `TVM_REGISTER_TARGET_KIND("maca", kDLMACA)` 注册一等 target（最显眼属性是 `thread_warp_size=64`，区别于 CUDA 的 32，牵动后续 GEMM 分派），`UpdateMACAAttrs` 规范化器自动补齐 `mtriple` 与 `mcpu`（探测设备架构，兜底 `xcore1000`）；`MACADeviceAPI` 把通用 `DeviceAPI` 一一映射到 `mc*` 运行时（显存强制 256 字节对齐）；`BuildTileLangMACA` 印源码后经 postproc/compile 两个 Python 回调调 `mxcc` 编出 `mcbin`，`MACAModule` 持产物按设备懒加载并以 `mcModuleLaunchKernel` 启动。Python 侧三条线（target detector、device codegen、execution backend）在 `import tilelang` 时经 `from . import maca` 自动挂载。引入的关键术语：`kDLMACA`、canonicalizer、`MACADeviceAPI`、`MACAModule`、`mcbin`/`mcir`、`target.build.tilelang_maca`、`TILE_LANG_MACA_ALWAYS_SRCS` 条件编译两层划分（关 MACA 仍能识别 target 但无法真编译）。
