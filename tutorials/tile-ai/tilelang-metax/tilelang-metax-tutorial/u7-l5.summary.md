本讲是 MACA 后端系列的收口篇，把 MACA、CUDA、ROCm 三个 GPU 后端横向对比，揭示差异及 TileLang 的统一抽象手法。核心结论沿四个维度展开：一是 warp_size 与 target triple——CUDA 恒为 32、MACA 恒为 64、ROCm 看 CDNA(64)/RDNA(32)，该值牵动 GEMM 的 warp 划分与 fragment lane 映射；MACA 的 target kind 是本仓库新增的，由 canonicalizer `UpdateMACAAttrs` 把 triple 钉成 `mxc-metax-macahca`、mcpu 探测成 `xcoreXXXX`，而 CUDA/hip 的 kind 来自上游 TVM。二是张量核指令分派——同一份 `T.gemm` 经 `ResolveGemmImpl` 选后端、再经 `SelectInst` 选指令键（两级分派），CUDA 走 mma/wgmma/tcgen05 能力降级，ROCm 走 mfma/wmma，MACA 恒返回键名 `maca.mma`（底层硬件指令家族为 mfma）。三是运行时 API——`cu*`、`hip*`、`mc*` 一一对应，MACA 独有显存 256 字节对齐断言；编译链路 mxcc 产出 mcir/mcbin。四是执行后端——与 target 正交，三者默认 `tvm_ffi`，CUDA 有 nvrtc、MACA 有 mcrtc，ROCm 不登记 rtc。关键洞见是这些差异被公共层 `src/backend/common/target_utils.cc` 以 `TargetIs*` 三连判收敛，上层只需调一个 FFI（如 `TargetHasAsyncCopy`），即「公共分发 + 后端自有实现」模式，为后续「新增后端」提供模板。
