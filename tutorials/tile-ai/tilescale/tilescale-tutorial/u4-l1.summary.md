本讲讲解 TileLang 的布局推理（Layout Inference）pass：它为每个寄存器 fragment 及需 TMA 搬运的 shared 缓冲区推导出线程级布局。核心数据结构是 Layout（记录逻辑下标到线性位置的仿射映射，用于 shared memory）与 Fragment（在其上多了线程号、寄存器槽与复制份数，寄存器 fragment 必须用它）。每个 tile op 通过虚函数 InferLayout 声明约束，强度由 InferLevel（kStrict/kCommon/kFree）控制。算法分四步：浮动 buffer 全复制、严格约束收集（如 gemm 累加器 C 必须为 fragment）、BFS 常规传播、自由模式在 buffer 共享的连通分量内枚举并选总寄存器占用最小的方案、按底层 storage Var 做别名收尾。结果以 attr::kLayoutMap 注解贴回每个 Block，本 pass 不生成指令，TMA/mma 指令生成与下标重算交由下游 LowerTileOp 完成。可通过 pass 配置 tl.layout_visualization_enable 与 tl.layout_visualization_formats 在两个 pass 之间打印 Shape/Thread/Index 三行做可视化诊断。关键结论：fragment 的 OutputShape 乘积等于逻辑元素总数除以线程数，由 mma/wgmma 指令的固定输出分布决定，这是「gemm 累加器必须是 fragment」的编译期根因。
