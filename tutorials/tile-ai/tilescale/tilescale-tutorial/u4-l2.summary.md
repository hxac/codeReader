本讲拆解软件流水线的编译器落地链：前端 `T.Pipelined(num_stages=N)` 只是在 `For` 上挂 `num_stages` 注解，真正改写由四道 pass 完成。`PipelinePlanning` 分析循环体每条语句的读写，判定 copy 生产者（global→shared）与消费者，规划出 `stage`/`order`/`async_stages`，并在「copy 全在尾部」时把非 copy 的 stage 减 1，将缓冲副本数从 `num_stages+1` 省到 `num_stages`。`InjectSoftwarePipeline` 负责落地：给跨级 buffer 加版本维（多缓冲，用 `floormod` 轮转选槽）、把循环展开成 prologue/body/epilogue 三段（循环偏斜让生产者 prefetch 未来迭代）、插入 `async_scope`/`commit`/`wait` 占位。最后按路径二选一注入硬件异步指令：非 warp 特化的 `InjectPTXAsyncCopy` 替换为 `cp.async`（Ampere sm_80+，须排在 `ThreadSync` 之后）；warp 特化+TMA 的 `InjectTmaBarrier` 配 `mbarrier` 的 `expect_tx`/`arrive`/`wait`（Hopper sm_90+）。核心结论是 shared tile 副本数 ≈ `num_stages`，`num_stages` 越大越能隐藏访存延迟，但 shared memory 与寄存器代价也越大，选值是「延迟 vs 占用率」的权衡（甜点通常 2~4）。关键术语 num_stages、stage/order、copy stage、num_versions、prologue/body/epilogue、async_scope、cp.async、TMA/mbarrier 将被后续 warp 特化与自动调优讲义承接。
