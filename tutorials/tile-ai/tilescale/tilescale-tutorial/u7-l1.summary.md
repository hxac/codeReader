本讲打开 TileLang 的 C++ 后端降级逻辑，阐明 `T.gemm`/`T.copy`/`T.reduce_sum` 等高层 tile 原语如何变为 GPU 硬件指令。核心是算子层的「双轨制」：A 轨 `tl.tileop.*` 经 `TIR_REGISTER_TL_TILE_OP` 注册并挂 `TLOpBuilder` 属性，把调用反序列化为 `TileOperator` 对象，实现 `Lower`/`InferLayout`/`Clone` 参与降级与布局推理；B 轨 `tl.*` 用 `TIR_DEFINE_TL_BUILTIN` 仅注册名字与副作用，不经降级、由 codegen 原样打印成 C 调用。`ParseOperator` 是两条轨的分叉点，被 `LowerTileOp` 与 `layout_inference` 两个 pass 共用分发。所有 A 轨算子共享三段式骨架：构造反序列化（`args[i]` 与 Python `call_intrin` 实参严格对齐）→ `InferLayout` 声明布局约束（强度由 `InferLevel` 表达）→ `Lower` 出硬件指令。`GemmNode::InferLayout` 以 `ICHECK` 强制累加器 C 为 fragment，其 `Lower` 拼 `tl::gemm_ss<...>` 模板字符串交 `tl::tl_gemm` 由 codegen 实例化，体现「TIR 描述、C++ 模板落地」的分层。reduce 用 `MakeInitValue/MakeReduce` 把规约语义（幺元+合并函数）与具体指令解耦。远程搬运分两套：CP-engine 的 `tl.tileop.put/get`（A 轨，按 scope 选 `tl::cp_warp/cp_block`）与 NVSHMEM 的 `tl.Putmem*`（B 轨，直出 `nvshmem*`）——双轨制正是 CP-engine 与 NVSHMEM 两条通信路线在算子层的投影。
