本讲介绍 TileScale 分布式通信的 **CP-engine 路线**，与 u6-l2 的 NVSHMEM 路线相对照：前者用 `put_block/put_warp/get_block/get_warp` + `wait_eq/wait_ne` 等 Python 原语，经 C++ 端 `PutOp/GetOp/WaitOp`（`remote_copy.cc`/`sync.cc`）降级为 `tl::cp_warp/cp_block/wait_*` 设备模板，靠 CUDA 线程自行 load/store 远端对称堆地址完成跨 PE 搬运，而不直接调用 `nvshmem*` C API。核心要点有三：一是四原语靠 `scope`（block/warp）区分，`dst_pe/src_pe` 是否为 `IntImm(-1)` 决定本地还是远程；二是 `unroll_factor` 与 `enable_aggressive_vectorize`（int4 16 字节宽）仅作用于 warp 级搬运的吞吐旋钮，块级则走 `nvshmem_cp_threadgroup` 自动分块；三是统一的远程寻址公式 `remote_addr = get_remote_base_ptr(peer) + (addr - base[me])`，依赖各 PE 对称堆同构，`wait_*` 以 `ld_volatile_global` + `pragma unroll 1` 自旋实现完成通知，`kernel.initialize(allocator=...)` 注入基址表 `meta_data` 是其必经一步。
