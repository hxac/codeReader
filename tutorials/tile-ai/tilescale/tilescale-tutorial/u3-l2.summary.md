本讲回答"`tilelang.lower` 的输入 `PrimFunc` 从哪来"。`@T.prim_func` 是定义时（而非调用时）触发的装饰器，把普通 Python 函数转换并替换为 `tvm.tir.PrimFunc`（TIR）对象，其结构由 params、buffer_map、Stmt 语句树及 device kernel 属性构成。关键认知是：前端阶段所有 `T.*` 计算原语都只是待降级的高层 intrin——`T.copy`/`T.gemm` 分别生成 `tl.tileop.copy`/`tl.tileop.gemm` 的 `call_intrin`，真正的 TMA、mma 等硬件指令要等后续 pass 才出现。仓库并存两代前端：v1 复用上游 TVMScript 的 `parse`，再用 overrides 给 `local.var` 这类标量赋值打补丁；v2 则是当前 `T.prim_func` 实际走的路线，靠 `DSLMutator` 在编译期把 Python AST 整棵改写成对 `Builder`（即 `__tb`）方法的调用，执行这些调用即用 `ir_builder.tir` 往 IR 树堆节点。v2 还引入 `LazyJITFunc` 与 `T.const`，实现按 shape 的两阶段特化与缓存，是 `tilelang.lazy_jit` 的前端基础。
