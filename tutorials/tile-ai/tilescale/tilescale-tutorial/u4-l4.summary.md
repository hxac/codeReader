本讲聚焦 TileLang 的 `OptimizeForTarget` 流水线中四道存储/内存 pass。`FlattenBuffer` 把多维 `Buffer` 拍平为一维物理内存、重写下标并按需把索引提升为 int64（`bool`→`int8`），是后续存储 pass 的前提（函数参数 buffer_map 刻意不拍平）。`StorageRewrite` 用活跃变量分析（liveness analysis）让生命期不重叠的临时缓冲（主要 local/global）复用存储，但检测到动态 shared 或开启 `merge_static_smem` 时关闭复用、让位给下游专门 pass。`MergeSharedMemoryAllocations` 把多个 `shared`/`shared.dyn` 分配合并成单个 `UInt(8)` arena，用线性扫描（linear-scan）加 best-fit free list 打包，Hopper 因 TMA/wgmma 要求 1024 字节对齐；`enable_aggressive_merge` 把访问归到最内层作用域以更激进复用，但 warp 特化下被强制关闭。`ThreadSync` 基于 shared 读写冲突（RAW/WAR/WAW）仿真自动插入 `__syncthreads`，支持循环外提、async-wait 后补屏障及部分线程参与的命名屏障。四者在 `SplitHostDevice` 之后严格顺序执行，共享「线性化访问 + 活跃区间分析 + 区间打包/冲突检测」的统一思想。
