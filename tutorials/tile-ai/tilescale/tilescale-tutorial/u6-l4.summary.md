本讲承接 device 侧远程原语，转向 host 侧运行时准备。核心结论：device 用哪族原语决定 host 做哪套运行时准备，二者必须配对。NVSHMEM 路线（`get_pe`/`putmem`）靠对称堆自动寻址，host 侧用 `init_distributed(init_nvshmem=True)` 调 `pynvshmem.init_nvshmem_by_uniqueid` 引导（PE 号即 torch rank），并用 `nvshmem_create_tensor` 分配自动 free 的对称堆张量；CP-engine 路线（`get_rank`/`put_block`）靠远程基址表，host 侧用 `init_dist` + `get_allocator` + `kernel.initialize`，二者不可混用。`launch.sh` 用 torchrun 按卡数拉进程，经环境变量注入 NVSHMEM/NCCL 开关（关键 `NVSHMEM_BOOTSTRAP_MPI_PLUGIN` 复用 torch rendezvous，规模信息全走环境变量）。`perf_fn`（warmup + 256MB 刷 L2 + event 多轮去首次）测延迟，`example_allgather.py` 以 `dist.all_gather_into_tensor` 为参考做逐元素 allclose 正确性校验。
