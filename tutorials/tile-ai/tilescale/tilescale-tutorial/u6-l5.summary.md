本讲拆开 CP-engine 路线中被当作黑盒的 `get_allocator`，讲清 `tilescale_ext` C++ 扩展如何支撑跨进程 GPU 显存共享与所有权管理。核心模块有四：`tensor_from_ptr` 用 `at::from_blob` 零拷贝地把裸指针包成 torch 张量，`take_ownership` 决定 deleter 是否 `cudaFree`，是整条链路的所有权开关；CUDA IPC 经 `_create_ipc_handle`（`cudaIpcGetMemHandle`）生成可序列化 handle、`_sync_ipc_handles`（`cudaIpcOpenMemHandle`）打开 peer handle 并写回 GPU，要求显存必须由 `cudaMalloc` 直接分配，故绕开 torch caching allocator；`BaseAllocator` 一次 `cudaMalloc` 独占所有权，用 `all_gather_object` 交换 handle 拼出远程基址表 `[rank, num_ranks, *基址]`，按 bump 加对称偏移切出无所有权视图；该表经 `kernel.initialize` 注入 device 的 `__constant__ meta_data`，device 侧 `get_rank / get_num_ranks / get_remote_base_ptr` 按 `0 / 1 / 2+rank` 读取，支撑远程寻址公式。核心结论：所有权收口在 allocator，只有它 `cudaFree` 一次，所有视图（`take_ownership=False`）与 IPC 映射都不释放。本讲引入的关键术语为后续 DeepEP 对称堆与分布式实战提供运行时基础。
