本讲给出 TileScale（Python 包 `tilelang`）的仓库全景地图。仓库分三层：`src/`（C++ 编译器与算子后端：transform pass、op、codegen、设备模板）、`tilelang/`（Python DSL 外壳）、`3rdparty/`（上游 TVM/CUTLASS 子模块）。核心结论是 `import tilelang` 的加载链：`env.py` 算出库搜索路径 `TL_LIBS` 并配好 TVM 路径 → `import tvm` → `libinfo.find_lib_path` 按平台命名规则在 `TL_LIBS` 中定位 `.so` → `ctypes.CDLL` 加载 `libtilelang.so` → 导出 DSL/JIT/编译接口 → 可选挂载分布式扩展。构建由 `scikit-build-core + CMake` 驱动，产出 `libtilelang.so`（含编译器）、`libtilelang_module.so`（runtime-only 精简版）与 CUDA+Torch 时的 `tilescale_ext._C.so`。关键设计是「源码与产物分离」：分布式扩展源码在 `tilelang/utils/ts_ext/`，产物却装到顶层 `tilescale_ext/`，其缺失不影响核心 import。`TL_LIBS` 在 pip 模式指向 `tilelang/lib`，开发模式指向 `build/lib` 与 `build/tvm`，与 CMake 输出目录严格对应。
