本讲介绍 TileScale 用 TileLang 重新实现 DeepEP 的节点内（intranode，NVLink 互联）Expert Parallel 通信。核心结论：原始 `deep_ep` 包仅作正确性参考 oracle（由 `install_deepep.sh` 安装，需探测 CUDA 架构、补 NVSHMEM 并修 `libnvshmem_host.so` 软链 bug），TileScale 自身 kernel 由 TileLang JIT 生成，不依赖它。

引入的关键术语：MoE 的 Expert Parallel（EP）、不均衡 all-to-all、dispatch/combine 二段式、`EPBuffer` 统一封装。完整 EP 通信分三段：`get_dispatch_layout`（唯一非分布式步骤，单卡一次扫描统计 `num_tokens_per_rank`、`num_tokens_per_expert`、布尔掩码 `is_token_in_rank`）→ `dispatch`（notify 跨卡 all-to-all 交换计数并算前缀和，再用 `T.put_warp` 把 token 推往目标 rank）→ `combine`（反向回送专家输出并按 token 求和，不带权重）。关键不变量：专家在 rank 间均匀切分（全局专家号 e 落在 rank e//num_local_experts）；通道数 `num_channels = num_sms//2`。dispatch/combine 共用「通道 + 环形缓冲 + head/tail 队列」机制，发送方维护 tail、接收方维护 head，靠 acquire/release 与 `T.wait_ge/wait_ne` 同步，全程复用 u6-l3 的 CP-engine 远程拷贝原语与 u6-l5 的 `tilelang.get_allocator(is_distributed=True)` 注入远程基址表。实现范围仅 intranode normal mode，internode 与 low-latency 模式仍为 TODO。8×H100 基准下 dispatch/combine 延迟与带宽与原版 DeepEP 基本持平。
