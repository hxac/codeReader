本讲是 u3（编译流水线）的收尾，负责把编译产物变成 Python 里可调用、可测速的对象。`compile`/`jit`/`lazy_jit`/`par_compile` 四个入口同源，最终都汇聚到 `JITKernel`，经 `cached()` → `KernelCache`（内存+磁盘两级缓存）落点，命中即返回，未命中才调 `lower()` 真正编译。真正注册的执行后端只有五个：`tvm_ffi`（默认）、`cython`、`nvrtc`（仅 CUDA）、`torch`（仅 Metal）、`cutedsl`；`auto` 按 target 选默认，CUDA→`tvm_ffi`、Metal→`torch`；`dlpack` 只是 `tvm_ffi` 的历史别名，`ctypes` 是内部适配器类，均非独立后端。关键结论：只有 `tvm_ffi` 要求 `lower()` 产出可运行的 `rt_mod`，其余后端只要源码、自走编译路径（即 u3-l5 的「两条编译路径」）。核心术语包括 Adapter（适配器）、`BaseKernelAdapter`、`TVMFFIKernelAdapter`、DLPack 零拷贝张量桥接、stream/device 对齐 thunk、`Profiler`、`TensorSupplyType`、`do_bench`（L2 flush + CUDA event 计时），为 u5 自动调优与 u6 分布式（`JITKernel.initialize`、`init_table` 注入 rank/远程基址表）承接。
