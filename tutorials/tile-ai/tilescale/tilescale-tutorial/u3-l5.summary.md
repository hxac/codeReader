本讲承接 u3-l4，拆解 TileLang 编译流水线「最后一公里」：如何把经 OptimizeForTarget 改造好的 IR 变成可跑在 GPU 上的 CUDA/HIP 源码与二进制。核心模块有四：其一，host/device codegen 分工——device codegen 把 device kernel 打印成 GPU 源码、host codegen 打印 CPU 启动器，二者按 `target.kind.name` 分发到以 `target.build.tilelang_*` 命名的 TVM-FFI 全局函数；其二，设备源码生成器 `CodeGenTileLangCUDA/HIP` 作为「源码打印机」，遍历 IR，把 LowerTileOp 已降级的低层 intrin（`ptx_mma`、`tma_load`、`tl_gemm` 等）逐条翻译成 `tl::xxx` 模板调用文本，由特性标志位驱动 `Finish()` 按需 `#include` 设备模板头；其三，编译回调机制——C++ codegen 通过 FFI 回调 Python 注册的 `tilelang_callback_cuda_compile/hip_compile` 真正调 nvcc/hipcc 产 cubin/hsaco，`enable_device_compile` 决定走「真编译」还是「只出源码」；其四，多后端与 NVSHMEM 链接——TileLang 自实现 cuda/hip/cutedsl/c 的 codegen，llvm/webgpu/metal 复用上游 TVM，`auto` 按 CUDA→HIP→Metal 探测，而 NVSHMEM 链接须在回调路径与 JIT `compile_lib` 路径两处分别接 `-lnvshmem_device/host` 与 `-rdc=true`。引入的关键术语：host/device codegen、codegen 即源码打印机、编译回调、两条编译路径（tvm_ffi 回调路径 vs cython/nvrtc JIT 路径）、cubin/hsaco/PTX、SUPPORTED_TARGETS。
