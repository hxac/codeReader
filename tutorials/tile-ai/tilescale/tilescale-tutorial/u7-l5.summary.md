本讲是 Unit 7 的收尾课，不讲新的编译机制，而是讲如何把改动安全贡献回 TileScale，覆盖四个最小模块。测试体系以 pytest 为骨架，`testing/python/` 按子系统（kernel/language/transform/layout 等）分目录，`testing/conftest.py` 固定随机种子并兜底「零用例被收集」的误绿，`tilelang.testing` 提供 `main()` 单文件运行、`requires_distributed` 及按 SM 架构跳过的装饰器；`testing/cpp/` 目前仅占位。基准测试位于 `benchmark/`，按算子族分目录，是可执行脚本而非断言用例；`benchmark_matmul.py` 通过 `@autotune` 叠在 `@jit` 之上遍历配置（默认 288 个，开 Roller 缩到 top-10），输出最优延迟与 TFLOPS。格式化统一走 pre-commit：ruff 管 Python、clang-format 管 C++、另有 codespell/pymarkdown，`format.sh` 作为封装默认只查改动文件并以 `git diff --quiet` 守门。CI（`ci.yml`）当前仅有 self-hosted NVIDIA + CUDA-12.8 + Python 3.12 单矩阵，lint 用 Python 3.8 做 AST 检查、3.9 跑 pre-commit，tests 将分布式与非分布式用例分两段跑。贡献流程为 fork → 带子模块克隆 → `uv` 建环境 → `--no-build-isolation --editable .` 安装 → 本地 lint+test → 提 PR。关键术语：pytest marker、pre-commit、ruff、TFLOPS、merge-base、editable 安装、pytest-xdist。
