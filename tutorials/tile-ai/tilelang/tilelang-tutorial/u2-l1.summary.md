本讲是 DSL 语言基础第一课，承接上一讲 GEMM 实跑，逐行拆解「一个 tilelang kernel 是如何被声明出来的」，覆盖四个最小模块。

首先，在 tilelang 中一个 kernel 就是一个 TIR PrimFunc：用 `@T.prim_func`（或外层 `@tilelang.jit`）装饰 Python 函数，装饰器会在编译期「执行一次」函数体，把 `T.Kernel`、循环等语句搭建成 TIR AST，产出 `PrimFunc` 对象。函数体里写的是「搭建 IR 的指令」而非运行时计算流程。

其次，`T.Tensor` 是描述「带形状与 dtype 的显存」的抽象，默认 scope 为 `global`，由 `TensorProxy` 生成 TIR Buffer；`T.Buffer` 是其已弃用别名，dtype 支持字符串、`T.float32`、`torch.float32` 三种等价写法。

第三，`with T.Kernel(...)` 声明启动上下文：`*blocks` 决定 gridDim 与 blockIdx 维度，`threads` 决定 blockDim；`as` 后的变量即 blockIdx 绑定，单维可写 `as bx`、多维写 `as (bx, by)`，其来源是 `KernelLaunchFrame` 的 `frames[0:-4]`，`T.ceildiv` 用于向上取整算网格数。

最后，符号维度处理编译期未知维度：term-level 的 `T.dynamic`（生成 TIR `Var`，`T.symbolic` 是其弃用别名）与 eager 模式专用的 `T.const`（运行时从实际张量推断形状），二者均支持逗号分隔一次声明多个，实现「一次编译、多种 shape」。

核心结论：`T.Kernel` 与 `T.const` 都依赖 `Builder.current()`，脱离 builder 上下文会抛 `JITNoBuilderError`；lazy 风格把 Python 整数烤进 IR（换 shape 通常重编译），eager 风格用 `T.const` 延后到运行时绑定。这些概念为后续讲义的内存层级、控制流、编译流程等主题奠定基础。
