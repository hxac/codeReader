本讲覆盖 tilelang 的测试体系与贡献流程，对应最小模块 `testing.python`（`testing.cpp` 目前仅为 `.gitkeep` 占位，`USE_GTEST OFF`，无独立 C++ 单测）。核心结论：tilelang 几乎全部通过 Python 集成测试间接验证 C++ 引擎，测试集中在 `testing/python/` 下「目录镜像子系统」组织；本地以 `python3 -m pytest testing` 运行。引入的关键术语包括 pytest **marker**（`perf` 性能测试默认被 `conftest.py` 的 `pytest_collection_modifyitems` 跳过，需 `--run-perf` 放行；`slow` 表长扫描）、**conftest.py** 的「零用例保护」（退出码 5）、`tilelang.testing` 的**硬件条件装饰器**（`requires_cuda` / `requires_cuda_or_cdna` / `requires_cdna` / `requires_gfx950` / `requires_cuda_compute_version_{ge,gt,le,lt,eq}`，导入期探测硬件、不满足则优雅 skip）及 `main()` 脚本入口。正确性测试遵循「`matmul` 工厂 + `run_gemm` + `profiler.assert_allclose(ref_program)`」三段式范式，example 测试仅需调用其 `main()`。贡献规范由 pre-commit（ruff + clang-format + codespell + pymarkdown）、`format.sh` 与 CI lint 作业三层强制，`testing/**`、`examples/**` 对 ruff 的 `UP/FA` 规则放宽。
