本讲梳理 tilelang 的编译总流程：DSL（写成 PrimFunc）如何变成可执行的 CUDA/HIP 源码。总入口 `tilelang.lower()` 的主体 `lower_to_host_device_ir()` 分五步推进——封装 IRModule、`determine_target` 解析 target、`PreLowerSemanticCheck` 语义检查、`resolve_pipeline` 跑 Pass 流水线、`Filter` 拆分 host/device。引入的关键术语有：IRModule（PrimFunc 容器）、Pass（IR→IR 变换）、Target、PassContext（Pass 运行时配置容器）、calling_conv（host/device 标记）、CompiledArtifact（编译产物）。

各枢纽统一采用「注册表 + 惰性加载」：`resolve_pipeline` 按 `target.kind.name` 选 Pass 序列（PassPipeline 仅是薄包装，真实顺序写死在各后端 lower 回调里，CUDA 约 50 个 Pass）；`resolve_device_codegen`/`resolve_host_codegen` 用 `supports_target` 谓词区分变体（如普通 CUDA 与 CuTeDSL）。PassContext 由 JIT 层用 `with tvm.transform.PassContext(config=...)` 打开，pipeline 内 Pass 经 `get_pass_context()` 回读开关（如 `disable_vectorize`）。

核心结论：`lower()` 不写死任何后端逻辑，仅按 target 查表调度，故能同时支持 cuda/hip/metal/cpu/webgpu；`SplitHostDevice` 是 pipeline 内部的 IR 变换（给函数打 calling_conv 标记），其后 `Filter` 才把模块分拣成 host_mod/device_mod；代码生成分「编译」与「只生成源码」两条路径，二进制编译默认交由 JIT 层负责。后续讲义将承接 JIT 装饰器、编译缓存与 Pass 内部实现。
