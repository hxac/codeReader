本讲回答 `tilelang.lower()` 产出的 `CompiledArtifact`（IR 与源码字符串）如何变成「喂 torch.Tensor、吐 torch.Tensor」的可调用对象，由 execution_backend 与 adapter 两套机制共同实现。**execution_backend（执行后端）** 是「按 target kind 注册 + 惰性加载 + `supports_target`/`is_available` 谓词双重过滤」的注册表，`auto` 取可用列表第一个，故各后端注册文件的书写顺序决定默认偏好（CUDA 默认 `tvm_ffi`）；其 spec 上的 `enable_host_codegen`/`enable_device_compile` 是给 `lower()` 的指令，决定产物 `rt_mod` 是否非空。**adapter（适配器）** 由 `BaseKernelAdapter` 以模板方法模式定下契约：子类实现 `_convert_torch_func()` 返回真正的执行闭包并赋给 `self.func`，`__call__` 委托之；`result_idx` 标记自动分配的输出位，stream/device 用 thunk 在调用时即时读取。`JITKernel` 作为工厂两处消费 execution_backend：先读 spec 标志传给 `lower()`，再以 `if/elif` 选定 adapter 类。五种 adapter（`tvm_ffi`/`nvrtc`/`cython`/`torch` 即 Metal/`cutedsl`）归为两种产物策略：策略 A 薄包装 TVM `rt_mod`（靠 DLPack 互通），策略 B 在构造时自编译源码、用 cuda-python 或 ctypes 启动，Metal 直接交 `torch.mps`、cutedsl 为工具链变体。
