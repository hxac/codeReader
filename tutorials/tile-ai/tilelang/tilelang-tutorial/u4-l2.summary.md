本讲聚焦 `tilelang.jit` 与 `tilelang.jit.kernel` 两个最小模块，讲解 `@tilelang.jit` 装饰器如何把 Python 函数包装成 `JITImpl` 并落地为可执行 kernel。核心结论有四点。其一，装饰函数有 lazy 与 eager 两种执行模式，由 `_infer_jit_mode` 委托 `JITFunc._is_lazy_style` 在首次调用时自动推断并固化：lazy 风格在函数内嵌套 `@T.prim_func` 并返回它，调用返回 `JITKernel` 对象、支持 `out_idx`；eager 风格用 `T.const`、`T.Tensor` 注解、`T.empty` 与 `return`，调用直接返回结果张量、不支持 `out_idx`。其二，`JITImpl.__call__` 走三层缓存——`_call_form_cache`（lazy 无 tensor 快路径）、`_kernel_cache`（键为 `parse_args` 产出的 `(p1_key, p2_key)` 二元组）、`JITFunc` 上的 `p1_cache`。其三，编译调用链逐层加码：`get_tir` 取 IR、`compile` 经 Pass 与 codegen 得 `JITKernel`、`get_kernel_source` 取设备源码；`par_compile` 用线程池批量编译，是 autotuner 的底层引擎。其四，`JITKernel` 由 `tilelang.lower` 产物（`CompiledArtifact`）与按 `execution_backend` 选择的 `adapter` 组成，`__call__` 委托给 `adapter.func`；eager 模式「一次模板、多 shape」复用由 `TirTemplate` 的 phase1（`T.const` 占位）/phase2（实参 shape 替换）两阶段机制实现。引入的关键术语有 `JITImpl`、lazy/eager、`out_idx`、`JITKernel`、`adapter`、`execution_backend`、`parse_args` 的 `p1_key`/`p2_key` 与 `TirTemplate`，供后续讲义承接。
