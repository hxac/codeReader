本讲拆解 tilelang 编译缓存机制，核心是为同一 kernel 反复编译避免重复劳动。引入关键概念**缓存键（cache key）**——键相同即输入相同可复用，键设计决定假命中与永远 miss 的权衡；键普遍用 **SHA-256** 把 JSON 字典（`sort_keys=True`）压成 64 位哈希。全讲刻画**四层缓存**（由近及远、作用域递增、速度递减）：① `_CallFormCache`，lazy 且无 tensor 参数的最快路径，靠「上次调用」记忆连哈希都省；② `_kernel_cache`，会话级内存缓存，键为 `parse_args` 产出的 `(p1_key,p2_key)`，捕获编译参数与运行期形状，配合 `p1_cache` 实现「同模板多 shape」复用；③ `KernelCache`，按 execution_backend 分发的单例，进程内存加跨进程磁盘两级，键由 `_generate_key`（TIR script 哈希、target、pass_configs、compile_flags、版本等）构成，磁盘目录按「版本/平台」命名空间隔离；④ `CUDABinaryCache`，缓存 cubin/fatbin 裸设备二进制，编译选项必须进键以防 fast-math 假命中。磁盘命中经 `JITKernel.from_database` 跳过 lower/codegen 秒级返回；健壮性靠 staging 原子写与加载失败自愈。总开关为 `env.is_cache_enabled()`，`TILELANG_DISABLE_CACHE` 为高优先级硬开关，`disable_cache()` 为运行时软开关，共同控制③④。
