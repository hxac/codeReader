本讲串联编译流水线的「最后一棒」，讲清展开后的 device TIR 如何变成可被 nvcc 编译的 CUDA C++。核心模块有四：一是设备代码生成 `CodeGenTileLangCUDA` 继承 `CodeGenC`，用访问者模式把底层 intrinsic（`mma_sync`/`cp.async`/`wgmma`）打印成 C++，并在 `Finish()` 中按 `need_*` 标志实现「按需 include」模板头；它经 `BuildTileLangCUDA` 走 nvcc 出 cubin，或经 `BuildTileLangCUDAWithoutCompile` 仅产源码供 `get_kernel_source()` 调试。二是 tile op 注册机制：`LowerTileOp` 在 `EvaluateNode` 处经 `ParseOperator` 查 `TLOpBuilder` 属性表把 `tl.tileop.*` 占位构造成 `XxxNode`，再调 `Lower()` 展开。三是两类 lowering 分工：GEMM 走「C++ 框架 + Python 策略」的混合模式，`GemmNode::Lower` 跨语言回调 Python `tl.gemm.lower`；Copy 全程纯 C++ 用函数指针表选 TMA/cp.async/循环。四是两段式 GEMM 分发：C++ 注册表（`GemmImpl::SelectInst`）按架构选指令键并算 warp 切分，Python 注册表（`resolve_gemm_impl`）按键挑实现类发射指令，衔接点是 FFI `tl.GemmGetGemmInstructionKey`。最后，模板头注入走 `-I $TILELANG_TEMPLATE_PATH`（默认 `src/`），让 `tl::AllReduce`、`tl::cp_async_*` 等调用命中 `src/tl_templates/cuda/` 下的预写模板。
