本讲承接 u1-l2（安装与构建），解决「`import tilelang` 之后包里到底装了什么、C++ 引擎藏在哪里」的问题，覆盖三个最小模块。

**仓库两面性**：tilelang 是一个编译器，同时拥有用户面（`tilelang/` Python 包，含 DSL、JIT、编译入口、缓存、profiler）与引擎面（`src/` C++ 源码，含 Pass、tile op lowering、代码生成、运行时）。二者通过 TVM 的 `tvm_ffi` 机制相连——C++ 侧 `TVM_REGISTER_GLOBAL("tl.xxx")` 注册的函数被 `init_ffi_api("tl")` 挂到 Python。存在系统级前后端镜像：`transform↔transform`、`tileop↔op`、`cuda↔cuda`、`backend↔backend`；而 `language/`、`carver/`、`autotuner/` 是纯 Python，`src/transform/`（39 个 Pass）等是 C++ 重实现。

**包入口引导**：`__init__.py` 按序做四件事——算版本、初始化日志、加载 native 库、导出公共 API。引入关键概念**轻量导入（light import）**：`env.is_light_import()` 为真时跳过 native 库加载与重模块导入，让无 GPU 机器也能 import。native 库定位靠 `libinfo.find_lib_path` 跨平台拼名（Linux 为 `libtilelang.so`，Windows 特例为 `tvm_compiler.dll`）并在 `env.TL_LIBS` 搜索根中查找。

**环境层 `env.py`**：用 `EnvVar` 描述符 + `Environment` 类把全部环境变量集中定义，实例化为全局 `env` 单例；读取遵循「强制覆盖 > os.environ > 默认值」三级优先级且动态生效；同时计算 `TL_LIBS`（区分安装版/ dev 版）并探测 CUDA/ROCm 路径。

核心结论：三类入口为 DSL 入口 `tilelang.language`、编译入口 `tilelang.engine.lower`、对外 API `jit/compile/Profiler/autotune`。
