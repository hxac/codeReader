本讲解释用户写的 target 如何变成 TVM Target 并决定代码生成走向。统一入口 `determine_target` 把 "auto"/字符串/字典/Target 四类输入归一化（必要时物化为 Target），归一化器会被调用两次以确保补全后端属性。"auto" 按 CUDA→HIP→Metal 顺序遍历探测器注册表（dict 插入序）取首个非 None 命中，llvm/c/webgpu 不参与自动探测；探测器与归一化器由各后端在自身 target.py 末尾注册，HIP 归一化器负责补全 mtriple 与 thread_warp_size。语言层为门面模式：tilelang.language 默认即 CUDA 方言，各后端共享 language.common 并追加硬件扩展（CUDA 方言最胖，含 TMA/cluster/warpgroup；CPU/WebGPU 最瘦），以 __tilelang_dialect__ 标识当前方言。CuTeDSL 不是独立 kind，而是 kind 仍为 cuda、仅在 target.keys 追加 "cutedsl" 标签的后端变体，device codegen 注册表用 supports_target 谓词在同一 kind 下分流到普通 cuda 或 cutedsl codegen。探测器/归一化器、device codegen、execution backend 均采用「按 target kind 注册 + 惰性 import + 谓词匹配」的同一套注册表模式，resolve_* 为各自查表入口。
