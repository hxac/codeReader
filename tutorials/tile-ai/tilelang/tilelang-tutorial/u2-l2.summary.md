本讲聚焦 tilelang 的内存层级与数据搬运，承接 u2-l1 的 kernel 骨架，覆盖三个最小模块：`tilelang.language.allocate`、`tilelang.language.copy_op` 与 `tilelang.language.fill_op`。核心结论是：GPU 显存延迟高，高性能 kernel 的标准套路是把一个数据块（tile）沿 global→shared→fragment 搬到寄存器里反复计算，再写回 global。tilelang 用 scope 字符串标注缓冲驻留的内存：`T.alloc_shared` 对应 `shared.dyn`（编译为 `extern __shared__`，且多个分配会被 `merge_shared_memory_allocations` 合并到一块动态共享内存）；`T.alloc_fragment` 对应 `local.fragment`（带 layout 推理语义、可对接张量核，lowering 时重映射为寄存器 `local`）；`T.alloc_local`/`T.alloc_var` 为线程私有寄存器。Python 侧仅声明 scope，物理分配发生在 C++ codegen，且 CUDA 后端禁止 `alloc_global`，global 数组必须作为 `T.Tensor` 参数传入。`T.copy(src, dst)` 是核心搬运原语，只生成 `tl.tileop.copy` intrinsic，extent 由两侧推断并支持「头地址语法糖」，后端依 scope 组合自动选择 TMA / cp.async / ldmatrix / 普通循环；其变体 `T.async_copy`（仅 global→shared、SM80+、不自动 wait）与 `T.tma_copy`（用户自管同步）需手动管理同步。`T.fill` 与 `T.clear` 生成 `tl.tileop.fill`，用于初始化缓冲，累加型操作（如默认 `T.gemm`）前必须先清零。
