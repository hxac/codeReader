本讲是 tilelang 的「Hello World」，以 `examples/quickstart.py` 为主线，串起「写 DSL → 编译 → 调用 → 验证 → 看源码 → 测延迟」全链路。讲义覆盖四个最小模块：

一是 `tilelang.jit`：`@tilelang.jit` 把 Python 函数包成可编译对象 `JITImpl`，函数体是 DSL 蓝图而非运行逻辑。有 lazy（返回 PrimFunc，调用返回 kernel 对象）和 eager（用张量注解书写，调用即编译执行返回结果张量）两种模式，由 `_infer_jit_mode()` 自动推断；`.compile(...)` 走显式编译返回 `JITKernel`，内部经 TIR 函数、`tilelang.lower()` 与缓存层，并用 adapter 包装成可接 PyTorch tensor 的可调用对象。

二是 `tilelang.language`（默认 CUDA 方言）：`T.Kernel(grid..., threads=...)` 描述启动上下文；`T.alloc_shared`（scope `shared.dyn`）与 `T.alloc_fragment`（scope `local.fragment`）分配片上缓冲；`T.copy` 是语法糖式并行搬运，表达「global→片上→global」的 tile 数据流。

三是计算核心：`T.gemm(A,B,C)` 默认累加（`clear_accum=False`，需先 `T.clear`），自动 dispatch 到 CuTe/HIP 张量核；`T.Pipelined(range, num_stages=N)` 用多级缓冲实现软件流水线以隐藏访存延迟。

四是 `tilelang.profiler`：`get_kernel_source()` 看生成的 CUDA/HIP 源码，`get_profiler().do_bench()` 自动测延迟，支持 `event`/`cupti`/`cudagraph` 后端与 `TensorSupplyType` 输入供给。

核心结论是：tilelang 把 Python 写的 tile 级 DSL 翻译成含 shared memory 与张量核调用的真实设备 kernel。关键术语 `@tilelang.jit`、`JITKernel`、adapter、`T.Kernel`、`T.copy`、`T.gemm`、`T.Pipelined`、`T.clear`、`T.Parallel`、`T.ceildiv`、`tilelang.lower()`，供后续 DSL（u2）、计算调度（u3）、编译流水线（u4）承接。
