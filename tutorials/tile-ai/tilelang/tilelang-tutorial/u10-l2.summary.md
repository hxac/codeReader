本讲是手册收尾篇，从「怎么用」转向「怎么改」，反向应用 u6/u7 建立的链路做二次开发，讲解三条扩展路径。

新增一个 tile op 需改四层并靠同名串联：Python language 层用 `call_intrin` 留 `tl.tileop.<name>` 占位节点；C++ op 层实现 `TileOperatorNode` 的纯虚钩子 `Lower`/`InferLayout`，用宏 `TIR_REGISTER_TL_TILE_OP` 注册 op 并绑 `TLOpBuilder` 属性表，由 `LowerTileOp` Pass 内的 `ParseOperator` 查表构造；Python tileop 层用 `@tvm_ffi.register_global_func` 注册 `tl.<name>.lower`/`infer_layout` 供 C++ 回调；多后端时再加 `(inst_name, predicate)` 注册表分发（唯一性约束）。核心模型是「DSL 留占位、后按硬件展开」。

新增一个 Pass 需三步：C++ 用 `CreatePrimFuncPass` 包装变换、用 `TVM_FFI_STATIC_INIT_BLOCK`+`refl::GlobalDef().def("tl.transform.<Name>")` 注册；Python 加 `_ffi_api.<Name>()` 薄包装；最后在某个后端 `pipeline.py` body 里按正确相对顺序调用。关键结论：未接入 pipeline 的 Pass 永不执行，Pass 相对顺序（如 `InjectSoftwarePipeline`→`LayoutInference`→`LowerTileOp`）至关重要。`PassPipeline` 是薄壳，真实顺序写死在 body，`resolve_pipeline(target)` 按 `target.kind.name` 查表，多个 kind 可共享一条 body。

移植新后端需补五类注册点加包入口：language 方言（设 `__tilelang_dialect__`）、pipeline、tileop 实现、device/host codegen、execution_backend，全程用同一 `target.kind.name` 串联；CPU 后端是最瘦参照模板。

贯穿全文的三个统一模式：属性表（`TLOpBuilder`）、注册表+惰性加载+谓词匹配、`TVM_FFI_STATIC_INIT_BLOCK`+`refl::GlobalDef` 的 C++→Python FFI 桥。
