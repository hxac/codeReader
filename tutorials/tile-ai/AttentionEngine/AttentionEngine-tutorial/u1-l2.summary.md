本讲承接 u1-l1，目标是把 AttentionEngine 这条编译链在本机跑起来，覆盖三个最小模块：环境搭建、`meta_tensor` 形状元信息、运行 `mha.py`。核心结论有三：其一，AttentionEngine 不是 `pip install` 包，需带 submodule 克隆、源码编译 TileLang，并用 `PYTHONPATH` 同时挂载 `attention_engine/` 与 `3rd_parties/tilelang`，再用 `LD_PRELOAD` 预加载 `libcuda.so` 绑定 CUDA 驱动符号。其二，`meta_tensor` 是纯 Python 形状占位类（只存 `shape` 与 `kargs`），并非 torch 的 meta device 张量，能接受字符串维度描述动态形状；三个 `meta_tensor` 组成 `qkv_meta`，是 `AttentionEngine(...)` 编译阶段的唯一形状来源。其三，`mha.py` 把 `score_mod`/`mask_mod`/`OnlineSoftmax`/`CustomIO` 组装后构造 `mod`——构造即编译，`mod` 可像普通 PyTorch 算子一样前向与反向；`do_bench_attention` 同时做与 flash-attn 的正确性比对和延迟/tflops 测量，吞吐按 `F/t × 1e-9` 估算。引入的关键术语包括 `qkv_meta`、`meta_tensor`、`AttentionEngine` 构造签名（`tune`/`tune_file`/`infer_mask`/默认 `backend="tl"`、`device=H100()`）、`do_bench_attention` 与 TFLOPS 估算公式，供后续讲义承接。
