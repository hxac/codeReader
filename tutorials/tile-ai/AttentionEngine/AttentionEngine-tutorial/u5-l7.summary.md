本讲是 AttentionEngine 学习路线收官篇，从整体视角回答能力边界、待办现状与二次开发方向三问。核心结论：框架能力须沿表达力、场景、平台三个正交维度分别度量——online_func 不支持自动微分，四段方法须手写，反向只算 q/k/v 梯度、不算 custom input 张量；score_mod 反向由手写的 SymbolScalar._backward 完成，仅支持 Add/Mul/Div/Tanh/Max/Log 六类算子，其余抛 NotImplementedError，底层 graph.py 覆盖面更窄。关键概念包括：声明型 roadmap 与代码 TODO 两层待办会不一致，且 roadmap 常落后于代码（解码、combine kernel 已部分落地却仍挂未完成）；二次开发采用「层级责任模型」——新算子落 IR、新场景落 lower 加 template 加引擎分发、新后端落 codegen 加 template 加 backend 分流；静态 autotuner（decider.py）逻辑已就绪但未接线，是边界清晰的改进切入点。方法论是：判断功能真实状态永远以代码为准，而非文档 checklist。
