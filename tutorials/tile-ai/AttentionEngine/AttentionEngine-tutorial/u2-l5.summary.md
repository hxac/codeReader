本讲讲解 `lower_score_mod` 如何把用户用 Python 写的 `score_mod` 函数降级成 kernel 代码。分三步：一是符号化——构造 scores、b、h、q_idx、kv_idx 等符号诱饵（用逐元素的 `SymbolScalar`，而非带行规约的 `SymbolicArray`）喂入 `score_mod` 执行一遍，靠运算符重载自动挂出符号 DAG，无需解析源码；二是前向降级——用 `generate_tl_from_dag` 发射函数体，再由 codegen helper（`func_block`、`call_op`、`arg_def`）拼出函数定义 `score_mod_func_def` 与调用 `call_score_mod`，二者共用同一份 `input_vars` 名字表当形参/实参；三是反向降级——不依赖 PyTorch autograd，而由 `SymbolScalar._backward` 手写的反向模式自动微分，给定上游梯度 `dsT` 沿 `prev` 链递归分发、多路径用 Add 累加，把结果挂到 `qkT.grad` 上后发射成 `score_mod_backward`，并采用 recompute-in-backward 先重算前向中间量以省显存。核心约束：`_backward` 仅支持 Add/Mul/Div/Tanh/Max/Log，故 sigmoidattn 用 tanh 等价写 sigmoid 而非 exp（Exp 反向未实现），体现了符号 autodiff 能力边界反向约束用户写法。最终产物 `lowerScoreModOutput` 会填入 Jinja2 模板。
