本讲承接 u2-l3，讲清符号 DAG 如何经 `generate_tl_from_dag` 发射成三种后端代码。核心是 `tl_gen.py` 里签名相同的三套发射器 `to_tl_op`/`to_cute_op`/`to_pytorch_op`，由调度入口按 `to_tl > to_cute > pytorch` 的布尔优先级三选一，而 DAG 后序遍历、去重与 inplace 复用逻辑对三后端完全复用，体现中间表示与目标语言的解耦。三后端的本质差异在于循环结构与索引对齐：tl 用 `for...in T.Parallel(...)` 加方括号下标、按维度名对齐；cute 用 `#pragma unroll` 与 C++ `for`、圆括号下标、按位置对齐；pytorch 不生成循环，靠张量广播、`[...,None]` 补维与 `.sum` 降维。数值技巧上，tl 与 cute 都把 `exp(x)` 换底为 `exp2(x*1.442695)`（log₂e）以借 GPU 快速指数指令，tl 的 `log` 写成 `log2(x)*0.69314718`（ln2），cute 直接用 CUDA 内建 `__logf`，pytorch 用原生 `torch.exp`/`torch.log` 不改写；`Exp2`/`Log2` 节点则保持原生、不乘常数。落点上，tl 是训练与解码的 GPU kernel 主力，cute 仅见于 `lower_cute.py`，pytorch 仅作为线性注意力 mod 预处理的宿主机参考实现。
