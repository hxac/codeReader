本讲承接 u3-l3 的引擎分发，单独拆解「训练阶段、Q 头多于 KV 头」的 GQA 降级路径。核心形状约束是 `head > head_kv` 且训练期 `q_seqlen == kv_len`，引擎据此在 `_select_lower_template` 分流到 `lower_gqa.py`。关键结论是：`lower_gqa` 只是 `lower.py` 的「换模板 fork」——IR、降级三件套（lower_kernel/score_mod/online_func）逐字共享，分组语义对降级层完全透明；真正的 GQA 差异全沉淀在模板 `attn_gqa_tl.py`：kernel 多一个 `groups` 形参，K/V 用 `heads_kv = heads // groups`，加载写回头下标做 `by // groups`（前向）、`bx // groups`（反向）整除，反向 dK/dV 因多 Q 头共享同一 KV 头改用 `atomic_add` 归并梯度。需厘清命名陷阱：脚本/benchmark 的 `groupnum` 指 KV 头数，kernel 的 `groups` 指组大小（H/G），二者互为倒数。`lower_gqa` 还存在缺 `-inf→-1e38` 保护、infer_mask 简陋等外围分叉。本讲引出的术语 head/head_kv/groups/by//groups 将由 u4-l3 的解码 GQA（lower_decode_gqa、split-kv）承接。
