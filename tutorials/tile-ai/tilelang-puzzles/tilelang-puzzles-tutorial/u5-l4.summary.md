本讲是「卷积、量化与性能工程」单元的收官篇，几乎不引入新的 DSL 语义，而是把 GEMM（u4-l4）与卷积（u5-l1/l2）中已写好的代码当作研究对象，从工程方法角度回答「怎么把 kernel 写快，并证明它确实变快」。全讲由三个最小模块构成「测得准 → 看得懂 → 调得动」的闭环。模块一讲解 GPU 计时方法学：因 GPU 异步执行与 JIT 冷启动开销，朴素墙钟时间不可信；`bench_puzzle` 用 warmup（预热丢弃）、repeats（重复平均）、成对 CUDA Event 时间戳与前后 synchronize 同时堵住这两个陷阱，给出稳态耗时。模块二讲解代码检视：`compile().print_source_code()` 让 TileLang 从黑盒变玻璃盒，可确认 `T.alloc_shared` 落到 `__shared__`、`T.gemm` 落到 Tensor Core 的 `mma`/`ldmatrix`、`T.Pipelined` 生成 prologue/稳态/epilogue 三段调度。模块三讲解三个调参旋钮——block size、num_stages、shared vs fragment——及其物理约束：寄存器总量、共享内存容量、occupancy（每 SM 可驻留 block 数）。核心结论包括：`num_stages` 与 shared 副本数近似线性，存在 occupancy 拐点（经验值 2~4）；累加器放 fragment、输入 tile 放 shared；调参须一次只改一个旋钮、先保证正确性再计时再读 codegen。本讲方法论可迁移至 Triton、CUDA C 等任何 GPU kernel 工程。
