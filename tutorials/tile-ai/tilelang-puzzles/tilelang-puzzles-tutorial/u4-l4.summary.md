本讲在 u4-l3 朴素 GEMM 基础上，不引入新算子语义，只通过两项改动实现大幅加速。第一项是**共享内存优化**：把一次性的输入 tile A、B 用 `T.alloc_shared` 从寄存器（fragment）挪到片上共享内存，而把高频读写的累加器 `C_local` 留在寄存器；这既缓解了朴素版因 C 占用过大导致的**寄存器溢出**，又对齐了 `T.gemm`（Tensor Core MMA）以共享内存为高效输入来源的特性。第二项是**软件流水线**：用 `T.Pipelined(K // BLOCK_K, num_stages=3)` 替换 `T.Serial`，让「搬运下一段 tile」与「计算当前段」重叠，用计算掩盖访存延迟，编译器自动生成 prologue、稳态、epilogue 三段调度。两项互补，前者解决容量与布局，后者解决时序。验证手段为「正确性 + 生成代码 + 性能」三件套：`test_puzzle`、`compile().print_source_code()`（可见 `__shared__` 缓冲）、`bench_puzzle`（warmup=10、repeats=100、CUDA Event 计时）。`num_stages` 受 shared memory 容量约束，典型经验值 2~4，非越大越好；文档里的 `T.Pipeline` 系笔误，实际 API 为 `T.Pipelined`。这两项优化是后续卷积、量化矩阵乘等高性能 kernel 的通用骨架。
