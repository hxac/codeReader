本讲承接 Puzzle 02，从「算得并行」转向「搬得省、搬得快」，主题是 GPU 内存层级与显式寄存器优化。它讲清三级内存：global memory（显存，最大最慢、所有线程可见）、shared memory（block 内共享、中等）、registers（线程局部、最快最小），核心直觉是「越快越小」，性能工程应让数据尽量待在快的存储里。主角 `T.alloc_fragment` 把「一个 block 内所有线程的寄存器」抽象成一块可像普通 buffer 操作的 fragment，框架自动完成逻辑下标到具体线程寄存器的映射，免去手写 CUDA 线程映射；配合 `T.copy` 在 global 与 fragment 间批量搬运（如 `ldg128` 一次搬 128 位），将朴素 mul-relu 改写为「批量搬入寄存器、块内计算、批量搬出」，与朴素版计算同构，差别只在数据落点。还引入 `@tilelang.jit` 的 `pass_configs` 开关（`TL_DISABLE_WARP_SPECIALIZED` / `TL_DISABLE_TMA_LOWER`）关掉本节用不上的高级 lowering，让生成代码更易读；并用 `compile().print_source_code()` 配合 `bench_puzzle`（CUDA Event + warmup + repeats + synchronize）构成「正确性 + 生成代码 + 性能」三件套。本讲是后续二维 fragment、`T.alloc_shared` 共享内存与 `T.Pipelined` 三级搬运链路的起点。
