本讲拆解 TileLang kernel 的结构与项目的测试/基准框架，覆盖三个核心模块。其一，kernel 由 `@tilelang.jit` 装饰（EagerJIT 即时编译风格），函数体分 host 声明部分（用 `T.const` 声明符号维度、`T.Tensor` 标注输入形状与 dtype、`T.empty` 分配输出）与 device 计算部分（`with T.Kernel`），并以 return 输出收尾；符号维度在 `compile` 时由调用方绑定，分块大小等则作为编译期超参数直接写成 Python 形参。其二，`T.Kernel(各维度 block 数, threads=N) as (块索引...)` 决定启动配置，位置参数个数即 grid 维数与块索引变量个数，`T.ceildiv` 用于算向上取整的 block 数，块索引（如 bx、pid_n）是各 block 定位自身数据区间的依据。其三，`test_puzzle` 仅凭编译后 KernelParam 的 shape/dtype 自动造随机输入，并按「最后一个张量即输出」的约定跳过输出张量，跑 torch 参考实现后用 `torch.allclose`（带 atol/rtol 容差）比对；`bench_puzzle` 则用 CUDA Event 配合 `synchronize` 与 warmup 做公平计时。核心结论：项目所有 puzzle 共享这套骨架与「输出放最后」的约定，因此每个 puzzle 的验证代码极简，开发者只需补全 `with T.Kernel` 内的 DSL 代码。
