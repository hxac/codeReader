本讲承接 u9-l1 四阶段信任模型（Manifest→Test→Implementation→Benchmark），聚焦把算子 `status` 从 `spec-only` 翻转为 `implemented` 这一状态跃迁，涵盖三个最小模块。第一，**status 翻转**是「一把钥匙」：这一行 YAML 改动同时打开 codegen 开关（合成真实方法体）、收紧 validator 关卡（spec-only 只过 L0，implemented 须过 L0–L4）、激活实现 PR 的窄化写权限。第二，**carve-out（豁免清单）**：信任模型默认实现 PR 不许碰 manifest 契约字段，但翻转时允许改 `status`、`source.kernel_map` 条目、`source.test`/`source.bench`（发现性指针，非契约字段）、（仅 promotion 时）`workloads`、（仅随 compile-test 证据时）`torch_compile_fullgraph`；其余如 `signature`、`roofline.*`、`shape_rules` 须单独 manifest-only PR 加人审。第三，**kernel_map 必填已升级为 L0 硬错误**：`_l0_kernel_map` 对 implemented 缺 `kernel_map` 直接报错，而 carve-out 又允许填它，使「翻转时补 kernel_map」既必要又合法。核心铁律：实现不服从 spec 就标 spec-only、修代码，绝不改 manifest 迎合代码，也不许删契约字段压 validator 错；carve-out 只收窄禁止项，不放松信任边界。
