本讲是 TileOPs 性能基准篇的首讲，核心模块为 `BenchmarkBase[W]` 泛型基类与 `bench_kernel` 计时协议。`BenchmarkBase` 用类型参数 `W`（workload 能力协议，而非 `WorkloadBase`）精确声明基准需求，子类实现 `calculate_flops` / `calculate_memory` 抽象契约，`profile` 入口调 `bench_kernel` 拿纯 kernel latency 后，由 `_build_result` 组装成含 TFLOPS 与带宽的结果字典，并透明标注任何协议偏离。

`bench_kernel` 实现 NVIDIA SOL-ExecBench 风格协议：10 warmup + 3 trials × 50 repeats，返回 trial mean 的中位数，剔除 JIT 与系统抖动。关键机制包括：输入克隆池预克隆 3 份轮转以打破地址复用缓存惯量（超 1 GB 跳过并标注）、L2 flush 用按真实 L2 大小分配的缓冲 `zero_()` 挤出旧缓存。计时主路径经 `torch.profiler` 走 CUPTI，用 `record_function` 标注窗口投影到设备时间线，`_sum_kernel_time_us` 只累加窗口内 kernel（排除 flush、不依赖 kernel 名，支持多 kernel 协作算子）。CUPTI 投影失败（`n_regions != n_repeat`）时回退 CUDA-events，但该路径含约 50–60 微秒 launch overhead，对快 kernel 膨胀约 6–7 倍、不可用于 SOL 效率；新增开关 `TILEOPS_ALLOW_CUDA_EVENTS_FALLBACK=0` 可禁止回退直接抛错，体现「宁可失败，不可撒谎」的诚实测量原则。本讲确立了「测出的 latency 可信」这一性能篇基石，承接后续 u6-l2、u6-l3 与 u7。
