本讲讲 elementwise 家族（60+ 算子）的模板化复用，核心是三个伞形基类（umbrella base）：`UnaryOp`（1→1）、`BinaryOp`（2→1，支持 N 维广播）、`FusedGatedOp`（(M,2N)→(M,N)，唯一支持 lazy 构造）。叶子算子退化为 T1 薄包装，仅填 `kernel_cls` 与 `_op_name`（兼作 manifest dispatch key 与 custom_op 命名后缀）即可继承整条 forward/构造/注册链路。配套四机制：`coalesce_broadcast_dims` 把 N 维广播按「同广播行为」贪心合并到最少有效维，降低 kernel 内 divmod 次数，同形连续时退化为零 divmod 快路径；inplace 分发由二级基类 `_UnaryActivationMixin` 收拢，走 `mutates_args=("x",)` 的 `_wrapped_inplace`（保证 `y is x`），原地性在包装层而非 kernel；FP8 e5m2 走「kernel 出 fp16、Op 层 `_apply_fp8_post_cast` 非饱和 cast」两段式（e4m3fn 由 kernel 饱和直出）；`UnaryOp`/`FusedGatedOp` 手写 `eval_roofline`（按 `FLOPS_PER_ELEM` 系数），`BinaryOp` 则交 manifest codegen 合成——三种基类的刻意不对称。类体内 `_wrapped=None` 是安全默认，包加载时由 `__init__.py` 注册循环覆写为真实 custom_op。
