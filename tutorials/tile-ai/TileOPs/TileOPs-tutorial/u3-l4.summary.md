本讲是 Kernel 层进阶篇，解决 cumsum 在 M 小、N 大时单 kernel 跑不满 GPU 的问题。核心是形状驱动的 kernel 分发：满足 M<128、N>8192 且 op_kind 为 sum 时走三阶段并行扫描，否则走单 kernel 顺序扫描；判据在 CumulativeKernel 构造期写入 use_parallel，Op 层与 manifest 对此完全无感。三阶段并行扫描为 local-scan（块内前缀和并产出 tile 总和，二维网格全并行）→ carry-scan（对 tile 总和做排他型前缀和，一线程一行，唯一串行但极轻）→ propagate（加进位并做边界 cast），把长度 N 的顺序依赖压缩到 n_tiles。全程用 fp32 中间量 tile_sums/tile_carries/y_local，遵循提升到 fp32 累加、边界 cast 的数值约定。cumprod 因数值溢出与乘法进位复杂度永远回退到顺序后端，与 cumsum 共骨架仅累加器初值（0/1）与运算（+/×）不同。本讲是「多 kernel 协作」的范例，体现 Op/Kernel 双层分离的扩展性。
