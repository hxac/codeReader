本讲义拆解 Op 基类的 kernel 安装流程，覆盖三个最小模块。核心入口是 `_install_kernel_map`：它把子类声明的默认登记表 `default_kernel_map` 与用户传入的覆盖表 `kernel_map` 合并，对每个解析出的 kernel 类做架构校验后写回 `self.kernel_map`，且默认 kernel 与用户覆盖 kernel 走同一段校验代码。关键术语 `supported_archs` 是 `Kernel` 类属性，`None` 表示不限架构、直接放行，列表（如 `[90]`）表示仅可在这些 SM 版本运行，不匹配则在构造期 fail-fast 抛 `ValueError`。`get_sm_version()` 把设备能力压成整数（Hopper=90）。核心结论有三：架构检查发生在 kernel 类层面、早于 `forward`；`default_kernel_map` 既是抽象属性又是 override 基准，用户只能逐 key 替换已有条目、不能新增；`GemmOp` 用条件注册配合运行时 `.get()` 实现非 SM90 自动回退。复合 Op 走另一分支，架构校验下放给子 Op。
