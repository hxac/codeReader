本讲覆盖 Roofline 模型三个最小模块：profile 加载、effective 计算、func 公式签名。核心结论：GPU profile YAML 只存 theoretical（厂商 spec）与 calibration（微基准测出的峰值比例），effective = theoretical × calibration 由 load_profile() 加载时注入，不写进 YAML；用标定后的有效峰值当 SOL 效率分母，使效率落在可解读区间，H20 因理论值为政策压低数而 calibration 结构性偏高。func 模式推荐签名 func(op) -> (flops, bytes)，codegen 在类定义期 eager 解析 dotted 路径并 emit return fn(self)，坏路径在 codegen 闸门即报错。多输入 dtype 字节记账、post-broadcast 的 N_total、条件性张量与多阶段融合三类场景必须用 func 而非 inline 的单一 elem_bytes。基准 M4 仅调 op.eval_roofline() 取 (flops, bytes) 并测 raw time，与 M5 效率计算严格解耦，禁止本地公式。
