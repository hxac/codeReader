本讲承接家族基类与伞形基类，把「家族复用」推进到按空间维数分裂的算子族（pool / reduction），核心是：当家族差异恰好是「几维」这种可参数化标量时，最高效的做法不是再加继承层，而是把维数塞进一个类属性，让流水线代码统一驱动。

引入的关键概念：**ndim 泛化基类**——pool 用 `ndim: ClassVar[int]` 把 MaxPool/AvgPool 的 1d/2d/3d 合成一套 forward/_eager_forward/_get_kernel 流水线，输入秩恒为 nd+2，差异只落在类属性与查表；**变体类属性**（`_kernel_slot`/`_returns_indices`/`_generic_slot`/`_spatial_slot`）在共享基类内区分 indexed 与快路径等变体；**表驱动命名**——kernel 构造关键字由按 ndim 索引的四张字典（`_POOL_DIM_NAMES` 等）生成，永远用 `**kwargs`、永不走位置参数；**kernel-cache key 不变量**——重构可删过度设计，但 cache key 字段集合必须保持稳定，否则缓存失效或错误命中。

本讲两个重要结论：其一，本轮重构把 indexed max-pool 的 forward 从 `__init_subclass__` 工厂自动生成改回每个叶子显式声明（剥离过度设计），`_returns_indices` 转为驱动形状推导与 roofline 字节记账；其二，`MeanPoolingForwardOp` 从 attention 家族迁入 pool 家族却仍以独立 eager Op 身份存在，示范了「归属（组织）」与「机制（复用）」相互独立——享受目录归属但不沾染泛化机制。最后以 reduction 家族作对照：reduction 参数化的是「任意归约轴」而非「固定空间秩」，故用 `_multidim`（normalize_dim/flatten_for_multidim/restore_multidim_shape）运行时把任意秩压成 (M,N) 复用单维 kernel，kernel 层用 `_primitives` 的 `T.macro` 工厂共享原语。两套策略都恪守「类属性驱动 + 关键字驱动 + cache key 稳定」三条铁律，且 `eval_roofline`/`_validate_dtypes` 两个 codegen 契约必须 class-local、不可靠继承传递。
