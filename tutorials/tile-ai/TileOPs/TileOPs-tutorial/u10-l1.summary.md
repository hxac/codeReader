本讲围绕「编译边界不变量」：被 dynamo 追踪的 `Op.forward` 不得构造 `Kernel`、不得进入 TileLang builder。对 lazy-dispatch 算子（forward 在运行时查 kernel cache、miss 时现构造，典型如 pool），eager 预热只藏 miss 路径、不满足冷调用契约。正解是把「查 cache→构造→launch」整条不可追踪路径藏进 `torch.library.custom_op` 的 eager 体，fake 体用 `_infer_output_shapes` 推输出 meta，`forward` 收敛成一行单次分发。配套的 weak 全局注册表 `compile_boundary._OP_REGISTRY` 由 `register_instance` 在 `Op.dispatch_kernel` 这唯一的零样板点用 `str(id(op))` 作字符串 key 登记。三重设计理由：`WeakValueDictionary` 防内存泄漏；dynamo 的 `ID_MATCH` 弱守卫使被复用的 `id()` 无法命中陈旧图，保 stale-graph 安全；字符串 key（而非 int）避免同帧多实例编译时 int 被泛化为不可哈希的 `SymInt`。规范范本为 pool.py、batch_norm.py；elementwise/rope/dropout 仍用旧式 int key 表，属待迁移状态。构造期即建好 kernel 的算子空真满足不变量，不需此边界。
