本讲把 u1-l2 跑通 `GemmOp` 的手感正式化为契约，覆盖三个最小模块。其一，**ops 导出聚合**：`tileops.ops` 是算子的唯一公开入口，`__init__.py` 把散落各子模块（`gemm.py`、`norm/`、`reduction/` 等）的算子类收集重导，配 `__all__` 白名单，用户统一写 `from tileops.ops import XxxOp`，绕开内部文件布局以保持重构稳定性。其二，**可调用契约**：每个 `Op` 都是可调用对象，套路是「先实例化再调用」——`op = XxxOp(构造参数)`、`out = op(*inputs)`，`__call__` 透明转发给子类必须实现的抽象方法 `forward`；构造期经 `dispatch_kernel` 安装 `kernel_map`，调用期才在 `forward` 里真正选并 JIT 编译 kernel，命中缓存后走快路径。其三，**input-inferred（输入推断）谱系**：TileOPs 尽量把形状与 dtype 延迟到调用时从输入张量推断，而非构造时写死。`GemmOp`/`SoftmaxFwdOp` 完全推断，`RMSNormFwdOp` 因对齐 padding 与字节记账把 `normalized_shape` 和 keyword-only 的 `dtype` 留在构造期提交，但前导维仍调用时推断。核心判据：是否构造期绑定取决于该维度是否影响 kernel 物理结构。配合的实践模式是以 PyTorch 函数为地面真值对比输出与误差。本讲引入的关键术语有「可调用契约」「构造期/调用期」「dispatch_kernel」「kernel_map」「input-inferred」「快路径缓存」，供后续 u2-l1 进入 `Op` 基类内部机制时承接。
