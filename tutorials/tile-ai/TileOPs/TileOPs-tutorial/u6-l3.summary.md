本讲承接 u6-l1（可信 kernel 计时），解决基准数字如何收集、归类、落盘并与基线对比。核心是 `BenchmarkReport` 静态收集器：`record/dump/clear` 三个 `@staticmethod`，状态存类级 `_records`，由 conftest 钩子驱动生命周期——session 开始 `clear()`、结束 `dump("profile_run.log")`。`record()` 一次调用双写两条路径：`_records` 喂人类可读的 markdown 报告，线程局部 `_bench_results.entries` 喂 conftest 转写成 JUnit XML `user_properties`，保证「人看的」与「机器读的」一致。引入关键术语：**tag 体系**（`tileops` 为被测方，`torch-ref`/`fa3`/`fla`/`flashinfer` 等为基线），conftest 用 `tag.startswith("tileops")` 拆分并支持 `tileops-fused` 等变体；**规范身份（canonical identity）**——传 Op 实例才能拿到「类名 + 模块」与 kernel config，字符串别名会丢失模块信息致归类混淆；**SOL 效率**——需可对比基线才能计算。两条信任边界：每个基准必须记至少一条非 `tileops` 基线；ref 函数必须就地定义，绝不从 `tests/` 或 `workloads/` 导入，以防正确性判据与性能基线耦合漂移（oracle 隔离）。产物为 raw time（M4）。
