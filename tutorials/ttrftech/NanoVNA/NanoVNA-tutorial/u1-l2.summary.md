本讲打通 NanoVNA 固件从源码到芯片的完整链路，覆盖四个模块：Makefile 构建系统、ChibiOS 子模块与板级支持包、链接脚本内存布局、DFU 烧录与 CircleCI 流水线。核心结论：`make` 用 arm-none-eabi 交叉工具链编译，以 nano.specs 精简库压缩体积，业务源码在 CSRC 清单中追加；ChibiOS 经 git 子模块引入，因需要 I2S 全双工 DMA 而用作者 fork 的 I2SFULLDUPLEX 分支，板级文件在仓库内的 NANOVNA_STM32_F072 目录；本机无工具链时可用与 CI 同源的 docker 镜像编译。链接脚本把 128K Flash 划为 96K 程序区与 32K 校准区（.calsave 段为 NOLOAD，升级不丢校准），RAM 仅 16K，中断主栈与线程栈各 0x200。VERSION 从 make 变量经 -D 宏进入版本菜单与 version 命令。烧录走 STM32 内置 USB DFU bootloader，`make flash` 即 dfu-util 写 0x08000000 后自动复位；CI 仅纯三段数字 tag 触发 GitHub Release 发布。关键术语：交叉编译、git 子模块、BSP、链接脚本、NOLOAD、DFU。
