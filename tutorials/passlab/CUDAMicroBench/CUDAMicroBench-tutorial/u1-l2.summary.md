本讲解决 CUDAMicroBench 如何编译与运行：先用 nvcc 与 nvidia-smi 体检工具链、驱动与计算能力，再以 CoMem_AXPY 为例走通编译、运行与多规模实验。核心结论：仓库无统一构建，Makefile 仅四种风格——单行式为主，另有带 -g -G 与 -arch=sm_30 的调试式、DynParallel 的变量式、依赖 Common 的 CUDA Samples 多架构模板。关键概念：host 与 device 分层；nvcc 把 .c 按 C、.cu 按 C++ 编成单一可执行文件，混编需 extern "C" 对齐符号；-arch 决定产物可运行的 GPU 架构（sm_30 已不可编译）；-G 关闭 GPU 优化，不能用于性能结论；-rdc=true 是动态并行前提；编译无需 GPU，运行需要。test.sh 即各基准的实验设计：多规模扫描加 nvprof 采集（如 branch_efficiency；新环境可用 nsys/ncu 替代）；程序 time 为 10 次平均墙钟，含拷贝与主机开销，大于纯 kernel 时间。
