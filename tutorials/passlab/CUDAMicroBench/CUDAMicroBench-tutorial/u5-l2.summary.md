本讲以 ReadOnlyMem_1D_Texture 讲解一维纹理内存：独立于全局内存、按空间局部性缓存的只读数据通路。四个最小模块：texture<float,1> 纹理引用声明（元素类型不支持 double）；cudaBindTexture 绑定／cudaUnbindTexture 解绑的生命周期（绑定只登记地址、不搬数据，kernel 内 tex1Dfetch 按元素下标读取）；三个 kernel（warmingup／纹理版／全局版）构成同程序同配置的单变量对照，唯一变量是 x 的读取通路（纹理版签名无 x 参数）；顺序访问下纹理不占优的归档数据解读。核心结论：顺序合并访问的 AXPY 上，两台机器五个规模纹理版均比全局版慢 1%～4%，规模越大差距越小，「只读放纹理更快」是依赖访问模式与架构的条件命题。判定快慢须看 nvprof 的 kernel 时间行（本基准 kernel 仅占 wall time 约 2%），并以 warmingup 比值为噪声标尺。纹理真正主场是 2D 邻域与随机 gather；现代替代为 __ldg()，旧式纹理引用 API 已弃用、推荐纹理对象。
