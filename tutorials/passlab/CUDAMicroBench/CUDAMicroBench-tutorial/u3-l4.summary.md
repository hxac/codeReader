本讲以 TaskGraph 基准（单文件的共轭梯度求解器，来自 CUDA Samples）讲解 CUDA Graph，针对 launch-bound（提交受限）问题：任务多而碎时，CPU 逐个提交 kernel 的 API 开销成为瓶颈。核心是三步工作流：stream capture（捕获区间内操作只记录不执行，cuBLAS/cuSPARSE 库调用产生的 kernel 一并入图）→ instantiate 把图纸编译成可执行实例 cudaGraphExec_t → 循环内一次 cudaGraphLaunch 整图重放。CG 一次迭代约含 14 个主机 API 调用（SpMV、点积、SAXPY、memset/memcpy 及 r1_div_x、a_minus 两个单线程标量 kernel），graph 化后节省约 K(n−1) 次提交。最关键设计：pointer mode 设为 DEVICE，让随迭代变化的 α、β 标量留在 GPU 上由单线程 kernel 生产消费，图得以不加修改地自洽重放；分工为图管迭代体、主机管控制流，每次 launch 后须同步读回残差。结论：收益主要体现在 CPU 侧 API 时间而非端到端 wall time，kernel 越碎、迭代越多收益越大。
