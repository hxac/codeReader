本讲以 CoMem_AXPY 的 axpy_cuda 为样本，确立全项目通用的包装骨架：cudaMalloc 分配 → cudaMemcpy 主机到设备（H2D）→ kernel 计算 → cudaMemcpy 设备到主机（D2H）→ cudaFree。关键概念：host/device 两个内存世界、设备指针不可在主机解引用、cudaMemcpyKind 方向参数目的在前源在后且须与指针匹配、cudaMalloc 只分配不初始化、kernel 启动异步、默认流按提交顺序隐式排序保证正确性、cudaDeviceSynchronize 提供测量栅栏与错误可见性、启动期与执行期两类错误、cudaGetLastError 查询即清除错误状态。核心结论：原代码从不检查 API 返回值，分配失败或方向写反均为静默失败，须用 CUDA_CHECK 宏紧贴每步调用；微基准在计时循环内反复分配释放并在每个 kernel 后同步，故 main 测得的墙钟远大于纯 kernel 时间。
