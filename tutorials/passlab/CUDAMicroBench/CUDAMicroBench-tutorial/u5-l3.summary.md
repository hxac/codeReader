本讲以 ReadOnlyMem_2D_Texture（矩阵加法）为例讲两条只读数据通路。模块一：二维纹理生命周期——`texture<float,2>` 声明、`cudaCreateChannelDesc<float>()` 通道描述符、`cudaBindTexture2D` 按 width/height/pitch（字节行距）绑定普通显存、kernel 内 `tex2D(tex,x,y)` 取数、`cudaUnbindTexture` 解绑；绑定不搬数据。模块二：四个被测 kernel（`add`、`add_const`、`add_texture`、`add_texture_constant`）共享输入与二维 16×16 线程网格，逐级单变量叠加对照；纹理只加速读、写仍走全局内存。模块三：常量内存 `__constant__` + `cudaMemcpyToSymbol` 三段式，收益来自 warp 内同址广播，异址访问反而串行化；因 kernel 参数本就走常量通路，`add_const ≈ add`（偏差 ≤3%）。模块四：纹理缓存赌空间局部性、常量缓存赌同址广播；对完美合并的流式负载，纹理收益强依赖架构代际（Carina 上为噪声，Fornax 上快 2.4–4.3 倍）。方法论教训：源码的 pitch 与 `tex2D` 坐标顺序疑似转置错误，被「方阵 + 全 1 数据」双重掩盖，校验 PASS 不等于实现正确；两份归档非同一版二进制，须先核对 nvprof Calls 列再跨机器对比；host 不计时，一切数据来自 profiler，且 memcpy 占 96% GPU 时间。
