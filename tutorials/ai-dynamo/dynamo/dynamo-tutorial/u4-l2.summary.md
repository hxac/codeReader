本讲剖析 Rust 侧 `lib/llm/src/http/` 的 OpenAI 兼容 HTTP 层。核心结论：HttpService 由一个 axum Router 加共享 State 组成——系统路由不做 inflight 记账（draining 期 `/live`、`/metrics` 仍 200），推理路由叠 `track_inflight_inference` 与端点开关检查，生命周期是 ServiceStage 三态机（Ready→Draining→Stopping）配优雅关停超时。关键澄清：`InflightPermit` 是记账器而非限流器，只统计响应体未完成的请求，真正准入在路由器与引擎侧。三类协议端点（OpenAI/Anthropic/Generate）共享一套 State，差异在 handler 内部，Generate 按能力而非模型名取引擎。流式增量由 `DeltaGenerator` 拼装，chat 与 completions 共享 `DeltaGeneratorState`，usage 对后端总量取 max；非流式强制带 usage。`/v1/responses/input_tokens` 用 len/3 本地估算、不做就绪门、绝不触达后端；embeddings 内部线格式为 base64(LE f32)，解码统一在 `preprocessor.rs` 的 `decode_base64_to_floats`；后端错误凭 `ErrorType` 分类（InvalidArgument→400、过载可配、未知消毒 500），类型信息经 jail 旁路全程存活，字符串前缀恢复分支已删除。
