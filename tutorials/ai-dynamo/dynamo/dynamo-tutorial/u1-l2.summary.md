本讲以无需 GPU 的 sample 假后端跑通 Dynamo 最小可运行组合：frontend 进程对外暴露 OpenAI 兼容 HTTP API（/v1/chat/completions、/v1/models），配上一个 worker 进程，用 curl 即可拿到流式响应，安装可选容器或 PyPI。引入的关键术语：聚合模式（agg.sh，单 worker 兼做 prefill 与 decode）与分离模式（disagg.sh，prefill/decode 两类 worker，以合成的 disaggregated_params 交接）、TTFT、服务发现后端 kubernetes/etcd/file/mem。核心结论：本地开发不需要 etcd/NATS，frontend 与 worker 双方同传 --discovery-backend file 即可零依赖；file 模式即“写文件注册 + TTL 10 秒与 keep-alive 模拟租约 + inotify 监听目录”，worker 死亡后注册至多 10 秒消失。sample 后端启动链 run(SampleLLMEngine)→from_args→Worker.run 是各 Python 后端共用范式，token 按 (i+1)%32000 轮转、内容无语义，TTFT 下界由 --delay 决定；且每条请求生成全新块哈希，相同前缀不会带来 KV 命中加速，模型名宜用真实 HF 名以便加载分词器。
