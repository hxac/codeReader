本讲为 KV 感知路由单元收官，讲清 Dynamo 如何把「为请求选一个 worker」开放为插件。核心是 filter–score–pick 三段式：WorkerFilter 做硬性资格过滤，WorkerScorer 产出有限、越低越好、可相加的成本，WorkerPicker 从候选表挑一行；候选行序未指定，三段须无副作用且不阻塞。策略要读 CACHE/LOAD 等信号必须先在 required_worker_inputs 声明（声明式输入），未声明则宿主不物化；自定义策略拿到的是原始重合度，而非内置打分用的有效重合度。WorkerSelectionPolicyRegistry 走 provider→factory→policy 三级生命周期：provider 启动时解析并校验 YAML 参数，factory 每个分区调用一次，policy 状态分区私有；type/实例名/角色三层命名对应配置，default 为保留名永远回落内置选点器，未知类型、重复注册或非法参数一律启动失败。WorkerCatalog 管理 worker 注册目录与 endpoint 防御性回查；SelectionServiceBuilder 以 registry 为必需参数构造选点服务，ext-proc 与 Python 前端复用同一注册表。策略经编译期链接进入镜像：空默认 catalog 是依赖别名插槽，custom-policy feature 下随 import 填充注册表；WorkerSelectionPolicy 实现 WorkerSelector，可与内置选点器互换同一插槽。
