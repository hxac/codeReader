本讲是仓库「地图课」：Dynamo 物理上分三层——Rust 核心（lib/ 的 Cargo workspace，35 个成员 crate，按运行时基座、LLM 引擎、路由、KVBM、mocker/sidecar、绑定工具六组记忆）、Python 扩展（components/src/dynamo/，打成 ai-dynamo wheel）与 K8s 部署（deploy/ 的 Operator、Helm、inference-gateway），跨层改动属非平凡变更。核心结论：PyO3 扩展 crate dynamo-py3 用空 [workspace] 节把自己排除出顶层 workspace、由 maturin 单独构建出 `_core` 扩展；仓库实际产出两个 wheel——ai-dynamo-runtime（含 .so 与 dynamo.runtime/llm 包装层）被 ai-dynamo（frontend、各引擎后端、planner）依赖，版本四处对齐；引擎依赖按 extra（vllm/sglang/trtllm/mocker）拆分且互斥，这是不同后端需不同容器镜像的根因。关键概念：Cargo workspace、crate、PyO3、cdylib、maturin、wheel/extra、Operator/CRD、Helm chart；Python 侧 import 到的 DistributedRuntime 等类实为 PyO3 暴露的 Rust 结构体。外围目录 examples/ 重学习、recipes/ 重生产、tests/ 与 benchmarks/ 同名但职责不同。
