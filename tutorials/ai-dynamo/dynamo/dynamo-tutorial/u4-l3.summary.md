本讲讲请求进引擎前的最后整形与块哈希数学。OpenAIPreprocessor 按「MiniJinja 模板渲染 → 分词 → 多模态媒体收集 → 装配 PreprocessedRequest」工作，分词分三分支（直取 token、nvext 预分词、本地分词），并兼任 token 预算门卫（InvalidArgument/400）。图片抓取受三道 SSRF 防线：黑名单快查、DNS 逐 IP 复查、连接期 BlocklistResolver 与重定向逐跳复检；Rust 与 Python 两侧策略逐条对齐，DYN_MM_ALLOW_INTERNAL 是唯一内网逃生门。LocalModel/ModelDeploymentCard 供给分词器、模板与 kv_cache_block_size（默认 16，须与引擎 page 一致）。token 块化给出 BlockHash、链式 SequenceHash（种子 1337）与 PositionalLineageHash 三种身份，核心推论「相同前缀 ⇒ 相同前缀块哈希」是 u6 KV 感知路由与 u9 KVBM 的数学地基。salt_hash 由 lora 与 salt 派生作缓存隔离键；多模态身份折叠进块内帧编码，不破坏图片前的文本前缀复用，build_mm_exact_routing_info 在此收口整条流水线。
