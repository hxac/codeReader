本讲为 u5 收官，讲 frontend 如何用后端原生 Python 前后处理替换全 Rust 管线。`--dyn-chat-processor` 三档：默认 dynamo 走 Rust 的 OpenAIPreprocessor；vllm/sglang 档经 `chat_engine_factory` 回调（Rust watcher 发现支持 chat 的模型时惰性触发）改用 Python，路由、HTTP、指标仍留在 Rust。VllmProcessor 策略是借组件：复用 vLLM 的 InputProcessor/OutputProcessor 但从不构造引擎，支持 n>1；SglangProcessor 策略是自己写：同步整形加自实现批量刷新，支持进程池预处理、首 chunk 立即刷，但不支持 n>1。本讲引入术语：chat processor（frontend 进程内完成 OpenAI 请求到流式响应整段整形的组件）与带外注解（`_dynamo_annotated` 信封中的 event/comment，携带 llm_metrics，HTTP 层剥离、不进客户端响应）。核心结论：两档产出的 dynamo_preproc 字典与输出信封结构必须一致，字段名是跨语言硬契约、多写被静默丢弃，因此两档可互换；context 必须透传，否则取消链断裂。承接 u5-l1 注入链与 u5-l2 请求整形，为 u6 路由（routing 字段）与 u8 worker 侧接入铺垫。
