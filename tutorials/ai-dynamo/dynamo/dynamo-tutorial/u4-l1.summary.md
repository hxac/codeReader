本讲是 lib/llm 引擎层首篇，立起「装配」骨架。核心结论：装配由两个正交决策构成——EngineConfig（引擎在远端还是本进程）与 RouterConfig（请求如何分发）；enforce_disagg 已废弃，拓扑由 worker 注册类型决定。EngineConfig 三变体：Dynamic（远端 worker，惰性装配）、InProcessText（引擎自分词，echo 用）、InProcessTokens（框架分词，mocker 用，带 is_prefill/is_decode）。装配路径：Python 侧以 EntrypointArgs(EngineType.Dynamic) 调 make_engine 过 PyO3 桥，经 LocalModelBuilder → LocalModel → select_engine 得到 EngineConfig；Dynamic 携带 chat_engine_factory 回调，落实「引擎逻辑留 Python、路由与发现归 Rust」，网络组件要等 watcher 发现 worker 后才生成（KV 模式建 KvRouter，Decode worker 建 PrefillRouter，最终组出 RoutingHost）。引擎另一端由 Input 枚举（Http/Grpc/Text/Stdin/Endpoint）决定输入源；EngineDispatcher 与 StreamingEngineAdapter 这对反向适配器让一个引擎同时服务 completions 与 chat 端点；有 factory 时 chat 管线走 build_preprocessed_pipeline，否则走全 Rust 的 build_pipeline。
