本讲是「KV 感知路由」单元的入口篇，区分 Dynamo 三种路由部署形态：frontend 内嵌 Rust 路由（无路由 RPC）、frontend 内 Python processor（路由仍在进程内）、独立路由进程 dynamo.router（多一跳 RPC，不提供 OpenAI 兼容 HTTP）。独立路由器由 StandaloneRouterHandler 暴露三个端点：generate 真转发、best_worker_id 纯查询不记账、get_overlap_scores 返回分层缓存重合度，请求与响应以固定字段名的 dict 信封跨界。关键结论：独立路由器不接收 --router-mode，固定走 KV 感知；该参数属 frontend 与 worker 广告（worker 卡片会整体覆盖 frontend 配置），七种模式经 ROUTER_MODE_MAP 映射为 Rust RouterMode 枚举，仅 KV 模式附带 KvRouterConfig。Python 的 KvRouter 是 PyO3 薄壳，inner 即 Arc<RoutingHost>；tracker 等元数据不会自动跨界，须显式注入 routing_data 才能存活。mocker 会发布真实 KV 事件，是路由实验的正确工具；这些为下一讲 Rust 路由核心（RoutingHost 打分与调度）铺垫。
