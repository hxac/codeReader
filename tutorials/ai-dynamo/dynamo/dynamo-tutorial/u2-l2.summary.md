本讲拆解 Dynamo 的 Python↔Rust 边界，分四个最小模块：一是注册入口——绑定 crate dynamo-py3 编译出 dynamo._core 扩展模块，`#[pymodule]` 初始化函数在 import 时经 register_core 集中注册全部类与函数；二是「wrapper + inner」模式——DistributedRuntime、Endpoint、Client、Context 等 pyclass 皆为薄壳，inner 持有 Rust 原生结构体或 trait 对象，需回调 Python 的类另存 event_loop；三是异步桥——PythonAsyncEngine 把 Python 异步生成器实现为 Rust AsyncEngine trait，经 spawn_blocking 与 with_gil 保证 GIL 安全，`__anext__` 按需拉取转成 Rust Stream，Context 依签名探测注入；四是 dynamo.runtime 与 dynamo.llm 纯 Python 再导出层，make_engine 定义于 rust/llm/entrypoint.rs。核心结论：三步法（包装层 import 行、lib.rs 注册行、Rust 定义文件）可定位任何 _core 符号；Rust 错误统一经 to_pyerr 转为 Python 异常。
