# 用 fir1 设计定点滤波器系数

## 1. 本讲目标

上一讲 **u2-l1** 我们已经知道：锐化核 \(h=\frac{1}{32}[1,\ 0,\ -9,\ 48,\ -9,\ 0,\ 1]\) 是一组「和为 1、直流增益为 1、只增强高频」的好系数。但那组系数是**从哪儿来的**？本讲就回答这个问题。

我们把上一讲「直接给出的结论」，还原成「可以亲手设计出来的过程」。具体回答三个问题：

1. 怎么用 Octave 的 `fir1` 函数自动设计出一个高通滤波器？它的参数 `8`、`0.5`、`"high"` 各代表什么？
2. `fir1` 给出的是一串**小数（浮点）系数**，而 FPGA 硬件只能高效处理**整数（定点）运算**——这中间怎么转换？为什么要「乘 32 再取整」？
3. 设计出来的系数，如何与硬件 `sharp_arith.vhd` 里的乘加表达式**一一对应**？为什么有 7 个抽头，硬件却只对 5 个抽头做乘法？

学完本讲，你应该能自己用 `fir1` 复现这组系数，并解释软件设计的浮点系数如何「翻译」成硬件里的定点整数运算。本讲是连接 **算法（Octave）** 与 **实现（VHDL）** 的关键一环。

## 2. 前置知识

本讲建立在 **u2-l1** 已建立的认知上（卷积、FIR、抽头、系数、锐化、直流增益、频率响应），不再重复。这里只补充三个本讲要用的新概念。

### 2.1 浮点（小数）与定点（整数）：硬件为何偏爱整数

在 Octave / MATLAB 里，一个数可以是任意小数，例如 `0.2754` 或 `-0.0228`，精度很高，这叫**浮点（floating-point）**。

但 FPGA 硬件做小数乘法很「贵」：需要专门的定点格式、对齐小数位、处理符号。相比之下，**整数乘法和加法**可以用逻辑门（LUT）非常高效地实现。所以一个常见的工程套路是：

> **设计阶段用浮点追求精度，实现阶段把系数量化为定点整数，最后用一个「除以 2 的幂」来还原小数。**

「除以 2 的幂」在硬件里几乎是免费的——它就是一次**右移**（right shift），不需要真的做除法。本项目的「除以 32」就是这个套路（\(32 = 2^5\)，右移 5 位）。

### 2.2 归一化频率与奈奎斯特

`fir1` 的第二个参数 `0.5` 是一个**归一化频率**，它不带 Hz 单位，而是一个 0 到 1 之间的比例：

- `1` 代表**奈奎斯特频率（Nyquist frequency）**，也就是采样频率的一半（\(F_s/2\)）。这是数字信号里能表示的最高频率。
- `0.5` 就代表 \(0.5 \times F_s/2 = F_s/4\)，即采样频率的四分之一。

把频率写成 0 到 1 的比例，好处是「与具体采样率无关」——无论视频是 720p/74.25 MHz 还是别的，`0.5` 永远指「奈奎斯特的一半」。

### 2.3 「高通」与「锐化」不是一回事（本讲的题眼）

这个区别是本讲最重要的直觉，请记住：

- **高通滤波器（high-pass）**：彻底**滤掉**低频（平均亮度），只保留高频（边缘）。它的**直流增益为 0**——对一张全灰的图，高通输出是全黑（把平均亮度删干净了）。
- **锐化滤波器（sharpening）**：**保留**原图（平均亮度不变），再**叠加**一份高频。它的**直流增益为 1**——对全灰的图，输出还是同样的灰（亮度不变），只在边缘处加强。

二者的关系是：

\[
\text{锐化} = \text{原图} + \text{（放大的）高频} = \text{恒等} + k\cdot\text{高通}
\]

用系数语言说：**锐化核 = 高通核 + 一个只在中心为 1 的「恒等核」**。本讲我们会看到，`fir1(..., "high")` 先给出一个直流增益为 0 的高通核，然后设计者把它的中心系数「抬高」一截，让它变成直流增益为 1 的锐化核。这一抬，正是 48 与 16 的差别（后面会算）。

## 4. 核心概念与源码讲解

### 4.1 用 fir1 设计高通 FIR 核

#### 4.1.1 概念说明

手工凑一组锐化系数（比如「中间大、两边负」）是可以的，但要精确控制截止频率、过渡带、纹波，靠手凑不靠谱。信号处理里有一套成熟的**自动设计方法**：给定阶数和截止频率，用「加窗 sinc 法（windowed-sinc）」算出最优系数。Octave 的 `fir1` 函数就是干这个的。

`fir1` 的调用形式是 `fir1(阶数, 归一化截止频率, 类型)`：

- **阶数 = 8**：滤波器的**阶（order）**。阶数 \(N\) 决定抽头数为 \(N+1\)，所以 `fir1(8, ...)` 产生 **9 个系数**（注意不是 7 个）。
- **截止频率 = 0.5**：归一化到奈奎斯特，即 \(F_s/4\)（见 2.2）。对高通滤波器，高于这个频率的成分被保留。
- **类型 = "high"**：高通（high-pass）。若省略则默认是低通。

`fir1` 默认用**汉明窗（Hamming window）**，能在阻带（被滤掉的频段）提供约 53 dB 的衰减，是兼顾过渡带宽度与纹波的常用选择。

#### 4.1.2 核心流程

用 `fir1` 设计一个高通核的步骤：

1. 设定阶数 8、归一化截止频率 0.5、类型 `"high"`。
2. `fir1` 内部先算「理想高通」的冲激响应（一串 sinc 值），再乘上汉明窗压低旁瓣。
3. 得到一串浮点系数 \(h_{\text{hp}}[k]\)，长度为 9，**关于中心对称**（线性相位 FIR 的特征）。
4. 关键性质：因为是高通，这 9 个系数的**和约为 0**（直流增益为 0）。

数学上，理想高通冲激响应（截止 \(\omega_c = 0.5\pi\)）为：

\[
h_{\text{hp}}[n] = \delta[n] - \frac{\sin(\omega_c n)}{\pi n}
\]

注意 \(\sin(0.5\pi n)\) 在 \(n=\pm2,\pm4,\ldots\) 处为 0——这意味着**第 ±2 个抽头天然就是 0**。这个「天然的零」会一路保留到最终的硬件里，是后面「m2/p2 被省略」的根本原因。

第 11 行打印出的，是一串绝对值小于 1 的小数，关于中心对称，且总和约为 0。这正是「纯高通」的长相。

#### 4.1.5 小练习与答案

**练习 1**：把 `fir1` 的第一个参数从 `8` 改成 `6`，抽头数会变成多少？为什么？

**答案**：抽头数 = 阶数 + 1 = 7。阶数 6 → 7 个抽头。注意：本项目最终硬件用 7 个抽头，但设计脚本用的是阶数 8（9 个抽头），其中最外两个抽头量化后为 0，等效成 7 个有效抽头（见 4.2）。

**练习 2**：如果忘了写 `"high"`，写成 `fir1(8, 0.5)`，得到的是高通还是低通？直流增益约为多少？

**答案**：默认是**低通**。低通保留直流，直流增益约为 1（`sum ≈ 1`）。这与锐化想要的「高频增强」相反，所以本项目必须指定 `"high"`。

### 4.2 定点量化：乘 32 取整

#### 4.2.1 概念说明

`fir1` 给出的是小数，硬件要整数。把小数系数「翻译」成整数系数的过程叫**定点化（fixed-point quantization）**。本项目用的办法极其简洁：

\[
h_{\text{q}} = \frac{1}{32}\,\texttt{round}\!\big(32 \cdot h_{\text{hp}}\big)
\]

也就是**先把每个系数乘 32，再四舍五入取整**。这样原本的 `0.5`、`-0.2754`、`0.0228` 等小数，就变成了 `16`、`-9`、`1` 这样的整数（运算时除以 32 还原）。

为什么选 32？三个理由：

1. **32 是 2 的幂**（\(2^5\)）。硬件里「除以 32」= 右移 5 位，几乎零成本。
2. **精度够用**：把系数放大 32 倍后取整，最大量化误差 \(< \frac{1}{2\times32} \approx 0.0156\)，对 8 位（0~255）像素足够。
3. **取整后出现干净的整数**：本项目的系数恰好量化成 `[1, 0, -9, 48, -9, 0, 1]` 这样的小整数，乘法器只需做「乘 9、乘 48」这种简单常数乘法。

> 取整用 `round`（四舍五入）而不是 `floor`（截断）：`round` 的最大误差是 0.5，`floor` 的最大误差接近 1，`round` 精度更高。例如 \(0.729 \to \texttt{round}=1\) 而 \(\texttt{floor}=0\)。

#### 4.2.2 核心流程

定点化的完整推理（这是本讲最值得想清楚的一段）：

1. **高通核量化**：对 `fir1(8,0.5,"high")` 的 9 个系数乘 32 取整，理论推算结果约为
   \[
   \texttt{round}(32\,h_{\text{hp}}) \approx [\,0,\ 1,\ 0,\ -9,\ 16,\ -9,\ 0,\ 1,\ 0\,]
   \]
   两端的 `0` 和第 ±2 位的 `0` 都来自 sinc 函数的天然过零点；中心和约为 0（仍是高通）。

2. **去掉零抽头**：两端各一个 0 抽头对滤波无贡献，删掉后得到 7 个抽头：
   \[
   [1,\ 0,\ -9,\ 16,\ -9,\ 0,\ 1]\ /\ 32
   \]
   注意它的**中心是 16，和为 0**——还是一个纯高通。

3. **加恒等变锐化**（题眼兑现）：按 2.3，锐化 = 恒等 + 高通。把「恒等核」（中心为 1、其余为 0，即中心加 \(\frac{32}{32}\)）叠加上去，**只抬中心系数**：
   \[
   16 + 32 = 48
   \]
   于是高通核 \([1,0,-9,16,-9,0,1]/32\) 变成锐化核：
   \[
   [1,\ 0,\ -9,\ \mathbf{48},\ -9,\ 0,\ 1]\ /\ 32
   \]
   此时系数和 \(=1+0-9+48-9+0+1 = 32\)，除以 32 = **直流增益 1**，与 u2-l1 的结论完全吻合。

4. **验证不失真**：最后用 `freqz` 画这组**定点系数**的频率响应，确认量化（和加恒等）没有破坏「直流 0 dB、高频提升」的形状。

> 48 与 16 的差恰好是 32，绝非巧合——它就是「为恢复直流增益而补上的恒等贡献」。这个推理同时由硬件系数（确定）和加窗 sinc 理论（中心 \(1-\omega_c/\pi = 0.5\)，乘 32 = 16）双向印证。

**步骤**：

1. 在 Octave 执行：
   ```octave
   pkg load signal
   h = fir1(8, 0.5, "high");
   q32 = round(32*h)      % 本项目用的放大倍数
   q16 = round(16*h)      % 更小的放大倍数
   q64 = round(64*h)      % 更大的放大倍数
   ```
2. 观察 `q32`、`q16`、`q64` 三个整数向量。

**需要观察的现象**：

- `q32` 应约为 `[0, 1, 0, -9, 16, -9, 0, 1, 0]`（待本地确认精确值）。
- `q16`：放大倍数小，更多的非零抽头会**坍缩成 0**（如 `1 → 0`），精度下降。
- `q64`：放大倍数大，系数变「大」（如 `16 → 32`），精度更高，但硬件乘法器要处理更大的数。

**预期结果**：放大倍数（2 的幂）是「精度」与「硬件代价」的折中。32 恰好让本项目得到一组**干净的小整数**（最大 48），是甜点选择。

#### 4.2.5 小练习与答案

**练习 1**：把高通量化结果 `[0,1,0,-9,16,-9,0,1,0]` 删掉两端各一个 0，得到 7 抽头 `[1,0,-9,16,-9,0,1]`。手动把它变成锐化核，应该得到什么？

**答案**：把中心 \(16\) 加 \(32\)（叠加上恒等核）→ \(48\)，得到 `[1,0,-9,48,-9,0,1]/32`。验证：和 \(=32\)，直流增益 \(=1\)。

**练习 2**：为什么用 `round` 而不是 `floor` 来取整？用 `floor` 会怎样？

**答案**：`round` 的量化误差 ≤ 0.5（在放大前的系数尺度上），`floor` 的误差接近 1，`round` 更准。若用 `floor`，正系数会偏小、负系数会偏大（更负），引入系统性偏差，频率响应会偏离设计。

### 4.3 系数软硬件对照：从 Octave 到 VHDL

#### 4.3.1 概念说明

设计出的系数 `[1,0,-9,48,-9,0,1]/32` 在三个地方出现，必须**完全一致**：

1. **Octave 软件滤波**（`sharp_image_filter.m` 的 `f_hor`）——软件参考结果。
2. **VHDL 硬件实现**（`sharp_arith.vhd` 的乘加表达式）——实际电路。
3. **仿真验证的期望图**（U5 单元）——逐像素比对的「标准答案」。

三者一致，才能保证「硬件算出来的 = 软件设计的」。本模块聚焦第 1、2 项的对照，并解释一个现象：**明明有 7 个抽头，硬件的乘加表达式里却只出现 5 个抽头**。

原因正是 4.1 提到的「天然零」：第 ±2 个抽头（硬件里叫 `tap_m2` / `tap_p2`）的系数是 0，**乘 0 等于 0**，所以硬件干脆不写它们——既省两次乘法，又省了对应的布线。这是「算法设计的选择」直接转化为「硬件的简化」的典型例子。

#### 4.3.2 核心流程

把锐化核 \([1,0,-9,48,-9,0,1]/32\) 翻译成硬件乘加，逐项展开：

| 抽头 | 系数 | 硬件表达式 | 说明 |
|------|------|-----------|------|
| `tap_m3` | \(+1\) | `tap_m3` | 乘 1，直接取值 |
| `tap_m2` | \(0\)  | （省略）   | **m2 为 0，不参与运算** |
| `tap_m1` | \(-9\) | `- (9*tap_m1)` | 乘 -9 |
| `tap_00` | \(+48\)| `+ (48*tap_00)` | 乘 48（中心像素，权重最大）|
| `tap_p1` | \(-9\) | `- (9*tap_p1)` | 乘 -9 |
| `tap_p2` | \(0\)  | （省略）   | **p2 为 0，不参与运算** |
| `tap_p3` | \(+1\) | `+ tap_p3` | 乘 1，直接取值 |

加上「舍入偏置 +16」后除以 32，就得到硬件里那一行 `sum` 表达式。命名上，`m` = minus（负方向/前几个抽头），`p` = plus（正方向/后几个抽头），`00` = 中心。

#### 4.3.3 源码精读

先看实体端口，确认 7 个抽头的命名与类型：

[sharp_arith.vhd:13-19](https://github.com/automatesolutions/FPGA_FIR-FILTER/blob/3f7aef90f4d34fa62f00ca72c260fc49c3c04a8c/FPGA-FIR-Filter-master/FPGA-Design/sharp_arith.vhd#L13-L19) — 7 个输入抽头 `tap_m3 … tap_p3`，每个都是 `integer range 0 to 255`（一个 8 位像素的值）。

接着是那条点睛的注释：

[sharp_arith.vhd:27](https://github.com/automatesolutions/FPGA_FIR-FILTER/blob/3f7aef90f4d34fa62f00ca72c260fc49c3c04a8c/FPGA-FIR-Filter-master/FPGA-Design/sharp_arith.vhd#L27) — `-- filter coefficients [1;0;-9;48;-9;0;1]/32`，硬件作者用注释把系数「钉」在代码旁，方便与 Octave 对照。它与 `sharp_image_filter.m` 第 13 行的 `f_hor`、`sharp_frequency_response.m` 第 11 行的 `filter` **逐字相同**。

然后是核心乘加表达式：

[sharp_arith.vhd:34](https://github.com/automatesolutions/FPGA_FIR-FILTER/blob/3f7aef90f4d34fa62f00ca72c260fc49c3c04a8c/FPGA-FIR-Filter-master/FPGA-Design/sharp_arith.vhd#L34) —
```vhdl
sum := (tap_m3 - (9*tap_m1) + (48*tap_00) - (9*tap_p1) + tap_p3 + 16) / 32;
```
对照上面的表格，这一行**恰好**是 7 个抽头按系数 \([1,0,-9,48,-9,0,1]\) 的加权求和：

- `tap_m3`（×1）、`tap_p3`（×1）直接出现；
- `- (9*tap_m1)`、`- (9*tap_p1)` 是两个 -9 抽头；
- `+ (48*tap_00)` 是中心 48 抽头；
- **`tap_m2`、`tap_p2` 完全没有出现**——因为系数为 0；
- `+ 16` 是舍入偏置（见下），`/ 32` 是定点还原。

关于 `+ 16`：整数除法 `/ 32` 默认是**截断（向零取整）**。为了让它等价于「四舍五入」，先加 \(16 = 32/2\) 再除。这与 4.2 里 Octave 用 `round` 的意图一致，只是硬件用「加半再截断」来实现 round。（`+16` 的舍入与饱和截断的完整讨论见 **u4-l2**。）

#### 4.3.4 代码实践

**目标**：在源码层面把「软件系数」与「硬件表达式」逐项对上，并定位被省略的两个抽头。

**步骤**：

1. 打开 `Octave/sharp_image_filter.m` 第 13 行，记下 `f_hor` 的 7 个系数。
2. 打开 `FPGA-Design/sharp_arith.vhd` 第 34 行的 `sum := (...)`。
3. 列一张映射表：`f_hor` 的第 1~7 个系数，分别对应 `sum` 表达式里的哪一项。
4. 找出 `sum` 表达式里**没有**出现的两个抽头名。

**需要观察的现象**：

- 7 个系数里，有 5 个能在 `sum` 里找到对应项（×1 的两项被写成直接相加）。
- `tap_m2` 和 `tap_p2` 在 `sum` 里**找不到**。

**预期结果**：缺失的两个抽头正是系数为 0 的位置。这验证了「7 抽头系数 → 5 次乘法」的简化是合理的，也印证了 4.1 中「sinc 天然过零」的设计源头。

#### 4.3.5 小练习与答案

**练习 1**：`sum` 表达式里为什么 `tap_m3` 和 `tap_p3` 前面没有写 `1*`？

**答案**：因为它们的系数是 \(+1\)，乘 1 等于原值，省略 `1*` 既清晰又省一次乘法。硬件综合工具通常也会优化掉 ×1，但写出来更易读。

**练习 2**：如果某天我们把锐化核换成了一组「7 个系数全不为 0」的核（比如平滑核），`sharp_arith.vhd` 第 34 行需要怎么改？

**答案**：需要补上 `tap_m2` 和 `tap_p2` 两项（乘以它们各自的新系数），并相应调整其余系数。也就是说，**「省略两个抽头」是当前这组系数特有的红利**，换核后这个红利就没了——抽头数的取舍是二次开发时要权衡的点（详见 u6-l3）。

把本讲三个模块串起来，完成一次「从设计到对照」的完整闭环。

## 6. 本讲小结

- `fir1(8, 0.5, "high")` 用加窗 sinc 法设计出 **9 抽头高通核**：阶数 8 → 9 个系数，截止频率 0.5（奈奎斯特的一半），类型 `"high"` 使其**直流增益为 0**。
- **定点化**用 `round(32*...)`：乘 32（\(2^5\)，硬件里除以 32 = 右移 5 位）再四舍五入，把小数系数变成干净的小整数 `[0,1,0,-9,16,-9,0,1,0]`。
- **高通 ≠ 锐化**：高通直流增益 0（删亮度），锐化直流增益 1（保亮度）。把高通核中心 \(16\) 加 \(32\)（叠加恒等核）得到锐化核 `[1,0,-9,48,-9,0,1]/32`，和为 32、直流增益 1。
- sinc 在 ±2 处天然为 0，使 `tap_m2`/`tap_p2` 系数为 0，**硬件因此省掉两次乘法**（7 抽头只做 5 次乘法）。
- 同一组系数在三处出现且完全一致：`sharp_image_filter.m`（用）、`sharp_arith.vhd`（实现）、`sharp_frequency_response.m`（验），构成「算系数→实现→验证」的闭环。
- 硬件 `sum` 表达式里的 `+16` 是「加半截断」式四舍五入，与 Octave 的 `round` 意图一致（舍入与饱和的细节留待 u4-l2）。

## 7. 下一步学习建议

本讲搞定了「系数从哪来、怎么定点化、怎么对应到硬件」。接下来有两个方向：

- **横向（算法验证）**：运行 `sharp_frequency_response.m`，用 `freqz` 亲眼确认这组定点系数的频率响应确实是「直流 0 dB、高频提升」，把「时域系数」与「频域形状」对应起来（u2-l1 已铺垫 freqz，可对照复习）。
- **纵向（进入硬件）**：进入 **U3 单元**，从顶层 `sharp.vhd`（u3-l1）开始，看这 7 个抽头是如何由 `sharp_slice` 用行存储（`sharp_linemem`）和移位寄存器「攒」出来的，以及 `sharp_arith` 在整条数据通路里被调用了几次（提示：垂直、水平各一次）。`sharp_arith` 的舍入 `+16` 与饱和截断到 0~255 的完整逻辑，则在 **u4-l2** 精读。

建议阅读顺序：u3-l1（顶层）→ u3-l3（sharp_slice 数据流）→ u4-l2（sharp_arith 精读）。
