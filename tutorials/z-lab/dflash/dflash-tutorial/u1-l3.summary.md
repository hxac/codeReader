本讲聚焦 dflash 包的骨架与模块导出机制。包内仅四个源码文件、无更深的子包：`__init__.py` 充当门面；`model.py` 是复用 Qwen3 组件的 PyTorch / Transformers 参考实现；`model_mlx.py` 是面向 Apple 芯片的 MLX 实现；`benchmark.py` 提供数据集与评测 CLI。两种实现依赖互不兼容，须用独立虚拟环境隔离安装。

包入口用 `__all__` 声明四个顶层公开 API：`DFlashDraftModel`、`extract_context_feature`、`sample` 来自 `dflash.model`，`load_and_process_dataset` 来自 `dflash.benchmark`；MLX 的符号均不在其列，须显式导入子模块才能获取。

核心机制是模块级 `__getattr__`（PEP 562）实现的懒加载：`__init__.py` 没有任何顶层 import，故 `import dflash` 极轻、不加载任何深度学习框架；仅当首次访问某个 API 时，`__getattr__` 才作为一张分发表按名从对应子模块按需导入，白名单之外的名字一律抛 `AttributeError`。此设计与 `pyproject.toml` 互为前提——核心依赖故意不含 torch/mlx，重依赖置于四个可选分组，`packages.find` 限定包发现范围。本讲只解释「包怎么导出」，API 内部如何加速生成留待后续讲义。
