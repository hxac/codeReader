本讲是入门单元的收尾，目标是用最小代码跑通 DFlash 第一次生成。覆盖四个最小模块：Transformers 后端 Quick Start 逐行解读、草稿模型主入口 `spec_generate` 的方法签名、target 与 draft 在代码层面的协作、MLX 后端的流式生成示例。

核心结论：库型后端有两条等价路径——Transformers 需 GPU，用面向对象的 `draft.spec_generate(...)` 一次性返回完整序列；MLX 需 Apple 芯片，用自由函数 `stream_generate(...)` 逐块流式产出。`spec_generate` 只暴露五个参数（target、input_ids、max_new_tokens、stop_token_ids、temperature），是内核函数 `dflash_generate` 的薄封装；`block_size`、`mask_token_id`、`return_stats` 被刻意隐藏，前两者来自草稿模型的 config（`b16` 即 block_size=16）。

最关键的设计概念：草稿模型是「残缺」的——没有自己的 `embed_tokens` 和 `lm_head`，而是在块起草阶段借用 target 的这两层（两个「借」），因此草稿用 `AutoModel` 加载、target 用 `AutoModelForCausalLM` 加载且必须同卡。`temperature=0.0` 走贪心 argmax，升温会降低草稿与 target 的吻合度、拉低平均接受长度从而削弱加速——这是 target/draft 协作中验证门槛的体现。本讲把 `dflash_generate` 当黑盒使用，其三阶段内部算法留给第二单元。
