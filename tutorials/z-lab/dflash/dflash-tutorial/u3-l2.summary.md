本讲讲解 MLX 后端投机解码的推理驱动层，覆盖三个最小模块。第一是钩子捕获：`_patch_model` 用 `_LayerHook` 包裹 target 指定层，target 每次前向都把多层隐藏状态抄进 `model._hidden_states`，再 `concat(axis=-1)` 拼成草稿的 context 输入；`_get_layers` 适配三种 target 封装，patch 幂等。第二是流式生成主循环 `stream_generate`：prefill（预填充 prompt 缓存与隐藏状态、采首 token）→ decode 循环（草稿以「锚点+mask」起草 `bs-1` 个候选，target 一次前向验证整块，取最长公共前缀 `accepted`，每轮产出 `accepted+1` 个 token，含一个 target 兜底 token）→ 收尾；全程靠 `mx.async_eval` 重叠草稿与验证。第三是缓存回滚：被拒候选的脏 K/V 必须裁掉，核心公式 `trim = bs - accepted - 1` 等于被拒数，由 `_trim_recent_cache` 对逐层缓存尾部裁剪（`RotatingKVCache` 需先 `_temporal_order` 还原时间序，普通 `KVCache` 直接 `trim`）；`hidden` 同步切片到 `accepted+1`，与缓存回滚共享「停在锚点之前」的不变量。`GenerationResponse` 打包每轮文本、token、产出数、吞吐与显存。关键分流 `can_trim_prompt_cache` 决定走本讲的普通裁剪路径还是 u3-l3 的 GDN 状态回滚路径；草稿缓存因只有 context、无 proposal 而几乎免回滚。
