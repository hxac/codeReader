DFlash 不自带推理引擎，而是把「草稿起草 + 目标验证」的加速能力集成进四种后端：vLLM 与 SGLang 是服务型（起 HTTP 服务、OpenAI 兼容接口），Transformers 与 MLX 是库型（Python 直接 import 调用）；选择取决于硬件与用途——生产部署用 vLLM/SGLang，读源码用 Transformers，Apple 芯片本地用 MLX。由于四种后端依赖互相冲突，必须用 `pyproject.toml` 的 `optional-dependencies` 分组配合独立虚拟环境隔离安装（如 `.[vllm]`），其中 vLLM 分组未锁版本但需 v0.20.1+，SGLang 需从 git PR 拉取，MLX 精确锁版本。配置 DFlash 的三要素是目标模型、草稿模型（带 `-DFlash` 后缀）与草稿规模（`num_speculative_tokens` / block_size）：vLLM 通过 `--speculative-config` 一段 JSON 传入，SGLang 用一组独立 CLI flag 描述，两者是同一信息的两种写法。加速关键在于让每步平均接受 token 数 E[a] 尽量大，单步产出为 E[a]+1；起草规模并非越大越好，需权衡接受率。库型后端的草稿规模分别写在 Transformers 的模型 config 与 MLX 的 `stream_generate` 参数中。DFlash 加速在服务端透明完成，不改变客户端调用方式。
