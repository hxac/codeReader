本讲承接 u2-l1 的全局控制流，彻底打开 decode 循环里的两个黑盒：`sample` 函数与「验证+接受+裁剪」。三个最小模块：**sample 采样**、**target 验证与接受长度**、**接受后双 KV cache 裁剪**。`sample` 用 `temperature < 1e-5` 分流贪心（`argmax`）与温度采样（`logits/T → softmax → multinomial`）；它在 `dflash_generate` 中被调三次，其中草稿候选永远贪心（不传温度），prefill 首 token 与 target 验证用用户温度——这一不对称是本讲关键。验证时 target 对整块一次前向，`block_output_ids[:, 1:]` 与 `posterior[:, :-1]` 天然对齐，`cumprod` 求最长公共前缀得接受长度 a∈[0, B-1]，兜底 token 永远来自 target、必被采纳，故每轮产出 a+1 个。核心洞察：因草稿贪心，「被接受即等于 target 采样」，被拒处写回的也是 target 采样，故 **DFlash 输出与单独用 target 采样完全等价，是纯加速手段、不损失质量**。接受后须裁剪两套 cache：target 缓存用新 `start` 裁以回滚被否决候选的脏 K/V，draft 缓存用旧 `start` 裁以丢弃投机尾巴；不裁会静默出错或崩溃。调高温度会让 target 偏离自身 argmax，降低草稿命中率与平均接受长度、削弱加速，但输出分布不变，是速度与多样性的权衡。
