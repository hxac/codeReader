本讲是 DFlash 评测模块的实现篇，聚焦 `benchmark.py` 的三条后端运行器与指标计算。三条运行器定位不同：**Transformers 后端**(`_run_transformers`)用 `torchrun`+NCCL 起多卡分布式，`_dist_*` 读 `RANK`/`WORLD_SIZE`/`LOCAL_RANK`，数据采用**跨步分片** `range(rank,len,size)` 均衡负载，`_dist_gather` 汇总到 rank 0，每个样本同跑 `bs=1` baseline 与 DFlash 做对照；**Server 后端**(`_run_server`)对 vLLM/SGLang 用 `ThreadPoolExecutor` 并发压测，先 warmup 再计时，vLLM 走 `/v1/chat/completions`(服务端套模板)、SGLang 走 `/generate`(客户端套模板)；**MLX 后端**(`_run_mlx`)单进程本地，baseline 用 `mlx_lm` 原生流式。核心结论：**库型后端**(Transformers/MLX)在单次运行内同跑 baseline 与 DFlash，经 `_make_decode_metrics` 归一化后用 `_print_decode_summary` 报**加速比**(= baseline TPOT / DFlash TPOT)与**接受长度直方图**；**服务型后端**只压测当前配置，报**吞吐**(tok/s)与平均接受长度，不报同次加速比。关键术语：TPOT=1/tps、接受长度(含兜底 token，取值 [1,B])两条库型后端口径一致。
