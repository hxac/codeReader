# 项目定位与仓库总览

## 1. 本讲目标

学完本讲后，你应该能够：

- 准确说出本仓库**是什么**：它不是一套可运行的软件代码库，而是一份用 Vivado 生成的「后实现（post-implementation）」评估报告数据集。
- 说出本仓库配套论文的**主题与评估对象**。
- 识别仓库**根目录下的全部条目**，并能用一句话说明每个条目的用途。
- 建立正确的学习预期：本仓库里没有需要「编译/运行」的源代码，你的主要学习对象是**报告文件**以及它们背后的 FPGA 评估方法。

> 这是整个学习手册的第一篇，目的是帮你「先看清地图，再上路」。如果你带着「我要把项目跑起来」的预期打开本仓库，本讲会帮你把预期调整到正确位置。

## 2. 前置知识

本讲是入门第一篇，对前置知识要求很低。下面几个概念了解一下即可，不懂也不影响阅读。

- **仓库（repository）**：用 Git 管理的一个项目目录，里面存着项目的所有文件和历史版本。
- **FPGA（现场可编程门阵列）**：一种可以通过编程改变内部电路的芯片。本实验评估的 CIC 滤波器最终就是要在 FPGA 上「跑」的。
- **Vivado**：AMD/Xilinx 公司的 FPGA 开发工具。本仓库里的报告文件都是 Vivado 在综合（synthesis）和实现（implementation）阶段自动生成的。
- **CIC 滤波器**：一种常用于数字信号抽取/插值的滤波器结构，全称会在 [4.2](#42-配套论文背景待确认) 和后续讲义里展开。本讲你只需要知道「它是这篇论文的主角」。

> 对 FPGA、Vivado、CIC 完全陌生的读者：不用担心，本讲只讲「仓库长什么样」，不要求你懂技术细节。涉及原理的内容（CIC 是什么、报告怎么读）会在后续讲义逐篇展开。

## 3. 本讲源码地图

## 4. 核心概念与源码讲解

本讲按三个最小模块展开：先读 `README.md` 这份「自我介绍」，再讲它配套的论文背景，最后梳理仓库顶层目录结构。

### 4.1 README.md：仓库的「自我介绍」

#### 4.1.1 概念说明

每个 Git 仓库根目录下通常都有一个 `README.md` 文件，它是仓库的「名片」：用最短的文字告诉访客「这个仓库是干什么的、该怎么用」。

本仓库的 `README.md` 非常简短——**只有一句话**。但这句话信息量很大，它同时交代了三件事：

1. 仓库里**装的是什么**：Vivado 生成的 utilization（利用率）和 timing（时序）报告文件。
2. 报告的**用途/出处**：是为某一篇论文准备的。
3. 论文的**标题**。

因此，读懂这一句话，就等于读懂了整个仓库的定位。

#### 4.1.2 核心流程

理解 `README.md` 的阅读流程：

1. 打开仓库 → 找到根目录的 `README.md`。
2. 阅读正文 → 提取出「**数据类型**」「**来源工具**」「**关联论文**」三个要素。
3. 用这三个要素给仓库下「定位结论」：这是一个**报告数据集仓库**，而非可运行的软件。

#### 4.1.3 源码精读

`README.md` 全文只有一行（共 1 行）：

```text
This project contains the utilization and timing report files generated by Vivado for the "Post-Implementation Evaluation of CIC Filters for Digital Audio Applications on FPGA" paper.
```

永久链接：[README.md:1](https://github.com/gitlab.upt.ro/elisei.ilies/CIC-filters.git/blob/e49b263d702c6fb0d4ea1d5b8390d307e6ba43d1/README.md#L1)

逐段拆解这一句英文：

| 英文片段 | 中文含义 | 对我们的意义 |
| --- | --- | --- |
| `This project contains ...` | 本项目包含…… | 说明仓库的核心内容是「文件」，而非代码 |
| `the utilization and timing report files` | 利用率与时序报告文件 | 这就是我们要学习的数据对象（两类报告） |
| `generated by Vivado` | 由 Vivado 生成 | 报告来自 AMD/Xilinx Vivado 工具 |
| `for the "..." paper` | 为「……」论文而准备 | 这些报告服务于一篇学术论文 |

由此可得到本仓库的**定位结论**：

> 本仓库是一个**数据/报告仓库**（data/report repository），它把一篇 FPGA 论文所需的全部 Vivado 评估报告集中存放，供读者查阅、比对和复现实验。

### 4.2 配套论文背景（待确认）

#### 4.2.1 概念说明

很多学术数据仓库都围绕一篇论文建立。本仓库配套的论文标题在 `README.md` 里已经写明：

> **Post-Implementation Evaluation of CIC Filters for Digital Audio Applications on FPGA**
> （中文大意：FPGA 上面向数字音频应用的 CIC 滤波器后实现评估）

拆解这个标题，可以读出论文的三个核心要素：

- **研究对象**：CIC 滤波器（CIC = Cascaded Integrator-Comb，级联积分梳状滤波器）。
- **应用场景**：数字音频（digital audio applications）。
- **评估阶段**：后实现（post-implementation），即在 FPGA 上跑完 Vivado 的「实现」阶段之后，用真实布线结果来评估。
- **评估平台**：FPGA。

> 什么是「后实现评估」？简单说：把设计从代码变成 FPGA 上的真实电路（经过综合 + 布局布线），然后用量化指标（用了多少资源、能跑多快、时序是否满足）来评价它。这正是本仓库那些报告文件要回答的问题。

#### 4.2.2 核心流程

把「论文 → 数据仓库」的关系画成一条链：

```text
论文提出实验目标
   │
   ▼
用 Vivado 跑综合 + 实现（不在本仓库内）
   │
   ▼
生成 utilization / timing 报告  ──►  存入本仓库（vivado_reports/）
   │
   ▼
论文据此做对比、分析、下结论
```

关键点：**本仓库只承载这条链的「报告产物」一段**。论文正文、生成设计的源码、Vivado 工程文件都不在仓库里。

#### 4.2.3 源码精读

论文标题的唯一「出处」就是 `README.md` 的那一行。我们把其中论文标题部分单独标出：

永久链接：[README.md:1（论文标题部分）](https://github.com/gitlab.upt.ro/elisei.ilies/CIC-filters.git/blob/e49b263d702c6fb0d4ea1d5b8390d307e6ba43d1/README.md#L1)

> 引用片段：`... for the "Post-Implementation Evaluation of CIC Filters for Digital Audio Applications on FPGA" paper.`

> ⚠️ **待确认（重要）**：论文的**正文（全文 PDF、摘要、实验细节、具体音频参数）并不在仓库内**。本仓库只提供报告数据，论文内容需要你另行从论文出处获取。因此本讲及后续讲义中凡涉及「论文具体结论/具体音频采样率」之处，若报告文件无法佐证，一律标注「待确认」，不做编造。

#### 4.2.4 代码实践

1. **实践目标**：明确「仓库内的信息」与「论文内的信息」的边界。
2. **操作步骤**：
   - 重新查看 `README.md`。
   - 在本子上分两栏：左栏写「能从本仓库直接获得的信息」，右栏写「需要查论文正文才能获得的信息」。
3. **预期结果（示例）**：
   - 左栏：报告文件、Vivado 工具来源、论文标题、报告里能读到的资源/时序数据。
   - 右栏：论文的实验动机、具体音频指标、结论表述（待确认，论文不在仓库）。
4. **需要观察的现象**：你会意识到「仓库能自证的信息」其实有限——这有助于你在后续学习中区分「数据事实」与「论文观点」。

#### 4.2.5 小练习与答案

**练习 1**：论文标题中的 "Post-Implementation" 是什么意思？

> **参考答案**：指「实现（implementation）阶段之后」的评估，即 Vivado 完成布局布线后，用真实的资源占用和时序结果来评价设计，而不是停留在纯综合或纯理论的估算层面。

**练习 2**：为什么本仓库无法用来验证「论文具体用了哪个音频采样率」？

> **参考答案**：因为论文正文不在仓库内，报告文件只记录 FPGA 实现后的资源/时序结果，不包含音频系统的具体采样率等应用层参数；这类信息需查论文原文，故标注「待确认」。

### 4.3 仓库顶层目录结构

#### 4.3.1 概念说明

了解一个仓库，最有效的方式之一是「看它顶层放了什么」。不同类型的仓库，顶层结构差异巨大：

- **软件项目**：通常有 `src/`、`package.json`、`Makefile`、`Cargo.toml`、测试目录等——你能看出「用什么语言、怎么构建」。
- **数据/报告仓库**：顶层通常是一堆数据文件或几个数据目录，没有构建脚本。

本仓库属于后者。看清顶层结构，能立刻帮你建立正确预期：**这里没有需要编译运行的代码，有的是大量 Vivado 报告文件**。

#### 4.3.2 核心流程

顶层探索流程（按「由外到内」三步）：

1. **列根目录** → 看清顶层有哪些条目。
2. **逐条归类** → 每个条目是「说明文件 / 数据目录 / 辅助目录」中的哪一类。
3. **进入核心目录** → 只看一层，知道核心数据是怎么分层组织的（更深层在后续讲义）。

#### 4.3.3 源码精读

仓库根目录下有 3 个顶层条目（本仓库被 Git 追踪的文件共计 655 个，几乎全部位于 `vivado_reports/` 内）：

| 顶层条目 | 类型 | 用途说明 |
| --- | --- | --- |
| `README.md` | 说明文件 | 仓库自我介绍，说明数据来源与关联论文（见 [4.1](#41-readmemd仓库的自我介绍)） |
| `vivado_reports/` | **核心数据目录** | 存放全部 Vivado 报告，本仓库的「主角」 |
| `CIC-filters-tutorial/` | 辅助目录 | 学习手册输出目录，你正在读的讲义就在这里 |

其中核心目录 `vivado_reports/` 的第一层（**只看一层**，更细的命名规则在 u1-l2 讲）：

| `vivado_reports/` 下条目 | 含义 |
| --- | --- |
| `reports_at_100Mhz/` | 100 MHz 时钟约束下的报告 |
| `reports_at_290Mhz/` | 290 MHz 时钟约束下的报告 |
| `reports_at_300Mhz/` | 300 MHz 时钟约束下的报告 |
| `summary.xlsx` | 汇总表（跨配置聚合结果，内部结构待确认，在 u3-l5 详讲） |

> 关键结论：仓库按**时钟频率**做顶层分组，每个频率目录里再按「实现方案 × 报告类型 × 参数」组织具体文件。这就是后续「频率 × R × N 实验矩阵」的物理体现。具体的目录命名约定（如 `R16_N4`、`impl/synth`）将在 **u1-l2** 详细拆解。

#### 4.3.4 代码实践

这是一个「命令行探索型实践」，用只读命令看清结构。

1. **实践目标**：亲手列出仓库顶层，确认它「没有构建脚本」。
2. **操作步骤**：在仓库根目录依次执行下面的只读命令。
3. **命令（全部只读，安全）**：

   ```bash
   # 1) 列出根目录全部条目（含隐藏文件）
   ls -la

   # 2) 查看 Git 追踪了哪些文件（顶层概览）

   # 3) 统计追踪文件总数，确认绝大部分在 vivado_reports/ 下
   git ls-files | wc -l
   git ls-files | grep -c '^vivado_reports/'

   # 4) 查看 vivado_reports 第一层结构
   ls vivado_reports/

   # 5) 查看提交历史，理解仓库的演进
   git log --oneline
   ```

4. **预期结果**：
   - `ls -la` 输出 `README.md`、`vivado_reports/`、`CIC-filters-tutorial/`（外加 `.git` 等 Git 内部目录）。
   - `git ls-files | wc -l` 显示约 **655** 个追踪文件。
   - `grep -c '^vivado_reports/'` 显示绝大多数文件都在 `vivado_reports/` 内。
   - `ls vivado_reports/` 输出 `reports_at_100Mhz  reports_at_290Mhz  reports_at_300Mhz  summary.xlsx`。

5. **需要观察的现象**：注意**没有任何** `*.v` / `*.vhd`（HDL 源码）、`*.tcl`、`Makefile`、`*.json` 工程描述出现在顶层——这印证了「无源码、无构建脚本」的判断。

> 待本地验证：文件总数等数字以你本地 `git ls-files | wc -l` 的实际输出为准（本讲记录的是撰写时的值 655）。

## 7. 下一步学习建议

你已经看清了仓库的「顶层地图」。接下来建议按学习路线继续：

- **下一步（u1-l2《目录结构与文件命名规则》）**：钻进 `vivado_reports/`，搞懂 `timing_impl_R16_N4.txt` 这类文件名里每一段（`R`、`N`、`impl`/`synth`）的含义，以及三种实现方案目录的区别。
