本讲是全手册收尾，回答「仓库报告如何生产、如何复现」，核心立场是：这是「报告数据集」而非「工程源码」仓库，复现=补齐缺失上游+照抄报告头部已固化的下游命令。最小模块有三：(1) Vivado 流水线五步——准备设计→建工程(加源码与 .xdc 约束，用 `create_clock -period` 锁定 100/290/300MHz 频率点)→综合(synth)→实现(impl，含 opt/place/route，产物标记为 `Design State : Routed`)→导出报告；报告所属阶段靠文件名 `_synth_`/`_impl_` 与 utilization 头部 `Design State` 判定，时序报告则靠文件名加 WNS 佐证。(2) 三种生成路径各有「指纹」：CIC Compiler 走 IP Catalog，Design 名恒为 `cic_compiler_0`，受 IP 参数限制导致实验矩阵稀疏；MATLAB HDL Coder 由 `dsp.CICDecimator` 生成 RTL，Design 名为 `CIC_R{R}_N{N}`、随参数变化、覆盖最全；Open-source 手写 RTL，Design 名固定 `cic_d`。(3) 两条导出命令差异：`report_timing_summary` 带 `-rpx`(故时序报告 .txt 与 .rpx 成对)，`report_utilization` 不带。可复现性要素分两类：已固化(Vivado 2022.2、器件 xc7a100tcsg324-1、速度等级 -1、报告命令、实验机)可直接从头部读取；缺失(HDL、.xdc、.tcl、.xpr、.xci、.m)须读者自行补齐。复现成功判据为重跑后头部 Device/Design State 一致且 WNS 接近仓库记录值(如 CIC Compiler R16_N4@100MHz 的 6.274 ns)。
