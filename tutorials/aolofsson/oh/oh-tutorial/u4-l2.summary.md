本讲承接 u4-l1 的 `dv_top` 三段式骨架，聚焦测试平台运行时的「激励来源、回放、生命周期」三件事，不展开 emesh 104 位包位序（留给 u5-l1）。核心是 `.emf` 文本事务格式：一行一个事务，由五个下划线分隔的十六进制段组成——`srcaddr/datahi`、`datalo`、`dstaddr`、`ctrlmode`、`access`；字段语义以 `egen.pl` 的 `printf` 为权威。`ctrlmode` 的 bit0 是写位、bits[2:1] 是 datamode（字节/半字/字/双字），字节数满足 `8 ≪ datamode`；同组字段靠写位区分读写。

运行时由 `dv_driver` 承载「回放（stimulus）+ 监视（emesh_monitor）+ 仿真存储（ememory）」三件套，按通道 generate 展开，全局完成信号是各通道 done 的与归约。真正加载 `.emf` 的是 `stimulus.v`：用 `$readmemh` 一次性读入，IDLE→ACTIVE→PAUSE→DONE 状态机按 `dut_ready` 节拍回放，遇无效行即停。`oh_simctrl` 用一个 `initial` 串起复位→load→go 的 mode 序列，`dut_done` 后判 PASSED/FAILED，并以独立 `initial` 做 TIMEOUT 兜底。`egen.pl` 按字节预算生成随机写、哈希去重，再为每写追加 READ 与 EXPECTED，自动产出「激励 + 黄金参考」一对文件。

需注意：本仓库存在接口漂移——`dv_driver.v` 实例化的 `stimulus`/`ememory` 与现版 `stimulus.v` 及缺失的 `ememory.v` 对不上，`dv_driver.v` 当前属架构意图而非可直接编译的实现，读源码以实际文本为准。
