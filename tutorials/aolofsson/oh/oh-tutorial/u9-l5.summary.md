本讲是 OH! 手册收官篇，从「读」转向「写与交付」，覆盖三个最小模块。**设计规范**：OH! 风格统一的根源是 README 里 Design/Coding/Documentation 三套家规——核心分别是解耦（Separate）、只用一份白名单关键字（assign/always/case/posedge/generate/$signed 等，无 initial/casex/defparam）、每个信号进表带波形；它们靠 review 落地，是 soft/hard 双实现成立的根因。**流片检查**：`tapeout_checklist.md` 把送厂前自检分成 14 大类，其中设计/时钟/复位/验证四类与本手册直接挂钩，每条都对应已讲原语（`oh_rsync` 异步进同步出、`oh_fifo_cdc` 覆盖所有跨域、`asic_clkicgand` 门控时钟），形成规范—原语—清单闭环。**二次开发**：新增 emesh 外设 = 复制 GPIO 骨架换内核，六步法为 regmap.vh → RTL（emesh_unpack + 地址译码 + emesh_readback）→ dut 包装 → emf 激励 → build.sh → sim.sh。核心结论是「以源码为准、用双手弥合文档与现实」——build.sh 指向不存在的 libs.cmd、gpio.v 用旧名 enoc_unpack、dv_top 存在接口漂移，均需据实修。
