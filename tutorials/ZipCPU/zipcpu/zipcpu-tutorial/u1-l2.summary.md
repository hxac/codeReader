本讲梳理 ZipCPU 的 monorepo 结构与层级构建系统。仓库分五个顶层目录：rtl/ 存 Verilog 硬件与四种顶层封装（zipsystem/zipbones/zipaxil/zipaxi），sw/ 构建交叉工具链 binutils、GCC、newlib（产出 zip-gcc 等），sim/ 提供独立 C++ 指令级模拟器与基于 RTL 的 Verilator 模拟器两套，bench/ 承担汇编测试与形式化验证，doc/ 存 ISA 规范。顶层 Makefile 仅做调度，用 SUBMAKE 将工作转发到各子目录，默认 all: rtl sw sim；关键依赖为 vsim 依赖 rtl（模拟器需先有 Verilator 模型），test 串起 bench、sim、formal 全链路。核心结论：make rtl 的产物落在 rtl/obj_dir/，是 Verilator 生成的 C++ 模型（V*__ALL.a），同一份 RTL 经不同 OPT_* 配置编译出多个变体，可运行模拟器由 sim/verilator 在此基础上链接得到；bench/asm 产出可执行 ELF 测试程序，bench/formal 产出 SymbiYosys 证明结论而非程序。构建前须按 INSTALL.md 装好依赖（含源码编译 Verilator），make sw 首次会中途失败，需把 sw/install/cross-tools/bin 加入 PATH 后重跑续编，全程不污染系统全局。
