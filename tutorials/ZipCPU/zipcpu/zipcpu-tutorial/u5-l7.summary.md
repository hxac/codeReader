本讲为《ZipCPU 学习手册》收官篇，讲如何把 CPU 集成进自定义 SoC。核心积木四块：地址译码器 `addrdecode` 用 `(addr^BASE)&MASK==0` 把地址变成独热的从设备选中线，并多留一位 `request[NS]` 表示「无命中→bus error」；总线互连 `wbxbar` 是 NM 主×NS 从的 Wishbone crossbar，由 `skidbuffer`、`addrdecode`、优先级仲裁、在途计数与超时构成，访问不同从设备可并行；`zipaxil` 是 AXI-Lite CPU 顶层，对外暴露分离的指令主端口（只读 AR/R）、数据主端口与调试从端口，本身不含互连/存储/外设；`board.h` 用 `volatile` 指针定义软件地址映射，须与硬件 `SLAVE_ADDR` 一致。关键结论是「协议边界」：`zipaxil` 为 AXI-Lite，`wbxbar`/`memdev`/`wbscope` 为 Wishbone，不可直连，应整链路统一协议（`zipaxil`+`axilxbar` 或 `zipbones`+`wbxbar`）。官方测试台走 CPU 直连单内存模型的最简验证，自定义 SoC 才需把 crossbar 与多从设备加回去——这正是二次开发的核心工作。
