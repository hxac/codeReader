本讲深入 `sim/verilator` 目录，讲解 ZipCPU 如何用 Verilator 把 Verilog RTL 编译成 C++ 库（`rtl/obj_dir/V*__ALL.a`），再由 C++ 测试台链接成可执行模拟器。核心组件包括：`testb.h` 中的 `TESTB<VA>` 基类模板，封装模型实例化、`tick()` 时钟生成、复位与 VCD 波形；整 CPU 测试台 `zipcpu_tb.cpp` 靠 `-DZIPBONES` 宏同时服务 ZipSystem 与 ZipBones，主流程为「ELF 加载 → 调试端口复位/设 PC/放行 → `tick()` 循环 → 成功失败判定」。引入的关键术语有 DUT、调试端口命令寄存器（`CMD_REG`、`CMD_HALT`、`CMD_STEP`、`CMD_GO`）、SIM 指令的带外通道、Wishbone 握手、以及 RAM 基址 256 MiB 的布局约定。三种运行模式 `-a` 自动/`-s` 单步/交互对应 Makefile 的 `atest`/`stest`/`itest`，`test` 目标把三种顶层 × 两种自动模式串行回归。核心结论：HALT＝成功（CPU 监管态睡眠触发 `test_success()`），BUSY＝失败（原地空转永不睡眠），非法访问触发 `m_bomb` 也是失败出口，最终靠返回码做 CI 判定。组件测试台（`div_tb`/`mpy_tb`/`pfcache_tb`）只链接单模块库，用大量边界扫描配 `assert` 深测单一模块，与整 CPU 端到端测试互补；ZipSystem 配置下还会打印 IPC 作为流水线效率指标。
