本讲承接 u2-l4 与 u4-l1，讲清训练循环如何把分数组装成 token 级张量。奖励有两条来路：model-based（奖励模型产出已是 token 级的 `rm_scores`）与 rule-based（`compute_score` 返回标量），`RewardManager` 是统一入口。其 `__call__` 检测到 `rm_scores` 即短路返回、跳过规则函数，故 model-based 优先；但 `fit()` 注释所谓「combine」与实现的 short-circuit 不符，须以代码为准。TinyZero 默认关闭奖励模型，实际只走 rule-based。

`RewardManager` 逐条用 `attention_mask` 切开左填充 prompt 与右填充 response，解码出可读文本，按 `data_source` 路由到对应 `compute_score`，再把标量放到最后一个有效 response token（其余位置为 0），即稀疏奖励的末位放置；两条来路共享此不变量。因 response 右填充，不用 mask 直接放末位会把分数丢到 pad 上被清零。

关键术语：稀疏奖励、token 级与标量分数、`data_source` 路由、末位放置、`num_examine`（仅控制调试打印）。验证用 `val_reward_fn`（同 `RewardManager`、贪心解码、只走规则奖励），最后 `.sum(-1)` 压成样本级。产出的 `token_level_scores` 是 PPO 一切计算的起点，下接 `apply_kl_penalty` 与 `compute_advantage`。
