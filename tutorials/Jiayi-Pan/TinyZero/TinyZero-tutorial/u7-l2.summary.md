本讲讲数据并行下因 response 长度差异极大导致的负载不均，分两条主线解决。第一条是 driver 侧的跨 rank 均衡：`_balance_batch` 在 generate 后、前向前对整个 batch 重排，使 dispatch 的等分竖切每个 rank 拿到的 token 总量接近；它用 `equal_size=True` 保证各组样本数相等以对齐 `chunk(world_size)`，并写入 `global_token_num` 到 meta_info。第二条是 worker 侧的单卡动态 batching：`use_dynamic_bsz=True` 时 `rearrange_micro_batches` 把「固定条数切」换成「按 `max_token_len` token 预算切」（`equal_size=False`），各 micro batch 计算量稳定以吃满 GPU，并用 `all_reduce(MAX)` 对齐 DP 组内 micro batch 数量避免快慢卡等待。两者共用内核 Karmarkar-Karp 最大差分法（LDM），用小顶堆优先合并 spread 最大者、合并时「大配小」做差分逼近最优。`get_seqlen_balanced_partitions` 是统一入口，返回索引分组并做不重不漏校验；只读前向需用 `get_reverse_idx` 还原顺序，训练反传因梯度可交换而丢弃索引。该均衡机制对自定义任务透明。
