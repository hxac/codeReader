本讲聚焦 PPO/GRPO 训练循环中策略网络 Actor 的前向与参数更新，主角是 `DataParallelPPOActor`（文件 `verl/workers/actor/dp_actor.py`）。该类有三大方法：底层前向 `_forward_micro_batch`、只读重算 `compute_log_prob`、训练更新 `update_policy`；当构造时不传 `actor_optimizer`，它退化成冻结的参考策略（Reference Policy），复用前向代码只供算 `ref_log_prob`。

`_forward_micro_batch` 是 logits 到 log_prob/entropy 的核心：用切片 `[:, -response_length-1:-1]` 实现 next-token 预测的 shift 对齐，`logits.div_(temperature)` 原地做温度缩放，返回当前策略下每个 response token 的对数概率与熵。`use_remove_padding=True` 时改走 `flash_attn_varlen` 压成变长序列跳过 padding，并可叠加 Ulysses 序列并行。`compute_log_prob` 是 `eval()+no_grad()` 的只读前向，专用于 recompute `old_log_probs`，使 PPO importance ratio 初始≈1；temperature 须显式从 `meta_info` 取以防静默错误。

`update_policy` 采用 mini-batch（决定 step 频率）→ micro-batch（决定单次显存）→ 梯度累积的三层结构，`gradient_accumulation = ppo_mini_batch_size // ppo_micro_batch_size` 用于 loss 归一，使累积梯度等价于整 mini-batch 平均梯度。核心 loss 组合为 `policy_loss = pg_loss - entropy_loss*entropy_coeff`，GRPO 路线再 `- kl_loss*kl_loss_coef`（loss 端 KL，与 reward 端 KL penalty 互斥）。需注意 FSDP 后端下 `update_policy` 是单 epoch，`ppo_epochs` 配置仅用于 MFU 估算。
