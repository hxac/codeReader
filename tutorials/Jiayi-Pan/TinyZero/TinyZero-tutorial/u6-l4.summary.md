本讲讲解 veRL 的 `vLLMRollout` 如何用 vLLM 推理引擎完成 RL 中的 rollout（让当前策略生成一批回答）。它与 FSDP 训练态权重解耦：生成前由 sharding manager 同步权重、重建 KV cache，生成后 offload 让出显存（权重同步细节属下一讲）。硬约束：`free_cache_engine=True` 必须搭配 `enforce_eager=True`，因为 CUDA graph 固化了 KV cache 地址，与动态释放/重建 cache 互斥。`_pre_process_inputs` 用 nonzero 找首个非 pad 位置，把左填充 prompt 还原为无填充的 `List[int]`，仅对左填充有效。`generate_sequences` 把 vLLM 变长 response 右填充对齐到 `response_length`，用 `get_eos_mask`（在首个 eos 处截断）重建 response 的 attention_mask，用「prompt 末位 + arange」重建连续递增的 position_ids；prompt 左填充、response 右填充是贯穿全局的关键概念。vLLM 返回的 logprobs 不直接使用，调用方改用 FSDP actor 的前向重算 `old_log_probs`，以保证 PPO 的 importance ratio 起点为 1。两条采样路径：`do_sample=False`（来自 meta_info）走贪心验证，借 `update_sampling_params` 上下文管理器临时改参、用完还原；`rollout.n>1` 走 `repeat_interleave` 扩展 batch，是 GRPO 的入口开关。
