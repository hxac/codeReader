本讲解决数据进入训练主循环前的「最后一公里」：把 u2-l1 产出的 parquet 行（含 `prompt`、`data_source`、`reward_model.ground_truth`、`extra_info` 等字段）转换为 PyTorch 张量样本，核心是 `RLHFDataset` 与配套的 `collate_fn`。它涵盖四个最小模块：`RLHFDataset` 构造时仅用 pandas 读 parquet 为 `self.dataframe`，tokenize 是惰性的，发生在 `__getitem__` 里——按行取出 chat 列表，取 `chat[0]['content']`，调用 `tokenize_and_postprocess_data` 得到 `input_ids` 与 `attention_mask`，再用 `compute_position_id_with_mask` 推出 `position_ids`，最终返回「张量+非张量」混合字典。`tokenize_and_postprocess_data` 采用**左填充**（内容在右端），因为 rollout 生成从序列右端追加 token；超长时 `truncation='error'` 直接报错，避免悄悄截断破坏任务。`compute_position_id_with_mask` 用 `clip(cumsum(mask)-1, min=0)` 一行由 mask 推出位置编号，与填充方向无关，真实 token 总从位置 0 起递增。`collate_fn` 按字段类型分流：张量 `torch.stack` 成 `[batch, seq_len]`，非张量（如 `data_source`、`reward_model`）装进 `dtype=object` 的 numpy 数组，使奖励函数仍能取到任务类型与正确答案。关键术语：左填充、`truncation='error'`、`attention_mask`、`position_ids`、`collate_fn`、惰性 tokenize。本讲产出「一个 batch 的张量样本」，为 u3-l1 的 `DataProto` 协议与 u4-l3 的训练主循环铺路。
