本讲讲解如何为 TinyZero 端到端新增一个全新 RL 任务。核心结论是：接入新任务只需改动「数据-奖励-路由」三件套——数据预处理脚本、规则奖励函数、以及一行路由分支；而 Worker、训练主循环、PPO/GRPO 算法、Ray 调度等通用基础设施完全透明、原样复用，无需改动。

关键概念 `data_source` 是贯穿三件套的字符串契约：在预处理脚本中写进 parquet 每一行（同时写入 `prompt` 与 `reward_model.ground_truth`），训练时由 `RewardManager` 读出，再经 `main_ppo.py` 的 `_select_rm_score_fn` 做**子串匹配**路由到对应的 `compute_score`。

三件套分别对应：第一件套 `make_prefix` 把题目翻译成以**未闭合 `<think>`** 结尾的 prompt，须保证 prompt 的 `<answer>` 格式约定与奖励抽取标签一致（否则奖励恒为 0）；第二件套 `compute_score(solution_str, ground_truth)→标量` 用「提取→校验→求值→分级打分」模板，countdown 较复杂、只比数值的任务可极简到整数比较甚至直接复用 `multiply.compute_score`，其中 `format_score` 提供起步信号但忌过高以防 reward hacking；第三件套在路由顶部 import 并加 `elif "xxx" in data_source` 分支，未命中即抛 `NotImplementedError`。本讲以「两数求和」为沙盒串通全链路。
