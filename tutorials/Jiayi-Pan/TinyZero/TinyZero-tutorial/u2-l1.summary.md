本讲精读数据预处理脚本 `examples/data_preprocess/countdown.py`，讲清 countdown 训练数据的「出厂全流程」。countdown 任务给定目标数 `target` 与一组可用 `numbers`，要求用算术运算凑出目标，因结果可机器判错对而天然适合 RL。讲义拆为三个最小模块：`gen_dataset` 用随机参数（6 个数字、target≤1000、数字 1~100、seed=42）描述样本生成规格，但在主流程中实际未被调用，数据来自 `load_dataset('Jiayi-Pan/Countdown-Tasks-3to4')`；`make_prefix` 把 `(target, numbers)` 翻译成自然语言 prompt，核心是用 `<think>` / `<answer>` 标签约定输出格式并以未闭合的 `<think>` 引导续写，提供 `base` 与 `qwen-instruct` 两套仅外壳不同的模板；`make_map_fn` 作为高阶函数，把 prompt 组装成 veRL 期望的 parquet 字段。核心结论有二：其一，prompt 的格式约定与奖励函数 `reward_score/countdown.py` 强耦合，改 prompt 必须同步改奖励函数，否则奖励恒为 0；其二，`data_source`（路由奖励函数）与 `reward_model.ground_truth`（判分参考 `{target, numbers}`）是数据与训练系统之间的两根接口线。最终通过 `to_parquet` 写出 train/test.parquet，可选地用 `hdfs_io` 的 `makedirs`/`copy` 拷到 HDFS。
