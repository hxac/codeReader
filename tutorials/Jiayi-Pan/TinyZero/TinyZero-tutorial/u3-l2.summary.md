veRL 采用「单控制器（single-controller）」架构：一个 driver 进程跑训练主循环并握有完整 DataProto，负责编排；各 GPU 上只放被动的 Ray worker actor 负责计算。driver 不裸调 ray，而是通过 WorkerGroup 调方法，group 内部由 func_generator 统一执行「dispatch → execute → collect」三段式骨架，其中带 @register 的方法被运行时动态绑定到 group 上。

资源侧，RayResourcePool 把抽象的 process_on_nodes（每节点进程数列表，其和为 world_size）翻译成 Ray PlacementGroup，每进程对应一个 bundle（1 GPU + 若干 CPU），默认 STRICT_PACK 打包到节点；关键参数 max_colocate_count 决定 num_gpus = 1/max_colocate_count，即一张 GPU 上能挤几个角色进程。

RayClassWithInitArgs 包装「类 + 构造参数」，RayWorkerGroup 遍历资源池逐槽位将其远程化为 actor，并注入 RANK/WORLD_SIZE/MASTER_ADDR 等环境变量，master 地址端口由 rank 0 选定并经「注册中心」广播给其余 rank。

create_colocated_worker_cls 实现 colocate：把多个角色合体进同一 WorkerDict 进程共享显存，再用 spawn 拆成多个逻辑 group 视图——物理一组 actor、逻辑多个 worker group。main_ppo 的三张表（role_worker_mapping/resource_pool_spec/mapping）是接线图，三个 Role 都指向唯一 global_pool；FSDP 后端选 max_colocate_count=1，靠进程级合体而非 GPU 级分时来共享显存。
