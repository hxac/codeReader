本讲解决「文件放在哪、工程怎么搭」。项目遵循 Vivado 目录约定：`Fir_filter.srcs/sources_1/new/` 下放 6 个 `.v`（含设计源与 testbench），`constrs_1/imports/` 下放板级 XDC。核心是工程重建脚本 `Fir_filter.tcl`，它按 `create_project → 建 fileset（sources_1/constrs_1/sim_1）→ 导入源 → 设 top → 建 run（synth_1/impl_1）` 的顺序凭空搭起工程，目标 part 为 `xc7a100tcsg324-1`（Artix-7 / Nexys A7-100T）。关键配置：综合/实现顶层为 `fir_filter`，仿真顶层为 `fir_filter_tb`——同一工程两套顶层，靠 fileset 的 top 属性而非目录区分。两个重要坑：脚本源文件路径硬编码为 `../Vivado_projects/Fir_filter/...`，且 `validate_required=0` 跳过文件存在性检查，fresh clone 直接 `source` 会在 `import_files` 处失败，手动新建工程并添加源最稳妥。XDC 是 Digilent 主板模板，所有约束行被注释，且模板端口名（`CLK100MHZ` 等）与本项目 `clk/xn/yn` 对不上；当前设计面向仿真，约束暂不起作用，下板时需取消注释并改写端口名。引入术语：project、part、fileset、top、run、XDC、Tcl。
